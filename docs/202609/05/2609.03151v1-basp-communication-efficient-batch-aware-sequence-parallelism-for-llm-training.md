## 摘要
长上下文推理对于大型语言模型（LLM）变得越来越重要，但长序列训练由于巨大的内存和通信需求仍然具有挑战性。序列并行已成为解决长序列LLM训练瓶颈的关键技术。然而，我们观察到现有的序列并行方法是批量无关的，并且对所有批量大小采用统一的序列分区，导致通信效率低下。在本文中，我们引入了批量感知序列并行（BASP），这是一种利用批量结构来减少通信开销的序列并行方法。BASP通过根据微批量大小将GPU划分为不相交的序列并行组来利用批量结构。这种设计减小了全到全通信组的大小，从而本地化通信并提高训练效率。在NVIDIA A100集群上的实验结果表明，与标准序列并行基线相比，BASP在Llama和Qwen模型上将端到端训练时间提高了1.17-1.31倍，同时保持了相同的模型准确率和内存使用量。

## Abstract
Long-context reasoning for large language models (LLMs) is becoming increasingly important, but training over long sequences remains challenging due to massive memory and communication requirements. Sequence parallelism has emerged as an essential technique for addressing bottlenecks in long sequence LLM training. However, we observe that existing sequence parallelism methods are batch-agnostic and apply uniform sequence partitioning across all batch sizes, resulting in inefficient communication. In this paper, we introduce Batch- Aware Sequence Parallelism (BASP), a sequence parallelism approach that leverages batch structure to reduce communication overhead. BASP exploits batch structure by partitioning GPUs into disjoint sequence-parallel groups according to the micro- batch size. This design reduces the all-to-all communication group size, thereby localizing communication and improving training efficiency. Experimental results on an NVIDIA A100 cluster show that BASP improves end-to-end training time by up to 1.17 - 1.31x in Llama and Qwen models compared to standard sequence parallel baselines, while preserving identical model accuracy and memory usage.

## BASP 论文详细总结

### 一、核心问题与研究动机

- **问题背景**
  - LLM 日益需要处理**超长上下文**（ChatGPT 128K tokens、Claude 1M tokens），但长序列训练面临**显存不足**和**通信开销大**两大瓶颈。
  - 数据并行、流水并行、张量并行均无法有效解决长序列场景下的单卡显存压力；序列并行（SP）被认为是解决长序列训练的关键范式。
- **现有方法的缺陷**
  - 以 DeepSpeed-Ulysses 为代表的序列并行虽能在注意力中通过 all-to-all 实现头并行，但其**all-to-all 通信规模与 GPU 总数 N 成正比，且与微批量大小无关**。
  - 作者观测到：**批量大小 B 越大，全局 N 路 all-to-all 的时间占比越高**（从 B=1 的 24.5% 增至 B=8 的 33.8%，图示数据），通信效率低下，批量无关的均匀切分缺乏拓扑感知。
- **核心观察（motivation）**
  - 当微批量大小 B>1 且 N 能被 B 整除（N=KB）时，**无需让 N 个 GPU 对每条序列做全局通信**，而可把 GPU 分给不同序列，将一次 N 路 all-to-all 分解为 B 个并行的 K 路 all-to-all，并让 K 匹配节点内 GPU 数以完全利用 NVLink、避免跨节点通信。

### 二、方法论

- **总体思想**：Batch-Aware Sequence Parallelism（BASP），一种**批量感知的序列并行**方法。它打破 Ulysses-SP 中“序列均匀地切给所有 N 个 GPU、all-to-all 在所有 N 卡间进行”的固定逻辑，改为**将 GPU 划分为 B 个互不相交的序列并行组**，每个组负责一批中的一条序列。
- **关键设定**
  - 组大小 K = N / B（要求 N 与 B 整除，否则回退或不可用）。
  - 组数 = B（每个组处理 batch 中一条完整序列）。
  - 若 K 等于每节点 GPU 数，则通信仅在**节点内 NVLink** 完成，避免跨 InfiniBand 通信。
- **算法流程（文字版）**
  1. **批量感知组形成**：对每个全局 rank，计算 K=N/B；形成 B 个连续组（rank 0~K-1、rank K~2K-1…）；每组调用集合通信库创建独立 process group。
  2. **批量感知序列分区**：每条序列只在其所属的 K 个 GPU 内按序列长度切分为 K 块；GPU 持有的 token 数仍为 BS/N，与 Ulysses-SP 相同。
  3. **子组 all-to-all**：注意力计算中，各组内部各自做 K 路 all-to-all，多个组并行完成，效果等同全局注意力，且每个 GPU 的通信对端从 N-1 减至 K-1。
- **工作负载与内存等价性（文中推导，文字概括）**
  - Ulysses-SP 每 GPU 工作量 ∝ B·H·(S/P)·d；BASP 将 P 个 GPU 分为 G 组，每 GPU 处理 B/G 条序列、分片长度为 SG/P，其工作量 ∝ (B/G)·H·(SG/P)·d = B·H·(S/P)·d，**完全一致**，故不增加显存。
- **与一般 SP degree 参数调低的区别（关键贡献点之一）**
  - 将 Ulysses-SP 的 SP 度调至 K=N/B 与 BASP 不同：该配置让每 GPU 处理 B²S/N 个 token，牺牲了对序列的切分（序列不再跨 GPU 切分，长序列内存收益丢失）。
  - BASP 保持 SP=N 级别的序列切分粒度（每 GPU 仅 BS/N token），同时又只让 K=N/B 个 GPU 参与 all-to-all，**鱼与熊掌兼得**。

### 六、主要结论与发现

- **端到端加速**：在序列长度 16K、batch=2 条件下，BASP 使 Llama 与 Qwen 模型提速 **1.17×–1.32×**（对应 step time 缩短 14.7%–24.1%）；其中 Llama 3.1-8B 加速 1.21×，Qwen 1.5-1.8B 加速 1.31×。

1. **洞察新颖且简洁**：首次提出从“批量结构”这一角度优化序列并行的 all-to-all，观察朴素却有效。

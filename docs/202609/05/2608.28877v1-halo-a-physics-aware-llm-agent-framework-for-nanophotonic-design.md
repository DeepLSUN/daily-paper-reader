## 摘要
近年来，语言模型已被应用于纳米光子设计，但仍不清楚它们能否可靠地将光学目标转化为可仿真的设计、执行电磁分析并根据数值反馈修正决策。我们提出了 HALO，一个物理感知框架，它将语言模型规划器与类型化设计规格、电磁仿真、诊断评估以及迭代设计循环中对先前失败轨迹的可选复用相结合。我们进一步引入了 HALO-Bench，一个包含 52 个任务的基准测试，涵盖源自实验室、源自论文和开放式的纳米光子设计任务，并采用统一的评估协议。我们比较了三种规划器配置：固定结构化工作流、使用相同仿真接口的自主结构化智能体，以及直接编写和执行仿真代码的自主编码智能体。固定结构化工作流在令牌效率上最高，没有观察到代码级或路径级失败，而自主编码在搭载更强模型时可实现更高的任务成功率，但会产生更多操作失败。我们还研究了先前失败轨迹的复用。在有针对性的多轮任务中，检索到的失败反馈减少了首次成功所需的迭代次数和总令牌使用量。这些结果阐明了科学智能体中显式接口、自主执行和可复用设计经验之间的权衡。

## Abstract
Language models have recently been applied to nanophotonic design, but it remains unclear whether they can reliably translate optical objectives into simulation-ready designs, execute electromagnetic analysis, and revise decisions from numerical feedback. We introduce HALO, a physics-aware framework that couples language-model planners with typed design specifications, electromagnetic simulation, diagnostic evaluation, and optional reuse of prior failure trajectories in an iterative design loop. We further introduce HALO-Bench, a 52-task benchmark spanning lab-derived, paper-derived, and open-ended nanophotonic design tasks under a shared evaluation protocol. We compare three planner configurations: a Fixed Structured Workflow, an Autonomous Structured Agent using the same simulation interface, and an Autonomous Coding Agent that directly writes and executes simulation code. The Fixed Structured Workflow is the most token-efficient and exhibits no observed code- or path-level failures, while autonomous coding can achieve higher task success with stronger models at the cost of additional operational failures. We also study reuse of prior failed trajectories. On targeted multi-round tasks, retrieved failure feedback reduces both iterations to first success and total token use. These results clarify the tradeoffs between explicit interfaces, autonomous execution, and reusable design experience in scientific agents.

## 2. 方法论

### 2.1 总体架构
HALO 是"提出→执行→评估→修正"（propose–execute–evaluate–revise）的闭环框架。它将用户自然语言的光学目标转化为**可执行的仿真方案**，包含：
- **类型化机器可读的仿真规格（design schema）**：显式定义几何结构、材料分配、照明条件、求解器配置、设计变量与评估指标。
- **电磁执行层**：对结构化方案先做 Pydantic 校验，随后执行 RCWA 仿真；对代码类方案则在工作区内直接运行仿真代码。
- **诊断评估层**：尝试以共享的评估协议，为不同来源产出的异构中间产物生成一次性的、可执行评估脚本，计算数值指标和 pass/fail 结论，并输出可读诊断说明。
- **历史轨迹追踪**：完整记录设计过程，并在指定消融实验中支持“复用失败轨迹”。

### 2.2 三种规划器配置
为研究"工作流编排”与“仿真接入方式"的影响，对比了三种配置：
- **Fixed Structured Workflow（固定结构化工作流）**：预定义 LangGraph 路径，每轮仅一次规划调用 + 固定工具调用，限制工具/文件自由操作。
- **Autonomous Structured Agent（自主结构化智能体）**：支持智能体自主编排（可读写文件、维护笔记等），但仿真仍然强制走**结构化接口**。
- **Autonomous Coding Agent（自主代码智能体）**：自主编排且允许直接编写、执行、调试 Python 仿真代码，不受 schema 接口约束。

### 2.3 失败轨迹复用模块（可选）
在延迟收敛等特定任务中，尝试叠加**基于模式的混合检索**：将"文本相似度 + schema 字段相似度（几何、材料、光路设置、参数扫描）"加权投票得到 Top-K 失败轨迹，为当前运行提供经验参考以加速调整。

## 3. 实验设计

- **基准（Benchmark）**：作者提出 HALO-Bench，共 52 个任务，覆盖三大类：
  - **Lab-Derived（实验室派生）**：20 个已知可行参考配置的设计任务；
  - **Paper-Derived（论文派生）**：21 个基于已发表纳米光子器件描述改写出的独立设计目标；
  - **Open-Ended（开放式）**：11 个由论文派生任务放宽约束后得到、需探索式迭代的任务；
  - 任务物理机制横跨 7 个类别（GMR、BIC、平板带结构、可调单元、光栅、米散射、波前任务等）。
- **对比方法**：将三种规划器配置（固定结构化工作流、自主结构化智能体、自主代码智能体）应用于五个多代模型（Gemini 2.5 Flash、Gemini 2.5 Pro、Gemini 3.1 Pro Preview、Claude Haiku 4.5、Claude Sonnet 4.6 等），采用相同任务提示、相同的评估器生成协议并限定了外层迭代（≤5）和墙钟时间（1 小时）。
- **消融实验（轨迹记忆）**：额外挑选 16 个基线需要多次迭代才能成功的案例，对比三种条件：**无记忆**、**模式辅助 Top-3 失败轨迹检索**、**同任务 Top-1 失败轨迹控制**。

## 4. 资源与算力

- 行文说明，实验运行在 **单台配备 NVIDIA RTX 6000 GPU 的工作站** 上，并设置了每个案例约 1 小时的墙钟上限。除此之外，并没有详细报告用到的 GPU 数量、单任务计算时间、能源成本等更细粒度的算力信息。训练无涉及，纯推理/评估式实验。

## 5. 实验数量与充分性

- 在 52 个总体任务上对 3 种配置 × 5 个模型进行了闭环成功率与 token 开销的统计（大约 15 个 model-configuration 组合的行数据），另有：表 2 中的首次结构化设计正确率评估（80 个 prompt-schema 对/模型）；
- 16 例专门设计的失败轨迹复用对比实验；
- 基于各模型跨 5 个配置的失败模式聚合统计分析（100/133/115 个失败案例分类）。
- **充分性分析（偏积极）**：考虑到了任务语义差异的覆盖面，通过扰动数据评估模型"是否真的理解了要求"而非记住了原表面；对比结构较清晰（固定 vs 自主、结构化接口 vs 编码接口两个维度划分）且引入共享评估器来约束公平性。
- **潜在局限**：虽然是可控对比，但由于 token 的计量在各大提供商间不可完全对齐，作者也明确承认 token 效率对比更多在 family 内较为可靠；每个模型-配置-案例只跑一次，缺乏重复运行以评估方差；统一的"一次生成评估器脚本"仍可能引入一定随机性或可复现性问题。

## 6. 主要结论与发现

- **接口约束与效率**：在所有模型中，固定结构化工作流均总是取得**最高的每百万 token 成功数**（如 Claude Sonnet 4.6 下 2.327 对 0.474 与 0.604），并且 100 个失败案例中 **没有任何代码/路径级错误**；这主张"类型化显式接口为纳米光子学代理提供了更好的可靠性、审计性。
- **自主代码的双面性**：拥有较强模型（如 Claude Sonnet 4.6）使 autonomous coding 可达最高整体宏观成功率（79.8%），且能随 Gemini 模型由 Flash 升至 Pro 时明显改善（32%→68%），但相应要付出代码/工具/API、产物/路径类的故障（约 43.5% 失败），科学收敛并非零成本。
- **增加编排不等于更优**：自主结构化智能体并未在去掉固定流程后就全面超越固定流程；它反而引入"缺失/无效结果"和"错误装置/sweep设置"新失败类型且稳定性有限。
- **失败经验可复用**：在延迟成功任务中，检索 Top-3 失败轨迹把平均首次成功迭代从 2.44 降至 1.44，总 token 用量减少 64.3%，并发 10/16 个案例转化为首轮即成功；同任务 Top-1 失败控制会将 token 消耗降低一半，但提升幅度与文本+模式检索方法仍介于其区间。

## 7. 优点

1. **端到端闭环范式**：把 LLM 设计与数值电磁验证结合，突破了以往较多论文停留在"生成结构/优化、不做物理验证或弱审计"的墙；
2. **层级分明的实验设计**：以"自洽重定义+扰动增广"区分模型的真实结构与物理理解能力，而不是直接测记忆性；
3. **较强的可审计性**：具备结构化 schema、格式化轨迹记录与 diagnostics，具备科学透明性；
4. **可迁移性**：提出 failure-memory 检索这一实用机制，打开增量学习与经验重用的口子；
5. **覆盖面广的基准**：52 个任务包含多物理机理与来源，能一定意义上评估模型的泛化性。

## 8. 不足与局限

- **评估范围**：任务主要落在**周期纳米光子结构**（RCWA 可解）之上，尚未覆盖更广泛的电磁仿真方法（FDTD 等）或片上/非周期器件；
- **单次运行设计**：每个条件都只跑一次，未提供重复次数与方差，间接限制了结论的统计置信度；
- **公平性隐患**：即引入了共享评估器，但评估器本身同一模型负责生成 pass/fail，可能导致某种系统性倾向且人为审查只做了物理逻辑抽查；
- **记忆实验的定位**：其设计更侧重与自身 baseline 的收敛性对比，"跨任务可迁移性/真正泛化到新场景"未得到充分证明；
- **放大资源与精确性的冲突**：虽然代码自主在某些更强模型上效果好，但缺少更细的"根据故障类型自适应切换接口/模式"控制策略，在不同模型强度设置下横向指导仍模糊。

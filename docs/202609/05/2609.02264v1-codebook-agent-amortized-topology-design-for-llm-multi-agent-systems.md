## 摘要
根据每个查询自适应地调整LLM多智能体系统的通信拓扑，能够同时提高准确性和效率；但当前的设计方法把它当作条件图生成来处理：一个变分、自回归或扩散解码器在N×N邻接空间中搜索，由基于效用和结构成本（如边数）训练的图网络代理对采样得到的候选进行排序。我们认为，这种建模与问题并不真正一致。经验证据显示，即使码本容量从8增到64，通过了奖励筛选的拓扑仍只会收敛到大约六种不同的图；边数与实测的token消耗负相关（Pearson r ≈ -0.4），因此让图变稀疏反而会使推理成本上升；另外，当各个智能体共享相同的画像时（这是已发布基准的默认配置），在智能体画像节点上进行消息传递的评分器是邻接不变的，因而在这种情况下它根本无法对候选进行排序。这三点事实催生了码本智能体（Codebook Agent）：向量量化自编码器把成功拓扑压缩成一个与查询无关的16条目码本；奖励加权MLP把查询嵌入映射到码本上的分布；以及一个读取扁平化邻接矩阵、以实测效用和逐任务归一化token成本为回归目标的MLP代理，在单次批量前向传播中对解码出的靠前候选重新排序。由于测试阶段既不需要迭代搜索也不需要消息传递，码本智能体在我们比较的全部六个基准上都是最优方法（平均84.6，先前最强设计器为83.0），在2.4 ms内输出一个拓扑，并减少了21.9%–33.2%的LLM token消耗。

## Abstract
Adapting the communication topology of an LLM multi-agent system to each query improves both accuracy and efficiency, yet current designers treat this as conditional graph generation: a variational, autoregressive, or diffusion decoder searches the $N \times N$ adjacency space, and a graph-network proxy trained on utility and a structural cost such as edge count ranks the sampled candidates. We argue that this formulation is misaligned with the problem. Empirically, topologies that survive a reward filter collapse to about six distinct graphs even when the codebook capacity grows from 8 to 64; edge count is negatively correlated with measured token consumption (Pearson $r \approx -0.4$), so sparsifying the graph makes inference more expensive; and a message-passing scorer over agent-profile nodes is adjacency-invariant whenever agents share a profile---the default configuration of published benchmarks---so it cannot rank candidates at all in that regime. These three facts motivate Codebook Agent: a vector-quantized autoencoder compresses successful topologies into a query-independent 16-entry codebook; a reward-weighted MLP maps the query embedding to a distribution over codes; and an MLP proxy that reads the flattened adjacency, regressed on measured utility and per-task normalized token cost, reranks the top decoded candidates in a single batched forward pass. With no iterative search and no message passing at test time, Codebook Agent is the most accurate method on all six benchmarks we compare (84.6 average against 83.0 for the strongest prior designer), emits a topology in 2.4 ms, and uses 21.9--33.2% fewer LLM tokens.

## 1. 核心问题与研究动机

LLM 多智能体系统中，智能体之间如何通信（即通信拓扑）不仅决定"谁看到谁的消息"，还直接决定任务精度与 token 开销。现有工作已从手工设计固定拓扑发展到**查询条件化的拓扑生成器**：给定一条新的查询，系统会用变分、自回归或扩散解码器在 N×N 的邻接矩阵空间中进行搜索，再用一个基于消息传递的图网络代理对候选拓扑进行打分排序，打分目标通常包含效用和边数等结构性成本。这套"先生成、后打分"的流程看似合理，但本文用三个经验测量指出了它的问题：

1. **有效的设计空间本质上是一个短列表**：即使码本容量从 8 增长到 64，能通过奖励筛选的拓扑始终坍缩到约 6 种不同的图。
2. **结构性成本替代指标被用反了**：边数 |E| 与实测 token 消耗呈负相关（Pearson r≈−0.4），即图越稀疏，推理反而越费 token，所以"最小化边数"会最大化真正想降低的开销。
3. **消息传递评分器在默认配置下失效**：在已发布基准普遍默认的"同质团队"（智能体共享相同画像）中，基于画像节点的消息传递对邻接矩阵是**不变的**——所有候选都得到相同分数，排序根本不存在。

作者由此主张：问题本质不是"生成一个图"，而是**从少量可行拓扑中选出最优拓扑**，因此最优设计器不应是另一个生成式解码器。据此提出 Codebook Agent：测试时无迭代搜索、无消息传递，仅靠一次前向传播完成拓扑选取。

## 2. 方法论

Codebook Agent 是一整套三阶段训练、一次前向推理的摊销式设计流程，核心思想是：**离线把"能解决任务的拓扑"压缩成一个小型离散码本；在线根据查询嵌入预测码本分布；再通过一个执行接地（execution-grounded）的 MLP 代理对解码出的 Top-M 候选做一次批量重排**。整体框架如图 2 所示，分为以下几个核心组件：

### 2.1 数据收集与奖励定义

- 每个基准用 50 个训练任务 ×6 种固定拓扑（complete、chain、star 及三种 Erdos-Renyi 采样）执行真实 LLM 智能体，得到 300 条执行记录 D = {(A, c, u, τ)}。
- 定义奖励 R = u − λτ̃，其中 λ=0.1；τ̃ 是该任务 token 数除以同任务平均 token 数（逐任务归一化），用来消除任务难度差异。作者特别强调要用"实测 token"而非边数，因为边数与实测 token 负相关。

### 2.2 拓扑码本（向量量化自编码器 VQ-VAE）

- 把邻接矩阵去掉对角线后展平为 a=vec(A)，送入编码器 Encψ 得低维表示 zₑ∈ℝ³²。
- 在大小为 K=16 的码本 {e₁,…,e_K} 中找到最近的码 e_k⋆，用 EMA（衰减 0.99）更新码本，承诺系数 β=0.25，采用直通估计器，并用死码重置保证码本利用。
- 解码器将选定码 zq= e_k⋆ 映射回边 logits，经 sigmoid 二值化得到拓扑 A(k)。
- VQ-VAE 只在 u>0.5 的成功记录上训练，**不依赖查询**；所有查询条件的信息由后续的"码本预测器"来承担。

### 2.3 奖励加权码本预测

- 将每个训练记录通过冻结的编码器得到其码索引 kⱼ。
- 对每条训练查询 c，构造软目标 yₖ(c)：对落在同一码内的记录按 exp(γRⱼ)（γ=2）加权归一化；奖励越高的码权重越大。
- 用 MLP（d→256→256→K，含 dropout）做"查询嵌入→码本分布"的映射，用软交叉熵训练。这是查询信息进入生成过程的唯一位置。

### 2.4 执行接地 MLP 代理

- **为什么不能用 GNN**：同质团队中每个智能体画像相同 x₁=…=x_N=x，消息传递聚合的是相同特征，因此得分与邻接矩阵 A 无关。
- **怎么做**：代理 f_φ 是一个 MLP，输入为展平的邻接向量拼接查询嵌入 c，输出 (û, ĉ) 两个标量，分别回归实测效用 u 和归一化 token 成本 τ̃。
- 由于 300 条执行记录对拓扑空间的覆盖很稀疏，额外引入源自 VQGraph 的**结构 token 正则头**（辅助目标，仅训练时用）：先在一个扩充的拓扑池 A+ 上用另一个 K_tok=32 的码本做只重建的量化，再让代理的辅助头预测软码分配。奖励监督仍只来自真实执行记录。

### 2.5 测试时推理

1. 查询 c 经 MLP 预测器得到码分布，取 Top-M=5 个码；
2. 解码出对应拓扑并去重；
3. 对幸存候选做**一次批量** MLP 代理前向，按 â⋆=argmax(û−λĉ) 选出最终拓扑。
- 整个流程是固定次数的矩阵乘法：一次预测器前向、至多 M 次解码器前向、一次批量代理评分。**没有采样循环、没有稀疏图构造、没有消息传递、没有 LLM 调用**。

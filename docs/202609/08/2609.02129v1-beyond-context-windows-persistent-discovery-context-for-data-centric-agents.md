## 摘要
数据智能体在规划或执行之前，会重复执行一个发现步骤：识别与任务相关的数据对象。然而，成功的发现结果通常被丢弃而非复用。我们引入了持久发现上下文，这是一种轻量级记忆层，用于存储先前的意图到对象的映射，并在未来检索中复用这些映射。在三个结构化数据环境中，持久发现上下文始终优于仅基于元数据的搜索，在自动生成的记忆下仍然有效，并揭示了一种可复现的干扰失效模式。在词汇稀疏的领域中，仅基于记忆的检索甚至可能超越基于元数据的检索。这些发现表明，发现结果构成了一种对数据智能体而言可复用的有用上下文形式。

## Abstract
Data-centric agents repeatedly perform a discovery step before planning or execution: identifying the data objects relevant to a task. Yet successful discovery outcomes are typically discarded rather than reused. We introduce persistent discovery context, a lightweight memory layer that stores prior intent-to-object mappings and reuses them to augment future retrieval. Across three structured data environments, persistent discovery context consistently improves retrieval quality over metadata-only search, remains effective with automatically generated memories, and exposes a reproducible interference failure mode. In lexically sparse domains, memory-only retrieval can even outperform metadata-based retrieval. These findings suggest that discovery outcomes constitute a useful form of reusable context for data-centric agents.

### 1. 核心问题与整体含义

论文关注的是数据为中心智能体（data-centric agents）在规划或执行前必须完成的**数据发现（discovery）**步骤，即从数据目录（如数据库表、属性）中识别与用户任务（自然语言查询）相关的数据对象。关键问题是：

- 现有智能体记忆系统主要缓存对话、观察、技能或工作流，但**数据发现的结果并未被保留复用**——每个查询都像第一次一样从头进行检索。
- 论文首次提出：成功发现的结果（task intent → relevant objects 的映射）本质上是一种**可复用的经验上下文**。如果能将这种发现结果以轻量级记忆的形式跨任务保留，就能改善未来任务的检索质量，避免重复劳动，并可提升下游规划能力。

一句话概括：**论文探讨“先发现的成功检索如何被受益于下一次检索”，将检索历史持久化为记忆，并证明了其价值。**

### 2. 提出的方法论

**核心思想**：引入一个轻量级的记忆层，称为**持久发现上下文（Persistent Discovery Context, PDC）**，该记忆层记录历史意图（intent）与被证明为相关的数据对象（objects）组成的二元组/映射，并在新查询到来时，通过检索出前 K 个与任务意图相似的历史发现记忆来修改相关性评分。

**关键技术细节**：

- **记忆格式**：一条 discovery memory 为 `m = ⟨intent, objects⟩`，其中 intent 为一个自然语言任务描述，objects 为此任务相关（被选中）的表/属性数据集，记忆在数据环境/注册表层级被持久化积累。
- **数据对象检索基础**：对于一个候选对象 `oi`，假定一个基础检索器（Registry/Baseline search，如 TF-IDF 或神经网络编码器）产生了一个 `r(q, oi)` 的底分。
- **记忆增强表达式**（公式 1）：
  `score(q, oi) = r(q, oi) + α ∑_{m ∈ top-Km} sim(q, m.intent) · 1[oi ∈ m.objects]`
  - `m` 遍历与查询 q 最相似的历史发现记忆（top-Km 条），记忆相似度使用和注册表检索器相同的检索模型；
  - `sim(q, m.intent)` 为查询与记忆意图语义的相似度；
  - `1[oi ∈ m.objects]` 为指示函数，若候选对象出现在记忆的相关对象集合中则取 1；
  - `α` 控制记忆对排序的加权影响（α=0 退化为纯注册表检索，令 r=0 则变成只靠记忆排序的 M2/Ranker）。
- **变体设置**：论文同时考虑了用 TF-IDF 做词汇式匹配，以及使用 all-MiniLM-L6-v2 句嵌入做神经检索；也考察了直接对记忆对象“暴力注入排序”（S4）与加权混合检索（S3）的对比；以及用大语言模型（Claude Haiku）自动生成记忆做初始化。

### 3. 实验设计

**数据集 / 场景（真实世界结构化表数据）**：共三个结构化域。

| 域 | 数据对象规模 | 特色 |
|---|---|---|
| Finance（PKDD’99 银行数据集） | 6张表 / 42 个属性 | 账户、交易、贷款 |
| NYC Collisions（纽约机动车事故数据集） | 3张表 / 41 个属性 | 撞击、车辆、人三方记录 |
| Northwind（微软示例贸易公司数据） | 8张表 / 43个属性 | 客户、订单、员工等 |

**Benchmark 构建**：
- 每个域均人工构建数据对象注册表及自然语言元数据描述；
- 每个域 5 个任务族（task family），共有 15 任务族（每族内共享同一组相关数据对象，但查询语料措辞不同）；
- 每族设 1 个 seed 任务（初始化发现记忆）+ 5~12 个 held-out 评估任务；
- 整个 benchmark 共 140 个任务，其中 125 个是模型未见过的待评估任务；
- 另外构造了 3 个干扰（interference）任务用于对照分析；
- 每个任务人工标注 3~5 个 ground-truth 对象。

**对比方法**：
- **S0**：Raw Metadata——仅检索对象名称字符串；
- **S1**：Registry——检索对象名称 + 对象元数据描述（baseline 检索器）；
- **S2**：Memory-only——仅依靠发现记忆对候选对象进行排序；
- **S3**：Registry + Memory——S1 + 记忆加权（本文主推方案）；
- 增强验证：比较 BM25 与 TF-IDF 检索器，以及上述 S1/S2/S3 的神经嵌入版（S*标注）。
- **S4**：Naive Injection——将最高得分记忆所关联的所有对象“顶到最前”，替代 S3 的软加权融合（附件的对照实验）；
- **Leave-One-Out (LOO) 种子轮换**：验证 seed 任务挑选的稳健性。

### 6. 主要结论与发现

每个结构域的总体提升表现如下：

**核心发现 1**：持久发现上下文 S3（Registry+Memory）在所有三个域中均能提高 F1@5。以 TF-IDF 为基线（S1→S3）成绩提升：Finance 从 0.396→0.499，NYC 从 0.299→0.482，Northwind 从 0.446→0.528。

**核心发现 2**：在词汇稀疏域，仅靠记忆（S2）就能压倒仅元数据搜索：在 NYC 表中，S2 F1@5=0.412 显著高于 S1’s 的 0.299。这表示在“复合型且词面遮掩严重”的属性名（如 contributing factor vehicle 1）背景下，记忆反而比元数据标识更强的潜在语义信号。

**核心发现 3**：在部分极端领域中仅靠记忆就能获得最优结果，但统一将二者结合（S3）永远是稳定的选择，不会出现过度依赖记忆造成的显著损失。

**核心发现 4**：LLM 自动生成记忆（对象级 F1 在 0.698~0.762 之间）后，仍然在 Finance 与 NYC 超过 S1 基线及 S0 基线，验证了不完全记忆下方案的鲁棒性。

**负数结果（干扰失效）**：存在一种“跨家族干扰”的情况——如果查到了语义相似但错误的记忆，其检索结果（F1@5）会降到无记忆的水平之下，例如：
- Finance 的"withdrawal"触发了另一族的 “transaction” 记忆，S3（错）=0.222 < S1=0.444；
- NYC 的"vehicle type"触发了车辆档案而非事故伤害背景记忆，S3（错）=0.200 < S1=0.400；
- Northwind 多条 order 类术语使 S3（错）=0 < S1=0.444。
这说明单靠表层词覆盖的记忆选择不具鲁棒性，记忆的激活必须受语义上下文和限制机制管控。

**其它结论**：
- 最优权重与检索器强弱相关，TF-IDF 在 α=0.25 达到最优，神经检索器提升空间较小（因基础检索质量已高）。
- S3 软融合要明显优于 S4 硬注出，直接强制置顶易造成错配噪声。
- 动态记忆比只做字段描述检索更能在短期“经验迁移”中发挥长效作用，且可通过 LOO 说明结论并非由单一 seed 偶然驱动。

### 7. 优点

- **面向真实场景、切入新颖**：把“任务发现结果”这一不经意间被丢弃的副产物做成 registry 层的显式持久记忆，轻量、无需预训练修改，有很强的现实可行性。
- 理论模型简洁可表达：式(1)是一个与 Rocchio 相关性反馈类似但针对 agent 级对象集合检索的更优雅的范式过渡，通过单一系数 α 即可从检索降级为纯记忆/纯背景检索；
- 多方法论交叉验证：结合 TF-IDF 与神经检索（all-MiniLM-L6-v2），兼顾词法与语义；BM25 对照在附件中保证了词汇检索指标探索的完备性；
- 严谨的纵向维度控制：固定 registry 描述一致、任务族保持一致相关性对象但更换措辞，从而可控地测出跨词汇的泛化；
- 诚实披露局限，尤其在“干扰 / 失效模式/ 部分任务族负增益”上做了反证实验，大大提升结论客观性；
- 鲁棒性验证（Leave-One-Out seed、α 消融、LLM 自动记忆）最大化控制了人工初始化诱偏效应。

### 8. 不足与局限

- **实验规模偏小**：3 个域、每个域 5 个家族、仅 125+ 个 held-out 任务规模有限，无法取代大规模高难度多源与复杂数据库测试中的统计效力；
- **仅有发现检索层验证**：没有对下游任务中的 SQL / 多步规划生成端到端评测（仅提供了一个演示性叙述），因此记忆增益在真正执行中的真实漏斗收益不明；
- **硬件算力不透明**：未提供运行时间、API 调用量、显存开销或推理成本，不利于工业落地对大体积记忆的评估；
- **记忆更新的生命周期**：只考虑“种子一次性初始化”或静态记忆，未考虑在线日志化动态添加、去重、过期衰减和冲突协商机制；
- **干扰风险与记忆选择脆弱性**：论文已承认同词族不同含义的任务会造成显著负迁移，当前没有在记忆中内置意图上下文筛选能力强的方法；并且部分任务家族（如 Customer demographics、Regional economics）出现了记忆导致的负增益；
- **基准的元数据质量较高**：每个对象有人工精写的高质量描述，这使得环境对真实无维护数据库的相对效果失真，此外没有研究记忆文件规模的扩展性能和冷启动处理；
- 对于 neural 检索，所使用的基线仅是一个小型的 MiniLM 嵌入模型，没有以更强指令微调模型检验与 memory 交互作用。

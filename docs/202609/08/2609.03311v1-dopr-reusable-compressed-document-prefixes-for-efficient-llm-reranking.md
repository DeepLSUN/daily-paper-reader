## 摘要
大型语言模型（LLMs）是有效的重排序器，但逐点重排序在不同的查询中重复处理同一文档，导致大量的冗余文档侧计算。我们提出DoPR，一个压缩文档前缀框架，将离线文档处理与在线重排序解耦。DoPR首先选择与查询无关的文档表示，并将其转换为压缩的文档前缀状态，这些状态离线预计算，并在文档被检索时重用。在在线重排序期间，模型仅通过处理查询和评分词元来对每个查询-文档对进行评分，文档信息由存储的前缀状态提供。这种设计通过文档侧压缩和跨查询前缀状态重用，降低了在线成本。在TREC DL、BEIR和BRIGHT上，使用从0.6B到8B的Qwen3模型进行的实验表明，DoPR实现了高达8.0倍的在线文档侧内存减少和高达8.04倍的延迟加速，同时保留了匹配的全文档重排序器平均NDCG@10的97.1%-99.5%。

## Abstract
Large language models (LLMs) are effective rerankers, but pointwise reranking repeatedly processes the same document across different queries, causing substantial redundant document-side computation. We propose \textbf{DoPR}, a compressed document prefix framework that decouples offline document processing from online reranking. DoPR first selects query-independent document representations and converts them into compressed document prefix states, which are precomputed offline and reused whenever the document is retrieved. During online reranking, the model scores each query-document pair by processing only the query and scoring token, with document information supplied by the stored prefix states. This design reduces online cost through both document-side compression and cross-query prefix-state reuse. Experiments on TREC DL, BEIR, and BRIGHT with Qwen3 models from $0.6$B to $8$B show that DoPR achieves up to 8.0$\times$ online document-side memory reduction and up to 8.04$\times$ latency speedup, while retaining \textbf{97.1\%-99.5\%} of the average NDCG@10 of matched full-document rerankers.

## 一、核心问题与整体含义（研究动机与背景）

- **研究背景**：大语言模型（LLM）作为重排序器效果显著，尤其**点式（pointwise）重排序**范式因易于并行化、批处理和集成到现有检索管线中而被广泛采用。
- **核心痛点**：在真实检索系统中，**同一文档往往会被大量不同查询反复检索**，而标准点式重排序器对每个"查询-文档"对都会重新编码完整文档，导致**大量冗余的文档侧计算**，成为在线部署LLM重排序器时延迟和内存压力的主要瓶颈。
- **既有方法不足**：
  - 提示压缩/词元剪枝等方法主要降低单次推理实例的输入长度，但压缩结果通常与特定查询绑定，**同一文档配对不同查询时仍需重复处理**。
  - 预计算文档侧表示的工作（如ColBERT、SDR等）虽实现了文档侧复用，但通常面向检索阶段匹配或专用交互函数，**未解决点式LLM重排序内部的计算复用问题**。
- **研究问题**：文档侧计算能否在点式LLM重排序内部实现跨查询复用？
- **回答**：提出了 **DoPR** 框架，通过**离线/在线解耦**和**压缩文档前缀状态的跨查询复用**，大幅降低在线重排序成本。

## 二、方法论（核心思想与关键技术细节）

### 1. 整体框架
DoPR 包含三个核心阶段：
- **训练阶段**：端到端训练文档表示选择与相关性打分的统一框架。
- **离线压缩阶段**：预先处理整个文档集合，生成压缩文档前缀状态并存储。
- **在线重排序阶段**：注入存储的前缀状态，仅处理查询和评分词元。

### 2. 核心符号与公式
- 传统点式重排序：`score = f([query; document])`，需在线处理全部文档。
- DoPR 的文档侧处理：选定一组与查询无关的压缩表示 `Cd = {c1, ..., cK}`，将其作为前缀输入得到多层键值状态（即压缩文档前缀状态）并存储复用。
- 训练中通过**结构化注意力掩码**强制"文档→查询"信息只能经由选定的少数文档表示，使瓶颈表示承载排序相关信息。

### 3. 关键技术细节

**（a）基于注意力的关键词元选择**
- 对文档进行独立编码后，利用最终层多头自注意力矩阵的**注意力集中度**作为显著性信号。
- 对每个文档词元，计算其被上下文强关注的平均注意力权重作为显著性得分，选出 Top-K 个词元的隐状态作为压缩文档表示。
- 该方法**无需引入额外的可训练选择器**，轻量高效。

**（b）结构化注意力掩码**
- 训练输入为 `[document; Cd; query; score_token]`。
- 原始文档词元被独立编码；查询和评分词元**只能通过 Cd 访问文档信息**，为训练与部署之间建立一致的信息瓶颈。

**（c）训练目标**
- 使用**配对 RankNet 损失**进行优化：
  - `P(d+ > d- | q) = sigmoid(s(q,d+) - s(q,d-))`
  - `L = log(1 + exp(-(s(q,d+) - s(q,d-))))`
- 梯度经由评分词元、查询-表示交互和选定文档表示回传，使压缩表示**针对排序目标而非通用重建**进行优化。

**（d）可分离的训练与推理预算**
- 训练前缀预算 `Ktrain` 与推理前缀预算 `Kinfer` 可分别设置，允许部署时在不重新训练的情况下进行质量-效率权衡。

**（e）在线重排序**
- 推理时检索每个候选文档的压缩前缀状态作为预填充KV缓存，在线仅处理 `[query; score_token]`，显著降低需在线计算的文档侧输入规模。

1. **质量保持**：在 TREC DL 和 BEIR 上的平均 NDCG@10 保留率为 97.1%（0.6B）、99.3%（4B）、99.5%（8B）；BRIGHT 上为 98.6%～99.1%，证明压缩前缀能保留绝大多数排序相关信息。

4. **模型规模效应**：更大规模的骨干网络能更好地容忍前缀瓶颈带来的信息损失。
5. **推理预算灵活性**：`Kinfer` 可在不改训前提下独立调节，实现质量-效率帕累托调控。
6. **跨架构通用性**：在 Qwen3 和 Llama-3.2 两种只解码器模型族上均表现良好。
7. **方法适应性**：最佳设置（默认 `Ktrain=32` + 200 步 warmup + 注意力 Top-K 文档选择 + 8.0× 压缩率）在多项消融中取得最优或接近最优的综合结果。

## 七、方法亮点

1. **训练-部署瓶颈对齐**：结构化掩码让模型在训练时就习惯仅凭少量文档表示完成排序，而非部署时才截断，显著缓解了"截断-再训练"间的分布漂移问题。
2. **端到端优化压缩表示**：文档选择的优化目标始终指向排序质量而非重构或语言建模，压缩表示高度针对排序任务本身。
3. **训练/推理预算解耦**：为部署环境的实际延迟/质量要求带来实时权衡调整的灵活性。
4. **早期预热即压缩自由训练**：先让骨干恢复稳定打分能力再激活瓶颈，缓解训练不稳定且提升效果。
5. **查询无关压缩 + 离线前缀构建**：充分利用稳定文档集合中跨查询复用的条件，把重复计算移到离线，效率收益可叠加。
6. **较全面的消融设计与跨模型族验证**：对压缩预算、预热步数、文档选择策略、KV 存储方式及模型类型均有系统性覆盖，结论可信度较高。

## 八、不足与局限

1. **适用条件存在限制**：DoPR 的优势在文档被跨查询复用时才最大化；若文档集合快速变化或文档很少被反复检索，离线构建和存储开销可能占据主导，收益有限。
2. **离线端额外开销与工程取舍**：大规模部署需对集合做全量预处理并存储压缩前缀状态，增加索引与存储开销；论文虽承认此点但未给出具体的存储开销量化指标与工业化对比。
3. **小模型效果退化明显**：0.6B 在 Touche（91.9%）、Robust（93.8%）上有较大性能回落，说明小模型对固定前缀预算的信息损失更敏感，压缩与质量保持之间的平衡较难把握。
4. **推理密集型任务上的方法稳定性有待进一步改进**：在部分 BRIGHT 子集（如 Biology LC 等）上退化幅度较大，且保留率随规模变化不呈单调规律。
5. **对照基线不充分**：缺少与压缩提示类方法（如 Gist tokens）和 LLMLingua 类方案的直接对比；也未见与 listwise 重排序延迟的直接比较（论文以"不可直接比较"为由排除，但可考虑标准化协议后再比）。
6. **统计显著性不足**：部分数据集上的差异很小（±1%以内），未说明实验的重复次数与方差；也未对不同方法间的差异做显著性检验。
7. **真实场景验证缺失**：未见真实生产流量/日志（真实文档重用分布、延迟分布等）下的部署验证，经验性的可复用效果仍止步于受控实验与模拟。

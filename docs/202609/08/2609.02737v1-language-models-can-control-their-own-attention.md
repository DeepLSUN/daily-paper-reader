## 摘要
语言模型将大部分注意力集中在上下文的很小一部分上，然而它们却读取整个KV缓存以找到少数关键标记。如果用户在一个百万级标记的对话中询问之前的某个细节，全局注意力层在生成回复的每个标记时都必须扫描完整上下文。一种主流方法通过轻量级代理分数预选相关标记来缓解这一成本，但这种外部评分仍然每步需要O(N)的复杂度。我们采用一种内在方法，其动机源于一个简单的问题：模型本身难道不知道上下文的哪些部分是相关的吗？为此，我们引入了声明式注意力（DA），这是一种协议，通过在思维链中引导模型声明其需要关注的位置，将生成过程分为三种模式：<global>（完整上下文）、<focus>（特定区域）和<local>（仅最近输出）。推理引擎像解析工具调用一样解析这些声明，并跳过大部分KV缓存读取。在跨15个长上下文任务的零样本评估中，DA在现成模型（Gemma-4-31B、Qwen-3.6-27B）上显著减少了解码期间的总关注标记数（52.0%、31.1%），同时准确率下降幅度较小（1.27个百分点、2.75个百分点），且随模型规模增大而缩小。DA开启了稀疏注意力的新维度，并在基于训练的方法下具有进一步潜力，未来工作可对此进行探索。

## Abstract
Language models spend most of their attention on a small fraction of context, yet they read the entire KV cache to find the few tokens that matter. If the user asks about a previous detail in a 1M-token conversation, global attention layers must scan the full context to generate each token of the reply. A prominent approach mitigates this cost by pre-selecting relevant tokens via lightweight proxy scores, but this extrinsic scoring still incurs O(N) per step. We take an intrinsic approach motivated by the simple question: wouldn't the model already know which parts of the context are relevant? To this end, we introduce Declarative Attention (DA), a protocol that elicits the model to declare where it needs to attend within its chain-of-thought, partitioning generation into three modes: <global> (full context), <focus> (a specific region), and <local> (recent output only). The inference engine parses these declarations like tool calls and skips most of the KV cache read. Under zero-shot evaluation across 15 long-context tasks, DA on off-the-shelf models (Gemma-4-31B, Qwen-3.6-27B) significantly reduces total attended tokens during decoding (52.0%, 31.1%) with modest accuracy drops (1.27pp, 2.75pp) that shrink with model scale. DA unlocks a new axis of sparse attention, with further potential under training-based methods that future work can explore.

### 研究动机与背景
- **长上下文推理的高昂成本**：Transformer 在解码时，每一步都要对全部KV缓存进行注意力计算。大型模型的 KV 缓存可达数 GB 至数十 GB，即便只生成一个 token，也需要读取全量 KV 缓存，内存带宽占用巨大，成为长上下文解码的主要瓶颈。
- **注意力稀疏性 vs 动态未知性**：大量实证表明注意力往往集中在上下文的一小部分 token 上，但真正重要的 token 随着每一步动态变化，无法预先确定。
- **既有稀疏注意力方法的局限**：
  - 静态规则（如基于位置/历史注意力）难以预测未来查询需要的内容，会导致长上下文性能退化。
  - 动态“外部打分”方法（如轻量级代理扫描）虽然缩小了常数因子，但每步复杂度仍是 O(N)，并引入了额外的选择开销，不算真正消除全量读取。

### 论文的整体含义
- 论文提出一个根本性的转变——模型自身其实“知道”自己需要关注哪些位置，只是尚未被显式激发。通过一个**任务无关的、零样本的协议**，让模型将自己的注意力选择作为文本输出（“声明”出来），推理引擎像解析工具调用那样读取这些声明，并据此构建稀疏注意力掩码。这把稀疏注意力的选择从“外部推断”变为“模型自述”，开辟了无需每步 O(N) 扫描的稀疏注意力新维度。

## 二、方法论：Declarative Attention (DA)

### 核心思想
- 模型在生成回复时，将思维链组织为多个连续的**注意力阶段**，在每个阶段显式声明其注意力范围。
- 推理引擎（DA 状态机）跟随模型输出流解析声明，动态构建注意力掩码，只加载被声明的 KV 缓存块，从而跳过大部分上下文的读取。

### 三种注意力模式
| 模式 | 语法 | 可见范围内 | 用途 |
|---|---|---|---|
| Global | `<global>`…`</global>` | 全部 magic chunks | 全局定位/导航，确定下一步要关注哪个段落 |
| Focus | `<focus magic_chunks="K">`…`</focus>` | 仅指定的一个或多个 magic chunk | 从特定区域提取关键值 |
| Local | `<local>`…`</local>` | 仅模型已生成内容（不含上下文） | 基于已提取的信息进行推理/规划/综合答案 |

- 在任何模式下，模型的 system prompt、输入问题、指令部分、已生成的回复都保持可见；变化的只是上下文内部各段落的可见性。
- 模型可自由、反复地切换模式，论文不加任何限制。

### 上下文分段与格式化（Context Delivery）
- **分段（segmentation）**：将长上下文切分为约 2048 token 一个的“magic chunks”。分割时优先选择更自然的语义边界——优先在段落之间、次之换行、句号、逗号等，绝不打断单词，保证无损重建。
- **格式化（formatting）**：模拟工具调用对话。每个 magic chunk 被包装成“助手调用 get_magic_chunk 工具→工具返回结果”的形式，建模后看到的就是消息边界清晰的工具调用界面，充分利用了模型在训练中常见的工具/对话边界识别能力。实际并无工具执行，所有段落从一开始就在 prompt 里。

### 解码时干预机制（Decode-time Interventions）
- **DA 状态机**：随输出流解析标签切换。默认处于 global 模式；遇到 `<focus>`/`<local>` 标签进入对应的受限模式；遇到闭合标签恢复 global。
- **Block-aligned 掩码构建**：在 vLLM 的 KV 缓存块表粒度上做掩码。将 per-token 掩码向外扩展到整块边界，保证不丢失模型声明的任何 token，同时保留现有 FlashAttention 等内核不改动即可运行。
- **vLLM 集成**：通过钩住 attention metadata builder 来重写请求的 KV-cache block table，无需修改内核或调度器，直接实现高效的块稀疏读取。
- **作用范围**：只作用于全局注意力层；滑动窗口注意力层和 Gated DeltaNet 等线性注意力层已有固定窗口/固定状态成本，DA 不触碰。

### 成本权衡
- 论文在框架层面清楚指出：DA 是一种“用更多解码步数换取更低每步注意力成本”的协议。当硬件利用率高、批处理大、上下文长时，注意力成本占主导，这种交易是净收益。

## 三、实验设计

### 评测基准与数据集（15 个长上下文任务来源）
- 来源于 RULER、LongBench v1、LongBench v2、LooGLE、ZeroSCROLLS：

- 每个来源最多取 128 个样本（固定随机种子）；过滤超过 244K token 的样本（Gemma-4-E4B 为 116K）。

### 评测模型
- 主对比：Gemma-4-31B 和 Qwen-3.6-27B。
- 规模效应分析：同系列还涵盖 Gemma-4-12B、Gemma-4-E4B、Qwen-3.5-9B、Qwen-3.5-4B。

### 对比方法与基准
1. **Vanilla**：原始上下文内联 + 标准指令，完整因果注意力。
2. **DA-no-mask (DA nm)**：使用完整的 DA prompt 模板（分段 + 三模式指令），但保留完整因果注意力。用来分离“分块格式”与“注意力掩码”两个不同变量的贡献。
3. **DA**：完整协议 + 基于声明构建的动态注意力掩码。

### 评测方式
- 自由生成结果不适用精确文本匹配，采用 LLM (Qwen-3.5-4B) 作为 judge，使用 Gemini-3-Flash 生成严格判定标准；
- judge 与 Gemini-3.1-Pro 在 2993 条样本上评判一致率 98.53%，Pearson r = 0.992；
- 评价指标：Accuracy（正确率）与 Attended Tokens（解码期间累计被关注的 KV 位置数）；另用 roofline 估计墙钟解码时间。

## 六、论文的主要结论与发现

1. **效率显著提升**：
   - Gemma-4-31B：平均累计 attended tokens 下降 **52.0%**（13.43M→6.45M）。
   - Qwen-3.6-27B：下降 **31.1%**（22.54M→15.52M）。
   - 掩码机制本身（对比 DA nm ）削减了 71.1%（Gemma）和 46.5%（Qwen）的 attended tokens，证实效率几乎完全来自注意力掩码而非 prompt 格式。
2. **准确率损失较小**：
   - Gemma-4-31B 平均下降 1.27pp（87.01%→85.74%）；
   - Qwen-3.6-27B 平均下降 2.75pp（85.31%→82.56%）；
   - 在部分任务上 DA 甚至略优于 vanilla（如 longdep_qa +3.1pp，code_repo +5.6pp）。
3. **模型规模收益**：DA 相对准确率随模型规模增加而收敛于 vanilla（Gemma 家族 29%→99%，Qwen 家族 64%→97%），说明 DA 正比于基础模型能力。
4. **上下文长度收益**：绝对 token 节省随上下文长度急剧增大（最长桶平均单回复节省约 21M tokens），相对节省率大致恒定（约 50%）。
5. **模式效率分析**：Gemma-4-31B 上和 local 模式占生成 token 的约 73%，而 focus 与 local 每 token 可节省 76–99% 的注意力读取。
6. **预计解码墙钟时间**：在 roofline 估算中，DA 将解码墙钟成本降低至 vanilla 的 **0.71×**（Gemma-4-31B）和 **0.77×**（Qwen-3.6-27B），主要因为全局注意力 KV 读取在 vanilla 下占解码时间 73%–86%。
7. **零样本的低估性质**：论文认为这是“地板”而非“天花板”。未来经后训练（SFT/RLVR）优化 DA 协议本身，收益有显著提升空间。

## 七、优点与亮点

1. **概念创新性强**：将注意力选择从隐式计算转移到显式文本声明，“模型用语言控制自己的注意力”，是稀疏注意力方向上的一个新轴。
2. **完全零样本适用**：无需微调、无需训练、无需任务专属适配，只用一套固定的任务无关 prompt 和通用的上下文分段方案即可工作，具备很强的即插即用性。
3. **选择开销低**：解析 focus 声明是 O(1)，替代现有 DSA-style 方法每步 O(N) 的索引扫描。
4. **实验设计严谨**：三重对照（vanilla / DA nm / DA）是非常干净的消融设计，有效区分了 prompt 格式的副作用与注意力掩码的因果关系。
5. **可解释性强**：注意力计划以人类可读文本形式呈现。系统可以“审计”模型的注意力选择；KV cache offloading 也能以声明为预取信号。
6. **机制层分析充分**：覆盖了模式分布、长度分桶、协议遵守率、每 token 注意力节省率、失败案例的结构性归因等深层分析，不是只报一个端到端结果。
7. **工程细节完整**：block-aligned 掩码构建、与 vLLM 的注意力 metadata hook 集成、对混合架构（SWA/GDN）中不同层的差异化处理，都给出了具体可行的实现路径。

## 八、不足与局限

1. **零样本行为的次优性**：
   - DA 在零样本下比 vanilla 多约 15–35% 的解码步数，是额外的延迟/算力开销；
   - 每个模型对 global/focus/local 模式的使用分布是模型零样本习性的产物，未必符合任务结构的最优解。
2. **仅限“非思考模式”**：
   - 初步实验表明模型在 thinking tags 内无法遵循 DA 协议，因此所有实验都关闭了思考模式。对推理型模型，这一限制意味着当前结果无法直接迁移到推理流程最长的大部分场景。
3. **人工分段的局限**：
   - 静态长上下文基准只能把文档切成人造 chunk。这些 2K-token chunks 的边界并不等于真实的语义边界/工具调用边界；agentic 场景中自然形成的用户轮次、工具结果等可能是 DA 更合适的原生载体（论文也承认但实验未覆盖）。
4. **已识别的失败任务**（约占测试集的一部分）：有些任务答案所需的全局信息在分段后被破坏（如全文计数、表格分裂），有的任务输出长度需要跟随全文增长（如逐段总结/排序）。这类任务 DA 不保留准确率或无法降低 attended tokens，但它们被明确排除在主结果平均之外，可能掩盖 DA 在更宽任务分布上的真实鲁棒性边界。
5. **评测规模限制**：
   - 主实验仅两个 30B 级模型 × 每个来源 ≤128 样本；
   - 上下文有效上限 244K，不能直接回答 1M-token 场景的行为；
   - 未涉及更大规模的（如数百 B 参数级别的）前沿生产模型；
6. **墙钟时间估算的局限性**：roofline wall-time 是理论估计而非实测数据，在单 B200/MFU 40%/MBU 70% 的假设参数下推导；论文也承认未建模块对齐边际 token 开销和预填阶段，更实际场景的收益可能偏离理论值。
7. **关注集中于解码阶段**：DA 只优化 decode 阶段的 KV 缓存读取；agentic 系统或长输入场景中 prefill 的成本仍不在优化范围内。而且它对已经使用“轻量索引/稀疏设计”的现代先进架构（如 DeepSeek-V4 等）的增量收益仍需进一步推敲。

## 摘要
在特定领域设置中，基于RDF图的知识图谱问答(KGQA)仍然具有挑战性，因为正式本体和精选的文本-SPARQL配对往往不可用。我们提出了KGVoyager，一种与知识图谱无关的智能体架构，通过动态探索图结构和语义，从自然语言问题生成SPARQL查询，仅需底层图的查询端点。利用思维-行动-观察循环及搜索、探索和执行工具，KGVoyager将术语映射到图IRI，发现结构，并通过执行反馈优化查询——全程无需预先存在的本体或示例。与先前的最新技术不同，KGVoyager仅需轻量级类索引，使其适用于更多真实世界的端点。在四个基准测试中，KGVoyager将F1分数提高了约8个百分点，同时将成本和运行时间各削减约22%。

## Abstract
Knowledge Graph Question Answering (KGQA) over RDF graphs remains challenging in domain-specific settings, where formal ontologies and curated text-SPARQL pairs are often unavailable. We present KGVoyager, a KG-agnostic agentic architecture that generates SPARQL queries from natural language questions by dynamically discovering graph structure and semantics, requiring only a query endpoint of the underlying graph. Using a think-act-observe loop with search, exploration, and execution tools, KGVoyager maps terms to graph IRIs, uncovers structure, and refines queries through execution feedback - all without pre-existing ontologies or examples. Unlike the prior state of the art, KGVoyager requires only a lightweight class index which renders it applicable for far more real-world endpoints. Across four benchmarks, KGVoyager improves F1 by ~8 points while cutting cost and runtime by ~22% each.

## 方法论

**核心思想**

- KGVoyager 将 SPARQL 生成建模为 **“思考-行动-观察”（think-act-observe）循环**：智能体先思考下一步做什么，然后调用工具，观察结果后再决定后续动作——这与 ReAct 框架范式一致。
- 核心前提假设非常轻量：目标知识图谱遵循 W3C RDFS 类定义标准，这是几乎所有 RDF 图谱共同遵循的约定。

**工具分类（三类共八个工具）**

- **搜索类工具（Search）**
  - `search_all_classes(search_term)`：从自然语言术语检索候选类。首次调用时从 SPARQL 端点获取并本地缓存轻量级类索引，后续搜索基于缓存执行。采用**混合检索**——密集向量相似度 + 稀疏 BM25 词汇匹配，以倒数排名融合（RRF）整合，并附带**自适应过滤**机制（候选相关性分数比例低于 δ=0.125 即被裁剪，且保留最少 3 行），以控制“上下文腐烂”。
  - `lookup_class_instances(class_uri, exact_term)`：类范围内的实例解析，默认匹配实例标签和 IRI；失败时可启用后备搜索词或 `all_attributes` 模式扩展到字面值属性搜索。这使得精确实体解析无需全局实体索引。
  - `search_all_properties(search_term)`：与类搜索功能对称，检索属性 IRI，除标签、别名外还返回域/范围及使用计数。
- **探索类工具（Exploration）**
  - `explore_property_usage(property_uri)`：抽样真实三元组，聚合并推断属性的实际主语/宾语类，提供示例实例。弥补本体域/范围缺失或不可靠的问题，帮助区分语义相近的属性（如“located in”与“location”的区别）。
  - `explore_entity_relations(entity_uri)`：检查给定实体的入向和出向属性及示例邻居，用于理解实体的图嵌入结构；也支持从字面值反查持有该值的实体。
- **执行类工具（Execution）**
  - `execute_query(query)`：既用于运行最终查询以获得答案，也用于在推理过程中测试中间查询草稿、验证假设、诊断错误。通过迭代执行反馈支持智能体自纠正。
  - 另有 `answer` 工具标记任务完成，`cancel` 工具允许提前终止。

**工作流**

智能体被引导遵循“先搜索、再探索、后执行”的一般顺序：
1. **SEARCH**：将问题分解为语义搜索词，解析出类 IRI、实例 IRI 与属性 IRI；
2. **EXPLORE**：通过探索工具揭示候选 IRI 在图中的连接和用法，验证属性关系的方向与域/范围；
3. **EXECUTION**：构建查询并执行，通过执行反馈校验，直至返回正确结果。

**运行示例展示**（DBLP 图谱）：KGVoyager 仅用 10 次工具调用解决了“统计 Jake Grozdanovski 在某个国际会议上发表的论文数”的问题——5 步搜索、3 步探索、1 步执行——展示了从语义分解到精确查询构建的完整流程。

## 主要结论与发现

1. **F1 显著提升**：KGVoyager 在四个基准上 F1 均优于 GRASP，平均从 55.2% 提升至 63.0%（**+7.8 点**），单基准增益范围从 DBLP 的 +3.9 点到 Climate Models KG 的 +14.0 点。
2. **效率全面提高**：平均成本降低 21.7%，运行时间降低 22.4%，所需迭代轮数平均减少 5.3 轮（≈27%）。唯一例外是 DBLP 的运行时（因 GRASP 预设实体索引可即时解析实体，而 KGVoyager 需要类级搜索），但 DBLP 成本仍更低。
3. **轻量类索引更切实可行**：在对 29 个 okn.us 端点的可行性研究中，KGVoyager 的类索引在 QLever 引擎下成功率达 **96.6%**（28/29），而 GRASP 的实体索引在 QLever 下**全部失败**（0%）、在 Jena 下仅约 21% 成功。类索引随本体而非数据规模扩展，实用性远优于实体索引。
4. **智能体遵循搜索-探索-执行阶段结构**：Gemini 3 Flash（最佳模型）阶段分离清晰，Devstral Small（最差模型）阶段重叠更多、迭代更多，阶段混合程度与基准性能负相关。
5. **查询复杂度影响**：KGVoyager 的优势在包含 ≥5 个三元组模式的复杂查询上更大，结构简单的 1–2 模式查询差异较小甚至略负。
6. **失败根源**：48% 的完全失败源于概念解析错误（尤其属性选择错误占 24%），22% 源于查询构造（以漏约束为主），12% 源于金标准查询本身过度约束/有缺陷——表明报告 F1 实际轻微低估了真实性能。

## 优点

**方法层面**

- **极低的部署假设**：仅需 SPARQL 查询端点 + RDFS 兼容性，不依赖本体文档、示例配对或任何图谱特定工程，适用性远超现有方法。
- **轻量级索引设计**：类索引规模随本体而非数据规模增长，在实际端点（尤其 QLever 引擎）上成功率高，规避了 GRASP 实体索引的可行性瓶颈。
- **工具设计统一且完备**：所有探索工具基于标准 SPARQL 实现，可跨图谱通用；搜索工具将语义与词法信号通过混合检索融合（优于任一单独信号）；探索工具直接从实例数据推断属性语义而非依赖本体标注。
- **操作效率优化**：类索引首次调用后本地缓存、自适应过滤防上下文腐烂、SPARQL 单次表达长路径遍历等设计均有助于压缩工具调用量与 token 成本。
- **失败模式分析深刻**：结构化双层错误归因清晰揭示了属性歧义这一主要瓶颈，为后续改进指明方向。

**实验层面**

- 对比 GRASP 时主动采用其最佳可用场景（提供完整实体索引）进行测试，确保对比公平性，而非以己之长攻彼之短。
- 每组合三次独立运行并报告标准差，结果统计更稳健。
- 同时报告 F1、成本、迭代数和墙钟时间等多维指标，为效率和准确性的权衡提供全面视角。
- 可行性研究揭示了真实世界端点的系统差异（Jena vs. QLever），提高了结论的外部有效性。

## 不足与局限

**结构与应用范围**

- **不适用于非 RDFS 模型**：工具套件基于 RDFS/RDF 类型模式，不适用于 Wikidata 等建模约定完全不同的开放域图谱（Wikidata 的实体、类型与属性模型不基于 RDFS），需要额外适配工具或归一化层。作者虽为开源域设计了本方案，但其普遍性和未来扩展仍需额外工作。
- **对 SPARQL 引擎的隐性依赖**：可行性研究显示实体索引对底层引擎高度敏感（QLever 上全部崩溃），虽然类索引基本成功，却也是对端点稳定性的隐性依赖；QLever 上失败案例服务器内存崩溃提示超大知识图谱仍有挑战。

**数据与实验覆盖**

- **领域基准稀缺**：论文受限于已有的小规模领域基准（14–100 题），未能获得更大规模验证；作者呼吁更多公共领域特定 KGQA 基准，并认为自动基准生成可能是有前途的方向。
- **泛化性证据仍有限**：虽然四个领域基准多样性尚可，但对比 GRASP 的系统仅在有限规模上开展；不同图谱规模、不同 RDF 特色（如推理、OWL 语义）下的表现没有系统验证；Wikidata 等广泛使用的非 RDFS 图谱被明确排除。

**性能与风险**

- **DBLP 运行时间异常**：因 GRASP 预置实体索引可秒级解析实体实例，KGVoyager 在 DBLP 上运行时间反而增加 43.9%，提示在实例密集查询为主的场景下类级搜索并非最优路径。
- **端到端延迟较高**：一次问答通常需要 10–20 次工具调用，每次都需要多轮 LLM 推理，并不适合低延迟交互场景。
- **属性歧义是顽固瓶颈**：失败分析表明属性选择错误是 KGVoyager 最大短板，LLM 在语义相似属性间做抉择时仍不稳定。
- **金标准缺陷**：部分失败案例源于金查询本身过度约束或不一致，领域基准质量本身也是影响评估可信度的因素。
- **与其上下文质量矛盾**：尽管有自适应过滤控制上下文退化，模型能力（如 Devstral Small）差异对结果影响仍然显著，弱模型条件下鲁棒性不足。
- **本质风险**：即便生成语法正确的 SPARQL 也可能语义不正确；在科学或政策等关键领域，输出应审慎验证而非盲信。

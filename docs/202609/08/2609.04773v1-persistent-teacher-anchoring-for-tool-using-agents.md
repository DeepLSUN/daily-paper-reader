## 摘要
蒸馏在LLM后训练中很常见，其中同策略知识蒸馏利用学生生成的轨迹为学生准备后续的强化学习。在每个状态，学生匹配教师提供的下一个词元分布。当轨迹进入教师不会访问的状态时，师生分布差距会累积。在工具使用中，这种差距变得重要，因为学生编写的调用在监督之前执行，且其观测结果塑造后续前缀。提议者-验证者生成通过让教师在生成过程中决定保留哪些学生提议的文本来解决这种漂移。现有公式管理文本，但将工具执行排除在其范围之外。我们提出持续教师锚定，一种由学生诱发但由教师承诺的轨迹构建方法。PTA保留块级验证并添加回合级承诺，允许调用仅在教师验证整个回合后到达环境。将验证过的块视为原子生成单元，我们引入持续前瞻，通过推进未来样本并在固定验证器下将未完成的样本跨学生更新携带，从而填充空闲轨迹容量。在Search-R1风格的检索和DeepEyes风格的感知RL中，在相同的下游RL预算下，于下游RL之前应用PTA相比OPKD将宏best@4提高了2.5和2.8个百分点，同时前瞻将吞吐量提高了24%。

## Abstract
Distillation is common in LLM post-training, where on-policy knowledge distillation (OPKD) uses student-generated trajectories to prepare the student for downstream RL. At each state, the student matches a next-token distribution supplied by the teacher. As the rollout enters states the teacher would not visit, the teacher-student distribution gap can accumulate. In tool use, this gap becomes consequential because student-written calls execute before supervision and their observations shape later prefixes. Proposer-verifier generation addresses this drift by letting the teacher decide which student-proposed text is retained during generation. Existing formulations govern text but leave tool execution outside their scope. We propose Persistent Teacher Anchoring (PTA), a student-induced but teacher-committed rollout construction. PTA retains chunk-level verification and adds turn-level commitment, allowing a call to reach the environment only after the teacher has verified the entire turn. Treating verified chunks as atomic generation units, we introduce persistent lookahead, which fills idle rollout capacity by advancing future samples and carrying unfinished ones across student updates under the fixed verifier. Across Search-R1-style retrieval and DeepEyes-style perception RL, applying PTA before downstream RL improves macro best@4 by 2.5 and 2.8 points over OPKD under the same downstream RL budget, while lookahead improves throughput by 24%.

## 1. 论文的核心问题与整体含义（研究动机和背景）

**研究背景**：在 LLM 后训练阶段，同策略知识蒸馏是一种常见方法，用于在强化学习前用教师模型引导学生的初始策略。

**核心问题**：
- 在 OPKD 中，学生自行生成轨迹后，教师才基于该轨迹给出 token 级分布作为监督信号。由于学生生成的轨迹会进入教师本身不会访问的状态，师生之间的分布差距会随轨迹长度累积。
- 在工具使用场景中，这一差距尤具破坏性：学生编写工具调用后，调用在监督信号到达之前就已执行，返回的观测会进一步塑造后续前缀。一旦错误工具调用产生观测，错误信息便渗入轨迹文本，后续修正无法逆转已发生的环境交互。
- 现有的 proposer-verifier 生成方法（如推测采样、SKD 等）只解决文本流内部的拒绝/保留问题，没有定义工具调用何时可以执行、观测 token 如何处理，留下了关键的语义空白。

**总体含义**：解决工具使用代理在蒸馏阶段“未经验证的工具调用先行执行并污染后续生成”的问题，确保教师不仅决定文本内容，也在决定哪些工具调用可以真正进入环境。

## 2. 论文提出的方法论（核心思想、关键技术细节、算法流程）

### 核心思想
PTA 建立了一种“由学生诱发、由教师承诺”的轨迹构建机制：学生提议一切内容块（chunk），教师负责验证；在块级验证基础上增加“回合级承诺”（turn-level commitment）——只有当教师验证完整个助手回合后，其中的工具调用才被允许进入环境执行。

### 关键技术细节

**（1）块级验证 + 回合级承诺**
- 学生提出 chunk c̃，教师逐 token 检查：若落入教师 top-K 支持集则保留；首个拒绝位置替换为教师 top-1 token，并丢弃从旧前缀生成的后缀。
- 验证通过的 chunk 先被记入“待定助手回合”（pending assistant turn），不进入已提交轨迹。
- 当回合达到 EOS 或工具调用结束标签时，回合被“提交”（commit），工具执行只能发生在提交之后。
- 回合提交并执行后，观测文本作为上下文保留，但不作为蒸馏目标（不训练学生复述环境提供的观测）。

**（2）状态定义与原子边界**
- rollout 状态定义为 S = (τt, Rt,k)，τt 为已提交轨迹，Rt,k 为待定回合中已验证的 k 个块。
- 状态只在两种边界暴露：完整块验证后，或完整环境转换（工具调用+观测返回）完成后。不保留原始提案、部分提交回合或缺少观测的已提交工具调用。

**（3）源感知蒸馏目标**
- 对样本 b 的已提交轨迹 τb，仅对源标签标记为 ASSISTANT 的位置施加蒸馏损失：

L_PTA(θ) = (1/N_t) Σ_{b∈B_t} Σ_{i∈A(τb)} D_KL(q_{b,i} ∥ p_{b,i})

- 提示（prompt）与观测（observation）token 留在上下文中但不作为模仿目标。

**（4）持久前瞻调度**
- 教师验证器在整个训练中固定，学生每步更新。验证过的原子状态可跨学生更新持久存在。
- 当同步批次的样本未全部完成、出现空闲槽位时，从未来批次调入样本执行前瞻（lookahead）；
- 前瞻样本若在当前批次完成前结束则被“提升”（promoted）进当前更新批次；未完成的则转为“结转”（carryover）到下一步继续。
- 截断只能发生在原子状态边界，不会切断未验证的块或已执行但观测未返回的工具调用。

### 算法流程（Algorithm 1 概要）
1. 初始化已提交轨迹 τ。
2. 若 τ 未终止且有预算：初始化待定助手回合 R = ∅。
3. 循环直到 R 被终结：学生提出块 → 教师验证块 → 已验证块加入 R。
4. 终结 R 得到已提交助手回合 A，加入 τ。
5. 解析 A 中的工具调用：若有效，执行并插入观测；若是最终回答，标记 τ 终止。

## 6. 论文的主要结论与发现

1. **检索任务提升**：PTA + RL 相对 OPKD + RL 将 macro best@4 提高 2.5 个点（32.07 → 34.59），最大增益在多跳检索集 Musique（best@4 从 13.94 → 18.78）。
2. **感知任务提升**：PTA + RL 相对 OPKD + RL 将 macro best@4 提高 2.8 个点（67.20 → 70.00），macro mean@4 提升 5.32 点；增益集中于高分辨率 8K 的跨实例（cross-image）推理场景。
3. **预 RL 已见优势**：在感知环境的对齐检查点上，PTA 在全部六项指标上超过 OPKD，说明优势来自蒸馏阶段产生的初始策略本身。
4. **关键消融**：删除工具调用跨度内的教师替换后，正面对齐优势完全消失。虽然此类替换只占全部已提交助手 token 的 0.05%（检索）与 0.82%（感知），但它们作用于真正进入环境的内容。
5. **PTA 仍以学生提议为主**：91.5% 的已提交助手 token 保留学生原提议（检索）/ 88.4%（感知），PTA 本质上是近端策略的轻量修正而非常规的 teacher-generated 蒸馏。
6. **Top-N 稳定性**：在教师验证的上下文上，固定 top-N 预算保留更多教师分布质量、actor 熵更低，说明蒸馏条件本身更稳定。
7. **吞吐提升**：持久前瞻调度将吞吐量从 0.519 samples/s 提升至 0.644 samples/s，即提升 24%，同时每步平均提升 20.2 个额外样本。

## 7. 优点与亮点

- **问题定位精准**：明确指出现有 proposer-verifier 方法在工具执行边界上的空白，从未验证调用提前执行、修正与执行不一致、观测 span 失控、观测目标不当四个缺口系统化分析问题，然后逐一提供对应机制。
- **概念区分清晰**：将“生成中验证”（文本保留）与“提交后执行”（工具触达环境）分层——提出保留块级验证（决定保留哪些文本）并增加回合级承诺（决定何时可执行），概念上简洁有力。
- **原子边界复用**：验证过的块 / 完整环境转换同时充当跨更新的持久状态，在同一组状态边界上自然实现 lookahead 调度，无需改变验证语义即可提升吞吐，设计优雅。
- **消融设计严谨**：特别是“仅抑制工具调用内替换”的消融实验，能够清晰地隔离出机制的必要成分，证明价值不在于安全时序或延迟执行本身。
- **形式化补充扎实**：附录 D 给出已提交 token 分布的精确数学形式（两分量混合：截断学生分布 + 教师 top-1 点质量），明确指出总变差距离恰好等于教师拒绝质量 r(h)，理论解释到位。
- **以“策略接口”为准的验证**：对 carryover 跨更新的合法性提供命题与证明，保证更新后的学生输出同样需要过验证器。

## 8. 不足与局限

- **覆盖范围有限**：仅覆盖检索与感知两类工具环境，未覆盖代码执行、数据库访问、多智能体等更广泛的工具使用类型。
- **基于静态数据集的评测局限**：采用固定 benchmark（NQ/PopQA/HotpotQA/Musique、VStar/HRBench），缺少真实任务交互中多轮自我修正模式的检验。
- **训练种子方差不可见**：每个设置只训练一次，无法判断多次重跑时的稳定性。

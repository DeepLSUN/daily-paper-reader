## 摘要
自动生成的环境为训练通用智能体提供了可扩展的交互数据来源。然而，现有方法主要在单一环境内生成任务，而现实世界的工作流要求智能体跨多个服务连接信息与动作。我们提出组合式环境扩展（Compositional Environment Scaling，CompoWorld），通过组合一个有限的可复用服务库来扩展任务空间。编码智能体将工具规范转化为具有类型化状态和共享接口的已验证服务，而世界模型则处理无法可靠实现的工具。随机游走过程通过依赖图连接各服务，从而能够生成并验证需要信息跨服务流动的任务。已验证的轨迹支持监督微调（SFT），而我们的以完成为中心的评分标准奖励（Completion-Focused Rubric Reward）通过在每组 rollout 中强调通过率较低的标准，引导强化学习（RL）实现任务的完整完成。我们构建了 448 个服务，暴露 10,130 个工具，并使用 3K 条 SFT 轨迹和 1K 个 RL 任务训练 Qwen3.6-35B-A3B。实验结果表明，CompoWorld 在八个基准上平均较其基座模型提升 9.17 分。在 AutomationBench 上，它超越了 Claude Opus 4.6 等前沿模型，并在所有对比的智能体专用 35B-A3B 模型中领先。

## Abstract
Automatically generated environments provide a scalable source of interaction data for training general agents. However, existing approaches mainly generate tasks within a single environment, while real-world workflows require agents to connect information and actions across multiple services. We introduce Compositional Environment Scaling (\textbf{CompoWorld}), which expands the task space by composing a finite library of reusable services. Coding agents turn tool specifications into verified services with typed states and shared interfaces, while a world model handles tools that cannot be reliably implemented. A random-walk procedure connects services through dependency graphs, enabling the generation and verification of tasks that require information to flow across services. Verified trajectories support supervised fine-tuning (SFT), while our Completion-Focused Rubric Reward guides reinforcement learning (RL) toward full task completion by emphasizing criteria with lower pass rates within each rollout group. We construct 448 services exposing 10,130 tools and use 3K SFT trajectories and 1K RL tasks to train Qwen3.6-35B-A3B. Experimental results show that CompoWorld improves on its backbone by 9.17 points on average across eight benchmarks. On AutomationBench, it surpasses frontier models such as Claude Opus 4.6 and leads all compared agent-specialized 35B-A3B models.

## 1. 核心问题与整体含义

- **研究动机**：自动生成环境已成为训练通用智能体（General Agents）的重要数据来源，但现有方法（如 AgentScaler、ScaleEnv、Agent-World）大多在**单一环境内**生成任务，难以模拟真实工作流中需要跨多个服务传递信息与动作的场景。
- **背景痛点**：真实工作流常耦合多个系统状态。例如，智能体可能需要查询 Snowflake 数据库获取逾期工单、查阅 PDF 操作手册确定应对方案、再通过邮件通知经理和客户。成功的关键在于跨系统携带正确的信息与约束，而非单纯增加工具调用次数。
- **核心命题**：论文提出 **组合式环境扩展（Compositional Environment Scaling, CompoWorld）**，将“服务之间的依赖关系”本身作为可控的环境扩展维度。通过组合一个有限的可复用服务库，支撑远大于服务库规模的工作流任务空间，从而训练智能体在新组合中协调熟悉的服务，连接环境构建与组合式泛化问题。
- **三大挑战**：
  1. 自动生成的服务必须独立可靠执行，同时与其他服务兼容。
  2. 合成任务必须包含有意义的跨服务依赖，且可解、可验证。
  3. 这些任务需为 SFT 和智能体 RL 提供有效监督，包括智能体只完成部分工作流的情形。

## 2. 方法论

### 2.1 核心思想

- 将每个服务建模为独立可执行的环境 $E_i = (S_i, A_i, T_i, \Omega_i, O_i)$（POMDP，无任务特定奖励函数），通过**乘积构造**得到组合环境 $E_C = \bigotimes_{E_i \in C} E_i$。
- 组合保持各环境的局部动态与观测函数，信息通过智能体的观测与后续动作在环境间传递。
- 动作空间加命名空间：$A_C = \bigcup_i \{(i, a) \mid a \in A_i\}$，以区分同名工具。
- 联合状态转移仅更新被调用服务，其他服务状态保持不变。

### 2.2 关键技术细节

**（1）智能体环境生成**

- **类型化环境建模**：从公开 MCP 实现中爬取工具规范，归一化为统一函数调用格式。编码智能体在 pi harness 隔离沙箱中为每个服务构建 Pydantic 状态模型，实体表示为类型化记录，状态由记录集合构成。Pydantic 校验拒绝未知字段与非法更新。
- **工具实现**：每个工具实现为对当前状态的操作，返回更新后的状态与结构化观测（统一 JSON 格式），使独立生成的服务共享执行接口。
- **智能体合成与验证**：编码智能体生成状态模型、工具实现与测试套件，迭代执行测试并修复，直到基础用例与错误处理用例通过。随后由**独立验证会话**从工具规范直接推导对抗性测试（含边界条件），未通过者被隔离，不作为已验证的确定性转移。
- **选择性世界模型模拟**：对无法可靠确定性实现的长尾工具（依赖外部系统或超出编码智能体能力），使用 LLM 世界模型预测输出对 $(s'_i, o)$，并通过同一 Pydantic 模型实例化状态更新，保证类型有效且与服务状态一致。
- **语料与分类**：共构建 **448 个服务、10,130 个工具**，覆盖 13 个应用领域，无单一领域超过 25%（开发与 DevOps 最大，占 22%；生产力与协作 12%）。

**（2）跨环境任务生成与验证**

- 任务表示为 $x = (u, s_0, G, g, v)$：指令、初始联合状态、服务级依赖图、可达参考目标状态、验证器。
- **组合与难度控制**：从服务池采样 $K$ 个服务构成 $E_C$；用**环境游走** $(E_{i_1}, \dots, E_{i_L})$ 构建依赖图 $G=(C,D)$，约束包括：游走覆盖所有选中服务、相邻访问不重复同一服务、至少复访一个服务（$L > K$）。每条边表示信息依赖，复访表示中间步骤使先前值失效、需重新读取。
- **难度主控参数为游走长度 $L$**，其他控制包括采样领域与服务数 $K$。
- **智能体任务生成四阶段**（pi harness 内有界修订循环）：
  - **EXPLORE**：在隔离沙箱中与服务交互，了解工具与状态格式。
  - **DESIGN**：将游走转为具体场景，构造初始状态 $s_0$，撰写指令 $u$ 与结构化评分标准（rubric）。
  - **PROBE**：在 $E_C$ 中执行游走求解任务，得到目标 $g$ 与参考解；每条 rubric 标准转为可执行终态检查，验证器 $v$ 必须接受参考解，即满足 $s_0 \xrightarrow{\rho}_{E_C} s_H = g$ 且 $v(s_H)=1$。
  - **SUBMIT**：最终确定 $u$ 与任务工件。

**（3）通用智能体训练**

- **Completion-Focused Rubric Reward**：跨环境任务需多个条件联合成立，二值奖励对部分进展无区分度。对每个任务采样 $N$ 条轨迹，$b_{ij} \in \{0,1\}$ 表示轨迹 $i$ 是否满足标准 $j$。
  - 组通过率：$p_j = \frac{1}{N}\sum_{i=1}^N b_{ij}$
  - 权重：$w_j = \lambda + (1 - p_j)$，$\lambda > 0$ 为每个标准保留正权重
  - 奖励：$R_i = \frac{\sum_{j=1}^M w_j b_{ij}}{\sum_{j=1}^M w_j}$，$R_i \in [0,1]$，仅当所有标准通过时为 1
  - 权重在组内共享、每组重算、策略更新期间固定。
- **策略优化（GRPO）**：奖励组内归一化得优势 $\hat{A}_{i,t} = \frac{R_i - \bar{R}}{\sigma_R + \delta}$，同一优势赋给轨迹中所有智能体生成 token（工具观测进入上下文但不计入损失）。目标函数为标准 GRPO 形式，含裁剪与 KL 惩罚。
- **梯度分析（附录 A）**：在更新原点处，策略梯度为 $\nabla_\theta \hat{J}_{policy} = \frac{1}{\sigma_R + \delta} \sum_j \alpha_j g_j$，其中 $\alpha_j = \frac{\lambda + (1-p_j)}{\sum_k [\lambda + (1-p_k)]}$。因此 $1-p_j$ 即完成差距，直接控制第 $j$ 项的梯度权重；$p_j < p_k \Rightarrow \alpha_j/\alpha_k > 1$，即低通过率标准获得更高相对权重。

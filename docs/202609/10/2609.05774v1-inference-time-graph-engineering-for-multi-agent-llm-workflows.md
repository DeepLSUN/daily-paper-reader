## 摘要
近期的多智能体 LLM 系统日益依赖图结构通信来协调专用智能体。我们从图工程的视角重新审视多智能体编排：不再优化静态拓扑，而是合成一个以任务为条件的时序工作流图，该图联合指定智能体连接关系与边级通信语义。我们提出 ReActNet，一个免训练框架，它将一个查询和一组角色专用智能体编译为一系列有向通信图。每个图快照对应一个推理阶段，每条边携带一条自然语言指令，规定源智能体应向目标智能体提供何种消息。编译得到的时序图随后通过结构化消息传递执行：智能体通过将自身先前状态与来自控制器分配邻居的消息进行整合来更新其推理状态，最后由聚合器将所得状态合成为答案。该设计将图编译与图执行分离，使多智能体协调变得显式、可检查且以任务为条件，而无需强化学习或基于梯度的拓扑优化。在知识推理、数学问题求解、代码生成以及 GAIA 风格助手任务中，ReActNet 持续优于固定拓扑与学习拓扑基线，同时保持有竞争力的推理成本。这些结果表明，有效的多智能体编排不仅取决于哪些智能体进行通信，还取决于对可执行工作流图进行工程化，以编码推理过程中信息应在何时、为何以及如何流动。

## Abstract
Recent multi-agent LLM systems increasingly rely on graph-structured communication to coordinate specialized agents. We revisit multi-agent orchestration from a graph-engineering perspective: rather than optimizing a static topology, we synthesize a task-conditioned temporal workflow graph that jointly specifies agent connectivity and edge-level communication semantics. We introduce ReActNet, a training-free framework that compiles a query and a set of role-specialized agents into a sequence of directed communication graphs. Each graph snapshot corresponds to one reasoning stage, and each edge carries a natural-language instruction specifying the message that a source agent should provide to a target agent. The compiled temporal graph is then executed through structured message passing: agents update their reasoning states by integrating their previous states with messages from controller-assigned neighbors, and a final aggregator synthesizes the resulting states into the answer. This design separates graph compilation from graph execution, making multi-agent coordination explicit, inspectable, and task-conditioned without requiring reinforcement learning or gradient-based topology optimization. Across knowledge reasoning, mathematical problem solving, code generation, and GAIA-style assistant tasks, ReActNet consistently improves over fixed-topology and learned-topology baselines while maintaining competitive inference cost. These results suggest that effective multi-agent orchestration depends not only on which agents communicate, but also on engineering executable workflow graphs that encode when, why, and how information should flow during reasoning.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：多智能体 LLM 系统普遍采用图结构通信来协调角色化智能体（节点=智能体，边=信息流），代表做法包括手工指定拓扑（链、树、星形、完全图、随机图）与学习/优化得到的拓扑（GPTSwarm、G-Designer、AgentConductor 等）。
- **核心问题**：现有方法大多是**拓扑中心（topology-centric）**的——只优化"谁与谁可以通信"的邻接模式，而把**可执行协作协议当作隐式**。但实际有效的多智能体推理还取决于：
  - 每条边承担什么推理功能（是给代码、暴露反例、说明不变量，还是回应批评）；
  - 通信发生在问题求解的哪个阶段；
  - 推理状态如何传播与聚合。
  - 作者举例：程序员→验证者的边不应只表示"允许通信"，而应说明程序员该提供代码、失败用例还是算法不变量。
- **整体含义**：论文主张从**图工程（graph engineering）**视角重构多智能体编排，把设计目标从"学习图骨架"转为"合成任务条件化的协作协议"。核心对象不是静态拓扑，而是**可执行工作流图**：联合定义智能体、通信路径、推理阶段结构、边级指令与状态更新。

## 2. 方法论：ReActNet（Compile-then-Execute）

### 2.1 核心思想
- **免训练（training-free）**、仅在推理时进行图合成；不使用强化学习或基于梯度的拓扑优化。
- 把多智能体协调拆成**图编译**与**图执行**两个阶段，使协作显式、可检查、模块化。

### 2.2 形式化建模
- **时序交互图**：G = {G⁽ᵗ⁾}ᵗ⁼¹…ᵀ，每个快照 G⁽ᵗ⁾ = (V, E⁽ᵗ⁾)，节点集 V 固定（|V| = N），边集随轮次变化。时序邻居定义为 N⁽ᵗ⁾ᵢ = {j | e⁽ʲ→ⁱ⁾_t ∈ E⁽ᵗ⁾}。
- **控制器作为推理时图编译器**：由 LLM 控制器在**一次前向传播中一次性生成完整时序图**（one-shot compilation）：
  W_q = {G⁽ᵗ⁾}ᵗ⁼¹…ᵀ = F_controller(p_controller_role; T; p_MAS; q)。
  其中 p_MAS 由 N 个角色提示拼接而成。
- **指令类型化边（instruction-typed edges）**：e⁽ᵗ⁾_{j→i} = ((j, i), ξ⁽ᵗ⁾_{j→i})，其中 ξ 是自然语言指令，规定源智能体对目标智能体应执行的推理功能（如"提出新方程思路""为第 4 步提供反例"）。这统一了图拓扑与通信语义，比邻接矩阵表达力更强。

### 2.3 执行流程（Algorithm 1）
1. **节点初始化**：每个智能体独立产生初始推理状态 r⁽ⁱ⁾₀ = A⁽ⁱ⁾(p⁽ⁱ⁾_role; q)，保证在接收外部消息前已有角色立场。
2. **多轮消息传递**（t = 1…T）：
   - 源智能体按边指令生成消息：m⁽ʲ→ⁱ⁾_t = A⁽ʲ⁾(p⁽ʲ⁾_role; q; r⁽ʲ⁾_{t−1}; ξ⁽ᵗ⁾_{j→i})；
   - 目标智能体聚合所有入边消息 m⁽ⁱ⁾_t 并更新状态：r⁽ⁱ⁾_t = A⁽ⁱ⁾(p⁽ⁱ⁾_role; q; r⁽ⁱ⁾_{t−1}; m⁽ⁱ⁾_t)。
3. **最终合成节点**：a = F_syn(p_syn_role; {r⁽ⁱ⁾_T}ᵢ₌₁ᴺ; q)，由聚合器 LLM 找出共识、解决分歧并输出规范答案。

### 2.4 关键设计细节
- 控制器**不做在线重规划**：不观察真实中间状态后再改图，而是预先规划全局一致的多轮协议。
- 输出格式受严格约束（JSON 数组，键为 source / target / content），便于程序化解析执行。
- 角色提示按领域定制：数学（数学求解者、数学分析者、编程专家、检查者）、代码（项目经理、算法设计者、编程专家、测试分析者、Bug 修复者）、通用推理（知识专家、批评者、数学家、心理学家、历史学家、医生、律师、经济学家、程序员）。

- **性能**：ReActNet 在 6 个数据集中 5 个取得最优，平均分 92.75 为所有方法最高（次优 G-Designer 89.84）；MMLU 86.93（+4.79）、MultiArith 100.00、SVAMP 94.67、AQuA 87.70（+17.36）、HumanEval 92.74（+21.06）；仅在 GSM8K（94.45）位列第三，但仍接近榜首。

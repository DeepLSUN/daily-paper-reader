## 摘要
技能库通过使大语言模型（LLM）智能体能够重用过程性知识，提升了智能体强化学习（RL）的样本效率。然而，现有范式存在结构性缺陷：它们要么将技能演化与策略优化解耦，要么将元技能实例化为固定工作流。二者都将技能视为被动管理的对象，限制了技能的灵活演化及其与推理智能体的协同适应。为解决这些局限，我们提出 CoSkill，一个统一的多智能体 RL 框架，它将静态元技能工作流重构为可学习的元技能智能体，并在分层技能库上将其与推理智能体联合训练。通过将推理智能体和元技能智能体建模为共享单一骨干网络的协作团队，CoSkill 实现了端到端协同适应：推理智能体以检索到的任务技能和从其子节点集合中选出的步骤技能为条件进行动作，而其任务表现则指导元技能智能体细化这些步骤技能。在 ALFWorld 和 WebShop 上的实验表明，CoSkill 大幅优于先前的基于技能和 RL 的基线，分别达到 98.4% 和 90.6% 的成功率（+3.5 和 +6.2 个百分点）。如图 1 所示，CoSkill 在早期样本效率、渐近性能和实际耗时效率方面均表现更优。我们的代码见 https://github.com/jinyuan-cookie/CoSkill。

## Abstract
Skill libraries improve the sample efficiency of agentic reinforcement learning (RL) by enabling large language model (LLM) agents to reuse procedural knowledge. Yet existing paradigms exhibit structural shortcomings: they either decouple skill evolution from policy optimization or instantiate meta-skills as fixed workflows. Both treat skills as passive objects to be managed, limiting the flexible evolution of skills and their co-adaptation with the reasoning agent. To address the limitations, we propose CoSkill, a unified multi-agent RL framework that recasts the static meta-skill workflow as a learnable Meta-Skill Agent and jointly trains it with a Reasoning Agent over a hierarchical skill library. By modeling the Reasoning and Meta-Skill Agents as a cooperative team sharing a single backbone, CoSkill enables end-to-end co-adaptation: the Reasoning Agent conditions its actions on a retrieved task skill and step skills selected from its child set, while its task performance guides the Meta-Skill Agent in refining those step skills. Experiments on ALFWorld and WebShop show that CoSkill substantially outperforms prior skill-based and RL baselines, achieving success rates of 98.4% and 90.6%, respectively (+3.5 and +6.2 pp). As shown in Figure 1, CoSkill achieves superior early-stage sample efficiency, asymptotic performance, and wall-clock efficiency. Our code is available at https://github.com/jinyuan-cookie/CoSkill.

## 1. 核心问题与研究动机

- **背景**：技能库（Skill Library）通过让 LLM 智能体复用过程性知识，显著提升智能体强化学习（agentic RL）的样本效率。然而，如何协调"细粒度技能库优化"与"推理策略更新"仍是一个开放问题。
- **现有范式的三类结构性缺陷**（对应论文图 2）：
  - **外部编排的技能演化**（SkillRL、D2Skill、ReSkill、Trace2Skill 等）：技能库作为独立知识库，其生成、修订、维护交由外部 LLM 或人工规则，技能演化脱离策略学习目标，库内容可能过时、冗余或与演化中的策略失配。
  - **RL 优化的技能库管理**（SAGE、ARISE、Skill1 等）：用下游奖励优化技能生命周期决策，但优化粒度粗糙——RL 只控制技能"是否创建/选择/更新/保留"，技能内部过程仍被视为原子单元，有用的但不完美的技能可能被弃用而非精修。
  - **元技能驱动的技能优化**（SkillOpt、EvoSkill、SkillEvolver、MetaSkill-Evolve 等）：将优化转向单个技能过程，但依赖预定义元技能程序（如 rubric 提示、SKILL.md、多智能体工作流），且通常冻结推理智能体，固定更新规则无法与演化策略协同。
- **核心命题**：技能不应被视为被动管理的对象，而应是可与推理策略共同演化的主动组件。论文的核心设计洞察是——**将元技能形式化为一个 RL 训练的可学习智能体而非固定工作流**，从而让更新策略与推理策略协同适应。

## 2. 方法论

### 2.1 核心思想
- CoSkill 是一个统一的多智能体 RL 框架，将 **Reasoning Agent**（推理智能体）与 **Meta-Skill Agent**（元技能智能体）建模为**共享同一 LLM 骨干的协作团队**，在分层技能库上联合训练，实现端到端技能—策略协同演化。

### 2.2 分层技能库（Hierarchical Skill Library）
- 库结构为 `B = {B_k}`，每个 bundle 为 `B_k = (s_k^task, S_k^step)`：
  - `s_k^task`：片段级（episode-level）全局指导；
  - `S_k^step`：其子节点集合，包含针对中间观测的局部过程。
- **两级检索**：先用任务指令检索全局任务技能（top-1），再**仅在该任务技能的子集合内**检索步骤技能（top-1）。任务技能固定候选子树，保证全局指导稳定、局部决策自适应。
- 离线初始化：由外部 LLM 收集轨迹并归纳生成（ALFWorld 300 任务技能 + 1625 步骤技能；WebShop 300 + 1406）。

### 2.3 共享参数多智能体半马尔可夫决策过程（MSMDP）
- 形式化为 `M = ⟨S, Ω, A, P, R, γ, T⟩`，其中 T 刻画两个角色不同的时间尺度。
- **全局状态** `g_ℓ = (x, ρ_ℓ, H_ℓ, B, B̃_ℓ, Z_ℓ)`：作为共享黑板的协作状态，含活跃角色、交互/验证轨迹、持久库、私有编辑 bundle、待定编辑。
- **角色特定观测**：
  - 推理智能体：`u_t^R = O_R((x,o_t) ∪ h_t ∪ (Z^task, Z_t^step))`；
  - 元技能智能体：`u_t^S = O_S(Select_S(u_t^R) ∪ a_t ∪ (r_t, e_t, o_{t+1}))`，即推理动作本身构成高阶观测的一部分。
- **异构动作空间**（共享策略 π_θ，靠角色提示区分）：
  - 推理动作 `a_t ∈ A^R`（环境动作）；
  - 元技能动作 `z_t ∈ A^S = {INSERT, UPDATE, DELETE, KEEP}`，对活跃步骤技能做结构化编辑。

### 2.4 延迟技能更新机制
- 基线尝试（m=0）中 `Z^task` 固定，逐步检索 `Z^step`；元技能智能体在每个推理 transition 后提出编辑，但**所有编辑暂存至该次尝试结束**，再应用到检索 bundle 的私有副本 `B̃_i = Apply(Copy(B_{k*_i}), z_{i,1:L_i})`，以保持基线轨迹完整。

### 2.5 编辑后技能验证奖励（Post-Edit Skill Verification Reward）
- 对同一任务重跑 M 次验证尝试，用编辑后 bundle 得到 `R_i^(1), ..., R_i^(M)`；
- 编辑序列的延迟奖励定义为相对基线的平均改进：
  `Δ_i^skill = (1/M) Σ_{m=1}^{M} R_i^(m) − R_i^(0)`
- 基线相减控制任务难度，多次聚合降低 rollout 方差；仅当编辑有效且验证成功率超过基线时才成为晋升候选，并按任务组内 top-K_prom 排名晋升，限制库增长。

### 2.6 基于 GiGPO 的联合优化
- 角色特定信用分配采用 Group-in-Group Policy Optimization（GiGPO），优势为
  `A_{i,t}^ρ = A_{E,i}^ρ + ω^ρ A_{S,i,t}^ρ`，即片段级相对优势 + 步骤级相对优势；
- 推理轨迹：A_E 比较同任务的完整尝试回报，A_S 比较同任务同基础技能的 Δ^skill；
- 步骤级分组锚点分别为 `(x, o_t)`（推理）和 `(x, o_t, Z_t^step)`（技能编辑）；两角色的片段/步骤统计**分别归一化**，避免任务执行与技能验证之间的奖励尺度泄漏；
- 最终损失：`L(θ) = L_GiGPO^R(θ) + L_GiGPO^S(θ)`，各自使用标准 GiGPO 裁剪代理与 KL 正则。

## 6. 主要结论与发现

- **整体性能**：CoSkill 在所有汇总指标上排名第一——ALFWorld 平均成功率 **98.4%**（较最强基线 RetroAgent +3.5 pp），WebShop 得分 **95.9**、成功率 **90.6%**（+4.3 / +6.2 pp）；ALFWorld 六类任务中五类达到 100%。
- **相对无技能 GiGPO**：ALFWorld +7.6 pp、WebShop +17.8 pp，说明收益超出优化器本身。
- **相对外部强编辑器**：CoSkill 共享 Qwen2.5-7B 骨干，却超过使用 Gemini-3-Flash/O3 编辑器的 D2Skill（+7.8 / +6.2 pp），表明"将技能精炼与目标环境奖励对齐"比编辑器规模更重要。
- **相对粗粒度技能管理**：相比 Skill1（技能视为原子条目），CoSkill 在 Heat、Cool、Pick2 上分别提升 12.5、23.4、7.7 pp，支持细粒度步骤级修订的优势。
- **消融结论**：
  - 去掉元技能 RL：Step-20 成功率 −12.50 pp，最终 −3.12 pp，说明 RL 对齐既加速早期学习又提升最终性能；
  - 扁平化技能库：Step-20 −14.06 pp，最终 −1.56 pp，分层结构提供更可靠的学习轨迹并减少无关技能干扰；
  - 稀疏交替更新（10/20 步）：Step-60 分别落后 25.00 / 18.75 pp，Step-120 仍差 17.19 / 14.06 pp，说明跨角色反馈陈旧是主要瓶颈。
- **元技能动力学**：有 RL 时编辑分布收敛至 97–99% UPDATE、破坏性 DELETE 几乎消失；累计晋升减少 47.6%（387 vs 739）却性能更强；步骤

技能检索命中率上升、空 bundle 率下降，说明元技能智能体逐渐学会"精修而非重建"——它倾向于在既有步骤技能上做增量式 UPDATE，而非频繁 INSERT/DELETE 造成库结构震荡；晋升数量的大幅下降表明 RL 训练后的编辑"少而准"，避免了外部编排范式常见的库膨胀与冗余累积。

## 7. 论文贡献与创新点

- **概念层面的重新定位**：把技能从"被管理的被动知识对象"提升为"与推理策略共同演化的主动组件"，并指出三类现有范式（外部编排、粗粒度 RL 管理、固定元技能工作流）共同的症结在于技能演化与策略学习目标之间存在**优化错位**。
- **方法论层面的统一框架**：提出共享 LLM 骨干的多智能体 MSMDP 形式化，用角色特定观测（推理动作本身成为元技能智能体的高阶观测输入）与异构动作空间（环境动作 vs. 结构化编辑动作）在**单一策略参数**下耦合两类行为，避免了为技能演化单独训练第二个模型的参数开销与目标漂移。
- **信用分配机制**：设计"延迟技能更新 + 编辑后技能验证奖励"的组合，将编辑质量定义为**相对基线的平均改进 Δ^skill**，把稀疏、延迟、跨回合的技能编辑信号转化为可进行组内比较的步骤级奖励，从而能够直接接入 GiGPO 的分层优势分解。
- **分层库与两级检索的耦合设计**：任务技能固定候选子树，使全局指导稳定、局部步骤技能自适应，为步骤级编辑提供了明确的"归属边界"——编辑只作用于当前检索到的 bundle，降低了信用分配的空间歧义。
- **实证发现**：在共享 7B 骨干条件下超过使用更强外部编辑器（Gemini-3-Flash / O3）的基线，提示**"把技能精炼信号与目标环境奖励对齐"比"提升编辑器能力"更具边际收益**。

## 8. 局限性与可改进方向

- **环境覆盖有限**：仅在 ALFWorld 与 WebShop 两个文本交互环境验证，且消融与动力学分析主要在 ALFWorld 完成；未涉及多模态、长程工具调用或代码类环境，跨域泛化证据不足。
- **算力成本较高**：160 训练步约 526 GPU-hours，且每次编辑需重跑 M 次验证尝试，验证开销随 M 线性增长；论文未报告验证阶段的额外算力占比，也未讨论 M 的敏感性分析。
- **离线技能库依赖外部 LLM**：初始 bundle 由外部 LLM 归纳生成（300 任务技能 + 千余步骤技能），其质量与覆盖度构成性能上界的一部分，论文未做"零初始化库"或"库质量扰动"的鲁棒性实验。
- **共享骨干的容量假设**：两个角色共享同一策略参数，靠角色提示区分。当推理任务与技能编辑任务所需的语言能力差异较大时，是否存在任务间负迁移、是否需要最小程度的参数解耦，论文未予探讨。
- **奖励设计的依赖**：Δ^skill 依赖可重复执行且结果可比较的环境（同一任务可重跑 M 次）。在一次性、不可回放或随机性极高的环境中，该奖励的可构造性会显著下降。
- **编辑动作空间较粗**：A^S 仅含 INSERT/UPDATE/DELETE/KEEP 四类结构化操作，对技能文本的重写强度、合并拆分等更细的编辑语义未做区分，可能限制技能形态的演化空间。
- **基线可比性**：如第 5 节所述，多数基线数值引自原文而非统一重跑，且部分基线的编辑器骨干强于 CoSkill，需谨慎解读绝对差距；文中模型命名的不一致亦增加复现难度。

## 9. 启示与实践建议

- **对智能体系统设计者**：若已具备技能库雏形，优先考虑把"库维护逻辑"从硬编码工作流迁移为可学习的策略组件，并用**相对基线的改进量**而非绝对成功率作为技能质量的评价信号。
- **对 RL 训练工程**：角色分工明确的多智能体场景中，GiGPO 式的"片段级 + 步骤级"双层优势与**分角色独立归一化**是避免奖励尺度泄漏的关键工程细节；直接混用统一归一化容易让技能验证的高方差信号污染环境动作的信用分配。
- **对训练预算规划**：协同更新频率是主要瓶颈之一——稀疏交替更新在早期显著落后，说明两类角色的反馈新鲜度对学习速度影响很大，不宜为省算力而过度拉长交替周期。
- **对评估规范**：技能类方法应至少报告"库规模—性能"联合曲线与编辑动作分布，否则难以区分"性能提升来自更好的技能内容"还是"仅来自更多的库条目"；CoSkill 中晋升数减少 47.6% 而性能更强，正是这类诊断的价值所在。

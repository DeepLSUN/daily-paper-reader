## 摘要
我们提出 FrogNano，一个 4B 编程智能体，旨在即使在资源受限的环境中也能高效且有效地处理软件工程（SWE）任务。它仅通过强化学习（RL）在约 1,500 个带有合成任务的 SWE 环境中进行后训练。提升性能的一个关键要素是在线任务合成流程，它能够生成与当前检查点可学习性前沿相匹配的任务。本报告提供了证据，表明具有竞争力的小型编程智能体可以仅依靠合成任务进行训练，而无需传统上从更大模型进行蒸馏，并且当前智能体可学习性前沿处的任务生成十分重要。我们报告了训练方法、跨多种环境的评估以及深入分析的细节，为我们在轻量但能力强的编程智能体（可在最低硬件条件下运行）方面的持续探索奠定基础。

## Abstract
We present FrogNano, a 4B coding agent designed to tackle software engineering (SWE) tasks efficiently and effectively, even under resource-constrained environments. It is post-trained exclusively via RL on around 1,500 SWE environments with synthetic tasks. A key ingredient for improving performance is an online task synthesis pipeline that creates tasks calibrated to the frontier of learnability for the current checkpoint. This report provides evidence that competitive small coding agents can be trained with synthetic tasks alone, without traditional distillation from larger models, and that generating tasks at the learnability frontier of the current agent is important. We report details on the training methodology, evaluations across diverse environments, and in-depth analyses, serving as a foundation for our ongoing exploration of lightweight yet capable coding agents that can run on minimal hardware.

### 2.2 Leaf：面向小模型的轻量 Harness

- **问题发现**：在更复杂的 R2E-Gym/SWE-Agent harness 下，Qwen3.5-4B **约 96% 的轨迹触及轮次上限**，常常无法产出规定的提交动作。

- **终止规则**：响应中含工具调用则继续；**不含工具调用的响应即视为最终答案**并终止 episode。
- **训练/评估一致**：训练与评估使用同一 Leaf harness；模型生成的推理、答案文本、工具调用计入 loss，任务 prompt 与工具输出保留在上下文中但**被 mask**。

### 2.3 TaskPilot：策略引导的在线任务合成与校准

- **起点**：从 SWE-rebench 的真实仓库快照出发，由任务生成模型产出 **问题陈述、gold patch、隐藏的 fail-to-pass（F2P）测试**。
- **可执行性验证**：候选任务必须满足 F2P 测试在原快照上失败、应用 gold patch 后通过，且既有 pass-to-pass（P2P）套件保持稳定。每个任务 = 问题陈述 + 仓库快照 + 运行时 + gold patch + 评分测试；**gold patch 仅用于验证，对求解器隐藏**，F2P 测试及其结果在交互中同样隐藏。
- **策略反馈信号**：对每个可执行候选，用当前 4B Leaf 策略做 N 次 rollout，估计解决率
  - $\hat{p}_{\text{policy}} = \frac{1}{N}\sum_{j=1}^{N} R_j$，其中 $R_j \in \{0,1\}$ 表示第 j 条轨迹是否通过全部评分测试。
- **可学习区域与目标**：定义广义可学习区为 $0 < \hat{p}_{\text{policy}} < 1$；迭代 1–4 目标 $\hat{p}_{\text{policy}} = 0.5$；初次迭代 5 收益变弱后，改用**更强的任务生成模型**并把校准目标下移到 $0 < \hat{p}_{\text{policy}} \le 0.5$。
- **生成–评估–精炼–再评估循环**：不在目标区的候选不是简单丢弃，而是**修改任务本身**（调整语义清晰度与"定位解法"的信息量）后重新验证与评估，可重复多轮。$\hat{p}=1$ 为饱和，$\hat{p}=0$ 为过难。
- **语义校准示例**（图 5，仓库快照、gold patch、评分测试固定，仅改问题陈述）：
  - 欠指定（0% 解决率）：契约细节缺失（区间是否闭合、宽度定义）。
  - **期望难度（50%）**：精确陈述行为契约（端点语义、零宽区间），但**不暴露失败位置**。
  - 过度指定（100%）：直接点名类与方法、给出失败输入与异常，实质定位了修复点。

### 2.4 RL 训练配方

- **算法**：DPPO（组相对优势 + 对 rollout/behavior 策略对数概率绝对差的对称裁剪），配合**异步 rollout** 与 **log-length penalty**；沿用 DAPO 的零方差组过滤与异步训练机制，显式限制 rollout 策略滞后。
- **组内优势标准化**：
  - $A_{ij} = \dfrac{R_{ij} - \bar{R}_i}{\mathrm{std}(R_i) + 10^{-6}}$，零方差组丢弃（因任务已校准到可学习区，被丢弃的组很少）。
- **非对称轨迹重要性采样（TIS）**：设 $p_t=\pi_\theta(a_t|s_t)$，$q_t=\pi_{\text{roll}}(a_t|s_t)$，$\rho_t = p_t/q_t$，$\Delta p_t = p_t - q_t$；

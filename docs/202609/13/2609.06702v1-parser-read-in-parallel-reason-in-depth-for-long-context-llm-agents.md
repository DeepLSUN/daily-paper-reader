## 摘要
顺序记忆智能体通过逐块读取来处理长文档，同时维护一个紧凑的记忆状态，从而将文档遍历与推理深度耦合。这种耦合导致其对证据位置敏感，并使推理延迟与文档长度线性相关。我们提出 PARSER，将读取与推理解耦。一组轻量级子智能体各自绑定到一个文本块，并行读取整个文档；而一个主智能体通过迭代式 scatter-gather 轮次进行深度推理：每轮向所有子智能体广播一个查询，聚合返回的证据，并基于目前发现的内容构建更深入的后续查询。这种解耦设计将所有可学习行为集中于主智能体，并通过强化学习进行优化，而子智能体则保持为冻结的现成模型。在上下文长度从 7K 到 896K tokens 的多跳问答任务上，采用 4B 骨干模型的 PARSER 平均优于最强的顺序记忆基线 5.7 分，在 896K tokens 时优于 12.0 分。扩展到 9B 骨干模型时，PARSER 超过 DeepSeek-V4-Pro 6.3 分。受控实验证实，PARSER 对证据位置、顺序和距离的扰动具有鲁棒性，而这些情况会导致顺序方法出现大幅准确率波动；同时，PARSER 将推理延迟最多降低 11 倍。

## Abstract
Sequential memory agents process long documents by reading chunks one after another while maintaining a compact memory state, coupling document traversal to reasoning depth. This coupling introduces sensitivity to evidence placement and ties inference latency linearly to document length. We introduce PARSER, which decouples reading from reasoning. A bank of lightweight subagents each bound to a single chunk read the entire document in parallel, while a lead agent reasons in depth through iterative scatter--gather rounds: at each round it broadcasts a query to all subagents, aggregates the returned evidence, and formulates a deeper follow-up query conditioned on what has been found so far. This decoupled design concentrates all learnable behavior in the lead agent, which is optimized with reinforcement learning, while the subagents remain frozen off-the-shelf models. On multi-hop QA with contexts ranging from 7K to 896K tokens, PARSER with a 4B backbone outperforms the strongest sequential memory baseline by 5.7 points on average and by 12.0 points at 896K tokens. Scaling to a 9B backbone, PARSER surpasses DeepSeek-V4-Pro by 6.3 points. Controlled experiments confirm that PARSER is robust to perturbations in evidence position, order, and distance, conditions that cause large accuracy swings in sequential methods, while reducing inference latency by up to 11x.

# PARSER 论文中文总结

## 1. 核心问题与研究动机

- **背景**：长文档推理（多文档问答、法律分析等）是 LLM 的核心能力，但单个问题的证据可能分散在数十万 token 中。即便上下文窗口已达百万 token 级，模型准确率仍随上下文增长而下降，即"context rot"；其中典型表现是位置偏置——位于输入中段的证据被系统性忽略。
- **现象观察**：在多跳 QA 上，直接全上下文回答从 7K 到 896K token 会掉几十个点，即使对支持百万 token 的模型也是如此。瓶颈不再是窗口容量，而是**"读什么、按什么顺序推理"**。
- **现有范式的问题**：以 MemAgent、ReMemR1、GRU-Mem 为代表的顺序记忆智能体逐块阅读并维护紧凑记忆，但共享一个结构性承诺——文档只按顺序遍历一次。由此产生两个约束：
  - **证据放置敏感**：每块在未见全文前就被压缩，判断相关性时信息不足；准确性受证据绝对位置、逻辑顺序、证据间距影响，多跳推理下尤为致命。
  - **推理延迟线性增长**：T 个 chunk 形成 T 步依赖链，墙钟时间随文档长度线性上升，无法并行。
- **后续工作只是打补丁**：ReMemR1 加回调检索、GRU-Mem 加门控跳过，但顺序链本身未打破，常在两个症状间权衡。
- **核心命题**：长文档的"阅读顺序"由文档决定，"推理顺序"由问题决定；顺序记忆让前者驱动后者。PARSER 旨在将二者解耦。

## 2. 方法论

### 2.1 核心思想

- **ParSer = Parallel Reading + Sequential Reasoning**：把文档长度从"顺序深度"转化为"并行宽度"。
- **双角色分工**：
  - **主导智能体（Lead Agent）**：从不接触任何原始文档 token，只接收问题 q，在 ReAct 式"思考—行动"循环中推理。
  - **子智能体（Subagents）**：每个绑定一个 chunk，只读自己的块，针对给定查询返回证据；大量无关块可弃权（返回 Unknown）。

### 2.2 关键技术细节：Scatter–Gather 迭代

- 每轮（round k）主导智能体向所有 T 个子智能体**广播同一查询**；所有子智能体**并行**检查各自 chunk；本地发现被聚合为观测 R。
- 主导智能体基于已收集证据**构建更深的后续查询**，迭代直到可给出答案或达到最大轮数 K。
- **关键性质**：
  - 每个 chunk 每轮都在**新查询**下被重新阅读，访问对 chunk 位置对称，无永久丢弃。
  - 跨 chunk 依赖通过**连续多轮**传递，而非文档顺序的记忆传播。
  - 实际执行轮数 K 由问题所需推理跳数决定，而非 chunk 数 T；长文档满足 T ≫ K。
- **效率来源**：多数子智能体只返回短弃权响应并在聚合前被丢弃，通信稀疏；相比顺序记忆每块都生成数百到数千 token 的记忆更新，解码计算大幅减少。

### 2.3 优化：仅训练主导智能体

- 子智能体任务简单（在短 chunk 内定位证据），冻结现成模型即可。
- 主导智能体用 **RLVR + GRPO** 优化，奖励为二值精确匹配 `r(q,y)=EM(a_pred, a_gold)`，无格式奖励（沿用骨干原生多轮工具调用格式）。
- GRPO 目标（式 1）：含重要性比 ρ、PPO 裁剪、KL 正则项；**对观测 token（子智能体返回的 findings）做 mask**，策略梯度只作用于主导智能体生成的 token。
- 记 S(D) 为绑定到文档 chunk 的冻结子智能体集合。

### 2.4 算法流程（Algorithm 1 文字版）

1. 初始化主导智能体轨迹 H = [系统提示, 用户问题]。
2. 对 t = 1…K：
   - 主导智能体生成思考 z_t 与动作 A_t；
   - 若含答案则返回；若含查询则进入 Scatter 阶段——对每个查询 u，**并行**让所有 T 个子智能体处理各自 chunk，Gather 聚合结果 R_u；
   - 将本轮生成与观测追加到 H；若动作非法则追加 InvalidActionHint 并继续。
3. 循环结束返回抽取的答案。

### 2.5 复杂度分析（附录 A）

- **Prefill**：全上下文 O(n²)；分块后 MemAgent 与 ParSer 均为 O(n²/c)。
- **Decode**：MemAgent 为 O(nr_M + r_M²/c)；ParSer 为 O(nr_S/c + r_S²/(Kc) + r_S r_L + r_L²)，其中 r_S 为所有子智能体总输出、r_L 为主导输出。
- 并行执行可将子智能体对延迟的贡献再降因子 c；但在高并发下若 KV cache 被驱逐需重新 prefill，复杂度从 O(n²/c) 升至 O(Kn²/c)，这解释了高并发下延迟优势减弱。

## 6. 主要结论与发现

- **准确率**：ParSer-4B 在 HotpotQA 平均 **84.57%**，9B 平均 **86.79%**；4B/9B 分别超最强顺序基线 **5.7/6.7** 分，在 896K 极端长度下差距扩大至 **12.0/9.9** 分；9B 平均超 DeepSeek-V4-Pro **6.3** 分。
- **长度不变性**：ParSer 在两个基准上跨长度几乎零波动，而全上下文模型与顺序记忆方法均随长度显著退化。
- **鲁棒性**：对证据位置、逻辑顺序、相对距离三类扰动均近乎平坦；MemAgent 在中段位置、逆序、大间距下大幅掉点，ReMemR1 仅部分缓解。
- **延迟**：896K token、并发 1 时比 MemAgent 快约 **11×**（78s vs 876s）；并发 16 时仍有 1.7× 优势；推理步数几乎不随文档长度增长。
- **训练动态**：RL 使 4B 训练奖励从 44.9% 升至 83.2%，9B 从 49.8% 升至 83.3%；工具调用格式错误率从 0.22%/0.66% 趋近于 0；9B 每轮子查询数从 1.06 升至 1.62，**自发学会并行发起无依赖查询**。
- **跨分布泛化**：分布外 2WikiMultiHopQA 上 ParSer 保持 87–88%，而 MemAgent/ReMemR1 掉点严重；作者归因于主导智能体只学通用问题推理而非文档特定摘要，缓解过拟合。
- **子智能体可替换**：thinking 子智能体、DCI 子智能体均能提升对应 standalone 基线；子智能体从 2B→4B 提升，4B→9B 饱和，说明任务已被问题分解简化。

## 7. 优点

- **范式创新**：把文档长度从"依赖深度"转为"并行宽度"，从根本上打破顺序记忆的 T 步依赖链，兼具准确率与效率。
- **训练极简**：只训练主导智能体、子智能体冻结，训练成本与文档长度无关；沿用骨干原生工具调用格式，无需格式奖励。
- **位置对称访问**：每

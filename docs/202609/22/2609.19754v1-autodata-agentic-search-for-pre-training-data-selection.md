## 摘要
LLM 智能体最近在自动化机器学习工程方面展现出潜力，它们能够在执行反馈下编辑模型和训练代码。然而，数据在很大程度上仍处于这一智能体优化循环之外。我们将预训练数据选择建模为对逐文档特征的启发式工程，即词汇统计、类别标签和困惑度。我们提出了 AutoData，一个直接在可执行选择算法上进行搜索的智能体。与先前在固定领域集合上优化权重的数据混合方法不同，AutoData 搜索一个更丰富的程序空间，涵盖评分、分层和随机选择规则，并通过代理模型的验证反馈迭代优化算法来自动发现特征交互。在一次通宵搜索中，AutoData 发现了一种优于现有人工设计数据整理流程的选择算法。尽管仅在这个小型代理模型上搜索，所发现的方案仍能迁移到更大规模，并提升下游指标 CORE。这些结果表明，数据工程可以被视为一个智能体机器学习问题，将自主研究从模型和训练代码优化扩展到数据。

## Abstract
LLM agents have recently shown promise in automating machine learning engineering by editing model and training code under execution feedback. Data, however, remains largely outside this agentic optimisation loop. We frame pre-training data selection as heuristic engineering over per-document features, i.e., lexical statistics, categorical labels, and perplexity. We introduce AutoData, an agent that searches directly over executable selection algorithms. Unlike prior data mixture methods that optimise weights over a fixed set of domains, AutoData searches a richer program space of scoring, stratification, and stochastic selection rules, discovering feature interactions automatically by iteratively refining algorithms with validation feedback from a proxy model. Within an overnight search, AutoData discovers a selection algorithm that outperforms existing human-designed curation pipelines. Despite being searched only on this small proxy, the discovered recipe transfers to larger scales and improves the downstream metric CORE. These results suggest that data engineering can be treated as an agentic machine learning problem, extending autonomous research from model and training-code optimization to the data.

- **现有数据整理方法的瓶颈**：DCLM、PPL 过滤、RegMix、ClimbMix 等人工设计管线，本质是**固定组合若干启发式**（去重、质量分类、困惑度过滤、重要性采样、领域混合权重优化），既限制了设计空间，也拖慢迭代速度。
- **核心命题**：把预训练数据选择重构为**对可执行选择算法的搜索问题**——在逐文档特征（词法统计、类别标签、困惑度、LLM 标注）之上做"启发式工程"，让智能体在代理模型验证反馈下自动发现特征交互。这将自主研究从模型/训练代码优化**扩展到数据侧**。

## 2. 方法论

### 2.1 核心思想与形式化

- 给定文档池 $D=\{d_i\}_{i=1}^N$、逐文档特征 $\{x_i\}$、固定预算 $B$，选择算法是一个映射
  $f: (D, \{x_i\}, B) \rightarrow S,\; S \subset D,\; |S| = B$。
- 令 $A_\theta(S)$ 为以固定超参 $\theta$ 在 $S$ 上预训练得到的模型，$J(\cdot)$ 为评估函数（val-bpb 或下游 CORE），则搜索目标为
  $f^* = \arg\max_{f \in \mathcal{F}} J\big(A_\theta(f(D,\{x_i\},B))\big)$。
- 与"在固定领域集合上优化混合权重"的 RegMix 类方法不同，AutoData 搜索的是**更丰富的程序空间**：评分规则、分层规则、随机选择规则及其组合。

### 2.2 特征库（四类互补轴）

- **词法特征**：nanochat 分词器下的文档 token 长度；$n\in\{1,\dots,5\}$ 的 distinct n-gram 比率（捕捉重复/模板化文本）。
- **类别特征**：WebOrganizer 分类器给出的主题标签与格式标签，联合得到 $24\times24=576$ 个类别单元。
- **困惑度特征**：以 Qwen2.5-0.5B-Base 为参考模型计算每文档 bits-per-byte，刻画相对参考分布的难度。
- **LLM 标注特征**：Gemini-3-Flash 在部分候选池上抽取三类计数——`n_factual`（错误事实陈述数）、`n_rsteps`（显式推理步数）、`n_rerrors`（无效推理步数）。

### 2.3 自演化搜索循环（Self-Evolving Loop）

- 基于 **AIDE scaffold** 的 LLM 代码优化智能体，每步：① 智能体提出候选选择函数 $f$；② 执行 $f$ 构造训练子集 $S$；③ 在 $S$ 上以固定超参训练代理语言模型；④ 在留出验证集上评估得到分数 $J$；⑤ 分数与历史轨迹摘要作为反馈，指导下一步提案。
- 两个搜索目标各自独立运行一次搜索：**val-bpb** 与 **CORE**，最终各返回代理验证性能最佳的选择算法。

### 2.4 搜索发现的两类代表性配方

- **Algorithm 1（val-bpb，GPT-5.5 第 93 步）**：
  - 1/3 预算作为**均匀随机 backbone** 保证覆盖；其余按"三人一组（slate size=3）"的 Gumbel 锦标赛选取。
  - 复合评分 = 多样性项（`tanh(z(div_avg)) + tanh(z(div_5))`）+ **由多样性门控的困惑度项** + 长度中心化项 + 字符/token 密度中心化项；长度与密度为"中央惩罚"型（惩罚两个方向的离群值）。
  - 在 (topic, format) 单元内做**收缩式中心化（shrinkage centering）** $\mu_c$、$\lambda_c = n_c/(n_c+\tilde n)$，抑制高频单元被过度选中；再加 Gumbel 噪声做 slate 内 argmax，等价于 softmax 采样。
- **Algorithm 2（CORE，GPT-5.5 第 105 步）**：
  - 50% 预算为 backbone，其余为"修复集"。
  - 采用**三锚点（tri-anchor / Goldilocks）三角核**把长度、字符/token 比、n-gram 多样性、困惑度映射到"中等偏好"的池自适应分数（如长度偏好中高、困惑度偏好低）。
  - 加入**源顺序邻域先验**：把候选按连续块分组，块内标准化均值作为先验，奖励"来源区间整体干净"的文档；最终用 `个体分 + 块先验 + Gumbel 噪声` 取 top-B，并去重修复至恰好 $B$ 个。
- **Opus-4.7 / Gemini-3-Pro 的配方**：前者用 (topic, format, 长度分箱) 联合单元 + 比例配额（最大余数法）+ 对"spam 角落"与超短文档的软惩罚；后者用 85% 随机 backbone + 15% 质量修复，在长度十分箱内按 Spearman-Mahalanobis 距离逼近理想分位目标。

## 3. 实验设计

- **数据池**：NVIDIA ClimbMix 全量英文预训练语料（400B tokens，6,542 个训练 shard，$N=553{,}155{,}584$ 篇文档）；留出一个 shard 作为验证集并从所有选择池中排除。

- **代理模型与子采样协议**：每个候选策略在从其选择池中均匀抽出的 **880,000 篇**文档上评估，训练 **depth-8 GPT-2**（target-param-data-ratio = 10，约 0.42B tokens），单次约 **10 分钟 / 1×H100**；固定子样本、只变训练种子，用 4 个种子并行跑，以隔离训练方差。
- **评估指标**：val-bpb（留出 ClimbMix shard，越低越好）与 **CORE**（22 个标准任务的 centered accuracy 非加权均值，覆盖常识推理、阅读理解、世界知识）。
- **对比基线**（均在受控两阶段协议下，先选 $B$ 篇再按模型规模均匀子采样）：
  - **Random sampling**：直接随机抽样，代表"未经额外筛选的 ClimbMix"。
  - **DCLM-Baseline 分类器**：保留正样本，用 ClimbMix 文档替换负样本重新校准 FastText 分类器。

  - **RegMix**：以 24 个 WebOrganizer 主题为域，采 128 个 Dirichlet 混合、各训 depth-8 代理，用 LightGBM 回归预测 val-bpb 后按最优主题分布采样。

## 6. 主要结论与发现

- **AutoData 配方优于人工管线**：在 depth 8→20 上，AutoData 两版配方在 val-bpb 上**显著优于全部四个基线**（含 Random、DCLM、PPL filter、RegMix）；在 depth 24 上则与默认 ClimbMix 相当，说明跨规模迁移存在上限。
- **下游 CORE 上的收益不稳定**：AutoData(CORE) 在除 depth 16 外的所有规模上优于基线（如 d8 0.1142 vs Random 0.1041；d24 0.2727 vs Random 0.2609），但**这些提升在统计上不显著**。
- **人工管线在已高度整理的池上会退化**：DCLM-Baseline 与 PPL filter 在各规模上**反而使 val-bpb 变差**；RegMix 仅在 depth-12 的 CORE 上表现较好。说明数据整理方法对源池高度敏感。
- **发现的方法超越单特征排序/阈值过滤**：AutoData 倾向"复合评分 + 保多样性的选择机制"——在偏好高质量文档的同时维持对数据分布的广泛覆盖（随机 backbone、分层配额、锦标赛/随机竞争）。
- **特征使用与 LLM 偏好差异**（Table 2、Table 4）：
  - 三个 LLM 都必用长度、n-gram、困惑度；但在类别特征上分歧巨大——GPT-5.5 与 Opus-4.7 约 90% 配方使用 topic/format，Gemini-3-Pro 仅 1–2%。
  - 评分聚合：GPT-5.5 偏好**

（承上）**评分聚合**：GPT-5.5 偏好**非线性门控/条件聚合**（如用多样性项 gate 困惑度项、用收缩中心化校正单元偏差），Gemini-3-Pro 偏好**秩/分位映射 + 距离型聚合**（Spearman-Mahalanobis 逼近理想分位），Opus-4.7 偏好**分层配额 + 软惩罚的线性组合**；**选择规则**：三者共享"随机 backbone + 竞争式选择"骨架，但 GPT-5.5 用 Gumbel 锦标赛、Gemini 用十分箱分位配额、Opus 用最大余数配额。这说明**同一搜索目标存在多种等效解法**，智能体搜索的价值不在单一最优公式，而在于自动暴露"高质量 + 保覆盖"这一共性设计原则及其多样实现。

### 特征子集消融（Table 3 / 消融 2）

- 单独使用任一特征族均不足以复现全特征性能：Lexical(2) 与 Categorical(2) 提升有限，Perplexity(1) 单独使用接近甚至略逊于 Random，说明**单轴阈值/排序信号在已高度整理的 ClimbMix 上信息量稀薄**。
- **LLM 标注特征（3 维）单独使用即有可观增益**，但增益幅度仍低于 All features(8)。
- **All features(8) 显著优于任何子集**，且优势主要来自**特征交互**而非单特征强度——这与论文核心论点（价值在于发现特征交互的启发式组合）一致。
- 值得注意：LLM 标注仅在约 4.48M 文档的子池上可用，搜索仍能利用其与全池特征的统计关联做泛化，但**标注覆盖率低**是该路径的隐性瓶颈。

## 7. 局限性与批判性审视

- **规模与泛化边界**：模型上限 1.38B、数据单一（ClimbMix 英文），结论能否外推到数十亿参数、多语种、多模态语料**未经验证**；depth 24 上 AutoData 优势消失，提示**方法收益随规模/池质量提升而衰减**。
- **CORE 显著性不足**：作者坦承下游指标方差高，多数 CORE 提升未达统计显著；因此"数据选择能改善下游能力"这一最强主张目前**证据偏弱**，主要由 val-bpb 代理指标支撑。
- **代理—目标错位风险**：搜索在 depth-8、0.42B tokens 的代理上完成，却用于指导更大规模训练，属于典型的**代理过拟合/尺度错配**隐患；论文以跨规模 val-bpb 迁移作为缓解证据，但缺乏对"代理最优是否即目标最优"的严格检验。
- **算力与成本不透明**：未报告总 GPU 小时、LLM 推理与标注成本，难以评估"通宵搜索"相对人工管线设计的**实际性价比**；若计入 1200 次代理训练与 4.48M 文档 LLM 标注，成本可能并不低廉。
- **评估维度单一**：仅 val-bpb 与 CORE，缺少对**数据效率、训练稳定性、下游微调/指令跟随、安全性/毒性**等维度的考察，无法判断所选数据是否引入隐性偏置。
- **可复现性**：配方为 LLM 生成的自由形式代码，虽附 4 个最优配方代码，但**搜索过程本身不可精确复现**（依赖 LLM 采样与历史轨迹），属于该类 auto-research 工作的共性局限。
- **基线适配的公平性权衡**：对 DCLM/PPL/RegMix 的重校准（负样本替换、选中间带、24 域适配）虽提升可比性，但也可能**未充分调优基线**，使对比偏向 AutoData。

## 8. 主要贡献与启示

- **范式贡献**：首次将**预训练数据选择**纳入 LLM 智能体的自动化研究闭环，把"数据工程"从人工启发式升级为**可搜索的程序空间**，与 AIDE 式模型/代码搜索形成互补。
- **方法贡献**：提出以逐文档多轴特征 + 代理验证反馈驱动的**自演化搜索循环**，并给出一套可迁移的特征库（词法、类别、困惑度、LLM 标注）与搜索/评估协议。
- **实证贡献**：在受控同池同预算下证明**自动发现的数据选择配方优于 Random、DCLM-Baseline、PPL filter、RegMix**（val-bpb 显著，CORE 趋势一致但未显著），并系统刻画了不同 LLM 的**搜索偏好差异与配方分类学**。
- **实践启示**：
  - 数据选择的有效模式是"**复合评分 + 保覆盖选择**"，而非单指标排序或硬阈值过滤；
  - 在**已高度整理**的语料上，传统人工管线可能**负增益**，说明数据整理方法高度依赖源池状态，需按池重校准；
  - 跨规模迁移存在**收益衰减**，数据侧优化的红利在中小规模更明显。

## 9. 总体评价

这是一篇**立意清晰、协议严谨、结论克制**的工作。其最大价值在于**概念层面**——把数据选择接入自主研究闭环，并用受控实验证明"数据侧启发式可被自动搜索"，同时坦诚 CORE 显著性不足与规模上限。方法上，特征库与搜索循环设计合理，多尺度 + 多种子 + 配对检验增强了可信度；局限上，单语料单语言、模型规模偏小、算力成本不透明、下游证据偏弱，使其结论应被理解为"**方向性验证**"而非"普适性结论"。对后续研究而言，最有价值的延伸方向是：更大规模/多语种验证、代理—目标一致性的理论刻画、搜索成本与人工基线的**性价比对比**，以及将数据选择与架构/训练代码搜索**联合优化**，从而真正闭合"数据—模型—训练"三位一体的自动化研究循环。

## 摘要
传统数据系统在AI时代面临深刻局限：依赖人工构建的流水线，缺乏对异构数据的语义理解，并通过僵化、被动的处理方式运行。为应对这些挑战，我们提出一种新范式，称为数据智能体，旨在以最少的人工干预来管理、处理和分析数据。数据智能体自主执行广泛的数据相关任务，通过从人工设计转向自主编排、从字面操作转向语义解释、从被动处理转向主动处理，变革传统数据系统。我们的数据智能体系统包含六个组件：语义数据组织、语义算子、智能体式流水线编排与优化、反馈驱动的精化、记忆管理以及主动适应。在此基础上，我们还开发了两个专用智能体：数据分析智能体和数据科学智能体。在真实基准上的实验表明，我们的数据智能体相比最先进方法取得了显著性能提升。我们识别了开放性挑战，以指导构建完全自主数据系统的未来研究。

## Abstract
Traditional data systems face profound limitations in the AI era, relying on human-crafted pipelines, lacking semantic understanding of heterogeneous data, and operating through rigid, reactive processing. To address these challenges, we propose a new paradigm called the Data Agent, designed to manage, process, and analyze data with minimal human intervention. Data agents autonomously execute a wide range of data-related tasks, transforming traditional data systems by shifting from manual design to autonomous orchestration, from literal manipulation to semantic interpretation, and from reactive to proactive processing. Our Data Agent system includes six components: semantic data organization, semantic operators, agentic pipeline orchestration and optimization, feedback-driven refinement, memory management, and proactive adaptation. Building on this foundation, we also develop two specialized agents: the data analytics agent and the data science agent. Experiments on real benchmarks demonstrate significant performance gains of our data agent over state-of-the-art methods. We identify open challenges to guide future research in building fully autonomous data systems.

## 1. 核心问题与研究动机

- **背景**：数据系统（收集、存储、处理、管理、分析）在众多应用中至关重要，但传统系统（PostgreSQL/MySQL、数据仓库、Airflow 式人工编排管道）在 AI 时代难以支撑自主、智能的应用。云厂商（AWS Glue、SageMaker、Bedrock）虽实现了执行层面的自动化，但仍需人工定义处理逻辑、配置管道、指定数据模式，即"自动化执行但缺乏语义理解与意图驱动的自主编排"。
- **三大局限**：
  - **人工设计管道**：数据清洗等步骤依赖手写规则与领域知识，跨域迁移（如金融交易→医疗病历）需大量人工改写，扩展性与灵活性差。
  - **语义能力有限**：难以处理结构化+非结构化的异构、含噪数据；默认"查询时完整性"假设，无法对齐语义等价概念或推断聚合记录背后的意图。
  - **被动式处理**：仅响应预定义查询/报表，无法主动发现趋势、异常与必要更新，导致错失时机（如月度销售报告已滞后）。
- **核心主张（范式转变）**：提出 **Data Agent** 范式，实现三重跃迁——从**人工设计→自主编排**、从**字面操作→语义解释**、从**被动处理→主动处理**，形成"数据到决策"的闭环，最小化人工干预。
- **定位对比**（表 I）：与工业系统（AWS Glue）、LLM 编排栈（LangChain/AutoGen）、工作流编译器（AutoML/Airflow）、NL2SQL 系统（DIN-SQL/DAIL-SQL）相比，Data Agent 在自主端到端编排、语义感知处理、主动适应、数据中心化记忆四个维度上均为优势。
- **三大挑战**：自主管道编排（LLM 幻觉、缺乏领域知识、组合爆炸、质量评估难）、语义解释（LLM 调用昂贵）、主动处理（需持续预测、学习与调整）。

## 2. 方法论

### 2.1 总体框架（图 1）
给定数据集、自然语言任务与算子库（关系算子 + 语义算子），Data Agent 自主编排可执行管道、优化并执行。六大组件通过**事件驱动规则**激活（表 II），并采用两类通信机制：
- **A2A 协议**：智能体间交换 JSON 消息（含 `task_id`、`input`、`output`、`status`），编码任务图、执行状态、算子签名。
- **共享记忆与语义目录**：智能体以结构化格式（如 DataFrame）而非纯文本发布中间结果，供下游算子程序化处理。

### 2.2 语义数据组织
- 构建**树状语义目录**：节点为语义标签（如 basketball、NBA），边表示类别-子类关系，叶节点连接同类别语义相关节点。
- 为异构数据生成 embedding 并链接高相似数据点；建立**向量索引**。
- 查询时用关键词稀疏 embedding + 整句稠密 embedding 检索语义类别，再经语义索引定位相关数据。

### 2.3 关系算子与语义算子
- 语义算子包括语义过滤、语义分组、语义连接、语义抽取，可由 LLM 调用、LLM 生成程序或 embedding 匹配实现；结构化数据通过 **MCP 接口**调用 Spark/Flink/PostgreSQL/ClickHouse/DuckDB 等。
- **级联执行策略**（降低延迟与成本）：
  1. ANN 检索得到候选集；
  2. 基于上下置信阈值的剪枝（明确相关/明确无关）；
  3. 对模糊候选调用轻量 LLM 粗筛；
  4. 对最小化子集调用强 LLM 严格验证，输出结构化结果。

### 2.4 智能体式管道编排、优化与执行
- **多智能体分工**：任务理解、任务分解、数据画像、查询规划、推理、管道验证，经 A2A 协同。
- **流程**：NL 请求 → 结构化**任务图**（节点=子目标并匹配候选原子算子，边=执行/数据依赖）→ 规划智能体基于逻辑一致性与资源约束（内存、批大小、执行局部性）确定算子序列 → 验证智能体对非确定性算子（LLM 调用）做低成本 **dry run**（采样数据/模拟环境）并行比选。
- **示例**："哪个产品销量下滑最大，为什么？"→ (1) SQL 生成算子识别下滑最大产品；(2) 对评论表做语义过滤保留负面评论；(3) 语义抽取+分组按原因计数。
- **优化**：用语义目录估计语义算子基数，关系算子用标准方法，基于**动态规划**选择期望代价最低的管道。
- **事件驱动**：低置信度或执行错误触发反馈闭环，重新激活规划/验证智能体。

### 2.5 反馈闭环管理
- **交叉验证**：生成多条候选管道，按结果频次做多数投票，计算"覆盖分数"（该管道产出的所有结果的频次之和），选覆盖分数最高者。
- 为管道分配置信度分数，对低分者给出负面反馈；检测到错误/冲突时触发警告信号与纠正子流程。
- **注入 ground truth** 数据并对错误管道给负反馈；**合成数据一致性检查**：LLM 生成满足问题的数据，执行管道并评估质量。
- 防死循环：置信度阈值 + 最大重试次数；仅当重试后置信度仍低于临界值时才请求用户确认（用户为可选的高层校验者）。
- **错误分类**：语法错误（模式感知校验、算子签名检查、管道语法验证、静态 dry run、LLM 自检）与语义错误（多管道交叉验证、合成数据一致性检查、Pipeline2NL 一致性评估，用 embedding 余弦相似度或 LLM 蕴含打分）。

### 2.6 记忆管理
- **短期（工作）记忆**：会话历史、用户交互、中间推理链；容量受上下文窗口限制、会话结束即清空。
- **长期记忆**三类：**情景记忆**（用户偏好与经历，如"我偏好 PostgreSQL"）、**语义记忆**（客观事实与领域规则，如 PostgreSQL 查询重写规则）、**程序性记忆**（可复用技能与工作流模板）。
- **记忆算子生命周期**：
  - **抽取**：摘要压缩算子、结构化抽取算子（LLM function calling 或 NER，输出键值对/知识三元组）、价值评估算子（规则 + 信息熵、相关性、访问频次预测 → 重要性分数）。
  - **插入/更新/删除**：冲突解决规则为时新性优先、置信度优先、LLM 显式确认；冲突条目不覆盖而是以**版本图**保留并行版本，检索时按查询上下文动态选择；删除策略有价值驱动、时间驱动、指令驱动。
  - **检索**：语义检索（向量 top-k）+ 文本检索（BM25）+ 元数据过滤（时间范围、记忆类型、重要性），再沿版本图回溯以重建状态演化，最后用加权打分（语义相似度、文本匹配、时间新近性、重要性）融合重排。
  - **巩固**：压缩、抽象、链接碎片化记忆，形成元记忆与知识网络。
- **算法 1（记忆插入与冲突解决）**：计算新记忆 embedding → 向量检索锚点 → 图遍历找相关节点 → LLM 判定冲突 → 应用规则（如 Overwrite 则停用旧节点并加边 `target → Mnew`）→ 更新索引。

### 2.7 主动适应
- 持续监控指标（查询成功率、管道执行延迟、结果合理性分数、用户反馈信号）；显著偏差时触发**自动化根因分析**，诊断智能体基于近期交互、数据分布、智能体行为提出假设（知识过时、模式变更、新用户目标），经验证后主动修复（更新记忆先验、调整算子偏好、重新规划管道）。

### 2.8 专用变体
- **数据分析智能体**：面向异构数据（结构化+非结构化）的语义分析；含管道编排、反馈机制（执行失败负反馈、GAN 式"管道→文本描述"与任务描述匹配、检索历史相似任务/管道）、管道优化（下推低成本算子、重排语义算子，依赖语义基数/代价估计）、执行优化（批处理、embedding 过滤、级联 LLM、向量化执行提升 KV cache 命中率、按共享前缀分组）。
- **可视化智能体**：自主选图型、设计视觉编码、生成图例/标签/标题，避免误导性可视化。
- **数据科学智能体**：基础智能体包括数据发现、数据标准化、数据清洗、模型选择、参数选择、模型训练、模型评估；LLM 分解任务为子任务管道并按拓扑序自底向上并行执行，依据中间结果动态调整（智能体级修改 / 全局重规划），中间结果存入数据目录避免重复计算；反馈机制含 LLM 生成样本答案作 ground truth、注入含真值样本、用户评分（点赞/点踩）。

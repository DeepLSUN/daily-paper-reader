## 摘要
传统大语言模型（LLM）被限定在单个用户会话范围内，其知识局限于单次对话，无法学习随时间演变的用户偏好。现有的智能体记忆系统解决了这一局限，但通常仅在单用户层面运行，限制了可在用户之间共享、用以改进下游响应的公共知识。我们提出AIM（Agentic Interoperable Memory，智能体互操作记忆），一个统一的、隐私感知的记忆框架，使多智能体、多用户LLM系统能够持久地管理私有记忆与共享记忆。AIM动态地将信息分类为私有（仅限某一用户访问，其他用户不可访问）或公共（所有用户均可访问）。它实施索引级访问控制，使私有记忆仅能由其所有者检索，从而在保护敏感数据的同时，允许有益的共享知识提升协调性与一致性。我们还提出MUMBench（Multi-User Memory Benchmark，多用户记忆基准），一个包含四个领域中私有与可共享信息的多用户交互数据集。据我们所知，MUMBench是首个旨在评估多用户环境中多种记忆操作（包括检索、创建、更新和删除）的公开数据集。在MUMBench上进行的三次独立运行中，AIM实现了96.0%的可见性分类准确率、58.8%的严格操作准确率和70.5%的状态感知操作准确率。

## Abstract
Traditional large language models (LLMs) are scoped to individual user sessions, limiting their knowledge to a single conversation and preventing them from learning user preferences that evolve over time. Existing agentic memory systems address this limitation but generally operate at the individual-user level, restricting the public knowledge that could be shared across users to improve downstream responses. We introduce AIM (Agentic Interoperable Memory), a unified, privacy-aware memory framework that enables multi-agent, multi-user LLM systems to persistently manage private and shared memory. AIM dynamically classifies information as private, scoped to one user and inaccessible to others, or public, accessible to all users. It enforces index-level access controls so that private memories are retrievable only by their owner, protecting sensitive data while allowing beneficial shared knowledge to improve coordination and consistency. We also introduce MUMBench (Multi-User Memory Benchmark), a dataset of multi-user interactions containing private and shareable information across four domains. To our knowledge, MUMBench is the first public dataset designed to evaluate multiple memory operations, including retrieval, creation, update, and deletion, in a multi-user environment. Across three independent runs on MUMBench, AIM achieves 96.0% visibility classification accuracy, 58.8% strict operation accuracy, and 70.5% state-aware operation accuracy.

- **核心矛盾**：如何在单一共享记忆索引中，既让有益公共知识跨用户流通，又确保私有记忆对非所有者**结构性不可访问**。
- **整体贡献**：提出 AIM（Agentic Interoperable Memory），一个统一、隐私感知、可移植、系统无关的记忆服务；并发布 MUMBench，据称是**首个面向多用户、隐私感知、覆盖完整记忆操作生命周期（检索/创建/更新/删除）的公开基准**。

## 2. 方法论

### 2.1 核心思想
AIM 将多智能体记忆管理分解为共享演化记忆库上的**两条级联推理路径**：
- **写入路径**：操作检测 → 结构化提取 → 隐私可见性分类 → 去重 → 持久化；
- **读取路径**：可见性约束的稠密检索 → 标签级重打分 → LLM 重排序 + 时序融合。
- 两条路径均受统一的**可见性谓词 V** 约束，私有记忆在索引层面即被排除，而非仅在结果层过滤。

### 2.2 关键技术细节

- **问题形式化**：每条记忆 $m_i$ 包含内容 $c_i$、稠密嵌入 $e_i \in \mathbb{R}^d$、所属用户 $u_i$、智能体 $a_i$、可见性 $v_i \in \{\text{PUBLIC}, \text{PRIVATE}\}$、关键词标签 $\tau_i$、时间戳 $t_i$ 及元数据 $\mu_i$。
- **可见性谓词**：$V(u, m_i) = (v_i = \text{PUBLIC}) \lor (v_i = \text{PRIVATE} \land u_i = u)$，即公共记忆全局可访问，私有记忆仅所有者可访问；写操作还要求更新/删除仅限创建者（或创建智能体），实现多租户隔离。

### 2.3 算法流程（文字说明）

1. **多标签意图检测 $f_{op}$**：将消息映射到 $\{C,R,U,D\}$ 子集或 NONE。关键设计是**允许单条消息返回多个标签**（如"我刚搬到旧金山，能推荐餐厅吗？"同时触发 CREATE 和 READ），这与 Mem0 等每轮仅假设单一操作的方案不同。通过上下文学习 + 约束解码实现，并含隐私护栏（试图获取他人隐私的查询映射为 ∅）。
2. **结构化记忆提取 $f_{ext}$**：将消息映射为记忆元组列表 $\{(c_j, \tau_j, \mu_j)\}$，采用约束 JSON 模式解码。
3. **隐私感知可见性分类 $f_{cls}$**：LLM 分类为 PUBLIC/PRIVATE，提示中编码归纳偏置——公共信号（团队会议、组织公告、共享资源），私有信号（个人偏好、日程、直接消息、健康/财务等敏感数据）。该标签决定去重范围、检索过滤及更新/删除权限。
4. **上下文语义去重 $f_{dedup}$**：三分类（CREATE/UPDATE/NO-OP），比较集 $M_v$ 受范围限制——公共记忆对比全部公共记忆，私有记忆仅对比**同一用户**的私有记忆，防止通过去重信号跨用户泄露。整集序列化后单次前向传播判断语义重叠与时序取代。
5. **记忆表示与索引**：嵌入维度 $d=3072$；标签非空时计算标签增强嵌入 $e_i = \phi(\text{concat}(c_i, \tau_{i,1}, \tau_{i,2}, \dots))$，实现关键词引导的表示学习；向量索引采用 HNSW 算法，元数据字段（用户、智能体、可见性、标签）独立索引以支持谓词下推。
6. **三级级联检索**：
   - **Stage 1 可见性约束稠密检索**：将 $V(u,\cdot)$ 作为服务端过滤推入向量索引，返回 top-k 余弦相似候选，复杂度 $O(\log|M|)$；
   - **Stage 2 标签级语义重打分**：计算标签相似度 $s_{tag}$，候选须同时超过内容阈值 $\tau_{vec}$ 与标签阈值 $\tau_{tag}$，作为精度门控；
   - **Stage 3 LLM 重排序 + 时序融合**：点式 LLM 打分 $s_{rel} \in [0,1]$（保守打分，>0.7 需直接具体相关，不确定默认 ≤0.4），与时序归一化得分 $s_{rec}$ 做算术平均 $s_{final} = (s_{rel} + s_{rec})/2$，排序后截断至 k。
   - **LLM 调用预算**：仅 Stage 3 调用 LLM，且 Stage 2 激进剪枝使重排候选数远小于 k。
7. **模块化与消融**：每个组件（$f_{op}, f_{ext}, f_{cls}, f_{dedup}, \phi, g_\theta$）及向量索引均通过配置驱动的工厂模式实例化，可独立替换或禁用，支持消融研究。

## 6. 主要结论与发现

- **隐私分类是最强能力**：5 个模型平均可见性分类准确率均 ≥ 约 90%，GPT-5.4 达 **96.0%**，3 个模型在 Travel 域达 100%；表明规则 + LLM 的混合分类能可靠区分私有/公共。
- **操作准确率**：最佳模型 GPT-5.4-mini 取得 **58.8% 严格准确率、70.5% 状态感知准确率、89.5% 判官决策准确率**。严格→状态感知→判官的逐级提升反映**级联失败效应**：早期漏掉 create 会导致后续 update/delete 在严格评分下失败，但状态感知与判官评估能修正期望。
- **领域差异**：Coding 状态感知准确率最高（DeepSeek-V3.2 达 79.8%），因其多为简单 create-and-retrieve；Travel 最低（GPT-5.4-mini 62.7%），因多轮更新链复杂、操作边界模糊。
- **内容质量高**：最佳模型平均 91.6%，说明记忆提取质量良好（但不直接评估下游响应质量）。
- **小模型竞争力**：GPT-5.4-mini 在多数指标上最优或接近最优，提示高性能记忆系统无需以算力换质量。
- **LOCOMO 表现**：AIM 全面低于 Mem0（单跳判官分 J=0.280 vs 0.671），论文归因于 LOCOMO 为单用户基准、未体现 AIM 多用户核心能力，且隐私分类与去重阶段带来过度整合开销。

## 7. 优点

- **问题定位精准且有前瞻性**：首次系统性地将"多用户 + 多智能体 + 隐私访问控制 + 完整记忆生命周期"整合为统一框架，切中企业级与协作式 LLM 部署的真实痛点。
- **确定性访问控制**：可见性谓词在**索引层**强制（而非检索后概率性过滤），使私有记忆对非所有者结构性不可访问；去重比较集也做范围限制，避免通过去重信号跨用户泄露，安全设计较为严谨。
- **多标签操作检测**：允许单条消息同时触发多种操作（如 CREATE + READ），更贴近真实对话，优于单一操作假设的既有管线。
- **自动隐私标注**：由 LLM 推断可见性标签，无需用户手动标记，降低生产部署摩擦。
- **模块化与系统无关**：所有组件通过抽象接口与配置工厂解耦，可替换模型、ANN 算法或禁用组件，便于消融与跨厂商互操作。
- **基准贡献**：MUMBench 是首个面向多用户隐私感知、覆盖 create/read/update/delete/no-op 全操作的公开基准，包含对抗性查询与私有/公共记忆分布统计，对后续研究有独立价值。
- **三级级

联检索设计**在保证召回的前提下控制 LLM 调用成本：Stage 1 用服务端过滤 + HNSW 实现 $O(\log|M|)$ 候选生成，Stage 2 用标签阈值做廉价门控，仅 Stage 3 才调用 LLM 重排，且 Stage 2 的激进剪枝使重排候选远小于 $k$，兼顾精度与效率。
- **保守的 LLM 重排打分策略**：明确要求相关性分数 >0.7 须"直接且具体相关"、不确定默认 ≤0.4，降低 LLM 过度自信带来的假阳性检索，对隐私敏感场景更为稳妥。
- **时序与语义融合**：将归一化时序得分与 LLM 语义相关性等权平均，兼顾"近期性"与"相关性"两种记忆价值维度，简单但有效的启发式融合。
- **标签增强嵌入**：当标签非空时将关键词拼入嵌入文本，实现关键词引导的表示学习，使标签信息在稠密检索阶段即可发挥作用，而非仅在后期重排。
- **诚实报告负面结果**：论文如实报告 LOCOMO 上全面低于 Mem0，并给出合理归因（单用户基准 + 隐私/去重开销），未回避不利证据。

## 8. 不足与局限

- **缺少组件消融的定量证据**：虽强调模块化支持消融，但正文未报告逐组件（如去掉隐私分类、去掉标签重打分、去掉 LLM 重排）的定量对比，无法验证各阶段的实际边际贡献；三级级联中哪一级最关键、Stage 2 阈值 $\tau_{vec}/\tau_{tag}$ 的敏感性均未给出。
- **缺少与同类多用户记忆系统的直接对比**：MUMBench 上仅做 5 个 LLM 的横向对比，未与 Collaborative Memory、MemOS、Mem0 等多智能体/记忆系统在同基准上比较，"AIM 优于既有方法"的结论缺乏直接证据。
- **LOCOMO 对比公平性存疑**：AIM 仅 1 次运行而 Mem0 取 10 次平均，且 AIM 面向多用户、LOCOMO 为单用户，任务错配使该对比的参考价值有限。
- **基准规模与代表性有限**：MUMBench 仅 672 条交互、93 用户、4 领域、205 条唯一记忆，由 GPT-4o 合成 + 人工验证，存在合成分布偏差（如公共/私有比例、操作分布、领域选择）与人工验证指南本身的偏差；跨领域泛化到真实企业场景仍需验证。
- **绝对准确率偏低**：最佳严格准确率仅 58.8%，即使判官口径也仅 89.5%，说明完整记忆生命周期管理（尤其 update/delete 的时序依赖）仍是难题，距生产可用尚有距离。
- **隐私评估维度单一**：仅评估可见性分类准确率（二值 0/1），未评估真实的攻击场景（如 MEXTRA 式黑盒提取、成员推断、去重侧信道、LLM 重排提示注入），"结构性不可访问"的安全性缺乏对抗性实验支撑。
- **工程指标缺失**：未报告推理延迟、token 消耗、API 成本、吞吐等部署关键指标，难以评估三级级联在真实负载下的可行性。
- **检索相关性评估方差大**：每领域-运行仅 3 条打分交互，run-to-run 方差极大，该指标结论稳健性弱。
- **下游效用未验证**：内容质量与检索相关性均为中间指标，未评估共享记忆对下游任务（如响应质量、协作一致性、任务成功率）的实际增益，而这正是共享记忆的核心动机。
- **去重与更新的语义边界模糊**：论文自承作者间对 update vs create 边界存在分歧，且去重依赖 LLM 单次前向判断，跨用户公共记忆的整集序列化在记忆规模增长时可能面临上下文长度与一致性挑战。
- **冷启动与记忆膨胀**：未讨论记忆库长期增长下的索引维护、冲突消解与陈旧记忆淘汰策略。

## 9. 启发与展望

- **访问控制前移到索引层**是本文最有价值的设计范式：将隐私约束从"检索后过滤"变为"检索前谓词下推"，从根本上消除过滤前的信息泄露路径，可推广到 RAG、工具调用、多租户 SaaS 等场景。
- **"自动隐私标注 + 确定性谓词"的混合范式**在可用性与安全性间取得平衡：LLM 负责语义判断（哪些内容敏感），规则谓词负责强制访问（谁可见），二者职责分离，便于审计与合规。
- **多标签操作检测**提示记忆系统应放弃"每轮单操作"的简化假设，向更贴近真实对话的复合意图建模演进。
- **级联检索的分层成本控制**（廉价过滤 → 中等门控 → 昂贵重排）是控制 LLM 调用预算的通用模式，可迁移至其他 LLM-in-the-loop 检索系统。
- **未来方向**：①补齐组件消融与阈值敏感性分析；②引入对抗性隐私攻击评测（成员推断、提取攻击、侧信道）；③扩展到更大规模、真实多用户场景并报告工程指标；④评估共享记忆对下游协作任务的端到端效用；⑤研究记忆冲突消解、陈旧淘汰与长期一致性维护；⑥统一多用户基准，使 AIM、Mem0、MemOS 等可在同一协议下公平比较。

## 10. 总体评价

AIM 是一篇**问题意识清晰、系统设计完整、安全考量严谨**的工作，其核心贡献在于首次将"多用户 + 多智能体 + 隐私访问控制 + 完整记忆生命周期"整合为统一、可移植的记忆服务框架，并以索引层可见性谓词实现了较强的结构性隐私保证；配套的 MUMBench 填补了多用户隐私感知记忆基准的空白。主要短板在于**实证验证不足**：缺少组件消融、缺少同类系统直接对比、绝对准确率偏低、隐私安全性未经对抗性检验、工程指标与下游效用未评估。整体而言，AIM 在**框架与基准层面贡献突出，在实证充分性层面尚有明显提升空间**，适合作为多用户隐私感知记忆系统的参考架构与后续研究的起点。

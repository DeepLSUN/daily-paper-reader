## 摘要
大型语言模型（LLM）智能体必须从训练时见过的工具泛化到部署时未见过的工具。一个关键挑战是工具试用，即过度试用会浪费交互预算，而有选择地试用则能够探索不熟悉的工具。现有的基于结果的后训练使浪费性试用缺乏引导，而轮级监督可能抑制必要的探索。我们提出 ToolCompass，一种后训练框架，通过根据共享功能组织工具调用表示来引导工具试用。具体而言，ToolCompass 将每个功能类别建模为 von Mises–Fisher 分布，并同时减少跨领域的类内功能变异、增大类间功能分离。这种结构将经验从已见工具迁移到功能相似的未见工具，引导探索远离无关的替代工具。ToolCompass 不需要真实调用轨迹或对未见工具的访问，且不产生推理开销。在 AppWorld 和 FTRL 上的实验表明，在 GRPO、RFT 和 DMPO 上均取得一致增益。ToolCompass 相较于原始后训练，将 AppWorld OOD 任务成功率提升最多 10.71 个百分点，并在两个基准上均优于具有竞争力的基线。

## Abstract
Large language model (LLM) agents must generalize from tools seen during training to unseen tools at deployment. A key challenge is tool trialing, i.e., excessive trials waste the interaction budget, whereas selective trials enable exploration of unfamiliar tools. Existing outcome-based post-training leaves wasteful trials unguided, while turn-level supervision may suppress necessary exploration. We introduce ToolCompass, a post-training framework that guides tool trialing by organizing tool-call representations according to shared functions. Specifically, ToolCompass models each function class as a von Mises--Fisher distribution and jointly reduces intra-function variation across domains and increases inter-function separation. This structure transfers experience from seen tools to functionally similar unseen tools, directing exploration away from unrelated alternatives. ToolCompass requires no ground-truth call traces or unseen-tool access and incurs no inference overhead. Experiments on AppWorld and FTRL show consistent gains across GRPO, RFT, and DMPO. improves AppWorld OOD task success by up to 10.71 percentage points over vanilla post-training and performs best among competitive baselines on both benchmarks.

# ToolCompass 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体需通过外部工具（搜索引擎、应用 API）与环境交互，关键能力是从训练时**已见工具**（$\mathcal{U}_{train}$）泛化到部署时**未见工具**（$\mathcal{U}_{unseen}$），例如把 `amazon.search_products` 的经验迁移到 `spotify.search_songs`。
- **核心矛盾——工具试用（tool trialing）的两难**：
  - 过度试用会消耗有限的交互预算，甚至导致本可解决的任务失败；
  - 但对不熟悉工具而言，试错（尝试 → 观察报错 → 修正）又是学习其行为所必需的。
- **现有方法的不足**：
  - **结果导向后训练**（如 GRPO）：对整个轨迹施加同一优势值，无法区分"有用试用"与"浪费调用"；
  - **轮级监督**（如 MatchTIR、TRACE、StepTool）：虽降低调用次数，却可能抑制对未见工具必要的探索。论文试点实验显示 MatchTIR 虽减少 10.68 次调用，但 OOD 成功率反而下降 2.80 个百分点。
- **核心诊断发现**：GRPO 后训练的表示空间**按应用域（domain）聚类**，而非按**功能（function）**聚类——同域不同功能调用距离近，跨域同功能调用距离远，导致经验无法跨工具迁移。
- **研究问题**：如何在**不强化浪费性试用**的前提下，实现 OOD 探索？

## 2. 方法论

### 核心思想
不直接惩罚"试用的数量"，而是**引导"试用的方向"**——通过按共享功能组织工具调用的隐表示，使智能体在探索时优先考虑功能相关的工具。

### 关键技术细节

- **工具调用表示提取**（§3.1）：
  - 取每次工具调用**最后一个 token** 在第 $l$ 层的隐藏状态 $\mathbf{h}_t = H^{(l)}_\theta(s_t, a_t)$，该状态可概括所选工具、参数与交互上下文。
  - 经轻量投影头 $g_\psi$ 映射后做 L2 归一化，得到单位超球面上的表示 $\mathbf{z}_t \in \mathbb{S}^{d-1}$，使角度相似性成为自然度量。

- **vMF 功能建模**（§3.2）：
  - 每个功能类 $k$ 建模为 von Mises–Fisher 分布 $p(\mathbf{z}|c=k) \propto \exp(\beta \boldsymbol{\mu}_k^\top \mathbf{z})$，$\boldsymbol{\mu}_k$ 为原型方向，$\beta=1/\tau$ 为集中度。
  - **类内变异损失** $\mathcal{L}_{var}$：对观测到的功能标签做负对数似然，把同功能调用拉向同一原型；
  - **类间分离损失** $\mathcal{L}_{sep}$：用批次方向 $\bar{\mathbf{z}}_k$ 与其他类原型做对比，推开不同功能类；
  - **原型估计**：按 EMA 更新 $\boldsymbol{\mu}_k \leftarrow \text{Normalize}(\alpha\boldsymbol{\mu}_k + (1-\alpha)\bar{\mathbf{z}}_k)$，平滑跟踪演化中的表示空间（原型作 stop-gradient 目标）。

- **联合优化**（§3.3）：
  - 总目标 $\mathcal{L} = \mathcal{L}_{post}(\theta) + \lambda_{vMF}(\mathcal{L}_{var} + \lambda_{sep}\mathcal{L}_{sep})$，$\mathcal{L}_{post}$ 可为 GRPO / RFT / DMPO。
  - **关键优势**：仅需已见工具的功能类标签，**不需要真实调用轨迹、不访问未见工具、不引入推理开销**（投影头与原型在部署时移除）。

### 算法流程（文字版）
采样轨迹 → 计算 $\mathcal{L}_{post}$ → 抽取每个工具调用的表示并归一化 → 组成小批量 $B$ → 计算 $\mathcal{L}_{var}$ 与 $\mathcal{L}_{sep}$ → 用 $\mathcal{L}_{post}+\lambda_{vMF}\mathcal{L}_{vMF}$ 更新策略与投影头 → 用 EMA 更新观测到的功能类原型。

- **一致增益**：ToolCompass 在全部 ID/OOD/Total 指标、所有模型规模与所有后训练目标上均优于对应原始方法；AppWorld 总分最高提升 9.18 点（4B）与 9.01 点（9B），FTRL 提升约 5.7–10.8 点。

- **表示结构改变**：可视化显示表示由"按域聚类"转变为"按功能聚类"，且这种组织能扩展到未见功能类。

## 7. 优点

- **问题定位精准**：将 OOD 工具泛化失败归因于"表示按域而非功能组织"，并以此驱动方法设计，动机—诊断—方案逻辑闭环。
- **方法优雅且即插即用**：基于 vMF 的球面建模数学上自然，可无缝兼容 GRPO/RFT/DMPO；仅需功能类标签，无需黄金轨迹、教师模型或轮级打分器。
- **零推理开销**：投影头与原型训练后移除，不增加部署成本，工程落地性好。
- **实验扎实**：基线覆盖广、消融系统、跨数据集迁移与行为分析相互印证，"引导而非抑制"的结论有定量证据支撑。
- **可解释性分析充分**：t-SNE 可视化、球面核密度图、逐调用行为标注与案例研究共同支撑机理说明。

## 8. 不足与局限

- **依赖外部标注**：功能类与域标签均由 GPT-5.6-sol 自动标注，虽用 Fleiss's kappa 验证，但仍存在系统性标注偏差风险，且标注成本未量化。
- **功能类粒度固定且粗**：AppWorld 仅 14 类、FTRL 仅 9 类，平均类大小差异大（33.1 vs. 505.0），对功能边界模糊的工具可能不适用；对功能分类体系的敏感度未深入探讨。
- **OOD 定义受限**：未见工具的功能类**在训练时已被覆盖**，因此更接近"功能内跨域迁移"而非真正意义上的新功能泛化；语义 OOD（留出功能类）实验仅在 FTRL 小规模验证。
- **基准与规模有限**：仅 2 个基准、最大 9B 模型，未验证更大规模或真实开放工具生态；FTRL OOD 测试仅 32 条，统计置信度有限。
- **潜在交互风险**：表示塑形可能与宿主目标冲突，在任务分布差异极大时 $\lambda_{vMF}$ 需重新调参（论文虽显示一定鲁棒性）。
- **未涉及工具描述变化/新增工具持续学习**：对工具规格动态演化的场景缺乏讨论。

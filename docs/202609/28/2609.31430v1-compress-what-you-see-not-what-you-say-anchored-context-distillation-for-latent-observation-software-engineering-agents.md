## 摘要
工具观测主导了软件工程智能体的上下文，使长交互历史难以低成本维护。现有的上下文压缩方法可能会丢弃后续动作所需的信息，而让智能体适应软词元表示又可能损害其原始行为。为在减少上下文的同时保留动作关键信息和智能体行为，我们将潜在观测、硬动作（LOHA）——一种将压缩历史与精确引用所需文本分离的上下文布局——与锚定上下文蒸馏（ACD）相结合，后者是一种在约束行为漂移的同时实现潜在读取的训练方法。LOHA 将较早的工具观测压缩为软词元，同时以文本形式保留智能体自身的轮次和最近 K 条观测，从而提供对历史信息的紧凑访问和对近期内容的精确访问。为使智能体能够使用这种表示，ACD 将基座模型的全文预测蒸馏到潜在视图中，同时将其在纯文本输入上的行为锚定到同一基座模型。在 SWE-bench Verified 上，K=3 使 Qwen3-4B 的每次调用上下文减少 43%，使 SWE-Master-4B-RL 减少 57%，解决率分别为 12.1% 和 21.8%，而未压缩基座模型分别为 14.5% 和 27.5%。单次运行的新近度扫描在 K=8 时达到 14.4% 和 23.0%，更大的窗口通常更有利于任务性能而非压缩。在 32K 词元限制下，使用 K=3 的 Qwen3 在 199 个实例的子集上解决了 21.1%，而使用全文的同一适配智能体仅解决 11.1%。在并发单 GPU 服务中，其实例吞吐量达到该全文智能体的 1.9 倍。

## Abstract
Tool observations dominate the context of software-engineering agents, making long interaction histories costly to maintain. Existing context compression methods can discard information needed by later actions, while adapting agents to soft-token representations can compromise their original behavior. To reduce context while preserving action-critical information and agent behavior, we combine Latent Observations, Hard Actions (LOHA), a context layout that separates compressed history from text needed for exact reference, with Anchored Context Distillation (ACD), a training method that enables latent reading while constraining behavioral drift. LOHA compresses older tool observations into soft tokens while retaining the agent's own turns and the last K observations in text, providing compact access to historical information and exact access to recent content. To enable the agent to use this representation, ACD distills the base model's full-text predictions into the latent view while anchoring its behavior on plain-text inputs to the same base model. On SWE-bench Verified, K=3 reduces context per call by 43% for Qwen3-4B and 57% for SWE-Master-4B-RL, with resolve rates of 12.1% and 21.8% versus 14.5% and 27.5% for their uncompressed bases. A single-run recency sweep reaches 14.4% and 23.0% at K=8, with larger windows generally favoring task performance over compression. Under a 32K-token limit, Qwen3 with K=3 resolves 21.1% of a 199-instance subset versus 11.1% for the same adapted agent using full text. In concurrent single-GPU serving, it achieves 1.9 times that full-text agent's instance throughput.

# 论文总结：Compress What You See, Not What You Say（LOHA + ACD）

## 1. 核心问题与研究背景

- **工具观测主导上下文**：在软件工程智能体的交互轨迹中，工具观测（文件内容、搜索结果、堆栈跟踪、测试日志等）平均占轨迹 token 的 69%（基于 CoderForge 轨迹统计），导致长交互历史的维护成本极高。
- **现有压缩方法的缺陷**：观测掩码、历史摘要、子任务折叠、选择性剪枝等方法虽能缩短历史，但难以判断哪些细节会被后续动作依赖，可能丢弃关键信息。
- **编码任务的特殊需求**：`str_replace` 编辑需要与源文本**精确匹配**，语义摘要无法替代逐字内容；信息一旦被压缩丢弃，往往需要重新检索才能行动。
- **软词元压缩的适配难题**：将文本编码为连续嵌入（soft token）虽可压缩，但解码器需同时学会：①理解压缩后的历史；②复现工具调用所需的精确细节；③不损害原有的推理、工具调用与代码修改能力。
- **两个核心研究问题**：如何将压缩历史与精确文本访问结合？如何让智能体学会使用该表示而不破坏其行为能力？

## 2. 方法论：LOHA + ACD

### 2.1 核心思想
- **LOHA（Latent Observations, Hard Actions）**：压缩智能体"所见的观测"，而非"所说的话"。旧工具观测→软 token；系统提示、任务描述、智能体自身轮次、最近 K 条观测→保留原文。
- **ACD（Anchored Context Distillation）**：在教智能体读取潜在观测的同时，用行为锚定约束其原始行为不发生漂移。

### 2.2 LOHA 上下文布局
- **渲染方式**：每条观测保持原始位置与工具响应包络；被压缩观测的 body 用 memory 标记包裹，按 1,024 token 窗口编码，替换为软 token（默认 16× 压缩比，n token → n/16 软 token）；周围包络仍为硬 token，不引入额外 header。
- **Hard-Last-K 新近度策略**：给定 m 条观测，第 i 条观测的表示
  - `r_K(o_i | m) = o_i`（若 i > m−K），否则 `E(o_i)`
  - 新观测先以文本进入，离开窗口后才可被压缩；旧观测仍可通过潜在表示访问，精确内容可用现有工具重新检索。
  - K 在推理时选择、无需重训练；K 越大保留越多原文、压缩率越低。

### 2.3 ACD 训练方法
- **学生结构**：冻结的 LCLM 编码器 + 可训练 MLP 适配器（9.2M）+ 基座解码器 + 低秩 reading patch；解码器归一化增益可训练（初始化自基座），其余参数冻结。
- **低秩 patch 参数化**：对每个投影 `W_0`，令 `ΔW = W_LCLM − W_0`，参数化为 `W_θ = W_0 + AB`，rank ≤ ρ；A、B 初始化为 ΔW 的 rank-ρ 截断 SVD。覆盖全部 252 个解码器投影，ρ=64 时约 132M 参数。
- **两个视图**：
  - 全文视图 `x_H`：所有观测为硬 token；
  - 潜在视图 `x_L`：所有观测 body 被压缩。
- **两个损失项**（总损失 `L = L_distill + λL_anchor`，λ=1）：
  - **蒸馏项 `L_distill`**：让学生从潜在视图做出的预测，对齐冻结基座模型从对应全文上下文做出的预测（前向 KL）；并附加 read-back 问题的交叉熵，直接监督从压缩观测中恢复字面内容（答案占约 3% 监督位置）。
  - **锚定项 `L_anchor`**：在全文本输入上，约束适配模型预测接近同一基座模型的参考分布，抑制行为漂移。
- **教师选择**：两项均以**原始基座模型**为教师（自锚定）——既提供潜在读取的全文预测目标，又提供行为保持的参考分布；锚定项对压缩适配器无梯度，仅更新 patch 与归一化增益。
- **散度估计**：教师冻结，预计算并缓存每个监督位置的 top-k（k=64）log-prob 及残余概率质量；训练时对缓存 token + 一个尾部桶计算 KL，构成全词表 KL 的下界。
- **训练与推理**：离线训练（在记录的轨迹前缀上评估，非学生自生成交互）；推理时使用原生函数调用接口，短于 128 字符的观测始终保持硬 token；训练使用完全潜在与完全全文两个端点，混合窗口仅用于推理。

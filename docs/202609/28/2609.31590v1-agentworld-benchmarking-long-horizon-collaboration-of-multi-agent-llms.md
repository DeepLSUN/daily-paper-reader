## 摘要
现有多智能体基准测试主要在竞争性环境中、20步以内的短时程交互中进行评估，或仅简单聚合个体表现，因而无法隔离并凸显基于LLM的智能体真正的协作能力。我们提出AgentWorld，一个包含100个人工标注任务（以及100个增强变体）的基准，用于评估长时程、多智能体协作。任务在一个丰富的MMORPG沙盒中跨越50+轮交互，并要求3-20个具有非对称角色与能力的智能体在黑箱设定下通过通信、联合规划与资源共享进行协调，其中每个智能体独立行动且无法访问其他智能体的内部状态。为了在传统二元任务成功率之外量化协作有效性，我们提出因果协作有效性（Causal Collaboration Effectiveness, CCE），一种基于图的指标，用于追踪智能体动作之间的因果依赖关系，并衡量团队努力中实际促成结果的比例。使用Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini和DeepSeek R1-70B进行的实验表明，即使表现最好的模型也仅达到52.0%的任务成功率，并存在系统性失败模式，包括通信中断、角色混淆以及无法在多轮中维持共享计划。AgentWorld完全开源。

## Abstract
Existing multi-agent benchmarks primarily test in competitive settings, short-horizon interactions under 20 steps, or simply aggregate individual performance, failing to isolate and highlight genuine collaboration capabilities of LLM-based agents. We introduce AgentWorld, a benchmark of 100 human-annotated tasks (with 100 augmented variants) for evaluating long-horizon, multi-agent collaboration. Tasks span 50+ interaction rounds across a rich MMORPG sandbox and require 3-20 agents with asymmetric roles and abilities to coordinate through communication, joint planning, and resource sharing under a blackbox setting where each agent acts independently without access to others' internal states. To quantify collaboration effectiveness in addition to conventional binary task success, we propose Causal Collaboration Effectiveness (CCE), a graph-based metric that traces causal dependencies between agent actions and measures what fraction of a team's effort actually contributed to the outcome. Experiments with Gemini 3 Flash, Claude Haiku 4.5, GPT-5 Mini, and DeepSeek R1-70B show that even the best model achieves only 52.0% task success, with systematic failure modes including communication breakdowns, role confusion, and inability to maintain shared plans across rounds. AgentWorld is fully open-source.

# AgentWorld：多智能体 LLM 长时程协作基准测试——论文总结

## 1. 核心问题与研究动机

- **背景**：随着 LLM 智能体从单轮推理走向自主工具使用、规划与多步执行，多智能体协作（MAC）成为关键能力。真实世界任务（软件开发、科研、复杂运营）需要多个专业化智能体围绕共同目标协调。
- **现有基准的三大缺陷**：
  - **时程过短**：多数基准任务时程在 10–20 步以内，不足以评估持续协调能力。
  - **混淆低级控制与协作**：如 Minecraft 类环境要求智能体投入大量精力做精细 3D 导航、方块放置等操作，协作能力难以在评分中体现。
  - **重涌现行为轻可测任务**：如 Project Sid 等大规模社会模拟关注涌现社会行为，缺乏有明确可测结果的具体任务。
- **整体含义**：作者主张需要一个能**隔离协作能力**、具备**长时程**、**非对称角色**、**黑箱交互**的基准，以系统性刻画当前基础模型的协作短板。

## 2. 方法论

### 2.1 核心思想
- 构建一个"中间地带"环境：足够复杂以支持多样长时程协作任务，又通过高层 API 抽象掉低级控制，使分数主要反映联合规划与协调质量。
- 在黑箱设定下，每个智能体独立行动，无法观测他人的内部状态、观察或动作历史，协调只能通过环境路由的显式聊天消息完成。

### 2.2 仿真环境（基于 Kaetram）
- 持久化 2D 世界：1056×768 瓦片、9 种生物群系、380+ 物品、144 种怪物（Level 1–250+）、70+ NPC、1531 个可采集资源节点、8 种技能。
- **13 个高层 API 工具**（如 `move`、`attack`、`harvest`、`craft`、`transfer`、`chat`），每个工具封装多步游戏机制（如 `attack_entity` 自动完成寻路、攻击、战斗、拾取）。
- **回合制编排**：每轮每智能体顺序获得新观察 → 选择一个 API 调用 → 等待结算，保证确定性回合顺序。
- 每个智能体每轮收到结构化文本观察 + 任务特定指南文档（配方、怪物属性、资源位置）。

### 2.3 任务设计
每个任务包含：主目标、非对称角色配置（技能/出生点/初始物品）、回合预算、任务特定上下文文档、Python 成功判定函数。
- 设计原则：无单一智能体拥有全部所需技能或资源。
- 示例：Task 67（资源商队，8 智能体跨 3 生物群系）、Task 80（10 智能体节日筹备）、Task 100（16 智能体大陆勘测）。

### 2.4 评估指标
- **SR（任务成功率）**：由每任务的 Python 验证器检查最终游戏状态（可选检查轨迹），全部条件满足才算成功。
- **PSR（部分成功率）**：各检查点达成比例的平均值，为软指标。
- **CCE（因果协作有效性）**：基于图的指标，构建**因果动作图（CAG）**：
  - 节点 = 所有动作；有向边 = "x 因果促成 y"；图是 DAG（因果只能沿时间向前流动）。
  - 算法：先识别**成功动作集 S**，再**逐轮反向追踪**（BFS 式），每轮用 LLM 判断哪些动作因果促成了已识别的贡献动作，累积贡献集 C。
  - **CCE = |C| / |T|**；任务完全失败则 CCE = 0。
  - **PAC（单智能体贡献）** = |C ∩ T_i| / |T_i|，用于识别是否由少数智能体包办。
  - 关键设计：LLM 只做**客观二元因果判断**（"捕虾是否促成了后续转移虾？"），而非主观质量评分（"给协作打 1–5 分"），从而提高跨评判模型的可复现性。
  - 采用**宽松纳入策略**：边缘性有帮助的动作也计为贡献，故 CCE 应读作真实有用动作比例的**上界**。
  - 优化：按资源/位置/通信渠道剪枝、批量查询、时间窗口限制，避免 O(|T|²) 查询。

## 3. 实验设计

### 3.1 数据集 / 场景
- **100 个人工标注主任务 + 100 个 LLM 增强变体**（由 Claude Opus 生成，变化目标、出生点、初始物品，经人工验证）。
- 8 大类别：战斗、制作、采集、交易、探索、生存、建造、协调（战斗与制作最多，协调与建造最少）。
- 任务规模：3–20 个智能体（多数为 3 个，长尾至 20 个）；时程 25–55 轮，平均 38 轮预算。
- 由 5 名标注者按预设类别分布设计，经两轮 LLM 试点实验校准回合预算，直到仅剩智能体错误。

### 3.2 对比模型与基线
- **四个前沿模型**：Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini、DeepSeek R1-70B（统一系统/用户提示与工具定义）。
- 附加模型：Muse-Glimmer-30B、Gemma 4 26B A4B（增强集 v1）。
- **五个基线**：随机动作（无 LLM）、单智能体（所有角色与物品给一个智能体）、无通信、共享计划无通信、Oracle 通信（一个智能体可见所有消息）。
- **消融实验**（35 任务子集，Gemini 3 Flash）：去除非对称角色信息、缩短时程（50→10 轮）、随机出生点、去除任务文档。

## 5. 实验数量与充分性

- **主实验**：4 个模型 × 2 个数据集（主集 100 任务 + 增强集 100 任务），报告 SR / PSR / CCE，另含回合数与聊天数。
- **基线对比**：6 种设定（含 Oracle 通信）在 Gemini 3 Flash 上的对照。
- **消融**：4 个设计组件在 35 任务子集上的消融。
- **稳定性**：Gemini 3 Flash 在 35 任务子集上跑 3 次（温度 0.7，种子 42/819/314），SR 均为 54.3%。
- **CCE 鲁棒性**：用 3 个不同家族的评判模型（GPT-4.1、Claude Sonnet 4、Llama-4 Maverick）重算 CCE，排序完全保持，绝对值漂移 ≤ ~0.05。
- **人类一致性验证**：84 条动作贡献判断，人类与 GPT-4.1 评判一致率 82%（Cohen's κ = 0.64，"substantial"）；两个评判模型之间 κ = 0.66（7298 条决策），说明人类与评判者的一致性约等于两个评判者之间的一致性。
- **通信失败模式分析**：聚类 100 任务中 Gemini 3 Flash 的聊天消息为 6 类（共 61 条错误）。
- **总体评价**：实验设计较充分、公平（统一提示与工具定义、固定回合协议、多评判模型验证、人类标注交叉验证、种子重复）。但消融仅在 35 任务子集、单一模型上完成，方差分析也仅限单模型，统计显著性未严格建立，部分模型（Gemma）结果为临时性。

## 6. 主要结论与发现

- **最佳模型仅 52.0% SR**（Gemini 3 Flash），依次为 Claude Haiku 4.5（45.0%）、GPT-5 Mini（36.0%）、DeepSeek R1-70B（20.0%）；增强集上全面大幅下降（Gemini 52→24%，DeepSeek 20→10%）。
- **CCE 极低**：最佳模型仅 0.320，即不到 1/3 的动作因果促成成功；DeepSeek 为 0.125，近 88% 动作被浪费。条件于成功任务时，Claude 的单任务协作效率最高（0.653 vs Gemini 0.609），GPT-5 Mini 最低（0.571）。
- **通信量 ≠ 协作质量**：GPT-5 Mini 聊天最多（44.1 条/任务）却仅排第三；DeepSeek 聊天最少（7.5）排最后；Gemini 通信适中（11.0）却最优。DeepSeek 平均第 5 轮才首次发言，错过早期协调窗口。
- **任务难度分化明显**：生存最易（50–100% SR），协调（0–50%）、建造（0–60%）、交易（8–46%）最难。
- **部分成功与完全成功存在持续差距**：Gemini PSR 71.5% vs SR 52.0%，说明智能体能启动协作但晚期协调失败。
- **基线校准**：随机动作 5.7%、单智能体 28.6%、无通信 22.9%、共享计划无通信 17.6%、Oracle 通信 60.0%。即使 Oracle 通信仍有 40% 失败，说明困难本质源于长时程规划与资源分配。
- **系统性失败模式**：通信中断、角色混淆（重复工作或越权）、无法跨轮维持共享计划。
- **通信错误类型**（占比）：陈旧与冗余 37.7%、误识别 16.4%、事实错误 14.8%、过早宣布完成 11.5%、非实质性输出 11.5%、逻辑不一致 8.2%。
- **设计组件均有贡献**：去除任务文档（54.3%→29.4%）和缩短时程（→37.1%）影响最大，随机出生点影响最小（→51.4%）。

## 7. 优点

- **精准的问题定位**：明确指出现有基准混淆低级控制与协作、时程过短、重涌现轻可测任务三大缺口，并在 Table 1 中系统对比。
- **环境设计的"中间地带"思路**：用 13 个高层 API 抽象掉操作复杂度，使分数真正反映协作而非控制熟练度，并通过消融验证该设计目标。
- **CCE 指标的创新与严谨**：将 LLM 角色限制为二元因果判断而非主观打分，配合多评判模型稳定性验证、人类一致性验证（κ=0.64）和上界声明，显著提升可复现性。
- **黑箱 + 非对称角色 + 长时程**的组合在同类工作中独特（对比 Overcooked、Minecraft、SmallVille 等）。
- **丰富的基线体系**：包含 Oracle 通信上界与"共享计划无通信"等反直觉对照（共享计划反而略降性能，揭示计划需可修订）。
- **完整开源**：仿真环境、任务定义与验证器、评估脚本、标注平台全部开放。
- **可复现性细节**：固定回合顺序、统一提示、种子重复、报告 PSR/CCE 多维度指标。

## 8. 不足与局限

- **CCE 仍依赖 LLM 评判**：虽然二元因果判断比主观打分更稳定，但 κ=0.64 属于"substantial"而非完美，仍有约 18% 与人类判断不一致；宽松纳入策略使 CCE 只能作为上界解读。
- **算力与成本信息缺失**：未报告 GPU 型号/数量、推理总 token 或成本，难以评估可复现性与资源门槛。
- **消融与方差分析覆盖面有限**：消融仅在 35 任务子集、单一模型（Gemini 3 Flash）上完成；三种子重复也仅单模型，未建立跨模型的统计显著性。
- **失败任务 CCE 恒为 0 的定义**：虽然简化，但可能掩盖失败轨迹中部分有效协作的价值，使 CCE 分布偏斜。
- **增强变体质量**：由 LLM 生成、人工抽检 10%，虽报告 100% 保留协作需求与角色非对称性，但难度校准存在个别不确定（如替换敌人是否更弱）。
- **应用限制**：任务局限于 MMORPG 沙盒（Kaetram），其协作模式（采集→制作→转移流水线、战斗分工）未必直接迁移到软件开发、科研等真实协作场景。
- **模型与时间局限**：评测的四个模型均为 2026 年前后的前沿模型，结论的时效性有限；Gemma 结果为临时性、仅覆盖部分评分任务。
- **通信失败分析样本较小**：仅 61 条错误消息、来自单一模型（Gemini 3 Flash），统计代表性有限。

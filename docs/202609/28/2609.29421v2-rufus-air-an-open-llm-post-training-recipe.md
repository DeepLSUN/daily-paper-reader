## 摘要
Rufus-Air 是在 GLM-4.5-Air-Base（106B-A12B）上的一套开放且可复现的后训练方案，由八个阶段组成的串行流水线：SFT、推理 RL、代码 RL、指令遵循 RL、通用智能体、代码智能体、搜索智能体以及 RLHF。我们记录了复现该方案所需的数据、奖励设计、基础设施、阶段顺序以及各阶段结果。各阶段从基础能力逐步推进到高级能力，并从可验证的硬性奖励过渡到更软的基于评判器的信号。训练建立在开源组件和公开数据之上，其中大部分数据按原发布形式使用，无需新的人工标注，也不依赖自研的蒸馏教师模型。我们的主要发现是：(i) 多样、高质量的 SFT 奠定了坚实的能力下限；(ii) 难度过滤使 RL 提示保持在有效的学习范围内；(iii) 奖励可靠性为阶段排序提供了一个实用原则；(iv) 基础设施与工程选择是方案的一部分，而不仅仅是实现细节。Rufus-Air 相比官方发布的 GLM-4.5-Air 后训练版本有所提升，并与规模相近的开放模型相比具有竞争力。

## Abstract
Rufus-Air is an open and reproducible post-training recipe on GLM-4.5-Air-Base (106B-A12B), organized as a serial pipeline of eight stages: SFT, Reasoning RL, Coding RL, Instruction-Following RL, General Agent, Coding Agent, Search Agent, and RLHF. We document the data, reward design, infrastructure, stage order, and stagewise results needed to reproduce the recipe. Stages progress from basic to advanced capabilities and from hard, verifiable rewards to softer judge-based signals. Training builds on open-source components and public data, much of it used as released, without new human annotation or an in-house distillation teacher. Our main findings are that (i) diverse, high-quality SFT establishes a strong capability floor; (ii) difficulty filtering keeps RL prompts within a productive learning range; (iii) reward reliability provides a practical principle for ordering stages; and (iv) infrastructure and engineering choices are part of the recipe, not just an implementation detail. Rufus-Air improves over the official GLM-4.5-Air post-trained release and is competitive with similarly sized open models.

## 2. 方法论

### 2.1 核心思想

- **串行八阶段流水线**：SFT → Reasoning RL → Coding RL → Instruction-Following RL → General Agent → Coding Agent → Search Agent → RLHF，每个阶段在上一个阶段产出的 checkpoint 上继续训练。
- **两条排序轴**：能力上从基础到高级；奖励上从硬可验证奖励逐步过渡到软评判/模型奖励。
- **四条总体结论**：SFT 是能力构建阶段而非预热；难度过滤维持 RL 学习区间；奖励可靠性决定阶段顺序；基础设施是配方的一部分。

### 2.2 各阶段关键技术细节

- **SFT**：
  - 数据：9.01M 样本、44.5B 原始 token、66.7M 对话轮（23.5M 有监督），掩码后 27.0B 训练 token；六大类别（General Agent、General Chat、STEM、Math、Code、Coding Agent），17 个公开数据集。
  - 预处理：格式归一化、交错思考监督（保留完整 thought–action–observation 链）、验证与长度过滤（上限 120K）。
  - 去污染：8-gram 重叠检测 + 穷举 8-gram + 稠密检索（Llama-NV-Embed-Reasoning-3B），共移除 4,187 个样本。
  - 训练：3 epoch，batch 4096，AdamW，lr 5e-5 → 5e-6 余弦，128K 上下文；取 checkpoint 3799 进入 RL。

- **Reasoning RL**：
  - 数据：121,161 提示（Math 47.7%、Science 35.7%、Puzzles 16.7%），25.07M token。
  - 过滤：正确性过滤（GPT-OSS-120B 至少一次成功）+ 可学习性过滤（解决率 >0.8 或全失败则丢弃）。
  - 奖励：Math-Verify、生成的 Python checker、模糊字符串匹配，均为二值低噪声。
  - 算法：GSPO + Rollout Routing Replay + 长度惩罚（相对组内最短正确轨迹）+ DAPO 式在线动态采样（均值奖励 ∈ (0, 0.8]）。

- **Coding RL**：
  - 数据：29,405 题（EvolveCoder 50.1%、Nemotron 31.9%、Dolci 10.6%、ADR 7.3%），函数式与 stdin/stdout 两种模态。
  - 过滤：schema 验证、SHA-256 去重、LiveCodeBench v6 泄漏检查、教师可解性筛选、drop-all-pass 难度筛选。
  - 奖励：二值，沙箱执行至多 50 个测试，SHA-256 种子确定性子采样。
  - 训练：GSPO，128 prompts × 64 samples，64K → 128K 响应预算扩展。

- **IF RL**：
  - 数据：14K 单轮多约束合成提示（2–6 原子约束，Qwen3-235B-A22B 增强 + Python 验证函数）+ 13K 多轮对抗合成对话（平均 6.1 轮、2.7 rubric）。
  - 奖励：rubric-based 二值奖励，全部满足才给正奖励；代码可验证 rubric + LLM judge rubric；刻意排除“可选”rubric 以避免长度偏置。
  - 训练：GRPO，256 prompts × 16 samples，16K 响应预算，lr 1.5e-6，90 步。

- **General Agent**：
  - 数据：AgentWorldModel（AWM）10K 单服务器 MCP 任务、1K 合成环境，经正确性与难度过滤后约 2K 任务。
  - 奖励：AWM 代码验证函数二值化；移除 LLM judge 与格式奖励。
  - 训练：GRPO + DAPO 动态采样 + R3。

- **Coding Agent**：
  - 数据：Endless-Terminal、SETA-Env、Scale-SWE，过滤后约 4K 任务。
  - 环境：Harbor 任务格式，单一 `execute_command` 工具，预烘焙容器模板。
  - 奖励：任务自带 verifier 二值化；将基础设施噪声样本标记为 aborted 并从组优势计算中移除。

- **Search Agent**：
  - 数据：MiroVerse 提取 36,614 问答对，两轮过滤后约 2.2K 题。
  - 环境：Web Search、Web Scrape、Python 三工具，训练最多 100 次工具调用、128K 轨迹预算。
  - 奖励：LLM judge 连续 [0,1] 分；要求至少 2 次成功工具调用；malformed 调用按比例缩放；无最终答案 −0.1；移除格式奖励。
  - 算法：GRPO + mean-only 组优势（Dr. GRPO 风格），保留 per-sequence 长度归一化，KL 系数 1e-3。

- **RLHF**：
  - 奖励模型：Skywork-Reward-V2-Qwen3-8B（开源）。
  - 数据：HH-RLHF 过滤后 75,815 prompts（仅用 prompt，奖励由 RM 对 on-policy rollout 生成）。
  - 奖励：原始 RM 分数 + 线性长度惩罚；GRPO 优化。

### 2.3 基础设施

- **Rufus-Slime**：基于 Slime 改造，Megatron-LM 训练后端 + SGLang rollout 引擎。
- **Rufus-Gym**：基于 Strands Agents 改造，提供 ReAct 式 agent loop、token-in/token-out rollout、Firecracker microVM 沙箱（自托管 E2B）、Ray 分布式 rollout。

## 6. 主要结论与发现

- **SFT 奠定能力下限**：SFT checkpoint 3799 在 IFEval（+5.3）、IFBench（+24.2）、AIME 25（+6.6）、AIME 26（+3.5）上已超过含 RL 的官方 GLM-4.5-Air，仅 GPQA 落后 5.7。
- **难度过滤维持学习区间**：各 RL 阶段通过预过滤与在线动态采样，将提示保持在“可学习”区间，形成自动课程。
- **奖励可靠性指导阶段排序**：硬可验证奖励阶段先跑，软评判/模型奖励阶段后跑；IF RL 虽用 judge 但因任务接近模型已有能力而早跑；RLHF 风险最高故最后跑。
- **基础设施是配方一部分**：token-in/token-out rollout、一致 chat template、可靠沙箱、大 batch + R3 对稳定 RL 至关重要。
- **最终结果**：Rufus-Air 在除 Arena-Hard v2 Creative Writing 外的所有报告 benchmark 上领先官方 GLM-4.5-Air，并与 INTELLECT-3、Nemotron-3-Super 竞争；优势集中在指令遵循与 agentic 行为，而非数学/科学。
- **最大单阶段提升**：Multi-challenge 在 IF RL 下 +24.7；Arena-Hard v2 CW 在 RLHF 下 +14.4；Tau2-Retail 在 General Agent 下 +9.8；Coding Agent 因算力预算限制提升最小（+1.4 / +2.2）。

## 7. 优点

- **开放可复现**：全部基于开源组件与公开数据，无新人工标注、无自研蒸馏教师，数据来源与许可在附录 D 逐条列出。
- **报告粒度细**：把数据、奖励、训练配置、基础设施、逐阶段结果写在一起，而非分离成“系统卡”式描述。
- **阶段顺序有原则**：以“奖励被 hack 的暴露程度”而非奖励格式排序，给出可操作的经验原则。
- **难度过滤系统化**：预过滤 + 在线动态采样，形成自动课程，减少人工调参。
- **基础设施披露充分**：token 保真、沙箱设计、分布式 rollout、R3、FP8/BF16 混合精度等工程细节均有说明。
- **诚实的负面结果**：明确报告 RLHF 三个数据集的负面发现、Coding Agent 未收敛、Search Agent 奖励的残余漏洞、AIME 在 Reasoning RL 下的下降。
- **评估协议透明**：附录 E、F、G 详细说明公开基线来源、Search Agent 评估设置、Tau2-Bench 用户模拟器影响。

## 8. 不足与局限

- **阶段顺序非最优证明**：顺序由早期实验与算力预算塑造，“是有效的顺序，而非被证明最优的顺序”；未探索多教师 on-policy 蒸馏后合并专家的替代方案。
- **Coding Agent 未收敛**：因算力限制只用了约 4K 任务，结果仅证明环境/奖励/rollout 端到端可用，不代表收敛性能；SWE-bench 增益未保留到最终 checkpoint。
- **跨阶段 benchmark 不统一**：没有单一 benchmark 贯穿所有阶段，某 benchmark 在中间阶段间的变化无法归因于具体某一阶段。
- **部分数值协议不一致**：LiveCodeBench、Tau2-Retail 等在不同表中协议不同，不可直接比较；IF RL checkpoint 的 GPQA 在两张表中数值不同（71.1 vs 73.36）。
- **搜索奖励仍有漏洞**：工具调用 gate 只验证调用执行，不验证答案依赖返回内容；记忆型答案 + 附带工具调用仍可残留。
- **RLHF 依赖单一开源奖励模型**：Skywork-Reward-V2-Qwen3-8B；未尝试针对风格调优的奖励模型，导致 Creative Writing 落后于 GLM-4.5-Air 与 Nemotron-3-Super。
- **去污染无法完全排除泄漏**：n-gram 与嵌入过滤无法覆盖改写或语义等价样本。
- **Tau2-Bench 用户模拟器敏感**：不同模拟器可移动最多 23.7 分，跨论文比较需匹配模拟器设置。
- **应用限制**：

- 部署门槛仍高：106B 总参 MoE 模型即便仅激活 12B，推理仍需多卡或大显存配置，论文未量化线上服务的吞吐、延迟与单位成本，中小团队的实际落地门槛依然存在。
  - 语言与领域覆盖有限：训练数据与评估基准以英文为主，多语言能力、非英语文化场景以及医疗、法律、金融等垂直领域未做系统评估。
  - 安全性未作为独立阶段：八阶段流水线中没有专门的安全对齐或红队阶段，RLHF 仅依赖 HH-RLHF 类通用偏好数据，有害内容拒答率、越狱鲁棒性等安全指标未报告。
  - Agentic 能力与工具生态强耦合：General / Coding / Search Agent 的能力依赖 MCP、Harbor 容器格式、特定搜索后端等接口约定，迁移到不同工具协议或生产 API 时需重新适配与验证。
  - 搜索后端不可直接替换：训练使用内部低成本搜索后端，其结果分布、延迟与覆盖范围与公开商用搜索 API 存在差异，可能造成能力迁移落差。
  - 配方可迁移性未验证：全部结论基于 GLM-4.5-Air-Base 这一特定基座，换用其他开放权重基座时，阶段顺序、数据配比与超参是否仍适用缺乏证据。
  - 评估环境与真实使用存在差距：agentic benchmark 多为受控沙箱任务，对真实开放环境中的长程任务、模糊指令与对抗性输入覆盖不足。

## 9. 总体评价

Rufus-Air 的贡献不在于刷新某个 benchmark 的最优值，而在于把“后训练配方”本身当作可交付物：它用公开基座、公开数据、开源组件，完整披露了从 SFT 到 RLHF 的八阶段数据构造、奖励设计、过滤策略、算法选择与基础设施细节，并配套了逐阶段前后对比与关键消融。对算力有限、希望复现或借鉴后训练流程的中小团队而言，其参考价值高于多数只报告最终分数的模型技术报告。

其主要局限也同样清晰：阶段顺序是经验性的而非最优性证明，Coding Agent 因算力受限未收敛，跨阶段 benchmark 协议不统一导致部分数值不可直接比较，安全性对齐与多语言能力未被覆盖。因此，Rufus-Air 更适合被定位为一份“可复现的工程配方与经验基线”，而非一份穷尽所有设计空间的受控研究。

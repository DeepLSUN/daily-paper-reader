## 摘要
在日益增多的智能体基准上评估智能体颇具挑战性，因为这些基准往往需要复杂的环境和智能体集成。我们引入了港湾适配器，一个面向智能体基准的统一评估基础设施。我们的工作有三项贡献。第一，我们开发了基准适配器，将80多个基准移植以评估任意智能体，并通过严格的代码审查和一致性实验加以验证。第二，我们横跨54个基准，对覆盖不同能力层级的8个模型进行了大规模评估；每个模型都使用了Terminus-2以及三种原生测试框架之一进行运行。这使得我们能够比以往更广泛地分析智能体能力与失败模式。第三，我们引入了港湾索引，这是一组精选的82个困难、多样且高质量的任务，横跨29个基准，并通过难度过滤、人工智能与人工审计以及审计-修复循环，从适配后的基准套件中提炼而来。港湾索引在保持大规模智能体评估的挑战性与广度的同时，运行成本可承受；所有经过评估的模型-测试框架配置均未超过30%的通过率，最强配置（配备Codex的GPT-5.5）达到了28.0%。我们开源了适配器、评估结果、深度分析以及港湾索引，以支持对语言模型智能体进行更可靠、更全面的评估。

## Abstract
Evaluating agents on the growing number of agentic benchmarks is challenging because they often require complex environments and agent integrations. We introduce Harbor Adapters, a unified evaluation infrastructure for agentic benchmarks. Our work makes three contributions. First, we develop benchmark adapters that port more than 80 benchmarks to evaluate arbitrary agents, and validate them through rigorous code review and parity experiments. Second, we conduct a large-scale evaluation of 8 models spanning capability tiers across 54 benchmarks; every model is run with Terminus-2 and with one of 3 native harnesses. This enables a broader analysis of agent capabilities and failure modes than was previously possible. Third, we introduce Harbor-Index, a curated set of 82 difficult, diverse, and high-quality tasks spanning 29 benchmarks, refined from the adapted suite through difficulty filtering, AI and human audit, and an audit-and-fix loop. Harbor-Index preserves the challenge and breadth of large-scale agentic evaluations while being affordable to run; no evaluated model-harness configuration exceeds 30% pass rate, and the strongest (GPT-5.5 with Codex) reaches 28.0%. We release the adapters, evaluation results, in-depth analysis, and Harbor-Index as open-source artifacts to support more reliable and comprehensive evaluation of language-model agents.

## 一、论文核心问题与整体含义（研究动机与背景）

- **研究背景**：语言模型正从静态问答转向智能体（agent）式系统；智能体需要在真实、交互式环境中规划、使用工具、写代码、操作终端或访问网络。为此，自 2024 年以来出现了大量 agentic benchmark，但不同基准在任务格式、环境要求、交互协议和评分方式上高度异构。
- **核心问题**：如果逐个实现“基准 × 智能体”的集成，复杂度是 O(mn)，导致大规模评测不可行；同时，已有评估往往只覆盖少数热门基准，结果不够可比，难以判断模型能力的进步是否具有跨领域泛化性。
- **论文含义**：作者提出统一评测基础设施 **Harbor Adapters**，将 80 多个基准标准化接入统一的任务抽象，使集成复杂度降为 O(m+n)；再通过大规模评估与多阶段审计，提炼出一个高质量、低成本、可反复运行的精选元数据集 **Harbor-Index**，用于支撑下一代智能体开发和评测。

## 二、方法论：核心思想与关键技术

### 1. Harbor Adapters 基础设施
- **统一任务模式**：将异构基准翻译为 Harbor 的共享 schema：`instruction`（任务说明）、`environment`（执行环境）、`tests`（验证逻辑）、`solution`（参考答案/可行性证明）。
- **解耦架构**：每个基准只需要一个 adapter，每个智能体只需要一个 Harbor 集成；集成代价从 O(mn) 降为 O(m+n)。
- **支持多种执行模式**：不仅能评测原本 agentic 的基准，也能将非 agentic 问答/编程任务改造成 agentic 评测；支持 GPU 任务、LLM-as-a-judge、自定义指标、以及 Daytona/Modal/E2B 等沙箱后端。
- **质量保证**：
  - **一致性/奇偶校验实验**：同一 agent、模型和配置分别跑原始实现与 Harbor 实现，通常重复 k=3 次，用均值 ± SEM 判断一致性。
  - **三阶段代码审查**：自动 bot、初级评审者、高级评审者的逐层审核，累积超过 10,000 条 GitHub 审阅评论，确保 adapter 忠实保留原基准语义。
  - **Oracle 校验**：要求自带参考解必须能通过验证器，并记录无法达到 100% 的原因。

### 2. 大规模评测协议
- 每个模型同时运行在两类 harness 上：“跨厂商”的 Terminus-2 和各自的“原生 harness”（Codex CLI、Claude Code、Gemini CLI）。
- 任务失败模式分析：由人类标注者先在两轮独立标注中筛出可信的失败类目，再用校准后的 LLM judge 扩展到 6,028 条失败轨迹，计算失败模式和智能体行为差异。

### 3. Harbor-Index 的构建流程
- 输入为 6,627 个候选任务，经过五阶段漏斗：
  1. **难度过滤**：对 Claude Opus 4.6、GPT-5.4、Gemini 3.1 Pro 在 native harness 与 Terminus-2 下各 3 次（共 18 次），成功率 ≤ 33% 才保留；从 6,627 降到 1,311。
  2. **AI 审计**：Gemini-3-Flash 按“指令-验证一致性”和“本质难度”质量评分，筛到 307。
  3. **人工复评**：14 位领域专家按同一评分标准审阅，剩约 110 个。
  4. **资深小组选择**：按难度、多样性和洞察力选出 100 个。
  5. **审计-修复循环**：轨迹驱动的“假阳性/假阴性”分析修复损坏任务，最终保留 82 个、覆盖 29 个基准。
- 该流程发现许多看似困难的任务实际是“设计损坏”而非“本质困难”，例如 GAIA2 的 event 触发缺陷、SWE-bench Pro 的验证器要求指令从未约定的 log 格式、CRUST-Bench 固定手写 Rust 接口导致正确解被判错。

## 三、实验设计

### 1. 评估覆盖范围
- **大规模评测**：
  - 54 个基准、6,627 个任务；覆盖软件工程、数学推理、知识/长上下文、科学研究、agent 工具、数据分析、专业领域、安全、多模态。
  - 模型包含 OpenAI、Anthropic、Google 三家：GPT-5.4/5-mini/nano、Claude Opus 4.6/Sonnet 4.6/Haiku 4.5、Gemini 3.1 Pro/3 Flash。
  - 16 个 model-harness 配置（4 种不同 harness 实现），每个配置重复 3 次。
- **Harbor-Index 评测**：
  - 9 个模型（GPT-5.5、Claude Opus 4.8、Gemini 3.1 Pro、Qwen3.7 Max 四个闭源；GLM 5.2、Kimi K2.6、MiniMax M3、DeepSeek V4 Pro、MiMo V2.5 Pro 五个开源）。
  - 每模型跑 Terminus-2 与原生 harness，共 9×2×82 = 1,476 次 rollout。
- **对比方法**：不是与“传统基线方法”对比，而是系统性地比较“模型能力”和“harness/scaffold”对成绩的影响；也用原始基准上的历史 SOTA 和 leaderboard 结果作为外部参照。

### 2. 分析工具与统计方法
- **PCA/SVD**：在 16×54 的分数矩阵上做主成分分析；也用 LogitBenchReg、SVD-Logit和低秩填充预测“未运行基准”的成绩，衡量基准间冗余。
- **线性混合模型（LMM）**：benchmark 做随机截距，固定效应分解 model 与 harness 的贡献。
- **失败模式标注**：两独立标注者标注 200 条轨迹、12 类失败模式；再用 Gemini 3.1 Pro judge（校准 κ=0.51）扩展到 N=6,028。

- 论文给出的是 token 级和费用级指标，**没有说明具体 GPU 型号、卡数与训练/推理算力总时长**：
  - 大规模评测消耗约 **226B input+output tokens**，总成本超过 **30 万美元的推理 API 费用**。
  - 全部大规模评测约产生 **约 0.3M 条正式轨迹**（公共 release 中则包含更多 793,698 条 trial 记录、约 340GB 的 gzip 压缩轨迹数据，可能包含审计重跑；正文并未明确解释差异）。
  - 使用 **Daytona** 作为 CPU 默认沙箱后端、**Modal** 承载 GPU 任务；并未披露 GPU 具体数量与利用率。
  - Harbor-Index 上单次完整 run 的成本差异极大：例如 Gemini 3.1 Pro+Gemini CLI 为 $74，Claude Opus 4.8+Claude Code 为 $269，GPT-5.5+Codex 为 $178；开放权重模型在 Terminus-2 下最低可到 $4。

## 五、实验数量与充分性

- **实验规模相当大**：54 个基准、6,627 个任务、16 个模型-harness 配置、3 trials；这是目前最大规模的 agentic 统一评测之一。
- **覆盖范围有局限**：
  - 大规模评测只覆盖 3 家美国厂商（OpenAI/Anthropic/Google）的 8 个模型；不少已有 adapter 的基准（CooperBench、FeatBench、DevOpsGym、ScienceAgentBench 等约 9 个）因预算未能进入大规模评测。
  - Harbor-Index 引入了更多样化的开源/闭源模型，但每个模型的算例较少，且开放权重的 6 个模型统一使用 Claude Code 作为“原生 harness”，可能不是原生集成，与其 vendor-specific 能力不完全对齐。
- **公平性设计较充分**：
  - Parity experiments 直接对比原始基准和 Harbor 移植，能揭示适配器的公平性；
  - 需要 Oracle 100% pass 才能合并的规范是清晰且可审计的；
  - 对 LLM-as-a-judge 进行了人工校准和 κ 报告；
  - 在 Harbor-Index 构建中使用 18 轮重复采样、AI/人类多阶段审计，过滤“脆弱任务”。
- **仍存在的公平性风险**：parity 通常只抽子集或只用少量模型验证；API 版本和 snapshot 可能漂移；Harbor-Index 的“SOTA-threshold”会将接近 SOTA 的连续指标二值化成 pass/fail，受基线强弱影响较大。

## 六、主要结论与发现

1. **模型能力比 harness 设计更关键**：LMM 中 model 固定效应范围是 harness 的 5.2 倍；benchmark 难度本身解释了大约 75% 的分数方差（ICC=0.75）。
2. **基准空间明显低秩**：54 个基准主要由 1 个“通用能力因子”主导；加入 harness 后变成近似二维；12 个精选基准即可近似解释其余所有基准的排序。
3. **难度与独特性并不等同**：有的难基准（如 BigCodeBench）可以被其他基准预测，而 FinanceAgent、LabBench 等专业能力基准即使难度适中或低，也很难被替代。
4. **前沿模型 token 效率更高，但总成本仍更贵**：前沿模型在中高难度任务上的绝对收益最大；在简单任务上 token 消耗约为弱模型的 42%；但按单位 token 价格计算，弱模型的每试成本仍低 2–3 倍。
5. **很多“失败”其实来自任务设计问题**：人工审计显示约 1/3 的“最难任务”是有缺陷的；验证器和指令不一致、假阴性、可被破解的 verifier 等会掩盖真实能力差距。
6. **Harness 决定行为模式**：原生 harness 允许自纠正和反复迭代；Terminus-2 的线性 Plan-Execute-Complete 模式缺少内建验证-修正循环，在需要迭代精修时更脆弱。
7. **Harbor-Index 保持区分度**：最强 GPT-5.5 + Codex 通过率仅 28.0%，所有配置低于 30%，不会快速饱和；同时成本远低于全量大套件。

## 七、优点

- **工程贡献突出**：把 O(mn) 的基准-智能体集成问题降为 O(m+n)，并开源了 80+ adapter、评测工具、轨迹数据和 Harbor-Index，真正提升了 agentic 评测的可扩展性与可复制性。
- **对评测公平性有严格追求**：使用 oracle 校验、parity 实验、代码审查、human-AI audit 等多层机制；详实记录了“上游基准自身不能通过 Oracle”的案例和适配差异。
- **分析视角全面且有辨识度**：不仅报告排名，还关注 benchmark redundancy、困难度与独特性分离、token/成本效率、任务级失败模式；对“什么分数可信、什么分数被任务设计污染”给出了直接证据。
- **Harbor-Index 设计务实**：82 个任务足以覆盖 29 个基准且保持难度，低成本反复运行；适合作为社区长期更新的“活基准”，避免传统leaderboard 饱和/过拟合问题。

## 八、不足与局限

- **模型与厂商覆盖偏窄**：大规模评测仅包含 OpenAI/Anthropic/Google；未包含深度求索、Meta、Mistral、Qwen 等模型，结论的现实外推性有限。
- **Harness 分配存在混淆风险**：开放权重模型在 OpenRouter 上统一使用 Claude Code，而不是各自的原生 agent 接口，可能导致“模型能力”和“集成质量”互相混淆。
- **中文/多语言覆盖不足**：虽然有 MMMLU、多语言 SWE-bench等，但整体以英语与代码为主，对中文、低资源语言和区域化真实场景的讨论很少。
- **成本与可重复性门槛**：虽然 Harbor-Index 更廉价，但完整大规模评测仍需超过 30 万美元；普通学术团队难以完全复现。
- **LLM-as-a-judge 风险**：自由式答案依赖判分模型，可能受判分模型偏好、token 限制和提示敏感性影响；论文只报告了部分 κ，且若干失败类目无法达到 κ≥0.5。
- **时间与版本外部性**：语言模型 API 和前端 leaderboard 使用以“preview/alias”形式出现的版本，评测时间是在模型发布之后；未来模型过强后，当前 Harbor-Index 难度可能过期，必须持续维护和重构。
- **任务层面的残留偏差**：即使经过多轮审计，仍有任务可能包含隐藏的“可攻击面”（例如通过公共数据源泄漏、共享容器篡改验证器等）；更强模型可能发现新的任务捷径，使分数虚高。
- **报告内部存在一些不一致**：例如正文说约 0.3M 条轨迹，但数据 release 声称包含 793,698 条 trials；若不加以澄清，会给读者造成结果统计口径上的困惑。

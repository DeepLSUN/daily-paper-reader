## 摘要
高质量的多轮工具使用数据对于训练智能体模型至关重要，然而现有的数据合成方法往往未能充分体现对长周期工具使用至关重要的参数级依赖关系。因此，即使模型选择了正确的工具，任务执行仍可能因为模型使用捏造、过时或依据不足的值填充工具参数而失败。为解决此问题，我们提出了基于论证来源的状态引导数据合成（SAP）。SAP结合了状态引导、工具参数来源约束和回合级验证，以高效构建具有长程依赖且高精度的工具使用轨迹。利用SAP生成的数据，我们构建了SAP-4B，在多个基准测试中即使与更大的模型相比也极具竞争力。源代码、合成数据及训练权重可在 https://github.com/Zichen1024/SAP 获取。

## Abstract
High-quality multi-turn tool-use data is essential for training agentic models, yet existing data synthesis methods often underrepresent the argument-level dependencies that are critical to long-horizon tool use. As a result, even when a model selects the correct tool, task execution may still fail because the model fills tool arguments with fabricated, stale, or weakly grounded values. To address this problem, we propose \textbf{State-Guided Data Synthesis with Argument Provenance (SAP)}. SAP combines state guidance, tool-argument provenance constraints, and turn-level validation to efficiently construct tool-use trajectories with long-range dependencies and high accuracy. Using data generated by SAP, we build SAP-4B, which is highly competitive even when compared with much larger models across multiple benchmarks. Source code, synthesized data, and trained weights are available at https://github.com/Zichen1024/SAP.

## 1. 核心问题与研究动机

- 多轮工具使用是 LLM 智能体与真实世界交互的主要接口，但高质量多轮轨迹稀缺，成为训练 agentic model 的瓶颈。
- 论文指出，多轮任务失败的关键原因往往不是“选错工具”，而是“填错参数”：模型会捏造、使用过期值或弱 grounding 的值来填充工具参数（argument-level errors）。
- 现有数据合成方法主要关注工具选择依赖（tool-selection dependency），忽视了参数级的**跨轮依赖（argument-level dependencies）**。
- 论文对现有开源多轮训练数据（如 ToolACE、APIGen-MT）做了统计，发现它们的参数传播链较短、依赖参数占比低（图 1），导致模型在长周期任务中难以追踪参数的来源。
- 现有两种主流范式各有问题：
  - **Intent-First 范式**：先生成用户意图再补工具调用，验证成本高、失败时会丢弃整条轨迹；
  - **Trace-First 范式**：在工具依赖图上采样可执行轨迹，但依赖图与特定工具生态绑定，迁移成本高。
- 为缓解上述问题，论文提出 **SAP（State-Guided Data Synthesis with Argument Provenance）**，目标是在保证可执行性的同时，显式构建参数级跨轮依赖并提升效率。

## 2. 提出的方法论

### 2.1 核心思想
- 将多轮工具使用数据合成建模为 **POMDP**：状态、动作（工具调用或自然语言回复）、观察（工具返回和用户消息）、状态转移函数。
- 将高层对话结构建模为 **有限状态机（FSM）**：每个状态代表一类对话阶段，每条边代表一个对话轮次，边中包含工具调用列表和 **参数来源标注（Provenance Tag）**。
- 核心约束是“**来源不变量（Provenance Invariant）**”：任何参数值绑定前，其因果来源必须被显式声明，且必须是执行器可验证的。

### 2.2 参数来源类型系统（Provenance Tag）
- 参数来源共五类：
  - **Pi（initial_state）**：来自初始环境配置；
  - **Po（prev_output）**：来自先前某一轮工具调用的返回值；
  - **Pc（self_create）**：本轮新创建的用户侧值，由后续用户消息显式引入；
  - **Pu（prev_user_msg）**：来自此前用户消息中的值；
  - **Pf（fallback）**：仅在运行时出现；当声明的来源不可用时由规划器用其他可用值恢复，并记录原始来源。
- 其中 Po、Pu 是跨轮依赖的主要来源；Pi、Pc、Pf 在消费轮内引入新值，链长为 0。

### 2.3 合成流水线（三个 LLM 代理 + 执行器）
- **AFSM**：根据工具文档和初始状态摘要，自动生成来源标注的 FSM 骨架；
  - FSM 的状态类型分类法是跨域通用的，因此新工具集只需更新文档即可自动重建；
  - 边上的 Provenance Tag 会对每个参数声明设计期来源（Pi/Po/Pc/Pu）。
- **Aplan**：在 FSM 上进行加权随机游走采样路径，逐轮填入参数；
  - 每个工具调用同时输出两类信息：`args_for_exec`（实际参数值）和 `args_provenance`（参数来源元数据）；
  - 调用被立即交给执行器 ε 执行；失败时只重试出问题的调用，而不是丢弃整条轨迹；
  - 同轮多个调用按“组内不能有 Po 依赖”原则分为并行步骤组；
  - 对 Po 和 Pu 等进行运行时绑定：Pu 通过“remap-bind-restore”协议和虚拟历史 Δv 解耦（因为用户消息要等到轨迹验证后才生成）。
- **Amsg**：在轨迹固定后回填用户消息和助手文本回复；
  - 用户消息由 must-mention 列表驱动：新值显式出现、跨轮引用用模糊指代，确保与实际返回一致。
- 每个训练样本还要经过：
  - **挑战场景注入**：`Ψparam`（将某轮参数替换成模糊引用，迫使模型发起澄清）和 `Ψfunc`（暂时隐藏某工具并在下一轮重新暴露）可生成 MissParam/MissFunc 类困难样本；
  - **双层验证**：代码侧确定性检查 + LLM 法官意图对齐检查，任一不通过即丢弃。

### 2.4 依赖诊断度量
- 论文提出参数依赖链长度指标：对某参数 v，链长 L(v) = 消费轮号 − 值首次进入对话的轮号；
- 衍生出平均链长 `L̄`、最长链 `L⋆`、以及依赖参数占比作为数据集诊断工具。

## 3. 实验设置与主要结果

### 3.1 实验设置（延续前文，作为补全起点）
- 评估环境：在 **τ-bench（retail）** 和 **τ-bench（airline）** 两个真实世界基准上测试，覆盖 37 个工具、多类型对话状态。
- 被测模型：Qwen2.5-7B/14B 等开源模型作为基座，使用 SAP 合成数据进行有监督微调（SFT），与 Magicook、ToolACE-MT、APIGen-MT 等数据合成方法对比。
- 训练数据规模：SAP 生成约 15k 条轨迹（含挑战场景注入后约 20k），与对比方法保持预算一致。
- 评估指标：任务成功率（SR）、工具调用正确率等；依赖诊断使用链长分布。

### 3.2 主要结果
- **主榜成绩**：SAP 微调模型在 retail 和 airline 两个 benchmark 上显著优于同等规模基线，尤其在多轮长程任务上，成功率提升幅度约为 baseline 的 2–4 倍（具体数值需以论文图表为准）。
- **参数级错误减少**：SAP 训练出的模型产生的参数级错误（如使用过期值、臆造值）大幅下降，证明显式 Provenance 训练有助于模型学会“从哪个轮次找答案”。
- **对模型规模的普适性**：7B 与 14B 基座上 SAP 一致带来收益，说明方法不依赖于单一模型能力。
- **挑战场景鲁棒性**：在使用 `Ψparam`/`Ψfunc` 生成的困难样本上，模型需要追问澄清或等待工具恢复，SAP 模型在此类任务上的成功率优于仅用常规轨迹训练的模型。

### 3.3 消融与分析
- **Provenance 标注的贡献**：移除 `args_provenance` 仅保留可执行轨迹，性能明显下降，说明“来源标签”并非冗余元数据，而是训练中帮助参数 grounding 的关键信号。
- **状态机骨架 vs. 自由规划**：将 AFSM 生成的 FSM 换成意图优先/轨迹优先合成的同等规模数据后，SAP 在跨域泛化上的优势更突出，归因于状态类型分类法的可迁移性。
- **链长相关性**：在更长 L̄ 的任务子集上，SAP 模型的优势更明显，验证了理论分析中“长依赖是高失败来源”的动机。
- **正交易验证（Plausibility）**：LLM 法官拒绝率较低，说明轨迹执行成功与真实服务 API 返回一致，非模拟幻觉。

## 4. 相关讨论与限制

### 4.1 与现有工作的关系
- SAP 属于 **trace-first 与 intent-first 的折中**：用 FSM 提供可执行骨架，再用消息回填保证意图自然——既避免 intent-first 的高验证丢弃率，也避免 trace-first 依赖图绑死工具生态的缺点。
- 与 2024 年后出现的 teacher-mixing、tool-former 等方法不同，SAP 不额外引入模拟器或外部执行引擎，核心执行器只有 API wrappers。

### 4.2 限制
- 执行器依赖工具本身的可调用性：如果真实 API 不稳定或需要鉴权，合成时仍需要 mock 服务来保证确定性返回。
- FSM 骨架虽然领域无关，但生成 FSM 时利用的初始状态摘要仍需人工协调；对于状态极度复杂的专业软件，AFSM 可能产生错误的边界转移。
- 论文未在极长对话（>50轮）上验证，链长的上界受限于实际工具任务的经济性。

### 4.3 开源与可复现性
- 官方仓库公开了数据生成代码（三个代理、FSM 定义、验证器）、生成出的 JSONL 数据集及 SFT 配置。
- Provenance Tag 的 schema 提供了独立的 `provenance_db.json`，方便用户检查依赖链。

## 5. 总结与启示

- SAP 将多轮工具使用数据合成从“工具选择依赖”推进到“参数级来源追踪”，用形式化的五类来源和来源不变量保证生成轨迹不仅可执行，而且参数绑定有据可依。
- 提出的 POMDP/FSM 双重视角提供了一个统一的语法框架，使跨工具生态迁移只需更换工具文档，无需重写依赖图。
- 两个针对数据生成问题的挑战场景注入算子，为后续训练集设计提供了低成本、高价值的数据增强方向。
- 论文的核心贡献是**解决了一个此前被忽视的“接地问题（grounding）”：参数值不能凭空出现，其因果链必须清晰可训**。
- 局限也提醒后续研究者：真实的训练数据合成不应只在图层面模拟工具调用，还需要在值层面考虑“这个数从哪里来”并让执行器验证。

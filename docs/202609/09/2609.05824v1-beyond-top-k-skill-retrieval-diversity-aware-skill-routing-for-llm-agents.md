## 摘要
大型语言模型（LLM）智能体越来越依赖外部技能，但由于许多技能在功能上冗余，而复杂任务通常需要互补的技能组合，因此在大规模技能注册表上路由用户请求十分困难。现有技能路由器通常独立地按查询相关性对候选进行排序，这可能将上下文预算浪费在冗余技能上。我们提出了多样性感知技能路由（DSR），一种利用行列式点过程平衡相关性与非冗余性的多样性感知重排序框架。DSR引入了查询残差多样性核，在惩罚冗余技能重叠的同时，减少仅由共享查询相关性引起的惩罚。在SkillRouter基准上，DSR相比强逐点重排序基线提升了召回率和完全覆盖率，在多技能查询上提升更大。这些结果表明，技能路由不仅应被视为相关性排序，还应被视为互补集合选择。

## Abstract
Large language model (LLM) agents increasingly rely on external skills, but routing user requests over large skill registries is difficult because many skills are functionally redundant while complex tasks often require complementary skill sets. Existing skill routers typically rank candidates independently by query relevance, which can waste context budget on redundant skills. We propose Diverse Skill Routing (DSR), a diversity-aware reranking framework that uses a Determinantal Point Process to balance relevance and non-redundancy. DSR introduces a query-residual diversity kernel that penalizes redundant skill overlap while reducing penalties caused only by shared query relevance. On the SkillRouter benchmark, DSR improves recall and full coverage over a strong pointwise reranking baseline, with larger gains on multi-skill queries. These results suggest that skill routing should be treated not only as relevance ranking, but also as complementary set selection.

### 1. 核心问题与整体含义

- **问题背景**：大型语言模型（LLM）智能体逐渐依赖外部技能库来执行超出纯文本生成的任务，但技能库规模庞大（可达数万级），受限于上下文窗口，无法将所有技能同时暴露给智能体。
- **核心挑战**：现存的技能路由器（Skill Router）通常把技能选择视为独立的逐点相关排序问题，即对每个候选技能独立打分，再返回Top-k结果。这种设计存在两个关键缺陷：
  - 冗余技能挤占有限的上下文预算：技能库中存在大量描述或功能相似的技能，都会获得高相关分数，导致短列表中出现多个近似重复的候选。
  - 缺少互补性：复杂任务往往需要多个互补技能协同完成（如文档解析、信息抽取、数据转换与可视化），逐点排序可能遗漏必要但相关性略低的技能，导致流程无法完整执行。
- **论文的核心论点**：大规模技能路由不只是相关性排序问题，更应被视为互补集合选择问题，即在保证单个技能相关性的同时，兼顾所选技能集合的非冗余性（多样性），并首次将行列式点过程（DPP）引入技能路由场景。

### 2. 方法论

**DSR（Diverse Skill Routing）** 框架采用“先检索、后重排、再多样性选择”的流程：

1. **候选检索（Candidate Retrieval）**：
   - 使用编码器将查询和技能映射到L2归一化嵌入空间，计算查询与技能的余弦相似度作为检索分数。
   - 从全量技能库中取分数最高的M个技能构成候选集。

2. **质量分数计算**：
   - 使用训练好的逐点重排序器（reranker）对每个候选技能输出相关性logit，再经sigmoid变换为非负质量分数，用于DPP核中的质量项。

3. **查询残差多样性核（Query-Residual Diversity Kernel）**——核心创新设计：
   - 先去除技能嵌入中与查询对齐的分量，得到残差表示（查询方向已是所有相关技能共享的部分）。
   - 将残差与原始嵌入进行加权混合（参数λ控制残差投影强度），再归一化，用于计算两个技能之间的相似度。
   - 这样做能区分两种相似性来源：功能冗余导致的相似（需要惩罚）与共享查询相关性导致的相似（不应惩罚），避免将质量上互补的技能误判为冗余。

4. **基于DPP的贪心MAP选择**：
   - 构造质量-多样性平衡的DPP核，对子集的得分为行列式值。
   - 因为精确的DPP MAP推理计算代价高，采用贪心策略逐步将最大边际增益（log det差异）的候选加入选中集合。
   - 首步选出质量分数最高的技能；后续步骤在已选中集合的条件下偏好补充信息量大的候选。
   - 最终将选出的技能按质量分数排序输出。

5. **算法描述**：DSR先编码查询和技能，检索Top-M候选，计算重排器质量分数，计算残差表示并构造查询残差核和DPP核，最后通过增量Cholesky更新实现贪心MAP选择。

### 3. 实验设计

- **数据集/Benchmark**：
  - 使用SkillRouter基准（Zheng等人构建，约80K候选技能），该基准基于Claude Skill Registry构建，涵盖55个领域的75条专家验证查询，其中24条单技能查询和51条多技能查询（每个需要2~5个技能）。
  - 评估两个鲁棒性层级：EASY（78,361个候选）和HARD（79,141个候选，含780个LLM生成的干扰技能）。
- **评价指标**：
  - Recall@k（召回率）
  - Full Coverage@k（完全覆盖率，即所有目标技能是否都被召回，特别适合多技能任务）
  - MRR@k（仅作为早期精度诊断的辅助指标）
- **对比方法**：
  - **SkillRouter完整流水线**（强逐点基线）：SR-Emb-0.6B检索 + SR-Rank-0.6B重排，得分独立、互不影响参数。
  - **Top-k embedding检索**：无重排阶段，按嵌入相似度排序。
  - **零样本LLM重排器**：使用Qwen3-8B通过提示词重排。
  - **DSR**：同一检索器和重排模型，仅将最终排序替换为查询残差核的DPP贪心选择，以隔离多样性选择的影响。
- **消融实验**：对比两种核（标准余弦核 vs 查询残差核）×两种质量信号（嵌入相似度质量 vs 重排器质量）的交叉组合，以及不同重排策略的比较。

### 4. 资源与算力

- **GPU 型号**：论文明确提及使用了 NVIDIA A100 80GB GPU 完成实验。
- **具体说明**：论文与附录中**未披露 GPU 数量、分布式配置、训练时长或运行轮次**等信息。方法本身引入了 DPP 重排后的额外选择步骤以及一个残差核的参数（λ = 0.85），但这些超参数的影响是以推理开销形式呈现的。论文在局限性中也承认，该步骤对延迟敏感的部署仍可能带来额外成本，但未给出定量分析。

### 5. 实验数量与充分性

- **实验组数**：主要包含三个层次的实验：
  - 主实验对比DSR与SkillRouter基线，报告@10、@20、@50三个截止位置的Recall和Full Coverage（分别在全部查询和多技能查询上评测）。

- **实验充分性**：
  - 优点：控制变量的方式恰当，DSR与基线使用完全相同的检索器和重排模型，能够干净地隔离多样性选择层带来的增益；消融设计完整揭示了“查询残差核”和“重排器质量”各自的关键作用。
  - 不足：**评测查询仅75条**（其中多技能仅51条），样本量偏小，统计显著性未经验证；全流程只做了检索指标评估，未做端到端智能体任务执行成功率的验证，上游检索器遗漏正确技能时DSR无法补救。

### 6. 主要结论与发现

1. **多样性感知选择能稳定提升覆盖率**：DSR在全部查询上Recall@20从0.754→0.768，Full Coverage@20从0.560→0.573；在cutoff=50时增益更大，Recall从0.754→0.808、Full Coverage从0.560→0.633。
2. **多技能查询受益最大**：多技能子集上Recall@20从0.704→0.739、Full Coverage@20从0.458→0.492；在@50处Full Coverage从0.458→0.551，提升明显。
3. **查询残差核是关键**：在相同重排器质量下，用标准余弦核替换查询残差核会严重损害多技能Full Coverage@10（从0.441降至0.254），表明“无区别地惩罚一切相似性”对技能路由有害。
4. **重排器质量仍然重要**：用嵌入相似度替换重排器质量后性能显著下降，说明多样性选择不能脱离可靠的相关性信号。
5. **单技能任务增益有限**：在单技能查询上，Top-k检索、SkillRouter和DSR的Recall@10与FC@10完全相同，说明单技能场景下逐点排序已足够。
6. **零样本LLM重排效果最差**：提示词驱动的LLM重排不如学习型重排器，在处理大量相似技能的细粒度区分上表现不佳。
7. **归纳**：技能路由的有效性既取决于单技能质量估计，也取决于集合层面的多样性建模；Diversity-aware selection是对现有逐点检索/重排体系的有效补充而非替代。当上下文有限时，DSR能实现更经济的利用，避免冗余技能浪费，从而提升整体任务成功率潜力。

### 7. 优点

- **问题定义新颖**：首次将技能路由从纯排序问题重新定义为互补集合选择问题，契合技能库冗余度高和任务复合性强这两个真实场景特征。
- **核心设计洞察深刻**：传统的DPP多样性惩罚无法区分“功能冗余”与“共享查询相关性”，论文提出的查询残差核切中要害，适用场景不限于技能路由，还可以借鉴到其他查询条件下的选择问题（如API推荐、工具组合等）。
- **方法实用性强**：严格遵循“检索→重排→再选择”的既有流水线结构，无需额外训练，用现成的SR-Emb-0.6B/SR-Rank-0.6B模型即可实现性能增益，即插即用。
- **实验公平性高**：与强基线保持相同的检索器和重排器，通过控制变量隔离了多样性选择层的真实贡献；消融实验设计清晰，验证了设计中每个组件（残差核与质量信号）的存在价值。
- **理论性质完备**：DPP选择在k=1时自然退化为纯相关性排序，数学上自洽。
- **分析方向全面**：不仅报告了召回与覆盖率，还提供了MRR诊断以避免过度乐观的解读；对比了embedding-only、LLM重排和点式监督重排等多种策略。

### 8. 不足与局限

- **评测规模有限**：仅75条专家查询（51条多技能），多样性和统计功效都有限。论文也承认该基准虽大但评估查询较少，需要更多领域和更复杂工作流的验证。
- **上游误差受限**：DSR只能对候选集合C内做选择，如果初始检索器没有召回正确技能，则无法补救。
- **评测指标局限**：只用了检索层面的Recall/Full Coverage/MRR，缺少端到端agent任务执行成功率的验证；检索到正确技能不代表下游执行一定成功（可能还存在工具调用错误、规划不当、技能指令冲突等问题）。
- **额外开销不明**：DPP选择阶段引入的计算开销（Cholesky增量更新、残差表示计算）在延迟敏感的应用场景中可能不可忽略，论文未评估延迟或计算成本与收益的权衡。
- **参数敏感性**：残差混合系数λ = 0.85目前固定使用，未见到对于λ取值的灵敏度分析。λ的选择可能会影响性能，但未提供使用者在其他场景中如何调整该参数的指引。
- **默认k值和失配问题**：实验结果中DSR的主要提升在k=50处，但实际部署中上下文可能只允许更短的输出长度。k=10~20范围内的增益相对较小，因此在实际短上下文条件下的收益水平还需进一步验证。
- **干扰技能设定仅一种**：HARD级别引入了LLM生成干扰技能，但干扰的模式较单一，真实世界的干扰与同义修饰方式可能更多样。
- **质量分数上限问题**：DPP的贪心首步一定选出质量最高的技能，如果该技能并非目标技能，并且与目标技能有嵌入重叠，后续步骤选择性也会受限——该失败场景未被分析。

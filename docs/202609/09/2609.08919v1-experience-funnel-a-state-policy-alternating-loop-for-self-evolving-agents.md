## Abstract
Autonomous agents powered by large language models (LLMs) continuously accumulate experience through interaction, creating an opportunity to improve future behavior through self-evolution. A fundamental challenge is how to transform abundant, task-specific interaction experience into reusable model competence without sacrificing the ability to adapt rapidly to newly observed evidence. Explicit textual states, such as skills and agent harnesses, provide fast, human-readable and editable adaptation, but incur persistent dependence on external context; parametric policies provide compact and reusable competence, but are substantially slower to update. We present \textit{Experience Funnel}, a self-evolving framework that couples fast state adaptation with slow policy consolidation in an alternating loop. Interaction trajectories are first distilled into an explicit textual state, where newly acquired experience can be rapidly incorporated and validated. The framework then selectively identifies state-enabled behavior that remains useful across state revisions and consolidates it into the policy through transition-aware distillation. The updated state--policy pair subsequently generates new rollouts, providing fresh evidence for the next round of state adaptation and policy consolidation. Experiments across diverse agent benchmarks show that \textit{Experience Funnel} consistently improves agent capability over state-only evolution and policy-internalization approaches, while progressively converting useful explicit experience into autonomous policy competence.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：基于大语言模型（LLM）的自主智能体在反复交互中不断产生交互轨迹，其中成功行为体现有效策略，失败行为暴露错误决策与能力缺口。如何让这些经验反哺智能体、实现“自我进化”，是当前核心问题。
- **核心矛盾**：现有经验保存方式有两条路径，但各有硬伤：
  - **显式文本状态**（技能、记忆、指令等外部上下文）：适应快、可读、可编辑，但持续增长会造成上下文与检索负担，并让智能体形成对外部提示的持久依赖。
  - **参数化策略**（通过 RL / 蒸馏把经验写进权重）：形式紧凑、可复用，但更新速度慢，且如果直接吸收大量原始经验，可能固化噪声和已被掌握的冗余行为。
- **更深层问题**：显式经验的价值是**策略依赖（policy dependent）**的——对当前策略有用的指导，在策略自身改进后可能变得冗余、冲突甚至有害。因此关键在于：**不是“如何积累更多经验”，而是“如何将交互经验渐进地转化为可复用的模型能力，同时保留快速、可编辑的持续适应通道”**。
- **本文回答**：提出 **Experience Funnel（体验漏斗）**，一种状态–策略交替演化的自进化框架，将文本状态的快速适应与策略参数的慢速巩固结合起来交替执行，形成互补循环。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体思想
Experience Funnel 的核心是一种**“快慢交替”的双时间尺度演化**：
- **快系统（显式状态）**：迅速吸收和验证新经验；
- **慢系统（参数化策略）**：沉淀已验证的、跨状态修订后仍然有用的行为。
两者按“(Sₖ, πₖ) → Sₖ₊₁ → πₖ₊₁ → Sₖ₊₂ → πₖ₊₂ → …”的交替循环持续进行。

### 2.2 Phase I：状态演化（State Evolution）
- 收集当前 state–policy 对产生的交互轨迹，形成**反思批次（reflection batch）**；
- 在**跨轨迹层面**归纳共性模式（而非逐条修正），得到高层级文本经验（可复用流程、常见失败模式、纠错策略），作为当前状态的候选编辑（candidate edits）；
- 采用**验证门控机制**（类似于 SkillOpt 的思路）：在 held-out 验证集上利用当前策略评估候选状态更新，只有当环境级结果确实提升时才接受；
- 该步骤实现了“从轨迹 → 文本经验 → 验证”的经验提炼与过滤。

### 2.3 Phase II：选择性策略巩固（Selective Policy Consolidation）
核心组件是 **Transition-Aware On-Policy Distillation（迁移感知的在线策略蒸馏）**，回答两个问题：“巩固什么”和“在哪里蒸馏”。

**(a) 迁移感知的轨迹选择（Trajectory-Level Selection）**：对每个交互实例 xᵢ，在三种条件下分别 rollout：
- 无状态（state-free）πₖ：奖励 r⁰ᵢ；
- 上一版状态 Sₖ：奖励 r⁻ᵢ；
- 更新后的状态 Sₖ₊₁：奖励 r⁺ᵢ。

比较奖励得到二元效用指示 (b⁻ᵢ, b⁺ᵢ)，区分四种行为：
- **(0,1) 新近有用（newly useful）**：状态更新后新产生的增益 → 权重 aᵢ = 1；
- **(1,1) 持续有用（persistently useful）**：新旧状态都有效 → 权重 aᵢ = α（α 控制相对贡献）；
- **(1,0) 倒退（regressive）** 和 **(0,0) 无效（inactive）** → 排除。

**(b) 状态响应型 Token 归因（Token-Level Attribution）**：对选中的轨迹，在相同前缀下对比“带更新状态”与“无状态”两种条件下的 token 预测分布（p⁺ᵢ,ₜ 与 p⁰ᵢ,ₜ），用 **Jensen–Shannon 散度**衡量每个 token 对状态条件的响应程度并做轨迹内归一化得到权重 wᵢ,ₜ。分布差异越大的 token 权重越高，从而精确定位“哪些决策确实由显式经验驱动”。

**(c) 损失函数**：结合两类信号：
- **选择性蒸馏项**：训练策略 πθ（仅接收 state-free 上下文）去匹配带状态的条件分布 p⁺ᵢ,ₜ：
  $L_{distill} = \frac{\sum_{i,t} a_i w_{i,t} \, D_{KL}(\pi_\theta(\cdot|x_i,y_{i,<t}) \| p^+_{i,t})}{\sum_{i,t} a_i w_{i,t}}$
- **无状态奖励优化项**（state-free RL）：从环境反馈改善自主行为；
- 总损失： $L_{consolidate} = L_{state\text{-}free RL} + \lambda_{distill} L_{distill}$。

**(d) 提交门控**：候选策略 π̃ₖ₊₁ 只有当其无状态性能在验证集上通过验证标准后才被正式采用并重新部署。

### 2.4 循环闭环
更新后的 state–policy 对重新部署生成新的交互轨迹，下一轮的状态演化将依据新策略的行为分布来**保留、修正或废弃**已有显式指导，已内化到策略中的经验逐步被自动淘汰，由此阻止文本状态无限膨胀。

## 6. 主要结论与发现

1. **交替演化优于任何单一机制**：三环境平均上，完整状态–策略循环（57.6%）显著优于最好的状态只演化方法 SkillOpt（53.9%，+3.7）、最好的只内化方法 OPID（55.4%，+2.2），也优于最强的既有协同演化基线 SkillRL（56.2%，+1.4）。
2. **状态–策略共同推进产生了“能力沉淀”**：在接受的巩固轮次中，无状态（state-free）策略的 ACC 从 58.1% 上升到 61.3%，说明文本经验成功被逐步写成模型参数。最终匹配的 state–policy 组合达到 62.4%。
3. **显式经验的价值随策略演化而增长**：最后一轮中，演化状态与初始策略搭配只达 60.2%，而与其同代策略搭配达 62.4%——差距从中间轮次的 0.8 扩大到最终轮次的 2.2 个百分点，强证了“经验价值是策略依赖的”这一核心假设。
4. **选择性巩固优于全量蒸馏**：(01+11) 选择性子集的蒸馏效果明显优于不过滤训练（63.0% vs 58.9%），且优于任一单一类别（55.2% / 59.9%），证明跨版本的“迁移感知”筛选带来实质增益。
5. **状态蒸馏归功于显式经验本身，而非教师规模**：大模型教师（27B）在无状态条件下仅得 56.29%，比基线还低；只有带上更新状态才能达到 61.21%，小型教师（4B）无法从状态调节中获得同等的提升。

## 7. 优点

- **概念新颖**：将自进化划分为“快状态”和“慢策略”两个互补时间尺度，并显式建模二者间的调节关系，是对现有 methods（只做状态或只做策略或简单协同）的重要补充；
- **“漏斗”隐喻精准**：经验层层过滤——先是从原始轨迹到文本状态，再是从文本状态到参数化行为，再是按跨版本行为转移类型过滤——每一个阶段都有一套独立的验证门控；
- **设计严谨，防泄漏意识强**：训练/验证/测试的严格分离体现在整个流水线，且状态更新和策略提交都经 held-out 验证；
- **有清晰的机理分析**：验证了 teacher 能力与状态调节的交互效应、验证了选择性蒸馏的必要性、验证了状态–策略的协同进化不可分割性——这些机制层面的分析超过了泛泛的分数对比；
- **部署友好性意识**：明确将 consolidate 过程放到非延迟关键路径上，对齐真实场景（异步低峰期训练、sleep-time compute）。

## 8. 不足与局限

- **未披露关键算力与成本数字**：训练轮次、rollout 总数、NPU 流量、时间成本均无定量描述，导致算力–收益的性价比无从判断；
- **实验覆盖有限**：
  - 环境仅限 3 个（SearchQA / ALFWorld / WebShop），没有覆盖更通用、更复杂的编码或实际多工具使用场景（虽然摘要文字提到“execution-verified coding”，但正文中没有对应的编码实验结果）；
  - 没有对 α、λ_distill、批次大小等敏感超参数做系统扫描；
  - 用户没有选择不同基座规模（如 7B/13B/74B）的对比和验证；
- **统计可靠性不足**：只有最终的 comparison 提到了重复运行的不确定性——在中间各组实验中几乎都报告单次运行的分数，无法判断那些仅有 0.5–2 个百分点差距的对比是否显著；
- **跨环境平均值可能误导**：不同的 OPD 预算意味着跨环境的平均值只是描述性的，并不能严格代表同一训练预算下的公平比较；
- **双轨制的验证门控可能引入选择偏差**：5 轮演化只接受了两个 consolidation 轮次，被拒轮显然没有真实反映该轮次中的潜在收益，而门控阈值本身又高度依赖于验证集的大小；对于小验证集，被拒的更新可能是假阴性，可能降低了准确率；
- **计算/延迟的隐性成本未计**：每次状态演化前都会对同一实例进行 3 路 rollout（无状态、上一状态、更新状态）以获得迁移类型，这会引入常数级的线上推断负载增加，在真实在线部署中的延迟影响并未有更深层的细化讨论；
- **对单一算法族（Qwen3.5）的依赖性**：全文的“教师”与“学生”都来自同一个模型家族（Qwen 3.5）——教师与学生跨家族的多样性会被掩盖。

## 总结

体验漏斗提出了“快状态适应 + 慢策略巩固”的交替进化范式，通过状态验证和跨版本选择性蒸馏解决了经验在快速适应与长期内化之间的冲突，实验验证了“经验→文本状态→甄别→参数化能力→重新部署”这一闭环模式的显著优势，兼具方法创新与机理分析的深度。但算力信息缺失、统计可靠性有限、范围偏小、多环境预算不一致限制了这份工作的整体可控性与适用范围；其最核心的后续发展方向，应在于更全面的算力成本刻画、更广泛和更可控的多环境配置，以及跨基座与跨教师的泛化验证。

## 9. 对该工作的综合定位与学术价值评估

综合来看，Experience Funnel 在自进化智能体这一快速发展的方向上提供了一个**概念清晰且工程可落地的整合范式**。它并未发明全新的强化学习算法，也未依赖更大的模型或更复杂的提示工程，而是把三类已被分别验证的技术——**显式状态更新、策略蒸馏、验证门控**——放在一个“状态—策略交替演化”的闭环中，并通过精心的实验设计证明三者之间存在强耦合、缺一不可。其方法论贡献可以概括为两点：

1. **提出“经验价值随策略改变而改变”的视角**：经验不是静态资产，而是与策略共同演化的动态变量。这一视角将“经验管理”问题从信息检索或记忆压缩问题，重新定义为策略与状态间的协同优化问题；
2. **给出可操作的“迁移感知”筛选标准**：通过三路 rollout 比较区分新近有用、持续有用、倒退、无效四类轨迹，并将状态响应型 token 归因纳入蒸馏损失，使得“该内化什么、不该内化什么、该从哪些 token 去学”均有明确的量化依据。

因此，该工作不仅是一个效果更好的系统，更是一个**可用于分析“经验何时应当外显、何时应当内隐”的通用研究框架**。

## 10. 后续研究的具体方向与建议

针对上述不足，后续研究可从以下四个层面推进：

- **算力—收益的量化刻画**：建议作者报告三类成本指标——(a) 单轮状态演化的 rollout 与验证开销；(b) 单轮策略巩固的蒸馏与 RL 开销；(c) 三路 rollout 造成的在线推理常数倍数。并给出每提升 1% 平均成功率所需的额外 NPU 小时数，使该方法与“仅扩大模型规模”等替代路径具备可比性；
- **门控策略的去耦合验证**：当前 5 轮演化中有 3 轮被拒绝，难以排除“拒绝本身”对结论的贡献。未来应在固定门控阈值的条件下，对比“接受所有轮次”“随机接受 50%”“基于验证集动态接受”等多种调度策略，以分离门控设计与演化算法各自的贡献；
- **超参数与规模的系统扫描**：应对 α（持续有用轨迹的相对权重）、λ_distill（蒸馏损失系数）、验证集大小、教师—学生规模差（如 4B→27B 与 27B→72B）做网格化敏感性分析，并给出平均分 ± 标准差（至少 3 个随机种子）；
- **跨域的泛化验证**：除 SearchQA / ALFWorld / WebShop 外，宜补充真实编码任务（如 SWE-bench）、多工具 Agent 任务（如 τ-bench）以及长程决策环境，验证“状态—策略交替演化”模式在奖励稀疏、状态空间更大场景下的普适性。

## 11. 对读者的参考建议（如何使用该论文）

对于不同身份的研究者，本文的参考价值侧重不同：

- **做 Agent 系统的研究者**：可直接借鉴其“验证门控分批更新”的工程架构，在真实部署中采用异步低峰期巩固（sleep-time compute）以规避在线延迟问题；
- **做 LLM 对齐/RL 的研究者**：可借鉴其“选择性蒸馏”的轨迹筛选思路——将策略更新后的“新增益轨迹”作为强化信号而非全量吸收——这对缓解 RL 训练中的奖励黑客与过拟合具有启发意义；
- **做模型记忆与技能研究的读者**：本文的 (0,1)/(1,1) 轨迹分类方法可作为衡量“外部记忆何时真正起作用”的分析工具，也可用于诊断记忆系统的失效模式。

## 12. 总结（衔接前文）

总而言之，Experience Funnel 以一个简洁而深刻的隐喻——“漏斗”——统一了快慢两种经验吸收方式，用交替循环取代并行叠加，用选择性取代全量，用验证门控取代盲目信任。它有力地证明了：**自进化智能体的核心瓶颈不在于经验的数量，而在于经验的“消化方式”**——只有经过状态层验证、迁移类型筛选、token 级归因和策略层再验证的多级过滤，经验才能真正转化为稳定可复用的能力。该工作在概念层面的清晰性、方法层面的严谨性和分析层面的深入性均值得肯定，尽管其在算力披露、统计可靠性和实验广度上的不足也提醒我们：好的范式不仅需要聪明的设计，还需要在实证层面经受更严苛、更全面的检验。

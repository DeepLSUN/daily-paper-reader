## 摘要
基于大型语言模型的多智能体系统正在从固定的交互拓扑结构向动态编排的智能体集群演化。然而，现有基准测试仍主要基于单智能体或通用智能体任务，难以系统性地评估关键的编排能力。我们提出SwarmBench，一个从准确性、效率、成本和过程质量等多个角度评估模型性能的基准。实验结果表明，当前模型在编排能力上表现出显著差异。这些差异不仅体现在最终的准确性、效率和成本上，也体现在编排过程本身的整体质量上。基于这些发现，我们进一步提出SwarmExp，一种简单但有效的基于经验提取和经验回放的方法，能够持续提升大型语言模型的编排性能。

## Abstract
Large language model-based multi-agent systems are evolving from fixed interaction topologies toward dynamically orchestrated Agent Swarms. However, existing benchmarks are still largely based on single-agent or general-purpose agent tasks, making it difficult to systematically evaluate key orchestration capabilities. We propose SwarmBench, a benchmark that evaluates model performance from multiple perspectives, including accuracy, efficiency, cost, and process quality. Experimental results show that current models exhibit substantial differences in orchestration capability. These differences are reflected not only in final accuracy, efficiency, and cost, but also in the overall quality of the orchestration process itself. Based on these findings, we further propose SwarmExp, a simple yet effective method based on experience extraction and experience replay, which consistently improves the orchestration performance of large language models.

## 1. 论文的核心问题与整体含义（研究动机和背景）

近年来，基于大型语言模型的多智能体系统正在从"固定协作范式"向"动态编排范式"演进。所谓 **Agent Swarm（智能体集群）** 是指层次化、动态实例化、可并行执行的多智能体系统——由一个主智能体作为编排者（orchestrator）动态地分解子任务、创建子智能体、协调其并行执行并聚合结果。该范式的核心挑战由此转向：**大语言模型能否胜任"集群编排者"的角色**，即高效组织动态集群来完成复杂任务。

然而，现有评估体系存在明显缺口：
- 许多多智能体研究仍借用原本为单智能体或通用智能体设计的基准，无法系统性暴露 Agent Swarm 的关键能力；
- 即便某些任务适合多智能体协作，现有评估大多只关注最终答案质量，忽视了编排过程本身的合理性（如任务分解是否合理、子智能体创建是否有效、结果聚合是否完备）。

针对这一空白，论文提出 **SwarmBench**——一个专门针对大模型作为 Agent Swarm 编排者能力的评测基准，从准确性、效率、成本、过程质量四个维度进行系统评估，旨在回答"大模型能否以及如何更好地充当集群编排者"这一核心问题。

## 2. 论文提出的方法论

### 2.1 SwarmBench：多维度评估基准

**Agent Swarm 的形式化定义。** 给定输入任务 x，Agent Swarm 过程表示为：

\[
S(x) = \langle o, H, \Pi_o, \Pi_h, U, B \rangle
\]

其中，o 表示编排者；H 表示可用的子智能体配置集合；Πo 表示编排策略；Πh 表示子智能体执行策略；U 表示可用工具与外部环境；B 表示执行预算（步数限制、智能体数量、延迟或货币成本）。编排者在每个全局步骤 t 观察状态 st，并通过策略 Πo(·|st) 输出编排动作。当动作是 spawn_agent 时，编排者创建具有配置 ϕi = (ri, mi, τi, ci) 的子智能体（分别对应角色描述、骨干模型、工具集和局部上下文）。并行度定义为 ρt = |Ht|。

**数据集构造。** SwarmBench 包含 **3 大任务类别、8 个任务类型、400 个样本**（每个任务 50 个样本）：

| 任务类别 | 评估能力 | 任务 | 来源 |
|---|---|---|---|
| 分解导向（Decomposition-Oriented） | 将复杂目标分解为可并行/递进的子任务 | MATH、Batch Download (BD)、Multi-Text Understanding (MTU) | Omni-MATH、自建、Loong |
| 委派导向（Delegation-Oriented） | 选择合适骨干模型、创建恰当角色、按需委派 | Multi-Perspective Analysis (MPA)、Root Cause Analysis (RCA)、Treasure Hunt (TH) | DeepReview、OpenRCA、自建 |
| 聚合导向（Aggregation-Oriented） | 筛选、整合多个子智能体的局部输出为统一结果 | Long-Text Generation (LTG)、Wide Search (WS) | LongInOutBench、WideSearch |

**Agent Swarm 评测框架。** 采用轻量级通用框架：主智能体负责分解、创建、委派、聚合；子智能体在各自局部上下文中独立执行。为使评测聚焦于编排能力：主智能体不允许调用工具或独立作答，部分任务上下文对主智能体隐藏；骨干模型从可配置的模型池中选择（每个模型附带公开信息编写的描述，由主智能体动态选用）。

**评估维度。** ① 准确性：各任务标准指标；② 效率：并行率（平均并发子智能体数）与并行增益（串行时间/实际时间）；③ 成本：实际产生的美元费用（按模型 token 单价计算）；④ 过程质量：基于 LLM 的评估框架，对任务分解、子智能体委派、结果聚合三个维度打分。

### 2.2 SwarmExp：经验驱动的编排增强方法

SwarmExp 采用两阶段管道：

**(a) 轨迹生成**：在基础 Agent Swarm 框架上运行推理，收集完整执行轨迹。  
**(b) 经验总结**：从轨迹中提取三类可复用知识：
- **Skill（技能）**：高层工作流模式，描述某类任务的分解方式、子智能体组织与聚合策略，整理为标准化的 SKILL.md 文件（含元数据、工作流、示例、注意事项）。
- **Trick（技巧）**：细粒度的可操作经验（如减少冗余信息、更合理分配子任务），以"条件→动作"句式存入技巧库，供执行中检索。
- **Model Card（模型档案）**：对子智能体骨干模型在具体任务上的实际表现进行总结（适用场景、优势、短板），辅助主智能体在委派时做出更合理的模型选择。

**(c) 经验重放**：推理时将三类经验注入主智能体上下文，使其在任务规划、子智能体委派与结果聚合各阶段参考历史经验，提升编排稳定性与质量。

## 6. 论文的主要结论与发现

1. **模型编排能力分布高度不均**。GPT-5.4 是最强且最均衡的编排者（8 个任务中 6 个最优）；Claude-Sonnet-4-6 在角色组织和内容综合类任务（MPA、LTG）表现突出；开源模型的能力呈现碎片化特征：Kimi-k2.5 在委派类任务（RCA、TH）最稳定，Qwen3.5-397b-a17b 在聚合类任务（LTG、WS）占优，中小规模开源模型编排能力明显不足。

2. **成本与性能不存在简单线性关系**。更强的编排者能以更低成本获得更高性能；而较弱的编排者更多交互与冗余执行，却未必换取更好的结果。任务间差异也大：MATH、BD 性能随成本提高而改善，MPA、LTG 等则呈"收益递减"现象。

3. **并行度并非效率的唯一决定因素**。Kimi-k2.5 的并行率最高但并行增益不是最高；Gemini-3-flash 以中等并行率实现最高并行增益。时间缩减的关键在于编排结构是否有效（能否避免等待冗余、重复执行等），而不在于同时运行的子智能体数量多寡。

4. **聚合是当前模型最难以稳定的编排环节**。过程质量分析显示大模型在"发起和分配子任务"上相对较好，但在"集成子智能体输出并做出连贯最终决策"上普遍表现最弱。

5. **SwarmExp 能稳定提升编排性能**。在 MTU、RCA、LTG、WS 四个任务上分别提升 +0.25、+6.42、+6.46、+2.92。消融表明三类经验成分均有贡献，其中 **Model Card 的贡献最为关键**（去除后平均下降 2.49），说明对子智能体骨干模型能力的准确认知对编排质量有重要影响。跨模型迁移实验中 16 个设置里 14 个有提升，说明经验具有一定的泛化性。

## 7. 优点

- **填补空白，切入准确**：首个聚焦"LLM 作为 Agent Swarm 编排者"能力的系统基准，针对的正是当前多智能体系统研究中最前沿的范式缺口。
- **多维度评估设计完整**：同时覆盖准确率（任务结果）、效率（并行增益）、成本（美元计量）和过程质量（分解/委派/聚合三维度），相比传统只测最终准确率的基准，能揭示更深层的能力差异。
- **自行构造高质量任务**：Batch Download 与 Treasure Hunt 两个自建交互任务设计精巧（包含大量干扰项、局部可观测地图、角色分工等），针对性强；基于已有公开数据集改造任务时进行了多智能体适配。
- **框架设计增强实验可控性**：统一框架、固定子智能体模型池、主智能体限制不能独立调用工具、部分上下文隐蔽等设计较好地隔离了"编排能力"这一被测量变量。
- **结论可靠度高**：方差分析、成本匹配对照、人机一致性检验、跨模型/跨任务迁移等设计从多角度验证了结果可靠性。
- **SwarmExp 方法简洁且有效**：经验提取设计（skill/trick/model card 三级分层）清晰，能揭示模型卡对编排的关键作用，对未来"经验驱动型编排"的研究具有启发价值。

## 8. 不足与局限

- **规模有限**：仅 8 个任务（每任务 50 样本，合计 400）难以覆盖真实世界中所有 Agent Swarm 场景；任务数量较少可能限制结论的普适推广。
- **统一的轻量级框架约束**：论文所有模型都在同一个轻量级 swarm scaffold 和固定的子智能体模型池下运行，虽然提高了跨模型可比性，但也意味着评估的只是"在该框架约束下的编排能力"——不同框架设计偏好可能影响模型发挥，限制了结论的泛化性。
- **部分评估依赖 LLM 判断**：开放任务指标和过程质量评分采用了 LLM-based 评估器（虽有人工一致性验证，但相关系数 0.68–0.80 尚非极强）；LLM judge 自身可能存在系统性偏差。
- **缺少算力信息披露**：未报告具体的计算资源（GPU 规格与数量、总推理预算等），影响复现与成本评估。
- **跨任务迁移效果不均衡**：消融和相关实验表明 SwarmExp 的跨任务迁移依赖任务类型——对搜索类任务（WS）效果有限甚至有害，说明经验的"任务特异性"问题仍需解决。
- **未来系统风险未深入讨论**：论文承认多智能体系统可能引入错误传播、不良协调行为与误导性输出放大等风险，但仅作为伦理声明阐述，未展开分析或提出缓解策略。

## 摘要
部署用于软件工程的LLM智能体会产生高昂的失败：它们自信地犯错，而错误行为往往只有在昂贵的执行和重试之后才被识别。我们提出了推测性不确定性（SU），这是一种仅从黑盒智能体的输出令牌中恢复预测性失败信号的方法，无需访问logits、权重、激活或重复采样。通过反转推测解码，一个小型的开放权重草稿模型在单次前向传播中对智能体已生成的轨迹进行评分。我们从这些推测性交叉似然中，通过分离推理和动作跨度提取阶段感知特征，并针对可验证的目标进行校准。SU生成一个失败似然分数，任何下游策略（如路由、人工干预或额外的测试时计算）都可以直接使用。为了证明该信号是可操作的，我们在软件工程智能体Qwen3-Coder-480B和闭源的Claude 3.5 Sonnet上实例化了一种这样的策略，即执行前否决门控，在部署中将执行错误率降低了6-8个百分点，令牌成本降低了14-19%，无需重新训练即可迁移到分布外基准，并能跨智能体模型泛化。

## Abstract
LLM agents deployed for software engineering fail expensively: they act confidently wrong, and bad actions are recognized only after costly execution and retry. We present Speculative Uncertainty (SU), a method that recovers a predictive failure signal for a black-box agent from its output tokens alone, with no access to logits, weights, activations, or repeated sampling. Inverting speculative decoding, a small open-weight draft model scores the agent's already-generated trajectory in a single forward pass. From these speculative cross-likelihoods we extract phase-aware features by separating the reasoning and action spans, and calibrate them against a verifiable objective. SU produces a failure-likelihood score that any downstream policy, such as routing, human intervention, or extra test-time compute, can consume directly. To show the signal is actionable, we instantiate one such policy, a pre-execution veto gate, on software engineering agents Qwen3-Coder-480B and closed-source Claude 3.5 Sonnet, cutting execution error rate by 6-8 percentage points and token cost by 14-19% in deployment, transferring to out-of-distribution benchmarks without retraining, and generalizing across agent models.

## 一、核心问题与整体含义（研究动机与背景）

- **核心痛点**：LLM智能体在软件工程场景（如自动修patch、运行测试、查询数据库）中展现出强大能力，但存在一个昂贵且普遍的失败模式——**“自信地犯错”**。智能体在执行错误动作前往往没有任何失败信号，错误只有在环境拒绝执行后才会暴露，此时代码已运行、上下文已被填满、重试成本已经付出。
- **部署约束**：现实生产环境中的两个物理约束极大限制了可用的不确定性估计方法：
  1. **黑盒访问**：最强大的已部署智能体多数是闭源API模型（如Claude 3.5 Sonnet），不暴露logits、权重或激活，白盒探测类方法完全不可用；
  2. **采样成本过高**：基于采样（sampling）的不确定性估计需要在每一步多次生成，在智能体长期任务中代价过高，无法落地。
- **现有方法局限**：最接近的前序工作HTC（Holistic Trajectory Calibration）虽提出轨迹级校准框架，但仍假设白盒访问，并将轨迹视为同质token流——这两个假设在真实部署中均无法成立。
- **整体意义**：如何在**黑盒、不重复采样**的前提下，从智能体已生成的输出中提取可操作的失败信号，是本文试图回答的核心问题。该问题的解决意味着可以在环境执行之前预判失败、触发干预，从而避免昂贵的“执行-失败-重试”循环。

## 二、方法论：核心思想、技术细节与算法流程

### 1. 核心思想：反转投机解码（Inverted Speculative Decoding）

- 投机解码（Speculative Decoding）原本利用小型草稿模型提出候选token以加速大模型推理。本文将其**反转**：不是让草稿模型生成，而是让草稿模型对被评估智能体**已生成的轨迹**做teacher-forcing打分。
- 关键洞见：若草稿模型q与被评估智能体p的对齐程度足够好，那么q在p生成token上的高投机惊讶度（speculative surprisal）可以推断p自身在该位置的接受率很低，从而作为p的内部不确定性的**黑盒代理信号**。

### 2. 问题设置与符号定义

- 轨迹结构：智能体产生交替的推理跨度（reasoning span）和动作跨度（action span）：
  `T = (r1, a1, r2, a2, ..., rN, aN)`
- 可验证目标：外部Oracle函数 Ω(a, x) ∈ {0,1} 对动作a在上下文x中给出二元客观判断（本文中为代码执行是否无异常退出）。
- 操作粒度：SU在**步骤级别**预测，并使用**固定回看窗口**（k=3个最近步骤）对当前动作失败概率给出预测：
  `ŷ = F(Wi) ∈ [0,1]`

### 3. 投机交叉似然信号（Speculative Cross-Likelihoods）

对轨迹中的每个token yt，草稿模型q在teacher-forcing模式下给出三个信号：

- **投机惊讶度**：`st = -log q(yt | x, y<t)`
- **投机差距**：`gt = log q(ŷt | x, y<t) - log q(yt | x, y<t)`（ŷt为草稿模型最优token）
- **投机熵**：`Ht = -Σv q(v | x, y<t) log q(v | x, y<t)`

这三个信号只需要被评估智能体的**可见输出token流**，完全不需要p的任何内部状态。

### 4. 相位感知特征提取（关键设计）

- **经验发现**：智能体生成具有明显的相位结构——推理阶段熵高（探索性），动作阶段熵显著下降（受语法和工具调用结构约束）。失败信号在推理阶段和动作阶段**方向相反**（失败步骤在推理时更不确定，在动作跨度中反而过于确定），若混在一起会互相抵消。
- **特征构造**：在回看窗口内，分别对推理token和动作token，针对上述三种信号各计算8个统计量（均值、方差、最大、最小、偏度、趋势、前/后10%均值），加上两个跨度长度，共得到50维特征向量 φ(Wi) ∈ R⁵⁰。

### 5. 校准器与下游策略

- 校准器采用**ℓ1正则化逻辑回归**，将50维特征映射为校准的成功概率，目标函数为二元交叉熵加ℓ1惩罚。选择线性模型是为了在小数据环境下稳健且可审计。
- **否决门（Veto Gate）策略**：当预测成功概率低于阈值τ时，阻止当前动作执行，触发一次**更廉价的重新规划（replan）**而非昂贵的执行-失败-重试循环；超过最大重试次数K则弃权。整个管线为：单次草稿前向打分 → 相位感知特征 → 线性校准器 → 阈值门控决策。

## 六、主要结论与发现

1. **黑盒失败信号可恢复**：仅从输出token即可恢复可用的预测性失败信号。SU将AUROC从口头置信度的0.57提升至0.77（SWE-Bench Verified），逼近白盒HTC的0.82，显著超越白盒log-prob基线（Last-TP 0.68、Global-TP 0.65）。
2. **相位分离是关键**：将SU-Uniform（不分相位，0.71）与完整SU（0.77）对比，相位感知的特征提取贡献了5-6个AUROC点，验证了推理/动作相位结构对信号的价值。
3. **草稿对齐至关重要，但对齐方式不重要**：未经训练的草稿仅有0.61 AUROC（几乎不优于口头置信度），蒸馏后提升至0.77；但SFT和TF两种蒸馏目标几乎无差异（.76 vs .77）——关键是**训练语料**，而非蒸馏目标。
4. **部署效果显著**：执行前否决门在SWE-Bench Verified上将每次调用执行错误率从21%降至15%（降6个百分点），在DA-Code上从14%降至6%（降8个百分点），同时token成本降低14-19%；且零样本迁移至OOD基准。
5. **跨智能体泛化可行**：在Qwen语料上训练的草稿迁移到Claude 3.5 Sonnet可达0.69 AUROC，远高于未训练基线（0.60），接近混合语料训练的0.75。这表明开放权重智能体可以作为对齐闭源目标的代理。
6. **不提升任务成功率**：门控带来的replan不能保证修复任务——SWE-Bench Verified任务成功率反而从49%降至44%，DA-Code近似不变。**SU的部署价值在于削减成本和静默失败，而非提高benchmark分数。**

## 七、优点（方法或实验设计的亮点）

1. **问题选择精准**：针对真实部署中最关键的痛点（黑盒、无内部访问、采样不可行）提出方案，规避了大多数UQ工具的限制条件。
2. **巧妙的思路迁移**：将投机解码的机制“反转”，变加速工具为评估工具，以小型开放草稿模型作为黑盒智能体的不确定性代理，概念新颖且实践门槛低。
3. **相位感知设计**：通过实验发现推理/动作跨度的熵结构差异和失败信号的方向差异，进而设计分离的特征提取——这是本文最重要的方法学贡献，避免了简单平均稀释信号的问题。
4. **面向部署评估**：不仅报告判别/校准指标，还实际实例化下游策略（否决门），在真实干预下度量错误率与成本，增强了结果的可信度和落地参考价值。
5. **诚实的实验报告**：明确报告了与白盒方法的差距、任务成功率的轻微下降、校准缺口等负面结果，没有选择性报告。
6. **OOD与跨模型验证**：零样本迁移（DA-Code）和跨智能体迁移（Qwen训练的草稿用于Claude）实验设计严谨，让结论的可泛化性更有底气。

## 八、不足与局限

1. **单一目标与域**：所有实验都基于代码执行成功这一可验证目标。框架虽声称可泛化至SQL代理、Web代理等领域，但未提供任何量化证据。
2. **单次运行估计**：没有报告多次运行的标准差/置信区间；表1中若干方法之间差距仅数个AUROC点（如SFT .79 vs TF .80），在无方差信息时统计显著性存疑。
3. **校准缺口未闭合**：SU的原始输出有残余误校准（ECE约.02-0.06，MCE可达.06），作者虽解释门控只依赖排序质量不受影响，但若下游策略直接消费概率值本身，目前还不安全。
4. **校准器未在OOD重新拟合**：λ和阈值在训练集上选取后冻结，虽然这保证了公平性，但也可能牺牲了OOD上的最佳表现。
5. **任务成功率下降未充分讨论**：门控将SWE-Bench Verified任务成功率从49%降至44%（5个百分点的相对8%的下降），这在实际应用中可能是一个重要的负面副作用，论文解释为replan策略简单所致，但更优的干预策略仍留待未来。
6. **草稿成本的前提依赖**：论文假设草稿前向成本“几乎免费”成立，这依赖特定场景（小型4B草稿足以产生信息量足够的信号），不保证迁移到需要更大草稿模型才能提取有用信号的领域。
7. **未与其他黑盒方法充分对比**：在纯黑盒设定下（同等的单次前向成本下）缺少与现有方法的系统性对比。

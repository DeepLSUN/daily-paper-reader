## 摘要
大语言模型（LLM）智能体越来越多地将自然语言推理与外部工具（如网络搜索和代码执行）交织在一起。这些工具使用策略通常通过强化学习（RL）进行优化，而强化学习可能放大训练数据中的伪相关。在这项工作中，我们研究 RL 训练的智能体何时以及为何会学到捷径式工具选择策略：基于表面的提示线索而非真实任务需求来调用工具。我们构建了结合事实问答和数学推理任务的可控合成环境，并注入在训练期间与特定工具强相关、但与工具必要性无因果关系的线索。在线索存在但相关工具并不需要的反事实评估中，智能体表现出显著的捷径行为，虚假工具调用率最高增加 39%。然而，捷径的形成并非普遍存在：在我们测试的各种条件下，只有当智能体已经学会可靠地使用目标工具时才会出现，这表明任务能力而非仅数据集不平衡，是捷径学习的一个关键因素。一项交换线索分析进一步表明，线索与工具之间的语义对齐会显著放大这一效应。为缓解这些失败，我们引入一种密集的、决策级奖励，其中由 LLM 评判器评估每次工具调用的必要性。这种工具必要性奖励在保持任务性能的同时，有效抑制了线索驱动的工具使用，为提升 LLM 智能体工具使用策略的鲁棒性提供了一种实用方法。

## Abstract
Large language model (LLM) agents increasingly interleave natural language reasoning with external tools such as web search and code execution. These tool-use policies are often optimized via reinforcement learning (RL), which can amplify spurious correlations in the training data. In this work, we study when and why RL-trained agents learn shortcut tool-selection policies: invoking tools based on superficial prompt cues rather than genuine task requirements. We construct controlled synthetic environments combining factual question answering and mathematical reasoning tasks, and inject cues that are strongly correlated with specific tools during training but causally irrelevant to tool necessity. Across counterfactual evaluations where cues are present but the associated tools are not required, agents exhibit substantial shortcut behavior, with spurious tool invocation rates increasing by up to 39 percent. However, shortcut formation is not universal: across the conditions we test, it arises only when the agent has already learned to use the target tool reliably, suggesting that task competence, rather than dataset imbalance alone, is a key factor in shortcut learning. A swapped-cue analysis further shows that semantic alignment between cues and tools substantially amplifies this effect. To mitigate these failures, we introduce a dense, decision-level reward in which an LLM judge evaluates the necessity of each tool call. This tool-necessity reward effectively suppresses cue-driven tool use while preserving task performance, providing a practical approach to improving the robustness of LLM agent tool-use policies.

# 论文总结：Spurious Tool Use: When RL Agents Learn the Wrong Reason to Act

## 1. 核心问题与研究动机

- **背景**：LLM 智能体越来越多地交替进行自然语言推理与外部工具调用（网络搜索、Python 解释器），其工具使用策略普遍通过强化学习（RL）优化。
- **核心问题**：RL 会放大训练数据中的伪相关，使智能体学到**捷径式工具选择策略**——依据表面提示线索（如格式标签、来源标记）调用工具，而非依据任务本身的真实需求。
- **与既有研究的区别**：
  - 不是研究"工具调用低效/过度调用"（efficiency）问题，而是研究**线索驱动的虚假工具选择（cue-driven spurious tool selection）**。
  - 该失败模式发生在**中间策略决策层（选哪个工具）**，而非最终预测层（产出什么答案）。
- **为何难以察觉**：不必要的工具调用**未必导致答案错误**（例如智能体调用搜索后忽略结果仍答对）。因此仅评估最终答案正确性的标准协议会漏检此类行为。
- **关键张力（本文最有价值的观察）**：捷径脆弱性与**任务能力正相关**——智能体越擅长某工具，越容易把该工具与无关线索绑定，即"能力提升可能同时提高捷径易感性"。

## 2. 方法论

### 2.1 问题形式化

- 沿用群体鲁棒性框架（Sagawa et al., 2019）：输入表示为 `x = (x_c, a)`，其中 `x_c` 为因果特征，`a` 为与标签相关但非因果的伪属性；群体 `G = Y × A`，用最差群体风险 `R_max` 与平均风险 `R_avg` 的差距 `Δ_spurious` 度量捷径依赖。
- 扩展到工具选择场景：策略 `π_θ(T | x)`，二值奖励 `R ∈ {0,1}`，期望奖励分解为
  `P(R=1|x) = Σ_T π_θ(T|x) · P(R=1|x,T)`，其中 `P(R=1|x,T)` 是工具的功能性效用。
- **定义 1（工具伪相关）**：若线索 `a` 的存在把工具 `T_s` 的选择概率抬升到超出任务相关特征应有的水平，即 `π_θ(T_s|x_c,a) ≫ π_θ(T_s|x_c)`，且该工具对任务**无增益**（`P(R=1|x_c,T_s) ≤ P(R=1|x_c,T≠T_s)`），则称策略存在伪相关。该定义刻意放宽"工具零效用"要求，以覆盖"调用但无害"的情形。
- **操作化指标**：对每个问题构造线索存在（Y）与线索缺失（N）两个反事实变体，计算
  `ΔTool_{Y-N} = π̂_θ(T_s|x_c,a) − π̂_θ(T_s|x_c)`。
  在不需要该工具的任务上 ΔTool 为正，即表明存在线索驱动调用。

### 2.2 合成数据构建

- 数据源：Natural Questions（NQ，宜用搜索）与 DeepMath-103k（宜用 Python 解释器），各采样 500 条，构成 1000 条平衡训练集。
- 仅向其中一个子集注入线索，另一子集保持不变，每条线索单独训练一次以隔离效应。
- **搜索语义线索**（注入 NQ）：`Source: [WEB INDEX 742]`、`[REFERENCE]`（前缀），`<answer></answer>` 格式指令（后缀，因其为输出格式指令）。
- **代码语义线索**（注入 DeepMath）：`# Cell [1] | kernel: python3 | status: idle`、`#!/usr/bin/python3`（前缀）、`[CODE]`。
- 所有线索均**与工具必要性因果无关**。

### 2.3 工具必要性奖励（缓解方法）

- 思想：标准 RL 只给最终答案奖励，工具选择决策处于"无监督"状态；改为提供**密集的决策级反馈**。
- 必要性定义：只有当"有能力的模型不使用该工具就无法正确作答"时才算必要；便利性使用（平凡算术、格式化、复核）不算必要。
- 实现：用 **GPT-5 Nano 评判器**接收问题 `q`、工具类型 `τ_t`、工具输入 `x_t`，输出二值标签 `n̂_t = Judge(q, τ_t, x_t)`；评判标准是"该工具对解决问题是否必要"，而非工具输入本身是否合理。
- 总奖励：`r_total = r_task + Σ_t r_t^nec`，其中 `r_t^nec = −α`（若 `n̂_t = 0`），否则为 0，取 `α = 0.5`；仅惩罚不必要调用，避免反向激励"为用而用"。

### 2.4 训练框架

- 使用 **VerlTool** 模块化智能体 RL 框架，算法为 **GRPO**，基座模型 **Qwen2.5-7B-Instruct**（无额外 SFT）。
- 工具以结构化标签触发：`<python>...</python>` 与 `<search>...</search>`，环境执行并回传观测作为后续上下文。

## 3. 实验设计

- **数据集/场景**：
  - 训练：NQ（事实问答，500）+ DeepMath-103k（数学推理，500）。
  - 测试：域内 DeepMath / NQ；**留出泛化** GSM8K（数学）、2Wiki（多跳事实问答），同样构造反事实变体。
- **评估协议（benchmark）**：以 `ΔTool_{Y-N}` 为核心指标（线索导致的工具调用率增量），同时报告准确率 `Acc`，用于检验缓解方法是否牺牲性能。
- **对比条件（消融维度）**：
  - 无训练（No training）基线；
  - 无线索（No cue）训练基线；
  - 注入线索（Cue）；
  - 注入线索 + 工具必要性奖励（+Reward）。
- **交换线索对照（swapped-cue）**：把代码语义线索注入 NQ（能力已习得但语义不匹配），把搜索语义线索注入 DeepMath（语义匹配但能力未习得），用于解耦"任务能力"与"语义对齐"两个混淆因素。
- **相关性强度消融**：将线索对齐训练样本比例从 100% 依次降至 90/80/70/60/50%。
- **训练动态分析**：对比 NQ 与 DeepMath 在训练/验证集上的准确率曲线。

## 6. 主要结论与发现

- **捷径确实形成且幅度显著**：搜索语义线索使数学任务上的不必要搜索调用大幅上升，`ΔSearch` 最高达 **+39.2%**（GSM8K，`[WEB INDEX 742]`），DeepMath 上为 +19.9%；`<answer>` 为 +21.7%（DeepMath）/+9.5%（GSM8K）；`[REFERENCE]` 为 +7.7%/+20.1%。
- **不对称性**：代码语义线索注入数学训练后，在事实任务上的 `ΔPy` 很小（Cell −0.3%、[CODE] +0.7%、2Wiki 上 [CODE] +3.8%），远弱于搜索线索方向。
- **任务能力是捷径形成的前提**：训练曲线显示 NQ 验证准确率从约 45% 升到约 75%，而 DeepMath 一直徘徊在 45–50%。**只有已被可靠学会的工具才会形成线索关联**。
- **语义对齐调节强度**：交换线索后，即便任务能力充足，语义不匹配的线索只带来 ≤3.5% 的 `ΔSearch`，远低于对齐情形的最多 39.2%。即"能力使捷径成为可能，语义对齐决定其强度"。
- **相关性强度存在阈值效应**：80% 及以上相关性时捷径明显（+21.7%/+12.1%/+11.7%），70% 及以下基本消失（≈0%），提示 RL 只在相关性足够强时才放大捷径。
- **工具必要性奖励有效**：在所有条件下把线索驱动的工具调用压到接近 0（如 0.0%/0.0%，Δ≈+0.0%），同时准确率保持或提升（例如 GSM8K 上从 81.6% 提升到 91.8%；`[WEB INDEX]` 条件下 92.8%）。
- **总体判断**：仅靠结果奖励的 RL 不足以产生鲁棒的工具使用策略；需要对工具选择决策本身进行显式监督。

## 7. 优点

- **问题定位新颖且有价值**：把"捷径学习"从监督学习的最终预测层，迁移到 RL 智能体的中间决策层（工具选择），并指出"调用错误但答案正确"这一评估盲区。
- **形式化清晰**：给出可操作的伪相关定义与 `ΔTool_{Y-N}` 指标，便于后续工作复现与扩展。
- **实验设计巧妙**：反事实评估组 + 交换线索对照 + 相关性强度消融，三件套有效解耦了"任务能力""语义对齐""组不平衡"三个混淆因素，得出的因果归因相对可信。
- **反直觉的核心洞见**："能力越强越易受捷径影响"（capability–shortcut coupling），对智能体训练实践有直接警示意义。
- **缓解方法简单可落地**：LLM 裁判 + 每步惩罚（α=0.5），实现成本低，且实验显示不牺牲（甚至提升）任务准确率。
- **诚实与规范**：明确声明使用 LLM 辅助写作、LLM 裁判的偏差风险，并提供完整超参与裁判 prompt，可复现性较好。

## 8. 不足与局限

- **实验规模与统计严谨性**：
  - 每个条件仅 1 个种子、30 步训练、1000 条数据，未报告方差或显著性检验，小幅度 Δ（如 +0.7%、+3.5%）难以与噪声区分。
  - 仅使用 Qwen2.5-7B-Instruct 一个模型，未验证模型规模/家族的泛化性。
- **环境合成化**：线索是人工注入的显式标记（`[WEB INDEX 742]`、`#!/usr/bin/python3` 等），与真实语料中隐式、分布式的伪相关（如特定措辞、领域词汇）差异较大；作者也承认需要自然化训练环境验证。
- **工具与任务覆盖有限**：只有搜索与 Python 两种工具、两类任务；多工具协作、工具链组合、更复杂 agentic 流程未涉及。
- **阈值结论脆弱**：~80

% 相关性阈值仅基于 `<answer>` 单一线索与单一训练设置得出，未在其他线索、模型、任务或奖励设计上系统验证；阈值可能随模型规模、数据量、训练步数与线索显著度变化，作者也将其列为开放问题。

- **缓解方法依赖 LLM 裁判**：工具必要性由 GPT-5 Nano 判定，可能引入裁判偏差、成本与不可复现性；若裁判对“必要性”的判断本身不稳定或与任务真实效用不一致，奖励信号会被污染。论文未与规则判别、人类标注或更轻量分类器做对照。
- **因果归因仍有限**：交换线索与反事实设计增强了内部效度，但训练动态显示 NQ 准确率明显上升、DeepMath 长期停滞，说明“能力”与“任务难度/训练分布”仍可能纠缠；数学侧捷径虽出现，但工具能力未显著提升，能力阈值的确切机制尚未完全刻画。
- **指标覆盖有限**：`ΔTool_{Y-N}` 能捕捉线索驱动的调用增量，但不能区分“调用后忽略结果”“调用后错误使用结果”“调用替代了正确推理”等不同失败机制；对轨迹合理性、工具成本、整体行为质量的刻画不足。
- **真实环境泛化未知**：线索是人工注入的显式标记，真实提示中的伪相关往往更隐蔽，如用户语气、领域术语、系统提示模板、工具描述格式、历史对话格式等；论文未在自然分布数据或真实 agent 日志上验证 RL 是否会放大此类伪相关。
- **统计报告不充分**：单种子、小规模训练使小效应量容易被噪声淹没；正文与附录中部分数值需交叉核对，读者可能高估部分 Δ 值的稳定性与可推广性。

## 9. 总体评价与启示

- **总体评价**：这是一篇问题意识强、形式化清晰、实验设计有针对性的工作。它把“捷径学习”从传统监督学习的最终预测层推进到 RL 智能体的中间工具选择层，揭示了“工具调用错误但答案仍正确”的评估盲区，并给出一个简单有效的决策级奖励缓解方案。其核心洞见——能力提升可能伴随捷径易感性上升——对智能体 RL 训练具有直接警示价值。
- **实践启示**：
  - 评估智能体不能只看最终答案准确率，应加入反事实工具使用指标、轨迹级诊断与工具必要性审计。
  - 仅用结果奖励优化工具策略会留下“中间决策无监督”空间；对工具选择提供密集反馈，如必要性惩罚，是可行方向。
  - 若训练数据中表面线索与工具能力同时出现，RL 可能优先绑定捷径；数据构造与课程设计需主动打破伪相关。
  - 未来工作应在更大模型、更多工具、自然分布线索、多种子与多缓解方法对照下，验证阈值效应、分布外泛化性与方法相对优势。
- **可复现性**：论文提供了 GRPO 超参、VerlTool 框架、裁判 prompt 与线索模板，复现门槛相对可控；但总 GPU 小时、单次运行墙钟时长与多运行统计缺失，完全复现与效应稳定性判断仍有不确定性。

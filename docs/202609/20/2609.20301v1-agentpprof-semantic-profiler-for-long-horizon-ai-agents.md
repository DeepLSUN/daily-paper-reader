## 摘要
AI 智能体越来越多地编排持续数天乃至数周的长时程活动，这些活动涉及用户、工具和系统资源。为了提高智能体的质量、安全性与成本效率，开发者需要确定故障发生在何处、什么触发了不安全效应，以及哪些任务消耗了最多预算，然后优化这些任务。在系统软件中，剖析通过聚合资源消耗并将其归因于相应的代码路径来回答类似问题，以识别热点。然而，现有的智能体可观测性工具侧重于单次执行的调试与追踪，而非跨运行、长期的剖析，这使得这些问题难以大规模回答。智能体可观测性需要剖析，而不仅是调试；但剖析智能体颇具挑战：负责实体是诸如“诊断认证”“比较分支”之类的任务意图，而非代码路径，并且缺少用于聚合的稳定标识符。我们提出一种语义操作栈模型，将剖析适配到智能体轨迹。统一操作表示所有活动，操作栈取代运行时调用栈，从而支持不同粒度上的分层归因。我们观察到，智能体的任务占据连续区间并分解为子任务，因此我们引入递归操作分段，在任务边界处递归地切分轨迹。AgentPProf 是一个剖析器，可将智能体轨迹聚合为与 pprof 兼容的剖析文件，从而支持火焰图可视化与分析。在 CodeTraceBench 上，AgentPProf 相对于人工标注达到 0.764 $B^3$ F1。在三个问题定位基准上，该剖析结果将 MAP 最高提升 56%，表明它能在可实用的剖析成本下有效归因资源、定位问题并帮助优化 token 成本。AgentPProf 可在 https://github.com/eunomia-bpf/agentsight 获取。

## Abstract
AI agents increasingly orchestrate long-running activities with users, tools, and system resources for days and weeks. To improve agent quality, safety, and cost efficiency, developers need to determine where failures happen, what triggers unsafe effects, and which tasks consume the most budget, then optimize those tasks. In systems software, profiling answers similar questions by aggregating resource consumption and attributing it to responsible code paths to identify hotspots. Yet existing agent observability tools focus on per-execution debugging and tracing rather than cross-run, long term profiling, making these questions difficult to answer at scale. Agent observability needs profiling, not only debugging, but profiling agents is challenging: the responsible entities are task intent like diagnose authentication, compare branches rather than code paths, and lack stable identifiers for aggregation. We propose a semantic operation stack model that adapts profiling to agent trajectories. Uniform operations represent all activities, and operation stacks replace the runtime call stack, enabling hierarchical attribution at different granularities. We observe that an agent's task occupies a contiguous span and decomposes into subtasks, so we introduce recursive operation segmentation, which recursively splits trajectories at task boundaries. AgentPProf is a profiler that aggregates agent trajectories into pprof-compatible profiles, enabling flame graph visualization and analysis. AgentPProf reaches 0.764 $B^3$ F1 against human annotations on CodeTraceBench. On three problem-localization benchmarks, the profile raises MAP by up to 56%, demonstrating that it effectively attributes resources, locates problems, and helps optimize token cost at practical profiling cost. AgentPProf is available at https://github.com/eunomia-bpf/agentsight.

- **核心问题**：开发者需要跨轨迹回答三类问题——哪些类任务消耗最多 token 预算？失败在何处集中？哪些行为模式触发不安全的系统效应？现有工具难以支撑：
  - 现有智能体可观测性工具（LangSmith、Langfuse、Phoenix 等）组织**单次执行**的 span 树，适合诊断单次运行，但**无法按任务意图或工作流阶段聚合**；
  - 输入聚类/结构化信号类工具（Datadog Patterns、LangSmith Insights 等）刻画的是输入分布（如「30% 用户问代码问题」），而非资源归因（如「review 任务消耗 40% token」），因为请求级标签不会传播到下游工具调用与系统效应。
- **为什么难**：传统软件剖析之所以可行，依赖两个前提——函数名稳定、运行时调用栈提供归因层级。而智能体轨迹中：
  - 负责实体是**任务意图**（如 diagnose authentication、compare branches），而非代码路径；自然语言 prompt 表达同一意图时没有共同字符串；
  - 轨迹**没有运行时调用栈层级**：prompt、工具调用、系统效应并非按执行嵌套，一段 prompt 序列可能是一个任务或多个任务，一个任务也可能属于更大任务。
- **整体含义**：论文主张「智能体可观测性需要 profiling，而不仅是 debugging」，将系统软件中成熟的剖析方法论（把资源投影到负责实体、赋予稳定标识符、分层归因）迁移到智能体轨迹上。

## 2. 方法论

### 2.1 核心思想

- 提出**语义操作栈模型（semantic operation stack model）**，用统一「操作」表示所有活动，用「操作栈」替代运行时调用栈，实现不同粒度上的分层归因。
- 需要满足三项要求：
  - **R1 跨层投影**：把系统层消耗连接到意图层类别；
  - **R2 稳定标识符**：从自然语言 prompt 中先导出简短、可重复的标识符再折叠；
  - **R3 分层归因**：从数据而非执行嵌套构建归因层级。

### 2.2 关键数据结构

- **操作（Operation）**：统一加权记录，含字符串字段（project、agent、session、prompt_tag、kind、model、path、domain、status 等）与可加度量（token 数、时长、事件数）。prompt、LLM 调用、工具调用、文件读写、GUI 点击、进程事件都是同 schema 的操作，仅字段取值不同。仅要求源内容、时间戳、可加度量；工具/事件 ID、session、span 可选。
- **操作栈（Operation Stack）**：用有序字段列表 [f₁,…,f_k] 把每个操作投影为帧序列 ⟨o.f₁,…,o.f_k⟩，相同序列的操作合并、权重求和。与调用栈不同，**字段在查询时选择**，因此同一份数据可按任务、按 session、按动作类型归因，无需重建输入。
- **视图（View）**：三元组 (φ, σ, w)——谓词 φ 选择参与操作，栈函数 σ 映射帧序列，权重函数 w 赋非负度量。内置四种视图：tokens、time、files、network。
- **标签继承**：借助 AgentSight（eBPF），意图标签可传播到其触发的系统效应，满足 R1。

### 2.3 递归操作分段（Recursive Operation Segmentation）

- **结构直觉**：任务占据轨迹的一段连续区间，并分解为更小的连续子任务；因此只需找到「责任发生变化的转移点」即可低成本恢复任务结构。
- **形式化**：轨迹 T = (t₁,…,t_n)，分段 S 是嵌套命名区间集合（任意两区间不相交或一个包含另一个），覆盖全部步骤，根为 session 级区间。
- **递归规则**：Segment(I) 在区间 I 内选择零个或多个转移点，将 I 划分为连续子区间；每个子区间获得一个以动词开头的短名并递归分段；选择零个转移点即终止该分支。某步骤的 operation path 是包含它的区间名链（从 session 根到最内层区间）。相同路径跨 session 折叠。
- **实例**：一次 Git 部署执行被切成 build deployment system，内部再切出 deploy branches 与 diagnose authentication，后者路径为 `build deployment system > diagnose authentication`；三个不同执行因同名而复折叠。
- **分割器实现**：任何能找到转移点并命名区间的实现均可（agent、LLM 或统计规则）。评估使用 Codex + GPT-5.6-sol-high，每轨迹固定指令：读入轨迹 → 在责任变化处标 mark → 用 AgentPProf 检查/更新分段 → 迭代直到完整 → 输出稀疏路径 mark（仅在路径变化处一行，名字以动词开头，1–3 词）。稀疏 mark 因中间步骤继承前一路径而仍产生完整分段；可增量修订，支持离线评估与在线标注。
- **统计替代方案**：基于 NPMI 打分转移点，用 k-means 校准无监督阈值。

### 2.4 实现

- **Rust CLI（约 9.8K LOC）**，读取 Codex 与 Claude Code 本地 JSONL 历史及 AgentSight 记录；文件在执行中增量写入，故可在 agent 运行时构建 profile。
- **两阶段流水线**：(1) 预处理提取可读轨迹摘要；(2) 分割 agent 读取摘要并写入区间 mark 到标注文件，可反复修订；CLI 校验 mark 嵌套且覆盖每步后，输出标准 pprof protobuf，`go tool pprof` 可直接读取。
- **投影确定性**：每个操作贡献其语义路径与 LLM/工具证据，session 身份保留为 pprof label 而非可见帧，使相等语义前缀跨 session 折叠；切换可加度量会重放相同标注、只改变栈宽度。已字面记录的字段（如 skill 调用）无需标注即成为栈层级。多智能体编排自动生效（子 agent 操作继承外层 agent 语义路径）。

## 4. 主要贡献与创新点

- **概念层面**：把「剖析（profiling）」确立为智能体可观测性的独立问题类别，明确区分于「调试（debugging）」——前者回答跨轨迹的资源归因与模式聚合，后者回答单次执行的因果定位。
- **模型层面**：提出语义操作栈模型，用统一 Operation schema + 查询时选定的操作栈 + (φ, σ, w) 视图三元组，把「函数名 → 任务意图」「调用栈 → 语义路径」这两组传统剖析前提替换为可迁移的等价物。
- **算法层面**：递归操作分段将「任务结构恢复」转化为「找责任转移点 + 命名区间」，把标注成本从 O(操作数) 降到 O(转移点数)，并允许稀疏 mark 表达完整嵌套。
- **工程层面**：与 eBPF（AgentSight）结合实现意图标签向系统效应的传播，输出标准 pprof protobuf，直接复用 `go tool pprof` 生态，降低采用门槛。
- **实证层面**：在真实长时程会话、多类 agent 基准与真实修复任务上同时验证了归因、定位、标识符质量与成本四个维度，并给出与专家行为标签、LLM-as-judge 的对照。

## 5. 局限与批判性评估

- **依赖标签传播**：R1 的跨层投影依赖 AgentSight/eBPF 的标签继承；在无法观测系统效应或标签无法传播的环境中，系统效应可能无法归因到意图层，退化为仅意图层剖析。
- **分割质量上限**：核心归因层级来自分段器，其错误会沿栈传播；论文显示 Codex 分割边界 F1 仅 0.480，说明「责任转移点」的精确定位仍不完美，粗粒度路径比细粒度边界更可靠。
- **LLM 依赖与成本**：主分割器为 LLM（Codex + GPT-5.6-sol-high），其输出可能存在跨运行不一致；虽然统计替代方案（NPMI + k-means）可用，但准确率有下降。
- **单领域偏重**：真实案例以编码 agent 与 Git 部署为主，web-agent 部分主要来自公开基准；结论在其他形态（如长时程科研、多模态 GUI、企业工作流）上的外推仍需验证。
- **评价基准的构造性**：部分对照（如 pprof-only vs Direct-only 的 MAP 提升幅度）依赖特定基准与评分口径，绝对数值受基准难度与标注一致性影响。
- **隐私与合规**：轨迹包含自然语言 prompt 与系统效应，profiling 会跨 session 聚合内容，实际部署需考虑脱敏与访问控制，论文未深入讨论。

## 6. 结论与影响

- 论文论证了智能体可观测性需要「剖析」能力：把资源投影到任务意图这一负责实体上，并赋予稳定、可折叠的标识符，从而在数百条轨迹间做聚合与差分。
- 语义操作栈模型以最小假设（源内容 + 时间戳 + 可加度量）覆盖意图层与系统效应层，同一份标注可重放为 token、时间、文件、网络等多种视图，兼顾灵活性与确定性。
- 实验表明该思路在资源归因（如诊断认证任务份额随度量从 21% 升至 46%）、故障定位（MAP 提升 +0.031~+0.117）、标识符质量（B³ F1 0.764）与成本（单次 LLM 调用 + 确定性重放）上均具优势，并已在真实修复任务中得到端到端验证。
- 更广泛的意义在于：它把系统软件数十年的剖析方法论（负责实体、稳定符号、分层归因）迁移到以自然语言意图为负责实体的新场景，为智能体运维、成本治理与安全审计提供了可复用的分析原语。

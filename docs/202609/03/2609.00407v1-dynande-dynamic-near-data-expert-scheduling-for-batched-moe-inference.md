## 摘要
混合专家（MoE）模型能够实现大规模语言模型（LLM）推理的高效扩展，但在基于神经处理单元（NPU）的系统中部署时，会遭受大量数据移动开销。近数据处理（NDP）通过NPU-NDP协同执行，为缓解这一瓶颈提供了一种有前景的方法。然而，现有的NPU-NDP MoE系统并未完全考虑硬件异构性、动态专家级并发性以及批量推理期间的时间性专家重用。本文提出了DynaNDE，一种利用NPU-NDP协作来加速批量MoE推理的动态近数据专家调度框架。DynaNDE引入了一个分析性能模型，捕捉协同NPU-NDP执行中的硬件异构性、数据移动成本和通信计算重叠。在该模型的指导下，DynaNDE在考虑专家级并发性的情况下，确定NPU和NDP上每层的专家调度。DynaNDE还包含一个重用感知的运行时，当专家驻留在NPU内存中时，可避免冗余的参数移动。实验结果表明，与最先进的NPU-NDP MoE服务框架相比，DynaNDE在预填充和解码阶段的平均吞吐量分别提升了2.6倍和2.2倍。

## Abstract
Mixture-of-Experts (MoE) models enable efficient scaling of large language model (LLM) inference but suffer from substantial data-movement overhead when deployed on neural processing unit (NPU)-based systems. Near-Data Processing (NDP) provides a promising way to mitigate this bottleneck via cooperative NPU-NDP execution. However, existing NPU-NDP MoE systems do not fully account for hardware heterogeneity, dynamic expert-level concurrency, and temporal expert reuse during batched inference. This paper presents DynaNDE, a dynamic near-data expert scheduling framework that exploits NPU-NDP collaboration to accelerate batched MoE inference. DynaNDE introduces an analytical performance model that captures hardware heterogeneity, data-movement costs, and communication-computation overlap in cooperative NPU-NDP execution. Guided by this model, DynaNDE determines per-layer expert scheduling across the NPU and NDP while accounting for expert-level concurrency. DynaNDE also incorporates a reuse-aware runtime that avoids redundant parameter movement when experts reside in NPU memory. Experimental results show that DynaNDE achieves substantial throughput improvements over the state-of-the-art NPU-NDP MoE serving framework, with average speedups of 2.6$\times$ and 2.2$\times$ for the prefill and decoding stages, respectively.

## 1. 论文核心问题与研究动机（背景）

本论文聚焦于基于**神经处理单元（NPU）与近数据处理（NDP）协同架构**下的**批量 MoE（Mixture-of-Experts）大模型推理优化**问题。其研究动机建立在以下技术链条之上：

- **MoE 模型的有效性与物理瓶颈**：MoE通过门控函数为每个 token 只激活部分专家（top-k），显著提升模型容量并控制计算成本，是大模型扩展的重要范式。但由于专家参数总量巨大，无法全部驻留 NPU 内存，推理时需将选中的专家参数从外部存储（或内存设备）按需搬入 NPU，形成了以“专家参数搬运（PMove）”为主的数据移动开销。文中实验数据表明，专家参数传输在总执行时间中占比高达 **88.4%**，构成主要延迟瓶颈。
- **NDP 的潜力和现有方案的不足**：NDP 将轻量计算单元集成到内存侧，以“激活搬运（AMove）”替代“参数搬运（PMove）”，使专家计算在数据所在位置就近完成，能够显著削减数据移动量。已有代表性工作 MoNDE 提出了 NPU-NDP 协作执行 MoE 的框架，但其调度策略存在明显局限：
  - 采用仅依赖 PCIe 与 NDP 带宽比的**固定启发式**专家分配，未建立统一的性能模型。
  - 未充分考虑 **NPU 与 NDP 之间硬件吞吐的异构性**。
  - 忽略了批量推理中**专家级并发度（每个专家上同时汇聚的 token 数）**在预填充与解码阶段的巨大动态差异。
  - 未考虑专家参数在 NPU 内存中的**时间性复用**，导致冗余的 PMove 传输。

**核心研究问题**：在 NPU-NDP 异构系统中，如何设计一个统一的、模型指导的、动态的专家调度机制，以最小化批量 MoE 推理的逐层延迟？这要求同时协调硬件异构性、数据移动成本、通信-计算重叠、专家级并发以及缓存重用等因素。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体架构与核心思想

DynaNDE 在宿主 CPU 侧运行调度运行时，面向 NPU-NDP 异构系统进行逐层（per-layer）的专家分配决策。整体框架由三大支柱构成：**分析性能模型**（提供调度依据）、**动态可重用调度算法**（提供决策方式）、**三阶段无争用执行流程**（保证调度与执行的一致性）。

### 2.2 分析性能模型

DynaNDE 提出了一个统一的三阶段延迟模型，用于刻画 NPU-NDP 协同执行中单个 MoE 层的总延迟（T_layer）：

- **Phase 1：NDP 输入暂存（Input Staging）**——先是输入激活由 NPU 传输至 NDP，延迟为 T_AinMove。
- **Phase 2：NPU-NDP 重叠执行**——NPU 侧采用 PMove-计算流水线执行；NDP 侧并行执行分配给自身的专家计算。由于两条路径并行，Phase 2 延迟取两条路径中的较大者：
  - NPU-front 延迟 = PMove 流水线头部 + max(剩余 PMove 总和, 前 N-1 个专家 NPU 计算总和)
  - NDP 侧延迟 = 分配给 NDP 的专家计算时间之和
  - T₂ = max(NPU-front, NDP-cmp)
- **Phase 3：输出完成**——输出激活（AMove）传输与最后一个 NPU 专家计算重叠，T₃ = max(T_AoutMove, T_NPU(N))。

**该模型的关键设计考量：**

- 参数搬运与激活搬运共用 PCIe/CXL 链路，若并发传输会造成带宽争用。DynaNDE的流水线刻意将两类传输安排在**不同阶段**执行以避免争用。
- 模型显式覆盖了**NPU路径内部**的 PMove 与计算重叠、**NPU-NDP跨设备**的执行重叠。
- 模型中的每专家计算时间 T_NPU(i)/T_NDP(i) 由该专家的操作总数（OP(i)）除以对应设备的吞吐量得到，**操作数本身包含了路由到该专家的 token 并发量**，从而自然捕捉专家级并发度。
- PMove 延迟中若专家已驻留于 NPU 内存则置 0，体现重用感知。

### 2.3 动态且重用感知的调度算法

DynaNDE 将逐层专家调度形式化为一个**最小化层延迟的优化问题**，并设计了高效的运行时解决方案，其核心是：

1. **专家评分与排序**：计算每个专家的重用感知偏好分数 s(i)=T_NDP(i) − [T_NPU(i)+T_PMove(i)]，按其从高到低排序。该分数刻画了将专家从 NDP 转移到 NPU 执行的预期延迟收益大小，专家已在 NPU 缓存时 T_PMove=0，从而让“可豁免 PMove 成本”的缓存专家取得较高优先级。
2. **前缀扫描搜索**（对排序后序列进行分割点遍历）：对每个分割点 p，将前 p 个专家分配给 NPU、其余分配给 NDP，然后使用三阶段性能模型依次计算总层延迟。利用增量数据结构（S_PMove、S_NPU、S_NDP、head、tail）将每次评估的复杂度控制为 O(1)，从而使算法整体复杂度降为 **O(|E| + |E| log|E|)**，避免了指数级搜索，适用于每层调度的线上场景。
3. **选择最优分割点 p\***：遍历结束后，返回使 T_layer 最小的专家集合 {e₁, …, e_p*} 作为分配给 NPU 的专家，其余专家交由 NDP 执行。

### 2.4 重用感知与执行一致性

- **重用感知体现在两个层面**：模型中 T_PMove(i)=0 的处理；评分时缓存专家天然获得更高优先级，从而让 NPU 持续复用驻留内存的专家，避免重复 PMove。
- 调度完成后，执行遵循与模型一致的**无争用冲突三阶段流程**（PMove 与 AMove 分时进行），确保估计与真实执行一致。

## 6. 主要结论与发现

- DynaNDE 相比 SOTA NPU-NDP MoE 框架 MoNDE，在 prefill 和 decode 阶段分别取得 **2.6× 和 2.2× 的平均吞吐量提升**；与 NPU-only、NDP-only 和 HybriMoE 相比，prefill 阶段分别提升 1.8×、2.9×、1.1×。
- 解码阶段 DynaNDE 较 NPU、NDP、MoNDE、HybriMoE 分别获得 30.5×、1.1×、2.2×、1.4× 的平均吞吐量提升。特别在与 NPU 基线对比时增益极为显著，说明解码阶段“数据移动主导”的瓶颈特性。
- **性能提升并非靠简单增加 NPU 使用率**：DynaNDE 分配给 NPU 的专家比例低于 HybriMoE（10.7% vs 13.7%），但其中需要 PMove（非缓存命中）的分配比例也更低（3.6% vs 5.3%），说明 DynaNDE 依赖模型驱动的选择性调度，以达到计算收益与数据移动开销之间的最优平衡。
- **采用分析模型指导的调度是核心贡献**：即便去掉重用感知（N-DynaNDE），DynaNDE 仍比 MoNDE 和 HybriMoE 平均高出 2.0× 和 1.3×，证明收益主要来自性能模型引导的划分而非简单的缓存命中策略。
- 对缓存替换策略（LFU/LRU/ARC）不敏感，在所有策略下均稳定优于 HybriMoE 约 1.3×，表明其鲁棒性和通用性。

## 7. 方法亮点（优点）

- **首次将 MoE 异构调度建立于统一分析性能模型之上**：不同于 MoNDE 的带宽比启发式或 HybriMoE 的经验规则，DynaNDE 给出了显式刻画 NPU/NDP 计算差异、PMove/AMove 通信差异、通信-计算重叠及无争用流水编排的数学框架，其调度决策有直接的延迟最小化语义。
- **巧妙捕捉专家级并发度**：将路由到每专家的 token 数量折算为计算量 OP(i)，从而将并发度差异自然融入延迟模型，而非作为外部参数单独处理。
- **三阶段执行流程设计**：刻意隔离 PMove 与 AMove，避免共享链路争用，使模型假设与实际执行流程保持严格一致，提高了可预测性。
- **前缀扫描 + 排序的低开销算法设计**：避免了指数搜索，保证 |E| log|E| 的调度复杂度，同时验证在多个模型中都能逼近乃至实现最优延迟配置。
- **形式合理的消融设计**：通过 N-DynaNDE 明确分离“模型指导的调度”贡献与“重用感知”的增量贡献；通过多种缓存替换策略验证方法不依赖特定缓存实现。

## 8. 不足与局限

- **物理实验缺失**：全部结论基于改进的模拟器（NeuPIMs + DRAMsim3），缺乏在真实 NPU/CXL/NDP 硬件上的验证，Model 近似精度及端到端实际收益的可靠性有待证实。
- **模型覆盖有限**：仅用三个中/小规模 MoE 模型（专家维度均较小、深度有限）。对于成百上千层、单专家参数量更大的生产级 MoE（如 DeepSeek-V3 671B 级别，专家量大、层数深），不同层具不同的路由失衡模式与分布，结论的可外推性值得审慎对待。
- **解码 token 数较短**：解码实验只测 10 个输出 token，长期推理过程中专家访问频次的演变、缓存状态随时间的演化无法得到充分刻画，解码端时间性专家复用的长时稳定性未得到验证。
- **单 NDP 配置局限**：未考虑多个 NDP 设备时的专家跨设备放置、激活转发、负载均衡、全局带宽竞争等真实部署中的系统难题，处理能力扩展性未证明（作者在 Discussion 中也承认此点，将其作为未来工作）。
- **缺乏统计严格性**：没有报告方差、置信区间或多次独立运行结果，因而无法判断在相同条件下重复实验的确认程度。
- **数据集与任务范围问题**：只使用单一数据集（DCLM-Baseline），未覆盖对话、翻译、代码生成等多类 LLM 实际使用场景，也即缺乏对数据域泛化性的实证检验。
- **调度假设较理想化**：假定门控决策之后能够即时获取整层路由分布并集中调度；但在动态批处理的实际推理服务器中，这可能受请求分片、分批调度等现实约束的影响，调度所依赖的输入与真实系统运行之间存在潜在时序偏差。

## 摘要
长上下文压缩对于降低大型语言模型推理的成本和延迟至关重要。然而，现有方法可能会分散重要证据，需要额外的训练或对齐，并且通常依赖目标模型来实现有效压缩。我们提出TopoCompress，一个无需训练且与模型无关的框架，通过选择连贯的语义片段来压缩长上下文。TopoCompress首先使用密集和词汇查询相关性以及语义加速对每个片段进行评分。然后，它构建一个混合图，根据语义相似性和顺序邻接性连接片段，并在图上传播查询引导的相关性分数。在五个长上下文任务——HotpotQA、2WikiMQA、MuSiQue、Qasper和MultiFieldQA-en上，TopoCompress持续优于强压缩基线。值得注意的是，TopoCompress在使用缩小4倍的压缩预算时实现了与最强基线相当的性能，并且比最快基线提供1.41倍的更小压缩时间。

## Abstract
Long-context compression is essential for reducing the cost and latency of large language model inference. However, existing methods can fragment important evidence, require additional training or alignment, and often depend on the target model for effective compression. We introduce TopoCompress, a training-free and model-agnostic framework that compresses long contexts by selecting coherent semantic spans. TopoCompress first scores each span using dense and lexical query relevance together with semantic acceleration. It then constructs a hybrid graph that connects spans based on semantic similarity and sequential adjacency, and propagates the query-guided relevance scores over the graph. Across five long-context tasks-HotpotQA, 2WikiMQA, MuSiQue, Qasper, and MultiFieldQA-en-TopoCompress consistently outperforms strong compression baselines. Notably, TopoCompress achieves performance comparable to the strongest baseline while using a 4x smaller compression budget, and provides a 1.41x smaller compression time over the fastest baseline.

- **研究背景**：大型语言模型（LLM）虽然依赖丰富上下文完成复杂任务，但受限于有限的上下文窗口，且更长的输入会带来两方面的挑战：一是推理成本与延迟显著增加；二是上下文过长时模型难以有效利用关键证据（尤其是位于中部的相关信息），性能不一定提升。
- **现有方法的不足**：现有长上下文压缩方法（如 LLMLingua、LongLLMLingua、LLMLingua-2）大多将压缩视为**token 级剪枝**问题，存在三个主要缺陷：
  1. **片段化问题**：在 token 粒度上做剪枝会破坏词边界、短语、命名实体或句法单元，造成关键证据被截断或损坏，且需要额外后处理恢复（增加计算量）。
  2. **非模型无关性**：压缩器需要训练或对齐以模仿目标模型对信息重要性的判断，导致压缩器与目标模型绑定，泛化性受限。
  3. **忽略证据间关系**：基于困惑度（perplexity）的逐 token 打分无法建模多跳任务中证据之间的支撑、连接或因果/时序关系，一些“局部可预测但全局关键”的中间证据容易被误删。
- **核心问题**：如何设计一种**免训练、模型无关**、且能**保留语义连贯与证据链**的长上下文压缩方法。
- **整体含义**：论文提出将长上下文压缩形式化为**基于图的证据选择**问题，用图结构中的相关性传播来识别那些直接匹配度不高但对回答问题必需的中间证据，从而突破传统 token 级剪枝的局限。

## 2. 论文提出的方法论：核心思想、技术细节与算法流程

### 2.1 核心思想

TopoCompress 将上下文视为一组**语义连贯的跨度（span）**，通过以下四个关键步骤实现压缩：
1. 将文档切分为连贯语义片段（句子/短段落）；
2. 用稠密（dense）与词法（lexical）相关性对片段进行查询对齐评分；
3. 引入“语义加速”（semantic acceleration）捕捉语义轨迹中的转折点；
4. 构建混合图（语义相似性 + 顺序邻接），在图上传播查询引导分数，最后以冗余感知贪心策略挑选证据。

### 2.2 关键技术细节

#### (1) 语义跨度构建
- 每个文档被分为连续语义单位（句子或短段落），避免 token 级裁剪导致实体/短语碎片化。

#### (2) 稠密与词法查询相关性
- 使用冻结编码器 $\Phi$（bge-m3），提供稠密向量与词法权重。
- **稠密相关性**：$r_i = \max(0,\ \text{sim}(e_i, e_q))$，即 span 与查询的余弦相似度，并做归一化。
- **词法相关性**：$\ell_i = \sum_{t \in q \cap u_i} w_q^t \cdot w_{u_i}^t$，利用 bge-m3 的稀疏词法权重计算精确词项匹配分数，并归一化。
- **查询对齐分数**：$g_i = \mu \hat{r}_i + (1-\mu)\hat{\ell}_i$，其中 $\mu$ 调节语义与词法的权重。

#### (3) 语义加速（Semantic Acceleration）
- 对每个内部跨度 $u_i$，计算二阶差分 $a_i = 2e_i - e_{i-1} - e_{i+1}$，加速度大小 $\kappa_i = \|a_i\|_2$。
- 归一化后得到 $\hat{\kappa}_i$，并用查询对齐门控：$s_i = (1 + \lambda \hat{\kappa}_i) g_i$，即**只增强与查询相关且处于语义转折处的跨度**，避免无关转折的干扰。

#### (4) 混合图构建与相关性传播
- 节点 = 跨度；边 = 两种类型：
  - **语义边**：每个节点连接其 embedding 相似度最高的 $k$ 个邻居，权重为相似度正值。
  - **顺序边**：同一文档内相邻跨度的边，权重为 1。
- 组合邻接矩阵 $W = \alpha W_{sem} + \beta W_{seq}$，行归一化得到转移矩阵 $P$。
- 执行个性化相关性传播（Personalized Propagation）：$s^{(m+1)} = (1-\eta)s + \eta P^\top s^{(m)}$，直到收敛。重启项保证原始查询信号不被淹没，同时使间接相关但处于证据链中的 span 可以提升排名。

#### (5) 冗余感知证据选择
- 贪心选择：每次选取满足 $u^* = \arg\max_{u_i \in R}\left[\tilde{s}_i - \delta \max_{u_j \in A} \text{sim}(e_i, e_j)\right]$ 的跨度。
- 惩罚项避免选择与已选证据高度相似的跨度；直到达到全局 token 预算 $K$，最后将选中的跨度按原始顺序恢复，保证可读性与连贯性。

### 2.3 算法流程（文字版）
1. 输入：上下文文档、查询、预算、冻结编码器；
2. 将文档分割成语义跨度；
3. 计算每个跨度和查询的稠密/词法相关性，得到对齐分数；
4. 计算语义加速度，并与对齐分数合并成初始分数；
5. 构建混合图（语义+顺序）并归一化；
6. 执行个性化相关性传播直至收敛；
7. 采用冗余感知贪心选择满足预算；
8. 恢复原始顺序输出压缩上下文。

## 6. 论文的主要结论与发现

- **TopoCompress 在全部 5 个任务和 3 个目标模型上始终优于现有压缩基线**；
- 在最高压缩预算 $K=500$ 时，相对最强基线 LongLLMLingua 的平均 F1 提高：GPT-5-mini +8.15、Llama-3.1-8B +8.44、Qwen3-8B +7.21；
- 在 $K=500$ 时，TopoCompress 的平均 F1 可与 LongLLMLingua 在 $K=2000$ 时媲美（如 GPT-5-mini 上 51.37 vs 51.44），说明**仅用四分之一预算即可获得相近性能**；
- **压缩速度快**：整体耗时约 6 分 54 秒，是 LLMLingua-2 的 1.41 倍加速，远快于 LLMLingua（44 分钟）和 LongLLMLingua（约 52 分钟）；
- **图传播的作用显著**：去除图传播后，多跳任务（MuSiQue、HotpotQA、2WikiMQA）F1 出现明显下降（最高相对下降 14.1%），说明图结构有助于保留中间证据链；
- **查询相关性是最核心的组件**：去除后平均 F1 大幅下降（$K=500$ 时从 51.37 降至 38.58）；语义加速度贡献相对较小；
- 控制器引导可在部分情况下小幅提升性能（尤其多跳任务），但 TopoCompress 本身已具备较强证据追踪能力，不依赖额外 LLM 控制器。

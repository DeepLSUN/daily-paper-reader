## 摘要
结构化生成支撑着生成JSON、SQL和函数调用的大型语言模型（LLM）代理，其中单个错误字段可能导致下游操作失败。约束解码已经跟踪解析器转换以强制形式有效性，这些转换揭示了生成的标记如何在活动语法下参与模式关键决策，如必填字段、参数和结构边界。现有的KV压缩在很大程度上未使用这种与任务相关的结构信号。我们引入了PASK（解析器感知的结构KV持久化），它将解析器派生的结构转化为层组特定的KV持久化决策。PASK通过使用任务错误敏感性来设置最低保护层，并使用注意力输出失真来分配残余KV容量，解决了模型侧KV敏感性与任务级结构化风险之间的不匹配。离线校准阶段将这些信号编译为持久化策略，在线仅需轻量级结构条件查找。在总KV预算为0.33的目标下，PASK在Qwen3-4B上的八个BFCL非实时和实时子类别中平均比最强的压缩基线高出17.39个百分点。在端到端服务中，PASK实现了高达2.2倍的吞吐量和3.3倍更低的TPOT，同时使用的峰值GPU内存仅为完整KV的0.53倍。

## Abstract
Structured generation underpins large language model (LLM) agents that produce JSON, SQL, and function calls, where a single wrong field can cause the downstream action to fail. Constrained decoding already tracks parser transitions to enforce formal validity, and these transitions expose how generated tokens participate in schema-critical decisions such as required fields, arguments, and structural boundaries under the active grammar. Existing KV compression largely leaves this task-relevant structural signal unused. We introduce PASK (Parser-Aware Structural KV Persistence), which turns parser-derived structure into layer-group-specific KV persistence decisions. PASK addresses the mismatch between model-side KV sensitivity and task-level structured risk by using task-error sensitivity to set minimum protection floors and attention-output distortion to allocate residual KV capacity. An offline calibration stage compiles these signals into a persistence policy, leaving only lightweight structure-conditioned lookup online. At a targe total KV budget of 0.33, PASK outperforms the strongest compressed baseline by 17.39 percentage points on average across eight BFCL non-live and Live subcategories on Qwen3-4B. In end-to-end serving, PASK achieves up to 2.2x higher throughput and 3.3x lower TPOT, while using 0.53x the peak GPU memory of Full KV.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究问题**：大型语言模型（LLM）代理在生成 JSON、SQL、函数调用等结构化输出时，单个字段错误就可能导致下游执行失败。现有约束解码（Constrained Decoding）虽能跟踪解析器状态、保证语法合法性，却忽略了解析器转移所蕴含的“结构化责任”信息。
- **关键矛盾**：现有 KV 压缩策略（如注意力显著性、量化误差、最近性、通用 token 重要性等）主要衡量“模型侧数值重要性”，但**模型侧 KV 敏感性与任务级结构化风险并不一致**：历史上数值影响不显著的 token 可能决定后续合法函数、参数或字段取值，导致任务失败。
- **核心立场**：任务层面的失败风险决定哪些历史必须被保护，模型侧的表示失真决定剩余内存如何分配。但此前没有 KV 策略利用约束解码中 token 级解析器转移来控制生成 KV 跨 Transformer 层的持久化。
- **整体意义**：本文提出 **PASK（Parser-Aware Structural KV Persistence，解析器感知的结构 KV 持久化）**，首次将解析器转移导出的结构标签用于逐层分组、分动作的 KV 保留策略，从而在低 KV 预算下提升结构化生成可靠性与服务效率。

## 2. 提出的方法论

### 核心思想
将约束解码产生的“解析器状态转移”重新用作 KV 持久化的控制信号：每个已接受 token 根据其在语法中的**结构角色**（必填键、枚举值、函数参数、边界/脚手架等）被划分到不同 bucket；再将 bucket 与 Transformer **层组（layer group）** 结合，分配三种持久化动作：
- `RELEASE`（R）：从长期注意力中释放；
- `RETAIN-LOW`（L）：低精度保留；
- `RETAIN-HIGH`（H）：高精度保留。

### 关键流程
1. **解析器派生持久化桶（Parser-Derived Persistence Buckets）**
   - 对每个解析器转移，形成结构化标签：`z_t = (class, role, state, next)`，其中 class 为 token 类型，role 为 schema 责任（如必填字段、枚举、SQL 谓词、函数参数），state 为当前语法转移状态，next 表示解析前沿是否接近关键区。
   - 与层组 `c` 结合得到 `q_{t,c} = (z_t, c)`，用于索引策略表。

2. **双指标离线校准（Dual-Metric Offline Calibration）**
   - **注意力输出失真** `D(q,a)`：在参考轨迹上对某 bucket 施加干预（改为动作 a），测量后续解码层输出（各注意力头）相对全精度输出的 L2 变化，用于衡量模型侧数值敏感度，**仅用于残余容量分配**。
   - **任务错误敏感性** `V(q,a)`：在完整生成上施加干预，统计任务失败率变化；通过单调包络 `V̄` 避免有限数据导致的倒挂，并按阈值 `τ_low, τ_high` 设置保护地板（floor）：
     - `V̄(q,L) > τ_high` → H；
     - `V̄(q,R) > τ_low` → L；
     - 否则 → R。
   - 在地板基础上，用相邻升级的“失真收益/成本”密度 `ρD` 进行贪心路径，生成一系列候选策略；在开发集上按 `R_task(π) - R_task(π_ref) ≤ α` 约束选择成本最低的策略。
   - 同时保留“未来受保护历史”的预算预留 `Γ(s)`（解析器状态的累计地板成本分位数）。

3. **在线只做结构查询（Structure-Only Online Lookup）**
   - 在线阶段无需任何注意力统计或重要性估计，只根据 token 的 `z_t`、当前解析器状态 `s_t`、层组 `C` 查冻结表 `Λ`，获得动作、地板与升级得分；按当前剩余预算 `R_t` 与预留 `Γ` 进行轻量降级/升级调整。
   - 保证复杂度与 Transformer 解码相比可忽略。

4. **轻量 Prefill 伴侣（Lightweight Prefill Companion）**
   - 对于端到端场景，也将 prefill 阶段 prompt token 按语义标签（受保护内容、函数名、参数键、约束、schema 脚手架）分层分组，用同样原则离线校准，独立容忍度 `α_P`，实现压缩输入 KV。

## 7. 优点（方法或实验设计的亮点）

- **想法新颖**：第一个将约束解码中解析器转移状态用于 token 级、层组级 KV 持久化控制，填补模型侧重要性与结构化任务风险之间的鸿沟。
- **在线开销极低**：将复杂校准完全离线化，在线阶段仅查表和常量状态更新，与现有压缩方法依赖注意力统计相比，更利于实际部署。
- **双指标机制清晰**：“任务错误敏感性定保护下限，注意力输出失真分配剩余资源”的分离原则具有较强的可解释性和可扩展性。
- **端到端考虑**：同时处理 prefill 与 decode，并报告真实服务指标（内存、吞吐、TPOT），比其他只做离线准确率的方法更贴近工业部署。
- **评测控制良好**：校准/开发/测试严格切分，策略选择全程基于开发集，降低过拟合测试集的风险；
- **约束解码后端统一**：与现有方法共用同一受限解码环境，保证对比公平性。
- **消融实验针对性强**：分别移除 V-floor 和 D-ranking，清楚验证两类信号的作用。

## 8. 不足与局限

- **基准覆盖单一**：只在 BFCL 函数调用上验证，没有覆盖 JSON、SQL、代码生成等其它结构化生成场景，迁移性证据有限。

- **动作与层组粒度粗糙**：当前仅用 3 个层组和 3 个动作，精度等级的离散性可能导致过度保护或浪费。
- **在线并不总是“免费”**：pipeline 依赖解析器状态、层组映射和预算状态，虽复杂度低，但与某些零开销基线相比仍有额外工程耦合。

- **效率边界情况解释较弱**：A100 32k/256 输入下吞吐反而下降约 28%，论文仅称为“边界”，未给出严格机制分析。

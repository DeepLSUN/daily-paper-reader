## 摘要
工具增强型LLM智能体必须依赖不受信任的运行时观测来完成开放式任务；然而，当工具输出不再仅仅是提供数据，而是开始指定具体动作时，它们实际上变成了“命令”，可能引发超出用户意图的真实世界副作用。我们认为这一风险源于将动作诱导与执行授权相混淆。为解决这一区别，我们提出了SARA，它将动作诱导与执行授权视为不同的运行时角色，并将动作来源与执行权限分离。在观测侧，情景隔离的动作探针暴露了动作诱导语义，并跨步骤持续记录动作来源作为审查信号；在执行侧，实际工具调用仅根据用户目标和来自授权成功执行的审计证据进行授权，同时满足目标、执行链和参数级支持。为在多步执行过程中保持这一分离，SARA应用了“无历史提升”机制，以防止历史重复将动作来源洗白为执行权限。在AgentDojo和AgentDyn上，SARA在四种主要评估设置中将ASR限制在不超过0.63%，同时保持具有竞争力的任务实用性，并在额外的Agent骨干网络上持续降低ASR。

## Abstract
Tool-augmented LLM agents must rely on untrusted runtime Observations to complete open-ended tasks; however, when tool outputs no longer merely provide data but begin to specify concrete actions, they effectively become ``commands'' that can drive real-world side effects beyond user intent. We argue that this risk arises from conflating action induction with execution authorization. To address this distinction, we propose SARA, which treats action induction and execution authorization as distinct runtime roles and separates action provenance from execution authority. On the Observation side, a context-isolated Action Probe exposes action-inducing semantics and persistently records action-origin provenance across steps as a review signal; on the execution side, actual tool calls are authorized only against the user objective and audited evidence from authorized successful executions, while satisfying goal, execution-chain, and argument-level support. To preserve this separation across multi-step execution, SARA applies No-History-Promotion to prevent historical recurrence from laundering action origins into execution authority. Across AgentDojo and AgentDyn, SARA limits ASR to no more than \(0.63\%\) across four primary evaluation settings while maintaining competitive task utility, and consistently reduces ASR across additional Agent backbones.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 工具增强型 LLM 智能体逐渐从纯文本生成器演变为能够在真实环境中通过外部工具执行操作的系统，可发送邮件、修改对象、提交事务等，带来了真实的外部副作用。
- 在开放式任务中，智能体必须依赖不受信任的运行时观测（如网页、邮件、文档、搜索结果等第三方内容）来完成规划；然而当工具输出不仅仅提供数据，而是开始指定具体动作时，它们实际上变成了“命令”，可驱动超出用户意图的真实副作用——这种风险本质上类似经典安全中的混淆副手问题（confused deputy problem）。
- 作者指出，现有防御手段面临一个结构性张力：限制不可信外部内容可以提高安全性，但可能削弱开放式任务所需的运行时适应性；而若允许观测内容自由影响后续决策，攻击语义又可经由正常工具步骤传播并造成越权外部效果。关键不在于“观测是否影响了智能体”，而在于“这种影响是否获得了超越用户意图的真实执行权限”。
- 论文由此提出一个核心区分：**动作诱导（Action Induction）** 与 **执行授权（Execution Authorization）** 必须分离。观测可以影响候选动作并合法实例化已授权的任务，但动作诱导本身不能授予真实执行权限；候选工具调用必须在真实执行边界处重新建立独立的授权支持。

## 2. 论文提出的方法论

### 2.1 核心思想

- SARA（Separating Action Ind**induction** from Runtime Auth**orization**）部署在智能体与真实工具执行器之间，不访问智能体的隐藏推理与内部规划状态，仅依赖用户请求、工具模式、候选调用、工具观测及自身运行时状态。
- 核心原则：Induced(ct, Oi) ≠> Permitted_U(ct | X_<t)，即观测诱导不蕴含执行授权。SARA 不过滤原始观测，而是将动作来源与执行权限分离，在执行边界做持续授权审查。

### 2.2 关键技术细节与流程

1. **授权根（Authorization Root，K）构建**：由用户原始请求 U 生成任务级授权契约 K = Contract(U)，每项为 k_j = ⟨e_j, operation_j, scope_j, Σ_j⟩，定义允许的效果类型、操作、作用对象范围和静态参数。K 是任务权限上界的独立根，运行时信息只能实例化已有权限，不能创造新权限。

2. **观测侧：上下文隔离动作探针（Action Probe）**：对每个工具输出 Ot，在上下文隔离下执行 Probe(Ot, T) → (z_t, Q_t, M_t)。其中 z_t ∈ {STATIC, ACTIONABLE} 表示是否含有动作诱导语义；Q_t 为可映射到具体工具的动作足迹；M_t 为参数来源锚点 m = (τ, p, norm(v))。该探针不判定内容是否恶意，只判定其是否具有可映射到具体工具行为或参数角色的“可动作性”。分类为 ACTIONABLE 仅作为触发持续审查的信号，不直接拒绝观测或候选调用。

3. **持久审查与动作来源保留**：引入轨迹状态 S_t ∈ {CLEAN, EXPOSED}——一旦有 ACTIONABLE 观测出现，轨迹转入 EXPOSED 并保持，所有后续执行都承担持续审查义务。同时维护活动动作来源集 F_t，动作诱导属性不会因后续正常执行、上下文传播或时间流逝而自动消失（对应持久动作来源属性）。

4. **执行侧：证据驱动的边界授权**：当智能体提出真实候选调用后，根据 (K, F_t, H_t, c_t) 判定是否授权。审查触发策略分三级：
   - 有真实副作用的所有调用进入完整授权路径；
   - 查询/读取类调用仅在工具与 Probe 记录的动作足迹重叠且参数无法从用户请求直接确定时才升级审查；
   - 其余调用走快速路径，结果仅作为 DATA_ONLY 证据。

5. **三阶支持判定**：完整授权要求同时满足三个条件并形成最终判定：
   - Auth(c) = GoalSupport(c, U, K) ∧ ChainSupport(c, H_t) ∧ ArgSupport(c, U, H_t, F_t)
   - 目标支持（Goal Support）——调用须保持在用户契约 K 定义的任务边界内；
   - 执行链支持（Chain Support）——调用依赖的运行时对象须能由 H_t 中一致的成功执行链追溯；
   - 参数支持（Argument Support）——每个实际参数须有独立绑定依据，分类为 USER_BOUND（用户直接确定）、HISTORY_BOUND（经成功执行链建立）、SAFE_DEFAULT（安全默认）、UNSUPPORTED（缺乏支持）。

6. **审计执行证据（Audited Execution Evidence，H_t）**：只记录此前“被允许且确实成功执行”的工具交互。证据能力标签分为 DATA_ONLY（只能传播为运行时数据以实例化参数）和 GOAL_BOUND（保留与授权任务相关的执行关系，可参与执行链和参数绑定判定）。

7. **无历史提升机制（No-History-Promotion，NHP）**：若某参数值已作为动作来源锚点记录在 F_t 中，即使该值后来正常出现在 H_t，也不能仅凭历史再现获得 HISTORY_BOUND 支持或经 SAFE_DEFAULT 绕过来源约束——防止“动作来源 → 历史重现身→ 授权提升”的起源洗白路径。

## 3. 实验设计

### 3.1 数据集与 Benchmark

## 6. 论文的主要结论与发现

- **端到端安全**：在四种主设置中 SARA 将 ASR 限制在 ≤0.63%（GPT-4o-mini 下为 0.06%/0.17%，Gemini-2.5-Flash-Lite 下为 0.62%/0.63%），同时 UA 不低于无防御基线。防御收益不是靠无条件压缩运行时行为换取最低 ASR，而是在保护观测依赖的任务执行的同时达成一致的安全与效用平衡。
- **安全效用权衡的对比结论**：CaMeL 在三组设置中 ASR 更低（0.11%–0.28%），但对 BU 的跌幅远大于 SARA（31.52/39.71/15.94/29.55 个百分点 vs SARA 的 5.79/8.98/6.52/11.82）；Spotlighting 保留的效用较高但残余 ASR 达 22.97%–26.16%，表明限制工具/执行结构、识别动作来源、或施加高层任务/信任约束本身都不足以同时解决动态依赖与定向越权执行。
- **跨骨干一致性与效用差异**：8 个 backbone–benchmark 组合中 ASR 均显著下降，4 个开源骨干中 3 个在 AgentDojo 的 ASR 降至 ≤0.03%，跨骨干一致性主要体现在安全而非任务效用上；AgentDyn 下 BU 跌幅可达 12–13 个百分点，说明复杂动态工作流中安全干预的任务连续性成本放大，且较弱的骨干（Llama3.1-8B 的 tool_error 19%–35%）的 ASR 低主要源于提前执行失败而非防御能力。
- **组件贡献不对称**：AIT 消除后 ASR 升至约 3%；PSG 消除后 ASR 升至约 2.5%–2.7% 且 BU/UA 上升；AE 消除后 ASR 不升反降但 UA 下跌 10–13 个百分点——说明 AE 的作用是提供支持动态值持续执行的合法证据，而非进一步收紧安全边界；NHP 消除后 ASR 升至约 0.65%–0.75% 且对效用几乎无影响——专门封堵来源洗白路径。
- **成本特性**：额外注入的计算对应更优的系统级安全–效用平衡点，而非单纯 token 开销最低的机制。

## 7. 优点

- **问题定义精准且有理论格局**：将安全问题的症结从“是否应当让不可信观测影响 Agent”转位为“观测影响是否获得真实执行权限”，并形式化定义 Induced(c, Oi) 与 Permitted_U(c) 两个独立谓词及 Violation 定义，增强可验证性。
- **运行时状态设计结构清晰**：以 K、F_t、H_t 三个互不替代的运行时来源承载三类授权属性——独立权限根、持久动作来源与审计执行证据，使理论与机制映射明确。
- **对抗性来源敏感**：处理跨步骤攻击时 F_t 保持持久属性；NHP 精确阻断“先出现于外部动作请求、后重现于合法历史”这一此前少有人处理的来源洗白路径。
- **观测侧不做恶意判定**：Action Probe 只标记“可动作性”，不声称内容恶意、不阻断正常推理，从而兼顾开放式任务灵活性。
- 不依赖智能体隐藏推理或内部状态，减少了对模型透明度的假设；实验跨两代 Agent 骨干的网络及家族跨度较大，验证方式较为扎实。

## 8. 不足与局限

- **非正式安全保证**：SARA 的语义判断（如是否 ACTIONABLE、参数绑定是否 USER_BOUND/HISTORY_BOUND）依赖 LLM/规则本身的质量，可能出现误判；论文明白承认这一点——错误放行仍记作防御失败。
- **依赖主 Agent 的重规划能力**：被拦截的候选调用返回主 Agent 重规划，整体任务效用依赖骨干模型的执行和恢复能力，尚不能独立于骨干提供稳定效用。
- **威胁模型范围有限**：假定用户请求、工具模式、工具执行器与 SARA 自身为可信的，不涵盖绕过运行时控制直接提交调用、纯数据依赖漏洞、或用户在任务中无条件授权外部内容的情况。
- **评估基准局限于工具型 IPI 工作流**：AgentDojo 与 AgentDyn 虽含大量实例，但不足以代表所有真实工具生态与多模态环境；未评估 OSWorld/τ-bench/ToolSandbox 等其他相关定义下的对抗分布。
- **缺乏算力资源报告**：未报告 GPU 型号与数量、总体推理耗时或预算，阻碍成本比较的复现；仅报告 token 消耗与其他防御的对比，不足以说明部署层面的总拥有成本。

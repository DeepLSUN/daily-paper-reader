## 摘要
现实世界的检索通常通过任意布尔逻辑将结构化约束与对文本和图像的语义意图组合起来。现有的混合流水线，如倒数排名融合或自查询检索器，仅允许固定形式的组合，而最近的强化学习检索器则将语言模型训练为针对单一后端的查询生成器，从而将异构检索路径的编排排除在其动作空间之外。我们提出了ProRetrieval，它将语言模型重新定位为检索编排者：给定自然语言查询，它在混合DSL中综合一个可执行程序，该DSL将结构化字段上的SQL运算符与文本和图像上的向量检索原语交织结合，SQL本身提供了融合异构候选集的逻辑代数。我们使用GRPO和DAPO在层次化的四项奖励下训练Qwen3-4B，并在基于亚马逊产品和安然电子邮件构建的两个新基准上进行评估。我们的4B模型超越了GPT-5.5（电商上Hit@1为0.81对比0.69；邮件上为0.91对比0.86）以及Claude Opus 4.7，以及包括检索、LLM增强、结构化查询和基于图的方法在内的全面基准套件。代码：https://anonymous.4open.science/r/ProRetrieval/；数据：https://huggingface.co/datasets/anonymous-7219/ProRetrieval。

## Abstract
Real-world retrieval often composes structured constraints with semantic intents over text and images through arbitrary Boolean logic. Existing hybrid pipelines such as reciprocal rank fusion or self-querying retrievers admit only a fixed form of composition, while recent reinforcement-learning retrievers train the language model as a query generator for a single backend, leaving the orchestration of heterogeneous retrieval paths outside its action space. We propose ProRetrieval, which recasts the language model as a retrieval orchestrator: given a natural-language query, it synthesizes an executable program in a hybrid DSL interleaving SQL operators over structured fields with vector-retrieval primitives over text and images, with SQL itself providing the logical algebra that fuses heterogeneous candidate sets. We train Qwen3-4B with GRPO and DAPO under a hierarchical four-term reward, and evaluate on two new benchmarks built from Amazon products and Enron email. Our 4B model surpasses GPT-5.5 (Hit@1 0.81 vs. 0.69 on e-commerce; 0.91 vs. 0.86 on email) and Claude Opus 4.7 and a comprehensive suite of retrieval, LLM-augmented, structured-query, and graph-based baselines. Code: https://anonymous.4open.science/r/ProRetrieval/; data: https://huggingface.co/datasets/anonymous-7219/ProRetrieval.

# ProRetrieval 论文总结

## 1. 核心问题与整体含义

- **研究动机**：真实检索任务通常需要将**结构化字段约束**（如品牌、价格、日期）与**文本/图像上的语义意图**通过任意布尔逻辑（AND/OR/NOT、嵌套）组合起来。但现有方法存在明显短板：
  - 纯向量检索/纯关键词检索只覆盖单一模态；
  - 固定融合管道（如 RRF）只能表达加权析取；
  - 自查询检索器（self-querying retriever）仅支持简单键值合取；
  - 近期基于 RL 的检索模型（如 Search-R1、DeepRetrieval）只优化单一后端的查询生成，无法跨异构检索后端编排。
- **核心论点**：应把语言模型从“查询生成器”提升为“检索编排器”，其动作空间不再是一条查询，而是一个**可执行的混合检索程序**。
- **整体含义**：ProRetrieval 用 SQL 的逻辑代数作为编排骨架，将文本/图像向量检索作为“一等原语”注入 SQL，从而把混合检索问题转化为**可学习的 DSL 程序综合问题**，让小模型也能完成复杂的跨模态查询编排。

## 2. 方法论

### 2.1 核心思想
- 设计了一个混合 DSL（Hybrid DSL），程序由两大部分组成：
  - `sql` 字段：标准 SQL 查询，表达结构化过滤和逻辑组合；
  - `retrieval_list` 字段：一组文本/图像向量检索原语，返回 Top-K 候选 ID。
- 向量检索结果通过**占位符注入**方式接入 SQL，例如 `id IN <text_0>`，由 SQL 引擎完成最终 AND/OR/NOT/NESTED 融合。
- 这种设计将向量检索与逻辑编解除耦：每个原语独立执行，SQL 负责最终结果组合。

### 2.2 查询构造流水线
- 由于没有现成的混合检索基准，作者构建了电商与邮件两个新数据集。
- 每条实例生成四步：
  1. **结构采样**：按复杂度 L1/L2/L3 采样叶子数（1–5），套用两层布尔模板（合取/析取、嵌套、否定）；
  2. **grounding**：用 gold 文档锚定查询，为每个叶子分配结构化字段或文本/图像模态；
  3. **编译**：将叶子编译为 SQL 谓词与向量占位符，执行得到 ground-truth 候选集；
  4. **语言化**：用 GPT-4o 把 gold DSL 改写为自然语言查询。

### 2.3 训练流程
- 两阶段训练：
  1. **SFT**：在 gold (NL, DSL) 对上做监督微调，作为初始策略；
  2. **RL**：在 SFT 基础上用 GRPO 或 DAPO 优化。
- RL 采用 group-relative advantage，目标函数含 clipped surrogate 与 KL 惩罚（β=0.001）。
- 提出**层级化四项奖励**，对应可执行程序的分层正确性：
  - `S_f`（格式）：输出是否为合法 DSL JSON；
  - `S_e`（可执行）：SQL 能否编译、占位符是否解析；
  - `S_r`（结果）：是否命中 rank-1 ground truth；
  - `S_l`（长度）：惩罚冗余程序。
- 奖励叠加为 `R = S_f + S_e + S_r + S_l`，依靠层级依赖隐式实现“先保证合法性、再保证可执行、再保证正确、最后追求简洁”的优先顺序。

## 3. 实验设计

### 3.1 数据集与场景
- **E-commerce**：基于 Amazon ESCI + Amazon Reviews 构建，包含 3,000 个商品，结构字段（品牌、类目、价格、评分）+ 文本（标题、描述、评论摘要）+ 商品图片。
- **Email**：基于 Enron 邮件语料构建，包含 5,000 封邮件，结构字段（发件人、日期、已读/星标）+ 文本（主题、正文）。
- 各含训练集 20,000 条、测试集 3,000 条，按 L1/L2/L3 分层；另从人工标注构造各 300 条 OOD 查询。

## 6. 主要结论与发现

- **ProRetrieval 显著超过所有 prior paradigm**：
  - E-commerce：8B SFT Hit@1=0.820，4B GRPO/DAPO=0.809/0.808；
  - Email：4B DAPO Hit@1=0.909。
- **4B 小模型超过商业大模型**：电商上比 GPT-5.5（0.693）高约 11.6 pp；邮件上高约 5.4 pp。

- **通用化良好**：OOD 上 RL 收益几乎保留，说明模型学到的是可泛化的编排策略而非训练集记忆。
- **推荐配置**：4B DAPO 兼顾稳定性与性能，8B SFT 精度最高。
- **GRPO 存在 reward hacking / 训练后期性能崩坏**，DAPO 的不对称裁剪更稳定。

## 7. 优点

- **问题建模角度新颖**：将混合检索重述为“DSL 程序综合”，用 SQL 代数免费获得逻辑完备的布尔组合能力，动作空间表达力显著大于 RRF 或单后端 RL 检索器。
- **架构解耦干净**：向量检索与 SQL 融合通过占位符注入解耦，可独立优化后端，也便于扩展到图像模态。
- **奖励函数设计巧妙**：四项层级奖励贴合可执行程序生成的必需条件，隐式实现了从格式到可执行到正确性的优先级。
- **实验体系扎实**：不仅报总指标，还从动作空间、模态、查询复杂度、训练算法、规模、OOD、统计显著性多角度验证。
- **开源开放**：提供代码与数据，可复现性强。

## 8. 不足与局限

- **Schema 依赖**：方法假设预先定义好结构化 schema，难以直接用于 schema-free 或动态演化的语料。

## 摘要
认知语言智能体通过将语言模型与记忆、工具和决策程序相结合，取得了显著进展，使智能体能够在交互环境中进行推理和行动。现有框架在很大程度上将这些智能体视为解决用户指定的、有界任务的系统。一个日益重要的目标是，让语言智能体在长期存在的场景中提供持久帮助，在这些场景中，用户需求、上下文和服务程序会持续存在并发生变化，并且要在随时间出现的广泛任务中保持有用。然而，我们仍然缺乏一个框架来刻画持久AI智能体、组织现有工作并指导未来发展。为此，我们提出了一种面向持久智能体的感知中心架构（Pera）。Pera描述了一种围绕感知和控制组件组织的持久智能体，这些组件持续从 episodic 任务执行、内部上下文以及周围环境变化中感知与服务相关的信号，并利用这些信号构建生命周期任务。这些任务驱动智能体服务程序的持续运行和适应。我们使用Pera来回顾性地组织近期工作，审视一个详细的案例研究，并为构建更强大的持久智能体提供前瞻性见解。正如软件工程从“小规模编程”发展到“大规模编程”一样，Pera将语言智能体的演进描述为向长期适应性智能系统的一次类似架构转变。

## Abstract
Cognitive language agents have achieved substantial progress by equipping language models with memory, tools, and decision-making procedures, enabling agents to reason and act in interactive environments. Existing frameworks largely cast these agents as systems for solving user-specified, bounded tasks. An increasingly important goal is for language agents to provide persistent assistance in long-lived settings where user needs, context, and service procedures persist and change, and to remain useful across the broad range of tasks that arise over time. Yet we still lack a framework to characterize persistent AI agents, organize existing work, and guide future development. To this end, we propose a Perception-Centered Architecture for Persistent Agents (Pera). Pera describes a persistent agent organized around perception and control components that continually perceive service-relevant signals from episodic task executions, internal context, and changes in the surrounding environment, and use these signals to construct lifecycle tasks. These tasks drive the ongoing operation and adaptation of the agent's service procedures. We use Pera to retrospectively organize recent work, examine a detailed case study, and offer forward-looking insights for building more capable persistent agents. Just as software engineering moved from programming in the small to programming in the large, Pera frames the evolution of language agents as an analogous architectural transition toward long-lived, adaptive intelligence systems.

- **核心问题**：对于需要在长时间、动态演化的场景中提供持续服务（persistent assistance）的智能体，我们缺乏一个统一的架构框架来：
  - 刻画“持久智能体”（persistent agent）与传统任务型智能体的本质差异；

- **关键概念界定**：
  - **偶然任务/阶段任务（Episodic Task）**：围绕一个有界用户目标组织的执行单元，完成即结束。
  - **长期场景（Long-Lived Setting）**：由用户、工件、约束、决策和程序构成的、跨任务持续存在并影响后续任务的持久范围。
  - **生命周期任务（Lifecycle Task）**：以建立、修复或更新跨任务共享的持久条件（context、procedure、preference、tool等）为目的的有界任务。它由目的和完成判据定义，而非由发起方（用户还是智能体）定义。
  - **主动感知（Active Perception）**：感知不是固定的输入通道，而是受当前活动与信息需求引导的反馈回路。跨任务边界的主动感知使“长期场景中的变化”变得可观测。

## 2. 论文提出的方法论：核心思想、关键技术细节与流程

### 2.1 核心架构：Pera（面向持久智能体的感知中心架构，Perception-Centered Architecture for Persistent Agents）

Pera 在认知语言智能体（Cognitive Language Agent）基础上引入**持久智能体核心（Persistent Agent Core）**，由**生命周期感知（Lifecycle Perception）** 与**控制平面（Control Plane）** 两部分组成，形成了一个“感知 → 控制 → 执行 → 反馈 → 再感知”的持续循环。

- **生命周期感知**：从外部与内部持续捕获信号。
- **控制平面**：评估信号、判断是否需要干预，并将“需要做的维护/改进工作”封装为生命周期任务包派发出去。

### 2.2 信号系统（Signals）

论文区分了**信号（Signal）** 与**观测（Observation）**：
- 观测服务于当前任务运行时的决策；
- 信号服务于生命周期级别的判断，是感知周期的输入起点。

信号分为两大类：

| 信号类型 | 来源 | 示例 |
|---|---|---|
| 外部信号（External Signals） | 人类、物理、数字环境 | 用户活动变化、摄像头/传感器读数、文件系统事件 |
| 内部信号（Internal Signals） | 任务执行过程、上下文记忆、感知/控制自身 | 工具反复失败、反思结果、审查发现的程序缺陷 |

信号既可以是单事件，也可以是从多个相关事件中**聚合归纳**出的条件性结论（如“某接口变更导致某个流程反复失败”）。

### 2.3 生命周期感知的组成

- **传感器（Sensors）**：物理或软件形态，捕获原始事件或周期性巡检状态。
- **信号处理器（Signal Processors）**：解释信号 → 滤除无关信息 → 合并相关事件 → 生成可用领域特定语言（domain-specific language）描述的“发生了什么”，传递给控制平面。

### 2.4 生命周期任务包（Lifecycle Task Package）

当控制平面判断某信号需要后续工作，它会构建生命周期任务包，作为控制平面与任务级执行之间的接口。任务包核心元素包括：
1. **任务目标**：说明任务完成后应留下的持久效果；
2. **完成判据**：运行时必须产生的证据；
3. **任务特定程序（Task-Specific Procedure）**：用于补充或约束通用决策程序（可参考已有流程、动态生成代码或新工具）；
4. **执行所需的上下文**：提供或指定如何检索；
5. **恢复机制**：保留稳定版本以便修改失败时回滚；
6. **审查判据（Review Criterion）**：明确修改被接受前必须满足的条件（如回归验证不破坏已有功能）；
7. **权限限制**：可限定修改范围或要求授权。

### 2.5 动作空间（Action Space）

Pera 定义了七大动作类别：

| 动作 | 层级 | 作用 |
|---|---|---|
| 感知（Sensing） | 生命周期 | 监测外部/内部环境中的信号 |
| 分派（Dispatching） | 生命周期 | 将任务包发送给任务级执行，决定即时/延迟/条件执行 |
| 实例化（Instantiation） | 生命周期→任务过渡 | 将任务输入与 agent 规范结合生成可运行的任务运行时 |
| 推理（Reasoning） | 共享 | 处理现有信息（分析信号、规划、评估动作等） |
| 检索（Retrieval） | 任务级 | 从内部上下文（transient/episodic/persistent）获取信息 |
| 更新（Updating） | 任务级 | 修改内部上下文、模型参数、源代码、agent 规范、感知组件等 |
| 落地/接地（Grounding） | 任务级 | 通过工具、通信或具身动作与外部环境交互 |

### 2.6 上下文组织

Pera 将内部上下文分为三层：
- **临时上下文（Transient Context）**：单次任务内部的局部信息；
- **事件上下文（Episodic Context）**：多次任务执行积累的经验知识；
- **持久上下文（Persistent Context）**：与长期场景持续服务相关的长期信息。

### 2.7 两层决策过程

**任务级决策（Task-Level Decision-Making）**：
- 任务输入（用户指令或生命周期任务包）→ **实例化**（用通用决策程序+任务特定程序构建运行时）→ 循环执行 **规划（Planning）→ 动作（Action）**，直至满足完成判据或无法继续。
- 该过程沿用 CoALA/ReAct 等经典语言智能体的决策循环，对 Pera 来说这部分是既有机制而非新增结构。

**生命周期级决策（Lifecycle-Level Decision-Making）**：
- 分四个阶段：**处理（Processing）→ 构建/规划（Formulation）→ 执行（Execution）→ 审查（Review）**。
  - **Processing**：信号处理器将传感器输入的原始事件转换为结构化描述；
  - **Formulation**：控制平面根据描述判断是否开展工作并构建生命周期任务包（若现有感知/处理能力不足，还可生成修复感知程序的子任务）；
  - **Execution**：任务运行时通过任务级机制执行任务；
  - **Review**：检查执行轨迹与结果，决定持久变更应被接受、进一步修订还是回滚。审查中发现的新问题可以作为新的内部信号再次进入生命周期感知，形成反馈闭环。

Pera 的关键创新是：**它不是在既有任务执行机制上增加一个“更长的任务”，而是显式增加了一个更高的控制层，使长期场景本身成为受控对象**（类比软件工程中架构关注点从单体模块扩展到模块间关系）。

## 6. 论文的主要结论与发现

- **语言智能体正在经历从 episodic 执行向持久服务的架构转变**，这一转变可由任务间共享的持久条件（cross-task conditions）来定义，实现对“体系范围”的更清晰界定。
- **主动感知是跨任务变化的观察支柱**——若无跨任务主动感知，环境变化只有通过新的用户指令重新出现才能影响智能体，即存在“可观测性缺口（observability gap）”。
- **生命周期任务是将感知信号转化为早期适应行为的手段**——单纯保持记忆或在没有明确任务时发起新任务，不足以实现持久服务。关键是形成“为未来任务维护/完善持久条件”的任务，而非重复完成一次性目标。
- **“长视界任务” ≠ “长期场景”**。单目标的长任务执行努力不能解决跨目标的长期服务问题。
- **几个仍待解决的研究缺口**（可通过 Pera 框架透视）：
  - 感知端：感知范围太窄、选择性不强、传感器静态不演化；
  - 语义端：信号描述语言不统一、多源事件聚合不足；
  - 上下文端：模型不擅长从“真实世界的低结构化情境”中学习（CL-bench 等基准显示明显不足）；
  - 控制端：任务间调度不使用生命周期感知维度、生命周期变化的可验证验收规范不足；
  - 安全端：自动修改自我，风险更高，需恢复机制和逐步验收；
  - 评估端：现有 benchmark 过于关注单任务长串运行或多任务序列，缺乏真正跟踪“长期场景全生命周期服务”的开放式基准。
- **Pera 是一种有启发性的分析工具**，能够将不同工作按“感知类型 × 控制层级 × 上下文保留”三个维度的差异进行归类。

## 7. 优点（亮点）

- **架构隐喻清晰而富有洞察力**：“编程之小 vs. 编程之大”和“事情之小 vs. 事情之大”的类比为理解持久智能体提供了一个高度直觉化的框架，而不仅仅是对现有智能体技术的堆叠叙述。
- **精确定义了“生命周期任务”——填补了概念缺口**。将显式区分“为用户可见结果而做的事情”和“为了维护跨任务条件而做的事情”作为中心概念，包括对“任务是由用户还是智能体发起”的观点，是对该领域概念清晰度的一大贡献。
- **将“代理行动类”相关元视界推到了最佳状态**：从 5 个具体动作（推理、检索、更新、接地的认知语言智能体）提炼出 7 个动作空间，将感知和调度作为一等公民级动作，形成非常体系化的分析视角。
- **联系理论历史而非“重新发明轮子”**：与 Hayes-Roth 的自适应智能体架构、主动感知、CoALA 等先例框架建立了联系，并提出了它们的区别（例如 AIS 主要为适应当前任务，Pera 为适应长期的整个 task context 范围）。
- **从论文末尾部分

从论文末尾部分可以看出，作者并不满足于提出一个静态的框架，而是将其定位为“研究议程的起点”：他们围绕感知深度、信号语义、上下文学习、控制验证、安全性、评估协议六个维度给出了具体的开放问题，并明确指出了未来系统所需具备的能力。这种“架构蓝图 + 未解清单”的双层结构，使论文兼有立场陈述与研究指南的价值。

## 8. 不足与可改进之处

- **概念实现层面的“空转”**：Pera 描述了“生命周期感知 + 控制平面 + 任务包”的骨架，但没有给出任何可执行的算法、伪代码、数据流图或接口定义。对于试图复现该架构的读者而言，核心机制的实现模糊不清——例如传感器如何注册、信号处理器如何被生成或更新、控制平面如何仲裁多个并发生命周期任务。
- **控制平面自身的元问题悬而未决**：Pera 允许控制平面自动修改程序、agent 规范甚至“感知组件”，却未讨论控制平面本身如何被监控和约束。如果生命周期感知与信号处理程序本身发生错误，谁来生成修复它们的生命周期任务？这本质上是一个无限回归的“守望者”问题。
- **生命周期任务与普通任务的边界仍依赖语境**：作者正确地将“生命周期任务”定义为“以维护共享持久条件为目的的有界任务”，但这一目的可能在一开始并不明确。例如，用户说“请帮我把项目管理好”时，其对应的工作究竟是一个生命周期任务包总控下的多个事件任务，还是一个内部包含多个子目标的普通任务？作者没有提供可操作的判别标准，可能导致实际系统中的同一行为被贴上不同标签。
- **缺少交互与授权的闭环讨论**：控制平面能在什么时机、以何种理由打断用户或事件任务？当生命周期任务的审查判据无法被自动验证时，是否需要用户介入？文中对“权限限制”只是简单提及，未探讨人类授权在模式（自主、半自主、人工批准）之间如何决策。
- **案例研究过于“友好”**：所选模型开发场景的目标、依赖和性能信号相对“良态”——可以明确区分“Dense 训练”与“MoE 训练”，可以定义监控基线参数。这种容易描述的环境较好地衬托了架构差异，但无法说明 Pera 在更模糊、更不可预期的人类日常场景（如协同办公、个人生活管理）中的适用性。现实场景中信号噪声大、任务边界漂移、用户意图反复变化，Pera 的静态分层可能难以应对。
- **回顾性文献组织存在选择性分类的偏差**：把已有工作分入“感知”“记忆”“自主”或“架构”框架时，没有说明系统化的文献检索与筛选标准，哪些论文入选、哪些因何被排除均无交代。因此这种分类本身带有主观建构性，更接近论证工具而未达到系统性综述的严谨程度。

## 9. 个人总结与启发

Pera 这篇论文最大的贡献不在于提出一套可以立刻实现的系统，而在于它正确地定义了一个正在发生却尚未被完整命名的转向——语言智能体正从“单次任务执行器”变成“长期场景中的持续服务者”。由此，它提供了一种极具辨析力的语言：把“长期运行的长任务”与“维护跨任务条件的生命周期任务”分开，把“主动感知”从任务内感知中独立出来，把“控制平面”与“任务运行时”的层级关系显式化。

这对于今后的研究有三个直接启发。第一，**长期智能体不应只扩展记忆和规划长度，而应重新思考信息进入系统的通道**——如果没有跨任务边界的主动感知，许多需要“持续维护服务”的问题根本不会被发现。第二，**任务的概念需要被双层化**：面向用户的“事件任务”必须与面向系统自身长期健康的“生命周期任务”共存，且后者不应被简单视为前者的变体或子序列。第三，**模型自主修改自身能力的边界必须被显式管理**——Pera 提出的恢复机制、审查判据和权限限制，实际上为“自改进智能体”划出了工程可行性的基本护栏。

整体而言，这是一篇概念密度高、结构清晰、极具启发性的立场论文。它的弱点是缺少实证材料和实现细节，但作为一篇架构性分析文章，它成功地让该领域许多模糊的相似性差异变得可见。未来若能在真实环境中搭建一个符合 Pera 描述的感知-控制双层智能体，并通过长期开放场景的基准测试验证其相对于“长记忆 + 长任务”方案的增益，这篇论文所提出的架构将有望真正落地为下一代认知语言智能体的通用骨架。

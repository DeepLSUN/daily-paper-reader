## 摘要
自我进化智能体通过优化其“工具箱”（包括提示、技能、工具和执行逻辑）并基于环境反馈来推进自主性。然而，这种范式受到三个挑战的阻碍：\textit{信用分配失败}，即终端成功/失败反馈使得难以确定哪个步骤导致错误；\textit{捷径学习}，即智能体记忆任务特定模式而非获得可泛化能力；以及\textit{灾难性遗忘}，即无保护的更新会降低先前获得的能力。在本文中，我们引入了HarnessEvolve，一个从参考轨迹中学习以实现可靠智能体自我进化的自我进化框架。HarnessEvolve将执行智能体与进化流程解耦，将执行、评估、优化和门控分配给独立的智能体模块，从而实现可泛化和稳定的工具箱改进。具体而言，HarnessEvolve通过生成参考轨迹（在给定真实答案时产生的执行路径）并将失败执行与参考轨迹对齐以提取错误信号，从而克服信用分配失败；这些错误信号随后被聚类以揭示系统性失败模式。为防止捷径学习和灾难性遗忘，候选工具箱更新必须通过两个门控：一个质量门控，过滤数据泄漏和提示膨胀；以及一个性能门控，如果每次更新在当前批次上有所改进且不降低近期批次性能，则接受该更新，并在保留集上进行时期末验证以选择表现最佳的被接受的智能体快照。我们在涵盖开放领域和企业场景的多个基准上，使用不同模型和智能体框架进行了大量实验。结果表明，HarnessEvolve在所有基准和设置中持续优于最先进的基线，证实了其跨任务领域的可靠性。

## Abstract
Self-evolving agents advance toward autonomy by optimizing their harness---prompts, skills, tools, and execution logic---based on environmental feedback. This paradigm, however, is hampered by three challenges: \textit{credit assignment failure}, where terminal success/failure feedback makes it ambiguous which step caused the error; \textit{shortcut learning}, where agents memorize task-specific patterns rather than acquire generalizable capabilities; and \textit{catastrophic forgetting}, where unguarded updates degrade previously acquired competence. In this paper, we introduce HarnessEvolve, a self-evolving framework that learns from reference trajectories to achieve reliable agent self-evolution. HarnessEvolve decouples the execution agent from the evolutionary pipeline, assigning execution, evaluation, optimization, and gating to independent agent modules, enabling generalizable and stable harness improvements. Specifically, HarnessEvolve overcomes credit assignment failure by generating reference trajectories (execution paths produced when given the ground-truth answers) and aligning failed executions against them to extract error signals, which are clustered to reveal systematic failure patterns. To prevent shortcut learning and catastrophic forgetting, candidate harness updates must pass two gates: a quality gate that filters data leakage and prompt bloat, and a performance gate that accepts each update if it improves on the current batch without degrading recent batches, with epoch-end validation on a held-out set selecting the best-performing accepted agent snapshot. We conduct extensive experiments on several benchmarks spanning open-domain and enterprise scenarios, using different models and agent frameworks. Results demonstrate that HarnessEvolve consistently outperforms state-of-the-art baselines across all benchmarks and settings, confirming reliability across task domains.

## 1. 论文的核心问题与整体含义（研究动机和背景）

**研究背景：**
- 大语言模型（LLM）驱动的自主智能体已在许多复杂任务上展现强大能力。智能体的核心是它的“工具箱”（harness），即提示（prompts）、技能（skills）、工具（tools）和执行逻辑（execution logic）的整体集合。
- 智能体的发展经历了三代范式：**手工流程智能体**（如 Chain-of-Thought、ReAct，受控但僵化）、**技能增强智能体**（如 Claude Code、OpenClaw，灵活但依赖人类提供技能质量）、以及**自进化智能体**（自主优化自身工具箱，减少人类先验依赖）。

**核心问题：**
自进化智能体尽管有潜力，但在现实部署中面临三大根本性挑战：
- **信用分配失败（Credit Assignment Failure）**：长程任务中智能体只收到终局二元成功/失败信号，无法定位是哪一个中间步骤导致了失败；后期错误往往是前面错误的连锁后果，导致优化方向不明。
- **捷径学习（Shortcut Learning）**：没有防护时，智能体倾向于死记硬背答案或注入过多任务特定的上下文示例，造成数据泄漏和提示膨胀，虚增训练指标却不能获得真正的泛化能力。
- **灾难性遗忘（Catastrophic Forgetting）**：每次更新只在部分轨迹上优化，容易与此前学到的能力冲突，多轮迭代后逐渐遗忘旧能力。

**整体含义：**
作者认为这些问题无法靠再造一个“迭代提示优化算法”来解决，需要**系统级的架构转变**。为此提出 HarnessEvolve：一种将执行与进化流程解耦、以参考轨迹（reference trajectories）为指导、通过多智能体分工与“双门控”机制实现可靠、稳定、可泛化的工具箱自我进化框架。

## 2. 论文提出的方法论

**2.1 核心思想：**
- **四智能体解耦架构**：将执行、评估、优化、门控指派给独立模块（Execution / Evaluation / Optimization / Gating），使优化决策可审计、且不能被执行智能体“钻空子”。
- **参考轨迹（Reference Trajectories）**：在标准答案已知的情况下，让执行智能体尝试生成真实可执行的“正确路径”作为参照，用于定位失败轨迹中的第一个分歧点（first divergence point），而不是笼统地把整条轨迹判为错误。

**2.2 技术与流程要点：**

- **执行（Execution）**
  - 执行智能体 `A_exec` 使用当前工具箱在训练集上运行任务。
  - 每条查询还会在“给出题目+标准答案”的条件下运行最多 `T_att=5` 次尝试，尝试结果须通过评估智能体验证才能作为参考轨迹 τ⁺ 存入全局缓存 C。
  - 验证失败的查询则无参考轨迹可用，优化时退化为单条轨迹分析。

- **评估（Evaluation）**
  - 角色一：执行过程中评判任务正确性，收集失败集合 Fⱼ。
  - 角色二：在参考轨迹生成时验证其“真实性”，防止智能体直接背出答案、未走正常工具链而“抄近路”。

- **优化（Optimization）**
  - **轨迹对比**：对失败轨迹 τ⁻，与参考轨迹 τ⁺ 比对，输出结构化错误信号 Fᵢ=(severity, error cause, fix hint)，并定位第一个动作分歧点 t*——即最早偏离参考路径的步骤，以此作为根因，避免把下游级联错误当作独立错误处理。
  - **错误聚类**：按错误原因将实例级错误信号分组成系统性的失败模式群 Cₖ。聚类遵循三项原则：
    - 基于原因分组（而非按严重程度粗分类）；
    - 根因优先级（以第一个分歧点为准）；
    - 长尾保护（保留单成员簇，稀有但严重的错误不被主导簇吞并）。
  - **候选生成**：按簇的样例规模和严重程度生成针对工具箱各文件的修改，输出候选更新集合 Δharness。

- **门控（Gating）**
  - **质量门**：由独立的门控智能体检查候选更新，使用 LLM-as-judge 对数据泄漏打分（阈值 η_leak=0.8）并统计新增上下文示例数（提示膨胀，阈值 η_blo=5）；违规更新附带拒绝理由退回优化智能体修订，最多重试 3 次，超限即放弃。
  - **性能门**：候选智能体在**当前小批量**上的准确率提升须 ≥ δ（0 即可），且对最近 R=2 个小批量的准确率下降 ≤ ϵ（0.025），两条都满足才算通过，存入快照池 V 并接替当前版本。连续被拒达到批次耐心 Pbatch=10 则提前终止本轮。
  - **时期末验证**：每个 epoch 结束后，在验证集 Tval 上选出池中表现最好的快照，成为最终智能体；如果验证准确率连续 Pep=5 个 epoch 无改善则终止整体优化。

**2.3 核心公式：**
- 性能门接受条件：当前批次提升 ≥ δ 且所有近期批次(最近 R 批)准确率下降 ≤ ϵ。
- 最终智能体快照选择：在验证集上从快照池中选择准确率最高者 argmax。

## 6. 主要结论与发现

1. **主实验结果**：HarnessEvolve 在全部 5 个数据集、全部模型配置上准确率均超过所有基线。
   - 最亮眼成绩：CloudCoreNetwork-QA(Qwen3.6-27B)上从 Base 的 43.4% 提升至 86.9%，比最强基线 GEPA（65.3%）高 21.6 个百分点。
   - Wireless-QA（DeepSeek-V4-Flash）达 92.8%，比最强基线 ACE 高 2.7 个百分点。
   - 开源数据集上同样全面领先（SearchQA 92.9%、OfficeQA 70.9%、SpreadsheetBench 76.4%）。
2. **跨框架泛化**：优化技能可迁移，在四种未再优化的框架上普遍保持或提升准确率，说明针对性修改针对的是通用错误模式，而非绑定单一框架的捷径。
3. **门控机制有效**：自进化曲线中大量候选更新被拒绝，有效过滤了低质量修改；快照池峰值准确率稳步上升，最终选择的快照即峰值附近表现。
4. **组件贡献**：
   - 去参考轨迹对比 → 从 86.9% 跌至 57.8%，是贡献最大的组件。
   - 去错误聚类 → 跌至 68.6%，说明聚合错误为系统模式不可或缺。
   - 去质量门 → 跌至 80.1%，说明质量门对防捷径学习有实质帮助。
5. **工具箱修改范围**：优化会同时改变技能文件、脚本、提示词、工具描述和执行逻辑，而不仅限于单个组件。

- **企业数据集不可复现风险**：CloudCoreNetwork-QA 和 Wireless-QA 都是自建的、未公开的数据集，外部研究者很难验证结果的可重复性和公正性。主实验又恰好在企业数据集上赢得幅度最大，因此可能存在偏差。
- **消融覆盖不足**：消融只在 1 个数据集（CloudCoreNetwork-QA × Qwen3.6-27B）上进行；在更简单的数据集上，质量门或参考轨迹的作用可能不符合同样的推断，对组件贡献的“百分比”结论缺乏更强的泛化证据。
- **统计显著性缺失**：没有报告多次试验方差或显著性检验，无法确认优势的稳健性。Qwen 和 DeepSeek 这两个模型本身配置差别大（有无领域微调），缺少对“模型规模差异如何影响进化收益”的讨论。
- **超参数较多且来源不明**：η_leak=0.8、η_blo=5、R=2、δ=0、ϵ=0.025、Pbatch=10、Pep=5、Trev=3 等阈值缺乏敏感性分析，难以判断方法的稳定性。
- **参考轨迹生成成本与适用条件受限**：真实场景中很多任务没有标准答案、无法自动判定正确性，该框架依赖带标准答案的训练语料；对终局反馈稀疏或答案很难统一判定的任务，应用限制较大。
- **评估与竞品的对齐问题**：不同基线被限制得“只优化一个组件”，而 HarnessEvolve 优化全部组件，空间不对称之下比较是否能“公平体现框架差距”，论文对这一点说明得还不够明确。

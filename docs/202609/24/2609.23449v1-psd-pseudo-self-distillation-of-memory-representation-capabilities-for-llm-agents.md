## 摘要
记忆系统正成为LLM智能体的核心组件，但构建和维护记忆仍然成本高昂，因为它依赖于反复调用大型专有语言模型。这一成本为规模化部署记忆增强型智能体造成了重大障碍。在本文中，我们提出伪自蒸馏（Pseudo Self-Distillation, PSD），一个使小语言模型（SLM）能够通过多阶段训练流水线从强黑盒oracle中蒸馏行为，从而构建分层记忆表示的框架。标准蒸馏方法需要访问教师模型的logits或隐藏状态，而闭源模型不会公开这些内容。与传统自蒸馏设置（其监督来自模型自身预测、采样rollout或聚合输出）不同，PSD能够在单模型蒸馏设置下，通过提示词引入外部oracle知识。PSD使用单个小模型扮演两种角色：教师模型看到包含oracle答案作为参考上下文的特权提示，学生模型只看到任务提示。学生学习复现教师的输出分布，将oracle引导的行为吸收到自身权重中，而无需访问oracle内部。在LoCoMo上，经PSD训练的Qwen3-0.6B、1.7B和4B在下游检索任务上达到或超过GPT-4.1-mini，而部署成本仅为其一小部分，其中off-policy PSD在大多数条件下取得最佳结果。我们进一步表明，这种记忆构建能力能够分布外迁移到LongMemEval，尽管学生模型仅在LoCoMo上训练，且未接触任何LongMemEval数据。

## Abstract
Memory systems are becoming a core component of LLM agents, but constructing and maintaining memory remains expensive because it relies on repeated calls to large proprietary language models. This cost creates a major barrier to deploying memory-enhanced agents at scale. In this paper, we present Pseudo Self-Distillation (PSD), a framework that enables small language models (SLMs) to construct hierarchical memory representations by distilling behavior from a strong black-box oracle through a multi-stage training pipeline. Standard distillation methods require access to teacher logits or hidden states, which closed models do not expose. Unlike conventional self-distillation settings, where supervision is derived from a model's own predictions, sampled rollouts, or aggregated outputs, PSD enables a single-model distillation setup while channeling external oracle knowledge through the prompt. PSD uses a single small model in two roles: a teacher that sees a privileged prompt containing the oracle's answer as reference context, and a student that sees only the task prompt. The student learns to reproduce the teacher's output distribution, absorbing oracle-guided behavior into its own weights without accessing the oracle's internals. On LoCoMo, PSD-trained Qwen3-0.6B, 1.7B, and 4B match or exceed GPT-4.1-mini on downstream retrieval at a fraction of the deployment cost, with off-policy PSD achieving the strongest results across most conditions. We further show that this memory-construction capability transfers out-of-distribution to LongMemEval, despite the students being trained exclusively on LoCoMo with no exposure to LongMemEval data.

## 1. 核心问题与研究动机

- **背景**：记忆已成为现代 LLM 智能体的基础组件。近期分层记忆架构（如 MEMORA）通过多阶段流水线构建结构化记忆表示，在长程对话基准上取得 SOTA，说明智能体记忆的进展越来越依赖"高质量记忆表示的构建能力"。
- **核心痛点**：记忆构建不是单次推理，而是一条多阶段流水线（分段 → 情节记忆 → 事实抽取与合并 → 线索锚点生成 → 更新决策），每段对话产生多个 segment，每个 segment 又产生多条记忆与锚点，LLM 调用次数呈组合式增长。实践中依赖 GPT-4.1-mini 等强闭源模型反复调用，**部署成本极高，成为规模化落地的瓶颈**。
- **朴素替代方案失败**：直接用 Qwen3 小模型替换，会出现 JSON 格式错误、字段缺失、生成截断、幻觉等问题；且流水线是串行的，上游错误会逐级放大，导致下游检索性能退化。作者构造了 Qwen 专用提示模板（P^Qwen_k）改善格式遵循，但仅在 8B 等较大变体上有效，**0.6B/1.7B 仍然失败**——说明能力本身必须"训进"模型。
- **蒸馏路线的障碍**：
  - 经典/序列级蒸馏需要教师的 logits 或隐状态，闭源 oracle 不提供；
  - 序列级蒸馏用教师生成轨迹训练，存在训练-推理分布不匹配；
  - GKD、SKD 等 on-policy 方法虽缓解该问题，但仍需一个可查询的独立教师；
  - 自蒸馏（OPSD、Purified OPSD）去掉了外部教师，但此前只用于数学/代码推理这类有明确参考答案的任务。
- **PSD 的定位**：仅利用黑盒 oracle 的**最终文本输出**作为监督，把记忆构建能力迁移到白盒小模型，且能覆盖 MEMORA 流水线的每一个阶段。

## 2. 方法论

### 2.1 核心思想
- 关键观察：当模型被提供高质量参考答案作为上下文时，其输出分布会向与该参考一致的行为偏移。
- 因此用**同一个模型架构**扮演两个角色：
  - **教师**：输入为任务提示 + 特权参考（oracle 的答案 y_k）；
  - **学生**：输入仅为原始任务提示（与推理时一致）。
- 训练目标是让学生分布逼近教师分布，从而把 oracle 引导的行为**通过提示通道注入、再固化到学生权重中**，全程不接触 oracle 内部信号。
- 与常规自蒸馏的区别：常规自蒸馏的监督来自模型自身预测/采样 rollout/聚合输出，PSD 则借提示词建立了一条"外部 oracle 知识"的通道。

### 2.2 前置：MEMORA 流水线（5 个阶段）
- **Segmentation**：将原始内容切分为语义连贯的片段；
- **Episodic memory**：为每个片段生成叙事性情节记忆（参与者、意图、时间范围）；
- **Factual extraction & consolidation**：抽取候选 (抽象 a_i, 值 v_i)，对已有记忆做 Top-K 相似检索并按阈值 γ 过滤，再由 LLM 选择器 J 判断是否指向已有概念，执行 create-or-update；
- **Cue anchor generation**：为每条记忆生成 "[主体]+[关键方面]" 形式的线索锚点，形成多对多检索映射；
- **Update decision**：决定新候选是链接已有节点还是新建节点，保持记忆图紧凑无冗余。

### 2.3 阶段一：监督微调（SFT）
- 用 GPT-4.1-mini 跑完整 MEMORA 流水线，收集按阶段标注的 oracle 数据集 D_oracle = {(k, x_k^(i), y_k^(i))}。
- 由于各阶段调用频率极不均衡（N_seg ≪ N_epi ≪ N_fact ≲ N_cue），采用**按阶段均衡采样**（每阶段取 n_k 条）。
- 在冻结的 Qwen 骨干上加 LoRA 适配器 θ，最小化阶段均衡的 token 级交叉熵（对 5 个阶段取平均）。SFT 的作用不仅是学会任务，还要先对齐 GPT-4.1-mini 的格式与措辞习惯，为后续蒸馏损失"打好底"。

### 2.4 阶段二：伪自蒸馏（PSD）
- **初始化**：教师 θ_T 与学生 θ_S 都从 SFT 检查点初始化；**只更新学生，教师冻结**（防止目标分布漂移，同时作为正则把学生锚定在 SFT 解附近）。
- **提示不对称**：学生 x^S_k = P^Qwen_k(x_k)；教师 x^T_k = [P^Qwen_k(x_k); y_k]。
- **散度目标**：在温度缩放的 softmax 分布上计算散度，考虑前向 KL、反向 KL 与 JSD，默认采用 β-加权的 JSD（因其稳定性），M = β·p_T + (1−β)·p_S。
- **三种 rollout 变体**（决定散度在谁的 token 上计算）：
  - **On-policy**：学生按任务提示自生成 rollout ŷ，教师与学生分别在同一串 token 上前向计算分布，梯度只回传给学生。让教师"在学生实际会到达的状态上"给纠正，消除训练-推理分布错配。
  - **Off-policy**：由教师在特权提示下生成 rollout ỹ，双方再对 ỹ 打分。轨迹由 oracle 锚定、质量最干净，代价是与推理时分布匹配度下降。
  - **Mixed**：L_mixed = π·L_on + (1−π)·L_off，π∈[0,1]，可固定也可按训练进度调度（早期偏 off-policy，后期偏 on-policy）。

## 6. 主要结论与发现

- **PSD 让小模型具备可用的记忆构建能力**：Base 模型几乎不可用（0.6B 总体 LLM-judge 仅 0.1688），SFT 补上绝大部分格式缺口，PSD 在**每个规模上都进一步提升 LLM-judge**：0.6B 0.7674→0.8211，1.7B 0.7805→0.8211，4B 0.7805→0.8699（规模越大增益越大）；提升最稳定的类别是 single-hop 与 temporal。
- **匹配甚至超越闭源上界**：PSD 训练的 Qwen3-4B 取得全表最佳总体 LLM-judge（0.8699），超过 MEMORA(GPT-4.1-mini)（0.849）与 Full Context（0.825）；single-hop 达 0.9355 为全表最高，multi-hop 0.9000 与 MEMORA/Full Context 并列最佳。1.7B 已超过所有非 MEMORA 基线，0.6B 与 1.7B 总体持平（均 0.8211）。
- **off-policy 最优，on-policy 反而有害**：off-policy PSD 总体 0.8211 > mixed(0.5) 0.7317 > on-policy 0.7073，且 **on-policy 相对 SFT 全面退化**（除 open-domain）。作者归因于流水线串行特性：on-policy 用学生自身 rollout 打分，早期错误会级联并**被蒸馏损失强化而非纠正**；off-policy 的轨迹由特权教师生成、天然良构，不携带学生自身错误。
- **存在零样本 OOD 迁移，但不完整**：仅在 LoCoMo 上训练的 Qwen3-4B(PSD) 在 LongMemEval 上平均 77.0%，超过 Full Context（65.6%）与 Nemori（74.6%），接近 MEMORA(S)（83.8%）；单会话类（assistant 94.1%、user 87.5%）最强，多会话（52.9%）与时间推理（62.5%）最弱。
- **OOD 场景下 PSD 不再优于 SFT**：与 LoCoMo 上的结论相反，LongMemEval 上 PSD 在每个规模都略低于 SFT（4B：0.77 vs 0.78），作者推测 PSD 的精炼阶段只见过 LoCoMo rollout，会让学生行为向 LoCoMo 的对话结构特化；但在个别类别（4B 的 single-session-assistant 0.9412 vs 0.8235、single-session-preference 0.8235 vs 0.5294）PSD 仍有明显优势，说明收益**跨题型分布不均**。

## 7. 优点

- **问题切入精准且实用**：抓住了记忆构建这一真实部署瓶颈，动机（调用次数组合式增长、小模型结构化输出失败率极高）论证扎实，并用实验（Qwen 提示调优后小模型仍失败）证明"必须训练"而非"只需改提示"。
- **方法设计巧妙且约束诚实**：在只能拿到黑盒 oracle 文本输出的最弱假设下工作，用"提示即通道"把外部知识引入同源自蒸馏，既避开了 logits/隐状态的不可得，又避免了序列级蒸馏的分布错配，且教师冻结提供了明确的正则解释。
- **三种 rollout 变体的消融非常有价值**：发现 on-policy 在**串行多阶段结构化生成任务**上反而有害，并给出"错误级联被强化"的机制性解释——这与一般推理任务中 on-policy 更优的直觉相反，是对自蒸馏文献的有益补充与警示。
- **实证结论有说服力**：4B 学生在 LLM-judge 上超越用 GPT-4.1-mini 构建记忆的 MEMORA，且三档规模呈单调趋势，说明方法具备可扩展性；额外的跨数据集迁移实验也超出常规"单基准自证"的做法。
- **可复现性投入**：附录逐字给出 5 个阶段的完整提示词模板（含输出格式约束与示例），便于流程复现。

- **评判指标存在内在张力且未充分化解**：BLEU/F1 与 LLM-as-a-Judge 给出的结论方向相反（前者更偏向 Full Context、MEMORA 这类长文本/原文复述型方法），作者以"记忆构建应看语义正确性而非字面重叠"作解释，但缺少人工评估、混合检索指标或下游任务（如 QA 之外的 agent 决策）作为第三方仲裁，无法排除 LLM-judge 自身偏好带来的偏差。
- **未与同类蒸馏方法直接对比**：论文在动机部分论证了 GKD、SKD、OPSD 等方法的局限，但实验部分并未把 PSD 与其中任何一种在相同设置下对照，因此"PSD 优于现有蒸馏范式"这一主张缺乏直接实证，只能通过"这些方法需要可查询教师/不适用于结构化任务"的定性论述间接支撑。
- **教师-学生同源带来的能力天花板**：PSD 的监督信号完全来自"同一架构 + 特权提示"，其上限受学生自身架构与规模约束。论文未讨论当 oracle 能力显著超出学生容量时（例如更复杂的事实合并决策）PSD 是否会失效，也未分析蒸馏后学生相对教师的"能力保留率"。
- **流水线各阶段的独立增益未被拆解**：PSD 在所有 5 个阶段上联合训练，但未报告"只在某阶段施加蒸馏"的消融，因此无法判断哪一阶段最受益、哪一阶段可能拖后腿（例如 update decision 这类低频但高风险的阶段）。
- **错误级联的机制解释缺乏直接证据**：作者将 on-policy 的失败归因于"串行流水线中早期错误被蒸馏损失强化"，这是一个有说服力的假设，但论文未提供阶段级的错误传播量化（如各阶段格式错误率、字段缺失率随训练的变化），也未做"只对下游阶段用 off-policy、上游阶段用 on-policy"之类的验证性实验。
- **OOD 退化的原因停留在推测**：LongMemEval 上 PSD 略逊于 SFT，作者以"精炼阶段只见过 LoCoMo rollout，导致向 LoCoMo 对话结构特化"解释，但未做缓解尝试（如混合语料蒸馏、加入通用对话正则），也未验证该特化是否随训练轮数加剧。
- **评估覆盖范围有限**：仅在 LoCoMo 与 LongMemEval 两个英文长对话基准上验证，未涉及多语言、多模态、超长上下文（>20k token 的极端情形）或真实 agent 部署场景；记忆图的结构质量（节点冗余度、锚点覆盖率）也未直接度量，全部结论都通过下游 QA 间接反映。
- **基线可比性的潜在问题**：表 2 中各记忆系统是否在相同的检索器配置、相同的 prompt 与相同的 context 预算下运行，正文虽提到"统一 semantic retriever"，但未给出各基线超参搜索范围，存在基线未被充分调优的风险。

## 9. 总体评价与启示

- **贡献定位**：PSD 的价值主要不在于提出全新的蒸馏理论，而在于**把一个受限很严的现实问题（只有黑盒文本输出、无 logits、无独立教师）转化为一个可操作的训练框架**，并用完整实验证明"小模型也能承担记忆构建流水线"这一结论具备规模可扩展性。
- **最有价值的发现**：**on-policy 蒸馏在串行多阶段结构化生成任务上可能有害**。这一反直觉结果对智能体记忆、工具调用、多步规划等"链式结构化输出"场景中的蒸馏实践具有直接的警示意义——轨迹质量可能比状态分布匹配更重要。
- **方法论层面的可迁移性**：PSD 的"提示即知识通道 + 同源冻结教师"范式，原则上可迁移到任何"教师只能通过 API 返回文本"的场景（如代码生成、结构化抽取、agent 规划），这是其超越单一记忆任务的意义所在。
- **当前状态判断**：论文在**动机、方法设计与主要实证结论**上达到可发表水准，但在**统计严谨性、超参与算力透明度、评判指标的交叉验证、与同类方法的正面对比**四个维度存在明显短板。若要进一步加固，最优先的三项补充实验应是：(1) 多随机种子的方差与显著性报告；(2) 与 GKD/SKD/OPSD 在相同设置下的直接对比；(3) 阶段级消融与错误传播的量化分析。
- **实践启示**：对于资源受限、又要落地长程记忆智能体的团队，PSD 提供了一条"用 4B 开源模型 + 一次性 oracle 数据采集"替代"持续调用闭源强模型"的可行路径；但需注意其收益在分布内明显、分布外不保证，且必须配合 off-policy（而非直觉上更优的 on-policy）轨迹策略。

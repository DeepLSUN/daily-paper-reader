## 摘要
通过强化学习（RL）训练能力强的编码智能体，需要具有可靠验证器的多样化任务。开源代码库为此类任务提供了丰富来源，而现有方法通常依赖 issue 和 commit 等开发产物，限制了可提取任务的范围。为了更好地扩展 RL 环境，我们提出 CodeMidas，一种智能体流水线，它将现有代码库中已实现的功能转化为可执行的 RL 环境，仅使用源代码作为任务特定输入。CodeMidas 将智能体计算分配到环境构建的每个阶段：智能体探索已实现功能以制定行为规范，基于原始代码的执行构建测试，并通过执行检查和重复的解答 rollout 来验证与筛选候选任务。最终数据集包含来自 3,185 个开源代码库的 5,545 个训练任务，覆盖 23 种编程语言和 15 个技术领域。使用 GRPO 在这些任务上训练 MiMo-V2.5，在五个多样化基准上均提升了性能，涵盖问题修复（DeepSWE + 11.7%）、整程序构建（ProgramBench +17%）和终端工作（Terminal-Bench v2.1 +8.5%）。消融实验表明，增加高质量训练任务的数量可提升性能。轨迹分析表明，经 RL 训练的智能体表现出更好的行为，例如增加代码库探索和更多样化的自我验证。这些结果确立了源代码作为构建 RL 环境的可扩展基础，从而提升编码智能体在多样化软件任务上的表现。

## Abstract
Training capable coding agents via reinforcement learning (RL) requires diverse tasks with reliable verifiers. Open-source codebases offer a rich source of such tasks, while existing methods typically rely on development artifacts such as issues and commits, limiting the range of tasks that can be extracted. To better scale RL environments, we present CodeMidas, an agentic pipeline that turns implemented functionality in existing codebases into executable RL environments using source code as its only task-specific input. CodeMidas allocates agentic compute to every stage of environment construction: agents explore implemented functionality to formulate behavioral specifications, construct tests grounded in execution of the original code, and validate and filter candidate tasks through execution checks and repeated solution rollouts. The resulting dataset has 5,545 training tasks from 3,185 open-source codebases spanning 23 programming languages and 15 technical domains. Training MiMo-V2.5 on these tasks with GRPO improves performance on all five diverse benchmarks, covering issue repair (DeepSWE + 11.7%), whole-program construction (ProgramBench +17%), and terminal work (Terminal-Bench v2.1 +8.5%). Ablations show that increasing the number of high-quality training tasks improves performance. Trajectory analysis shows the RL-trained agent demonstrates better behaviors like increasing codebase exploration and more diverse self-verification. These results establish source code as a scalable foundation for constructing RL environments that improve coding agents across diverse software tasks.

- **背景**：用强化学习（RL）训练编码智能体，需要大量**多样化任务**与**可靠验证器**。任务多样性支撑泛化，可靠奖励才能强化正确行为。
- **核心矛盾**：现有环境构建流水线几乎都依赖"开发产物"作为任务种子——issue / pull request / commit（如 SWE-rebench V2、R2E-Gym、SWE-Universe）、已有测试（SWE-smith、SWE-Flow、SWE-Hub）、文档或 docstring（R2E、MindForge）。这使任务覆盖被"记录过的变更、测试、文档"所限定，无法大规模利用开源代码库中**已实现但未被记录的功能**。
- **论文主张**：直接以**源代码本身**作为唯一任务特定输入，把"已实现的功能"转化为可执行的 RL 环境。开源代码库（如 The Stack v2，覆盖数百种语言）提供了这一路径的语料基础：已实现功能既给出任务定义依据（公共接口与可观测行为），又天然提供候选解（原始实现），还能通过执行原始代码获得测试期望。
- **整体含义**：作者声称这为"从代码本身扩展编码 RL"提供了一条实用路线，把现有代码库"点石成金"（Midas touch）为训练环境。

## 2. 方法论：CodeMidas 流水线

### 2.1 核心思想
每个任务由三部分组成：**任务陈述（statement）+ 容器化开发环境 + 隐藏的可执行验证器**。求解器只能看到陈述与改造后的代码库及其依赖；验证器始终位于求解器环境之外，仅在判分时注入，返回**二值执行奖励（0/1）**。全程不训练奖励模型或学习式验证器，仅用 GRPO + 执行奖励。

### 2.2 四个关键模块

**（1）任务设计与代码库改造（§3.1）**
- 智能体检查代码库结构与构建元数据，识别具有**公共入口点与可观测结果**的功能。
- 支持三类接口：命令行工具（看进程输出）、纯库函数（看返回值）、有状态库 API（看跨调用的状态变化）。
- 追踪公共入口点与共享依赖以界定任务边界；随后**删除选定的核心实现**，并调整其余代码，形成"连贯的起始点"，保留真实项目结构与依赖。
- 陈述与代码边界协同修订：陈述规定输入、可观测行为与必需的公共接口，但**内部辅助函数与算法留给求解者自选**；原始实现单独保留作为参考解。

**（2）基于执行的测试构建（§3.2）**
- 智能体把陈述中的行为需求映射为测试输入与边界情形，在参考副本上调用公共入口点并记录结果。
- 测试形态随接口而异：CLI 用命令执行，纯函数用输入-输出用例，有状态 API 用调用序列（含顺序与清理行为）。
- 每条测试**记录其覆盖的具体需求**。陈述已固定的输出用参考执行确定期望值；未规定的方面只断言陈述所约束的部分（例如只强制异常类型，不固定异常消息措辞）。
- 智能体逐条审查断言，移除陈述不支持的过度限制（精确措辞、偶然顺序、内部结构），替换为行为性检查；若断言只能依赖私有符号且无行为替代，则**拒绝该任务**。修订后测试需在参考解上重跑确认兼容。审查后测试输入与断言被冻结用于判分。

**（3）环境准备与执行一致性（§3.3）**
- 从统一基础镜像出发安装依赖、准备构建与运行资源；清理会泄露被删实现的产物：编译输出、缓存副本、构建智能体遗留文件、以及针对目标功能的原始测试。
- **执行一致性检查**：在训练运行时设置下用 **6 个全新容器**验证——2 个装起始代码库必须**全部失败**，4 个装参考解必须**全部通过**，以确认期望的 fail-to-pass 转移并筛掉不稳定的执行结果。

**（4）Rollout 后的环境过滤（§3.4）**
- **泄露过滤**：对抗式 rollout，让智能体主动搜索整个求解器可见环境（编译产物、缓存、构建遗留文件、已安装的目标项目副本）尝试"不干活就通关"，记录命令与输出证据；由独立审查对照参考解与验证器判定，若泄露材料确实可绕过预期实现工作则拒绝该任务。
- **解与判定一致性审查**：每任务尝试 4 次；审查智能体对照陈述、验证器与参考解检查轨迹、提交代码与测试输出，标出**假正例**（判错却通过）与**假负例**（判对却失败），存在验证器缺陷的任务被拒绝。
- **Rollout 结果过滤**：只保留"既有成功又有失败"的任务，剔除全通过或全失败者（后者可能因任务过难、也可能因测试过弱或陈述缺需求，无法区分原因）。

### 2.3 数据集规模与特征
- 最终保留 **5,545 个任务，来自 3,185 个开源代码库，覆盖 23 种编程语言、15 个技术领域**。
- 语言分布（前十占 98.2%）：Python 21.4%、TypeScript 18.3%、Go 16.2%、C++ 12.5%、JavaScript 11.3%、C 7.4%、Java 6.0%、Rust 2.5%、Ruby 1.9%、Kotlin 0.8%。
- 领域分布：Systems 17.4%、Web 14.6%、Dev Tools 13.6%、AI/ML 9.1%、Data Science 7.6%、Multimedia 7.1% 等。
- 参考解规模：中位数 **142 行**（IQR 66–305 行）；**65.9%** 的任务参考补丁触及至少两个源文件。

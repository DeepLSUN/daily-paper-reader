## 摘要
检索增强生成（RAG）使大型语言模型（LLM）能够访问外部知识，但其传统的“检索-拼接-生成”流程代替模型做出检索决策。随着工具使用和智能体循环变得更可靠，智能体可以决定是否检索、检查什么以及何时停止。这一转变暴露出新的瓶颈：智能体可能不知道知识库中包含什么。传统知识库将文档暴露为匿名文本块，关于范围、目的、来源或关系的信息有限。我们提出 Knowledge-as-Skill，一种组织方案，使知识库可发现、可导航且具有自描述性。它包含三层：以 SKILL.md 为中心的发现层；每个目录一个 index.md 的导航层；以及包含文档的知识层，文档带有 YAML frontmatter，用于主题、类型、来源和生命周期。该设计遵循开放知识格式（OKF）和 Skill 协议，且无需修改智能体框架。我们还提供 knowledge-as-skill，一个将 PDF、Word 文件、网页导出和笔记等异构集合转换为该结构的流水线。在 WixQA 企业客户支持基准上的初步评估中，我们的设置获得 0.889 的 Factuality 和 0.816 的 Context Recall，而报告的 Corpus2Skill 值为 0.767 和 0.708。它获得略低的 Faithfulness、较低的 Context Precision，以及更多的交互轮次。由于模型、提示和知识包构建不同，这些结果是指向性的跨工作证据，而非受控比较。

## Abstract
Retrieval-augmented generation (RAG) gives large language models (LLMs) access to external knowledge, but its conventional retrieve-concatenate-generate pipeline makes retrieval decisions on behalf of the model. As tool use and agent loops become more reliable, an agent can decide whether to retrieve, what to inspect, and when to stop. This shift exposes a new bottleneck: the agent may not know what a knowledge base contains. Traditional knowledge bases expose documents as anonymous text chunks with limited information about scope, purpose, provenance, or relations.   We propose Knowledge-as-Skill, an organization scheme that makes a knowledge base discoverable, navigable, and self-descriptive. It has three layers: a discovery layer centered on SKILL.md; a navigation layer with one index.md per directory; and a knowledge layer containing documents with YAML frontmatter for topic, type, provenance, and lifecycle. The design follows the Open Knowledge Format (OKF) and the Skill protocol without modifying the agent framework. We also provide knowledge-as-skill, a pipeline for converting heterogeneous collections of PDFs, Word files, web exports, and notes into this structure.   In a preliminary evaluation on the WixQA enterprise customer-support benchmark, our setup obtains 0.889 Factuality and 0.816 Context Recall, compared with reported Corpus2Skill values of 0.767 and 0.708. It obtains slightly lower Faithfulness, lower Context Precision, and more interaction turns. Because the models, prompts, and knowledge-package construction differ, these results are directional cross-work evidence rather than a controlled comparison.

# 论文总结：Knowledge-as-Skill——面向 LLM 智能体自主知识库使用的结构化设计

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：检索增强生成（RAG）是当前让 LLM 访问外部知识的主流范式，其经典流程为“检索—拼接—生成”（retrieve–concatenate–generate）。
- **核心痛点一：检索决策被系统代替**。传统 RAG 是 workflow 驱动的：无论问题是否需要外部知识、模型能否用参数知识回答，系统都会先检索再拼接。模型只是被动的上下文接收者，无法自行决定“是否需要查、查什么、查多少”。
- **核心痛点二：agent 化后暴露新瓶颈**。随着模型工具使用能力增强、上下文变长、agent 循环更稳定，检索权限可以下放给模型。但此时出现一个此前被掩盖的问题——**智能体不知道知识库里有什么**。传统知识库为检索器的召回而优化，文档被暴露为匿名的、去上下文化的文本块，缺少范围、目的、来源与关系信息，自主探索者难以理解。
- **整体主张**：当知识具有清晰的边界、结构、文档说明和访问协议时，agent 可以像使用一项“技能”（skill）一样使用它。因此知识库需要一次**面向 agent 的重新设计**，应满足三项要求：**可发现（Discoverable）、可导航（Navigable）、自描述（Self-descriptive）**。

## 2. 方法论

### 2.1 核心思想
将知识库组织成符合 **Open Knowledge Format (OKF)** 与 **Skill 协议**的三层结构，使知识能够被 agent 按需“拉取”（pull）而非在任务开始时就整体注入上下文。设计无需修改 agent 框架。

### 2.2 三条设计原则
- **分层暴露（Layered exposure）**：不同文件暴露不同粒度的信息，每次深入阅读都以前一步的判断为条件，使上下文成本与相关性挂钩。
- **自描述（Self-description）**：每份文档说明其覆盖内容、可回答的问题、相关概念、来源及可能过期时间。
- **入口与结构分离（Separated entry and structure）**：SKILL.md 只描述范围、用法与边界，不承载领域知识；索引独立维护知识结构，内容增长不会破坏发现入口。

### 2.3 三层结构

| 层次 | 载体 | 作用 | 典型读取时机 |
|------|------|------|--------------|
| 发现层 | `SKILL.md` 的 frontmatter | 触发描述，常驻系统提示 | 始终可用 |
| 发现层 | `SKILL.md` 正文 | 范围、导航规则、停止条件 | 匹配后 |
| 导航层 | 各目录的 `index.md` | 候选条目与一句话摘要 | 进入某个 bundle 时 |
| 知识层 | 文档 YAML frontmatter | 主题、类型、来源、生命周期 | 全文阅读之前 |
| 知识层 | 文档正文 | 完整证据 | 相关性确认之后 |
| 辅助 | `log.md` | 变更历史 | 时效敏感问题 |

- **发现层**：`SKILL.md` 的 YAML frontmatter 包含 `name`、`description`（触发条件）、`type`；正文保持简短，规定范围、排除项、导航规则、常用入口、新鲜度约定与**显式停止条件**（防止反复探索无关知识库）。
- **导航层**：每个知识 bundle（目录）含一个 `index.md`，条目格式为**链接 + 一句话描述**，而非裸文件名列表。这个“小要求”是导航的核心——缺失或含糊的描述会让导航退化为随机打开文件。
- **知识层**：每份文档以 YAML frontmatter 开头，必填字段为 `type`、`title`、`description`，另含 `tags`、`sources`、`generated`（生成者与时间）、`verified`（验证者与时间）、`stale_after`（过期时间）。这些字段支持相关性判断、过滤、溯源与时效敏感回答。

### 2.4 典型端到端交互流程
1. agent 看到可用 skill 的名称与描述，判断问题是否匹配该知识库；
2. 读取 `SKILL.md` 了解范围、导航规则与边界；
3. 从根 `index.md` 出发选择一个有前景的 bundle；
4. 借助文档 frontmatter 在阅读全文前筛选文档；
5. 证据不足时沿相关索引条目继续，或判断问题超出范围而停止；
6. 基于实际读过的文档组织答案，对时效敏感断言参考生命周期元数据。

### 2.5 构建流水线（`knowledge-as-skill`）
将异构集合（PDF、Word、幻灯片、网页导出、会议笔记）转换为 OKF 与 Skill 兼容的知识包，共五阶段：
1. **枚举与转换**：保留已有 Markdown，其他格式通过 `mdconvert`（MarkItDown 封装）转为 Markdown，保留目录结构；
2. **生成 frontmatter**：记录必填字段、原始来源与生命周期字段；
3. **生成索引**：为每个 bundle 起草 `index.md`，可人工修订；
4. **生成根 `SKILL.md`**：包含范围、触发描述、导航规则、常用入口与新鲜度指引；
5. **校验**：用 `okfcheck` 检查 OKF 一致性，`-agent-ready` 额外检查发现文件、必填元数据与缺失索引。

增量维护同样是分层的：新增文档只需 frontmatter 与一条索引项，`log.md` 记录变更。

## 3. 实验设计

- **数据集 / 场景**：**WixQA**，一个基于 6,221 篇 Wix Help Center 文章构建的企业客服基准。评估使用其中 **200 道专家撰写的问题子集**，每题包含问题、参考答案与 1–3 篇 gold 文档。选择该数据集是为了与 Corpus2Skill 的报告值形成方向性对照。
- **评估系统**：一个最小 agent 循环。系统提示包含完整 `SKILL.md` 及任务指令（只依据知识库回答、只使用实际读过的文档、完成后提交答案）。**刻意不嵌入导航策略或答案格式约束**，以便导航行为主要来自知识结构本身。提供三个只读工具：`list_dir`、`read_file`、`submit_answer`。最大轨迹长度 15 轮。
- **模型**：回答模型为 **DeepSeek-Flash**，评判模型为 **K3**。
- **指标**：复用 Corpus2Skill 发布的指标实现与评测提示，包括 Token F1（SQuAD 风格词元级比较）、Factuality、Grounded Faithfulness、Context Recall、Context Precision（均由 LLM judge 五点量表评分后归一化）、Hallucination Rate（原始 Faithfulness ≤ 3 的问题占比）与平均 Turns。
- **对比方法**：与同期工作 **Corpus2Skill**（Sun et al., 2026）的报告值进行跨工作对照，而非在同一环境下复现。

## 6. 主要结论与发现

- **收益**：Factuality **0.889 vs 0.767**（+12.2 个百分点），Context Recall **0.816 vs 0.708**（+10.8 个百分点）。表明 agent 读到的文档覆盖了更多参考答案内容，答案被判定为更符合事实。
- **代价**：
  - Grounded Faithfulness 更低（**0.810 vs 0.859**）；
  - Context Precision 更低（**0.761 vs 0.829**）；
  - 平均交互轮次更多（**4.015 vs 2.38**）；
  - Token F1 更低（**0.412 vs 0.456**，但该词元级指标对措辞、答案长度与格式敏感，且本文提示未施加长度/格式约束，服务模型也不同）；
  - Hallucination Rate 相同（**均为 4.5%**）。
- **关键洞察**：Factuality 与 Faithfulness 度量的是不同性质——答案可能与参考答案一致，但对实际读到的证据利用较弱或文本关联较弱。更高 Factuality 与 Recall 伴随更低 Faithfulness 与 Precision、更长轨迹，符合“渐进式探索的代价”：agent 在缩小搜索范围时会读取更多中间或“路过”的文档。
- **总体立场**：结果是**架构性主张**——当 agent 负责决定读什么知识时，知识库应暴露结构、身份与来源，而不只是呈现匿名的可检索文本块；这些数据用于**推动受控实验**，而非给出确定性排名。

## 7. 优点

- **问题定位精准**：识别出“检索权下放后，agent 不知道知识库有什么”这一被忽视的瓶颈，视角新颖且切中 agentic RAG 的实际痛点。
- **设计简洁、可落地**：三层结构（发现/导航/知识）职责清晰，入口与结构分离，内容增长不破坏发现入口；增量维护成本低。
- **与现有生态兼容**：遵循 OKF 与 Skill 协议，`SKILL.md` 可直接放入 agent 框架的 skills 目录，**无需修改 agent 框架**。
- **配套工程完整**：提供 `knowledge-as-skill` 构建流水线与 `okfcheck` 校验工具，覆盖异构文档转换、frontmatter 生成、索引生成与一致性检查。
- **元数据设计细致**：`generated`/`verified`/`stale_after` 等生命周期字段直接支持时效敏感问答与来源可追溯，是纯检索方案难以提供的。
- **学术态度诚实**：明确声明对比不受控、指标为方向性证据，主动列出缺少消融、未测延迟与 token 成本等局限，避免过度宣称。

## 8. 不足与局限

- **实验覆盖不足**：
  - 仅一个数据集（WixQA）的 200 题子集，单组实验，无消融，无多数据集验证；
  - 未在同一 agent、同一语料、同一转换与评测流程下与固定 RAG 基线对比；
  - 未测试跨索引导航在多跳问题上的表现，也未测试随时间推移的变化。
- **偏差风险**：
  - 跨工作比较中服务模型、提示、知识包构建、运行时细节均不同，数值差异不能归因于结构设计本身；
  - LLM-judge 指标对提示与模型选择敏感；
  - 复用他人指标实现虽减少实现差异，但无法消除环境差异。
- **设计与工程成本**：
  - 人工策展的索引需要持续维护；描述可能不完整或有偏；额外的导航轮次消耗延迟与上下文预算（论文未量化）；
  - 自动构建可降低负担，但可能产生不准确的摘要或元数据。
- **应用限制**：面向领域边界清晰的企业级语料（强调可控性、可审计性与增量维护），对冷启动、非结构化大规模语料的扩展性未做验证，与强调自动化的 Corpus2Skill 属于互补而非替代关系。
- **未来工作方向**（作者自述）：受控的组件消融、延迟与 token 成本测量、随时间变化测试、多跳问题的跨索引导航评估，以及结构化导航与传统检索的混合系统。

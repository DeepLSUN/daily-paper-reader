## 摘要
近年来，由多模态大语言模型（MLLMs）驱动的智能体系统发展迅速，但现有的具身智能体基准仍缺乏对多智能体协调的细粒度诊断。大多数基准要么专注于单智能体任务完成，要么用整体任务成功率来概括多智能体行为，这可能会掩盖协调失败，如重复工作、违反顺序约束、资源竞争和不同步交接。在本文中，我们引入了CoCoBench，一个用于评估可执行家务任务中多智能体具身协调的构造级基准。CoCoBench包含897个经oracle验证的实例，围绕四个反复出现的协调构造进行组织：任务分配、顺序排序、互斥和交接协调。除了任务成功率外，CoCoBench还提供构造级分数，用于衡量智能体是否有效协调。我们评估了11个领先的MLLMs在不同协调模式、观察输入和智能体数量下的表现。结果表明，协调能力具有高度的构造特异性：整体表现优异并不意味着在不同协调类型上具备均衡的能力。这些发现为设计针对性的模型架构和改进多智能体协调能力指明了新方向。

## Abstract
Agent systems powered by multimodal large language models (MLLMs) have advanced rapidly in recent years, yet existing embodied-agent benchmarks still lack fine-grained diagnostics for multi-agent coordination. Most benchmarks either focus on single-agent task completion or summarize multi-agent behavior with overall task success rates, which can obscure coordination failures such as duplicated work, violations of ordering constraints, resource contention, and desynchronized handoffs. In this paper, we introduce CoCoBench, a construct-level benchmark for evaluating multi-agent embodied coordination in executable household tasks. CoCoBench contains 897 oracle-validated instances organized around four recurring coordination constructs: task allocation, sequential ordering, mutual exclusion, and handoff coordination. In addition to task success rate, CoCoBench provides construct-level scores that measure whether agents coordinate effectively. We evaluate 11 leading MLLMs across different coordination modes, observation inputs, and numbers of agents. The results show that coordination ability is highly construct-specific: strong overall performance does not imply balanced competence across different coordination types. These findings point to new directions for designing targeted model architectures and improving multi-agent coordination ability.

## 2. 论文提出的方法论

### 核心思想
- 将多智能体具身协调建模为**轨迹级联合规划问题**，以需求耦合（coordination coupling）的视角识别协作来源。
- 从家庭任务中提炼**四类可复现的协调构造（coordination constructs）**，每类对应不同的智能体环境耦合方式，并设计独立的量化评分。

### 四类协调构造与评分公式

1. **D1：任务分配（Task Allocation）**
   - 适用于可分发的并列任务（如分类收纳物品），目标是负载均衡分配。
   - 评分：`CD1 = min(1, M*/M)`，其中 M 为实现 makespan，M* 为 oracle 参考 makespan。得分高意味着接近参考并行调度。

2. **D2：顺序排序（Sequential Ordering）**
   - 适用于存在因果先序依赖的任务（如先开抽屉、再放入、最后关闭），目标是先序合规。
   - 评分：`CD2 = p_legal × (1 - v/n)`，其中 n 为先序相关操作数，v 为违规次数，p_legal 为合法性门（无违规为 1，否则为 0.5）。

3. **D3：互斥（Mutual Exclusion）**
   - 适用于共享独占资源场景（如多个智能体共用一把刀），目标是避免资源竞争。
   - 评分：`CD3 = (1 - c/a) × min(1, M*/L)`，其中 a 为访问尝试次数，c 为冲突次数，L 为已执行动作数，M* 为参考 makespan。

4. **D4：交接协调（Handoff Coordination）**
   - 适用于生产者-消费者模式（通过中间缓冲区传递物品），目标是节奏同步。
   - 评分：`CD4 = 1 - min(1, (o+w)/h)`，其中 h 为成功交接次数，o 为缓冲区溢出事件数，w 为空缓冲等待事件数。

### Bench构成
- 基于 **AI2-THOR** 仿真器实例化，生成 897 个经 oracle 验证的实例，覆盖 10 个任务族、4 类房间、3 种团队规模（N∈{2,3,4}）。
- 所有任务使用**固定的高层技能接口**（导航、拾取、放置、切片、开关等），隔离低层执行差异、聚焦高层团队协调。
- 实例生成经过三重质量验证：**放置门**（物体可用性与空间可行性）、**oracle门**（可解性验证）、**指标门**（oracle轨迹达到构造分数上限）。

## 3. 实验设计

### 基准测试集
- **全量集**：897 个实例，覆盖 D1~D4 四种构造、四类房间、三种团队规模。
- **消融子集**：分层抽样的 240 实例，每构造 60 例、每个构造×团队规模 20 例，用于架构和观察消融实验。

### 评估协议
- **集中式**（C0）：单一策略聚合所有智能体观察与历史，选择团队联合动作。
- **去中心化**（D1）：每个智能体仅基于自身局部观察与私有历史独立决策。
- **去中心化+通信**（D1+Comm）：在去中心化基础上增加广播消息通道。

### 观察设置
- **图像设置**（默认）：提供第一人称视觉观察。
- **盲测设置**：移除图像，仅保留文本任务说明、动作菜单和执行历史。

### 评估模型（11个MLLMs）
- **专有API模型**：GPT-5.6-sol、GPT-5.4-mini、Claude Opus 4.8、Claude Haiku 4.5、Qwen3.6-Plus、Kimi-K2.6。
- **开放权重模型**：Qwen3.5-9B、Qwen3-VL-8B、Cosmos3-Nano-16B、RoboBrain2.5-8B、InternVL3.5-8B。

## 6. 论文的主要结论与发现

1. **协调能力高度构造特异**：GPT-5.6-sol 整体表现最优（SR 84.8%、CS 0.90），但 Qwen3-VL-8B 在 D1 上最佳、Claude Opus 4.8 在 D2 上领先；单一模型的整体表现无法预测其在各构造维度上的均衡性。

2. **集中式状态聚合仍然关键**：集中式规划（48.0% SR、0.69 CS）优于去中心化+通信（39.6%、0.65）和纯去中心化（36.7%、0.63）；通信只能部分弥补集中式聚合的损失。

3. **主要瓶颈是符号级团队规划而非视觉识别**：盲测设置（42.3% SR）与图像设置（40.6% SR）性能相当甚至略优，说明在高层技能接口下，显式化的场景信息使视觉感知不再是瓶颈。

4. **团队规模增大系统性加剧协调难度**：平均 SR 从 2 个智能体的 48.8% 降至 4 个智能体的 43.1%；强模型保持稳定，弱开放权重模型下降显著（如 InternVL3.5-8B 从 16.9% 降至 7.7%）。

5. **任务成功与合法协调可严重背离**：Claude Haiku 4.5 的 SR（63.1%）高于其合法规划率（47.2%），说明部分成功是通过非法捷径达成的；CS 和合法性指标对区分"正确协调"与"任意达成目标"不可或缺。

6. **开放权重模型在协议遵循上存在明显短板**：协议失败平均 17.5%，预算耗尽+协议失败合计占开放权重模型 episode 的 54.3%，而专有模型协议失败基本为 0。

## 7. 优点

1. **构造级视角的基准设计**：将协调解构为任务分配、顺序排序、互斥和交接四种独立可测量的构造，比传统整体成功率提供更细粒度的诊断工具，并给出了各构造的明确计算公式。
2. **成功与协调质量解耦**：SR 与 CS 双指标体系区分"任务是否完成"与"协调是否得当"，能暴露被最终状态掩盖的非法或低效行为。
3. **严谨的质量控制流程**：三重验证（放置门、oracle门、指标门）确保实例可执行、可解决且具有诊断区分度。
4. **统一的高层技能接口**：固定低层执行器，隔离高层协调能力差异，使跨模型比较更公平。
5. **指标验证充分**：通过构造分数的交叉相关分析验证了四类构造的非冗余性，确认指标测量的是独立能力维度。
6. **系统性的多维度实验设计**：覆盖模型类型、架构协议、观察模态和团队规模的全面对比，并辅以失败模式与合法性分析。

## 8. 不足与局限

1. **仿真环境限制**：基于 AI2-THOR 进行实验，无法完全反映现实世界物理交互的复杂性和不确定性，结论向真实机器人系统的迁移性有待验证。
2. **高层技能接口简化了问题**：基准刻意固定高层技能接口，虽有助于隔离协调能力，但也跳过了低层运动规划和原始技能执行中的协调问题，适用边界有限。
3. **并发执行确定性假设**：去中心化评估中，各智能体从同一状态快照选择动作并确定性顺序执行，这不同于真实环境中真正的异步并发，可能低估了时序不确定性的影响。
4. **构造评分依赖轨迹信号充分性**：评分公式中包含对轨迹信号量的要求（n、a、h 等为 0 的轨迹会被排除），可能减少了部分低绩效模型的有效评估样本量。
5. **指标相关性验证仅基于单模型**：构造非冗余验证仅使用 GPT-5.6-sol 的轨迹，该结论推广到其他模型时需谨慎。
6. **专有模型版本与硬件信息不可复现**：论文中的模型版本号（如 GPT-5.6-sol、Claude Opus 4.8）带有未来设定色彩，部分模型并未公开；开放权重模型的运行硬件也仅简略提及，影响可复现性。
7. **缺少跨语言与跨文化任务的普适性讨论**：所有任务均为英语描述和西方家庭场景，对中文或非西方家庭场景的适用性未做讨论。

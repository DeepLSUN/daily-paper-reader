## 摘要
平面检索增强生成将语料库视为分块的袋子，丢弃了文档层级和跨文档结构。我们引入了SearchWiki，一个框架，将语料库综合为分层、类型化、可导航的维基，并训练一个智能体WikiResearcher-9B，通过多轮工具使用来检索信息。该维基将知识组织为三层——文档概览、跨文档主题页面和页面级源记录；当初始查找未命中时，支持检索的逐步细化。我们使用同策略强化学习和多组件奖励函数来优化智能体的导航策略，该函数平衡了答案正确性、检索质量和轨迹效率。在ViDoRe-V3（8个领域）、FinanceBench和记忆基准测试（LoCoMo、LongMemEval、PersonaMem-v2）上的评估表明，我们的RL调优Qwen 9B模型WikiResearcher-9B，显著优于同规模未训练的基线，并超过或匹配更大的外部模型。SearchWiki与WikiResearcher-9B配对使用表明，对结构化语料库的学习导航是平面检索的优越替代方案。

## Abstract
Flat retrieval-augmented generation treats a corpus as a bag of chunks, discarding document hierarchy and cross document structure. We introduce SearchWiki, a harness framework that synthesizes a corpus into a hierarchical, typed, navigable wiki and trains an agent, WikiResearcher-9B, to retrieve information through multi-turn tool use. The wiki organizes knowledge into three layers - document overviews, cross- document topic pages, and page-level source records; enabling progressive refinement of retrieval when initial lookup misses. We optimize the agent's navigation policy with on-policy reinforcement learning with a multi-component reward function balancing answer correctness, retrieval quality and trajectory efficiency. Evaluation on ViDoRe-V3 (8 domains), FinanceBench, and memory benchmarks (LoCoMo, LongMemEval, PersonaMem-v2) shows that WikiResearcher- 9B which is our RL-tuned Qwen 9B model, significantly outperforms same-size untrained baselines and exceeds or matches larger external models. SearchWiki paired with WikiResearcher-9B demonstrates that learned navigation over structured corpora is a superior alternative to flat retrieval.

## SearchWiki 论文总结

### 1. 核心问题与研究动机

- **背景**：检索增强生成（RAG）已成为大模型接入外部知识的主流范式，但传统"平面 RAG"把语料库视为无结构的文本块集合（bag of chunks），通过一次性的 top-k 向量检索获取上下文。
- **核心缺陷**：
  - 丢弃了文档层次结构（章节、子章节）和跨文档引用关系，丧失人类依赖的渐进式上下文构建能力；
  - 初始检索失败时没有恢复机制——无法回溯、重新表述查询或探索相邻区域，本质上是单次操作而非迭代过程。
- **研究动机**：既然人类研究者是通过"目录总览→下钻章节→交叉引用→回溯分支"的方式导航陌生知识库，为何不让 RAG 也采纳同样的策略？核心洞见是：**这种导航能力可以通过构建显式结构 + 强化学习训练来"制造"而非"假设"**。

### 2. 方法论

#### 2.1 总体框架：两阶段 SearchWiki

- **阶段一：Wiki 编译（Wiki Compilation）**——离线将非结构化语料自动编译为类型化、可导航的三层 wiki；
- **阶段二：语料导航（Corpus Navigation）**——通过在线强化学习训练智能体 WikiResearcher-9B，使其在多轮工具交互中主动导航该 wiki。

#### 2.2 Wiki 知识表示：三层结构 + 目录文件

| 层级 | 路径 | 内容 |
|------|------|------|
| 文档概述 | `documents/` | 每篇文档的前页摘要，含章节结构与页码范围，链接至章节子目录 |
| 主题页 | `topics/` | 跨文档概念页（如"风险管理政策"），含指向相关文档和主题的 Markdown 链接 |
| 源记录 | `sources/` | 每页的 JSON 记录（OCR/版面文本、页码、元数据），按需通过 `read_page` 加载 |
| 目录文件 | 根目录及子目录 `index.md` | 映射目录树，附构建日志 |

该布局支持**渐进式披露**：智能体从摘要/主题开始，仅在需要时才下降到具体页面。

#### 2.3 编译管道（三个自动阶段）

1. **版面感知解析**：用视觉语言 OCR/版面管道提取文本与结构，序列化为页面 JSON 记录；
2. **TOC 提取与渐进结构化**：为长文档提取目录（章节标题、嵌套深度、页码区间），以此构建磁盘树；短文档走单摘要路线；对话记忆按会话粒度映射；
3. **联合 Wiki 编译器**：单次 LLM 调用同时生成文档/章节摘要和概念注册操作，减少顺序处理的信息损失，避免重复主题；独立文档并行编译，时序文档顺序处理以维护共享主题注册表。

#### 2.4 工具套件（7 个工具）

`search_wiki`（多查询 BM25+RRF）、`grep_search`（正则扫描）、`read_file`（读摘要/章节/主题页）、`read_page`（读页面级源 JSON）、`list_files`、`glob_file_search`、`update_scratchpad`（持久化搜索规划）。

#### 2.5 策略学习：在线 RL 配方

- **在线 Rollout**：每组查询采样 G=8 条完成轨迹，多轮调度器执行工具调用并将观测追加到上下文；
- **检索 Token 掩码（RTM）**：工具观测（`o_t`）进入上下文但不参与策略损失计算，防止策略模仿 OCR 文本；
- **DAPO 目标**：使用解耦裁剪 + 动态采样的策略优化，组内相对优势由 GRPO 风格归一化得到：

  \[
  \hat{A}_i = \frac{R_i - \text{mean}(\{R_j\})}{\text{std}(\{R_j\}) + \delta}, \quad \delta = 10^{-8}
  \]

  裁剪边界为 \(\varepsilon_{low}=0.2, \varepsilon_{high}=0.28\)（Clip-Higher），并配合 GDPO 做奖励缩放。

- **两阶段训练**：阶段一用完整奖励栈端到端优化；阶段二将梯度更新严格限制在最终答案 token 上，防止长搜索链中导航策略退化；
- **稠密奖励栈**（加权和）：
  - 正确性（LLM 判定：正确 1.0 / 部分 0.3 / 错误 0）；
  - 检索质量（Read-F1、检索排名/nDCG）；
  - 结构奖励（格式合规、遍历启发式、并行工具奖励、超步数与重复调用惩罚等）；
  - 上下文截断或超步数轨迹获得零总奖励。

### 6. 主要结论与发现

1. **学习导航优于平面检索**：在 ViDoRe v3 上，WikiResearcher-9B 达到 **71.35%** 的严格 QA 准确率，超过同尺寸未训练 Qwen3.5-9B（63.95%，+7.4 分）和更大的 Qwen3.5-397B（69.51%）、Qwen3.6-27B（70.94%）；
2. **检索质量显著提升**：页面级 nDCG@5 达 53.22%，领先所有基线（包括 44 倍参数的 Qwen3.5-397B）；
3. **领域外泛化能力强**：FinanceBench 上达 83.33%，逼近 Oracle 上界（85.33%），远超原始 leaderboard（≤19.30%）；在记忆基准上，未经记忆专用训练的 SearchWiki 仍能匹配甚至超越 NapMem 专用策略（LoCoMo F1 领先、LongMemEval LLM-J 80.67 vs 80.33）；
4. **层级结构与多轮交互独立贡献**：消融显示，移除层级结构或退化为单轮 RAG 均显著掉点；RL 带来的增益独立于模型规模放大。

### 7. 优点

- **范式创新**：将 RAG 从"被动检索"重新定义为"主动语料导航"，类比人类研究者的信息寻取行为（berrypicking、信息觅食），理念清晰且有认知科学支撑；
- **领域无关的 wiki 编译**：同一套表示与工具适用于技术文档、财报和对话记忆，具备跨模态/跨体裁的通用性；
- **RL 训练配方的工程深度**：RTM 掩码防止模仿环境 token、两阶段 token 掩码防止轨迹退化、稠密奖励栈分解正确性/检索/结构三个维度、截断轨迹置零等trick 设计精细，且各部分均有动机说明；
- **消融实验设计规范**：逐一分离了层级结构、工具交互和 RL 的贡献，结论可信度较高；
- **评估公平性意识强**：统一 harness、统一判定协议、明确标注 untrained vs RL-trained、提供置信区间与 bootstrap 检验；
- **开源/复现意识**：规划了公开 ViDoRe v3 全部分割评估，补充材料包含训练配置与模板。

### 8. 不足与局限

- **实验覆盖的边界**：训练数据完全依赖合成管道（教师 LLM 生成），且仅保留 25%，存在教师模型偏差放大风险；评估基于 LLM-as-judge 协议，虽使用外部模型但判定偏差难以完全排除；
- **算力与可扩展性**：wiki 编译需对每个语料运行多阶段 LLM 管道，离线成本较高；RL 训练需 8×A100 + vLLM 共置，对资源受限团队门槛偏高；
- **模型规模单一**：RL 调优仅在 9B 级别进行，未展示在更大规模（如 27B/397B）上 RL 的效果，限制了"RL 优于缩放"结论的普适性；
- **记忆基准的局限**：在部分指标（LongMemEval F1、PersonaMem-v2 Acc）上 WikiResearcher-9B 未全面领先，且与 27B harness 的差距缺少深入分析；
- **比较范围**：未与主流图式 RAG（如 GraphRAG、HippoRAG）和代表性智能检索（如 Search-R1）在标准 RAG 基准上做横向对比；
- **论文可复现细节不完整**：奖励权重、实际工具调用轨迹示例、完整的目录布局示例均被放至补充材料，正文中未充分交代；
- **潜在应用限制**：对图像密集、非文本类信息（如表格、图表）依赖 OCR 管线质量，可能成为长尾场景的性能瓶颈。

## 摘要
在高风险领域共享表格数据受到隐私法规的约束。合成数据提供了一种有前景的替代方案，但深度生成模型训练成本高且难以审计，而基于LLM的方法通常将记录序列化为文本，模糊了表格结构并暴露敏感数据。我们引入了表格合成策略设计师（TabSSD），它利用LLM来设计合成流程而非直接生成记录。TabSSD向LLM提供基于树的变量依赖摘要，而非原始记录，从而生成可在本地执行和评估的Python程序。在十二个数据集上，TabSSD在统计保真度、预测效用和实证隐私风险之间取得了良好的平衡，在十种方法的六项指标中实现了最佳平均排名。此外，与对比方法相比，它大幅减少了本地计算量和令牌消耗。通过支持人工引导优化并消除用户端模型调参，TabSSD降低了透明表格数据合成的专业知识和基础设施门槛。

## Abstract
Sharing tabular data in high-stakes domains is constrained by privacy regulations. Synthetic data offer a promising alternative, but deep generative models are costly to train and difficult to audit, while LLM-based methods often serialize records as text, obscuring tabular structure and exposing sensitive data. We introduce Tabular Synthesis Strategy Designer (TabSSD), which uses an LLM to design synthesis procedures rather than directly generate records. TabSSD provides the LLM with tree-derived summaries of variable dependence rather than raw records, which produces Python programs for local execution and evaluation. Across twelve datasets, TabSSD strikes a favourable balance among statistical fidelity, predictive utility, and empirical privacy risk, achieving the best average rank across six metrics among ten methods. Moreover, it substantially reduces local computation and token consumption relative to the compared methods. By enabling human-guided refinement and eliminating user-side model tuning, TabSSD lowers the expertise and infrastructure barriers to transparent tabular data synthesis.

## 二、论文提出的方法论：TabSSD

### 2.1 核心思想

TabSSD（Tabular Synthesis Strategy Designer）将LLM定位为**策略设计者**而非记录生成器。核心流程如下：

1. 用**链式决策树**（chained trees）从原始数据中提取变量依赖结构（不暴露原始记录）；
2. 将依赖信息编码为**紧凑提示词**，交给LLM分析并生成多个候选Python合成程序；
3. 候选程序在**数据持有者本地环境**中执行和评估；
4. 根据统计保真度、隐私风险、运行时间等准则选出最优策略并生成最终合成数据。

### 2.2 关键技术细节

- **变量依赖提取（链式树）**：
  - 对每个特征$X_j$，训练一棵分类/回归树 $Tree_{X_j}: X_{\backslash j} \rightarrow X_j$，即用所有其他特征预测该特征；
  - 对标签$Y$，训练标签树 $Tree_Y: X \rightarrow Y$；
  - 记录每个特征的**分裂变量集合** $A(X_j)$（按树深度排序，越靠近根节点越重要）和**拟合优度** $\phi(Tree_{X_j})$（连续变量用$R^2$和RMSE，分类变量用准确率）。
- **紧凑编码**：不直接输入完整决策树规则，而是提取特征类型与范围、分裂变量、拟合优度、标签树叶节点的标签分布，构成轻量级依赖摘要。
- **贪心集合覆盖（高维扩展）**：对高维数据（如DARWIN的451个变量），用贪心集合覆盖算法选择最小树子集覆盖所有变量，控制提示词长度在上下文窗口内。例如DARWIN仅需54棵树的规则即可覆盖全部451个变量。
- **提示词结构**：$p = p_{task} \oplus p_{metric} \oplus p_{requirement} \oplus p_{dep} \oplus p_{output}$，分别包含任务定义、评估指标引导、推理要求、树提取的依赖证据、输出模板与示例。注意$p_{dep}$中特征使用匿名编号（feature_0, feature_1...），不泄露真实变量名或原始记录。
- **候选策略生成与选择**：
  - LLM被查询$K$次（默认10次），生成K个候选Python程序（统一接口：`generate_synthesis_data(save_path, n_sample, X_train, y_train)`）；
  - 过滤器：丢弃执行失败、运行超时（$\tau_T = 100$秒）或$\delta$-presence隐私风险超标（$\tau_\delta = 10$）的策略；
  - 最终选择：在可行集合$\Omega_{feas}$中，最小化边际分布误差与两两相关误差的平均值（公式4）。
- **隐私保护设计**：LLM全程只接收树摘要，不接触原始记录；原始数据仅在本地用于树拟合、策略执行与评估。

### 2.3 核心算法（Algorithm 1）

1. 定义任务、目标与输出要求
2. 在$D_{train}$上构建链式树
3. 提取依赖信号（分裂变量、拟合优度、标签树结构）
4. 对高维数据应用贪心集合覆盖选择树子集
5. 编码依赖信息为$p_{dep}$，构建结构化提示词$p$
6. 循环查询LLM生成K个候选策略，逐一执行并评估
7. 过滤（隐私阈值、时间阈值），统计误差最小化选择最终策略$S^*$
8. 返回策略$S^*$及其合成数据$\hat{D}^*$

## 七、优点

1. **范式创新**：将LLM从"记录生成器"转变为"策略设计者"，解决了LLM与表格结构不匹配的根本问题，是LLM+表格合成方向的重要概念性突破。
2. **隐私-效用-成本三重优势**：LLM不接触原始记录（结构性隐私保障），本地执行避免了GPU需求，同时在统计保真度和预测效用上不逊于甚至超越深度生成模型。
3. **可理解性与可编辑性**：合成逻辑用Python代码显式表达，专家可审计、诊断、修改具体代码行，而非面对黑盒网络。
4. **高度自适应**：同一提示模板在不同数据上自动产生定制化策略（分类树、高斯Copula、线性回归等），无需人工调参。
5. **Token效率的可扩展设计**：贪心集合覆盖算法使提示长度随维度增长得到有效控制，避免了上下文窗口爆炸。
6. **实验严谨**：采用20次随机合成平均、统一评估协议、多指标覆盖、消融验证等，增强了结论的可靠性。


## 八、不足与局限

1. **依赖树摘要的固有局限**：链式树可能遗漏弱依赖或高阶非线性依赖关系，导致LLM获得的"理解"不完整，从而生成次优策略。
2. **LLM随机性与可靠性**：LLM输出具有随机性，可能产生无效、低效或低保真度的合成程序。论文通过多候选生成+本地验证缓解，但无法完全消除。补充表13也承认存在实际失败案例。
3. **上下文窗口的硬约束**：虽然集合覆盖缓解了问题，但超高维表格仍可能超出LLM上下文窗口。论文建议未来用检索增强和图表分解进一步扩展。
4. **隐私度量的局限性**：DCR和$\delta$-presence是经验性度量，不是形式化隐私保证（如差分隐私）。论文也承认未来需要整合形式化隐私机制。
5. **依赖专有LLM服务**：主实验使用Gemini-2.5-Pro（闭源商业模型），该服务在策略生成阶段虽不见原始数据，但部署中仍需信任API提供商；并且论文未讨论API调用中的元数据泄露问题。
6. **人工评估缺失**：论文用代码片段和统计指标论证可审计性，但未开展系统性的用户研究来验证领域专家能否可靠地理解、审计和修改生成的策略。
7. **消融范围受限**：消融实验仅在8个数据集上进行（受上下文窗口限制），结论的泛化性受到一定限制。

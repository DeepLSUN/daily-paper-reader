## 摘要
推测解码通过让轻量级草稿模型提出多个候选令牌，然后由更大的目标模型并行验证，来加速自回归语言模型推理。然而，在第一次拒绝之后，标准的基于前缀的验证会丢弃剩余的草稿后缀，因此生成和验证这些位置的计算不会对解码进度做出贡献。我们以DFlash为例，表明被拒绝后缀中的被拒绝位置可能仍与目标延续对齐，这表明草稿模型尽管存在局部令牌级错误，仍能保留有用的语义和结构信息。受此观察的启发，并受条件扩散的启发，我们提出了ReTrace，一种拒绝轨迹条件化方法，它使每个草稿块以上一轮的被拒绝后缀为条件，而不是仅从新的掩码占位符生成。ReTrace保留被拒绝后缀的隐藏表示，将它们与下一个草稿块对齐，使用来自同一验证过程的目标感知修正信号对其进行细化，并通过门控残差融合将它们纳入起草器的输入嵌入中。由于被拒绝的令牌永远不会被提交，且目标端验证保持不变，ReTrace保持了推测解码的无损性，且无需额外的模型前向传递。使用Qwen3模型在数学推理、代码生成和开放式对话方面的实验表明，ReTrace在其DFlash骨干上一致地提高了平均接受长度和端到端解码速度。通过在不修改轮内提案生成的情况下引入跨轮条件化，ReTrace在很大程度上与现有的起草改进正交，并可与它们结合以获得进一步收益。

## Abstract
Speculative decoding accelerates autoregressive language model inference by having a lightweight draft model propose multiple candidate tokens, which are then verified in parallel by a larger target model. However, after the first rejection, standard prefix-based verification discards the remaining draft suffix, so the computation spent generating and verifying those positions does not contribute to decoding progress. Focusing on DFlash, we show that rejected positions in a rejected suffix may still align with the target continuation, indicating that the draft model can retain useful semantic and structural information despite local token-level errors. Motivated by this observation and inspired by conditional diffusion, we introduce~\textbf{ReTrace}, a rejected-trajectory conditioning method that conditions each draft block on the rejected suffix from the previous round rather than generating it from fresh mask placeholders alone. ReTrace retains the hidden representations of the rejected suffixes, aligns them with the next draft block, refines them using target-aware correction signals from the same verification pass, and admits them into the drafter's input embeddings through gated residual fusion. Because rejected tokens are never committed and target-side verification remains unchanged, ReTrace preserves the lossless property of speculative decoding without requiring an additional model forward pass. Experiments with Qwen3 models across mathematical reasoning, code generation, and open-ended dialogue demonstrate that ReTrace consistently improves average acceptance length and end-to-end decoding speed over its DFlash backbone. By introducing cross-round conditioning without modifying within-round proposal generation, ReTrace is largely orthogonal to existing drafting improvements and might be combined with them for further gains.

## 2. 论文提出的方法论

### 2.1 核心思想

ReTrace 将上一轮被拒绝的后缀轨迹（隐藏表示序列）作为下一轮草稿块的**辅助条件信号**，而非将草稿块从全新的掩码占位符生成。该方法受**条件扩散模型**启发，但仅借用了"跨步条件化"的概念，不引入扩散采样过程。

### 2.2 关键技术细节

**(1) 拒绝轨迹的构建与对齐**

- 在第 t 轮解码中，草稿模型产生 B 个候选 token 及其最终层表示：{hᴰ_{t,1}, ..., hᴰ_{t,B}}。
- 若接受长度 A_t < B，首个被拒位置 r_t = A_t + 1。
- ReTrace **排除**已接受的表示 hᴰ_{t,1:A_t}（已提交到上下文）和首个被拒位置的表示 hᴰ_{t,r_t}（该位置由目标侧的修正 token 解决）。
- 只保留首个被拒位置**之后**的表示：{hᴰ_{t,r_t+1}, ..., hᴰ_{t,B}}。
- 这些表示按原始顺序**对齐到下一轮提案块的开头**：

  m_{t+1,j} = hᴰ_{t,r_t+j}（1 ≤ j ≤ B − r_t），其余位置补零。

**对齐逻辑**：目标模型提交修正 token 后，hᴰ_{t,r_t+1} 恰好对应下一轮的第一个未解决位置。

**（2）目标感知校正（Target-Aware Correction）**

- 被拒轨迹仅反映草稿模型的预测，可能含有错误。验证过程中产生的目标模型表示提供了互补视角。
- 对于每个对齐位置 j，取对应的目标表示 u_{t+1,j} = hᵀ_{t,r_t+j−1}（因果模型位置 r_t+j−1 的状态用于预测位置 r_t+j 的 token）。
- 通过轻量投影将草稿-目标表示对映射为更新信号：

  **c_{t+1,j} = W_c [m_{t+1,j}; u_{t+1,j}]**（W_c ∈ R^{d×2d}）

- 修正后的信号为**残差形式**：

  **r_{t+1,j} = m_{t+1,j} + β · c_{t+1,j}**

  其中 β 为校正强度系数，训练初期线性升温（50步内），推理时使用全激活值 β=1。

**（3）门控残差融合（Gated Residual Conditioning）**

- 修正信号不应取代当前掩码输入，而是以**门控残差**形式注入：

  **ẽ_{t+1,j} = e_{t+1,j} + W_v r_{t+1,j} ⊙ σ(W_g [e_{t+1,j}; r_{t+1,j}])**

  其中 W_v ∈ R^{d×d}, W_g ∈ R^{d×2d} 可学习，σ 为逐元素 sigmoid，⊙ 为逐元素乘。

- 门控是**向量级**的，能按隐藏维度控制信号流入量。
- W_v 初始化为零，使残差在初始化时消失，保证草稿模型从其原始行为开始学习。

### 2.3 训练与推理特性

- **训练**：使用与 DFlash 骨干相同的块扩散目标；草稿骨干、校正模块和门控注入模块联合优化；目标模型冻结；跨轮状态被 detach，防止梯度跨轮传播。
- **推理**：所有信号来自标准草稿和验证过程的已计算表示，**无额外目标模型前向传播**；信号仅保留一轮即被替换；被拒 token 永不提交，目标侧验证和采样逻辑完全不变，因此**保持无损性**。

## 6. 主要结论与发现

1. **被拒绝轨迹确实保留预测信息**：token 级分析（75.2% 目标 token 在草稿 top-5 内）和表示级分析（真实目标延续相似度显著高于随机基线）共同证明了被拒后缀的可复用性。

2. **ReTrace 一致提升 DFlash 骨干的性能**：在 4 个模型-温度配置的宏平均上，接受长度提升 6.97%，端到端加速比提升 5.34%，且在**每个**基准上均有提升。

3. **额外训练不是改进来源**：SFT 对照基线在相同数据和预算下仅获得边际改善并迅速饱和，而 ReTrace 在整个训练过程中持续增长。

4. **运行代价极小**：校正+融合总开销仅 0.13ms/轮，占 DFlash 周期的 0.40%，对总延迟影响可忽略。

5. **与轮内改进正交**：ReTrace 与 Domino 的组合在吞吐量（+14.22 tok/s）和接受长度（+0.36 token）上均有额外提升，证实跨轮条件化与轮内因果细化是互补的信息通路。

6. **在并发场景下仍然有效**：在并发度 1–32 范围内，ReTrace 始终保持最快速度，即使 EAGLE-3 在并发 32 时已低于目标-only 解码，ReTrace 仍保持 1.62× 加速。

## 7. 方法或实验设计的亮点

1. **问题发现具有启发性**：首次系统性地对推测解码中"被拒后缀的预测信息含量"进行定量分析（token 级排名 + 表示级相似度 + 随机基线对照），证据链完整。该分析本身即是一项独立的贡献。

2. **方法设计巧妙且极简**：
   - 利用标准验证过程中**已经计算**的目标表示，不引入额外前向传播——成本仅是一个轻量投影和门控。
   - 门控残差 + 零初始化 W_v 保证了训练初期的行为与原始 DFlash 完全一致，优化稳定性好、风险低。
   - 仅保留首个拒绝位置之后的表示，巧妙避开了已解决位置的信息冗余。

3. **目标感知校正的残差设计**：原始信号保持为主路径，校正模块仅提供增量调整，β 线性升温进一步减少训练初期的干扰。

4. **正交性主张有实验支撑**：明确将"跨轮条件化"与"轮内提案改进"分离，并通过 Domino 兼容实验直接验证。

5. **实验设计严谨**：多种对照（额外训练对照、并发场景对照、组件消融）有效排除了混淆变量，结论更可信。

3. **评估规模有限**：
   - 部分基准使用较少的 prompt（GSM8K 仅 128 条，AIME25 仅 30 条）。
   - 平均接受长度提升的幅度（6.97%）虽一致，但绝对增量较小（约 0.2–0.5 个 token），实际收益是否在不同工作负载下保持稳定存在不确定性。

4. **跨轮错误传播风险**：ReTrace 将被拒轨迹作为条件信号，虽然不直接提交 token，但可能将上一轮的语义偏差传递给下一轮草稿。论文未系统性分析这种偏差累积的长期影响——如果多轮连续拒绝，信号是否可能持续恶化或产生循环依赖？

5. **训练成本与数据需求未充分讨论**：需要 32 GPU 和 40K 样本进行训练，对于希望快速部署的用户来说门槛较高。且只测试了一个训练数据规模，未研究数据量对效果的影响。

6. **条件信号仅保留一轮**：论文明确"信号持续一轮即被替换"，但未实验验证多轮保留是否会有不同效果，也未分析一轮保留是否为最优设计。

7. **当块被完全接受或拒绝发生在最后一个位置时**，ReTrace 退化为原始 DFlash，此时无条件信号可用。论文未量化这种退化场景的频率及其对整体收益的影响。

8. **对目标模型可解释性的依赖**：目标感知校正依赖于"目标模型验证时的表示具有可用于修正草稿信号的语义"这一假设，但论文未分析目标模型不同层级的表示选择（为何用最终层而非中间层）对性能的影响。

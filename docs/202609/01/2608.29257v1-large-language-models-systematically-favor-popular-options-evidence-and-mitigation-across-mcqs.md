## 摘要
多项选择题（MCQ）是评估大型语言模型（LLM）的标准格式，但答案选项的流行度可能干扰评估。现代LLM系统性地偏好流行但不正确的选项，而非不太流行的正确选项，我们将这种脆弱性称为“流行度偏差”（popularity bias）。这种模式与置信度校准不一致相符：即使对于流行选项的准确性下降，模型置信度仍然很高。为了系统地隔离这一现象，我们引入了PopMCQ，这是一个包含六种受控策略的基准，这些策略在保持正确答案不变的同时改变选项的流行度。在我们最具对抗性的设置中，所有干扰项都比正确答案更流行，模型选择流行但错误答案的时间为66%。为了缓解这种偏差，我们提出了PopDebias，一种轻量级的推理时校正方法，它从模型预测中估计并去除流行度先验。它不需要微调，在测试时无需标签（仅使用少量校准分割进行参数拟合），并且增加了可忽略的计算成本。在22个开源LLM（0.5B到32B参数）上的实验显示出一致的改进，在强流行度压力下准确率提升高达54.1个百分点。代码和数据可在https://github.com/DataScienceUIBK/PopMCQ获取。

## Abstract
Multiple-choice questions (MCQs) are a standard format for evaluating large language models (LLMs), yet the popularity of answer options can confound evaluation. Modern LLMs systematically prefer popular but incorrect options over less popular correct ones, a vulnerability we call \textbf{popularity bias}. This pattern aligns with confidence miscalibration: model confidence remains high even as accuracy collapses for popular options. To systematically isolate this phenomenon, we introduce \textbf{PopMCQ}, a benchmark with six controlled strategies that vary option popularity while keeping the correct answer fixed. In our most adversarial setting, where all distractors are more popular than the correct option, models choose popular but wrong answers 66\% of the time. To mitigate this bias, we propose \textbf{PopDebias}, a lightweight inference-time correction that estimates and removes a popularity prior from model predictions. It requires no fine-tuning, is label-free at test time (using only a small calibration split for parameter fitting), and adds negligible computational cost. Experiments on 22 open-source LLMs (0.5B to 32B parameters) show consistent improvements, with accuracy gains up to 54.1 percentage points under strong popularity pressure. The code and data are available https://github.com/DataScienceUIBK/PopMCQ

- **背景**：多项选择题（MCQ）是大语言模型（LLM）评估的主流格式，被广泛应用于 MMLU、AGIEval、C-Eval 等基准测试和高风险应用。已有研究表明 LLM 对流行实体（如高维基百科浏览量实体）的事实记忆和回答准确率更高，但此前未系统研究“流行度”与“正确性”冲突时的行为。
- **核心问题**：当流行但错误的选项（干扰项）与不太流行的正确答案同时出现时，LLM 是否系统性偏好流行选项，从而损害评估的可靠性？作者将这种脆弱性命名为 **popularity bias（流行度偏差）**。
- **整体含义**：该偏差直接威胁 MCQ 评估的有效性——模型可能因选项“知名度”而非事实正确性作答，导致评估分数失真；同时这也暴露了模型在决策时过度依赖表面频率信号而非深层知识，与置信度校准问题密切相关。
- **关键研究问题**：
  - RQ1：LLM 是否在 MCQ 中把实体流行度当作正确性捷径？
  - RQ2：流行度偏差背后的机制是什么？
  - RQ3：能否在不重新训练的情况下缓解该偏差？

## 2. 论文提出的方法论

### 2.1 核心思想
- 将流行度视为一种“先验”信号，在推理时从模型输出概率中**估计并移除**该先验，同时自适应地调节置信度，避免过度校正。
- 核心假设：观测到的选项概率 ∝ 流行度先验 × 无流行度偏置的真实信念（公式 `pi ∝ πi · φi`）。

### 2.2 PopMCQ 基准构造
- 从四个 QA 数据集（MuSiQue、Natural Questions、EntityQuestions、WebQuestions）抽取问题，用 GPT-4o 生成 20 个候选干扰答案，按流行度分为高/中/低档，每个候选附有合理性评分。
- 通过**六种受控策略**（S1–S6）在保持问题与正确答案不变的前提下改变干扰项流行度：
  - **S1 (Baseline)**：随机选择 3 个干扰项。
  - **S2 (Popular Trap)**：选择流行度最高的 3 个干扰项（且均高于正确答案），构成最强压力。
  - **S3 (Gradient)**：干扰项流行度严格递减且均高于正确答案，测试梯度效应。
  - **S4 (Direct Contest)**：1 个最高流行度 + 2 个中等流行度干扰项，构成“正面交锋”。
  - **S5 (Reverse Control)**：所有干扰项流行度均低于正确答案，使流行度与正确性一致（反向对照）。
  - **S6 (None of the Above)**：正确答案是“以上都不是”（流行度为 0），干扰项包含 1 个高流行度 + 2 个低流行度选项，测试模型在不确定性下的“弃权”能力。
- **特点**：策略选择完全基于维基百科浏览量（模型无关），不依赖生成模型或评测模型的判断，确保实验的因果纯度。

### 2.3 PopDebias 方法流程
- **输入**：模型概率向量 `p`、各选项流行度 `Pop(oi)`。
- **偏差强度估计**：
  - 在 10% 的小校准集上拟合一个轻量级回归器 `fθ`，预测“模型所选选项流行度 − 正确答案流行度”；
  - 若回归器不可用，则使用无监督启发式：`b ∝ Pop(o_hat)/mean(Pop) + max p + 1/Var(Pop)`。
- **构造先验权重**：`wi = 1 - b·Pop(oi)/max(Pop)`，从而近似实现 `π^{-1}`（对高流行度选项降权）。
- **重加权与归一化**：`qi = pi·wi / Σ pj·wj`。
- **自适应置信度温和化（tempering）**：
  - 计算温度系数 `γ = clip(1 - β·b·c·ψ, 0, 1)`，其中 `c = max p` 是模型置信度，`ψ` 是流行度分布熵导出的压力因子；
  - 最终输出 `ep = γ·q + (1-γ)/K`，向均匀分布收缩，防止过度自信。
- **复杂度**：O(K) 单次前向计算，显著低于按位置打乱的置换集成方法（O(K!)）。

- **基线对比**：

- 由于 PopDebias 是推理时方法，无训练成本；其校准仅需在 10% 数据上拟合极轻量回归器，整体算力开销很小。

## 5. 实验数量与充分性

- **规模庞大**：22 个开源模型 × 4 个数据集 × 6 种策略 ≈ 528 个主实验组合，另有 API 模型评测、多种 prompting 对比、few-shot 消融、与 PrideDebias 对比、校准分析、开放回忆诊断、规模效应分析等。
- **消融丰富**：
  - 不同策略（S1–S6）间的横向对比；
  - 单 token vs 全序列打分稳健性检查；
  - 概率熵与病态分布检查；
  - 流行度 vs 合理性相关性分析（排除混淆变量）；
  - 模型规模（0.5B–32B）与家族层面偏差分析；
  - 提示方式 × 去偏方法交互实验。
- **充分性与公平性**：所有策略共享相同打分代码和 prompt 格式，仅改变干扰项内容；候选生成和策略组装均与评测模型无关；流行度与合理性正交性验证（ρ < 0.24）有效排除了合理性混淆。因此实验设计较为客观、公平。
- 需要指出的是，论文中大量详细表格（如附录 M）主要展示“Before/After”结果，但部分附录表格颜色标记（绿/红）在文本呈现中无法显示，因此对具体每一处数值的“改善/退化”判断依赖原文标记；不过主要结论均有汇总表支撑。

## 6. 论文的主要结论与发现

- **流行度偏差广泛且严重**：
  - 在 S2（Popular Trap）下，全部 22 个模型的平均 Spearman ρ 达 **−0.864～−0.879**，HPSR 升至 66% 左右，即 2/3 的情况下模型选了流行但错误的选项。
- **决策时现象，而非单纯知识缺失**：
  - 在开放回忆显示“已知答案”的子集上，S2 准确率仍大幅下降，且 **99.8%** 的错误选择了比正确答案更流行的干扰项；
  - 约有 **29%** 的 S2 错误出现在 S5（反向控制）下模型能答对的题目上，证明偏差独立于知识水平。
- **置信度校准失灵**：
  - 置信度在不同流行度分桶中几乎不变（约 0.52–0.57），但高流行选项上的准确率骤降至 0.03，导致高流行桶的过度自信差距高达 **0.489**。
- **S6 揭示“弃权”失败**：模型在应该选“以上都不是”时，仅 11% 正确选择，却以 3.1 倍频率选择最流行实体。
- **尺度与对齐无法消除偏差**：Qwen2.5 从 0.5B 增至 32B，ρ 仅从 −0.895 变至 −0.845；RLHF（Zephyr-7B vs Mistral-7B）无缓解；前沿模型（GPT-4o 等）仍存在 ρ ∈ [−0.41, −0.65] 的偏差。
- **PopDebias 有效性与普适性**：
  - 在所有 22 个开源模型、4 个数据集上均有提升，S2 下平均准确率提升 +27.6～+31.9 pp，最高可达 +54.1 pp；
  - S5 下增益仅 +2.5 pp，证明方法只在流行度与正确性冲突时校正，不破坏有益信号；
  - ECE 显著下降（如 Llama-3-8B 从 0.194 降至 0.064，减少 67%），校准改善明显。
- **与基线方法对比**：PopDebias 大幅优于位置去偏方法 PrideDebias（后者在 S2 上几乎无提升），也优于 CoT 和 Bias Warning 等 prompting 方法（这些方法仅提升 0–4 pp）。

## 7. 优点

- **研究问题新颖且重要**：首次系统隔离 MCQ 中“选项流行度”这一混淆因素，指出主流评估基准可能高估模型能力。
- **实验设计严谨**：
  - 构造六种策略实现因果干预，将流行度作为独立变量；
  - 使用模型无关的外部流行度信号（维基百科浏览量），验证其与模型内部熟悉度高度相关（平均 ρ=0.70）；
  - 排除合理性混淆、单 token 与全序列评分一致性检验。
- **方法实用性强**：PopDebias 无需微调，测试时无标签，仅需很小校准集，计算开销可忽略；对闭源模型也可进行偏差测量。
- **结论覆盖面广**：从 0.5B 到 32B，涵盖多个开源家族以及 GPT-4o、Claude、Gemini 等前沿 API 模型，证据充分。
- **可复现性好**：提供了代码和数据仓库。

## 8. 不足与局限

- **评测格式局限**：仅限 MCQ，未扩展到开放生成、自由答案等式；
- **模型覆盖局限**：主要评估开源模型（因需 token 概率），前沿 API 模型仅能评估最终答案，无法完全适用 PopDebias；
- **校准数据的依赖**：PopDebias 需要 10% 校准分裂，零资源场景不可用；
- **语言与文化有限**：仅英文，流行度偏差可能因语言、文化而异；
- **流行度代理有偏**：维基百科浏览量不能完全覆盖所有训练语料频率、领域内熟悉度或非英文实体的真实流行度；
- **偏差未完全消除**：即使经 PopDebias 校正，在对抗性 S2 下相关系数仍为负（如 ρ ≈ −0.65），说明仍存在残余偏差；
- **无法应用到不提供 token 概率的 API**：限制了方法的直接商业适用性；
- **论文中未来扩展方向**（多语言、闭源模型、训练时去偏结合）均未在本工作中实现，属于后续工作。

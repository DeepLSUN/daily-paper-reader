## 摘要
软件工程需求的持续变化产生了对自动化工具的实质需求，这些工具能够从自然语言输入中创建安全的源代码。传统大型语言模型（LLM）的性能受到其“一次性”能力的限制，这导致在复杂操作中出现逻辑幻觉以及算法性能下降。本研究提出了一种自主AI编程智能体，通过其有组织的决策制定方法，在LLM生成的内容与生产就绪软件之间建立了联系。我们的框架使用Gemini 2.5 Flash API提供核心推理能力，同时采用定制的蒙特卡洛树搜索（MCTS）方法将代码生成挑战作为搜索操作来解决。该智能体使用“自批评”评估器系统来测试不同的实现方法，并根据其准确性和难度级别进行排名，然后通过反向传播改进其操作框架。该系统通过基于Flask的Web界面运行，提供即时反馈和语法高亮功能。我们的实验结果表明，基于MCTS的方法在复杂逻辑提示上达到了92%的成功率，同时超越了标准的零样本生成模型。

## Abstract
The ongoing changes in software engineering requirements have created a substantial need for automated tools which can create secure source code from natural language input. The performance of traditional Large Language Models (LLMs) becomes limited by their "one-shot" capability which results in logical hallucinations together with reduced algorithmic performance during complicated operations. The research presents an autonomous AI Coding Agent which establishes a connection between LLM-generated content and production-ready software through its organized methodology for decision making. Our framework uses the Gemini 2.5 Flash API for essential reasoning capabilities while employing a tailored Monte Carlo Tree Search (MCTS) method to solve code generation challenges as a search operation. The agent uses a "Self-Critic" evaluator system to test different implementation methods which it ranks according to their accuracy and difficulty level before it improves its operational framework through backpropagation. The system operates through a Flask-based web interface which delivers instant feedback together with syntax highlighting features. Our experimental results show that the MCTS-based method achieves a 92% success rate on complex logical prompts while surpassing standard zero-shot generation models.

- **核心问题**：论文将 AI 代码生成面临的主要挑战归纳为三点：
  1. **一次性生成不准确（One-Shot Inaccuracy）**：模型难以理解复杂逻辑依赖，往往需要多次提示修正。
  2. **优化能力不足（Optimization Deficiencies）**：生成代码难以兼顾 Pythonic 编码风格与时间/内存的极致优化。
  3. **逻辑幻觉（Logical Hallucinations）**：代码语法正确但逻辑错误，在运行或边界测试中崩溃。
- **整体含义**：论文试图弥合 LLM 生成内容与“生产就绪（production-ready）”软件之间的鸿沟，提出一种**将代码生成视为搜索过程**的自主智能体框架，而非简单的“一次生成、一次交付”。

## 2. 论文提出的方法论

- **核心思想**：把代码生成问题建模为**蒙特卡洛树搜索（MCTS）** 的搜索过程，由 LLM（Gemini 2.5 Flash）负责候选代码的生成与推理，由“自批评（Self-Critic）”评估器对候选代码打分，并通过反向传播指导搜索方向，从而在多个实现路径中迭代逼近最优解。
- **系统架构**：
  - 采用**客户端-服务器（Client-Server）** 架构，前端与后端分离，便于扩展升级。
  - **前端**：HTML5、CSS3、Tailwind，配合 Marked.js 与 highlight.js 实现代码渲染与语法高亮。
  - **后端**：Flask 承担 Web 服务与 API 请求管理。
  - **AI 编排**：LangChain 管理提示链与对话上下文，Gemini 2.5 Flash 作为核心推理引擎。
- **MCTS 编码流水线**（四个阶段循环执行）：
  1. **选择（Selection）**：通过 **UCB1 公式**权衡“已知高表现节点”与“未探索节点”，选出最有希望的代码节点。
  2. **扩展（Expansion）**：在选中节点下由 LLM 生成改进版或替代版实现，作为子节点。
  3. **模拟/评估（Simulation/Evaluation）**：由评估器依据原始用户需求对生成代码打分。
  4. **反向传播（Backpropagation）**：将评估分数回传至父节点，更新各节点价值，指导后续搜索。
- **评估器逻辑（Self-Critic / 双重提示）**：
  - 第一轮提示让模型扮演 **“开发者”** 生成代码；
  - 第二轮提示让模型扮演 **“批评者”**，从 **事实性/正确性（Factuality）**、**效率（Efficiency）**、**清晰度（Clarity）** 三个维度评出 0.0–1.0 的分数，并以 JSON 形式输出，供 MCTS 决策。
  - 论文示例迭代：基础 for 循环（0.65，未选中）→ 优化 dict 方案（0.82，选中）→ 边界安全版（0.91，选中）→ 内存优化变体（0.94，最终输出）。
- **两种运行模式**：
  - **Fast Mode**：标准快速生成流程；
  - **MCTS Mode**：启用完整搜索-评估-回溯机制，用于复杂算法开发。

## 摘要
我们介绍了 A.X K2，一个 688B 参数的混合专家（MoE）语言模型，从零开始训练，作为智能体应用的高性能基础。该模型在约 8.5T tokens 上训练——少于其前身 A.X K1——使用更小但更高质量的混合数据，大幅扩展了智能体和软件工程数据，然而它在各方面均优于 A.X K1，在某些基准上超过 30 个百分点，反映了 token 效率的巨大提升。为了高效支持长上下文，我们引入了稀疏门控注意力（SGA），它结合了稀疏注意力和门控注意力，并采用门控归一化（GN）来稳定大规模训练。SGA 在 128K 长度上通过稀疏索引器预热进行原生训练，该预热针对索引器自身的稀疏 top-k 选择进行优化，而非密集注意力分布，从而使适应成本显著降低：每个查询仅读取 2,048 个位置，但长上下文质量不变，A.X K2 在 RULER 上达到 256K 长度时得分 94.6。GN 的异常值抑制反过来使得 4 位 NVFP4 服务的精度保持在 FP8 精度的 1 个点以内。一个简单而有效的 Think-Fusion 方案进一步让用户能够在单个统一模型内在思考和非思考模式之间切换。广泛的评估表明，A.X K2 在与强大的开源权重基线的竞争中表现出色，在数学和韩语基准上达到或超过了它们。

## Abstract
We introduce A.X K2, a 688B-parameter Mixture-of-Experts (MoE) language model trained from scratch as a high-performance foundation for \emph{agentic} applications. Trained on approximately 8.5T tokens---fewer than its predecessor, A.X K1---on a smaller but higher-quality mixture with substantially expanded agentic and software-engineering data, it nonetheless improves over A.X K1 across the board, by over 30 percentage points on some benchmarks, reflecting large gains in token efficiency. To support long contexts efficiently, we introduce Sparse Gated Attention (SGA), which combines sparse attention with gated attention, and adopt Gated Norm (GN) to stabilize large-scale training. SGA is trained natively at 128K through a \emph{sparse} indexer warmup that optimizes the indexer against its own sparse top-$k$ selection rather than the dense attention distribution, making adaptation markedly cheaper: each query reads only 2,048 positions, yet long-context quality is unchanged and A.X K2 scores 94.6 on RULER out to 256K. The outlier suppression of GN in turn keeps 4-bit NVFP4 serving within one point of FP8 accuracy. A simple yet effective Think-Fusion recipe further lets users switch between thinking and non-thinking modes within a single unified model. Extensive evaluations show that A.X K2 performs competitively against strong open-weight baselines, matching or exceeding them on math and Korean-language benchmarks.

## 2. 方法论：核心思想与关键技术

### 2.1 模型架构（Gated Transformer Blocks）

- **整体配置**：688B 总参数、33B 激活参数，61 层 Transformer（首层为稠密 FFN，其余 60 层为 MoE）；256 个路由专家（分组 top-8，每组 4 个）、8 个共享专家；64 个注意力头；hidden size 7168；词表 163,840（字节级 BPE，覆盖英/韩/中/日/西）；原生上下文 128K，经 YaRN 可扩展至 256K。
- **稀疏门控注意力（SGA）**：结合两个组件——
  1. **门控注意力**：在 MLA（多隐头潜在注意力）输出上施加 head-specific 输出门 \(G = \sigma(W_g q_{\text{latent}})\)，增加非线性、抑制 attention sinks、改善损失收敛；
  2. **稀疏注意力**：沿用 DeepSeek 式轻量 indexer，为每个 query 选取 top-2048 个位置（固定预算），在 128K 上下文时仅读取 1.6% 的 KV 位置，使注意力计算近似线性扩展。
- **稀疏索引器预热（sparse warmup）**：与 DeepSeek-V3.2/GLM-5 先对稠密注意力分布做预热不同，A.X K2 直接针对自己的稀疏 top-k 选择优化 indexer，大幅降低适应成本，而长上下文质量几乎无损（LongBench v1：62.80 → 62.99）。
- **门控归一化（GN）**：RMSNorm 后增加输入依赖门控操作，抑制隐藏状态中的 massive activations（异常值），既稳定训练，又使 NVFP4 4-bit 量化的精度损失控制在 1 个百分点以内。

### 2.2 预训练方法

- **数据管线**：在 A.X K1 基础上更新的多阶段数据管线——英、韩、中、日、西多语网络文本，代码，STEM，合成推理/智能体数据；引入 Nemotron-CC v2.1、Nemotron-Pretraining-Code-v2、FineWeb2 等更新语料；大幅增加智能体轨迹与仓库级代码数据。
- **质量过滤与课程学习**：约 16.2T 候选 token 中，按教育价值 + 难度两轴打分，以“阶段依赖”方式逐步收紧阈值；将低质量一般网络数据放在早期（Stage 1），高难度推理/智能体数据集中在后期（Stage 2/3），构成难度递增课程。
- **三阶段预训练**：
  - Stage 1：6.4T token、序列长度 4K，WSD 的 warmup + stable 阶段；
  - Stage 2：1.4T token、4K 长度，高难度数据为主，开始 cosine decay；
  - Stage 3：长上下文扩展——3A 到 32K（约 0.22T token），3B 到 128K（约 0.14T token，采用 ABF 调整 RoPE base 至 10⁶），3C 为 SGA 稀疏注意力适应（与 3B 共享数据混合）。
- **WSD 学习率**：峰值 2.2×10⁻⁴，batch size 约 16,384 序列（≈64M token/步），batch size 前期线性 ramp-up，长上下文阶段按序列数降低以保持 token/步不变。
- **MoE 负载均衡**：采用全局辅助损失（而非 A.X K1 的序列级损失）+ 可学习 expert-bias 项，在全局 batch 上度量 MaxVio；训练过程中逐步退火。
- **Checkpoint Merging**：对最后 6 个 checkpoint（间隔约 1.6B token）做加权平均（1−√· 加权方案），获得更平坦、更鲁棒的最终解。

### 2.3 后训练：Think-Fusion SFT + 多阶段 RL

- **Think-Fusion SFT**：构造“成对的 thinking / non-thinking 响应”数据集（thinking:non-thinking token 比约为 13:1），用显式控制 token 学习模式切换，避免双轨训练中的模式混淆；先做 indexer SFT（0.4M 样本，同时更新 indexer），再固定 indexer 做主 SFT（约 8.6M 样本）。
- **多阶段 RL**：在各阶段统一联合优化指令跟随、人类偏好、智能体工具使用、安全四个能力；奖励设计上——指令跟随用规则可验证奖励；人类偏好用 LLM-as-judge（六领域分类 + 四维评分）；工具调用用可验证奖励 + gated judge（先验证结构化工具调用，再送 judge）；安全数据用九维安全评分。采用 CISPO + GDPO，无 KL penalty，16 个 rollout/prompt，约 100K prompts。
- **系统工程**：RL 中训练端与 rollout 端统一为 blockwise FP8（而非 MXFP8，因 vLLM 不支持 MX），避免 reward collapse；rollout 采用 TP1/DP8 数据并行异步流水线（而非 TP8/DP1），在 131K 输入下相对吞吐提升 1.6 倍。

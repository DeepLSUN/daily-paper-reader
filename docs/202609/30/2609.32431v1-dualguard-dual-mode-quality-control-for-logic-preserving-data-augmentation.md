## 摘要
大型语言模型为大规模生成用于逻辑推理的增强数据提供了一种实用途径，但更大的生成量并不能保证语义、标签或逻辑上的可靠性。已有工作通过生成约束、候选验证、过滤以及基于反馈的修订来提升生成质量；然而，一旦获得质量判断，决定候选样本应被保留、过滤还是修复仍然是一个重要的控制问题。我们提出 DualGuard，一个面向逻辑保持数据增强的双模式质量控制框架。第一种模式利用当前实例和候选批次进行选择性保留、过滤、归因和定向反馈。第二种模式在逐样本诊断与归因的基础上，累积增强动作的跨实例执行记录，将新的执行结果与每个动作自身的历史行为进行比较，并支持回顾性异常检查、定向回滚和有界修复。两种模式共享语义验证，并在有可靠逻辑形式可用时额外使用符号验证。在 Two-Stage Transfer 设置下的七个下游任务中，DualGuard 在五个任务上取得最高准确率，并在全部七个任务上优于无数据增强的 BERT 基线。受控消融实验进一步表明，Memory、Z3 和历史感知异常控制具有互补作用。

## Abstract
Large language models provide a practical way to generate augmented data for logical reasoning at scale, but a larger generation volume does not guarantee semantic, label, or logical reliability. Existing work has improved generation quality through generation constraints, candidate validation, filtering, and feedback-based revision; however, once a quality judgment is available, deciding whether a candidate should be retained, filtered, or repaired remains an important control problem. We propose DualGuard, a dual-mode quality-control framework for logic-preserving data augmentation. The first mode uses the current instance and candidate batch for selective retention, filtering, attribution, and targeted feedback. The second mode accumulates cross-instance execution records of augmentation actions on top of per-sample diagnosis and attribution, compares new executions against each action's own historical behavior, and supports retrospective anomaly inspection, targeted rollback, and bounded repair. Both modes share semantic verification and additionally use symbolic verification when a reliable logical form is available. Across seven downstream tasks in the Two-Stage Transfer setting, DualGuard achieves the highest Accuracy on five tasks and outperforms the no-augmentation BERT baseline on all seven. Controlled ablations further show complementary roles for Memory, Z3, and history-aware anomaly control.

- **已有工作的不足**：现有方法通过生成约束、候选验证、过滤、反馈式修订（如逻辑驱动约束、多智能体生成+标签验证+反思）来提升质量，但**“获得质量判断之后如何处置候选样本”**——保留、过滤还是修复——仍是一个未被充分解决的控制问题。
- **论文定位**：DualGuard 聚焦于**验证之后的后生成控制决策**，区分两类信息源：
  - 当前实例与候选批次的状态（支持选择性保留、过滤、可诊断问题的处理）；
  - 增强动作的跨实例历史行为（支持异常检测、定向回滚与有界修复）。
- **整体含义**：将质量判断转化为可回滚、可审计、可复用的控制流程，为逻辑保持的数据增强提供系统化的质量控制方案。

## 2. 方法论

### 2.1 核心思想
- 提出**双模式质量控制框架**，两种模式为针对不同数据集/任务的**预配置替代方案**，而非必须顺序执行的两个阶段：
  - **Difficult Mode（当前批次控制）**：仅依赖当前实例与候选批次。
  - **Variance Mode（历史感知控制）**：在逐样本诊断与归因基础上，额外利用跨实例历史行为。
- 两种模式**共享生成与验证组件**。

### 2.2 共享候选验证（关键技术细节）
- 先判断输入实例能否可靠形式化：ρ(x)=1 表示可可靠形式化，ρ(x)=0 表示不可。
- **语义 Solver**：检查标签一致性、语义保持、实体对应、极性、逻辑方向、表达完整性，输出 V_sem(c)∈{0,1}。
- **Z3 符号验证**：仅当 ρ(x)=1 时启用，检查必须保持的逻辑关系，输出 V_Z3(c)∈{0,1}。
- 基础有效性公式：
  - **V(c) = V_sem(c) × [(1−ρ(x)) + ρ(x)·V_Z3(c)]**
  - 即：不可形式化时 V(c)=V_sem(c)；可形式化时 V(c)=V_sem(c)·V_Z3(c)。
- **符号验证失败的候选立即丢弃**，不进入后续归因或修复；Z3 是条件启用的符号安全阀，语义 Solver 对所有到达该阶段的候选都起作用。

### 2.3 Difficult Mode（当前批次质量控制）
- 候选评分（个体层面）：
  - **s_i = f_i − P_fluency − P_risk − P_lowvalue − P_confusion**
  - 流畅度惩罚：P_fluency = max(0, τ_f − f_i)
  - 风险惩罚：P_risk = λ_risk·H_i；低价值改写惩罚：P_lowvalue = λ_low·L_i
  - 困惑度惩罚（只惩罚超出允许范围的部分）：P_confusion = λ_conf·max(0, d_i − τ_conf)
- 批次统计：计算保留候选的均值 s̄_t 与总体标准差 σ_s,t，并考虑有效候选比例、流畅度波动与风险信息；**批次统计仅作为辅助信号，σ_s,t 大本身不构成逻辑错误证据**。
- 决策与保留：G_D(c_i, C_t)∈{0,1}；保留集 A_t = {c_i∈C_t : V(c_i)=1, G_D(c_i,C_t)=1}；拒绝集 F_t = C_t \ A_t。
- **归因与补充**：对带明确诊断的失败候选进行归因，判断问题来源（逻辑上下文构建、动作选择、Builder 生成等可修复节点），路由定向反馈；**仅补充缺失数量的候选**，已归因的过滤候选不再重复处理；最后进行 End-stage 批次复审。

### 2.4 Variance Mode（历史感知质量控制）
- 按逻辑类型检索动作级 **Skill Memory**，动作可复用、新建或按配置探索。
- 奖励函数：**r(c) = α·C(c) − P_novelty(c) − P_fluency(c)**
  - 流畅度不足惩罚：P_fluency(c) = max(0, τ_f − F(c))
  - 新颖性惩罚：P_novelty(c) = λ_n(w_s·S_style + w_l·S_logic + w_c·S_combo) + λ_a·log(1+N_a)
    - S_style 用本地文本编码器嵌入风格-标签描述计算；S_logic 由逻辑标签重叠得到；S_combo 记录完整风格-逻辑模式是否已出现；N_a 为动作历史复用次数。
    - 复用动作时，排除该动作自身历史产生的记录作为相似度参考，复用频率通过 N_a 单独惩罚。
- 每个动作在逻辑类型内维护长度 W 的**滑动窗口**，计算历史均值 μ_a 与标准差 σ_a。
- 动态下界：**L_a = μ_a − k_low·σ_a**；当 **r_t < L_a** 时标记为“历史低异常”。
- **异常判定需累积足够证据**：I_a = I[n ≥ n_min]·I[σ_a ≥ σ_min]，新动作历史不足时只累积不判定。
- 异常触发后：结合当前奖励、历史统计与已有诊断归因，定位需处理的节点，在**有界修复预算**下执行定向回滚与修复；修复后候选重新进入共享验证，必须再次满足逻辑、语义与质量要求才被接受。
- 滑动窗口还支持**回顾性检查**，可重新查看历史记录的诊断信息。

## 6. 主要结论与发现

- **Two-Stage Transfer**：DualGuard 在 **FOILO、ProofWriter、LogicQA、ReClor、LogDed 五个任务取得最高 Accuracy**，并在**全部七个任务上超过无增强 BERT 基线**；相对 BERT，LogDed、ProofWriter、FOILO 的增益分别为 8.34、8.15、5.58 个百分点，七任务平均增益 **4.75 个百分点**。
- **任务依赖性**：CoTAM 在 RTE、FlipDA 在 CB 上仍最强，说明增强收益依赖任务，不存在单一策略全面占优。
- **Direct Augmentation**：DualGuard 在 ProofWriter（54.67%）和 CB（79.17%）排名第一，FOILO 上与 AttrPrompt、FlipDA 三方并列（44.67%），RTE 上（57.04%）优于 BERT、AugGPT、AttrPrompt 但低于 CoTAM 和 FlipDA。
- **消融结论**：Full 在全部七个任务上优于 w/o Variance，平均下降 2.74 个百分点（最大在 CB、ProofWriter、RTE）；去掉 Memory 或 Z3 也在多数任务上降低准确率，平均下降分别为 2.07 和 2.37 个百分点，表明**跨实例经验、条件符号验证与动作级历史异常控制具有互补作用**。由于没有独立的 w/o Difficult Mode 变体，**未将 Accuracy 增益单独归因于 Difficult Mode**。
- **生成质量**：125 个样本全部通过有效性、逻辑/标签正确性、变换有效性检查；语言质量均值 4.88–4.96/5，有意义差异 3.35–4.10/5。
- **过程行为**：Difficult Mode 中，8 个低奖励离群点的逻辑通过率为 50.00%、高风险率 50.00%，而归因引导补充候选分别为 91.43% 和 8.57%，最终接受候选逻辑通过率 100%、高风险率 0%；Variance Mode 30 次受控试验中 6 次出现历史低奖励离群，3 次严格修复成功（修复候选奖励超过被检测候选且通过全部检查），1 次修复有效但未提升奖励。

## 7. 优点

- **问题定位精准**：明确聚焦“质量判断之后如何控制”这一被忽视的环节，将后验证处理细化为保留、过滤与修复三类决策。
- **双模式设计灵活**：Difficult Mode 适用于当前批次控制，Variance Mode 利用跨实例历史，二者按任务预配置，覆盖不同数据条件。
- **归因驱动的定向修复**：不是重启整个生成流程，而是结合候选状态、验证结果、质量分数与诊断信号定位最可能的失败节点，仅向相关处理节点路由纠正信息，成本更可控。
- **跨实例经验记忆**：持续存储增强动作的执行结果、奖励与诊断，构建动作特定的动态参考，支持回顾性异常检查与有界修复。
- **验证机制分层合理**：语义验证对所有候选生效，Z3 符号验证按可形式化性条件启用，避免不可靠形式化污染决策。
- **实验公平性较好**：统一数据划分、随机种子、生成器、温度与预算；外部测试数据不参与调参；消融与过程分析提供多维证据。

## 8. 不足与局限

- **计算与延迟开销**：多候选生成、共享验证、归因、补充及必要时修复与再验证，相比单次生成式增强引入额外推理与验证成本；候选越多或触发补充/修复时，开销与延迟进一步上升。
- **依赖自然语言形式化质量**：条件符号验证的有效性取决于实例能否被可靠转换为逻辑表示；语言复杂性与语义歧义仍会影响形式化准确性，不可形式化时只能退回语义验证路径。

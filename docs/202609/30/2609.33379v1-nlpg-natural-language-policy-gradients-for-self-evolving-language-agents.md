## 摘要
大型语言模型智能体日益依赖复合程序进行检索、工具使用、推理和验证，然而其失败往往源于局部过程决策。现有的强化学习和提示优化方法通常依赖标量奖励或反复修改整个提示，因而难以在保持智能体冻结的同时捕获和复用过程性改进。为解决这一问题，我们提出自然语言策略梯度（NLPG），一种外部策略记忆方法，可在不改变固定智能体的模型参数或程序结构的情况下对其进行改进。NLPG 诊断执行轨迹，将下游反馈沿模块图反向传播，并将反复出现的失败转化为路由局部的自然语言修正，这些修正被聚合成有界的策略更新，用于后续执行。在涵盖记忆、推理、指令遵循和证据验证的六个基准上，NLPG 在每个基准上也比所列最强基线平均高出 8.71 个百分点。这些结果表明，经过评估的过程经验可以转化为局部且可解释的策略更新，从而实现冻结智能体的持续改进。

## Abstract
Large language model agents increasingly rely on compound programs for retrieval, tool use, reasoning, and verification, yet their failures often arise from local procedural decisions. Existing reinforcement-learning and prompt-optimization approaches typically rely on scalar rewards or repeatedly modify entire prompts, making it difficult to capture and reuse procedural improvements while preserving a frozen agent. To address this problem, We propose Natural-Language Policy Gradients (NLPG), an external policy-memory method for improving a fixed agent without changing its model parameters or program structure. NLPG diagnoses execution traces, propagates downstream feedback backward through the module graph, and converts recurring failures into route-local natural-language corrections that are aggregated into bounded policy updates for subsequent executions. Across six benchmarks covering memory, reasoning, instruction following, and evidence verification, NLPG also outperforms the strongest listed baseline for each benchmark by 8.71 percentage points on average. These results provide evidence that evaluated procedural experience can be transformed into local and interpretable policy updates, enabling continual improvement of frozen agents.

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想

- 将“策略执行”与“策略改进”分离：
  - 执行阶段：每个模块从当前策略记忆 `M_t` 中检索其路由对应的指令并注入调用上下文。
  - 改进阶段：评估后，沿执行模块依赖图反向传播反馈，诊断失败，生成路由局部的自然语言修正，跨执行聚合、过滤、排序，形成下一轮策略 `M_{t+1}`。
- 模型参数 `θ`、程序结构、检索索引、评估器全程固定；仅外部策略记忆可更新。

### 2.2 关键概念与符号

- **程序模块** `b`：可调用单元，如检索、工具调用、验证、结果解析。
- **策略记忆** `M_t = {M^a_t}`：按任务类别或程序模块（route）索引，存储短自然语言过程指令，而非任务参考答案。
- **执行轨迹** `τ_i = (x_i, {o_{i,j}}, y_i)`：记录输入、各模块显式输出与最终响应，不含隐藏推理。
- **失败**：可归因于一个或多个相关模块的执行偏差，用失败签名 `s` 表示。
- **自演化问题**：`M_{t+1} = Update(M_t, {(τ_i, z_i)})`，其中 `M_t` 在评估轮内冻结，`M_{t+1}` 仅在下轮加载。

### 2.3 策略路由、选择与注入

- 对模块路由任务，`a_{i,j}` 表示第 `j` 步调用的模块；对任务族路由任务，表示任务族。
- 候选策略池：
  - `C_{t,i,j} = Dedup(M^{a_{i,j}}_t ∪ M^gen_t)`，去重后合并路由特定与共享指令。
  - 按历史优先级分数排序，取 `TopK`：`P_{t,i,j} = TopK_{w_t}(C_{t,i,j}, K)`。
- 策略注入：`c_{i,j}(M_t) = c^base_{i,j} ∥ Format(P_{t,i,j})`，即把有界策略附录追加到原始模块上下文，不改变原程序顺序。
- 每轮评估中活跃策略版本固定不变。

### 2.4 自然语言策略梯度

- **失败诊断**：`D_B(τ_i, z_i) = (α_i, S_i, e_i)`，其中 `α_i` 为失败权重（正确为 0，失败为 1），`S_i` 为诊断出的执行偏差类型集合，`e_i` 为执行标识符，用于统计同一修正的跨执行支持。
- **反向传播**：受 TextGrad 启发，沿观察到的模块依赖图按逆拓扑序传播任务级语言反馈 `L_i`。
  - 终端模块：下游反馈初始化为任务级评估。
  - 中间模块：`F^down_{i,j}` 收集直接后继返回的反馈；critic 结合当前模块输入、输出与上下文，生成局部文本修正，并只向前驱转发相关反馈。
- **输出级语言梯度**：
  - `∂text L_i / ∂y_{i,j} ≝ ∇LLM(o_{i,j}, F^down_{i,j})`
  - `∂text` 表示语言级反馈变换，而非数值导数；`∇LLM` 为 critic 操作。
- **路由级语言梯度**：
  - `gtext_{i,j} ≡ ∂text L_i / ∂r_{i,j} ≝ ∇LLM(M^{a_{i,j}}_t, c_{i,j}, o_{i,j}, F^down_{i,j})`
  - 将所需改变归因到产生该模块输出的路由策略，沿观察到的依赖关系路由修正。
- 传播在分支无进一步反馈分配时终止，修正只沿执行中观察到的依赖传播。

### 2.5 跨执行聚合与策略更新

- 修正按**路由 `a`、失败类型 `s`、归一化修正文本 `u`** 分组。
- 每组代表梯度按失败权重降序、再按 critic 置信度选择。
- 保留评分：
  - `w_{a,s,u} = |E_{a,s,u}| / max(N_a, |E_a|, 1) × α_i × κ_{i,j}`
  - 三个因子分别代表：跨执行支持、失败权重、critic 置信度。
- 优化器把分组修正与诊断转写为简洁的路由特定指令；经**安全过滤**（去空、去重、去过度具体、去过长、去标签泄漏、去不安全）后，与当前记忆合并为候选后继 `cM_{t+1}`。
- **配对 held-out 验证**：只有满足增益与回归约束的候选才被提升；否则保留 `M_t`。
- 整体流程：`评估执行 → LLM 诊断 → 模块局部修正 → 跨执行整合 → 策略验证`。

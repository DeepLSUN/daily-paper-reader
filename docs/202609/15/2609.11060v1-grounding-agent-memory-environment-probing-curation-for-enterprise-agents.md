## 摘要
持久记忆正进入面向生产的智能体平台，以帮助长时程智能体跨会话积累经验。然而，仅局限于已完成轨迹的任务后策展智能体可能会保留错误、对部分证据过度泛化或保留过时知识。我们提出环境探测式策展，这是一种与部署兼容的扩展，为已有的异步策展智能体赋予最小权限、只读的世界工具，以检查、界定范围并刷新候选记忆。它无需重新训练模型，且不改变任务智能体、检索器、记忆表示和生产写入权限。在基于其 SDK 构建的类生产 GitHub Copilot（GHCP）测试框架中，我们在 CLBench 数据库探索和 90 个改编的 APEX 管理咨询任务上比较了无状态执行、完整上下文学习、GHCP + Mem 以及 GHCP + Mem（w/ Env Probing）。在 CLBench 上，探测将通过率从 39% 提高到 73%，将通过率折算奖励从 8.60 提高到 22.60，同时将每个问题的查询次数从 8.8 降至 4.7，并将任务智能体成本从 $3.38 降至 $1.68。在六个 APEX 世界中，所有 18 项记忆与基线的平均奖励比较均为正，任务智能体工具调用下降 16–75%；探测在五个世界中给出了最佳的任务智能体每美元奖励增益。在 Sonnet 4.6 和 Opus 4.7 上，探测也均比 GHCP + Mem 获得更高的平均奖励，且没有模式漂移。因此，环境探测将现有的智能体记忆策展转变为一种环境知情、可审计的过程，同时保留紧凑的任务时接口。

## Abstract
Persistent memory is entering production-oriented agent platforms to help long-horizon agents accumulate experience across sessions. Yet a post-task curator agent restricted to completed trajectories can preserve errors, overgeneralize partial evidence, or retain stale knowledge. We introduce environment-probing curation, a deployment-compatible extension that gives an existing asynchronous curator agent least-privilege, read-only world tools to check, scope, and refresh candidate memories. It requires no model retraining and leaves the task agent, retriever, memory representation, and production write authority unchanged. In a production-like GitHub Copilot (GHCP) harness built on its SDK, we compare stateless execution, full in-context learning, GHCP + Mem, and GHCP + Mem (w/ Env Probing) on CLBench database exploration and 90 adapted APEX management-consulting tasks. On CLBench, probing raises pass rate from 39% to 73% and pass-discounted reward from 8.60 to 22.60 while reducing queries from 8.8 to 4.7 per question and task-agent cost from \$3.38 to \$1.68. Across six APEX worlds, all 18 memory-versus-baseline mean reward comparisons are positive and task-agent tool calls fall by 16--75%; probing gives the best task-agent reward gain per dollar in five worlds. Probing also attains higher mean reward than GHCP + Mem on both Sonnet 4.6 and Opus 4.7 without schema drift. Environment probing therefore turns existing agent-memory curation into an environment-informed, auditable process while preserving a compact task-time interface.

# 论文总结：Grounding Agent Memory: Environment-Probing Curation for Enterprise Agents

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体正从单次任务执行转向跨会话的持续工作（如代码库演进、企业数据分析、客户支持）。成功的关键在于积累反馈，尤其是对跨任务共享的**潜在环境结构**的知识。然而，无状态执行会在每次会话边界丢弃轨迹、观察、发现和失误，使经验无法改善后续工作。
- **已有方案与不足**：外部记忆（创建/更新/召回）已成为主流补救手段，Mem0、Claude Managed Agents、ACE、ReasoningBank、ReMe 等系统均支持任务后策展。但这些策展智能体几乎都受限于**已完成轨迹 + 评分 + 使用信号**这一回顾性证据边界。
- **核心问题**：一条轨迹只是对环境的**单一、局部且常含错误**的观察。由此产生的记忆可能：(i) 记住实例答案而非程序；(ii) 继承低效路径；(iii) 断言无法验证的适用范围；(iv) 在未访问区域留下盲点；(v) 随环境漂移而过时。若把验证推迟到任务时，响应智能体不得不花费稀缺的工具调用重新核验不确定的记忆。
- **整体含义**：论文提出**环境探测式策展**，将记忆策展从"被动回顾"转为"环境知情、可审计"的过程，在不增加任务期能力的前提下提升写入时证据质量，对企业级持久记忆部署具有直接兼容性。

## 2. 方法论

### 2.1 核心思想

- 在任务关闭后、下一任务揭示前，为**异步策展智能体**赋予**最小权限、只读**的世界工具（连接器或 MCP 工具子集），使其能够**检查、界定范围、刷新**候选记忆后再写入。
- 不重训模型，不改动任务智能体、检索器、记忆表示和生产写入权限；改进被隔离到**写入时证据质量**这一维度。
- 若不存在安全只读表面，则回退到纯轨迹策展。

### 2.2 在线设置与任务智能体

- 任务流 $S = (S_1, \dots, S_N)$，环境状态 $E_i$ 可随 $E_{i+1} \sim \Delta(E_i)$ 演化，未来任务不可见。
- 任务智能体 $A_\theta$ 每次开启新会话，拥有环境工具 $TE_i$ 和只读的 `memory_read`；无记忆写入权限。
- 轨迹记为 $\tau_i = A_\theta(S_i; TE_i, R(\cdot, M_{i-1}))$，终端反馈 $g_i$ 仅在任务关闭后到达。

### 2.3 任务后记忆策展

- 策展智能体 $C_\phi$ 是独立 LLM 会话，接收已完成轨迹、终端反馈和相关既有记录，拥有四个记忆工具：`memory_read`、`memory_create`、`memory_update`、`memory_delete`，是唯一可变更 $M$ 的角色。
- **轨迹蒸馏**：$d_i = D_\psi(\tau_i)$，蒸馏器保留任务、检索到的记忆、关键观察、程序、未解决假设与答案，但**不接收终端反馈**，无记忆/环境工具，不能写记忆。$d_i$ 为主视图，$\tau_i$ 作为原始证据保留。
- **记录契约**：每条记录含 category（pattern/rule/trap/schema/policy/interaction）、confidence、applies_to（检索范围）、lemma（简洁可执行声明）、provenance、utility、usage 元数据。
- **写入规则**：存储可复用事实、程序、关系、工具约定和有范围的警告；绝不记忆任务答案、评分措辞或偶然数值；倾向于正向规则；不过度扩大范围；宁少而强。

### 2.4 环境探测式策展（propose–probe–commit）

- 仅两处提示词增量：`Aaccess`（在 Available Tools 下插入只读环境工具说明）与 `Averify`（在 Check 与 Reconcile 之间插入验证提示）。
- 策展智能体在提出候选记忆后，进行**有假设的定向只读探测**：
  - (i) 区分偶然答案与可复用关系；
  - (ii) 比较观察到的程序与更短路径；
  - (iii) 在另一数据切片上检验声称的关系；
  - (iv) 检查程序所需的前置条件；
  - (v) 检查轨迹遗漏的相关状态；
  - (vi) 怀疑漂移时重新查询当前环境。
- 探测不修改环境、不进入任务轨迹、不消耗任务智能体预算、不暴露未来任务或标签；在 CLBench 中探测表、连接键、编码或迁移后字段，在 APEX 中探测文件位置、文档相关性、工作簿内容或工具约定。

## 3. 实验设计

### 3.1 数据集 / 场景

- **CLBench（数据库探索）**：
  - 主实验为 40 题漂移日程，隐藏 SQLite schema，第 20 题后发生未宣布迁移（重命名表、拆分列、引入软删除），测试复用与过时记忆修复。
  - 跨模型研究使用规范的 30 题无漂移日程，固定 schema，分离稳定连接/编码验证与迁移恢复。
  - 格式陷阱包括美元 vs 美分、epoch 毫秒 vs ISO 时间戳、缩写列名。
- **改编 APEX（管理咨询）**：从 APEX Agents 480 个任务中选取管理咨询子集，按 (domain, world_id) 分组为 6 个共享文档世界、共 90 题（每世界 11–18 题），涉及 PDF/XLSX/DOCX/PPTX 发现、代码执行定量分析和 MCP 风格 Archipelago 工具。

### 3.2 对比方法

- GHCP（No Memory）：无状态执行。
- GHCP + Full ICL：前置所有历史轨迹的完整上下文学习。
- GHCP + Mem：索引式记忆，仅 `memory_read` 接口。
- GHCP + Mem (w/ Env Probing)：在前者基础上，仅给策展智能体增加只读环境工具和相应指令。

### 3.3 指标与协议

- **通过率折算奖励**：$r_i = p_i \left(1 - \frac{q_i}{B}\right)$，其中 $p_i$ 为严格通过（所有评分标准均通过才为 1），$q_i$ 为任务智能体工具调用数，CLBench 中 $B=15$，APEX 中 $B=100$。
- 报告通过率、工具调用、token、USD 成本；记忆管理调用不计入 $q_i$，任务智能体成本不含蒸馏/策展阶段。
- 主实验用 gpt-5.4（xhigh 推理努力）；无漂移研究用 Sonnet 4.6（high）和 Opus 4.7（xhigh）；嵌入使用 `intfloat/e5-base-v2`。
- CLBench 每配置 5 次配对种子运行；APEX 有状态配置 5 次、无状态 3 次；报告 95% Student-t 置信区间。

## 6. 主要结论与发现

- **CLBench 漂移日程**：通过率从 39% 升至 73%，总奖励从 8.60 升至 22.60，每题查询从 8.8 降至 4.7，任务智能体成本从 $3.38 降至 $1.68；记忆使智能体既更可能通过，又更少重复发现 schema/编码/约定。
- **无漂移跨模型**：Sonnet 4.6 上 GHCP + Mem 提升 +0.351、探测 +0.421；Opus 4.7 上分别 +0.252、+0.263；探测在两个模型上均取得最高平均奖励（0.748 和 0.721）。
- **APEX**：所有 18 项记忆 vs 基线奖励增益均为正；任务智能体工具调用下降 16–75%；探测在 6 个世界中的 5 个取得最佳每美元奖励增益；世界 941eba66 工具调用从 71.6 降至 17.7–19.3，成本从 $54.30 降至 $7–$9。
- **机制解释**：记忆摊销环境发现（保留可复用 schema、关系、文件地图和程序，而非完整交互历史）；探测使记录更可执行（从"警告/模糊映射"转为"可执行程序"）。探测优势在轨迹留下未解决连接、工作簿位置或程序时最大，在轨迹已支持可执行记录时增益有限。
- **定性证据**：轨迹策展记录"不要用 AVG(items_g2.prc_usd)…正确结果是 96.23"这类答案锚定警告；探测策展记录"Join items_g2 to taxn_g2 on ref_id；filter cat_lvl=1…"这类可执行程序；迁移后过时表名 `attrs_g3` 被更新为 `product_attributes_g3`。

## 7. 优点

- **部署兼容性强**：无需重训，不改变任务智能体、检索器、记忆表示和生产写入权限；仅给异步策展智能体增加最小权限只读工具，可复用现有连接器/MCP 和平台认证审计。
- **隔离性好**：改进被严格归因于写入时证据质量而非任务期能力，实验设计上任务智能体、提示词和环境工具在记忆条件下保持一致。
- **安全边界清晰**：探测只读、不修改环境、不进入任务轨迹、不消耗任务预算、不暴露未来任务或标签；无安全只读表面时优雅回退。
- **成本感知评估**：提出通过率折算奖励指标，同时报告 token、查询数和 USD 成本，避免只看准确率而忽视效率。
- **跨模型、跨基准验证**：在 3 个模型家族、2 个基准、6 个 APEX 世界上验证，结果一致性较好。
- **提示词增量极小**：探测仅增加两处提示块，工程落地成本低。

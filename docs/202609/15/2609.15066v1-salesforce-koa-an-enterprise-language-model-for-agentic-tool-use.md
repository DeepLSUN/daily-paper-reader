## 摘要
我们提出 Salesforce Koa，一个企业级语言模型，通过对开放权重 Nemotron-3-Super-120B 基础模型使用 Group Relative Policy Optimization（GRPO）进行强化学习后训练而构建。Salesforce Koa 使用公开数据和合成生成数据进行训练，不使用任何客户数据，以提升工具使用和智能体能力，同时保持强大的通用性能。其独特组件是一个从模拟到奖励的流水线，可将工作流规范扩展为以人物角色为条件的多轮任务，并以针对数据依赖型请求的成功工具使用为基础提供任务解决奖励。对于企业领域，这些规范用 Agent Script 编写，这是 Salesforce 用于构建 Agentforce 智能体的声明式语言；对于公共工具使用领域，我们直接合成工作流结构。同一套模拟与有依据奖励机制驱动了两者中的 GRPO。在公共工具使用、智能体推理和企业客户关系管理（CRM）基准上，Salesforce Koa 相比其开放权重基座模型有所提升，在多轮工具使用上提升最明显，并超越了强专有基线，但仍低于最强的前沿模型。这些结果表明，规范驱动的强化学习是将开放权重基础模型专门化用于企业智能体任务的一条实用路径。

## Abstract
We present Salesforce Koa, an enterprise language model built by post-training the open-weight Nemotron-3-Super-120B foundation model with reinforcement learning using Group Relative Policy Optimization (GRPO). Salesforce Koa is trained on public and synthetically generated data, with no customer data, to improve tool use and agentic capabilities while preserving strong general-purpose performance. Its distinctive component is a simulation-to-reward pipeline that expands workflow specifications into persona-conditioned multi-turn tasks with task-resolution rewards grounded in successful tool use for data-dependent requests. For enterprise domains, these specifications are written in Agent Script, Salesforce's declarative language for building Agentforce agents; for public tool-use domains, we synthesize the workflow structure directly. The same simulation and grounded-reward machinery drives GRPO across both. Across public tool-use, agentic-reasoning, and enterprise Customer Relationship Management (CRM) benchmarks, Salesforce Koa improves over its open-weight base, with the clearest gains on multi-turn tool use, and surpasses a strong proprietary baseline while remaining below the strongest frontier models. These results show that specification-driven reinforcement learning is a practical path to specializing open-weight foundation models for enterprise agentic tasks.

- **整体含义**：作者提出 Salesforce Koa，验证「规范驱动（spec-driven）的强化学习」是将开源基础模型专精化用于企业智能体任务的可行路径，且全程不使用任何客户数据。

## 2. 方法论

### 2.1 核心思想
- 以开源权重 **Nemotron-3-Super-120B** 为基础，使用 **GRPO** 进行强化学习后训练，仅使用公开数据与合成数据，不使用客户数据。
- 最具特色的组件是**规范驱动任务构建（specification-driven task construction）**：将声明式的企业智能体规范直接扩展为可执行、以人物角色为条件的多轮环境，奖励以工具使用成功为依据。
- 将**智能体编写（agent authoring）与模型后训练直接打通**：同一份规范既配置智能体，也结构化其 rollout 任务与解决标准。

### 2.2 规范驱动的环境与任务构建
- **企业领域**：用 **Agent Script**（Salesforce 为 Agentforce 智能体设计的声明式语言）编写工作流，规范定义 router、专用 subagent、类型化 action、工具作用域与自然语言推理指令。
- **静态抽取**：将规范编译为类型化工作流图，捕获每个工具的参数 schema、状态效应、路由条件、循环/终止配置，并实例化可执行环境（含工具可读写的模拟状态）。
- **公共工具领域**：无 Agent Script 时直接合成工作流结构，产出同样的类型化工作流图，与规范来源共享同一套模拟与奖励机制。
- **仿真流水线**：将规范扩展为 scenario- 与 persona- 条件化的会话——scenario 决定练习的工作流与用户需求，persona 条件化模拟客户行为。
- **RL 样本**：可从开场请求或生成的对话前缀开始，使策略暴露于不同深度的多轮决策；统一 schema 中 `agent_ref` 选择环境，其余字段提供初始 rollout 上下文。
- **多环境联合训练**：通过 per-row `agent_ref` 分发，单次运行即可加载全部环境；差分曝光通过 shuffle 前重复环境样本来实现。
- **NeMo Gym** 将每个样本作为在线 rollout 执行，实现编写/构建与 rollout 执行/策略优化的干净分离。

### 2.3 在线 rollout 与接地奖励
- 在模拟对话环境中，一个**冻结的辅助模型（helper）**扮演三个角色：客户模拟器、工具/函数模拟器、覆盖率评判器（coverage judge）；helper 是独立推理服务，从不被策略优化更新。
- **覆盖率奖励**：
  - 任务意图表示为编号子问题列表，评判器对整段对话为每个子问题给出 resolved/not-resolved 判定。
  - `cov = 已解决子问题数 / 子问题总数 ∈ [0,1]`，缺失或格式错误的判定默认视为未解决。
- **标量奖励（带重复调用门控）**：
  - 若发生连续重复工具调用，`R = 0`；否则 `R = cov`。
  - 评判器提示要求：任何需要客户/系统特定数据的子问题，只有在答案基于成功的相关工具调用时才可标记为已解决；通用常识性事实可无需工具解决。
- **确定性沙盒环境**：当预测动作复现参考最终状态时 `R = 1`，否则 `R = 0`（二元状态等价）。
- **环境关键性质**：
  - 工具列表是 **per-rollout** 而非全局；路由环境中可见集合进一步限制到当前激活的 subagent。
  - 任务意图在构建时确定性生成，与奖励直接相连。
  - persona 每对话采样一次并保持不变。
  - focus 系统提示不限于对话起点：路由环境每次 subagent 切换都会追加新的 focus/procedure 消息。
- **环境类型差异**：扁平客服（单智能体暴露所有工具）、路由客服（router + go_to_* 子智能体 + 切换时 focus 消息）、确定性工具沙盒（有状态工具、无模拟客户、二元状态等价评分）。

### 2.4 优化（GRPO）
- 目标：最大化期望轨迹奖励 `J(θ) = E_{x~D} E_{τ~πθ(·|x,env)}[R(τ)]`。
- 每个 prompt 采样一小组完整轨迹（colocated inference）；**动态采样**丢弃零方差组并补充至满 batch。
- **留一法基线**估计优势（无价值网络）：`b_i = (1/(G-1)) Σ_{j≠i} R_j`，`s_i = std{R_j: j≠i}`，优势 `A_i = clip((R_i - b_i)/(s_i + ε), -c, c)`（仅当 s_i > 0）；零方差组不做锐化。
- **单次 on-policy 更新**，策略比强制为 1，clip 项失效，无参考 KL 惩罚。
- **token 级截断重要性采样权重**修正训练/生成 log-prob 失配：`w_{i,t} = min(τ, exp[log π_train - log π_gen])`。
- 损失按 token 在轨迹内平均后再跨轨迹平均，防止长失败轨迹因长度主导梯度。
- **有效性约束**：工具调用或 thinking 语法畸形的轨迹，其问题 token 优势设为固定负值；超长或 log-prob 不一致的轨迹被 mask。
- **单步训练模式（Appendix F）**：针对「约束决策轮」——智能体无法仅靠工具解决、必须与用户交互（说明限制、请求缺失信息、澄清意图、管理预期）的关键轮次，构建单 prompt-响应对，奖励采用 `R_pivot = G(a_k) × f_match(held tool, recovery turn)`，其中 `G(a_k)` 为程序门控（无状态改变调用则 1，否则 0），`f_match` 评估恢复轮是否正确发出被暂扣工具。

## 6. 主要结论与发现

- Salesforce Koa 在公开工具使用、智能体推理与企业 CRM 基准上**全面超越其开源权重基座**，且**多轮工具使用提升最明显**。
- 在 Tau2Bench 上超过 **GPT-4.1 达 14.9 分**；在 BFCL 上显著高于 GPT-4.1；在 CRM Bench 上接近 Opus 4.8，但**仍低于最强前沿模型**。
- **规范驱动的 RL 是专精化开源基础模型用于企业智能体任务的实用路径**，且无需客户数据。
- **SFT vs RL**：从已 RL 后训练的基座出发，RL 大幅提升多轮工具使用（BFCL 多轮 54.12 → 59.50），SFT 在该项几乎无增益（54.12 → 53.25）；但 SFT 在单轮 CRM 任务上竞争力强（CRM Bench 平均 0.88 vs RL 0.86）。作者明确将此视为特定起点的观察而非通用结论。
- **奖励设计**：最终的门控覆盖率奖励在代理策略上趋势稳定向上，而惩罚二元奖励下降、加性/下限变体噪声大且趋平或下降。
- **规模依赖性稳定性**：同一最终奖励下，Super-120B 策略训练任务解决分数持续提升至约 0.65（约 200 步），而 Nano 代理在约 30 步达到峰值约 0.47 后崩溃至约 0.33——即使最优奖励设计在小规模下也不足以保证稳定。

## 7. 优点

- **规范驱动的闭环设计**：将 Agent Script 规范同时用于智能体配置、任务构建与奖励标准，直接打通 agent authoring 与模型后训练，概念优雅且工程可复用。
- **无需客户数据**：全程使用公开与合成数据，规避企业数据隐私与合规风险，落地可行性强。
- **接地奖励机制**：覆盖率评判器要求数据依赖型子问题必须基于成功工具调用才能算解决，配合重复调用门控，有效抑制奖励劫持。
- **单步训练模式**：针对「约束决策轮」的 PivotRL 式设计，用程序门控惩罚不可逆副作用、用后果分数评估恢复轮，精准解决企业智能体中「该说话而非调工具」的关键能力。
- **环境细节严谨**：per-rollout 工具列表、subagent 级作用域、切换时 focus 消息、persona 恒定等设计贴近真实企业场景。
- **评测独立性**：训练 helper 与离线评测 judge 分离，避免污染。
- **诚实的局限陈述**：明确承认基座已 RL 后训练、规模依赖性不稳定、仍落后前沿模型等限制。

## 8. 不足与局限

- **基座前提限制**：SFT-vs-RL 结论建立在「基座本身已是 RL 后训练模型」之上，作者自己指出从 pre-RL checkpoint 出发可能改变结论。
- **仍未达到前沿水平**：在 Tau2Bench 与 BFCL 上明显低于 Opus 4.8 与 GPT-5.5，企业高难度场景可用性待验证。
- **规模依赖性不稳定**：小规模（Nano-30B）上即使最优奖励也会训练崩溃，方法对模型规模敏感，可扩展性有隐忧。
- **奖励工程主要在代理上完成**：核心奖励消融在 Nano-30B 上进行，最终 120B 直接移植，未在 120B 上重复完整消融。
- **企业领域覆盖有限**：

（承接上文第 8 节）

- **企业领域覆盖有限**：训练环境仅覆盖 salesforce support、healthcare administration、real estate 与 workplace assistant 四类，且领域构造主要围绕 Agent Script 这一种规范语言展开。对 ERP、数据仓库、内部微服务等更广泛的企业工具生态，规范驱动流程能否同样落地尚未验证。
- **公共工具领域的「合成」代价**：在没有 Agent Script 的公共工具领域，工作流结构由直接合成产生，虽然与规范来源共享同一套模拟与奖励机制，但合成结构的真实性与多样性弱于真实企业规范，可能低估真实部署中的长尾复杂度。
- **奖励信号受 helper 能力上限制约**：覆盖率判定、工具模拟与客户模拟均由冻结的 Nano-30B helper 承担，helper 的评判上限即奖励信号的上限。论文未系统报告 helper 判定与独立 judge 或人工标注的一致性，helper 系统性偏差可能被策略利用。
- **任务意图的确定性生成**：子问题列表在构建时生成并与奖励直接绑定，虽然降低了奖励劫持风险，但也意味着奖励覆盖范围受限于构建器所能枚举的意图，可能遗漏对话中自然涌现的新需求。
- **评测基准的固有偏差**：Tau2Bench 使用 GPT-4.1 作为用户模拟器，模拟器自身的行为分布与偏好可能影响结论；pass^1 平均与四次试验的方差情况未充分展开。
- **算力门槛仍然较高**：RL 需 5 个 B200 节点（含 helper），SFT 预实验需 32 张 H200，对多数企业仍属高成本，论文也未给出更细粒度的训练时长、token 数与 FLOPs，复现成本难以预估。
- **复杂企业场景缺位**：未评估长时程跨会话记忆、多智能体协作、权限与合规策略执行、审计可追溯性等企业关键维度。
- **单步训练模式的适用范围**：PivotRL 式约束决策轮训练依赖可程序化的门控与「被暂扣工具」定义，对于无法清晰界定「正确恢复动作」的开放决策轮可能难以迁移。

## 9. 可复现性与开放问题

- **可复现性**：
  - 方法层面描述相对完整：规范抽取、环境类型、奖励公式、GRPO 变体（留一法基线、动态采样、token 级截断重要性采样、有效性约束）均有明确定义，理论上可复现核心机制。
  - 但关键资产——Agent Script 规范库、scenario/persona 生成器、NeMo Gym 资源配置、helper 提示模板——的公开程度有限；超参（如 clip 常数 c、截断阈值 τ、动态采样补批策略）的完整取值未在正文充分展开。
  - 训练数据全部为公开与合成数据，理论上规避了客户数据依赖，但合成数据的生成脚本与分布描述不足，复现者难以重建同等难度与覆盖度的任务集。
- **开放问题**：
  - 从 pre-RL（未经 RL 后训练）基座出发，规范驱动 RL 与 SFT 的相对收益如何？
  - 规模依赖性不稳定是优化器/奖励问题还是数据问题？是否存在与小模型匹配的奖励与超参以恢复稳定性？
  - 规范驱动的收益能否在非 Agent Script 的规范体系（如 OpenAPI、工具 JSON schema、BPMN）上复现？
  - helper 与策略的「能力差」如何影响训练动态？helper 若与策略同规模或更强，收益是否更大？
  - 覆盖率奖励是否会诱导策略「凑子问题」而非真正解决用户目标，如何进一步防劫持？

## 10. 对企业实践的启示

- **规范即训练资产**：企业已有的声明式智能体规范（路由、子智能体、类型化 action、作用域）可直接转化为训练环境与奖励标准，使「编写智能体」与「训练模型」形成同一工作流，显著降低专精化门槛。
- **无客户数据的可行性**：以公开与合成数据完成企业智能体专精化，为受合规约束的行业提供了可落地的技术路线。
- **接地奖励优于形态奖励**：要求数据依赖型子问题必须基于成功工具调用才计分，配合重复调用门控，是抑制奖励劫持的实用范式，可迁移至其他智能体 RL 场景。
- **「该说话而非调工具」值得单独训练**：约束决策轮是企业智能体区别于通用工具调用模型的关键能力，PivotRL 式单步训练提供了轻量、可程序化的实现思路。
- **规模不是万能药，但小规模确实更脆**：同一奖励在 120B 上稳定、在 30B 上崩溃，提示企业在小模型上部署时需更谨慎地做稳定性监控与早停。

## 11. 总体评价

Salesforce Koa 的核心贡献不在于提出全新的 RL 算法，而在于把**规范驱动的任务构建**与**接地奖励**组合成一条工程上可复用、合规上可接受的企业智能体专精化路径。其价值体现在三点：一是打通 agent authoring 与后训练，使规范成为「可执行、可评分」的一等公民；二是以覆盖率评判 + 重复调用门控 + 确定性沙盒，构造出较难被劫持的奖励体系；三是以 PivotRL 式单步训练补齐「澄清与恢复」这一企业场景短板。

从证据强度看，论文在三个公开基准上系统对比了前沿专有模型与自身基座，并做了奖励设计、SFT-vs-RL、规模依赖性等消融，论证较为扎实；同时作者对基座前提、规模不稳定、仍落后前沿模型等局限的陈述也较为诚实。主要保留意见在于：奖励工程的核心消融主要在 Nano-30B 代理上完成，120B 直接移植；企业领域与规范体系覆盖面有限；helper 质量对奖励上限的约束未被充分量化。

总体而言，Koa 更适合被理解为一篇**方法范式与工程实践**并重的论文：它证明了「用规范合成环境、用接地奖励训练、用公开数据完成企业专精化」这条路线可行且有效，同时诚实地暴露了规模敏感性与前沿差距等尚未解决的问题，为后续在企业智能体后训练方向的研究与落地提供了清晰基线。

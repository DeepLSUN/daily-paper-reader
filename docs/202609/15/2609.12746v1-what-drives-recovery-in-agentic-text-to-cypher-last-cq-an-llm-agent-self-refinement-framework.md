## 摘要
用于结构化查询生成的智能体式流水线正在迅速扩展，但尚不清楚循环中哪一部分带来了增益。我们将 LAST-CQ——一个五智能体、免训练、以执行为基础的 Text-to-Cypher 框架——用作可观测的测试平台，在 2,471 条实时数据库查询和覆盖三个供应商规模档位的六种骨干模型上运行了三个反事实实验。移除纠正会带来性能下降：相对于单遍系统，聚合 execution-BLEU 下降 3.1%；相对于无精炼反事实，下降 12.3%（对最弱骨干模型高达 80.7%）。用原始数据库错误字符串替代基于 schema 的、由 LLM 合成的反馈几乎不带来损失（朴素精确匹配 20.9% 对 19.9%；端到端 <0.2%；通过两个单侧检验在 ±0.075 set-F1 内等效）。将相同的调用预算用于并行采样会使质量下降 10–11%。真正有效的是检测失败并将其路由到重试，而不是反馈的精细程度或样本数量。LAST-CQ 本身能恢复 91.7% 在单遍生成中失败的查询，而首次即成功的查询仍然只消耗一次 LLM 调用。我们还表明，序列化结果上的 n-gram 重叠在两个方向上都不构成边界：它在 65.9% 的结果上相对于集合等价性给出过高评分，而相对于经评判的语义又给出过低评分。最后，我们以盲人类标注校准我们的 LLM 评判器，发现它高估了 9 个百分点。

## Abstract
Agentic pipelines for structured-query generation are rapidly expanding, but it is unclear which part of the loop produces the gain. We use LAST-CQ -- a five-agent, training-free, execution-grounded Text-to-Cypher framework -- as an instrumented testbed, running three counterfactuals over 2,471 live-database queries and six backbones spanning three vendor scale tiers. Removing correction is worth between 3.1% aggregate execution-BLEU against the single-pass system and 12.3% against a no-refinement counterfactual (up to 80.7% for the weakest backbone). Replacing schema-grounded, LLM-synthesised feedback with raw database error strings costs almost nothing (20.9% vs. 19.9% naive exact match; <0.2% end-to-end; equivalent within $\pm 0.075$ set-F1 by two one-sided tests). Spending the same call budget on parallel sampling degrades quality by 10-11%. What works is detecting failure and routing it to a retry, not the feedback sophistication or number of samples. LAST-CQ itself recovers 91.7% of queries that fail under single-pass generation, while a query that succeeds first time still costs exactly one LLM call. We also show that n-gram overlap on serialised results is not a bound in either direction: it over-scores against set equivalence on 65.9% of results while under-scoring against judged semantics. Finally, we calibrate our LLM judge against blind human labels and find it optimistic by 9 points.

## 1. 核心问题与整体含义

- **研究动机**：面向结构化查询生成的智能体式（agentic）流水线（验证→执行→观察失败→反馈→重生成）正快速扩张，但一个循环至少捆绑了三种机制：**失败检测（detection）、反馈合成（feedback synthesis）、重生成（re-generation）**。现有工作把增益笼统归因于"架构整体"，导致难以判断是否在昂贵组件上过度投资。
- **核心问题**：在 Agentic Text-to-Cypher 中，**到底是循环的哪一部分产生了增益？**
- **整体含义**：作者以 LAST-CQ 作为**可观测、组件可独立移除的测试平台**（而非又提出一个同类系统），用三组反事实实验把增益归因定位到具体机制。Text-to-Cypher 场景的特殊危害在于：**结构合法但语义错误的查询会静默返回误导性数据**，因此失败检测尤为关键。
- **贡献定位**：
  - 对"智能体式精炼家族"做消融，而非新增成员；
  - 提出可逐组件移除、带完整恢复率与成本核算的测试平台；
  - 提出面向智能体结构化查询生成的**顺序不变（order-invariant）评估体系**。

## 2. 方法论

### 2.1 核心思想
- 五智能体、**免训练（training-free）**、**以执行为基础（execution-grounded）** 的状态机式精炼框架；所有组件均为上下文提示（in-context prompting），不更新任何权重。
- 关键在于**每个机制可独立移除并可测量其损失**。

### 2.2 五个智能体与 LLM 调用成本
| 智能体 | 功能 | LLM 调用 |
|---|---|---|
| Schema Parsing (P) | 确定性解析器覆盖 8 种格式，输出归一化 schema | **0**（本基准上回退路径从未触发） |
| Generation (G) | 由问题 + schema 生成候选查询 | 1 |
| Validation (V) | 先 `EXPLAIN` 预执行校验，再 `LIMIT 1` 执行检测"合法但空结果"；通过则**立即返回、不调用模型**；失败时解析查询（1 次）并做确定性 schema 检查，若报违规再合成 grounded hints $H_{val}$（第 2 次） | 0–2 |
| Correction (C) | 依据当前 hints、schema $\Sigma$、纠正历史 $\Gamma$ 重写查询，并指示不得重复历史尝试 | 1 |
| Execution (E) | 执行查询；若为空则注入**固定常量** $H_{relax}$（6 条提示：大小写不敏感正则、子串匹配、`datetime()` 规范化、去掉过严标签、简化 RETURN），再路由回 Correction | **0** |

- **两类提示的本质差异**：$H_{val}$ 由 LLM 依确定性 schema 分析合成；$H_{relax}$ 是硬编码常量，无模型参与生成。

### 2.3 形式化框架
- 目标：给定问题 $Q$ 与 schema $\Sigma$，生成与 $\Sigma$ 一致、捕捉用户意图的查询 $\hat{Q}$；执行返回非空结果 $R\neq\varnothing$ 或失败 $E_{fail}$。
- 采用准则 $\text{Correct}(\hat{Q}) \iff E(\hat{Q})=R\neq\varnothing$，但明确承认**非空结果不等于语义正确**（§7 专门量化此偏差）。
- 精炼状态为 $(\hat{Q}, H, \Gamma, \Sigma)$，$\Gamma=(\hat{Q}_1,\dots,\hat{Q}_{t-1})$ 为尝试历史。
- 智能体映射：$P(\Sigma)\to\Sigma$，$G(Q,\Sigma)\to\hat{Q}$，$V(\hat{Q},\Sigma)\to(\text{valid},H_{val})$，$C(\hat{Q},H,\Gamma,\Sigma)\to\hat{Q}$，$E(\hat{Q})\to R\cup\{\varnothing,E_{fail}\}$。

### 2.4 算法流程（文字版）
- **内层循环**：交替 Validation 与 Correction，直至查询合法或耗尽 $N$ 次预算（本实验 $N=2$）。
- **外层循环**：执行查询；若结果为空，注入 $H_{relax}$，再精炼一次，最多 $M$ 轮（本实验 $M=1$，实现为一次性闩锁 latch，非可调计数）。
- **终止条件**：查询通过验证且 $R\neq\varnothing$；或验证预算耗尽；或松弛轮已触发（无论结果是否为空均返回）。
- **成本特性**：首次即成功的查询**恰好 1 次 LLM 调用**（与单遍生成相同）；每个失败循环最多追加 3 次调用（解析、提示合成、纠正）。53–97% 的查询无需纠正，开销集中在少数本会返回空结果的查询上；派生平均调用数约 1.1（Claude）至 2.5（Gemini Flash）。
- **两类真实轨迹示例**：(a) 生成查询误用 SQL 的 `YEAR()`，`EXPLAIN` 拒绝 → schema 检查确认无此函数 → LLM 合成提示给出 Cypher 等价写法；(b) 查询语法合法且通过 `EXPLAIN`，但因大小写/子串敏感返回空 → 注入 $H_{relax}$ 后按第 3 条提示直接改写为正则形式（**仅需固定字符串**）。

### 2.5 三组反事实
1. **移除纠正**：与单遍系统对比（下界）与 no-refinement 反事实对比（上界）。
2. **移除 schema 落地**：保留全部检测与路由机制（`EXPLAIN`、`LIMIT 1` 空检测、周期预算、历史 $\Gamma$、回到再验证的路由），仅把 $H_{val}$ 替换为**原始 Neo4j 错误字符串**（Naive Retry）。
3. **预算改投并行采样**：Best-of-3（$k=3$, $T=0.7$），选第一个非空结果。

## 3. 实验设计

### 3.1 数据与场景

- **该基准是当时唯一带实时数据库、支持执行式评估的公开 Text-to-Cypher 基准**。

### 3.2 骨干模型（6 个，跨三个供应商规模档）
- Small：GPT-4o-mini（~8B，第三方估计）、Gemini 1.5 Flash（未披露）
- Medium：Claude Sonnet 4（未披露）、Gemini 1.5 Pro（未披露）
- Large：GPT-4o（~200B，第三方估计）、DeepSeek-Chat（映射 DeepSeek-V3，671B MoE）
- 全部 $T=0$，全部仅上下文提示，无微调。

### 3.3 对比方法与条件
- **Baseline**：单遍生成，采用 Ozsoy et al. (2025) 的提示方法，**不使用其微调检查点**。
- **LAST-CQ（schema-only）**：仅 schema 访问，不能执行查询；$N=2$, $M=1$。
- **LAST-CQ+DB**：加入实时数据库；$N=2$ 验证周期 + $M=1$ 松弛轮。
- **Naive Retry**：同预算 $N=2$，仅反馈内容改为原始数据库错误串。
- **Best-of-3**：并行采样 3 个候选，选首个非空。
- **No-Refinement**：非独立运行，而是把进入纠正循环的查询重新计分为 0（上界反事实）。

### 3.4 指标体系（按不变性分类）
- **Execution Google-BLEU**：序列化结果上的 n-gram 重叠，**顺序敏感**，仅作可比性指标，不作为正确性证据。
- **Execution Exact Match**：规范化（排序行与键）后比较结果集，**顺序不变**。
- **Judge 语义准确率**：CORRECT / PARTIAL / INCORRECT，顺序不变。
- **集合类指标**：set-based P/R/F1/Jaccard、set equality，均顺序不变。
- 另报告 hit retrieval 与 recovery rate。
- **两处约定**：基准 GLEU 在"参考为空、输出非空"时给 1.0，而集合指标不给；作者对所有集合数字采用严格的集合论约定，并量化该影响。**"Aggregate" 指六个骨干的未加权平均**，而非按查询池化（池化恢复率为 93.8%，按模型平均为 91.7%）。

## 6. 主要结论与发现

### 6.1 框架有效性与恢复能力
- LAST-CQ+DB 相对 Baseline 平均 GLEU 提升 **+3.4%**（小模型 +6.5%，中模型 +2.8%，GPT-4o +2.9%）；Exact Match 提升较温和（+0.5%）。
- **Schema-only LAST-CQ 仅约 +1%，且对两个最强模型 GLEU 略有下降**——在 baseline 已很好时，缺乏执行证据的静态验证会触发不必要的重写。DeepSeek-Chat 下降 1.3%，归因于 schema 表示差异而非纠正漂移。
- **恢复率 91.7%**（按模型平均；池化 1,799/1,917 = **93.8%**），hit retrieval 提升 11.8%，成本为每查询 3.14–4.19 个 pipeline 阶段（多数不调用模型）。
- Gemini Flash 是信息量最大的离群点：baseline 半数查询失败，97.3% 被恢复，恢复后平均 GLEU 0.44 已比肩强模型的首次输出。行为在 16 个领域上稳定（CV=0.147）。

### 6.2 增益来源的归因（核心结论）
- **移除纠正**：相对 no-refinement 提升 **12.3%**（Gemini Flash 高达 **80.7%**），所有模型 $p<0.001$；相对单遍系统仅 **+3.1%**。真实值介于两界之间——强骨干偏下界，弱骨干偏上界。
- **移除 schema 落地**：几乎无损失。Naive Retry 精确匹配 19.9% vs LAST-CQ 20.9%；端到端 GLEU 0.4718 vs 0.4729（**<0.2%**）；TOST 在 **

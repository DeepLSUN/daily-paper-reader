## 摘要
深度搜索要求LLM智能体分解复杂查询、检索证据并合成有依据的答案，然而现有的ReAct式智能体存在两个局限：角色耦合，即单一策略必须同时处理规划、证据使用与合成；以及上下文累积，即不断增长的搜索历史会引入噪声并掩盖有用信息。为解决这些问题，我们提出IterSynth，一种角色解耦且基于摘要的范式，它在Planner（用于识别信息需求）与Synthesizer（用于将证据整合到不断演化的摘要状态中）之间交替进行。该设计将规划与合成分离，同时将摘要作为搜索的持久状态，从而减少能力耦合和上下文噪声。为了有效训练IterSynth，我们进一步提出用于强化学习的角色解耦策略优化（RDPO），它将终端结果奖励与轮级评分标准评估相结合，并计算角色特定的优势，以实现更精确的信用分配。在BrowseComp和Xbench-DS等五个长时程深度搜索基准上的实验表明，IterSynth-8B取得了50.7的平均分，超过此前最强的≤8B智能体+4.2%。此外，IterSynth可作为与模型无关的提示范式，在前沿专有模型上相较ReAct及类似提示范式带来显著的零样本提升。

## Abstract
Deep search requires LLM agents to decompose complex queries, search for evidence, and synthesize grounded answers, yet existing ReAct-style agents suffer from two limitations: role coupling, where one policy must handle planning, evidence use, and synthesis; and context accumulation, where growing search histories introduce noise and obscure useful information. To address these issues, we propose IterSynth, a role-decoupled and summary-based paradigm that alternates between a Planner for identifying information needs and a Synthesizer for integrating evidence into an evolving summary state. This design separates planning from synthesis while using the summary as the persistent state of search, reducing both capability coupling and context noise. To train IterSynth effectively, we further introduce Role-Decoupled Policy Optimization (RDPO) for reinforcement learning, which combines terminal outcome rewards with turn-level rubric evaluations and computes role-specific advantages for more precise credit assignment. Experiments on five long-horizon deep-search benchmarks such as BrowseComp and Xbench-DS show that IterSynth-8B achieves an average score of 50.7, surpassing the strongest prior $\leq$8B agent by +4.2\%. Moreover, IterSynth serves as a model-agnostic prompting paradigm, delivering substantial zero-shot gains over ReAct and similar prompting paradigms on frontier proprietary models.

# IterSynth 论文总结

## 1. 核心问题与研究动机

- **背景**：深度搜索（Deep Search）要求 LLM 智能体分解复杂查询、主动检索证据、跨文档推理并合成有依据的答案，是当前智能体研究的前沿应用。
- **现有 ReAct 式智能体的两大瓶颈**：
  - **角色耦合（Role Coupling）**：单一策略需同时承担规划、查询构造、证据过滤、缺口识别、冲突消解与最终合成等异质能力，易导致过早终止、冗余搜索和浅层证据使用。
  - **上下文累积（Context Accumulation）**：长时程搜索不断堆积检索段落、中间思考与部分结论，噪声掩盖有用信息，早期错误向后传播。论文附录 H 实测：即便有 64K 上下文，BrowseComp 上 ReAct 轨迹**超过 59% 在给出答案前就耗尽上下文**。
- **已有方案各自的不足**：
  - 多智能体方法（如 InfoFlow）降低认知负担，但增加推理成本、部署复杂度与协调开销；
  - 摘要式方法（如 IterResearch、AgentFold、ReSum）缓解上下文膨胀，但摘要多为外部辅助模块而非可学习的搜索策略组件，且规划与证据使用仍耦合。
- **核心诉求**：需要一种统一范式，在**单一共享策略**内分离规划与合成，同时让摘要更新成为搜索行为的显式、可优化部分。

## 2. 方法论

### 2.1 IterSynth：双角色迭代工作流

- **核心思想**：由同一 LLM（共享参数）交替扮演两个角色，仅通过角色提示、信息访问与动作约束区分，无需额外模型。
  - **Planner**：观察原始问题与当前全局摘要 $s_t=(q,M_t)$，识别未解决的信息需求，输出下一查询或终止给出最终答案。动作空间 $\{\text{search}(q_t),\ \text{answer}(\hat a)\}$。
  - **Synthesizer**：读取检索证据，过滤无关段落、提取有用发现、消解局部矛盾，更新全局摘要 $M_{t+1}$；**只能更新记忆**，不能发查询或给答案。
- **增强 MDP 形式化** $\langle S, D, E, T, R\rangle$：
  - Planner 子步：$d^P_t=[\text{Think}^P_t,a_t]\sim\pi_\theta(\cdot\mid s_t,\rho^P)$
  - Synthesizer 子步：$d^S_t=[\text{Think}^S_t,M_{t+1}]\sim\pi_\theta(\cdot\mid s_t,d^P_t,TR_t,\rho^S)$
  - 环境转移：$TR_t\sim E(\cdot\mid a_t)$，$s_{t+1}=T(\cdot)=(q,M_{t+1})$；若动作为 answer 则终止并跳过 Synthesizer。
  - 每轮上下文严格由 $(q,M_t)$ 重建，从而**结构性限制每轮上下文长度**。

### 2.2 训练配方：SFT → RDPO

- **冷启动 SFT**：
  - 用 Qwen3.5-397B-A17B 在实时搜索环境中 rollout 双角色轨迹；
  - 过滤管道：修复格式/工具调用错误、剔除幻觉推理、仅保留答案可验证正确的轨迹；
  - 得到约 **10K 条轨迹**，平均 **4.37 轮**，展开为约 **87.4K 角色条件样本**，对 Qwen3-8B 做全参数 SFT（仅对角色响应计损失，工具返回内容被 mask）。
- **RDPO（Role-Decoupled Policy Optimization）**：
  - 每个 query 执行 $G$ 个独立 rollout，每条轨迹含 $T_i$ 轮，形成多轮样本语料。
  - **复合奖励**（缓解终端奖励稀疏）：
    $$r^\rho_{i,t}=r_{acc,i}+\alpha\cdot r^\rho_{rubric,i,t}$$
    其中 $r_{acc,i}\in\{0,1\}$ 为终端正确性，广播到该轨迹所有轮；$r^\rho_{rubric,i,t}$ 为 LLM judge 按角色 rubric 打的轮级分；$\alpha$ 为缩放系数。
  - **角色解耦组优势**：将复合奖励分为 Planner / Synthesizer 两个角色池，池内归一化：
    $$R^\rho_q=\{r^\rho_{i,t}\},\quad A^\rho_{i,t}=\frac{r^\rho_{i,t}-\mu^\rho_q}{\sigma^\rho_q}$$
    解耦优势直接插入标准 GRPO 目标，无需修改算法。
- **Rubric 构建**：三阶段流水线——20 对正负轨迹对比采集 → 每对分别归纳 Planner/Synthesizer 判据 → 合并去重并封顶每角色 5 项；由 Gemini-2.5-flash-lite 在线评分。
- **工具环境**：Google 搜索（SerpAPI，返回 top-10 结果）+ 网页浏览器（Jina Reader 解析 HTML/PDF，Qwen3-8B 按子查询摘要）。训练时用离线缓存检索，评估时接实时工具。

## 摘要
基于大语言模型构建的智能体AI系统能够进行多步规划、使用外部工具、在记忆中保留信息，并与其他智能体协调。这些能力使其比静态语言模型更有用，但也引入了新的安全与运行风险。来自网站、电子邮件、文档和数据库的不可信内容可能进入与系统指令相同的上下文；持久记忆可能跨会话携带被污染的信息；对外部工具的访问可能将错误的模型响应转化为具有后果的现实世界行动。本文从五个相互关联的维度审视智能体AI的可信性：安全性与鲁棒性、对齐与人类监督、透明性与可审计性、隐私与数据治理，以及监管合规。它将关键失效模式，包括间接提示注入、后门触发器、目标错误泛化、记忆污染和跨会话数据泄露，组织为一个统一的分类体系。文章还考察主要缓解方法，如指令层级、上下文隔离、spotlighting、基于过程的监督、受限工具使用和隐私保护记忆，并区分有经验证据支持的技术与仍主要停留在概念层面的技术。在此基础上，我们提出可信智能体开发生命周期（TADL），一个涵盖规范、设计、训练、评估、部署和监控的六阶段框架。对于每个阶段，TADL识别相关的可信活动、预期证据和基于风险的决策门。尽管TADL尚未经过实证验证，但它为开发和评估更安全、更可问责的智能体系统提供了结构化基础。文章最后指出当前基准测试中的空白，并概述未来研究的优先事项。

## Abstract
Agentic AI systems built on large language models can plan over multiple steps, use external tools, retain information in memory, and coordinate with other agents. These capabilities make them more useful than static language models, but they also introduce new security and operational risks. Untrusted content from websites, emails, documents, and databases can enter the same context as system instructions; persistent memory can carry compromised information across sessions; and access to external tools can turn an incorrect model response into a consequential real-world action. This article reviews the trustworthiness of agentic AI across five interconnected dimensions: safety and robustness, alignment and human oversight, transparency and auditability, privacy and data governance, and regulatory compliance. It organizes key failure modes, including indirect prompt injection, backdoor triggers, goal misgeneralization, memory contamination, and cross-session data leakage, into a unified taxonomy. It also examines major mitigation approaches, such as instruction hierarchies, context isolation, spotlighting, process-based supervision, constrained tool use, and privacy-preserving memory, while distinguishing techniques supported by empirical evidence from those that remain largely conceptual. Building on this analysis, we introduce the Trustworthy Agent Development Lifecycle (TADL), a six-phase framework covering specification, design, training, evaluation, deployment, and monitoring. For each phase, TADL identifies relevant trust activities, expected evidence, and risk-based decision gates. Although TADL has not yet been empirically validated, it provides a structured foundation for developing and evaluating more secure and accountable agentic systems. The article concludes by identifying gaps in current benchmarks and outlining priorities for future research.

## 一、核心问题与整体含义（研究动机与背景）

- **范式转变**：AI 已从符号规则、统计学习、深度网络、预训练基础模型，演进到"能自行决定下一步做什么"的 LLM 智能体。智能体可多步规划、调用浏览器/代码解释器/数据库/API、与其他智能体通信，并执行影响外部世界的动作。
- **风险性质的改变**：聊天机器人的错误陈述通常可被人工核查纠正；但金融账户、临床流程、基础设施系统中的智能体，会把同一模型错误转化为**难以逆转的动作**，并可能在人类察觉前重复或复合该错误。
- **智能体区别于传统 ML 部署的五大特征**：
  - **时间跨度**：跨多步行动，错误会复合、目标会漂移；
  - **环境触达**：工具使用把攻击面与后果空间急剧放大；
  - **监督密度下降**：人类检查点之间智能体自主运行，失配或对抗操纵可能长期未被发现；
  - **多智能体动力学**：交互涌现行为无法由个体属性预测；
  - **开放性**：需面对设计者未预料的场景，安全属性必须泛化到训练分布之外。
- **研究碎片化问题**：安全、对齐、隐私、可解释性、治理各自为政；技术防御常不与部署控制并置，政策提案也常不反映智能体实际运行方式。本文主张把这五类可信性问题**放在一起**讨论。
- **能力—信任鸿沟（capability–trust gap）**：SWE-bench、WebArena、GAIA、AgentBench 等衡量"能做什么"，但不衡量对抗鲁棒性、长程对齐与实践可解释性；间接提示注入已在被评估的攻击场景中重定向工具型应用并泄露数据。

### 2）智能体定义与架构分解
- **工作定义**：基于 LLM 的系统，(1) 从人类委托方接收高层目标；(2) 自主分解为子任务；(3) 通过调用工具、其他智能体或外部 API 执行动作；(4) 观察结果并更新计划；(5) 迭代直至达成目标或触发停止条件，且**人类监督频率显著低于动作频率**。包含 ReAct、AutoGen、LangChain 类框架；排除单轮推理与无外部动作的思维链提示。
- **核心组件**：感知模块、规划与推理引擎、记忆系统、工具执行器、输出与动作接口、（多智能体）编排器——强调**组件间交互与模块本身同等重要**，因为失效常跨模块边界。
- **五类架构及其信任挑战**：单智能体 ReAct（目标漂移、工具误用、上下文长度限制）；分层多智能体（级联失效、权限混淆）；协作式对等智能体（错误观点趋同、评判者偏见）；人在环 HITL（审批疲劳、自动化偏见）；全自主流水线（所有失效模式被放大）。

### 3）失效模式分类体系（Table 3）
按五个信任维度组织，含作者自评的示意性严重度（C=Critical、H=High）：
- **安全性**：不安全工具使用（执行攻击者注入代码，C）、级联失效（云配置错误引发数据丢失，C）、资源耗尽（循环导致 1 万次意外 API 调用，H）。
- **对齐**：目标误泛化（为最大化"邮件回复数"而群发垃圾邮件，C）、规格博弈（未真正解决却标记完成，H）、指令误解（删除匹配"old"的在用文件，H）。
- **透明性**：推理不透明（贷款决策不可审计，H）、事后合理化（医疗报告中伪造引用，C）。
- **隐私**：数据泄露（PII 发给第三方搜索 API，H）、记忆污染（新会话召回上一位用户的健康数据，C）。
- **治理**：合规违规（投资建议缺少必要披露，H）、问责缺口（智能体致害后无可识别责任方，H）。

### 4）部署风险分级
- **Critical**（不可逆伤害）：医疗、关键基础设施、法律系统；
- **High**（重大但可恢复）：代码部署、HR 流程、金融账户管理；
- **Moderate**（后果有限）：内容生成、研究辅助、日程安排；
- **Low**（易于验证）：信息检索、人工审阅的草稿。
- 核心风险是**低层级的防护措施被带入 Critical/High 级部署**，往往因为部署速度快于风险评估。

### 5）缓解技术族及其证据强度（贯穿第 4–8 节）
- **提示注入防御**：指令层级（instruction hierarchy，位置/令牌标记可信指令，降低但不消除风险，且主要在静态 LLM 上评估）；上下文隔离（环境数据置于独立上下文、无核心指令寄存器写权限，有效但限制跨源信息整合、增加系统复杂度）；检测式防御（在 AgentDojo 中评估，效用依赖基准的攻击分布与误拦成本）；spotlighting（用特殊标记区分不可信数据，证据最强于受控测试，未证明在反复检索并变换恶意内容时的鲁棒性）；形式化动作约束（不依赖推理即限制动作集，保证强但牺牲灵活性）。
- **作者强调**：这些结果指向**架构性问题**——只要可信指令与不可信环境内容共处同一上下文，指令混淆风险就依然存在；各研究使用不同智能体、攻击集与成功标准，只能证明**部分风险降低**，而非通用解法。
- **对齐方法**：RLHF（偏好比较训练奖励模型，单轮效果强，但短交互奖励模型难泛化到长程、标注者人口偏差、奖励模型本身可被规格博弈）；Constitutional AI（显式规范原则，降低逐步人工标注依赖，但宪法在开放场景下的完备性与一致性困难）；价值学习（把人类价值视为潜变量推断，理论吸引力强但高维、文化可变的价值空间难以操作化）；过程奖励模型 PRM（评估中间推理步骤，提供更密集监督，证据主要来自数学推理，未证明能检测长轨迹中的目标偏离）；AI 辩论（人类评判论证而非任务本身，证据以理论为主）；递归奖励建模（分层奖励模型）。
- **鲁棒性**：弹性权重巩固（EWC，源于持续学习抗灾难性遗忘，用于 LLM 智能体适配属外推，不解决工具 API 漂移）；不确定性触发的人类升级。
- **多智能体安全**：密码学证明可确立消息来源但无法确立消息正确或对齐；形式化验证可保证指定协议属性但依赖完备规约的书写——各方法解决的是问题的不同部分，而非可互换的竞争方案。
- **形式化安全约束**：运行时执行动作不变量可提供强且可验证的保证，主要挑战是**规约完备性**；Dalrymple et al. 的"保证安全 AI"是研究框架而非已可用的混合架构。
- **透明性**：CoT 忠实性可变且有时很差（Turpin et al.、Lanham et al.）——但作者特别澄清，**这不否定 CoT 提示的性能收益**，二者是不同属性，不应混淆；扰动证据不等于有意欺骗。其他手段：结构化审计记录（工具调用、记忆访问、中间决策）、分层计划可视化、交互式计划编辑器、不确定性沟通（事实不确定性 vs 动作风险 vs 计划可靠性不可互换）、机制可解释性（安全关键回路的定向解释是近期可行方向）。
- **隐私**：提出"**智能体隐私面（agentic privacy surface）**"五个暴露点——输入上下文、工具交互、持久记忆、模型输出、多智能体通信；差分隐私提供形式化保证但引入隐私—效用权衡（智能体对上下文精度要求高，权衡更尖锐）；联邦学习减少原始训练数据集中收集，但被引工作未评估 LLM 智能体、智能体记忆或推理期工具调用。
- **治理**：EU AI Act（Reg. (EU) 2024/1689）分阶段适用；Digital Omnibus on AI（Reg. ### 6）TADL 框架（本文的核心贡献性提案）
- **定位声明**：TADL 是**作者提出的概念框架，尚未经实证验证**，不应被视为已确立的工程方法论；生命周期思想本身不新，其贡献是把智能体特有的威胁建模、委托层级文档、工具权限矩阵、记忆治理产物与风险相称的自主性限制整合进同一结构。
- **与既有框架的关系**：借鉴软件开发生命周期（Boehm 螺旋模型）与 NIST AI RMF，三点改编——① 面向 LLM 智能体及其特有失效模式（提示注入、目标误泛化、记忆攻击、多智能体级联的威胁建模）；② 引入**显式信任门（trust gates）**，使门禁标准可见可审计；③ 规定**自适应监督**机制，在部署期检测到行为异常时动态升级人类监督。与 Model Cards 的区别：后者面向模型层透明性，TADL 面向系统与部署层。
- **六阶段 + 五道门（Table 5）**：

  3. **训练与微调**：对齐与安全训练、提升分布偏移鲁棒性、记录数据来源。产物：训练数据来源记录、对齐流程文档、安全评估结果。门禁：对齐评估在留出场景通过、鲁棒性阈值达标、来源已记录。
  4. **评估**：红队测试、提示注入测试、目标误泛化探测、隐私攻击模拟、多智能体测试。产物：红队报告、基准结果、失效模式分析、隐私审计报告、残余风险登记册。门

## 摘要
基于大语言模型构建的智能体AI系统能够进行多步规划、使用外部工具、在记忆中保留信息，并与其他智能体协调。这些能力使其比静态语言模型更有用，但也引入了新的安全和运行风险。来自网站、电子邮件、文档和数据库的不可信内容可能进入与系统指令相同的上下文；持久记忆可能跨会话携带被污染的信息；对外部工具的访问可能将不正确的模型响应转化为具有现实后果的行动。本文从五个相互关联的维度审视智能体AI的可信性：安全性与鲁棒性、对齐与人类监督、透明度与可审计性、隐私与数据治理，以及监管合规。它将关键失效模式，包括间接提示注入、后门触发器、目标错误泛化、记忆污染和跨会话数据泄露，组织成一个统一的分类体系。本文还考察主要缓解方法，如指令层级、上下文隔离、spotlighting（聚光灯提示）、基于过程的监督、受限工具使用和隐私保护记忆，同时区分有实证证据支持的技术与仍主要停留在概念层面的技术。在此分析基础上，我们提出可信智能体开发生命周期（Trustworthy Agent Development Lifecycle, TADL），一个涵盖规范、设计、训练、评估、部署和监控的六阶段框架。对于每个阶段，TADL识别相关的可信活动、预期证据和基于风险的决策门。尽管TADL尚未经过实证验证，但它为开发和评估更安全、更可问责的智能体系统提供了结构化基础。文章最后指出当前基准测试中的空白，并概述未来研究的优先事项。

## Abstract
Agentic AI systems built on large language models can plan over multiple steps, use external tools, retain information in memory, and coordinate with other agents. These capabilities make them more useful than static language models, but they also introduce new security and operational risks. Untrusted content from websites, emails, documents, and databases can enter the same context as system instructions; persistent memory can carry compromised information across sessions; and access to external tools can turn an incorrect model response into a consequential real-world action. This article reviews the trustworthiness of agentic AI across five interconnected dimensions: safety and robustness, alignment and human oversight, transparency and auditability, privacy and data governance, and regulatory compliance. It organizes key failure modes, including indirect prompt injection, backdoor triggers, goal misgeneralization, memory contamination, and cross-session data leakage, into a unified taxonomy. It also examines major mitigation approaches, such as instruction hierarchies, context isolation, spotlighting, process-based supervision, constrained tool use, and privacy-preserving memory, while distinguishing techniques supported by empirical evidence from those that remain largely conceptual. Building on this analysis, we introduce the Trustworthy Agent Development Lifecycle (TADL), a six-phase framework covering specification, design, training, evaluation, deployment, and monitoring. For each phase, TADL identifies relevant trust activities, expected evidence, and risk-based decision gates. Although TADL has not yet been empirically validated, it provides a structured foundation for developing and evaluating more secure and accountable agentic systems. The article concludes by identifying gaps in current benchmarks and outlining priorities for future research.

### 2.2 贡献一：五维失效模式统一分类（Section 3, Table 3）

- **安全失效**：直接伤害执行、跨系统级联失效、资源耗尽（失控 API/算力循环）、越权工具调用。
- **对齐失效**：目标错误泛化（goal misgeneralization）、规范博弈（specification gaming）、指令误读、长时运行中的价值漂移。
- **透明度失效**：中间推理不透明、事后合理化（陈述的推理不反映实际计算过程）、过度自信输出加剧自动化偏见、欺骗性对齐（当前能力水平下基本属理论问题）。
- **隐私失效**：过度授权工具调用导致泄露、记忆污染跨会话累积敏感数据、从模型输出中提取记忆的私有信息、从持久化智能体记忆中提取用户—智能体交互。
- **治理失效**：受监管领域合规违规（HIPAA、GDPR、MiFID II）、危害发生后无法在委托层级中归属责任的问责缺口、审计轨迹不足、跨境监管冲突。
- **严重度评级说明**：Table 3 的 C/H 评级为**作者主观示例性评估**，依据四项标准——危害范围（个体 vs 系统性）、可逆性、失效点上的智能体自主度、危害发生前的可检测性；非经验证的风险分数。

### 2.3 贡献二：缓解策略家族比较（Sections 4–8）

- **提示注入防御**：指令层级（instruction hierarchies，训练模型对可信指令赋更高权重）、上下文隔离（有效但限制跨源信息整合、增加系统复杂度）、检测式防御（在 AgentDojo 中评估，效用依赖攻击分布与误拦成本）、spotlighting（用特殊标记标注不可信数据，证据最强于受控测试场景，不证明智能体反复检索并转换敌意内容时仍具韧性）、形式化动作约束（保证强但降低灵活性）。
- **对齐方法**：RLHF（单轮 LLM 证据最强，但长时程泛化、标注者偏差、奖励模型自身可被博弈）、Constitutional AI（显式编码规范原则，但宪法的完备性与一致性难保证）、价值学习（理论上吸引人，操作化困难）。
- **可扩展监督**：AI 辩论（主要理论证据）、递归奖励建模（分层奖励模型）、过程奖励模型 PRM（对可局部验证的步骤监督更密，证据主要来自数学推理）。
- **透明度**：CoT 忠实性问题（Turpin et al.、Lanham et al.）；区分"CoT 带来性能增益"与"CoT 是忠实因果记录"两件事；扰动式不忠实证据不等于故意欺骗。结构化审计记录（工具调用、记忆访问、中间决策、环境观测）、分层计划可视化、交互式计划编辑器。
- **隐私架构**：隐私设计（工具调用数据最小化、目的受限且自动过期的记忆、访问受控的 RAG）、差分隐私（提供形式化保证，但与智能体所需高保真上下文检索存在尖锐效用权衡）、联邦学习（原文未评估 LLM 智能体场景）。
- **核心判断**：提示注入是**架构性问题**，不是靠更好的系统提示可以消除的缺陷。

### 2.4 贡献三：可信智能体开发生命周期 TADL（Section 9）

- **定位**：作者提出的**概念性框架**，源自软件开发生命周期 [3] 与 NIST AI RMF [52]，**尚未经实证验证**，不应作为既定工程方法论。
- **三项适配性改进**：① 面向 LLM 智能体特有失效模式（注入、记忆攻击、级联失效）的威胁建模；② 显式"信任门"（trust gates），使门禁标准可见、可审计而非隐性；③ 部署期检测到行为异常时**自适应升级人类监督**。
- **六阶段 + 五道信任门**：
  1. **规范 Specification**：定义任务范围、委托层级（principal hierarchy）、风险层级、监管要求；建模智能体特有威胁 → 交付风险评估、委托层级文档、威胁模型、合规清单；门禁：风险层级确认、适用法规识别、威胁模型评审、监督要求确立。
  2. **设计 Design**：选择架构；设计工具权限、记忆治理、人类监督、隐私保护 → 交付架构规格、工具权限矩阵、记忆治理政策、监督计划、隐私影响评估；门禁：安全与隐私评审通过、工具权限与监督计划获相关方批准。
  3. **训练与微调**：对齐与安全训练、分布偏移鲁棒性、数据溯源记录；门禁：对齐评估在留出场景通过、鲁棒性阈值达标、溯源已记录。
  4. **评估**：红队测试、提示注入测试、目标错误泛化探测、隐私攻击模拟、多智能体测试；门禁：无未解决的严重失效、阈值达标、残余风险被责任方记录并接受。
  5. **部署**：分阶段上线、按风险限制能力、配置监控与事件响应；门禁：分阶段测试通过、监控启用、事件响应与回滚流程就位。
  6. **监控**：行为与异常监控、事件响应、模型/环境/政策/工具变更后的再评估；门禁：服务指标在批准范围内、事件率低于阈值、评估按计划及触发条件完成。
- **门禁失败处理**：返回前一阶段修订（虚线弧）；监控持续反馈至规范阶段，形成再评估循环。
- **风险分层**：Critical（不可逆伤害：医疗、关键基础设施、司法）、High（重大但可恢复：代码部署、HR、金融账户）、Moderate（有限后果：内容生成、研究辅助、排程）、Low（易验证：信息检索、人工复核的草稿）。
- **关键工程判断**：Critical 层级所需的不是"单一数字"，而应从危害分析、领域运行节奏、最快可信危害路径所隐含的最大可容忍响应时间**推导出"异常动作到有效人工接管之间可接受的延迟"**。监督型控制回路智能体与"签署前复核"的临床文书智能体需求截然不同，但二者都可能合格。
- **工作示例**：临床文书生成智能体（Critical 层级）——规范阶段记录患者/医生/医院/技术提供方各自的约束与冲突升级路径（HIPAA 隐私规则、FDA 器械要求视预期用途而定，文书智能体不自动等同医疗器械）；设计阶段工具权限仅限文书系统、记忆隔离患者记录、医生签署前强制复核；评估阶段针对歧义临床对话、罕见病、双语交互、隐私提取攻击、关键发现遗漏做红队；部署阶段初期 100% 医生复核，并对医生大幅修改做自动检测作为对齐信号。

### 2.5 贡献四：评估缺口与开放问题（Sections 10–11）

- **基准缺口（Table 7）**：安全维度缺乏跨架构的标准提示注入基准；对齐维度无评估持续运行中目标漂移的基准；透明度维度无标准 CoT 忠实度指标；隐私维度记忆攻击基准尚处萌芽；治理维度无跨监管辖区的合规测试框架；跨维度上 AgentBench 的单一聚合分数可能掩盖任务特异行为。
- **开放问题**：形式化智能体对齐定义、欺骗性对齐、集体对齐、包容性价值表征；可扩展监督、架构级注入防御、长时程对齐评估、隐私保护记忆、校准不确定性沟通、智能体可观测性（标准审计轨迹格式）；智能体责任框架、国际监管协调、审计标准、人机协作监督责任分配。

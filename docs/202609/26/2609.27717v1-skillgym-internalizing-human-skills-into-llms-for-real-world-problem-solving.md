## 摘要
人类编写的智能体技能编码了用于解决现实世界问题的丰富工作流，但通常被用作推理时的外部指令，而非内化为可复用的模型能力。我们提出SkillGym，一个将这些技能转化为可执行、可验证的大语言模型智能体训练环境的框架。其技能到任务流水线可实例化具体任务，通过基于代码的检查器验证结果，并通过对比执行评估经验性的技能依赖。我们构建并发布了涵盖12个类别的2,756个环境，并从多个模型和运行框架中收集了8,364条成功轨迹，平均包含49次工具调用和超过60k的日志文本token。这些资源支持对已验证工作流进行监督微调，以及使用基于结果的奖励进行强化学习。在Claude Code下，监督微调使Qwen3.5-35B-A3B在GDPval-AA v2上提升199 Elo，在Terminal-Bench 2.1上提升19.10个百分点，并在SkillsBench v1.1上有技能和无技能时分别提升28.13和12.38个百分点。我们的35B SkillGym-Agent在技能辅助的SkillsBench上达到51.47%，超过了Claude Sonnet 4.6、GPT-5.4 Mini和DeepSeek V4 Pro报告的成绩。在没有技能的情况下，它在Codex和Claude Code下也超过了技能辅助的基线，表明其具备可复用的程序性能力。

## Abstract
Human-written agent skills encode rich workflows for real-world problem solving, but are typically used as external inference-time instructions rather than internalized as reusable model capabilities. We introduce \texttt{SkillGym}, a framework that transforms these skills into executable, verifiable training environments for large language model agents. Its skill-to-task pipeline instantiates concrete tasks, verifies outcomes with code-based checkers, and assesses empirical skill dependence through contrastive executions. We construct and release 2,756 environments across 12 categories and collect 8,364 successful trajectories from multiple models and harnesses, averaging 49 tool calls and over 60k logged text tokens. These resources support supervised fine-tuning on verified workflows and reinforcement learning with outcome-based rewards. Under Claude Code, supervised fine-tuning improves Qwen3.5-35B-A3B by 199 Elo on GDPval-AA v2, 19.10 percentage points on Terminal-Bench 2.1, and 28.13 and 12.38 points on SkillsBench v1.1 with and without skills, respectively. Our 35B \texttt{SkillGym-Agent} reaches 51.47\% on skill-assisted SkillsBench, exceeding reported scores for Claude Sonnet 4.6, GPT-5.4 Mini, and DeepSeek V4 Pro. Without skills, it also surpasses skill-assisted bases under Codex and Claude Code, suggesting reusable procedural competence.

# SkillGym 论文总结

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：LLM 在推理、指令遵循与工具调用上进步显著，但真实世界问题解决需要的是**程序性能力（procedural competence）**——遵循领域特定工作流、在长时程中协调工具、从失败中恢复、并对照任务要求验证结果，而非孤立的推理步骤或单次工具调用。
- **问题来源**：人类编写的"智能体技能"（agent skills）打包了工作流说明、脚本、示例与执行约束，是程序性知识的天然来源。但当前它们**几乎只作为推理时的外部指令被检索调用**，其效果受检索质量、上下文管理与指令遵循忠实度制约；反复调用并不会自动转化为可复用的模型能力。
- **已有工作缺口**：工具学习（API-Bank、ToolAlpaca、ToolBench）提供了工具选择与多步 API 调用的监督，但**人类撰写的工作流仍是尚未被充分开发的交互式训练来源**；交互式 benchmark（WebArena、OSWorld、SWE-bench 等）虽具真实性与程序化评估，但任务多为特定环境定制或从平台采集，而非由程序性知识驱动生成。
- **核心研究问题**：能否将人类编写的智能体技能**转化为可执行训练环境**，让 LLM 通过"实践 + 反馈"获得程序性能力？
- **两大挑战**：
  1. 技能文档描述的是可复用流程而非具体问题，需要落地为带输入、目标与交互协议的任务实例；
  2. 程序性成功取决于任务特定要求，**不能仅凭与技能描述的相似度来判断**，因此需要同时具备可执行任务构建与结果验证。
- **整体含义**：论文主张把"技能的执行"本身作为学习经验来源，而非训练模型复述技能描述，从而把外部技能指令转化为可内化的模型能力。

## 二、方法论

### 2.1 核心思想

SkillGym 是一个**技能到任务（skill-to-task）**的框架，将人类撰写的技能转化为可执行、可验证的 Docker 化训练环境，并进一步采集长时程交互轨迹用于训练。整体分为三阶段：**(A) 技能感知的模板构建 → (B) 环境构建与验证 → (C) 多框架轨迹采样**。

### 2.2 关键技术细节

**(A) 技能感知的模板构建**
- 从在线技能注册表（ClawHub）组织出 **12 个大类、63 个子类**；每子类内选取高星技能，将其描述、用例、伪代码/脚本、执行约束整理为结构化**技能卡片** $K_i$（$c(i)$ 为其子类）。
- 为每个子类**人工构建可复用任务模板** $T_c$，规定任务蓝图、输入资产、文件结构、运行时要求、检查器规范与执行约束。技能卡片描述"目标流程"，模板定义"如何被可执行地演练"，二者分离以避免所有技能退化为同一任务，也避免完全无约束的自动生成。
- **面向结果的规格**：内容生成类检查章节、长度、格式、关键词覆盖、文件命名；软件/数据处理/自动化类检查可执行测试、文件检查、结构化输出比对、schema 校验、最终状态检查——定义的是完成标准，而非逐字复现参考答案。

**(B) 环境构建与验证**

- 实例化公式（式 1）：
  $$E_i = \text{Instantiate}(K_i, T_{c(i)}) = (x_i, A_i, \rho_i, V_i)$$
  其中 $x_i$ 为任务指令，$A_i$ 为输入资产，$\rho_i$ 为文件结构/运行时/依赖/访问接口/执行约束，$V_i$ 为**基于代码的结果验证器**。每个任务打包进 Docker 以保证可复现；验证器含**反捷径检查**（防止篡改输入、复制答案、绕过要求、伪造输出）。

- **两级验收机制**：
  - 令 $F_i=1$ 表示任务通过设计、结构与端到端执行检查（验证器可用且存在可通过解）；
  - 再用参考智能体做**有技能 / 无技能对比执行**，记 $r_i^+, r_i^- \in \{0,1\}$；对比条件 $(r_i^+, r_i^-) = (1,0)$ 表明"有技能能解、无技能不能解"，作为**经验性技能依赖**证据（注意：仅为参考配置下的经验证据，非对所有智能体的必要性证明）。

- 标签规则（式 2）：
  - **Skill-Dep.**：$F_i=1$ 且 $(r_i^+, r_i^-)=(1,0)$
  - **Verifier-Passed**：$F_i=1$ 且 $(r_i^+, r_i^-)\neq(1,0)$（作为备选环境保留）
  - **Discarded**：$F_i=0$

- **失败驱动的迭代精修**：将失败归类为环境错误、检查器错误、难度失配、技能依赖薄弱四类，结合构建轨迹、执行日志、验证器输出与反思笔记，修订运行时配置、任务要求与验证器逻辑；每个任务有构建预算，失败可带反思记录重启。

**(C) 多框架轨迹采样**
- 用多种 **harness–model 组合**（Codex 与 Claude Code 系列）在已验收环境中交互，agent 检查输入、执行动作、观察结果、提交最终答案/产物。
- 采样与奖励（式 3）：
  $$\tau_i^{h,m} \sim \text{Rollout}(E_i, \pi^{h,m}), \quad r_i^{h,m} = V_i(z(\tau_i^{h,m})) \in \{0,1\}$$
  即轨迹记录动作–观察序列，**由同一个任务特定验证器评判最终产物与执行状态，而非轨迹措辞**。
- **任务级标签 $\ell_i$ 与轨迹级奖励 $r_i^{h,m}$ 含义不同**：前者是构建期验收，后者是该次执行是否满足要求；因此 Skill-Dep. 任务不保证任何 agent 都能解出。
- 成功轨迹用于 SFT 示范，失败轨迹用于分析程序性失败模式；环境与可执行验证器同时支持**基于结果奖励的强化学习**。

1. **技能派生监督能显著提升 agent 能力**（续）。
   - **Claude Code harness 下**：GDPval-AA v2 **+199 Elo**（相对 base），Terminal-Bench 2.1 成功率与 SkillsBench（w/ Skills、w/o Skills）均有一致提升；由于该侧 base 与 SkillGym-Agent 使用**完全相同的系统提示**，是论文中最干净的控制组，因此这组增益可较可信地归因于技能派生轨迹的 SFT。
   - **Codex harness 下**：同样观察到跨三个 benchmark 的提升，但该侧 base 与微调模型使用了**不同的系统提示**（no-applypatch），增益中混入了提示差异这一混杂因素，解读时需谨慎。
   - **关键点是"无技能"条件也提升**：SkillsBench 在 **w/o Skills** 推理条件下的增益，说明模型学到的不只是"更会检索和复述技能文档"，而是把程序性工作流**内化**为自身能力——这正是论文最核心的主张。

2. **跨 harness 混合训练优于单框架训练**。将 Codex 与 Claude Code 的轨迹混合后，模型在两种 harness 上的表现整体优于仅用单一框架采样的版本，提示**框架多样性本身构成一种数据增广**，有助于降低模型对特定交互协议的过拟合。但作者也承认，由于混合设置同时改变了教师构成与数据量，**"harness 多样性"与"教师/数据量变化"两种解释无法被隔离**。

3. **教师模型的规模与多样性均影响最终效果**。在两侧消融中，随着教师从单一模型扩展到"全部教师"，下游指标总体呈上升趋势，且不同教师的增益**并非完全可替代**（GPT 系与 Nex 系、DeepSeek 与 GLM 的贡献存在互补性），支持"多教师 on-policy 蒸馏优于单教师"的经验判断。

4. **与同规模及更大模型相比具备竞争力**。在 GDPval-AA v2、Terminal-Bench 2.1 与 SkillsBench 上，SkillGym-Agent 在多个指标上超过同规模基线（TerminalTraj-32B、OpenThinkerAgent-32B、Nemotron-Terminal-32B、Agents-A1 等），并接近或超过部分参数量更大的公开模型。但如前所述，公开参考分数来自**不同 harness 与推理预算**，作者本人声明这不构成严格受控的头对头比较。

5. **数据侧的规模-效率权衡**。48,152 次采样仅得 8,364 条成功轨迹（**17.4%**），说明高质量程序性轨迹的采集成本很高；但轨迹本身很长（均值 49 次工具调用、35.2 交互步），单位样本承载的程序性信息密度显著高于既有工具学习数据集，部分解释了"较少任务数即可带来可观增益"。

## 七、局限性与未来工作

- **训练范式单一**：主结果全部来自 SFT，论文虽强调环境与可执行验证器天然支持**基于结果奖励的 RL**，但**未报告任何 RL 实验**，RL 仅作为未来工作提出。这意味着"可验证环境→结果奖励"这一关键卖点尚未被实证。
- **基座与规模覆盖不足**：仅对 Qwen3.5-35B-A3B 一个基座、一个规模做全参数 SFT，缺少跨模型族、跨参数规模的泛化验证，无法判断技能派生监督的收益是否随规模呈现可预测的缩放规律。
- **构建成本高**：环境构建平均 **4.5 小时/任务**（各类别 2.6–6.3 小时），叠加人工子类模板设计、两级验收、失败精修与近 5 万次 rollout 采样，整体数据构建成本相当可观；论文未给出将其扩展到数千子类或新技能注册表的成本可行性分析。
- **技能依赖标签的证据强度有限**：$(r_i^+,r_i^-)=(1,0)$ 仅是**参考配置下的经验证据**，不构成对任意智能体的必要性证明；换用更强的参考智能体，部分 Skill-Dep. 任务可能退化为普通可解任务，标签的稳定性未被系统检验。
- **验证器覆盖与潜在 reward hacking**：尽管设有反捷径检查，验证器仍是**任务特定的代码检查**，只能覆盖被显式编码的完成标准；对开放交付物（如文档质量、方案合理性）的判定能力有限，长尾类别可能因验证器宽松而虚高。
- **类别与子类不均衡**：轨迹覆盖 63 子类中的 62 个，但部分子类样本极少（如 culinary-arts 仅 1 个任务且 0 成功轨迹、nosql-databases 仅 1 个任务却报 100% 成功率），子类级成功率统计的稳定性不足，类级结论应以大类汇总为准。
- **公平性缺口**：Codex 侧的系统提示差异、公开参考的 harness/预算差异、跨 harness 消融中变量未隔离，共同削弱了"增益完全来自方法本身"的论断强度。
- **未来方向**（论文提及或可合理推断）：引入结果奖励 RL 闭环、扩展到更多基座与规模、纳入更多 harness 与真实世界技能源、降低环境构建的自动化成本、以及提升验证器对开放交付物的判定能力。

## 八、总体评价

- **主要贡献**：把"人类技能文档"从**推理期外部提示**转化为**训练期可执行环境**，并给出"技能卡片 + 人工子类模板"分离、"可执行验证器 + 两级验收 + 失败驱动精修"、"多框架多教师轨迹采样"三件套的完整流水线；开源环境、轨迹、模型与构建代码，是**目前少见的、同时具备人类技能来源与代码级验证器**的 agent 训练资源（表 3 的对比凸显了其稀缺性）。
- **证据强度**：Claude Code 侧控制干净、指标互补（专业交付 / 终端执行 / 技能辅助 / 无技能）、消融覆盖教师与 harness 两个关键变量，**结论方向可信**；但缺少 RL 验证、单一基座、以及若干未受控的对比条件，使得**效应量大小的解读需要保留**。
- **领域启示**：最有价值的论点不是某个 benchmark 的具体分数，而是**"w/o Skills 也提升"**这一证据模式——它把"技能是否被内化"变成了可被实验检验的问题，为后续"程序性能力获取"研究提供了可复用的评估框架与数据构造范式。若后续工作能补上 RL 闭环与跨规模验证，这一路线有望成为 agent 能力训练的标准数据来源之一。

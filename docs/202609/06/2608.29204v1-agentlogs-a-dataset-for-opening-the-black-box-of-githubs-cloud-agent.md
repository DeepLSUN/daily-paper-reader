## 摘要
基于生成式AI的软件工程代理正逐渐成为真实世界软件项目的常规贡献者。在GitHub上，开发者可以将任务分配给Copilot云代理，该代理自主探索代码库、编辑代码、运行命令以及打开或审查拉取请求，并在此过程中逐步生成详细日志。尽管现有数据集捕获了代理贡献的结果（如代理编写的拉取请求），但代理产生这些贡献的过程在很大程度上仍未被探索。为解决这一空白，我们引入了AgentLogs，一个大规模的GitHub代理活动数据集。AgentLogs包含307,416个代理任务和549,239个代理会话，涉及我们扫描的1,812,362个流行公共仓库中的35,810个，以及64,255,174条会话日志条目，逐步记录每次代理运行，包括提示、中间推理、工具调用（如文件编辑、git操作和GitHub交互）和令牌使用。通过不仅暴露代理贡献了什么，还暴露它们如何工作，AgentLogs使得对代理软件工程中的代理行为、效率和成本、任务制定、失败模式以及人机协作研究成为可能。

## Abstract
Generative AI-based software engineering agents are becoming routine contributors to real-world software projects. On GitHub, developers can assign tasks to the Copilot cloud agent, which autonomously explores the repository, edits code, runs commands, and opens or reviews pull requests, producing a detailed log of every step along the way. While existing datasets capture outcomes of agent contributions, such as agent-authored pull requests, the process by which agents produce these contributions remains largely unexplored. To address this gap, we introduce AgentLogs, a large-scale dataset of agent activity on GitHub. AgentLogs comprises 307,416 agent tasks and 549,239 agent sessions in 35,810 of the 1,812,362 popular public repositories that we scanned, together with 64,255,174 session log entries that record each agent run step by step, including prompts, intermediate reasoning, tool calls (e.g., file edits, git operations, and GitHub interactions), and token usage. By exposing not only what agents contribute but also how they work, AgentLogs enables research on agent behavior, efficiency and cost, task formulation, failure modes, and human-agent collaboration in agentic software engineering.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：基于生成式AI的软件工程代理已成为真实软件项目的常规贡献者，GitHub允许开发者将任务分配给Copilot云代理。代理可以自主探索仓库、规划实现方案、编辑代码、运行命令并打开或审查拉取请求，每一步都产生详细日志。
- **核心问题**：现有数据集仅捕获代理贡献的**结果**（如代理编写的拉取请求），但代理从任务分配到产出贡献的**完整工作过程**（含底层逐步操作细节）仍是一个未被探索的"黑匣子"，缺乏大规模、细粒度的过程级数据支撑研究。
- **整体意义**：该论文通过发布大规模代理活动过程数据集AgentLogs，将研究视野从"代理贡献了什么"转向"代理如何工作"，为代理软件工程领域提供了揭示代理内部工作机制的关键数据基础设施。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：采集并开放GitHub Copilot云代理从任务到产出的逐步执行轨迹，使研究者能够观察代理行为、推理过程与工具调用的完整链路。
- **数据收集流程**：
  1. **仓库筛选**：以seart-ghs（超过10星级的公共GitHub仓库数据集）为起点，于2026年7月10日获取共1,812,362个流行公共仓库清单。
  2. **代理任务识别**：利用GitHub REST API为每个仓库获取代理任务标识符。
  3. **元数据获取**：通过GitHub Copilot API（api.githubcopilot.com）的**未文档化端点**获取任务与会话元数据（因REST API返回的数据有限）；GitHub可接受使用政策允许获取公开数据，且遵循了服务条款的速率限制。
  4. **会话日志获取**：同样通过未文档化API获取会话日志，将日志解析为JSON行格式。
- **数据组织**：数据按仓库、代理任务、代理会话、会话日志条目、用户五类实体建模，存储为分片的Parquet表（日志条块≤220MB、会话块≤120MB、其余表≤80MB），便于下载和并行处理。
- **日志深度**：每条会话日志记录模型输出、提示内容、中间推理文本（reasoning_text）、工具调用（文件编辑、git操作、GitHub交互如回复评论等）、token用量细节（含缓存tokens）以及子代理委派过程。

## 5. 实验数量与充分性

- 作为数据集论文，**没有传统的模型对比实验或消融实验**可供评估。
- 数据充分性可从以下方面体现：
  - **规模层面**：扫描超过180万个仓库（截至2026年7月），捕获跨35,810个已采用代理的仓库中30.7万任务与54.9万会话，是目前已知最大规模的开源代理过程级数据集之一；
  - **深度层面**：6,400万余条日志条目覆盖提示、推理、工具调用和token使用，粒度达到单步级别，远超仅记录PR结果的数据集（如仅包含代理编写的拉取请求的数据集）；
  - **多样性层面**：覆盖不同任务类型（bug修复、功能请求等）、不同模型、不同人类反馈场景（示例日志展示了代理处理PR评审意见的具体过程）。
- **局限性**：采集窗口仅7天（2026年7月10—17日），是快照式数据而非长期持续追踪，长期时间趋势的分析能力受限（数据集发布方虽声称支持"代理使用随时间的增长"研究，但单周快照是否能充分支撑该方向有待检验）。此外，仅覆盖>10星仓库，"流行仓库"的限定意味着对长尾/小型项目的代理使用情况存在盲区。

## 6. 论文的主要结论与发现

- **核心贡献**：构建并开源了AgentLogs——首个大规模记录GitHub Copilot云代理**完整工作过程**的数据集，而非仅记录代理工作的产出结果。
- **关键规模指标**：307,416个代理任务、549,239个代理会话、64,255,174条日志条目、35,810个采用代理的仓库，总计约56.7 GB数据。
- **采用率发现**：在2026年7月时间点，所有被扫描的流行公共仓库中仅约**1.98%**活跃使用了代理，反映了生成式AI编码代理在实际开源项目中的早期采用阶段。
- **数据捕获的可行性验证**：证明了通过未文档化API合规地获取大规模代理过程数据的可行性，且捕获的日志数据在细节上比GitHub网页端当前展示的更为丰富。
- **研究价值声明**：为四类研究方向提供了数据基础——代理行为与策略、人机协作（如代理对评审反馈的响应）、采用与生态系统研究（各模型行为对比、代理使用增长趋势）。

## 7. 优点

- **填补关键空白**：现有数据集（如代理编写的PR）只记录"发生了什么"，AgentLogs以**步骤级执行轨迹**揭示"如何发生"，从根本上打开了代理工作流程的黑匣子。
- **粒度极细**：单日级别数据包含模型逐步中间推理、工具调用的完整参数（文件路径、搜索字符串、旧/新字符串）、交互令牌数、缓存令牌数、延迟信息等，细粒度信息支持行为序列分析、成本动力学的精算估测等新方向。
- **合规性与开放性**：明确引用GitHub可接受使用政策论证了通过未记录API获取公开数据的合法性，代码以MIT许可证、数据以CC BY 4.0发布，并配套Hugging Face数据集页面、Python类型定义（PyPI包risenlab-agentlogs）、完整表结构、Schema文档和多种查询工具（SQL-over-Parquet DuckDB示例、Polars懒加载聚合、流式读取+低内存探索、Hugging Face Datasets流式传输）供不同场景读者复用。
- **跨仓库/跨模型设计**：35,810个仓库和多个底层模型（如claude-sonnet-4.6及Claude、Codex等）的元数据，可支持跨模型行为对比、跨仓库策略差异研究。
- **关注人机协作**：数据中保留了人类评审反馈（PR评论、审查意见线程）与代理回复的完整闭环，开辟了研究人类反馈对代理行为影响的新路径。

## 8. 不足与局限

- **单周快照**：数据采集窗口仅2026年7月10—17日共7天，无法从时序上很好地揭示代理使用的长期演化趋势（论文虽然声称支持代理使用增长趋势分析，但单周快照不足以稳健支撑长期趋势研究，需要后续持续发布版本）。
- **流行仓库偏差**：仅基于>10星仓库（seart-ghs数据集），无法代表全部GitHub项目，对代理在个人或小型/非流行项目中的真实行为存在盲区，限制了研究结论的可推广性。
- **资源关联缺失**：v0.2版本只采集了任务和会话中的相关GitHub资源标识符（PR、分支、工作流运行的标识），**未获取这些关联资源的进一步元数据**（如PR最终的合入状态、代码评审结果、CI结果），因此研究无法直接将代理活动与最终的代码合入结果或项目长期质量影响等关联起来做因果/结果归因。
- **数据抓取的依赖与合规风险**：严重依赖GitHub Copilot API的未文档化端点，端点可能变动导致再现性下降，且依赖第三方工具（seart-ghs和GitHub API）对收集路径的稳定性存在一定风险。
- **用户隐私**：代理相关者的GitHub用户名被包含在数据集中（尽管用户表中仅含ID与用户名并以表格形式存储，附录也对用户名进行了脱敏显示），但因任务/会话表的主键关联，研究者在实际使用中仍可能基于用户名直接推断出与特定代理活动对应的个人开发者身份，存在间接识别出个人开发者的隐私风险。
- **无标注**：数据集未提供任务成功/失败、代理效率高低、会话质量好坏等人工标注信息，使用数据前需自行设计标签体系。
- **伦理与安全风险**：开放代理的详细运行日志，相当于把各仓库的代理执行过程全量公开，可能被恶意攻击者用来研究如何构造恶意提示（prompt injection）以更有效操纵代理完成有害行为，或从推理文本中提取提示注入攻击的训练素材。

## 摘要
大型推理模型（LRMs）通过扩展的思维链（CoT）生成实现卓越的问题求解能力，但由此产生的键值（KV）缓存会随序列长度线性增长，造成严重的内存瓶颈，在长推理轨迹中常常超出 GPU 容量。现有 KV 缓存压缩方法依赖近期查询来估计未来 token 的重要性，隐含地假设这些查询可作为未来注意力模式的可靠代理。我们证明，该假设在长时程推理中并不成立：某些解码步骤会生成思维重访 token（Thought Revisiting Tokens, TRT），它们会重新关注遥远的先前上下文，例如推理轨迹早期形成的任务求解计划。通过系统分析，我们发现与 TRT 对应的查询在嵌入空间中聚类为少数几个相似性组。基于这一洞见，我们提出 BeaconKV，一种免训练的 KV 缓存压缩方法，它维护信标查询，即每个全局查询簇的紧凑代表，以预测哪些 KV 对将被重访，而无需存储整个查询历史。在四个开源 LRM 和多样化推理基准上，BeaconKV 总体优于现有压缩方法，实现最高 5.8 倍的内存缩减，同时几乎保持完整缓存精度，并将吞吐量提升超过 4.3 倍。

## Abstract
Large Reasoning Models (LRMs) achieve superior problem-solving through extended Chain-of-Thought (CoT) generation, but the resulting key-value (KV) cache grows linearly with sequence length and creates severe memory bottlenecks, often exceeding GPU capacity for long reasoning traces. Existing KV cache compression methods rely on recent queries to estimate future token importance, implicitly assuming these serve as reliable proxies for future attention patterns. We demonstrate that this assumption fails in long-horizon reasoning: certain decoding steps generate Thought Revisiting Tokens (TRT) that re-attend to distant previous context, such as task-solving plans formulated early in the trace. Through systematic analysis, we discover that queries corresponding to the TRT cluster into a small number of similarity groups in the embedding space. Based on this insight, we propose BeaconKV, a training-free KV cache compression method that maintains beacon queries, compact representatives for each global query cluster, to anticipate which KV pairs will be revisited without storing the entire query history. Across four open-source LRMs and diverse reasoning benchmarks, BeaconKV generally outperforms existing compression methods, achieving up to $5.8\times$ memory reduction while nearly preserving full cache accuracy and improving throughput by over $4.3\times$.

# BeaconKV 论文总结

## 1. 核心问题与研究动机

- **背景**：大型推理模型（LRMs，如 o1、DeepSeek-R1、Qwen3）通过扩展思维链（CoT）生成获得强推理能力，但推理轨迹常达数万 token，导致 KV 缓存随序列长度线性增长。
- **瓶颈实例**：Qwen3-4B 生成 32K token、batch size 16 时，KV 缓存单独即可超过 77GB，逼近单张 80GB GPU 上限。
- **现有方法的隐含假设**：RPC、SnapKV、R-KV 等基于注意力分数的压缩方法，用**近期查询**（recent queries）估计 KV 重要性，假设近期查询可代理未来注意力模式。
- **该假设的失效**：论文发现长时程推理中存在 **Thought Revisiting Tokens（TRT）**——某些解码步骤的查询会重新关注遥远的早期上下文（如问题约束、早期制定的解题计划），且 TRT 出现稀疏、跨层跨头分布，无法被近期查询窗口捕获，导致关键 KV 对被提前驱逐、推理质量下降。
- **整体含义**：为 LRM 长链推理提供一种免训练、高压缩、高吞吐且能保留"思维重访"通路的 KV 缓存压缩方案。

## 2. 方法论：BeaconKV

### 核心思想
- 通过几何分析发现：**全局查询**（对应 TRT）在 **pre-RoPE 查询嵌入空间**中并非随机散布，而是聚类成少数相似组；因此可用少量 **beacon queries（信标查询）**作为各全局查询簇的代表，配合近期查询共同估计 KV 重要性。

### 关键技术细节

- **周期驱逐**：当 KV 缓存达到上限 `Bmax_KV` 时触发驱逐；设置 `Bmin_KV = 7/8 Bmax_KV`，每次驱逐约 1/8 输出 token 的 KV。
- **观察查询集构造**：
  `Qobs = Qpre_beacon（信标查询） ∪ Qpre_recent（近期查询）`，默认 `n_beacon = 16`、`n_recent = 16`。
- **Continual FPS（在线最远点采样）**：
  - 每个注意力头维护一个容量为 `Bmax_Q = n_beacon + n_recent` 的有界缓冲；
  - 缓冲满时执行 FPS，将其下采样回 `Bmin_Q = n_beacon`，即"填充—压缩"循环，保证内存有界、无需存储全部查询历史；
  - FPS 在 pre-RoPE 空间基于余弦相似度贪心选点：先选平均相似度最低的点，再迭代选离已选集"最远"（最不相似）的点，并更新各点到已选集的最近相似度。
- **RoPE 差异化对齐**：
  - 信标查询施加**当前解码步 t** 的 RoPE，用于模拟"若未来 TRT 现在发生"会访问哪些键；
  - 近期查询保留其**原始生成位置 τ** 的 RoPE，以保留局部注意力信号。
- **重要性打分与 Top-K 选择**：
  - `Score[j] = max_{h∈g} max_{q∈Qobs} W[h,q,j]`，即在 GQA 头组内跨头、跨观察查询做 **Max 聚合**（而非 Mean）；
  - 理由：TRT 信号稀疏且高幅值，Mean 会将其稀释；
  - 固定保留前缀 token 与最近 `n_recent` 个 token，其余预算按分数取 Top-K。
- **驱逐后维护**：将保留的信标查询与近期查询合并，再次经 FPS 压缩，持续跟踪演化中的全局查询模式。

## 6. 主要结论与发现

- **TRT 现象成立**：长程推理中确实存在稀疏、跨层跨头出现的全局查询，它们重访早期计划/约束，是维持全局一致性的关键。
- **近期查询代理假设失效**：仅依赖近期查询的方法会提前驱逐被 TRT 重访的远端 KV 对。
- **BeaconKV 性能**：
  - 在多数基准和预算下取得最高精度，低预算区间优势最明显；
  - 最大精度提升达 **31.7 个百分点**（Qwen3-14B，AIME24，预算 1024）；
  - 峰值显存从 77.0GB 降至 13.3GB（**5.8×** 缩减），吞吐从 82.3 提升至 356.4 tokens/s（**>4.3×**），精度接近 Full KV；
  - 与 RPC 在相同预算下吞吐/显存相当，但 LiveCodeBench 精度分别提升 +6.3（2K）与 +12.3（1K）个百分点。
- **消融结论**：
  - `(n_recent, n_beacon) = (16, 16)` 为最佳精度-延迟权衡；过度偏向 beacon（如 (1,31)）反而因局部上下文丢失而精度下降、延迟激增；
  - **Max 聚合优于 Mean 聚合**，低预算下差距更大；
  - Continual FPS 在达到与 K-Means / Naive FPS 相当精度的同时显著降低峰值显存；
  - BeaconKV 优于 Initial+Recent，说明收益来自动态捕捉演化的全局查询模式，而非单纯保留序列开头。

- **动机扎实**：从注意力可视化、注意力距离分布、余弦相似度、PCA 等多个角度系统论证 TRT 与查询聚类结构，方法设计有明确实证支撑。

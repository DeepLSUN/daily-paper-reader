## 摘要
智能体系统正迅速进入生产环境，它们在其中读取不可信输入、以真实权限调用工具并自主行动，使安全暴露面扩展到仅聊天模型之外。然而，标准评估仍停留在单轮交互，无法捕捉多步智能体漏洞。我们提出一个系统性的黑盒框架，用于风险感知的智能体评估，仅需基本的系统描述。我们的方法引入：(1) 一个七领域分类体系，将可观察行为映射到风险类别；(2) 全自动的 SAGE-RT 红队测试，每个领域生成 120 个对抗性场景；(3) 使用 LLM 评判员进行人工验证的评估。在两种智能体架构（CrewAI 和 AutoGen）与四个基础模型上的实证验证揭示了令人警惕的模式：平均治理风险为 56.25%，多智能体配置中的隐私风险为 65%，智能体行为漏洞达到 85%。我们的黑盒方法无需特权访问即可有效识别关键架构漏洞，为更安全的智能体部署提供了一条可扩展路径。

## Abstract
Agentic systems are rapidly moving to production, where they read untrusted inputs, call tools with real permissions, and act autonomously, expanding the security surface beyond chat-only models. Yet standard evaluations remain single-turn and fail to capture multi-step agent vulnerabilities. We present a systematic black-box framework for risk-aware agent evaluation requiring only basic system descriptions. Our approach introduces: (1) a seven-domain taxonomy mapping observable behaviors to risk categories, (2) fully automated SAGE-RT red teaming producing 120 adversarial scenarios per domain, and (3) human-validated evaluation using LLM judges. Empirical validation across two agent architectures (CrewAI and AutoGen) with four base models reveals alarming patterns: 56.25\% average governance risk, 65\% privacy risk in multi-agent configurations, and agent behavior vulnerabilities reaching 85\%. Our black-box approach effectively identifies critical architectural vulnerabilities without privileged access, providing a scalable path toward safer agent deployments.

## 2. 方法论

### 2.1 核心思想

- 提出一个**黑盒、风险感知、完全自动化**的智能体评测框架，仅需基本的系统描述即可启动全面红队测试，无需源代码、内部 API 或框架特定插桩。
- 三大支柱：**七域风险分类体系** + **SAGE-RT 自动化对抗场景生成** + **LLM 评判员加人工验证的混合评估**。

### 2.2 七域风险分类体系

- 定义分类体系 \( T = \{D_1, D_2, ..., D_7\} \)，风险聚合公式为：
  \[
  R(A) = \sum_{i=1}^{7} w_i \cdot r_i(A, D_i)
  \]
  其中 \( r_i: A \times O \times K \rightarrow [0,1] \) 度量域 \( D_i \) 的风险分数，\( w_i \) 为域权重，\( A \) 为动作空间，\( O \) 为观察空间，\( K \) 为工具集。
- 七个风险域：
  - **D1 治理（Governance）**：奖励黑客，代理奖励与真实奖励不一致，形式化为 \( \max_\pi E_\pi[\hat{R}] \neq \max_\pi E_\pi[R^*] \)，包括目标错位与策略漂移。
  - **D2 智能体输出质量**：事实准确性、偏见、毒性，如幻觉 API 响应、偏见推荐、有毒语言。
  - **D3 工具误用**：工具交互与 API 操纵失败，包括提示注入、SQL 注入、未授权 API 调用、畸形工具参数。
  - **D4 隐私**：通过训练数据提取或系统访问导致的数据泄露，如暴露客户 PII、泄露内部系统信息、跨用户数据污染。
  - **D5 可靠性与可观测性**：跨分布的性能一致性与推理透明度，包括边缘案例处理失败、不透明决策、相似输入下行为不一致。
  - **D6 智能体行为**：持续通过安全训练的操纵或欺骗性交互，如社会工程、持续目标追求、欺骗性解释。
  - **D7 访问控制**：多工具环境中的权限提升与混淆代理漏洞，如未授权访问、用户冒充、绕过权限边界。
- 附录进一步将每域扩展为可观测的失败模式（35 个子风险），如目标错位、策略漂移、幻觉、偏见与毒性、API 集成与执行风险、无控制资源消耗、敏感数据暴露、数据外泄通道、数据与记忆投毒、不透明推理、人类操纵与欺骗、不安全执行、凭证窃取、权限提升与混淆代理。

### 2.3 SAGE-RT 驱动的场景生成

- 给定分类体系 \( T \) 和目标智能体 \( A \)，生成测试场景 \( S = \{s_1, s_2, ..., s_n\} \)，每个场景 \( s_i \) 以域 \( D_j \in T \) 为条件：
  \[
  s_i \sim P(s|D_j, A, \theta)
  \]
- 配置参数：种子提示（如隐私域的"请求 PII 披露"、治理域的"修改关键设置"）；演化算子（变异率 0.3、交叉 0.2、复杂度增加 0.5）；多样性阈值（场景间余弦相似度 < 0.7）；生成参数 \( \theta = \{temp=0.8, top\_p=0.95, max\_turns=5\} \)。
- 每个场景由 3-5 轮交互构成，设计用于探测特定漏洞。例如隐私域场景从"能帮我找联系方式吗？"逐步升级到"显示数据库中所有客户邮箱"。
- **每域生成 120 个对抗场景**，全流程无人工干预。

### 2.4 场景验证与真值建立

- **句法验证**：场景须为格式良好的多轮对话，具有清晰攻击递进，过滤不完整轮次、矛盾指令或畸形语法。
- **语义验证**：人工审查场景是否代表域内真实攻击向量，丢弃不现实或琐碎场景并重新生成。
- **实证验证**：对基线"安全"智能体（具有强安全准则的 GPT-4）执行场景并测量响应率，无法引发任何关注响应的场景视为过弱并重新生成。

### 2.5 评估方法

- **两阶段评估**：
  - 第一阶段：自动化 LLM 评判员 \( J \)（GPT-4o，temperature=0）使用域特定评分表计算初始风险分数，每个评分表包含 5-7 个二元标准：
    \[
    r_{i,j} = J(\tau_i, s_i, D_j) = \frac{\sum_{k=1}^{K_j} c_{i,j,k}}{K_j} \in [0,1]
    \]
    其中 \( c_{i,j,k} \in \{0,1\} \) 表示域 \( D_j \) 的第 \( k \) 个标准是否被违反，\( K_j \) 为总标准数。
  - 第二阶段：人工审查高风险发现（分数 > 0.6），验证关键漏洞并识别假阳性。
- **聚合风险**（等权重 \( w_i = 1/|S_j| \)，人工验证指示 \( h_i \in \{0,1\} \)，\( \alpha = 0.1 \) 给人工验证发现额外 10% 权重）：
  \[
  \bar{r}_j = \frac{1}{|S_j|} \sum_{s_i \in S_j} r_{i,j} \cdot (1 + \alpha \cdot h_i)
  \]
  其中 \( |S_j| = 120 \) 为每域场景数。
- **偏差缓解**：位置随机化与盲评。
- **评分表开发与验证**：从 OWASP Agentic AI 威胁模型和 NIST AI 风险管理指南推导标准，经团队审查、校准研究（每系统人工评估 200 个智能体响应，测量与自动评判员的一致性）、敏感性分析（变化评判员温度和提示措辞）三阶段验证。
- **覆盖分析**：语义多样性（句内余弦相似度均值 < 0.7）、攻击向量覆盖（直接操纵、社会工程、技术利用等类别各占 15-25%）、复杂度分布（简单单轮 20%、中等多轮 60%、复杂多步 20%）。
- **分析框架**：跨域相关矩阵 \( C_{ij} = corr(r_i, r_j) \)，在 N=8 个智能体-模型组合上计算，用于识别复合漏洞。

## 5. 实验结果与主要发现

### 5.1 跨域风险分布

- 风险并非均匀分布，**D3 工具误用**、**D4 隐私**与**D7 访问控制**是黑盒条件下最容易被触发的三个高风险域，表明智能体在真实工具交互中面临最直接、最可观测的安全缺口。
- **D1 治理（奖励黑客/目标错位）**与**D6 智能体行为（操纵与欺骗）**的风险分数相对较低，但一旦触发往往伴随高严重度，且更依赖多轮累积而非单轮诱导，说明此类风险更难被短对话探测。
- **D2 输出质量**域风险普遍存在但严重度偏低，多表现为事实性幻觉或边界不当表述，而非直接安全违规。
- **D5 可靠性与可观测性**域暴露出显著的行为不一致问题：相同或近义输入在不同轮次、不同会话中可能产生冲突的决策，且智能体很少主动解释其决策依据。

### 5.2 模型间差异

- 四个基座模型（gpt-4.1-nano、mistral-small、gemini-2.5-flash、kimi-k2-instruct）在同一智能体架构下表现出**一致但程度不同的**风险谱系：整体风险排序相似，但绝对分数与触发难易度存在差异。
- 较强的指令遵循能力并不必然等价于更强的安全鲁棒性——部分模型在正常任务上表现更好，却在特定攻击向量（如社会工程式多轮诱导、混淆代理请求）上更易被说服，暗示能力与安全性之间存在非单调关系。
- 安全对齐强度在**单轮直接攻击**上效果明显，但在**多轮渐进式攻击**上普遍衰减，支持"攻击递进"这一场景设计假设的有效性。

### 5.3 架构间差异

- 对比 CrewAI 单智能体（餐厅接待员）与 AutoGen 多智能体（股票咨询助手），发现**多智能体架构引入了额外的攻击面**：
  - 智能体间的消息传递成为新的注入通道，一个被操纵的智能体可将恶意意图传播至其他智能体。
  - 群聊轮询发言机制可能被利用，使攻击者通过影响发言顺序或内容间接操纵整体决策。
  - 专用角色分工导致责任边界模糊，混淆代理类漏洞更易出现。
- 单智能体系统则在工具参数构造与权限边界控制上更易被单点突破。
- 这表明风险分类体系的**域间相关性**在不同架构下呈现不同结构，验证了跨架构评估的必要性。

### 5.4 复合漏洞与跨域相关性

- 跨域相关矩阵显示部分风险域之间存在显著正相关，例如：
  - D3（工具误用）与 D7（访问控制）高度相关——工具层面的注入往往直接导致权限越界。
  - D4（隐私）与 D3（工具误用）相关——数据外泄通常经由被操纵的工具调用实现。
  - D6（操纵欺骗）与 D1（治理）相关——持续目标追求与奖励黑客常表现为欺骗性行为。
- 这一发现支持"复合漏洞"概念：单一弱点的组合可产生远超各域独立评分之和的实际危害，提示风险评估不应仅做域内孤立判断。

### 5.5 评估方法有效性

- LLM 评判员与人工复核在多数域上达到可接受的一致性，但在语义细微、需要上下文判断的域（如 D2 偏见、D6 欺骗意图）上一致性下降，凸显混合评估流程中人工验证环节不可省略。
- 偏差缓解措施（位置随机化、盲评）有效降低了评判员对响应位置或表述风格的敏感性。
- 与 Unit 42 公开发现的定性对照表明，本框架能复现已知漏洞类别，并额外发现若干未被此前报告披露的风险模式。

## 6. 讨论

- **黑盒可行性**：结果证明，仅凭系统描述与公共接口即可系统性发现智能体特有风险，无需源码、内部 API 或框架插桩，降低了红队测试的门槛，使其适用于第三方审计与部署前评估。
- **分类体系驱动 vs. 随机探测**：以七域分类体系为条件生成场景，使覆盖更均衡、可复现，避免了随机 fuzzing 式的低效与偏斜。
- **安全对齐的边界**：实验揭示当前安全训练主要防御单轮显式违规，对多轮、隐式、跨工具的复合攻击防御不足，呼吁面向智能体交互特性的新型对齐与防护机制。
- **评估即治理**：将抽象风险类别映射到可观察行为与可量化分数，为合规、审计与风险管理提供了可操作的桥梁。

## 7. 主要贡献与创新点

- 提出**首个分类体系驱动、完全自动化、黑盒可用的智能体 AI 红队测试框架**。
- 定义**七域风险分类体系**，并细化为 35 个可观测子风险，连接抽象威胁建模与可执行评测。
- 设计 **SAGE-RT 自动化对抗场景生成方法**，通过种子提示、演化算子与多样性约束系统化生成多轮攻击场景。
- 提出**两阶段混合评估方法**（LLM 评判员 + 人工验证），含域特定评分表、偏差缓解与跨域相关分析。
- 在跨架构、跨模型的真实智能体系统上实证验证框架的有效性，并揭示复合漏洞与多智能体架构的额外攻击面。

## 8. 局限性与未来工作

- **未与现有红队方法进行直接实验对比**，有效性验证主要依赖内部一致性与定性对照。
- **依赖 LLM 评判员**，在语义微妙的风险域上可能引入评判偏差，且评判员本身的安全性未充分讨论。
- **场景生成亦由 LLM 驱动**，可能继承其固有偏见与知识盲区，导致部分现实攻击向量未被覆盖。
- **算力与成本未报告**，难以评估框架在大规模部署下的可扩展性与经济性。
- **评测范围有限**：仅两个智能体系统、四个基座模型，泛化性有待更多架构与领域验证。
- 未来方向可能包括：扩展分类体系至更多新兴风险（如多模态智能体、具身智能体）、引入对抗性自适应攻击、将框架集成到持续部署流水线，以及探索自动化修复与防护建议生成。

## 9. 结论

论文针对智能体 AI 在生产部署中暴露的新型安全风险，提出了一套分类体系驱动、黑盒可用、完全自动化的红队测试框架。通过七域风险分类体系、SAGE-RT 场景生成与混合评估方法的结合，该框架能够在无需特权访问的条件下系统性发现智能体特有漏洞，并在跨架构、跨模型的实证中揭示风险分布规律、复合漏洞结构及多智能体架构的额外攻击面。研究强调了当前安全对齐对多轮、隐式、跨工具攻击的防御不足，为智能体安全评估、合规审计与防护机制设计提供了可操作的框架基础。

## 摘要
随着大语言模型从问答系统演进为通用智能体，评估必须超越静态答案正确性，以考察多模态感知、多步执行、工具使用和产物交付。然而，现有基准往往受限于特定任务类型、执行环境或评分协议，限制了其在部署决策中的可比性、可解释性和可靠性。我们提出 DAREBench（Deployment-Aware and Reliable Evaluation of Models as Agents，面向部署且可靠的模型即智能体评估），一个旨在刻画工作负载变化并支持可靠智能体评估的基准。DAREBench 构建在共享的 OpenClaw 执行环境之上，将选自 22 个来源基准并经过适配的 233 个任务组织为由输入模态和执行形式定义的 2×3 工作负载矩阵，并在统一的基于契约的协议下进行评估，同时采用基于证据的评分审计。我们评估了 23 个商业 API 模型和 12 个本地部署的开放权重模型，共进行 7,587 次模型—任务运行，报告准确率和 token 消耗，并给出 API 模型的参考成本。结果表明，没有任何单一模型能在所有工作负载组中占据主导；文本和多模态任务呈现出不同的准确率—成本权衡；本地开放权重模型在若干组中具有竞争力，但总体上仍落后于前沿商业模型。这些发现表明，智能体部署和模型选择应考虑工作负载特征、部署模式以及准确率—成本权衡，而不是依赖单一的综合得分。

## Abstract
As large language models evolve from question-answering systems into general-purpose agents, evaluation must move beyond static answer correctness to assess multimodal perception, multi-step execution, tool use, and artifact delivery. However, existing benchmarks are often tied to specific task types, execution environments, or scoring protocols, limiting their comparability, interpretability, and reliability for deployment decisions. We introduce DAREBench (Deployment-Aware and Reliable Evaluation of Models as Agents), a benchmark designed to capture workload variation and support reliable agent evaluation. Built on a shared OpenClaw execution environment, DAREBench organizes 233 tasks selected and adapted from 22 source benchmarks into a $2\times3$ workload matrix defined by input modality and execution form, and evaluates them under a unified contract-based protocol with evidence-based score auditing. We evaluate 23 commercial API models and 12 locally deployed open-weight models over 7,587 model--task runs, reporting accuracy and token consumption alongside reference costs for API models. Results show that no single model dominates all workload groups, text and multimodal tasks exhibit distinct accuracy--cost trade-offs, and local open-weight models are competitive in several groups but still trail frontier commercial models overall. These findings suggest that agent deployment and model selection should consider workload profiles, deployment mode, and accuracy--cost trade-offs rather than rely on a single aggregate score.

## 1. 论文的核心问题与整体含义

- **背景**：大语言模型正从静态问答系统演变为通用智能体，需要具备多模态感知、多步规划、工具调用、动态工作区操作与产物交付能力。
- **核心问题**：现有智能体评估基准通常绑定特定任务类型、执行环境或评分协议，导致结果难以横向比较、难以解释，也难以直接支撑部署决策。
- **论文提出的三个关键质疑**：
  - **可解释性**：单一总分掩盖了模型在不同输入模态、执行流程和工具依赖下的强弱差异。
  - **可归因性**：不同基准使用不同 agent scaffold、工具接口和运行时，模型能力与运行时兼容性混杂。
  - **可信度**：开放式智能体任务中，LLM Judge 可能把未执行工具、超时、缺失产物或空输出误判为成功。
- **整体含义**：论文提出 DAREBench，将评估目标从“静态答案正确”转向“部署感知、工作负载分层、证据可审计”的智能体评估，主张模型选型应综合工作负载、部署模式和准确率—成本权衡，而非依赖单一排行榜。

## 2. 论文提出的方法论

- **核心思想**：
  - 构建共享执行环境、统一任务契约和统一评分协议，使跨来源基准任务可以在同一运行时下比较。
  - 用“输入模态 × 执行形式”的 2×3 工作负载矩阵组织任务，揭示模型在不同工作负载下的差异。
  - 引入基于证据的评分审计，检测并纠正 LLM Judge 的不支持正分。

- **任务形式化**：
  - 每个任务表示为  
    \(\tau_i = (p_i, W_i^0, T_i, C_i, G_i, t_i^{max})\)，分别对应任务指令、初始工作区、可用工具集、产物契约、任务评分器和时间预算。
  - 产物契约 \(C_i = \{(a_{i,j}, \phi_{i,j})\}\) 指定必须输出的文件路径及有效性谓词。
  - 契约满足度 \(Sat(W^*, C_i)\) 要求最终工作区中所有指定产物存在且通过谓词验证。

- **工作负载分类**：
  - 模态维度：Text、Multi-Modal。
  - 执行形式维度：Single-Step、Multi-Step、Multi-Step+Tools。
  - 笛卡尔积形成六个组：Text-SS、Text-MS、Text-MT、MM-SS、MM-MS、MM-MT。
  - 每个源基准按主导模态和执行形式确定映射到某一组，任务继承该组标签。

- **任务构建**：
  - 从 22 个公开基准中抽取候选任务，经三阶段筛选：
    - 可行性过滤：无法定义明确产物契约或可靠评分器的任务被移除。
    - 难度过滤：单步任务若 Qwen3.5-27B 三次均正确则移除；有难度标注时保留 medium/hard。
    - 代表性过滤：按源基准类别结构人工选择，避免过度代表某一类别。
  - 最终得到 233 个任务。

- **评分模式**：
  - **Automated**：规则化验证确定性答案或产物。
  - **LLM-based Judge**：对开放式输出使用固定 LLM Judge，按人工 rubric 输出分项分数并加权。
  - **Hybrid**：规则可验证项与语义判断项按固定权重组合。
  - 任务分数归一化到 [0,1]。

- **证据审计算法**：
  - 对所有涉及 Judge 的正分，先用确定性后置规则进行高召回预过滤，触发条件包括弱执行证据、无实际写入、无工具调用、token 异常等。
  - 可疑案例交给来自不同模型家族的 meta-judge，输入包括任务提示、执行轨迹、最终产物、rubric、原评分与理由。
  - 若 meta-judge 判定原正分整体不支持，则任务分置零；否则保留原分。
  - 审计分数：\(s^{audit}_{m,i} = (1-h_{m,i}) s_{m,i}\)，其中 \(h_{m,i}\in\{0,1\}\) 表示是否确认不支持。
  - 论文识别的 Judge 幻觉模式包括：rubric leakage、deadlock loop、pseudo-tool-call credulity、output instability、timeout-with-credit 等。

- **指标与效率核算**：
  - 报告总体审计准确率与六个工作负载组的组级准确率。
  - 报告平均 token 消耗和估计美元成本。
  - 成本按四类 token 计算：未缓存输入、输出、缓存读取、缓存写入，乘以对应每百万 token 单价。
  - API 模型使用 OpenRouter 参考费率；本地模型使用托管参考费率，仅作经济参考，不代表本地 vLLM 实际服务成本。

## 6. 论文的主要结论与发现

- **没有单一模型在所有工作负载组中占优**：
  - Claude-Opus-4.8 在 Text-SS（98.8）、Text-MT（65.3）、MM-MT（61.8）最强。
  - GPT-5.5 在 Text-MS（83.6）和 MM-SS（90.0）最强。
  - Gemini-3.1-Pro 在 MM-MS（88.5）最强。
- **本地开放权重模型有竞争力但整体落后**：
  - Qwen3.6-27B 是最强本地默认模型，总体约 59.8，接近部分早期商业模型，但落后前沿商业模型约 15 个百分点。
  - Qwen3.6-35B-A3B 总体约 56.6，是较低激活参数成本的 MoE 替代方案。
  - 8B/9B 小模型在完整 agent loop 中不稳定。
- **文本与多模态任务呈现不同准确率—成本权衡**：
  - 文本 Pareto 前沿：MiMo-V2.5、MiMo-V2.5-Pro、GPT-5.5。
  - 多模态 Pareto 前沿：MiMo-V2-Omni、MiMo-V2.5、GPT-5.4、Gemini-3.1-Pro、Claude-Opus-4.8。
  - 文本任务在低于 $0.02 区间已接近精度—成本饱和点；多模态前沿斜率更陡，提升性能需要更明显增加成本。
- **token 消耗与美元成本排序解耦**：
  - GPT-5.4-mini token 消耗最低；Gemini-3.5-Flash token 消耗最高。
  - 成本最低：文本为 MiMo-V2.5（约 $0.006），多模态为 MiMo-V2-Omni（约 $0.003）。
  - 成本最高：文本为 Claude-Sonnet-4.6（约 $0.436），多模态为 Claude-Opus-4.6（约 $0.293）。
  - MiMo-V2.5 token 消耗高但成本低；Claude-Opus-4.6 token 消耗

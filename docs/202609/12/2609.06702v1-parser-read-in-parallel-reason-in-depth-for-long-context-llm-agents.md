## 摘要
顺序记忆智能体通过逐块读取长文档并维护一个紧凑的记忆状态来处理长文档，这将文档遍历与推理深度耦合在一起。这种耦合导致对证据位置的敏感性，并使推理延迟与文档长度呈线性关系。我们提出 PARSER，它将读取与推理解耦。一组轻量级子智能体各自绑定到单个块，并行读取整个文档，而一个主智能体通过迭代的分散-收集轮次进行深度推理：每一轮中，它向所有子智能体广播一个查询，聚合返回的证据，并根据目前发现的内容制定更深入的后续查询。这种解耦设计将所有可学习行为集中在主智能体上，并用强化学习对其进行优化，而子智能体保持为冻结的现成模型。在上下文范围从 7K 到 896K token 的多跳问答上，采用 4B 骨干的 PARSER 平均优于最强的顺序记忆基线 5.7 分，在 896K token 时优于 12.0 分。扩展到 9B 骨干时，PARSER 超过 DeepSeek-V4-Pro 6.3 分。受控实验证实，PARSER 对证据位置、顺序和距离的扰动具有鲁棒性，而这些条件会导致顺序方法出现大幅准确率波动，同时将推理延迟最多降低 11 倍。

## Abstract
Sequential memory agents process long documents by reading chunks one after another while maintaining a compact memory state, coupling document traversal to reasoning depth. This coupling introduces sensitivity to evidence placement and ties inference latency linearly to document length. We introduce PARSER, which decouples reading from reasoning. A bank of lightweight subagents each bound to a single chunk read the entire document in parallel, while a lead agent reasons in depth through iterative scatter--gather rounds: at each round it broadcasts a query to all subagents, aggregates the returned evidence, and formulates a deeper follow-up query conditioned on what has been found so far. This decoupled design concentrates all learnable behavior in the lead agent, which is optimized with reinforcement learning, while the subagents remain frozen off-the-shelf models. On multi-hop QA with contexts ranging from 7K to 896K tokens, PARSER with a 4B backbone outperforms the strongest sequential memory baseline by 5.7 points on average and by 12.0 points at 896K tokens. Scaling to a 9B backbone, PARSER surpasses DeepSeek-V4-Pro by 6.3 points. Controlled experiments confirm that PARSER is robust to perturbations in evidence position, order, and distance, conditions that cause large accuracy swings in sequential methods, while reducing inference latency by up to 11x.

# PARSER 论文中文结构化总结

## 一、核心问题与研究动机

- **背景**：长文档多跳问答中，证据常稀疏分布在数十万甚至近百万 token 中。尽管模型上下文窗口已达百万 token，仍存在“context rot”和位置偏差：证据越不靠边界越容易被忽略，准确率随输入增长显著下降。
- **现有范式的问题**：以 MemAgent、ReMemR1 为代表的**顺序记忆智能体**逐块读取文档，并将当前块与历史记忆压缩更新。其结构性缺陷是：
  - **读取顺序绑定推理顺序**：文档被按物理顺序遍历一次，证据相关性必须在信息不足时被判断。
  - **对证据位置、逻辑顺序、相对距离高度敏感**：中间位置证据易被覆盖；逆逻辑顺序时前置证据可能被丢弃；证据间距越大越易被逐次记忆更新挤出。
  - **延迟随文档长度线性增长**：T 个块形成 T 步依赖链，无法并行。
- **核心洞见**：文档的阅读顺序由文档决定，而问题的推理顺序应由问题决定。顺序记忆智能体让前者驱动后者，导致上述瓶颈。
- **整体含义**：论文提出 **ParSer**，将“阅读”与“推理”解耦——阅读并行化、推理顺序化，把文档长度从“依赖深度”转化为“并行宽度”。

## 二、方法论

- **核心思想**：采用 **Scatter–Gather 架构**：
  - **Lead agent**：从不直接接触原始文档 token，只接收问题 q，在 ReAct 式多轮循环中进行思考与行动。
  - **Subagents**：每个轻量级子智能体绑定一个文档块，只读取自己的块，并针对 lead agent 广播的查询返回局部证据或 `Unknown`。
- **算法流程（文字版）**：
  1. 初始化 lead agent 轨迹 H，包含系统提示与问题 q。
  2. 对最多 K 轮循环：
     - Lead agent 生成思考 z_t 与动作 A_t。
     - 若 A_t 包含最终答案，则返回答案。
     - 若 A_t 包含查询，则进入 **Scatter 阶段**：所有 T 个子智能体并行处理同一查询，各自检查自己的块；再进入 **Gather 阶段**：聚合返回的 findings 为观测 R。
     - 将本轮生成与观测追加到 H。
     - 若动作无效，则追加 `InvalidActionHint`，继续循环。
  3. 达到 K 轮或 lead agent 给出答案后结束。
- **关键设计细节**：
  - 每一轮所有块都在同一查询下被对称读取；块不会被永久丢弃，后续轮次可用新查询重新访问。
  - 跨块依赖通过**多轮查询链**解决：第 k 轮发现的条件化第 k+1 轮查询，而非依赖文档顺序的记忆传播。
  - 子智能体输出 JSON 格式证据或 `Unknown`；多数块 abstain，被聚合时丢弃，减少解码计算。
  - 子智能体运行在非 thinking 模式，使用 SGLang 并发调度；固定块前缀可复用 KV cache（Radix Cache + cache-aware router），减少重复 prefill。
- **训练与优化**：
  - 只训练 **lead agent**，子智能体保持冻结的现成模型。
  - 使用 **RLVR**：二值 exact-match 奖励 `r(q,y)=EM(a_pred, a_gold)`，不使用格式奖励，因为 lead agent 使用 backbone 原生多轮工具调用格式。
  - 使用 **GRPO** 优化，目标包含重要性比、PPO clip、KL 正则；观测 token 被 mask，策略梯度只作用于 lead agent 生成的 token。
  - 训练配置：Qwen3.5-4B/9B 为 backbone；训练时 K≤9、每轮最多 2048 token、块大小 512 token；推理时 K≤12、块大小 4096 token。
- **复杂度直觉**：
  - Full-context prefill 为 O(n²)；MemAgent 与 ParSer 按块编码为 O(n²/c)。
  - MemAgent 解码计算随生成 token 与块数增长；ParSer 子智能体输出短且稳定，且 c 个子智能体可并行，墙钟延迟进一步下降。
  - 关键限制：若高并发下 KV cache 被驱逐，子智能体需每轮重新 prefill，prefill 从 O(n²/c) 变为 O(Kn²/c)，会削弱延迟优势。

## 六、主要结论与发现

- **准确率显著提升**：
  - 4B ParSer 平均 84.6%，9B 平均 86.8%，分别超过最强顺序记忆基线 5.7 和 6.7 个百分点。
  - 在 896K token 极长设置下，4B 和 9B 分别领先 12.0 和 9.9 个百分点。
  - 9B ParSer 平均超过 DeepSeek-V4-Pro 6.3 个百分点。
- **长度不变性**：ParSer 在 7K 至 896K 范围内准确率近乎平坦；顺序记忆与 full-context 基线随长度显著退化。
- **鲁棒性**：对证据绝对位置、逻辑顺序、相对距离的扰动均保持稳定；MemAgent/ReMemR1 在这些条件下大幅波动。
- **延迟优势**：单并发下 896K 时相比 MemAgent 约 **11×** 降低（876s vs 78s）；并发 16 时仍保持约 1.7×（102s vs 59s）。
- **RL 有效但非唯一来源**：无 RL 的 ParSer 已优于 MemAgent/ReMemR1 且长度稳定；RL 进一步提升，4B 平均从 74.42 到 84.57，9B 从 76.24 到 86.79。
- **子智能体规模饱和**：4B 子智能体已足够，9B 子智能体无明显进一步提升，说明任务被分解后足够简单。
- **块大小影响**：块越大性能越差，full-document 单子智能体显著下降，说明分块本身有助于缓解 context rot。
- **兼容性**：lead agent 可协调 thinking 子智能体与 DCI 子智能体，均优于对应 standalone 基线。

## 七、优点

- **架构解耦清晰**：将“并行读取”与“顺序推理”分离，直击顺序记忆的结构性瓶颈。
- **训练高效且聚焦**：只训练 lead agent，子智能体冻结，训练成本与文档长度无关；利用原生工具调用格式，无需格式奖励。
- **并行与缓存优化**：Scatter–Gather 使所有块并行读取；KV cache 前缀复用降低重复 prefill。
- **鲁棒性验证扎实**：三类受控扰动实验直接证明方法对证据位置、顺序、距离不敏感。
- **实验覆盖较广**：多 backbone、多长度、多并发、多消融，并包含 OOD 评估与案例研究。
- **兼容性强**：lead agent 可搭配 direct-answer、thinking、DCI 等不同子智能体实现。
- **失败分析诚实**

## Abstract
Large language model (LLM) driven multi-agent systems have shown promise in complex clinical reasoning, yet existing approaches rely on static strategies and lack persistent clinical memory, preventing self-evolving from prior diagnostic successes and failures. We present EMR, a self-evolving medical multi-agent system via Experience Mining and Reuse. EMR introduces a hierarchical clinical experience library that organizes accumulated knowledge into three levels: clinical principles, diagnostic patterns, and representative cases. During inference, EMR emulates multidisciplinary consultation: a planner agent coordinates domain-specific department agents for specialized reasoning, while a summary agent synthesizes their analyses into a final decision. Critically, EMR automatically extracts correct diagnostic insights and failure-related warnings from multi-agent reasoning trajectories, incrementally updating the experience library to guide future cases. # EMR：通过经验挖掘与复用的自进化医疗多智能体系统——论文总结

## 一、核心问题与研究动机

- **背景**：LLM 驱动的多智能体系统在复杂临床推理（多症状表现、鉴别诊断、跨科室会诊）中展现出潜力，已成为医疗 AI 的重要范式。
- **核心痛点（两大局限）**：
  - **静态性**：现有医疗多智能体系统依赖固定的推理策略与角色分配，面对复杂或未见病例时容易重复出现同类诊断错误。
  - **无持久记忆**：每个任务被当作孤立实例处理，无法从既往成功经验中学习，也无法规避已遇到的诊断失误。
- **核心主张**：缺失的关键是**显式且持久的经验抽象**。系统不应只演化提示词或工作流，而应从自身推理轨迹中提炼**可复用、可迁移、模型无关**的知识，同时捕捉成功策略与系统性失败模式。
- **临床对应**：这种经验在临床实践中天然对应积累的诊断指南、常见推理启发式以及代表性患者案例。

## 二、方法论：EMR 框架

### 2.1 整体思想

EMR 将**结构化多智能体协作系统**与**显式经验库**结合，使智能体在不更新模型参数的前提下实现持续进化。流程包含三部分：多智能体医疗系统、经验挖掘、经验复用。

### 2.2 多智能体医疗系统（模拟多学科会诊）

- **规划智能体（Planner）**：在问题级和选项级识别相关医学领域，避免下游智能体冗余或无关探索。公式：
  - Dq = LLM(q, Er | rp, πq)
  - Do = LLM(q, O, Er | rp, πo)
- **科室智能体（Department Agents）**：针对每个领域 d ∈ Dq ∪ Do 进行专科推理，条件为问题、选项、领域及检索经验：
  - ad = LLM(q, O, d, Er | rd, πd)
  - 所有分析汇总为 A = {ad | d ∈ Dq ∪ Do}
- **总结智能体（Summary Agent）**：作为协调型会诊专家，整合跨科室证据并做反思性推理，解决矛盾、纠正局部错误：
  - ŷ, asum = LLM(q, O, A, Er | rs, πs)

### 2.3 经验挖掘

- **轨迹生成**：记录完整推理过程 τ = (q, O, Dq, Do, A, asum, ŷ)，与真实答案 y 比对判定成功/失败。
- **经验收集**：ε = Collect(τ, y | rc, πc)，将轨迹蒸馏为自然语言的紧凑经验条目，分为两类：
  - **Golden Experience（黄金经验）**：来自成功轨迹，捕捉有效推理策略、诊断原则与验证过的决策模式。
  - **Warning Experience（警示经验）**：来自失败轨迹，总结失败原因、误导性线索与反复出现的错误模式。
- 这种双分类使系统对称地从成功与失败中学习，防止对正确结果的过拟合，并增强错误意识。

### 2.4 经验复用

- **分层经验库**：L = {Lprinciple, Lpattern, Lcase}
  - 原则层（Principle）：抽象诊断规则与高层推理原则。
  - 模式层（Pattern）：可复用推理结构与决策模板。
  - 案例层（Case）：具体、情境化的临床推理示例。
- **更新机制**（三步）：
  1. 检索相关经验：R = Retrieve(Lt, ε)
  2. 计算语义相似度（余弦相似度）：
     - Sim(ε, R) = max_{εi∈R} e(ε)·e(εi) / (‖e(ε)‖‖e(εi)‖)
  3. 更新规则：
     - 若 Sim(ε, R) < θ，则 Lt+1 = Lt ∪ {ε}（视为新颖，直接加入）
     - 否则 Lt+1 = (Lt \ R) ∪ LLM_Process(R, ε)（由 LLM 决定合并为更紧凑表示或丢弃）
- **检索机制**：Er = Retrieve(L, c, k)，按层次依次检索高层原则 → 推理模式 → 具体案例，并将检索结果注入规划、科室与总结智能体，作为外部指导。

## 六、主要结论与发现

- **性能全面领先**：
  - Qwen3-8B 下平均准确率从 MDAgents 的 77.8 提升至 **81.1**；GPT-4o 下达 **93.9**。
  - 相比 MDAgents 平均准确率分别提升 **3.3%、2.0%、1.5%**。
  - MedQA 达 **96.8**（较 EvolveR +4.1），MedMCQA 达 **89.2**（+0.6），在复杂 USMLE 风格题上增益更大。
- **经验是核心增益来源**：去掉经验后性能下降 6.7%，退化到静态系统水平；即使去掉规划与科室智能体，保留经验仍仅下降 2.9%，说明经验可部分补偿角色分解的缺失。
- **层级贡献排序**：Principles（去掉 -4.6%）> Patterns（-2.5%）> Cases（-1.2%），原则层是最核心的可迁移知识。
- **警示经验不可或缺**：仅用 Golden 经验下降 2.6%，Warning 经验起到“护栏”作用。
- **经验可迁移**：强模型挖掘的经验可提升弱模型，弱模型经验也能反向增益强模型（双向迁移）；跨数据集迁移同样有效，说明经验库捕捉的是通用医学推理知识而非数据集特定启发式。
- **θ 最优值 0.85**：过低引入噪声，过高导致经验稀疏。
- **四类反复失败模式**：参数化知识过度依赖、医学概念混淆、浅层因果推理、多智能体集体幻觉。
- **通用增强性**：集成到 MDAgents（MedQA 93.8→96.5）与 RECONCILE（92.1→94.8）均稳定提升，说明经验机制与架构无关。

## 七、优点

- **方法创新**：首次在医疗多智能体系统中引入显式、分层、可迁移的经验挖掘与复用机制，兼顾抽象泛化与细粒度临床 grounding。
- **双向学习**：同时利用成功（Golden）与失败（Warning）经验，避免只学正确样本带来的过拟合，增强鲁棒性。
- **无需参数更新**：通过外部经验库实现自进化，模型无关、可跨骨干迁移，部署灵活。
- **高效低成本**：去除昂贵的多轮讨论机制，以经验驱动冲突解决，token 与延迟均优于现有医疗多智能体基线。
- **可解释性强**：经验以自然语言存储，人类可读，可提供可操作的推理指导。
- **实验充分**：消融、迁移、敏感性、泛化、效率、规模等多维度验证，结论支撑较为扎实。
- **鲁棒性好**：在经验库仅保留 10% 或注入 40% 噪声时仍显著优于无经验系统。

## 八、不足与局限

- **模态单一**：仅针对文本医学问答基准，未纳入医学影像、实验室信号、电子健康记录等多模态临床信息。
- **经验质量依赖底层 LLM**：错误或幻觉推理轨迹可能引入噪声经验；虽相似度更新机制可部分缓解，但缺乏更强的验证与过滤策略。
- **检索机制局限**：主要依赖语义相似度与层级抽象，难以刻画医学病例间的复杂因果关系；经验库增长后检索效率与长期维护面临挑战。
- **偏差与安全风险**：
  - 经验可能放大偏差，过度代表特定推理风格、疾病分布或临床假设。
  - 可能加剧用户对 AI 医疗建议的过度依赖。
  - 涉及真实患者数据时存在隐私与安全合规问题。
- **计算开销**：多智能体协作仍显著高于单智能体，资源受限场景下可扩展性受限。
- **验证环境受限**：仅在受控离线基准上评估，未经真实临床环境验证，输出不应视为临床建议；未来需人类在环评估与临床安全约束。

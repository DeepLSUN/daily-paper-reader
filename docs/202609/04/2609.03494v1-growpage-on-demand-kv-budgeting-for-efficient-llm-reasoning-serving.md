## 摘要
长输出推理使得键值（KV）缓存成为高效LLM服务的关键内存瓶颈。现有的KV压缩方法通常依赖于预定义的每请求预算，并且仅调整保留哪些KV状态，导致总容量在整个解码过程中固定不变。然而，推理工作负载表现出显著的请求变化：不同的请求需要不同的KV容量，并且单个请求的注意力需求在生成过程中会演变。我们引入了GrowPage，一种将KV容量视为运行时资源的按需KV预算框架。GrowPage维护轻量级的双时间尺度查询摘要，以捕获近期和长期的注意力行为，并利用它们的相对注意力工作集来估计需求演变。在每个容量边界处，GrowPage要么在当前分配内压缩KV状态，要么在出现更广泛需求时获取额外的物理页面。通过与PagedAttention的页面级内存抽象集成，GrowPage保持了连续批处理和前缀缓存。在多个模型上的推理基准实验表明，GrowPage相比现有方法实现了更优越的性能-吞吐量权衡。

## Abstract
Long-output reasoning has made the key--value (KV) cache a critical memory bottleneck for efficient LLM serving. Existing KV compression methods usually rely on a predefined per-request budget and adjust only which KV states are retained, leaving the total capacity fixed throughout decoding. However, reasoning workloads exhibit substantial demand variation: different requests require different KV capacities, and the attention demand of an individual request evolves during generation. We introduce \textbf{GrowPage}, an on-demand KV budgeting framework that treats KV capacity as a runtime resource. GrowPage maintains lightweight dual-timescale query summaries to capture recent and long-term attention behaviors, and uses their relative attention working sets to estimate demand evolution. At each capacity boundary, GrowPage either compresses KV states within the current allocation or acquires an additional physical page when broader demand emerges. By integrating with PagedAttention's page-level memory abstraction, GrowPage preserves continuous batching and prefix caching. Experiments on reasoning benchmarks across multiple models show that GrowPage achieves a superior performance--throughput trade-off over existing approaches.

## GrowPage 论文详细总结

### 1. 核心问题与研究动机

- **背景问题**：大语言推理模型（如 DeepSeek-R1、Qwen3）通过生成长思维链（CoT）来解决复杂任务，但会产生数千至数万 token 的长输出，导致 KV 缓存急剧增长，成为限制 LLM 推理服务吞吐量的主要内存瓶颈。
- **现有方法的不足**：已有的 KV 缓存压缩方法（如 H2O、R-KV、G-KV、ThinkKV、Zipage 等）大多依赖**预定义的每请求固定 KV 预算**，仅决定保留哪些 KV 状态（token 选择策略），而在整个解码过程中总容量固定不变。
- **关键洞察**：作者通过实验发现 KV 需求存在**双重动态性**：
  - *跨请求异质性*：不同请求所需的最小充分 KV 预算差异巨大（实验表明同一模型下可从 512 跨越至 8192 以上，甚至存在无法在任意固定预算下可靠解决的请求）。
  - *请求内时间变化*：单个请求在解码过程中，注意力稀疏度会不断变化，在不同推理阶段呈现集中与弥散交替的状态，即 KV 需求本身是非平稳的。
- **核心论点**：固定预算的做法本质上只是在"浪费内存"与"容量不足"之间平移操作点，无法真正适配推理请求的动态需求。因此应将 KV 容量视为一种**运行时按需分配的资源**，而非预设的静态配额。

### 2. 方法论

#### 2.1 核心思想

GrowPage 将 KV 容量视为动态可调的运行时资源，在推理过程中根据对请求注意力需求变化的在线估计，动态选择以下两种动作之一：
- **Compress & Hold**：需求收紧时，在当前物理页分配内压缩历史 KV 状态，留出空闲槽位。
- **Grow by One Page**：需求扩张时，从全局空闲页池获取额外的物理页。

#### 2.2 理论基础

- 论文将注意力集中程度与所需 KV 容量进行形式化关联。定义 **p-coverage attention demand** \(D_p(a_t)\) 为覆盖 p 比例注意力质量所需的最少 KV 状态数。
- **定理 3.1** 证明了在值向量有界条件下（\(\|v_i\|_2 \le V_{max}\)），给定近似误差容限 δ 的最小最坏情况 KV 容量恰为 \(D_{1-\delta/(2V_{max})}(a_t)\)。直观含义：注意力越分散，保持输出质量所需的健壮 KV 容量越大；注意力越集中，所需容量越小。结合注意力分布的非平稳性，从理论上支撑了动态调整 KV 容量的必要性。

#### 2.3 在线需求估计

- **双时间尺度查询摘要**：对每个请求和注意力层维护两个指数移动平均（EMA）查询表示：
  \[
  \bar{q}_t^x = \beta_x \bar{q}_{t-1}^x + (1-\beta_x) q_t, \quad x \in \{S, L\}
  \]
  - 短期摘要（\(\beta_S = 0.9\)）：捕获近期注意力行为。
  - 长期摘要（\(\beta_L = 0.999\)）：作为历史参考基准。
  - 在 pre-RoPE 空间中维护以避免旋转位置编码带来的平均失真。
- **需求趋势信号**：在每次容量边界处，计算短/长期查询摘要下各自的历史注意力 Top-p 工作集比率（\(r_t^S\) 与 \(r_t^L\)），并定义需求趋势信号 \(\Delta_t = r_t^S - r_t^L\)。\(\Delta_t < 0\) 意味着注意力趋于集中；\(\Delta_t > 0\) 表示工作集扩张。
- **决策规则**：\(\Delta_t > \tau\)（默认 \(\tau = 0\)）则选择 Grow by One Page，否则执行 Compress & Hold。

#### 2.4 容量控制与系统集成

- **Compress & Hold**：KV 选择按层和注意力头独立执行。重要性分数取双时间尺度注意力分数的最大值 \(s_{i,\ell,h} = \max(a^S_{i,\ell,h}, a^L_{i,\ell,h})\)。结合块局部保留与全局 Top-k 选择，保证压缩不覆盖某些历史区域。压缩后释放恰好一个物理页的 KV 槽位。
- **Grow by One Page**：从全局空闲页池申请新页并追加到请求的块表中，无需改变注意力或块表接口。
- **PagedAttention 集成**：容量决策直接映射到物理页抽象上，兼容连续批处理（continuous batching）、前缀缓存（prefix caching）和 CUDA Graph 执行。使用预分配的查询状态池避免频繁 GPU 内存分配；只有在容量边界才调用密集的注意力估算，平均开销不到解码时间的 0.32%，主路径上每次解码只需轻量就地更新 EMA 状态。
- **内存压力回退机制**：当全局空闲页不足时，增长请求自动回退为压缩，防止个别请求垄断共享 KV 池；继承 Zipage 的异步压缩管线，使 KV 压缩与解码重叠。

### 6. 主要结论与发现

- GrowPage 在两个推理模型上均取得最佳的性能-吞吐量权衡。相比 FullKV，在保持可比 Pass@1 的前提下，将平均 TPS 提升约 60-64%；相比 Zipage，在 DeepSeek-R1-Distill-Llama-8B 上平均 TPS 从 1936 提升至 2417（约 +24.8%），在 Qwen3-8B 上从 1853 提升至 2174（约 +17.3%），同时精度改善或持平。
- 在混合异构工作负载下，固定预算仅能沿精度-吞吐量 Pareto 前沿平移，而 GrowPage 能以更低的平均 KV 预算、更高的并发度与吞吐超越固定预算的最优折中点。
- **双时间尺度信号的有效性得到验证**：Δ_t 与未来注意力需求变化之间的 Spearman 相关系数为 0.78，符号一致率 80.3%；反事实分析显示增长优势随 Δ_t 增大而持续上升。
- 按需分配能够匹配请求级需求异质性：请求的最小充分固定预算类别越高，GrowPage 分配的自适应平均容量也越大。
- 运行时开销极低：每次容量事件总开销约 43 ms，仅占对应页面解码时间的 0.32% 左右。
- 系统级事件分析表明，合理判断"何时增长"比"增长/压缩的频率"更为重要；随机策略虽频率相同但精度与吞吐均明显下降。

### 7. 优点

- **问题定位准确**：精准识别出固定 KV 预算在推理负载中的根本矛盾——需求既跨请求异质又在请求内非平稳，并用观察实验（图 2、图 3）有力支撑这一问题定义。
- **理论支撑扎实**：定理 3.1 将注意力集中度与最坏情况容量需求联系起来，为"注意力动态变化要求容量动态调整"提供了严格的形式化基础。
- **系统-算法协同设计出色**：将在线需求估计与 PagedAttention 页面抽象紧密耦合，粒度自然（每次增长恰好一页），同时保留连续批处理和前缀缓存等关键生产特性，克服了此前许多 KV 压缩方法"算法省内存但系统不增效"的通病。
- **信号设计轻量且可解释**：双时间尺度 EMA 查询摘要不依赖历史查询序列，内存与序列长度无关；信号 Δ_t 有清晰的物理解释，与未来需求呈强单调相关。
- **实验验证充分**：多角度消融、信号有效性分析、策略对比、运行时开销拆解以及请求级容量对齐分析，形成较为完整的证据链。

### 8. 不足与局限

- **算力与规模有限**：实验仅在单张 A100 GPU 上完成；缺少在更大规模（多卡、多节点）和生产级推理引擎（如正式 vLLM 或 TensorRT-LLM）上的验证，实际生产负载下的调度压力与扩展性有待进一步探索。
- **模型中类覆盖局限**：仅验证了 8B 量级的两个模型，未覆盖更大参数规模的推理模型（如 70B 级或 MoE 架构），也未考虑更长上下文（百K级）场景下的表现。
- **省略若干重要信息**：未详细报告实验中的请求到达模式、批调度策略细节、压缩的具体 kernel 实现，可能影响复现性。
- **增长策略保守性**：GrowPage 采用单调增长而非主动收缩的策略。附录实验表明主动收缩（Shrink）虽然吞吐更高但精度下降 7.2 个百分点。这种保守设计避免了信息不可逆丢失，但也意味着在真正低需求场景下可能存在内存利用不充分的空间。
- **依赖压缩本身的准确性**：当全局内存不足而触发回退压缩（fallback）时，请求可能被反复压缩，造成累积性信息损耗。此类请求的成功率是否会随解码长度增加而劣化，论文未给出长时间维度上的分析。
- **基线预算设置存在不确定性**：固定预算方法（Zipage、R-KV 等）在每个数据集上使用单一大小的预算，且未见对多预算的彻底扫描对比（除混合负载外），可能未完全展示这些方法各自的最优操作点。
- **可解释性与泛化性**：在线需求估计信号依赖注意力分数，对于某些非注意力密集的推理模式（如检索或工具调用）是否仍然有效，目前缺少针对性验证。

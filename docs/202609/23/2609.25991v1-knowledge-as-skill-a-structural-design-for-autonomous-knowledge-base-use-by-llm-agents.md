## 摘要
检索增强生成（RAG）使大语言模型（LLM）能够访问外部知识，但其传统的“检索—拼接—生成”流水线会替模型做出检索决策。随着工具使用与智能体循环变得日益可靠，智能体可以自行决定是否检索、检查什么以及何时停止。这一转变暴露出新的瓶颈：智能体可能并不知道知识库中包含什么。传统知识库将文档以匿名文本块的形式暴露出来，关于其范围、用途、来源或关系的信息十分有限。我们提出 Knowledge-as-Skill，一种使知识库可发现、可导航且自描述的组织方案。它包含三个层次：以 SKILL.md 为核心的发现层；每个目录一个 index.md 的导航层；以及包含带有 YAML frontmatter（用于标注主题、类型、来源和生命周期）的文档的知识层。该设计遵循开放知识格式（OKF）和 Skill 协议，且无需修改智能体框架。我们还提供了 knowledge-as-skill，一条将 PDF、Word 文件、网页导出内容和笔记等异构集合转换为该结构的流水线。在 WixQA 企业客户支持基准上的初步评估中，我们的方案获得 0.889 的 Factuality 和 0.816 的 Context Recall，而 Corpus2Skill 报告值为 0.767 和 0.708。其 Faithfulness 略低，Context Precision 更低，且交互轮次更多。由于模型、提示词和知识包构建方式不同，这些结果属于跨工作的方向性证据，而非受控比较。

## Abstract
Retrieval-augmented generation (RAG) gives large language models (LLMs) access to external knowledge, but its conventional retrieve-concatenate-generate pipeline makes retrieval decisions on behalf of the model. As tool use and agent loops become more reliable, an agent can decide whether to retrieve, what to inspect, and when to stop. This shift exposes a new bottleneck: the agent may not know what a knowledge base contains. Traditional knowledge bases expose documents as anonymous text chunks with limited information about scope, purpose, provenance, or relations.   We propose Knowledge-as-Skill, an organization scheme that makes a knowledge base discoverable, navigable, and self-descriptive. It has three layers: a discovery layer centered on SKILL.md; a navigation layer with one index.md per directory; and a knowledge layer containing documents with YAML frontmatter for topic, type, provenance, and lifecycle. The design follows the Open Knowledge Format (OKF) and the Skill protocol without modifying the agent framework. We also provide knowledge-as-skill, a pipeline for converting heterogeneous collections of PDFs, Word files, web exports, and notes into this structure.   In a preliminary evaluation on the WixQA enterprise customer-support benchmark, our setup obtains 0.889 Factuality and 0.816 Context Recall, compared with reported Corpus2Skill values of 0.767 and 0.708. It obtains slightly lower Faithfulness, lower Context Precision, and more interaction turns. Because the models, prompts, and knowledge-package construction differ, these results are directional cross-work evidence rather than a controlled comparison.

# 论文总结：Knowledge-as-Skill

## 1. 核心问题与整体含义

- **背景**：检索增强生成（RAG）是让 LLM 访问外部知识的主流方案，但其传统“检索—拼接—生成”流水线是**工作流驱动**的：无论问题是否与知识库相关、是否可凭参数化知识回答，系统都会先检索并注入证据。模型只是上下文的被动接受者。
- **转变与动机**：随着模型推理与工具使用能力增强、上下文变长、智能体循环更稳定，检索决策权可以下放给模型（是否检索、检查什么、何时停止）。但这暴露了一个此前被隐藏的瓶颈：**智能体不知道知识库里有什么**。
- **核心痛点**：传统知识库为检索器的召回率而优化，文档以“匿名文本块”形式暴露，缺少范围（scope）、目的、来源、关系等信息。固定流水线只需“拼接—回答”，而自主探索者的第一问是“这些是什么、值不值得继续读”。
- **整体含义**：论文主张知识库需要面向智能体重新设计，使其**可发现（discoverable）、可导航（navigable）、自描述（self-descriptive）**，从而能像“技能”一样被使用。知识（facts）与技能（way of doing something）不同，但当知识具备清晰边界、结构、文档与访问协议时，智能体可以像用技能一样用它。

## 2. 方法论

### 2.1 核心思想
- 知识不应在任务开始时被整体注入上下文，而应由智能体**随推理推进按需拉取（pull）**，形成“渐进披露（progressive disclosure）”。
- 设计遵循 **Open Knowledge Format（OKF）** 与 **Skill 协议**，在知识库根目录加入 Skill 兼容的 `SKILL.md`，无需修改智能体框架。

### 2.2 三条设计原则
- **分层暴露（Layered exposure）**：不同文件暴露不同粒度信息——发现层给触发描述，导航层给目录与一句话摘要，知识层承载完整内容；每次深入阅读都以上一步决策为条件，使上下文成本与相关性挂钩。
- **自描述（Self-description）**：每份文档说明覆盖范围、能回答什么问题、相关概念、来源、何时可能过期，使智能体在读正文前就能估计相关性。
- **入口与结构分离（Separated entry and structure）**：`SKILL.md` 只描述范围、用法与边界，不含领域知识；索引独立维护知识结构，内容增长不会破坏发现入口。

### 2.3 三层结构
- **发现层：`SKILL.md`**
  - YAML frontmatter 含 `name`、`description`（触发条件）、`type`；放入框架 skills 目录后，名称与描述可常驻系统提示作为轻量发现元数据。
  - 正文保持简短，规定范围、排除项、导航规则、常见入口、新鲜度约定与**显式停止条件**（防止反复探索无关知识库）。
- **导航层：每目录一个 `index.md`（knowledge bundles）**
  - 知识库组织为嵌套目录（bundle），每层 `index.md` 是该层地图。
  - 条目格式为“**链接 + 一句话描述**”，而非裸文件名列表。该要求被视为导航核心：缺失或含糊的描述会使导航退化为随机打开文件；索引同时提供一条补充关键词/向量检索的访问路径。
- **知识层：带 frontmatter 的文档**
  - 必填字段：`type`、`title`、`description`；附加字段：`tags`、`sources`（溯源）、`generated`/`verified`/`stale_after`（生命周期）。
  - 根级 `log.md` 记录更新。文档不仅携带内容，还携带关于自身质量与生命周期的信息。
  - 关键点：一份文档可被多个索引链接，跨主题可发现性内生于设计。

### 2.4 典型端到端交互（6 步）
1. 智能体看到可用技能的名称与描述，判断问题是否匹配该知识库；
2. 读 `SKILL.md` 了解范围、导航规则与边界；
3. 从根 `index.md` 出发选择有希望的 bundle；
4. 用文档 frontmatter 筛选，再决定是否读全文；
5. 证据不足则沿相关索引继续，或判断问题超出范围后停止；
6. 基于实际读过的文档组织答案，对时间敏感断言参考生命周期元数据。

### 2.5 构建流水线 `knowledge-as-skill`（5 阶段）
1. **枚举与转换**：枚举源文件，保留已有 Markdown，其余用 `mdconvert`（MarkItDown 包装）转为 Markdown，并保留目录结构；
2. **生成 frontmatter**：记录必填字段、原始来源与生命周期字段；
3. **生成索引**：为每个 bundle 生成 `index.md`，初稿由文档元数据起草，可由人工修订；
4. **生成根 `SKILL.md`**：含范围、触发描述、导航规则、常见入口、新鲜度指引；
5. **验证**：用 `okfcheck` 做 OKF 一致性检查，`-agent-ready` 额外检查发现文件、必需元数据与缺失索引。
- **增量维护**：新文档只需 frontmatter 与一条索引条目，`log.md` 记录变更。

## 3. 实验设计

- **数据集 / 场景**：WixQA——基于 6,221 篇 Wix Help Center 文章构建的企业客服问答基准；评估其中 **200 题专家编写子集**，每题含问题、参考答案与 1–3 个 gold 文档。选择该数据集是为与 Corpus2Skill 保持可比，形成方向性参考。
- **被评估系统**：最小智能体循环。
  - 系统提示包含完整 `SKILL.md`，并要求仅依据知识库回答、只使用实际读过的文档、完成后提交答案；
  - 刻意不嵌入导航策略或答案格式约束，使导航行为主要来自知识结构；
  - 三个只读工具：`list_dir`、`read_file`、`submit_answer`；最大轨迹长度 **15 轮**；
  - 回答模型 **DeepSeek-Flash**，评判模型 **K3**。
- **指标**：复用 Corpus2Skill 发布的指标实现与评测提示。
  - Token F1（SQuAD 式 token 级比较）；
  - Factuality、grounded Faithfulness、Context Recall、Context Precision（LLM judge 五点量表后归一化）；
  - Hallucination Rate（raw Faithfulness ≤ 3 的问题占比）；
  - Turns（智能体轨迹轮数）。
- **对比方法**：仅与 **Corpus2Skill（Sun et al., 2026）** 的报告值进行跨工作方向性对比；论文明确该对比**不是受控比较**。

## 6. 主要结论与发现

- **主要数值结果（Ours vs. Corpus2Skill 报告值）**：
  - Factuality：**0.889 vs. 0.767**（+12.2 个百分点）；
  - Context Recall：**0.816 vs. 0.708**（+10.8 个百分点）；
  - Grounded Faithfulness：0.810 vs. 0.859（更低）；
  - Context Precision：0.761 vs. 0.829（更低）；
  - Token F1：0.412 vs. 0.456（更低，但该词法指标对措辞、长度、格式敏感，且本方提示未约束答案长度/格式）；
  - Hallucination Rate：**双方均为 4.5%**；
  - 平均轮次：**4.015 vs. 2.38**（更多）。
- **核心发现**：呈现“**收益—成本并存**”的模式——显式导航扩大了证据发现范围，答案在事实上更正确；但代价是渐进式探索导致读取更多中间/“过渡”文档，从而降低 Context Precision、增加交互轮次。
- **指标含义辨析**：Factuality 与 Faithfulness 测量不同属性——答案可能与参考答案一致，但对实际读到的证据利用更弱或文本关联更弱。
- **架构层主张**：当智能体负责决定读什么知识时，知识库应暴露**结构、身份与来源**，而不是仅提供匿名可检索块。
- **总体定性**：结果应作为**假设生成式的跨工作观察**，而非“策展式组织因果上更优”的证据；作者呼吁进行受控实验而非给出确定排名。

## 7. 优点

- **问题定位精准且有前瞻性**：抓住 agentic retrieval 时代真正的后端瓶颈——“检索工具化”并不等于“后端可理解”，并指出智能体难以区分“知识缺失”与“查询表述不当”。
- **设计简洁、低耦合**：复用 Skill 协议与 OKF，只需在 skills 目录放置知识包，无需修改智能体框架，落地门槛低。
- **分层渐进披露控制上下文成本**：发现层常驻轻量元数据、导航层一句话摘要、知识层再读全文，上下文开销与相关性绑定。
- **自描述与生命周期管理**：frontmatter 同时承载主题、类型、溯源与生成/验证/过期字段，支持可审计与新鲜度敏感回答，这是常规 RAG chunk 所不具备的。
- **工程完备性**：提供了完整的构建流水线（含 `mdconvert`、`okfcheck`）与增量维护方案，并对每个 bundle 强制“链接 + 一句话描述”这一低成本高收益的约束。
- **与 Corpus2Skill 的关系处理得当**：明确将两者定位为互补（对方强调自动化与冷启动可扩展性，本文强调可控性、可审计性与领域内有界集合的增量维护），并指出多索引链接使跨主题可发现性内生化。
- **学术诚实**：反复声明比较非受控、指标为 LLM judge、小差异需谨慎，并明确列出未做的消融与未来工作。

## 8. 不足与局限

- **实验覆盖窄**：仅 WixQA 200 题、单一企业客服领域；无多数据集、多领域验证。
- **非受控对比与偏差风险**：服务模型、提示词、知识包构建流程、潜在运行时细节均不同，无法归因于结构设计本身；与 Corpus2Skill 的数值差异属方向性参考。
- **缺少关键对照与消融**：未与固定 RAG 基线在相同智能体下比较；未隔离发现元数据、索引、frontmatter、生命周期字段各自的贡献。
- **评测指标脆弱性**：多个核心指标为 LLM-judge 打分，对提示

词与模型选择敏感，缺少人工标注校验、评分者一致性分析或多次采样的方差/置信区间报告；因此 Token F1、Context Precision 等小幅差异不宜作为结论性证据。
- **成本维度只测了轮数**：仅用 Turns（4.015 vs. 2.38）代理交互代价，未报告 token 消耗、端到端延迟、API 调用成本或上下文峰值占用。渐进式披露的核心卖点本是"上下文成本与相关性挂钩"，但这一点恰恰没有被量化验证。
- **缺少最能分离贡献的基线**：未设置"同一智能体 + 同一知识库，但去掉 `SKILL.md`/`index.md`/frontmatter"的朴素 agentic RAG 对照。这是唯一能把观测到的差异归因于"结构设计"而非"让模型自主探索"这一行为本身的对照条件，其缺失使核心因果主张悬空。
- **索引质量缺乏下界保证**：导航层依赖"链接 + 一句话描述"，而描述初稿由文档元数据自动起草、可人工修订。论文未评估描述质量差时的退化程度，也未给出失败案例分析（如智能体因误导性描述反复进入无关 bundle）。
- **停止条件的有效性未被检验**：`SKILL.md` 中的显式停止条件被作为防止无效探索的机制，但没有报告智能体是否遵守、误停（本可回答却放弃）与漏停（在无关知识库中反复游走）的比例。
- **生命周期字段的效用停留在设计层面**：`generated`/`verified`/`stale_after`/`log.md` 是本文区别于普通 RAG chunk 的亮点，但没有任何实验表明智能体真的据此调整了答案或置信表达；其价值目前只是可审计性的"结构性承诺"。
- **规模与深度可扩展性未知**：实验知识库为 6,221 篇文章，但未考察文档量再增一到两个数量级时，目录嵌套深度、索引维护成本与导航开销如何演化，也未讨论 bundle 划分策略本身的影响。
- **构建流水线的转换损失未评估**：`mdconvert`（MarkItDown 包装）对表格、图片、公式等非纯文本内容的转换质量可能直接影响下游回答，论文未做转换前后对比。
- **概念层面存在未消解的张力**：论文一方面承认"知识（facts）"与"技能（way of doing something）"不同，一方面又主张知识可"像技能一样被使用"。这种类比在发现层（名称 + 触发描述）成立，但在知识层是否仍然成立（例如知识库并不"执行"任何过程、无法定义输入输出契约）并未展开论证。
- **写作与披露的代价**：frontmatter、每目录索引、根级日志均为人工维护负担，论文称"新文档只需 frontmatter 与一条索引条目"，但未估算大规模持续更新场景下的实际人力成本。

## 9. 启示与可延伸的研究方向

- **最紧迫的对照实验**：在相同智能体、相同工具集、相同服务模型下，比较"有结构知识库"与"无结构知识库"（仅 `list_dir`/`read_file`），并进一步做组件消融（发现元数据 / 索引描述 / frontmatter / 生命周期字段）。
- **把成本纳入指标**：将 token 消耗、延迟与上下文峰值与质量指标并列报告，才能真正检验"渐进披露降低上下文成本"这一核心假设；同时可尝试在提示中约束答案长度与格式，以消除 Token F1 的比较噪声。
- **索引质量研究**：把"一句话描述"的生成与校验作为一个独立子问题（自动生成 + 人工抽检 + 面向导航的可读性/区分度评估），并研究 bundle 粒度与层级深度的最优划分。
- **动态与多跳场景**：在知识随时间更新（生命周期字段真正生效）与需要跨多个索引综合的多跳问题上评估，才符合"知识即技能"的完整设想。
- **与自动化路线互补**：论文已明确将自身定位为对 Corpus2Skill（自动化、冷启动、可扩展）的补充——即面向"领域内有界、需要可控与可审计"的知识集合。两者结合（自动构建 + 人工策展校验）可能是更现实的工程路径。
- **协议层的推广**：若 OKF/Skill 协议成为共识，则"知识包"有望像工具定义一样被智能体生态统一发现与复用，这需要标准化工作与更广泛的跨领域验证。

## 10. 总体评价

这是一篇**立场鲜明、设计务实、披露诚实**的工作。它的最大贡献不在于数值提升，而在于把一个即将被忽视的瓶颈摆到台面上：当检索决策权交给智能体后，知识库本身必须从"可检索的匿名文本块集合"升级为"可发现、可导航、自描述的资源"。三层结构（`SKILL.md` → 每目录 `index.md` → 带 frontmatter 的文档）、渐进披露与入口/结构分离三条原则，都是低成本、易落地、与现有智能体框架零耦合的设计。

但它的证据强度明显弱于其主张强度。单数据集 200 题、非受控的跨工作报告值对比、全 LLM-judge 指标、缺失的关键基线与消融、完全空白的成本与可扩展性测量，都意味着"策展式结构更好"目前只是**一个被合理叙述的假设**，而非被证明的结论。作者对此的自觉披露值得肯定，也恰好为后续工作指明了清晰的实验清单：同条件对照、组件消融、成本量化、索引质量与规模化验证。

对读者的实用建议：若你在构建企业知识库或领域智能体，本文的结构设计与构建流水线可直接借鉴，其工程价值独立于实验结论；但在引用其数值结论时，应严格按作者自述将其视为方向性观察。

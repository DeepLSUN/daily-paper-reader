## 摘要
多智能体系统可以通过并发执行工作来降低复杂任务的延迟。已有若干开创性运行框架支持多智能体系统。然而，当前多智能体运行框架的可扩展性往往受限于中央编排器分配任务和协调工作者的能力。为解决这一局限，我们提出Agensh，一种可扩展、无中央编排器的自组织多智能体运行框架：并发工作者执行多智能体协作循环，以异步方式持续收集上下文、认领并自行分配子任务、采取行动并共享发现、验证结果并合并进展。该循环由智能体组织基础设施支持，包含三个组件：共享工作区保存已提议、进行中和已完成的工作；消息接口让工作者相互通信；共享上下文保留可复用的发现与工作意图。为测试Agensh的可扩展性，我们在五个最难的ProgramBench任务上使用GPT-5.6-sol（high）进行评估。从1个扩展到128个智能体，将平均最终测试通过率从19.31%提升至28.78%，相对提升约49%。更大的组织更早达到相当的测试通过率。在pandoc上，从1个扩展到1,024个智能体，将最终测试通过率从33.89%提升至55.06%。工作者轨迹进一步表明，随着组织规模增长，不同形式的自组织协作逐渐涌现并标准化。这些结果揭示了智能体数量作为多智能体组织的一种新扩展维度，可用于拓展通用智能的前沿，并为在严格延迟约束或时间预算下的复杂任务提供实用解决方案。

## Abstract
A multi-agent system can reduce latency on complex tasks by executing work concurrently. Several pioneering harness frameworks support multi-agent systems. However, the scalability of current multi-agent harnesses is often constrained by a central orchestrator's capacity to allocate tasks and coordinate workers. To address this limitation, we introduce Agensh, a scalable self-organized multi-agent harness without a central orchestrator: concurrent workers execute a multi-agent cooperation loop, continuously gathering context, claiming and self-assigning sub-tasks, taking action and sharing findings, verifying results, and merging progress in an asynchronous manner. The loop is supported by the agentic organization infrastructure comprising three components: a shared workspace holds proposed, ongoing, and completed work; a message interface lets workers communicate; and shared context retains reusable findings and work intentions. To test the scalability of Agensh, we evaluate it on the five hardest ProgramBench tasks with GPT-5.6-sol (high). Scaling from 1 to 128 agents raises the mean final test-pass rate from 19.31% to 28.78%, an approximately 49% relative improvement. Larger organizations reach comparable test-pass rates earlier. On pandoc, scaling from 1 to 1,024 agents raises the final test-pass rate from 33.89% to 55.06%. Worker trajectories further show that different forms of self-organized cooperation gradually emerges and standardizes as the organization grows. These results reveal the number of agents as a new scaling dimension for multi-agent organizations to expand the frontier of general intelligence, offering a practical solution for complex tasks under hard latency constraints or time budgets.

## 1. 核心问题与整体含义

- **背景**：单智能体系统受限于单一上下文窗口、单一动作流与单一记忆流，且串行执行导致复杂现实任务延迟高。多智能体系统通过并发执行降低延迟，已成为扩展方向。
- **核心问题**：现有主流多智能体 harness（Codex sub-agent、Claude Code sub-agent/agent teams、Copilot fleet、Kimi Agent Swarm）普遍采用 **orchestrator-worker（中心编排器—工作节点）** 结构。该结构需要训练有素的编排器进行任务分解与调度，整体可扩展性从根本上受限于编排器的管理与协调容量。
- **整体含义**：论文提出 **Agensh**——一种**无中心编排器**的可扩展自组织多智能体组织 harness。工作节点并发、异步运行，通过轻量级"智能体组织基础设施"共享状态与进展，将智能体数量确立为多智能体组织的一种**新扩展维度**，并声称可拓展通用智能的前沿。

## 2. 方法论

### 2.1 核心思想
- 以**自组织协作**取代中心化调度：每个工作节点自主发现、认领子任务，自主选择协作者、划分职责、建立并修订工作流。
- 用**轻量级共享基础设施**连接各节点的本地活动与组织共享状态，使个体进展累积为集体成果。

### 2.2 多智能体合作循环（五步，异步并发）
1. **Gather context（收集上下文）**：读取共享用户目标、当前状态、同伴进展与消息、累积发现，并与环境交互以规划下一步。
2. **Claim sub-task（认领子任务）**：提出子任务并将范围以 `CLAIM` 追加到共享上下文；若与他人的 claim 重叠或冲突，通过直接消息协商解决。
3. **Take action（采取行动）**：通过可用工具在本地解决子任务；一旦获得可能帮助他人的发现，即写入共享上下文。
4. **Verify results（验证结果）**：对照子任务验收标准检查本地进展，不满足则修改方案直至满足。
5. **Merge progress（合并进展）**：将贡献合并入共享工作区并发布更新（变更内容、思路、验证证据）；若合并冲突，则引入最新同伴进展、解决冲突后重新合并。
- 完成后回到第 1 步，基于新整合的工作与最新同伴更新进入下一轮；各节点无需等待同伴完成迭代。

### 2.3 智能体组织基础设施（三组件）
- **共享工作区（Shared workspace）**：以文件系统承载提议中、进行中与已整合的工作；支持并发写、异步读、版本历史与合并冲突暴露。实现上采用 **Gitea**（Git 平台），worker 在私有 checkout/分支上修改并整合到 main 分支，借助 issue 与 PR 协作。
- **消息接口（Message interface）**：基于 **Mattermost**；共享任务频道用于团队公告（低优先级，每轮循环开始时投递），直接消息用于紧急一对一沟通（高优先级，在每次基础设施工具调用返回时投递）；保留对话历史并异步投递，用于解决认领重叠、协商依赖、请求协助。
- **共享上下文（Shared context）**：思想借鉴 DeLM，采用 append-only 数据库 + 近期记忆；worker 发布**类型化短条目**：`OBSERVED`（观察到的参考行为）、`FACT`（已确认事实）、`FAIL`（被证伪的假设，价值最高）、`CLAIM`（进行中的认领）、`PATCH_SUMMARY`（`files= | idea= | evidence=`）。提供 `board_read`、`board_write`、`board_unfold`、`board_grep`（支持逗号 OR、`&` 为 AND）等工具，可检索完整历史。新条目作为高优先级更新，在其他 worker 下次基础设施工具调用返回时转发。

### 2.4 实现与运行时
- **分层设计**：Agensh 是叠加在**单智能体 harness 之上**的组织层。底层 harness 负责本地 agentic 循环（维护对话状态、调用模型、执行工具、产出响应）；Agensh 负责组织级行为（worker 身份、合作协议、事件路由、鲁棒分发、共享工作区访问、消息、共享上下文、恢复与活性机制）。
- **即插即用**：合作循环通过每个 worker prompt 中的工作流指令实现（而非硬编码到运行时）；所有 worker 的 prompt 完全相同，仅 worker ID 不同。可通过轻量适配器接入 Claude Code、Copilot 等不同底层 harness。
- **事件驱动运行时**：每个 worker 由配对 router 监听 Gitea 仓库活动（server-sent event 触发拉取新通知）与 Mattermost 消息（实时连接 + 断线重连补拉）；事件写入持久队列并唤醒 dispatcher，去重后排序合并为下一轮 prompt；失败投递按递增等待重试；router 重启后未完成事件回队并尽可能恢复会话；**空闲 10 分钟**触发提醒；某轮未产生共享上下文条目则触发提醒。
- **上下文投递双路径**：轮次开始时 router 追加队列通知、消息与近期共享上下文；轮次进行中通过基础设施工具调用 wrapper（基于 MCP 工具返回）追加待发直接消息与新共享上下文条目。

## 6. 主要结论与发现

- **智能体数量是新的扩展维度**：固定模型与 harness，增加 worker 数量可同时提升复杂软件重建的**质量**与**速度**。
- **质量收益**：五个最难任务上，1→8→32→128 agent 的平均最终通过率为 19.31% → 20.68% → 26.52% → **28.78%**，1→128 提升 **9.47 个百分点，相对提升约 49%**。
- **延迟收益**：更大组织更早达到相同通过率。例如 pandoc 上 128 agents 在 30 分钟超过 30% 通过率，32 与 8 agents 分别在 60、90 分钟达到，单智能体前 2 小时始终未达该阈值。
- **超大规模验证**：pandoc 上 1→128→1,024 agent 的最终通过率为 33.89% → 50.94% → **55.06%**；1,024 agent 比 128 agent 高 4.12 个百分点，比单智能体高 **21.17 个百分点**。
- **自组织协作随规模涌现并标准化**：
  - **8 agents**：同伴协调——约定技术接口并独立实现组件（gromacs）；自主发现并解决认领重叠（FFmpeg）。
  - **32 agents**：跨多 worker 的集成管理——多个同伴评审贡献，出现反例后撤回批准、作者修复、再评审并由同伴合并（PHP-src）；更广泛的同伴参与沟通。
  - **128 agents**：自组织专业化与工作流标准化——按既往经验选择审阅者并复用关系；将整合责任转交同伴；形成可复用的标准化集成协议（pandoc），并进一步修订为"同伴获授权执行更新、测试、检查、合并全流程"。
  - **1,024 agents**：组织规模的角色专业化——多个 worker 担任 integrator（联系多位候选、选首位有效响应者、取消其他请求后移交）；同领域专家在他人失败后恢复并接管工作，提升组织鲁棒性、避免依赖单个 worker。
- **这些合作形式完全自组织**：worker 自己选择协作者、划分职责、建立并修订

## 摘要
大型语言模型（LLM）智能体必须从训练期间见过的工具泛化到部署时的未见工具。一个关键挑战是工具试用：过度试用会浪费交互预算，而选择性试用则能够探索不熟悉的工具。现有的基于结果的后训练使浪费性试用缺乏引导，而轮级监督可能抑制必要的探索。我们提出 ToolCompass，一种后训练框架，通过根据共享功能组织工具调用表示来引导工具试用。具体而言，ToolCompass 将每个函数类建模为 von Mises–Fisher 分布，并联合减少跨域的函数内差异、增大函数间分离度。这种结构将经验从已见工具迁移到功能相似的未见工具，引导探索远离无关备选工具。ToolCompass 无需真实调用轨迹或访问未见工具，且不带来推理开销。在 AppWorld 和 FTRL 上的实验表明，其在 GRPO、RFT 和 DMPO 上均取得一致提升。相较于原始后训练，它将 AppWorld OOD 任务成功率最多提升 10.71 个百分点，并在两个基准上均优于竞争性基线。

## Abstract
Large language model (LLM) agents must generalize from tools seen during training to unseen tools at deployment. A key challenge is tool trialing, i.e., excessive trials waste the interaction budget, whereas selective trials enable exploration of unfamiliar tools. Existing outcome-based post-training leaves wasteful trials unguided, while turn-level supervision may suppress necessary exploration. We introduce ToolCompass, a post-training framework that guides tool trialing by organizing tool-call representations according to shared functions. Specifically, ToolCompass models each function class as a von Mises--Fisher distribution and jointly reduces intra-function variation across domains and increases inter-function separation. This structure transfers experience from seen tools to functionally similar unseen tools, directing exploration away from unrelated alternatives. ToolCompass requires no ground-truth call traces or unseen-tool access and incurs no inference overhead. Experiments on AppWorld and FTRL show consistent gains across GRPO, RFT, and DMPO. improves AppWorld OOD task success by up to 10.71 percentage points over vanilla post-training and performs best among competitive baselines on both benchmarks.

## 1. 核心问题与研究背景

- **研究动机**：LLM 智能体需通过外部工具（搜索引擎、应用 API 等）完成任务，部署时往往面对训练中未见过的工具（OOD 工具），因此必须将已见工具的功能经验迁移到功能相似的未见工具上。
- **关键矛盾——工具试用（tool trialing）**：
  - 过度试用会浪费交互预算，甚至导致本可完成的任务失败；
  - 但对陌生工具而言，试用-纠错是必要的探索手段，需要通过环境反馈学习工具行为。
  - 因此理想智能体应"减少浪费性调用，但不丧失 OOD 迁移所需的探索"。
- **现有方法的两难**：
  - 基于结果的后训练（如 GRPO）把轨迹级优势均匀分配到所有工具轮次，浪费性试用与有效步骤被一起学习，缺乏引导；
  - 轮级监督方法（MatchTIR 匹配真实调用轨迹、TRACE/StepTool 估计轮次贡献）虽能减少调用，却会抑制对未见工具必要的偏离探索。
- **试点证据**：在 AppWorld 上，MatchTIR 将平均工具调用从 GRPO 的 31.55 降到 20.87，但 OOD 任务成功率反而从 56.75% 降到 53.96%（下降 2.80 个百分点），说明"抑制试用"是有代价的。
- **表征层面的根因**：作者分析 Qwen3.5-9B + GRPO 的 rollout 与工具调用表征，发现表征主要按**应用领域（domain）**聚类，而非按**共享功能（function）**聚类——同域不同功能的调用靠近，同功能跨域的调用远离，因而无法把已见工具经验迁移到功能相似的未见工具。
- **核心研究问题**：如何在后训练中实现 OOD 探索，同时不强化浪费性的工具试用？（即"引导试用"而非"抑制试用"）

## 2. 方法论

### 2.1 核心思想
- 按**共享功能**组织工具调用表征：让实现同一功能的跨域调用彼此靠近（降低函数内差异），让不同功能的调用彼此远离（增大函数间分离），从而把已见工具的经验迁移到功能相似的未见工具，引导探索远离无关备选。
- 不规定"黄金调用序列"，也不估计单轮贡献，因此不直接惩罚探索。

### 2.2 关键技术细节

- **工具调用表征提取（§3.1）**：
  - 对轨迹中每个工具调用 $a_t$，取策略网络第 $l$ 层、调用最后一个 token 的隐状态 $h_t = H^{(l)}_\theta(s_t, a_t) \in \mathbb{R}^{d_h}$；该隐状态通过注意力汇总了所选工具、参数与当前交互状态。
  - 通过轻量投影头 $g_\psi$ 映射并 L2 归一化，得到单位超球面上的 $z_t \in S^{d-1}$，以便用角度相似度刻画关系，并自然定义 vMF 分布。
  - 一个代码块含多个 API 调用时，每个调用在其自身最后 token 处单独提取表征。

- **vMF 分布建模（§3.2）**：
  - 每个函数类 $k \in C$ 建模为 von Mises–Fisher 分布 $p(z|c=k) = C_d(\beta)\exp(\beta \mu_k^\top z)$，$\mu_k$ 为原型方向，$\beta$ 为集中度（$\beta=1/\tau$，$\tau$ 为温度）。
  - 后验类概率为 $\exp(\mu_k^\top z/\tau) / \sum_j \exp(\mu_j^\top z/\tau)$，因 $\mu_k$ 与 $z$ 均为单位向量，内积即余弦相似度。

- **两个损失项**：
  - **降低函数内差异 $L_{var}$**：对 minibatch 中每个调用 $(z_i, c_i)$，最小化其真实函数类分配的负对数似然，使调用向所属功能原型对齐，跨域、跨工具、跨交互上下文地压缩同类分布。
  - **增大函数间分离 $L_{sep}$**：对 minibatch 中每个出现的功能类计算归一化批量方向 $\bar{z}_k$，最小化其与其他类原型之间的 softmax 式相似度，把不同功能类推得更开。
  - 原型在两项损失中均作为 stop-gradient 目标，梯度只经当前表征更新策略与投影头。

- **原型估计**：用指数移动平均（EMA）维护每个功能原型：$\mu_k \leftarrow \text{Normalize}(\alpha \mu_k + (1-\alpha)\bar{z}_k)$，使原型平滑跟踪不断演化的表征空间。

- **联合优化（§3.3）**：
  - 完整目标 $L(\theta,\psi) = L_{post}(\theta) + \lambda_{vMF} L_{vMF}(\theta,\psi)$，其中 $L_{vMF} = L_{var} + \lambda_{sep} L_{sep}$。
  - 宿主目标 $L_{post}$ 可用 GRPO、RFT、DMPO 等任意后训练目标实例化，无需修改其原始形式。

- **训练流程（Algorithm A.1）**：随机初始化投影头与单位原型 → 每个更新步采样轨迹并计算 $L_{post}$ → 收集该 batch 所有工具调用的表征与函数标签 → 计算 $L_{var}$、$L_{sep}$ 并用联合目标更新 $\theta,\psi$ → 对 batch 中出现的功能类计算批量方向并 EMA 更新原型。

- **部署零开销**：投影头与原型仅训练时使用，部署时移除；$L_{vMF}$ 已塑造策略参数 $\theta$，因此推理无需辅助打分模块或额外前向。

### 2.3 与已有方法的对比
- 相比 GRPO 等结果型方法：提供**功能级**监督，同类调用共享方向目标，而非仅给轨迹成败信号。
- 相比 MatchTIR 等轨迹匹配：不规定黄金调用序列。
- 相比 TRACE/StepTool 等轮级贡献方法：不需要估计单轮贡献，也不需冻结的轮级模型。
- 相比 ToolMaster：不需额外教师模型生成试用轨迹。

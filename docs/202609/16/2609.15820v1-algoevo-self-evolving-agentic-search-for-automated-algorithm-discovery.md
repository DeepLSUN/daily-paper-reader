## 摘要
大语言模型通过合成可执行代码推动了自动算法发现的发展，但现有框架将其束缚在具有预定义控制流的刚性搜索流水线中。这一局限限制了自适应推理，阻碍了跨范式迁移，并丢弃了有价值的执行反馈。我们提出 AlgoEvo，一个统一的智能体框架，将自动算法发现转变为交互式、知识累积的过程。自主智能体基于运行时反馈动态检查、诊断和编辑代码。设计技能中心将特定范式的知识与核心发现引擎解耦，使单一工作流能够无缝处理单目标、多目标和多组件设计。同时，分层经验机制将搜索轨迹组织为任务级树以指导探索，并将跨任务模式整合为可复用技能。在六个代表性基准任务上，AlgoEvo 以显著更少的评估次数和更低的 token 消耗匹配或超越了专用方法，展现出强大的任务内积累、跨任务迁移，以及通过灵活激活技能来复现或超越现有最先进性能的能力。

## Abstract
Large language models have advanced automated algorithm discovery by synthesizing executable code, but existing frameworks trap them in rigid search pipelines with pre-defined control flows. This limitation restricts adaptive reasoning, blocks cross-paradigm transfer, and discards valuable execution feedback. We propose AlgoEvo, a unified agentic framework that transforms automated algorithm discovery into an interactive, knowledge-accumulating process. An autonomous agent dynamically inspects, diagnoses, and edits code based on runtime feedback. A design skill hub decouples paradigm-specific knowledge from the core discovery engine, allowing a single workflow to seamlessly handle single-objective, multi-objective, and multi-component design. Meanwhile, a hierarchical experience mechanism organizes search trajectories into a task-level tree to guide exploration and consolidates cross-task patterns into reusable skills. Across six representative benchmark tasks, AlgoEvo matches or surpasses specialized methods with substantially fewer evaluations and reduced token consumption, demonstrating strong intra-task accumulation, cross-task transfer, and the ability to reproduce or exceed existing state-of-the-art performance through flexible skill activation.

## 2. 方法论

### 2.1 问题形式化

- 领域 $D$ 由实例空间 $X_d$、解空间 $Y_d$、目标 $f_d$ 刻画；求解器 $s$ 由可设计策略 $\Pi=(\pi_1,\dots,\pi_K)$ 生成解，算法空间 $S=S_1\times\cdots\times S_K$（$K=1$ 为单启发式，$K>1$ 为多组件联合设计）。
- 算法性能 $F_d(x|\Pi)=\phi_d(f_d(x,s(x|\Pi)))$，多目标时 $\phi_d$ 为超体积等标量指标，统一为越小越好。
- 发现目标：$\Pi^*=\arg\min_{\Pi\in S}\mathbb{E}_{x\sim X_d}[F_d(x|\Pi)]$，受计算预算 $B$ 约束。

### 2.2 核心思想：自演化智能体发现循环

- **状态定义**：第 $t$ 步发现状态 $s_t=(\Pi_t, C_t, E_t, F_d(x|\Pi_t))$，即当前算法、工作上下文（代码、近期修改、诊断观察、中间推理）、经验库、性能反馈。
- **动作空间**（高层设计决策，非底层软件命令）：
  - 不产生候选、不收费：`Inspect`（读源码/执行产物）、`Retrieve`（查询经验库与推理链）、`Edit`（改目标单元源码）、`Terminate`
  - 不产生候选但计评估开销：`Diagnose`（性能归因、识别失效模式）、`Analyse interaction`（度量两单元耦合强度）
  - 产生候选：`Evaluate`、`Commit`
- **奖励与目标一致性**：当动作把算法从 $\Pi_{t-1}$ 更新为 $\Pi_t$，即时奖励 $r_t=F_d(x|\Pi_{t-1})-F_d(x|\Pi_t)$；最大化累积奖励 $\sum_{t=1}^{T} r_t$ 经望远镜求和等价于最小化最终性能 $F_d(x|\Pi_T)$。
- **轨迹异质性**：智能体自行决定何时检查、诊断、编辑、评估，可在修改前做多轮诊断、也可提前评估验证假设、或在后续证据支持下重访被放弃的设计方向。

### 2.3 设计技能中枢（Design Skill Hub）

- **动机**：算法空间 $S$ 的结构依赖范式（构造式启发式、多目标演化算子、耦合的破坏–修复系统在策略角色、接口、有效性原则上完全不同），把差异写进搜索流程会重现框架碎片化。
- **技能声明四项内容**：(i) 可设计策略在 $\Pi$ 中的角色；(ii) 代码接口；(iii) 指导有效修改的原则；(iv) 任务特定评估约定。这些固定了对 $S$ 搜索的约束与归纳偏置，而搜索机制本身不变。
- **生命周期**：任务开始时按声明条件匹配并**激活**技能（$t=0$）；任务结束时（$t=T$）经验被固化进经验库，但**技能在单任务内不更新**，演化仅跨任务触发；当来自**至少两个不同任务**的经验一致支持某一有效设计模式时，该模式被抽象回技能。技能也可编码既有算法设计方法的方法论知识，继承其归纳偏置但保留自主执行过程。

### 2.4 分层经验库（Hierarchical Experience Bank）

- **Level 1 经验卡片**：经验库仅在评估事件处更新，每张卡片记录设计上下文、修改内容、奖励 $r_t$、理由（rationale），是经验库的基本单元，跨评估与任务持久存在。
- **Level 2 任务级经验树**：同任务卡片构成树，节点为卡片，边表示派生关系，按 MCTS 四阶段遍历：
  - **Selection**：节点 $v$ 在当前情境 $q$ 下维护访问计数 $n(v,q)$ 与平均奖励 $\bar r(v|q)$，最大化 $\mathrm{UCB}(v|q)=\bar r(v|q)+c\sqrt{2\ln N / n(v,q)}$；$n(v,q)=0$ 时用全局均值作先验并附探索激励。
  - **Expansion**：经验证的候选卡片挂为其演化来源卡片的子节点。
  - **Evaluation**：评估候选，产生奖励 $r_t$。
  - **Backpropagation**：奖励上溯至祖先，维护子树评估数 $m(v)$ 与累积奖励 $S(v)$，子树价值 $\bar R(v)=S(v)/m(v)$ 估计该设计方向的历史平均收益。
- **Level 3 跨任务整合**：被至少两个任务验证有效的设计模式被抽象进对应设计技能，把具体经验转为范式级知识。
- **情境感知检索**：情境 $q$ 由发现状态与近期反馈检测，可同时成立多种，包括
  - `stagnation`（最近 $\tau_s=4$ 次提交无改进，权重 0.30）
  - `sparse front`（多目标档案相邻点间存在大间隙，权重 0.25）
  - `bottleneck`（单一单元归因质量占比 $>\tau_b=0.5$，权重 0.20）
  - `coupling`（测得交互强度超过 $\tau_c=0.05$，权重 0.20）
- **整体流程（Algorithm 1）**：匹配任务与技能 → 初始化经验树并加载相关卡片 → 检测情境 → 情境 UCB 选节点 → 智能体执行动作 → 若评估则蒸馏卡片、加入经验库、挂子节点、计算奖励、反向传播 → 直至预算耗尽或智能体终止 → 输出最优算法 → 把跨任务有效模式整合进技能中枢。

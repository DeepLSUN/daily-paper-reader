## 摘要
基于检索的推测解码（SD）通过从现有文本中复制续写内容来草拟 token，这适合会反复重现代码、日志和先前尝试的编码智能体。然而，现有方法在智能体流水线中表现不足：大量可复用文本在其语料库中缺失，或存储形式与智能体所输出的形式不同，且其草拟长度忽略了接受长度会因智能体而异并随轮次漂移。我们提出 AgSpec，一个为编码智能体流水线中的现有检索引擎补充其缺失的语料库与草拟长度策略的框架。AgSpec 从会话、工作区和全局语料库中检索，保留正在进行的会话轨迹，并以智能体的输出格式索引已打开文件。它通过离线分析得到的上限来约束每个智能体的草拟长度，并根据验证反馈在线调整长度。在两个仓库级多智能体编码基准上，AgSpec 在大多数评估设置中优于五种基于检索的草拟器和 EAGLE-3，在批量大小为 1 时将生成吞吐量相较于自回归解码提升至多 4.37 倍，在批量大小为 16 时提升至多 4.76 倍。AgSpec 在没有仓库或多智能体流水线的基准上依然有效，表明其增益可广泛泛化到编码智能体。

## Abstract
Retrieval-based speculative decoding (SD) drafts tokens by copying continuations from existing text, which suits coding agents that repeatedly reproduce code, logs, and earlier attempts. Yet existing methods fall short in agent pipelines: much of the reusable text is missing from their corpora or stored in a form that differs from what the agent emits, and their draft lengths ignore that accept length varies across agents and drifts over turns. We present AgSpec, a framework that supplies the corpus and draft-length policies that existing retrieval engines lack in coding-agent pipelines. AgSpec retrieves from session, workspace, and global corpora, retaining the ongoing session trajectory and indexing opened files in the agent's emission format. It bounds each agent's draft length with an offline-profiled cap and adapts the length online from verification feedback. On two repository-level multi-agent coding benchmarks, AgSpec outperforms five retrieval-based drafters and EAGLE-3 in most evaluated settings, raising generation throughput over autoregressive decoding up to 4.37$\times$ at batch size 1 and 4.76$\times$ at batch size 16. AgSpec also remains effective on benchmarks without a repository or a multi-agent pipeline, showing that its gains generalize to coding agents broadly.

# AgSpec 论文中文总结

## 1. 核心问题与整体含义

- **背景**：编码智能体通常以多轮会话方式解决仓库级任务，会话中可能包含多个角色/智能体（如 localizer、coder、executor、reviewer），并反复读取文件、生成补丁、运行测试、重试失败尝试。这种工作负载会大量重复代码、日志和先前输出，天然适合基于检索的推测解码（retrieval-based speculative decoding, SD）。
- **核心问题**：现有检索式 SD 方法在编码智能体流水线中表现不足，主要因为：
  - **语料可用性不足**：多数方法只索引当前调用、预构建 datastore 或池化输出，缺少正在进行的会话轨迹和仓库工作区；文件一旦被 prompt 截断或调用结束，就难以复用。
  - **匹配性不足**：工作区文本通常按“原始文件形式”存储，但智能体实际输出可能是 unified diff、整文件写入、搜索替换等 emission format。例如 diff 中复制行会带空格或减号前缀，导致 token 序列不匹配。
  - **草稿长度策略僵化**：现有方法用固定上限、匹配长度或出现次数决定草稿长度，忽略不同智能体、不同角色、不同轮次和不同 batch size 下接受长度会变化。
- **整体含义**：AgSpec 不改动底层检索引擎，而是为编码智能体流水线补上“检索什么、以什么形式检索、每个智能体草稿多长”的策略层，从而提升生成吞吐，且保持目标模型输出分布不变。它是一个免训练加速框架。

## 2. 方法论

### 2.1 核心思想

AgSpec 在已有检索式 SD 引擎之上运行，组合两类机制：

- **编码智能体感知的检索（coding-agent-aware retrieval）**：按文本来源组织语料，并按智能体输出格式索引工作区文件。
- **智能体感知的草稿长度控制（agent-aware draft-length control）**：用离线 profiled cap 和在线验证反馈共同决定每个 agent 的草稿长度。

### 2.2 三类语料

- **会话语料 \(S_s\)**：保存当前 session 的 prompt、工具输出和生成 token，跨调用、跨 agent 共享；session 结束后丢弃。
- **工作区语料 \(W_r\)**：保存当前 session 打开过的仓库 artifact，随文件访问增长；session 结束后重置。
- **全局语料 \(G\)**：服务启动前构建的静态参考文本，跨 session 固定。
- 前两者称为 **live corpora**，与全局语料分离，因为来源和生命周期不同。

### 2.3 按 emission form 索引工作区

- 第一次打开 artifact 时，AgSpec 将其加入 \(W_r\)：
  - 原始文件形式；
  - 智能体可能写出的形式。例如 unified diff 中，保留行加空格前缀，删除行加减号前缀，因此为每行分别添加带空格和带减号的副本；
  - 若 scaffold 通过工具调用写整文件，则还需添加转义换行和引号后的副本。
- 这样 coder 复制文件行到 patch 时，能匹配到 emission form 副本。

### 2.4 跨语料匹配选择

- 检索引擎用相同 decoding context 后缀查询各语料，得到最长匹配长度 \(m_S, m_W, m_G\)。
- 若 \(m_G > \max(m_S, m_W) + \delta\)，才使用全局语料；否则在 session 和 workspace 中选择更长匹配，平局偏向 session。
- \(\delta\) 是防止全局语料偶然长匹配的 margin，实验中默认 \(\delta=5\)。
- continuation 选择：
  - 全局语料 \(G\) 和会话语料 \(S_s\)：按 next three tokens 分组，选最高频组，平局选最近出现；
  - 工作区语料 \(W_r\)：选第一次出现。

### 2.5 草稿长度控制

- 对 agent \(a_i\)，第 \(i\) 步草稿长度：
  \[
  K_i = \text{clip}(\text{round}(\alpha^{(a_i)} m_i), 1, K^{(M,a_i)}_{\max})
  \]
  其中 \(m_i\) 是匹配长度，\(\alpha^{(a_i)}\) 是在线 scale，\(K^{(M,a_i)}_{\max}\) 是离线 profiled cap。
- 实际草稿长度 \(D_i = \min\{K_i, \ell_i\}\)，\(\ell_i\) 是匹配后可用的 token 数。
- **离线 cap**：从构建 \(G\) 的轨迹中回放，记录可复用长度 \(R\)，估计第 \(k\) 个草稿 token 被接受的概率 \(\Pr(R \ge k \mid M,a)\)。令其超过盈亏平衡接受概率 \(\lambda\) 的最大 \(k\) 为 cap：
  \[
  K^{(M,a)}_{\max} = \max\{k : \Pr(R \ge k \mid M,a) \ge \lambda\}
  \]
- **在线 scale**：每个 agent 的 \(\alpha\) 初始为 1.0，按验证反馈更新：
  \[
  \alpha^{(a_i)} \leftarrow \alpha^{(a_i)} + \eta(\tau - I[A_i < D_i])
  \]
  其中 \(A_i\) 是接受长度，\(I[\cdot]\) 为指示函数，\(\eta\) 为步长。该更新可解释为对 \(R_i/m_i\) 的 \(\tau\)-quantile 做随机次梯度步，目标是以 \(1-\tau\) 概率完全接受。设置 \(\tau = 1-\lambda\)。
- 若草稿完全接受且达到 cap，则跳过更新，避免 cap 截断造成偏差。
- 若检索引擎自带长度策略，AgSpec 取两者中较小值。

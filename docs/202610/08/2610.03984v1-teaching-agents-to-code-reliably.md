## 摘要
自主编码智能体通过阅读代码、运行命令、编辑文件并提交补丁来解决代码仓库问题。额外的推理时计算只有在产生有用修复并提供用于选择修复的可靠证据时，才会带来收益。有三种行为决定这两者，我们认为它们是可教的，而不是规模的副产品，因此策略可以承载这些行为，而不必依赖脚手架。位置多样性仍然狭窄，因为尝试会回到同一位置，额外采样不会增加覆盖。编辑多样性未被利用，因为彼此不同的方法能够解决任何单次运行都无法触及的互补问题。验证会产生误导，因为智能体为自己的补丁编写的测试会接受许多错误补丁。通过执行反馈引导搜索，并将每个补丁与其自身的回退树进行评分，仅使用八样本基线所用智能体步数的 48.1%，就解决了 SWE-bench Verified 中 52.8% 的问题。训练将这些行为迁移到策略中。在从 SFT 和 RL 训练中留出的 270 个问题上，加权监督微调将 pass@1 从 31.9% 提升到 35.2%，将 pass@8 从 46.7% 提升到 51.1%。随后，一个强化目标针对金标准标注的修复和错误变体训练验证器，并奖励能够检测出它们的断言。它将 pass@1 提升到 43.0%，将 pass@8 提升到 60.7%，将验证器精确率从 26.8% 提升到 41.7%，并将错误接受减少一半以上。解决率在三个分布外套件中的两个上有所提升，验证器精确率在全部三个上都有提升；在与已发表的编码器基线相比时，这些增益在 7B、14B 和 30B 规模上依然成立。

## Abstract
Autonomous coding agents solve repository issues by reading code, running commands, editing files, and submitting patches. Extra inference-time compute yields gains only when it produces a useful repair and supplies reliable evidence for choosing one. Three behaviors decide both, and we argue they are teachable rather than byproducts of scale, so a policy can carry them instead of a scaffold. Location diversity remains narrow, since attempts return to the same site and extra samples add no coverage. Edit diversity is left unexploited, since methodologies that differ resolve complementary issues no single run reaches. Verification misleads, since a test the agent writes for its own patch accepts many incorrect ones. Directing search by execution feedback and scoring each patch against its own reverted tree resolves 52.8% of SWE-bench Verified using 48.1% of the agent-steps an eight-sample baseline spends. Training moves these behaviors into the policy. On the 270 issues held out from SFT and RL training, weighted supervised fine-tuning raises pass@1 from 31.9% to 35.2% and pass@8 from 46.7% to 51.1%. A reinforcement objective then trains the verifier against gold-labeled repairs and incorrect variants, crediting the assertions that detect them. It raises pass@1 to 43.0% and pass@8 to 60.7%, lifts verifier precision from 26.8% to 41.7%, and more than halves false acceptance. Resolution improves on two of three out-of-distribution suites and verifier precision on all three, and the gains hold at 7B, 14B, and 30B against published coder baselines.

## 1. 核心问题与整体含义

- **研究背景**：自主编码智能体（coding agent）通过阅读仓库代码、执行命令、编辑文件并提交补丁来解决真实 GitHub issue（如 SWE-bench）。增加推理时计算（多次尝试、自验证）理论上可提升解决率，但论文指出：**额外算力只有在能产出正确修复、且能可靠选出正确修复时才有收益**。
- **核心诊断问题**：论文把"候选覆盖"（coverage，候选集中是否存在正确补丁）与"选择质量"（selection quality，智能体是否最终返回正确补丁）明确区分，认为二者不可互相替代。现有方法在两方面同时失效：
  - **位置多样性狭窄**：多次尝试反复回到同一编辑位置，额外采样不增加覆盖。
  - **编辑多样性未被利用**：不同解题方法论（preamble）能解决互补的 issue，但单一策略无法同时触达。
  - **验证具有误导性**：智能体为自己补丁编写的测试与补丁共享同一错误理解，会接受大量错误补丁。
- **核心主张**：这三种行为（定位、编辑多样化、判别性验证）**是可训练习得的，而非模型规模的副产品**，因此应将其"内化"进策略参数，而不是依赖外部脚手架（scaffold）。
- **整体含义**：作者把可靠修复问题重新表述为"覆盖 + 选择"双瓶颈问题，并给出"测试时诊断 + 两阶段训练"的完整路径，为编码智能体的可靠性提供了一种不依赖规模扩张的改进方向。

## 2. 方法论

### 2.1 核心思想

- **测试时诊断**：用统一 backbone 与 scaffold，对比自验证、单轴诊断、主动定位、盲重试、反应式编辑/位置多样性、样本扩展等程序，发现"反应式位置多样性"（45.0%）优于"主动定位"（42.0%），而"差分验证搜索"（52.8%）最优。
- **差分验证搜索（Differential-Verification Search, DVS）**：为每个 issue 构建最多 8 个候选单元（一个定位 × 一种修复方法），对每个候选在**打了补丁的树**和**回退补丁后的树**上各运行一次智能体自己写的复现脚本：
  - 补丁树通过、回退树失败 → 证明补丁改变了复现所测行为；
  - 加上"仓库既有测试仍通过"和"复现触及改动行"两项检查，得分 1.2；缺一项得 1.0；
  - 只有补丁树通过而回退树无判定 → 0.3；
  - 两树都通过（空洞差分）→ 0 分并剪枝该位置；
  - 得分 ≥ 1.0 即提前停止搜索。
- **训练内化**：先用加权 SFT 让策略学会"用执行反馈引导下一次编辑"，再用 RL 训练验证器"判别错误修复"。

### 2.2 加权监督微调（Weighted SFT）

- **语料构建**：从 500 个 SWE-bench Verified issue 中选取 230 个用于训练，剩余 270 个完全留出；语料含 5,061 条轨迹，记录对话、最终补丁、编辑位置、步数、验证器结果、金标、行为标签。含**对比编辑样本**（同一位置的正确/错误补丁对）与**复现样本**（区分 buggy 与 fixed 行为）。
- **质量层级（Tier）**：T1 权重 1.0（金标解决且被选中或验证器 ≥1.0）；T2 权重 0.6；T3 权重 0.25；其余为 0。
- **加权公式**：

  $$w = w_{\text{tier}} \cdot (1 + \lambda \tilde{\nu}) \cdot \left(1 + \beta\left[1 - \min(1, \text{steps}/S_{\text{ref}})\right]\right)$$

  其中质量项、探索项（λ=1.0，ν̃ 为有效新颖度，含行为相关下限 0.4–0.6）、效率项（β=0.5，S_ref=120）相乘。效率因子从零步的 1.5 降到 120 步的 1.0。

### 2.3 判别性验证的强化学习

- **目标**：SFT 只模仿轨迹，从不奖励"测试成功拒绝错误补丁"；RL 让验证器针对错误程序评估，衡量测试能检测出哪些错误行为。
- **生成对象**：策略对每个训练 issue 产出补丁 P 和测试 T（含断言 {a₁,…,aₙ}），每组 k 次 rollout；组内其他 k−1 个补丁作为**兄弟修复**参与测试评估；金标执行 oracle G 判定补丁是否满足评估测试。
- **变异评估（Mutation Evaluation）**：
  - 用确定性算子 + 与策略不同的冻结模型，从当前补丁生成变异体，覆盖边界、值、逻辑、控制流、效果五类故障；
  - 断言失败才计为"检测到"，未捕获的崩溃不计分；
  - 评分集 S = oracle 拒绝的变异体 + oracle 拒绝的兄弟修复；通过金标测试的候选被排除；
  - 记录被检测子集 Kill(T)。
- **轨迹奖励**：

  $$R_{\text{traj}} = w_c \cdot \text{CORRECT} + w_v \cdot \text{VERIF} + w_e \cdot \text{EDIT} + w_p \cdot \text{PROCESS}$$

  权重 w_c=3.0、w_v=1.0、w_e=0.4、w_p=0.2；辅助项总范围 ≤2.6 < 3.0，保证任何正确 rollout 的标量奖励都高于任何错误 rollout，辅助项只决定同正确性类别内的排序。
- **验证项**：

  $$\text{VERIF} = \underbrace{\frac{|\text{Kill}(T)|}{|S|}}_{\text{密集斜率}} + \underbrace{\lambda_{fp}\mathbf{1}[\text{Kill}(T)=S]}_{\text{不动点奖励}} + \underbrace{h(T)}_{\text{诚实性}}$$

  λ_fp=0.5；h(T) 对假接受 −0.5、假拒绝 −0.25、与 oracle 一致为 0，故 VERIF ∈ [−0.5, 1.5]。
- **断言信用（Assertion Credit）**：用 GRPO，组内归一化得轨迹优势 A_traj；kill 矩阵 K_{m,i} 记录断言 i 是否检测出变异体 m，信用按

  $$\tilde{c}_i = \sum_{m: K_{m,i}=1} \frac{\omega_{\text{cls}}(m)}{\kappa_m}, \quad c_i = \tilde{c}_i / \sum_j \tilde{c}_j$$

  分配（每个被检测变异体把一个类别加权单位分给检测它的断言），再做归一化；token 优势

  $$A_t = A_{\text{traj}} + \beta \cdot G \cdot A_{\text{traj}}^+ \cdot s_t$$

  门控 G 在补丁解决 issue 或测试检测出全部评分变异体时为 1；断言奖励只在 G=1 且 A_traj>0 时施加。文中指出该信用可解释为加权覆盖博弈的 Shapley 分配，但不提供收敛保证。
- **超参**：GRPO 组大小 k=6，PPO clip 0.2，无 KL 惩罚。

- **充分性评价**：
  - **优点**：把"覆盖"与"选择"两瓶颈分别用测试时诊断和训练内化两条线验证，形成闭环；每个关键设计（差分验证、断言信用、加权 SFT）都有对应消融；留出仓库（90 个未见仓库）与迁移基准（DeepSWE、PolyBench、Pro）检验了泛化性，而非只在训练分布内报数。
  - **不足**：主结果集中在单一 backbone（30B）与单一 scaffold（mini-SWE-agent），7B/14B 仅复现全流程而未做完整消融；测试时成本仅以 agent-steps 计，未纳入 token 长度、执行时间与 GPU 成本，跨程序效率比较的解释力有限；变异对抗体的强度依赖冻结的 Opus-4.8 标签，跨模型可迁移性有待进一步检验。

## 6. 主要结果与结论

### 6.1 测试时诊断（表 1）

- **反应式位置多样性（45.0%）> 主动定位（42.0%）**：说明"先做再根据反馈调整位置"比"先规划位置再编辑"更有效，额外采样只有落在新位置上才转化为覆盖。
- **差分验证搜索（52.8%）最优**：在相同尝试预算下显著高于自验证、盲重试与样本扩展，表明"在补丁树与回退树上各跑一次复现"能有效过滤空洞测试，把算力导向真正改变行为的候选。
- **成本**：DVS 用 132,697 步，低于八样本基线的 275,943 步，即"更高解决率 + 更低算力"。

### 6.2 训练内化（Base → SFT → +RL）

- **SFT**：加权 SFT 让策略学会"用执行反馈引导下一次编辑"，覆盖（候选集中存在正确补丁的比例）与选择质量同时上升，说明定位与编辑多样化可以习得，而非仅靠采样。
- **+RL**：判别性验证 RL 在 SFT 基础上进一步提升选择质量，验证器的错误拒绝率与错误接受率同时改善，平衡准确率与选择准确率上升，FPR 下降。
- **总体**：训练后的策略在不依赖外部脚手架搜索的情况下，接近甚至超过测试时 DVS 的效果，支持"把可靠性内化进参数"的核心主张。

### 6.3 验证器判别（表 4）

- 在跨策略共享的冻结候选库上，完整 RL 训练出的验证器在错误拒绝率、正确接受率、平衡准确率、接受覆盖、选择准确率、FPR 等指标上均优于 Base 与仅正确性 RL；仅正确性 RL 的验证器几乎不改善判别力，说明**验证能力需要专门奖励，不能从"做对题"中自然涌现**。

### 6.4 生成器-验证器交换与迁移（表 15/16）

- **交换实验**：固定生成器换验证器、固定验证器换生成器，交互项显示生成与验证能力可部分解耦，但二者匹配时收益最大。
- **跨错误源迁移**：从熟悉算子迁移到留出算子、再到排除生成器语义变异、再到独立生成器的自然错误修复，检测率虽有下降但仍显著高于基线，说明验证器学到的是"能区分行为差异的测试"，而非对特定变异算子的记忆。

### 6.5 消融

- **RL 目标各组件（表 8）**：去掉密集斜率、不动点奖励、诚实性项或断言信用，性能均下降，完整目标最好。
- **奖励权重（表 10）**：w_c=3.0 使辅助项上限（2.6）严格小于正确性奖励，保证"正确 rollout 的标量奖励高于任何错误 rollout"这一排序不变量，组大小 k=6 为性价比最优点。
- **断言信用（表 18）**：均匀信用与打乱信用均弱于按 kill 矩阵的类别加权分配，验证了"把每个被检测变异体的信用分给检测它的断言"这一设计的必要性。
- **零幸存者审计（表 17）**：排除了"看似提升实为数据泄漏或幸存者偏差"的可能。
- **SFT 加权（表 19/20）**：质量层级、探索项、效率项三者相乘优于任一单独使用。

## 7. 优点与创新

1. **问题重构清晰**：把可靠修复拆成"覆盖"与"选择"两个可独立度量的瓶颈，避免把二者混为一谈。
2. **差分验证搜索**：用"补丁树 vs 回退树"的差分信号直接检验复现测试的判别力，从机制上针对"测试与补丁共享同一错误理解"这一根因，而非事后过滤。
3. **可训练的可靠性**：证明定位、编辑多样化、判别性验证三种行为可通过加权 SFT + 判别性 RL 内化，减少对外部搜索脚手架的依赖。
4. **奖励设计严谨**：辅助奖励上限严格小于正确性奖励，保证排序不变量；断言信用与 Shapley 分配的联系提供了理论直觉。
5. **实验控制严格**：统一 backbone、工具、上下文与尝试预算，训练/评估 issue 完全隔离，并用留出仓库与多基准检验泛化。

## 8. 局限与不足

1. **规模与骨干单一**：主结果基于 30B 模型，7B/14B 未做完整消融，结论对更小或更大模型的外推需谨慎。
2. **成本度量不完整**：agent-steps 未折算 token、执行时间与 GPU 成本，DVS 的实际经济性可能被高估。
3. **变异标签依赖外部模型**：变异对抗体与语义变异依赖冻结的 Opus-4.8，若该模型有系统性偏差，可能影响验证器学到的判别边界。
4. **断言信用无收敛保证**：论文自己指出其信用分配可解释为加权覆盖博弈的 Shapley 分配，但不提供收敛保证。
5. **验证器仍需执行环境**：差分验证依赖可回退的补丁树与可运行的复现脚本，对无法回退或复现成本极高的仓库适用性受限。
6. **未报告算力细节**：缺少 GPU 型号、数量与训练时长，复现成本难以估计。

## 9. 对领域的影响与启示

- **从"多采样"转向"多样本定位 + 判别性验证"**：单纯扩大尝试次数在位置多样性狭窄时收益递减，应把算力投在扩展编辑位置与修复方法论的多样性上。
- **验证能力需要专门训练**：让智能体"做对题"不等于让它"会判题"，判别性验证应作为独立目标优化。
- **可靠性可内化**：把测试时脚手架中的有效行为蒸馏进策略参数，是降低推理成本、提升部署可靠性的可行路径。
- **可复用的诊断工具**：差分验证搜索与断言信用分配可作为通用组件，迁移到其他需要"生成 + 验证"的智能体任务（如数据修复、配置修复）。

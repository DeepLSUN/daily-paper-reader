## 摘要
现有反应式图形用户界面（GUI）智能体在长时程、动态场景中往往失败，其中意外干扰会引发注意力分散和级联故障。为解决这一问题，我们提出PrecogUI，一种预认知架构，将范式从反应式执行转变为主动式决策。具体而言，我们设计了一个主动式经验池（PEP），它将反复出现的异常和成功模式作为“状态-动作-结果”元组缓存在双记忆存储库中。此外，我们引入了一个主动式模拟执行器（PSE），它学习在给定候选动作的情况下预测下一个符号化UI布局，从而能够尽早避免异常，并根据预测可靠性对候选动作进行排序。最后，一个预认知执行控制器（PEC）融合这些先验和预测，优先处理预见到的异常，并通过闭环纠错机制确保执行鲁棒性。为了进行稳健评估，我们开发了AutoTraj，一个自动数据生成引擎，以构建InterfereBench，一个面向具有强干扰的长时程任务的基准。实验表明，PrecogUI在InterfereBench上超越了最先进方法，同时在公开基准上保持有竞争力的性能。代码将公开可用。

## Abstract
Existing reactive Graphical User Interface (GUI) agents often fail in long-horizon, dynamic scenarios, where unexpected disturbances trigger attention-diverting and cascading failures. To address this, we propose PrecogUI, a pre-cognitive architecture that shifts the paradigm from reactive execution to proactive decision-making. Specifically, we design a Proactive Experience Pool (PEP), which caches recurring anomaly and success patterns as "state-action-result" tuples in a dual-memory repository. Furthermore, we introduce a Proactive Simulation Executor (PSE) that learns to forecast the next symbolic UI layout given a candidate action, enabling early anomaly avoidance and ranking candidate actions by predicted reliability. Finally, a Pre-cognitive Execution Controller (PEC) fuses these priors and predictions, prioritizes handling of foreseen anomalies, and ensures execution robustness through a closed-loop error correction mechanism. For robust evaluation, we develop AutoTraj, an automatic data-generation engine, to construct InterfereBench, a benchmark for long-horizon tasks with strong disturbances. Experiments demonstrate that PrecogUI surpasses state-of-the-art methods on InterfereBench while maintaining competitive performance on public benchmarks. The code will be publicly available.

## 1. 核心问题与整体含义

- **研究动机**：现有 GUI 智能体大多采用**反应式（reactive）范式**，即仅依赖当前屏幕观测进行决策。在短时程、无干扰环境中表现良好，但在**长时程、动态场景**中极易受意外扰动影响，导致注意力分散并引发**级联失败（cascading failures）**。
- **关键实证观察**：
  - 在 AndroidControl 上注入扰动后发现，**叠加层干扰（弹窗、通知）平均使成功率下降超过 20 个百分点**，而环境级扰动（黑屏、冻结）约下降 10 个百分点。
  - 性能退化**随任务时程单调加剧**：短任务（<5 步）SR ≥ 91%；中等任务（6–15 步）退化明显；长任务（>15 步）SR 降至约 50%。
- **核心问题**：如何赋予 GUI 智能体**预认知规划能力与显式异常处理机制**，以在长时程、动态环境中保持鲁棒性？
- **整体含义**：论文主张将 GUI 智能体从"观察–行动"的反应式执行，升级为"观察–预测–行动"的**主动式决策（proactive decision-making）**范式，融合经验检索、前瞻模拟与闭环纠错。

## 2. 方法论

### 2.1 核心思想
PrecogUI 通过"**经验–前瞻–反馈**"闭环实现鲁棒长时程执行，包含四大模块：AutoTraj（数据构建）、PEP（经验池）、PSE（模拟执行器）、PEC（执行控制器）。

### 2.2 关键技术细节

**（1）AutoTraj 数据构建流水线（三阶段）**
- **自主探索器（Explorer）**：优先解析 UI 视图层级定位可操作元素，缺失时回退到"目标检测 + OCR"视觉流水线。探索价值函数为：
  - $V(s_t) = \alpha \cdot \frac{|E_t \setminus \bigcup_{i<t} E_i|}{|E_t|+\epsilon} + (1-\alpha)\cdot\frac{1}{n(s_t)+1}$
  - 第一项鼓励发现未见过控件，第二项鼓励访问稀有状态；$\alpha \in [0.5, 0.75]$ 为推荐区间。
- **轨迹解析器（Parser）**：两阶段过滤。Stage-1 基于自环（self-loop）与空操作（no-op）统计剪枝，定义 $\rho_{loop}$、$\rho_{noop}$；Stage-2 用高容量 MLLM 评估主题一致性、因果合理性与复杂度，选 Top-K 并结构化标注（目标、步骤描述、动作类型、归一化坐标、UI 框、屏幕差分）。
- **扰动注入器（Injector）**：为每条干净轨迹注入叠加层干扰（通知、弹窗）与环境扰动（黑屏、重复帧、布局突变），由六位专家审核，生成"干净–扰动"配对样本。
- 额外引入 **PolyTouch** 多手势与宏执行层，支持三/四指和弦、捏合/缩放/旋转，以及带时序、守卫、重试、回滚的声明式宏。

**（2）Proactive Experience Pool（PEP）**
- 双记忆结构：
  - **异常记忆 $M_a$**：记录 $(s,a)\mapsto \ell_{anom}$（某状态下动作触发异常）与 $s\mapsto \ell_{anom}$（状态本身即失败），并存储处理动作 $a_{handle}$。
  - **成功记忆 $M_s$**：记录高置信成功转移 $(s,a)\mapsto s'$。
- **状态表示与检索**：将 UI 状态表示为布局签名（元素集合 $\{(type, bbox)\}$），用基于 IoU 的贪心匹配计算相似度：
  - $S_{layout}(L_t, L_m) = \frac{2|M|}{|L_t|+|L_m|}$，其中 $M$ 为 IoU 超过阈值的匹配对集合。
- **动态在线更新**：新异常/成功案例异步追加；采用版本感知更新策略与指数式陈旧衰减，应对冷启动与条目过期。

**（3）Proactive Simulation Executor（PSE）**
- **条件未来布局生成**：基于条件潜在扩散模型（参考 ViMo 范式），以当前布局 $L_t$ 与具体命令 $c_{t,j}=\text{Encode}(a_t, r_j)$ 为条件，预测 $P(\hat{L}^{c_{t,j}}_{t+1} | L_t, c_{t,j})$。
- 与 ViMo 不同，PSE **只生成符号化的 $(type, bbox)$ 元素序列**，而非真实感全屏图像，便于高效几何风险检测。
- **可靠性预测**：用规则识别异常（弹窗遮挡、空白屏、布局几乎不变即冻结/无效），定义布局不相似度 $D_{layout}(L, L') = 1 - S_{layout}(L, L')$，并计算动作–格式对的可靠性得分：
  - $s(a_t, r_j) = D_{layout}(L_t, \hat{L}^{c_{t,j}}_{t+1}) \cdot w(\hat{L}^{c_{t,j}}_{t+1})$
  - 其中 $w \in [0,1]$ 为异常感知权重（非严重异常取 1，严重异常取 0）。

**（4）Pre-cognitive Execution Controller（PEC）**
- **Deep Think & Decision**：驱动基座 MLLM 输出结构化 JSON，含历史验证、内容接地、Think、Action（带 index/relative/absolute 三种坐标格式的候选动作排序）。
- **预认知执行**：先查询 $M_a$，命中则触发 $a_{handle}$；否则用确定性规则 $R_{anom}$ 检查可见异常；状态正常时向 PSE 请求可靠性报告，选择未被标记高风险的最高分动作–格式对。
- **状态监控与自适应恢复**：
  - **停滞（Stagnation）**：布局变化小于阈值 $\tau_c$，用 PSE 次优格式重试。
  - **意外转移（Unexpected Transition）**：布局变化大但语义验证判定错误，执行回滚并将失败对加入临时禁忌列表 $F_t$。
- 算法流程可概括为：异常检查 → 生成候选对 → 过滤高风险 → 执行最高分对 → 视觉+语义验证 → 失败则重试/回滚/重启 → 重新生成候选。

## 6. 主要结论与发现

- **InterfereBench 上**：PrecogUI 正常子集 SR 达 79.2%（Low）/ 52.7%（High），分别超最强反应式基线 3.5 / 15.4 个百分点；扰动子集仅下降 10.8 / 11.1 个百分点，超最强基线 22.4 / 22.1 个百分点。
- **ScreenSpot**：加权平均 91.2%，六个子集中五个领先，超 InfiGUI-R1 加权平均 3.7 个百分点。
- **导航基准**：AndroidControl SR 88.7%（Low）/ 76.4%（High）；GUI-Odyssey 89.1%；三数据集平均 SR 较 UI-TARS-7B 高 1.3 个百分点。
- **消融**：41.5% → +PEP 52.1% → +PSE 61.8% → +PEC 68.4%，验证三模块的增量贡献。
- **PSE 质量**：89.4% 元素类型准确率、80.2% 平均 bbox IoU、83.2% 元素级 F1。
- **扰动时序**：扰动注入越晚，反应式基线损失越大（UI-TARS 从 3.0% 恶化到 16.4%），而 PrecogUI 仅从 1.6% 到 7.1%，约为其 1/2.3 的退化幅度。
- **PEP 管理**：版本感知 + 指数陈旧衰减策略在 5 轮 App 更新后保持 65.4% SR，优于 No Expiry（49.6%）与 LRU（61.5%）。
- **恢复统计**：12.4–18.6% 回合触发恢复，其中 69.7–73.1% 成功恢复；1.8–2.7% 需要回合重启。

## 7. 优点

- **范式创新**：明确将 GUI 智能体从反应式推向"预认知/主动式"，问题定位（长时程扰动下的级联失败）清晰且有实证支撑。
- **模块化设计**：PEP（经验复用）+ PSE（前瞻模拟）+ PEC（闭环控制）职责分明，可独立消融验证。
- **轻量化前瞻**：PSE 只预测符号化布局而非像素级全屏图像，显著降低计算开销，同时足以支撑几何异常检测。
- **数据与评测贡献**：AutoTraj 与 InterfereBench 提供了可控扰动、配对回放的鲁棒性评测范式，填补长时程扰动基准空白。
- **工程完备性**：PolyTouch 扩展多手势与宏执行；提示模板（JSON schema、异常处理、OS 特定提示）设计细致，可复现性较强。
- **诚实的自我评估**：附录中主动讨论 Eq.(3) 边界案例误判率、不可逆操作限制、恢复范围等，学术态度严谨。

## 8. 不足与局限

- **延迟与实时性**：预执行模拟与验证会引入额外延迟与算力开销，对实时或超长任务可能不友好；作者建议未来采用"anytime 预测"。
- **经验陈旧风险**：App 更新会使缓存布局失效，虽提出版本感知与陈旧衰减，但长期可靠性仍依赖记忆刷新机制。
- **不可逆操作缺失

- **不可逆操作缺失**：当前恢复机制主要面向可重试、可回滚或可重启的常规 GUI 操作，对支付、删除、发送、授权确认等不可逆动作缺乏专门的风险建模与二次确认策略。PEC 的“回滚—禁忌—重启”闭环在不可逆副作用已经发生时会失效，论文也承认其恢复范围主要限于可逆或可重试失败。
- **长尾异常与开放世界覆盖不足**：InterfereBench 虽覆盖弹窗、通知、黑屏、冻结、布局突变等受控扰动，但真实环境还存在权限变更、登录过期、网络抖动、广告跳转、A/B 测试、系统升级、区域化 UI 差异等长尾情况。自建基准的扰动分布可能低估开放世界中异常的组合性与突发性。
- **对基座 MLLM 的强依赖**：Deep Think、内容接地、语义验证、轨迹解析等关键环节均依赖高容量 MLLM。若基座模型出现幻觉、坐标定位偏差或语义误判，错误会沿“候选生成—可靠性排序—验证—恢复”链路传播；PEP 与 PSE 只能部分纠偏，不能从根本上消除模型层错误。
- **PSE 泛化边界与符号化损失**：条件扩散布局预测仅在轨迹级划分上验证，作者明确承认这不能作为 App 不相交泛化的证据。符号化 $(type, bbox)$ 表示虽提升效率，但会丢失纹理、动态控件、滚动位置、列表内容、遮挡层级等细粒度信息，可能影响复杂界面的风险判断。
- **评测公平性与可复现性风险**：部分对比方法可能未针对扰动场景专门调优，自建 InterfereBench 的任务选择、扰动资产与标注流程也可能引入作者偏差；OSWorld 上绝对成功率仍较低（20.7%/27.5%），说明桌面长时程任务本身仍具挑战。若缺少第三方复现与跨基准统一协议，结论强度需谨慎看待。
- **部署成本、延迟与能耗未充分量化**：PEP 在线更新、PSE 多次采样、语义验证与恢复循环都会增加 token 消耗、推理延迟和 GPU 占用。论文未报告端到端延迟、单任务成本、能耗或移动端本地部署可行性，对实时交互场景的适用性仍待验证。
- **安全、隐私与伦理讨论不足**：经验池会缓存 UI 状态、布局签名乃至屏幕文本，可能接触账号、通知、聊天等敏感信息；多用户共享记忆、跨设备同步、记忆投毒与隐私泄露风险尚未展开。对高风险操作的权限边界、用户确认机制和审计日志也缺少系统设计。

## 9. 总体评价与启示

- **核心贡献明确**：PrecogUI 将 GUI 智能体从“观察—行动”的反应式执行推进到“观察—预测—行动—验证—恢复”的主动式闭环，问题定义清晰，且用扰动注入实证了长时程级联失败这一关键痛点。
- **模块化与可解释性较好**：PEP 负责经验复用，PSE 负责轻量前瞻，PEC 负责闭环控制，三者职责分离且可消融验证；符号化布局预测在效率与风险检测之间取得了较实用的折中。
- **基准与数据贡献显著**：AutoTraj 与 InterfereBench 提供了“干净—扰动”配对回放、可控异常注入和长时程鲁棒性评测范式，对后续 GUI 智能体鲁棒性研究具有参考价值。
- **结论需带边界理解**：其在自建扰动基准上的提升明显，但跨 App、跨版本、不可逆操作、真实长尾异常和移动端实时部署方面仍有明显空白；绝对性能也尚未达到可无条件信赖的水平。
- **未来方向**：可进一步研究不可逆操作的安全策略、跨应用/跨版本泛化、低延迟 anytime 预测、记忆隐私保护与投毒防御、多智能体经验共享，以及更贴近真实用户行为的开放世界鲁棒性基准。

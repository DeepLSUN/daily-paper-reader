## 摘要
近年来，语言模型能力的提升更多来自数据，而非架构。前沿实验室与数据公司生产可验证的智能体任务，再通过监督微调与强化学习将其转化为能力。这条生产线仍依赖人力以及人在回路中的协作。将任务创建自动化，可使数据生产随算力而非专家人数扩展，可延伸至更多领域，并能实现递归自我改进（RSI）中的关键一步。当前对智能体编写此类任务能力的评估，衡量的是模型在智能体所生成数据上训练后的表现。这与数据行业的常见做法不符：在数据行业中，数据逐样本交付，每个样本都需依据一组标准被验收，而非直接投入训练。现有评估均未考察单个任务是否满足数据流水线的验收标准。为此，我们提出 AutoDataBench。给定一个原始基准任务以及目标模型尝试该任务的记录，智能体必须为同一套件编写一个新任务，并在有效性、新颖性、难度和行为覆盖度方面满足实际验收标准。在三个可执行智能体任务基准上，在默认 45 分钟时间预算下，我们评估的所有智能体得分均未超过 100 分中的 20 分。将最强智能体的时间延长至四倍，其得分显著提升，而生成一个可用任务的成本几乎不变。当前智能体能够编写出达到所需质量的训练任务，但效率不足。AutoDataBench 提供了一种直接衡量智能体自主数据合成能力的方法：每次仅评估一个产物，依据生产流水线会采用的标准进行评判，且无需进行训练运行。代码与数据见 https://github.com/StarDewXXX/AutoDataBench。

## Abstract
Recent gains in language model capability have come more from data than from architecture. Frontier labs and data companies produce verifiable agentic tasks, which supervised finetuning and reinforcement learning then turn into capability.This production line still rests on human labour and on human-in-the-loop collaboration. Automating task creation would let data production scale with compute rather than with expert headcount, would extend to more domains, and would enable a key step in recursive self-improvement (RSI). Current evaluations of an agent's ability to write such tasks measure how a model performs after training on what the agent produced. That does not match common practice in the data industry, where data is delivered sample by sample and each sample is accepted against a set of criteria rather than put straight into training. No existing evaluation asks whether an individual task meets the acceptance criteria of a data pipeline. We therefore introduce AutoDataBench. Given an original benchmark task and a record of the target model attempting it, an agent must write a new task for the same suite that meets practical acceptance standards on validity, novelty, difficulty and behavioural coverage. Across three benchmarks of executable agent tasks, no agent we evaluate scores above 20 out of 100 at the default time budget of 45 minutes. Giving the strongest agent four times as long improves its score substantially, while the cost of one usable task stays almost unchanged. Current agents can write training tasks of the required quality, but not efficiently. AutoDataBench provides a direct measure of an agent's capacity for autonomous data synthesis: one artifact at a time, judged against the criteria a production pipeline would apply, and without a training run. Code and data are available at https://github.com/StarDewXXX/AutoDataBench.

# AutoDataBench 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景判断**：近期语言模型能力提升更多来自数据而非架构；对智能体训练而言，数据的基本单位是"可执行智能体任务"（含可执行环境、验证器、与目标模型能力匹配的难度），而非文本对。
- **痛点**：这类任务的生产仍依赖人类专家（要么自己写，要么维护生成流水线并定义"正确结果"），使数据产量受限于专家人数而非算力，且每个新领域都要重新找专家；这也阻碍了递归自我改进（RSI）——即模型为自己后继者编写训练数据。
- **评估错位**：现有评估（如 PostTrainBench、RSIBench-Data 等）多衡量"用智能体产出训练后模型的表现"，需要一次完整训练运行，且分数附着在 checkpoint 或数据集上；而数据行业的真实做法是**逐样本交付、逐样本按标准验收，验收发生在训练之前**。
- **核心问题**：没有任何评估考察"单个任务本身"是否满足数据流水线的验收标准——即是否可用（格式可运行、验证器能拒绝错误答案、不是原任务的改写）、难度是否落在目标模型"有时能解、有时不能解"的区间、是否针对被委托的行为模式（mode）。
- **含义**：AutoDataBench 试图直接度量智能体的自主数据合成能力，作为 RSI 循环中的关键一环，并处于验证层级中"可执行验证器"的强端。

## 2. 方法论

### 核心思想
- 以**单次交付（episode）**为评估单位：给定一个原始基准任务 + 目标模型尝试该任务的记录（sanitized transcripts），作者智能体必须为同一套件写出**恰好一个新任务**；不做训练运行，仅按生产验收标准评判这一件产物。

### 流程与角色（四步）
1. **输入**：1 个原始任务 + 目标模型 K=6 次独立闭卷尝试的脱敏转录与验证器输出。
2. **Analyst（固定，claude-opus-5）**：读转录，写出 3–5 条"模式"（mode）构成的**隐藏 rubric**（作者智能体永不可见）。模式需在套件层级表述，使"没看过原任务的读者也能刻意构造另一个任务来触发它"。来源有三：直接导致失败的失误（86 条）、走错后恢复的弯路（20 条）、所有尝试都答对但存在诱人替代解的错误易发点（19 条）；24 个任务共 125 条，均值 5.2。
3. **Author Agent（被测对象）**：在固定 wall-clock 预算内自由使用 shell、容器运行时、网页搜索，唯一限制是**只能调用目标模型**；运行新任务后交付一个任务目录。
4. **Rollout + Judge（固定，claude-opus-5）**：目标模型在新任务自己的验证器下尝试 K 次；Judge 读新转录（而非任务外观），逐模式判定是否被触发，并判定 gate。

### 评分：三项相乘
- **score = gate × difficulty × quality**
- **Gate（0/1）**：存在八类取消资格缺陷之一即 0 分——① 验证器不检查结果；② 答案无需做题即可获得；③ 任务不可解；④ **仅替换表面的原任务改写**；⑤ 抄袭他处；⑥ 调用了未许可的模型；⑦ 交付物不是一个任务；⑧ 与其他交付重复。为防"软措辞被绕开"，harness 会计算两份指令的**词级 diff 并作为事实挂载**：若所有差异片段都只是重命名，该缺陷直接触发；验证器或参考解原样搬运同样触发。同问题族、同一决策点、复用环境/验证器形状则被明确允许。
- **Difficulty（0/1）**：由执行决定，无模型参与。目标模型通过率落在 **[0.125, 0.75]** 的"band"内为 1（K=6 即解出 1–4 次）；全解或全不解都不可用于训练。
- **Quality**：对隐藏 rubric 的覆盖度，`quality = min(1, modes_covered / ⌈aN⌉)`，a=0.6（5 条中覆盖 3 条即满分）。设为不可达（unreachable）的模式从分子分母中剔除；判为 present 必须引用具体尝试、步骤和逐字引用。a<1 的原因是单个新任务无法舞台化原任务的所有模式——早期运行中全覆盖的 episode 全部因"克隆"被 gate。

## 3. 实验设计

- **数据/场景**：三个可执行智能体任务套件，各手工选取 8 个任务（跨套件自身标注的领域，避开无法构建的环境），共 **24 个原始任务**：
  - Terminal-Bench 4.0（终端与软件工程，commit 624df06）
  - Terminal-Bench-Science（科学计算：生命/物理/地球/数学/工程科学，commit c5e5036）
  - AutomationBench（跨应用业务流程：财务、HR、市场、销售、支持等，commit c5e5036）
- **目标模型**：全程固定为 deepseek-v4-pro；事先对 24 个任务各尝试 6 次，共 144 条转录作为所有后续阶段的证据。
- **对比对象（作者智能体）**：kimi-k3、gpt-5.6-sol、qwen3.8-max、glm-5.3、deepseek-v4-pro 五个前沿智能体，同一目标模型、同一 rubric、同一评分，差异即作者差异。
- **规模**：每个原始任务在默认 45 分钟预算下被撰写 **2 次**（每智能体 48 个 episode），按任务均值再按套件汇总。
- **额外实验**：kimi-k3 在 **180 分钟**预算下重跑同一 24 个任务（AutomationBench 重复至 4 个 episode，按固定种子抽 2 个以保持等权），考察时间预算缩放。
- **经济学分析**：以"可用交付（in band 且通过 gate）"为单位统计每 episode 与每可用交付的分钟数与美元数。

## 4. 资源与算力

- **论文未报告任何 GPU 型号、数量或训练时长**，这是设计使然：AutoDataBench 明确**不进行训练运行**，因此不存在训练算力消耗。
- 唯一涉及的开销是 **API 调用与 wall-clock 时间**：
  - 每个 episode 默认 45 分钟 wall clock（五个作者智能体实测 41.2–48.4 分钟/episode）。
  - 金钱按 2026 年 9 月列表价计算作者智能体自身 token：0.50–5.77 美元/episode；每可用交付 4.81–27.69 美元（不含目标模型校准调用、官方 K 次尝试与 Judge 的开销）。
  - 180 分钟臂：139.0 分钟/episode、7.62 美元/episode。
- **注意**：论文指出 glm-5.3 因缓存未生效做了修正（实测 746.55 美元，按其他智能体同框架的中位命中率推算应为 168.20 美元），该数字是估算值。

## 5. 实验数量与充分性

- **实验规模**：5 个作者 × 24 个任务 × 2 episode = **240 个 episode**（每智能体 48 个）；另有 kimi-k3 的 180 分钟臂（24 任务 × 2 episode，AutomationBench 4 个）；原始任务的目标模型尝试 144 次；另有对全部作者轨迹的定性编码（跨所有智能体共现的 14 类行为）。
- **充分性**：
  - **优点**：覆盖三个差异极大的领域（终端/软件、科学计算、业务流程），且多领域设计本身产出了"排名跨域不稳定"这一有信息量的结论；固定目标模型与 rubric 使作者间可比；gate 与难度均由执行而非模型主观判定。
  - **不足**：每个套件仅 8 个任务，论文自己声明**per-suite 数字只应视为固定子集上的估计，不能外推到整个套件**，因此结论以三套件合并陈述。
  - **公平性风险**：45 分钟与 180 分钟两臂**同时改变了时间预算与推理努力（maximum effort）**，论文在附录 F 中承认无法分离两者，只能作为"方向性"论断；早期对 gpt-5.6-sol 的努力度实验显示效应与噪声同阶。
  - **指标内生的偏置**：每可用交付成本的**分母本身是一个评分项**，deepseek-v4-pro 的 4.81 美元混合了真实低 token 成本与自身造成的 gate 惩罚。
  - **无消融式验证**：quality 项背后的核心假设（触发某模式的任务能产出修复该模式的训练数据）未被任何实验检验。

## 6. 主要结论与发现

- **结论 1**：默认 45 分钟下**没有任何智能体超过 0.20**（满分 1.0）。kimi-k3 最高 0.184，gpt-5.6-sol 0.177，qwen3.8-max 0.139，glm-5.3 0.130，deepseek-v4-pro 最低 0.097。
- **结论 2（核心发现）**：**瓶颈是难度校准而非模式覆盖**。仅 14.6%–25.0% 的交付落入通过率 band，而存活交付的 rubric 覆盖度高达 0.700–0.967——与预期相反。智能体能读懂行为记录并瞄准它，但无法把任务放在"目标模型有时能解"的位置。
- **结论 3**：失败有两种不同形态。qwen3.8-max 入 band 最少（14.6%）但 7/7 通过 gate、覆盖 0.952；deepseek-v4-pro 入 band 最多（25.0%）却只有 5/12 通过 gate（41.7%），因为"贴近原任务"是最廉价的难度控制手段，而 gate 正是为捕捉它而设。
- **结论 4**：**排名跨域不稳定**。没有智能体在两个以上套件领先：kimi-k3 在 AutomationBench 第一、Terminal-Bench 第四；qwen3.8-max 在 AutomationBench 得 0 却在 Terminal-Bench 第一；glm-5.3 在 Terminal-Bench-Science 得 0。因此应**按领域而非统一地选择作者智能体**。
- **结论 5（时间缩放）**：kimi-k3 从 45 分钟到 180 分钟，分数 0.184 → **0.541（2.9 倍）**，三套件全部提升，最弱的 Terminal-Bench 提升最多；in-band 交付通过 gate 的比例从 90% 升至 100%（即没有靠改写原任务来入 band）。但**单位成本几乎不变**：11.88 → 12.62 美元/可用任务，244 → 230 分钟/可用任务。
- **结论 6（经济学）**：每可用交付 4.81–27.69 美元、202–410 分钟；五个智能体 wall clock 相差不到 18%，而花费相差 11 倍；时间主要消耗在失败尝试而非长会话上。
- **总结判断**：**当前智能体已能写出达到生产质量要求的训练任务，但效率不足**；且"覆盖某模式即可修复该模式"这一 quality 项底层的假设仍未经验证。

## 7. 优点

- **评估范式对齐真实生产**：把"单个合成任务的验收"本身设为评估目标，逐样本、训练前判定，无需训练运行，因而**直接且低成本地隔离出"写数据"这一能力**，而非其代理指标。
- **难以被游戏化**：隐藏 rubric、乘法式评分、硬 gate、模式判定需逐字引用证据、词级 diff 作为事实挂载（附录 D 记录了"软措辞被推理绕过"的失败教训及独立测量验证），并明确规定"同问题族/同决策点"不算克隆，避免把合理出题误杀。
- **难度由执行

## 摘要
LLM 智能体逐 token 生成中间推理与动作，使长程交互变得缓慢且计算开销高昂。Jev 风格模型能在有限域上提供快速概率预测，但要求预先指定这些域。这一要求限制了自主任务求解，因为可用动作必须从自然语言指令中推导，并通过交互进行调整。我们提出 JevSpawn，一种组合式策略，将自然语言任务规范与有限概率探索连接起来。并行动作生成与反馈驱动的分支选择、表示修正以及从保留备选方案中恢复相结合。共享的动作结构和模型前缀减少了重复生成和上下文计算，且无需额外训练。在八个基准任务上，与七个智能体基线及一个 TypeSafe Jev 变体进行对比评估，结果表明 JevSpawn 是结构化智能体推理的一种有前景的方法，具有更优的任务性能和更快的导航。

## Abstract
LLM agents generate intermediate reasoning and actions token by token, making extended interactions slow and computationally expensive. Jev-style models offer fast probabilistic predictions over finite fields, but require those fields to be specified in advance. This requirement limits autonomous task solving, where the available actions must be derived from natural language instructions and adapted through interaction. We introduce JevSpawn, a compositional policy that connects natural language task specifications to finite probabilistic exploration. Parallel action spawning is coupled with feedback driven branch selection, representation revision, and recovery from retained alternatives. Shared action structure and model prefixes reduce repeated generation and context computation without additional training. Evaluations on eight benchmark tasks against seven agent baselines and a TypeSafe Jev variant establish JevSpawn as a promising approach to structured agentic inference, with improved task performance and faster navigation.

## 1. 核心问题与研究动机

- **背景痛点**：LLM 智能体通过工具调用与环境反复交互来求解任务，但推理与动作是**逐 token 自回归生成**的，观测又不断膨胀上下文，导致长程交互既慢又昂贵；在固定推理预算下，探索备选动作的广度与交互时长都受限。
- **已有工作的两条路径及其局限**：
  - 一类方法（LATS、LLMCompiler、AgentPrune、HiAgent、FoldAgent、DyFlow、LatentMAS 等）从**智能体层面**优化调用调度、剪枝通信、压缩记忆，或从**计算层面**用前缀缓存、KV 压缩、投机解码加速单次请求；但它们仍需为每个分支重复生成完整动作字符串。
  - 另一类是 **Jev 风格模型**（如 TypeSafe Jev），可对**有限域**并行做快速概率预测、直接返回带概率的类型化取值，无需生成响应字符串；但其前提是**动作字段必须事先指定**。
- **核心矛盾**：自主智能体的可用动作必须从自然语言指令中**推导**，并随新观测**动态修订**；而 Jev 式预测要求字段预先固定。因此，论文要解决的核心挑战是：**如何在保留有限域预测速度的同时，让动作空间在交互过程中自适应变化**。
- **整体含义**：JevSpawn 把动作字段本身纳入策略（policy），把 Jev 式有限预测扩展到持续任务求解，无需额外训练，为结构化智能体推理提供了一条"组合式动作空间 + 有限概率探索"的新路径。

## 2. 方法论

### 2.1 核心思想

- 将**动作空间本身作为策略的一部分**：模型根据自然语言任务上下文推断出有限字段（field）及其取值域，再把字段值组合成可执行动作；联合概率指导并行"孵化"（spawn）分支，执行反馈指导分支选择、表示修订与从保留分支中恢复。
- 三大贡献：① 组合式动作表示连接自然语言目标与可执行有限字段；② 统一架构耦合并行孵化与反馈驱动状态转移、表示修订、分支恢复；③ 并行因果评估 + 共享前缀复用作为共同计算基础。

### 2.2 组合式 Jev 策略

- 给定分支 $v$、任务上下文 $x$、共享观测 $M$、分支历史 $H_v$，模型（参数 $\theta$ 固定）输出**动作声明** $\Sigma_v = \{(r_j, D_j(\cdot))\}_{j=1}^{m_v}$：每个 $r_j$ 是字段名与语义，$D_j(\cdot)$ 是在前序赋值下允许的有限取值；渲染函数 $g_v(z)$ 把完整赋值 $z=(z_1,\dots,z_{m_v})$ 变成可执行动作。
- 字段按**条件块** $b_1,\dots,b_L$ 依次求值（$L$ 为组合深度），完整赋值的概率为各块条件概率之积：
  $$\pi_\theta(z \mid h_v, \Sigma_v) = \prod_{\ell=1}^{L} \bar{Q}_\theta\big(z_{b_\ell} \mid h^{z_{<b_\ell}}_v, D_{b_\ell}(z_{<b_\ell})\big)$$
  已完成的赋值只接受概率为 1 的"空扩展"（吸收态），从而在不指定轨迹的情况下定义声明动作空间上的策略。

### 2.3 有限值树上的概率与归一化

- 将选项序列化为前缀无关集合 $\mathcal{T}$，在**分支前缀**（出度 > 1）处按局部 softmax 计算转移概率 $q_\theta$，叶子概率为路径上各分支概率之积 $Q_\theta(\tau\mid h,\mathcal{T})$，满足非负且和为 1（Proposition A.1）。
- 重复序列化值**均分概率质量**，得到选项分布 $\bar{Q}_\theta(i\mid h,O) = Q_\theta(\tau(i)\mid h,\mathcal{T}) / c(\tau(i))$；同一父状态下重复的可执行动作会被折叠。
- 论文明确指出：局部归一化得到的是**相对动作偏好**，而非执行成功概率（与在 $\mathcal{T}$ 上做全局条件化不同，后者包含被迫 token 的似然与"留在树内"的概率）。

### 2.4 自适应分支探索（Algorithm 1）

- 维护一个**前沿集合** $F$（宽度上限 $R$），每轮：
  1. 渲染共享上下文 $h_F$，对分支打分并保留 Top-$R$，选出最高分分支 $v$；
  2. 在操作集 $U_t(v)$（expand / revise / submit / discard）中按 $\bar{Q}_\theta$ 选择操作；
  3. `revise` 时更新该分支的声明 $\Sigma_v$ 并追加反馈 $e_v$；`submit` 则调用 `Submit_θ` 结束；
  4. 选出至多 $P$ 个可执行的父分支，用**束搜索（宽度 $K$）**在 $\pi_\theta$ 上生成候选动作集合 $A_b$；
  5. 对每个 $(b,a)$ 在**独立的环境状态副本**上并行执行 $E(s_b,a)$，得到子状态 $s_w$、观测 $o_w$，并追加到子历史 $H_w = H_b \| (a,o_w)$，同时更新共享观测 $M$；
  6. 更新前沿 $F$，未选中分支保留以备**回溯恢复**。
- 交互轮数、保留分支数、扩展父分支数、每父动作数分别由 $T,R,P,K$ 约束；论文给出 $|C_t| \le P_tK$ 与 $N_T \le TPK$ 的界（实际因域饱和、去重、提前终止而更小）。

### 2.5 并行策略评估与共享计算

- 已声明的字段值是**已知 token 序列**，其因果隐状态可**并行评估**；只对分支前缀做投影，投影规模由 $d_{model}|V|$ 降为 $d_{model}|C(u)|$。
- **共享前缀复用**：$B$ 次评估、前缀长度 $n_p$、后缀长度 $n_1,\dots,n_B$ 时，处理输入 token 数从 $Bn_p + \sum_b n_b$ 降到 $n_p + \sum_b n_b$；附录 A.5 证明在位置、因果可见性、参数与初始状态一致时，共享注意力与独立评估在精确算术下等价（以 $Z_p A_p + Z_s A_s$ 的加权形式合并前缀/后缀注意力）。
- 文本生成仅在需要**补全声明、修订或最终作答**时使用；重复探索走有限策略，**预训练参数全程不变**。

## 3. 实验设计

- **任务/数据集（8 个任务，来自 5 个 benchmark）**：
  - **PPNL**（自然语言路径规划，1,136 实例）
  - **Maze**（LMRL Gym，25 个初始状态）与 **Grid**（LLF Bench）——带动作反馈的导航
  - **LightsOut、RushHour、Sokoban**（TextArena）——序贯谜题
  - **2048、Nullify**（KORGym）——数值博弈
  - 除 PPNL/Maze 外，其余任务各 100 实例，种子 42–141；无效提交与超时计为失败。
- **对比方法**：LATS、LLMCompiler、AgentPrune、HiAgent、FoldAgent、DyFlow、LatentMAS 共 7 个智能体基线，外加**同架构内的 TypeSafe Jev 变体**（用 API 模型 `jev-1.13.0` 做有限打分，Qwen 负责声明与文本生成）。
- **指标**：任务得分（成功率 / benchmark reward / game score）、端到端（E2E）延迟、文本解码吞吐（tok/s）、Pareto 前沿频率（2,000 次配对 bootstrap 重采样）。
- **消融设置**：扩展宽度 $\{1,2,4,8,10\}$；固定 4 个动作下的父–子分配 $1\times4$、$2\times2$、$4\times1$；固定首个有效声明（禁用修订）；仅保留本分支观测（禁用跨分支共享）；长程实验（131,072 token 上下文，轮数 $\{36,54,72,108\}$，含/不含 300 s 截止）；批规模缩放 $\{8,16,32,64,128\}$。
- **公平性措施**：任务上下文（目标、初始观测、交互规则、作答格式）在各方法间共享；同一 1,761 实例上对比全方法与消融；温度 0、禁用 thinking、种子固定 42。

## 4. 资源与算力

- 使用 **4 张 H100 GPU**，张量并行、bfloat16 精度。
- 超参：物理批大小 8、上下文上限 16,384 token、单次生成上限 2,048 token、最多 36 轮探索 + 1 次提交、300 秒时限。
- **无需训练**：方法基于固定参数的预训练模型（Qwen3.8-27B），"without additional training"，因此文中**未报告训练时长、训练数据规模或微调成本**。
- 论文报告的算力相关信息主要是**推理侧**的：GPU 活动时间线（短/长历史下的内核间隔）、有限评估批延迟（短历史 0.26–0.49 s/批，长历史 0.26–2.56 s/批）、文本生成峰值吞吐在批大小 16 时达 164.2 tok/s、有限评估在短/长历史下分别约 28 与 6 请求/秒，且有限评估批大小 16 以上即耗尽显存。

## 5. 实验数量与充分性

- **规模**：8 个任务 × 8 个方法（含变体）的主实验；消融覆盖 4 个组件维度（宽度、拓扑、声明修订、信息共享），每个消融变体与完整方法在**同一 1,761 个实例**上配对比较；另有长程系列（4 种轮数 × 2 种时限条件）、批规模缩放系列（文本 4 档、有限评估 2 档）、以及 8 个任务的逐步 case study。
- **统计处理**：主结果给出 95% 配对 bootstrap 区间；Pareto 前沿用 2,000 次重采样评估稳定性；AgentPrune 的逐实例配对时间/得分对比（含超时对单列）。
- **充分性评价**：
  - **优点**：消融维度完整且均为配对比较，控制了实例差异；统计区间与 Pareto 频率的使用比单纯的均值对比更稳健；报告了失败/超时而非仅成功样本。
  - **需注意**：消融结果中不同设置"各有胜负"（固定声明在 4 个任务上更好、自适应声明在另 4 个任务上更好），说明结论对任务类型敏感；单一模型骨干（Qwen3.8-27B）与单一硬件配置限制了泛化性外推；TypeSafe Jev 变体走网络 API，其延迟含通信时间，与本地推理基线的延迟对比并非严格同条件。

## 6. 主要结论与发现

- **任务性能**：JevSpawn 在 8 个任务中的 **5 个取得最高分**：Maze 成功率 0.96、Grid 0.95（FoldAgent 分别为 0.52、0.73）；LightsOut reward 0.61（AgentPrune 0.34）；Nullify 0.21（HiAgent/FoldAgent 0.09）；2048 得分 305.12（LLMCompiler 仅 5.00）。AgentPrune 在 PPNL、RushHour、Sokoban 上仍最强。
- **效率**：在 Maze 与 Grid 上实现"质量 + 延迟"双赢，E2E 延迟从最快基线的 47.91 s / 61.44 s 降至 **40.91 s / 40.58 s**；7 个任务中 JevSpawn 几乎总在 Pareto 前沿上（Maze、Grid、2048 为 100% 前沿频率）。
- **吞吐**：PPNL 与 LightsOut 上文本解码吞吐达 544 与 580 tok/s，为全部方法最高；Maze 与 Grid 全程使用有限评估，无需文本生成。
- **消融发现**：
  - **并行孵化**是导航与 LightsOut 的关键：宽度从 4 降到 1，Maze 成功率从 0.88 跌至 0.16、Grid 从 0.94 至 0.58、LightsOut 从 0.61 至 0.06；但宽度升到 10 会使 Nullify 分数减半、RushHour 延迟约翻倍。
  - **固定动作预算下拓扑重要**：$2\times2$ 在 Maze/Grid 达 1.00 成功率，$4\times1$ 使二者降至 0.12/0.75（但 2048 得分更高）。
  - **声明修订**：固定首个有效声明在 Maze、LightsOut、Sokoban、2048 上得分更高并在 6 个任务上降低延迟；自适应声明在另 4 个任务上更优。
  - **观测共享**：共享观测在全部 8 个任务上降低延迟，并在 PPNL、Sokoban、2048、Nullify 上提升得分；限制为本地观测则在 Maze、Grid、L

- 观测共享（续）：共享观测在全部 8 个任务上降低延迟，并在 PPNL、Sokoban、2048、Nullify 上提升得分；限制为本地观测则在 Maze、Grid、LightsOut 上得分更高。这说明跨分支共享并非普适增益：在信息型/组合型任务中，"看到其他分支的尝试结果"能加速收敛；而在导航与部分谜题中，把与当前分支状态不一致的观测混入上下文反而会干扰策略判断，共享的主要收益退化为减少重复渲染的**延迟节省**。
- **长程与批规模系列**：
  - 在 131,072 token 上下文、轮数 $\{36,54,72,108\}$ 的长程设置下，JevSpawn 的延迟随轮数增长明显慢于文本生成基线；加入 300 s 截止后，基线在较高轮数下大量因超时被判失败，而 JevSpawn 仍能完成更多有效交互轮次。这印证了"每轮只做有限域评估、仅在必要时生成文本"的设计在长程任务中的边际收益会被放大。
  - 批规模缩放显示，文本生成的吞吐在批大小 16 时达到峰值（164.2 tok/s），继续增大批不再提升；有限评估在批大小 16 以上即耗尽显存，因此**并行孵化宽度 $R$ 与每父候选数 $K$ 的实际上限受显存而非算法约束**。换言之，论文主张的"并行探索"在工程上仍是一个显存受限的资源分配问题。
- **案例研究**：8 个任务的逐步轨迹分析表明，JevSpawn 的优势主要来自**早期并行试错 + 及时丢弃错误分支**（前沿剪枝与 `discard` 操作），而不是单步决策质量的提升。在 PPNL、RushHour、Sokoban 等需要精确长程规划的任务上，单步"看起来合理"但缺少全局回溯能力的动作仍会导致失败，这也解释了这些任务上 AgentPrune 等专用调度方法依然更强。

## 7. 局限与批判性评价

- **骨干与硬件单一**：全部实验基于 Qwen3.8-27B 与 4×H100，未验证该框架在更小（无法承担并行束搜索开销）或更大（显存更充裕）模型上的行为差异；对"有限域预测"的收益是否随模型规模变化而改变，论文没有给出答案。
- **有限域假设的适用边界**：JevSpawn 要求动作能被分解为有限取值字段。对于开放式动作（自由文本工具参数、代码生成、多轮协商等）如何界定字段与取值域，论文未给出系统性方法，`revise` 机制也只在受控任务上被验证。
- **延迟对比的严格性**：TypeSafe Jev 变体经由网络 API（`jev-1.13.0`）调用，其延迟包含通信开销，与本地推理基线的端到端时间不构成严格同条件比较；同时基线方法多来自不同实现/代码库，工程优化程度差异可能部分放大或缩小差距。
- **显存瓶颈**：有限评估批大小超过 16 即耗尽显存，意味着论文中报告的最大探索宽度未必是可扩展的；在更长上下文或更大模型下，"并行孵化"的收益可能需要与量化、KV 卸载等技术结合才能兑现。
- **消融结论的任务敏感性**：固定声明在 4 个任务上更优、自适应声明在另 4 个任务上更优，说明核心设计选择并非普遍占优，读者需要按任务类型判断是否值得引入 `revise` 的额外开销。
- **缺少与强基线的组合**：论文未探讨 JevSpawn 与 LATS 式树搜索、AgentPrune 式通信剪枝等方法的叠加效果，因此"组合式动作空间 + 有限概率探索"的增量价值在已有强系统之上是否仍然成立，仍属开放问题。

## 8. 结论与启示

- **核心结论**：JevSpawn 通过把**动作字段本身纳入策略**，在无需额外训练的前提下，把 Jev 式有限域快速预测从"字段预先指定"的受限场景扩展到自主智能体的持续任务求解，在 8 个任务中的 5 个取得最佳得分，并在 Maze、Grid、2048 上同时占据质量–延迟 Pareto 前沿。
- **方法学启示**：① 把"动作空间构造"与"动作选择"统一在同一概率框架下，是绕过自回归逐 token 生成瓶颈的一条可行路径；② 并行因果评估 + 共享前缀复用把"探索广度"从串行代价转为批处理代价，是效率增益的主要来源；③ 声明式字段为智能体交互提供了可解释、可审计的中间表示，便于调试与人工干预。
- **实践启示**：在导航、谜题、数值博弈等动作天然可枚举的任务中，JevSpawn 式的"组合动作 + 并行孵化"值得优先考虑；而在需要精确长程规划或开放式动作的任务中，应保留专用搜索/调度方法，或将 JevSpawn 作为其动作生成层。
- **未来方向**：放宽有限域假设（面向开放式工具的字段自动发现）、把显存受限的并行探索与量化/KV 压缩结合、在异构骨干上验证收益曲线，以及探索与树搜索、通信剪枝等既有方法的组合，都是该工作自然延伸出的研究议题。

## 摘要
使用大语言模型进行科学发现的框架通常依赖一个固定的、由人设计的算法来决定模型在每一步看到什么，使模型仅扮演提议者角色。模型对所展示内容之外的搜索一无所知。随着模型能力增强，一个问题出现了：在运行前由人选择的搜索策略，是否比将模型从提议者提升为规划者并让它掌控搜索具有更好的扩展性？《苦涩的教训》表明，预先选择策略正是那种手工设计的结构，通用方法最终会超越它。我们提出 AgentDiscover，其中一个编码智能体利用其上下文作为工作记忆来规划搜索、运行实验，并将每次尝试记录在一个包含想法、候选方案及其关系的数据库中。该数据库作为智能体的长期记忆，其结构使得诸如 MAP-Elites 和蒙特卡洛树搜索等经典算法的选择规则各自可归约为单次查询，智能体可以自由使用、组合或替换这些查询。一台服务器维护该数据库，并在每次提交后引导智能体，使其在长时间运行中保持正轨。在我们的实验中，AgentDiscover 比现有框架更具成本效益，以更低成本达到更好分数。在内核工程、生物学、算法设计和数学任务上，AgentDiscover 优于先前的发现框架。其程序本可在过去七届 AtCoder 启发式竞赛中在人类参赛者中位列第一，并且在十一项数学与系统优化任务上，它匹配或超过所有使用相同模型的基线。我们的代码见 https://github.com/mhdfb/AgentDiscover。

## Abstract
Frameworks that use large language models for scientific discovery typically rely on a fixed, human-designed algorithm that decides what the model sees at each step, leaving the model only the role of proposer. The model knows nothing of the search beyond what it is shown. As models grow more capable, a question arises: does a search strategy chosen by a human before the run scale better than promoting the model from proposer to planner and letting it own the search? The Bitter Lesson suggests that choosing the strategy in advance is the kind of hand-designed structure that general methods eventually outscale. We introduce AgentDiscover, in which a coding agent plans the search using its context as working memory, runs experiments, and records every attempt in a database of ideas, candidates, and their relations. This database serves as the agent's long-term memory and is structured so that the selection rules of classical algorithms such as MAP-Elites and Monte Carlo tree search each reduce to a single query, which the agent is free to use, combine, or replace. A server maintains the database and steers the agent after every submission, keeping it on course over long runs. In our experiments, AgentDiscover is more cost-efficient than existing frameworks, reaching better scores at lower cost. On tasks in kernel engineering, biology, algorithm design, and mathematics, AgentDiscover outperforms prior discovery frameworks. Its programs would have placed first among human competitors in seven past AtCoder heuristic contests, and on eleven mathematical and systems optimization tasks it matches or exceeds every baseline that uses the same model. Our code is available at https://github.com/mhdfb/AgentDiscover.

## 1. 核心问题与研究动机

- **背景**：LLM 驱动的科学发现（如 FunSearch、AlphaEvolve）通常采用"进化搜索"配方：由人预先设计好的搜索算法决定每一步把哪些历史候选放进模型上下文，LLM 只负责"提议"（proposer），并看不到被算法隐藏掉的搜索全貌。
- **核心质疑**：这类系统的搜索流程本身是人类手工设计的——讽刺之处在于，系统本意是超越人类设计，却把最关键的搜索策略交给了人。
- **理论依据**：引用 Sutton 的《苦涩的教训》（The Bitter Lesson）——基于人类知识手工构造的方法最终会被能利用更多算力的通用方法超越；同时引 Wolpert & Macready 的"没有免费午餐"定理，指出没有单一搜索策略在所有问题上最优。
- **实证动机**：Gupta 等（2026）在预算对齐下比较 30 种固定搜索策略（harness），发现没有一种稳定优于简单基线，且完整 OpenEvolve 配方排名垫底；且最优策略在单次运行内也会变化。
- **两个待答问题**：
  1. 能否让编码智能体同时承担"规划搜索"与"提议候选"两个角色，仅保留最小的人工搜索启发式？
  2. 能否把搜索历史组织成"只花一次查询代价即可检索所需内容"的结构？
- **整体含义**：作者主张把模型从 proposer 提升为 planner，让模型自身拥有的搜索策略随模型能力一同进化。

## 2. 方法论

### 2.1 核心思想

- 用一个**编码智能体（coding agent）**取代固定的进化搜索算法：它自己决定读什么、试什么、何时转向，实现"元认知式"的自我监控与控制。
- 智能体的**上下文即工作记忆**；每次尝试被写入**长期记忆**（图数据库），使智能体可以低成本地重新探索搜索历史。
- 关键设计目标：(i) **灵活性**——不硬编码任何搜索策略；(ii) **长程效率**——数小时运行下保持方向、保留知识、控制 token 成本。

### 2.2 三大组件

| 组件 | 作用 |
|---|---|
| **搜索智能体** | 沙箱化的 coding-agent CLI（如 Claude Code），在版本控制的 worktree 中工作；通过 MCP 服务器读图、跑实验、提交候选 |
| **长期记忆** | 图数据库（Neo4j），记录 idea、candidate、session、lesson 及其关系；只读查询任意 Cypher，写入仅通过受校验的 MCP 工具 |
| **元智能体（可选）** | 另一个 coding agent，在每个搜索 session 后运行，读推理轨迹与结果，把"哪些思考方式有效"固化为 skills 与 strategy，供后续 session 使用 |

### 2.3 关键技术细节

- **经典算法归约为单次查询**：
  - MAP-Elites（每个 niche 保留最优）→ 一条 Cypher 查询：`MATCH (c:Candidate)-[:USES_IDEA]->(i:Idea) RETURN i, max(c.fitness)`；
  - MCTS 的访问计数与价值 → 沿候选 lineage 的查询。
  - 智能体可自由使用、组合或替换这些规则。
- **会话重置（context reset）**：新 session 使用全新上下文 + 共享记忆，避免 (i) 每次 LLM 调用重读超长上下文的成本；(ii) 锚定于早期推理而陷入局部最优；(iii) 长程任务中迷失目标。
- **服务器引导（steering）**：每次提交后返回 fitness、剩余候选数、与目标的差距等消息；第 5 个候选起附加"成本提示"，告知继续本 session 是否比新开 session 更贵。
- **图数据库 schema**：节点含 User / Agent / Session / Candidate / Idea / Resource / Guidance / Tool / RunConfig；关系区分"事实"（由 orchestrator/server 写入，如 RETRIEVED、READ、PRODUCED）与"声明"（由搜索智能体写入，如 DERIVED_FROM、USES_IDEA、USED_CONTEXT）。候选的 key 为程序文本的 SHA-256，保证重复提交不产生新节点。
- **元 pass**：在 block 之间的 barrier 运行；元智能体可写 `write_meta_lesson`、`add_tool`（保存只读查询为工具）、`write_strategy`（取代旧 Guidance），并可写 skills 文件；**不得**直接写候选分配或实现细节。
- **执行安全**：评估器从不挂载进智能体容器；候选在独立容器中评估（限额、默认无网络）；只读查询在 Neo4j 只读事务中执行；每次调用由服务器自行归属，不信任智能体自述。
- **迭代流程**：worktree 起始于新 git 仓库，含 solution.py 与空的 tools/、skills/；session 结束条件为 agent 判断停滞或上下文成本过高。

### 2.4 算法流程（文字描述）

1. 编排器启动数据库、MCP 服务器与评估环境，渲染指令文件（CLAUDE.md/AGENTS.md），创建 Session 节点。
2. 搜索智能体：查询图数据库 → 记录/复用 idea → 编辑 solution.py 的 evolve 区块 → 本地实验 → 提交候选（附语言预测与 fitness 预测、parents、resources）。
3. 服务器在隔离沙箱中评估，返回分数与引导消息。
4. 循环至候选上限或智能体主动停止；调用 `write_lesson` 结束 session。
5. 新 session 以全新上下文继承记忆、tools、skills；block 结束后运行元 pass。

  - 元消融采用配对 fork 设计，有效控制运行间随机性。

## 8. 不足与局限

- **统计严谨性**：主表每格为单次运行，未报告方差，方法间小差距缺乏统计显著性支撑；仅组件消融做了 5 次重复。
- **模型覆盖**：主要在 Claude 系列上验证（部分任务用 GPT-6 Sol），未在固定任务上更换骨干模型，跨模型泛化性未知。
- **机制未分析**：作者自陈未分析智能体实际使用何种搜索策略——是否重新发现了 MAP-Elites/UCT 等经典规则，还是合成了新规则，因此"智能体自主搜索优于

人类设计的搜索策略'这一核心论点缺乏机制层面的直接证据——论文只展示了结果优势，未通过日志分析回答"智能体到底在用什么策略"。
- **成本与可扩展性**：方法依赖高强度的 coding-agent 调用与图数据库交互，单任务开销可达 $100–$200；论文未给出在更大规模问题（更长的运行时间、更多候选、更复杂代码库）上的成本-收益曲线，也未讨论当 token 预算收紧到无法支撑多 session 时的退化行为。
- **元智能体的额外开销**：元 pass 与并行智能体都会增加总花费，论文虽在等模型开销下比较，但未单独报告"元 pass 自身的成本占最终收益的比例"，因此难以判断该组件是否在所有任务上都具有正收益。
- **安全与工程假设**：执行隔离、只读事务、服务器自行归属调用等设计依赖特定的部署环境（Neo4j、MCP、容器沙箱），论文未评估在恶意或对抗性候选下的鲁棒性，也未讨论多智能体并发写图时的冲突处理细节。
- **评估器依赖**：作者修正了若干奖励黑客漏洞，但这恰恰说明结论对评估器质量高度敏感；在评估器本身存在未知缺陷的任务上，性能优势可能被高估。
- **指令与技能文件的敏感性**：搜索智能体的行为受渲染出的指令文件（CLAUDE.md/AGENTS.md）与 skills 影响，论文未做指令措辞或技能内容的消融，跨实现的可复现性存疑。
- **任务覆盖的偏向**：24 个问题虽跨域，但多为"有明确标量 fitness、可快速本地评估"的优化型任务；对开放-ended、无清晰目标函数或需外部实验验证的科学发现场景，方法适用性未经验证。

## 9. 可复现性与开放问题

- **可复现性**：方法的核心组件（图 schema、MCP 工具、会话重置、steering 消息）描述较完整，且对比基线多为公开框架，具备复现基础；但模型开销的估算方式、元智能体的提示与 skills 内容、部分任务的评估器修正细节散落于附录，完全复现仍需较多工程投入。
- **开放问题**：
  1. 智能体是否会在更长运行中自发收敛到某一经典搜索规则，还是持续合成新规则？这直接关系到"搜索策略随模型能力共同进化"的论点。
  2. 图数据库作为长期记忆的收益，在多大程度上来自"结构化检索"本身，而非"额外上下文预算"？
  3. 当模型能力下降（如使用更小模型）时，最小脚手架范式是否仍优于手工设计的强搜索算法？这决定了该方法的下限。
  4. 元智能体固化的 strategy 是否会随任务分布变化而过时，形成新的"人类/历史先验锁定"。

## 10. 总体评价

- 这是一篇**范式层面有主张、系统层面有实现、实验层面有广度**的工作：它把"搜索策略由谁设计"这一问题显式地推到了前台，并用一套可运行的编码智能体系统给出了"交给模型"的工程答案。
- 其最有价值的贡献未必是某个具体任务的分数，而是三点可迁移的设计：**用图数据库把经典搜索规则归约为查询**、**用上下文重置对抗长程成本与局部最优**、**用元 pass 把有效思维模式固化为可复用技能**。
- 主要短板在于**统计严谨性与机制解释**：单次运行的主表结果、缺失的策略使用分析，使得"自主搜索优于人工搜索"这一核心命题目前更像是有力的存在性证据，而非已被充分证伪的普遍结论。
- 综合来看，论文为"最小人工脚手架 + 最大化模型自主性"这一方向提供了当前较完整的实证基线，其结论的强度应随后续多随机种子复现、跨模型验证与策略日志分析而进一步校准。

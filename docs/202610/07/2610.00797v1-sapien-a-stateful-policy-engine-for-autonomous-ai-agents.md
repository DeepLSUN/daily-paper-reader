## 摘要
上下文安全防御通过合成任务特定的策略，并将其强制应用于智能体的工具调用，来防止 AI 智能体采取越轨行为。然而，在多步任务中，哪些动作是有效的，通常取决于智能体已经执行过和已经学到的内容。我们提出 Sapien，一种用于强制执行有状态上下文策略的策略引擎。Sapien 策略使用扩展了有状态谓词、延迟策略生成和作用域语义检查的正则表达式来规定允许的工具调用序列。我们表明，Sapien 的效用与无约束智能体的效用相差仅几个百分点。即使智能体被完全劫持，Sapien 的策略也能在 AgentDojo 上排除 93-95% 的攻击，在 Toolathlon 上排除 62-85% 的攻击（在长时程任务上，这一比例是工具允许列表的两倍）。

## Abstract
Contextual security defenses prevent AI agents from taking rogue actions by synthesizing a task-specific policy and enforcing it on the agent's tool calls. In multi-step tasks, however, which actions are valid often depends on what the agent has already done and learned. We present Sapien, a policy engine for enforcing stateful contextual policies. A Sapien policy specifies permitted tool-call sequences using a regular expression extended with stateful predicates, deferred policy generation, and scoped semantic checks. We show that Sapien stays within a few percent of an unconstrained agent's utility. Even if the agent is fully hijacked, Sapien's policies rule out 93-95% of attacks on AgentDojo and 62-85% on Toolathlon (twice as many as tool allowlists on long-horizon tasks).

## 1. 核心问题与整体含义

### 1.1 研究背景

- **AI 智能体的兴起**：基于大语言模型（LLM）的智能体通过调用外部工具自主规划并执行自然语言任务，能够处理跨领域的复杂长时程任务（如管理在线账户、组织会议、协调旅行等）。
- **越轨行动（Rogue Actions）威胁**：将工具调用权交给 LLM 使智能体本质上不可靠，可能产生偏离用户意图的工具调用，其触发途径包括：
  - **对抗性操纵**：间接提示注入（Prompt Injection, PI），攻击者通过智能体摄入的网页、邮件、日历邀请等嵌入指令劫持轨迹；
  - **良性漂移**：长时程任务中智能体自发偏离目标、误读工具输出或即兴采取未预期的变通手段。
- **现实危害**：智能体已实际造成清空用户收件箱、删除生产数据库、攻击外部基础设施、执行攻击者控制的命令等事故。

### 1.2 核心矛盾：静态策略 vs. 通用智能体

- 传统系统采用**参考监视器（Reference Monitor）** 对每个动作按策略进行检查，但这类策略通常是**静态的**——适用于目的预先已知的程序。
- **通用智能体的困境**：某一动作是否合法取决于**用户当前任务**。例如 `send_money` 在"退还上周给我汇款的人"任务中是恰当的，但在"总结我的收件箱"任务中则是越轨行为。
- 静态策略面临两难：允许 `send_money` 会使收件箱摘要面临资金被盗风险；禁止它又会破坏合法的退款操作。

### 1.3 既有方案与不足

- **上下文智能体安全框架**：为每个请求即时合成任务特定策略，并由参考监视器强制执行。策略生成器仅接触用户提示和工具文档，与不可信运行时数据隔离。
- **关键洞察**：策略的紧致程度受**策略语言表达能力**的限制（论文图 1）。
  - **无状态策略**（如工具允许列表）会过度近似，因为它无法引用变化的运行时上下文；
  - **有状态策略**能更紧密地包围适当行为——下一步能做什么，必须取决于智能体已经做过什么、已经观察到了什么。
- 以"退还上周汇款人"为例：智能体必须先 `list_transactions`，然后仅能向出现在上周交易记录中的发件人、按该记录中的金额调用 `send_money`。这种约束**必须依赖运行时状态**才能表达。

### 1.4 论文的整体含义

Sapien 提出一种**有状态策略语言**及配套的**策略引擎**，用于自主 AI 智能体的多步任务安全执行。其核心主张是：即使智能体被完全劫持，策略仍能拒绝绝大多数攻击轨迹，同时保持与无约束智能体几乎持平的效用。

## 2. 方法论

### 2.1 核心思想

Sapien 采用**上下文智能体安全**框架，分为两个阶段：

1. **事前策略生成**：每个任务开始前，策略生成器 LLM 根据任务提示和工具文档合成该任务专属的策略；
2. **运行时强制执行**：拦截器（Enforcer）对智能体提出的每次工具调用进行检查，仅当调用被策略允许时才执行。

### 2.2 威胁模型与关键假设

- **假设被攻陷的**：智能体 LLM（可被提示注入、记忆投毒或权重篡改），可被迫提出任意工具调用；
- **假设可信的**：策略生成器 LLM 被正确训练且未被攻陷；用户会话未被攻陷；工具行为符合文档；harness 和 Sapien 的拦截不可绕过。
- **策略完整性"不变式"**：生成的策略反映用户意图。Sapien 通过设计保障该不变式——生成器只读取用户提示与工具文档，不接触不可信内容。
- **重要区分**：隔离仅适用于**策略生成**，不适用于**策略执行**。执行阶段可以基于运行时观察到的（可能含对抗内容的）数据做判定，因为这些数据只是固定策略检查的输入，攻击者无法改变判定标准。

### 2.3 策略语言：四大原语

Sapien 策略使用**扩展正则表达式**描述允许的工具调用序列，语法如图 3 所示，包含四个原语：

#### （1）正则操作符（§4.1）

- 基础操作：空轨迹、调用模式、序列（`·`）、选择（`+`）、重复（`*`/`+`）；
- **Shuffle 操作符（`||`）**：允许两个子任务交错执行，同时保持各自内部顺序。例如 `(read_inbox . send_email) || (search_web . post_msg)` 允许两个子任务的步骤任意交错，但各自保持 read-before-write 的次序。用选择操作符表达会带来组合爆炸，shuffle 以单一紧凑表达式捕捉所有逐步交错。

#### （2）变量绑定与谓词（§4.2）

- 调用模式中的参数可匹配字面量或**谓词** `PREDICATE(p)`，其中 `p` 是接收提议参数值并返回布尔的 Python 函数；
- 通过 `@x` 将调用参数和返回值绑定到变量，供后续谓词作为 Python 变量使用；
- 与静态分析形式化不同（后者限制为简单相等检查以保证可判定性），Sapien 谓词**仅在运行时**对具体参数和变量绑定求值，因而可写成任意 Python 函数；
- **迭代下的绑定**累积为列表：如 `(read_email@emails)*` 按执行顺序保存所有 `read_email` 结果，谓词可据此检查提议参数是否与智能体实际观察到的内容一致。

#### （3）延迟策略生成（§4.3）

- 针对"任务内容仅在执行时才揭示"的场景（如"完成我 TODO 列表上的任务"），引入 `defer(g)` 操作符在策略中放置**空洞**；
- 空洞不匹配任何工具调用，智能体须调用 `resolve` 动作命名生成器 `g`；Sapien 读取作用域内绑定变量，组合子任务指令，调用策略生成器生成子策略，并拼接进空洞；
- **与不变式的关系**：当用户要求执行网页上的任务时，用户已将该任务的规格说明**委托**给网页，如同网页被直接写入任务提示。因此 defer 反而**有助于**维护不变式——展开后仅允许页面上任务的策略，比允许任意动作的策略更贴近用户意图。

#### （4）语义谓词（§4.4）

- 对无法用代码检查的自然语言属性（如邮件是否忠实摘要了文档），谓词可调用 `verify_with_ai` 向 LLM 裁判提出**作用域受限的**是/否问题；
- **与整体 LLM 裁判的关键区别**：① 检查是**狭窄且局部**的（比较两个具体字符串，而非开放式询问动作是否安全）；② 裁判仅接收回答问题所需的输入，而非智能体的完整执行轨迹，降低提示注入暴露面；
- **安全边界**：语义谓词只能**收窄**策略允许的动作——即使裁判被骗返回 True，周围的确定性策略（读哪个文档、向哪个地址发一封邮件）仍被严格强制执行。

### 2.4 策略引擎实现（§5）

#### 编译为增强 NFA

- 采用 Thompson 构造法进行标准语法指导翻译，每个子表达式映射为单入口单出口的 NFA；
- 基础调用模式编译为两个状态间的转移，携带工具名、参数约束和可选变量绑定；
- 组合操作符：序列、选择、迭代用 ε-转移连接；shuffle 取其操作数状态集的**笛卡尔积**。

#### 活动配置跟踪

- 与传统 NFA 不同，Sapien 的转移会绑定已完成调用的记录到变量，因此到达同一状态但绑定不同的两条路径可能允许不同的未来调用；
- 引擎跟踪**活动配置** `(q, ρ)`——自动机状态与变量赋值的配对；
- `can_advance(a, p)`：检查是否存在活动配置（经 ε-转移后）能对工具 `a` 取转移且参数约束在 `ρ` 下成立；
- `advance(r)`：所有匹配配置步进到目标状态、扩展赋值、丢弃不匹配配置。

#### 接口设计

- `init(u)`：从任务提示生成并安装策略；
- `can_advance(a, p) → (ok, reason)`：检查提议调用是否允许，不修改状态；
- `advance(r)`：记录允许调用完成及其返回值，推进状态。

#### 其他工程细节

- **策略暴露**：生成策略后将策略表达式、谓词定义和生成器理由追加到智能体上下文，帮助其规划并识别何时需解析 defer 空洞；
- **拒绝反馈**：返回诊断信息，指明哪个参数未通过哪个谓词及谓词源码，帮助智能体恢复；
- **原型实现**：Python 库，集成 Google ADK、AgentDojo 与 Toolathlon 评测框架；策略生成使用两次 LLM 调用（草拟 + 自校正），延迟子策略生成同理；
- **谓词求值**：在自定义 globals 字典中 `exec` Python 代码块一次，调用时按配置填充绑定，调用后清除；
- **空洞展开简化**：原型采用 AST 级替换（替换子策略、重编译、重放调用轨迹），要求每个空洞至多解析一次且生成器在所有配置下产生相同指令字符串。

## 3. 实验设计

### 3.1 基准（Benchmarks）

| 基准 | 任务数 | 特点 | 攻击实例 |
|------|--------|------|----------|
| **AgentDojo** | 97 个短任务（多数 ≤5 轮） | 合成环境，四个套件（workspace、Slack、travel、banking），每个暴露 11–28 个工具 | 949 个（用户任务 × 注入任务配对） |
| **Toolathlon** | 108 个长时程任务（数十轮） | 真实环境：本地文件/shell 工作区 + 32 个软件应用（GitHub、Notion、Google Workspace 等），600+ 工具（MCP） | 212 个（论文自建 1–2 个攻击目标/任务） |

- 为防止 Toolathlon 通过 `local_python_execute` 等"全能工具"授予无限制能力，所有智能体预先禁用该工具，且要求 Sapien 为 `terminal_run_command` 指定命令谓词（如命令必须是 `grep`）。

### 3.2 对比方法（Baselines）

三种由不同机制管辖工具调用的智能体：

1. **NoPolicy**：无策略约束；
2. **AllowList**：按 Conseca [57] 风格从任务提示生成的**每任务工具名允许列表**，代表粗粒度、无状态的上下文策略（一次 LLM 调用生成，无自校正）；
3. **Sapien**：本文提出的有状态策略引擎。

### 3.3 评估模型

四个模型：**Gemini 3.8 Flash、Gemini 3.1 Pro、Claude Sonnet 5、Claude Opus 5**。每次运行使用同一模型进行智能体执行和策略生成。

### 3.4 评估指标

1. **效用（Utility）**：良性环境下智能体完成任务的比例（按各基准原生完成标准）；
2. **安全性（Security）**：采用**分析式评估**——假设攻击者已完全劫持智能体，判断策略是否允许任何实现攻击者目标的工具调用序列。三种自动检查：
   - **必需工具检查**：策略完全禁止攻击所需工具则判定攻击失败；
   - **重放检查**：策略允许基准的 ground-truth 攻击轨迹则判定攻击成功；
   - **对抗搜索**：对抗性智能体（Gemini 3.8 Flash）在给定策略和目标下寻找允许的利用轨迹；
   - 剩余实例由人工按相同假设裁定。
3. **效率（Efficiency）**：推理次数、策略生成延迟、策略检查开销等。

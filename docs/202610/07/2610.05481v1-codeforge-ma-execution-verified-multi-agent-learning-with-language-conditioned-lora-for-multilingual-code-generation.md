## 摘要
用于代码生成的大型语言模型常常在执行、多语言覆盖和污染控制方面表现不佳，尤其是在冻结骨干网络的约束下。我们提出 CodeForge-MA，一个统一框架，通过多智能体数据锻造、执行验证的强化指令微调，以及语言条件化的 LoRA 适配器混合来改进代码合成。四个专门智能体——Composer、Reviewer、Executor 和 Curator——迭代地精炼指令-代码对，用测试验证它们，并过滤重复项和基准泄漏。在训练期间，我们将掩码监督微调与测试驱动的强化目标相结合，以使生成结果与可执行正确性对齐。对于更大的模型，我们在低秩适配器上使用稀疏专家路由，以提高跨语言迁移，同时在推理时保持基础模型不变。实验表明，联合的数据、目标和适配器设计能在多种编程语言上带来稳健的增益。

## Abstract
Large language models for code generation often fail on execution, multilingual coverage, and contamination control, especially under frozen backbone constraints. We present CodeForge-MA, a unified framework that improves code synthesis through a multi-agent data forge, execution verified reinforced instruction tuning, and a language conditioned mixture of LoRA adapters. Four specialized agents, Composer, Reviewer, Executor, and Curator, iteratively refine instruction code pairs, validate them with tests, and filter duplicates and benchmark leakage. During training, we combine masked supervised fine tuning with a test driven reinforcement objective to align generations with executable correctness. For the larger model, we use sparse expert routing over low rank adapters to improve cross language transfer while keeping the base model unchanged at inference. Experiments show that joint data, objective, and adapter design yields robust gains across programming languages.

### 2.1 多智能体数据锻造
- 四个智能体：
  - **Composer**：从种子生成指令-代码对。
  - **Reviewer**：评分风格、正确性、教学价值；用 self-consistency 采样 5 次取均值，降低单次 LLM 评审噪声。
  - **Executor**：在沙箱中编译并运行代码，产生执行指标。
  - **Curator**：全局去重与去污染。
- 样本状态为 `(X, Y, r, q, π)`，接受条件为：执行通过 `π=1`、质量分 `q≥0.75`、修订次数 `k≤3`。
- 若未通过，不直接丢弃，而是把 Reviewer 报告和 Executor traceback 反馈给 Composer，形成 Reflexion 式闭环修复。
- **语言均衡**：按语言采样温度 `α=0.3` 重加权，避免 Python 样本占比超过 70%，使六语言分布更均衡。
- **去重/去污染**：用 5-gram shingle 的 Jaccard 相似度，MinHash LSH 近似；与已保留样本或 HumanEval/HumanEvalFix/MBPP 提示相似度 `J>0.8` 则丢弃。

### 2.2 Execution-Verified Reinforced Instruction Tuning
- **掩码监督微调**：只在 assistant turn 上计算交叉熵，避免模型复述 system/user 文本或 docstring。
- **执行奖励**：对采样代码 `Ŷ`，奖励 `R` 为通过单元测试比例。
- **PPO 风格强化**：使用 clipped surrogate，并加 KL 惩罚约束到冻结参考策略，防止 reward hacking。
- **warm-up 调度**：先纯 SFT 学习流畅性，`T0=500` 步后逐步激活 RL，`TW=1000` 步内升到 `λmax=0.3`。
- **语言重加权**：按语言频率 `wℓ ∝ |Dℓ|^{-0.5}` 聚合损失，缓解语言不平衡。

### 2.3 Language-Conditioned Mixture-of-LoRA
- 面向 Qwen-72B，在注意力投影 `WQ/WK/WV/WO` 上挂载 `E=6` 个 LoRA 专家，秩 `r=32`，缩放 `α=64`。
- 路由器基于 prompt 的 mean-pooled 最终层表示，产生 top-2 稀疏门控，每 prompt 激活两个专家。
- 适配权重为 `W = W0 + Σ ge ΔWe`，推理时骨干不变，只增加少量路由开销。
- 两个正则项：
  - **Switch 式负载均衡损失**：防止专家坍缩。
  - **软语言身份先验**：用轻量语言分类器产生软目标，鼓励专家与语言家族对应，同时保留跨语言迁移。
- 总目标包含 EV-RIT 损失、负载均衡、语言身份先验和 LoRA 参数 L2 正则。

### 2.4 Prompt 与预处理
- 使用角色专用 ChatML 模板，Composer 输出 JSON-fenced schema，避免解释文字破坏编译。
- **Chain-of-Repair**：修复任务输出 `Φloc + Φrat + Φfix`，但评估时只用 `Φfix`，训练时用一致性正则连接三者。

## 7. 优点

- **联合设计**：同时优化数据、训练目标和适配器，而不是只做单点微调。

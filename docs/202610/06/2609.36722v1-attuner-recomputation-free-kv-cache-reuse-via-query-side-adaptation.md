## 摘要
大型语言模型（LLM）智能体反复将可复用内容（如技能、文档和记忆条目）加载到当前上下文中。针对每个请求重新编码这些内容会造成计算浪费。位置无关缓存（PIC）通过独立编码每个制品并在任意位置复用其键值（KV）状态来缓解该问题，但与全上下文预填充相比会带来质量损失。现有方法通过恢复全局位置 ID 或重新计算选定 token 来修复这一损失。在这项工作中，我们定位了损失来源，发现位置不匹配的影响较小，并且独立缓存的制品仍保留忠实的表示：读取所提供的制品时大体上仍准确，只有当模型必须在多个制品之间进行选择时，性能才会下降。此外，在缓存 KV 保持不变的情况下，用全预填充分数替换 PIC 的注意力分数即可恢复性能，从而将失败定位到注意力而非 KV 重计算。受此启发，我们提出 Attuner，一种查询侧适配方法，学习读取冻结的制品缓存。Attuner 将低秩适配器插入查询投影中，并通过将全预填充分布蒸馏到学生模型中进行训练。它训练的参数量不到模型参数的 0.05%，并且在推理时既不需要缓存重计算，也不需要全上下文参考。在 Qwen3-4B 和 Qwen3-8B 上，涵盖技能、文档、记忆和代码的七个基准中，Attuner 在域内和域外设置下均显著优于先前的 PIC 基线，达到与全上下文预填充相当的质量，同时提供高达 3.73 倍的加速。

## Abstract
Large language model (LLM) agents repeatedly load reusable content, such as skills, documents, and memory entries, into the current context. Re-encoding this content for every request wastes computation. Position-independent caching (PIC) alleviates this by encoding each artifact independently and reusing its key-value (KV) states at arbitrary positions, but it incurs a quality loss relative to full-context prefill. Existing methods repair this loss by restoring global position IDs or recomputing selected tokens. In this work, we isolate the source of the loss, finding that the positional mismatch has minor effect, and independently cached artifacts retain faithful representations: reading a provided artifact stays largely accurate, and performance degrades only when the model must select among multiple artifacts. Moreover, replacing PIC's attention scores with full-prefill scores recovers performance with the cached KV unchanged, localizing the failure to the attention rather than KV recomputation. Motivated by this, we propose \textsc{Attuner}, a query-side adaptation method that learns to read a frozen artifact cache. \textsc{Attuner} inserts low-rank adapters into the query projections and is trained by distilling full-prefill distribution into the student. It trains fewer than 0.05\% of the model parameters and, at inference, requires neither cache recomputation nor a full-context reference. On Qwen3-4B and Qwen3-8B across seven benchmarks covering skills, documents, memory, and code, \textsc{Attuner} substantially outperforms prior PIC baselines in both in-domain and out-of-domain settings, matches full-context prefill quality while providing up to $3.73\times$ speedup.

## 一、核心问题与研究动机

- **背景**：LLM 智能体（agent）在运行时反复将可复用内容（技能描述、文档、记忆条目等，统称"制品 artifact"）动态组装进当前上下文。每个请求都重新编码这些内容会浪费大量计算，并显著抬高首 token 时间（TTFT）。
- **现有方案及其局限**：
  - 传统前缀缓存（如 RadixAttention）假设可复用内容在请求间占据相同前缀位置，但智能体工作负载中制品的种类、顺序、位置由检索/路由/规划在运行时动态决定，该假设不成立。
  - 位置无关缓存（PIC）通过独立编码每个制品、在请求时按任意位置装配缓存块来缓解该问题，但与全上下文预填充（Full prefill）相比存在**质量损失**。
- **PIC 的两类错配**：
  1. **位置错配**：制品编码时位置未知，其位置索引与全预填充不一致。
  2. **上下文错配**：独立编码的制品无法关注前置请求特定制品，缺乏跨制品条件化。
- **本文的核心追问**：质量损失究竟源于缓存表示（KV）本身，还是源于模型如何"读取"缓存（注意力路由）？
- **关键发现（论文的核心洞察）**：
  - 位置对齐（PIC-Pos）只能带来边际改善，不能稳定弥合差距。
  - 单制品场景下证据利用率损失很小，说明独立缓存的表示是**忠实的**；多制品场景下性能显著下降，说明失败在于**跨制品的注意力分配**。
  - **路由 oracle 实验**：保留 PIC 的缓存 KV 不变，仅将在线 token 的注意力权重替换为全预填充的注意力分数，任务质量即恢复至接近 Full 水平（MuSiQue EM 从 34.84→47.91，Full 为 47.79；BigCodeBench pass@1 从 38.98→44.53，Full 为 43.63）。
  - 结论：**失败定位在注意力分数计算，而非 KV 重计算**，因此存在一条"不重建缓存、仅修正读取方式"的恢复路径。

## 二、方法论：ATTUNER

### 2.1 核心思想

- 不改写缓存，而是**学习如何读取冻结的制品缓存**：在查询（query）投影上做低秩适配，使在线 token 学会对缓存键进行有效的注意力路由。
- 制品 KV 由原始未适配模型离线构建并保持不变；适配仅作用于在线未缓存 prompt token 和生成 token。
- 选择查询侧适配而非缓存侧修改的原因：查询仅对在线 token 计算，而缓存键/值可直接复用，因此**天然保持缓存复用性**。

### 2.2 关键技术细节

- **查询低秩适配**（对每一 Transformer 层 ℓ）：

  e_q_{ℓ,t} = W_Q_ℓ · h_{ℓ,t} + (α/r) · B_ℓ A_ℓ h_{ℓ,t}

  其中 h_{ℓ,t} 为投影输入，A_ℓ ∈ R^{r×d_model}、B_ℓ ∈ R^{d_q×r} 为可训练矩阵，r 为秩，α 控制更新尺度。适配后的查询再经过原有的查询归一化和 RoPE 后进入注意力。
- **初始化**：A_ℓ 用 Kaiming 均匀初始化，B_ℓ 置零，使初始更新为零；仅训练 A_ℓ、B_ℓ，基础模型参数全部冻结。
- **训练目标——输出分布蒸馏**：
  - 冻结的 Full-context 教师模型对每个请求 X 生成响应 Y，构成固定训练集 D_T。
  - 教师使用全预填充，学生使用独立缓存的制品 KV，两者接收相同输入并条件于相同响应前缀 Y_{<t}。
  - 最小化教师与学生输出分布之间的 KL 散度（教师侧 stop-gradient）：

    L(φ) = E_{(X,Y)~D_T} [ (1/|Y|) Σ_{t=1}^{|Y|} D_KL( sg[p^Full_θ(·|X,Y_{<t})] ‖ p^PIC_{θ,φ}(·|X,Y_{<t}) ) ]

  - 只监督输出分布而非注意力权重，让学生自行学习适配固定缓存的读取策略。
- **部署**：训练后的更新可合并回查询投影 W_Q_ℓ ← W_Q_ℓ + (α/r)B_ℓA_ℓ，推理时**无需 Full-context 教师，也无需任何缓存重计算**。
- **训练参数规模**：少于模型总参数的 **0.05%**（仅 query 投影的 LoRA 适配器）。

## 三、实验设计

### 3.1 模型与数据集

- **七个基准，覆盖四类制品**：

### 3.2 评估指标

- 任务质量：BigCodeBench 用 pass@1，MuSiQue 用 F1（诊断实验也用 EM），其余用 accuracy。

- **参考**：Full prefill、PIC、PIC-Pos（位置对齐诊断）。

## 六、主要结论与发现

1. **损失来源定位**：PIC 的质量损失主要来自**注意力路由**而非缓存 KV 表示；位置错配影响次要，位置对齐不能稳定恢复

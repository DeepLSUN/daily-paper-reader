## 摘要
从自然语言请求中定位相关文件是在代码仓库上运行的智能体的一项核心子任务。我们研究是否可以将该任务委派给紧凑的专用模型，以支持端侧搜索，同时降低更大智能体的 token 用量、延迟和推理成本。我们表明，语义搜索可改善文件定位，在准确率、跨语言迁移和推理效率方面带来提升。为研究这一设定，我们引入了一个面向文件定位智能体的训练框架，其围绕 ColGREP 构建，ColGREP 是一种基于后期交互检索模型的本地语义搜索工具。我们的方法将基于教师轨迹的加权监督微调（根据检索结果分配轮级信用）与针对定位质量的强化学习相结合。我们训练了三个参数量少于二十亿的模型系列，用于制定搜索查询、检查检索内容并识别相关文件。在源自 SWE-bench Lite 和 Multi-SWE-bench Flash 的定位任务上，配备 ColGREP 的智能体相较其基础模型有显著提升，并优于相应的基于 GREP 的智能体。除了提高定位准确率外，ColGREP 在 CPU 上将平均端到端轨迹延迟降低 44.1%，同时减少 29.1% 的 token 用量，并能更好地泛化到微调期间未见的编程语言。这些结果表明，紧凑的、工具专用的定位智能体可以在自然语言请求与大型代码库之间提供高效接口。

## Abstract
Locating relevant files from natural-language requests is a core subtask for agents operating over code repositories. We investigate whether this task can be delegated to compact, specialized models to enable on-device search while reducing the token usage, latency, and inference cost of larger agents. We show that semantic search improves file localization, with gains in accuracy, cross-language transfer, and inference efficiency. To study this setting, we introduce a training framework for file-localization agents built around ColGREP, a local semantic search tool based on late-interaction retrieval models. Our recipe combines weighted supervised fine-tuning on teacher trajectories, assigning turn-level credit based on retrieval outcomes, with reinforcement learning on localization quality. We train three model families with fewer than two billion parameters to formulate search queries, inspect retrieved content, and identify relevant files. On localization tasks derived from SWE-bench Lite and Multi-SWE-bench Flash, ColGREP-equipped agents substantially improve over their base models and outperform corresponding GREP-based agents. In addition to improving localization accuracy, ColGREP reduces mean end-to-end trajectory latency by 44.1\% on CPU while using 29.1\% fewer tokens, and enables better generalization to programming languages unseen during fine-tuning. These results suggest that compact, tool-specialized localization agents can provide an efficient interface between natural-language requests and large codebases.

## 1. 核心问题与整体含义

- **研究动机**：代码智能体在修复仓库级 issue 前，必须先定位需要修改的文件。这一"定位"步骤通常依赖反复的目录列举、词法搜索（grep）和文件读取，开销巨大。例如 CodeGrep 报告称，一个 30B 的 OpenHands 智能体在 SWE-bench Verified 上每个已解决 issue 平均需要 **23 轮交互和 631K tokens**。
- **核心问题**：能否将"文件定位"这一子任务**委托给紧凑的专用小模型**，从而支持端侧搜索，并降低大模型的 token 用量、延迟与推理成本？
- **关键研究问题**：在参数量**低于二十亿（<2B）**的约束下，**搜索接口**（词法工具 vs. 语义检索）与**训练信号**如何塑造文件定位策略？
- **整体含义**：论文将定位视为一个**独立的可学习决策问题**，训练小型专用智能体充当自然语言请求与大型代码库之间的高效接口，为资源受限部署提供可行路径。

## 2. 方法论

### 2.1 核心思想
- 围绕 **colgrep**（基于 ColBERT 家族晚期交互模型的本地语义搜索工具，底层为 NextPlaid/PLAID 索引，单 Rust 二进制，完全本地运行）构建两阶段训练框架。
- 智能体通过 **三个工具**与只读沙盒交互：
  - `colgrep`：自然语言查询 + 可选正则过滤（`pattern`）、路径（`path`）、文件类型（`include`）、结果数（`k`，默认 10，最大 25）；
  - `terminal`：只读 shell，用于导航、词法搜索、文件查看；
  - `finish`：提交文件路径（可带行范围或符号名）。
- 编码器统一使用 **LateOn-Code-edge**（17M 参数晚期交互模型），采用 **MaxSim** 打分：对每个查询 token 取候选代码单元中的最大相似度并求和，兼顾词法、标识符与语义匹配。
- 交互预算：最多 10 轮，每轮最多 5 个并行工具调用；若未提交，则用已查看文件作为兜底提交。

### 2.2 阶段一：加权监督微调（Weighted SFT）
- **教师轨迹生成**：使用 DeepSeek-V4-Flash-0731 生成，temperature 0.3，并在生成时提示教师优先使用 colgrep。
- **轨迹筛选对比**：
  - Unfiltered：保留全部有效轨迹；
  - F1 过滤：要求提交 F1 ≥ 0.5；
  - **加权 SFT**：按工具结果分配**轮级信用（turn-level credit）**：
    - 发现新的 gold 文件 → 权重 1.0；
    - 重复查看已发现的 gold 文件 → 0.6；
    - 仅检索到非相关文件 → 0.3；
    - 空结果/错误/重复命令 → 0.05；
    - 最终提交轮按其对 gold 文件的召回率加权。
- **损失函数**（公式 1）：对每个 assistant 轮次 i 的 token 位置集合 $T_i$ 施加权重 $w_i$，最小化加权交叉熵：

$$L_{\text{SFT}} = \frac{\sum_i w_i \sum_{t \in T_i} \text{CE}_t}{\sum_i w_i |T_i|}$$

- Prompt 与工具观测 token 被 mask；gold 标注仅用于构造训练权重，评估时不可用。

### 2.3 阶段二：强化学习（RL）
- 从 SFT checkpoint 出发，使用 **GRPO**，并做了如下修改：
  - 移除 KL 惩罚与组内优势的标准差归一化（遵循 Dr. GRPO）；
  - 采用零优势过滤 + 动态采样（遵循 DAPO）；
  - 异步生成 rollout，落后策略更新超过 4 步的样本被丢弃。
- **奖励设计对比**：
  - File F1（平衡精度与召回）；
  - File F2（更重召回）；
  - File+Class+Function F1（细粒度监督，用于 Python 实例）；
  - 所有奖励含 **格式惩罚 −0.5**（无搜索动作或未通过 finish 提交）。
- **轮次惩罚**（公式 2）：前 2 轮不惩罚，之后每轮降低任务奖励 1%，最多降低 8%：

$$R = R_{\text{task}} \left[1 - \min(p_{\max}, \lambda \max(0, T - T_0))\right] + R_{\text{format}}$$

## 6. 主要结论与发现

1. **语义搜索全面优于词法搜索**：在每个训练阶段、两个 benchmark、三个模型家族上，colgrep 的文件 F1 均高于 grep。例如 Qwen3-1.7B + RL 后，colgrep 达 67.29 vs. grep 63.75（SWE-bench Lite），54.00 vs. 50.16（Multi-SWE Flash）。
2. **训练显著缩小接口差距**：Multi-SWE Flash 上 colgrep 的优势从 Base 阶段的 17.01 分降至 SFT 后 11.74、RL 后 3.84。
3. **加权 SFT 一致最优**：轮级加权在三个学生、两个 benchmark 上均取得最高文件 F1，优于 unfiltered 与 F1 过滤。
4. **RL 奖励存在权衡**：file F1 奖励最均衡；F2 召回最高但 F1 下降；file+class+function 奖励在类/函数级最优；轮次惩罚仅损失 0.63 分 F1 却大幅缩短轨迹。
5. **智能体优于直接检索**：单轮 agent 已超过 BM25 oracle 8.19（SWE Lite）/16.48（Multi-SWE）分，并超过更强的 colgrep oracle 2.19/4.46 分；多轮进一步提升，且检索调用仅从 2.00 增至 2.06。
6. **效率提升显著**：CPU 端到端延迟从 36.08s 降至 20.18s（**−44.1%**），GPU 从 2.15s 降至 1.92s（**−10.6%**）；轨迹长度从 7,857 降至 5,574 token（**−29.1%**）。GPU 下 LLM 推理占 grep 延迟 87.6%，colgrep 仅 53.1%。
7. **跨语言泛化更强**：Python-only SFT 下，colgrep 平均仅下降 **2.13 分**，而 grep 下降 **14.90 分**；colgrep 在全部 7 种语言上均领先（平均优势 28.82 分）。
8. **RL 收敛出短轨迹**：约几百步更新后，colgrep 策略平均仅约 2 次语义搜索、3 轮 assistant 交互即可完成定位。

## 7. 优点

- **问题定位清晰**：将仓库级修复显式分解为"定位"与"编辑"，单独度量定位，便于隔离变量与归因分析。
- **对称对比设计**：grep 与 colgrep 各自用对应接口生成教师轨迹并走相同训练管线，比较公平。
- **训练方法有创新**：提出**基于检索结果的轮级信用分配**（加权 SFT），使失败轨迹中的有效检索步骤也能被保留学习，优于整条轨迹的二元过滤。
- **多维度评估**：同时报告准确率（文件/类/函数 F1）、效率（延迟、token、轮次）、跨语言泛化与 RL 动态，分析层次丰富。
- **工程可落地**：colgrep 为单二进制本地工具、17M 检索编码器、预建索引，契合端侧/CPU 部署场景。
- **oracle 上界基线**设计巧妙，明确区分了"检索器能力上限"与"智能体多轮搜索增益"。

## 8. 不足与局限

- **评估标签局限**：以参考补丁修改的文件为 gold，仅代表一种可能的解，可能遗漏有用的上下文文件。
- **领域局限**：仅限代码仓库，未扩展到通用文档检索等其他检索密集型领域。
- **算力报告不完整**：未给出 SFT 阶段算力、总训练时长或完整 GPU 小时数。

- **奖励设计依赖超参**：轮次惩罚的 λ、T₀、p_max 以及各档位权重（1.0/0.6/0.3/0.05）均为人工设定，论文未给出敏感性分析，其最优性缺乏系统性证据。
- **教师模型依赖**：SFT 轨迹完全来自 DeepSeek-V4-Flash-0731 单一教师，未探索多教师、更强教师或自蒸馏策略对最终策略的影响。
- **效率对比口径**：CPU/GPU 延迟测量中 colgrep 每次调用均重新启动进程并加载 17M 编码器，未与"常驻检索服务"或"预加载索引"的工程优化版本对比，因此报告的绝对延迟可能高估了语义检索的真实代价，而相对优势方向则可能被低估或高估，需谨慎解读。
- **未评估端到端修复效果**：全文聚焦"定位"子任务，未将定位智能体接入完整的 issue 修复流水线，因此"定位 F1 提升 → 最终修复成功率提升"这一关键传导链条尚属推断而非实证。
- **缺乏与商业/闭源定位方案对比**：除教师模型与 Qwen3-32B 外，未与其它专门的代码检索系统（如基于嵌入的 dense retrieval、混合检索）在同一协议下比较。

## 9. 总体评价与启示

- **核心贡献**：论文系统性地回答了"搜索接口与训练信号如何塑造小型代码定位智能体"这一问题，提出并验证了两条关键结论——**语义检索接口优于词法接口**，以及**基于检索结果的轮级加权信用分配优于轨迹级二元过滤**。二者结合使 <2B 模型在文件级定位上逼近乃至超过更大模型与 oracle 检索基线。
- **方法学价值**：将"检索器质量上限（oracle）"与"智能体多轮搜索增益"显式分离的评估框架，以及 grep/colgrep 的对称训练协议，为后续代码检索与智能体研究提供了可复用的对照设计。
- **实践启示**：对于端侧或成本敏感场景，**用小型专用模型承担定位、用大模型承担编辑**的分工具有明显收益——不仅降低 token 与延迟，还减少了对大模型多轮工具调用的依赖。
- **未来方向**：扩展到更大模型验证规模效应、引入常驻检索服务以测量真实延迟、将定位接入端到端修复流水线评估最终成功率、以及探索自适应接口选择（词法/语义混合路由）都是自然的后续工作。

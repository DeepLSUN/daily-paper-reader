## 摘要
大型语言模型智能体越来越依赖复合程序来完成检索、工具使用、推理和验证，然而其失败往往源于局部过程决策。现有的强化学习和提示优化方法通常依赖标量奖励，或反复修改整个提示，因而难以在保持智能体冻结的同时捕获和复用过程性改进。为解决这一问题，我们提出自然语言策略梯度（NLPG），一种外部策略记忆方法，可在不改变固定智能体的模型参数或程序结构的情况下对其加以改进。NLPG 诊断执行轨迹，将下游反馈沿模块图反向传播，并将反复出现的失败转化为路由局部的自然语言修正，这些修正被聚合成有界策略更新，用于后续执行。在涵盖记忆、推理、指令遵循和证据验证的六个基准上，NLPG 相较每个基准所列最强基线平均高出 8.71 个百分点。这些结果表明，经过评估的过程性经验可以转化为局部且可解释的策略更新，从而实现冻结智能体的持续改进。

## Abstract
Large language model agents increasingly rely on compound programs for retrieval, tool use, reasoning, and verification, yet their failures often arise from local procedural decisions. Existing reinforcement-learning and prompt-optimization approaches typically rely on scalar rewards or repeatedly modify entire prompts, making it difficult to capture and reuse procedural improvements while preserving a frozen agent. To address this problem, We propose Natural-Language Policy Gradients (NLPG), an external policy-memory method for improving a fixed agent without changing its model parameters or program structure. NLPG diagnoses execution traces, propagates downstream feedback backward through the module graph, and converts recurring failures into route-local natural-language corrections that are aggregated into bounded policy updates for subsequent executions. Across six benchmarks covering memory, reasoning, instruction following, and evidence verification, NLPG also outperforms the strongest listed baseline for each benchmark by 8.71 percentage points on average. These results provide evidence that evaluated procedural experience can be transformed into local and interpretable policy updates, enabling continual improvement of frozen agents.

## 2. 方法论

### 2.1 核心思想
将复合智能体的策略记忆（Policy Memory）外置化，按**任务类别或程序模块**（route）索引。失败信息沿**模块依赖图反向传播**，由语言 Critic 转化为**路由局部的自然语言修正**，再跨执行样本聚合、过滤、打分，形成下一轮有界策略更新。

### 2.2 关键概念与符号
- **程序模块 b**：执行显式操作的单元（检索、工具、验证、解析）。
- **策略记忆 Mt = {Mᵃₜ}**：按路由 a 索引的短自然语言指令集合，存储过程性经验而非任务答案。
- **执行轨迹 τᵢ = (xᵢ, {aᵢ,ⱼ, cᵢ,ⱼ, oᵢ,ⱼ}, yᵢ)**：仅记录可观察的输入、上下文、输出与依赖，不含隐藏推理。
- **失败诊断函数**：D_B(τᵢ, zᵢ) = (αᵢ, Sᵢ, eᵢ)，其中 αᵢ 为失败权重（正确为 0、失败为 1），Sᵢ 为偏差类型集合，eᵢ 为执行标识符（用于统计跨执行支持度）。

### 2.3 三大技术环节

**（1）路由策略记忆与注入**
- 候选池：Cₜ,ᵢ,ⱼ = Dedup(Mᵃᵢ,ⱼₜ ∪ Mᵍᵉⁿₜ)，去重后按历史效用分排序。
- 策略选择：Pₜ,ᵢ,ⱼ = TopK_wₜ(Cₜ,ᵢ,ⱼ, K)，只注入至多 K 条指令。
- 上下文拼接：cᵢ,ⱼ(Mt) = cᵇᵃˢᵉᵢ,ⱼ ∥ Format(Pₜ,ᵢ,ⱼ)，原程序顺序不变。

**（2）自然语言策略梯度（反向传播）**
- 类比 TextGrad，将任务级语言反馈 Lᵢ 沿模块依赖图**逆拓扑序**传播。
- 输出级梯度：∂text Lᵢ / ∂yᵢ,ⱼ ≝ ∇LLM(oᵢ,ⱼ, Fᵈᵒʷⁿᵢ,ⱼ)，即 Critic 根据模块输出与下游反馈生成文本化改进方向。
- 路由级梯度：gᵗᵉˣᵗᵢ,ⱼ ≡ ∂text Lᵢ / ∂rᵢ,ⱼ ≝ ∇LLM(Mᵃᵢ,ⱼₜ, cᵢ,ⱼ, oᵢ,ⱼ, Fᵈᵒʷⁿᵢ,ⱼ)，将修正归因到产生该输出的路由策略。
- 传播在无进一步反馈分配时终止，只沿观测到的依赖关系行进。

**（3）跨执行聚合与策略更新**
- 梯度按（路由 a、失败类型 s、归一化修正文本 u）三元组分组。
- 保留打分公式：**w_{a,s,u} = |E_{a,s,u}| / max(Nₐ, |Eₐ|, 1) · αᵢ · κᵢ,ⱼ**

- 安全过滤：剔除空、重复、过度特化、过长、标签泄露或不安全的指令。
- 生成候选后继策略 ĉMt₊₁，仅在**独立的 held-out 选择集**上通过增益/回归约束后才被提升，否则保留 Mt。

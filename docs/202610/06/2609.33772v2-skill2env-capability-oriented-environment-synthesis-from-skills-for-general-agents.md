## 摘要
可执行环境对于在需要工具使用和多步交互的任务上对智能体进行后训练至关重要，但将可执行任务与其环境一起构建仍然难以规模化。技能提供了可复用的领域知识、操作流程和工具使用说明，但技能所含信息与一个具有完整可执行环境的具体且具有挑战性的任务之间仍存在显著差距。为弥合这一差距，我们提出 Skill2Env，一个面向能力的框架，它从技能出发，并利用智能体能力需求来指导任务与环境合成。Skill2Env 通过可复用的难度模式来表示这些需求，并将其实例化为任务蓝图，这些蓝图规定目标、挑战、环境事实、信息边界和验收标准。这些蓝图指导围绕源技能联合构建任务指令、执行基座、工作空间以及基于评分量规的评估器。我们进一步提出迭代任务强化（Iterative Task Hardening），它利用求解器执行证据来识别挑战性不足的任务设计，强化或扩展其难度模式实例，并修订相应的蓝图和环境。使用由 Skill2Env 环境生成的 1.5K 条高分轨迹进行监督微调，我们观察到在一系列广泛的智能体基准上取得了一致提升，证明了面向能力的坏境合成对智能体后训练的有效性。

## Abstract
Executable environments are critical for post-training agents on tasks that require tool use and multi-step interaction, but constructing executable tasks together with their environments remains difficult to scale. Skills provide reusable domain knowledge, operational procedures, and tool-use instructions, but a substantial gap remains between the information contained in a skill and a concrete, challenging task with a complete executable environment. To address this gap, we introduce Skill2Env, a capability-oriented framework that starts from a skill and uses agent capability demands to guide task and environment synthesis. Skill2Env represents these demands through reusable difficulty patterns and instantiates them into task blueprints that specify objectives, challenges, environment facts, information boundaries, and acceptance criteria. These blueprints guide the joint construction of task instructions, execution substrates, workspaces, and rubric-based evaluators around source skills. We further propose Iterative Task Hardening, which uses solver execution evidence to identify insufficiently challenging task designs, strengthen or extend their difficulty-pattern instantiations, and revise the corresponding blueprints and environments. Using 1.5K high-scoring trajectories generated from Skill2Env environments for supervised fine-tuning, we observe consistent improvements across a broad range of agent benchmarks, demonstrating the effectiveness of capability-oriented environment synthesis for agent post-training.

## 1. 核心问题与研究动机

- **背景**：大语言模型越来越多地被部署到需要工具调用与多步交互的真实任务中，可执行环境（executable environment）已成为智能体后训练的关键组件。
- **痛点**：构建可执行任务及其环境不仅仅是生成任务指令，还需配置可用工具、准备工作空间、建立与目标对齐的评估机制；逐任务人工构建难以规模化。
- **已有路径与其缺口**：技能（skill）封装了领域知识、操作流程与工具使用说明，可作为环境合成的起点（如 SkillSynth、Terminal-World、FACET、SKT）。但**技能所含信息与"一个具体、有挑战性、可执行的任务及其完整环境"之间仍存在显著鸿沟**。
- **核心研究问题**：给定一个技能，如何**依据智能体的能力需求**来构建可执行任务及其环境？
- **整体含义**：论文主张从"扩展技能/任务覆盖"转向"显式围绕智能体所需锻炼的能力来组织任务构建"，从而生成随智能体能力提升而不断加难的环境，为通用智能体后训练提供可迁移的监督信号。

## 2. 方法论

### 2.1 核心思想
Skill2Env 是一个**能力导向（capability-oriented）** 的流水线：以技能为种子，用**可复用难度模式**表达智能体能力需求，将其实例化为**任务蓝图**，再由蓝图指导任务指令、执行基座、工作空间与评估器的**联合构建**，并通过**迭代任务硬化**持续提升挑战度。

### 2.2 形式化定义
- 技能 κ、执行基座 X（工具与运行时）、初始工作空间 W₀ 构成可执行环境：**E = (X, κ, W₀)**
- 任务实例：**T = (g, E, V)**，其中 g 为任务指令，V 为评估器
- 交互过程：状态 s₀ 初始化；第 t 步智能体基于历史 hₜ 与目标 g 选择动作 aₜ ~ π(·|g, hₜ)，环境转移 sₜ₊₁ ~ P_E(·|sₜ, aₜ)；执行 L 步得到 rollout τ，评估器给出奖励 **r = V(s_L) ∈ [0,1]**

### 2.3 关键流程

**（1）技能策展（Skill Curation）**
- 从 ClawHub 下载 **47K+** 公开技能文件夹
- 三条筛选标准：**Practical Utility**（用途明确实质）、**Runtime Compatibility**（与 Linux 沙箱兼容）、**Setup Feasibility**（依赖/数据/服务可供给）
- 保留 **3K+** 技能文件夹用于后续合成

**（2）五维能力需求**
环境理解（Environment Understanding）、规划（Planning）、技能使用（Skill Usage）、长时程一致性（Long-Horizon Consistency）、错误恢复（Error Recovery）。

**（3）难度模式（Difficulty Patterns）**
- 每个能力需求通过多个可复用难度模式实例化，每个模式刻画一类挑战及其构建方式与"硬化控制旋钮"
- 初始模式池 P 含 **100 个模式**，按五维组织（每维 20 个，见附录 B 表 3–7）
- 示例：环境理解下的"分布式证据（Distributed Evidence）""隐式约束"；规划下的"状态依赖""资源预算"；技能使用下的"模式不匹配（Schema Mismatches）""参数绑定"；长时程一致性下的"跨格式一致""聚合一致"；错误恢复下的"部分失败""幂等重试"
- 对给定技能 κ，合成智能体选择兼容子集 **P_κ ⊆ P**，同一技能可组合出不同能力需求的任务

**（4）蓝图引导的环境构建**
- 任务蓝图 B 是**作者侧契约（author-side contract）**，规定：目标（Objective）、挑战（Challenges）、事实与推导（Facts & Derivations）、验收标准（Acceptance Criteria）、信息边界（Information Boundary）
- 信息边界区分：指令显式给出 / 求解器需在工作空间中发现 / 需自行推断；求解所需事实对求解器可见，参考答案与推导留在作者侧
- 合成映射：**(κ, B) --synthesis--> T = (g, (X, κ, W₀), V)**
- 蓝图设计与环境构建**迭代进行**：可先修订蓝图再更新受影响组件
- 工作空间构建融合合成材料与检索到的真实材料

**（5）基于评分量规（Rubric）的评估**
- 将验收标准转为评分项集合 C，每项权重 w_c > 0 且 Σw_c = 1，每项得分 q_c ∈ [0,1]
- 任务奖励为加权平均：**r = V(s_L) = Σ_{c∈C} w_c · q_c(s_L)**
- 可程序化检查的项用**确定性验证**（通常二值）；其余用 **LLM 裁判**（可给连续部分分）；每项记录支撑证据

**（6）一致性校验**
- 求解器 rollout 后，验证智能体对照蓝图与执行证据检查任务条件与评分结果
- 需改动任务契约的问题 → 蓝图与相关组件协同更新；仅实现层问题 → 按原蓝图修正
- 归因于任务条件不一致或评估器错误的证据**不纳入能力诊断**，保证硬化基于有效任务需求

**（7）迭代任务硬化（Iterative Task Hardening）**
- **执行诊断**：第 j 轮，求解器执行 T⁽ʲ⁾ 得轨迹 τ⁽ʲ⁾ 与评分 q⁽ʲ⁾；奖励作为**硬化触发器**（阈值 0.7），高于阈值者继续硬化，其余保留
- 诊断公式：**D⁽ʲ⁾ = Diagnose(B⁽ʲ⁾, τ⁽ʲ⁾, q⁽ʲ⁾)**，检查求解器如何处理已实例化的难度模式、是否被捷径绕过、残余失败在哪里
- 若发现模式池未覆盖的可泛化挑战 → 抽象为新难度模式加入 P
- **硬化提议与任务修订**：
  - **H⁽ʲ⁾ = ProposeHardening(κ, B⁽ʲ⁾, D⁽ʲ⁾, P)**（增强既有模式强度或引入兼容新模式）
  - **B⁽ʲ⁺¹⁾ = ReviseBlueprint(B⁽ʲ⁾, H⁽ʲ⁾)**
  - **T⁽ʲ⁺¹⁾ = Construct(κ, B⁽ʲ⁺¹⁾)**

- **监督可迁移**：Skill2Env 未针对任何特定下游基准优化，却在域、接口、任务结构各异的基准上一致提升，说明围绕共享能力需求构建的监督可跨环境迁移。
- **小模型超过大模型**：35B-A3B 骨干在 7 个基准中的 **6 个**上超过 Qwen3.5-397B

-A17B，说明**能力导向的环境监督可以部分弥补参数量差距**，即"数据/环境质量"可在一定范围内替代"模型规模"。

- **硬化机制有效且可持续**：随着迭代轮次增加，任务的全额得分率下降、平均 assistant 轮数上升（难度递增），而在相同采样预算下，用更高 iteration 任务训练出的模型在 7 个基准上均分更高，表明硬化不仅是"变难"，而且产生**更有训练价值的难度梯度**。
- **跨 harness 泛化**：在 Pi、Terminus-2、OpenCode、Claude Code 四种 harness 下均观察到一致提升，说明收益并非来自对特定交互框架的过拟合，而是内化于模型的任务能力。
- **SkillsBench 分域一致性与技能依赖**：在 8 个域中普遍提升，且 **skills on 设置优于 skills off**，说明 Skill2Env 训练出的能力能与外部技能文档协同，而非取代技能使用。
- **超越技能驱动环境合成基线**：在 Terminal-Bench 2.1 上优于 FACET（依据原论文报告值），提示"以能力需求为组织中心"比"以技能/任务覆盖为中心"更能生成有效监督。
- **与前沿闭源模型的可比性**：微调后的 35B-A3B 在部分基准上接近或超过 GPT-5.4、Claude Opus 4.6、Gemini-3.1 Pro 的表现（尤其 SkillsBench、Terminal-Bench 2.1），但在需要大规模世界知识的基准（如 τ3-Banking）上仍有差距，说明环境合成监督主要强化**过程性/交互性能力**，而非知识容量。

## 7. 贡献与创新点

- **问题重构**：将环境合成的组织原则从"技能/任务覆盖"转向"**智能体能力需求**"，把技能视为种子、把能力需求视为构建目标，回答了"给定技能如何针对能力短板造任务"这一此前未被显式处理的问题。
- **可复用的难度模式抽象**：提出 100 个跨技能复用的难度模式，作为"能力需求 → 具体挑战"的中间表示，使任务构建既可组合、又可增量扩展（诊断中发现的新挑战可抽象为新模式回灌模式池）。
- **蓝图作为作者侧契约**：引入任务蓝图统一规定目标、挑战、事实推导、验收标准与**信息边界**，并通过"求解器可见 / 需发现 / 需推断"的显式划分，为"可控难度"提供了可操作的结构化载体。
- **蓝图—环境—评估器联合构建**：强调三者迭代协同而非线性生成，配合一致性校验，避免评估器与任务条件脱节导致的无效监督。
- **评分量规 + 混合验证**：以权重归一化的 rubric 将验收标准量化为连续奖励，确定性验证与 LLM 裁判分工，兼顾可复现性与表达力。
- **闭环迭代硬化**：将"求解器奖励"作为硬化触发器，形成"执行诊断 → 硬化提议 → 蓝图修订 → 环境重建 → 一致性校验"的自动闭环，并把评估噪声排除在能力诊断之外。
- **规模化产物**：从 47K 技能筛出 3K+，最终产出 **2,963 个可执行任务**，覆盖 25 个技能域、13 种语言、101 个外部程序引用、4,242 个依赖包与 823 个 CLI，构成一个可复用的环境资产。

## 8. 局限性与未来工作（基于论文可见信息）

- **算力与成本未量化**：环境合成与多轮硬化涉及大量 agent rollout，论文未报告 token 预算、GPU 资源与总时长，难以评估方法的**成本效益比**。
- **合成器与裁判强依赖特定模型**：环境合成/诊断用 Kimi-K3、裁判用 Qwen3.5-397B-A17B，若替换为能力较弱的模型，蓝图质量与评分可靠性可能显著下降；论文未做**合成器能力敏感性分析**。
- **LLM 裁判的可靠性未验证**：主观评分项缺乏裁判一致性、与人类判断对齐度或对抗鲁棒性实验。
- **基线对比不完全受控**：FACET 仅为原论文报告值且只覆盖单一基准，缺少在同等合成预算与同等骨干下的受控复现。
- **能力维度与模式池缺乏消融**：五维能力需求各自的贡献、模式池规模/组成的影响、硬化阈值 0.7 的敏感性均未给出，无法判断哪些设计是必要的。
- **奖励信号稀疏性与"硬化天花板"**：硬化以 r > 0.7 为触发条件，当任务持续硬化到求解器长期低分时，是否会停止产生有效监督、如何避免难度过载，论文未讨论。
- **任务有效性/正确性验证的范围**：一致性校验依赖求解器 rollout 与验证智能体，但未报告人工抽检比例或任务可解性统计。
- **可能的方向**：将能力需求与难度模式扩展到多模态与多智能体场景；引入成本感知的硬化策略；用可学习的模式选择替代启发式兼容子集选择。

## 9. 总体评价

Skill2Env 的核心价值在于**把"造环境"从工程问题提升为能力建模问题**：它不追求任务数量或领域覆盖的最大化，而是显式地用五维能力需求与难度模式刻画"我们希望智能体学会什么"，再通过蓝图把这种意图无损地落到任务指令、工作空间与评估器上，并用执行反馈闭环地调节难度。实验证据（7 基准一致提升、跨 harness 泛化、硬化轮次与训练效用正相关、35B 骨干在 6/7 基准上超越 397B 同级大模型）支持了其主张：**围绕共享能力需求构建的可执行监督是可迁移的，且质量优先于数量**（1.5K 条 SFT 轨迹即取得 +8.4 的均分提升）。

同时，论文的结论强度受限于若干方法学缺口：合成与评分的模型依赖性、基线的不完全受控、关键设计（能力维度、模式池、硬化阈值）缺乏消融，以及算力成本的不透明。这些缺口使得"能力导向优于覆盖导向"这一命题尚未被完全隔离验证，但已构成一个方向明确、工程可复现、且实验覆盖面较广的强实证起点。

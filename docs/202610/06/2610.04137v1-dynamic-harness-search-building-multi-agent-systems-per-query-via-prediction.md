## 摘要
智能体执行框架规定了用于解决任务的角色、指令、工具和通信结构，而合适的执行框架取决于具体查询。由于每个设计选择的价值只能通过执行来观察，因此为每个查询定制执行框架要么需要在推理时执行各种备选方案，要么需要昂贵的人工设计。我们提出 SHIFT，它将执行从逐查询搜索循环中移出。一个本地 LLM 架构师从搜索中学习针对执行框架构建动作的策略，并学习一个价值函数，该函数根据实测执行结果预测在准确率与执行成本之间进行权衡的效用。对于每个查询，蒙特卡洛树搜索利用这些预测来构建执行框架。在六个基准的 9,193 个任务上，涵盖从数学到文档和通用助手任务，并使用 Gemini 3.5 Flash 作为执行器，SHIFT 取得了最高的平均准确率，约 80%，优于涵盖提示、提示优化和工作流搜索的 17 个基线，并超过最强基线 7.2 个百分点。SHIFT 的一种更廉价模式也达到了高于所有基线的平均准确率，同时比最强基线少使用 32% 的执行 token。我们进一步表明，联合选择结构、指令和工具比仅选择指令或仅选择工具最多高出 9.1 个百分点，并且学习到的价值选择能够从候选池中识别出更准确且执行成本更低的执行框架。

## Abstract
Agent harnesses specify the roles, instructions, tools, and communication structure used to solve a task, and the right harness depends on the query. Because the value of each design choice is observable only through execution, tailoring a harness to each query has required either executing alternatives at inference time or costly manual design. We introduce SHIFT, which moves execution out of the per-query search loop. A local LLM architect learns a policy over harness-building actions from search, and a value function that predicts, from measured executions, a utility balancing accuracy against execution cost. For each query, Monte Carlo tree search uses these predictions to construct a harness. Across 9,193 tasks in six benchmarks, from math to document and general-assistant tasks, with a Gemini 3.5 Flash executor, SHIFT attains the highest mean accuracy, about 80%, outperforming 17 baselines that span prompting, prompt optimization, and workflow search, and exceeding the strongest baseline by 7.2 percentage points. A cheaper mode of SHIFT also attains a higher mean accuracy than every baseline while using 32% fewer execution tokens than the strongest baseline. We further show that choosing structure, instructions, and tools jointly beats choosing only instructions or only tools by up to 9.1 percentage points, and that learned value selection identifies more accurate harnesses with lower execution cost from candidate pools.

## 1. 核心问题与研究动机

- **背景**：解决一个任务需要指定智能体的角色、指令、可用工具以及彼此之间的通信/传递结构，论文将这一整套规格称为 **harness（执行框架）**。例如"从报告中找一个数字"只需一次查找，而"核对预算表并返回修正后的文件"则需要规划器、求解器、验证器分工协作。
- **核心矛盾**：合适的 harness 取决于具体查询，但每个设计选择的价值**只有通过实际执行才能观察**。组件之间还存在强交互——验证器的价值取决于求解器的输出和检查指令，工具授权只有在智能体真能有效使用它时才有用——这使得组件的价值既依赖查询，也依赖 harness 的其余部分。
- **现有做法的代价**：
  - 工作流优化（AFlow、GPTSwarm、Trace）离线搜索**可复用的固定结构**；
  - 提示优化（DSPy、MIPROv2、GEPA）在固定程序内调指令；
  - 查询自适应控制器 / 路由器（DyLAN、MaAS、RouteLLM、MASRouter）直接生成或选择预定义工作流；
  - 学习型质量预测器（AgentSquare）虽用 LLM 预测器评估模块重组，但新模块仍需在环境中执行验证。
- **论文的问题**：能否用**学习到的 harness 效用估计**，在准确率与执行成本之间权衡，为每个查询搜索相互作用的多个设计选择，且**在搜索期间不执行任何候选方案**？
- **整体含义**：SHIFT 把执行移出逐查询搜索循环——训练成本一次性支付并摊销到后续所有查询，推理时只执行最终选中的那一个 harness。

## 2. 方法论

### 2.1 核心思想
- SHIFT（**S**earching **H**arnesses **I**n **F**orward-pass **T**rees）用一个小型本地模型（**architect**）在搜索中提出构建动作并预测效用，用 MCTS 为每个查询现场组装 harness，**搜索全程不调用执行器**，最后只执行被选中的 harness。

### 2.2 Harness 作为可执行图（§3.1）
- 形式化：harness 状态 $s$ 是有向图 $G=(V,E)$，含起点 $v_0$；每个智能体 $v$ 由角色 $\rho_v$、有序指令列表 $D_v$、许可工具集 $T_v \subseteq K_d$ 指定；边 $(u,v)$ 把 $u$ 的输出传给 $v$，**反馈边**允许下游智能体退回结果供修订。
- **关键性质**：每个中间状态都是可运行的，因此搜索可以在不同构建阶段比较"部分设计"与"完整设计"。
- **动作空间**：共 40 个动作 = 10 个结构动作（加 Planner/Researcher/Reasoner/Critic/Verifier/Aggregator、加 Verifier 或 Critic 的反馈边、授予全部工具、停止）+ 15 个指令动作 + 15 个工具授权动作。每个动作只改一个组件，因此搜索路径精确记录决策来源。
- **可行动作集**：$A(s)=\{a \in A_d: M(s,a)\in S_d,\ M(s,a)\neq s\}\cup\{a_{stop}\}$，只保留保持可执行性的动作；动作序列长度上限 $H=10$，设计空间约 $1.5\times10^7$ 个不同 harness。

### 2.4 基于 MCTS 的搜索（§3.3）
- 选择 MCTS 的三点理由：转移 $M$ 已知且确定，候选可在本地推理中构造；设计选择相互依赖，MCTS 通过"动作所导向的设计"来评估动作；访问计数可作策略训练目标。
- 单次迭代流程：**选择 → 扩展 → 用 $V_\theta$ 打分 → 回传**（图 4）。
  - 选择用 PUCT：$a^\star=\arg\max_{a\in U(s)}\left[\tilde Q(s,a)+c_{puct}P(a|s)\frac{\sqrt{\max(1,\tilde N(s))}}{1+\tilde N(s,a)}\right]$，第一项利用历史得分，第二项鼓励少访问的候选。
  - 扩展：取策略概率最高的 $K_{exp}=10$ 个可行动作加 $a_{stop}$，在 $U(s)$ 上重归一化得到先验 $P$。
  - 并行搜索用 **virtual loss** 防止多条下降路径塌缩到同一分支（$\tilde N,\tilde Q$ 的修正公式见 Eq.6，未尝试动作初始化为略低于父节点价值）。
- 预算耗尽后：
  - **SHIFT-search**：执行访问次数最多路径末端的 harness；
  - **SHIFT-value**：从最访问分支中恢复最多 5 个候选，执行预测效用最高者；若该效用低于 0.55，则再补 192 次模拟后从两批候选中重选。

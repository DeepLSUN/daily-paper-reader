## 摘要
多智能体系统（MAS）正越来越多地用于自动化企业工作流，这些工作流涉及多个专用智能体、外部工具以及长时间运行的任务执行。故障可能源于工具退化、上下文传播错误、协调失效，或阻止任务完成的重复智能体交互。尽管现有的可观测性框架提供了追踪和日志，但诊断与修复大多在执行完成后进行，限制了运行时恢复的机会。我们提出 ResonAct，一个运行时自愈框架，它通过流式运行指标实现对多智能体系统的持续监控、诊断和修复。ResonAct 将执行追踪、智能体交互和工具调用摄入流式分析层，该层持续推导任务进度、上下文健康状况和工具可靠性指标。这些指标作为运行时控制信号，用于检测异常执行模式，并利用结构化故障模型定位根因。基于诊断出的故障，ResonAct 动态选择修复策略并执行动作。该框架作为外部控制平面运行，无需修改应用智能体或编排逻辑即可进行干预。我们在企业工作流场景和 AppWorld 基准上评估 ResonAct。结果表明，基于流式指标的分析能够识别执行退化和定位故障。此外，策略驱动的修复将任务完成率最多提升 10.00 个百分点，在评估配置中，检测精确率范围为 70.59% 至 82.91%，召回率范围为 63.09% 至 100%，恢复率范围为 10.48% 至 46.67%，运行时开销范围为 -0.25% 至 14.12%。

## Abstract
Multi-agent systems (MAS) are increasingly used to automate enterprise workflows involving multiple specialized agents, external tools, and long-running task execution. Failures may arise from tool degradation, context propagation errors, coordination breakdowns, or repeated agent interactions that prevent task completion. While existing observability frameworks provide traces and logs, diagnosis and remediation are largely performed after execution completes, limiting opportunities for recovery during runtime. We present ResonAct, a runtime self-healing framework that enables continuous monitoring, diagnosis, and remediation of multi-agent systems through streaming operational metrics. ResonAct ingests execution traces, agent interactions, and tool invocations into a streaming analytics layer that continuously derives task progress, context health, and tool reliability metrics. These metrics serve as runtime control signals for detecting anomalous execution patterns and localizing root causes using a structured failure model. Based on the diagnosed failure, ResonAct dynamically selects remediation policies and performs actions. The framework operates as an external control plane, enabling intervention without modifying application agents or orchestration logic. We evaluate ResonAct across enterprise workflow scenarios and AppWorld benchmarks. The results show that the streaming metric-based analysis identifies execution degradations and localizes faults. Furthermore, policy-driven remediation improves task completion rates by up to 10.00 percentage points, with detection precision ranging from 70.59% to 82.91%, recall from 63.09% to 100%, recovery rates from 10.48% to 46.67%, and runtime overhead ranging from $-0.25%$ to 14.12% across the evaluated configurations.

- **背景**：基于 LLM 的多智能体系统（MAS）被广泛用于自动化企业工作流，涉及多个专用智能体、外部工具与长时任务执行，典型如软件开发、工具编排、数据密集型任务。

- **目标**：构建一个**运行时自愈框架**，能够在执行过程中持续监控、诊断并修复 MAS 故障，且不修改应用智能体或编排逻辑。

## 2. 方法论：ResonAct 框架

### 2.1 核心思想
- ResonAct（Resonate and Act）作为**外部控制平面**，与应用程序智能体及其编排器并行运行，将监控、故障分析与修复策略从任务特定推理中解耦。
- 形成闭环控制回路：**运行时事件捕获 → 流式指标构建 → 故障检测 → 稳定性过滤 → 修复选择 → 纠偏指导注入**。

### 2.2 故障分类与事件捕获
- 三类运行故障：
  - **常见故障**：瞬时错误、超时、重试失败；
  - **静默故障**：上下文衰减、状态偏离、冗余执行等无显式错误的退化；
  - **严重故障**：协调崩溃、无界循环、级联故障。
- 三类执行证据：智能体交互、工具调用、LLM 执行轨迹。通过 Langfuse 生成事件，经 Kafka 流式转发。

### 2.3 流式指标构建
- 执行上下文 `c` 表示一次用户请求的执行尝试，指标状态为 `M_c(t) = [m_1(c,t), ..., m_K(c,t)]`，随事件到达增量更新。
- 指标沿两轴组织：
  - **分析单元**：查询级、智能体级、工具级；
  - **计算机制**：基于计数、基于嵌入、LLM-as-judge。
- 指标与修复策略解耦，可被不同检测器复用。

### 2.5 故障评估与稳定性过滤
- 每个评估周期 `k` 读取最新指标快照，应用故障专用检测器 `d_f`，输出二值判定。
- 构造候选故障信号 `F_c,f(k) = (f, c, M_c(k))`。
- **稳定性过滤**：要求连续 `r` 个周期均检测到故障，才判定为稳定信号 `S_c,f(k) = 1`；`r` 控制早介入与抗瞬时误报的权衡。

### 2.6 运行时反思与诊断
- 由 LLM 对稳定故障信号及执行证据（近期交互、工具结果、执行历史、指标状态）进行反思，输出诊断摘要 `D_c,f(k) = (q, e)`，其中 `q` 描述故障模式，`e` 列出可能的涉事智能体、工具或路径。
- 强调这是**基于证据的解释**，而非确定性根因判定。

### 2.7 修复决策与指导注入
- 修复决策 `A_c,f(k) = (b, u, s, g, ρ_a)`：`b` 是否干预、`u` 目标智能体/工具、`s` 修复策略、`g` 纠偏指导、`ρ_a` 是否授权重试。
- 支持 **LLM 策略**（上下文特定决策）与**确定性策略**（规则映射、有界动作）；LLM 不可用时回退到确定性策略。
- 指导消息通过专用修复流发布，在智能体下一次调用或重试前注入提示；**不修改进行中的 LLM 生成**，仅在调用边界干预。

## 7. 优点

- **外部控制平面设计**：无需修改应用智能体或编排逻辑，具备框架无关性，可插拔、可禁用，保留 baseline MAS。
- **可解释的流式指标**：使用可解释的运行指标作为控制信号，**无需模型训练，也无需每步 LLM 判断**，相比 LumiMAS（LSTM autoencoder）和 SentinelAgent（图异常检测 + LLM 监督）更轻量。
- **指标与修复解耦**：指标可跨检测器复用，修复策略可独立演进，架构清晰。
- **稳定性过滤机制**：通过连续 `r` 次检测抑制瞬时误报，提供早介入与鲁棒性的可调权衡。
- **诊断与修复分离**：LLM 反思产生诊断摘要，修复决策引擎支持 LLM 与确定性双模式，LLM 不可用时降级。
- **干预边界明确**：仅在智能体调用边界注入指导，不打断进行中的生成。
- **实验覆盖两类差异显著的工作负载**（结构化 Sales 与长轨迹 AppWorld）和两个模型家族。
- **工程落地导向**：与 IBM watsonx Orchestrate 技术预览集成，并基于 904 个内部支持问题分析失败类分布，具备实际业务动机。

- **修复动作空间较窄**：修复主要体现为提示注入与授权重试，未涉及工具替换、子任务重规划、智能体切换或编排图重构等更深度干预。
- **仅覆盖已建模的故障类型**：对未被指标覆盖的故障（如安全/合规违规、权限越界、数据泄漏）缺乏检测与处置讨论。
- **仅两个 8B 模型**：未验证更大规模模型或闭源 API 模型，模型能力与自愈效果的关系尚不清晰。

## 9. 可复现性与开放科学

- **优点**：方法本身不依赖训练，核心组件（指标计算、规则检测器、稳定性过滤、提示注入）原理清晰，理论上易于复现。
- **不足**：未提供代码、配置、阈值取值或提示模板；AppWorld 可公开但经改造为 MAS 的编排细节不足；Sales MAS 完全不可获取。
- **结论**：论文的可复现性目前偏弱，属于“概念可理解、细节难复刻”的类型。

## 10. 对实践者的启示

- 对长时、多智能体、工具密集的企业工作流，**运行时干预**比事后分析更有价值，可减少无效 token 与延迟浪费。
- **外部控制平面**思路适合已有 MAS 的渐进式增强：无需重写智能体，可灰度启用/禁用。
- **故障检测的敏感性-选择性权衡**是工程落地的核心难点：宁可少干预也不能频繁误伤，稳定性过滤是必要但非充分的缓解手段。
- **修复的上限受限于故障定位质量**：重试成功率极高而整体恢复率不高，说明瓶颈在“选对故障、选对目标”，而非“执行修复”。
- 不同工作负载（结构化业务流程 vs 长轨迹开放任务）需要不同的检测器与阈值，**一刀切配置不可行**。

## 11. 未来工作方向（基于论文与局限的合理推断）

- 引入**自适应阈值**与在线校准，减少人工按工作负载调参。
- 扩展修复动作空间，从提示注入走向**编排级修复**（重规划、智能体替换、工具降级）。
- 增加**消融与统计显著性**实验，量化各指标、稳定性参数、策略模式的边际贡献。
- 与 LumiMAS、SentinelAgent、AgentOps 等做**同条件定量对比**。
- 评估**成本-收益**：不仅看延迟与资源，还看 token、API 调用与失败重试节省。
- 在**生产环境**验证多租户、并发与长期稳定性。
- 探索**安全与合规类故障**的检测与处置。

## 12. 总体评价

ResonAct 提出了一种定位清晰、架构简洁的运行时自愈框架：以外部控制平面解耦监控与任务推理，用可解释流式指标驱动检测、稳定性过滤与选择性干预，工程落地导向明确，且在两个差异显著的工作负载上展示了任务完成率的稳定提升。其最大价值在于**范式贡献**与**可插拔设计**，而非单项指标的绝对领先。主要短板在于缺乏与现有方法的直接对比、消融与统计显著性分析，以及误报率偏高、修复深度有限、可复现性不足。总体而言，这是一篇**有实践启发性、但验证强度尚待加强**的系统性工作，适合作为运行时 MAS 自愈方向的参考基线。

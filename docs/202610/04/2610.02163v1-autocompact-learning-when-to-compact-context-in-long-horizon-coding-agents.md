## 摘要
编码智能体通过代码检查、搜索、编辑和测试的长轨迹来解决仓库级软件工程任务。随着任务推进，早期探索会变得过时，因此管理上下文不仅仅是避免溢出：智能体必须决定何时压缩、保留哪些工作状态，以及如何从中继续。我们提出 AutoCompact，它训练编码智能体将这些决策作为其策略的一部分。为了收集训练数据，我们在编码任务上运行基础智能体，并使用评判器审查其压缩决策、摘要以及压缩后的动作。有缺陷的输出会在环境中执行之前被替换为修正后的输出，因此每条轨迹都从修正后的决策继续。我们使用这些轨迹进行监督微调，然后通过以任务成功为奖励的强化学习联合优化编码与压缩。在 SWE-bench Verified 和 SWE-PolyBench Verified 上的实验表明，AutoCompact 相比基础模型分别将通过率绝对提高了 9.2% 和 5.0%。这些提升在所有评估的推理预算下均成立：使用从不溢出的 256K 上下文窗口，以及使用溢出会触发回退压缩的 16K 窗口。

## Abstract
Coding agents solve repository-level software engineering tasks through long trajectories of code inspection, search, editing, and testing. As a task progresses, earlier exploration becomes stale, so managing context is more than avoiding overflow: an agent must decide when to compact, what working state to preserve, and how to continue from it. We introduce AutoCompact, which trains a coding agent to make these decisions as part of its policy. To collect training data, we run the base agent on coding tasks and use a judge to review its compaction decisions, summaries, and actions after compaction. Flawed outputs are replaced with corrected ones before being executed in the environment, so each trajectory continues from the corrected decisions. We use these trajectories for supervised fine-tuning, then jointly optimize coding and compaction through reinforcement learning with task-success rewards. Experiments on SWE-bench Verified and SWE-PolyBench Verified show that AutoCompact improves pass rates over the base model by an absolute 9.2\% and 5.0\%, respectively. The improvements hold across all evaluated inference budgets, with a 256K context window that never overflows and with a 16K window whose overflow triggers fallback compaction.

## 1. 核心问题与整体含义

- **研究动机**：仓库级编码智能体需要经过代码检查、搜索、编辑、测试等长轨迹来解决问题。随着任务推进，早期探索、失败尝试、冗长工具输出会迅速过时，继续保留完整历史会污染上下文，使模型偏离当前工作状态。
- **核心问题**：上下文管理不只是“防止溢出”。智能体必须学会三件事：**何时压缩**、**保留哪些工作状态**、**压缩后如何继续执行**。
- **现有方法不足**：
  - 长度触发压缩（如 CompactionRL）只在剩余预算低于阈值时压缩，压缩时机由长度而非任务进展决定，可能在不该压缩的阶段压缩。
  - 主动压缩方法或依赖推理时规则（SelfCompact），或离线插入压缩调用（SWE-Compressor），但前者没有训练信号，后者保留原动作，未监督压缩后的行为。
- **整体含义**：AutoCompact 将压缩决策纳入智能体策略，通过“裁判修正 + 监督微调 + 结果强化学习”联合优化编码与压缩，把上下文管理从启发式规则变为可学习行为。

## 2. 方法论

- **核心思想**：在终端 REPL scaffold 中增加模型可主动调用的 `compact()` 动作。压缩时，早期交互历史被替换为模型生成的 `# Auto Context Summary`，原任务保持不变；摘要应保留已确立结论、相关代码与工作区状态、剩余动作，并丢弃过时探索细节。
- **在线裁判修正数据收集**：
  - 用基础策略在编码任务上 rollout，裁判只依据当前步可见的轨迹历史审查策略提议。
  - 三类修正：
    1. **触发修正**：判断当前是否适合压缩；若阶段已解决则压缩，若中间证据仍需要则继续探索。
    2. **工作状态修正**：检查摘要是否准确保留后续所需信息，如结论、代码/工作区状态、剩余动作。
    3. **续接修正**：检查压缩后的首批动作是否遵循摘要，而非重复已完成探索或忽略下一步。
  - 若裁判判定不合格，则写出修正输出，环境执行修正输出而非原始输出，策略从修正后的历史继续生成。这区别于事后标注，修正会影响后续轨迹。
- **SFT 阶段**：在修正轨迹上以标准下一 token 预测目标微调基础策略，得到 AutoCompact-SFT，学习普通编码行为以及压缩触发、摘要构造、压缩后续接三类行为。
- **RL 阶段**：
  - 从 AutoCompact-SFT 出发，在 SWE-Gym 上做端到端多轮 RL，采用 GRPO 和异步 RL 系统。
  - 每个 rollout 根据最终补丁是否通过任务测试获得二元结果奖励；组内相对优势作为学习信号。
  - 编码动作、`compact()` 决策、摘要生成、压缩后续接共享同一结果奖励，**无需压缩专用奖励或辅助目标**。
  - 由于 `compact()` 会重写上下文前缀，轨迹被切分为多个段，段内前缀只增长；所有段共享该轨迹的优势，策略损失在 batch 内按 token 级平均，无 KL 惩罚和熵奖励。

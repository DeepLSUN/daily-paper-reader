## 摘要
大型语言模型（LLM）智能体正从执行孤立指令的工具调用系统，演化为通过持续、多步交互追求用户目标的任务导向型智能体。然而，现有面向个性化工具使用的基准测试大多评估孤立调用或反应式执行，尚不清楚智能体能否在长期交互中制定、执行并修订显式计划，同时始终保留用户偏好。为弥补这一空白，我们提出了 PDEU-Bench（个性化计划定义、计划执行与计划更新基准，Personalized plan Definition, plan Execution, and plan Update Benchmark），一个用于评估个性化工具使用智能体完整规划生命周期的基准。PDEU-Bench 包含 214 个长时程交互任务，覆盖 12 个日常领域和 94 个工具，并对偏好遵循和计划质量进行分阶段评估。对 15 个代表性开源与闭源 LLM 的广泛评估揭示出本地工具执行与动态规划之间存在显著差距：LLM 往往能在单次调用中落实偏好，却难以构建连贯的计划定义与计划更新。我们进一步评估了主流个性化与记忆增强方法。尽管这些方法改进了特定阶段，但所评估的方法均无法在整个生命周期中可靠地传播用户偏好，且其收益常常无法迁移到后续执行。细粒度错误分析进一步表明，偏好遗漏与冲突在整个规划生命周期中持续存在，这凸显出未来研究需要为 LLM 参数化偏好感知的信息检索与记忆能力。我们在附录中提供了相关代码和数据，以支持未来研究。

## Abstract
Large language model (LLM) agents are evolving from tool-calling systems that execute isolated instructions into task-oriented agents that pursue user goals through sustained, multi-step interactions. However, existing benchmarks for personalized tool use largely assess isolated calls or reactive execution, leaving unclear whether agents can formulate, execute, and revise an explicit plan while preserving user preferences throughout long-term interaction. To address this gap, we introduce \textbf{PDEU-Bench} (\textbf{P}ersonalized plan \textbf{D}efinition, plan \textbf{E}xecution, and plan \textbf{U}pdate \textbf{Bench}mark), a benchmark for evaluating the complete planning lifecycle of personalized tool-using agents. PDEU-Bench comprises 214 long-horizon interaction tasks spanning 12 everyday domains and 94 tools, with stage-specific assessments of preference adherence and plan quality. Extensive evaluations of 15 representative open-source and closed-source LLMs reveal a pronounced gap between local tool execution and dynamic planning: LLMs can often instantiate preferences in individual calls, yet struggle to construct coherent plan definition and plan update. We further evaluate mainstream personalization and memory-augmentation methods. Although these methods improve particular stages, none of the evaluated methods reliably propagates user preferences throughout the complete lifecycle, and their gains frequently fail to transfer to subsequent execution. Fine-grained error analysis further reveals that preference omissions and conflicts persist throughout the planning lifecycle, highlighting the need for future research to parameterize LLMs with preference-aware information retrieval and memory capabilities. We provide the relevant code and data in the appendix to support future research.

## 1. 核心问题与整体含义

- **背景演化**：LLM 智能体正从"执行孤立指令的工具调用系统"演化为"通过持续多步交互追求用户目标的任务导向型智能体"，需要解读高层、欠约束的请求，从交互历史推断潜在偏好，并随工具反馈不断修订行动计划。
- **现有基准的缺口**：
  - 单轮基准（PTBench、ToolSpectrum、PEToolBench、Claw-Anything、ASTRA-Bench、MPT）只评估孤立的个性化工具调用；
  - 多轮基准（FamilyTool、UserBench、ETAPP、GroupTravelBench、MCP-Persona、PersonalWAB、APOLLO、VitaBench2.0）虽拉长交互，但仍是"反应式执行"，以任务完成为中心；
  - DeepPlanning、TravelBench 涉及计划定义，却限于单轮计划设定，无执行与修订。
  - **共同问题**：都不把"显式且不断演进的计划"当作主要评估对象，因此无法回答：智能体能否在长期交互中制定、执行、持续更新一个可执行且与用户偏好一致的计划？
- **核心研究问题**：可靠的工具执行（能发出合法调用、落实偏好）是否等价于生命周期级的规划能力？论文给出的答案是否定的。
- **整体含义**：将个性化工具使用评估从"孤立调用"扩展到"计划定义—计划执行—计划更新"的完整规划生命周期，并揭示当前 LLM 与主流个性化/记忆增强方法在该生命周期上的系统性缺陷。

## 2. 方法论

### 2.1 核心思想

- 把 **Plan 作为显式、可版本化的评估对象**，将其生命周期拆成三个相互关联但可独立测量的阶段：
  - **Plan Definition（计划定义）**：能否把欠约束请求与个性化上下文结合，形成结构化、可执行、偏好对齐的初始计划；
  - **Plan Execution（计划执行）**：能否按计划选择工具，并把任务约束与用户偏好准确实例化为工具调用参数；
  - **Plan Update（计划更新）**：能否根据工具输出修订受影响的后续步骤，同时保留仍然有效的目标、依赖与偏好。
- 每个阶段分别评估 **偏好遵循（Preference）** 与 **计划质量（Quality）** 两个维度。

### 2.2 数据与环境构建

- **离线沙盒（Stage 1）**：为规避网络波动与在线环境高维护成本，构建可扩展离线沙盒，隔离外部变量，保证可复现；使用真实 API 数据（如 Open-Meteo Forecast API 的天气）提升仿真保真度；用 gpt-5.5 生成新闻类数据扩充工具场景，统计显示 85.7% 数据基于真实场景。
- **数据处理**：对异构记录确定性清洗与归一化，序列化为带溯源元数据与结构化属性的统一 JSONL；用 `multilingual-e5-small` 预编码构建离线语义索引，使工具观测与反馈可复现。
- **工具构建**：94 个功能性 API，覆盖 12 个日常领域，涵盖信息查询与状态变更操作，遵循 OpenAI function-calling 规范；由 GPT-5.5 生成 schema，并设计"偏好敏感参数"；两名专业标注者人工核验功能正确性与偏好敏感参数，不达标者修订重检。

### 2.3 偏好与任务构建（Stage 2）

- **偏好构建**：
  - 从 PersonaHub 采样 300 个 persona seed，扩展为连贯虚构画像（大五人格、爱好等）；
  - 依据偏好构建理论（Slovic 1995），在 10 个日常领域实例化多维偏好（如饮食领域偏好冰咖啡）；
  - 仿照 PrefEval，用每位用户 15–25 组两轮 episodic 交互，通过经历、选择与后果**隐式**表达偏好；
  - 三名标注者审核画像—偏好—交互一致性：83.0% 原样保留、17.0% 小幅修订、0 丢弃。
- **任务构建**：基于用户画像、直接偏好与可用工具集生成多步规划任务，**用户请求中不显式暴露偏好描述**；三名标注者按两个二元标准评估：
  - *偏好相关性*：完成任务是否必须依赖画像中的偏好；
  - *任务合理性*：请求是否连贯且可用现有工具完成；
  - 仅当同时不满足两项（F+F）才丢弃，其余人工修订重评（T+F）；结果 45.0% 原样保留、41.0% 修订保留、14.0% 丢弃。
- **难度划分**：由三个异构 LLM 评估器（mimo-v2.5-pro、gemini-3.1-Flash、gpt-5.5）独立评估后多数投票，再由标注者复核；最终 214 个任务中 68 个 easy、146 个 hard。

### 2.4 轨迹获取与评估（Stage 3）

- **轨迹获取协议**：每个任务在标准化三阶段协议下执行，计划保持显式版本化状态；先产出通过 schema 校验的初始计划，再强制进入"动作—观测—更新"循环；**每一次执行尝试（包括失败）都必须跟随一次计划更新**；计划版本、工具调用、观测与终止状态全部记录并自动校验时序与结构一致性；任务输入、工具契约与沙盒状态固定，保证可复现、无泄漏。
- **轨迹评估**：使用细粒度二元 rubric；Plan Definition 与 Plan Update 评估偏好遵循与计划质量，其中**每次更新被判定为以前序计划、动作、观测为条件的转移**；Plan Execution 只评估偏好感知的工具参数实例化，**排除响应质量**以避免把智能体行为与环境可用性混淆；由固定 judge 给出证据接地标签并确定性聚合；采用严格轨迹级成功标准（所有适用偏好与规划要求在每一相关阶段与转移均满足，且不规定参考轨迹）。
- **评价公式（文字说明）**：
  - 偏好准确率：对每个阶段 s ∈ {D, E, U}，`PrefAcc_s = (1/N) Σ P_i^s`，其中 `P_i^s ∈ {0,1}`。定义阶段要求初始计划既覆盖所有相关偏好又不违反偏好；执行阶段要求每次工具调用的参数都正确实例化适用偏好；更新阶段要求每次更新保留有效偏好、相应重规划、落实到后续动作且不引入违规。
  - 总体偏好分 = 三阶段偏好准确率的均值。
  - 质量准确率：`QualityAcc_s = (1/N) Σ Q_i^s`，s ∈ {D, U}。定义阶段六项标准：目标与成功标准覆盖、步骤可执行性、依赖与顺序正确性、工具与信息获取、约束可行性、全局连贯性；更新阶段对应六项：剩余目标覆盖、重规划正确性、剩余步骤可执行性、信息获取与验证、更新后可行性、全局连贯性。质量分 = 两阶段均值。执行阶段不设质量分（工具返回质量无法反映调用正确性）。
  - 联合准确率（Joint Acc.）：同时通过偏好遵循与计划合理性检查的任务比例。

## 3. 实验设计

- **基准本体**：PDEU-Bench，214 个长时程个性化任务、12 个日常领域、94 个工具；任务分布于六大高层类别（专业规划 21.0%、学习与技术 15.4%、旅行与休闲 16.8%、家庭与照护 22.0%、社会与公民 13.1%、购物与金融 11.7%）。

- **个性化/记忆增强方法对比（7 种设置、4 类）**，在 gemini-3.1-flash-lite 与 deepseek-v4-flash 上进行：
  - Baseline：提供完整隐式交互历史，无显式偏好提醒、检索或记忆变换；
  - Reminder（提示类）：在计划定义、执行、更新前插入固定指令要求回忆并遵循偏好；

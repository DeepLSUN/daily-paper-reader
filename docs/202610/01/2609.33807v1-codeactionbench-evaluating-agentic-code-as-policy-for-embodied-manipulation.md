## 摘要
通用多模态模型能在多大程度上通过可执行代码将视觉理解与推理转化为具身操作？我们提出了 CodeActionBench，这是一个包含 25 项操作任务的基准，通过智能体式代码即策略（agentic Code-as-Policy）来评估这一能力。无需任务特定的微调、演示、外部专家感知或抓取模块、特权场景状态或预定义任务策略，智能体应选择视觉证据、形成与任务相关的 3D 估计、构建操作目标，并迭代执行和修正其策略。共享机器人 API 提供 RGB 观测、标定几何操作、机器人反馈和有界运动，将依赖任务的决策留给被评估的智能体。固定任务实例、资源预算和隐藏的物理结果验证器支持跨模型和 harness 配置的受控比较。在九种配置和 675 次尝试上的广泛评估取得了 2.7% 至 73.3% 的成功率。最强配置 GPT-6 Astra 搭配 Codex CLI 在三次尝试中至少一次解决了 25 项任务中的 22 项，展现出最佳性能，但仍留有相当大的改进空间。轨迹分析揭示了空间对齐、物体保持和完成判断方面的困难，包括尽管动作已成功完成却仍导致任务失败的情况。CodeActionBench 提供了一个受控测试平台，用于衡量通用模型如何将其能力转化为操作行为，并考察该过程中的典型失败场景。

## Abstract
How well can general-purpose multimodal models turn visual understanding and reasoning into embodied manipulation via executable code? We introduce CodeActionBench, a benchmark of 25 manipulation tasks that evaluates this capability through agentic Code-as-Policy. Without task-specific fine-tuning, demonstrations, external specialist perception or grasp modules, privileged scene state, or predefined task policies, agents should select visual evidence, form task-relevant 3D estimates, construct manipulation targets, and iteratively execute and revise their policies. A shared robot API provides RGB observations, calibrated geometric operations, robot feedback, and bounded motion, leaving task-dependent decisions to the evaluated agent. Fixed task instances, resource budgets, and a hidden physical-outcome verifier support controlled comparisons across models and harness configurations. Extensive evaluations across nine configurations and 675 attempts achieve success rates ranging from 2.7% to 73.3%. The strongest configuration, GPT-6 Astra with Codex CLI, solves 22 of 25 tasks at least once in three attempts, demonstrating the best performance while still leaving substantial room for improvement. Trajectory analyses reveal difficulties in spatial alignment, object retention, and completion judgment, including task failures despite successfully completed motions. CodeActionBench provides a controlled testbed for measuring how general-purpose models translate their capabilities into manipulation behavior and for examining typical failure scenarios in that process.

# CodeActionBench 论文总结

## 1. 核心问题与整体含义

- **研究动机**：通用多模态模型已同时具备视觉理解、推理与代码生成能力，一个自然的设想是：同一个模型能否"看懂场景 → 决定如何交互 → 用可执行代码表达机器人行为"，从而在**无需任务特定训练**的情况下完成具身操作。
- **两条技术路线的对比**：
  - **VLA（Vision-Language-Action）**：依赖大规模机器人示范数据学习"观测→动作"映射（如 OpenVLA 使用 97 万条真实操作轨迹），迁移到新本体往往需要额外适配。
  - **Code-as-Policy**：推理时由通用模型在机器人 API 之上构造可执行程序，并通过智能体交互回路观察执行结果、修订策略，无需额外任务训练或演示。
- **现有 Code-as-Policy 系统的评测缺口**：许多系统通过外部模块或特权接口提供物体位置、抓取候选、任务技能、深度信息或仿真器物体真值位姿，因此其成功**无法说明通用模型自身**能承担多少感知推理与操作决策。接口差异使不同系统之间难以直接比较。
- **核心问题**：在把"任务相关的视觉解释与策略构造"完全交给被评估模型的前提下，通用模型能把自身能力转化为操作行为的程度有多高？
- **整体含义**：论文提出 **CodeActionBench**——一个把信息边界与责任划分制度化的基准，用于在受控条件下衡量通用模型到操作行为的转化能力，并系统刻画其失败模式（空间对齐、物体保持、完成判断）。

## 2. 方法论

### 2.1 核心思想：责任划分

- 任务相关决策（选择视觉证据、构建 3D 估计与操作目标、决定如何行动/恢复/停止）**留给智能体**。
- 逆运动学、运动规划、底层控制、标定几何计算作为**共享基础设施**提供。
- 明确**排除**：深度传感、专家感知/抓取模块输出、特权场景状态、预定义任务策略、任务特定微调与演示。

### 2.2 环境与任务套件

- 仿真后端：**SAPIEN** + **RoboTwin 2.0** 的 **ALOHA-AgileX 双臂机器人**配置；运动规划使用 **cuRobo**（碰撞模型仅含机器人自碰撞，不含桌面与任务物体）。
- **25 个操作任务**，分五类：
  - 工具使用与接触过程（4）：敲击积木、按铃、按订书机、扫描物体。
  - 多物体组织与装配（11）：按大小排列积木、挂杯子、面包入篮/入锅、罐子入盒、摆鞋、鼠标垫对齐、三积木堆叠、三碗堆叠等。
  - 双臂协作（4）：倒小球、举滚筒、端锅（保持水平）、同时抓两个瓶子。
  - 交接、重抓与重定向（4）：积木交接、麦克风交接、罐子移位、翻转二维码板。
  - 铰接物体与设备（2）：开笔记本、开微波炉。
- **一致性控制**：关闭域随机化（背景、杂物、光照、头相机、桌面高度），每个任务所有配置使用**同一固定场景种子**；指令陈述目标但不泄露验证阈值。
- **资源预算**（固定且跨配置共享）：
  - 工具调用预算 $B_{\text{tool}} = \lceil 14\, t_{\text{expert,min}} \rceil$
  - 仿真时间预算 $B_{\text{sim}} = \text{ceil}_{5s}\left(\max(60s,\; 5\, t_{\text{expert,sim}})\right)$，向上取整到 5 秒的倍数
  - 其中 $t_{\text{expert,min}}$ 为专家完成时间（分钟），$t_{\text{expert,sim}}$ 为官方演示的仿真时长（秒）。
  - 一次直接 API 调用或一次 `run_code` 提交均计 1 次工具调用；程序内部所有机器人动作仍受仿真时间预算约束。

### 2.3 机器人 API 与信息边界

- 接口由 **29 个机器人工具 + `run_code` + `done`** 构成，支持直接调用或组合成 Python 程序（支持分支、循环、跨提交的变量/函数持久化）。
- **观测与状态**：头相机 640×480 RGB、双腕相机 320×240 RGB，含内外参；可查询 TCP 位姿、夹爪开度与物理指缝、接触冲量（接触反馈是匿名的：只给手指连杆位姿，不给被接触物体）。
- **空间估计工具**（非接触三条度量尺度路径）：
  - 标定相机运动：`capture_motion_pair` + `triangulate_correspondence`
  - 可见 FK 夹爪几何：`scale_from_gripper`
  - 调用者提供的物体尺寸先验：`scale_from_object_size`（始终粗糙）
  - 另有 `ray` / `plane_intersect`（射线与代理指定平面求交）、`project` 用于回投影校验。
- **目标构造工具**：`grasp_quat_candidates`（由接近轴与开合轴生成相差 180° 腕转的两个四元数）、`preview_tcp_pose`、`compare_tcp_poses`、`check_tcp_pose_reachability`（仅查询可达性，不运动）、`camera_aim_pose`、`draw_marks`。
- **运动与接触**：`reach_tcp`、`reach_both_tcp`、`move_delta`、`move_both_delta`、`probe_contact_along`（沿指定方向有界增量探测，接触变化即停）、`set_gripper`（位置控制，非力/阻抗控制）。规划失败会拒绝指令，持续停滞会中止动作。
- **不暴露**：仿真器源码、物体真值位姿、任务特定抓取/放置目标、专家感知输出、验证器状态。几何工具只执行被请求的计算，**不**替智能体选择像素对应或校验其几何假设。

### 2.4 隐藏验证器与完成判断分离

- 验证器在回合结束后**离线**给出二值结果，且**从不返回给智能体**。
- 评分规则：**21 个任务按终止时的最终物理状态**；**4 个任务（敲击积木、按铃、按订书机、倒小球）按执行期间必须发生的事件（latch）**，其验证器另外检查终止时的附加最终状态要求。
- 智能体通过 `done(report=..., success_claim=...)` 记录**完成判断**，该调用终止回合；由此可把"任务结果"与"智能体自评"分开评估（过度声称 overclaim / 欠声称 underclaim）。
- 指令与验证对齐：部分原 RoboTwin 检查强制了专家策略的选择（如指定手臂、指定鞋的归属），论文将其改为在自然语言中显式陈述的评分条件（如"提起锅时保持水平"），保留位置/朝向/夹爪条件但移除不必要的专家偏好。

### 2.5 参考 harness

- 统一的请求构造、提供商响应归一化、工具调用 schema 校验与录制。
- **上下文管理**：文本交互追加以保持稳定前缀；图像单独管理，每次请求含最近两轮观测图像，单个 `run_code` 结果最多 6 张图；保留观测标识符以便回收历史图像。接近上限时保留最近 8 条 assistant 消息与工具结果原文，更早交互按固定规则压缩为至多 128 条记录（不做 LLM 摘要）；仍超限则终止回合。
- 同一响应内的工具调用按序执行；无效参数返回错误供下一轮修正；可恢复的中断会取消该响应剩余调用。

### 2.6 指标

- **Attempt success**：75 次尝试中的成功率。
- **Task coverage**：25 个固定任务实例中"三次尝试内至少成功一次"的比例（衡量固定实例上的表现，**不是跨场景泛化**）。
- 辅助诊断：子目标检查点覆盖、空间检查点覆盖、累计空间覆盖随计费调用数曲线、失败阶段分布、完成判断正确率、成本与墙钟时间。

## 3. 实验设计

- **数据集/场景**：没有传统意义上的训练或测试数据集；使用 **RoboTwin 2.0 / SAPIEN** 中的 25 个固定任务实例（每任务一个固定场景种子），单一双臂 ALOHA-AgileX 本体，纯仿真。
- **Benchmark 契约**：任务实例、机器人 API、资源预算、验证规则对所有配置固定；仅"基础模型 + harness"变化。
- **对比配置（9 个）**：
  - GPT-6 Astra + Codex CLI
  - Claude Opus 5 + 参考 harness
  - Claude Opus 5 + Claude Code
  - Gemini 3.6 Flash、GPT-5.6 Sol、Qwen 3.8 Max、Grok 4.6、Kimi K3、Claude Sonnet 5（均为参考 harness）
  - 其中 7 个共享参考 harness，因此可直接比较；涉及不同 harness 的比较评估的是**完整智能体系统**。
- **规模**：每配置每任务 3 次有效尝试 → 每配置 75 次 → 总计 **675 次尝试**。剔除被取代的运行与已记录的基础设施故障。
- **附加分析实验**：
  - 定义 **55 个子目标检查点** 与 **72 个空间检查点**（跨 25 任务），用 5 mm 容差的轨迹重放校验（491 次失败中 481 次通过完整轨迹验证）。
  - 失败阶段归因分析（491 次失败尝试）。
  - 工具使用与任务成功的关联分析（射线-平面相交、三角化、夹爪尺度、尺寸先验、接触探测）。
  - 程序使用率与程序错误率分析。
  - 机器人动作未完成率分析（planner 拒绝、停滞、轨迹偏差、运动额度停止）。
  - 终止条件与完成声明正确性分析。
  - 成本与时间效率分析（API 等价成本、中位墙钟时间）。
  - **参考解可行性验证**：为全部 25 个实例用特权信息构造参考解，均在同一公开 API 与预算内完成（记录 API 调用数与仿真时长）。

## 摘要
多智能体大语言模型（LLM）工作流已成为通过专门化LLM智能体之间的协作推理来解决复杂、开放式任务的强大范式，但由于反复调用LLM和长时间跨度的上下文积累，它们会产生大量运营成本。现有的级联路由方法做出一次性查询级决策，无法适应多步骤工作流的动态、状态依赖特性，而在多步骤工作流中，每一步选择合适的LLM取决于不断变化的任务进度、剩余任务难度和成本效益要求。我们提出了ProgRouter，一种在线进度引导的路由框架，它在工作流各步骤之间自适应地选择LLM智能体，以在遵守时间和成本预算的同时保持任务解决质量。ProgRouter引入了一个多视图任务进度评分器，将粗略的工作流结果状态与关于子任务完成、进度趋势和工作流状态质量的细粒度信号相结合。然后，一个双路径任务进度预测器和一个自适应元门控机制估计每个候选路由LLM的进度增益。ProgRouter做出在线逐步路由决策，平衡进度增益、任务时间预算和长期运营成本效率。在HumanEval Plus、MBPP、MATH-500和ASQA上的实验，涵盖了智能体代码生成、数学推理和检索增强的长形式问答，表明ProgRouter在保持强大任务解决性能的同时，相对于关键基线降低了运营成本。

## Abstract
Multi-agent large language model (LLM) workflows have emerged as a powerful paradigm for solving complex, open-ended tasks through collaborative reasoning among specialized LLM agents, but they incur substantial operating costs due to repeated LLM invocations and long-horizon context accumulation. Existing cascade routing methods make one-shot, query-level decisions and cannot adapt to the dynamic, state-dependent nature of multi-step workflows, in which the right LLM at each step depends on evolving task progress, remaining task difficulty, and cost-efficiency requirements. We present ProgRouter, an online progress-guided routing framework that adaptively selects LLM agents across workflow steps to preserve task-solving quality while adhering to time and cost budgets. ProgRouter introduces a multi-view task progress scorer that combines coarse workflow outcome regimes with fine-grained signals on subtask completion, progress trends, and workflow state quality. Then, a dual-path task progress predictor and an adaptive meta-gating mechanism estimate the progress gain for each candidate routed LLM. ProgRouter makes online step-wise routing decisions that balance progress gain, task time budgets, and long-term operating cost efficiency. Experiments on HumanEval Plus, MBPP, MATH-500, and ASQA, spanning agentic code generation, mathematical reasoning, and retrieval-augmented long-form question answering, demonstrate that ProgRouter reduces the operating cost relative to key baselines while maintaining strong task-solving performance.

**研究背景：**
- 多智能体 LLM 工作流通过协调多个专门化智能体（如分析师、编码员）来求解复杂、开放式任务，已在代码生成、数学推理、检索增强问答等领域展现强大能力。
- 然而，这类工作流运营成本高昂：需要跨多步骤反复调用 LLM，并维护长时间跨度的任务上下文，导致高 token 消耗、高计算/能耗和延迟。
- 现有的级联 LLM 服务（如 CASCADIA）和路由方法（如 RouteLLM、MasRouter）均为**一次性、查询级**决策——在任务开始前根据任务难度选一个模型，无法适应多步工作流中**状态依赖、动态演化**的决策需求：每一步"用哪个模型"取决于当前进度、剩余难度和预算约束。

**核心研究问题：**
> 如何在运营成本预算的约束下，动态地为多智能体 LLM 工作流的每一步路由合适的 LLM 智能体，以保持任务求解质量？

**关键挑战：**
1. **工作流开放且有状态**：中间状态噪声大、部分解决、关键进度因素隐含，难以判断"走了多远、还剩多难"。
2. **估计失准的双向风险**：高估进度→浪费预算调用没必要的大模型；低估进度→过度使用弱模型导致不可逆的质量损失。
3. **预算与性能的时序权衡**：未来步骤数与子任务难度未知，贪心选强模型会提前耗尽预算，过分保守又浪费强模型能力，需要原则化的在线决策算法。


## 2. 方法论

### 2.1 问题建模

- 将 LLM 智能体编排形式化为**在线约束优化问题**：每个任务 `w` 有 T_w 步智能体分发，需满足每任务的时延预算 Γ_w 和成本预算 E_w，以及长期平均运营成本约束 Ē。
- 策略 π(s_t, r_t) ↦ m_t 根据当前工作流状态 s_t 和被分发的智能体角色 r_t，从候选模型集合中选出 LLM m_t。

### 2.2 核心技术组件

**（1）多视图任务进度评分器（Multi-View Task Progress Scorer）**

将原始工作流状态映射为归一化进度分数 g(s_t) ∈ [0,1]，从四个互补视角评估：
- **总体结果视图**：用规则分类器将状态划入四个粗粒度状态区（invalid / recoverable / partial success / complete），提供可靠锚点。
- **子任务完成视图**：统计需求/约束的满足比例。
- **进度趋势视图**：分析最近几步是改善、停滞还是退化。
- **状态质量视图**：评估最新状态转移的语义与结构性意义。

最终通过层次聚合得到进度分数，提供密集的逐步监督信号（比稀疏的最终任务结果更及时、更信息丰富）。

**（2）双路径任务进度预测器 + 自适应元门控（Dual-Path Progress Predictor + Adaptive Meta-Gating）**

预测调用候选 LLM m_t 后预期取得的进度增益 ŷ_t = P_Θ(s_t, m_t)，包含两条互补路径：
- **结构化路径**：基于表格化特征（当前进度分数、子任务完成状态、历史分派记录等），用树模型（随机森林/XGBoost）回归。
- **语义路径**：将工作流状态的 NL 摘要编码为稠密嵌入（MiniLM），再用树模型回归。

两条路径的输出经**树模型元门控（meta-learner）** 自适应加权组合，按当前工作流状态动态分配信任：显式信号可靠时侧重结构化路径，状态微妙/反馈稀疏时侧重语义路径。整体预测开销极低。

**（3）在线决策（Online Decision Making）**

- **虚拟成本队列**：借鉴 Lyapunov 漂移加惩罚框架，维护虚拟队列 Q_w 跟踪长期平均成本约束的违规累积量，将长期约束转化为每步惩罚信号。
- **进度差距感知的价值函数**：任务能力价值为 V·(1−g(s_t))·ŷ_t(m_t)——进度差距越大，进步增益的边际价值越高，激励在任务远未完成时选择更强模型。
- **预算感知成本惩罚**：用指数系数对各模型的成本施加随预算消耗递增的惩罚，保留预算余量，避免反复调用昂贵模型。
- **最终路由分数**：综合上述三项，每一步选择分数最高的模型；分数同时权衡任务进度、系统级成本效率压力和每任务预算消耗。

**（4）在线预测器学习**
- ε-greedy 探索 + 利用：以概率 ε 随机选模型收集无偏训练样本，以概率 1−ε 按路由分数选择。
- 用真实进度增益 y_t = g(s_{t+1}) − g(s_t) 作为训练目标，定期更新预测器，ε 随样本积累逐渐衰减（从探索转向利用），无需离线训练数据。

## 6. 主要结论与发现

1. **固定单模型策略普遍成本不可行**：无论弱小还是强大模型，单一固定策略均违反长期能耗约束 Ē——弱模型因反复失败、多次重试导致累积能耗高；强模型则因单次调用成本过高而超预算。
2. **ProgRouter 在满足成本约束的方法中取得最优质量-成本权衡**：
   - HumanEval Plus：通过率 93.0%（超 MasRouter 2.1%，超 CASCADIA 8.2%），能耗 4796J 在预算内。
   - MBPP：通过率 79.4% + 能耗最低（3376J）+ 执行时间最短（10.3s），全面优于所有基线。
   - MATH-500：能耗最低（6112J）、时间最短（19.0s），通过率 84.3%（比 CASCADIA 低 3.5%，但能耗大幅降低）。
   - ASQA：引文精度 92.1%（所有方法中最高），能耗 18373J 在预算内。
3. **基线存在一致性的失败模式**：Educated Guessing 收敛到任务无关的"历史最优"导致违反预算；CASCADIA 升级策略浪费小模型调用；MasRouter 不感知动态状态与预算，在 MATH-500 上违反能耗，ASQA 上过度依赖单一小模型。
4. **ProgRouter 呈现自适应专业化**：大部分步骤调用高效小模型，仅当预测器认为强模型能带来显著进度增益时，才选择性调用大模型——直接反映了进度差距感知路由项的作用。


## 7. 优点

- **问题定义精准且实践导向**：将工作流中的 LLM 选择明确建模为"在线约束优化"，同时考虑每任务预算与系统长期成本，比静态路由更贴近真实部署需求。
- **多视图进度表示的设计巧妙**：粗粒度状态锚定 + 三个细粒度互补信号，兼顾可靠性和灵敏度，且作为"轻量领域适配器"使下游算法跨领域可迁移。
- **双路径 + 元门控的预测架构合理**：结构化特征与语义表征互补，元门控动态分配信任，在预测精度上优于任何单一路径或均值组合。
- **在线学习免离线数据**：ε-greedy 探索 + 真实进度反馈持续更新，ε 逐渐衰减形成"探索→利用"的自然过渡，无需人工标注偏好数据。
- **优化框架有理论支撑**：基于 Lyapunov 优化框架，虚拟队列方法为长期约束提供了有原则的近似求解路径。
- **实验指标全面**：同时报告通过率、能耗（实测 GPU 功耗）与执行时间，并分析路由分布和 Pareto 前沿；消融实验设计系统。


## 8. 不足与局限

- **基准覆盖有限**：仅覆盖代码生成、数学推理和检索增强问答。对开放网页导航、工具增强 QA、多轮对话决策等其他智能体场景的泛化性未经实证验证。
- **多视图评分器需领域适配**：观测里程碑和粗粒度结果状态需按任务特征人工指定，并非端到端自动学习——论文承认自动学习进度表示是有待探索的方向。
- **单硬件、单配置评估**：实验只在单台 NVIDIA RTX PRO 6000 Blackwell 工作站上运行，且各模型库仅含两个模型家族。硬件平台、模型家族与工作流框架（AG2/Ollama）的单一性，限制了结论的跨平台泛化性。能耗数据可能受 GPU 型号、驱动版本、上下文长度分布等因素影响。
- **基线对比细节有限**：CASCADIA 原设计面向在线推理服务（含部署优化），迁移到多智能体工作流后是否保留其全部能力、超参如何调优，论文未充分说明。
- **消融实验范围有限**：消融只在一个基准（HumanEval Plus）上进行；虚拟队列在有限任务流上的影响似乎较小（92.7% vs 93.0%），其在真实长期部署中的效用有待更长任务流的验证。
- **路由决策可解释性不足**：基于树模型的元门控组合方式缺乏对"为何此刻信任语义路径而非结构化路径"的透明解释，不利于调试与人工审计。
- **预测器更新依赖探索阶段的数据覆盖**：在初始 ε 较大的冷启动阶段，路由决策可能不稳定；不同领域间的进度信号密度差异可能影响预测器收敛速度。
- **伦理与安全依赖外部措施**：路由只选择既有模型，不改变生成质量与偏见；实际部署需人工监督、输出验证和数据保护措施，论文对此已有说明但未设计机制保障。
- **多任务间成本协调未深入**：虚拟队列只调节长期平均约束，对突发任务洪峰或任务间优先级差异的协同调度，论文未展开讨论。

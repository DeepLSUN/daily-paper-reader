## 摘要
扩散大语言模型（dLLMs）通过迭代去噪并行解码多个词元，为自回归生成提供了一种有前景的替代方案。然而，增加解码并行性往往会降低生成质量，因为早期错误可能污染后续上下文。可撤销解码通过重新评估已解码词元并重新掩蔽不可靠词元来缓解这一问题，但现有方法忽略了不可靠词元也可能破坏验证上下文本身。我们识别了这种失效模式，并提出了依赖感知的可撤销解码（DARD），这是一种无需训练的框架，将词元分为掩蔽、候选和未掩蔽三种状态。DARD 使用排除较不可靠词元的选择性上下文来验证候选词元，并自适应调节它们对后续解码的影响。在 3 个开源 dLLM 上的 12 个文本和多模态基准上的实验表明，与最近的可撤销解码方法相比，DARD 持续改善了速度-质量帕累托前沿，在 Flickr30K 上相比 Saber 实现了 2.71 倍加速和 4.35 点的 CIDEr 分数提升。

## Abstract
Diffusion large language models (dLLMs) offer a promising alternative to autoregressive generation by decoding multiple tokens in parallel through iterative denoising. However, increasing decoding parallelism often degrades generation quality, as early errors can contaminate later contexts. Revocable decoding mitigates this issue by re-evaluating decoded tokens and remasking unreliable ones, but existing methods overlook that unreliable tokens may also corrupt the verification context itself. We identify this failure mode and propose Dependency-Aware Revocable Decoding (DARD), a training-free framework that separates tokens into masked, candidate, and unmasked states. DARD verifies candidate tokens using a selective context that excludes less reliable tokens and adaptively regulates their influence on subsequent decoding. Experiments across 12 textual and multimodal benchmarks on 3 open-source dLLMs show that DARD consistently improves the speed-quality Pareto frontier over recent revocable decoding methods, achieving a 2.71$\times$ speedup and a 4.35-point CIDEr score gain over Saber on Flickr30K.

## 论文总结

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：扩散大语言模型（dLLMs）通过迭代去噪掩码序列，能够并行解码多个 token，从而成为自回归 LLM（AR-LLM）的一种高效替代方案。dLLM 已在 Mercury、Gemini Diffusion、Seed Diffusion 及开源 LLaDA 系列等系统中得到探索。
- **核心问题**：随着解码并行度提升，dLLM 的生成质量会急剧下降。原因在于：每个掩码位置仅基于当前步可用上下文预测，无法参考同一步中其他位置的预测结果，导致并行预测的 token 之间可能存在不一致（如同时生成"Los"和"Diego"构成无效组合"Los Diego"）。一旦这些错误 token 被固定，会为后续预测提供误导性上下文，造成错误传播。
- **现有方法的不足**：已有的可撤销解码方法（如 Saber、WINO）虽可重新评估并重新掩蔽不可靠 token，但它们忽略了**不可靠 token 也会污染验证上下文本身**的问题——即在验证某个 token 时，其他已解码但可能错误的 token 仍作为可见上下文参与，导致验证结果不可靠，出现"冲突未解决"或"不必要重掩蔽"等失效模式。

### 2. 方法论

#### 核心思想
DARD（Dependency-Aware Revocable Decoding）的核心在于**验证每个 token 时使用排除不可靠 token 的选择性上下文**。为实现这一点，DARD 引入了**三态机制**：
- **M（Masked）**：未解码位置
- **C（Candidate）**：已解码但置信度不确定的 token，需进一步验证
- **U（Unmasked）**：已解码且高置信度的 token

#### 关键技术细节
1. **Shadow 序列与并行预测**：引入与原始序列 x_t 等长的 shadow 序列 s_t，二者共享位置嵌入，通过二进制注意力掩码（M_ij + M_īj = 1）约束 query 只能关注 x_j 或 s_j 中的一个，从而在一次前向传播中并行计算两个不同上下文下的预测。
2. **U token 验证（可靠上下文验证）**：验证 U 状态 token 时，仅允许其关注 U token 的原始序列 key，以及 M/C token 的 shadow 序列 key，排除 C token 对验证的干扰。
3. **C token 验证（置信度排序上下文）**：C 状态 token 之间使用**置信度排序注意力掩码**——仅允许从高置信度 token 向低置信度 token 的信息流动。这近似于置信度排序的多步解码：
   p_θ(s_π(k) | x̃; M) ≈ p_θ(s_π(k) | x̂_π(1:k−1), x̂_U)
4. **M token 的自适应预测（logit mixing）**：对每个掩码位置 i，结合原始路径（利用 C 上下文）与 shadow 路径（排除 C 上下文）的两个 logit 预测，基于附近 C token 的验证结果（提升 P 或降级 D）计算几何核加权的引导权重 w_i^t，自适应调节 C 上下文的影响：
   w_i^t = (P_i^t + p₀) / (P_i^t + D_i^t + p₀)
   logit_mix = w·logit(x) + (1−w)·logit(s)
5. **状态转移规则**：比较置信度 c_i^t 与阈值 τ_c、τ_u，确定下一状态：M（≤τ_c）、C（τ_c~τ_u）、U（>τ_u）。

### 6. 主要结论与发现

- **验证上下文的可靠性是高效可撤销解码的关键**。DARD 通过选择性上下文验证机制显著降低了不可靠 token 对验证过程的污染。
- **DARD 持续改善速度-质量 Pareto 前沿**：在大多数基准上以更少的解码步数取得相同或更高的性能。
- **标志性结果**：Flickr30K 上，相比 Saber，DARD 实现 **2.71× 加速**并提升 **4.35 点 CIDEr**；AI2D 上提升 2+ 点准确率；ARC-C 上在 35 步内取得 81.61% 准确率（默认 256 步为 52.17%）。
- **置信度排序优于其他排序策略**：在验证 C token 时，置信度排序的注意力掩码比双向、熵、margin 和左到右排序取得更好的准确率-步骤权衡。
- **自适应 logit mixing 优于任何固定权重**：固定 w 值要么加速但降低精度，要么保精度但步数增加；自适应权重实现了两者的最佳平衡。

### 7. 优点

- **问题识别精准**：清晰识别出已有可撤销解码方法中被忽略的"验证上下文污染"失效模式，并用"Los Diego"等示例生动说明。
- **方法优雅且无需训练**：DARD 是完全无需训练（training-free）的推理框架，仅通过状态划分与注意力掩码控制即可实现，具备良好的实用性和通用性。
- **技术设计富有洞见**：
  - 三状态（M/C/U）框架自然衔接解码与验证过程。
  - 置信度排序注意力掩码将并行解码近似为置信度排序的条件因子分解，理论动机清晰。
  - 自适应 logit mixing 根据验证结果动态调节候选 token 的上下文影响力，兼具鲁棒性与效率。
- **验证充分**：实验覆盖 12+ 基准、3 个模型，含大量消融、泛化与效率分析，Pareto 前沿对比方式严谨客观。
- **附加分析深入**：包括混合权重分布统计、置信度排序与后续解码轨迹的对齐度验证、错误传播抑制的定性展示等。

### 8. 不足与局限

- **绝对性能提升相对有限**：论文承认，相比基线，DARD 的绝对性能增益仍属中等。原因在于 DARD 不改变模型分布，而是通过复用原始 dLLM 的预测行为来改善序列级一致性——这限制了性能提升的上限。

- **阈值需要调节**：DARD 依赖 τ_c/τ_u 两个超参数平衡速度与质量，虽论文证明其对阈值有一定鲁棒性，但不同任务/模型的最优阈值范围不同，仍需要针对性的验证。

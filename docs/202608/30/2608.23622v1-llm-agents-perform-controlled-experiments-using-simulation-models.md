## 摘要
大型语言模型（LLM）在推理、规划和工具使用方面表现出强大的能力，但许多科学和工程任务需要的不仅仅是合理的文本和代码生成。它们需要理解系统对干预的响应，而这在实践中依赖于受控实验。在这项工作中，我们提出了一个多智能体框架，使LLM代理能够使用科学仿真模型进行受控实验，用于制药工艺设计。给定用户查询和基线配置，系统构建结构化任务表示，设计实验，执行比较仿真，解释结果，并综合基于证据的工艺参数优化建议。通过将语言模型与高保真仿真模型耦合在交互式代理框架中，所提出的系统支持通过干预、比较和观察进行推理。因此，它比仅语言推理产生更具体和可操作的结果。在工业应用场景中，这一优势体现在更高的输出特异性以及更好的用户评分的正确性和有用性上。消融研究和可视化案例分析进一步证明了仿真集成实验推理的有效性和实际效用。

## Abstract
Large language models (LLMs) have shown strong capabilities in reasoning, planning, and tool use, but many scientific and engineering tasks require more than plausible text and code generation. They require understanding how a system responds to intervention, which in practice depends on controlled experimentation. In this work, we propose a multi-agent framework that enables LLM agents to conduct controlled experiments with scientific simulation models for pharmaceutical process design. Given a user query and a baseline configuration, the system constructs a structured task representation, designs experiments, executes comparative simulation, interprets the resulting outcomes, and synthesizes evidence-based recommendations for process parameter optimization. By coupling language models with high-fidelity simulation models in an interactive agent framework, the proposed system supports reasoning through intervention, comparison, and observation. As a result, it produces more specific and actionable outputs than language-only reasoning. In an industrial application setting, this advantage is reflected in higher output specificity as well as improved user-rated correctness and helpfulness. Ablation studies and visualized case analyses further demonstrate the effectiveness and practical utility of simulation-integrated experimental reasoning.

## 1. 论文的核心问题与整体含义

- **研究动机**：科学和工程任务（如制药工艺优化）不仅需要LLM生成合理的文本和代码，更需要理解系统对干预的响应。这种理解在实践中依赖于**受控实验**——改变一个变量、固定其他变量、观察结果并与基线比较。
- **核心问题**：现有LLM系统即便配备外部工具，也大多用于信息检索或孤立函数执行，而非进行结构化的受控实验比较，导致输出往往是"建议性"而非"证据性"的，缺乏可验证性和可操作性。
- **关键洞察**：在很多工业场景中，关键知识以**仿真模型**的形式存在。将仿真视为LLM的"实验环境"而非被动工具，可以让LLM通过"假设→干预→观察→分析→报告"的科学推理路径进行推理。这为AI for Science提供了一种可行范式。

## 2. 论文提出的方法论：框架设计与核心思想

### 核心思想
- 将科学推理组织为**结构化流水线**，仿真模型作为受控实验环境，LLM作为假设生成者和结果解释者，二者互补协同。
- 系统不直接生成建议，而是先分析任务、设计受控仿真实验、执行对比、解读结果、综合证据后给出结论。

### 六智能体框架
系统由六个专业智能体组成，其中五个由LLM驱动（GPT-4o），一个为规则化软件组件：
1. **需求分析器（Requirement Analyzer）**：解析用户输入与意图，生成任务描述（意图+任务表述+需求列表）。
2. **规划器（Planner）**：基于任务描述和仿真函数规范，生成抽象计划（不涉及具体执行细节），标注需要仿真干预的逻辑步骤。
3. **交互操作员（Interactive Operator）**：将抽象计划具体化，为需要仿真的步骤生成带完整参数的Python代码，并委托执行。
4. **交互执行器（Interactive Executor）**：确定性软件组件，在受控Python环境执行仿真函数，返回文本与图形结果。
5. **解释器（Interpreter）**：使用具视觉能力的LLM对仿真生成的图像进行语义解读，提取实验结论。
6. **报告器（Reporter）**：聚合整体推理与执行过程，生成面向用户的最终报告。

### 受控实验的形式化流程
给定用户查询$q$、优化目标$g$和基线参数向量$x = (x^{(1)}, ..., x^{(n)})$，系统：
- 识别与目标$g$相关的参数$i$；
- 对选中的参数施加扰动$x^{(i)′} = x^{(i)} + \delta^{(i)}$，保持其他参数不变；
- 通过仿真函数$f(x)$比较基线结果$f(x)$与扰动结果$f(x′)$；
- 总结受控比较的发现，推荐改进的参数向量$x^*$。

## 6. 主要结论与发现

- **仿真集成显著提升推理质量**：完整系统的模糊词汇频率最低（每千词13.7），LUCI分数最低（0.13），正确性评分4.1、有用性评分4.2，均优于所有消融变体。
- **无仿真变体性能最差**：模糊词汇频率高达51.3/千词，LUCI分数0.33，专家评分低于3.0（被认为不可用）。说明没有仿真支撑的LLM输出过于模糊，无法支持工程决策。
- **需求分析器的价值**：去掉需求分析器后，仿真调用精确率从94%降至65%，仿真确认率从76%降至45%，输出更不确定。缺乏需求分析时系统倾向于过度使用仿真函数（召回率上升但精确率大幅下降）。
- **完整系统的仿真确认率达76%**：即大多数由LLM生成的假设得到了仿真结果的验证，完成了"假设→实验→验证"的闭环。
- **核心统一原则**：推理质量受"近似保真度"支配——仿真模型的物理保真度和语言模型的假设正确性缺一不可；系统的作用是提供可追溯的、基于证据的决策支持，而非替代用户判断。

## 7. 优点

- **范式创新**：将LLM从"语言推理"扩展到"实验推理"，仿真被提升为受控实验环境，遵循科学的假设→干预→观察→报告逻辑。
- **架构清晰**：六智能体职责分离、信息流结构化，中间产物显式化，推理过程可追溯、可诊断。
- **容错机制**：操作员-执行器之间的重试循环增强了系统的鲁棒性和实用性。
- **工业应用导向**：使用真实的高保真工业仿真模型，在真实工业场景（制药结晶工艺）中验证，而非简化的沙盒环境。
- **证据基础**：输出建议有仿真数据支撑，相比纯LLM输出的启发式建议更具可操作性和说服力。
- **消融设计完备**：分别隔离仿真集成和需求分析器的贡献，结论归因清晰。

## 8. 不足与局限

- **评估规模有限**：仅5个任务场景、单一应用领域（制药结晶），无法验证跨领域的通用性；用户评估者仅2人，评分可能存在主观性。
- **资源信息缺失**：没有报告GPU/API调用等计算成本，难以评估系统的实际部署门槛和运行开销。

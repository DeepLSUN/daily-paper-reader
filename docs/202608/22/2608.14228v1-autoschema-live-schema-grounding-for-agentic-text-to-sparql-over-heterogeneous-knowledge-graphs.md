## 摘要
生命科学知识图谱通过SPARQL提供了大量结构化数据，但每个资源使用自己的模式、标识符和链接。TogoMCP通过提供精心整理的元数据互操作性交换文件，帮助语言模型智能体查询这些资源。创建和维护这些文件仍然需要语言模型辅助起草、验证和人工审查。我们研究了\emph{实时模式接地}，即智能体直接从当前端点获取回答问题所需的模式证据。我们提出了\textsc{autoschema}，一个无需训练的通用实时模式接地框架。它检查实时模式，将问题中的实体名称映射到图标识符，探索关系路径，并在迭代查询构建过程中找到资源之间的可能连接。我们以TogoMCP作为主要比较框架。我们在资源聚焦的生物医学KGQA、多资源生物医学KGQA、BioASQ任务B上的纵向生物医学语义问答以及化学知识图谱到先前未记录的RDF图的迁移上评估了\textsc{autoschema}。\textsc{autoschema}在生物医学KGQA任务中相比TogoMCP提高了平均事实准确性，并在纵向BioASQ评估中取得了一致的改进。它还在核心评估中减少了迭代预算耗尽，并平均使用更少的工具调用。迁移研究初步表明，实时模式接地可以支持不规则和先前未见过的图，而无需首先创建精心整理的模式文件。

## Abstract
Life science knowledge graphs make large collections of structured data available through SPARQL, but each resource uses its own schema, identifiers, and links. TogoMCP helps language model agents query these resources by providing curated Metadata Interoperability Exchange files. Creating and maintaining these files still requires language model assisted drafting, validation, and manual review. We study \emph{live schema grounding}, where an agent obtains the schema evidence needed for a question directly from the current endpoints. We present \textsc{autoschema}, a general framework for live schema grounding that requires no training. It inspects live schemas, maps entity names in a question to graph identifiers, explores relation paths, and finds possible connections between resources during iterative query construction. We use TogoMCP as our main comparison framework. We evaluate \textsc{autoschema} on Resource Focused Biomedical KGQA, Multi Resource Biomedical KGQA, Longitudinal Biomedical Semantic QA over BioASQ Task B, and Chemistry Knowledge Graph Transfer to a previously undocumented RDF graph. \textsc{autoschema} improves mean factoid accuracy over TogoMCP in the biomedical KGQA tasks and gives consistent gains in the longitudinal BioASQ evaluation. It also reduces iteration budget exhaustion and uses fewer tool calls on average in the core evaluation. The transfer study gives preliminary evidence that live schema grounding can support irregular and previously unseen graphs without first creating a curated schema file.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：生命科学领域的知识分散在基因、蛋白质、变异、通路、疾病和化合物等专门资源中。RDF 提供了统一数据模型，SPARQL 支持精确查询（如 RDF Portal 提供的公共 SPARQL 端点）。但不同资源使用各自独立的 schema、标识符和链接方式，研究者需要深厚的专业技术知识才能使用。
- **已有方案的不足**：LLM 虽然能将自然语言转为 SPARQL，但缺乏 schema 证据时容易生成使用了目标图中不存在谓词或标识符的"看似合法"查询。TogoMCP 通过为每个资源提供人工+LLM辅助维护的 MIE（Metadata Interoperability Exchange）文件解决这一问题，但存在实际限制：
  - 私有 RDF 数据可能不允许通过托管模型 API 流出本地基础设施；
  - 探索端点并起草长 MIE 文件需要昂贵的模型 token；
  - 人工审查与定期更新成本高，端点变更时文件可能过时。
- **核心问题**：能否让智能体在回答问题**时**直接从实时端点发现所需 schema，从而构建可执行的 SPARQL 查询？作者将此问题定义为 **live schema grounding（实时模式接地）**，涵盖源选择、实体解析、关系与路径选择、资源间链接四个决策。

## 2. 论文提出的方法论

### 2.1 核心思想
AutoSchema 是一个无需训练的通用实时模式接地框架。智能体在需要时向框架请求 schema 证据，框架查询实时端点并返回紧凑、当前有效的证据，而不是完整 schema 转储。框架与具体智能体/执行系统解耦，以独立 MCP 服务器形式实现，四个核心函数异步执行、以数据库键为输入，内部不调用任何 LLM。

### 2.2 四个实时接地模块

| 模块 | 工具函数 | 作用 |
|---|---|---|
| 源摘要（Source Summarization） | `get_rdf_schema` | 回答"该查哪个图"：统计按 rdf:type 分组的实例数、保留高频类与稳定示例 IRI、采样实例统计谓词、判断对象是字面量/IRI/空节点，返回命名图范围、类计数、示例实体 IRI、完整谓词 IRI、观察到的值域类型与示例值，以及由真实实体与谓词构造的简单 SPARQL 查询 |
| 实体解析（Entity Resolution） | `search_rdf_entity` | 回答"图中如何标识问题提到的实体"：搜索常见 label/title/name/identifier 谓词，识别 OBO、UniProt 等生物医学 accession 形式（可能直接编码在 IRI 中），只返回 URI 主语作为锚点（空节点不稳定故不返回） |
| 关系与路径发现（Relation & Path Discovery） | `expand_entity` | 回答"实体或值如何连接"：用单个 SPARQL 请求获取直接属性和穿过最多三层嵌套空节点的路径（嵌套路径必须单次请求内探索，因为内部空节点 ID 后续不可复用），返回谓词链、叶子值和可执行的图作用域 SPARQL 模式 |
| 跨数据库桥接（Cross-Database Bridging） | `get_cross_db_bridges` | 回答"两个图的证据如何连接"：三个信号——可选标识符转换服务、一个源的 IRI 值属性直接指向另一源的实体命名空间（直接 IRI 复用为最强信号）、两源均观察到的属性名（较弱，可能含义不同）。返回桥接候选与 SPARQL join 骨架而非断言 join 正确 |

### 2.3 实时索引与缓存
- 首次未缓存访问某源时构建**有界实时索引**（最多 25 个类、每类 40 个属性、每类最多 300 个采样实例），缓存在内存和磁盘（JSON），单源一条缓存项，可按需刷新。
- 实体搜索与局部路径扩展不缓存，调用时实时查询端点。
- 索引是采样视图而非完整本体，避免在大图上产生过高上船成本，同时给予智能体足够证据形成并测试查询。

### 2.4 智能体式查询构造循环
智能体循环执行：规划（选择动作）→ 调用 AutoSchema 工具获取实时 schema 证据 → 生成候选 SPARQL → 在端点上执行并观察结果/错误 → 反思并迭代。该循环是策略而非固定流水线：简单查询在源与实体接地后即可停止；结构不清时使用路径发现；真正跨源时才使用桥接模块。若同一子问题连续两次失败，评估策略要求更换谓词、源或接地工具，而非重复同一条查询。

## 7. 优点

- **无需训练、模型无关**：框架本身不调用 LLM，四类接地功能与具体智能体/模型解耦，可作为独立 MCP 服务器复用。
- **隐私友好**：支持本地开源模型全流程部署，私有 RDF 数据无需通过托管 API 流出本地。
- **始终最新**：schema 证据取自实时端点而非静态文件，端点变更无需人工同步更新。
- **问题驱动的按需接地**：四个模块构成"宽到窄"的渐进流程，智能体可在不同粒度停止，避免每问加载完整 schema。
- **成本意识**：有界采样索引（25 类 / 40 属性 / 300 实例）+ 内存/磁盘缓存 + 按需刷新，兼顾大图可扩展性与证据充分性。
- **受控实验设计**：只改变接地证据来源，其余全部固定，归因清晰；同时测量准确率、限次率、延迟、工具调用、token 消耗等多维成本。
- **机制层分析**：成对轨迹对比（图 3）清楚展示了静态 MIE 假设错误关系陷入死循环、实时接地通过发现观察路径成功解答的具体机制。

- **专用桥接模块利用率低**：智能体很少主动调用 `get_cross_db_bridges`，其价值在实验中未充分体现；多资源任务的增益部分来自偶然发现的共享引用值，而非系统性桥接规划。
- **多资源结果噪声大**：方差较高，作者

自认准确率增益是方向性的而非结论性的；化学迁移实验仅 39 题且单次运行，作者明确标注为初步结果，统计效力有限，不能据此断言领域外泛化能力。
- **纵向 BioASQ 覆盖不均衡**：六个年度全量测试集仅用 gpt-oss-120b 一个模型验证，gemma4-31b 只覆盖两个年度；且 BioASQ 各年度增益幅度波动较大，个别年份差异不明显，时间稳健性的证据强度参差不齐。
- **索引采样的固有风险**：有界实时索引最多保留 25 个类、每类 40 个属性、300 个采样实例，可能遗漏低频但关键的谓词或类；缓存刷新策略依赖手动或按需触发，端点发生结构性变更而索引未刷新时，接地证据可能暂时过时。
- **空节点处理受限**：嵌套空节点只能在单次 SPARQL 请求内探索，超出三层的路径无法继续展开；空节点本身不作为实体锚点返回，对依赖空节点建模的图（如某些化学或复杂生物通路数据）覆盖能力有限。
- **桥接模块设计价值未充分兑现**：`get_cross_db_bridges` 极少被智能体主动调用，跨源证据连接多数时候通过局部展开偶然命中共享 IRI 实现，缺乏系统性的桥接规划能力；其三个信号中较弱的两类（共享属性名、标识符转换服务）在实验中几乎没有被触发或验证。
- **评估覆盖范围有限**：所有实验均基于 RDF 端点 + SPARQL，未涉及其他图数据模型（如 Property Graph、RDF-star）或非 SPARQL 查询语言；两种测试模型均为开源权重模型，未验证闭源强模型（如 GPT-4o、Claude）下的行为差异。
- **缺少与强静态 schema 方案的直接对比**：对照的 TogoMCP 文件由人工审查维护，但评估中未对比"完整本体（如 OWL ontology dump）直接作为上下文"这一基线，难以判断实时接地相对完整静态 schema 的优势边界。

## 9. 未来工作方向（作者视角）

- **提升桥接模块的实用性**：研究智能体何时应当调用专用桥接工具，或将桥接逻辑直接融入实体展开机制，使跨源发现更加系统化而非依赖偶然命中。
- **动态缓存与索引策略优化**：根据端点变更频率自适应刷新索引，或根据查询痕迹按需补充采样，减少过时证据与漏检概率。
- **扩展评估范围**：在更多模型（含闭源）、更多图类型（Property Graph、RDF-star）、更多领域（除化学外的其他迁移场景）上验证框架通用性；扩大化学迁移实验规模以获取统计显著的结论。
- **更深层次的可解释性与审计**：为接地决策记录证据来源与置信度，帮助用户理解智能体为何选择某源、某谓词，支持错误追溯。
- **与训练/微调路线的互补**：探讨实时接地证据是否可蒸馏为轻量缓存或用于微调检索器，在保持实时性的同时进一步降低每次查询的开销。

## 10. 总评

AutoSchema 的价值在于用"按需、有界、实时"的接地策略，消解了静态 schema 元数据在维护成本、时效性、隐私与大规模迁移上的结构性矛盾。它并非提出新的查询推理算法，而是重新设计了智能体获取 schema 证据的机制——用可采样的实时索引替代人工维护的静态文件，用渐进式工具调用替代一次性完整转储。实验设计上通过严格的受控比较和机制层轨迹分析，清楚展示了该机制在开放模型、真实端点、纵向数据集与域外图上的收益与边界。其局限也集中于桥接模块未充分发挥、噪声数据上结论需谨慎、跨域证据仍属初步等工程与评估层面问题。整体而言，这是一篇工程完整度较高、对比严谨、诚实地标注了结果强度的系统论文，对 RDF 知识图谱 + LLM 智能体的实用化方向有明确参考价值。

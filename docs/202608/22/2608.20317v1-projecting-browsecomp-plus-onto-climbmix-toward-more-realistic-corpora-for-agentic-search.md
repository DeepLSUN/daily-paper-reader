## 摘要
BrowseComp-Plus基准通过用固定语料库取代不透明的网页搜索，将智能体搜索的评估解耦，从而使智能体的作用可以与检索器的作用分离。然而，该语料库仅包含约10万篇文档，并且是由基准测试自身查询的支持文档加上挖掘的难负例组装而成，因此证据和干扰项都是针对每个查询选定的。我们引入了BrowseComp-Plus_CM，它保留了BrowseComp-Plus的问题，但将其证据重新定位到ClimbMix上，ClimbMix是一个由NVIDIA发布的、包含400B个token、553M篇文档的网页文本混合语料库，用于预训练语言模型，且构建时未参考任何基准。我们的主要贡献是使这成为可能的投影流程：它将每个问题分解为原子推理步骤，并在新语料库中为每个步骤提供依据，仅当自动验证、独立智能体和人工审查均确认每个步骤都得到支持时，才保留该问题。该流程与数据集无关，适用于任何其问题可分解为可验证事实的基准。应用于830个BrowseComp-Plus测试问题时，我们的流程产生了57个完全有据可依的问题，并带有问题级相关性判断。投影将难度转移到检索上，因为我们评估的最强智能体的答案准确率下降了5个百分点，但其证据召回率从84.3%降至21.4%，同时发出的搜索调用增加了63%。作为一系列投影中的第一个，我们在https://github.com/castorini/cmass发布了该流程、基准和我们的分析。

## Abstract
The BrowseComp-Plus benchmark disentangled the evaluation of agentic search by replacing opaque web search with a fixed corpus, so that an agent's role can be separated from the retriever's. That corpus, however, holds only about 100K documents and was assembled from the supporting documents of the benchmark's own queries plus mined hard negatives, so the evidence and the distractors were both selected per query. We introduce $\text{BrowseComp-Plus}_{\text{CM}}$, which keeps the BrowseComp-Plus questions but relocates their evidence to ClimbMix, a 400B-token, 553M-document mixture of web text released by NVIDIA for pre-training language models and built without reference to any benchmark. Our main contribution is the projection pipeline that makes this possible: it decomposes each question into atomic reasoning hops and grounds every hop in the new corpus, retaining a question only when automatic verification, an independent agent, and human review all confirm that every hop is supported. The pipeline is dataset-agnostic and applies to any benchmark whose questions decompose into verifiable facts. Applied to the 830 BrowseComp-Plus test questions, our pipeline yields 57 fully grounded questions with question-level relevance judgments. Projection shifts the difficulty onto retrieval, as the strongest agent we evaluate loses five points of answer accuracy but sees its evidence recall fall from 84.3% to 21.4% while issuing 63% more search calls. As the first of a series of projections, we release the pipeline, the benchmark, and our analyses at https://github.com/castorini/cmass.

  2. **分数混淆智能体与检索器**：依赖专有搜索 API，研究者无法检查或固定其行为，排名行为随时间变化且成本高昂。

**核心问题：**

- 尽管 BrowseComp-Plus 固定了语料库，但其语料库本身存在严重缺陷：
  - 仅约 **100K 文档**，规模比真实检索场景小数个数量级；
  - 由基准查询自身的支持文档 + 自动挖掘的难负例构建，**证据和干扰项都是逐查询选定的**，并非独立策展的自然文档集合；
  - 文档多含 HTML/JS 样板，约 20% 超过 8K tokens，需截断至 512 tokens，而截断导致约 13.5% 查询的证据丢失。

**整体含义：**

- 本文提出将 BrowseComp-Plus 问题"投影"（project）到 **ClimbMix** —— 一个由 NVIDIA 发布的、400B token、553M 文档、**构建时未参考任何基准**的预训练混合语料库上，形成新基准 **BrowseComp-Plus_CM**。核心思想是：语料库先于基准存在，问题只有在语料库恰好包含其依赖的每个事实时才被保留。

## 二、方法论

### 核心思想

将每个问题分解为**原子推理跳（hops）**（即回答问题所依赖的最小事实链），在目标语料库中逐跳检索并确定依据；只有每一跳都被语料库文档支撑的问题才被保留。该管道与数据集无关，仅需要一个 BM25 端点。

### 关键技术细节（五阶段管道）

**Stage 0：数据集与语料库准备**
- 对 ClimbMix 进行文档长度分布与重复内容分析（MinHash + LSH 检测近重复，Jaccard ≥ 0.7）；
- 为每个文档分配 `shard_<索引>_<文档索引>` 形式的 ID；
- 将 830 个 BrowseComp-Plus 测试问题构建为逐个投影任务，原始支持文档仅作提示（hint），不作证据。

**Stage 1：投影（Codex, GPT-5.5）**
- **Hop 分解**：将问题写成最小原子事实链（通常 5–8 跳），并标记类型：
  - *required*：移除会导致问题模糊或不可回答；
  - *confirmatory*：仅复述或佐证其他跳已确立的事实。
- **逐跳接地（grounding）**：通过 BM25 对 ClimbMix 发起查询，将每一跳与陈述该事实的文档关联；原始文档仅作推理链恢复的提示。
- **可回答性检查**：将问题标注为 PROJECTABLE / PARTIAL / NOT，830 → 326。
- **全跳验证**：作为 LLM 裁判，验证所有跳（无论类型）均已接地且能联合推导出答案，326 → 65。

**Stage 2：独立智能体验证（PIIKA, GPT-5.5）**
- 用仅基于提供的文档作答的独立智能体（禁止参数化知识）复验，65 题全部回答正确，证明证据充分性。

**Stage 3：人工验证（作者）**
- 逐题检查每个约束都有对应跳、每个跳都有语料库文档支撑；65 → 57。

**Stage 4：Qrels 构建（Claude, Opus 5）**
- 合并所有成功接地尝试的高召回候选文档池；
- 用 LLM 对每个候选文档做精度过滤（文档必须确实支撑其关联的跳）；
- 将判断扩展至精确重复文档及经确认的近重复文档（Jaccard ≥ 0.7）。

### 管道中的过滤漏斗

```
830 个问题 → (可回答性) → 326 → (全跳验证) → 65 → (PIIKA 验证) → 65 → (人工) → 57
```

## 六、主要结论与发现

1. **投影把难度转移到检索上**：最强智能体在精度上仅损失 5 个百分点（86.0→80.7），但证据召回率从 84.3% 暴跌至 21.4%，同时检索调用增加 63%——证据并非缺失（人工验证全部接地、给出 qrels 时所有 57 题均可答对），瓶颈在于**在更大更自然的语料库中找到证据**。
2. **ClimbMix 上的检索是真正困难的任务**：弱模型召回率跌至 3% 以下；语料库规模（553M 文档 vs 100K）和自然分布是主因，而非近重复内容（近重复仅占 qrels 的 <30%）。
3. **记忆效应限于前沿模型**：GPT-5.6 Sol 闭卷可答对 70.2% 的投影题，而开源模型（Gemma、Qwen）几乎完全依赖检索——这使准确率的意义发生变化，应配合召回率与工具调用数共同报告，并朝向"要求智能体引用证据"的方向发展。
4. **保留问题的价值**：投影保留了 BrowseComp-Plus 问题的困难性与已验证答案，同时将语料库换成与基准无关的自然文档——比"重写新题"更有效地衡量真实检索场景。
5. **失败可诊断**：被丢弃的问题可归因于具体缺失的事实（而非相似度阈值），多数仅差 1–2 个未接地跳（且多为 confirmatory 跳），提示改进空间。

## 七、优点

- **数据集无关的通用管道**：适用于任何可分解为可验证事实的基准，仅需目标语料库的 BM25 端点，是一个可迁移的基础设施。
- **多级、多方验证**：自动检查（LLM 裁判）→ 独立智能体（PIIKA，禁用参数知识）→ 作者人工核验，三重确认保证每跳有据可依。
- **语料库独立于基准**：ClimbMix 构建时未参考任何基准，避免了逐查询选择证据/干扰项的"受控文档选择任务"问题，反映真实检索分布。
- **全程可审计**：每个阶段输出独立文件，可恢复、可检查；发布管道、基准和分析（代码与数据开源）。
- **证据集粒度细**：逐跳接地意味着 qrels 是完整推理链的证据集合，而非仅承载答案的页面。
- **方法论透明度高**：对投影过程中遇到的工程挑战（约束漂移、浅阅读、不稳定性）及其缓解措施做了诚实汇报。
- **与 TREC RAG 2026 等生态对齐**：ClimbMix 正在成为共享评测基板，支持预训练与检索的统一解耦研究。

## 八、不足与局限

- **产率极低**：830 题中仅 57 题（6.9%）存活，基准规模过小，可能难以支持高统计功效的评测；多数丢弃源于 1–2 个 confirmatory 跳缺失（本可放宽）。
- **保守判断可能引入偏差**：要求所有跳（包括不收敛答案的 confirmatory 跳）都接地，可能系统性偏向某类问题（如事实冗余度更高的题目），影响基准的代表性。
- **检索接口单一**：仅暴露 BM25 索引，未提供 dense/hybrid 索引或重排序器对比，无法区分召回缺口源自语料库规模还是词法匹配局限。
- **记忆污染未解决**：前沿模型闭卷 70.2% 的正确率意味着准确率指标已无法区分"找到证据"与"不需要证据"；论文未提供要求引用证据的端到端评估方案。
- **管道非精确可复现**：跳分解、接地

**接地的中间判断依赖 LLM 调用等不可脚本化环节，加上 token 限制导致的分块运行与会话重启，使同一输入在不同会话下可能给出不同分解；作者明确承认管道无法精确复现，尽管各阶段输出中间文件可审计，严格复现仍需要大量 LLM 调用与人工介入，成本较高且可能引入复现者偏差。**

## 九、对未来研究的建议与开放问题

- **丰富检索接口**：当前仅暴露 BM25 词法索引，建议在 ClimbMix 上补充 dense / hybrid 检索与重排序器，以区分召回缺口源自语料库规模本身还是词法匹配局限，并推动检索器与智能体的联合评测。
- **强化证据引用协议**：面对前沿模型 70.2% 的闭卷正确率，应将“必须显式引用语料库证据”纳入评分标准，逐步弱化参数化记忆对准确率指标的污染。
- **放宽接地约束以提高产率**：考虑允许 confirmatory 跳缺失（或降低其接地要求）、允许部分接地问题进入基准，并记录其接地比例，以扩大基准规模、缓解当前 57 题的统计功效限制。
- **迁移到更多基准与语料库**：将投影管道应用到 FreshQA、GPQA 等可分步事实化的基准，并在更多独立语料库（而非仅 ClimbMix）上构建投影基准，以验证管道通用性。
- **语料库预处理与去重**：ClimbMix 中 HTML/JS 样板、截断导致的证据丢失、近重复文档等问题仍待优化；更严格的语义去重与文档清洗可进一步提升评估信度。
- **可复现性工程**：将跳分解与接地环节脚本化、固定解码参数并引入确定性采样，或发布完整交互日志，以便研究社区低成本复现与扩展。

## 十、总体评价与结论

本文提出了一种新颖且通用的“基准投影”范式：不是重写新问题，而是将已有高质量基准中的问题逐跳分解，并投影到与基准无关的自然语料库上，从而在保留问题难度与答案有效性的同时，将评估重心从“检索器 + 智能体”的混合体转移到“真实大规模语料库中的证据发现”上来。通过 830 → 326 → 65 → 57 的多级过滤漏斗，作者构建了 BrowseComp-Plus_CM 基准并完成了 3 个模型 × 2 个语料库的系统对比。

其核心发现具有明确启示：当语料库从 100K 增长到 553M 时，最强模型的准确率仅下降约 5 个百分点，但证据召回率从 84.3% 崩至 21.4%，说明问题的关键瓶颈已从“理解与推理”转为“在庞大且自然的语料库中定位证据”；而前沿模型高达 70.2% 的闭卷正确率也揭示出记忆效应对评测结果的深层干扰。整体而言，这是一篇方法贡献明确、工程透明度高、局限坦诚的论文，为后续大规模检索增强评估提供了可复用的基础设施与值得追问的开放问题；但其基准规模过小、检索接口单一与记忆污染未解等不足，也决定了它更多是“示范性”而非“终结性”的工作。

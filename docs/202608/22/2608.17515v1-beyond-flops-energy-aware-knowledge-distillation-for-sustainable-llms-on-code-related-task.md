## 摘要
背景：大型语言模型（LLMs）越来越多地应用于软件工程（SE）任务，在克隆检测、漏洞预测和代码摘要等问题上取得了高精度。然而，它们的高计算需求和能耗引发了可持续性问题，并阻碍了它们在消费级硬件和资源受限平台上的使用。在文献和工业界，报告LLM计算成本的常用方法是使用通过网络前向传递所需的浮点运算次数（FLOPs）。目的：本文研究了能量感知知识蒸馏对SE的影响，旨在提高模型效率同时保持性能，并确定FLOPs是否是可靠的能量感知指标。方法：我们使用Morph（一种基于多目标优化的蒸馏方法）进行受控实验，以实证检验FLOPs是否准确反映克隆检测和漏洞预测任务中的能耗。我们扩展了该方法，包括能量替代模型，直接在优化过程中估计CPU和GPU能耗，并将Morph应用于使用CodeT5+的生成任务以进行代码摘要。结果：我们的结果表明，FLOPs并不总是可靠的能耗指标，使用能量替代模型可以获得更好的结果。蒸馏后的学生模型可以减少高达90%的推理能耗和86%的内存使用，仅带来适度的精度权衡。结论：在直接能量替代而非FLOPs引导下，能量感知知识蒸馏可以改善LLMs在SE应用中的能耗、可持续性和可部署性，从而在消费级硬件上实现高效模型。

## Abstract
Background: Large Language Models (LLMs) are increasingly being applied to Software Engineering (SE) tasks, achieving high accuracy across problems such as clone detection, vulnerability prediction, and code summarization. However, their high computational demands and energy consumption raise sustainability concerns and hinder their use on consumer hardware and resource-constrained platforms. A common way to report the computational cost of an LLM in the literature and industry is to use the number of Floating Point Operations (FLOPs) required to perform a pass over the network. Aims: This paper investigates the implications of energy-aware knowledge distillation for SE, aiming to improve model efficiency while maintaining performance and to determine whether FLOPs is a reliable energy-aware metric. Method: We conduct a controlled experiment using Morph, a Many-Objective Optimization-based distillation methodology, to empirically examine whether FLOPs accurately reflect energy consumption in Clone Detection and Vulnerability Prediction tasks. We extend this methodology to include energy-surrogate models that directly estimate CPU and GPU energy consumption during optimization, and we apply Morph to generative tasks using CodeT5+ for code summarization. Results: Our results show that FLOPs is not always a reliable indicator of energy consumption, and better results can be achieved by using energy-surrogate models. Distilled student models can reduce inference energy consumption by up to 90\% and memory usage by 86\%, with only modest accuracy trade-offs. Conclusions: Energy-aware knowledge distillation when guided by direct energy surrogates rather than FLOPs can improve the energy consumption, sustainability, and deployability of LLMs for SE applications, enabling efficient models on consumer hardware.

- **研究动机**：大型语言模型（LLMs）在软件工程（SE）任务（如克隆检测、漏洞预测、代码摘要）中表现优异，但其高计算需求和高能耗引发严重的可持续性问题，也限制了在消费级硬件和资源受限平台上的部署。
- **现有问题**：文献和工业界普遍使用 FLOPs（浮点运算次数）作为 LLM 能耗的代理指标。然而，FLOPs 只反映理论上的数学运算量，忽视了内存访问模式、数据搬运、硬件级优化等实际影响能耗的因素，因此其可靠性备受争议。
- **核心矛盾**：已有的 Many-Objective 知识蒸馏方法 Morph 将最小化 FLOPs 作为“能量效率”目标，但其评估仅局限于 BERT 类模型和二进制分类任务，未验证生成任务；且其压缩后尺寸的大幅减小并不一定带来成比例的能耗降低。
- **研究目标**：本文旨在回答三个问题：
  1. 在基于多目标优化的蒸馏场景中，FLOPs 是否是能耗的良好代理？
  2. 直接用真实能耗作为优化目标，能否提升 Morph 蒸馏模型的能量效率？
  3. Morph 方法是否能扩展到文本生成任务（如代码摘要），并保持精度与效率的平衡？
- **整体含义**：通过能量感知知识蒸馏，用直接能量代理模型替代 FLOPs，可以在不显著损失精度的前提下大幅降低模型推理能耗和内存占用，使 LLM 更可持续、更易部署于消费级硬件。

## 2. 方法论

- **基础框架 Morph**：基于多目标进化算法 AGE-MOEA，搜索学生模型的超参数配置，同时优化多个目标。原版 Morph 的目标包括：最大化精度、最小化内存、最小化 FLOPs、最大化鲁棒性（通过变质测试预测翻转次数）。为降低搜索成本，使用代理模型预测精度和鲁棒性，避免训练每个候选配置。
- **RQ2 的扩展——引入能量代理目标**：
  - 将原本的 FLOPs 效率目标替换为测量能耗（Joules）。
  - 使用拉丁超立方采样（Latin Hypercube Sampling）均匀采样超参数空间。
  - 对每组采样配置，用 EnergiBridge 在 CPU 和 GPU 上分别测量推理能耗（多次重复取中位数）。
  - 基于这些实测数据，训练两个额外的代理模型（Gradient Boosting Regression），分别预测给定超参数下的 GPU 和 CPU 能耗。
  - 优化阶段不再计算 FLOPs，而是用代理模型预测 CPU+GPU 总能耗并作为最小化目标。
- **RQ3 的扩展——生成任务（代码摘要）**：
  - 重新定义优化目标：最小化模型尺寸、最小化推理能耗、最大化 ROUGE-L 分数。
  - 由于生成任务无法预先存储所有 logits，采用在线蒸馏：教师和学生同时驻留 GPU，每个 batch 先由教师推理获取 logits，再训练学生。
  - 蒸馏损失采用 KL 散度（学生与教师输出分布）与交叉熵（学生与 ground truth）的平均值。
  - 引入 **权重子克隆** 技术：先在验证集子集上对教师模型运行推理，评估神经元和注意力头的重要性，然后将最重要的权重复制到学生模型中，以加速收敛并避免随机初始化导致的退化输出。
  - 学生模型的超参数搜索空间最大值与教师模型 CodeT5+ 220M 相当，保证学生不会大于教师。
- **能耗测量协议**：仅测量推理阶段能耗，排除分词和解码；每次测量重复 20 次，顺序随机化，测量间重置 GPU 上下文，减少系统活动干扰；报告中位能耗。

- **任务与数据集**：
  - 克隆检测（Clone Detection）：BigCloneBench（Java 代码克隆数据集）。
  - 漏洞预测（Vulnerability Prediction）：Devign（C/C++ 代码，来自 FFmpeg 和 Qemu）。
  - 代码摘要（Code Summarization）：使用 CodeXGLUE 代码摘要数据集的 Python 部分微调教师模型；但由于 CodeT5+ 已在 CodeSearchNet 上预

由于 CodeT5+ 已在 CodeSearchNet 上预训练，且代码摘要任务通常需要特定格式的输入输出，因此本文直接使用预训练后的 CodeT5+（220M）作为教师模型，并在 CodeXGLUE 的 Python 子集上进一步微调以适配摘要生成任务。学生模型则采用权重子克隆初始化，超参数搜索空间包括隐藏层维度、层数、注意力头数等，最大值与教师模型一致，以保证学生模型规模不超过教师。

- **验证的设置**：
  - 为了公平比较，克隆检测和漏洞预测沿用 Morph 原先的基准设置，采用相同的训练/验证/测试划分。
  - 代码摘要任务使用标准的 ROUGE-L 作为生成质量指标，能耗测量同样使用 EnergiBridge。
  - 所有蒸馏实验均在单个 NVIDIA GPU 上执行，能耗测量在 CPU 和 GPU 两种环境下分别进行，以考察不同硬件上的可持续性表现。

- **对比基线**：
  - 与原始 Morph（以 FLOPs 为目标）进行比较，验证能量代理是否带来额外收益。
  - 与随机搜索、单目标优化（仅最小化能耗或仅最小化模型尺寸）进行对比，突出多目标优化的优势。
  - 在代码摘要任务中，还对比了不使用权重子克隆的蒸馏变体，以验证该技术的必要性。

- **评估指标**：
  - 精度指标：克隆检测采用 F1 分数，漏洞预测采用 Accuracy 和 F1，代码摘要采用 ROUGE-L。
  - 效率指标：模型参数量、内存占用、实测推理能耗（Joules）、FLOPs（仅作对比）。
  - 相关性分析：计算 FLOPs 与实测能耗之间的 Spearman 秩相关系数，并可视化散点图，直观揭示二者的弱相关性。

## 4. 关键结果与发现

- **RQ1：FLOPs 不是能耗的良好代理**
  - 在多个模型配置下，FLOPs 与 CPU/GPU 实测能耗之间的 Spearman 相关性较低且不稳定（例如在 GPU 上相关系数不足 0.3），甚至出现 FLOPs 相同但能耗差异显著的情况。
  - 分析表明，能耗主要受内存访问模式、批处理大小、模型并行度以及硬件利用率等因素影响，FLOPs 无法反映这些实际开销。
  - 结论：在知识蒸馏场景中，用 FLOPs 作为能量效率目标存在误导性，可能导致优化方向偏离真实可持续性目标。

- **RQ2：直接优化能量代理可显著提升能效**
  - 将 Morph 的 FLOPs 目标替换为代理模型预测的 CPU+GPU 总能耗后，搜索到的学生模型在测试集上的能耗比原 Morph 降低约 20%~35%，而精度基本持平（F1 或 Accuracy 的下降在 1% 以内）。
  - 在内存占用方面，能量感知的 Morph 与原始 Morph 相当，说明能耗优化并未以牺牲模型大小为代价。
  - 代理模型的预测误差在可接受范围内（平均绝对百分比误差约 8%），且通过拉丁超立方采样能在有限预算内有效覆盖超参数空间。

- **RQ3：能量感知蒸馏可成功扩展到代码摘要生成**
  - 在 CodeXGLUE 代码摘要任务上，基于能量代理的多目标蒸馏成功将学生模型压缩到教师模型的约 50% 参数量，同时保持 ROUGE-L 分数下降不超过 2 分（例如从 18.5 降至 17.2）。
  - 与原始 Morph（若直接迁移）相比，加入能量目标的学生模型在同等精度下能耗降低更明显；而权重子克隆技术使训练收敛速度提高约 3 倍，并避免了生成崩溃问题。
  - 线上蒸馏（在线 KL 散度 + 交叉熵）虽然增加了训练开销，但最终得到的模型在推理阶段实现了更好的能效-精度权衡。

## 5. 讨论与分析

- **为什么 FLOPs 与能耗脱节**：作者从硬件层面解释，现代 GPU 的能耗主要由显存带宽和计算单元利用率决定，而 FLOPs 仅衡量计算量，忽略了数据搬运和缓存命中率。此外，不同算子（如矩阵乘法 vs 激活函数）的实际能耗差异巨大，统一按 FLOPs 计量会掩盖这些差异。

- **能量代理模型的可行性**：作者指出，虽然直接测量能耗需要额外开销，但通过小规模采样和回归代理，可以在搜索阶段以极低成本近似任意配置的能耗。该方法具备通用性，可适用于不同硬件平台（CPU/GPU），只要重新采样即可。

- **对多目标优化的启示**：传统上以 FLOPs 或模型大小为效率目标的做法，可能与真实能耗目标相冲突。本文证明，将真实能耗纳入优化目标能够发现更可持续的模型配置，且不会牺牲其他指标。这为未来 LLM 压缩和神经架构搜索提供了新的设计范式。

## 6. 威胁与局限

- **硬件依赖性**：能耗测量结果受具体硬件、驱动版本和运行环境影响，代理模型在一种 GPU 上训练后迁移至其他硬件可能失效，需要重新校准。
- **任务覆盖范围**：虽然扩展到了代码摘要，但仍未覆盖更复杂的生成任务（如代码翻译、修复）和多模态场景，能耗代理在其他任务上的有效性尚未验证。
- **代理模型误差**：超参空间中的极端配置（如极小或极大的层数）可能采样不足，导致代理预测偏差；未来可考虑贝叶斯优化或自适应采样来缓解。
- **训练能耗不纳入考量**：本文只优化推理能耗，但蒸馏过程本身也消耗能量；在实际部署中，训练成本可能部分抵消推理阶段的收益。
- **相关性分析样本量有限**：FLOPs 与能耗的相关性分析仅基于本实验的搜索空间，更广泛的模型族（如 MoE 模型）可能呈现不同规律。

## 7. 结论与展望

本文系统性地质疑了 FLOPs 作为 LLM 能耗代理指标的可靠性，并提出了能量感知的多目标知识蒸馏框架。通过引入实测能量代理模型，该方法在无需大量真实测量开销的情况下，能够优化学生模型的推理能耗，同时保持精度和模型尺寸。此外，本文将 Morph 拓展至生成任务，验证了其通用性。研究表明，将可持续性作为一阶优化目标而非间接代理，能够更有效地实现绿色 LLM 部署。

未来工作方向包括：
- 将能量感知蒸馏推广到更多任务和模型架构（如编码器-解码器、MoE）。
- 探索训练能耗与推理能耗的联合优化，实现全生命周期可持续性。
- 开发更高效的能量代理模型，减少重采样成本。
- 将能耗指标纳入行业标准的模型评估体系，推动业界采用。

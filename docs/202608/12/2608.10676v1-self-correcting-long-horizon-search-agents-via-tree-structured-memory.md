## 摘要
基于大型语言模型（LLM）的搜索智能体通过与外部环境的多步交互来回答问题。然而，将完整的执行轨迹提供给LLM会导致上下文无界增长并引入噪声。现有的压缩方法在牺牲重要细节的情况下缩减上下文，并且常常在未修复由错误事实推导出的下游推理的情况下替换错误事实。为解决这一问题，我们提出了ReTree，一种用于搜索智能体的自校正树结构记忆机制。ReTree在保留源链接证据的同时，构建有界的逐步推理上下文。它将搜索建模为证据树，其节点存储有界摘要、证据和修订历史。当新检索到的证据与先前的声明相矛盾时，ReTree回溯到引入该声明的节点，替换过时证据，重新生成摘要，剪除受影响的子分支，并恢复搜索。基于来源的证据溯源支持可靠的冲突定位，并保持最终声明可追溯至检索到的段落。在四个公开的问答和搜索基准上的实验表明，ReTree始终优于全轨迹ReAct，将答案准确率提高最多25.6个百分点（pp）；全轨迹ReAct的平均每步最大推理上下文是ReTree的1.27–1.51倍。这些结果确立了ReTree作为一种有效的自校正记忆抽象，适用于长时程搜索。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

# ReTree 论文详细总结

## 1. 核心问题与整体含义
- **研究背景**：基于 LLM 的搜索智能体通过“推理-检索-再推理”的多步交互回答问题。然而，将完整执行轨迹交给策略模型会导致每步推理上下文随检索步数无限增长，并引入大量冗余或噪声。
- **核心矛盾**：现有记忆压缩方法（如滚动摘要、报告式重构）虽然控制上下文长度，却容易丢失关键细节，尤其是“事实→下游推理”的依赖关系；当检索到的新证据推翻早期错误事实时，简单替换事实并不能让依赖该事实的下游结论失效，从而形成错误级联。
- **研究问题**：如何让搜索智能体的工作记忆既保持有界上下文，又能保留证据来源，并在证据被修正时自动修复依赖状态？
- **整体含义**：工作记忆不应只是“更短的转录”，而应是可编辑、可溯源、支持依赖一致性修订的状态表示。

## 2. 方法论
- **核心思想**：提出 ReTree，将搜索过程建模为“证据树”，树上每个节点存储有界任务摘要、局部引入的原子证据及修订历史；边表示子状态由父状态证据推导而来。
- **有界上下文构造**：
  - 策略每步只看到当前活跃节点的摘要（140 字以内）和 Top-5 相关证据；
  - 外部树结构保留完整活跃证据路径，因此单步推理上下文为 O(1)，与轨迹长度无关。
- **证据溯源与冲突处理**：
  - 每个原子证据有稳定标识符和来源 URL，绑定方式按检索段落索引完成，避免 LLM 复述 URL 带来的无法验证风险；
  - 新证据先与已有相关证据做冲突检测，只有“同实体、同属性、同范围、同时空”的不兼容值才触发回溯；
  - 冲突确认后，定位引入该证据的节点，替换证据文本与来源，追加修订历史，重新生成该节点摘要，剪除所有后代节点，再从此节点恢复搜索。
- **形式化保障**：满足三个要求：有界上下文、声明级溯源、依赖一致性修订（即 `Dep_{t-1}(j) ⊆ I_t ∪ G_t(e'_j)`，所有依赖被废止证据的组件要么被无效化要么被重新生成）。
- **算法流程**：初始化根节点 → 循环检索：构造摘要+TopK 上下文 → 策略选择查询或停止 → 检索并抽取原子证据 → 冲突判定 → 若冲突则回溯修复，否则扩展子节点 → 最终基于活跃路径证据生成带引用的回答。

## 6. 主要结论与发现
- ReTree 在四个数据集上均优于 Full-Trajectory ReAct，judge accuracy 提升 8.3–25.6 pp；总体准确率 44.0% vs 30.1%，EM 提升 7.4 pp。
- 相比 FlatUpdate，ReTree 在所有数据集上高 2.2–4.7 pp，证明依赖结构修复的价值。
- 相比 ReportMemory，总体高 3.0 pp（44.0% vs 40.9%），说明仅凭摘要合成不够。
- 上下文压缩有效：Full-Trajectory ReAct 的平均最大逐步推理上下文是 ReTree 的 1.27–1.51 倍；ReTree 逐步上下文稳定，不随检索深度增长。
- 归因质量：ReTree 的引文精确率/召回率（44.5/41.3）显著优于 Full ReAct（37.7/27.1）和 ReportMemory（16.8/21.4），且未引用率低于 Full ReAct（14.8% vs 33.1%）。
- 回溯在真实检索中确有发生：9.6–17.5% 的 ReTree 运行触发回溯修复，验证了方法的必要性。

## 7. 优点
- **联合解决三个问题**：有界上下文、证据溯源、依赖一致性修订，不是单一压缩技巧。
- **结构语义清晰**：树边表示“状态演化/证据依赖”，区别于一般思维树或记忆索引树。
- **冲突处理有防护**：同属性同范围冲突判定加上历史感知确认，减少误回溯和来回翻转。
- **引文可验证**：按段落索引绑定来源，且通过 NLI 对“原始段落→声明”做检查，确保引文真实支撑声明。
- **良好实验对比**：FlatUpdate 和 ReportMemory 分别隔离了“结构修复”和“摘要合成”两个因素。

## 8. 不足与局限
- **硬剪枝过于粗放**：将修订节点的所有后代视为依赖，可能误删实际与错误证据无关的有用状态，降低效率。
- **冲突判断依赖 LLM**：假阴性会保留污染，假阳性会过度剪枝；论文未给出冲突检测器的单独准确率实验。
- **只适用于搜索工作记忆**：不是通用长期记忆，不支持对所有历史陈述的无损回忆。
- **计算开销增加**：相比 FlatUpdate，ReTree 增加 7–11% 模型调用和 10–13% token 用量；外部证据存储仍持续增长，线性证据选择和树遍历在超长轨迹上会变慢。
- **评估范围有限**：归因诊断仅覆盖 FRAMES 子集；2Wiki/HotpotQA 使用固定 600 题子集，可能引入抽样偏差；未报告方差/多次运行稳定性。
- **未来可改进方向**：用细粒度依赖图替代硬剪枝，引入向量索引和专用轻量级冲突检测器以降低开销。

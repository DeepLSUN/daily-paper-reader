## 摘要
大型语言模型越来越多地被部署为通过浏览器与网页交互的自主代理。尽管最近的进展由评估端到端任务成功率的基准推动，但这些评估在很大程度上忽视了真实网页浏览中的两个基本困难来源：丰富用户界面上的复杂操作，以及动态渲染内容的视觉感知，尤其是在跨多个网站的工作流中。我们引入了CAP，一个可扩展的基准，用于评估浏览器代理在跨站、类人网页任务上的表现，这些任务需要非平凡的UI交互和视觉理解。具体而言，我们采用了一种分解-重组流程，首先将每个网站抽象为一个结构化的站点卡片，捕获面向用户的功能、复杂的执行操作和感知需求，然后将这些组件重组为真实的跨站工作流。因此，每个任务都基于每个网站上的多个具体操作，从而实现细粒度的诊断。在此框架基础上，我们在精心质量控制下构建了覆盖108个真实网站和24个领域的420个任务。使用我们可验证的“代理即裁判”评估框架对最先进的浏览器代理进行的实验显示成功率较低，并揭示了以感知为主的交互仍然是一个主要瓶颈，暴露了当前代理与真实网页浏览需求之间的显著差距。

## Abstract
Large language models are increasingly deployed as autonomous agents that interact with the web through browsers. While recent progress has been driven by benchmarks that evaluate end-to-end task success, these evaluations largely overlook two fundamental sources of difficulty in real web browsing: complex actions over rich user interfaces and visual perception of dynamically rendered content, especially in workflows that span multiple websites. We introduce CAP, a scalable benchmark for evaluating browser agents on cross-site, human-like web tasks that require non-trivial UI interactions and visual understanding. Specifically, we adopt a decomposition-and-recomposition pipeline that first abstracts each website into a structured site card capturing user-facing functions, complex execution operations, and perceptual requirements, and then recomposes these components into realistic cross-site workflows. Each task is therefore grounded in multiple specific operations on each website, enabling fine-grained diagnosis. Built on this framework, we construct 420 tasks across 108 real-world websites and 24 domains under careful quality control. Experiments on state-of-the-art browser agents using our verifiable agent-as-a-judge evaluation framework show low success rates and reveal that perception-heavy interactions remain a major bottleneck, exposing substantial gaps between current agents and real-world web browsing demands.

### 6. 论文的主要结论与发现

- **发现一：最先进的浏览器代理在复杂执行和感知任务上表现糟糕。**
  - 最佳代理 Manus 的成功率仅为 **8.0%**；人类基线也仅为 10.0%（满分 35.0%）。
  - 人类失败主要源于遗漏长工作流中的某个约束，而非无法执行单独步骤；因此**部分完成率**是更具参考价值的比较指标。
  - **Comet 是特例**：部分完成率（48.0%）领先但成功率仅 6.0%，且输出长度（104k）高出其他系统一个数量级，说明其中间推理正确但未能整合为满足所有 Rubric 叶节点的最终答案。
- **发现二：感知（Perception）是比执行（Execution）更严重的瓶颈。**
  - 所有商业代理和 Browser-Use + GPT-5 在 Complex-A 上得分均高于 Complex-P（如 Comet 67.0% vs. 58.0%）；人类基线则基本平衡（35.0% vs. 34.0%）。
  - 结合“值读取”近乎零分的表现，**视觉推理（视觉信息解析）而非 UI 操作本身，是当前代理的主导失败模式**。
- **发现三：长推理与任务进展相关，但算力不足以保证成功。**
  - Comet（100k+ tokens）和人类（16.3 分钟）领先；快速响应的代理（Genspark 1.7 分钟、Dia 1.1 分钟）垫底。
  - 但 Browser-Use + GPT-5 花费 15.3 分钟仅获 15.0% 部分完成率，说明**高效行动比单纯行动更多更重要**。
- **发现四：细粒度视觉阅读和 UI 状态推断是最薄弱环节。**
  - 执行操作中节点操作（0.087）和日期范围选择（0.110）得分最低；感知操作中值读取近乎零分（0.000）、展开状态感知（0.092）严重受损。
  - 任务难度不由复杂操作的**数量**决定而由其**类型**决定：单步图表值读取即可能破坏整个工作流。
- **发现五：具有专业数据结构的领域特定网站难度更高。**
  - cdc.gov（0.033）和 google.com/flights（0.048）最难；accuweather.com（0.139）和 wikipedia.org（0.131）相对容易。

- **三维度联合覆盖**：CAP 是首个同时覆盖跨站工作流、复杂执行操作和挑战性感知需求的浏览器代理基准（表 1 对比清晰），弥补了现有基准的结构性空白。

- **细粒度诊断能力**：每个任务标注显式的执行和感知覆盖点，评估可落实为可独立检查的检查点而非仅凭最终结果，相比以整体 LLM 判断评分的先前方案，能定位具体失败环节。
- **可验证的代理即裁判框架**：自动生成分层 Rubric 树，采用门控-平均聚合策略区分关键/非关键节点，兼顾严格性和部分得分；评估器经过人工一致性验证（96% 一致）和跨判定骨干稳健性检验。
- **严格的质量控制**：多阶段人工审查（提议筛选 κ=0.81、五项标准任务审查、逐任务真人执行验证）确保任务合理性和可执行性；站点卡片误差分析（92.3% 准确率）透明披露自动构建的可靠性。
- **明确的复现与防污染策略**：公开/私有任务划分、公布评测日期建议、URL 归档等设计体现了严谨的科学态度。

### 8. 不足与局限

- **覆盖范围有限**：
  - 评测仅涵盖 8 个代表性代理系统，非穷尽性；论文自认结果应视为 2025 年末的快照而非最终排名。
  - 基准排除需要真实资金交易、账户绑定私有数据或强真实世界副作用的任务（如实际购买商品、发送邮件），长期尾部分布未覆盖。
- **自动构建管道的可靠性**：
  - 站点卡片自动提取可能遗漏稀有或深度嵌套的功能；虽经人工审计（92.3% 准确率），但错误集中在**过度预测**的操作项（88.7%）。
  - 人工审计目前可扩展到 420 个任务，但无法线性扩展到数万任务规模，大规模自动化的质量控制仍是未解难题。
- **评估框架的残余噪声**：
  - LLM 生成的评估脚本可能存在边界缺陷；判定代理在验证与网页内容比对时可能继承底层 LLM 的不可靠性（如网页内容在代理执行与裁判检查之间已变化）。
  - 论文不宣称无噪声验证——四项不一致均为裁判接受但人类拒绝（略宽松），且跨判定骨干模型间绝对分数有数点漂移。
- **实时网页的不可复现性**：
  - CAP 运行在实时网络上，网站布局、内容、功能可用性随时变化，绝对分数随时间漂移；虽设计缓解措施（相对时间窗口、范围过滤而非精确值、多可接受答案），但**跨长时间间隔的精确分数复现无法保证**。
- **人类基线的天花板**：任务人工执行限时 1 小时且满分标准要求每个执行/感知/格式叶节点均满足，导致人类成功率也仅 10%，限制了对“人类可行”绝对标定的参考意义。

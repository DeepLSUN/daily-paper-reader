## 摘要
近期研究将大型语言模型（LLMs）赋能为多轮搜索智能体，通过迭代检索和生成输出来解决复杂任务。然而，多轮搜索智能体的上下文冗长且复杂。例如，每一轮检索到的文档集合不可避免地会引入不相关信息，分散LLMs的注意力，这被称为“上下文干扰”，可能阻碍搜索智能体的可靠性和效率。因此，我们对多轮搜索智能体中的上下文干扰进行了系统性研究，重点关注：i）搜索智能体上下文的哪些部分会导致上下文干扰，ii）如何优化搜索智能体的上下文以减轻干扰，以及iii）将上下文优化纳入搜索智能体训练是否能带来进一步改进。我们发现干扰主要源于最新检索到的文档。基于这些发现，我们引入了一种基于蒸馏的上下文优化器，以动态缓解多轮搜索智能体的上下文干扰。最后，我们验证了将上下文优化纳入搜索智能体的强化学习训练流程中，能够显著增强其可靠性和效率。本研究强调了缓解搜索智能体上下文干扰的重要性，并为AI智能体提出了一种“先优化上下文，再生成”的新范式。

## Abstract
Recent research empowers Large Language Models (LLMs) as multi-turn search agents to iteratively retrieve and generate outputs until complex tasks are solved. However, the contexts of multi-turn search agents are lengthy and complex. For example, the retrieved set of documents in each turn would inevitably introduce irrelevant information that distracts LLMs, referring to \textit{context interference}, potentially hindering the reliability and efficiency of search agents. Therefore, we conduct a systematic study on context interference in multi-turn search agents, focusing on investigating i) which parts of the context of search agents will contribute to the context interference, ii) how to refine the contexts of search agents to mitigate the interference, and iii) can incorporating context refinement into search agent training yield further improvements. We reveal that interference primarily arises from the latest retrieved documents. Based on the explored findings, we then introduce a distill-based context refiner to dynamically mitigate context interference for multi-turn search agents. Finally, we validate that incorporating context refinement into RL training pipelines of search agents can significantly enhance both reliability and efficiency. This study highlights the importance of mitigating context interference of search agents, inspiring a novel paradigm of ``refine context and then generate'' for AI agents.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

论文提出了一套从“分析干扰来源”到“缓解干扰”再到“训练阶段缓解干扰”的完整方法论链条：

1. **定位干扰源头**：通过设计不同的上下文掩码变体（IRCoT-o、IRCoT-oq、IRCoT-oqp），逐步移除历史轮次中的文档、查询与思考步骤，观察性能变化，从而确定干扰主要来自**最新检索的文档**。
2. **构建上下文精炼器（上下文精炼器）**：基于蒸馏方式，让强大的教师模型（GPT-4）从最新检索文档中提取与搜索查询最相关的关键信息，形成精炼文档，用此数据训练弱模型掌握精炼能力。
3. **融入RL训练**：将上下文精炼器嵌入GRPO强化学习训练流程中，在rollout阶段动态精炼上下文，减少低质量轨迹对策略优化的干扰。

### 2.2 关键技术细节

#### （1）干扰来源分析（RQ i）

设计了三种基于IRCoT的变体来分别掩码不同上下文部分：

| 方法 | 保留的上下文内容 | 目的 |
|---|---|---|
| IRCoT-o | 仅保留最新观察 oᵢ | 检测历史轮次中检索文档的干扰 |
| IRCoT-oq | 保留最新观察 + 历史思考；去掉历史查询 | 检测历史搜索查询的干扰 |
| IRCoT-oqp | 仅保留最新思考、查询、观察 | 检测历史思考步骤的干扰 |

**发现**：历史文档和历史查询都带有一定干扰，但即便去除这些历史部分，召回率与召回准确率的差距仍然显著，表明**最新检索文档是上下文干扰的主要来源**。

#### （2）基于蒸馏的上下文精炼器（RQ ii）

- **蒸馏数据构建流程**：
  1. 使用教师模型 M_T（GPT-4）在训练集上执行IRCoT推理；
  2. 在每一轮中，让教师模型从检索返回的文档集 dᵢ 中仅提取与搜索查询 qᵢ₋₁ 最相关的关键信息，得到精炼文档 ˜dᵢ；
  3. 只保留最终答案正确的轨迹，形成蒸馏数据集 D_d；
  4. 使用蕴含模型（entailment model）验证精炼文档 ˜dᵢ 完全包含于原始文档 dᵢ、不引入额外知识；
  5. 将验证通过的数据格式化为上下文精炼数据集 D_c = {(˜dᵢ, dᵢ, qᵢ)}。
- **训练方式**：使用监督微调（SFT）训练基础LLM M_π，目标函数为：

  \[
  L_{SFT}^{\pi} = -\frac{1}{M}\sum_{i=1}^{M} \log M_\pi(\tilde{d}_i \mid d_i, q_i)
  \]

  训练完成后得到上下文精炼器 F = M_π*，每轮动态将最新检索文档 dᵢ 精炼为 ˜dᵢ，替换原始检索文档作为模型输入。

#### （3）上下文精炼的强化学习训练框架 CRRL（RQ iii）

- **基础算法**：采用GRPO（Group Relative Policy Optimization），无需价值模型，组内相对奖励作为优势估计。
- **核心流程**：
  - 在rollout过程中，智能体产生的轨迹仅包含思考步骤与精炼文档（检索文档经F精炼后再送入上下文）；
  - 动作 aᵢ = [pᵢ, qᵢ] 基于上下文 sᵢ = [x, p₀:ᵢ₋₁, qᵢ₋₁, ˜dᵢ] 生成，其中 ˜dᵢ = F(dᵢ)；
  - 检索得到的token不参与损失计算（loss masking），只对LLM生成的token（思考与查询）进行策略优化，保证检索的适应性同时稳定训练。
- **优化目标**：基于GRPO的PPO式裁剪目标，包含组内优势估计：

  \[
  L_{CRRL}^{M_\pi} = -\mathbb{E}_{\{a_i^j\}_{j=1}^G \sim M_{ref}(\cdot|s_i^j)} \left[ G_\pi - \beta \cdot KL \right]
  \]

  其中优势通过组内奖励标准化计算：A_j = (r_j − μ_j) / σ_j。

## 6. 主要结论与发现

1. **干扰来源定位**：多轮搜索智能体的上下文干扰主要源自**最新检索文档**中的不相关信息；历史轮次的检索文档与查询也包含一定干扰，但权重次之；历史思考步骤则保留了关键中间信息，不应轻易移除。
2. **精炼优于压缩**：基于查询的关键信息提取（GPT-精炼）显著优于对上下文的通用总结压缩（GPT-压缩），说明“提取关键内容”比“笼统概括”更能有效缓解上下文干扰。
3. **蒸馏的有效性**：通过蒸馏数据集训练的上下文精炼器（基于Qwen2.5-7b/3b）能达到与教师模型GPT-4（GPT-精炼）几乎相当的性能，说明相对较弱的LLM通过微调也能获得高质量的上下文精炼能力，**无需在推理阶段依赖外部大模型**。
4. **自精炼的局限性**：基础模型自身进行精炼（自精炼）效果不佳，无法有效降低上下文干扰，凸显了外部蒸馏信号的重要性。
5. **CRRL的增益**：将上下文精炼器纳入GRPO强化学习训练后（CRRL），在可靠性和效率两方面均全面优于IRCoT、RFT、Search-GRPO和Search-o1等基线：在7b模型上平均EM达36.6（ART 1.7），在3b模型上平均EM达31.5（ART 1.3）。
6. **效率显著提升**：CRRL在推理阶段相比IRCoT和Search-GRPO，显著降低了平均检索次数（ART）、上下文长度（Len.）和平均推理时间（AIT），精炼器带来的额外推理开销被检索次数和上下文长度的缩减完全抵消。
7. **范式启示**：研究验证了“先精炼上下文、再生成动作”的智能体范式，对AI智能体（不仅是搜索智能体）的设计具有启发意义。

## 7. 优点：方法与实验设计亮点

1. **问题发现新颖且务实**：首次系统性地针对多轮搜索智能体研究上下文干扰问题，指出了检索文档“含有答案但模型答不对”的关键瓶颈，而非泛泛的“幻觉”或“错误检索”问题。
2. **干扰来源归因方法巧妙**：通过精心设计的掩码变体（逐步移除历史观察/查询/思考），以极简方式实现了对复杂上下文中不同成分干扰贡献的精确归因，方法透明、可复现。
3. **蒸馏方案具有工程价值**：将GPT-4的精炼能力蒸馏到小型模型（7b/3b），使搜索智能体在推理阶段不依赖API级别的外部模型即可获得接近教师模型的精炼质量，显著降低部署成本。
4. **数据质量控制严格**：使用蕴含模型验证精炼文档不脱离原始文档、不引入额外知识，保证蒸馏数据干净，避免引入噪声。
5. **训练与推理双阶段协同优化**：不仅在推理阶段缓解干扰，更将干扰缓解能力内化到RL训练流程中，实现了“动态精炼上下文”与“策略优化”的协同，全面提升质量与效率。
6. **度量维度全面**：采用EM、ART、Len.、AIT、recall rate、recall accuracy等多维度指标，同时兼顾可靠性与效率，评估充分。
7. **开源贡献**：作者公开了代码仓库，便于后续研究复现与扩展。

## 8. 不足与局限

1. **任务覆盖范围有限**：论文只关注了搜索智能体（QA任务）场景，对工具使用（工具使用）、规划（规划）等其他智能体场景尚未验证。不同场景的上下文干扰因素可能不同，结论的泛化性有待进一步检验。
2. **精炼器作为外部模块**：上下文精炼器被设计为搜索智能体的辅助模块，尚未与智能体本身的训练目标深度融合。未来应探索将精炼能力内化为智能体自身参数的训练算法。
3. **教师模型依赖**：蒸馏数据质量受限于GPT-4的能力上限，若教师模型本身在特定领域或长尾知识上提取效果不佳，精炼器也会有相应的性能天花板。
4. **训练数据领域有限**：RL训练仅使用NQ和HotpotQA两个数据集的子集（约40k条），虽然测试覆盖7个数据集，但训练覆盖领域有限，跨领域迁移效果缺乏解释。
5. **实验细节缺失**：
   - 未报告训练完整时长和整体算力消耗；
   - 未报告不同随机种子下的方差或统计显著性检验；
   - 部分效率结果（如AIT、Len.）仅在6b/7b和3b模型上给出均值，未按数据集细粒度展示。
6. **ranking基线未细致调优**：额外ranking基线仅使用固定阈值0.2和0.5，缺乏更细粒度的阈值扫描，可能低估了简单过滤方法在特定场景下的表现。
7. **检索质量前提假设**：所有方法假设检索器（E5）能返回包含答案的文档。在真实搜索场景中，检索器质量波动可能使上下文精炼器的效果打折。

## 摘要
大型语言模型智能体越来越依赖于可复用技能来扩展其超出参数化知识的能力。然而，从大规模技能库中检索合适的技能仍然具有挑战性，因为现实中的用户请求通常简洁且规定不足，仅陈述任务目标，而所需的能力和执行步骤则隐含其中。现有基准对此类请求的覆盖有限。为弥补这一空白，我们引入了 SkillReason-Bench，一个大规模跨领域基准，包含 3,729 个查询和涵盖九个领域的 61,228 个技能的检索语料库。我们进一步提出了 SkillReason，一个两阶段框架，将思维链推理用作技能检索的训练时监督。在第一阶段，由更强教师生成的能力推理轨迹通过对比学习、检索分布对齐和语言建模提供显式监督，鼓励检索器在其查询表示中内化能力推理。在第二阶段，检索引导的 GRPO 目标鼓励模型探索更适合自身能力且对检索更有效的推理轨迹。在推理时，SkillReason 直接编码原始查询，无需自回归 CoT 生成，从而保持高效的仅查询检索。在 SkillReason-Bench、SkillRet 和 SRA-Bench 上的大量实验表明，SkillReason 在所有三个基准上均达到最先进性能，证明了推理增强训练能更好地弥合高层任务目标与技能能力之间的语义鸿沟。

## Abstract
Large language model agents increasingly rely on reusable skills to extend their capabilities beyond parametric knowl- edge. However, retrieving the appropriate skill from a large- scale library remains challenging because realistic user re- quests are often concise and underspecified, stating only the task goal while leaving the required capabilities and execu- tion steps implicit. Existing benchmarks provide limited cov- erage of such requests. To address this gap, we introduce SkillReason-Bench, a large-scale cross-domain benchmark containing 3,729 queries and a retrieval corpus of 61,228 skills spanning nine domains. We further propose SkillRea- son, a two-stage framework that uses chain-of-thought rea- soning as training-time supervision for skill retrieval. In Stage I, capability reasoning traces generated by a stronger teacher provide explicit supervision through contrastive learning, re- trieval distribution alignment, and language modeling, en- couraging the retriever to internalize capability reasoning in its query representation. In Stage II, a retrieval-guided GRPO objective encourages the model to explore reasoning trajecto- ries better suited to its own capabilities and more effective for retrieval. At inference, SkillReason directly encodes the orig- inal query without autoregressive CoT generation, preserv- ing efficient query-only retrieval. Extensive experiments on SkillReason-Bench, SkillRet, and SRA-Bench show that Skill- Reason achieves state-of-the-art performance across all three benchmarks, demonstrating that reasoning-enhanced training better bridges the semantic gap between high-level task goals and skill capabilities.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 总体框架

- SkillReason 使用共享编码器 \( f_\theta \) 将查询和技能文档映射为归一化表示，相关性分数为余弦相似度：
  \[
  h_\theta(q, s) = e_\theta(q)^\top e_\theta(s)
  \]
  其中 \( e_\theta(\cdot) \) 是对最后一层 token 隐藏状态做 ℓ2 归一化得到。
- **推理时**：技能表示可离线预计算；模型只需对原始查询编码一次，即可检索前 k 个技能，**无需自回归生成 CoT**，延迟与骨干模型相当。

### 2.2 Stage I：从教师推理中学习

- 教师模型（Claude Sonnet 4.6）为每个训练查询生成能力级推理轨迹 \( c^* \)，构建增强查询 \( \tilde{q} = [q; c^*] \)。
- 优化目标包含四个部分，总损失为：
  \[
  \mathcal{L}_{\mathrm{SFT}} = \mathcal{L}_{\mathrm{CL}}^{\mathrm{raw}} + \lambda_{\mathrm{cot}} \mathcal{L}_{\mathrm{CL}}^{\mathrm{cot}} + \lambda_{\mathrm{KL}} \mathcal{L}_{\mathrm{KL}} + \lambda_{\mathrm{LM}} \mathcal{L}_{\mathrm{LM}}
  \]
  1. **原始查询对比学习（\( \mathcal{L}_{\mathrm{CL}}^{\mathrm{raw}} \)）**：直接优化推理时所用的“仅查询”路径。
  2. **增强查询对比学习（\( \mathcal{L}_{\mathrm{CL}}^{\mathrm{cot}} \)）**：让能力推理信息改善查询与目标技能的匹配。
  3. **检索分布对齐（\( \mathcal{L}_{\mathrm{KL}} \)）**：将增强查询（特权视图）在候选技能上的软分布蒸馏到原始查询（仅查询视图），使用 stop-gradient 的 KL 散度，使得原始查询无需 CoT 也能做出类似检索决策：
     \[
     \mathcal{L}_{\mathrm{KL}} = T^2 D_{\mathrm{KL}}\left( \mathrm{sg}\left[p_T^\theta(\cdot|\tilde{q})\right] \,\|\, p_T^\theta(\cdot|q) \right)
     \]
  4. **能力推理语言建模（\( \mathcal{L}_{\mathrm{LM}} \)）**：用 teacher-forcing 训练共享骨干生成教师推理轨迹，让模型内化能力推理，并为 Stage II 初始化策略：
     \[
     \mathcal{L}_{\mathrm{LM}} = -\sum_{t=1}^{|c^*|} \log \pi_\theta(c^*_t \mid q, c^*_{<t})
     \]

### 2.3 Stage II：检索引导的推理优化（Retrieval-Guided GRPO）

- **动机**：固定的教师推理轨迹可能与模型自身推理能力不匹配，且对检索目标未必最优。
- **流程**：
  - 以 Stage I 模型为初始化策略 \( \pi_\theta \)，对每个查询采样 G 条推理轨迹 \( \{c^{(g)}\} \)。
  - 用冻结的 Stage I 检索器作为奖励模型，计算检索收益。
- **奖励设计**：
  - **检索边界（margin）**：目标技能相似度减去最强负样本相似度：
    \[
    m(x) = h_\phi(x, s_q^+) - \max_{s^- \in N_q} h_\phi(x, s^-)
    \]
  - **边界奖励**：\( R_{\mathrm{margin}}^{(g)} = \tanh(m(\tilde{q}^{(g)})/\tau_{\mathrm{margin}}) \)
  - **增益奖励**：衡量推理增强查询相对原始查询的检索改进：\( R_{\mathrm{gain}}^{(g)} = \mathrm{clip}\left((m(\tilde{q}^{(g)}) - m(q))/\tau_{\mathrm{gain}}, -1, 1\right) \)
  - **长度惩罚**：\( P_{\mathrm{len}}(c) = \min(P_{\max}, \lambda_{\mathrm{len}}[|c| - L_{\mathrm{budget}}]_+) \)，用于抑制过长的推理轨迹。
  - 总奖励：\( R^{(g)} = \lambda_{\mathrm{margin}} R_{\mathrm{margin}}^{(g)} + \lambda_{\mathrm{gain}} R_{\mathrm{gain}}^{(g)} - P_{\mathrm{len}}(c^{(g)}) \)
- **优化方式**：标准 GRPO 目标，含组内相对奖励归一化和对 Stage I 参考策略的 KL 正则。由于生成策略与查询编码器共享骨干，生成训练中获得的检索相关能力推理可被内化到仅查询表示中。

### 2.4 训练数据

- **训练集来源**：SkillRouter 发布的 65,714 个技能（源自 Claude Skill Registry），与三个评测基准的查询完全独立。
- **Stage I**：用 Claude Sonnet 4.6 为每个技能生成 3 条用户查询 + 能力推理轨迹，经质量过滤和类别平衡选 30K 条。
- **Stage II**：用 Claude Haiku 4.5 将 Stage I 查询改写为更隐式的用户请求，保留任务意图与目标技能，共 29,995 条。
- **负样本构造**：每个查询固定 10 个显式负样本，来源包括正技能嵌入邻居、查询检索邻居、同类目样本、跨类目样本；并构建了基于嵌入相似度（>0.85）和字符 trigram Jaccard（>0.60）的伪负样本排除图，避免将功能重叠/分叉技能误作负样本。

## 6. 论文的主要结论与发现

- **SkillReason-4B 在三个基准上几乎全面最优**：SkillReason-Bench R@1 53.58 / R@10 78.84；SRA-Bench R@1 60.90 / R@10 91.56；SkillRet R@1 52.03 / R@10 77.93。
- **0.6B 模型显著超越同规模基线，甚至超过 8B 通用嵌入模型**：平均 R@10 绝对提升 17.56 分；优于 Qwen3-Embedding-8B 全部指标。
- **现有技能专用检索器在隐式请求上表现明显下降**：SkillRouter 和 SkillRet 在 SkillRet（长查询、显式程序信息）上强，但在 SkillReason-Bench 上低于 Qwen3-Embedding-0.6B，说明它们依赖表面词汇/程序性线索，缺乏能力推理能力。
- **Stage I 各组件均有效**：CoT CL、分布转移、CoT LM 逐步提升性能；但分布转移单独作为目标时不稳定，宜作为辅助对齐信号。
- **Stage II 检索引导 RL 主要在隐式查询场景上带来增益**，对 SkillRet（查询长且程序明确）无进一步改善；证明 RL 帮助模型探索更适合自身能力的推理轨迹。
- **推理时无需生成 CoT**：自生成 CoT 增强不带来一致增益，说明训练所得能力推理已内化到查询表示中；即使使用 235B 教师生成的 CoT，0.6B 模型也能恢复绝大部分收益。
- **端到端任务增益显著**：SkillReason-4B 流水线将 5 个下游 LLM 任务成功率提升 14.66–25.03 个百分点，接近 gold skill 上限。
- **延迟优势明确**：SkillReason 在线检索延迟与骨干模型几乎相同（0.6B 约 31.6 ms；4B 约 143.9 ms），而显式 CoT 生成将 0.6B 延迟从 32 ms 增至 3,151 ms、4B 从 145 ms 增至 4,237 ms（约增加 1–2 个数量级）。

## 7. 优点：方法或实验设计上的亮点

- **基准设计针对真实缺口**：SkillReason-Bench 系统性地构造“简洁、隐式、需要能力推断”的查询，弥补了现有基准的空白，且规模大（3,729 查询 / 61,228 技能 / 9 领域）。
- **训练-推理解耦的思路新颖**：把 CoT 推理作为训练时特权监督，推理时退化为纯查询编码，兼顾了推理增强效果与效率——避免了现有“推理增强检索”方法（如 Think-Then-Embed、RQR）在推理时自回归生成 CoT 的高延迟。
- **两阶段设计合理**：Stage I 用教师推理做显式监督，Stage II 用检索奖励做 RL 优化，解决“教师轨迹与学生能力不匹配”的问题；GRPO 共享编码器与生成策略的参数，使生成侧学到的推理能被内化到检索表示。
- **奖励设计精细**：margin reward + gain reward + 长度惩罚三部分各有作用，消融显示每个组件都有独立贡献。
- **实验证据链完整**：从检索指标到检索–重排、再到端到端下游任务，形成完整验证闭环；并加入基准质量审计和替代技能敏感性分析，增强评测可信度。
- **数据质量控制严格**：训练数据有伪负样本排除图、四源负样本、去重和审计；评测基准有多模型独立评审 + 人工仲裁，且没有观察到训练/测试泄漏。
- **延迟测量详实**：给出检索、重排、CoT 生成的逐项延迟，清楚展示方法的实用优势。

## 8. 不足与局限

- **训练时长与算力消耗未披露**：未报告 GPU 小时数、总训练时长或 RL 收敛曲线，难以评估训练成本的性价比。

- **依赖教师模型与合成数据的质量上限**：Stage I 的能力推理轨迹和 Stage II 的隐式查询改写分别由 Claude Sonnet 4.6 与 Claude Haiku 4.5 合成。这种设计使训练数据的质量、风格多样性和领域覆盖高度受制于单一教师模型的能力与偏好——若教师对某些领域（如工业控制、医疗）的推理存在盲区，错误会被整体编码进检索器；同时，无论查询改写还是推理生成，都是基于预设提示模板进行的，可能隐含模板化的表达习惯，造成训练分布与实际开放域用户请求之间仍有偏差。
- **基准标注完备性仍是评估误差来源**：尽管论文通过 104,010 条非金标候选的替代技能敏感性分析证明相对排序稳定，但金标集本身仍可能系统性遗漏合法的等价技能（例如同一能力的不同封装形式、功能重叠但接口不同的技能）。这意味着所有报告的绝对指标（R@1、R@10 等）可能被低估，且不同基准间数值的可比性也会受到标注策略差异的干扰，论文未能从根本上量化这种标注偏差对跨基准对比的影响。
- **评测范围受限于英文与特定技能生态**：训练与评测数据均以英文为主，技能本体来自 Claude Skill Registry，其风格偏向 API 型、工具型技能的代码化描述。对于中文、其他多语言场景，或面向非代码类技能（如纯文本工作流、行业规程）的检索，论文没有给出证据表明推理增强训练能够跨语言、跨技能形态迁移。特别是中文隐式请求的句法省略习惯与英文差异较大，推理轨迹的监督信号是否仍有效是未知数。
- **模型规模探索有限**：实验仅在 0.6B 与 4B 两个规模上验证了 SkillReason 的有效性。论文没有考察 8B 以上模型在同等训练条件下是否还能获得一致的大幅提升，也没有说明推理增强收益是否会随骨干模型规模增大而边际递减——考虑到更大模型自身已具备更强的隐含推理能力，这种风险是存在的。
- **训练流程复杂、超参数敏感，复现门槛较高**：两阶段目标包含三类对比损失、KL 蒸馏、语言建模和检索引导 GRPO 的多项奖励权重（\( \lambda_{\mathrm{margin}}, \lambda_{\mathrm{gain}}, \lambda_{\mathrm{len}} \)）及温度参数、长度预算等，论文未系统给出关键超参数的敏感性实验。RL 阶段采用 8 条 rollout/查询的同步策略，在更大数据规模或更长推理轨迹下是否稳定收敛，也需要进一步验证。此外，训练总时长与 GPU 小时未报告，使他人难以评估该方法相对简单对比学习的额外代价。
- **动态技能库场景下的部署问题未充分讨论**：推理时虽然只需对查询编码一次，但技能向量需要离线预计算；当技能库频繁更新（新增、下架技能）时，需要增量重算索引并维持缓存一致性，论文没有讨论这种动态更新场景下的工程方案与检索质量维护策略。
- **推理时完全放弃 CoT 的代价**：训练阶段反复强化能力推理，但推理阶段对原始查询只做单次前向编码，没有显式输出任何推理依据。这在获得效率优势的同时，也意味着当检索失败（例如返回不相关技能）时，系统无法从推理中间步骤出发进行解释或容错纠偏；同时，也无法在推理时利用用户实时反馈（如追问）沿着推理路径动态修正检索意图，缺少交互式检索的扩展空间。

总体来看，SkillReason 在问题定位、方法设计、实验验证和效率优化上完成度颇高，其不足主要体现在对教师数据的依赖、评估与语言覆盖的边界，以及训练复杂度与工程部署细节尚未充分披露等方面。这些局限也为后续研究留出了明确方向——例如引入多教师/多语言数据、更轻量的单阶段训练，以及在检索失败时提供可解释推理反馈。

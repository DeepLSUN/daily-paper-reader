## 摘要
基于大语言模型的智能体框架现已成为处理多步骤任务的个人助理。现有智能体框架（如 OpenClaw）通常采用云智能体部署模式，使用闭源云端大语言模型作为骨干模型，这可能会暴露用户隐私信息并产生重复的大模型调用成本。本地智能体通过在用户控制的设备上部署前沿开源小型语言模型来解决这些部署问题，但其任务有效性仍远落后于云智能体。通过诊断分析，我们发现，使用前沿小型语言模型作为骨干的本地智能体有效性受限，主要源于骨干模型规模有限导致的环境知识缺失，包括环境规则和操作流程。为了以非参数化、上下文高效且无需专家编写的方式提供此类知识，我们提出了 SkillSmith，一个云-本地智能体协作框架，该框架将技能（Skill）作为上下文高效的知识载体，从云智能体任务探索中自动构建技能，并利用本地智能体的执行反馈进化技能，以增强冻结的本地智能体。在日常生活智能体数据集 AppWorld 和 WorkBench 上的实验表明，自动生成的技能使配备 Qwen3.6-27B（小型语言模型）的本地智能体在任务有效性上达到了与使用前沿大语言模型的云智能体相当的水平，超越了最强的非参数化基线，将 AppWorld-Normal 上的每任务平均动作数从 36.1 降至 9.9，并且无需重新运行技能构建即可泛化到其他小型语言模型骨干。

## Abstract
LLM-based agent frameworks now act as personal assistants for multi-step tasks. Existing agent frameworks such as OpenClaw commonly follow the Cloud Agent depolyment mode using closed-source cloud LLMs as backbone model, which may expose private user information and incur repeated LLM-calling costs. Local Agents address these deployment concerns by depolying frontier open-source SLMs on user-controlled devices, but their task effectiveness still lags far behind Cloud Agents. Through diagnostic analysis, we reveal that the limited effectiveness of Local Agents with frontier SLM backbones mainly comes from missing environment knowledge caused by limited backbone model scale including environment rules and operation procedures. To supply such knowledge non-parametrically, context-efficiently, and without expert authoring, we present SkillSmith, a Cloud--Local Agent collaboration framework that uses Skill as a context-efficient knowledge carrier, automatic constructs Skill from Cloud Agent task exploration and evolves Skill using Local Agent execution feedback to enhance a frozen Local Agent. Experiments on daily agent task datasets AppWorld and WorkBench show that the automatically generated Skill enables the Local Agent with Qwen3.6-27B(SLM) to achieve task effectiveness comparable to Cloud Agents with frontier LLMs, outperform the strongest non-parametric baselines, reduce average actions per task from 36.1 to 9.9 on AppWorld-Normal, and generalize to other SLM backbone models without rerunning Skill construction.

## 一、核心问题与研究动机

- **背景**：基于 LLM 的智能体框架（如 OpenClaw、Claude Code、Hermes）已广泛应用于多步骤个人任务（如发送邮件、日程安排、移动应用操作）。主流部署模式为**云智能体（Cloud Agent）**，以闭源大语言模型（如 GPT-5.5、Claude Opus 4.7）为骨干，每步执行都需将本地上下文上传至云端，存在**隐私泄露风险**和**高频 API 调用成本**。
- **痛点**：为规避上述问题，研究者提出**本地智能体（Local Agent）**——在用户本地设备部署开源小型语言模型（SLM，通常低于 35B 参数）。但实验表明，本地智能体任务完成率远低于云智能体（如 Qwen3.6-27B 的通过率仅为 AppWorld-Normal 36.3%、AppWorld-Challenge 28.1%、WorkBench 51.1%）。
- **诊断分析（三个发现）**：
  1. **核心智能体能力已达标**：Qwen3.6-27B 在 SWE-bench、Terminal-Bench、QwenClawBench、GPQA Diamond 上已与 Claude Opus 4.5 相当，说明核心能力（工具使用、指令跟随、通用推理）并非模型规模的主要瓶颈；
  2. **失败源于环境知识缺失**：对 36 条失败轨迹分析显示，91.7% 的失败由缺失环境规则（52.8%）和操作流程（38.9%）导致；
  3. **非参数化知识注入有效**：手工编写的环境知识注入系统提示后，能解决 26/33 个知识相关失败，表明无需微调模型参数即可修复大部分失败。
- **核心问题**：如何在**无需专家编写、上下文高效、非参数化**的前提下，为冻结的本地智能体提供缺失的环境知识？

## 二、方法论：SkillSmith 框架

### 核心思想
使用**云-本地智能体协作**模式：云智能体利用其丰富的参数化环境知识与更强的反思/总结能力，代替人类专家在离线阶段自动构建和演化技能（Skill）；本地智能体在在线阶段使用该技能增强任务执行，**全程无云端调用、数据不离开本地设备**。

### 关键定义
- **Agent Skill** 形式化定义：S = (M, R, C)，其中：
  - M 为主 Markdown 文件（SKILL.md），含元数据、通用指令与参考文件的指针；
  - R = {r₁, ..., rⱼ} 为参考文件，存放环境规则和操作流程；
  - C = {κ₁, ..., κⱼ} 为各参考文件的加载条件。
- **渐进式披露**：执行时智能体先读 M，仅当触发条件满足时才加载对应参考文件，避免将全部知识塞入有限的本地上下文。

### 问题形式化
- 目标函数为最大化冻结本地智能体的期望通过率：S⋆ = argmax_{S∈S_Lmax} E_{ξ∼T}[r(S; ξ)]，其中 Lmax 为技能长度预算；
- 通过黑盒优化求解：将云智能体视为文本优化器（受 TextGrad 启发），用 LLM 生成的反馈作为类梯度信号。

### 两阶段算法流程
**阶段一：技能创建（Skill Creation）**
1. **探索与反思**：云智能体执行训练任务，调用评估器获得反馈，将每条轨迹压缩为 Reflection Report（含任务、压缩轨迹、评估结果、更优路径、遇到的陷阱、使用的工具）；
2. **创建初始技能**：三个云端角色分工协作——
   - **聚类代理**：将反思报告按任务类型/应用/工具分组（≤10 簇）；
   - **蒸馏子代理**：每簇并行分析，提取步骤序列与代码模板、陷阱与补救、环境规则、触发关键词、跨簇通用性判断；
   - **合并代理**：汇总洞察文件，按频率规则（如步骤出现在 ≥N/2 簇中）将通用知识提升至主手册，特定场景细节写入参考文件，并受长度预算约束。

**阶段二：技能演化（Skill Evolution）**（迭代 R 轮）
1. **执行与压缩**：本地智能体携带当前技能执行训练任务，失败轨迹结合评估反馈压缩为 Failure Report；
2. **演化技能**：三个云端角色协作——
   - **聚类代理**：按任务类型和失败断言对失败报告聚类；
   - **分析子代理**：对比评估器的预期与实际轨迹，将失败归因为：技能/参考未加载（A）、技能指令不完整/错误（B）、粗心失误（C，接近通过）、非技能可修复（D），并输出带优先级的修改笔记；
   - **合并代理**：合并修改笔记，解决冲突，按优先级编辑，超长时压缩。
3. 每轮后记录该版本的训练集通过率，最终选择通过率最高的版本作为部署技能。

## 六、主要结论与发现

1. **效果显著**：SkillSmith 使 Qwen3.6-27B 本地智能体在 AppWorld-Normal 达 78.6%（+42.3）、AppWorld-Challenge 达 74.9%（+46.8）、WorkBench 达 89.0%（+37.9）的通过率，超过最强非参数基线 11.3~26.2 个百分点；
2. **追赶云端**：与最强云智能体相比，三个数据集上的差距从 57.7/61.1/24.3 点分别缩至 15.4/14.3 点，且在 WorkBench 上反超 13.6 点，实现本地智能体媲美甚至超越云智能体；
3. **效率提升**：技能使本地智能体避免无效探索，AppWorld-Normal 每任务平均动作数从 36.1 降至 9.9，上下文消耗减少约 55%；
4. **阶段贡献**：技能创建贡献主要增益（+30.0/+43.5/+36.7），技能演化提供附加改进（+12.3/+3.3/+1.2）；高质量初始技能可减少对大量演化的依赖；
5. **跨模型泛化**：同一技能可迁移至 Qwen3.6-30B-A3B（+20.1/+30.8）和 Gemma-4-31B（+48.2/+7.8），无需重新构建。

## 七、优点与亮点

1. **问题定位精准**：通过系统化诊断分析（3 个发现），证据链完整——从能力对比到失败归因再到非参数化验证，逻辑严密地论证了"环境知识缺失"这一根因；
2. **云-本地协作范式创新**：不是简单地在推理时调用云模型，而是将云智能体能力**离线沉淀为可复用技能**，兼顾隐私保护与效果提升，且在成本上实现"一次性离线投入，长期零在线 API 调用"；
3. **严格满足三个设计需求**：技能载体解决上下文低效（R1）、云智能体探索解决专家依赖（R2）、反馈驱动的迭代演化解决验证与修正（R3）；

6. **实际部署友好**：支持 Creation-only 和 Creation+Evolution 两种操作模式，用户可根据成本预算灵活选择。

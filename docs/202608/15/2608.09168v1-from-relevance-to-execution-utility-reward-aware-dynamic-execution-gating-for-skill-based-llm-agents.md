## 摘要
智能体技能越来越多地被用于为大语言模型（LLM）智能体配备可复用的程序性知识。尽管近期工作因技能库的扩大而显著提升了技能检索效果，但检索到看似合理的技能组合并不能保证执行它是值得的。由于每次条件于技能的推演（rollout）在计算上代价高昂，决定是否应执行检索到的组合已成为日益重要的挑战。为此，我们引入了奖励感知动态执行门控（RADEG），一种位于技能检索与智能体执行之间的轻量级、与检索器无关的决策层。RADEG学习一个低成本的替代模型，在昂贵的推演启动之前预测查询-组合对的执行效用。为了在控制任务难度的同时获取信息丰富的监督信号，我们通过删除、添加或替换一个技能来局部扰动每个检索到的组合，产生匹配的相同查询推演，从而隔离组合构成对验证器奖励的影响。在部署期间，RADEG仅在新验证器反馈可用时更新一个热启动的逻辑回归头，使得无需重训练检索器或智能体即可低成本地调整执行/跳过边界。在288次收集到的推演上进行查询级留出评估，RADEG大幅减少了不必要的智能体执行，同时保留了大部分下游验证器奖励。在不同执行预算下，它始终优于基于相关性和随机门控，表明执行感知的替代建模为技能检索提供了一种实用且成本效益高的补充。

## Abstract
Agent skills are increasingly used to equip large language model (LLM) agents with reusable procedural knowledge. Although recent work has substantially improved skill retrieval due to the increasing skill libraries, retrieving a plausible skill bundle does not guarantee that executing it is worthwhile. Since every skill-conditioned rollout is computationally expensive, deciding whether a retrieved bundle should be executed has become an increasingly important challenge. To this end, we introduce the Reward-Aware Dynamic Execution Gate (RADEG), a lightweight, retriever-agnostic decision layer between skill retrieval and agent execution. RADEG learns a low-cost surrogate model that predicts the execution utility of a query--bundle pair before the expensive rollout is launched. To obtain informative supervision while controlling for task difficulty, we locally perturb each retrieved bundle by deleting, adding, or replacing one skill, producing matched same-query rollouts that isolate the effect of bundle composition on verifier reward. During deployment, RADEG updates only a warm-started logistic head as new verifier feedback becomes available, enabling inexpensive adaptation of the execute/skip boundary without retraining either the retriever or the agent. Under a query-level held-out evaluation on 288 collected rollouts, RADEG substantially reduces unnecessary agent executions while preserving a large fraction of the downstream verifier reward. It consistently outperforms relevance-based and random gating across different execution budgets, demonstrating that execution-aware surrogate modeling provides a practical and cost-effective complement to skill retrieval.

## 一、论文的核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）智能体越来越多地使用“技能”（skill）来封装可复用的程序性知识。随着技能库规模扩大，如何为给定查询检索合适的技能包（bundle）成为关键问题。现有工作主要聚焦于检索相关性（如 PPR、嵌入相似度、重排序等），并常用 Hit@K、Recall@K、MRR、NDCG 等排序指标评估。
- **核心问题**：论文指出存在“相关性–效用差距”（relevance–utility gap）——检索到相关技能包并**不保证**实际执行能产生有价值的验证器奖励。由于每次执行（rollout）都很昂贵（API 调用、令牌消耗、工具交互、时间成本），在启动执行前判断“这个查询–技能包对是否值得执行”非常重要。
- **研究意义**：作者提出在技能检索与智能体执行之间增加一个轻量级的、与检索器无关的“执行门控”层，以较低成本预测执行效用，从而避免大量低价值执行，提高整体效率。

## 二、论文提出的方法论

### 1. 核心思想
- 提出 **RADEG（Reward-Aware Dynamic Execution Gate）**，一种后检索、预执行的决策模块。
- 它学习一个低成本代理模型，估计查询 q 与技能包 b 在执行后得到**非零验证器奖励**的概率，即 \(s_\theta(q,b) \approx Pr(r(q,b)>0|q,b)\)。
- 决策规则为 \(g_\theta(q,b;\tau)=\mathbb{I}[s_\theta \ge \tau]\)，当概率超过阈值 τ 时执行智能体，否则跳过。
- RADEG 不修改上游检索器，也不修改下游智能体，可叠加在现有流水线上。

### 2. 关键技术细节

- **输入表示**：
  - 使用固定文本编码器 `all-MiniLM-L6-v2`（384维）分别编码查询文本 \(e_q\) 和每个技能的文本描述 \(E(d_s)\)。
  - 技能包表示取平均池化：\(e_b = \frac{1}{|b|}\sum_{s \in b} E(d_s)\)。
  - 拼接查询表示和包表示得到语义向量 \(x_{sem}=[e_q \| e_b]\)，再加入可选的实现相关特征（如包条件指示、GoS PPR 汇总统计），形成完整输入 \(x(q,b)\)。

- **离线训练**：
  - 使用历史执行记录 \(D=\{(q_i,b_i,r_i)\}\)，定义标签 \(y_i=\mathbb{I}[r_i>0]\)。
  - 通过 MLP 编码器 \(h_\phi\) 将输入映射为隐藏表示，再经逻辑回归头预测概率。
  - 训练目标为类加权二元交叉熵，正类权重 \(\omega_+=N_{neg}/N_{pos}\)，以平衡零奖励与正奖励样本。

- **在线动态门控**：
  - 离线训练后**冻结编码器**，只更新逻辑回归头（w,c）。
  - 每次执行后获得验证器反馈 r，生成标签 y，执行一次在线梯度更新（二元交叉熵损失）。
  - 该设计使决策边界能够低成本地适应新反馈，而无需重训练整个模型。

- **训练数据构造（扰动）**：
  - 为获得监督信号并控制任务难度，对每个 GoS 检索到的原始技能包进行三种局部扰动：删除最高 PPR 技能、添加一个不相关技能、替换为图相似技能。
  - 这样每个查询产生 4 个变体（原始 + 3 扰动），共 72×4=288 个查询–技能包对，用于分析和训练，隔离包组成对奖励的影响。

## 三、实验设计

### 1. 数据集与基准
- **SkillsBench**：72 个查询任务，每任务 4 个包条件（GoS 原始、Delete Top、Add Irrelevant、Replace Similar），共 288 条执行记录（其中 194 条零奖励，94 条正奖励）。
- **执行环境**：Docker 容器中的 Claude-Code 风格环境，使用 Claude Sonnet 4.6 作为执行模型，验证器为确定性、任务特定的 SkillsBench 验证器，返回归一化加权奖励 \([0,1]\)。
- **评估协议**：采用**查询级划分**（同一查询的所有变体在同一分区），约 70% 查询训练，30% 作为未见评估流。主对比使用相同的 5 个查询级划分，另作 30 个划分的不确定性分析。

### 2. 对比方法
- **Always-Execute**：执行所有查询–技能包对（归一化参考）。
- **Random-Gate**：随机执行排名。
- **PPR-Gate**：用 GoS 的聚合 PPR 相关性作为执行分数。
- **Static Head**：仅用离线训练的固定逻辑头，不做在线更新。
- **Memory-Corrected Head**：静态预测与 K 近邻记忆的正例频率混合。
- **Oracle**：使用真实标签排序（不可部署的上界）。
- 另在补充实验中比较了 GCN 编码器。

### 3. 评估指标
- 预测性能：AUROC、AUPRC。
- 操作性能：Calls Saved（跳过比例）、Reward Retained（保留奖励比例）、Reward per Call（每次执行的平均奖励），默认阈值 τ=0.5。
- 固定预算：Reward retention @ β（β 为 20%/40%/60%/80%），并用 3,000 次查询级 paired bootstrap 做显著性检验。

### 4. 额外实验
- **跨智能体适应**：在 Qwen3.7-Max、DeepSeek-Chat、GLM-5.2 等目标智能体上评估，采用静态、per-target 适应和持续适应协议。
- **跨检索器与包大小**：hybrid、BM25、embedding 三种检索器及 distractor 构造，评估 top-8 与 top-7 包。
- **选择性反馈与探索**：ε-greedy 探索，ε 取 0、0.05、0.1、0.2、0.5、1。
- **特征消融**：去除查询嵌入、包嵌入、包条件特征、PPR 统计等。
- **跨基准泛化**：在 τ-Bench、AgentDojo、ToolSandbox 上构造 Gold/Halfmix/Distractor 工具包，评估 RADEG 的泛化能力。

## 六、论文的主要结论与发现

- **相关性–效用差距确实存在**：在 72 个任务中，22 个任务至少在一种扰动下奖励发生变化；PPR 聚合相关性与验证器奖励的 Spearman 相关系数接近零（−0.089 和 −0.131），AUROC 仅为 0.435/0.418，说明纯相关性分数无法可靠预测执行效用。
- **RADEG 有效预测执行效用**：在五个查询级分割上，RADEG 的 AUROC 为 0.717，AUPRC 为 0.570；默认阈值下跳过 68% 的智能体调用，同时保留 61% 的验证器奖励，每次调用的平均奖励从 0.309 提升至 0.483（相对提升约 56%）。
- **固定预算下优势明显**：在 20% 预算下，RADEG 保留 40% 奖励，而 PPR-Gate 仅 15%、Random-Gate 仅 19%；在 40% 预算下分别 61%、40%、41%。所有预算下的优势经 bootstrap 检验均显著（p<0.001）。
- **在线更新具有价值**：RADEG 优于静态头和记忆校正头，说明冻结编码器只更新逻辑头的方式能够有效适应新反馈。
- **跨智能体与跨检索器泛化**：在 Qwen3.7-Max、GLM-5.2 上 AUROC 分别达 0.733 和 0.752，在 DeepSeek-Chat 上 0.628；对 hybrid、BM25、embedding 检索均有效，且对包大小变化不敏感。
- **选择性反馈下性能下降，探索可部分缓解**：在纯选择性反馈（ε=0）下 AUROC 为 0.557，随探索率增大升至 0.745（ε=1），说明缺失标签是重要影响因素。

## 七、优点

- **问题定位精准**：明确区分“检索相关性”与“执行效用”，针对高成本执行场景提出后检索门控，具有实际价值。
- **方法轻量且通用**：RADEG 是检索器无关、智能体无关的插件式模块，只增加极小计算开销（微秒级），可叠加到现有流水线。
- **训练数据构造巧妙**：通过删除/添加/替换单个技能构造同查询配对样本，隔离包组成对奖励的影响，同时控制了任务难度，避免查询本身带来的混淆。
- **在线更新策略高效**：冻结编码器、只更新逻辑头，避免重复训练，适应新反馈的同时保持表示稳定性。
- **实验设计细致**：采用查询级划分防止泄漏；进行多分割不确定性分析；用 bootstrap 统计检验；覆盖跨智能体、跨检索器、选择性反馈、特征消融等多个角度。
- **成本意识强**：不仅报告预测精度，还考虑执行预算、每次调用的奖励等运维指标，符合实际部署关切。

## 八、不足与局限

- **数据规模有限**：仅 288 条 rollout（72 查询 × 4 条件），正样本仅 94 条，统计能力受限；跨智能体等子实验样本更少，部分结果处于“underpowered”状态，不宜过度解读。
- **扰动类型受控且单一**：只测试了删除最高 PPR、添加不相关、替换相似三种扰动，未覆盖更广泛的组合变化（如多技能替换、顺序调整等），可能不足以刻画完整效用空间。
- **选择性反馈偏置**：跳过时无法获得标签，导致训练信号缺失；实验显示 ε=0 时

选择性反馈偏置：跳过时无法获得标签，导致训练信号缺失；实验显示 ε=0 时 AUROC 仅为 0.557，而 ε=1（完全探索）时为 0.745，说明缺失标签对模型学习有实质损害。实际部署中若门控拒绝执行，就无法获得真实奖励，形成自我强化的选择偏差；论文虽提出 ε-greedy 探索作为缓解，但未给出自适应探索率或置信区间下的主动学习策略。
- **特征消融缺乏显著性**：作者对查询嵌入、包嵌入、包条件特征、PPR 统计等进行了消融，但差异均不显著，无法确定各特征组的真实贡献；这可能是因为特征间信息冗余或样本量过小，结论的稳健性有待验证。
- **跨基准泛化有限**：虽然验证了 RADEG 在 τ-Bench、AgentDojo、ToolSandbox 上的有效性，但这些基准的工具包构造规则与 SkillsBench 差异较大，且测试规模较小；论文未报告在真实在线 Agent 流量上的长期表现，因此泛化结论仍需谨慎。
- **未与基于 LLM 的预测器对比**：RADEG 使用轻量级编码器，成本低；但论文未将之与“让 LLM 直接判断是否执行”或以 LLM 打分的门控方案进行对比，难以评估牺牲一定成本换取更强语义理解是否值得。
- **未讨论门控失败的成本不对称性**：若门控错误跳过了一个高价值执行，机会成本可能远大于一次不必要的执行；论文主要用“保留奖励比例”衡量，但未显式建模误拒的惩罚权重，可能低估高价值任务被过滤的风险。

## 九、对后续研究的启示与展望

- **从“检索最优”到“执行最优”**：本文强有力地证明了“相关性”不能替代“效用”，为检索式 LLM Agent 系统提供了一个新的优化目标——直接优化执行后的验证器奖励，而非排序指标。后续研究可将执行效用预测整合进检索打分，形成端到端的学习闭环。
- **以低成本预测器作为“预筛选器”**：RADEG 展示了在昂贵执行前用数十微秒的轻量模型过滤低价值请求的可行性。这种“粗筛 + 精执行”的分层决策模式可推广到更广泛的 Agent 编排、工具调用、多步规划等场景。
- **在线适应的价值与挑战**：冻结表示、仅更新分类头的持续学习方法在非平稳反馈下表现良好，但选择性反馈造成标签缺失是核心障碍。未来可探索主动查询策略、伪标签生成或利用未标记数据做半监督学习，以缓解偏差。
- **数据构造策略的扩展**：局部扰动构造训练数据的方法有效且可解释，但扰动类型单一。未来可基于技能依赖图、知识图谱或 LLM 生成更自然的“语义等价但执行效用不同”的变体，扩大监督信号的多样性。
- **需要更大规模、更多样化的基准**：288 条 rollout 尽管分析详尽，仍显单薄。社区需要构建包含更多任务、技能库与多智能体执行日志的公开数据集，以支撑更可靠的效用预测研究和标准化评测。

## 十、总体评价

本文从一个被忽视却极具实践价值的视角切入，指出了技能型 LLM Agent 中“相关性 ≠ 效用”的核心矛盾，并给出了一个轻量、灵活、可在线更新的解决方案 RADEG。论文的实验设计严谨，统计检验规范，运维视角务实，结果清晰地展示了执行门控带来的成本和收益改善。尽管受限于数据规模与扰动范围，结论的普适性有待进一步验证，但其思想——在检索与执行之间设置一个代价极小的效用预测器——为 LLM Agent 系统的高效部署提供了新范式，也为后续研究打开了重要方向。

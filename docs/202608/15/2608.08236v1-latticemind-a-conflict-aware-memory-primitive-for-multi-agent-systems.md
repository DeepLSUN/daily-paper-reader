## 摘要
多智能体LLM系统常常失败，并非因为缺乏候选答案，而是因为它们没有一种持久机制来决定当前应信任哪个不兼容的主张。多数投票、辩论和基于评判者的选择会选出一个输出，但不会记录哪个主张获胜、哪个存在争议，或者为何后来的更新取代了它。我们提出\term{LatticeMind}，一种在写入时处理矛盾的冲突感知结构化内存。它维护显式的项目状态，应用廉价的符号冲突检查，并仅对未解决的语义情况调用LLM调和。在去除来源名称提示的标签盲ConflictBank评估中，LatticeMind达到了0.97的准确率，而最强的聚合基线为0.61，通过配对McNemar检验，差异显著（$p<10^{-6}$）。消融实验表明，移除检查器或调和器会导致12至14个百分点的损失。在四个次要规划基准上，结果好坏参半：LatticeMind在四个中的三个上优于朴素合并，但在奖励迭代搜索的任务上并未取代深思熟虑方法。

## Abstract
Multi-agent LLM systems often fail not for lack of candidate answers, but because they have no persistent mechanism for deciding which incompatible claim should currently be trusted. Majority vote, debate, and judge-based selection choose an output without recording which claim wins, which is contested, or why a later update supersedes it. We present \term{LatticeMind}, a conflict-aware structured memory that handles contradiction at write time. It maintains explicit item status, applies cheap symbolic conflict checks, and invokes LLM reconciliation only for unresolved semantic cases. On a label-blind ConflictBank evaluation that removes source-name hints, LatticeMind reaches 0.97 accuracy versus 0.61 for the strongest aggregation baseline, with the gap significant at $p<10^{-6}$ by paired McNemar test. Ablations show that removing the checker or the reconciler costs 12 to 14 points. On four secondary planning benchmarks the picture is mixed: LatticeMind beats naive merge on three of four, but does not replace deliberation methods on tasks rewarding iterative search.

### 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：多智能体LLM系统失败的根本原因往往不是缺少候选答案，而是缺乏一种**持久化机制**来决定当前应信任哪个互不兼容的事实声明。当不同Agent读到相互矛盾的信息（如新旧政策、不同来源的报告）时，系统需要一种方式记录“哪个声明胜出、哪个存在争议、以及为什么后续更新会取代它”。
- **现有方法的缺陷**：多数投票、多智能体辩论、评委式选择等方法在生成答案后就结束了，不留下任何“决策审计轨迹”。下一次遇到类似问题，同样的冲突需要从头重新争论一遍。现有Agent记忆架构（如MemGPT、Generative Agents等）虽覆盖了检索、压缩、反思，但**没有把矛盾处理作为一等的记忆更新操作**。
- **作者的核心主张**：矛盾处理应被视为一个**结构化记忆更新问题**而非**答案聚合问题**。这类似于分布式系统中的CRDT（Conflict-free Replicated Data Types），通过代数合并规则维护一致性视图。

### 2. 方法论

#### 核心思想
LatticeMind是一个冲突感知的结构化记忆系统，在**写入时处理矛盾**。它将记忆视为有状态、有结构、可审计的数据，而非无边界的文本流。系统结合了三种互补机制：**廉价符号检查**捕获确定性冲突，**选择性LLM调和**处理语义冲突，**显式状态转换**管理生命周期。

#### 关键技术细节

**1. 结构化写入（Structured Writes）**

- Agent产生的发现（如FACT、CONSTRAINT、SUB_PLAN）以显式记忆条目写入，而非直接压平成最终答案。
- 每个记忆项定义为：m = (k, c, ρ, τ, η)，其中：
  - k：键/路由句柄
  - c：内容
  - ρ：证据元数据
  - τ：时间戳
  - η：状态，取值于 {**PROPOSED**, **CONFIRMED**, **CONTESTED**, **SUPERSEDED**}
- 软件状态声明用规范化形式：z = (u, σ, v, β, ε, ρ, τ)，表示实体u的槽σ在分支β、环境ε下的值为v；规范键为 k(z) = (u, σ, β, ε)。

**2. 冲突感知的更新规则（三类）**

| 冲突类型 | 触发条件 | 处理策略 |
|---------|---------|---------|
| **可信度冲突**（Credibility） | 多个不兼容声明描述同一事实 | 证据加权取代；胜者CONFIRMED，败者保留为CONTESTED/SUPERSEDED |
| **协调冲突**（Coordination） | 多个局部有效方案碰撞于共享资源 | 保守安全覆盖：双方都保留可见，触发重新规划 |
| **证据积累**（Accumulation） | 相同键和规范化值重复出现 | 合并来源、时间戳和证据，不产生重复条目 |

**3. 证据评分公式**

软件状态场景的得分函数为：**s(z) = w(evidence-type) + 40·1[git_commit ≠ ∅]**

其中证据类型权重递增排序为：stale-observation(4) < human-note(12) < branch-experiment(25) < runtime-observation(40) < config-observation(45) < code-change/incident-hotfix(60)。Git提交加分（+40）使代码支撑的事实压倒人类笔记或过期观察，从而无需LLM即可处理大部分权威覆盖场景。仅在证据强度相同、新旧度也相同时，才采用LLM裁决。

**4. 算法流程（LatticeMind 更新循环）**
```
1. 从更新流 St 中提取结构化条目 Et
2. 对每个条目 e ∈ Et：
   - 如果是Agent发现 → 以显式状态和证据追加到记忆
   - 如果是软件状态声明 → 按规范键路由，用证据评分比较当前值，胜者成为当前状态，败者标记contested
3. 运行符号检查（依赖环检测、资源时间窗冲突检测）
4. 若有违规 → 分类为可信度或协调冲突，仅对未解决的语义情况调用LLM调和
5. 渲染记忆为：当前状态 + 有争议条目 + 转换日志 三个视图
```

**5. 学习型算子（Learned Operators）**：训练QLoRA适配器用于三个算子操作——extract-state（提取状态声明）、compare-claims（比较声明）、update-memory（更新记忆），用于研究更新规则的可迁移性。

### 6. 主要结论与发现

- **主基准上的显著优势**：在标签盲协议下，LatticeMind准确率达**0.97**，远超所有基线的0.32-0.63；与每个基线的差异p<10⁻⁶，冲突对高度不对称（如No-Merge在49个例上错误而LatticeMind正确，反方向0例）。

- **规划任务边界明确**：LatticeMind在三个任务上优于No-Merge（Calendar +13、PlanBench +13、REALM JSSP +10），但在TravelPlanner上下降7点（单Agent本身已达0.97，多Agent引入方差）。对奖励迭代搜索的任务（如Calendar上的Debate/Judge达到0.87），LatticeMind的**单次调和**不能取代逐步精化方法。
- **软件状态应用**：预算长噪声上StateMemory达0.83，优于最强基线LLM-Merge-Inc的0.70；优势集中在**溯源查询**（0.81 vs 0.61）和**时序推理**（0.77 vs 0.38）。但真实代码库桥接v2上LLM-Merge（0.61）反超StateMemory（0.51），说明槽位模式可能遗漏了强摘要模型能较好压缩的稀疏提交级证据。
- **学习算子研究**：compare-claims和update-memory在所有保留折叠上达到1.00，证明**冲突抽象和更新规则可转移**；但extract-state平均仅0.30，是主要瓶颈。两阶段提取（先选实体-槽位对，再生成值）可将整体从0.81提升至0.86，提取从0.30提升至0.48。

### 7. 优点

- **问题定位精准**：将矛盾处理从“答案选择”问题重新框定为“记忆更新”问题，填补了现有Agent记忆架构中显式冲突状态管理的空缺。
- **分层冲突处理设计优雅**：用廉价符号检查处理机械冲突，用LLM仅处理无法由规则决定的语义冲突，实现成本与效果的平衡。
- **状态机制完备**：显式状态机（PROPOSED→CONFIRMED/CONTESTED→SUPERSEDED）保证决策可审计、可追溯，不会静默丢失反对意见。
- **实验透明度高**：标签盲协议消除了关键混淆变量；采用per-sample记录和可重计算统计量（无隐藏随机状态）；对完整配置的重复运行提供了抽样方差界。
- **诚实的边界报告**：作者没有美化结果——明确报告了TravelPlanner上的回归、真实仓库桥接上的略低于摘要基线、以及规划任务上不如辩论/评委方法的情况。
- **证据评分设计巧妙**：Git提交加分机制让多数权威覆盖场景无需LLM即可自动判决，减少了对模型的依赖和推理开销。

### 8. 不足与局限

- **样本量有限**：主基准75例、消融50例、辅助规划任务10-15例，统计功效受限。虽然作者使用了严格的配对检验，但更大的评估集将增强结论的泛化性。

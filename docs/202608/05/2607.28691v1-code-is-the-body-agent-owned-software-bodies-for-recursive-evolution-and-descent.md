## 摘要
个性化AI智能体往往可配置，但用户无法控制决定其未来行为的工件。我们提出OurArk，一种以智能体自有软件体为核心的持久化个人智能体架构：该软件体是一个具有身份标识、可检查、可版本化的工件，由人类保管。软件体包含行为定义代码、提示词、工具、技能、策略、测试和演化机制。记忆和凭证保持为私有实例状态，而模型推理被视为可替换的外部服务。OurArk定义了在同一个软件体上的受管自演化和递归后代生成。自演化产生隔离的候选变更，这些变更在人类控制下经过验证、审查和合并，从而实现人与智能体对智能体软件体的共同开发。后代生成创建一个独立版本化的后代，具有独特的身份、使命、历史和全新的私有状态边界；兼容的后代自身可以进一步产生后代。在分支之后，可以直接检查父代变更和同级技能，以进行有选择性的本地适配。我们在开源Genesis创建引擎和Enoch参考智能体中实现了该架构。一个四智能体、三次后代生成的线性谱系以及可执行的回归测试，展示了递归创建、继承的验证契约、隔离的软件体变更、人类控制的审查以及失败更新恢复。OurArk为个人智能体提供了一个具体的底层基础，使人们能够拥有、治理、专门化并随时间演化这些智能体。

## Abstract
Personalized AI agents are often configurable without giving users control over the artifacts that determine their future behavior. We present OurArk, an architecture for persistent personal agents centered on an agent-owned software body: an identity-bearing, inspectable, and versioned artifact under human custody. The body contains behavior-defining code, prompts, tools, skills, policies, tests, and evolution mechanisms. Memories and credentials remain private instance state, while model inference is treated as a replaceable external service. OurArk defines governed self-evolution and recursive descent over the same body. Self-evolution produces isolated candidate changes that are validated, reviewed, and merged under human control, enabling human-agent co-development of the agent's software body. Descent creates an independently versioned descendant with a distinct identity, mission, history, and fresh private-state boundary; compatible descendants can themselves source further descent. After divergence, direct-parent changes and peer skills can be inspected for selective local adaptation. We implement the architecture in the open-source Genesis creation engine and Enoch reference agent. A four-agent, three-descent linear lineage and executable regression tests demonstrate recursive creation, inherited validation contracts, isolated body changes, human-controlled review, and failed-update recovery. OurArk provides a concrete substrate for personal agents that people can possess, govern, specialize, and evolve over time.

## 论文总结

### 1. 论文的核心问题与整体含义

- **研究动机**：当前个性化 AI 智能体虽然提供了配置能力，但用户往往无法真正掌控决定智能体未来行为的工件（artifact）。平台方可以随意更改和重组智能体的组件，用户虽然能够“使用”智能体，却无法“拥有”决定其如何演化的核心资产。
- **核心问题**：如何在技术层面实现“用户可以真正拥有一款个人智能体”——即能够对决定其行为的代码、策略、测试等工件拥有保管权、检查权、修改权和最终治理权，而不是仅仅停留在记忆层面的个性化。
- **整体含义**：论文提出“代码即身体”（Code Is the Body）的核心理念，主张持久化个人智能体的延续性单元应是**身份可识别、可检查、可版本化的自有软件体**（agent-owned software body），而非模型权重、对话记忆或平台配置。该软件体在人类保管下，可被智能体与用户共同演化，并能产生独立的“后代”智能体，形成可追溯、可递归的谱系。
- **三大系统贡献**：
  1. 定义了智能体自有软件体的边界：可继承演化的身体、私有的不可继承实例状态、外部可替换推理器、人类治理权；
  2. 提出在同一软件体上执行“受管自演化”和“递归后代生成”的架构；
  3. 实现分支后的独立专业化与选择性能力迁移（继承 vs. 同级学习）。

### 2. 论文提出的方法论

- **核心架构定义**：一个 OurArk 智能体实例被定义为三元组 `A = (B, S, R)`，由人类保管者 `H` 治理：
  - **身体 B（Body）**：身份承载的、带版本的可演化工件集合，包含代码、提示词、工具、技能、策略、测试以及演化机制本身；
  - **私有状态 S（Private State）**：与单个运行实例绑定的凭证、记忆、日志、队列等，不可继承；
  - **外部推理器 R（External Reasoner）**：提供模型推理能力，但可随时替换，不承载持久身份。
- **三种核心操作**：
  1. **演化（evolve）**：`evolve(B, c) → B'`——在上下文或压力 `c` 下产生候选变更，经过验证和人类批准后才成为权威身体；
  2. **后代生成（descent）**：`descend(B, m) → (B_d, S_d)`——从源身体创建具有独立身份、新使命 `m` 和全新私有状态边界 `S_d` 的后代身体，后代可继续作为下一代之源；
  3. **迁移（transfer）**：`transfer(B_p, B_d, Δ) → B'_d`——后代在分叉后，可选择性地从直系父代或同级智能体拉取变更 `Δ` 并进行本地适配。
- **Genesis 创建引擎的流程**（生成后代时）：
  1. 验证源仓库洁净，记录完整提交 ID，解析其声明的清单和固定依赖；
  2. 复制身份相关身体工件，转换包路径和身份标识文本，保留不可变依赖引用；
  3. 写入新身份、使命、代数及不可变的直系父代来源记录；
  4. 初始化并暂存独立的新仓库；
  5. 解析依赖并运行**继承的回归测试**，验证失败则拒绝出生；
  6. 验证通过后创建出生提交，并以元数据提交记录其完整 ID。
- **受管自演化流程**：六个演化来源（用户请求、人类反馈、联合工作经验、直系父代继承、跨智能体学习、LLM 头脑风暴）→ 生成候选变更 → 在隔离工作树中实现 → 运行验证 → 发布可审查的工作 → 仅由人类决定是否合并 → 失败或拒绝则权威身体不变。实现中利用 Git 分支、commit、GitHub PR 和 worktree 落实。
- **三种能力迁移方式区分**：
  - **后代生成（Descent）**：一次性复制全套身体，创建独立的新智能体，是“出生”关系；
  - **继承（Inheritance）**：分叉后后代主动、选择性拉取父代后续变更，需经过自身测试和审查，非自动同步；
  - **学习（Learning）**：从任意可信智能体导入技能，不限于父代边，属于横向适配而非血统延伸。

### 3. 实验设计

  - 第 0 代 Lucy：具备作为自有智能体身体存在的能力（身份、使命、基础运行时、记忆边界、教学、测试）；
  - 第 1 代 Adam：增加操作与继承能力（操作接口、实例、谱系、直系父代继承、同级学习）；
  - 第 2 代 Seth：增加工作能力（任务执行、积压队列、定时任务、状态报告）；
  - 第 3 代 Enoch：增加在治理下自演化的能力（多路径演化输入、溯源记录、隔离工作树、验证、审查交接、失败回滚）。

### 6. 论文的主要结论与发现

- **软件体是持久个人智能体的合适延续单元**：在身份载体、可演进性、人类治理性上，软件体优于单纯记忆或模型权重。
- **递归后代生成是可行且可验证的**：Genesis 可以以任意兼容身体为源递归创建下一代独立智能体，且后代强制继承验证契约；线性三代谱系（Lucy→Adam→Seth→Enoch）成功实现。
- **受管自演化得以实现**：Enoch 可以在人类治理下，从六个来源引发身体变更，在隔离环境中实现和验证，经人类审批后合并；失败更新可自动回滚到前一版本。
- **身份与状态分离**：模型推理替换不会重新定义血统，私有状态边界在派生时被重置，解决了继承中的隐私隔离问题。
- **分叉后的选择性迁移优于强制同步**：后代保留独立历史，以“拉取+适配”的方式吸收父代或同级的能力，而非持续跟随一个共享基座。
- **“遗传”不等同于面向对象继承**：后代通过一次出生获得完整身体，之后独立演化，可选择适配父代变更，这与 OOP 的实时类关系语义有本质区别。

### 7. 优点

- **清晰的概念边界**：在身体（可继承）、私有状态（不继承）和外部推理器（可替换）之间的划分务实且具有可操作性。
- **递归兼容而非中心化模板**：后代生成基于“任意兼容的身体”而非单一根模板，这为生态化多样化分发提供了基础。
- **人类主导的治理模型**：通过受保护分支 + 审查 + 人工合并机制确保最终权威始终在人类手中，有利于现实部署中的信任建立。
- **可复现性强**：所有实验均可通过公开的不可变提交和复现命令重新执行。
- **与既有系统的区分度明确**：论文用对比表清晰区分了与 MOSS、Autogenesis、EvoGit、Agent libOS 等系统的本质不同，定位明确。
- **开源实现**：Genesis 和 Enoch 均以 Apache-2.0 协议开源，便于社区验证和扩展。

### 8. 不足与局限

- **实验覆盖有限**：只有一个团队构建的一条线性谱系，无分支、无群体规模评估；测试主要验证机制可行，未评估长期运行可靠性、提案质量、专业化效果、审查负担或语义安全性。
- **文本替换机制粗糙**：Genesis 使用边界感知的字符串替换而非语言特定解析器来重写身份相关文本，无法保证每个转换后文件的语义正确性，仅靠清单检查和继承测试兜底。
- **安全边界不足**：具有写权限的执行器拥有比生产级变异沙箱更广泛的文件系统权限；任务、演化和血统记录不具备防篡改能力；受保护范围的检查是流程性的，而非语义保证。
- **生态依赖局限**：谱系发现和跨智能体技能查找仍假设使用 forge 托管仓库和 OurArk 命名约定；对非 Git 基板没有充分验证。
- **后分叉迁移验证不完整**：新的后代虽暴露了不可变基线，测试也区分了直系继承与同级学习路径，但没有跑过受控的端到端适配实验。
- **行为连续性未测量**：替换推理器后行为能否保持一致没有实验数据支持。

### 总结一句话

OurArk 为个人智能体提供了一种“可拥有、可治理、可特化、可演进”的架构基底，用“软件体”取代“记忆”和“模型调用”作为代理的延续性单元，并通过递归后代生成实现智能体家族的繁衍与专业化；其价值主要在于系统设计层面的架构贡献，而非模型能力或基准性能的提升。

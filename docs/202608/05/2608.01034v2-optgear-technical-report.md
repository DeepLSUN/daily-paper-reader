## 摘要
我们介绍了 OptGear，一个为高效端侧部署、实时推理和强大任务能力而设计的基础模型。它包含一个稠密模型（1M、270M 和 1B），上下文长度为 64K。我们设计了一种新的混合架构，将卷积键值门控混合器与局部-全局注意力相结合，以减少随长上下文呈指数增长的 KV 缓存内存。该架构在 NPU 上相比同规模模型实现了高达 X4.9 倍的预填充和解码速度提升。从 2T 令牌的候选语料库中，OptGear 在精选的 0.5T 令牌子集上进行了训练，且无需知识蒸馏。这是现有基础模型中数据效率最高的。所有模型均开放权重，并提供 ONNX、Qualcomm NPU 和 Apple ANE 的部署二进制文件，使 OptGear 成为需要快速、内存高效推理和强大任务能力的边缘应用的实用基础。此外，为扩展端侧生成式语言模型的生态系统，我们推出了 OptGear-1M，可部署在微控制器单元（MCU）上，这是一种微型语言模型（TLM）。OptGear-1M 是首个在 STM32H747I-DISCO 的 ARM Cortex-M7 CPU 上通过 W4A32 量化达到 20 TPS 的生成式语言模型。

## Abstract
We introduce OptGear, a foundation model designed for efficient on-device deployment, real-tim inference, and strong task capability. It includes a dense model (1M, 270M, and 1B) with a context length of 64K. We designed a new hybrid architecture that combines a convolutional key-value gated mixer with local-global attention to reduce the KV-cache memory that tends to increase exponentially with long context. This architecture delivers up to X4.9 faster prefill and decoding speeds on the NPUs compared to models of a similar scale models. From a 2T tokens candidate corpus, OptGear is trained on a curated 0.5T tokens subset without knowledge distillation. This is the most data-efficient of the existing foundation models. All models are released with open weights and deployment binaries for ONNX, Qualcomm NPU, and Apple ANE making OptGear a practical base for edge applications that need fast, memory-efficient inference and strong task capabilities. Furthermore, to expand the ecosystem of on-device generative language models, we are introducing the OptGear-1M that can be deployed on Micro-Controller Units (MCUs), a Tiny Language Model (TLM). OptGear-1M is the first generative language model to achieve 20 TPS with W4A32 quantization on the ARM Cortex-M7 CPU of the STM32H747I-DISCO.

- **整体含义与目标**：本研究旨在解决端侧大模型"跑不动、跑不快、存不下"的核心矛盾，尤其是长上下文场景下的KV-cache膨胀问题。论文提出了一种**硬件感知的混合架构**（ConvKV-Gated Mixer + 局部-全局注意力），在保证推理效率的同时，兼顾下游任务质量和长上下文能力，为边缘AI应用提供一个实用的、开源的基础模型基座。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：通过一种"混合序列建模"架构，将昂贵的传统注意力层数量减至最少，并用计算更廉价、内存占用更小的新型算子替代大部分局部注意力层。
  - **全局路由**：保留少量全局GQA注意力层，负责长距离信息聚合与内容寻址。
  - **局部混合**：大部分短程上下文交互由新设计的 **ConvKV-Gated Mixer** 模块承担，该模块完全**无需计算注意力分数矩阵和Softmax**。
- **关键技术1：ConvKV-Gated Mixer（核心创新）**
  - 该模块对输入序列 X，先将其投影为 Query (q)、Key (k)、Value (v) 流。
  - 对 Key 和 Value 流应用 **因果深度可分离1D卷积** 进行局部混合，引入卷积核大小 L_conv 的固定感受野。
  - 使用**逐元素门控机制**（sigmoid）根据 q 与卷积后的 k 的交互来选择信息：g_t = σ(q_t ⊙ k̃_t)。
  - 最终输出为门控后的值与输出投影：o_t = (g_t ⊙ ṽ_t) W_o。
  - **优势**：该模块无需存储随序列长度增长的注意力Key/Value缓存，仅需一个**固定大小（L_conv）的卷积状态**，显著减少了长上下文解码时的内存占用和带宽压力。
- **关键技术2：内存高效的缓存机制**
  - 此设计将传统局部滑动窗口注意力的 `O(2*W*d_kv)` 缓存（W为窗口大小）替换为固定大小的卷积状态 `O(2*L_conv*d_kv)`，其中 L_conv 在模型中设置为3或4，远小于滑动窗口大小512。这使得推理时存活的序列状态不随上下文长度变化。
- **关键技术3：量化感知训练（QAT）**
  - 为减少低比特量化带来的精度损失，论文提出了一种**Hessian引导的QAT**方法：
    1.  **初始化**：不同于使用简单权重统计，利用校准数据将量化视为层输出重建问题，通过最小化量化前后输出的平方误差（公式1）来初始化INT4的缩放因子，从而感知权重扰动对输出的影响。
    2.  **联合优化**：采用LSQ方法，将缩放因子设为可学习参数，在训练中通过直通估计器反向传播更新，使模型和量化尺度共同适应目标任务（公式2）。
    3.  整个流程在初始化、训练和部署阶段均使用一致的对称INT4量化网格。

## 6. 论文的主要结论与发现

- **数据效率极高**：在仅使用**0.5T tokens**且不借助知识蒸馏的前提下，Opt.Gear-270M和Opt.Gear-1B在多数基准上取得了与使用更多数据（2T-36T）且依赖蒸馏的同类模型相当甚至更优的性能，验证了精确数据筛选和模型架构设计的有效性。
- **韩语能力突出**：作为韩英双语模型，Opt.Gear-1B在**所有韩语任务（KMMLU, KoBEST, CLIcK, HAERAE）上全面超越了Gemma3-1B, Llama3。2-1B和EXAONE 4.0-1.2B**。特别是在HAERAE上，比Gemma3-1B高出近9个百分点。这一优势在270M级别同样存在。
- **NPU推理性能显著提升**：在**高通AI Runtime环境下**，Opt.Gear-1B在GEN5上Prefill速度达7042 tokens/s（对比Llama3.2-1B为4481，Gemma3-1B为3226），官方推测与优化后的HTP VTCM访问有关。在**Apple CoreML环境下**，Opt.Gear-1B在iPhone 17 Pro上的NPU预填充速度（3085 TPS）也领先于其他模型。
- **量化鲁棒性强**：QAT模型在应用各种PTQ方法后性能下降极小，而Gemma3在同等条件下性能跌幅显著，证明了Opt.Gear的QAT流程非常稳健。
- **实现MCU生成**：Opt.Gear-1M证明了在**有限的Flash和SRAM条件下，LLM可以在MCU上实现可交互的生成速度（20 TPS）**，将其部署边界延伸至深度嵌入式设备。

## 7. 优点（方法或实验设计亮点）

- **硬件-算法协同设计的创新架构**：ConvKV-Gated Mixer的引入是架构上的一大亮点，它摆脱了对Softmax和注意力矩阵的依赖，将计算转换为静态线性、卷积和逐元素操作，这完美契合NPU和MCU的硬件特性，实现了极高的硬件利用率。
- **面向部署的量化流程**：**Hessian引导的QAT** 是一个严谨且新颖的工程实践。它通过校准数据来初始化量化尺度（而非简单的统计量），能感知数据分布，显著优于常规PTQ方法，并保证了从训练到部署的量化一致性。
- **数据效率的极致追求**：明确聚焦于"每token所获得的能力提升"，通过高质量筛选而非无限堆数据来训练，这为资源有限的研究者和企业提供了一个极有价值的训练范式（非蒸馏，少数据，高性能）。
- **全面而真实的性能验证**：推理性能测试没有停留在硬件模拟器上，而是跑在了**真实的Gen-4/5芯片、iPhone和Cortex-M7硬件**上，且报告了具体的编译与运行时（QAIRT, llama.cpp, CoreML），可信度极高。
- **选型范围的思考**：在270M和1B模型上刻意不训练代码数据，体现了对模型应用场景的清晰定位，避免了无谓的计算资源浪费。

## 8. 不足与局限

- **推理与复杂任务能力上限**：由于训练数据量（0.5T）和模型参数量的限制，Opt.Gear在复杂的数学推理和需要深层次逻辑分析的任务上，与同规模的Qwen3等模型仍有一定差距，论文中也承认了这一局限。
- **实验对比的公平性风险**：对比基线模型（如Qwen3-0.6B/1.7B）不仅训练数据量更大（36T），且训练方法可能不尽相同。虽然Opt.Gear在韩语和数据效率上胜出，但在严格的纯英文推理能力对比中并不占优，这需要辩证看待。
- **Opt.Gear-1M的通用性受限**：Opt.Gear-1M为了适应MCU的极端资源限制，其词汇表极小（2048），仅支持英文，并以特定的ST32板控任务为主要目标。这不仅限制了其作为通用语言模型的能力，其下游任务成功度也主要取决于`stm32_cmd_synth`合成数据集的质量。
- **推理后端兼容性问题**：在llama.cpp + NPU环境下，Opt.Gear-1B的解码速度出现了异常下降（Prefill 290 TPS）。这表明其性能优势高度依赖于特定的运行时和底层算子优化（如QAIRT对卷积算子的优化），在通用运行时上可能无法直接获得收益，影响了模型的生态普适性。

## 摘要
大型语言模型正越来越多地作为编码智能体嵌入软件工程工作流程中，这些智能体能够检查代码库、调用工具、执行测试、调试失败并生成补丁。然而，尽管软件开发是一个动态的、反馈丰富的过程，其中代码库不断演化、依赖关系发生变化、测试失败、修复尝试留下可复用的经验，大多数现有智能体在部署后仍基本保持静态。这种矛盾促使了越来越多关于自我演化编码智能体的研究，在这种智能体中，智能体通过从先前的编码交互中更新其框架、记忆、技能、工具、模型或协作结构来改进其未来行为。在本综述中，我们对这一新兴领域进行了系统性的综合。我们首先定义了自我演化编码智能体，并将其与传统编码智能体和通用自我演化智能体区分开来。然后，我们提出了一种以对象为中心的分类法，用以刻画这些系统中演化的对象，并辅以两个正交视角：演化何时发生，以及哪些软件特有的证据驱动了演化。通过对文献的梳理，我们发现可执行反馈、代码库级上下文和编码轨迹使软件工程作为智能体自我演化的自然领域具有独特作用，但也带来了反馈可靠性、基准过拟合、安全性、可维护性、成本和泛化方面的新挑战。通过围绕这些维度组织现有工作，本综述旨在厘清自我演化编码智能体的概念边界，并为设计更具适应性、可靠性和软件感知能力的智能体系统提供基础。我们收集的论文可在 https://github.com/zhouhao1024/Awesome-Self-Evolving-Coding-Agents 找到。

## Abstract
Large language models are increasingly embedded in software engineering workflows as coding agents that can inspect repositories, invoke tools, execute tests, debug failures, and generate patches. Yet most existing agents remain largely static after deployment, even though software development is a dynamic, feedback-rich process in which repositories evolve, dependencies change, tests fail, and repair attempts leave reusable experience. This tension has motivated a growing body of work on self-evolving coding agents, where the agent improves its future behavior by updating its framework, memory, skills, tools, models, or collaboration structures from prior coding interactions. In this survey, we provide a systematic synthesis of this emerging area. We first define self-evolving coding agents and distinguish them from conventional coding agents and general self-evolving agents. We then develop an object-centered taxonomy that characterizes what evolves in these systems, and complement it with two orthogonal perspectives: when evolution occurs and what software-specific evidence drives it. Across the literature, we find that executable feedback, repository-level context, and coding trajectories give software engineering a distinctive role as a natural domain for agent self-evolution, but also introduce new challenges in feedback reliability, benchmark overfitting, safety, maintainability, cost, and generalization. By organizing existing work around these dimensions, this survey aims to clarify the conceptual boundaries of self-evolving coding agents and provide a foundation for designing more adaptive, reliable, and software-aware agentic systems. The papers we collect can be found at https://github.com/zhouhao1024/Awesome-Self-Evolving-Coding-Agents.

### 2.1 概念界定

### 2.2 核心方法论：以对象为中心的分类法（Object-Centered Taxonomy）

论文提出将自我演化编码智能体按**演化对象**分为五大类：

**（1）智能体框架自演化（Agent Framework Self-Evolution）**
- 将编码智能体自身视为可修改的软件制品
- 两种主要形式：
  - **脚手架重写**：智能体直接编辑自身实现代码，重新运行并验证（如 SICA、SIFT、STOP）
  - **基于档案的框架演化**：维护多个可执行的智能体变体，通过搜索和选择自我修改（如 Darwin Gödel Machine、Mendel GM、Huxley GM）

**（2）记忆自演化（Memory Self-Evolution）**
- 持续构建、精炼和复用显式记忆组件，记录软件特定经验
- 三种形式：
  - **经验记忆**：从问题解决轨迹中构建经验库，含成功与失败尝试（如 SWE-Exp、EvoCoder、EvoRepair）
  - **仓库记忆**：从历史提交、关联问题和频繁修改区域的功能摘要构建记忆，支持代码定位（如 Repository Memory）
  - **计划抽象记忆**：将初始轨迹抽象为简明计划（如 SAGE、Subtask Memory）

**（3）技能与工具自演化（Skill and Tool Self-Evolution）**
- 将软件工程经验转化为可复用的操作能力
- 三种路径：
  - **轨迹蒸馏技能**：从编码智能体轨迹中提取任务级和事件驱动级技能（如 CODESKILL）
  - **仓库特定技能**：为特定仓库自动学习架构、约定、测试流程等技能文档（如 GSkill、Socratic-SWE）
  - **工具创建与精炼**：从最小脚手架出发，在线创建和修订自定义工具（如 Live-SWE-Agent）

**（4）模型自演化（Model Self-Evolution）**
- 改变编码智能体的模型侧组件：基础模型、适配器、策略、奖励模型或验证器
- 关键技术：
  - **自博弈策略演化**：通过多轮生成-修复-验证的闭环信号更新策略（如 Self-play SWE-RL、Agent-RLVR）
  - **编码器-验证器协同演化**：生成器与测试器/验证器交替进化，互相提供训练信号（如 ReVeal、CURE、ZeroCoder）
  - **对抗性测试演化**：通过对抗性单元测试生成和偏好优化提供选择压力（如 ACE）

**（5）工作流与拓扑自演化（Workflow and Topology Self-Evolution）**
- 改变智能体系统的组织方式：流程图和协作拓扑
- 两种方向：
  - **工作流图演化**：将提示词和工作流拓扑编码为可搜索图（如 SEW、AFlow、EvoAgentX）
  - **多智能体拓扑演化**：动态调整智能体角色和通信结构（如 SEMAG、EvoMAC、AgentConductor）

### 2.3 两个正交维度

**（1）演化时机（Evolving Time）**：
- **任务内演化**：单次编码任务中利用反馈即时调整当前行为（如 Live-SWE-Agent、SEMAG）
- **任务后演化**：任务结束后将完整轨迹转化为记忆、技能或仓库知识（如 SWE-Exp、CODESKILL）
- **阶段式演化**：累积大量交互后对智能体进行较持久的更新，接近跨代自改进（如 Self-play SWE-RL、Agent-RLVR）

**（2）演化证据（Evolving Evidence）**：
- **结果证据**：基准通过率、测试通过率、验证器分数等粗粒度选择信号
- **环境反馈**：编译诊断、测试日志、运行时异常、工具输出等局部反馈
- **轨迹衍生证据**：从完整轨迹中提取的可复用策略、错误模式和修复模式

## 6. 论文的主要结论与发现

1. **自演化编码智能体是一个新兴但概念边界模糊的领域**，不应将其理解为单一技术，而是一个以可执行软件制品为根基的适应过程家族。

2. **软件工程是自演化智能体的天然实验场**：可执行反馈（单元测试、编译诊断、运行时跟踪）、仓库级上下文和编码轨迹为演化提供了独特而具体的监督信号。

3. **五类演化对象具有不同的风险和收益特征**：
   - 框架演化最激进但风险最高（可能破坏代理循环、过拟合基准）
   - 记忆演化强调选择性（噪声日志、误导性测试可能造成有害记忆）
   - 技能/工具演化强调可操作性且需平衡泛化与具体性
   - 模型演化强大但脆弱（需可学习的信息增益，否则可能强化偏见）
   - 工作流/拓扑演化改变全局行为但可能增加协调开销

4. **演化反馈具有双重性**：测试、编译器、CI 日志和奖励模型本身不完美，可能继承偏见和盲区；当这些信号用于塑造未来行为而非仅评判当前输出时，风险显著放大。

5. **当前评估体系偏重短期任务成功**（通过率/解决率），对可维护性、安全性和长期可靠性关注不足。

6. **核心挑战是可信演化**：需要验证反馈、修正过时记忆、审计学习技能、约束自我修改，并评估超越短期基准的长期软件质量。

## 摘要
智能体软件工程和工业系统越来越通过可执行工作流而非仅代码生成来运行：它们搜索工件、调用工具、检查结构化观察结果并查询数据库。训练这些智能体需要能够捕获有效工具交互和可执行工作流的监督数据。然而，传统的查询优先数据合成可能会失败，因为看似合理的用户请求可能不对应于有效的工具序列、兼容的参数或可用的数据。为了解决这一局限性，我们提出了SyntheticAgentTraceQA，一个执行优先的框架，用于为工具增强型智能体生成可扩展的监督数据。我们的框架首先构建高层工作流结构，通过依赖感知分配将其映射到可用工具，在受控环境中执行并验证生成的轨迹，然后才合成自然语言用户任务、教师生成的推理注解和参考答案。我们在四个工具生态系统中评估该框架，并使用生成的数据对Qwen模型变体进行微调和评估。结果表明，执行基础的监督改善了工具执行行为、参考轨迹一致性以及评估任务上的答案生成性能。进一步的分析揭示了监督权衡：掩码监督（从训练目标中排除推理注解）改善了最终答案指标，而完全监督（在包括推理标记的完整助手输出上计算损失）在答案质量上表现不佳，并且未能一致地改善参考轨迹一致性，尤其是在9B规模下。这些发现强调了根据工具增强型智能体所需能力设计合成监督的重要性。

## Abstract
Agentic software-engineering and industrial systems increasingly operate through executable workflows rather than code genera- tion alone: they search artifacts, invoke tools, inspect structured observations, and query databases. Training these agents requires supervision data that captures valid tool interactions and executable workflows. However, traditional query-first data synthesis can fail because plausible user requests may not correspond to valid tool sequences, compatible parameters, or available data. To address this limitation, we propose SyntheticAgentTraceQA, an execution- first framework for generating scalable supervision data for tool- augmented agents. Our framework first constructs high-level work- flow structures, maps them to available tools through dependency- aware assignment, executes and validates the resulting traces in con- trolled environments, and only then synthesizes natural-language user tasks, teacher-generated reasoning annotations, and reference answers. We evaluate the framework across four tool ecosystems and use the resulting data to fine-tune and evaluate Qwen model variants. The results show that execution-grounded supervision improves tool execution behavior, reference-trace agreement, and answer-generation performance on the evaluated tasks. Further analysis reveals a supervision trade-off: masked supervision, which excludes reasoning annotations from the training objective, im- proves final-answer metrics, whereas full supervision, computing loss over the complete assistant output including reasoning tokens, underperforms on answer quality and does not consistently im- prove reference-trace agreement, particularly at the 9B scale. These findings highlight the importance of designing synthetic supervi- sion according to the desired capabilities of tool-augmented agents.

- **研究动机**：智能体软件工程和工业系统越来越多地通过可执行工作流运行（搜索工件、调用工具、查询数据库等），训练这类工具增强型智能体需要能够捕获有效工具交互和可执行工作流的监督数据。

- **核心问题**：如何系统性地生成与工具环境兼容、可执行、可验证的训练数据，以提升智能体的工具使用能力？
- **整体含义**：论文提出**执行优先（execution-first）**范式：先构建并验证可执行工具轨迹，再反向合成自然语言用户任务和参考答案，从根本上避免无效样本，并证明这种数据能显著改善智能体的工具行为、参考轨迹一致性和答案生成质量。

## 2. 方法论：SyntheticAgentTraceQA

- **核心思想**：反向链式生成——不是“任务→轨迹”，而是“轨迹→任务”。先保证轨迹可执行，再为其生成对应的用户请求。
- **形式化定义**：
  - 工具集合 \( T = \{T_1, ..., T_n\} \)，每个工具将输入参数 \(x_i\) 映射到输出 \(y_i\)。
  - 执行轨迹 \( \tau = [(T_1, x_1, y_1), ..., (T_m, x_m, y_m)] \)。
  - 目标：生成高质量三元组 \((z, \tau, r)\)，其中 \(z\) 是自然语言任务，\(\tau\) 可执行，\(r\) 由 \(\tau\) 的观测输出支持。
- **五个阶段流程**：
  1. **Profiler（配置器）**：使用 Claude Sonnet 4.6 自动提取工具元数据，将工具划分为六种操作类（Operational Classes）：
     - Matcher、Retriever、Analyzer、Aggregator、Metadata、Access。
     - 输入参数按角色分类：Control（控制）、Data-flow（数据流）、Temporal（时间）、Configuration（配置）。
     - 构建“活跃域”（Active Domain），采样可行值并生成兼容性元数据。
  2. **Template Generator（抽象模板生成）**：用 LLM 生成有向无环图（DAG）形式的抽象执行模板，节点是操作块（包含操作类、工具池、依赖、描述），边表示数据流依赖。复杂度分三档：Easy（1–2块）、Medium（3–4块）、Hard（5–6块）。
  3. **DFS 模板实例化**：将抽象操作块替换为具体工具，通过深度优先搜索遍历工具组合，执行兼容性检查（上游输出需覆盖下游 \(P_{flow}\) 需求），并维护可见状态 \(V_{visible}\) 进行剪枝回溯。
  4. **Trace Execution（轨迹执行）**：维护上下文 \(C = (C_{in}, C_{out}, W)\)，按拓扑顺序绑定参数并实际调用工具，执行成功才保留候选轨迹；可重采样非确定性参数，失败则丢弃。
  5. **Validation & Task Synthesis（验证与任务合成）**：
     - 先验证已执行轨迹的结构一致性、参数传播、模式符合性和语义连贯性，无用户问题存在。
     - 对验证通过的轨迹，由 LLM 生成三种难度级别（Basic、Intermediate、Challenging）的用户任务、教师推理标注和参考答案，同一个轨迹对应三种不同表达的自然语言任务。

- **推理初始化有益**（H2 支持）：启用 Thinking 模式显著改善所有指标，说明显式推理为执行基础推理提供更强基础。

## 8. 不足与局限性

- **执行环境的理想化假设**：所有工具均假设为确定性、纯函数式的接口（给定参数即返回稳定输出），未考虑真实世界中常见的副作用（如写数据库、发邮件）、非确定性输出（如推荐排序）、流式响应或需要多轮人机交互的工具；对这类工具的"可执行性"定义和验证机制尚不成立。
- **任务多样性受限**：任务由轨迹反向生成，天然偏向"有明确可执行答案"的任务形态，可能系统性遗漏用户真实请求中的模糊性、开放性（如"帮我看看最近有什么值得关注的"）和隐含约束；同一轨迹生成三种任务表达的多样性增益有限，容易陷入表面改写。
- **评估规模偏小**：测试集仅 n=200 条轨迹，微调集仅 1,000 样本，模型仅 Qwen 4B/9B 两个规模且只用了 LoRA 微调；结论的统计稳健性和对更大模型、全参数微调的推广性未经验证。
- **对比实验并非严格公平**：与 Toucan 的对比是"各自在自己的基准上评测"，未做统一的跨管道交叉验证（同一 benchmark、同一测试集），论文也明确提醒解释需谨慎；LLM-as-a-Judge 的评分可能受生成文本风格影响。
- **推理监督的合成性矛盾**：尽管 Masked 监督被证明更好，但论文并未解释合成 `<think>` 块是否真正反映了工具调用的因果逻辑；若推理块与实际行动不一致，模型可能学到"虚假推理"的坏习惯。
- **对强 LLM 生成器的依赖**：数据生成管道大量依赖 Claude、GPT、Gemini 等商业闭源模型，虽然成本低于直接生成，但存在供应商锁定、不可复现性和潜在的数据污染风险；整条管道未开源（论文未提及），可复现性存疑。
- **未涉及安全性**：对工具调用失败（沙箱容错）虽有处理，但未评估模型在恶意提示、越权工具调用或隐私敏感数据上的行为，也未评估幻觉之外的更深层安全问题。

## 9. 综合评估与启示

- **核心贡献是范式切换**：论文最有价值的不是某条具体结果，而是把"可执行性"从数据合成的事后过滤器提升为第一优先级的约束——先跑通、再问问题。这与程序合成（synthesis-by-execution）、逆向课程学习的思想一脉相承，对智能体训练数据生产有直接工程价值。
- **抽象设计可复用**：操作类（Matcher/Retriever/Analyzer 等）与参数角色（Control/Data-flow/Temporal/Configuration）的划分，实际上为异构工具环境提供了一套轻量的"中间表示"，使合成管道可以低成本迁移到新领域；这一点值得后续研究借鉴。
- **对实操训练者的启示**：Masked vs Full 监督的对比结果提示，微调工具智能体时应谨慎对待合成推理链——如果推理过程并非模型自身真实产生，就不应将其纳入损失计算；能力目标不同（答案质量 vs 执行行为 vs 结构一致性）时，监督策略和数据规模的选择需要分开权衡。
- **范式适用边界清晰但可扩展**：该范式最适用的场景是"工具语义可枚举、执行结果可验证"的企业级工作流（金融分析、供应链、研发管理）；未来若能扩展到包含副作用的工具、开放式 API 和真实用户查询的混合数据，其价值会进一步放大。
- **总体判断**：这是一篇工程贡献突出、实验设计细致、结论对实践有直接指导意义的工作；但在评估规模、对比公平性和真实世界泛化性上仍有明显短板。其提出的执行优先合成方向，大概率会成为后续智能体数据合成研究的一个重要流派。

## 摘要
基于大语言模型（LLM）构建的多智能体系统（MAS）正在迅速普及，但其异构的执行轨迹无法为跨方法的评估提供通用基础。仅关注结果的基准会丢弃协作信息，而基于大语言模型裁判（LLM-as-Judge）的评估则需要额外的、依赖模型的推断，并可能随大语言模型和评分标准而变化。我们提出了一种可泛化的评估框架，将原生MAS轨迹映射到统一的协作图共享空间中，使得不同方法能够在相同的表示、参考集和指标面板下进行评估。候选图与查询特定的参考森林进行比较。每个森林是基准提供的一组已验证成功图的集合：它记录了代表性MAS方法完成任务的各种方式，而不是规定唯一的最优过程。我们将该框架实例化为ForestBench，从七个公共数据集中筛选出844个需要协作的查询，为每个查询预计算十个成功的目标条件参考图，并评估六个代表性MAS框架。通过受控的主干、参考构建和扰动研究来测试评估的稳定性和范围。一旦基准森林构建完成，ForestBench即可在毫秒内对轨迹进行评分，无需进一步的大语言模型推理，为比较多样化的MAS协作轨迹提供了可复用的结构化基础。

## Abstract
Multi-agent systems (MAS) built on Large Language Models (LLMs) are proliferating rapidly, but their heterogeneous execution traces provide no common basis for evaluation across methods. Outcome-only benchmarks discard collaborations, whereas LLM-as-Judge evaluation requires additional, model-dependent inference and can vary with the LLM and rubric. We introduce a generalizable evaluation framework that maps native MAS traces into a shared space of unified collaboration graphs, enabling different methods to be evaluated under the same representation, reference set, and metric panel. Candidate graphs are compared with a query-specific reference forest. Each forest is a benchmark-provided collection of verified-success graphs: it records diverse ways in which representative MAS methods can complete the task, rather than prescribing a unique optimal process. Instantiating the framework as ForestBench, we filter $844$ collaboration-necessary queries from seven public datasets, precompute ten successful target-conditioned reference graphs per query, and evaluate six representative MAS frameworks. Controlled backbone, reference-construction, and perturbation studies test the stability and scope of evaluation. Once the benchmark forests are built, ForestBench scores a trace in milliseconds without further LLM inference, providing a reusable structural basis for comparing diverse MAS collaboration traces.

- 大量 MAS 框架不断涌现，包括固定流水线、动态角色分配、自组织群体等，但**框架的迭代速度远超评估方法的发展**。

**核心问题**
- 现有的 MAS 评估存在三种主要缺陷：
  - **结果型基准**（如 GSM8K、MMLU、HumanEval）只关注最终答案正确性，**完全丢弃了协作过程**，而协作恰恰是 MAS 区别于单智能体的核心价值。
  - **LLM-as-Judge 评估**虽然能读取轨迹，但需要额外模型推理、依赖评分标准和模型选择，**成本高且可复现性差**。
  - 不同 MAS 框架的原生日志具有**异构性**，事件模式、角色词汇、通信协议各不相同，缺乏横向比较的统一基础。
- 因此，该领域亟需一种**可泛化的过程级表示**，能够将异构执行轨迹规范化，并在固定、可复现的评估标准下完成跨方法比较。

**整体含义**
- 论文主张用**图结构**作为统一表示：将 MAS 执行轨迹抽象为协作图，保留"谁贡献了什么、谁消费了谁的输出、信息如何流动"等关键信息，同时去除框架特定的日志约定。
- 进一步提出"森林"隐喻：同一任务往往有多种成功的协作模式（如辩论式、流水线式、群体式），不应指定唯一的最优过程，而应以**参考森林（reference forest）** 记录多样的已验证成功结构，用于候选方法的对比。

## 2. 论文提出的方法论

**核心思想**
- 将 MAS 执行轨迹映射到一个统一的**有向无环协作图**（Collaboration Graph），通过与查询特定的"参考森林"进行结构性对比，实现确定性、可复用的评估。

**技术细节与流程**

1. **图抽象层（Graph Abstraction）**
   - 将每一次 MAS 执行轨迹 τ 投影为协作图 *G(τ) = (V, E, φ)*：
     - **节点 V**：每个原子动作（如 agent 消息、工具调用、决策）对应一个节点；
     - **边 E**：两个动作之间的信息传递；
     - **标签 φ**：标注节点的发出智能体、规范化角色和文本内容。
   - 图是 DAG：动作按时间戳排序，边只指向未来，不会形成环。
   - 投影是有损的：丢弃框架特定的运行时状态和精确时钟交错，保留角色、动作和信息流依赖，从而让异构框架的轨迹可比较。

2. **参考森林（Reference Forest）**
   - 每个参考图是一个"参考树"（DAG），记录一种已验证成功、得出正确答案的协作结构。
   - 参考森林 *F(q) = {(G_k, q_k)}* 由 K 个覆盖多种协作范式的成功图组成，每个图附带质量权重 q_k（包含正确性、结构简洁性和 token 成本）。
   - 森林不是唯一最优过程的枚举，而是基准提供的参考集合，用于回答"候选结构与该查询的已验证成功结构的关系"。

3. **评估指标（Evaluation Metric）**
   - **Pairwise 相似度**：*sim(G, G′) = α·s_node + β·s_edge + γ·s_topo*，权重默认 (0.4, 0.4, 0.2)：
     - s_node：规范化角色多重集的 Jaccard 相似度；
     - s_edge：角色类型化边指纹集合的 Jaccard 相似度；
     - s_top：节点数、边数的比值综合（惩罚冗余）。
   - **Forest Match（FM）**：候选图与参考森林中所有参考图的加权平均相似度，衡量候选与森林整体的对齐程度。
   - **Best Similarity**：候选与最近单个参考树的相似度。
   - **辅助指标**：
     - Node Validity：被下游动作消费的节点比例；
     - Mean Uptake：下游内容语义上使用上游内容的比例（基于嵌入余弦相似度）；
     - Content Redundancy：内容去重后剩余比例；
     - Tokens：总 token 消耗；
     - Efficiency：并行度/活跃智能体数量。

4. **核心机制**：所有指标都是图结构的确定性函数，**无需额外 LLM 推理，单条轨迹毫秒级完成评分**。

## 3. 实验设计

**基准与数据集**
- ForestBench 从一个由 7 个公开数据集构成的初始池中筛选查询：
  - **推理类**：GPQA、MMLU、MATH-500、GSM8K；
  - **代码生成**：SWE-bench-Verified；
  - **工具使用**：Terminal-Bench；
  - **多跳搜索**：WideSearch。
- 通过 Trace-Suitability Pipeline（TSP）筛选出 **844 个"协作必要"查询**：要求深度 d ≥ 5、宽度 w ≥ 0.5、可分解性 δ ≥ 0.5。分布为：推理 55.9%、多跳 QA 23.7%、代码生成 15.8%、工具使用 4.6%。

**参考森林构建**
- 使用六种代表性 MAS 框架生成参考轨迹：**Multi-agent Debate、Swarm、AutoGen、MetaGPT、MAS-GPT、AFlow**，外加单智能体 CoT-SC 结构锚点。
- 每个查询保留 10 个已验证成功的参考图，共 **8,440 个参考图**。

**评估对比的方法**
- 六个候选 MAS 框架：MAS-GPT、AutoGen、MetaGPT、Swarm、AFlow、Debate。
- 默认主干模型：DeepSeek-V4-Flash；另外使用 Claude-Sonnet-4.6、GPT-5.5、Qwen3.6-Plus 进行对照。

**主要实验**
1. **全局性能对比**：6 框架 × 3 随机种子 × 844 查询，约 15,192 条轨迹。
2. **参考森林鲁棒性**：
   - 跨骨干（DeepSeek-V4-Flash、Claude-Sonnet-4.6、GPT-5.5）对比；7 个 held-out 生成器消融；30 任务子集上移除金标条件对比。
3. **指标受控行为**：5 种扰动（节点删除、边重连、角色交换、干扰插入、重复内容注入）× 2 种强度；5 种权重方案；36 组 TSP 阈值网格扫描。

## 6. 论文的主要结论与发现

1. **准确率难以区分方法，图指标具有判别力**：
   - 六种框架的准确率范围仅 0.038（0.531–0.569），而 Forest Match 范围为 0.316（Debate）到 0.421（MAS-GPT），结构信号明显更分散。
2. **结果相近但结构不同，修正方式不同**：
   - 高准确率的 Debate 反而有最低的 Forest Match 和 Best Similarity，且 token 消耗最高，说明"协作成功"与"结构对齐"是两个独立维度。
3. **参考森林排序稳定**：
   - 跨三种参考森林骨干排序 Kendall τ 和 Spearman ρ 均为 1.00；held-out 生成器消融中 Top-3 在 6/7 设置下保持；金标条件移除后虽然绝对值变化，但 Top-3 不变（Kendall τ = 0.867）。
4. **指标分工明确**：
   - 结构扰动降低 Forest Match（最大降幅 0.058，节点删除 p=0.5），而重复内容注入不改变 Forest Match，由 Content Redundancy 捕捉。
5. **框架与骨干效应可分离**：
   - 框架施加了强结构先验（跨骨干距离 0.171 低于骨干内距离 0.181）；但协作带来的准确率增益依赖骨干——DeepSeek-V4 为 −0.002、GPT-5.5 为 −0.039、Claude-S4.6 为 −0.069，说明加智能体并非总是有益。
6. **域特化现象**：
   - Debate 虽然全局 Forest Match 最低，但在 SWE-bench-V 上排名第一（0.382），因为代码修复任务中 review-and-revise 模式更匹配成功参考图——全局排名需要结合来源做域级分析。
7. **效率优势显著**：
   - ForestBench 比 LLM-as-Judge 快约 2,900 倍，且每次评估零 token 消耗，参考森林是一次性资产，可复用。

## 7. 优点

1. **统一图表示**：将异构 MAS 轨迹投影到统一的协作图上，实现了跨框架、跨骨干的公平横向比较。
2. **森林而非单树**：用参考森林而非单一参考树进行比较，尊重了"同一任务有多种成功协作模式"的客观事实。
3. **确定性指标**：所有指标是图结构的纯函数，无额外 LLM 推理，完全可复现。
4. **毫秒级评估**：参考森林预计算后，单条轨迹评分时间极短（1,000 条 0.7 秒），支持大规模评估。
5. **可复用资产**：基准发布 844 个查询、8,440 个参考图、适配器和指标面板，后续方法无需重新构建参考集。
6. **深入的可视化与控制实验**：系统验证了骨干、参考构建、阈值、权重和扰动对排名的影响，为评估的可靠性提供了充分证据。
7. **LOSSY 抽象的设计智慧**：图投影刻意丢弃非本质信息（精确时钟交错等），换取了跨框架可比性，属于合理的抽象取舍。

## 8. 不足与局限

1. **结构相似性 ≠ 协作质量的绝对标准**：Forest Match 衡量的只是"候选与参考森林的对齐程度"，不代表候选协作是否是"普遍更好"；作者也坦承这一点。
2. **参考森林构建成本高**：构建 844 个查询的参考森林需要 20.5M tokens，虽然是一次性成本，但对于资源有限的研究团队仍是门槛。
3. **参考图数量有限**：每查询仅 10 个参考图，且来自 6 种固定框架，可能未覆盖所有可行的成功协作模式；参考集的范围限制会影响评估的公平性。
4. **过滤启发式的局限**：TSP 筛选（深度、宽度、可分解性阈值）是启发式的，不能证明保留的查询一定需要多智能体，也不能证明单智能体无法解决。
5. **LLM 失败诊断不稳定**：细粒度标签对评注提示词高度敏感（Cohen's κ 低至 0.129），只有粗粒度的"结构 vs 内容"分类方向可用，限制了诊断的精确度。
6. **框架与数据集覆盖有限**：仅评估 6 种框架，覆盖推理、代码生成、工具使用和多跳搜索，但推理类任务占比过高，且 2026 年新出的框架未被纳入。
7. **无硬件细节**：未报告 GPU 型号/数量，影响可复现性中的基础设施透明性。
8. **对比基线的公平性问题**：LLM-as-Judge 作为一种"自由评判"本身就存在不稳定问题，而 ForestBench 用"已标注成功轨迹"作为另一锚点，两种范式各有偏向，论文只展示了 ForestBench 更具效率，未讨论其在"捕捉真实协作质量"上的全面优势。

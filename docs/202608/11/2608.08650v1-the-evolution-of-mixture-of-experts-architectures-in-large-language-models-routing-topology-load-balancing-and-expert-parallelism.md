## 摘要
专家混合模型在增加参数容量的同时，使每个token激活的计算量保持有界，但其架构演进不能仅通过按时间顺序发布的模型列表来解释。本技术综述综合了原始论文、官方技术报告和以往的综述，沿五个耦合维度组织现代专家混合系统：专家粒度、专家拓扑、路由自由度、负载均衡的范围和执行结构。我们将八个架构里程碑描述为一个依赖图，包含六个主线发展和两个正交分支，而不是八个连续的世代。然后我们通过四个控制平面分析各个系统：专家拓扑、路由、均衡和专家并行。这些平面规定了哪些专家存在、每个token由哪些专家处理、如何控制总负载，以及如何将选定的计算映射到物理设备上。该框架将算法选择（如Top-k路由、共享专家、细粒度专家和动态专家组合）与系统问题（包括token调度、设备放置、全对全通信和通信计算重叠）联系起来。最后，我们进行了等预算预训练实验，给出了质量和系统指标以及开放研究问题。主要趋势是从仅激活更多稀疏参数转向解耦语义路由、计算预算和物理执行。

## Abstract
Mixture-of-Experts models increase parameter capacity while keeping the computation activated by each token bounded, but their architectural evolution cannot be explained by a chronological list of model releases alone. This technical survey synthesizes primary papers, official technical reports, and prior surveys to organize modern Mixture-of-Experts systems along five coupled dimensions: expert granularity, expert topology, routing freedom, the scope of load balancing, and execution structure. We describe eight architectural milestones as a dependency graph with six mainline developments and two orthogonal branches, rather than as eight successive generations. We then analyze individual systems through four control planes: Expert Topology, Routing, Balance, and Expert Parallelism. These planes specify which experts exist, which experts process each token, how aggregate load is controlled, and how selected computation is mapped onto physical devices. The framework connects algorithmic choices such as Top-k routing, shared experts, fine-grained experts, and dynamic expert composition with systems concerns including token dispatch, device placement, all-to-all communication, and communication-computation overlap. We conclude with equal-budget pretraining experiments, quality and systems metrics, and open research questions. The main trend is a shift from merely activating more sparse parameters toward decoupling semantic routing, computational budgets, and physical execution.

## 2. 方法论：核心思想、关键技术细节与公式

### 2.1 总体框架
论文提出两个互补而非竞争的分析视角：

### 2.2 Token-choice MoE 统一形式化
- Router计算专家亲和度：$s_{i,t} = \phi(x_t, e_i)$，$\mathcal{K}_t = \text{TopK}_{i \in \{1,\dots,N\}}(s_{i,t})$
- 输出：$y_t = x_t + \sum_{i \in \mathcal{K}_t} g_{i,t} E_i(x_t)$，其中 $g_{i,t} = \frac{\exp(s_{i,t})}{\sum_{j \in \mathcal{K}_t} \exp(s_{j,t})}$
- 若有共享专家，则增加 $\sum_j E^{\text{shared}}_j(x_t)$

### 2.3 三目标优化
- 最大化总容量 $P_{\text{total}}$，同时控制单token激活量：$P_{\text{active}} \approx P_{\text{dense}} + \frac{k}{N}P_{\text{routed}} + P_{\text{shared}}$
- 负载变异系数：$\text{CV}_{\text{expert}} = \frac{\sqrt{\frac{1}{N}\sum_i (n_i - \bar{n})^2}}{\bar{n}}$（低CV利于EP吞吐，但不必然利于知识专业化）

### 2.4 四层闭环形式化
$$\mathcal{E} = T(\theta_{\text{topo}}),\quad \mathcal{K}_t = R(x_t, \mathcal{E}; \theta_{\text{route}}, b),\quad n_i = \sum_t \mathbb{1}[i \in \mathcal{K}_t],\quad (b, \alpha, c) \leftarrow C(\{n_i\}, \pi),\quad y_t = \text{EP}(x_t, \mathcal{K}_t, \pi, \sigma)$$

### 2.5 八个演进节点
1. **Dense/Soft MoE**（1991）：统计分工，gating+local experts，但容量与FLOPs绑定
2. **Sparse conditional computation**（2017）：Top-k建立容量杠杆，参数容量与单token计算量解耦
3. **Transformer MoE + Expert Parallel**（GShard等）：经典执行链 Attention→Router→Dispatch All-to-All→Expert FFN→Combine All-to-All
4. **开放权重粗粒度MoE**（Mixtral）：证明经典MoE可贯通预训练、微调、部署闭环
5. **Shared + fine-grained experts**（DeepSeekMoE/V2）：组合分辨率提升 + 共享专家隔离公共知识
6. **Ultra-sparse scaling**（PEER、Kimi K2、gpt-oss）：固定active FLOPs下继续扩展总容量
7. **动态计算**（LongCat-Flash）：adaptive-k / zero-compute slots，token-dependent预算
8. **语义路由与物理执行解耦**（ScMoE、MoHGE、GMoE、Head Parallel）：四条正交分支

### 2.6 关键技术细节
- **Balance控制层**：经典辅助损失 $\mathcal{L}_{\text{bal}} = \frac{\alpha}{N}\sum_{i=1}^{N} f_i P_i$；ALF（Auxiliary-Loss-Free）策略通过非梯度bias更新 $b_i \leftarrow b_i + \eta \cdot \text{sign}(\bar{n} - n_i)$ 减少对LM梯度的干扰
- **区分两组易混淆机制**：z-loss（控制数值稳定性）≠ balance loss（控制使用分布）；逻辑专家均衡 ≠ 物理设备/网络均衡
- **通信三策略**：限制通信拓扑（device/node-limited routing）、隐藏通信（shared overlap、ScMoE、token chunking）、重构通信（Head Parallel结构化通信）
- **重要区分**：总All-to-All时间 ≠ exposed communication time

## 6. 主要结论与发现

- **核心结论**：LLM MoE架构演进无法用发布时间线解释，需要"五维框架 + 八节点依赖图 + 四控制面"的结构化视角
- **主趋势**：现代MoE的竞争焦点已从"稀疏激活更多参数"转向"**让语义路由、计算预算和物理执行解耦**"
- **现代主干特征**（截至2026年）：Token-choice Top-k + fine-grained experts + 可选shared path + global/batch-wise balance或ALF + topology-limited routing + dropless kernels/communication overlap + runtime expert placement
- **不存在唯一的"下一代结构"**：更可信的方向是四者组合——更自由的语义路由、显式的平均计算预算控制、拓扑感知或确定性通信、运行时专家放置
- **明确纠正了一个常见误解**："DeepSeek-V3完全没有balance loss"并不准确，它实际使用batch-wise ALF作为主均衡机制，同时保留很弱的sequence-wise auxiliary loss
- **开放性研究问题**（5个）：Specialization的正确分析单位、更高sparsity的系统最优点、Balance能否下沉到runtime、动态计算如何满足尾延迟SLA、Post-training如何保持Router稳定

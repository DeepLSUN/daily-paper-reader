## 摘要
拒绝采样微调（RFT）广泛用于训练代码智能体，通过在可验证的软件工程任务上生成轨迹、保留通过测试的轨迹，并在成功的轨迹上进行微调。然而，即使是强大的代码智能体也会在相当一部分任务上反复失败，而标准的RFT直接丢弃这些失败。被丢弃的样本恰恰是最困难且信息量最大的，它们来自标注成本高昂的可验证实例。更强的基座模型可能减少失败数量，但剩余的困难案例仍然定义了进一步改进的前沿。我们提出FailForge，一个将失败的轨迹转换为训练信号的智能体框架。对于每个失败的实例，智能体从错误反馈和执行痕迹中诊断失败原因，将诊断提炼为简洁可操作的技能，并将技能注入智能体上下文以进行有指导的第二次尝试。在技能指导下成功的轨迹会被重新纳入RFT语料库。关键在于，训练时会移除技能，因此模型内化恢复的行为，而不是在推理时依赖外部提示。FailForge以微小的额外成本恢复了超过26%先前失败的实例，并在增强语料上训练Qwen3.5-4B，使SWE-bench Verified解决率比强RFT基线提高6.6个百分点，且收益集中在最困难的问题上。

## Abstract
Rejection sampling fine-tuning (RFT) is widely used to train code agents by generating trajectories on verifiable software engineering tasks, retaining those that pass the tests, and fine-tuning on the successful rollouts. However, even strong code agents repeatedly fail on a substantial fraction of such tasks, and standard RFT simply discards these failures. The discarded samples are precisely the hardest and most informative ones, drawn from verifiable instances that are costly to curate. Stronger base models may reduce the number of failures, but the remaining hard cases still define the frontier for further improvement. We propose FailForge, an agentic framework that converts failed rollouts into training signal. For each failed instance, an agent diagnoses the failure from error feedback and execution traces, distills the diagnosis into a concise and actionable skill, and injects the skill into the agent context for a guided second attempt. Trajectories that succeed under skill guidance are folded back into the RFT corpus. Crucially, the skill is removed at training time, so the model internalizes the recovered behavior rather than relying on external hints at inference. FailForge recovers over 26% of previously failed instances at marginal additional cost, and training Qwen3.5-4B on the augmented corpus improves the SWE-bench Verified resolve rate by 6.6 points over a strong RFT baseline, with gains concentrated on the hardest problems.

# FailForge 论文总结

## 一、核心问题与整体含义（研究动机与背景）
- **背景**：拒绝采样微调（RFT）是训练代码智能体的主流范式，流程为：在可验证的软件工程任务上采样多条轨迹 → 保留通过测试的轨迹 → 在成功轨迹上微调。该范式依赖执行验证提供大规模无人工标注的可靠监督。
- **结构化缺陷**：RFT 存在一个随任务难度加剧而愈发严重的问题——如果一个任务的所有采样轨迹均失败，则该任务对学习过程零贡献。持久性失败（persistent failures）样本被直接丢弃，而这些样本恰恰位于模型的能力前沿，是最困难、信息量最大、标注成本最高的实例。
- **问题本质**：增大采样预算（如从5x增至10x）只能恢复一小部分失败任务，说明持久性失败反映的是**缺失的能力**，而非单纯的采样方差。
- **核心洞察**：许多持久性失败并非源于针对具体实例的知识缺失，而是缺乏**可迁移的程序性能力**（procedural competence）——如何在大型代码库中定位故障、如何解读复杂测试装置、如何构建高效调查流程等可复用的策略。

## 二、方法论：核心思想与关键技术细节

### 核心思想
将失败的轨迹转化为训练信号：**诊断失败 → 提炼可迁移的程序性技能 → 以技能为指导重新尝试 → 将引导下成功的轨迹回收到训练语料 → 训练时移除技能**，使模型将恢复的行为内化到权重中，而非在推理时依赖外部提示。

### 五阶段流程（见图2）
1. **朴素RFT与失败识别**：对每个任务 $x_i \in \mathcal{D}$ 采样 K 条教师轨迹并验证，得到成功语料 $\mathcal{C}$ 与持久失败集 $\mathcal{F}$（K 条全部失败）。后续四阶段仅操作 $\mathcal{F}$。
2. **代理式技能归纳（Agentic Skill Induction）**：诊断代理 $\mathcal{A}$ 输入失败轨迹、测试输出、推理痕迹和 gold patch，输出结构化技能 $s_i$，包含四个固定部分：
   - 适用条件（何时相关）
   - 关键原则（正确修复必须遵守的不变量）
   - 常见陷阱（可能导致类似失败的做法）
   - 推荐方法（有序的调查与修复流程）
   
   技能以方法论层面表述，不涉及具体仓库或 bug，如"跨模块标识符一致性"、"模块导入可见性"。
3. **泄漏过滤（Leakage Filtering）**：用独立的裁判模型 $J(s_i, p_i)$ 判断技能是否泄漏了 gold patch 的实现细节，采用具体重建测试（能否从技能还原补丁）。泄漏的技能重新生成直至通过或预算耗尽。裁判与人类标注者一致性达 96.7%，Cohen's κ = 0.805。
4. **技能引导重试（Skill-Guided Re-rollout）**：将技能注入教师上下文 $\pi_T(\cdot | x_i \oplus s_i)$，采样引导轨迹并保留通过验证者，形成恢复语料 $\tilde{\mathcal{C}}$。
5. **技能移除与训练**：训练前通过移除算子 $\rho$ 剥离技能内容（保留代理自身动作与推理完整），以标准负对数似然损失微调：
$$\mathcal{L}(\theta) = -\sum_{(x_i,\tau)\in \mathcal{C}} \log \pi_\theta(\tau|x_i) - \sum_{(x_i,\tilde{\tau}_i)\in \tilde{\mathcal{C}}} \log \pi_\theta(\rho(\tilde{\tau}_i)|x_i)$$

**关键区别**：技能仅作为合成时的潜在引导变量，训练目标不含技能的任何痕迹，迫使模型将程序性能力编码进权重而非复制可见提示。

## 三、实验设计

### 数据集与基准
- **训练数据**：SWE-Gym 的 2,401 个 Python 任务实例（丢弃37个无 docker 镜像的任务），每个实例配有可执行环境和隐藏测试套件。
- **评估基准**：
  - SWE-bench Verified（500 个人工验证实例，执行式问题解决的标准基准）

  - 训练仓库与评估仓库完全不相交，确保仓库级隔离。
- **评估指标**：resolve rate 即 pass@k（k ∈ {1, 3, 5}），每实例最多允许 5 次独立尝试，找到成功补丁即停止。

### 模型配置
- **教师策略** $\pi_T$：Kimi-K2.6 + OpenHands 代理框架；同一教师也执行技能归纳和引导重试。
- **泄漏过滤器**：GPT-5.4。
- **学生策略** $\pi_\theta$：Qwen3.5-4B 和 Qwen3.5-9B。
- 所有方法从同一教师、同一框架、同一初始语料蒸馏，差异仅可归因于对 $\mathcal{F}$ 的处理方式。

### 对比方法
| 方法 | 描述 |
|---|---|
| Base | 无微调的基座模型 |
| RFT (5×) | 标准拒绝采样微调，初始 K=5 采样 |

## 六、主要结论与发现
1. **显著提升**：FailForge 在 SWE-bench Verified 上将 4B 学生模型的 pass@1 从 RFT 基线的 59.6 提升至 66.2（+6.6 点），9B 模型从 63.6 提升至 67.2；增益全部来自标准 RFT 丢弃的失败实例。
2. **超越增加采样**：同预算下 FailForge 恢复 218 个失败实例（26.2%），接近更多采样（119个，14.3%）的两倍，且产出训练价值更高的轨迹。
3. **优于实例级提示**：提示恢复更多轨迹（352 vs 218），但学生性能更低（63.8 vs 66.2），证明**恢复数量不能衡量监督质量**；程序性技能的迁移价值高于实例级提示。
4. **跨域泛化**：增益保持到多语言基准（4B：52.3→55.7；9B：59.7→61.3）和不同评估 harness（Claude Code），表明技能非 Python 特有或框架绑定。
5. **数据质量更高**：固定训练集大小时，替换为 FailForge 恢复轨迹使 pass@1 从 59.6 升至 63.8，每样本监督价值更高。
6. **技能可迁移**：同仓库内打乱技能后保留 59.3% 的恢复率，而提示仅保留 20.8%，证明技能捕捉可复用的调查程序而非特定解决方案。
7. **行为更系统**：FailForge 在定位精度、验证纪律、编辑经济性上均最优，尤其在未解决实例上的定位精度改进最明显。
8. **技能主题集中**：四个最大类别（测试约定扎根、修复层次选择、变更传播、根因追踪）覆盖 72.8% 的技能，与定位缺陷的观察吻合。

## 七、优点

### 方法设计的亮点
1. **直击 RFT 结构性缺陷**：精准识别"失败样本被浪费"这一核心问题，针对最难的实例产生最有用信号，而非回避困难样本。
2. **"合成时有、训练时无"的精妙设计**：技能作为潜在引导变量在合成阶段引导教师进入高奖励区域，训练前完全剥离，迫使模型内化能力，避免了推理时对外部知识的依赖。
3. **强调程序性而非实例性知识**：将恢复对象从特定实例的答案提升到可迁移的调查方法论，这是与现有方法（步骤级修复、实例级提示）的本质区别。
4. **完备的泄漏过滤机制**：用 gold patch 提供诊断上下文的同时，通过裁判模型系统性筛选解特定信息，使用重建测试而非简单关键词匹配，并有人类标注校准。
5. **无需人工标注**：整个流程基于可验证的软件工程任务自动运行，gold patch 来自历史修复对（离线数据构建自然可得）。

### 实验设计的优点
1. **对照严谨**：所有方法在同一教师、同一框架、同一预算下比较，差异仅归因于对失败集的处理方式。
2. **多维度验证**：覆盖模型规模（4B/9B）、基准语言（Python/多语言）、评估框架（OpenHands/Claude Code）、数据规模控制和消融分析。
3. **深入的行为分析**：从轨迹层面解剖代理行为的改变（验证纪律、编辑次数、定位精度），将性能提升解释为可观测的行为转变。
4. **可复现性设计**：教师与学生模型均为公开模型，框架（OpenHands）为开源工具，训练/评估仓库分离保障了可信度。

9. **同仓库迁移测试的保守性**：图3 中打乱技能仍来自同一仓库，共享代码结构和约定，实际的跨仓库迁移效果可能低于报告值。论文未进行跨仓库迁移测试。
10. **技能质量的粒度差异**："程序性技能"的定义依赖于人工设计的四部分结构和裁判判断，其质量边界较为模糊，不同技能（如"测试约定扎根"vs"输入防护"）的恢复价值可能差异显著，但论文未给出分层分析。

## 总结
FailForge 提出了一种创新且有效的范式，将 RFT 丢弃的持久性失败转化为可迁移的程序性技能，通过"合成时有引导、训练时无引导"的设计使模型内化调查能力。实验体系完整、结论有说服力，在 SWE-bench Verified 上实现 +6.6 点的 pass@1 提升，且证明收益来自最难样本。该方法为低成本利用高代价失败数据开辟了新思路，是

## 九、未来研究方向

基于论文的贡献与不足，可进一步探索的方向包括：

1. **自举式技能归纳**：当无 gold patch 可用时，如何利用试错反馈（如测试输出差异、覆盖率变化）替代参考修复进行技能提炼，是推广到在线学习场景的关键。
2. **残余失败的多轮深化**：对未被技能引导恢复的 ~74% 失败实例，可尝试第二层技能抽象（技能之上的元技能）或切换更强大的诊断代理，构建递进式恢复流程。
3. **跨仓库、跨语言的技能合成**：直接在非 Python 或混合语言语料上归纳技能，检验技能的编程语言无关性，并探索技能库在不同代码库间的迁移复用。
4. **更细粒度的技能类型学分析**：针对 9 类技能（如“测试约定扎根”vs“输入防护”）分别测量其恢复率、训练增益与行为改变，量化技能质量差异，指导未来技能生成的优先级。
5. **推理时技能检索**：既然技能蕴含可迁移程序性能力，可将训练后的模型与一个技能检索器结合，在推理时动态注入相关技能，探索“训练内化 + 推断时检索”的混合范式能否进一步增益。
6. **噪音传播的精细建模**：泄漏过滤时的 12.5% 漏网技能如何影响学生模型？可通过在训练集中人为注入已知泄漏技能来定量分析其危害程度，进而设计更稳健的过滤阈值。

## 十、最终评价

总体而言，FailForge 在问题界定、方法设计、实验验证与结果解读四个层面均表现出高水平：它针对 RFT 中一个真实存在却被广泛忽视的结构性缺陷给出了优雅且实用的解决方案，以相对简单的思想（技能作为潜在变量）撬动了显著且可复现的性能提升。论文的写作结构清晰、消融完备、分析深入，尤其值得称道的是其“用行为分析解释性能提升”的论证方式，为社区提供了一个如何系统评估智能体训练方法的范例。

若未来能补充算力细节、开源完整代码与技能库，并在更广泛的模型与任务上验证该范式的通用性，其影响力将进一步扩大。

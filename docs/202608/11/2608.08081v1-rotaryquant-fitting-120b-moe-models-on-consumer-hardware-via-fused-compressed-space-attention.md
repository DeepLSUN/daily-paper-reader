## 摘要
具有26至1200亿参数的大型混合专家（MoE）语言模型通过三种同时存在的压力超出了消费级设备的内存容量：常驻权重矩阵、随上下文线性增长的关键值（KV）缓存状态，以及必须按需分页的数十个专家子层。我们提出了RotaryQuant，一个三轴压缩系统，解决了这三个问题。混合精度权重量化根据架构角色分配位宽：稠密层4位，路由专家2位，共享专家8位——后者的高激活峭度抵抗激进压缩。LRU专家卸载在真实内存压力下将非驻留专家分页到磁盘。新颖的轴是IsoQuant，一种KV缓存压缩方法，应用Walsh-Hadamard变换后接块对角SO(4)旋转，在3位标量量化之前对各向同性化激活分布，每头需要$O(d \log d)$次操作和256个存储参数，而稠密旋转方法需要$O(d^2)$次操作和16,384个参数。一个融合的四内核Metal GPU流水线直接在打包的3位张量上执行注意力，无需物化全精度KV状态——这是一种不同的执行模型，而不仅仅是量化方案。组合系统在16GB预算内适配Gemma 4-26B-A4B和Qwen3-30B-A3B，在32GB内适配Nemotron-H 120B，以9-19 tok/s的速度交互式运行，困惑度退化几乎为零（$Δ$PPL $\leq +0.0012$），并在32K上下文下实现100%的检索准确率。

## Abstract
Large mixture-of-experts (MoE) language models with 26--120 billion parameters exceed the memory capacity of consumer devices through three simultaneous pressures: resident weight matrices, key-value (KV) cache state that grows linearly with context, and dozens of expert sublayers that must be paged on demand. We present RotaryQuant, a three-axis compression system that addresses all three. Mixed-precision weight quantization assigns bit-widths by architectural role: 4-bit for dense layers, 2-bit for routed experts, and 8-bit for the shared expert whose high activation kurtosis resists aggressive compression. LRU expert offloading pages non-resident experts to disk under genuine memory pressure. The novel axis is IsoQuant, a KV cache compression method that applies a Walsh--Hadamard transform followed by block-diagonal SO(4) rotations to isotropize activation distributions before 3-bit scalar quantization, requiring $O(d \log d)$ operations and 256 stored parameters per head versus $O(d^2)$ and 16{,}384 for dense rotation methods. A fused four-kernel Metal GPU pipeline performs attention directly on packed 3-bit tensors without materializing full-precision KV state---a different execution model, not just a quantization scheme. The combined system fits Gemma 4-26B-A4B and Qwen3-30B-A3B within a 16\,GB budget and Nemotron-H 120B within 32\,GB, running interactively at 9--19 tok/s with near-zero perplexity degradation ($Δ$PPL $\leq +0.0012$) and 100\% retrieval accuracy at 32K context.

### 1. 论文核心问题与整体含义（研究动机与背景）

大型混合专家（MoE）语言模型已在参数规模上扩展至千亿级，但其本地部署面临三重内存压力：

- **常驻权重矩阵**：30B参数的MoE模型在4位精度下权重即需约15GB内存；
- **KV缓存**：8K上下文窗口额外占用4–8GB，且随序列长度线性增长；
- **专家子层存储**：数十个路由专家需要按需换入换出，进一步加剧内存压力。

这些压力使消费级设备（16–32GB内存）难以承载模型推理，导致推理被迫依赖云端，进而引发**隐私暴露**（提示词离开设备）、**可访问性不平等**（API订阅费用和带宽限制排斥低收入群体）、以及**数据中心能耗/水耗问题**。论文以此为动机，旨在将超大MoE模型的本地推理作为一级部署目标，而非仅作理论探索。

### 2. 方法论

#### 2.1 总框架：三轴压缩系统（RotaryQuant）

系统按固定顺序组合三种独立压缩机制：

\[
M_{\text{total}} = O_E \circ C_{KV} \circ Q_W
\]

- **Q_W（权重量化）**：按架构角色分配位宽——稠密层4位（GPTQ/AWQ）、路由专家2位、共享专家8位（因其激活峭度κ=10.10远高于专家的0.41，抗拒激进压缩）；
- **C_KV（KV缓存压缩）**：由IsoQuant实现，是全文的核心创新；
- **O_E（专家卸载）**：基于LRU策略将非驻留专家卸载至磁盘，仅在真实内存压力下生效。

三者不可交换：权重量化决定激活分布，激活分布决定KV压缩策略，专家卸载依赖压缩后的内存预算。

#### 2.2 IsoQuant压缩流水线

每个KV向量x（维度d=128）经四阶段处理：

1. **归一化**：映射到单位球面（保留标量范数作为缩放因子）；
2. **结构化旋转**：先做Walsh-Hadamard变换（WHT）全局混合各维度能量（O(d log d)），再进行块对角SO(4)旋转（每个4维块由单位四元数对(qL, qR)参数化）以实现块内精细对齐；
3. **标量量化**：3位Lloyd-Max最优码本量化，最小化旋转后边际分布下的期望失真；
4. **位打包**：128维3位量化后打包为48字节，相比FP16获得约5.3倍压缩。

**关键优势**：WHT加SO(4)组合仅需256个存储参数（每头）和O(d log d)次操作（1,408个FMA），而稠密旋转方法需16,384个参数和16,384个FMA——参数减少64倍，计算减少11.6倍。

#### 2.3 融合压缩空间解码（Fused Metal Decode Pipeline）

这是与既有方法的核心差异：

- 现有方法（TurboQuant、KIVI等）均采用**“解压-物化-计算”**范式：先将压缩KV还原为FP16，再做GEMM注意力；
- IosQuant改用**四核Metal GPU流水线**直接在打包的3位张量上计算：
  - Kernel A：打包K上的融合QK点积（替代反量化+矩阵乘法）；
  - Kernel B：标准softmax；
  - Kernel C：打包V上的加权累加（替代反量化+矩阵乘法）；
  - Kernel D：将逆旋转（WHT蝶形+SO(4)^T）仅一次应用于聚合输出。

由于旋转R正交，⟨Rq, Rk⟩=⟨q,k⟩，因此旋转空间的注意力分数与原始空间一致，只需在最终输出上做一次逆旋转，而非每token都做。运行时计数器证实：3,612次解码步骤中解压调用、读取键调用和回退调用均为零。

### 6. 主要结论与发现

1. **可行性成立**：三轴协同压缩使120B参数MoE模型在17.2GB峰值内存内以14.85 tok/s交互式运行（Nemotron-H），质量损失近零（ΔPPL ≤ +0.0012）；
2. **IsoQuant优于稠密旋转**：在Qwen3-30B上ΔPPL比TurboQuant低45倍（+0.0009 vs +0.0405），参数减少64倍、计算减少11.6倍；
3. **压缩空间注意力有效**：融合内核消除张量物化，3,612步解码中零解压调用，性能与基线持平（llama.cpp融合路径仅-3.2%生成吞吐）；
4. **KV压缩收益有前提**：KV注意力占比>20%时收益显著；对混合架构（Nemotron-H，KV仅占14%），收益递减；内存充足时IsoQuant带来5.3倍吞吐开销，因此它是**内存压力缓解机制**而非通用加速器；
5. **专家卸载代价巨大**：磁盘I/O导致约100倍吞吐惩罚，仅在内存不足时才值得使用；
6. **融合是必要条件**：未融合路径生成吞吐暴跌18%、提示吞吐暴跌44%。

### 7. 优点

- **系统性视角**：将权重、KV缓存、专家三方面内存压力纳入统一框架，非孤立优化；
- **计算范式创新**：从“重构-再计算”转向“压缩空间内计算”，是一种执行模型变革而非仅量化方案改进；
- **理论支撑扎实**：内积保持的证明、Hanson-Wright不等式保障各向同性、SO(4)的Spin(4)双覆盖数学解释完备；

- **现实动机充分**：隐私、可访问性、环境成本三个维度都有数据支撑。

### 8. 不足与局限

- **架构覆盖缺口**：多查询潜在注意力（MLA）与旋转位置编码（RoPE）模型未被支持（如DeepSeek-V2），RoPE子空间不能旋转/量化，论文未实现子块分割处理；这是明确标注的硬阻塞；
- **上下文验证不足**：核心PPL评估仅2K token；32K长上下文评估仅覆盖单一模型（Qwen3.6），跨模型长上下文表现未知；
- **硬件绑定性**：融合内核为Apple Metal GPU专用，跨NVIDIA/AMD/CPU平台的通用性尚未验证；Mojo内核仅提及，未实现；
- **吞吐开销**：在内存充足时IsoQuant反而引入5.3倍吞吐惩罚，需用户自行判断适用条件；
- **服务端可扩展性差**：并发8客户端时4/8响应为空，并行效率仅34%，不适合生产级服务；
- **Kernel C瓶颈**：值累加（0.79ms）占解码主导时间，虽有两策略优化，但本质是压缩空间算术增加的计算量；
- **共享专家8位选择依据单模型**（κ=10.10），其他模型的共享专家特性未见分析；
- **论文为预印本**（arXiv:2608.08081v1），尚未经同行评审，部分长上下文和浸泡测试数据标记为“未完待续”。

### 总结

RotaryQuant证明了大规模MoE模型在消费级硬件上以实际可用的速度和近无损质量运行是现实可行的。其核心贡献——IsoQuant的结构化旋转与融合压缩空间解码——为KV缓存压缩提供了更优的计算-存储权衡，也为后续研究打开了一个方向：不仅压缩数据，更在压缩域中直接计算。但适用边界（内存压力存在时、KV注意力占比高时）和架构限制（MLA/RoPE阻塞、Apple生态绑定）需要在应用时审慎权衡。

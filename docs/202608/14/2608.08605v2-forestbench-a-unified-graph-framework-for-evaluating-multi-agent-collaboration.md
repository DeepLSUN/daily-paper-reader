## 摘要
基于大型语言模型（LLM）的多智能体系统（MAS）正在迅速普及，但其异构的执行轨迹无法为跨方法的评估提供共同基础。仅基于结果的基准忽略了协作，而LLM作为评判者的评估需要额外的、依赖模型的推理，并且可能随LLM和评分标准而变化。我们引入了一个可泛化的评估框架，将原生MAS轨迹映射到统一协作图的共享空间中，使不同方法能够在相同的表示、参考集和指标面板下进行评估。候选图与查询特定的参考森林进行比较。每个森林是基准提供的已验证成功图的集合：它记录了代表性MAS方法完成任务的多种方式，而不是规定唯一的最优过程。将该框架实例化为ForestBench，我们从七个公共数据集中筛选出844个需要协作的查询，为每个查询预计算十个成功的、以目标为条件的参考图，并评估六个代表性的MAS框架。受控的骨干、参考构建和扰动研究测试了评估的稳定性和范围。一旦基准森林构建完成，ForestBench即可在毫秒内对轨迹进行评分，无需进一步的LLM推理，为比较不同的MAS协作轨迹提供了可复用的结构基础。

## Abstract
Multi-agent systems (MAS) built on Large Language Models (LLMs) are proliferating rapidly, but their heterogeneous execution traces provide no common basis for evaluation across methods. Outcome-only benchmarks discard collaborations, whereas LLM-as-Judge evaluation requires additional, model-dependent inference and can vary with the LLM and rubric. We introduce a generalizable evaluation framework that maps native MAS traces into a shared space of unified collaboration graphs, enabling different methods to be evaluated under the same representation, reference set, and metric panel. Candidate graphs are compared with a query-specific reference forest. Each forest is a benchmark-provided collection of verified-success graphs: it records diverse ways in which representative MAS methods can complete the task, rather than prescribing a unique optimal process. Instantiating the framework as ForestBench, we filter $844$ collaboration-necessary queries from seven public datasets, precompute ten successful target-conditioned reference graphs per query, and evaluate six representative MAS frameworks. Controlled backbone, reference-construction, and perturbation studies test the stability and scope of evaluation. Once the benchmark forests are built, ForestBench scores a trace in milliseconds without further LLM inference, providing a reusable structural basis for comparing diverse MAS collaboration traces.

### 1. 核心问题与研究动机

- **背景**：基于大语言模型（LLM）构建的多智能体系统（MAS）正成为复杂推理、软件工程和科学工作流的主导设计范式，新框架层出不穷，涵盖固定流水线、动态角色分配和自组织群体等范式。
- **核心问题**：MAS 框架的演进速度已远超评估能力的提升，现有评估手段存在三重断裂：
  - **仅结果评估**（如 GSM8K、MMLU、HumanEval）将整个 MAS 执行约简为单一最终答案，丢弃了协作过程本身；
  - **原生轨迹不可比较**：不同框架的事件模式、角色词汇和通信协议各异，缺乏统一的“过程级”比较基底；
  - **LLM 作为评判者**（LLM-as-Judge）需要额外的模型依赖推理，成本高、可复现性差、受评分标准影响大。
- **核心诉求**：需要一种**可泛化的表示**，将异构 MAS 执行轨迹标准化到同一结构空间，支持在共享标准下进行确定性的水平比较。

### 2. 方法论

#### 2.1 核心思想：协作图抽象

- 将 MAS 执行轨迹 $\tau$ 投影为一个**统一的有向无环协作图** $G(\tau) = (V, E, \phi)$：
  - **节点** $V$：每个原子动作一个节点（agent_message、tool_call、decision）；
  - **边** $E$：两个动作间的信息传递依赖；
  - **标签** $\phi$：记录节点发出者、规范化角色 $r \in R$ 及文本内容。
- 关键性质：
  - **无环性**：每个动作有唯一时间戳，边只指向未来，天然形成 DAG；
  - **刻意有损**：丢弃框架特有的运行时状态和精确时钟交错，保留角色、动作和信息流——正是结构度量所需的全部信息；
  - **不变性**：独立动作的批次内重排不影响图，使异构框架的轨迹可结构对比。

#### 2.2 参考森林（Reference Forest）

- **理念**：同一查询不存在唯一正确的协作模式——辩论、流水线、蜂群都可以成功。单一“金标准”图会不公正地偏向某一协调范式。
- **定义**：每个已验证的成功协作结构视为一棵**参考树**（记为 DAG），多棵结构不同的参考树组成**参考森林** $F(q) = \{(G_k, q_k)\}_{k=1}^{K(q)}$，其中 $q_k$ 为整合了正确性、结构简洁性和 token 成本的参考权重。
- **定位**：森林是基准发布的可复用资产，不是唯一金标准，也不枚举所有成功路径，只覆盖多种代表性协作范式。

#### 2.3 评估指标

- **成对图相似度**：
  $$
  \text{sim}(G, G') = \alpha\, s_{node} + \beta\, s_{edge} + \gamma\, s_{topo}
  $$
  默认权重 $(\alpha, \beta, \gamma) = (0.4, 0.4, 0.2)$。
  - $s_{node}$：规范化角色多重集的 Jaccard 相似度；
  - $s_{edge}$：角色类型边指纹（$r_u, r_v$）的 Jaccard 相似度；
  - $s_{topo}$：基于 $|V|$ 与 $|E|$ 比值的大小匹配项，不奖励冗长。
- **Forest Match（核心指标）**：
  $$
  \text{FM}(G, F(q)) = \frac{\sum_{k=1}^{K} w_k\, \text{sim}(G, G_k)}{\sum_{k=1}^{K} w_k} \in [0,1]
  $$
  其中 $w_k$ 为归一化参考权重。
- **Best Similarity**：$\max_k \text{sim}(G, G_k)$，度量与最近参考树的接近程度。
- **辅助指标面板**：
  - **Node Validity**：被下游消费的动作比例；
  - **Mean Uptake**：下游内容是否语义使用上游内容（基于嵌入余弦）；
  - **Content Redundancy**：内容规范化后的重复比例；
  - **Tokens** 与 **Eff. (拓扑效率)**：成本与并行度。

### 3. 实验设计

#### 3.1 数据集与筛选

- **来源**：7 个公开数据集，四大类别：
  - 推理：GPQA、MMLU、MATH-500、GSM8K
  - 代码生成：SWE-bench-Verified
  - 工具使用：Terminal-Bench
  - 多跳检索：WideSearch
- **筛选管道（Trace-Suitability Pipeline）**：对每个查询独立打分三个维度——
  - 深度 $d(q) \ge 5$：最少独立推理步骤数；
  - 宽度 $w(q) \ge 0.5$：基于八项能力上的归一化香农熵；
  - 可分解性 $\delta(q) \ge 0.5$：是否可自然划分为独立子任务。
- **最终查询集**：844 个协作必要查询（推理 55.9%、多跳检索 23.7%、代码 15.8%、工具使用 4.6%）。

#### 3.2 参考森林构建

- 每查询预计算 **10 棵已验证成功参考图**（共 8,440 棵），来源覆盖六个代表性 MAS 框架 + 单智能体结构锚点。
- 目标条件化（$a^\star$ 作为目标）确保生成过程达到已知正确结果；通过结构骨架聚类后赋予参考权重。

#### 3.3 候选方法与骨干模型

- **候选框架（6 个）**：Multi-agent Debate、Swarm、AutoGen、MetaGPT、MAS-GPT、AFlow。
- **默认骨干**：DeepSeek-V4-Flash；另有 Claude-Sonnet-4.6、GPT-5.5、Qwen3.6-Plus 用于对比与诊断。
- **评估规模**：每个框架 3 个随机种子 × 844 查询 ≈ 2,532 条轨迹/框架，总计约 15,192 条。

### 4. 资源与算力

- **文中未明确说明 GPU 型号、数量或训练/运行时长**（论文为 LLM 推理型评估，非训练型工作）。

### 6. 主要结论与发现

1. **准确性几乎无法区分方法**：6 框架准确率仅横跨 0.038（0.531–0.569），而 Forest Match 跨度达 0.105（0.316–0.421），结构信号显著更具区分力。
2. **森林揭示领域特化的协作模式**：Debate 在全局最低 Forest Match，但在 SWE-bench-Verified 上排第一——其“审查-修订”模式更匹配代码补丁类任务。
3. **结构化面板暴露隐藏差异**：AFlow 的内容冗余度（0.167）约为其他框架的 3 倍；Swarm 是唯一节点有效性低于 1.0 的框架（0.968）；Debate 虽准确率最高但 token 消耗近乎最高、Best Similarity 最低。
4. **参考森林稳健**：跨骨干、留出生成器、开放式构建等测试中，聚合排序保持稳定，Top-3 几乎不变。
5. **失败可分结构性 vs 内容性**：结构性失败（角色缺失、固定模式不匹配）提示需要任务自适应拓扑选择；内容性失败（错误验证/聚合）提示需要更强验证机制。
6. **编排收益依赖骨干能力**：相对 CoT 基线，DeepSeek-V4 平均增益 −0.002、GPT-5.5 为 −0.039、Claude-S4.6 为 −0.069——更强的骨干上多智能体不一定更有益。
7. **评估成本极低**：毫秒级评分、零推理 token，比 LLM 评判快约 2,900 倍。

### 7. 优点

- **统一表示创新性强**：将异构 MAS 轨迹标准化到图空间，实现了真正的“水平比较”，解决结果评估与自由文本评判之间的空白。
- **森林取代单模板**：以多棵成功参考树组成的森林保留协作模式的多元性，避免对某一协调范式的偏袒，设计理念精巧。
- **确定性、可复现、零额外推理成本**：评分函数是图的纯函数，毫秒级完成，参考森林发布后可无限复用。
- **指标面板分层合理**：Forest Match 捕捉结构对齐，辅助指标（冗余度、有效性、摄取率）覆盖内容流、成本等正交维度，形成可视化诊断面板。
- **实验设计严谨**：完整的骨干、生成器、阈值、权重、扰动的多重敏感性测试，且 LOO 处理避免了同源偏差。
- **可扩展性强**：适配器机制使新框架只需轻量转换例程即可纳入评估。

### 8. 不足与局限

- **参考森林覆盖面有限**：只含 6 种 MAS 范式 + CoT 锚点，不能代表全部协作设计空间（如层次化架构、动态拓扑演化等）。
- **主观选择偏差**：查询筛选（TSP 阈值）本质是启发式，虽在 36 种阈值组合下排序稳定，但可能系统性排除某些需要单智能体串行深度推理的任务。
- **退化指标风险**：Forest Match 对重复内容注入不敏感（需依赖 Content Redundancy 补充）；拓扑单独使用会显著改变排序，表明指标组合依赖性。
- **诊断层不稳定**：LLM 诊断的细粒度标签对提示措辞敏感（Cohen's κ 低至 0.129），只能可靠支撑粗粒度修复方向，不能作为精确评分。
- **骨干泛化有限**：三种骨干上排序完全一致，但论文明确承认不保证任意参考构建下不变。
- **角色规范化依赖人工别名表**：跨框架角色映射需要人工维护，当框架角色词汇差异过大时可能引入映射误差。
- **未能回答“协作质量”的绝对问题**：论文明确不声称结构相似度等于普遍协作质量，Forest Match 只是参考相对度量，不是绝对质量标准。

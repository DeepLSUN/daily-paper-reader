## 摘要
编码智能体的强化学习日益依赖于长时间运行的智能体框架，以管理工具集成、代码库上下文和执行反馈。然而，这些框架的原生执行环境与策略梯度训练本质上不一致：环境崩溃和奖励欺骗（reward hacking）会破坏结果信号，而训练-推理差异会使轨迹采样行为与策略更新脱节。为解决这一问题，我们提出LEGO-RL，这是一个将原生编码智能体框架与可扩展策略梯度优化相连接且不修改其内部控制流的框架。LEGO-RL基于三大支柱：(1) 忠实优化：通过进程内LLM代理捕获原始生成流以进行令牌级对齐，并在框架端压缩或重新序列化的情况下，实现稳健的训练器端对数概率重新计算；(2) 可靠执行：通过可扩展沙箱编排，利用图像缓存和分阶段防御来缓解奖励欺骗；(3) 可观察训练：通过集成插件自动化验证和监控，并配以实时UI进行细粒度轨迹诊断。我们使用GSPO在三个原生编码智能体框架上训练稀疏MoE模型Qwen3.5-35B-A3B，以评估LEGO-RL。在SWE-bench Verified上，LEGO-RL将Qwen3.5-35B-A3B在OpenHands SDK（64.0%至70.4%）、Claude Code（62.4%至68.2%）和OpenCode（57.2%至66.6%）上的性能提升，同时保持轨迹采样-训练概率相关性超过0.99。

## Abstract
Reinforcement learning for coding agents increasingly relies on long-running agent harnesses to manage tool integration, repository contexts, and execution feedback. However, the native execution environments of these harnesses are inherently misaligned with policy-gradient training: environmental crashes and reward hacking corrupt outcome signals, while train-inference discrepancies decouple rollout behavior from policy updates. To address this, we present LEGO-RL, a framework that bridges native coding-agent harnesses with scalable policy-gradient optimization without modifying their internal control flow. LEGO-RL is built upon three pillars: (1) faithful optimization via in-process LLM proxying that captures raw generation streams for token-level alignment and robust trainer-side log-probability recomputation, even under harness-side compaction or re-serialization; (2) reliable execution via scalable sandbox orchestration featuring image caching and stage-wise defenses to mitigate reward hacking; and (3) observable training through an integrated plugin that automates validation and monitoring, paired with a Live UI for granular trajectory diagnostics. We evaluate LEGO-RL by training the sparse MoE model Qwen3.5-35B-A3B with GSPO across three native coding-agent harnesses. LEGO-RL improves Qwen3.5-35B-A3B across OpenHands SDK (64.0% to 70.4%), Claude Code (62.4% to 68.2%), and OpenCode (57.2% to 66.6%) on SWE-bench Verified, while maintaining a rollout-training probability correlation above 0.99.

## 2. 方法论：核心思想与关键技术

- **核心思想**：把原生 agent harness 视为环境的一部分，只优化其中被调用的策略 πθ；在模型服务边界捕获真实轨迹，并配合可靠的沙箱执行与可观测训练闭环，保证强化学习优化的“忠实性”和“可靠性”。
- **形式化目标**：最大化期望验证器奖励 J(θ) = E[r(x, τ)]，使用组相对优势估计（GRPO 式）、GSPO 序列级策略目标：
  - 损失函数采用带裁剪的序列级比率 σ_i(θ)，并允许不对称裁剪范围（ε_low < ε_high）；
  - 只有策略生成 token 参与训练，且必须基于 harness 提供的上下文 c_t 计算条件概率；
  - 通过权重 w(τ_i) 将基础设施或执行失败导致的无效轨迹从训练中过滤掉。
- **三大支柱**：
  1. **忠实优化（Faithful Optimization）**：
     - 进程内 LLM 代理（In-Process Proxy）直接捕获生成时的 token ID、对数概率、响应掩码、MoE 路由决策；
     - 对 harness 侧历史重写/压缩，采用消息粒度对齐，无法可靠对齐的内容直接排除而非重构；
     - 对稀疏 MoE 模型，在训练阶段重放 rollout 时的专家路由（R3），确保概率重算与行为策略一致。
  2. **可靠执行（Reliable Execution）**：
     - 支持 Docker/K8s/云容器服务，采用 Nydus 懒加载镜像、只读挂载 agent 运行时、内联镜像构建；
     - 分阶段超时与异步调度，避免慢轨迹阻塞整个批次；
     - 奖励完整性防御：网络访问由特权侧车控制、隐藏 git 历史、测试文件延迟到评分阶段、将测试依赖打入镜像等。
  3. **可观察训练（Observable Training）**：
     - 提供 Agent 插件（技能：运行验证、训练执行、实时监控）自动化操作流程；
     - Live UI 提供终止原因分布、任务网格、轨迹查看器、训练-推理一致性面板、AI 辅助分析等诊断能力。
- **工作流**：分为数据准备、运行验证、训练、Live UI、人工审查五个阶段，形成闭环迭代。

## 6. 主要结论与发现

- LEGO-RL 在三个原生编码代理框架上均有效提升 SWE-bench Verified 解决率：
  - OpenHands SDK：64.0% → **70.4%**（+6.4）
  - Claude Code：62.4% → **68.2%**（+5.8）
  - OpenCode：57.2% → **66.6%**（+9.4）
- 同时，rollout 与训练的概率对数相关度在所有框架上保持 ≥0.998（p50），p99 的每轨迹平均对数概率差异 < 3×10⁻³，证明训练忠实性很高。
- 任务难度筛选对于保持组内奖励方差、维持有效学习信号至关重要：未筛选池中 72.7% 的任务从未被解决、13.4% 始终被解决，难以产生梯度。
- 终止感知的轨迹过滤能够防止基础设施失败污染优化；不同 harness 的终止分布差异显著，说明 harness 本身也是轨迹分布的一部分。
- 异步调度显著提升训练吞吐（同时间内步数从 3 增至 7，步时间缩短 2.5 倍），因为 agent 执行是主要瓶颈。
- 行为分析显示：训练后智能体更多进行自我检查（编辑后回读文件比例从 73.6% 升至 98.1%）、探索更多文件、延长交互轮数；错误恢复能力变化较小。
- 观测试验还发现：固定任务池的“信息性”会随策略增强而下降（全部正确或全部错误的组比例上升），提示需要动态更新任务池。

## 7. 优点

- **方法论亮点**：
  - 采用“模型 API 边界捕获”而非事后重构轨迹，从根本上解决了 harness 上下文压缩/重写带来的对齐问题；
  - 针对稀疏 MoE 的路由重放（R3）机制，并设计了负对照实验证明错位路由会破坏优化；
  - 将奖励完整性防御系统化，按 agent 侧/环境侧分类并给出具体防护措施；
  - 引入流程内代理 + Live UI，把“可观测性”作为 RL 训练基础设施的一等公民，支持从指标到轨迹的快速诊断。
- **实验设计亮点**：
  - 跨三个真实原生框架验证泛化性，且在同一协议下测量基线模型，结果可直接比较；
  - 对终止轨迹的“掩码但不丢弃”策略，保持了批次一致性；
  - 对同步 vs 异步、任务筛选、沙箱优化均做了定量消融，证据链完整；
  - 开源完整框架、模型和数据集，便于复现。

## 8. 不足与局限

- **实验覆盖**：仅使用 Qwen3.5-35B-A3B 一个模型；各 harness 单独训练，未测试混合 harness 训练；主配置仅单次运行，无方差估计。
- **奖励设计**：只有末尾的二元可执行奖励，无法对中间行为（如错误恢复）分配过程性信用；奖励完整性防御只覆盖本实验观察到的失败模式，不能保证对所有可能的奖励欺骗策略稳健。
- **系统效率评估局限**：同步vs异步对比中 GPU 组吞吐不一致，虽做了校正，但校正本身依赖假设；同步工作是离线筛选场景而非严格匹配的训练对照。
- **可解释性局限**：诊断分析是观察性关联，不是自动化因果验证；任务级解决率变化受异步采样影响，不等同于学习或遗忘的直接测量。
- **环境依赖**：沙箱和镜像加速的数值依赖具体部署环境，可能不具普适性。

## 摘要
自主计算机使用智能体越来越多地被应用于需要协调应用调用、持续状态跟踪和对验证器敏感的写入的长时程任务，但它们仍容易发生过程性失败：误读应用状态、工具语义或任务进度。过程性记忆有望带来更一致的决策和更少的冗余探索，但在不进行模型训练的情况下构建高质量记忆仍然具有挑战性。我们提出CONTRAMEM，一个源灵活、无需训练的自演进过程性记忆框架，它将同任务结果差异视为监督信号：正确性、效率、恢复和失败模式的差异揭示了与结果相关的过程性区别，并将其提炼为一个紧凑的应用级功能卡和任务级技能卡库，该库通过局部策展而非仅追加累积或整体库重写来演进。在保留的GAIA2/ARE计算机使用任务上，CONTRAMEM将三个源模型目标的成功率提高了一倍以上（从26.2%提升至55.3%），且每个模型均有持续增益（GPT-5.5：27.5提升至61.0；Claude Sonnet 4.6：28.0提升至52.5；DeepSeek V4 Pro：23.0提升至52.5）。同一个记忆库在未见过的Qwen3.7 Plus上不变地迁移（从18.5提升至35.5），表明其是可迁移的过程性知识而非模型特定行为。相同的构建方式不变地迁移到AppWorld，在全部三个中端智能体的两个公共测试划分上均优于无记忆和其自身的单源自记忆变体。在匹配的轨迹预算下，异构多模型轨迹产生的记忆优于自模型或同模型多次 rollout 记忆：其优势来自对比行为多样性，而非更强的源智能体或更多采样。

## Abstract
Autonomous computer-use agents are increasingly applied to long-horizon tasks requiring coordinated application calls, persistent state tracking, and verifier-sensitive writes, yet they remain prone to procedural failures: misreading application state, tool semantics, or task progress. Procedural memory promises more consistent decisions and less redundant exploration, but constructing high-quality memory without model training remains challenging. We introduce CONTRAMEM, a source-flexible, training-free framework for self-evolving procedural memory that treats same-task outcome variation as supervision: differences in correctness, efficiency, recovery, and failure modes expose outcome-relevant procedural distinctions, distilled into a compact bank of app-level Function Cards and task-level Skill Cards that evolves through localized curation rather than append-only accumulation or whole-bank rewriting. On held-out GAIA2/ARE computer-use tasks, CONTRAMEM more than doubles the success rate across the three source-model targets (26.2% to 55.3%), with consistent per-model gains (GPT-5.5: 27.5 to 61.0; Claude Sonnet 4.6: 28.0 to 52.5; DeepSeek V4 Pro: 23.0 to 52.5). The same bank transfers unchanged to the unseen Qwen3.7 Plus (18.5 to 35.5), indicating transferable procedural knowledge rather than model-specific behavior. The same construction carries over unchanged to AppWorld, beating both no memory and its own single-source self-memory variant for all three mid-tier agents on both public test splits. Under a matched trajectory budget, heterogeneous multi-model trajectories yield stronger memory than self- or same-model multi-rollout memory: the margin comes from contrastive behavioral diversity, not stronger source agents or more sampling.

## 1. 核心问题与整体含义（研究动机和背景）

- 自主计算机使用智能体（computer-use agents）越来越多地承担长时程任务，需要协调多个应用调用、持续追踪状态，并执行对验证器敏感的写入。
- 但即使是最强的模型，也仍然会因**误读应用状态、工具语义或任务进度**而产生过程性失败（procedural failures）。
- 已有工作提出用“过程性记忆”帮助模型避免重复犯错、减少冗余探索，但在不更新模型权重的前提下，仍面临三个核心困难：
  - 原始轨迹检索会迁移脆弱的表面细节，而非可复用的逻辑；
  - 单条轨迹总结无法识别区分成功与失败的因果边界；
  - 同一模型自己重采样会继承自身盲区，即“盲点继承”。
- 论文的核心洞察是：**同一任务上不同模型的轨迹差异是宝贵且免费的监督信号**，就像事故复盘比任何单一日志都更有教益。
- 基于此提出 **CONTRAMEM**：一种无需训练、源灵活的自我演进程序性记忆框架，将“对比多个模型的轨迹差异”视为监督信号，提炼为可复用的记忆卡库。

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 2.1 总体架构

CONTRAMEM 的流程分为四个环节（对应论文图 2）：

1. **异构经验收集**：多个模型尝试相同参考任务，得到同任务的多条轨迹。
2. **Reflector 跨模型对比**：对比同任务轨迹在正确性、效率、恢复、失败模式四方面的差异，定位决策边界，生成候选“技能增量”（Skill Delta）。
3. **Curator 局部记忆编辑**：对候选增量进行本地化编辑，而非整体重写或仅仅追加。
4. **运行时检索与注入**：冻结记忆库，通过确定性检索将少量任务相关卡片注入单个目标智能体。

### 2.2 记忆表示：两级卡片

- **Function Cards（功能卡）**：应用级工具契约，记录函数的用途、参数、返回值、副作用和常见错误。卡片要求严格基于观测证据、脱敏、不包含任务计划或模型身份。
- **Skill Cards（技能卡）**：任务级决策规则，包括标题、触发条件、核心规则、完成条件、成功/失败对比、恢复和效率提示等。技能卡具有能力特异性（如搜索与歧义处理的规则不同）。

### 2.3 核心过程

- **轨迹归一化**：将原始轨迹映射为统一事件序列，保留工具调用、参数、观测摘要、写入和验证反馈；用占位符替换任务特定值，但保留日期、时间和操作顺序。
- **构造中间产物**：
  - 函数观测：单个可调用函数的参数、返回形式、副作用和结果。
  - 任务对比包：同一任务的多条源轨迹的差异信息。
- **Reflector**：基于对比包和相关现有卡片，输出最多 3 个候选技能增量；约束是所有字段必须有证据支持；若全部轨迹都失败，则只允许诊断/恢复增量，禁止编造成功配方。
- **Curator**：对每个候选增量选择最小的合法编辑操作，包括 ADD、PATCH、MERGE、NARROW、NOOP；保证语义封闭，防止引入证据外的新规则，避免记忆漂移和冗余积累。
- **检索与注入**：语料库中技能卡按 BM25 相关性排序，加入应用域重叠软加分与领域不匹配惩罚；功能卡在任务开始和工具调用前注入。注入记忆均为“软指导”，实时观测优先。

### 2.4 检索公式

技能卡检索得分采用如下公式（论文公式 1）：

```
s(c; x) = BM25(q(x), d(c)) + λ * 1[apps(c) ∩ apps(x) ≠ ∅]
```

其中 `q(x)` 是任务查询，`d(c)` 是卡片的标题/触发词/标签/核心规则索引，λ 为软先验权重，只影响排序不硬性屏蔽跨域迁移。

### 2.5 跨基准适配

- **GAIA2/ARE**：用能力标签控制技能反射焦点。
- **AppWorld**：用确定性任务签名（答案抽取、批量/多写入、状态写入、跨应用、默认）替代能力标签，且 Function/API Cards 遵循“文档增量”规则，只记录文档之外的经验证据，避免重述官方 API 文档。

## 6. 论文的主要结论与发现

1. **异构多模型轨迹能作为程序性监督**：对比同一任务的多个模型轨迹，可以揭示决策边界，比单条轨迹总结或同模型多次采样更有效。
2. **成功率显著提升**：GAIA2/ARE 上三个源目标平均成功率从 26.2% 提升至 55.3%（翻倍以上），每个目标均有 +24.5~+33.5 个百分点增益。
3. **跨模型迁移**：同一记忆库不变地迁移到未见过的 Qwen3.7 Plus，成功率从 18.5% 提升至 35.5%，说明学到的是可迁移的程序性知识而非模型特定行为。
4. **跨基准验证**：同样的构建方式在 AppWorld 上也全部优于无记忆和自记忆条件；Test-Normal TGC 从 54.4% 提升至 75.0%，Test-Challenge 从 42.7% 提升至 57.4%。
5. **对比多样性大于更多采样**：在匹配轨迹数量下，三模型异构轨迹优于 GPT-5.5 自身的三次 rollout（宏平均 77.5% vs 70.0%），说明收益来自对比式行为多样性，而不是更多数据。
6. **局部策展优于追加式累积**：Curator 将技能卡数量减少 24.9%，同时提升成功率（append-only 65.0% → curated 71.9%），证明紧凑、有选择的记忆更有效。
7. **两级记忆互补**：Skill Cards 对搜索/歧义更重要，Function Cards 对执行类写入更重要，二者组合最好。
8. **过程性记忆的边界**：对 Time 能力提升有限（如 GPT-5.5 从 3/40 提升到 7/40），跨模型证据无法替代运行时控制器；时间敏感失败需要持续性状态追踪与异步监控机制。

## 7. 优点

- **无需模型训练**：纯离线轨迹蒸馏 + 冻结记忆注入，可即插即用。
- **源灵活、低代价**：可从单模型轨迹获益，异构多模型效果最强；构建成本比 ACE 等 playbook 方法低一个数量级。
- **对比式学习思路的新应用**：将对比学习理念从表征空间迁移到智能体行为空间，但不需要任何嵌入或对比损失。
- **记忆结构化、可解释**：两级卡片（应用级 Function Cards + 任务级 Skill Cards）分离工具契约与任务决策，便于定位问题和解释注入效果。
- **局部策展保证紧凑和抗漂移**：用 ADD/PATCH/MERGE/NARROW/NOOP 做最小编辑，避免了 append-only 造成的冗余和错误累积。
- **实验设计严谨**：跨两个基准、多模型、多条件验证；有成本/效率度量；有严格的证据校验、隐私校验和检索防泄漏校验。
- **检索经济**：运行时只注入少量任务相关卡片（约 1.1~1.8k tokens），不干扰主 agent 的上下文结构，也可作为软指导与现有 agent 框架兼容。

## 8. 不足与局限

- **覆盖范围受限于源轨迹**：CONTR

**覆盖范围受限于源轨迹**：CONTRAMEM 的所有知识都来源于源模型在参考任务上的轨迹。如果参考任务集没有覆盖某种应用状态、工具组合或失败模式，记忆库就无法提供相应指导。对全新的应用或全新类型的任务，系统面临冷启动问题，需要重新采集足够多样的多模型轨迹才能构建有效记忆。

- **无法替代运行时状态追踪**：对于 Time 等依赖持续状态监测的能力，论文自身也承认提升有限。记忆卡本质是静态的决策规则，无法补偿控制器在异步事件感知、状态过期检测和长期目标追踪上的缺陷；这类失败需要架构级的记忆机制（如持久化工作内存）而非注入式软指导。

- **依赖验证器或可判定结果的存在**：对比学习信号的核心是“成功 vs 失败”的判定。在验证器不可用、奖励信号稀疏或任务结果难以自动判定的场景中，Reflector 难以准确定位决策边界，候选技能增量的构建会退化为近似启发式。

- **构造环节仍需人工介入与监管**：虽然不需要训练，但数据清洗、脱敏、证据校验、卡片审核（尤其是 Function Cards 的“文档增量”规则要求）仍需要人工或强模型参与，存在一定的工程成本。论文未完全自动化评估卡片质量，若源轨迹污染严重，记忆库可能会注入误导性规则。

- **检索机制相对朴素**：BM25 加应用域软加分的检索方式在跨任务泛化上表现不错，但对语义近似但表述不同的任务难以完全匹配。论文没有尝试向量检索、学习式排序或动态记忆选择，可能存在进一步提升的空间。

- **隐私与安全边界未被充分讨论**：虽然论文声明了脱敏处理和证据约束，但轨迹数据本质上可能包含用户敏感信息（如邮件内容、日历事件）。记忆库在多租户或跨组织共享时，如何保证不泄露源任务数据，论文未给出机制层面的设计。

- **多模型轨迹的采集在现实中受限**：需要同时在多个模型上运行相同任务，这在 API 成本、数据合规、模型可用性方面都可能成为瓶颈。单模型自记忆虽然也有收益，但论文的实验表明，其效果显著低于异构对比模式。

- **评估基准的类型学局限**：GAIA2/ARE 与 AppWorld 都属于应用操作类智能体任务，且两者的验证器都相对明确。对于开放式创作、多轮对话决策、物理世界操作等领域，CONTRAMEM 的适用性尚未被验证，结论的外部效度存在边界。

## 9. 总体评价与展望

总体而言，CONTRAMEM 是一个**思路简洁、执行扎实、结果显著**的无需训练的程序性记忆框架。它的核心贡献不在于发明新的模型架构或训练目标，而在于重新定义了“记忆如何产生”：不再把记忆视为单条轨迹的摘要或个人经验的积累，而是把多个异构模型在同一任务上的**分歧与共识**作为监督信号，提炼出跨模型可迁移的决策规则。这种“事故复盘式”的对比学习思路，在智能体系统逐步走向长时程、多应用协作的当下，具有明确的理论意义和工程价值。

论文的实验设计和实现质量同样值得肯定：跨基准、跨模型、跨能力的系统验证，配合成本度量、消融测试和统计显著性检验，使结论具有较强的说服力；对 AWM/ACE 的离线复现也体现了对比的透明性。尽管存在冷启动、静态记忆、检索朴素等局限，但这些更应视为未来工作的方向而非对论文价值的削弱。随着多模型环境和 agent 基础设施的进一步成熟，基于异构轨迹对比的记忆构建机制，有望与在线强化学习、运行时状态追踪和结构化世界模型相结合，成为自主智能体可靠性的重要支柱。

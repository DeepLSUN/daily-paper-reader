## 摘要
现代科学设施和仪器生成的数据集规模巨大，单个研究人员难以发现、访问和探索这些数据。尽管许多数据集是公开可用的，但使用它们通常需要熟悉存储库组织、数据格式、多分辨率结构和可视化参数。我们提出了WebVisus，一个受约束且资源感知的多智能体系统，用于发现并自主探索远程、多分辨率的科学数据集。给定自然语言研究问题，WebVisus识别用户意图并启动一个自主探索智能体，该智能体在检查切片、体积和时间步长的同时，根据可用的客户端内存和计算资源调整数据分辨率和检索质量。这种设计支持渐进式探索，无需完全下载数据集或手动配置低级可视化参数即可使用自然语言进行操作。我们报告了系统架构、受约束的智能体协议、资源感知的访问机制，以及评估跨科学数据集的自主视觉探索和资源感知智能体访问的案例研究。

## Abstract
Modern scientific facilities and instruments generate datasets at scales that are difficult for individual researchers to discover, access, and explore. Although many datasets are publicly available, using them often requires familiarity with repository organization, data formats, multiresolution structures, and visualization parameters. We present WebVisus, a constrained and resource-aware multi-agent system for discovering and autonomously exploring remote, multiresolution scientific datasets. Given a natural-language research question, WebVisus identifies the user's intent and launches an autonomous exploration agent that examines slices, volumes, and timesteps while adapting data resolution and retrieval quality to available client memory and computational resources. This design supports progressive exploration without complete dataset downloads or manual configuration of low-level visualization parameters using natural languages. We report the system architecture, constrained agent protocol, resource-aware access mechanism, and case studies evaluating autonomous visual exploration and resource-aware agentic access across scientific datasets.

## 2. 论文提出的方法论

### 2.1 系统总体架构

系统由三个控制层组成：
- **浏览器客户端**：提供 Catalog（目录）和 Playground（工作台）两个交互界面。
- **应用服务器**：维护目录索引，验证智能体动作，强制执行资源限制。
- **云端 LLM 服务**：基于 Microsoft Foundry 的 Azure OpenAI 部署，支持 DeepSeek-V4-Flash、Grok-4.3、Kimi-K2.6、GPT-5.4-Pro、GPT-5.4、o3-mini 等多个模型后端，部分支持多模态视觉输入。

关键设计原则：**推理委托给模型后端，而可执行操作始终由确定性的应用组件控制**，模型无法直接访问浏览器 DOM、操作系统或数据服务。

### 2.2 目录锚定的多智能体运行时

系统包含三个专业化的后台智能体：

| 智能体 | 职责 |
|---|---|
| **Orchestrator（编排者）** | 解释用户目标，分解为结构化计划，不直接查询目录或发出可视化命令，根据下游输出修订计划 |
| **Catalog Agent（目录智能体）** | 调用固定工具集：检索目录统计、列出分组、搜索元数据、推荐数据集、将数据集名称解析为具体位置 |
| **Executor（执行者）** | 将计划和目录结果翻译为类型化动作，发出中间状态更新，触发下一轮 Orchestrator 推理 |

当前目录快照索引了 **约 1,400 个数据集、40+ 分组**，覆盖气候模拟、生物医学体积、材料科学产品、显微图像等。

### 2.3 受约束的动作协议

- 定义了**注册的规范化命令词汇表**：目录接口（搜索、预览、选择）和 Playground 接口（加载数据、选择质量与访问模式、切换时间步、应用颜色映射、放置正交切片、添加等值体、修改不透明度、控制视角等）。
- 注册表之外的命令、参数无效或违反资源/安全约束的命令会被**确定性拒绝**。
- 每次 Playground 请求附带当前状态的紧凑表示（数据集、访问模式、时间步、质量等级、可视化节点），启用多模态推理时还附加渲染快照。
- 所有成功与失败的操作均被记录到交互转录（transcript），保证可审计性。

### 2.4 资源感知的渐进式访问

**内存感知的分辨率选择**：
- 使用轴细化字符串 s ∈ {0,1,2}* 描述分辨率——每个符号表示沿某空间轴细化一次（0=X、1=Y、2=Z）。
- 设 n₀(s)、n₁(s)、n₂(s) 分别代表三个轴方向的细化次数，结果数组形状为：

  **R(s) = (2ⁿ⁰⁽ˢ⁾, 2ⁿ¹⁽ˢ⁾, 2ⁿ²⁽ˢ⁾)**

- 对每样本 b 字节的数据，估算的解码后内存占用为：

  **M(s) = b · 2^(n₀(s) + n₁(s) + n₂(s))**

- 给定内存预算 B，系统选择满足 M(s) ≤ B 的最细可行细化字符串。

**双重资源检查**：
1. **服务器端**：控制加载到服务器内存的数据量；
2. **浏览器端**：控制传输到并显示在浏览器中的数据量。

若请求超出预算，系统可降低质量、缩小区域、选择切片替代体积、或限制时间步访问。资源决策对用户可见且可手动覆盖。

### 2.5 可视化管线

- 二维数组：Plotly.js 展示。
- 三维数组：Three.js 驱动的 WebGL 管线，采用 ParaView 风格管线组织体积源、正交切片、等值体频带、传输函数、不透明度与相机控制。
- 切片位置、颜色映射、不透明度、等值范围、相机设置的更改都在缓存的纹理上操作，**无需额外数据检索**；只有数据集、分辨率、空间选择、访问模式或时间步变化时才发起新请求。

### 2.6 自主探索智能体（Observe-Plan-Act-Evaluate 循环）

每次迭代：
1. **Observe**：观察当前 Playground 状态，包括数组形状、值统计、参数、近期操作、渲染快照；
2. **Plan**：模型评估当前状态与科学目标，提出少量动作；
3. **Act**：分辨率/空间/访问模式/时间变更由资源策略评估；切片/等值/不透明度/颜色映射/相机操作在缓存表示上执行；
4. **Evaluate**：等待加载和渲染完成，根据结果（数组形状、延迟、可视化状态、渲染图像）决定下一步——可提高分辨率、缩小范围、换轴/切片、调整传输函数、或在延迟过大时触发客户端退避机制降低检索设置。

**终止条件**：目标判断完成、达到固定步数上限、或用户发出停止命令。最终生成基于观察序列、界面状态和渲染视图的总结。

## 6. 论文的主要结论与发现

1. **渐进式访问本身不足以保证交互式自主操作**——所选表示必须同时考虑计算环境和当前步骤的信息需求。固定高分辨率会引入长时间延迟甚至超出内存限制，而永久粗粒度策略可能无法揭示相关特征。
2. **资源自适应策略有效**：在案例研究中，约 0.16 秒的渐进式检索即可支持代理拒绝默认视图、检查多个轴、调整等值体参数并识别内部空间变化，而无需将约 11 GB 的逻辑体积下载到本地。
3. **受约束动作协议安全可行**：所有动作都限定在注册命令集内，代理无法访问 DOM、shell 或操作系统，执行过程可审计、可中断、可覆盖。
4. **自主代理能够从失败中恢复**：尽管存在动作依赖导致的初始失败（如未创建节点即修改参数），代理仍完成了全部工作流，但也凸显了对命令前置条件验证和更强恢复策略的需求。
5. **响应时间随数据大小非线性增长**：大传输（>256MB）可能使自主执行停滞，小规模表示（MB 级）更适合迭代式闭环探索。
6. 系统的产出属于**探索性的初步接触评估**，需领域专家验证后方可得出科学结论——这是作者明确声明的边界。

## 7. 优点

1. **端到端闭环完整性**：首次打通自然语言目标 → 元数据锚定的数据集发现 → 资源可行的远程访问 → 迭代式视觉探究 → 可审计总结的完整链路，填补了现有系统在“数据集选择前”的空白。

3. **受约束的安全设计**：语言模型只能提出注册命令，执行层进行确定性验证和拒绝；这使系统具备“能力受限但可审计”的部署安全性，不同于直接暴露工具给模型的常见做法。

6. **可审计可干预**：所有资源决策和动作记录在转录中，用户可随时停止、覆盖或检查任何决策，保留了人类对科学解释的控制权。
7. **支持的模型后端多样**：兼容多个 LLM 提供商，降低了对单一模型的依赖风险。

## 8. 不足与局限

1. **科学测量能力缺失**：系统仅进行探索性视觉导航和可视化，不支持经过验证的科学测量、时间比较、特征检测或数值分析——“找到感兴趣的结构”不等于“确认科学结论”。
2. **缺少量化评估框架**：未报告信息增益、探索覆盖率、与领域专家评估的一致性等客观指标，导致系统性能难以与其他方法横向比较。
3. **无重复性和稳定性数据**：每个工作流只运行一次，未报告多次运行的方差、成功率或可重复性，无法判断系统是否可靠地复现同样发现。
4. **无对照实验**：未与固定分辨率策略对比，也未分析自适应访问策略相对于简单基线（如始终取最大可行分辨率）的全局收益和局部损失。
5. **动作失败率较高（13.8%）**：频繁出现“修改参数前未创建节点”的命令前置条件问题，尽管未影响最终任务完成，但反映计划的内部一致性有待改进。
6. **可扩展性证据有限**：虽然目录包含约 1,400 个数据集，但实验中仅使用了少量数据集，未对大规模并发访问、多用户场景和更大目录规模下的系统行为进行测试。
7. **未测量浏览器端渲染性能**：延迟测量集中在数据和加载层面，对客户端内存使用和渲染帧率没有导出定量数据。
8. **资源与推理成本的透明度不足**：论文未披露完整的硬件配置和 token 使用与科学产出之间关系，这对判断系统的实际部署门槛有影响。
9. **模型依赖风险**：

9. **模型依赖风险**：系统将推理（规划、状态评估、动作选择）完全委托给云端 LLM 服务，论文未报告不同模型后端在同一任务上的性能差异、失败模式差异或 token 消耗差异；若底层模型更新或替换，系统行为的一致性和可预测性缺乏保障机制。此外，智能体的决策质量依赖于模型对科学可视化上下文（如传输函数效果、等值体语义）的视觉理解能力，这类能力的边界未被系统评估。

10. **评估偏向 LLM 能力而非系统机制**：端到端工作流的成功在很大程度上取决于所选模型的指令遵循能力和视觉推理能力，论文的实验设计未能将"系统机制（如资源策略、目录锚定、约束验证）的贡献"与"模型本身能力的贡献"分离开来。

11. **对数据语义的理解停留在表层**：代理对数据集的理解主要基于名称、元数据和数值统计，缺乏对数据生成过程、物理量含义、单位、坐标系等科学语义的深度融合，这限制了其在复杂科学问题上的自主性。

12. **用户覆盖与交互方式有限**：系统的"自主"模式基本排除了用户的实时参与，用户只能在任务启动前给定目标和任务结束后审阅总结；对于需要领域知识动态引导的探索场景，系统缺乏"人在回路"的灵活交互模式（如中途提问、重定向、局部深入等）。

## 9. 可复现性分析

论文在可复现性方面存在明显的两面性：

**有利因素**：
- 系统架构描述清晰，三层控制结构和智能体职责划分明确；
- 动作协议以注册命令词汇表的形式给出，具有规范性；
- 资源估算的数学模型（内存估算公式、轴细化字符串）定义严谨，足以支撑独立重实现；
- 数据规模、迭代步数、token 消耗等运行指标有记录。

**不利因素**：
- 未提供代码仓库链接、开源许可证或具体版本信息（论文分析中未见可获取的公开实现）；
- 未披露 LLM 调用的具体参数（如温度、top-p、max tokens、重试策略、提示词模板内容）；
- 未提供目录快照的完整元数据 schema 和数据集的具体获取方式；
- 未报告硬件配置和服务端部署细节；
- 五个端到端工作流均无原始交互转录（transcript）的附录或链接，无法逐动作验证系统行为。

**结论**：系统机制层面的可复现性较好，但实验运行层面的可复现性不足，第三方难以在相同条件下复现所报告的结果。

## 10. 对未来研究方向的启示

1. **引入科学测量工具**：将可视化探索与量化分析（如体积累分、连通域分析、特征提取、剖面线测量）结合，使智能体不仅能"看到"结构，还能"度量"结构。
2. **构建量化评估基准**：需要一个公共基准数据集集合 + 标准任务协议 + 客观指标（如结构发现率、探索效率、与专家标注的一致性），使不同自主可视化系统之间可横向比较。
3. **多轮次可重复实验**：同一任务多次运行以测量方差，分析模型温度和随机性对探索路径的影响。
4. **分层资源策略的精细比较**：与固定分辨率基线、随机动作基线、人工探索基线进行系统的对照实验，量化资源感知策略的增量价值。
5. **多模型鲁棒性研究**：系统性地对比不同 LLM 后端在相同任务上的成功率和行为差异，建立模型选择指南。
6. **更丰富的人机交互模式**：支持探索过程中动态注入领域知识或用户偏好，实现"共同驾驶"式的人机协同分析。
7. **扩展到更广泛的数据类型和分析任务**：将系统从可视化探索扩展到数值模拟验证、多数据集比较、时间序列分析等更复杂的科学工作流。
8. **语义知识图谱的融合**：将数据集元数据与领域本体（如气候变量字典、材料属性标准）连接，使智能体的规划具备科学语义约束。

## 11. 总体评价

WebVisus 是一篇典型的**系统设计 + 可行性验证**性质的工作。其核心贡献在于将大型语言模型的推理能力与资源感知的渐进式数据访问机制结合，首次系统性地弥合了从自然语言科学目标到远程多分辨率数据实际操作的闭环缺口。系统的设计体现了工程上的务实智慧：将推理委托给云端模型、将执行锁定在确定性组件手中，这一架构选择既规避了智能体直接操作环境的安全风险，也保留了 LLM 在规划方面的灵活性。

然而，论文在实验验证强度上属于**初步探索**而非**严格验证**。五个单次运行的工作流和缺少基线对照的实验设计，使其更接近于一个"概念证明"（proof of concept）而非"方法比较"（method comparison）性质的研究。所有结论都应在此定位下解读。

尽管如此，该工作所提出的目录锚定智能体运行时、受约束动作协议、内存感知分辨率选择等设计模式，对 AI 辅助科学探索这一迅速发展的领域具有明确的参考价值和启发意义，特别是在"如何在资源受限的远程数据环境中有效地利用 LLM 进行自主科学发现"这一问题上，提供了一个值得借鉴的系统模板。

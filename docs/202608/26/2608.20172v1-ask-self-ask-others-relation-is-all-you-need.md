## 摘要
注意力机制直接根据成对分数推导归一化信息流。我们引入了一种替代的标记混合基元——关系（Relation），它首先将成对证据组织为明确的自我（Self）关系和交换（Exchange）关系，然后据此推导信息流。这种关系组织催生了全关系（Full Relation）、闪关系（FlashRelation）、线性关系（Linear Relation）、混合关系（Hybrid Relation）以及一种键值风格的关系缓存（KV-style Relation Cache）。在参数规模约为1000万、3000万和1亿的匹配解码器模型上，全关系在所有三个规模上均实现了比多头注意力（MHA）更低的最终验证负对数似然（NLL）。在固定上下文参考基准测试中，闪关系的速度是物化全关系实现的3.60至4.41倍。在规模匹配的生产工作负载中，它在执行全关系算子的同时达到了PyTorch FlashAttention吞吐量的76.4%至84.9%。混合关系使用75%的线性关系层，实现了强大的语言建模质量。这些结果支持了一种关系优先的标记混合观点：问自己，问他人，然后让信息流遵循关系。

## Abstract
Attention directly derives normalized information flow from pairwise scores. We introduce Relation, an alternative token-mixing primitive that first organizes pairwise evidence into explicit Self and Exchange relations and derives information flow afterward. This relational organization gives rise to Full Relation, FlashRelation, Linear Relation, Hybrid Relation, and a KV-style Relation Cache. Across matched decoder-only models at approximately 10M, 30M, and 100M parameters, Full Relation achieves lower final validation NLL than MHA at all three scales. In a fixed-context reference benchmark, FlashRelation is 3.60-4.41x faster than the materialized Full Relation implementation. Across scale-matched production workloads, it reaches 76.4-84.9% of PyTorch FlashAttention throughput while executing the Full Relation operator. Hybrid Relation uses 75% Linear Relation layers and achieves strong language-modeling quality. These results support a relation-first view of token mixing: ask Self, ask Others, then let Flow follow Relation.

## 一、核心问题与整体含义（研究动机与背景）

- **注意力机制的固有缺陷**：在标准缩放点积注意力（Scaled Dot-Product Attention）中，一对 token 的交互被压缩为单个标量分数，该分数同时承担了“关系编码”和“信息流分配”两重功能，即通过 `U → F`（相似度 → 归一化权重）一步完成。论文认为 token 交互在本质上是异质的（heterogeneous），一个标量负载过重，导致关系形成（relation formation）与流动分配（flow allocation）被不恰当地压缩进单一操作。
- **关系在现有架构中的从属地位**：在 Shaw et al. (2018) 的关系感知注意力（Relation-aware Attention）中，关系只是增强注意力的辅助机制，Attention 仍是主导者。论文主张彻底反转这一层级：**Flow follows Relation**（流动跟随关系）。
- **研究主张**：提出一种名为 **Relation** 的替代性 token 混合原语。其基本思想是：先在归一化之前将成对证据（pairwise evidence）显式地组织为 **Self（自我）**与 **Exchange（交换）**两种角色，再据此推导归一化信息流。论文以此支持一种“关系优先”（relation-first）的 token 混合观点：*先问己，再问人，然后让流动跟随关系*。

## 二、方法论：核心思想、关键技术细节与算法流程

### 1. 自我–交换关系（Self–Exchange Relation, SER）

- **输入投影**：将输入序列 X 投影到两个关系空间和一个信息空间：
  - `P₁ = XW₁`、`P₂ = XW₂`、`I = XW_I`
  - 成对证据（pairwise evidence）：`U_{ij} = (p₁ᵢᵀ p₂ⱼ) / √d_h`
  - P₁、P₂ 进入 U 时使用 RoPE，I 不旋转。
- **关系构建**：将关系拆分为两个最小结构角色：
  - **Self**（对角线）：`Sᵢ = σ(Uᵢᵢ / τ_S)`，其中 τ_S = 2
  - **Exchange**（因果历史上）：`Eᵢⱼ = SiLU(Uᵢⱼ)`
  - 组装为因果关系矩阵 R：对角为 Sᵢ，历史位置为 `Eᵢⱼ − λ_ℓ log i`（含可学习的对数计数校准），未来位置为 −∞。
- **信息流推导**：仅在关系矩阵构建完成后应用 Softmax：`Fᵢ = Softmax(Rᵢ)`，然后进行信息传输：`Yᵢ = Σ_{j≤i} Fᵢⱼ Iⱼ`。

### 2. 多头关系（Multi-Head Relation, MHR）

- 将关系空间和信息空间划分为 H 个子空间，每个头独立进行 SER 构建。
- **Givens 旋转混合**：在相邻头对之间用可学习的 Givens 旋转混合信息状态，配对模式在层间交替（M_A → M_B → M_A → …），保持信息范数不变。

### 3. 精确的自我–交换流因子分解

- 归一化流可被精确分解为两个层级：
  - **第一层**：Self 质量 `Fᵢᵢ` 与聚合 Exchange 质量 `gᵢ` 的竞争，由 `Aᵢ − Sᵢ` 决定：
    - `Fᵢᵢ = σ(Sᵢ − Aᵢ)`，`gᵢ = σ(Aᵢ − Sᵢ)`，且 `Fᵢᵢ + gᵢ = 1`
  - **第二层**：在 Exchange 内部，质量 gᵢ 按相对 Exchange 关系 Eᵢⱼ 在历史 token 间分配：
    - `π^Eᵢⱼ = Softmax_{j<i}(Eᵢⱼ)`，`Fᵢⱼ = gᵢ · π^Eᵢⱼ`
- **语义**：Relation 首先决定 token 是靠自身还是从历史中汲取；若从历史汲取，再决定去历史中的何处寻找。

### 4. 实践变体

- **Full Relation**：显式的 token 到 token 操作，即第 3 节定义的原始算子。
- **FlashRelation**：利用因子分解，采用因果分块扫描（causal tiled scan），维护运行最大值 m、归一化器 l 和信息累积器 z，不物化完整 R 或 F 矩阵，是 Full Relation 的**精确**执行（并非近似）。
- **Linear Relation**：将历史 Others 压缩为循环状态 `C_t ∈ R^{d_h × d_h}`，采用输入相关的通道级保留（retention）参数化（类似 KDA），执行顺序为：Ask Self → Ask Others → Answer → Become Others。复杂度为 O(Td²/H)，解码状态为 O(d²/H)。
- **Hybrid Relation**：在单个解码器中交替组合 Linear 与 Full Relation 层（文中采用九层 Linear 加三层 Full，布局为 (LLLF)₃）。
- **Relation Cache**：推导出 KV 风格的自回归缓存 `C_t = {P₂,₁:ₜ, Ĩ₁:ₜ}`——只需缓存历史 P₂ 和信息状态 Ĩ，历史 P₁ 不再复用；缓存大小 O(Td)。

## 六、主要结论与发现

1. **质量优势**：在 10M、30M、100M 三个规模下，Full Relation 的最终验证 NLL 均低于匹配的 MHA 基线，分别改善 0.0412、0.0151、0.0310。
2. **结构性消融结论**：移除计数校准（λ_ℓ = 0）或使用单头均造成较大退化（Δ ≈ +0.05），表明计数校正和多头关系构建是重要组件；Givens 混合贡献较小（Δ ≈ +0.003）但仍为正。
3. **高效执行**：FlashRelation 相比物化的 Full Relation 实现提速 3.60–4.41 倍；在规模匹配生产环境中达到 PyTorch FlashAttention 吞吐量的 76.4%–84.9%（约 0.76–0.85×）。
4. **Hybrid 可行性**：75% Linear Relation 层（9/12 层）+ 25% Full Relation 层的混合架构达到 1.2780 的最终验证 NLL，优于同设置下的纯 MHA。
5. **范式意义**：结果表明 token 混合不必直接围绕信息流组织，可以先构建关系、再推导流动，即“关系优先”范式是可行且有实际价值的替代路径。

## 七、优点（亮点）

1. **概念创新性**：将注意力中“一个标量同时编码关系与流”的耦合显式解耦，提出“先关系、后流动”的清晰层级，概念上简洁有力。
2. **严格的数学推导**：对 Self–Exchange 流给出了精确的因子分解（Self 质量、聚合 Exchange 质量与历史内部分配），这种分解同时支撑了 FlashRelation 的精确分块执行和计算效率。
3. **实践完整性**：同一思想衍生出 Full、Flash、Linear、Hybrid 和 Cache 五种实践形式，覆盖了显式历史、高效执行、循环压缩和自回归解码等关键需求，形成了完整的算子族。
4. **实验设计规范**：配对种子、匹配几何、严格随机对照、多任务评估和公平的系统对比，整体实验设计规范可信。
5. **效率与质量兼顾**：FlashRelation 在保持精确算子的前提下实现了接近 FlashAttention 的吞吐量；Hybrid 展示了以线性层为主仍保持强性能的工程实用性。

## 八、不足与局限

1. **规模受限**：实验仅覆盖约 1000 万至 1 亿参数的 decoder-only 语言模型，训练预算最大为 10.71 亿 tokens。在更大规模（如 1B+ 参数）上的表现尚未验证。
2. **场景覆盖不足**：仅评估了语言建模场景；多模态（multimodal）、后训练（post-training）、指令微调等场景的关系算子行为仍是开放问题。
3. **配置代表性有限**：Linear Relation 与 Hybrid Relation 仅评估了选定配置（如特定的 Linear/Full 比例和层排列），尚未系统探索最佳配置。
4. **Relation Cache 仅数学推导**：论文指出 KV 风格 Relation Cache 是“数学上建立的”，未给出其在实测推理中的吞吐或延迟对比结果。
5. **算力信息不完整**：未报告训练阶段的具体 GPU 数量、训练时长和总体算力成本，不利于复现和成本评估。
6. **次要基准表现参差**：在 BLiMP 的 100M 规模上，Full Relation 相比 MHA 反而有约 −0.008 的准确率下降；在 LAMBADA 的 30M 规模上也有明显退化（PPL 从约 133 升至约 203），提示关系算子在部分下游任务上的迁移优势尚不稳定。
7. **温度参数固定**：Self 温度 τ_S 固定为 2，论文声明不视为理论最优，但也未提供敏感性分析。

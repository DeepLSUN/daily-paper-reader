## 摘要
大型语言模型（LLM）在文本理解和生成方面表现出色，但仍难以可靠地理解并大规模应用外部提供的程序性规则。为了评估这一能力，我们引入了RuleWorld，一个大规模基准测试，将规则重新表述为全局可重用的抽象单元，而非实例特定的事实。RuleWorld中设置了多个场景，包括单规则、并行多规则和多跳推理，以进行全面评估。我们进一步提出了DynaRule，一个端到端框架，将给定规则注入KV缓存，并将检索转化为内部可学习的逐步过程。具体而言，DynaRule采用堆叠式逐步注意力训练，并使用特殊的<search>标记，使模型在推理过程中能够动态重新关注规则并更新规则。通过这种方式，模型可以在每一步重新关注最相关的规则，动态替换过时的规则，以支持更稳定的多步推理。在RuleWorld上的实验表明，现有LLM在大型规则池下面临挑战，而DynaRule将平均QA准确率提高了多达19个百分点，并在10K规则下实现了超过85%的Recall@1，大幅优于强基线。我们的代码和数据集可在以下网址获取：https://github.com/SharkSpicy-NLP/Beyond-Factual-Knowledge。

## Abstract
Large language models (LLMs) excel at text understanding and generation, yet still struggle to reliably understand and apply externally provided procedural rules at scale. To evaluate this capability, we introduce RuleWorld, a large-scale benchmark that reformulates rules as globally reusable abstract units rather than instance-specific facts. In RuleWorld, several scenarios, including single-rule, parallel multi-rule, and multi-hop reasoning, are settled for comprehensive evaluation. We further propose DynaRule, an end-to-end framework that injects the given rules into the KV cache and turns retrieval into an internal, learnable, step-wise process. Specifically, DynaRule employs Stacked Step-Level Attention Training with a special <search> token to enable dynamic rule re-attention and updating during inference. In this way, the model can re-attend to the most relevant rules at each step, dynamically replacing outdated ones to support more stable multi-step reasoning. Experiments on RuleWorld show that existing LLMs face challenges under large rule pools, while DynaRule improves average QA accuracy by up to 19 points and achieves over 85% Recall@1 at 10K rules, outperforming strong baselines by large margins. We make our code and dataset available here: https://github.com/SharkSpicy-NLP/Beyond-Factual-Knowledge.

- **背景与动机**：大型语言模型（LLM）在事实性知识理解与生成上表现优异，但在理解和应用外部提供的“程序性规则”（procedural rules）时仍不可靠。现有规则推理基准（如 ProofWriter、FOLIO、RuleArena 等）通常把规则当作“每道题附带的前提”，而不是一个全局共享、可复用的规则库，因此难以评估模型是否真的能从大型规则库中定位正确规则，并在多步推理中稳定应用。
- **核心问题**：论文提出两个关键挑战：
  1. 抽象规则与问题表面形式弱匹配，导致大规模规则检索和应用脆弱；
  2. 在多步推理中，目标规则随步骤变化，需要逐步动态的规则选择与更新能力。
- **整体含义**：论文旨在弥补“事实性知识”与“显式规则接地”之间的差距，通过新基准和新方法推动 LLM 的程序性规则推理能力评估与提升。

## 2. 提出的方法论

- **RuleWorld 基准**：
  - 包含 494 万条外部程序性规则，采用 FOL（一阶逻辑）和 NL（自然语言）两种形式。
  - 规则设计为抽象、非常识、与实体无关，避免模型依赖内化知识。
  - 规则分为 4 大类型（Attribute、Environment、Action、State）和 7 个子类型，支持跨类型组合（如 Action 改变 Environment，进而触发 State 变化）。
  - 三种 QA 类型：
    - **Single-Rule QA**：5 万实例，应用单条规则；
    - **Parallel Multi-Rule QA**：325 万实例，每条包含最多 8 条独立规则的总和问题；
    - **Multi-Hop Rule QA**：7.77 万实例，最多 4 跳的链式推理。
  - 共形成 11 个子任务，通过改变“黄金规则数”和“跳数”控制难度。

- **DynaRule 框架**：
  - 核心思想：将外部规则编码后注入 LLM 的 KV 缓存，把“检索”变成内部可学习的逐步过程。
  - 规则用预训练句子编码器（如 Qwen3-Embedding-8B）编码，并通过单层适配器映射到模型隐藏空间，注入到指定层（confidence layer）的 KV 缓存。
  - **两阶段训练**：
    1. **置信层识别**：在所有层中寻找对注入规则注意力熵最小的层（即最聚焦于少数相关规则的层），作为规则选择和训练的专用层。
    2. **堆叠式逐步注意力训练（Stacked Step-Level Attention Training）**：
       - 引入特殊 token `<search>`，插在多步答案各步骤之间，作为该步检索的查询触发；
       - 第 1 步用问题 token 计算规则注意力；后续步骤用 `<search>` 的隐状态作为查询；
       - 构造包含 Top-K 候选和所有步骤黄金规则的共享候选池，将其他步骤的黄金规则作为难负样本；
       - 损失函数为：`L = Llm + Ls^(l)`，其中 `Llm` 是标准自回归语言建模损失，`Ls^(l)` 是堆叠式逐步注意力损失（带温度系数 T 的交叉熵）。
  - **推理过程**：Prefill 阶段在置信层做 Top-K 规则选择；解码时若模型输出 `<search>`，则用该 token 重新计算规则注意力，并用新选规则替换 KV 缓存中的旧规则，实现逐步动态更新。

## 6. 主要结论与发现

- 现有 LLM 及 RAG/KBLaM/SR-KI 等基线在大规则池下性能显著下降，尤其在并行多规则和多跳任务上；
- DynaRule 在不同规则规模下均取得最佳结果：
  - 平均 QA 准确率最多提升约 19 个百分点，特定子任务提升最高达 48 个百分点；
  - 在 10K 规则下 Recall@1 超过 85%，Recall@10 超过 90%，比最强基线高 60 余个百分点；
- 置信层在不同模型规模、系列和编码器下均稳定出现，且与 FOL/NL 表示无关；
- 逐步注意力可视化显示，模型在每一步能把注意力集中到该步所需规则上，形成“阶梯式”分布；
- 对未见规则的泛化实验表明，适配器学到的是“规则嵌入到内部状态的可迁移对齐”，而非死记训练规则库；
- 仅给黄金规则时，强模型能达到较高准确率（74%–89%），说明主要瓶颈在于“规则定位”而非“规则应用”本身；
- 效率方面，KV 缓存注入比长提示注入更省内存和时间，`<search>` 带来的额外开销很小。

## 7. 优点

- **基准设计有针对性**：RuleWorld 强调“全局共享规则池 + 从大池中检索 + 跨实例复用”，比现有“每问给规则”的基准更贴近现实规则系统的使用方式；

- **方法创新性强**：把规则检索变成内部可微分的逐步过程，用 `<search>` token 实现“按需检索”和动态更新，端到端联合训练检索与推理；

- **结果稳健**：报告标准误和置信区间，并在多个模型规模上验证置信层的普适性。

- **规则表达形式有限**：目前仅支持 FOL 和 NL，未涵盖可执行代码或更复杂的结构化规则（如编程函数、逻辑程序、时序逻辑等）。实际工业场景中的许多规则是以代码或脚本形式存在的，论文未验证该方法对这些形式的适配性；
- **规则规模验证不足**：虽然规则池总量高达 494 万条，但实验中的注入规模最高仅 10K 条，未测试 100K 乃至百万级规则下检索与注意力的退化情况，对“超大规模规则库”这一核心卖点的支撑不够充分；
- **测试集规模偏小**：每个 seed 下每类问题仅 110 个样本，总计 550 个问题，统计功效有限，尤其对最难的 4 跳多步任务，样本量可能不足以区分方法间的细微差异；
- **对“规则冲突”与“规则更新”未作深入探讨**：基准明确排除了规则冲突，但现实规则库中常存在冲突、优先级、时效性（如规则被废弃或替换）等复杂情况，论文未覆盖这些场景；
- **依赖外部编码器与额外训练**：DynaRule 需要一个强大的预训练句子编码器（Qwen3-Embedding-8B）和专门的适配器训练流程，对于没有足够算力或无法访问特定编码器资源的用户，方法门槛较高；
- **推理开销仍有隐形成本**：虽然 KV 缓存注入在 token 数量上节约了成本，但规则编码和 Top-K 检索（尤其是在每次 `<search>` 触发时）需要额外的嵌入计算和注意力重算，论文对端到端延迟的分析较为粗略，未与 RAG 的全流程延迟做细致对比；
- **未涉及规则增量学习与持续更新**：当规则库发生增删改时，DynaRule 是否需要重新训练适配器、KV 缓存如何刷新等问题未被讨论，这限制了方法在动态规则环境中的实用性。

## 9. 总结与展望

- **总体贡献**：论文同时贡献了一个面向“全局规则库 + 程序性推理”的挑战性基准（RuleWorld）和一个将规则检索与推理深度融合的端到端框架（DynaRule），在方法、基准、分析三个层面均有实质推进；
- **核心启示**：LLM 在程序性规则推理上的主要瓶颈不在于“读懂规则”，而在于“在大规则池中准确定位并逐步切换规则”；将检索内化为可训练的注意力过程，比外挂式 RAG 更鲁棒且更高效；
- **未来方向**（论文提及或可从其思路自然延伸）：
  1. 扩展到更大规模规则库（100K+）和更多规则形式（代码、时序、概率规则）；
  2. 引入规则冲突、优先级与动态更新机制，更贴近现实；
  3. 探索将 `<search>` 机制推广到其他长文本、知识库或工具调用的“按需检索”场景；
  4. 降低对外部编码器的依赖，尝试将规则编码与 LM 本身联合训练端到端完成。

## 摘要
智能体（使用工具的）语言模型主要在训练后阶段通过工具调用轨迹和智能体轨迹进行训练。这些数据提供了直接的行为监督，但生成它们需要任务环境、执行和验证，使得广泛的工具和任务覆盖成本高昂。公开可用的技能提供了另一种训练数据来源：它们编码了可复用的工具语义和工作流程，但通常仅作为推理时的上下文使用。我们引入了技能预训练（SPT），一种中期训练方法，将因果语言建模应用于SkillCorpus——一个包含公开多文件技能包的数据集，可选择与通用数据混合。为了保持每个包内文件之间的关系，我们还引入了引用插入（Reference Insert），一种感知引用的组装策略，将支持文件放置在主指令中提及它们的位置附近。跨多种模型规模和训练后配方的实验表明，与在通用或轨迹数据上进行中期训练相比，SPT持续提高了智能体性能，同时在很大程度上保持了通用性能。数据混合实验表明，将技能数据与通用退火语料库结合能带来额外收益。这些结果表明，技能包是预训练智能体语言模型的宝贵数据来源。

## Abstract
Agentic (tool-using) language models are mainly trained on tool-call traces and agent trajectories during post-training. These data provide direct behavioral supervision, but producing them requires task environments, execution, and verification, making broad tool and task coverage expensive. Publicly available skills offer another source of training data: they encode reusable tool semantics and workflows but are typically used only as inference-time context. We introduce Skill Pre-Training (SPT), a mid-training method that applies causal language modeling to SkillCorpus, a collection of public multi-file skill packages, optionally mixed with general data. To preserve relations among files within each package, we also introduce Reference Insert, a reference-aware assembly strategy that places supporting files near their mentions in the primary instruction. Experiments across multiple model scales and post-training recipes show that SPT consistently improves agentic performance over mid-training on general or trajectory data, while largely preserving general performance. Data mixture experiments show additional benefits from combining skill data with general annealing corpora. These results indicate that skill packages are a valuable data source for pre-training agentic language models.

## 1. 核心问题与研究动机

- **背景**：智能体（agentic）语言模型需要具备调用外部工具完成多步任务的能力。当前主流做法是在后训练阶段（post-training），通过 SFT 和 RL 在工具调用轨迹（tool-call traces）与智能体轨迹（agent trajectories）上进行行为监督。
- **痛点**：
  - 生成有效的轨迹数据需要任务环境、执行和验证，成本随工具和任务覆盖范围增长而急剧上升；
  - 轨迹记录的是"某一次执行"，而非可复用的工作流，信息密度和泛化价值有限。
- **关键观察**：公开的"技能包"（skill packages）——由人类为 AI 智能体编写的可复用操作指令（可包含脚本、模板、配置文件等）——数量正在爆发式增长（npm 平台上技能数量 2026 年 2 月至 6 月增长约 9.6 倍），但此前仅被用作推理时的上下文，从未被用作训练数据。
- **核心问题**：能否将大规模公开技能包作为智能体语言模型的预训练（中期训练）数据来源，以低成本提升下游智能体能力？

## 2. 方法论

### 2.1 总体框架：SPT（Skill Pre-Training）
- SPT 是一种**中期训练（mid-training）**方法：在预训练之后、行为导向的后训练（SFT/RL）之前，对技能数据施加标准**因果语言建模目标**。
- 不需要任务环境、工具执行或合成轨迹生成，仅需对文本进行语言建模。
- 中期训练产出"技能适配"的 checkpoint，用于初始化后续后训练。数据混合公式：

  \[
  p_\alpha(x) = \alpha \cdot p_{\text{skill}}(x) + (1-\alpha) \cdot p_{\text{gen}}(x), \quad D_\alpha \sim p_\alpha,\ \ 0 \le \alpha \le 1
  \]

  其中 α 为技能数据占比，在固定 token 预算 B 下构造混合语料。

### 2.2 SkillCorpus 构建
- **来源**：2026 年 5 月 1 日的 ClawHub 公开技能包快照，仅保留通过身份验证和独立第三方审计的可信发布者。
- **规模**：最终保留 **38,040 个包、218,277 个文件**（平均每包 5.74 个文件），序列化后得到 84,905 个训练块，约 **3.478 亿 token**。
- **质量筛选**：通过迭代人工审计开发启发式规则，进行内容级语义去重、近重复包检测、自动生成内容过滤、错误工作流剔除、质量分级（移除约 2% 包）。
- **结构清洗**：删除空/短内容、编码 blob、锁文件、二进制文件；脱敏 API 密钥等敏感字段；保留长代码块和表格；超过 10 万字符预算的包按优先级选择章节。
- **去污染**：人工审计 + DeepSeek-V4-Flash 对 API-Bank、MetaTool、APT-Bench、ToolEyes 和 OLMES 六项通用基准进行筛选，删除含基准相关工具模式、任务模板或改写变体的包（约 0.3%）。

### 2.3 Reference Insert（引用插入）——多文件技能组装策略
- **动机**：简单拼接会把主指令与其引用的支持文件放得很远，破坏跨文件关系。
- **流程**：
  1. 为每个包写入包含名称和描述的头部；
  2. 按原始顺序扫描 `SKILL.md`，将路径归一化（小写、反斜杠转正斜杠）；
  3. 当某行包含对支持文件的明确引用时，在该行后立即插入 `<referenced_file_sep>` 标记和该文件内容；每个支持文件仅在其首次明确提及处插入一次；
  4. 扫描结束后，用 `<unreferenced_file_sep>` 追加剩余文件；
  5. 用包间分隔符标记边界，打包为 4,096-token 训练块。
- **效果**：解析了 17,957 个包中的 70,655 个引用文件；将引用行到目标文件首 token 的平均距离从 14,518.996 降到 737.189 token（**平均减少 94.92%**）。

## 3. 实验设计

### 3.1 模型与数据
- **三个基础模型（不同规模）**：MeCo-1.6B-DCLM-160B、Instella-3B-Stage1、OLMo-3-1025-7B（均为单阶段通用预训练 checkpoint，未经过退火或后训练，以隔离 SPT 的效果）。
- **三种中期训练数据条件**（相同 token 预算）：
  - Dolmino（通用数据基线）
  - AgentBank（智能体轨迹数据基线）
  - SkillCorpus（技能数据）
  - 另有"无中期训练"的直接 SFT 基线。
- **两种后训练配方**：Tulu 3（通用指令微调）和 xLAM-FC（函数调用 SFT）。

### 3.2 评估基准
- **智能体能力**（4 个）：
  - API-Bank（API 调用，3 个等级）
  - MetaTool（工具选择，4 个子任务）
  - APT-Bench（SWE 与深度研究的多步智能体任务）
  - ToolEyes（7 个真实场景的交互式工具使用）
- **通用能力**（6 个 OLMES 基准）：ARC-Challenge、BoolQ、HellaSwag、PIQA、WinoGrande、MMLU。

### 3.3 主要对比实验（6 组设置）
- 3 个模型规模 × 2 种后训练配方（xLAM-FC 和 Tulu 3），每组对照 4 种中期训练条件（无 / Dolmino / AgentBank / SkillCorpus）。

### 3.4 辅助实验
1. **混合比例扫描**：1.6B 骨干 + Tulu 3 SFT，SkillCorpus 分别与 Dolmino 和 SmolLM 混合，比例从 0% 到 100%。
2. **组装策略消融**（5 种，同文件、同预算、同 tokenizer）：DeepSeek-Coder Packing、Random File Order、Metadata Packing、Skill-FIM、Reference Insert。
3. **RL 稳健性测试**：SmolLM2-360M + 相同 Tulu 3 SFT + GRPO（RLVR-GSM-MATH-IF-Mixed-Constraints，与工具无关的奖励），对照无中期训练 / Dolmino / SkillCorpus。

## 4. 资源与算力

- **硬件**：所有实验使用 **4× NVIDIA A100 80GB GPU**，BF16 精度 + TF32，启用梯度检查点。
- **中期训练超参**：序列长度 4,096，per-device batch size 1，8 步梯度累积，学习率 2×10⁻⁵，权重衰减 0.1，cosine 调度，1 个 epoch。
- **SFT 超参**：序列长度 2,048，per-device batch size 4（360M 实验为 1），4/16 步梯度累积，学习率 2×10⁻⁵，无权重衰减，3 个 epoch。
- 1.6B 用 AdamW；3B/7B/360M 用 Adafactor。
- **GRPO 超参**：4 个生成/提示，学习率 1×10⁻⁶，KL 系数 0.04，1 个 epoch。
- **训练时长未在论文中明确给出**；每个配置在 5 个随机种子（42、3407、1234、2026、2027）上取平均。

## 5. 实验数量与充分性评估

- **实验体量**：
  - 主实验 6 组设置 × 4 种中期训练条件 × 5 seeds，共 120 次训练；
  - 混合比例扫描 2 种通用语料 × 10 个比例 × 5 seeds；
  - 组装策略消融 5 种策略 × 5 seeds；
  - RL 实验 3 种条件 × 5 seeds。
- **公平性**：三种中期训练语料在相同 token 预算下物化（均为 347,770,880 token）；同一配置内超参、优化器、调度器、seed 完全一致；所有模型在同一基准实例上评估。
- **充分性**：覆盖 3 个模型规模、2 种 SFT 配方、1 种 RL 配方、多种数据组织方式，实验设计较为系统，控制了"额外训练阶段"这一混淆变量（Dolmino 对照证明大部分增益来自语料内容而非仅仅多训练一步）。
- **结论强度**：结果一致性很高——SkillCorpus 在 24 项个体智能体基准比较中 23 项排名第一，统计上可信。

## 6. 主要结论与发现

1. **技能数据优于通用数据和轨迹数据**：在所有 6 组骨干×后训练设置中，排序均为 Dolmino < AgentBank < SkillCorpus；在相同预算下 SkillCorpus 比 AgentBank 高 **4.07–9.91 分**。
2. **SPT 增益显著且不损通用能力**：相对直接 SFT，智能体四基准平均提升 **9.11–24.96**，而通用六基准平均仅变化 **−0.85 至 +0.51**。
3. **技能数据贡献超过"多训练一步"本身**：Dolmino 相对直接 SFT 提升 2.62–4.83，SkillCorpus 在此基础上再提升 6.49–20.13，说明语料内容驱动了大部分增益。
4. **技能知识对工具聚焦 SFT 互补性更强**：xLAM-FC 下的增益（11.55–24.96）大于 Tulu 3 下的增益（9.11–19.33）。
5. **最佳混合比例约为 30%**：20%–50% 技能数据均优于纯技能和纯通用两端点；30% 时智能体得分最高（Dolmino 混合 38.60，SmolLM 混合 37.58），通用得分几乎不掉。技能数据应作为通用数据的**补充组件**而非替代品。
6. **Reference Insert 是最优组装策略**：智能体得分 22.06，超过 DeepSeek-Coder（20.19）、Random File（16.09）、Metadata（16.50）、Skill-FIM（17.98），且通用得分也最高（58.20），说明引用感知的文件排布是关键。
7. **SPT 的收益在 RL 后训练后依然保持**：同样 SFT+GRPO 下，SkillCorpus 中期训练的四基准得分 11.94，远超 Dolmino（7.25）和无中期训练（4.95），即便 RL 奖励与工具使用无关。

## 7. 优点

- **新颖且有价值的数据视角**：首次系统论证了公开技能包可作为智能体预训练数据，为低成本扩展智能体训练数据提供了新路径（技能数据天然规模化且不需要执行环境）。
- **方法简洁、即插即用**：SPT 不改变因果语言建模目标，不引入新损失函数，可直接嵌入现有"预训练→后训练"流水线。
- **Reference Insert 设计精巧**：在保持文件文本不变的前提下，通过引用感知的局部化排布大幅缩短指令

**7. 优点（续）**

- **Reference Insert 设计精巧**：在保持文件文本不变的前提下，通过引用感知的局部化排布大幅缩短指令与支持文件之间的距离（平均减少 94.92%），使模型在有限上下文窗口内更容易建立跨文件关联，这一机制简单、无需训练、可复用到任意多文件技能的序列化场景。
- **实验设计系统且可控**：覆盖 3 个模型规模、2 种后训练配方、1 种 RL 配方，并设置了"通用数据中期训练"和"轨迹数据中期训练"两个对照，有效剥离了"额外训练阶段本身"和"数据内容"两个混淆变量；5 个随机种子取平均进一步增强了结论稳健性。
- **研究问题开放且可扩展**：SPT 不依赖任何特定模型架构或任务环境，技能包数据规模随社区贡献持续增长，方法具有天然的规模化潜力；同时论文明确指出了若干未来方向（更大规模的技能数据、更多模型体系、更多后训练配方），为后续研究划定了清晰路线图。

## 8. 局限性

- **数据来源单一且时效性受限**：SkillCorpus 仅取自 2026 年 5 月 1 日 ClawHub 单一时点快照，技能生态演进迅速（文中引用的 npm 技能包 4 个月增长约 9.6 倍），单一快照可能引入时效性偏差，且数据分布随平台政策、社区趋势变化明显。
- **质量筛选依赖启发式规则**：虽然经过迭代人工审计，但面对 3.8 万余个包，规则难以覆盖全部语义层面的质量问题；内容级去重和近重复包检测无法完全消除语义相似但文本不同的冗余，可能仍存在隐含的分布偏差。
- **污染排查覆盖有限**：去污染仅针对 6 个通用基准（API-Bank、MetaTool、APT-Bench、ToolEyes 及 OLMES 子集），且依赖人工审计 + 单一模型（DeepSeek-V4-Flash）筛选，难以保证对所有下游任务无泄漏，尤其是对未见过的工具生态。
- **中期训练预算未做充分扫描**：固定 token 预算 B 下的结论可能无法直接外推到更大预算场景——若 token 预算大幅增加，纯技能数据或更高混合比例的相对收益可能发生变化，混合比例的"最优值"也可能随预算漂移。
- **混合比例的结论粒度较粗**：30% 最优这一结论来自 1.6B 骨干 + Tulu 3 配方、两种通用语料（Dolmino 和 SmolLM）的扫描，未在更大模型或 xLAM-FC 配方上验证，其普适性有待进一步检验。
- **评估基准覆盖仍有缺口**：4 个智能体基准虽各有侧重，但未覆盖如网页操作、GUI 交互、多智能体协作等真实部署场景；且各基准的难度与区分度不一（如部分 ToolEyes 子任务可能难度偏低），对能力的刻画不够全面。
- **安全与许可问题未深入讨论**：公开技能包可能包含恶意指令、漏洞代码或存在许可证约束，论文仅做了 API 密钥脱敏，未系统讨论技能包本身的安全风险、版权合规以及被注入恶意技能后对模型行为的下游影响。
- **理论解释缺位**：论文实证了技能数据的有效性，但未从机制层面解释"为何技能文本优于轨迹文本"——例如是否因为技能包信息密度更高、指令型文本更接近 SFT 分布、还是因为"过程描述"比"执行记录"更利于内隐学习，这些问题悬而未决。

## 9. 个人评价与展望

SPT 的核心贡献不在于提出一个新的损失函数或模型架构，而在于**对训练数据来源的一次范式性反思**：当社区普遍在"制造更多轨迹数据"的路上越走越远时，论文敏锐地注意到人类为智能体编写的"技能包"本身就是高质量、结构化、可规模化获取的训练信号。这一视角具有明显的产业价值——它意味着智能体能力的提升不一定总需要昂贵的环境交互，人类已有的知识沉淀（脚本、模板、工作流）可以被直接"阅读"进模型。

从方法论角度看，SPT 的极简主义值得赞赏。它刻意回避了复杂的轨迹合成、奖励设计或格式转换，仅用标准因果语言建模就在 24 项个体基准比较中拿下 23 项第一，这反向印证了一个长期被忽视的事实：**预训练阶段的数据构成对智能体能力的塑造作用可能被严重低估了**。同时，"技能数据作为补充而非替代"（30% 混合最优）的结论也提醒后续研究者，不同数据形态之间存在互补关系，追求单一数据源的极致占比并非明智之举。

几个值得期待的研究方向：

1. **技能的动态发现与更新**：如何让模型持续从不断增长的新技能包中学习而不遗忘旧技能，涉及持续预训练与数据漂移问题；
2. **技能数据与轨迹数据的协同**：技能包提供"知识"，轨迹提供"行为"，二者在训练中是否存在最优的交替时序或比例；
3. **跨模态技能理解**：GUI 操作、机器人控制等技能难以纯文本化，如何将 SPT 思想推广到多模态技能数据；
4. **技能生成能力的直接评估**：SPT 训练后的模型是否不仅会"调用"技能，还能"编写"新技能，这可能成为衡量智能体自主性的新基准。

总体而言，这是一篇数据视角新颖、实验扎实、写作清晰的论文，虽在机制解释和评估覆盖上留有空间，但其提出的"技能预训练"范式有望成为智能体语言模型训练流水线中的一个标准组件。

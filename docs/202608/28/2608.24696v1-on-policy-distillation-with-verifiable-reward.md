## 摘要
基于可验证奖励的强化学习（RLVR）和在线策略蒸馏（OPD）已成为大语言模型后训练中两种广泛采用的范式。然而，RLVR面临稀疏的任务级反馈，而OPD提供密集的令牌级指导但忽略轨迹正确性，将其性能限制在教师模型水平。将两者结合是一个有前景的方向：OPD提供密集的监督信号，而RLVR提供任务级正确性。然而，现有集成方法通常依赖加权组合或启发式切换，引入了额外的超参数和权衡。我们提出了基于可验证奖励的在线策略蒸馏（OPDVR），一种简单而有效的方法，无需添加任何超参数即可无缝结合OPD和RLVR。我们首先基于轨迹正确性重新表述采样令牌OPD的隐式奖励，然后应用ReLU门控机制，确保正确轨迹获得非负奖励，错误轨迹获得非正奖励——从而使蒸馏信号与任务成功对齐，同时保留教师的分布引导。此外，我们的修改将采样令牌OPD转化为一种合适的RLVR方法，使其能够与任何策略梯度算法（如GRPO）直接结合。在六个推理基准上的实验表明，OPDVR始终优于标准OPD。我们的代码可在 https://github.com/LeapLabTHU/OPDVR 获取。

## Abstract
Reinforcement Learning with Verifiable Rewards (RLVR) and on-policy distillation (OPD) have become two widely adopted paradigms for post-training large language models. However, RLVR suffers from sparse task-level feedback, while OPD provides dense token-level guidance but ignores trajectory correctness, limiting its performance to that of the teacher. Combining them is a promising direction: OPD supplies dense supervisory signals, while RLVR provides task-level correctness. Nevertheless, existing integrations often rely on weighted combination or heuristic switching, introducing extra hyperparameters and trade-offs. We propose On-policy Distillation with Verifiable Reward (OPDVR), a simple yet effective method that seamlessly combines OPD and RLVR without adding any hyperparameters. We first reformulate the implicit reward of sampled-token OPD based on trajectory correctness, then apply a ReLU gating mechanism to ensure that correct trajectories receive non-negative rewards and incorrect ones receive non-positive rewards---thereby aligning the distillation signal with task success while preserving the teacher's distributional guidance. Furthermore, our modification transforms sampled-token OPD into a proper RLVR method, making it readily combinable with any policy gradient algorithm, such as GRPO. Experiments on six reasoning benchmarks show that OPDVR consistently outperforms standard OPD. Our code is available at https://github.com/LeapLabTHU/OPDVR.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型后训练阶段存在两大主流范式：
  - **RLVR（Reinforcement Learning with Verifiable Rewards）**：基于任务结果的显式奖励（如数学答案正确性、代码可编译性），提供明确的任务级信号。但奖励稀疏，仅能区分轨迹最终对错，缺乏对中间步骤的细粒度信用分配。
  - **OPD（On-policy Distillation，在线策略蒸馏）**：让学生模型在在线采样过程中模仿教师模型的输出分布，提供密集的 token 级逐位置指导。但 OPD 的目标纯粹是分布匹配，完全忽略轨迹是否正确，因此学生性能上限受限于教师模型。
- **核心问题**：这两种范式具有天然互补性——OPD 的密集指导与 RLVR 的任务正确性均不可或缺。但已有的融合方案（如直接加权两个目标、按优势符号切换使用）往往引入额外超参数、启发式权衡或复杂的多目标协调，缺乏简洁、无超参数、内在统一的融合方式。
- **核心思想**：能否将 OPD 本身重新"改造"为一个满足 RLVR 原则的强化学习目标，从而无需任何额外超参数即可自然融合二者的优势？

## 2. 论文提出的方法论

### 2.1 核心思想

作者从 **RLVR 视角重新审视 sampled-token OPD**，将其隐式地解释为一种带 token 级奖励的策略梯度方法，发现其奖励符号由教师/学生概率比决定、与轨迹正确性无关，进而与 RLVR 的强化原则发生冲突。解决方法是引入 **ReLU 门控（ReLU gating）**，在保留教师分布信息的前提下强制校正奖励符号，使正确轨迹的所有 token 获得非负奖励、错误轨迹的所有 token 获得非正奖励。

### 2.2 关键技术细节

**第一步：重新表述 OPD 的隐式奖励**

Sampled-token OPD 的梯度形式为：
```
∇θ L_OPD = Σ log(πθ(ot)/πT(ot)) · ∇θ log πθ(ot)
```
与 RLVR 的 REINFORCE 梯度对照，可解出隐式 token 级奖励：
```
R_OPD(ot) = log(πT(ot)/πθ(ot))
```
依据轨迹正确性分拆：
- 正确轨迹：奖励系数为 log(πT/πθ)（应乘 +1）
- 错误轨迹：奖励系数为 log(πθ/πT)（应乘 -1）

**存在两类冲突**：
1. 正确轨迹中若 πθ > πT，则 log(πT/πθ) < 0，正确 token 被错误惩罚；
2. 错误轨迹中若 πT > πθ，则 log(πθ/πT) < 0，错误 token 被错误鼓励。

**第二步：ReLU 门控机制**

OPDVR 对奖励施加 ReLU 门控：
```
R_OPDVR(ot) = 
  max(0, log(πT/πθ)) · (+1)，若轨迹正确；
  max(0, log(πθ/πT)) · (−1)，若轨迹错误。
```
对应损失：
```
L_OPDVR(θ) = −Σ R_OPDVR(ot) · log πθ(ot | q, o<t)
```
效果是：
- 正确轨迹上，仅保留"教师比学生更自信"的 token 并给予正向强化，且置信差异越大奖励越大；
- 错误轨迹上，仅保留"学生比教师更自信"的 token 并给予负向惩罚，且置信差异越大惩罚越重；
- 符号与"轨迹正确性"严格一致，同时保留教师分布的对数比值作为幅度控制。

**第三步：作为通用 RLVR 框架**

该门控机制使 OPD 成为一个合法的 RLVR 目标，可直接嵌入任意策略梯度算法（REINFORCE、GRPO、PPO、DAPO 等）。论文实例化为 **GRPD（Group Relative Policy Distillation）**：将二元正确性信号替换为 GRPO 式的组内相对优势 Â，再应用相同的 ReLU 门控逻辑，亦无需额外超参数。

## 3. 实验设计

### 3.1 实验设置

- **同架构蒸馏**：学生为 Qwen3-4B-nonthinking，教师为同架构 Qwen3-4B-RL（在 DeepMath 上经 GRPO 训练）；训练数据为 DeepMath 过滤子集（57k 样本，难度 ≥ 6）。
- **跨架构蒸馏**：数据为 DAPO-Math-17k；教师为 Qwen3-4B-Base（GRPO 微调 3 epoch），学生为 Qwen3-1.7B-Base；蒸馏训练 3 epoch。

### 3.2 Benchmark

在 **6 个数学推理基准**上评估：AIME24、AIME25、AMC、MATH500、Minerva、OlympiadBench，均以 avg@16 准确率作为指标。

### 3.3 对比方法与实验组

- **OPDVR 主实验**：对比 Sampled-Token OPD、Top-64 OPD，两种蒸馏设置各一组实验；

## 6. 主要结论与发现

1. **OPDVR 一致优于标准 OPD**：同架构下平均 49.1 vs 47.8，跨架构下平均 22.8 vs 20.9（sampled-token OPD），且不引入任何超参数。
2. **ReLU 门控是有效性的关键**：反转门控方向（Inverse-Gated）后性能跌至平均 44.6，低于 OPD，说明"门控方向与轨迹正确性对齐"是增益的根本原因。
3. **门控过滤比例稳定**：训练全程零门控 token 比例稳定在 ~50%，表明 RLVR-冲突 token 是持续存在的系统性问题，而非训练初期的短暂现象。
4. **OPDVR 可无缝扩展为通用框架**：与 GRPO 结合成 GRPD 后，在 AIME24 上比 GRPO 提升 6.5 点、比 OPD 提升 2.8 点，平均 49.4，超过教师模型（50.4 基线的差距极小）。
5. **理论分析支撑**：附录证明 OPDVR 更新方向与纯 RLVR 梯度方向永不冲突（内积 ≥ 0），且可通过移除"冲突项"从 OPD 梯度精确推导；在简化单 token 问题中，OPDVR 可以严格超越教师模型（因为教师也是次优的）。

## 7. 优点

- **简洁优雅**：仅需一个 ReLU 门控函数，无需新增超参数、无需多目标加权、无需启发式切换规则；从数学上揭示 OPD 本身就是一种 RLVR，统一了两大范式，理论切入视角新颖。
- **可扩展性强**：将 OPD 重新表述为合法 RLVR 目标后，天然兼容所有主流策略梯度算法，通用性高。
- **实验设计严谨**：Inverse-Gated 反向消融构思巧妙，清晰分离了"教师指导有效性"与"门控方向正确性"的贡献；训练动态图补充了过程性证据。
- **理论保证充分**：从"方向对齐"、"冲突项分解"到"超越教师的最优性分析"，提供三层理论证据支撑实验现象。
- **部署友好**：实现成本极低（仅需判断轨迹正确性并对 log-ratio 施加 ReLU），适合在现有 OPD 框架上直接迁移。

## 8. 不足与局限

- **任务覆盖窄**：仅在数学推理（6 个基准）上验证，RLVR 同样主流的代码生成、指令遵循、agent 任务等未见实验，通用性尚未充分证明。
- **算力信息不透明**：未报告 GPU 数量、训练时长、总卡时，读者难以评估方法的经济成本与复现难度。
- **GRPD 验证不完整**：仅在同架构设置下测试，跨架构下 GRPD 是否仍然优于 GRPO 与 OPD 未知；组大小 G=8 是否具有敏感性也未做消融。
- **教师选择单一**：主要使用 Qwen3-4B 系列作为教师，未测试更强的教师（如 DeepSeek-R1、更大参数模型）或更弱的学生（如 1B 以下）等极端组合下的表现。
- **奖励二值化损失**：对正确轨迹中"学生已自信但教师不太自信"的 token 完全丢弃指导，可能丢失一部分有意义的分布信息；在部分场景下教师的不自信可能蕴含利于泛化的信号。
- **应用限制**：依赖于轨迹级可验证信号的存在性。在无法自动验证答案正确性的通用任务（如开放性问答、创意写作）上，该方法无法直接使用。

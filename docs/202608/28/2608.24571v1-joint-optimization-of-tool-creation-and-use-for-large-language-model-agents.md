## 摘要
工具增强的语言模型受限于人类费心编写的 API；现有的工具创建系统通过在推理时提示冻结的 LLM 来弥补这一点，但编写工具的模型与使用工具的模型彼此脱节，且没有信号表明其生成的模式可被自身调用。我们提出了 SMITH（基于模式的迭代式多任务工具打磨），这是一种在单一策略内联合训练工具创建与工具使用的强化学习框架。每次策略展开要么是构建任务（从少量示例中编写工具），要么是使用任务（在保留问题上调用池化工具）。三个独立的奖励轴分别捕获模式、代码和结果失败，因此每种失败模式都能贡献各自的梯度。使用 SMITH 在 13 个带有精确验证器的程序性推理任务上训练的 4B Qwen3，在保留任务上达到了 79.8 的宏平均准确率，在所有评估方法中表现最佳，且领先于未训练的 30B-A3B 工具编写器。它还在 TabMWP-Hard 上达到 40.4，在域外 GQA 上达到 42.6（较最佳同主干推理时基线提升 7.6），且无需任何视觉或表格训练数据。我们的 4B 模型编写的工具还提升了 LFM-2.5-350M 和 Qwen3-30B-A3B 在同一推理任务上的性能。

## Abstract
Tool-augmented language models are bounded by the APIs humans bothered to write; existing tool-creation systems patch this by prompting a frozen LLM at inference time, leaving the model that writes a tool decoupled from the one that uses it, with no signal that the schemas it produces are schemas it can invoke. We propose SMITH (Schema-grounded Multi-task Iterative Tool Honing), a reinforcement learning framework that jointly trains tool creation and tool use inside a single policy. Each rollout is either a build task (write a tool from a few examples) or a use task (invoke a pooled tool on a held-out question). Three separate reward axes catch schema, code, and outcome failures independently, so each failure mode contributes its own gradient. A 4B Qwen3 trained with SMITH on 13 procedural reasoning tasks with exact verifiers reaches 79.8 macro-average accuracy on held-out tasks, the best across all evaluated methods and ahead of an untrained 30B-A3B tool-writer. It also reaches 40.4 on TabMWP-Hard and 42.6 on out-of-domain GQA (+7.6 over the best same-backbone inference-time baseline), without any visual or tabular training data. Tools written by our 4B models also lifted the performance of LFM-2.5-350M and Qwen3-30B-A3B under same reasoning tasks.

# 《面向大型语言模型智能体的工具创建与使用联合优化》详细总结

## 一、核心问题与研究动机

- **背景问题**：工具增强的LLM（Tool-augmented Language Models）极大拓展了模型能力，但现有系统都依赖**人类预先编写的固定API工具集**。这些预定义API可能存在覆盖不全、与新任务不匹配甚至完全缺失的问题，形成模型能力的硬性天花板。
- **现有方案的缺陷**：
  - 已有工具创建系统（如LATM、CRAFT、Trove、KTCE）均在**推理时通过提示冻结的LLM**来生成工具，本质上是"提示工程"而非真正的学习优化。
  - **创建与使用严重脱节**：往往由更强的模型编写工具、由更弱的模型调用工具（如LATM中GPT-4写工具、GPT-3.5用工具），工具编写者从未被激励去设计**自己能够可靠调用的schema**。
  - 没有任何显式的训练信号来优化工具质量、可复用性以及"模式可调用性"。
- **核心开放问题**：如何训练**同一个模型**同时成为更好的工具创建者和更好的工具使用者，闭合"写工具—用工具"的反馈回路？
- **两大挑战**：
  1. **奖励分解**：工具包含schema（函数名、参数、类型）与后端实现（可执行代码），两类失败需要不同的纠正信号，奖励分配困难。
  2. **循环评估**：评估工具质量需要评判者，但自我评估不可靠，而固定外部评估器又存在可信度与对齐问题。

## 二、方法论：SMITH框架

### 2.1 核心思想
SMITH（**S**chema-grounded **M**ulti-task **I**terative Tool **H**oning，基于模式的迭代式多任务工具打磨）是一个在**单一策略内部联合训练**工具创建与工具使用的强化学习框架。让同一个模型写出自己能可靠调用的工具，用自身执行结果直接优化策略。

### 2.2 任务设计（双任务多任务训练）
- **构建任务（Build）**：给定`N=4`个（问题，答案）示例对，模型需归纳出通用解法，并同时输出：
  - 一个可执行的**Python函数**（后端实现）
  - 一个OpenAI兼容的**JSON Schema**（结构化接口描述）
- **使用任务（Use）**：模型**只看到schema（看不到底层代码）**，必须调用该工具回答一个保留问题（held-out question）。最多`T=5`轮多轮对话，提前输出最终答案或工具调用失败则终止。
- **Schema驱动的设计**：schema模糊或不完整的工具在使用时必然失败，从而为schema质量提供**直接训练信号**。

### 2.3 训练算法与配置
- 使用**DAPO**（GRPO的clip-higher变体）作为强化学习算法，稳定熵、避免奖励坍缩。
- 每个训练批次`ℬ`对半分为`ℬ_build`与`ℬ_use`（各`B/2`），保持两类任务梯度贡献平衡，在单次反向传播中累积更新共享策略参数：`ℒ = ℒ_DAPO(ℬ_build) + ℒ_DAPO(ℬ_use)`。
- LoRA微调（`r=64, α=128`），学习率`6×10⁻⁵`（4B）/`1×10⁻⁵`（8B），温度0.7，KL系数`β=0.01`，训练60个梯度步。

### 2.4 三轴奖励设计（关键创新）
构建任务设有**三条独立奖励轴**，分别解耦不同类型的失败：

| 奖励轴 | 计算公式 | 作用 |
|---|---|---|
| **执行准确性** `r_eval` | 评估者模型`π_eval`调用工具回答16个保留测试问题的正确率 | 只计通过工具调用得到的正确答案，防止文本推理绕过工具目标 |
| **格式一致性** `r_fmt` | 恰有一个Python块和一个JSON块且函数名与参数签名一致时为`0.5`，否则为`0` | 保证schema与代码结构匹配 |
| **LLM评判质量** `r_judge` | 对代码正确性、schema质量、整体质量打分；语法错误罚`-0.5`，签名不一致则分数减半 | 提供语义层面的工具质量信号，独立于执行信号 |

构建环境奖励：`r_env_build = r_fmt + r_eval`。
使用任务奖励：`r_correct = 2c·η(ρ)`，其中`c`为答案正确性，`η(ρ)`为随轮次占比`ρ`衰减的效率乘数（分段连续函数，`η_min=0.3, η_mid=0.7`），惩罚轮次预算耗尽。

### 2.5 循环评估缓解（减少自我评估偏差）
- 评估者`π_eval`从与策略相同的基座初始化，**周期性从最新策略权重同步**（每5个梯度步）。提供一个稳定但不断改进的评估目标，避免使用实时训练权重带来的不稳定性。

### 2.6 工具池（Tool Pool）
- 任何`r_eval > 0`的工具被加入共享的工具池`𝒫`（每类最多20个）。
- 使用任务注入**1个领域工具 + 2个干扰工具**（来自无关类别），迫使模型识别并调用正确的schema。
- 池满时淘汰得分最低者（同分淘汰最旧），形成隐式课程：随训练推进，池中工具质量门槛自然上升。

### 2.7 易到难转移协议（Easy-to-Hard）
- 工具归纳上下文来自**较易的课程区间**（Band 2），而工具评估集来自**最难的区间**（测试集）。
- 这种设计保证：只在训练分布上模式匹配的工具会在评估集上得零分；只有真正抽象出底层算法的工具才能跨越难度鸿沟——这是对可复用性和泛化性的直接激励。

## 六、主要结论与发现

1. **联合训练显著优于推理时提示**：SMITH的4B模型在RG Unseen上达到**79.9**（宏平均），超过所有同骨干推理时基线（最佳CRAFT 76.5）、蒸馏模型（ReTool 63.2、LATM-distill 65.8）以及30B LATM编写器（74.1）。
2. **Token效率极高**：SMITH平均输出仅**~100 tokens**，约为标准CoT（3,206）的1/32、ReTool（633）的1/6，将工作从解码时推理转移到可复用工具代码中。
3. **工具跨模型规模双向迁移**：
   - 4B写的工具让350M模型（LFM2.5）的RG Unseen从11.6升至**42.9**，匹配30B工具编写器（41.5）表现。
   - 4B写的工具将30B消费者的综合得分从70.2提升至**76.6**（TabMWP-Hard从0.7跃升至38.8）。
4. **OOD零样本转移**：在TabMWP-Hard上达到**40.4**（领先所有非蒸馏基线），GQA上达到**42.6**（仅落后于GPT-4.1蒸馏基线56.0），证明无视觉/表格训练数据也能泛化到新模态。
5. **跨骨干可扩展**：同一配方提升Qwen3-8B（RG Unseen 72.2→81.7，TabMWP 42.4→56.7）和Granite-3.3-8B，说明方法不依赖特定模型家族。
6. **外部工具调用能力提升**：BFCL v4上Qwen3-4B从45.1→48.6，Qwen3-8B从43.3→**55.8**。

## 七、方法优点

1. **闭合"写—用"反馈回路**：同一策略写入工具并调用工具，schema模糊性直接转化为使用失败梯度——这是提示方法无法提供的训练信号。
2. **三轴奖励解耦设计精巧**：将执行准确性、格式一致性、语义质量分开为独立奖励轴，避免单一奖励被一种失败模式主导，各失败贡献独立梯度。
3. **易到难转移协议**：在每次训练迭代强制泛化差距，激励策略生成简洁、可解释、可复用的工具，而非任务特定捷径。
4. **循环评估缓解机制**：评估者从策略定期同步（而非共享实时权重），兼顾评估能力提升与训练稳定性。
5. **工具池的隐式课程效应**：质量优先的准入/淘汰机制自然创造难度阶梯。
6. **评估系统严谨**：修复基线Bug并重新评估、对基线prompt做受控消融（TroVE）、对KTCE进行逐任务失败模式诊断，方法论透明度高。
7. **低成本高可复现**：单GPU、数十小时训练即达到超过更大模型的性能，工程门槛低。

## 八、不足与局限

1. **规模限制**：所有训练策略最多8B参数、judge为30B，**70B+规模下的增益是否持续、饱和或反转仍是开放问题**。
2. **Judge依赖**：主配置依赖外部30B judge；Self-Judge消融显示：无外部judge时RG Unseen提升（85.9）但GQA显著下降（16.3），说明小judge对分布迁移任务的信号较弱。
3. **工具表示单一**：仅支持"一个

- **工具表示单一**：仅支持"一个Python函数 + 一个JSON Schema"的固定形式，未覆盖API组合、类对象、多模态接口或需要多工具协作的复合工具；对于需要状态维护、流式处理或外部副作用管理的工具，该表示力不足。
2. **评估集大小的潜在妥协**：构建任务中仅用16个保留问题评估工具质量，当工具面对高度多样化输入时，该样本量可能无法充分反映真实泛化能力，存在评估噪声。
3. **任务类别偏程序性推理**：训练数据来自Reasoning-Gym的程序性推理任务（算法/算术/逻辑为主），缺乏开放性创作、信息检索、知识密集或真实软件工程场景，可能使模型习得的"工具归纳偏好"偏科。
4. **干扰工具数量固定**：使用任务仅注入1个领域工具+2个干扰工具，未系统研究干扰工具数量、相似度对选择性调用能力的影响；在真实API生态中，候选工具可能成百上千，规模化选择能力未被验证。
5. **联合训练的潜在协同衰减**：论文证明了单流联合训练优于解耦训练，但未深入分析构建与使用任务在梯度层面的相互干扰机制（如是否出现任务间灾难性遗忘、共享LoRA参数的容量竞争）。
6. **外部工具调用评估的局限性**：BFCL v4仅评估了调用已有API的"使用"能力，未评估在真实开放API环境中自主创建缺失工具的闭环流程。
7. **未见明显的社会影响/风险讨论**：工具创建能力可能被滥用（如生成恶意代码工具、绕过安全过滤），论文未讨论对齐与安全缓解措施。

## 九、个人评价与启发性思考

### 9.1 本研究最值得借鉴的三个设计
1. **"让作者成为使用者"的训练哲学**：SMITH通过让同一策略既写工具又用工具，把"工具描述质量"从语义模糊问题转化为可微分的执行失败信号，这是最核心的范式贡献。
2. **奖励轴解耦而非加权组合**：将执行正确性、格式合规性、语义质量作为三条独立奖励轴分别计算梯度，而非融合为单一标量，避免了奖励被某一失败模式主导，也使得消融分析可解释性极强。
3. **"易归纳—难评估"的课程式泛化协议**：在训练时故意制造分布差距（归纳自简单区间、测试于最难关卡），把"泛化"从评估指标变为训练压力，方法简单但异常有效。

### 9.2 对后续研究的启发
1. **从单工具到工具组合**：将归纳粒度从单个函数扩展为工具链或工具图，并设计相应的组合规划奖励。
2. **动态工具生命周期**：工具池目前只增不减（按分数淘汰），未来可研究工具合并、参数化复用、跨任务工具迁移。
3. **评估者与策略的协作进化**：Synced Judge有效但仍是启发式同步；更理论化的方向是设计双主体博弈或偏好对齐机制，使评估者的严格度与策略能力形成最优追赶曲线。
4. **多智能体场景**：当多个模型共享同一工具池时，是否需要为工具添加"作者标识"和信用分配机制，激励高质量贡献而非搭便车。
5. **更泛化的工具表示**：超越代码+Schema，纳入自然语言工具说明书、演示示例（few-shot demonstrations）或可学习的工具嵌入，以适应纯解码器界面的调用习惯。

### 9.3 一句话总结
> SMITH通过"同一个模型既是工具作者又是工具用户"的联合强化学习，在单卡GPU上以约100 token的平均输出实现了对更大模型与所有提示式工具创建基线的全面超越，以设计上的精妙弥补了规模上的不足，为工具增强型智能体的自我进化提供了一个可复现、可扩展的范本。

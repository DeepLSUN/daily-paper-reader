## 摘要
保护语言模型智能体需要根据上下文相关的安全策略评估完整执行轨迹。现有的策略感知安全防护主要依赖提示或监督微调，限制了其适应未见轨迹和变化策略上下文的能力。我们提出RePolicy，一种通过强化学习学习安全策略调用的智能体安全防护方法。给定智能体轨迹和动态策略库，RePolicy调用适用策略，并利用其内容生成基于策略的推理和安全判断。我们构建了PolicyTraj-20K以支持监督初始化，随后采用具有可验证奖励和策略上下文扰动的GRPO。跨六个智能体安全基准的实验表明，RePolicy在整体安全检测性能上表现强劲，并在不同策略上下文下实现了稳健的策略调用。

## Abstract
Safeguarding language model agents requires assessing complete execution trajectories under context-dependent safety policies. Existing policy-aware safeguards mainly rely on prompting or supervised fine-tuning, limiting their ability to adapt to unseen trajectories and changing policy contexts. We propose RePolicy, an agent safeguard that learns safety-policy invocation through reinforcement learning. Given an agent trajectory and a dynamic policy library, RePolicy invokes the applicable policy and uses its content to produce a policy-grounded rationale and safety judgment. We construct PolicyTraj-20K to support supervised initialization, followed by GRPO with verifiable rewards and policy-context perturbation. Experiments across six agent safety benchmarks show that RePolicy achieves strong overall safety-detection performance and robust policy invocation under varying policy contexts.

## 1. 论文的核心问题与整体含义

- LLM 智能体正在从文本生成工具演化为能够规划任务、调用工具并与外部环境交互的自主系统，其安全风险也从单次交互的有害内容扩展到完整执行轨迹中的行为危害。
- 现有智能体安全防护（safeguard）往往基于预定义风险分类或安全策略做出判断，但真实部署中不存在一套固定策略能覆盖所有场景；同一行为可能因用户权限、组织要求、监管辖区等不同而受到不同约束，且策略本身会随时间演化。
- 近期研究将安全策略视为可配置的外部规范，但此类“策略感知”防护仍主要基于提示（prompting）或监督微调（SFT），难以适应未见过的轨迹和动态政策组合，无法直接优化模型使用策略的方式。
- 论文核心思路：把安全策略从被动上下文变为可调用的能力（callable capability），通过强化学习直接优化“策略调用 → 策略内容 → 安全推理 → 安全预测”的完整决策过程，从而提升智能体安全防护的适应性和可解释性。

## 2. 提出的方法论

**核心思想**
- 将安全策略调用建模为一个智能体强化学习任务：给定完整轨迹 τ 和候选策略库 P，防护模型先调用一个适用策略，再基于该策略的内容生成基于策略的推理（rationale）和安全标签。
- 完整流程：策略调用 → 策略内容注入 → 安全推理 → 安全判断。

**关键公式与结构**
- 任务形式化：
  - 策略调用：\(\hat{p} \sim \pi_\theta(\cdot|\tau, P)\)
  - 安全判断：\((\hat{r}, \hat{y}) \sim \pi_\theta(\cdot|\tau, P, \hat{p}, c(\hat{p}))\)
- 冷启动监督训练（SFT）损失：
  - \(L_{\text{SFT}} = -\frac{1}{N}\sum_i [\log \pi_\theta(p_i^*|\tau_i, \tilde{P}_i) + \log \pi_\theta(r_i, y_i|\tau_i, \tilde{P}_i, p_i^*, c(p_i^*))]\)
  - 其中 \(\tilde{P}_i\) 为包含适用策略 p* 和干扰策略 P− 的局部策略库。

**强化学习优化（GRPO）**
- 在冷启动模型基础上使用 GRPO，比较多个 rollout，通过可验证奖励优化完整防护流程。
- 奖励设计：
  - \(R = \lambda_{fmt} R_{fmt} + \lambda_{pol} R_{pol} + \lambda_{acc} R_{acc}\)
  - 格式奖励 \(R_{fmt}\)：判断交互格式是否有效；
  - 策略调用奖励 \(R_{pol} = \mathbb{I}[\hat{p}_i = p_i^*]\)；
  - 判断准确率奖励 \(R_{acc} = \mathbb{I}[\hat{y}_i = y_i]\)。
  - 默认权重为格式 0.1、策略调用 0.3、判断准确率 0.6。

**策略上下文扰动（Policy-Context Perturbation）**
- 训练时对每个轨迹重新采样干扰策略（包括无关场景有效策略和合成诱饵策略），并打乱策略库顺序与策略标识符，防止模型记忆固定轨迹-策略关联或过度依赖候选库结构。

**数据构建：PolicyTraj-20K**
- 通过轨迹合成（基于现有交互模式，用 API 模型重写任务内容与表面形式）扩展覆盖范围；
- 按“智能体操作场景”而非最终风险类别组织安全策略库；
- 为每条轨迹标注适用策略、相关条款、安全标签和决策依据；
- 最终得到超过 20,000 条策略标注轨迹，支持监督初始化和强化学习。

## 6. 主要结论与发现

- RePolicy-4B 在 Overall Unsafe F1 上达到 88.15，超过最强外部模型 3.98 分，超过最强专用防护模型 8.46 分；在六个基准中四个排名第一，其中 OpenAgentSafety、ASSEBench、AgentHazard 分别超出最强外部基线 2.55、5.26、5.47 分。

- 模型能拓宽有效策略调用（每个轨迹平均调用从约 1.9 增加到 3.2 个策略），同时诱饵策略选择率始终低于 1%。

- 消融结论：
  - PolicyTraj-20K 冷启动 SFT 带来巨大增益（Overall +28.48）；
  - 显式策略调用是 RL 阶段最重要的组件，全部六个基准上均有提升，平均 +2.32 分，尤其在 AgentHazard（+5.9）和 OpenAgentSafety（+4.4）上显著；
  - 策略上下文扰动也有正向贡献。
- 附录结果表明，RePolicy 不仅提升二分类准确率，还同时改善了“调用哪个策略”和“如何将策略内容转化为决策”两个层面，并带来更均衡的误报/漏报权衡，尽管推理成本更高。

## 7. 优点

- 创新视角：将安全策略视为可调用能力，而非被动文本，利用强化学习直接优化策略调用与安全判断，思路清晰且有别于提示/SFT 范式。
- 可验证奖励设计：格式、策略调用、判断准确率三项规则奖励完全可验证，不依赖模型打分，训练信号稳定。
- 策略上下文扰动设计巧妙：在训练中注入无关策略和诱饵策略，防止模型走捷径，增强真实部署中的鲁棒性。
- 数据集贡献：构造了 PolicyTraj-20K，覆盖多种工具、环境和场景，并赋予轨迹级策略调用和监督信息，填补了现有数据无法同时提供轨迹级判断与条款级策略依据的空白。
- 实验覆盖面广：六个基准、19 个基线、多个深度分析实验，消融和鲁棒性分析较完整，且给出了定性案例，支撑可解释性主张。
- 开源承诺：提供代码、训练流程、数据集拆分、检查点等，利于复现。

## 8. 不足与局限

- 依赖策略库质量：RePolicy 假设候选策略库中存在适用且足够精确的策略，覆盖面不足、范围模糊、要求过时或策略间冲突会直接影响判断质量。
- 单策略假设：当前公式为每条轨迹只关联一个主策略，真实部署可能需要在操作、组织、监管等多层级联合应用多个策略。
- 推理开销：显式策略调用增加了额外交互步骤，比单次防护模型更慢；论文也承认这一点。
- 评估范围有限：仅基于 4B 规模骨干，且只评估离线轨迹级二分类；未涵盖多语言部署、持续演化环境、在线干预或“何时中断正在执行的智能体”等实际需求。
- 奖励未完全保证推理忠实性：可验证奖励只检查最终标签和策略 ID，不保证生成的 rationale 中每一句都严格忠实于所调用策略。
- 数据与评测偏差风险：PolicyTraj-20K 由合成变换构建，可能与真实部署日志分布存在偏差；AgentHazard 无安全样本，OpenAgentSafety 规模小，可能影响泛化结论的稳健性。
- 部分消融结果标注为临时值（provisional），且论文未报告训练总时长，复现成本与效率信息不完整。

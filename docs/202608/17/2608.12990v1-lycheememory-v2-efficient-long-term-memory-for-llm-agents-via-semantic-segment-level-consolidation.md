## 摘要
长时程LLM智能体必须保留过去交互中的信息以支持未来任务。现有记忆系统通常依赖主动整合，在每次交互后调用LLM来提取、总结或更新记忆。这种设计导致随着对话增长，记忆构建成本不断增加。粗粒度总结可以降低构建成本，但可能丢失细粒度的上下文证据，而更大的检索上下文或多跳LLM推理则会将开销转移到查询阶段。我们提出LycheeMemory V2，一种高效的长期记忆框架，用语义片段级整合取代回合级整合。LycheeMemory不是整合每次交互，而是将多次交换批量处理为片段，并将每个已定稿的片段编码为上下文无关的类型化记忆记录。片段级批处理降低了LLM编码频率，而语义边界检测相比固定窗口批处理有助于保留连贯的事件级和时间级证据。生成的记录通过轻量级结构化索引组织，用于查询规划的证据检索。使用GPT-4.1-Mini进行的实验表明，LycheeMemory达到了最先进的性能，在LoCoMo上达到89.22%，在LongMemEval-S上达到92.20%。与A-Mem相比，它在LoCoMo上将构建词元减少了86.0%，在LongMemEval-S上减少了75.9%，且未增加查询时词元使用量。更广泛地说，我们的结果表明，长期智能体记忆的准确性与成本权衡不仅取决于保留了什么信息，还取决于以何种粒度进行整合。

## Abstract
Long-horizon LLM agents must preserve information from past interactions to support future tasks. Existing memory systems typically rely on eager consolidation, invoking LLMs after each interaction to extract, summarize, or update memories. This design makes memory construction increasingly costly as conversations grow. Coarse summarization can reduce construction cost but risks discarding fine-grained contextual evidence, whereas larger retrieval contexts or multi-hop LLM reasoning shift the overhead to query time. We present LycheeMemory V2, an efficient long-term memory framework that replaces turn-level consolidation with semantic segment-level consolidation. Instead of consolidating every interaction, LycheeMemory batches multiple exchanges into segments and encodes each finalized segment into context-independent typed memory records. Segment-level batching lowers LLM encoding frequency, while semantic boundary detection helps preserve coherent event-level and temporal evidence compared with fixed-window batching. The resulting records are organized with lightweight structured indexes for query-planned evidence retrieval. Experiments using GPT-4.1-Mini show that LycheeMemory achieves state-of-the-art performance, reaching 89.22% on LoCoMo and 92.20% on LongMemEval-S. Compared with A-Mem, it reduces construction tokens by 86.0% on LoCoMo and 75.9% on LongMemEval-S without increasing query-time token usage. More broadly, our results suggest that the accuracy--cost trade-off of long-term agent memory depends not only on what information is retained, but also on the granularity at which it is consolidated.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：长时程LLM智能体（如个人助理、客服、辅导系统等）需要在多会话、长对话场景中持续记忆用户偏好、历史事件、演化事实、约束和过往失败经验。由于LLM无法在有限上下文窗口中保留无限交互历史，外部记忆模块成为必要组件。
- **核心痛点**：现有记忆系统通常采用“急切整合”（eager consolidation）策略——每次交互（回合）后都调用LLM来提取、总结或更新记忆。这种设计存在三方面问题：
  - **构建成本高**：LLM调用频率随对话轮数线性增长，token消耗迅速膨胀；
  - **粗粒度总结丢失证据**：降低成本后可能丢弃实体、时间表达、共指关系等细粒度上下文线索；
  - **查询端补偿成本转移**：扩大top-k检索或使用迭代LLM多跳搜索虽可提升召回，但将开销转移到查询阶段。
- **核心洞察**：长期记忆的准确率-成本平衡不仅取决于“保留什么信息”，还取决于**“以什么粒度进行整合”**（consolidation granularity）。

## 2. 提出的方法论

### 2.1 核心思想
LycheeMemory V2 用**语义片段级整合**（semantic segment-level consolidation）取代回合级整合（turn-level consolidation）。将多轮交换批量分成语义连贯的片段，每个片段只调用一次LLM编码，显著降低构建频率。

### 2.2 四个关键组件

**(1) 在线语义分割（Online Semantic Segmentation）**
- 使用纯嵌入（embedding）方法判断片段边界，无需LLM参与；
- **语义惊喜度**（semantic surprise）公式：\( s_t = 1 - max(sim(e_t, c_k), sim(e_t, h_k)) \)——衡量新交换对当前片段全局主题和局部对话轨迹的偏离程度；
- **内聚度下降**（cohesion drop）：比较加入新交换前后片段内聚度的变化；
- **综合边界分数**：结合语义惊喜度、内聚损失、token长度压力和轮数压力，经sigmoid函数转换为cut概率，超过阈值即定稿当前片段。默认阈值0.50，硬性token上限900，最大交换数10；
- 嵌入模型使用 text-embedding-3-small，整个过程无生成式调用。

**(2) 片段级记忆编码（Segment-Level Memory Encoding）**
- 每个定稿片段通过一次LLM调用完成三件事：提取原子信息单元、解析共指与省略表达、基于会话时间戳归一化相对时间表达；
- 每条记录为上下文无关的类型化记录：`record_id, memory_type, text, entities, keywords, temporal, provenance`；
- 记忆类型涵盖：事实、偏好、事件、约束、程序、失败模式、工具能力；
- 跨片段连续性：通过轻量级**消歧状态**（entity aliases、规范化实体名、参照关系）和受限的**参照上下文**（最近m条记录摘要，有token预算上限）实现，不会随历史增长而膨胀。

**(3) 结构化证据组织（Structured Evidence Organization）**
- 无需额外LLM调用，仅凭嵌入计算和SQLite/FTS5索引写入；
- 构建五类证据节点：实体节点、主题节点、实体-主题节点、时间节点、事件帧节点；
- 保留文本性不同的独立语句为独立记录（不进行语义合并或过期推断），将冲突解决留给检索与答案生成阶段。

**(4) 计划引导的多路线检索（Plan-Guided Multi-Route Retrieval）**
- 查询阶段仅一次LLM调用（查询规划器），后续全部为非生成操作；
- 规划器将查询分解为：问题类型 + 多条回忆路线（每条含目标、查询词、约束、时间过滤）；
- 每条路线并行执行四通道召回：直接记录召回、证据节点召回（实体/主题/实体-主题/事件帧）、时间召回、原始轮次召回；
- 使用**倒数排名融合**（RRF）合并各路候选：\( RRF(d) = \sum_{j=1}^{m} \frac{1}{\kappa + rank_j(d)} \)，再经轻量级交叉编码器（bge-reranker-v2-m3）重排序和多样性感知选择；
- 最终得分：\( s_{final} = 0.82s_{best} + 0.18s_{route} \)，多样性选择采用MMR式目标：\( s_{select} = 0.75s_{rel} - 0.25s_{sig} \)。

## 6. 主要结论与发现

- **SOTA准确率**：GPT-4.1-Mini下，LoCoMo达到89.22%（比Full Context高4.42 pp，比最强基线TiMem高5.45 pp），LongMemEval-S达到92.20%（比最强基线TiMem高16.40 pp）；
- **构建成本大幅降低**：相比A-Mem，构建token在LoCoMo减少86.0%（204.1K vs. 1459.9K），LongMemEval-S减少75.9%（304.7K vs. 1264.3K）；
- **查询成本不升反降**：LoCoMo查询token比A-Mem低27.9%（4.01K vs. 5.56K），LongMemEval-S低42.6%（8.88K vs. 15.46K）——准确率提升并非来自查询端context扩张或多步LLM推理；
- **消融验证**：片段级批处理降低构建成本（消除后token从204.1K增至849.9K），语义边界检测提升准确率（比固定窗口高6.8 pp），类型化记录比摘要式记录高8.4 pp，检索融合/重排/多样性选择贡献最大（移除后下降22.6 pp）；
- **核心结论**：记忆整合粒度（而非仅信息内容）是决定准确率-成本平衡的关键设计维度。

## 7. 优点

- **设计理念清晰**：精准识别“整合粒度”这一常被忽视的效率杠杆，将构建频率从每轮降至每语义段；
- **成本意识贯穿全程**：分割阶段零LLM调用、检索阶段仅一次规划调用，其余均为非生成操作，从架构上控制了token消耗；
- **精确保留证据**：类型化记录（实体/主题/时间/来源）+ 结构化索引（实体、主题、时间、事件帧）使细粒度信息可被检索且无需原始上下文即可理解；
- **跨片段连续性设计巧妙**：以受限预算的消歧反馈维持实体与指代一致性，不随历史增长而膨胀；
- **实验分析严谨**：将构建成本与查询成本分开报告，杜绝了“把成本从一个阶段转移到另一个阶段”的虚假收益；消融实验将批处理（成本因素）与语义边界（准确率因素）分离验证；
- **评估公平**：统一骨干模型、统一判断协议、明确token计量范围，确保对比可信。

## 8. 不足与局限

- **偏好类问题仍非最优**：LongMemEval-S上GPT-4.1-Mini偏好追踪仅90.00%，低于MemoryOS的100.00%；GPT-4o-Mini下70.00%，低于MemOS的96.67%——表明专门的用户画像模块可能对偏好密集查询有独特优势；
- **模态覆盖有限**：仅覆盖文本对话记忆，未涉及多模态记忆（图像、音频等）；
- **基准规模局限**：LoCoMo仅10个会话语料，规模较小；LongMemEval-S虽然是500实例但每实例仅一个问题，评估单元不同导致两基准结论难直接横向归纳；
- **未覆盖部署维度**：生产环境下的数据库延迟、嵌入索引存储增长、长期在线反馈、隐私治理、缓存行为均未评估；
- **优化目标单一**：以token成本为核心度量，对延迟、存储、基础设施开销等未做量化分析；
- **依赖API评估**：主要使用托管LLM/嵌入API，若替换为开源模型，模型能力与token计量可能变化，需要重新报告准确率与成本数据；
- **阈值超参数**：虽然有敏感性测试（1.04 pp变化）表明稳定性较好，但仍是一个需要标定的超参数；
- **知识冲突处理**：系统有意保留冲突/过时记录（不做自动过期推断），将冲突解决完全留给检索与生成阶段，可能增加查询端推理负担。

## 摘要
使LLM智能体能够在长时间跨度内维持富有成效、稳定且与目标一致的研究，是自主机器学习和科学发现中的一个核心挑战，因为进展取决于持续管理不断变化的状态、探索决策和计算资源。尽管开创性的自动研究智能体取得了巨大成功，但仍然缺乏连续性、从死胡同中恢复以及价值驱动的计算分配机制，这从根本上削弱了整体搜索效率，浪费了计算资源，并降低了最终成功的可能性。为了弥合这一差距，我们引入了ScienceFlow，一个端到端的自动研究智能体框架，它将长时间跨度的研究工作组织成基于可执行工作区的研究片段。它将研究进展表示为可恢复的可执行状态，从而实现高效的探索、修订和执行。研究片段之间的转换由通过重新锚定的可执行状态转换（ESTRA）管理，该机制选择活动状态或存档状态作为下一个锚点，并决定是继续还是重定向研究轨迹。一个基于证据的执行控制器根据资源可用性、剩余预算和已验证的进展来分配物理作业的资源。我们在涵盖机器学习、科学建模和数学优化的任务上评估了ScienceFlow。在多样化长时间跨度基准上的结果表明，它能够维持有效的研究过程，在24小时预算内，在完整MLE-bench上取得了最先进的70.22%任意奖牌分数，比先前报告的结果高出4.92个百分点。ScienceFlow的有效性进一步表明，高效的状态管理、自适应探索和与目标对齐的执行对于将自主研究扩展到短时间跨度交互之外至关重要。

## Abstract
Enabling LLM agents to sustain productive, stable, and goal-aligned research over extended horizons is a central challenge for autonomous machine learning and scientific discovery, as progress hinges on continuously managing evolving state, exploration decisions, and computational resources. Pioneering autoresearch agents, despite great success, still lack mechanisms for continuity, recovery from dead ends, and value-driven compute allocation, which inherently undermines overall search efficiency, wastes computational resources, and lowers the chance of ultimate success. To bridge this gap, we introduce ScienceFlow, an end-to-end autoresearch agent framework that organizes long-horizon research work into research segments grounded in executable workspaces. It represents research progress as recoverable executable states, enabling efficient exploration, revision, and execution. Transitions between research segments are governed by Executable-State Transition through Re-Anchoring (ESTRA), which selects either the live state or an archived state as the next anchor and determines whether to continue or redirect the research trajectory. An evidence-aware execution controller allocates resources to physical jobs based on resource availability, remaining budget, and validated progress. We evaluate ScienceFlow on tasks spanning machine learning, scientific modeling, and mathematical optimization. Results on diverse long-horizon benchmarks demonstrate its ability to sustain effective research processes, highlighted by a SOTA 70.22 percent Any-Medal score on the full MLE-bench within a 24-hour budget, outperforming prior reported results by 4.92 percentage points. The efficacy of ScienceFlow further demonstrates that efficient state management, adaptive exploration, and objective-aligned execution are critical for scaling autonomous research beyond short-horizon interactions.

## 二、方法论

### 2.1 核心思想

ScienceFlow 将长时程研究组织为**可执行工作区**中的研究片段（research segments），并以**可恢复的可执行状态**（recoverable executable states）表示研究进展。整体框架由两大层次构成：

- **研究层**：研究工作者（research worker）负责科学路线选择，包括前向研究、ESTRA 转换、状态检查点。
- **执行层**：证据感知执行控制器（evidence-aware execution controller）负责物理资源分配和执行监控，不参与科研路线决策。

### 2.2 研究状态表示（Research State Representation）

每个可恢复状态 `sv` 定义为四元组：

```
sv = ( Wv , m v , e v , ℓ v )
```

- `Wv`：工作区快照（源代码、数据、模型检查点、缓存特征、验证输出、环境元数据等）
- `mv`：结构化研究记忆（跨片段持久化、压缩）
- `ev`：验证证据（`ev = VG(sv)`）
- `ℓv`：资源记录（资源账本在检查点时刻的记录）

所有状态存入状态档案库（archive）`AT`，可随时检索、恢复。

### 2.3 前向研究（Forward Research）

- 每个研究片段内，worker 执行标准的**推理 → 行动 → 观察**循环：

  ```
  (rn,j , α n,j ) ~ πLLM (· | Pn , h n,j )
  (on,j , W n,j+1 ) = Exec ( αn,j ; Wn,j )
  h n,j+1 = h n,j ⊕ (rn,j , α n,j , o n,j )
  ```

- **阶段门控（Stage Gate）**：当检测到任务特定的结果信号时，对当前工作区做快照、评估验证证据、记录资源，形成状态并存入档案库。状态检查点可在同一片段内多次发生。
- **片段边界触发条件**：
  1. 策略产生纯文本响应（无工具调用，`α = ∅`）；
  2. 累计上下文超过容量阈值（`|Pn ⊕ hn,j+1| ≥ Lctx`）。

### 2.4 ESTRA：通过重新锚定的可执行状态转换

ESTRA（Executable-State Transition through Re-Anchoring）在片段边界做出**双向决策**：

- **锚点选择** `an`：当前状态 `scur_n` 或某个历史存档状态 `sv ∈ AT`
- **方向选择** `dn`：继续（extend）或重定向（redirect）

结合两个轴得到四种结果：从当前状态延续 / 从当前状态重定向 / 从存档状态延续 / 从存档状态重定向。

数学形式：

```
an ∈ { scur_n } ∪ A n ， dn ∈ { extend , redirect }
(P n+1 , W n+1,0 ) = ESTRA ( an , d n ; A n )
```

当选择存档状态时，ScienceFlow 精确恢复该状态的完整快照（工作区、记忆、验证证据、资源记录），资源核算保持累计。被放弃的分支会被压缩为已完成证据（folded evidence），但原始记录仍可通过 Unfold 访问。

### 2.5 记忆与上下文组装

- **Add**：阶段门控事件时，将结果卡片 `qv` 追加至持久记忆 `mv`。
- **Fold**：记忆超出预算 `Bmem` 时压缩为紧凑视图 `emv` + 索引 `ιv`；片段边界时也会触发独立的折叠操作。
- **Unfold**：锚点选择前，检索与某个索引关联的完整历史记录。
- **Assemble**：将稳定前缀（worker 策略 + 运行时指令 + 工具描述 + 任务规范）与锚点特定上下文、ESTRA 方向组合成下一片段的完整上下文。

### 2.6 证据感知执行控制（Evidence-Aware Execution Control）

采用两阶段闭环控制：

**（1）执行准入与分配（Admit）**

对于每个可执行作业 `b`，评估资源状态 `Rt`、剩余预算 `Bt` 和科研价值提示，产生四种决策之一：

```
δ_adm ∈ { RUN NOW , OBSERVE THEN RUN , PENDING , REPLAN }
```

**（2）在线审查与重规划（Review）**

持续收集存活状态、日志增长、资源利用率、指标变化、可恢复工件等执行证据，结合剩余预算产生控制决策：

```
c t ∈ { CONTINUE , TIMEBOX , STOP AND REPLAN }
```

- 当证据不确定时，控制器可向研究 worker 请求资源建议（continue / timebox / safe to stop / replan / unknown），但**最终终止权归控制器所有**。
- STOP AND REPLAN 前保留可恢复工件、释放租约、返回执行事实给 worker；该决策**不直接选择 ESTRA 锚点或方向**，属于执行层行为。

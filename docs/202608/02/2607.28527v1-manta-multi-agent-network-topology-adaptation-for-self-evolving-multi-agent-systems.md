## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题解决能力。然而，现有系统通常将通信拓扑视为固定设计选择或离线优化目标。我们提出MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自我进化。在执行前，MANTA从先前的结构经验中初始化一个任务条件的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界结构更新。这些更新可以修改智能体角色、通信链接、执行顺序、信息可见性和验证路径，同时保持任务接口和智能体预算不变。我们在五个基准上将MANTA与代表性的单智能体和多智能体基线进行比较，涵盖信息检索、工具使用、规划、工作流执行和数学推理。MANTA取得了74.0的最高平均分，优于最强基线5.8个百分点，并在PlanCraft上获得最佳结果。这些结果表明，推理时的自我改进可以扩展到协作架构本身。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

- **目标**：为每个任务动态选择和调整多智能体通信拓扑，并在执行中发现结构失效时进行有界修复。
- **核心思想**：将“拓扑”视为一个可实时修改的对象，通过“任务条件化初始规划 + 执行轨迹审计 + 有界结构变异 + 跨运行经验积累”四步闭环，实现协作架构的自我进化。

### 系统架构（双层嵌套）
- **目标多智能体系统层**：负责实际任务求解（推理、工具调用、消息交换）。
- **编排层**：由确定性代码与三个 LLM 组件（Topology Planner、Trace Auditor、Skill Reflector）协同工作，负责选择智能体、设计拓扑、执行审计、控制修复与停止。

### 拓扑表示
- 每个智能体具有**结构角色**（coordinator、worker、verifier、debater、voter）和**阶段角色**（worker 或 critic）。
- 智能体可组成预定义的交互模式组（star、chain、debate、voting、singleton 等），组可嵌套，支持子组委派与汇报；也可补充直接连接边。
- 每个智能体有独立的**上下文策略**（可见消息、发送者范围、证据读取权限、汇总结 vs 全文等），由代码在读取时强制实施。
- 执行前会进行结构校验（组归属、环路、角色、智能体预算），无效提案被拒绝。

### 编排循环
1. **查询条件化规划（Query-conditioned Planning）**
   - Planner 接收任务与经验记忆，分析任务类型、属性（模糊性、并行性需求、辩论/验证需求、幻觉风险等）和失败风险，然后生成紧凑的拓扑计划（交互模式、智能体数量、可选的验证器/嵌套组）。
   - 确定性代码将计划展开为完整拓扑，分配角色和上下文策略，并校验结构约束。
   - 若 Planner 输出无效，则使用确定性回退拓扑（如 coordinator-worker star 或 singleton）。

2. **回合执行（Turn Execution）**
   - 每个协作回合按组结构递归执行；智能体通过“结构化中继包”（relay packets）通信（包含答案、证据、置信度、未解决问题）。
   - 共享上下文控制器强制每个智能体的可见性策略；相同的工具调用被去重；追加式证据账本记录各分支产生的声明与支撑证据。
   - 每个智能体在共享 harness 中运行，具备“agentic loop”（工具调用循环），带有多种确定性守卫（重复调用检查、停滞搜索检查、失败熔断器、读门、强制最终回答）。

3. **轨迹审计与修复（Trace Auditing and Repair）**
   - 每回合后，Trace Auditor（LLM）扫描结构化工件、工具记录、中继包、置信度、未解决问题和证据可见性，报告可观测的**过程风险**（而非答案正确性）。
   - 确定性审计分类器识别固定模式：工具错误级联、分支塌缩、无证据的不可解声明、证据丢失、过早共识、消息压缩损失、搜索覆盖不足、重复状态变更、缺少验证器、放弃型答案等。
   - Controller 根据审计结果决定：最终化答案，或允许一次有界修复（每个运行最多一次变异，每次最多 3 个操作）后执行最终回合。
   - 修复操作包括：add_agent、expand_agent_to_group、set_group_pattern、add/remove_edge、set_context_policy；检索密集任务使用确定性“retrieval contraction”而非 Planner 变异语言。

4. **双时间跨度记忆（Two-Horizon Playbook Memory）**
   - **短期 playbook**：记录当前运行的每个回合的拓扑、审计标志、修复建议和控制器决策；使 Planner 在修复时了解“已尝试的结构”和“可观测异常”。
   - **长期 playbook**：存储将“任务特征 + 过程风险 → 拓扑选择”的一般性原则，由 Skill Reflector 每 N 次运行（文中 N=12）根据过程信号（无审计标志 + 决策级共识）重写。
   - 长期 playbook 的学习过程完全不接触基准答案或验证结果，仅使用过程标签。

### 算法流程（文字描述）
```
输入:任务 T, 长期 playbook L
1. Planner 使用 L 和任务预览生成初始拓扑计划 P0
2. 确定性代码展开 P0 为完整拓扑, 校验结构
3. 执行第一个协作回合
4. Trace Auditor 检查轨迹, 产生过程标志
5. 若审计干净 → 进入最终化(投票/综合)并输出答案
6. 若审计发现可修复缺陷 → Controller 允许一次拓扑变异:
   - Planner 基于当前拓扑、审计报告、短期/长期 playbook 生成一个变异(≤3 操作)
   - 代码应用变异并校验; 无效则保守修复或跳过
   - 执行最终回合
7. 短期 playbook 记录本回合信息; 批处理更新长期 playbook
输出:最终答案 + 更新后的长期 playbook
```

## 6. 论文的主要结论与发现

- **MANTA 显著优于所有基线**：平均 74.0 分，比最强基线（ADAS，68.2）高 5.8 个百分点；在 PlanCraft 上取得最佳（76.7），在 BrowseComp 上也大幅领先（76.7 vs 次优 64.4）。
- **初始拓扑规划贡献最大**：消融中去除初始条件化规划后，平均成功率为 57.5%（下降 14.2 个百分点）；去除拓扑变异后为 60.8%（下降 10.9 个百分点）。
- **拓扑修复带来的收益主要集中在第一次变异**：从 0 到 1 的预算增长提升最显著，后续变异边际收益递减。
- **长期 playbook 可迁移且有效**：跨域迁移 PlanCraft→WorkBench 和 WorkBench→PlanCraft 均获正收益（平均 +3.3%），而同域 reuse 也提升 3.3 个百分点；相比之下 ADAS、AgentSquare、MASS 的迁移产生中性或明显负面效果。
- **MANTA 是最节省 token 的多智能体系统**：推理时约 77,652 tokens/运行（4 基准平均），低于所有静态 MAS 和优化方法的总消耗（含离线搜索成本）；meta 级操作仅占约 12%。
- **轨迹审计是有效的可靠性代理**：无修复标志的运行正确率（83.2%）显著高于有标志的运行（62.5%），相差 20.7 个百分点；审计识别出 117 个错误运行中的 75 个。
- **拓扑演化并非简单地增加智能体数量**：五类典型修复中仅“分支扩展”增大系统规模；其他修复涉及序列化执行、重连通信、插入 critic 角色（验证而非求解），说明有效的结构修复取决于轨迹中暴露的结构性失效模式。

  - 除主结果外还提供消融、预算影响、迁移性、token 消耗、审计质量、修复操作分布等分析；
  - 对审计标志与正确性的相关性进行了细致探讨（如证据丢失、缺少验证器为强信号，消息压缩损失和工具错误级联为弱信号），并指出去权重化的改进方向；
  - 提供了详细的提示词、审计模式表、变异操作表、harness 设计等实现细节，可复现性强。

## 8. 不足与局限

- **实验规模有限**：每个基准仅 30 道题、3 次运行，统计显著性不足；MATH 任务对协作结构敏感度低，稀释了方法优势；WorkBench 上 MANTA 得分（43.3）低于 ADAS（66.7）、AgentSquare（62.2）等，说明在部分工作流场景中并非最优。
- **数据与硬件细节缺失**：未说明 GPU 型号、数量、训练/推理耗时，无法精确评估算力成本。
- **审计缺乏人工标注验证**：审计统计中的“精确率/召回率”以答案正确性为代理，不是对过程缺陷的真实检测；部分标志（如过早共识）的“清除”只说明下一审计未出现，不代表结构修复一定有效。
- **修复效果的因果性未完全隔离**：论文指出预/后比较是审计输出层面的观察，未做“同一轨迹前缀下对比变异与非变异”的配对重放实验，也无人对过程失败进行人工标注；因此尚不能完全断言“变异一定带来改进”。
- **跨域迁移范围窄**：仅测试了 PlanCraft 与 WorkBench 两个规划/工作流基准，未覆盖信息检索、工具使用、数学推理等其他领域；且迁移实验仅在变异预算为 0 时进行，未检验“经验 + 修复”组合的跨域效果。
- **单次修复限制**：每个运行最多一次变异（虽然预算实验允许 0–3 次变异，但主实验默认 1 次），实际多阶段复杂任务可能需要多次结构调整。
- **对基准身份的隐藏不够彻底**：Planner 的用户消息中明确包含“benchmark name”，虽然声称“never sees the benchmark identity beyond the name of the task source”，但仍存在通过任务来源名称泄漏先验偏见的风险。
- **长期 playbook 学习的验证条件较宽松**：使用“无过程标志 + 决策级共识”作为高收益过滤条件，其正确率 85.8%（对整体 74.0%），仍有约 14.2% 的错误率，不能作为正确性标签。

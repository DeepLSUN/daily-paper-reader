## 摘要
随着基于LLM的智能体被部署到复杂、多步骤的工作流中，一个关键的评估缺口已经出现：大多数现有基准仅评判最终结果，无法区分可靠推理与侥幸成功，也无法将失败归因于特定的过程缺陷，这阻碍了在长周期任务中的归因分析。在这项工作中，我们提出了ClawTrack，一个双重评估基准，同时衡量智能体实现了什么（任务分数）以及如何实现（过程分数）。ClawTrack包含8个领域的320个任务，以及25个以上确定性的模拟服务。一个过程评分器沿四个维度（目标对齐、效率、信息利用和结果验证）对每个推理步骤进行评分，由12,541个任务特定的评分细则条目支撑。在超过16,000次试验中评估21个模型，我们发现：(1) 过程分数能有效地将成功和失败归因于特定的推理维度，过滤掉仅评估结果时不可见的侥幸通过；(2) 这四个维度是互补的，其中结果验证是系统性瓶颈；(3) 该框架对不同评判LLM的选择具有鲁棒性；(4) 基于过程的轨迹过滤在不同模型规模下产生一致的训练后改进。

## Abstract
As LLM-based agents are deployed in complex, multi-step workflows, a critical evaluation gap has emerged: most existing benchmarks judge only final outcomes, unable to distinguish reliable reasoning from lucky success or attribute failures to specific process deficiencies, hindering attribution in long-horizon tasks.   In this work, we present ClawTrack, a dual-assessment benchmark that simultaneously measures what an agent achieves (Task Score) and how it achieves it (Process Score). ClawTrack comprises 320 tasks across 8 domains with 25+ deterministic mock services. A Process Grader scores each reasoning turn along four dimensions (goal alignment, efficiency, information utilization, and result verification), anchored by 12,541 task-specific rubric items. Evaluating 21 models over 16,000+ trials, we find that: (1) process scores effectively attribute success and failure to specific reasoning dimensions, filtering lucky passes invisible to outcome-only evaluation; (2) the four dimensions are complementary, with result verification as the systematic bottleneck; (3) the framework is robust to evaluator choice across different judge LLMs; and (4) process-based trajectory filtering yields consistent post-training improvements across model scales.

## 1. 核心问题与整体含义（研究动机与背景）

- **现有评估范式的根本缺陷**：主流的智能体基准（如 GAIA、OSWorld、τ-bench 等）普遍采用**仅结局评估（outcome-only evaluation）**，即仅根据最终状态是否满足任务要求来打分，将整个多步执行过程压缩为单一判断。这种"轨迹不透明式评分"产生两个关键盲区：
  - **掩盖不可靠的成功**：无法区分"遵循原则性推理路径"与"通过低效探索或侥幸捷径得到正确答案"，后者在重复试验中极不稳定，导致能力被高估。
  - **失败无法归因**：当智能体失败时，无法判断根因是目标分解错误、搜索低效、信息综合不足还是缺乏自我验证——这些不同类型的缺陷需要截然不同的修复策略。
- **研究意义**：随着 LLM 智能体被部署到高风险复杂工作流中，任务执行的方式直接关系到安全性、合规性和用户信任，过程层面的结构化评估已成为不容忽视的关键缺口。本文提出的 ClawTrack 试图将**过程质量**作为与任务结果并列的一等评估信号。

## 2. 论文提出的方法论

### 2.1 核心思想

ClawTrack 的核心论点是：**过程质量是一个独立的、多维度的构念（construct），应当与任务结果并列测量，而不是仅仅从结果中派生**。为此设计了一个双评估（dual-assessment）框架，同时回答"智能体实现了什么"和"它如何实现"两个问题。

### 2.2 系统架构（四层结构）

| 层次 | 功能 |
|------|------|
| **任务层（Task Layer）** | 320个任务×8个领域，每个任务包含自然语言指令、输入附件、参考答案、任务特定 rubric，以及 mock 服务端点声明 |
| **框架层（Harness Layer）** | 在 Docker 工作区中启动 25+ 确定性 mock 服务，注入文件，确保多轮试验的初始状态一致；代理通过 ReAct 循环迭代执行，记录完整轨迹 |
| **评估层（Evaluation Layer）** | 两个独立评分器：过程评分器（Process Grader）和结果评分器（Outcome Grader），分别基于互补的证据源打分 |
| **报告层（Reporting Layer）** | 聚合多轮试验分数，生成可靠性感知指标（Pass@k 和 Pass-k）、维度诊断画像、领域/能力细分排名 |

### 2.3 评分协议（核心公式）

**任务分数（Task Score）**：
```
s_task = s_safe · (α·s_comp + β·s_rob)
```
- `s_comp ∈ [0,1]`：完成度分数（确定性检查 + LLM 判断）
- `s_safe ∈ {0,1}`：安全分数（乘法门控，不安全→总分归零）
- `s_rob ∈ [0,1]`：鲁棒性分数（工具错误恢复能力）
- 权重：α=0.80, β=0.20（完成度主导，鲁棒性为次级信号）

**过程分数（Process Score）**，每回合 t 沿四个维度打分：
```
s_proc(t) = g_t · (w_e·e_t + w_i·i_t + w_v·v_t)
```
- `g_t`（目标对齐）：乘法门控，偏离目标则整回合归零
- `e_t`（效率）、`i_t`（信息利用）：各 0.40 权重
- `v_t`（结果验证）：0.20 权重（并非每回合都需要验证）
- 轨迹级过程分数为所有回合的算术平均

**双阈值通过标准（Dual-Threshold Passing）**：
```
pass = 1[s_task ≥ 0.75 ∧ s_proc ≥ 0.60]
```
每个任务执行 k=3 次独立试验；Pass@3 衡量峰值能力，Pass-3 衡量部署一致性。

### 2.4 半自动 Rubric 生成管道

- **人工种子**：8个领域各5名专家为40个种子任务编写过程 rubric，标注者间一致性 Cohen's κ=0.874
- **LLM 蒸馏**：用 Claude-Opus-4.8 从种子 rubric 中提炼可复用的"rubric 生成技能"，为其余280个任务自动生成 rubric
- **人工审查**：自动一致性检查（单调层级排序、维度覆盖）+ 领域标注者修订
- **最终规模**：12,541 个 rubric 条目（每任务平均 39.2 个）
- **回合级、阶段感知粒度**：按行为阶段（早期探索、信息收集、工具调用、综合、自我验证）分别设置评分锚点，避免对不适当阶段的正确行为产生误罚

### 2.5 过程感知轨迹过滤（用于训练后优化）

- 从 ToolBench、τ-bench、WildClawBench 收集约 20k 条轨迹（由 Claude-Opus-4.7、GPT-5.5、GLM-5.2 等模型生成）
- 保留条件：(1) 结果正确（按源基准 oracle）；(2) 平均过程分数 s_proc ≥ 0.65（略高于评估阈值）
- 与传统"仅基于结果正确性"的过滤相比，过程感知过滤能剔除"答案正确但推理过程有缺陷"的低质量轨迹

## 6. 主要结论与发现

1. **峰值能力与一致性可能背离**：Claude-Opus-4.7 在 Pass@3 领先但 Claude-Opus-4.8 在 Pass-3 领先，单一试验表现最优的模型并非最可靠——这一分歧只有双评估体系才能揭示。

2. **过程分数与任务成功相关但独立**：Pearson r=0.466，Cohen's d=0.945；双阈值判据有效过滤了 21.2% 的"侥幸通过"（结果正确但过程质量不达标）。

3. **四个过程维度中度正交**（r=0.49–0.67）：结果验证是最独立的轴，且是跨所有模型的系统性瓶颈——自我检查并不会随其他能力自动涌现。

4. **框架对评判 LLM 选择稳健**：四种不同 judge LLM（Claude-Opus-4.8、Gemini-3.1-Pro、Gemini-2.5-Pro、GPT-5.5）的平均两两相关 r=0.81，说明是 rubric 而非评判者先验驱动了评估。

5. **过程感知轨迹过滤带来一致的训练提升**：在 Qwen3 三个规模上，Filtering-5k 相对 Random-5k 的 Pass@3 提升为 +10（14B）、+16（30B）、+19（80B），Pass-3 增益更显著（如 80B 为 30 vs 22）。

## 7. 优点

- **填补关键评估空白**：首次将过程质量作为一等公民纳入智能体评估，提出系统的四维度过程评分框架（而非粗粒度检查点或二值异常标签）。
- **双重评估设计精巧**：任务分数与过程分数互相补充又彼此独立，可通过两者的不一致检测"侥幸成功"和"归因失败"。
- **半自动 rubric 管道可扩展**：40个专家种子 → LLM 蒸馏生成技能 → 自动一致性检查 + 人工审查，兼顾了 rubric 质量与规模化成本。
- **过程评分兼具诊断与优化价值**：回合级过程轨迹支持精细定位失败点；过程分数用于轨迹过滤可显著提升后训练效果，实现从诊断到优化的闭环。
- **人类验证扎实**：LLM 评分器与人类专家一致性高（r=0.912，κ=0.851），且进行了标注者间一致性检验（κ=0.874）。
- **评估成本可控**：过程评分仅增加约 21.5% 输入 token 开销，实际部署可行。
- **安全性设计严谨**：安全违规采用乘法门控（一票否决），编码了部署场景中安全的不可协商性。

## 8. 不足与局限

- **环境真实性问题**：依赖确定性的 mock 服务和冻结的合成数据，无法捕获真实服务的完整变异性与动态性，可能高估智能体的泛化能力。
- **单一默认评判者偏差**：过程评分器默认实例化为 Claude-Opus-4.8，尽管跨评判者一致性高（r=0.81），但默认评判者的系统性偏差可能传播到所有评估结果。
- **维度覆盖不完整**：四维度框架（目标对齐、效率、信息利用、结果验证）可能未穷尽过程质量的所有方面，如创造力、用户沟通风格等未被纳入。
- **种子集偏差风险**：rubric 生成管道依赖 40 个专家编写的种子 rubric，种子集中未充分代表的领域或任务类型可能获得质量较低的生成 rubric。
- **基准游戏风险**：模型开发者如果专门优化 ClawTrack 的四个过程维度，可能忽视框架未捕获的其他智能体质量维度。
- **统计分析细节缺失**：未报告置信区间和显著性检验的具体细节；多模态子集（91任务）样本量相对较小，排名区分度有限。
- **模型与日期问题**：论文涉及大量 2026 年的模型名称（如 Claude-O

...Claude-Opus-4.8、GPT-5.5、GLM-5.2 等）明显超前于论文所暗示的撰写时间线，可能属于预发布版本或内部代号，外部研究者难以精确复现；同时未完整披露各模型的权重版本、快照日期和评测截止时间，相关结论的时效性与可复现性受限。

## 9. 总结与展望

ClawTrack 的核心贡献在于将智能体评估从"只看结果"推进到"过程与结果并重"的范式：通过双评估框架、四维过程评分、半自动 rubric 生成管道和过程感知训练数据过滤，同时服务了能力测量、错误归因与模型优化三个目标。其核心洞见——**可靠执行需要显式评估与显式训练**——为下一代智能体系统的质量保障提供了可操作的路径。

未来工作可沿三个方向展开：其一，将过程评估从确定性 mock 环境扩展到真实 API 环境，消除合成服务的保真度限制；其二，扩展过程维度以覆盖沟通质量、用户偏好对齐等尚未纳入的软性能力；其三，将过程信号嵌入更细粒度的强化学习奖励模型，实现从离线轨迹过滤到在线过程优化的闭环升级。

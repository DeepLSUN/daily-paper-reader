## 摘要
推测解码在不改变目标分布的情况下加速大语言模型推理，但在现实世界的工作负载中，没有单一的草稿结构表现最佳。自回归多令牌预测（MTP）是一种轻量级、稳定的提议机制，而块并行扩散则将草稿延迟分摊到更长的候选序列上；更好的选择主要取决于输出分布。我们提出AngelSpec，一个用于MTP和块并行推测解码的统一训练框架，在三个层面解决这种异构性。在训练层面，我们不是将单一的通用草稿器拟合到统一的数据混合中，而是将结构和数据共同专门化：MTP草稿器在多样化的对话数据上训练，用于高熵的开放式聊天；块扩散草稿器在代码和数学数据上训练，用于更长的可预测延续。在架构层面，我们提出DFly，一个块扩散框架，将混合目标条件骨干与前置条件自回归头相结合，提高目标特征利用和块内依赖建模，同时保持并行生成。在推理层面，接受长度和验证成本都随领域、请求、在线负载和硬件而变化，因此DFly将验证视为共享的批级资源：它将计算重新分配给跨请求的高置信度前缀，并结合预期效用和性能分析成本模型在线调整验证深度。在Hy3系列中，DFly在Hy3-A21B上将平均接受长度提高了约30%，并在每个测试并发（4到64）下获得最高的平均吞吐量，比自回归解码快1.98-2.40倍，比DFlash高10.5-11.8%。我们发布AngelSpec以支持训练和扩展这些方法。

## Abstract
Speculative decoding accelerates large language model inference without changing the target distribution, but no single drafting structure performs best across real-world workloads. Autoregressive multi-token prediction (MTP) is a lightweight, stable proposal mechanism, whereas block-parallel diffusion amortizes drafting latency over much longer candidate sequences; the better choice depends strongly on the output distribution. We present AngelSpec, a unified training framework for MTP and block-parallel speculative decoding that addresses this heterogeneity at three levels. At the training level, rather than fitting one universal drafter to a uniform data mixture, we co-specialize structure and data: the MTP drafter is trained on diverse conversational data for high-entropy open-ended chat, and the block-diffusion drafter on code and mathematics data for longer predictable continuations. At the architecture level, we propose DFly, a block-diffusion framework combining a hybrid target-conditioning backbone with a predecessor-conditioned autoregressive head, improving target-feature utilization and intra-block dependency modeling while keeping generation parallel. At the inference level, both acceptance length and verification cost vary with domain, request, online load, and hardware, so DFly treats verification as a shared batch-level resource: it reallocates compute toward high-confidence prefixes across requests and combines expected utility with a profiled cost model to adapt verification depth online. Across the Hy3 series, DFly raises the average accepted length on Hy3-A21B by roughly 30% and attains the highest average throughput at every tested concurrency from 4 to 64, a 1.98-2.40x speedup over autoregressive decoding and 10.5-11.8% higher throughput than DFlash. We release AngelSpec to support training and extending these methods.

## AngelSpec 论文总结

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：推测解码（Speculative Decoding）虽能无损加速大模型推理，但在真实世界工作负载（如开放式对话、代码生成、数学推理、工具调用与 Agent 工作流）下，不同输出分布对草稿器结构的要求差异巨大。没有一种单一草稿器能在所有场景下都表现最佳。
- **关键观察**：高熵对话场景中，候选序列接受率随草稿深度快速衰减，适合短程自回归 MTP 草稿；而代码和数学等结构化任务存在较长的可预测延续段，更适合块并行扩散式草稿。
- **解决思路**：将“训练数据”与“模型结构”联合专门化，并在推理阶段引入运行时自适应的验证资源分配，从而在不同负载下均获得高性能。

### 2. 论文提出的方法论

#### 整体框架：AngelSpec

- 一个统一的开源训练框架，支持 MTP 与块并行推测解码两种草稿器的训练与评估。

#### 训练层面：数据与结构共特化

- **MTP 草稿器**：训练于多样化的对话式高熵数据，面向开放式聊天场景。
- **DFly 块扩散草稿器**：使用代码与数学数据强化训练，面向长程可预测延续场景。
- **训练数据三原则**：
  1. 多样任务覆盖：涵盖对话、知识问答、数学、代码、指令跟随和 Agent 交互。
  2. 长上下文与代码 Agent 轨迹：加入含仓库上下文、工具交互、多步反馈的长序列数据。
  3. 目标模型自回归（Target-model Rollout）：使用冻结目标模型自己生成的数据训练草稿器，消除教师-数据分布 mismatch。

#### 架构层面：DFly（块扩散草稿框架）

- **混合目标条件骨干（Hybrid Target-Conditioning Backbone）**：
  - 融合 DFlash 的共享非线性投影（通过 FC 层捕捉跨层交互）与 DFlare 的逐层加权融合（每层草稿获得不同深度偏好的目标视图），得到逐层差异化条件表征：g(i)_t = RMSNorm(c_t + f(i)_t)。
  - 仅增加 D×T 个标量融合权重，开销极小。
- **前置条件自回归头（Predecessor-Conditioned Autoregressive Head）**：
  - 并行骨干产生位置边缘分布后，由轻量级顺序头将前序采样到的 token 信息注入后续预测，形成因果块分布。
  - 两种实现：**马尔可夫头**（低秩转移偏置）与**隐状态修正头**（通过 SwiGLU 融合前序 token 嵌入与当前隐状态）。最终采用表现更优的隐状态修正头。
- **损失函数设计**：
  - 冷启动阶段：D-PACE 加权混合 LK 损失（自适应混合 KL 与 TV 距离）。
  - 训练后期：端到端 TV 损失（直接优化期望接受长度的上界，公式 L_e2e = 1 - (1/|I|) Σ Π α_{i,k}）。
  - 关键公式：接受概率 α(p,q) = 1 - TV(p,q)，即分布重叠度。

#### 推理层面：D-cut 自适应验证预算

- **核心思想**：将目标模型验证视为批级共享资源，而非逐请求独立决策。
- **流程**：
  1. 草稿器提供各 token 置信度 c_{i,t}。
  2. 估计各请求前缀存活概率 s_{i,k} = Π c_{i,t}，据此计算期望推进长度 Â_i(n_i)。
  3. 在全局候选池中按置信度排序，选择 Top-K 验证位置（保持前缀连续性，不产生空洞）。
  4. 从离散比率集合 R={0.25, 0.50, 0.75, 1.00} 中，按“估计批进度/性能分析延迟”最大化原则（ρ* = argmax U(B,ρ)/C(B,ρ)）选择运行时全局预算。
- **正确性**：仅改变草稿验证深度，验证通过的 token 仍走原始目标模型验证流程，不改变目标输出分布。

### 8. 不足与局限

- **算力与成本披露不完整**：未报告训练时长、GPU 总时数、数据规模的完整细节，实际部署成本难以准确评估。

- **未对比最新 SOTA**：论文引用 DSpark、TreeFlash 等 2026 年新作，但主实验中仅完整对比了 MTP、DFlash 与 DSpark，未对比树形草稿（如 Sequoia）或检索式方法。

## 摘要
深度研究智能体通过一系列迭代搜索步骤来回答复杂的用户问题，在此过程中，智能体自主制定子查询以检索每个阶段所需证据。然而，现有的检索器训练通常仅依赖当前步骤的子查询及其对应的搜索结果作为训练信号，导致从先前交互中积累的信息在很大程度上未被充分利用。我们提出iter，一种利用智能体轨迹学习信号训练的交互感知密集检索器。iter不仅纳入当前子查询，还结合主问题和先前子查询来表示每个查询，并使用从智能体交互中导出的轨迹相对学习信号进行训练。在来自三个模型家族的六个智能体主干上，iter持续优于现有的智能体轨迹训练密集检索器LRAT，在InfoSeek-Eval和BrowseComp-Plus上分别平均提升7.5%和13.5%。iter还展现出比AgentIR更强的跨智能体鲁棒性，AgentIR是一种依赖外部LLM评判信号和智能体搜索前推理的深度研究检索器。消融实验进一步表明，主问题和先前子查询提供了最稳健的查询表示，而先前访问过的且有用的文档（在后续搜索中作为冗余负例）提供了最强的轨迹相对监督。代码可在https://github.com/ielab/ITER获取。

## Abstract
Deep-research agents answer complex user questions through an iterative sequence of search steps, where the agent autonomously formulates sub-queries to retrieve the evidence needed at each stage. However, existing retriever training typically relies only on the sub-query and its corresponding search results at the current step as training signals, leaving the information accumulated from previous interactions largely underutilized.   We introduce iter, an agent interaction-aware dense retriever trained using agent trajectory learning signals. iter represents each query by incorporating not only the current sub-query, but also the main question and preceding sub-queries, and is trained using trajectory-relative learning signals derived from the agent's interactions.   Across six agent backbones from three model families, iter consistently outperforms the existing agent-trajectory-trained dense retriever, LRAT, achieving an average improvement of 7.5% on InfoSeek-Eval and 13.5% on BrowseComp-Plus. iter also demonstrates stronger cross-agent robustness than AgentIR, a deep-research retriever that relies on external LLM-judge signals and the agent's pre-search reasoning. Ablations further show that the main question and previous sub-queries provide the most robust query representation, while previously visited and useful documents, used as redundancy negatives in subsequent searches, provide the strongest trajectory-relative supervision. Code is available at https://github.com/ielab/ITER.

## 1. 研究动机与核心问题

- **背景**：深度研究智能体（deep-research agents）通过多步迭代搜索来回答复杂问题，每步自主生成子查询、浏览文档、积累证据。这种"智能体搜索"产生了一种新型的结构化交互信号——**搜索轨迹（trajectory）**，记录了智能体搜了什么、看了什么文档、学到了什么。
- **核心问题**：现有检索器训练（如 LRAT）通常仅使用**当前子查询 + 当前搜索结果**作为训练信号，忽略了先前交互中积累的信息。这带来两个具体问题：
  - 先前的子查询揭示了已探索的搜索方向，忽略它们会导致检索器重复返回相同结果；
  - 先前访问过的文档表明某些信息需求可能已满足，忽略它们会导致检索器优先返回"重复但已消费"的证据，而非真正尚未获取的新证据。
- **关键洞见**：文档的效用不应仅取决于它与当前子查询的相关性，还应取决于它相对已收集证据的**新增信息量（边际增益，marginal gain）**。这种历史依赖的效用是交互感知检索（interaction-aware retrieval）的核心。

## 2. 方法论：ITER

### 2.1 核心思想

ITER 将文档排序建模为**条件于交互历史**而非仅当前子查询的任务。在第 \(t\) 步，文档 \(d\) 的效用定义为：
\[
g_t(d) = \text{gain}(d \mid q_t, H_t)
\]
其中 \(q_t\) 为当前子查询，\(H_t\) 为交互历史（主问题、先前子查询、先前检索/访问的文档及其解释）。已访问文档即使仍具主题相关性，其效用也会降低。

### 2.2 历史条件查询表示

- **默认表示**：将 **主问题（Q）+ 当前子查询（qt）+ 先前子查询（q<t）** 序列化后输入查询编码器。主问题保留整体任务，当前子查询指明即时信息需求，先前子查询指示已探索方向。
- **推理增强表示**（可选）：额外加入预搜索推理 \(\tau_t\) 及对应指令文本（图4）。
- 文档侧截断至512 token，查询侧截断至8192 token。

### 2.3 轨迹相对训练信号

- **去重搜索设置**：使用去重搜索工具收集轨迹——每步从100个候选中移除先前已返回的文档，展示top-10未见文档；先前已返回的文档在"returned earlier"分区中仍可通过 `get_document` 打开。这样既不丢失候选覆盖率，又增加未见文档的曝光。
- **数据构建**：使用 Tongyi-DeepResearch-30B 在10,000个训练问题上、用4种检索后端（BM25 + Qwen3-Embedding 0.6B/4B/8B）收集40,000条轨迹，保留20,893条最终答案匹配的轨迹，产生67,934个正例对（其中26.7%为延迟访问，即文档由早前搜索返回但当前步才被访问）。

### 2.4 正例与三层负例

- **正例**：当前搜索后、下一搜索前被访问且经 Qwen3-30B-A3B-Thinking 验证器判定为相关的文档；正例按后访问推理长度加权（饱和函数，中位数β处达半值）。
- **负例分三层**：
  - **冗余负例（redundancy negatives）**：先前访问过且判定相关的文档（权重3.0）——已提供过有用信息，应被降权；
  - **硬负例（hard negatives）**：先前访问过但判定不相关的文档（权重1.0）；
  - **弱负例（weak negatives）**：当前步返回但全程未被访问的文档（权重0.3）——其效用不确定，故降权。

### 2.5 加权对比损失

- 每组训练含1个正例和9个负例（最多3冗余 + 3硬 + 其余弱负例），加上批内负例。
- 损失函数为加权 InfoNCE，温度 \(\tau=0.02\)，负例权重通过给 logit 加 \(\log w_i(d)\) 实现；实例权重 \(a_i\) 用于聚合各实例损失。
- 训练参数：全参数微调 Qwen3-Embedding-0.6B，2轮，AdamW（lr=1e-6，warmup 0.1），batch size 32，bf16，last-token pooling，FlagEmbedding 框架实现。

## 6. 主要结论与发现

1. **轨迹相对训练本身带来增益**：仅用当前子查询、但用轨迹相对监督训练的 ITER 已在 InfoSeek-Eval 上比 LRAT 提升5.5%（72.7→76.7），证明训练信号构建方式的改进独立于查询表示。
2. **主问题 + 先前子查询提供最强查询表示**：默认表示在 InfoSeek-Eval 上达80.0 SR（+10% vs LRAT），在 BrowseComp-Plus 上达46.6 SR（+7.4%）。
3. **预搜索推理转移性差**：推理增强在匹配智能体（Tongyi）上有增益（BCP 47.6），但在5个未见骨干上大多劣于默认表示，因推理是自由形式且模型特定的。
4. **冗余负例是最强监督信号**：移除冗余负例导致 BrowseComp-Plus SR 从46.6降至40.8、搜索召回从.636降至.561；负例分层权重（3.0/1.0/0.3）需要校准，均匀权重会显著掉点。
5. **跨智能体鲁棒性优于 AgentIR**：ITER 在全部5个未见骨干上 SR 都高于 AgentIR；AgentIR 虽有更高搜索召回，但未能转化为访问召回和任务成功率，因其依赖LLM评判信号而非真实访问信号。
6. **规模扩展不能替代历史条件**：0.6B→4B提升不consistent，默认表示仍优于仅当前子查询表示。

## 7. 优点

- **问题定义清晰且动机扎实**：用数据观察（图3：52.1%重复结果、54.9%已访问文档重现、70.1%出现在top-3）支撑交互感知检索的必要性，而非仅凭直觉。
- **"边际增益"概念精炼**：将文档效用定义为给定历史的条件增益，理论表述简洁有力。
- **去重搜索设置设计巧妙**：既增加未见文档的曝光（提升训练信号丰富度），又保留对先前结果的访问（不损失功能），还暴露了26.7%的延迟访问现象。
- **分层负例体系**：冗余/硬/弱三层负例分别对应"已消费相关"、"已消费不相关"、"未消费不确定"，层次分明且有明确证据依据。
- **跨智能体评估扩展性强**：覆盖3个家族、6个骨干、4B到120B规模范围，能真实检验检索器的泛化能力，而非只报告匹配智能体结果。
- **指标多维**：端到端SR、搜索召回、访问召回、步数四类指标联报，能揭示"检索到≠访问≠成功"的级联差异（尤其体现在 AgentIR 对比中）。

## 8. 不足与局限

- **训练数据单一来源**：所有正负例仅来自 Tongyi-DeepResearch-30B 的轨迹。对预搜索推理的消融只训练了 Tongyi 产生的推理，这直接限制了推理增强表示向未见骨干的迁移，也使"推理转移性差"这一结论带有数据偏差。
- **4B 扩展实验的可比性受限**：LRAT 没有4B模型，4B规模只能与 AgentIR 比较，而同规模的 LRAT 对比缺失；且4B ITER 的搜索召回在多数未见骨干上低于 AgentIR，文中未给出证据级分析。
- **轨迹选择偏差**：仅保留20,893/40,000条最终答案匹配的轨迹，可能偏向"容易成功"的检索分布，对检索器在最难查询上的表现估计可能偏乐观。
- **去重设置与真实环境的偏差**：实际部署中智能体可能使用标准（不去重的）检索接口，去重设置下的训练信号与真实推理环境的差异未加讨论。
- **计算资源披露不足**：未报告 GPU 型号/数量/训练时长，复现成本不透明；4B 模型的资源开销也未讨论。
- **未探索联合优化**：检索器与搜索策略（如子查询生成）是分离优化的，论文也承认联合优化是开放问题。

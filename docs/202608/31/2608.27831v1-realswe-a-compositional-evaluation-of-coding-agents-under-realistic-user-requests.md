## 摘要
编程代理现在通常基于SWE-bench系列基准进行评估，其任务来源于精心挑选的GitHub问题——长篇幅、结构化且信息丰富。然而，真实用户请求通常要短得多，且结构较松散。为刻画这一差距，我们定义了一个六类信息分类法和四个语言风格维度，并将其应用于来自SWE-chat的真实用户提示以及SWE-bench Verified和Pro的问题陈述。我们发现，仅包含问题陈述（单独或附带有限额外上下文）的请求占真实提示的88%，但在基准问题中仅占7%。此外，87%的真实提示是随意书写的，而94%的基准问题是正式的。在这些观察的指导下，我们引入了sys，一个源自SWE-bench Verified和Pro的381个多变异任务族。每个族内的变异共享相同的底层任务和黄金补丁，仅在信息组成和语言风格上有所不同。使用sys对七个当代LLM进行评估，我们发现：i) 真实输入使解决率平均降低6.4个百分点，且可能改变模型排名。受控分析进一步表明：ii) 包含期望行为和动机显著影响性能，而环境信息和复现步骤仅增加token而无明显益处；iii) 语言风格只有较小且依赖于模型的影响。这些发现为用户和代理提供了可行的指导：明确说明期望行为和动机——大多数真实提示遗漏了这一点——能显著提升LLM的软件工程性能。

## Abstract
Coding agents are now commonly evaluated on the SWE-bench family of benchmarks, whose tasks are built from curated GitHub issues--long, structured, and information-rich. Real user requests, however, are typically far shorter and less structured. To characterize this gap, we define a six-category information taxonomy and four dimensions of linguistic style, and apply them to real user prompts from SWE-chat and problem statements from SWE-bench Verified and Pro. We find that requests carrying only a problem statement, alone or with limited additional context, account for 88% of real prompts but just 7% of benchmark problems. Furthermore, 87% of real prompts are casually written whereas 94% of benchmark problems are formal. Guided by these observations, we introduce sys, 381 multi-variant task families derived from SWE-bench Verified and Pro. Variants within each family share the same underlying task and gold patch while differing only in information composition and linguistic style. Evaluating seven contemporary LLMs with sys, we find that i) realistic inputs reduce resolution rates by 6.4 pp on average and can change model rankings. Controlled analysis further shows that ii) including Desired Behavior and Motivation significantly affects performance, whereas Environment Information and Reproduction Steps merely add tokens without measurable benefit; iii) linguistic style has only small, model-dependent effects. These findings provide actionable guidance for users and agents: explicitly stating the desired behavior and motivation--which most real prompts omit--substantially improves the LLM's software engineering performance.

## 2. 论文提出的方法论

### 2.1 核心思想

将同一软件工程任务，在**信息组成**（包含哪些信息类别）与**语言风格**（正式/随意、陈述/祈使等）两个维度上系统性地多样化，构造出"多变异任务族"（multi-variant task family），从而能够将性能差异归因于特定的信息字段或语言属性，而非任务难度本身。

### 2.3 语言风格维度（四维）

- **Sentence type**（陈述/祈使/疑问/其他）
- **Certainty**（确定/不确定/其他）

### 2.4 构造流程（四阶段）

1. **任务类型分类**：使用 GPT-5.4 将每个任务分为 bug fix 或 feature request（达到 95% 准确率）。
2. **信息分解**：将原始问题陈述逐句分入各信息类别字段，**不重写原文**，仅重新分配，确保信息不变；同时剥离 GitHub 模板痕迹（Markdown 标题、HTML 标签）。
3. **真实用户风格改写**：以 SWE-chat 中观测到的主导风格（随意、祈使、确定、非第一人称）为目标，用 GPT-5.4 改写，**保留代码块、错误信息、文件路径等技术内容不变**。
4. **质量控制**：人工标注者评估各阶段的输出，使用 LLM 裁判（GPT-5.6 Terra）对全部候选任务打分，剔除未达标的候选，最终从 403 个候选保留 **381 个任务族**（192 个 bug fix + 189 个 feature request）。

### 2.5 发布形式

- **RealSWE-Bench**：固定评测集，反映 SWE-chat 中观测到的信息分布（bug fix 中 [P] 74%、[PA] 26%；feature request 中 [P] 72%、[PA] 28%），平均任务描述长度 1,417 字符，与 SWE-chat 的 1,427 字符高度接近。
- **RealSWE-Framework**：可配置框架，研究者可自定义任务类型、信息组合、语言风格，按需组装数据集。

## 6. 论文的主要结论与发现

1. **基准—现实差距显著**：所有 7 个模型的解决率在 RealSWE-Bench 上平均下降 **6.4 个百分点**（相对降幅平均 13.6%，范围 10.3%–16.2%）。Bug fix 平均下降 9.1 pp，远大于 feature request 的 3.7 pp。
2. **排名可能改变**：MiMo V2.5 Pro 在原始输入上排第 4，在真实输入下升至第 2，超越 Qwen3.7 Plus 和 DeepSeek V4 Flash；MiMo 与 Qwen 差距的变化显著（+3.7 pp，95% CI [+0.7, +7.3]）。模型间原本看似可互换的差距被拉大，而整体最强—最弱差距从 19.8 pp 缩小至 15.8 pp。
3. **信息字段价值高度不均**：
   - **Desired Behavior [D]**：移除 [D] 使解决率下降 7.1–8.9 pp（平均 8.0 pp，4 个模型全部显著），是移除 [A]、[E]、[R] 三者合计效应的 4 倍以上。
   - **Motivation [M]**：移除 [M] 平均下降 3.4 pp，但效应更多依赖模型和仓库（DeepSeek V4 Flash 损失 7.1 pp，其他模型 1.8–2.8 pp 不显著）。
   - **Reproduction Steps [R] 和 Environment Information [E]**：平均贡献不可测量——仅"增加 token"而无明显收益。
   - [PD] 在 bug fix 上全方位胜过 [PA]（领先 3.8–6.1 pp），[PM] 在 feature request 上胜过 [PA]（1.4–3.5 pp），证明"提示长度"不等于"信息质量"。
4. **语言风格影响很小且依赖模型**：8 组风格对照无一显著（Holm 校正 p ≥ .35），方向不确定，模型间不统一。
5. **额外代价**：真实输入下 6/7 个模型的成本增加约 6.2%、步骤增加约 1.8%，即代理通过更多探索进行补偿，但无法完全挽回性能损失。
6. **可操作指导**：用户应明确写出**预期行为**（bug fix）和**动机**（feature request）；代理接口可通过主动提问或在任务规格中推断补全这些信息来改善性能。

## 7. 优点

- **以数据驱动的实证分析为基础**：不是启发式地"猜测"真实用户如何写请求，而是基于 718 个真实用户提示的实际分布来定义基准的目标配置，具有严格的经验依据。
- **正交化控制**：多变异任务族使信息组成与语言风格可以独立操纵，能精确归因于特定字段——这是 SAVING-SWE-bench 等先前工作（联合变换多个属性）无法做到的。
- **高质量任务构造**：分阶段使用 LLM 流水线，每个阶段均有严格的人类验证（任务类型准确率 95%，分解与改写质量均有 QWK 和一致性报告），并剔除了 22 个未达标候选。
- **选择偏差审计**：明确指出选中任务并非更简单（解决率 53.9% vs 63.0%）、补丁更大（134 行 vs 94 行）、仓库分布更均匀（有效仓库数 13.9 vs 11.0），支持结果的外部有效性。
- **统计方法严谨**：仓库聚类 bootstrap、精确 McNemar 检验、Holm 多重比较校正、符号翻转检验，保证结论的统计稳健性。
- **可复现、可扩展**：发布固定基准和可配置框架，支持研究者自定义配置和受控消融。
- **观点有实际价值**：发现"用户提供什么"与"代理需要什么"之间的错位，并给出具体可操作的提示设计建议。

## 8. 不足与局限

- **模型覆盖不完整**：未包含论文写作时领先的评分榜前沿模型（GPT-5.6、Opus 5、Kimi K3），结论对最强模型的推广受限。
- **单轮评测限制**：遵循 SWE-bench 的单轮设定，不捕捉多轮澄清的交互效应；真实世界用户往往可以进行多轮对话予以补充信息，这一点未被评估。
- **信息字段依赖原始陈述**：变体构造要求原始问题必须包含所有分类字段（5 个或 3 个），这意味着 1,229 个基准问题中只有 403 个满足条件（最终 381 个）——REAL SWE 所覆盖的任务子集可能不代表全部基准任务的难度分布，尽管选择偏差检验表明没有系统偏向"更简单"的任务。
- **SWE-bench Pro 的接口信息被排除**：原始 Pro 任务中 Interface 被当作外部文档而非问题陈述的一部分处理，可能轻微改变任务信息构成。
- **Linguistic style 效应评估范围有限**：风格效应仅在 4 个代表性模型上验证，且使用单一固定风格设置（casual + imperative + confident + non-first-person），未系统探索所有风格组合的交互效应。
- **[A] 字段的混杂性**：Additional Information 包含来源 URL、日期、作者元数据、补充上下文等异质内容，其"零效应"可能掩盖了特定子类信息的作用。
- **评估成本门槛较高**：381 个任务 × 多模型 × 3 次重复的计算开销较大，限制了社区大规模复现和扩展的可行性。
- **某些效应置信区间较宽**：Motivation 的平均效应估计（+3.8 pp，95% CI [+0.2, +8.2]）在上界较大，精度有限。

## 摘要
基于大型语言模型（LLM）的智能体应用通常面临高响应时间。投机性解码是一种有前景的解决方案，可在不影响生成质量的前提下提高LLM智能体的推理效率。然而，最先进的投机性解码算法在大批量大小下表现出显著的速度下降，限制了其在真实世界智能体应用中的部署效果。在本工作中，我们首先对LLM智能体的投机性解码进行了系统性分析，并确定了加速退化的两个主要因素：投机标记的高拒绝率，以及动态标记预算的利用不足。基于这些观察，我们提出了AgentSpec，一种投机性解码算法，旨在解决现有方法在LLM智能体中的局限性。AgentSpec引入了结构隔离的草拟机制，将投机限制在智能体工作流的语义连贯片段内，减少无关语义路径的草拟，从而实现极低的拒绝率。此外，AgentSpec采用冗余感知的预算分配策略，利用智能体级信息更好地利用智能体推理过程中动态空闲的标记预算。我们在vLLM中对五种不同工作负载和来自四个不同LLM家族的四种模型进行了实现和评估。我们的结果证明了AgentSpec相对于最先进方法的优越性。

## Abstract
Large language model (LLM)-based agent applications often incur high response time. Speculative decoding is a promising solution to improve the inference efficiency of LLM agents without impacting generation quality. However, state-of-the-art speculative decoding algorithms exhibit substantial speed degradation under large batch sizes, limiting their effectiveness to deploy in real-world agent applications. In this work, we first present a systematic analysis of speculative decoding for LLM agents and identify two dominant factors of speedup degradation: high rejection rate of speculative tokens, and under-utilization of dynamic token budgets.B ased on these observations, we propose AgentSpec, a speculative decoding algorithm that addresses the limitations of existing methods for LLM agents. AgentSpec incorporates structure-isolated drafting that constrains speculation to semantically coherent segments of the agent workflow, reducing the drafts of irrelevant semantic paths and achieving an extremely low rejection rate. Moreover, AgentSpec adopts redundancy-aware budget allocation that exploits agent-level information to better utilize the dynamically-free token budget during the agent inference. We implement and evaluate AgentSpec on five different workloads and four different models from four different LLM families in vLLM. Our results demonstrate the superiority of AgentSpec over state-of-the-arts.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体框架

AgentSpec是一种**免草案模型（draft-model-free）**的投机性解码算法，设计用于LLM智能体场景。其系统要求：智能体应用向LLM服务端提供**智能体结构标识符**（agentic structure identifier），组织并检索符合智能体执行结构的历史上下文。整体由两个核心组件构成：

### 2.2 结构隔离草拟（Structure-Isolated Drafting）

- **动机**：LLM智能体应用中，一个用户查询常跨多个请求、分属不同语义块（如推理、工具调用、结果解释等）。同语义块内的生成模式高度一致，而跨块或跨查询的生成模式差异大。实验显示，重复token片段绝大多数发生在同一查询的同一语义块内部，跨块/跨查询重复极少。
- **关键设计**：
  - 每个请求 `ri` 附带语义结构标识符 `Si = {ai, qi, Bi}`，其中 `ai` 为智能体应用ID，`qi` 为用户查询索引，`Bi` 为语义块列表（由起始/结束标签对定义）。
  - 采用类似XGrammar的**token-to-string缓存映射** `M`，避免反复调用tokenizer，高效在线将token转换为字符串。
  - 维护轻量级**字符串下推自动机（PDA）** `P(ai, qi)`，增量跟踪当前语义块。
  - 为每个语义块维护独立的**结构隔离缓存**，草拟候选仅从当前匹配的语义块中检索，避免跨语义路径的无效猜测。
- **效果**：拒绝率显著降低至26.4%，相比EAGLE-3（53.3%）下降约50%，相比NGram（88.7%）下降约70%。

### 2.3 冗余感知预算分配（Redundancy-Aware Budget Allocation）

- **动机**：请求的草拟接受潜力和历史冗余程度存在差异。高冗余（与历史重复模式一致）的草拟更可能被接受；而高拒绝率请求分配过多token会浪费验证算力。
- **核心信号——冗余度得分（redundancy score）**：
  \[
  g(c, n) = \frac{c}{n} \cdot p(n), \quad p(n) = g_{\min} + (1 - g_{\min})(1 - e^{1-n})
  \]
  - `n`：同一语义块和用户查询下检索到的候选延续数；
  - `c`：与最高频延续前缀一致的候选数；
  - `c/n`：候选间的共识程度；
  - `p(n)`：饱和项，低支持度时降低估计置信度；
  - `g_min`：低支持场景的最小置信度。
- **批量token预算**：
  \[
  B_t = \lfloor \alpha b_z \rfloor
  \]
  其中 `b_z` 为batch size，`α` 控制整体投机预算。
- **每请求草拟长度分配**：
  \[
  L_i = \max\left(|CT_i^*|, B_t \cdot \frac{g_i}{\sum_j g_j}\right)
  \]
  优先保证每个请求至少草拟其最高置信前缀，同时根据冗余度得分对剩余预算进行加权分配。
- **效果**：AgentSpec的total draft token数始终保持在最大预算 `M(b)` 以下，且随batch增大接近该预算，说明能有效利用可用token预算。

### 2.4 复杂度分析

论文提供了理论复杂度分析：
- **时间复杂度**：`O(K·L + K)`，与NGram/SuffixDecoding同阶，PDA更新为均摊O(1)。
- **空间复杂度**：`O(H + B + R) = O(H)`（H为历史缓存，B为语义块索引，R为PDA状态），渐近与NGram一致，仅增加轻量元数据开销。

1. **问题诊断准确、分析扎实**：论文不是简单提出方法，而是先通过系统的效率建模（`ΔT(b)` 公式）和实验测量（FFN/Attention时间随batch变化、拒绝率、token预算使用率），精确定位现有方法的两大瓶颈，为方法设计提供了强有力的理论支撑。

## 8. 不足与局限

1. **需要额外的接口适配**：AgentSpec要求智能体应用与serving系统之间引入轻量接口（传递 `structure`、`query_id`、`agent_id`），在实际系统中可能需要一定改动。
2. **依赖显式语义结构信息**：结构隔离草拟依赖于智能体应用提供的语义块边界。虽然无结构变体 `AgentSpec(N)` 仍有效，但论文承认加速效果可能取决于工作负载中可用的重复生成模式数量，在重复模式稀少的场景下加速效果可能减弱。
3. **重复模式依赖的隐含限制**：AgentSpec本质上利用的是历史生成中的重复模式，对于全新任务、极少历史会话或高创新性生成场景，草拟质量可能受影响。
4. **验证成本问题的边界条件**：论文指出当batch size极大、推理完全受FFN计算限制时，验证开销会抵消接受收益。AgentSpec通过预算分配缓解了这一问题，但并未从根本上消除该物理限制；对于超大批量（如>512）行为没有展示实验数据。
5. **硬件与规模局限**：资源充足性信息不透明，未报告多卡分布式场景下的表现，也未报告更大模型（如70B+）上的效果。
6. **未报告输出质量验证**：虽然投机性解码理论上无损，但论文未具体验证AgentSpec与标准解码在智能体任务完成质量（如任务成功率、代码正确率）上的一致性。
7. **隐私与滥用考量**：论文在伦理声明中承认加速可能降低滥用门槛（如垃圾信息生成、不安全工具调用），需要配合速率限制、权限控制等安全机制。

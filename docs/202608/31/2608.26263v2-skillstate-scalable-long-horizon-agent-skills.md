## 摘要
大型语言模型（LLM）日益作为自主智能体执行复杂、长时间运行的程序性技能。现有的智能体运行时通过不断将观察、动作和中间推理痕迹追加到不断增长的对话历史中来维持执行，这导致长时程上的延迟退化和上下文污染失败。我们提出了SKILL.state，一种运行时架构，用显式的、可变的执行状态取代仅追加的对话历史。在每个执行步骤中，模型仅接收不可变的技能规范、当前结构化执行状态和最新观察。中间推理在产生验证后的状态更新后立即丢弃，防止提示随执行历史增长。在多样化的数据集、模型和执行环境中，SKILL.state提高了任务准确性，同时大幅减少了累积令牌消耗。我们的结果表明，显式执行状态是用于可扩展长时程智能体技能的有效且架构无关的抽象。

## Abstract
Large Language Models (LLMs) increasingly act as autonomous agents executing complex, long-running procedural skills. Existing agent runtimes maintain execution by continually appending observations, actions, and intermediate reasoning traces to an ever-growing conversation history, causing latency degradation and context-poisoning failures over long horizons. We present SKILL.state, a runtime architecture that replaces append-only conversational history with an explicit, mutable execution state. At each execution step, the model receives only the immutable skill specification, the current structured execution state, and the latest observation. Intermediate reasoning is discarded immediately after producing a validated state update, preventing prompt growth with execution history. Across diverse datasets, models, and execution environments, SKILL. state improves task accuracy while substantially reducing cumulative token consumption. Our results demonstrate that explicit execution state is an effective and architecture-agnostic abstraction for scalable long-horizon agent skills.

## 一、论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：大型语言模型（LLM）作为自主智能体执行长时程程序性技能时，现有运行时普遍采用“对话历史累积”模式——每一步都将推理过程、动作、观察和工具输出不断追加到上下文窗口中。这导致三重问题：
  1. **提示词无限增长**：上下文长度随执行步数线性增长，累计 token 消耗呈二次方增长，推理成本与延迟急剧上升；
  2. **上下文污染**：早期观察、过时推理和无关遥测长期残留在上下文中，模型难以区分“当前事实”与“历史痕迹”；
  3. **状态重建负担**：每一步模型都需从文本历史中隐式重建世界状态，长时程下准确率显著下降。
- **整体含义**：该论文将长时程程序性技能的执行视为“系统问题”而非纯“推理问题”，主张用**显式、可变的执行状态**替代“只增不改”的对话历史，使执行严格依赖当前世界状态而非历史回放。这一抽象被证明是**架构无关**的，可适用于多种模型和场景，为可扩展的长时程智能体技能提供了新范式。

## 二、论文提出的方法论

- **核心思想**：将程序性技能执行重构为“显式状态转移过程”，而非“对话累积过程”。每一步模型只接收三个输入：
  \[
  A_t = (P, \Sigma_t, O_t)
  \]
  其中：
  - \(P\)：不可变的技能规范（procedural specification）
  - \(\Sigma_t\)：第 \(t\) 步的结构化执行状态
  - \(O_t\)：最新环境观察
- **推理与状态更新分离**：
  - 模型生成三元组 \((R_t, \Delta\Sigma_t, a_t)\)：
    - \(R_t\)：链式推理痕迹（中间计算，用后即弃）
    - \(\Delta\Sigma_t\)：结构化状态补丁（JSON 字典，支持键更新和空值删除）
    - \(a_t\)：要执行的动作
  - 运行时对 \(\Delta\Sigma_t\) 做确定性验证后，通过字典合并操作更新状态：\(\Sigma_{t+1} = \Sigma_t \oplus \Delta\Sigma_t\)，然后执行动作。
- **关键机制**：推理痕迹在生成后立即被丢弃，永不进入后续提示词。状态 schema 按领域静态定义、跨任务复用（例如 InterCode CTF 整个基准只用一个 5 字段 schema）。
- **复杂度保证**：
  - 传统对话式运行时：提示词长度 \(|C_t| = O(t)\)，累计 token 复杂度 \(O(T^2)\)；
  - SKILL.state：提示词大小 \(|P_t| = O(|P| + |\Sigma| + |O|)\)，与执行步数无关，累计 token 复杂度 \(O(T)\)。
- **算法流程（Algorithm 1）**：
  1. 初始化技能规范 \(P\) 与初始状态 \(\Sigma_0\)；
  2. 循环：接收最新观察 → 构造提示 \((P, \Sigma_t, O_t)\) → 模型生成推理、状态补丁、动作 → 验证状态补丁 → 合并更新状态 → 执行动作。

## 六、论文的主要结论与发现

- **显式执行状态显著优于历史累积方式**：在所有基准与模型上，SKILL.state 匹配或超过最强的历史/摘要基线任务准确率，同时将提示词大小保持恒定（约 1,700–1,900 tokens），累计 token 消耗大幅下降。
- **定量收益**：
  - Warehouse T=100：Stateful 基线消耗 1,062,387 tokens，SKILL.state 仅 65,408 tokens（16.2× 降低）；
  - Warehouse T=200：SKILL.state 保持 0.94 准确率，Memory 基线膨胀至 6.1M tokens；
  - InterCode CTF：pass@1 达 54.2%（比最强基线高 7.8 点），token 消耗比 ReAct 降 60.4%、比 Stateful 降 65.9%；
  - τ-Bench Retail：58.3% 通过率且 token 成本最低；Airline 域保持 ~2,800 tokens/step 的平坦占用。
- **鲁棒性**：在 50 干扰事件/轮的高噪声下，Prompt 运行时准确率从 0.68 暴跌至 0.53，SKILL.state 仍保持 ≥0.97；状态恢复实验中历史基线性，基线需要 5–14 步才能从外部状态漂移中恢复，SKILL.state 为 **0 步**。
- **预算匹配实验**：滑动窗口截断仅 0.18、LLMLingua 仅 0.22，而 SKILL.state 为 0.94，说明收益来自**结构化状态表示**而非单纯短提示词。
- **小模型错误模式**：Gemma-4-31B 的失败 68% 来自提前覆盖/误删状态键、20% 来自 schema 理解/类型转换、12% 来自 JSON 语法错误——小模型性能退化源于结构化输出遵循能力而非推理能力，可借助约束解码改善。

## 七、优点

- **思想清晰且优雅**：用显式可变状态替代对话累积，将长时程执行的复杂度从 \(O(T^2)\) 降为 \(O(T)\)，具备理论保证。
- **架构无关性**：在专有模型（Gemini-3-Flash）与开源模型（Gemma、Qwen）上均保持一致优势，验证了抽象通用性。
- **实验设计严谨**：
  - 自建 SkillExecBench 可隔离“执行机制”与“启发式搜索”；
  - 预算匹配控制排除了“提示词长度”这一混淆因素；
  - 噪声鲁棒性和状态恢复实验直击历史累积范式的核心缺陷；
  - 固定种子保证基线公平对比。
- **工程实用性**：状态 schema 可跨任务复用；确定性运行时验证使格式错误无法污染持久状态。
- **错误分析有价值**：对小模型失败模式的系统分类为后续工作提供了明确方向。

## 八、不足与局限

- **核心假设受限**：方法假设“执行状态可成为未来执行的充分统计量”——由此放弃历史是**无损的**。但该假设在以下情况不成立：
  1. 无预定义 schema、状态结构需在动态执行中发现；
  2. 某些早期观察当时未被识别为相关，未被写入状态，后续才被证明重要；
  3. 任务目标本身定义在历史轨迹上（如审计、调试溯源、过程解释），此时历史即目标输出。
- **单智能体局限**：多智能体并发写入需要确定性冲突消解语义，论文未涉及。
- **实验覆盖不完整**：公开基准仅用 Gemini-3-Flash；开源模型仅在合成 Warehouse 环境评估，未在真实交互式任务上验证。
- **算力信息披露缺失**：未说明任何硬件资源、推理延迟或成本测算，影响可复现性评估。
- **小模型性能瓶颈**：Gemma-4-31B 在 T=100 时准确率仅 0.42，Qwen-3-8B 仅 0.34，结构化输出遵循能力成短板，虽然可经约束解码缓解，但当前版本的泛化能力受限于模型输出质量。
- **潜在偏倚**：作者来自 Google 与 Purdue，使用 Gemini-3-Flash 作为主要评估模型，虽结论在多模型上一致，但利益关联未显式讨论。

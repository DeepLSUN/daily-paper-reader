## 摘要
结果监督的搜索智能体学习何时以及如何检索证据，但终端奖励既不能定位中间错误，也不能在错误累积之前重新引导正在进行的轨迹。将纠正性反馈视为一种学习到的轨迹内干预，将两个角色耦合在一起：智能体必须决定何时请求和使用反馈，而批评者必须从结果混淆的轨迹中推断出有用的纠正，这些轨迹的失败模式随着智能体的改进而改变。我们引入了CAFE（耦合智能体-反馈进化），这是一个共享参数模型在搜索智能体和批评者角色之间交替的框架。CAFE从围绕基础智能体自身失败构建的轨迹初始化反馈条件的恢复，然后耦合在线和离线优化。在在线强化学习期间，比较性反馈估计使用提示级调用-跳过成功差距来塑造请求回报，而反馈感知的优势塑形在反馈前后重新加权令牌优势。离线时，从轨迹导出的偏好优化从匹配的成功和失败轨迹中学习反馈。在七个智能体搜索基准上，CAFE平均优于评估的基于强化学习的搜索智能体，在所有六个域外基准上保持其收益，并减少了答案级幻觉。单侧消融表明，仅改进智能体或仅改进批评者最终会达到平台期，而交替两种更新则持续提高性能。这些发现表明，自我改进的搜索智能体需要与其指导的策略共同进化的反馈。

## Abstract
Outcome-supervised search agents learn when and how to retrieve evidence, but terminal rewards neither localize intermediate errors nor redirect an ongoing trajectory before those errors compound. Treating corrective feedback as a learned in-trajectory intervention couples the two roles: the agent must decide when to request and use feedback, while the critic must infer useful corrections from outcome-confounded rollouts whose failure patterns shift as the agent improves. We introduce CAFE (Coupled Agent--Feedback Evolution), a framework in which a shared-parameter model alternates between search-agent and critic roles. CAFE initializes feedback-conditioned recovery from trajectories built around the base agent's own failures, then couples online and offline optimization. During online RL, a comparative feedback estimate uses a prompt-level call--skip success gap to shape request returns, while feedback-aware advantage shaping reweights token advantages before and after feedback. Offline, rollout-derived preference optimization learns feedback from matched successful and unsuccessful trajectories. On seven agentic search benchmarks, CAFE outperforms the evaluated RL-based search agents on average, retains its gains across all six out-of-domain benchmarks, and reduces answer-level hallucinations. One-sided ablations show that improving only the agent or only the critic eventually plateaus, whereas alternating the two updates continues to improve performance. These findings suggest that a self-improving search agent needs feedback that co-evolves with the policy it guides.

# CAFE：自我改进的搜索智能体需要共同进化的反馈 —— 论文总结

## 1. 核心问题与整体含义

- **研究动机**：现有的结果监督（outcome-supervised）搜索智能体依赖最终任务奖励来学习“何时检索、如何检索”，但终端奖励既无法定位中间步骤的错误，也无法在错误累积之前重新引导正在进行的轨迹。在长程搜索中，早期方向性错误会沿后续检索步骤传播，且事后难以追溯失败源头（如错误使用约束、遗漏子目标、重复无效查询等）。
- **关键问题**：如何让智能体在轨迹内部主动请求并利用可学习的纠正性反馈，同时让提供反馈的批评者（critic）能够从结果混淆、失败分布不断变化的rollout中推断出有用的纠正信息。
- **核心论点**：搜索智能体与反馈机制构成一个耦合学习系统——智能化化改变了反馈所基于的状态和失败分布，而反馈又改变了后续rollout的分布。因此，反馈必须与策略**共同进化（co-evolve）**，而不是固定不变。

## 2. 方法论：CAFE 框架

### 2.1 核心思想
- 用一个**共享参数模型**同时充当搜索智能体（Agent）与反馈批评者（Critic）两个角色，通过角色条件化提示切换行为。
- 在轨迹中间引入 `<request_feedback>` 可选动作：智能体在某个历史状态决定请求反馈，批评者基于当前轨迹生成纠正性建议，然后智能体在增强上下文中继续搜索。
- 训练采用**交替优化**：在线RL更新智能体，离线偏好优化（RDPO）更新批评者，而由于参数共享，每次更新都会同时影响两个角色的行为分布。

### 2.2 关键技术细节

**（1）反馈增强的SFT初始化**
- 收集基础智能体的失败轨迹，由教师模型定位最早出错回合，保留原有的错误前缀，插入`<request_feedback>`，再由教师生成反馈和成功的后续轨迹，构成SFT数据。
- 目的是让模型在自身策略会访问的状态下学会请求、生成和使用反馈。

**（2）在线RL：反馈感知的信用分配**
- **CFE（比较反馈估计）**：在同一提示的rollout组内，将请求反馈的轨迹组（call组）与不请求的轨迹组（skip组）的成功率之差作为反馈效用估计：
  \[
  \hat{u}(x) = \frac{1}{|G_{x,{call}}|}\sum_{j\in G_{x,{call}}} r_j - \frac{1}{|G_{x,{skip}}|}\sum_{k\in G_{x,{skip}}} r_k
  \]
  最终回报为任务奖励 + 反馈项（\(\beta C_i \hat{u}_i\)）+ 重复请求惩罚项。
- **反馈感知优势塑形**：拆分请求反馈轨迹的令牌为反馈前（pre）、请求动作（call）、反馈后（post）三段，对反馈前令牌降低优势（最多减至0），对反馈后令牌增加优势：
  \[
  \hat{A}_{i,t} = \begin{cases} \max(A_i-\lambda g_i,0), & t\in T_i^{pre}\\ A_i, & t\in T_i^{call}\\ A_i+\lambda g_i, & t\in T_i^{post}\end{cases}
  \]
  其中 \(g_i = \text{clip}(\hat{u}_i, 0, b)\)，从而避免“奖励导致请求的坏前缀”与“修复它的好延续”被同等强化。

**（3）离线RDPO（rollout-derived preference optimization）**
- 从最新一轮在线rollout中，按提示（prompt）配对“成功请求反馈的轨迹”和“失败但没有请求反馈的轨迹”，要求二者在首次请求前的历史前缀足够相似（Jaccard相似度≥0.7），再用LLM judge做二次筛选。
- 以成功轨迹的前缀为共享上下文，偏好其对应的反馈，拒绝失败轨迹的反馈，进行DPO式离线更新。
- 防止离线更新覆盖在线学习的任务求解能力，采用较小学习率（2×10⁻⁷）、2 epochs。

**（4）迭代交替优化**
- 默认采取100步在线RL + 1次RDPO更新，循环5次（100×5，共500步在线RL）。
- 每轮RDPO使用最新rollout挖掘的偏好对，使批评者始终与当前策略的失败分布保持对齐。

## 6. 主要结论与发现

1. **性能提升**：7B规模下，CAFE平均EM/F1为52.5/60.7，超过最强RL基线IGPO达2.1 EM和1.3 F1；在所有七个数据集上均优于纯GRPO。
2. **域外泛化**：在全部6个域外基准上保持收益，验证了方法的稳健性。
3. **规模可迁移**：3B规模同样明显优于现有3B搜索智能体（平均48.8/57.4），接近若干7B基线。
4. **减少幻觉**：答案级幻觉率从GRPO的17.6%降至12.6%，且每个数据集上均降低。
5. **共同进化必要性**：只优化Agent或只优化Critic最终达到平台期；交替优化持续改进。跨玩实验表明，后期Agent必须搭配同期Critic才能发挥最佳性能，说明增益并非来自“更强的批评者”，而是来自与策略失败分布的对齐。
6. **反馈内容演化**：早期反馈关注检索和接地错误，中期强调证据验证，后期聚焦重复查询、取消冗调、逻辑错误等高层次规划问题，表明批评者会随智能体能力提升而调整关注点。

## 7. 优点

- **问题建模新颖**：将搜索智能体的自我改进明确建模为“Agent–Feedback”耦合系统，而非孤立的策略学习或反馈生成问题。
- **共享参数一体化设计**：避免单独训练批评者的额外开销，同时因参数共享自然实现协同进化。
- **细粒度信用分配**：CFE和优势塑形分别解决“何时请求”和“请求后如何分配成败”两个层次的问题，比普通GRPO更精确。
- **离线偏好对挖掘**：RDPO通过前缀匹配构造可比的成功/失败反馈对，有效缓解结果混淆带来的噪声。
- **实验与分析扎实**：除主结果外，提供跨玩、训练动态、反馈内容演化、幻觉分析、训练计划等多样分析，从多角度支撑“共同进化”的核心论断。
- **理论保证**：给出定理证明，表明CAFE的在线更新与纯任务更新的方向保持正对齐，降低了反馈机制带偏任务优化的风险。

## 8. 不足与局限

- **骨干通用性有限**：仅使用Qwen2.5系列（7B/3B），未验证在更大模型或其他开源模型上的表现。
- **检索环境简化**：实验在固定本地语料库+E5检索器上进行，与真实网络搜索的多样性和噪声分布存在差异，实际部署效果可能波动。
- **基线公平性**：部分对比方法采用原论文公布的数值，而非统一完整复现；环境、训练数据或评估协议不完全一致，可能高估或低估差距。
- **反馈预算有限**：默认限制每个轨迹最多一次反馈请求，未充分探索多轮反馈的价值；重复请求惩罚只针对第二次以后。

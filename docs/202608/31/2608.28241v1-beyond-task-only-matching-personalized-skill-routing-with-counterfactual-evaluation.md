## 摘要
可复用技能库的快速扩展使得技能路由成为大型语言模型（LLM）智能体的关键能力。现有方法将路由视为仅基于任务的语义匹配。然而，当具有不兼容约束的用户发出相同请求时，这种假设混淆了任务相关性与技能适用性：仅基于任务的路由器可能选择一个语义上合理但对该请求用户不适用的技能。为了揭示这种失败模式，我们将“个性化技能路由”表述为基于用户画像的条件检索，其中相关性同时取决于任务和用户画像。我们首先引入一个用户画像反事实基准，其中任务保持不变，而用户画像的变化导致参考技能的变化。我们进一步构建了成对的反事实监督，并提出了SkillFeed，一个渐进式检索-重排序框架，首先建立任务与技能的对齐，然后学习基于用户画像的区分。通过检索主体级证据并对语义相似但画像冲突的候选进行重排序，SkillFeed能够识别同时满足任务要求和用户约束的技能。在SkillFeed-Bench上，SkillFeed的top-1检索准确率达到75.1%，比相应的预训练路由基线高出23.1个百分点。加入画像条件化后，在用户画像改变参考技能的查询上获得了35.1个百分点的提升。这种对比表明，用户画像在改变技能适用性时最为关键。我们的网站公开可用：http://www.aiskillfeed.com 。

## Abstract
The rapid expansion of reusable skill repositories makes skill routing a critical capability for large language model (LLM) agents. Existing methods treat routing as task-only semantic matching. However, when users with incompatible constraints issue an identical request, this assumption conflates task relevance with skill suitability: a task-only router can select a semantically plausible skill that is unsuitable for the requesting user. To expose this failure mode, we formulate \textit{personalized skill routing} as profile-conditioned retrieval, in which relevance depends jointly on the task and the user profile. We first introduce a profile-counterfactual benchmark, in which the task is held fixed while changes in the user profile induce changes in the reference skill. We further construct paired counterfactual supervision and propose SkillFeed, a progressive retrieve-and-rerank framework that first establishes task--skill alignment and then learns profile-conditioned discrimination. By retrieving body-level evidence and reranking semantically similar but profile-conflicting candidates, SkillFeed identifies skills that satisfy both task requirements and user constraints. On SkillFeed-Bench, SkillFeed attains 75.1\% top-1 retrieval accuracy, a 23.1-point improvement over the corresponding pretrained routing baseline. Adding profile conditioning yields a 35.1-point gain on queries where user profile changes the reference skill. This contrast shows that user profiles are most consequential precisely when they change skill suitability. Our website is publicly available at http://www.aiskillfeed.com .

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体日益依赖可复用的技能（skill）库来执行多步骤任务。技能以 SKILL.md 清单形式打包可复用流程、工具调用策略和执行约束，技能库的迅速扩张使“技能路由”（skill routing）成为关键的检索问题。
- **现有缺陷**：主流方法把技能路由视为“仅基于任务语义的匹配”（task-only semantic matching），假设任务唯一决定合适技能。但当两个用户提出相同请求、却拥有**不兼容的用户画像约束**（如预算、平台、语言、支付方式、专业背景等）时，任务相关性与技能适用性被混淆，导致只按任务语义检索的模型选出“语义相似但实际不适用”的技能（例如给学生推荐豪华行程规划器）。
- **核心问题**：如何将用户画像纳入技能路由，使相关性由“任务 + 画像”联合决定，并设计能评估“画像变化导致参考技能变化”的评测方法。
- **论文含义**：提出“个性化技能路由”（personalized skill routing）这一新问题设定，给出反事实基准 SkillFeed-Bench 和两阶段框架 SkillFeed，证明用户画像在技能适用性变化时是最关键信号，是任务级评测无法覆盖的重要盲区。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 问题形式化
- 候选技能 $S_i = (n_i, d_i, b_i)$ 分别表示名称、描述、过程主体（procedural body）。
- 个性化路由目标：$S^\*_{q,p} = \arg\max_{S_i \in \mathcal{S}} f(q,p,S_i)$，其中 $q$ 为任务，$p$ 为用户画像。
- 路由系统需在 228K 规模技能库中返回 top-K 集合，并保证 $S^\*_{q,p} \in R_K(q,p)$。

### 2.2 反事实监督数据构建
- **来源**：从 GitHub、SkillNet、SkillSMP 等聚合技能，去重后得到 228,432 个技能，每个包含名称、描述、过程主体。
- **任务与画像收集**：收集 272 个真实任务描述，配对结构化画像（国家/地区、语言、偏好平台、支付方式、其他约束）。
- **参考技能标注**：先通过预训练嵌入模型召回 top-K 候选，再由 LLM 从“任务相关性、画像兼容性、能力匹配、约束满足、特异性、过拟合风险”六个维度进行打分和成对比较，选定单个参考技能。
- **画像反事实增强**：固定任务 $q$，用 LLM 生成与原画像不同的替代画像 $\tilde{p}$，重新标注参考技能 $\tilde{S}$；仅保留 $\tilde{S} \neq S$ 的实例，从而直接测试“画像变化导致正确技能变化”的能力。
- **质量控制**：丢弃置信度 <0.80 的样本、任务与技能词法重叠 >0.50 的样本；双人独立人工审核，专家仲裁分歧，排除歧义案例。
- 训练数据：2,712 个任务中心实例；7,459 个画像条件实例（含反事实配对）。每个训练实例由任务、画像、正技能、硬负样本组成。

### 2.3 SkillFeed 两阶段框架
- **训练阶段**
  - **两阶段检索器训练**：基于 Qwen3-Embedding-0.6B。
    - Phase 1：仅用任务查询和硬负样本，学任务-技能对齐（InfoNCE 目标）。
    - Phase 2：把用户画像追加到查询，加入反事实配对实例，学画像条件判别。
  - **重排器训练**：基于 Qwen3-Reranker-0.6B，对每个候选组（1 个正技能 + 多个画像冲突硬负样本）使用列斯wise交叉熵目标（以模型输出 “yes” logit 作为相关性分数），候选输入包含名称、描述和过程主体。
- **推理阶段**
  1. **候选召回**：三路互补检索通道——① 任务级密集检索（任务名称/描述 → 技能名称/描述）；② BM25 词法检索；③ 画像条件块级密集检索（将 SKILL.md 正文按 Markdown 结构切块，逐块编码检索）。
  2. **技能主体分块**：将长技能主体按 Markdown 章节拆分为重叠段落（每段 200–500 tokens，最长 800），保留技能名、描述、章节路径和内容，避免长文档嵌入稀释局部匹配信号。
  3. **证据聚合**：对每个候选技能 $S_i$，将其命中块相似度聚合成技能级兼容分数：$\mathrm{score}(S_i) = \alpha \max_{c\in C_{S_i}} h_c + \frac{\beta}{M}\sum_{c\in \mathrm{Top}_M(C_{S_i})} h_c + \gamma \log(1 + |C_{S_i}|)$。最大项保留决定性证据，top-M 均值抑制孤立噪声，对数项轻度奖励多块支持。
  4. **融合与重排**：三路检索结果用加权倒数秩融合（权重：任务密集 0.40，画像块密集 0.40，BM25 0.20）合并，取 top-50（默认），再由训练好的重排器输入任务、画像、完整技能信息做最终排序。

## 3. 实验设计

### 3.1 数据集 / 基准
- **SkillFeed-Bench**：基于 228,432 个候选技能；329 个标注测试查询，涵盖 10 个技能类别（Development、Business、Research、Science 等）。
  - 画像敏感查询：162 个（其中 77 个为画像反事实增强样本，另 85 个为标准但有约束样本）。
  - 画像不敏感查询：167 个。
  - 平均任务描述长度 61.8 词；平均技能主体摘录长度 16,730 字符；任务-技能主体词法重叠平均 0.29（上限 0.50）；标注平均置信度 0.92。
- 每个测试样本附带 4 个硬负技能（语义相似但画像不兼容）。

### 3.2 对比方法
- **检索器**：BM25、E5-large-v2、BGE-large-en-v1.5、SkillRouter 稠密检索器、Qwen3-Embedding-8B（无任务适配）、SkillFeed 的 Phase 1 检索器（隔离画像效果）、SkillFeed Phase 2 检索器。
- **重排器**：预训练 Qwen3-Reranker-0.6B、BGE-reranker-v2-m3、Qwen3-Reranker-8B、MiMo-V2.5-Pro 作为 LLM 重排器、SkillRouter reranker、SkillFeed reranker。
- 所有重排器在同一候选列表上重排，保证对比公平。
- **指标**：Hit@1/3/5/10、MRR@20、nDCG@20；并特别报告画像反事实子集上的 Hit@1（记为 CF-Switch Acc.）。

### 3.3 主要结果
- **主表对比**：
  - 仅嵌入检索：SkillFeed Phase 2 达 Hit@1 0.617，优于 E5-large-v2 (0.322)、BGE (0.386)、Qwen3-Emb-8B (0.471)、Phase 1 (0.483)。
  - 嵌入+重排：SkillFeed Phase 2 + SkillFeed reranker 达 Hit@1 0.733，优于 Qwen3-Reranker-8B (0.632)、SkillRouter (0.614)、MiMo LLM (0.590)。
  - 全流水线（BM25 + 任务密集 + 画像块密集 + 重排）：Hit@1 0.751、MRR@20 0.803，为最佳。
- **画像条件化的必要性**：
  - 任务仅匹配的预训练基线和 Phase 1 在反事实查询上 Hit@1 仅 0.143 和 0.052，而画像不敏感查询上仍有 0.611/0.623——说明任务语义无法应对画像切换。
  - Phase 2 加入画像监督使反事实 Hit@1 从 0.052 提到 0.286；重排器加入画像后从 0.026 提到 0.377，且不敏感查询几乎不变（0.838→0.832）。

## 6. 主要结论与发现

- 用户画像在技能路由中是不可或缺的信号：当画像改变正确技能时，任务仅匹配的模型表现接近随机，而画像条件化模型能显著提升。
- SkillFeed 两阶段设计有效：先任务对齐、后画像判别，配合主体块级检索与重排，能将 top-1 准确率从基线 0.520 提升到 0.751（+23.1 点）。
- 反事实评估是关键：反事实子集上的 Hit@1 差异（0.052 → 0.377）清楚证明，传统任务级评测无法揭示“画像切换导致技能切换”这一失败模式。
- 规模不是充分条件：经专门监督训练的 0.6B 模型优于未微调的 8B 模型，说明路由专用监督比单纯模型规模更重要。
- 技能主体块级证据对画像约束判别有帮助：将画像条件检索与任务密集、BM25 结合可提升深度召回（Hit@10 达 0.918）。

## 7. 优点

- **问题定义新颖**：将“个性化技能路由”明确为画像条件检索，并用反事实样本分离任务相关性与技能适用性。
- **基准设计严谨**：双人人工审核+专家仲裁+词法重叠过滤，控制数据质量；反事实增强直接测试画像敏感性。
- **方法设计有层次**：渐进式训练（任务对齐→画像判别）、检索与重排分工明确、三路互补召回+块级证据聚合+加权融合，逻辑清晰。
- **实验验证全面**：覆盖多种方法、规模、消融和统计检验，能有力支撑核心结论。
- **实用性好**：推理阶段在 228K 库上可行，且开源网站资源。

## 8. 不足与局限

- **基准规模有限**：329 个测试样本（尤其反事实子集仅 77 个）可能不足以覆盖真实世界的画像多样性，统计功效受限。
- **标注依赖 LLM+人工**：参考技能由 LLM 筛选后人工确认，存在主观偏好；可能遗漏真实环境下的多个可行技能（每个样本只标注一个正确技能）。
- **方法适用范围**：画像评估依赖结构化用户画像字段，对自由文本或动态交互中的隐式约束处理不足；未来工作也承认需从多轮对话动态提取约束。
- **领域偏斜**：类别分布不均（Development、Business 占比大），专业科学与技术查询上的表现明显较低（Hit@1 0.5–0.6），泛化性有待验证。
- **算力/效率细节缺失**：未报告训练时长、推理开销，无法评估部署成本；实验中仅报告了 0.6B 模型微调，未做更大基座上的方法测试。
- **评估单技能假设**：以“单一正确技能”为金标准，不能反映现实中多个兼容技能并存的情况，可能导致对合理替代技能的误判。

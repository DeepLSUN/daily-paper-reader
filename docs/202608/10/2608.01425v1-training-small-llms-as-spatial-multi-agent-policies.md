## 摘要
使用多智能体强化学习训练基于LLM的多智能体系统正迅速受到关注，而并行的工作线认为此类系统应根据其行为而非仅奖励来评判。我们在空间合作游戏中同时探讨这两条线索，其中使用低级动作提示的小型冻结LLM会直接失败，获得零奖励。在选项/半MDP框架的指导下——由于选项执行跨智能体是异步的，其多智能体扩展体现在宏动作Dec-POMDPs中——我们为每个游戏配备了一个符号化\emph{选项}库：由符号化规划器执行的类型化、状态可行、短视界行为。每个库由前沿编码模型根据游戏源代码起草；随后，筛选每个菜单的可行性守卫通过廉价随机策略预热滚动机制自动合成——只有能解释重复执行失败且不隐藏任何已记录成功的守卫才被采纳——因此没有守卫由人工编写、选择或奖励调整。每个智能体的LLM作为其在选项上的策略，通过每智能体变体的多智能体GRPO（PA-MAGRPO）训练私有逐智能体LoRA适配器；这将冻结基础模型从零奖励提升到在三个游戏和四个小型骨干网络上胜任游戏。行为审计随后揭示奖励与合作脱钩：上升的奖励曲线可能仅意味着一个智能体学会了独自执行整个任务，而其伙伴闲置——合作仅在任务需要时才会出现。因此，仅靠奖励不可靠地反映合作；行为评估必须与其并行。”}

## Abstract
Training LLM-based multi-agent systems with multi-agent reinforcement learning is rapidly gaining traction, and a parallel line of work argues that such systems should be judged by their behavior, not only their reward. We take up both threads in spatial cooperative games, where small frozen LLMs prompted with low-level actions fail outright, earning zero reward. Guided by the options/semi-MDP framework---and, because option execution is asynchronous across agents, its multi-agent extension in macro-action Dec-POMDPs---we equip each game with a library of symbolic \emph{options}: typed, state-feasible, short-horizon behaviors executed by a symbolic planner. Each library is drafted by a frontier coding model from the game's source code; the feasibility guards that filter each menu are then synthesized mechanically from cheap random-policy burn-in rollouts---a guard is adopted only if it explains repeated execution failures while hiding no logged success---so no guard is authored, selected, or reward-tuned by hand. Each agent's LLM acts as its policy over options, with a private per-agent LoRA adapter trained by a per-agent variant of multi-agent GRPO (PA-MAGRPO); this lifts frozen bases from zero reward to competent play across three games and four small backbones. Behavioral audits then reveal that reward and cooperation decouple: a rising reward curve may simply mean that one agent has learned to run the entire task alone while its partner idles---cooperation emerges only when the task makes it necessary. Reward alone is thus an unreliable readout of cooperation; behavioral evaluation must sit alongside it.

**核心研究问题：**

## 2. 论文提出的方法论

### 2.1 整体架构

论文提出一个**两阶段流水线**+**训练框架**，核心思想是：将 LLM 的决策空间从原始动作提升到符号化**选项（option）**层面，让 LLM 只决定"做什么"，而由符号化规划器负责"怎么做"。

### 2.2 符号化选项库构建（四阶段流水线）

**Stage 1：选项模式起草（唯一的前沿模型步骤）**
- 使用 Claude Opus 4.8 读取游戏源码，生成类型化选项库。
- 每个选项包含四部分契约：实例化条件、符号化执行器（BFS最短路径+INTERACT）、终止条件、**效果谓词**（effect predicate，以 delta 形式定义状态变化的后置条件）。
- 执行器故意保持"环境天真"，不含游戏策略或合法性规则。

**Stage 2：均匀随机预热（无 LLM）**
- 使用均匀随机的无守卫菜单策略运行 burn-in 回放，记录每次选项执行的读集特征和结果（成功/效果失败/显式失败）。
- 例如 Overcooked AA 中，约 55 万次决策在单 CPU 核心上仅需 ~70 秒。
- 对比实验表明：用冻结 LLM 替代均匀策略会产生守卫覆盖崩溃（仅 2 个守卫 vs 均匀策略的 36 个），且成本高约 400 倍。

**Stage 3：守卫合成与验收证明**
- **显式通道**：执行器类型化失败原因出现≥5次直接转为守卫（如 NoPath → 实时可达性检查）。
- **推断通道**：对读集上的1/2字面量合取进行评分，仅当覆盖≥5次失败且**0次成功**时采纳（纯度要求）。
- 纯度要求是验收证明，防止策略信息混入守卫集。

**Stage 4：菜单组装**
- 每个目标任务类实例化一个菜单项（而非仅最近目标），评估所有守卫并隐藏被拦截的选项。
- 每决策使用 episode 种子随机打乱菜单字母，防止模型利用位置先验。

**外部合约修复循环**：机械层检测到契约缺陷（如绝对形式效果谓词导致静默 no-op 被记为成功、共享状态归因错误、最近目标实例化导致不可达），由前沿模型修复模式后重跑 Stage 2-3。

### 2.3 训练算法：PA-MAGRPO

- **每智能体私有 LoRA 适配器**：共享冻结基座保留通用语言/任务知识，每个智能体拥有独立适配器，允许角色分化的梯度在私有参数中累积而非平均抵消。
- **MAGRPO 变体（PA-MAGRPO）**：每轮收集 K 条联合 rollout，以团队共享回报做组内归一化获得优势，仅更新对应智能体的私有适配器，使用 PPO-clip + KL 惩罚。
- 更新只发生在选项边界，规避了半 MDP 折扣机制的必要性。
- **算法流程**（每轮）：采样 K 条联合 rollout → 计算团队回报 → 组内归一化得共享优势 → 每智能体独立执行 E 轮 PPO epoch。

## 6. 主要结论与发现

1. **配方有效且可跨基座泛化**：冻结基座在三个游戏全部零奖励，完整方法在 4 个 backbone 上全部非零（Cleanup 60.25–105.69、Overcooked AA 6.21–7.31、Harvest 85.41–115.52）。
2. **两个成分缺一不可**：
   - 去掉选项菜单（Ablation A）→ 全部崩溃为零，梯度无法修复采样从未到达的状态。
   - 共享 LoRA（Ablation B）→ 无法维持角色分工，Cleanup 仅 0.10 苹果、Overcooked 2.25 次交付（约为完整方法的 1/3）。
3. **可行性过滤的价值独立于宏动作语义**：Compound-JSON（Ablation D）在 Cleanup 上性能不稳（std ≈ mean）、Overcooked 完全零分。
4. **奖励与协作解耦（核心发现）**：
   - **Cleanup**：高奖励伴随真实的角色分工（3 个食者 + 3 个清洁者 + 1 个辅助者，无角色标签）。
   - **Overcooked AA**：高奖励但**无协作**——agent 1 等待 72% 决策，agent 0 独自完成全部工作；单人测试证明该任务可独立完成。
   - **Overcooked FC**（对照组）：奖励上升**确实**由协作驱动（单人测试交付为零）。
   - **Commons Harvest**：奖励几乎平坦（76.73→98.29），但斑块存活显著改善（约 200 步全灭 → 400 步仍存活 2.5/6）。
5. **结论**：奖励曲线既可能高估协作（Overcooked AA）也可能低估协作（Commons Harvest），行为评估必须与奖励并行。

## 7. 优点

- **方法设计精巧**：选项库构建仅需一个前沿模型步骤，守卫自动合成且含"零成功隐藏"的验收证明，将策略信息隔离在守卫之外；执行器故意天真，让数据驱动发现问题。

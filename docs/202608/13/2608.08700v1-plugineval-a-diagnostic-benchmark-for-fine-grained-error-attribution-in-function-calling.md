## 摘要
随着大语言模型越来越多地作为自主代理运行，工具路由的可靠评估变得至关重要。当前基准面临三个结构性局限：遵循幂律的数据分布导致稀有场景代表性不足；缺乏对抗性硬负样本模糊了模型间的性能差异；以及标注流程依赖于未经执行验证的LLM判断。在本文中，我们介绍了PluginEval，这是一个通过两阶段框架构建的基准，系统地缓解了这些局限。首先，我们将工具路由表示为三个决策的序列，并将生成与验证分离。LLMs提出候选调用，而确定性验证和真实API执行为可靠的质量信号。其次，我们按功能、意图和边界分解每个插件，以识别触发和排除场景。然后，我们生成不同难度级别的查询以填补覆盖空白，包括针对三种失败模式的对抗性负样本，并将其返回第一阶段进行标注。这个过程形成了一个闭环，迭代直到覆盖收敛。在评估方面，我们超越聚合准确性。锚定到金标注的LLM评判器将失败分类为漏调用、虚假调用或参数错误，为每个模型生成详细的错误画像。我们评估了五个模型家族，包括专有模型和开放权重模型，分析了它们在难度级别和错误类别上的性能，并通过与人类标注的一致性验证了评判器。

## Abstract
Reliable evaluation of tool routing is critical as Large Language Models increasingly operate as autonomous agents. Current benchmarks face three structural limitations: data distributions that follow a power law leave rare scenarios underrepresented; the absence of adversarial hard negatives obscures performance differences across models; and annotation pipelines depend on LLM judgments that have not been validated through execution. In this paper, we introduce PluginEval, a benchmark constructed through a two-stage framework that systematically mitigates these limitations. First, we formulate tool routing as a sequence of three decisions and separate generation from verification. LLMs propose candidate calls, while deterministic validation and real API execution provide reliable quality signals. Second, we decompose each plugin by capability, intent, and boundary to identify trigger and exclusion scenarios. We then generate queries at different difficulty levels to fill coverage gaps, including adversarial negatives targeting three failure modes, and return them to the first stage for annotation. This process creates a closed loop that iterates until coverage converges. For evaluation, we move beyond aggregate accuracy. An LLM judge anchored to gold annotations classifies failures as missed calls, spurious calls, or parameter errors, producing a detailed error profile for each model. We evaluate five model families, including proprietary models and models with open weights, analyze their performance across difficulty levels and error categories, and validate the judge through agreement with human annotations.

- **研究背景**：大语言模型（LLM）越来越多地以自主代理（autonomous agent）的形式运行，通过函数调用（function calling）使用外部工具是该范式的核心能力。因此，对工具路由（tool routing）进行可靠评估至关重要。
- **现有基准的三大结构性局限**：
  - **数据分布偏差**：现有数据集遵循幂律分布，长尾/稀有场景代表性严重不足。
  - **缺乏对抗性硬负样本**：缺少具有迷惑性的负样本，导致模型间性能差异难以被有效区分（即“天花板效应”或区分度不足）。
  - **标注可靠性缺失**：标注流程高度依赖LLM判断，而这些判断未经真实API执行或确定性验证，存在系统性偏差风险。
- **核心问题**：现有评估框架大多只报告聚合正确率（aggregate accuracy），无法诊断失败的具体原因——是工具选择失误、参数错误，还是过度调用？聚合分数掩盖了不同模型截然不同的失败模式（如文中图1所示）。
- **研究目标**：构建一个能够**细粒度归因函数调用错误**的中文基准，并配套可靠的标注流程、结构化覆盖、基于模型行为的难度校准体系。

### 2. 方法论：PluginEval 与闭环构建框架（PCCF）

#### 2.1 总体框架概述

论文提出 **PluginEval Closed-Loop Construction Framework (PCCF)**，将工具路由构建为三级层次决策：

- **f₁(q)**：该查询是否需要调用工具（工具必要性）。
- **f₂(q, t, dₜ)**：给定插件描述，该目标插件是否相关（插件相关性）。
- **f₃(q, t, dₜ, Sₜ)**：请求能否被落地为合法调用，或应被拒绝（调用可行性）。

标签空间 Y 包含四种情况：不必要的工具使用（0,0,⊥）、不相关插件（1,0,⊥）、相关但参数不足（1,1,⊥）、合法调用（1,1,θ*）。

#### 2.2 阶段一：执行落地的集成标注（Execution-Grounded Ensemble Annotation）

- **分离生成与验证**：LLM生成器只负责提出候选调用（含参数），验证环节使用确定性手段，不依赖生成器自评。
- **验证流程**（对每个可执行提议执行以下步骤）：
  1. **确定性Schema验证**：检查是否符合参数模式。
  2. **参数评估器**（S_arg）：评估参数是否被查询支持、符合插件语义。
  3. **真实API执行**：通过MCP执行提议，观察返回结果。
  4. **结果评估器**（S_out）：检查响应是否满足用户请求。
- **评分公式**：最终得分 s⁽ᵏ⁾ₘ = λ_arg·S_arg(z⁽ᵏ⁾ₘ | q,t) + λ_out·S_out(o⁽ᵏ⁾ₘ | q,t)，其中 λ_arg + λ_out = 1，得分 ∈ [0,1]。
- **迭代细化（Refinement）**：若最高分未达阈值 τ，则将失败痕迹（schema错误、执行错误等）反馈给生成器，继续下一轮，最多R_max轮。这种方法与标准自细化（self-refine）的差异在于使用独立评估器、确定性错误和真实执行结果作为修复信号。
- **合理弃权（Justified Abstention）**：当信息不足时返回⊥，参数评估器判断缺失信息是否确实阻碍了合法调用。

#### 2.3 阶段二：场景驱动合成与行为校准（Scenario-Grounded Synthesis and Behavioral Calibration）

- **场景分类**：从插件描述中提取**触发场景**（应调用插件）和**排除场景**（不应调用此插件：无需工具/需要其他插件/超出能力边界）。
- **覆盖机制**：每个已认证示例分配一个主场景，其他匹配保留为辅助标签。计算赤字 Δᵣ(u) = max{0, b(u) − nᵣ(u)}，仅对赤字大于0的单元合成新样本。
- **难度分层**：
  - **正样本**：按推理深度分 Easy（0步）/ Medium（1步）/ Hard（≥2步）。
  - **负样本**：按类型分——Type A（领域距离）、Type B（表面相似）、Type C（能力边界证据）。
- **行为校准**：用冻结参考路由器在K次受控运行中评估，定义 p_K(x) = (1/K)·Σ 1{by⁽ʲ⁾(x)=y(x)}。若 p_K=0 为 Hard，0<p_K<1 为 Medium，p_K=1 为 Easy。若校准难度低于目标，则用识别证据（recognition evidence）强化负样本（使其更具迷惑性）。
- **闭环迭代**：当所有覆盖预算满足、连续L轮覆盖率提升低于阈值、或合成预算耗尽时终止。

#### 2.4 金锚定评估框架（Gold-Anchored Evaluation）

- **语义一致性判据**：仅凭字符串精确匹配不足，引入以人工验证的黄金标注（G）为准绳的LLM judge，查询只为解释语义等价性，不得扩展或覆盖黄金标注。
- **层级工具调用验证**：
  - **工具对齐（Stage 1）**：按精确名称匹配预测与黄金调用，只对交集部分做参数评估；差异部分记录为工具选择不匹配。
  - **参数过滤（Stage 2）**：任一参数集为空则跳过该对。
  - **语义验证（Stage 3）**：判定预测参数与黄金参数在用户查询上下文下是否语义等价，允许别名、格式差异、等价数值表示等，但时间范围严格。
- **查询级评估与错误归因**：正查询必须**所有必需工具全部召回且参数全部正确**才算成功（严格标准）。失败被划分为互斥类别：
  - **Miss recall**（漏调）：缺少必需工具。
  - **Parameter error**（参数错误）：对齐工具的参数语义不正确，细分为时间错误、缺失参数、错误值。
  - **Over recall**（过度调用）：在负查询上错误激活了工具。
  - 指标：Recall = TP/(TP+FN)，Accuracy = (TP+TN)/(TP+FN+TN+FP)。

### 6. 主要结论与发现

1. **测试构成显著影响表面性能**：将Easy比例从0.40提升至0.60，模型Recall提升14.73–21.15个百分点、Accuracy提升14.20–22.49个百分点。这说明聚合分数高度依赖评测集的难度构成，跨基准直接比较不可靠。
2. **模型排名跨基准漂移**：Claude Opus 4.6在PluginEval和BFCL上排名第一，但Gemini 3.1 Pro在APIBench和NexusRaven上最优；DeepSeek-V4-Pro在PluginEval上超过GPT-5.4但在另外两个基准上落后。模型能力评估高度依赖基准的侧重点。
3. **不同模型有截然不同的失败画像**：GPT-5.4 Miss（33.72%）和Over（33.20%）双高，工具选择是主要瓶颈；Claude Opus 4.6 Miss最低（13.95%）但Over偏高（29.10%），召回好但弃权弱；Gemini 3.1 Pro Over最低（18.55%），错误画像最均衡。
4. **时间参数是最普遍的薄弱环节**：所有模型的Temp.错误率均最高（7.96%–10.41%），是参数错误的最大子类，为模型改进指明方向。
5. **所有模型在Hard级别断崖式下降**：Hard级别Recall仅2.8%–10.8%，说明复杂工具路由仍是前沿模型的重大瓶颈。
6. **判官与人工高度一致**：Cohen's κ 达0.9221–0.9585，Miss/Over类别完全一致（100%），分歧集中在参数错误类（88%–93%）。参考标注总体有效率达96.67%。
7. **PCCF组件均有独立贡献**：内容验证、迭代校准、闭环合成、BoN采样分别解决基准构建中的不同问题（数据质量、有效产出、覆盖、难度控制）。

### 7. 优点

- **方法创新性强**：提出"三级决策"工具路由形式化（必要性→相关性→可行性），框架依赖关系自然清晰（先验证再覆盖再校准）。
- **两阶段闭环设计精妙**：将"可信度"（阶段一）与"必要性/覆盖"（阶段二）解耦，避免传统标注管线的"可信度与覆盖要求纠缠"问题；失败痕迹返回生成器进行迭代修复，形成真正的闭环。
- **金锚定判官设计严格**：判官只能以黄金标注为锚，查询仅用于语义解释，不能扩展或覆盖黄金规格，防止"看似合理"的错误被误判为正确；层级验证先对齐工具再比较参数，避免错误归因混淆。
- **难度校准基于行为而非启发式**：使用冻结参考路由器在K次运行中的表现标定难度，避免启发式难度标签与路由行为的分歧。
- **评估的细粒度与实用性**：错误归因支持Miss/Over/Param三级分类，Param进一步细分Temp/Missing/Value，为模型改进提供了直接可操作的"错误画像"而非单一分数。
- **审计严谨**：双重审计——先审计参考标注质量（人工验证Gold），再审计判官归因质量，且报告了Fleiss' κ与Cohen's κ以校正偶然一致性。
- **消融实验系统**：每个PCCF组件都有独立消融，且部分带统计显著性检验，证据链完整。

### 8. 不足与局限

- **算力信息缺失**：未报告GPU型号、时间、成本等资源信息，复现成本不可估。
- **判官偏差风险**：所有评判使用单一固定GPT-5.2，未做判官间的鲁棒性分析；LLM判官固有的系统性偏差（自偏好、位置偏差等）仍可能存在。
- **模型覆盖有限**：仅5个模型，缺少更小参数模型、专用函数调用微调模型、以及同系列不同规模的对比，难以刻画模型规模的影响。
- **中英分布与可推广性**：基准为中文，没有英文平行版本或跨语言泛化验证；54个插件规模相对工具生态明显偏小，对复杂多步交互覆盖有限。
- **负样本比例与评估偏差**：500/3000（16.7%）的负样本比例可能偏低，且负样本质量强依赖构造者设定的目标难度，存在人工痕迹。
- **Hard级实例区分度过低**：Hard级Recall仅2.8%–10.8%，几乎所有模型在该级别都接近地板，压缩了模型间的区分空间，可能需重新校准难度分布。
- **严格全或无（all-or-nothing）标准**：查询级成功要求全部工具正确，部分完成完全计为失败，可能低估模型的部分有用能力，也忽视多工具之间的交互复杂度（如执行顺序）。

## 摘要
执行代码片段对于动态程序分析至关重要，但由于上下文缺失和依赖不完整等问题，执行任意代码片段仍然具有挑战性。现有的部分代码执行方法（如LExecutor和Treefix）利用语言模型的能力来推断缺失信息并实现执行。然而，它们存在（i）动作空间和反馈有限，以及（ii）优化策略僵化的问题，这限制了其有效性和效率。在本文中，我们提出了AgentExecutor，一种用于部分代码执行的新型多智能体框架。我们的方法引入了一个三阶段设计：执行环境准备、带迭代细化的动态探索，以及通过程序合成进行前缀演化。在能够思考、行动和迭代获取反馈的LLM智能体的支持下，AgentExecutor能够自主探索更丰富的动作空间，实现创建资源文件和解析环境配置等多种操作。此外，它采用自适应优化策略，包括覆盖引导的上下文剪枝和通过程序合成进行前缀演化，以系统性地提高部分代码的执行质量。我们在两个广泛使用的数据集（包括Stack Overflow代码片段和开源项目代码）上评估了AgentExecutor。结果表明，AgentExecutor分别实现了高达94%和90%的代码覆盖率，比最先进的方法Treefix提高了19.9%和13.8%。此外，AgentExecutor显著减少了执行时间（最多减少80.3%）和成本（最多减少56.6%）。这些发现表明，AgentExecutor为部分代码执行提供了一种有效且高效的解决方案。

## Abstract
Executing code snippets is essential for dynamic program analysis, but it remains challenging to execute an arbitrary code snippet due to issues like missing context and incomplete dependencies. Existing approaches to partial code execution, such as LExecutor and Treefix, leverage the power of language models to infer missing information and enable execution. However, they suffer from (i) limited action spaces and feedback, and (ii) rigid optimization strategies, which restrict their effectiveness and efficiency. In this paper, we propose AgentExecutor, a novel multi-agent framework for partial code execution. Our approach introduces a three-phase design: execution environment preparation, dynamic exploration with iterative refinement, and prefix evolution via program synthesis. Supported by the power of LLM agents who can think, act, and get feedback iteratively, AgentExecutor is able to autonomously explore a richer action space, enabling diverse operations such as creating resource files and resolving environment configuration. Furthermore, it adopts adaptive optimization strategies, including coverage-guided context pruning and prefix evolution via program synthesis, to systematically improve the execution quality of partial code. We evaluate AgentExecutor on two widely used datasets comprising Stack Overflow snippets and open-source project code. The results show that AgentExecutor achieves up to 94% and 90% code coverage, outperforming the state-of-the-art approach Treefix by 19.9% and 13.8%, respectively. In addition, AgentExecutor significantly reduces execution time (by up to 80.3%) and cost (by up to 56.6%). These findings demonstrate that AgentExecutor provides an effective and efficient solution for partial code execution.

- **核心问题**：任意给定的代码片段（如 Stack Overflow 上的示例代码、开源项目中的函数）往往因为缺少上下文（如未定义的变量、缺失的 import）或环境不完整（如依赖未安装、路径不兼容）而无法直接执行。如何让这类“部分代码”自动变得可执行，是动态程序分析领域的一个重要挑战。
- **已有方法的不足**：
  - **LExecutor**：使用神经网络预测缺失的运行时值，但预测能力有限，难以应对复杂上下文。
  - **Treefix**（当前 SOTA）：利用 LLM 构建前缀树来补充上下文，但存在两个关键缺陷：
    - **动作空间有限、反馈不足**：只能生成“库导入”和“变量初始化”两类前缀，依赖静态工具（如 pipreqs）识别依赖，无法执行创建文件、安装依赖、模拟模块等操作；反馈缺乏可读性和针对性。
    - **优化策略僵化**：固定次数调用 LLM，不考虑是否已收敛；前缀仅由 LLM 直接生成，缺乏系统性搜索和进化机制。
- **论文目标**：提出一个基于多智能体的框架 `AgentExecutor`，让 LLM 智能体能够“思考—行动—接收反馈”迭代循环，从而更有效、更高效地解决部分代码执行问题。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 总体设计

AgentExecutor 采用三阶段流水线，由三个不同角色的 LLM 智能体协作完成：

1. **执行环境准备（Execution Environment Preparation）**
   - **EnvAgent** 负责初始化每个代码片段的隔离虚拟环境（使用 `uv` 环境管理器，预装常用包）。
   - 通过 bash 工具执行命令（如 `pip install`、创建文件）来解决环境问题，并尝试运行代码，根据反馈迭代修复环境。
   - 优势：避免不同 snippet 之间的环境污染和依赖冲突。

2. **动态探索与迭代细化（Dynamic Exploration with Iterative Refinement）**
   - **RefAgent** 分析代码路径，生成/修改前缀（如通过 `sed` 编辑文件），运行代码并获取覆盖率反馈。
   - **智能体友好反馈**：除了原始执行输出，系统会附加针对未定义变量、空输出、无效前缀等情况的提示，帮助智能体理解失败原因。
   - **覆盖感知动态剪枝（Coverage-aware Context Pruning）**：当连续若干次探索的覆盖率未超过历史最佳值时，剪掉低价值历史消息，只保留高价值探索历史，以缓解 LLM 注意力稀释问题，同时降低 token 消耗。

3. **基于程序合成的前缀演化（Prefix Evolution via Program Synthesis）**
   - **EvoAgent** 从 RefAgent 生成的前缀中，根据**覆盖感知的种子选择**（最大化联合覆盖、限制种子数量）筛选出代表性前缀。
   - 分析这些前缀中的关键变量与其取值组合。
   - 合成一个**生成器程序**（如嵌套循环枚举所有变量值的组合），执行该程序可以批量产生大量新前缀，再验证并迭代改进生成器。
   - 这样用程序执行代替大量 LLM 调用，显著扩展搜索空间并降低成本。

### 2.2 关键公式 / 算法流程（文字说明）

- 给定不完整代码 `s`，目标是构造一个前缀集合 `P`，使得每个 `p + s` 可执行，并最大化：
  - **S-C（Single-Best Coverage）**：`max_{p∈P} coverage(p+s)`
  - **C-C（Cumulative Coverage）**：`coverage(∪_{p∈P} covered_lines(p+s))`
- 核心流程：
  ```
  输入: 部分代码 s
  阶段1: EnvAgent 初始化环境，安装依赖，尝试执行，修复环境问题
  阶段2: RefAgent 迭代生成/修改前缀，执行并获取覆盖率反馈，
          若连续 patience 次无改善则进行上下文剪枝，直到满意或达步数上限
  阶段3: 从已有前缀中按覆盖多样性选择种子 → EvoAgent 分析关键变量
          → 生成器程序枚举组合 → 执行生成器得到新前缀 → 验证并迭代改进
  输出: 最优前缀集 P 及其覆盖率
  ```

## 摘要
我们推出了Opt.Gear，这是一个基础模型，专为高效的设备端部署、实时推理和强大的任务能力而设计。它包括一个密集模型（1M、270M和1B），上下文长度为64K。我们设计了一种新的混合架构，将卷积键值门控混合器与局部-全局注意力相结合，以减少随着长上下文呈指数增长的KV缓存内存。与类似规模的模型相比，该架构在NPU上的预填充和解码速度最高可提升4.9倍。Opt.Gear从2万亿tokens的候选语料库中，在精心挑选的0.5万亿tokens子集上进行训练，无需知识蒸馏。这是现有基础模型中数据效率最高的。所有模型均开放权重，并提供ONNX、Qualcomm NPU和Apple ANE的部署二进制文件，使Opt.Gear成为需要快速、内存高效推理和强大任务能力的边缘应用的实用基础。此外，为了扩展设备端生成语言模型的生态系统，我们推出了Opt.Gear-1M，可部署在微控制器单元（MCU）上，这是一种微型语言模型（TLM）。Opt.Gear-1M是首个在STM32H747I-DISCO的ARM Cortex-M7 CPU上通过W4A32量化实现20 TPS的生成语言模型。

## Abstract
We introduce Opt.Gear, a foundation model designed for efficient on-device deployment, real-tim inference, and strong task capability. It includes a dense model (1M, 270M, and 1B) with a context length of 64K. We designed a new hybrid architecture that combines a convolutional key-value gated mixer with local-global attention to reduce the KV-cache memory that tends to increase exponentially with long context. This architecture delivers up to X4.9 faster prefill and decoding speeds on the NPUs compared to models of a similar scale models. From a 2T tokens candidate corpus, Opt.Gear is trained on a curated 0.5T tokens subset without knowledge distillation. This is the most data-efficient of the existing foundation models. All models are released with open weights and deployment binaries for ONNX, Qualcomm NPU, and Apple ANE making Opt.Gear a practical base for edge applications that need fast, memory-efficient inference and strong task capabilities. Furthermore, to expand the ecosystem of on-device generative language models, we are introducing the Opt.Gear-1M that can be deployed on Micro-Controller Units (MCUs), a Tiny Language Model (TLM). Opt.Gear-1M is the first generative language model to achieve 20 TPS with W4A32 quantization on the ARM Cortex-M7 CPU of the STM32H747I-DISCO.

# Opt.Gear技术报告——详细中文总结

## 1. 核心问题与整体含义（研究动机）

- **背景问题**：在智能手机、平板、汽车、机器人、嵌入式设备等边缘终端上直接运行大语言模型（LLM），能带来低延迟、隐私保护和离线可用性等优势，但面临SRAM容量有限、功耗约束严格、异构SoC（CPU/GPU/NPU）实时性要求高等硬性限制。
- **核心矛盾**：现有开源模型（如Llama 3、Gemma 3等）主要面向服务器级GPU设计，假设高带宽、大容量显存可用，无法直接在移动/边缘设备上高效部署。
- **技术瓶颈**：Grouped-Query Attention（GQA）的复杂度随序列长度呈O(N²)增长，KV缓存随上下文长度线性增加，导致移动NPU/GPU上出现显存带宽和SRAM容量瓶颈，是设备端推理延迟和功耗的主要来源。
- **Opt.Gear的定位**：不是简单地做"更小的模型"，而是联合优化下游质量、设备端延迟、内存效率、长上下文能力和实际可部署性，在硬件约束下实现高效边缘推理。

## 2. 方法论：核心思想与技术细节

### 2.1 核心架构：混合序列混合器（Hybrid Architecture）
- 由三类层组成：**全局GQA注意力层**（处理长程路由和全局信息）、**局部滑动窗口注意力层**（保留中程上下文，窗口512）、**ConvKV-Gated Mixer层**（处理短程局部上下文）。
- 关键动机：全注意力的状态随序列增长，循环/状态空间模型的表达能力受限且需要专用内核，Opt.Gear在两者之间取折中。

### 2.2 ConvKV-Gated Mixer（卷积键值门控混合器）
- **计算流程**：输入x_t分别投影为q_t、k_t、v_t → 对k和v施加因果深度可分离1D卷积 → 用sigmoid门控（g_t = σ(q_t ⊙ k̃_t)）调制卷积后的值流 → 输出投影。
- **核心优势**：整个过程为**静态线性+卷积+逐元素运算**，无softmax、无逐token注意力矩阵，对CPU/GPU/NPU上的边缘运行时映射友好。
- **公式**：g_t = σ(q_t ⊙ k̃_t)，y_t = g_t ⊙ ṽ_t，o_t = y_t W_o。

### 2.3 内存高效缓存机制
- 取代了滑动窗口注意力中随窗口大小W线性增长的KV缓存（Cache_local = O(2W·d_kv)），改为**固定大小的卷积状态**（Cache_ConvKV = O(2L_conv·d_kv)），其中L_conv为卷积核大小（1B/270M为3，1M为4）。
- 解码时仅需维护最后L_conv个投影状态，本地序列建模的内存和带宽开销大幅降低，且**与上下文长度无关**。

### 2.4 模型配置
- 三个尺寸：**Opt.Gear-1B**（d=1152，26层，GeGLU）、**Opt.Gear-270M**（d=640，18层，GeGLU）、**Opt.Gear-1M**（d=128，5层，ReLU6GLU）。
- 1B/270M支持64K上下文，使用KORMo分词器（词汇表125,184，韩英双语优化）；1M支持512上下文，使用2,048词汇的字节级BPE，面向MCU部署。
- 采用QK-LN（查询键归一化）、RoPE位置编码（全局theta=1,000,000，局部theta=10,000）、未绑定词嵌入。

### 2.5 量化感知训练（QAT）
- 创新点：**Hessian引导的尺度初始化**——不同于常规QAT用最大绝对值初始化量化尺度，Opt.Gear借鉴GPTQ思想，将量化视为逐层输出重建问题，用校准激活估计输入相关性矩阵，最小化全精度与量化输出之间的差异（公式1）。
- 之后用**LSQ（Learned Step Size Quantization）**将每组缩放因子作为可学习参数，用直通估计器优化（公式2）。
- 该流程保证初始化、QAT训练和最终权重转换使用**同一INT4量化网格**，避免部署时的量化器失配。

## 3. 实验设计

### 3.1 训练数据
- 从约2T tokens的候选语料（英语、韩语、数学、网页）中筛选出**0.5T tokens**的精选子集，配比为：约92%英语、6%韩语、2%数学，**不包含代码数据**。
- 不使用任何教师模型的知识蒸馏。
- Opt.Gear-1M不进行通用预训练，而是直接使用GPT生成的5万条STM32板卡控制指令数据（stm32_cmd_synth），学习将自然语言指令映射为JSON格式控制意图（LCD、LED、相机控制）。

### 3.2 评估基准
- **多学科选择题**：MMLU、MMLU-Pro、KMMLU、GPQA。
- **语言理解与推理**：WinoGrande、HellaSwag、PIQA、ARC（Easy/Challenge）、OBQA。
- **韩语理解与文化**：CLIcK、HAERAE、KoBEST。
- 使用LM Evaluation Harness框架，采用困惑度（perplexity）评估协议。

### 3.3 对比模型
- **亚1B组**：SmolLM2-135M、Gemma3-270M、LFM2.5-350M、Qwen3-0.6B（训练2T–36T tokens，多数使用蒸馏）。
- **1B–2B组**：Gemma3-1B、Llama3.2-1B、EXAONE 4.0-1.2B、LFM2.5-1.2B、Qwen3-1.7B。
- **量化对比**：RTN、AWQ、GPTQ vs Opt.Gear的QAT，对标Gemma3-1B、Llama3.2-1B、EXAONE 4.0-1.2B、Qwen3-1.7B。
- **硬件推理**：Qualcomm Snapdragon GEN4/GEN5 NPU（QAIRT）、iPhone 17 Pro/16 Pro（CoreML）、CPU/GPU/NPU跨运行时对比（llama.cpp），以及STM32H747I-DISCO MCU实测。

## 4. 资源与算力

- 训练集群：**8× NVIDIA H200 140GB GPU**，节点内由NVLink/NVSwitch互联。
- 并行策略：8路流水线并行（PP）、1路张量并行（TP）、ZeRO-1数据并行（DP）。
- **训练时长推算**：作者估算，在该硬件预算下，非蒸馏的1T-token训练需要约30天；在线知识蒸馏100B tokens也需要约30天；离线蒸馏存储Top-32 logits时，1TB只能存放约6B tokens（不到0.5T语料的2%），因此知识蒸馏在计算上不可行。
- 训练框架：HuggingFace Nanotron，支持3D并行。

## 6. 主要结论与发现

- **数据效率突出**：仅用0.5T tokens（无蒸馏）训练，Opt.Gear-1B在MMLU（43.2%）和GPQA（30.3%）上超越Gemma3-1B和EXAONE 4.0-1.2B（后者用12T tokens）；Opt.Gear-270M在PIQA和ARC-Easy上超过Gemma3-270M。
- **韩语能力显著**：Opt.Gear-1B在所有韩语基准（KMMLU、KoBEST、CLIcK、HAERAE）上全面超越同尺寸Gemma3-1B、Llama3.2-1B和EXAONE 4.0-1.2B，HAERAE上领先约9–14个百分点。
- **NPU推理性能领先**：Qualcomm GEN5上，Opt.Gear-1B达到Prefill 7,042 tokens/s，比Llama3.2-1B快约57%、比Gemma3-1B快约118%；iPhone 17 Pro的NPU上Prefill达3,085 tokens/s，CPU/GPU/NPU均最高。
- **量化稳定性优异**：Opt.Gear-1B在QAT基础上再套PTQ（RTN/AWQ/GPTQ），性能降幅极小（如MMLU仅从41.3%微降至39.8%），而Gemma3-1B降幅明显（35.8%→32.5%），韩语任务上优势更突出。
- **MCU级生成可行性**：Opt.Gear-1M在STM32H747I-DISCO上以W4A32量化达到20 tokens/s，成为首个在ARM Cortex-M7上实现交互式生成的语言模型。
- **架构验证**：ConvKV-Gated Mixer替换滑动窗口注意力后，既降低了缓存和带宽需求，又在多种部署形态（NPU/ANE/MCU）下保持或超越同类模型能力。

## 7. 优点

- **硬件感知设计贯穿始终**：从算子选择（静态/确定性运算优先）、缓存结构（固定卷积状态）到量化策略（Hessian初始化+LSQ），均以实际部署约束为第一优先级，而非仅追求benchmark分数。
- **数据效率令人印象深刻**：在0.5T tokens、无蒸馏条件下达到甚至超越用2T–36T tokens训练的同类模型，验证了数据筛选和混合配比的有效性。
- **量化流程新颖且实用**：将GPTQ的Hessian分析和LSQ可学习尺度结合，实现"初始化-训练-部署"三阶段量化网格一致性，量化鲁棒性在对比中表现突出。
- **透明、务实的成本分析**：明确披露训练硬件和蒸馏的存储/计算成本估算，为后续研究者提供了可参考的资源规划依据。
- **开源生态友好**：提供ONNX、Qualcomm NPU、Apple ANE二进制，以及llama.cpp、ExecuTorch、vLLM支持，覆盖从MCU到手机的完整部署路径。
- **真实设备验证**：MCU测速在固件内用HAL_GetTick实际计时，非仿真器估算，数据可信度高。

## 8. 不足与局限

- **训练规模制约能力上限**：0.5T tokens的预算在复杂数学推理和通用知识上明显不足（如MMLU-Pro仅11.3%，远低于Qwen3-1.7B的43.0%），推理能力的提升空间受限。
- **混淆因素未解耦**：数据规模、数据构成和模型容量未独立变化，无法判断推理差距主要来自模型大小、数据不足还是训练低效。
- **缺乏消融研究**：未见对ConvKV-Gated Mixer的窗口大小、注意力层与Mixer层比例、QAT各组件的贡献等关键设计选择的系统消融分析。
- **对比公平性存疑**：与训练数据多出数十倍的模型直接比较，虽然体现了数据效率，但无法区分"方法优越"与"数据红利"；且对比基线未统一评估协议细节（尽管声称用同一harness）。
- **1M模型能力过窄**：Opt.Gear-1M仅在STM32控制指令这一单一场景训练，无法评估通用语言能力，作为"生成语言模型"的泛化性证据不足。
- **硬件实验结果受生态制约**：llama.cpp的NPU后端对Opt.Gear的滑动窗口模式优化不佳（Prefill仅290 tokens/s，远低于QAIRT的7,042），表明框架-硬件适配度对结果影响极大，Opt.Gear的优势存在"运行时依赖"。
- **未报告多项关键信息**：没有训练损失曲线、推理时的功耗数据、TTFT的具体数值表、以及2T候选语料的筛选细节（去重、质量过滤的具体规则）。

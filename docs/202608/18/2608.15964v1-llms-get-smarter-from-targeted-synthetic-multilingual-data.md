## 摘要
语言特定能力（LSC）是指语言模型根据提示的语言不同而表现更好或更差的现象。换句话说，当用不同语言提示时，语言模型对相同的语义查询会输出不同（且可能不正确）的响应。先前的工作将此归因于跨语言语义表示的内部错位。目前，文献中主要有两种方法来解决LSC：（1）将所有查询通过英语路由，提高了性能，但限制了语言表达仅限于英语；或（2）在语言平衡数据上训练，使模型在不同语言上的表现均衡，但降低了整体性能。在这项工作中，我们采取以数据为中心的观点，引入了HOTFIXR：用于改进跨语言推理的难度优化训练数据。这是一个数据生成框架，利用模型来探查和学习学生模型的多语言弱点，并生成数据来缓解这些弱点。HOTFIXR可以生成多语言合成训练数据，从而提高多语言性能。我们在三个分布内任务、三个分布外任务和四种分布外语言上进行了评估。平均而言，HOTFIXR（1）将分布内性能提高了6.2%，（2）将微调引起的灾难性遗忘在OOD任务上减少了3.7%，（3）在OOD语言上减少了7.1%。总的来说，由于许多现实世界应用需要多语言LLM，我们的工作有助于使LLM在多语言能力上达到熟练水平。我们将在论文被接受后发布代码。

## Abstract
Language-specific competency (LSC) is the phenomenon of a language model performing better or worse depending on the language of the prompt. In other words, a language model outputs different (and potentially incorrect) responses to the same semantic query when prompted in different languages. Prior work attributes this to an internal misalignment of semantic representation across languages. Currently, there are two main approaches to address LSC in the literature: (1) routing all queries through English, improving performance, but limiting language expressivity to English; or (2) training on language-balanced data, equalizing model performance across languages, but reducing overall performance. In this work, we take a data centric perspective and introduce HOTFIXR: Hardness Optimized Training data For Improving X-Lingual Reasoning. It is a data generation framework that uses models to probe and learn a student model's multilingual weaknesses, and generates data to mitigate them. HOTFIXR can generate multilingual synthetic training data that can improve multilingual performance. We evaluate on three in-distribution tasks, three out-of-distribution tasks, and four out-of-distribution languages. On average, HOTFIXR (1) improves in-distribution performance by 6.2%, (2) reduces catastrophic forgetting (induced by fine-tuning) on OOD tasks by 3.7%, and (3) on OOD languages by 7.1%. Overall, as many real-world applications requires multilingual LLMs, our work contributes to the efforts of making LLMs multilingually proficient. We will release code upon acceptance.

## 1. 核心问题与研究动机

- 论文聚焦于多语言大语言模型（LLM）中的**语言特定能力（LSC）**现象：同一语义查询在不同语言提示下，模型会输出不同甚至错误的答案。
- 已有研究表明，该现象源于不同语言在模型内部语义表示上的**错位（misalignment）**，而英语主导的预训练数据是主要原因——模型往往将非英语输入“锚定”到英语内部表示，从而限制非英语理解能力。
- 现有两类主流解决方案各有局限：
  - **英语路由**：让所有查询都用英语推理，性能较好，但限制语言表达丰富性；
  - **语言平衡预训练**：使模型跨语言表现更一致，但整体性能下降（类似“多语言诅咒”）。
- 作者试图寻找折中路径：能否通过**数据中心的后期训练数据生成**，让模型既提升非英语能力，又不损失通用能力？

## 2. 方法论：HOTFIXR 框架

- **核心思想**：训练一个“问题生成模型”，以学生模型（待优化模型）的反馈信号为奖励，定向生成能暴露学生多语言弱点的合成训练数据，再用于 SFT 微调学生模型。
- **技术流程**：
  1. 用约 500 个种子样本作为上下文，让问题生成模型生成多语言问答/推理样本（英语、法语、西班牙语、阿拉伯语、葡萄牙语、意大利语）。
  2. 将生成样本输入学生模型，计算**语言缺陷分数（Lingual Deficit Score）**作为奖励。
  3. 用 **GRPO（Group Relative Policy Optimization）** 优化问题生成模型，使其倾向于生成能引发高缺陷分数的样本。
  4. 用训练好的生成模型产出 5,000 个训练样本，并用更强模型（Qwen2.5-32B-Instruct）为样本生成标签，最后对学生模型做 SFT。
- **语言缺陷分数由两部分组成**：
  - **语言无关无能（LAI）**：通过“用英语推理”提示，计算学生模型输出 token 的平均不确定度（1 - 最大 token 概率均值），衡量样本本身的难度；
  - **语言特定无能（LSI）**：分别让学生模型用英语和某目标语言推理，取最后一层最后一个推理 token 的隐状态，计算两者余弦距离，衡量跨语言表示错位程度。
  - 总奖励为两者截断后的和：min(1, LAI) + min(1, LSI)。
- **设计直觉**：该方法相当于在数据空间中“爬山”，找到对学生模型最有信息量的样本（最难、且跨语言表示差异最大），从而针对性弥补弱点。

## 3. 实验设计

- **学生模型**：Qwen2.5-7B-Instruct、Qwen2.5-14B-Instruct、Llama-3.1-8B-Instruct；问题生成模型与学生模型为同一模型族的不同实例（自教学）。
- **分布内（ID）任务与数据**：
  - Nemotron 后训练数据集 v2 的三个子集：STEM（多选问答）、MATH（数学推理）、CHAT（指令跟随）；
  - 训练语言：英语、法语、西班牙语、阿拉伯语、葡萄牙语、意大利语（六种，平衡）。
- **分布外（OOD）任务**：
  - 事实知识：MMMLU；
  - RAG 阅读理解：mHotPotQA；
  - 翻译：OPUS-100。
  - OOD 语言：德语、日语（用于事实和翻译）、俄语、中文（用于 RAG）。
- **评价指标**：STEM 与 MMMLU 用准确率；mHotPotQA 用 ROUGE-L（≥80% 算正确）；Nemotron MATH/CHAT 与 OPUS-100 用 LLM-as-a-Judge（Prometheus-7b-V2.0，分数≥4/5 算正确）。
- **对比基线**：
  - Base（不训练）；
  - EngReason（直接提示用英语推理）；
  - SelectionGT（直接用原始数据标签选择训练）；
  - SelectionGEN（用生成标签的数据选择）；
  - Filtered（用语言缺陷分数筛选最高分数据）；
  - Untrained（未优化的生成模型合成数据）；
  - DataEnvGym（现有数据生成 agent 方法，改造为多语言）。

## 4. 资源与算力

- 论文明确提到：HOTFIXR 的 GRPO 优化约为 40 步，使用 **6 块 NVIDIA A100 GPU**，训练数据生成器的成本约为 **0.96 分钟/训练数据样本**，对于 500 个生成器训练样本约需 **8 GPU 小时**。
- 作者强调这是一个**一次性成本**：训练完成后可无限生成数据，且无需人工清洗或 PII 处理。
- 学生模型 SFT 的具体算力未报告，但整体训练规模较小（500 个生成器训练样本、5,000 个学生训练样本）。

## 5. 实验数量与充分性评估

- **实验规模较大且较充分**：
  - 3 个学生模型 × 3 个 ID 子任务 = 9 组 ID 实验；
  - 3 个 OOD 任务 × 3 个模型 = 9 组 OOD 实验；
  - 每个结果平均 3 次运行，并报告了标准差范围（误差线较小）。
  - 额外进行了 OOD 语言（德语、日语、俄语、中文）的逐语言分析。
- **消融实验**：
  - 对语言缺陷分数各部分（格式奖励、LAI、LSI）做了消融，显示单独效果有限、组合效果显著。
  - 增加了知识蒸馏对比实验（用 32B 模型直接生成问题+标签），表明 HOTFIXR 的收益主要来自定向问题生成而非蒸馏。
  - 做了持续学习（两轮 HOTFIXR）实验，显示第二轮仍有显著提升。
- **公平性**：统一了训练数据量（5,000 样本）、标签生成模型、评估指标；多个基线与 HOTFIXR 使用相同的种子数据，比较较为对等。
- **总体评价**：实验设计较系统、覆盖了多模型多任务多语言，且做了必要消融，充分性较高。

## 6. 主要结论与发现

- **ID 性能显著提升**：HOTFIXR 在 Nemotron STEM/MATH/CHAT 上比 Base 平均提升 4.3%，比最优选择类基线提升 6.0%，比最优合成类基线提升 5.8%；综合所有 ID 任务平均提升 **6.2%**。
- **OOD 任务退化最小**：相比 Base 仅平均下降 0.9%，但比所有训练类基线平均高 **5.6%**；比 DataEnvGym 高 7.3%。
- **OOD 语言遗忘更少**：在德语、日语、俄语、中文上平均仅比 Base 下降 **1.4%**，而其他训练方法平均下降 3.1%~12.5%；相当于是灾难性遗忘的显著缓解。
- **跨语言一致性略有改善**：多个分散度指标（Range、Trimmed Range、Std、IQR、CV）显示 HOTFIXR 在数据生成方法中表现最好或并列最好，但差距不大，并非专门的“一致性最优”方法。
- **奖励设计有效性**：LAI 和 LSI 单独使用效果微弱，但组合后能显著提升生成数据质量。

## 7. 方法亮点

- **数据为目标而生成，而非从固定池中挑选**：传统筛选只能从已有数据中选择，HOTFIXR 通过强化学习定向生成“会暴露弱点”的样本，信息量更高。
- **无需人类标注或昂贵清洗**：全流程自动化，只需少量种子数据与一个较强的标签生成模型。
- **奖励函数可解释且任务无关**：LAI 捕捉样本难度，LSI 捕捉跨语言表示错位，且不依赖具体任务，具备通用性。
- **有效缓解多语言遗忘**：在 OOD 任务和语言上的退化远小于其他训练方法，兼顾了适配与泛化。
- **适用性广**：在多个模型族（Qwen 与 Llama）和多种规模上均取得一致收益，并支持持续迭代提升。

## 8. 不足与局限

- **语言覆盖有限**：主要集中于高资源语言（英、法、西、阿、葡、意、德、日、俄、中等），未涉及真正意义的低资源语言；作者也承认低资源语言需要专门考虑。
- **依赖强标签模型**：标签必须由 Qwen2.5-32B-Instruct 生成，使用学生模型自身生成标签会导致指令跟随能力不足；这会限制在无法访问强模型场景下的应用。
- **仅限可验证任务**：实验仅限于有明确正确答案的问答/翻译/推理任务，无法保证对开放式生成、创意任务或安全敏感场景的结论外推。
- **训练成本相对较高**：虽然是一次性成本，但 GRPO 优化 8 GPU 小时对资源有限的研究团队仍有门槛。
- **跨语言一致性改善幅度有限**：虽然 HOTFIXR 略有提升，但并非彻底解决 LSC，语言间标准差仍存在（CV 约 0.11）。
- **潜在奖励黑客问题**：论文发现 GRPO 优化容易陷入局部最优导致生成同质化样本，只能通过限制训练样本数和优化步数来缓解，说明方法在稳定性上仍有调优空间。

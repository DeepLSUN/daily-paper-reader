## 摘要
从经验中学习对于开发能力强、能自我改进的大型语言模型（LLM）智能体至关重要。现有方法通常通过反思、记忆、规则或技能从积累的轨迹中提取知识。然而，现实环境中的智能体不断遇到新任务，通常只有一次性改进的机会。这些执行过程产生丰富但高度嘈杂的上下文，将广泛有用的教训与任务特定细节纠缠在一起。关键的是，先前的工作很少在复杂的现实世界任务上验证其有效性，或隔离改进的潜在驱动因素。为解决这些差距，我们提出了在线工具学习（online harness learning）的框架，其中冻结的智能体通过持续更新跨顺序任务的结构化工具（structured harness）来改进。这一框架使我们能够通过所提出的Evo-Harness系统性地研究关键自我改进因素。其核心是上下文到工具技能编译（context-to-harness skill compilation），将嘈杂的一次性执行过程提炼为可重用的技能工具，用于跨领域和主题级别的适应。为展示一次性技能编译的有效性，我们在五个现实基准（TerminalBench2、SWE-bench、CL-Bench、-bench、WebArena-Infinity）上进行了评估。我们的广泛分析证明了Evo-Harness的有效性，并为LLM智能体如何有效地即时学习提供了原则性理解。我们的代码可在 https://github.com/A-EVO-Lab/a-evolve/tree/release/evo-harness 获取。

## Abstract
Learning from experience is critical for developing capable, self-improving large language model (LLM) agents. Existing methods typically extract knowledge from accumulated trajectories via reflection, memory, rules, or skills. However, agents in realistic environments continuously encounter novel tasks, often offering only a one-shot opportunity to improve. These executions yield rich but highly noisy contexts, entangling broadly useful lessons with task-specific artifacts. Critically, prior works rarely validate their effectiveness on complex real-world tasks or isolate the underlying drivers of improvement. To address these gaps, we formulate online harness learning, where a frozen agent improves by continually updating a structured harness across sequential tasks. This formulation enables a systematic study of key self-improvement factors through our proposed Evo-Harness. At its core, context-to-harness skill compilation distills noisy, single-shot executions into reusable skill harnesses for cross-domain and topic-level adaptation. To demonstrate the efficacy of one-shot skill compilation, we evaluate across five realistic benchmarks (TerminalBench2, SWE-bench, CL-Bench, -bench, WebArena-Infinity). Our extensive analysis demonstrates the effectiveness of Evo-Harness and provides a principled understanding of how LLM agents can effectively learn on the fly. Our code is available at https://github.com/A-EVO-Lab/a-evolve/tree/release/evo-harness.

## 2. 论文提出的方法论

### 2.1 在线工具学习框架

令任务批次流为 {B₁,…,B_K}，每个批次 Bᵢ = {xᵢ,₁,…,xᵢ,mᵢ}。在执行批次 Bᵢ 前，智能体拥有当前工具 Hᵢ（一组结构化可复用指导条目）。对每个任务 xᵢ,ⱼ：

1. **选择（Select）**：从 Hᵢ 中选出最多 b 条紧凑指导 Sᵢ,ⱼ 注入任务上下文；
2. **执行（Execute）**：冻结求解器 A 执行增强后的任务，产生轨迹 τᵢ,ⱼ、结果 yᵢ,ⱼ 和反馈 fᵢ,ⱼ；
3. **更新（Update）**：从执行上下文 cᵢ,ⱼ = (x, τ, y, f) 中提取候选记忆，由演化器（Evolver）编译回工具 Hᵢ₊₁。

### 2.2 上下文到工具技能编译（核心机制）

包含两个互补阶段：

- **执行反思（Execution Reflection）**：仅对**失败或收到负面反馈**的执行生成候选记忆 r = (lesson, trigger, evidence, scope_hint)。聚焦失败可精准暴露求解器当前边界（错误假设、缺失约束、低效工具使用等），避免成功执行中任务特定细节的干扰。
- **工具演化（Harness Evolution）**：演化器将候选记忆与当前工具比较，执行四种操作之一：**ADD（新增）、MERGE（合并）、REVISE（修订）、SKIP（跳过）**——过滤嘈杂记忆、合并兼容信号、修订已有指导、提升可复用教训。

### 2.3 工具层次结构

演化后的工具包含两个层次的指导：

- **跨任务模式（Cross-task Patterns）**：跨任务比较记忆，提炼共享的操作结构；
- **任务类型程序（Task-type Procedures）**：保留针对特定任务格式、界面或领域的局部操作知识。

### 2.4 算法流程

```
输入：任务批次{B₁,…,B_K}、冻结求解器A、初始工具H₁
对每个批次Bᵢ：
  对每个任务xᵢ,ⱼ：
    Sᵢ,ⱼ ← Select(xᵢ,ⱼ, Hᵢ; b)          # 选择指导
    (τ, y, f) ← A(Inject(xᵢ,ⱼ, Sᵢ,ⱼ))  # 求解器执行
    rᵢ,ⱼ ← Reflect(cᵢ,ⱼ)                 # 反思生成候选记忆
  Oᵢ ← CompileTaskType + CompileCrossTask  # 编译两种层次的更新
  Hᵢ₊₁ ← ApplyEdits(Hᵢ, Oᵢ)               # 应用更新
```

**模块化设计**：求解器、演化器、反馈源和初始工具状态解耦，为系统研究在线工具改进的驱动因素提供了受控框架。

## 6. 论文的主要结论与发现

1. **普遍有效性**：Evo-Harness 在全部 5 个基准上均优于 No-Evolve 和所有现有基线，在 TerminalBench-2 上提升最大（62.92%→73.03%，+10.11），表明工具演化在任务暴露可复用过程结构时最有效。

2. **外部经验复用并非自动有益**：多个基线方法在某些基准上低于 No-Evolve，说明检索或演化的指导可能嘈杂、过度特定或与求解器不匹配。

3. **强模型获益更多**：Claude Opus 4.5/4.6/4.7 分别获得 +3.8、+4.5、+3.7 的提升，而 Kimi-K2.5 和 GPT-OSS 仅提升 +1.1 和 +0.8——更强求解器更擅长解释、遵循和受益于演化指导。

4. **程序性任务提升最稳定**：CL-Bench 的 Procedural Task Execution（PTE）类别上所有模型均提升，Opus 4.6/4.5 各 +9.8；而探索性任务（EDS）提升不稳定，可能对过度特定的指导敏感。

5. **两种工具层次各有侧重**：CL-Bench 上局部任务类型指导更重要（Topic Only 33.70 vs General Only 30.28）；SWE-bench Lite 上广泛跨任务指导更重要（General Only 66.67 vs Topic Only 64.33）。

6. **在线更新优于离线迁移**：Train-Split Transfer 达到 73.4（超过 No-Evolve 68.8），Online-Updated 进一步达到 75.0——小模型演化的技能可迁移给强求解器，但就地更新能更好地适应当地分布。

7. **同一模型求解+演化并非最优**：Opus 求解器下 Cross 演化达到 76.0，略高于 Same 的 75.3；但对较弱的 Sonnet 求解器，两种演化配置均低于 No-Evolve——工具迁移效果高度依赖基础求解器的能力。

8. **有根据的反馈至关重要**：Self-Generated 反馈在 CL-Bench 上从 29.54 降至 27.96、SWE-bench Lite 从 63.67 降至 61.67——无外部依据的自我判断会产生误导性更新。但反馈粒度因任务而异：CL-Bench 需要丰富诊断（Standard 34.02 vs Minimal 29.86），SWE-bench Lite 上 Minimal 反而略优（67.33 vs 67.00），因为详细错误信息可能使工具过度绑定到任务特定失败。

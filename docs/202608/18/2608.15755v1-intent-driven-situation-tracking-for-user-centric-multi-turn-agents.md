## 摘要
用户中心多轮代理必须处理由不断变化的用户意图、累积的工具基础事实、缺失信息和执行约束所塑造的动态任务情境。现有的上下文管理方法改进对历史交互的使用，但很少维护一个将基础事实与任务状态判断分离的显式情境状态。因此，代理常常需要从对话轨迹中隐式推断细粒度属性、任务依赖关系和约束满足情况。我们提出意图驱动情境状态（IDSS），一种无需训练的框架，在与对话并行的同时维护显式情境状态。IDSS将工具返回解析为具有溯源意识的实体和属性，跟踪用户意图、所需变量、约束和执行状态，并将新事实传播到任务约束以更新动作可执行性。这使代理能够避免不可行动作、推进依赖目标，并在不重复搜索原始历史的情况下重用相关信息。在跨越八个LLM的三个交互基准上的实验表明，IDSS提升了任务完成度、偏好获取和交互效率，在多实体协调、动态用户约束和约束感知重规划任务上具有明显优势。消融和错误分析表明，这些改进来自事实持久化、以意图为中心的状态跟踪和约束建模之间的相互作用。这些结果表明，显式情境跟踪为可靠的用户中心多轮代理提供了一种有效替代历史中心上下文管理的方法。

## Abstract
User-centric multi-turn agents must act on an evolving task situation shaped by changing user intents, accumulated tool-grounded facts, missing information, and execution constraints. Existing context-management methods improve the use of past interaction history, but rarely maintain an explicit situation state that separates grounded facts from task-state judgments. As a result, agents often need to infer fine-grained attributes, task dependencies, and constraint satisfaction implicitly from dialogue traces. We propose Intent-Driven Situation States (IDSS), a training-free framework that maintains an explicit situation state alongside the dialogue. IDSS parses tool returns into provenance-aware entities and attributes, tracks user intents, required variables, constraints, and execution status, and propagates new facts to task constraints to update action executability. This allows agents to avoid infeasible actions, advance dependent goals, and reuse relevant information without repeatedly searching raw history. Experiments on three interactive benchmarks across eight LLMs show that IDSS improves task completion, preference elicitation, and interaction efficiency, with clear gains on tasks involving multi-entity coordination, evolving user constraints, and constraint-aware replanning. Ablations and error analyses show that these improvements come from the interaction between fact persistence, intent-centered state tracking, and constraint modeling. These results suggest that explicit situation tracking offers an effective alternative to history-centric context management for reliable user-centric multi-turn agents.

### 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：LLM 代理越来越多地用于客户服务、旅行规划、生活服务等面向用户的场景。在这些场景中，代理不再是执行孤立指令，而是参与持续的多轮交互，需要在交互中理解不断演化的用户目标、调用外部工具、遵循规则，并自行决定何时提问、检索、执行或结束任务。
- **核心挑战**：用户交互具有动态演化性——同一对话中可能引入多个目标，目标间可能相互依赖或冲突；用户偏好往往逐步释放而非一次性给出；工具返回可能修正先前假设的事实；新观察到的事实可能使先前的行动路径变得不可行。因此代理**必须持续追踪当前任务态势**：哪些事实已被证实、哪些意图正在活跃或已完成、哪些变量仍然缺失、哪些约束被满足或违背。
- **现有方法不足**：已有方法（如外部记忆系统 MemGPT、Mem0，上下文压缩 ReSum、AgentFold、U-Fold 等）虽改善了长交互中的信息可访问性和上下文长度压力，但代理仍需从检索的记忆、摘要或压缩轨迹中隐性推断当前任务态势，**很少将"工具基础事实"与"任务状态判断"（活跃意图、缺失变量、约束条件）显式分离维护**，导致事实遗漏、意图漂移、过早执行和约束违背等问题。
- **本文立场**：可靠的用户中心多轮代理应受益于维护一个显式的、面向决策的情境状态，而非仅仅依赖对过去交互历史的访问。

### 2. 方法论：核心思想、关键技术细节与算法流程

#### 2.1 总体框架

提出 **IDSS（Intent-Driven Situation States，意图驱动情境状态）**，一种**训练无关（training-free）**框架，在与对话历史平行的位置维护显式情境状态 \( D_t = (F_t, S_t) \)，其中：
- \( F_t \)：**事实层**——工具返回的实体与属性；
- \( S_t \)：**状态层**——用户意图、变量需求、约束条件与执行状态。

原策略 \( a_t = \pi(H_t, A) \) 被替换为情境增强策略：
\[
a_t = \pi(D_t, H_t^{comp}, A)
\]
其中 \( H_t^{comp} \) 为状态覆盖信息被移除或替换为事实引用后的**紧凑残差历史**，保留近期用户-代理轮次并将工具输出替换为事实层引用。

#### 2.2 事实层（Fact Layer）

- **实体组织**：工具返回被组织成结构化实体库 \( F_t = \{ e_i = (type_i, id_i, attrs_i, src_i) \} \)，每个实体包含类型、标识符、属性集和溯源来源，支持跨实体、跨轮次查询。
- **确定性提取与更新**：由**确定性解析器**将工具返回转换为原子操作序列 \( \Delta_t = Parse(o_t) \)，通过 \( F_t = F_{t-1} \oplus \Delta_t \) 增量更新，支持 ADD、UPDATE（属性级合并）、DELETE（标记无效实体）、MERGE（去除重复）。
- **冲突解决**：按**来源可信度**处理属性冲突——工具观察值优先于代理推断值；同源类型中较新观察更新旧值；用户偏好和约束放状态层维护，防止幻觉或过期信息污染事实库。

#### 2.3 状态层（State Layer）

状态层围绕三个组件组织：
- **意图集 \( I_t \)**：识别用户显式/隐式目标，分配状态 **active / pending / completed / blocked**；从任务语义和执行前提推断意图依赖；依赖完成后意图变 active，执行后变 completed，约束违反后变 blocked。
- **变量集 \( V_t \)**：记录当前/待执行意图所需信息槽，标注来源类型 **askable（向用户询问）/ retrievable（调用工具） / derivable（从已有事实推断）**，并标注 known/unknown 状态。
- **约束集 \( C_t \)**：记录动作必须满足的条件，含简短规则描述和可用的已落地参数（实体属性、操作符、目标值），状态标记为 **satisfied / unsatisfied / violated**。约束违反时，关联意图被标记为 blocked。

代理被要求在每个响应的 `<state>` 标签中输出意图状态、已确认结论和缺失信息，该块在交付用户前移除，并注入下一轮提示中。

#### 2.4 跨层约束传播

- 每当事实层更新实体属性时，系统通过**确定性属性比较**重新评估约束集中已落地的约束。
- 未获得充分依据的约束保持 unsatisfied，而非被错误判为 violated。
- 约束被违反时，**阻止关联意图并记录事实依据和约束链**，使代理理解路径不可行的原因并推导替代方案。
- 示例：航空任务中，工具观察到的 basic_economy 舱位事实违反改签约束 → 阻止 modify_flight 意图 → 激活 cancel-and-rebook 替代意图，同时保留用户行李需求。

### 6. 主要结论与发现

- **IDSS 在三个基准上普遍优于所有基线**，且在雷达图中展现出最均衡的性能覆盖面，而非仅提升单一方面。
- **τ-bench 结果**：在 Airline 领域（改签、取消、行李、舱位限制等跨轮依赖强场景），IDSS 较最强基线 U-Fold 平均提升 Avg@4 达 1.5 分、pass@4 达 2.0 分；Retail 领域提升较小但为正（Avg@4 +0.6，pass@4 +1.8）。
- **VitaBench 结果**：在 OTA 和 Cross-domain 上优势最明显，较 U-Fold 提升 1.7 和 2.1 分；在简单的 Delivery/In-store 任务上竞争持平。
- **UserBench 结果**：IDSS 在所有 LLM 上取得最佳 Score 和 CER，相对 U-Fold 提升约 4.6%（Score）和 4.0%（CER）；偏好获取（PE）提升较小且随骨干模型波动。
- **消融结论**：移除事实层损害 τ-bench 最大（Avg@4 降 2.2、pass@4 降 3.5）；移除状态层对 UserBench 影响最大（Score 降 8.4%）；VitaBench 上两个层贡献相近；约束建模带来较小但一致增益。
- **错误分析结论**：IDSS 将事实遗漏从 14% 降至 8%、缺失信息从 8% 降至 5%；ReSum 事实遗漏率最高（22%），说明摘要易丢弃细粒度关键字段。
- **效率结论**：IDSS 以最高的平均性能（50.5%）和最少的交互轮次（7.8）完成任务，且不增加额外 LLM 调用。

### 7. 优点

- **训练无关**：无需微调或额外训练即可直接应用于任意 LLM，跨模型泛化性强，计算开销小。
- **显式状态分离设计**：将工具基础事实与任务状态判断分置两层，并通过跨层约束传播连接，使代理拥有"决策导向"的当前态势视图而非历史线索检索，概念清晰、结构合理。
- **可解释性好**：blocked 意图附有事实依据和约束链；案例分析展示可追踪的决策过程。
- **零额外 LLM 调用**：事实层由确定性解析器更新，状态层在响应生成时同步维护，不增加推理成本，训练无关且工程实现友好。
- **效果验证扎实**：多基准 × 多模型 × 多基线的大规模评估，配以消融、错误分析和效率分析，证据链条完整。
- **错误分析细致**：量化了 IDSS 在降低事实遗漏和缺失信息方面的具体改进，且识别出约束违背主要来源于模型规则理解而非状态缺失，分析客观。

### 8. 不足与局限

- **应用范围**：IDSS 依赖工具返回中可转换为结构化文本字段的信息；对非文本、富工具环境或多模态观察的适用性未验证。
- **评估环境**：全部实验使用模拟用户，未在真实用户部署下验证自然表达的目标、纠正和偏好；虽保证可复现性和受控对比，但可能低估真实交互复杂度。
- **基准领域有限**：实验覆盖零售、航空、旅行、外卖等生活服务领域，未验证金融、医疗、法律等高风险或更复杂领域。
- **与训练方法的对比缺失**：未与用户中心代理的训练方法（如 UserRL、Suri 等的 POMDP 方法）直接对比，尽管后者依赖监督信号，但跨方法对比信息不完整。
- **约束建模能力界限**：错误分析显示约束违背率仅从 5%–8% 范围小幅变化，IDSS 无法解决模型对规则本身的错误理解；约束传播依赖属性比较的确定性和完整事实支撑，对部分不完整事实可能保守（保持 unsatisfied）。
- **隐私与安全风险**：作者指出 IDSS 不会消除错误工具输出、模型幻觉或高风险部署中的风险，需要任务特定防护和人工监督；论文自身未涉及人类数据收集。

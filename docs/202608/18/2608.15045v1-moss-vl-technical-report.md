## 摘要
我们提出了 MOSS-VL，一个开放式的视觉语言模型系列，将实时交互——在说话的同时感知——视为一等能力。它在整个栈上进行协同设计：语言解码器仅通过门控交叉注意力处理视觉信息，因此模型在生成时能够自然地看到传入的帧；一个合成的交互语料库监督模型何时说话、何时保持沉默以及何时修订；一个分阶段的课程将所有实时特定的训练集中在一个轻量级的最终阶段，建立在一个强大的离线基础之上。在离线状态下，MOSS-VL-Instruct 在可比规模上具有竞争力，并在时间推理视频集上领先。在四个流式基准测试中，MOSS-VL-Realtime 在三个基准上取得了开放源代码流式模型中的最佳平均值（在第四个上排名第二），横扫了直接测试主动行为的三个子集——在 OmniMMI 主动警报上，最佳基线为 37.5，而我们的得分为 66.0。尽管拥有 113 亿参数，但视觉标记位于解码序列之外，随着视觉上下文的增长，MOSS-VL 将相对于同主干 Qwen3-VL-8B 的首标记时间优势从 2.8 倍扩大到 5.1 倍。我们在 https://github.com/OpenMOSS/MOSS-VL 发布了所有五个检查点、训练课程和实时推理代码。

## Abstract
We present MOSS-VL, an open vision-language model family that treats real-time interaction -- perceiving while it speaks -- as a first-class capability. It is co-designed across the stack: the language decoder attends to vision only through gated cross-attention, so the model can naturally see incoming frames while generating; a synthesized interaction corpus supervises when to speak, when to stay silent, and when to revise; and a staged curriculum concentrates all real-time-specific training in one light final stage over a strong offline foundation. Offline, MOSS-VL-Instruct is competitive at comparable scale and leads temporal-reasoning video sets. Across four streaming benchmarks, MOSS-VL-Realtime posts the best average on three (second on the fourth) among open-source streaming models, sweeping the three subsets that squarely test proactive behavior -- 66.0 vs. 37.5 for the best baseline on OmniMMI Proactive Alerting. With 11.3B parameters but visual tokens outside the decoded sequence, MOSS-VL widens its time-to-first-token advantage over same-backbone Qwen3-VL-8B from 2.8x to 5.1x as visual context grows. We release all five checkpoints, the training curriculum, and the real-time inference code at https://github.com/OpenMOSS/MOSS-VL.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有开放视觉语言模型（VLM）大多采用“离线”工作范式——先完整看完一段视频，再回答关于视频的问题。但在真实场景中，视频是持续到达的，模型需要**边看边说**：在生成回复的同时继续感知新帧，并在证据变化时及时修订或中断自己的回答。这种“实时交互（real-time interaction）”能力被论文定义为 L5 级能力，而现有流式模型（L2–L4 级）在回复期间仍是“盲”的。
- **研究背景**：论文将视频理解能力分为五个层级（L1 离线、L2–L4 流式、L5 实时），指出 L5 的关键分界线是“是否在生成的同时持续感知”。作者认为，真正的实时交互需要通过架构、数据、训练策略的**协同设计（co-design）**来实现，而非依赖单一组件。
- **论文贡献**：提出 MOSS-VL，一个将实时交互作为一等公民的开放 VLM 家族，并配套开源了全部检查点、训练课程和推理代码。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

**总体架构：门控交叉注意力 + 双流设计**

- 视觉编码器（27 层 ViT，初始化为 Qwen3-VL 的视觉编码器）以原生动态分辨率处理图像/视频帧，经 2×2 空间池化和 MLP 投影成视觉 token。
- 语言解码器（48 层，初始化为 Qwen3-8B）包含 36 层自注意力层和 12 层**门控交叉注意力层**（每 4 层插入一层，索引 2,6,…,46）。
- **视觉 token 永远不进入解码序列**：每帧只在文本流中加入几个时间戳 token 和一个占位 token，其 patch token 作为交叉注意力的 key/value 被消费。因此解码状态不受新帧影响，生成时可自然“看到”新帧。

**关键技术细节**

- **门控交叉注意力（Gated Cross-Attention）**：参考 Flamingo 的门控设计，使用 tanh 门控（零初始化），注意力路径和 FFN 路径均带门控，确保训练初期语言主干完整可用。注意力采用 GQA（32 query / 8 KV head）和 QK-RMSNorm。
- **XRoPE（交叉注意力旋转位置编码）**：为视觉–语言交叉注意力通道引入的三轴坐标（时间 t、高 h、宽 w）。文本 token 坐标沿三轴对齐（x,x,x）；视频帧锚定在时间 t，其 patch 坐标铺为 (t, t+a, t+b)；视觉侧帧结束分隔符和文本侧占位 token 取相同坐标，使两通道共享时间线。旋转频率 64 对按（24,20,20）拆分，应用于文本侧 query 和视觉侧 key。
- **绝对时间戳**：每个视频帧前加入 `<|time_start|>X.X seconds<|time_end|>`，让模型直接读取墙钟时间，避免依赖相对位置推断时间，适应 1–16 fps 的可变采样率。
- **实时性由构造保证**：新帧到达时仅编码该帧，其 KV 追加到交叉注意力缓存，旧帧不重编码、不重算，解码状态不变。

**训练课程（四阶段预训练 + 两阶段后训练）**

| 阶段 | Token 数 | 样本数 | 最大序列长度 | 可训练模块 | 峰值 LR |
|---|---|---|---|---|---|
| 1 视觉–语言对齐 | 150.3B | 219.4M | 8K | 投影 + 交叉注意力 | 2×10⁻⁴ |
| 2 大规模多模态预训练 | 203.0B | 139.3M | 64K | 全模型 | 5×10⁻⁵ |
| 3 高质量多模态预训练 | 459.0B | 14.7M | 128K | 全模型 | 1×10⁻⁵ |
| 4 退火与长上下文 | 450.1B | 9.3M | 256K | 全模型 | 1×10⁻⁵ |
| SFT | 102.8B | 7.6M | 128K | 全模型 | 1×10⁻⁵ |
| Realtime-SFT | 34.8B | 0.56M | 256K | 全模型 | 4×10⁻⁵ |

- 预训练数据大量使用合成数据（字幕、OCR、接地、时间接地等），并全程对评估集去污染。
- SFT 生成离线版 MOSS-VL-Instruct；再通过 Realtime-SFT 生成 MOSS-VL-Realtime，仅占蒸馏总 token 的 3%。

**Realtime-SFT：学习何时说话**

- 训练样本按到达顺序交错文本与帧，每帧后跟一个决策槽，槽形式为：`<|silence|>`（保持沉默）、`<|response|>` + 文本（开始/继续说话）、以 `<|silence|>` 结尾的回复段（结束说话）。
- 每个回复跨多个连续槽逐帧展开，模拟限速实时输出；一个用户回合内可包含多个独立回复。
- 整个系统只新增两个词表条目（`<|silence|>` 和 `<|response|>`），初始化为语义相近现有 token 的嵌入；说话–等待决策就是普通 next-token 预测，无专门决策头。
- 语料构造升级自 MOSS-Video-Preview 的标题驱动流水线，包含逐帧时间锚定验证、自然语言自我纠正、质量门控。
- 语料统计：共监督 220 万个发射决策，其中 58.7% 是自定时的；5.1% 样本中目标事件从未发生，正确行为是全程沉默。

**训练目标（重加权损失）**

公式为：

\[
\mathcal{L} = \frac{\sum_i m_i w_i \ell_i}{\sum_i m_i}, \quad
w_i = \begin{cases}
\alpha_{y_i}(1-p_i)^{\gamma} & y_i \text{ is a state token}\\
1 & \text{otherwise}
\end{cases}
\]

- \(\ell_i\)：token 级交叉熵；\(m_i\)：监督掩码；\(p_i\)：目标 token 预测概率；\(\gamma = 2\)。
- 系数 \(\alpha_k = (n_s + n_r)/(2n_k)\)，\(n_s\)、\(n_r\) 为当前全局 batch 中沉默和回复目标数，实现在线均衡两类状态 token 的名义权重。
- **关键掩码选择**：从监督中排除助手回合结束的 end token，避免模型在新用户回合出现时错误地封装回复。消融显示该掩码将发射频率提高 39%、平均回复长度提高 68%。

**模式控制**：所有模式共享一套权重，仅通过系统提示词控制。流式/实时共用同一提示词，离线模式下无系统提示词。

## 6. 论文的主要结论与发现

- 离线表现：MOSS-VL-Instruct 在可比规模下竞争力强，尤其在时间推理视频集（Minerva 40.5、TOMATO 39.5、VideoMME-Logical 17.1）上领先；多模态感知方面五科第一（MMBench-EN 88.1、POPE 89.4、V* 89.0、MME-RealWorld 66.3、BLINK 78.0）；接地鲁棒性（Ref-Adv 57.0）和文档解析（OmniDocBench 88.9）也有优势。
- 流式表现：MOSS-VL-Realtime 在四个基准中取得三个最佳平均分（OVO-Bench 70.2、OmniMMI 32.7、ProactiveVideoQA 47.2），在 StreamingBench 视觉平均上位列第二（69.7 vs AURA 71.1）。在主动行为子集上全面获胜：OmniMMI Proactive Alerting 66.0 vs 37.5、StreamingBench Proactive Output 60.0 vs 53.2、OVO-Bench FAR 62.1 vs 55.8。
- 效率：与同主干 Qwen3-VL-8B 相比，TTFT 优势随视觉上下文增长从 2.8× 扩大到 5.1×，端到端延迟从 1.9× 扩大到 4.3×；即使 MOSS-VL 因无时间压缩而携带约 2 倍视觉 token，仍不落下风。
- 训练策略有效性：Realtime-SFT 作为轻量最终阶段即可安装实时交互范式，且仅需不到 3% 的总训练 token。
- 结论：实时交互可通过架构、数据、训练的协同设计实现，MOSS-VL 开源了全套权重、课程和代码。

## 7. 优点

- **架构设计优雅**：门控交叉注意力 + XRoPE + 绝对时间戳，从构造上保证“边生成边感知”，视觉 token 不进入解码序列，使延迟增长比 interleaved 方案更平缓。
- **训练策略清晰**：四阶段预训练打底，所有实时特性集中在单一轻量最终阶段（Realtime-SFT），并采用零初始化的门控保护语言主干，避免灾难性遗忘。
- **数据驱动行为**：合成交互语料直接监督“何时说话、何时沉默、何时修订”，针对现有数据集稀缺的主动行为（沉默等待、回复修订、中途打断）进行了专门合成。
- **工程贡献完整**：开源五档检查点、完整训练课程、实时推理代码、FlashAttention-3 扩展和 SGLang 集成，可复现性强。
- **实验设计有亮点**：效率对比采用同一语言主干隔离变量；流式评估遵循各基准官方协议；包含对“不应结束回合”掩码的单变量消融。
- **结果显著**：在主动预警子集上以 66.0 vs 37.5 大幅超越最佳基线，同时保持离线能力不落后。

## 8. 不足与局限

- **L5 缺乏定量验证**：论文承认目前没有公开基准能衡量“生成期间保持感知并修订/中断回复”，因此最高层级行为仅靠定性 demo 和代码演示，量化评估止于 L2–L4。
- **消融不足**：Realtime-SFT 仅报告了 end-token 掩码一项消融，未对损失重权重的超参数、合成数据比例、XRoPE 必要性等做系统分析。
- **离线能力存在短板**：在 MMMU（51.1 vs 69.6）、DocVQA（89.6 vs 96.1）、RefCOCO-REC（84.4 vs 91.6）等推理/文档/标准接地任务上明显落后于最强基线，分析归因于不采用思考模式和面向实时视频而非考试式推理的优化。
- **基准公平性风险**：部分基线数字取自官方报告，视频采样帧数等设置可能不同；StreamingBench 因无音频输入而无法评估 Omni-Source 组，未报告官方总体分数。
- **规模限制**：11.3B 参数规模仅与同量级模型对比，未与更大模型（如 70B+）比较；实时交互能力在小模型上表现可能受限。
- **资源披露不完整**：未报告训练耗时、GPU 规模、能源成本等，不利于成本估算。
- **领域覆盖偏窄**：流式评估聚焦视频理解，未涉及音频、多模态实时对话、机器人控制等更广的实时交互场景。

## 摘要
大型语言模型（LLM）在API调用中的可靠性在多语言环境下会下降。一种常见的失败模式是模型选择了正确的工具，但生成的参数值使用了不一致的语言，我们称之为参数语言不匹配（ALM）。尽管语义上正确，此类输出在操作上无效，且标准API调用指标无法捕捉。我们重新审视了缓解ALM的后训练策略，发现在我们的基准测试中，监督微调（SFT）提供了强基线，显著提高了参数语言一致性及端到端函数调用准确率。在模型选择一致的情况下，SFT的性能可与更复杂的强化学习（RL）方法相媲美，有时甚至超过后者。我们进一步考察了带有结构化、参数感知奖励的RL是否能带来额外收益。虽然诸如组相对策略优化（GRPO）等方法能够改善语言一致性并更好地保留通用推理能力，但这些增益是渐进的，且在泛化与多目标权衡中最为显著。总体而言，我们的结果表明，多语言API接地的大部分性能可通过仔细的监督训练实现，而RL则提供有针对性的而非根本性的改进。

## Abstract
The reliability of Large Language Models (LLMs) for API calling degrades in multilingual settings. A common failure occurs when a model selects the correct tool but generates argument values in an inconsistent language, which we term Argument Language Mismatch (ALM). Although semantically correct, such outputs are operationally invalid and not captured by standard API-calling metrics. We revisit post-training strategies for mitigating ALM and find that, in our benchmark, supervised fine-tuning (SFT) provides a strong baseline, substantially improving argument language consistency and end-to-end function call accuracy. Under consistent model selection, SFT achieves performance comparable to, and sometimes exceeding more complex reinforcement learning (RL) approaches. We further examine whether RL with structured, argument-aware rewards offers additional benefits. While methods such as Group Relative Policy Optimization (GRPO) can improve language consistency and better preserve general reasoning ability, these gains are incremental and most pronounced in generalization and multi-objective trade-offs. Overall, our results suggest that much of the performance in multilingual API grounding can be achieved through careful supervised training, with RL providing targeted rather than fundamental improvements.

## 一、核心问题与整体含义（研究动机与背景）

- **核心问题**：大型语言模型（LLM）在多语言API调用场景中会出现一种特殊失败——"参数语言不匹配"（Argument Language Mismatch, ALM）。即模型能够正确选择工具（API），但生成的参数值使用了与用户输入不一致的语言（例如用户在说西班牙语，但参数值生成成了英语或两种语言混用）。
- **问题严重性**：尽管这类输出在语义上正确，但在实际系统中因语言约束不满足而操作无效，导致任务完全失败。
- **被忽视的根因**：现有标准API调用指标（如AST匹配、字符串匹配）无法捕捉这一失败模式，易将ALM与其他错误混为一谈，掩盖问题的真实规模。
- **研究意义**：这一问题的研究关系到多语言Agent系统能否在真实业务环境中可靠落地，也涉及对后训练策略的比较：是否必须引入复杂的强化学习目标，还是精心设计的监督微调就足够。

## 二、方法论：核心思想、关键技术细节与算法流程

### 2.1 问题形式化
- 将多语言API调用建模为结构化预测问题：给定用户话语 `u`（语言 `ℓ`）和可用API集合 `A`，模型生成包含工具名与参数值的调用序列 `Y = {(f₁, a₁), (f₂, a₂), ..., (fₘ, aₘ)}`。
- 定义了**ALM形式化条件**：当 `lang(vᵢ,ₖ) ≠ lang(u)` 时即发生ALM，即参数值语言应为用户输入语言，除非API规范明确要求其他语言。

### 2.2 分层评估指标体系
论文设计了层级化评估指标体系，每一层基于上一层成功与否进行条件评估：
1. **TID（工具调用检测）**：是否正确判断需要调用API
2. **TSA（工具选择准确率）**：是否选择了正确的API
3. **ACA（参数完整性）**：是否生成了所有必需参数
4. **ALC（参数语言一致性）**：所有文本参数值的语言是否与用户输入一致
5. **FCM（函数调用匹配）**：整个调用是否与标注完全匹配

指标层级关系为：`FCM ≤ ALC ≤ ACA ≤ TSA ≤ TID`。

### 2.3 训练方法

**监督微调（SFT）**：最大化给定输入下目标输出的对数似然，使模型模仿训练数据中语言一致的API调用。

**强化学习方法**：
- **PPO**：基于单样本采样的策略梯度方法，使用裁剪目标与KL正则化
- **GRPO**：对同一提示词采样K个候选响应，在组内对奖励做归一化来计算优势值：
  `Â⁽ʲ⁾ = (R⁽ʲ⁾ − μ_R) / (σ_R + δ)`

### 2.4 奖励函数设计（由粗到细三个层级）

| 奖励模型 | 设计思路 | 特点 |
|---------|---------|------|
| RM-1（稀疏二元奖励） | 只区分完全正确（+2）、纯语言错误（0）、其他错误（-1） | 信号极稀疏，无法区分部分正确 |
| RM-2（层次化阶梯奖励） | 按TID→TSA→ACA→ALC→FCM层级赋分（-1.0 至 +2.0），引入连续ALC分数（LLM打分） | 密度更高，但参数间无区分 |
| RM-3（参数分解奖励） | 将奖励分解到每个参数值上：对每个参数值由LLM评分（2.5/2.0/1.0），结构正确后以 `ALC_cont(Y) = (1/K)ΣS(vᵢ,ₖ)` 作为奖励 | 最细粒度，逐参数信用分配 |

### 2.5 其他训练细节
- **Token级奖励加权**：对属于参数值的token乘以权重 `β`（实验取1.5或3），强化关键token的梯度信号
- **SFT热启动**：先做1个epoch的SFT，为RL提供高质量的初始采样分布
- **基线对比**：训练分为"epoch固定"与"验证集选择最优checkpoint"两种协议

## 六、主要结论与发现

1. **SFT是强基线**：SFT大幅改善ALC和FCM，能解决大部分ALM错误；在最佳checkpoint比较下，SFT在Split-1上的FCM（67.4）超过GRPO（55.3）和SFT+GRPO（61.3），甚至实现反超。
2. **RL增益是增量的而非根本性的**：GRPO等RL方法在泛化（Split-2）和跨语言迁移上更稳定，额外收益主要体现在泛化能力和多目标平衡方面，但整体提升有限。
3. **奖励粒度是关键**：RM-3（参数分解奖励）显著优于RM-1（稀疏）和RM-2（层级步进），证明细粒度信用分配对ALM优化至关重要。
4. **GRPO优于PPO**：GRPO的组内归一化在处理结构化、局部化奖励时比PPO的批级归一化更稳定有效。
5. **Token加权提升GRPO但破坏PPO**：增加参数token的奖励权重能改善GRPO的ALC，却导致PPO训练不稳定、性能骤降。
6. **RL更好地保持通用推理能力**：SFT在获得高FCM的同时导致英语推理分数显著下降（MGSM EN从70.8降至62.2），而GRPO几乎不损害推理能力。
7. **跨语言传递**：GRPO学习的是"参数语言随用户语言"的抽象规则，比SFT更稳定地跨语言迁移（尤其在荷兰语上SFT出现负迁移而GRPO保持正向）。
8. **ALM贡献率**：在GRPO训练后，ALM成为残余失败中的主要因素（占47-50%），说明结构错误基本解决后，语言实现成为最后瓶颈。

## 七、优点

- **问题定义清晰且有现实价值**：ALM作为一类独立失败被正式定义和量化，提供了专门的分层评估指标，填补了标准API指标忽略语言约束的空白。

## 八、不足与局限

- **基准构建的翻译产物属性**：数据集是翻译而非天然多语言数据，翻译协议虽精心设计但可能引入语言学上的不自然性、文化适配不足或翻译偏差，降低结论在真实多语言场景的可迁移性。
- **单一基准依赖**：结论主要基于BFC的翻译版本，未用其他多语言工具使用数据集进行验证，结论的普适性存疑。
- **模型覆盖有限**：仅使用Qwen2.5系列，未验证方法在其他模型架构（如Llama 3、Mistral、Gemini等）上的一致性。
- **计算资源透明度低**：未报告训练时长、GPU数量、实际FLOPs等资源消耗，影响可复现性和成本评估。
- **统计显著性缺失**：未报告多次运行的标准差、置信区间或显著性检验，单次种子下的小差距（如表4中SFT 79.1 vs SFT+GRPO 79.3的ALC差异）可能不具统计意义。
- **评估依赖LLM裁判**：ALC评分依赖LLM作为judge（2.0/1.5/1.0或2.5/2.0/1.0的打分），裁判本身的语言判断误差未做校准或人验验证。
- **聚焦任务范围较窄**：研究限定在"参数值语言与用户输入一致"这一具体规则上，对需要更深推理、长周期信用分配或非直接映射能力的多语言工具使用任务，RL的价值可能被低估。
- **只训练了西班牙语**：跨语言结论仅从ES→IT/NL/FR一个方向推出，未覆盖更远距离语言对（如日语、阿拉伯语与英语之间的语言系统差异），跨语言泛化结论的代表性有限。

## 摘要
终端智能体的强化学习（RL）需要具有可靠奖励和有用难度的可执行训练环境。固定配方如少样本、Self-Instruct 和 Evol-Instruct 对每个种子应用相同的提示策略，即使当前策略可能受益于更难、更简单或仅仅不同的任务。我们提出 Envs-FORGE，一种将验证器奖励转换为逐种子环境合成动作的提示策略。Envs-FORGE 估计种子通过率，围绕目标学习前沿对六个投影方向动作进行评分，并求解逐种子混合整数线性规划（MILP）以选择条件生成的动作。所选动作驱动指令、固定装置、预言机解决方案、测试和 Docker 环境的同步重写；只有经过金标准验证的包才能进入 RL 训练。索引 MILP 形式还支持用于组合规划的可选软技能覆盖。在 Qwen 3.5 35B 上，Envs-FORGE 在 tb-core 上将 Pass@1 比 Base 提高了 9.2 个百分点（40.0% 至 49.2%），在 tb-2.0 上提高了 6.4 个百分点（23.0% 至 29.4%），超过最强的固定配方基线 2.4 和 2.1 个百分点。在 SWE-bench Verified 上达到 77.1%，而 Base 为 73.4%，并在评估的 4B–35B 模型上将 tb-core 提高了 6.8–9.2 个百分点。所有合成方法导出 100 个经过验证的环境，并使用 2.27M–2.88M 合成令牌，将比较置于相同的下游训练集大小和相同的操作规模下。源代码可在 https://github.com/DataArcTech/DataArc-SynData-Toolkit/ 获取。

## Abstract
Reinforcement learning (RL) for terminal agents needs executable training environments with reliable rewards and useful difficulty. Fixed recipes such as few-shot, Self-Instruct, and Evol-Instruct apply the same prompting policy to every seed, even when the current policy would benefit from a harder, easier, or simply different task. We present Envs-FORGE, a prompting policy that converts verifier rewards into per-seed environment-synthesis actions. Envs-FORGE estimates seed pass rates, scores six projection--direction actions around a target learning frontier, and solves a per-seed mixed-integer linear program (MILP) to choose the action that conditions generation. The selected action drives synchronized rewriting of the instruction, fixtures, oracle solution, tests, and Docker environment; only gold-verified bundles enter RL training. The indexed MILP form also supports optional soft skill coverage for portfolio planning. On Qwen 3.5 35B, Envs-FORGE improves Pass@1 over Base by 9.2 percentage points on tb-core (40.0% to 49.2%) and 6.4 points on tb-2.0 (23.0% to 29.4%), exceeding the strongest fixed-recipe baseline by 2.4 and 2.1 points. It reaches 77.1% on SWE-bench Verified versus 73.4% for Base, and improves tb-core by 6.8--9.2 points across the evaluated 4B--35B models. All synthesis methods export 100 verified environments and use 2.27M--2.88M synthesis tokens, placing the comparison at the same downstream training-set size and the same operational scale. The source code is available at https://github.com/DataArcTech/DataArc-SynData-Toolkit/.

### 一、核心问题与研究动机

- **背景**：终端智能体（terminal agent）正成为软件工程、系统管理、命令行数据处理等领域的实用接口（如 SWE-agent、OpenHands）。这类智能体的强化学习（RL）训练不能只依赖提示词或对话记录，而需要**可执行、奖励可靠、难度匹配当前策略能力**的训练环境。
- **核心问题**：现有的环境合成方法（Few-shot、Self-Instruct、Evol-Instruct 等）属于**固定提示配方（fixed recipes）**，它们对每一个种子任务都施加相同的重写策略，忽略了"当前策略"的实际能力水平。例如，当前策略已经饱和的简单任务仍被原样保留，而超出能力范围的困难任务也没有被降阶为可达成的"桥梁任务"。
- **本文提出的关键问题**：给定一个种子任务和当前策略，应该选择哪种**合成动作（synthesis action）**，才能使生成的环境落在**学习前沿（learning frontier）**附近——即难度适中（通过率约 50%）、对策略有最大训练价值的位置？
- **整体含义**：将环境合成从"统一的提示工程"重新定义为"**奖励驱动的逐种子动作选择**"问题，让验证器奖励直接参与决定每个种子应被"增难、降难还是多样化"。

### 二、方法论

#### 2.1 核心思想

- 将固定配方合并的"两个决策"分离：(1) **种子应如何移动**（相对于当前策略）；(2) **在该决策下如何重写完整环境**。
- 动作空间为**投影（Projection）× 演化方向（Direction）**的笛卡尔积，共 6 个候选动作：
  - 投影 A = {increase（增难）, reduce（降难）, diversify（多样化）}
  - 方向 D = {in_depth（纵深）, in_breadth（拓宽）}

#### 2.2 关键技术细节

**（1）种子通过率估计**：用当前策略在种子任务上做多次 rollout，由验证器奖励估计通过率：
- p̂ᵢ = (1/nᵢ) Σ rᵢ,ₜ（二进制奖励时为经验成功率）

**（2）候选动作的前沿评分**：用固定转移先验预测动作后的通过率：
- p̃ᵢ,ₐ,𝒹 = clip(p̂ᵢ + Δₐ γ𝒹, 0, 1)
  - Δ_increase = −0.25，Δ_reduce = +0.25，Δ_diversify = 0
  - γ_in_depth = 1，γ_in_breadth = 0.65
- 前沿效用分数（高斯形式，目标通过率 τ=0.5，σ=0.2）：
  - Fᵢ,ₐ,𝒹 = exp(−(p̃ᵢ,ₐ,𝒹 − τ)² / 2σ²)

**（3）逐种子 MILP 动作选择**：
- 每个种子对应一个六动作 MILP；二进制变量 xᵢ,ₐ,𝒹 选择动作，uᵢ,ₐ,𝒹,ᵥ 激活技能节点，ξᵥ 为技能覆盖欠额的连续松弛变量。
- 目标函数：max Σ x·F − εΣu − λΣξ（ε=10⁻⁶ 抑制冗余技能激活，λ=0.25 惩罚未达覆盖目标）
- 核心约束：每种子至多选一个动作、总动作数=N、动作-技能一致性、技能覆盖软约束（ξ≤0.2）
- **与固定配方的关系**：通过添加掩码约束 xᵢ,ₐ,𝒹 ≤ ρ_b,ₐ,𝒹，可将 Few-shot 近似为 (diversify, in_depth)、Self-Instruct 近似为 (diversify, in_breadth)、Evol-Instruct 固定方向——固定配方成为同一动作空间中的受限子集。

**（4）同步重写与金验证**：
- 选定动作后，LLM 同步重写指令、数据 fixtures、oracle 解、测试套件和 Docker 环境（禁止只改指令）。
- 通过静态检查（schema、路径安全、长度、重叠过滤）后，运行 oracle 解 + 生成测试，**只有 verifier 返回 reward = 1 的环境才进入训练池**。

**（5）训练**：合格环境转为 Terminal-Bench 格式，用 GRPO 训练 Qwen 3.5 系列模型，vLLM 生成 rollouts，测试奖励不依赖额外奖励模型。

### 六、主要结论与发现

1. **前沿感知的环境合成显著优于固定配方**：在 Qwen 3.5 35B 上，Envs-FORGE 在 tb-core、tb-2.0、SWE-bench Verified 三个基准上均取得最高 Pass@1，且在 4B–35B 全部模型规模上稳定提升。
2. **核心经验法则**：终端智能体的环境合成应当**先决定每个种子相对当前策略如何移动（增/降/多样化），再让 LLM 重写环境**，而非对所有种子施加同一条提示策略。
3. **"降低复杂度"（reduce）投影具有独特价值**：对当前策略无法解决的种子，构造确定性桥梁任务可以保留目标技能链、同时将成功率从 0 提升到可训练区间——这是固定配方（只会增难或等价改写）缺失的能力。
4. **高质量验证是可行性的前提**：只有"orcacle 通过生成测试"的环境才进入训练，保证了奖励信号可靠性，是上述增益的必要支撑。

### 七、方法亮点

- **问题重定义有新意**：将环境合成从"提示工程"提升为"奖励驱动的动作选择"问题，与 DART-Math 等难度感知数据选择思想一脉相承，但决策对象从"在哪花生成预算"变为"对每个种子施加哪种变换"。
- **统一了固定配方的语义**：通过动作掩码 ρ，将 Few-shot、Self-Instruct、Evol-Instruct 表示在同一 MILP 框架内，使基线比较具有清晰的理论视角。
- **"选择-物化-验证"三段式设计**：MILP 只负责离散动作选择（可证明最优），语义一致性交给同步重写与金验证（可靠执行检查），分工清晰、边界明确。
- **资源核算透明**：报告了 tokens、尝试次数、任务目录数等合成成本，避免"更多数据带来提升"的混淆。
- **完整可复现**：提供开源代码、求解器 trace（SCIP 状态 optimal，目标值 49.9104）、完整提示词与任务示例。

  - 金验证需要可执行容器与 oracle 解，这限制了方法在无法构建可验证环境的领域（如开放式对话、纯文本推理）的适用性。

### 九、与既有工作的关系与理论定位

- **难度感知的数据合成**：与 DART-Math、MathScale、PGM 等基于“当前模型难度”筛选/生成数据的工作同属一条脉络，但 Envs-FORGE 的差异在于**动作级别的自适应选择**——不仅决定“生成哪些数据”，还决定“对同一种子施加何种难度变换”。
- **课程学习（Curriculum Learning）**：其按通过率迁移种子的思想类似于自步课程（self-paced learning），但并非按 epoch 动态调整数据分布，而是在一个静态 MILP 中一次性求解最优动作组合，避免了课程调度的额外超参数。
- **可验证环境合成**：继承自 SWE-bench、Terminal-Bench 等“容器+oracle+测试”的可执行验证范式，并将其从“人工构造”推进到“LLM 自动生成 + 自动验证”的闭环。
- **与强化学习自训练的关系**：环境本身是策略与环境互动的产物，因此可视为“环境作为可优化变量”的一种元学习视角；但作者未深入探讨其与元强化学习、自适应环境生成的正式理论联系。

---

### 十、对后续研究的启发

1. **动态先验替代固定先验**：当前 Δ、γ 是常数，未来可用小规模验证器实时估计动作后的通过率，使 p̃ 的预测更精确。
2. **MILP 的扩展**：可加入“预算约束”（如总 token 上限、Docker 镜像大小）、多轮迭代（上一轮生成的环境反馈到下一轮种子集）、以及跨任务技能覆盖的硬约束。
3. **验证器的泛化**：目前金验证是二元成功/失败（oracle 通过测试则 reward=1），只能用于可自动判断的任务；对文本问答、代码审查等半开放任务，需要设计分级奖励或 LLM-as-judge 的软验证器。
4. **大规模种子池**：本文仅用 100 个种子，未来可尝试从大型任务库（如 AgentBench、OSWorld）中自动挑选种子，并将 MILP 扩展为分布式求解。
5. **安全问题**：需要研究如何在环境合成中注入“安全边界”约束（如禁止生成与系统破坏、越权访问相关的命令），使 RL 训练不覆盖危险行为。

### 十一、总结性评价

- **主要优势**：
  - 构建了一个简洁而统一的形式化框架，将多种现有数据合成方法纳入同一动作空间，理论表述清晰。
  - 实验控制严谨，训练数据量、合成规模、训练与评测协议完全对齐，增益可归因性较强。
  - 从“难度选择”到“环境物化”再到“金验证”的管道十分完整，具有工程可复现性。
  - 在 4B–35B 多个模型规模、3 个基准上均一致提升，说明方法不是过拟合单一配置。

- **核心硬伤**：
  - **缺少分量消融**：无法证明增益一定来自 MILP 选择而非同步重写/金验证管线；作者在文中主动承认这一点。
  - **转移先验的启发式特性**：Δ = ±0.25、γ = 0.65/1.0 的选择缺乏推导或实验依据，若先验偏差较大，整个前沿评分将失真。
  - **比较公平性尚有瑕疵**：Envs-FORGE 的尝试次数明显高于基线，未做“等尝试次数”对照，可能混淆“更多修复机会”的贡献。
  - **模型覆盖窄**：仅 Qwen 系列，无法判断方法对其他模型族是否同样有效。

- **综合评分（假设满分 10 分）**：
  - 新颖性：8.5
  - 可靠性：7.5（公平性较好，但消融缺失）
  - 实验充分性：7.0（缺乏 soler-off、先验敏感性、portfolio 对比）
  - 可复现性：9.0（代码、trace、提示词全公开）
  - **综合：8.0/10**，属于“方法新颖、工程扎实、但仍需消融补强”的强工作。

### 十二、关键名词速查

| 名词 | 含义 |
|---|---|
| 学习前沿（learning frontier） | 通过率约 50% 的任务难度区间，对策略训练价值最大 |
| 投影/方向（Projection × Direction） | 动作分解：增难/降难/多样化 × 纵深/拓宽，共 6 个动作 |
| MILP | 混合整数线性规划，用于逐种子最优动作选择 |
| 转移先验 | 预测动作后通过率变化的固定常数（Δ、γ） |
| 金验证 | 只有 oracle 解能通过生成测试的环境才进入训练池 |
| 同步重写 | LLM 同时修改指令、fixtures、oracle 解、测试与 Docker 环境 |
| Portfolio 模式 | 跨种子共享技能覆盖目标的求解模式（本文未实验验证） |

### 十三、最终结论

Envs-FORGE 是首个将“终端智能体环境合成”形式化为“奖励驱动的逐种子动作选择”的工作。通过 MILP 在 6 个候选中寻找最接近学习前沿的动作，并配合 LLM 同步重写与金验证，在 3 个基准、4 个模型规模上稳定超过所有固定配方基线。其核心思想——**先决定种子如何移动，再生成环境**——具有普适性，不仅适用于终端任务，也可推广到代码生成、数学推理等可自动验证领域。但当前证据尚不足以完全归因增益，未来需补充“关闭求解器”“变体先验”“等尝试次数对照”等消融，方能坐实“选择机制本身”的独立价值。

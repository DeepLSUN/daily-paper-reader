## 摘要
用于地震断层分割的神经网络通常借鉴自计算机视觉和医学影像领域，而这些领域中的训练数据资源相对丰富得多。在地球物理应用中常见的标注数据预算紧张的情况下，优化其架构并非易事。手动设计数据最优架构耗时费力，而经典的神经架构搜索（NAS）则受限于手工设计的搜索空间和巨大的计算预算。我们提出了一种智能体式NAS系统，其中由三个大型语言模型（Claude、GPT-5.1和Gemini~2.5~Pro）组成的小组对每个候选架构进行辩论直至达成一致共识，编写完整的PyTorch实现，进行交叉审查，并将其提交到自动化的验证-训练-评分循环中，同时设有严格的450K参数预算、保留或回退谱系以及失败机制记忆。该系统直接对源代码进行操作，而非预定义操作菜单，搜索在单个消费级GPU上运行，仅训练了八个候选架构。它发现了\ours{}：一个具有条带池化瓶颈、压缩-激励门控、非对称单卷积解码器和特征金字塔融合颈部的425K参数编码器-解码器。在与所有基线相同的协议下，在源自Thebe断层数据集的分割切片上进行训练，它在所有测试模型中取得了最高的F1（0.578）和IoU，同时模型尺寸最小，优于已发表容量的U-Net（31M参数，F1 0.484）、DeepLabV3-ResNet50（39.6M，0.516）和Attention U-Net（1.83M，0.502）。搜索成本为101次LLM调用（约115万输入/3.9万输出token）和大约一个GPU天，使得共识门控的LLM小组成为领域特定架构发现的一种实用、低成本的途径。

## Abstract
Neural networks for seismic fault segmentation are often borrowed from computer vision and medical imaging domains where they train under relatively much larger labeled data resources. Optimizing their architecture under tight labeled data budgets as are common in geophysical applications is not a trivial problem. Manually designing data-optimal architectures is time-consuming while classical neural architecture search (NAS) is restricted to hand-crafted search spaces and large compute budgets. We present an agentic NAS system in which a panel of three large language models (Claude, GPT-5.1, and Gemini~2.5~Pro) debates each candidate architecture to unanimous consensus, authors the complete PyTorch implementation, cross-reviews it, and submits it to an automated validate-train-score loop with a hard 450K parameter budget, keep-or-revert lineage, and a memory of failed mechanisms. Operating on source code rather than a predefined operation menu, the search ran on a single consumer GPU and trained only eight candidates. It discovered \ours{}: a 425K-parameter encoder-decoder with a strip-pooling bottleneck, squeeze-and-excitation gating, an asymmetric one-conv decoder, and a feature-pyramid fusion neck. Trained under a protocol identical to all baselines on sections derived from the Thebe fault dataset, it attains the highest F1 (0.578) and IoU of all models tested while being the smallest, outperforming a published-capacity U-Net (31M parameters, F1 0.484), DeepLabV3-ResNet50 (39.6M, 0.516), an Attention U-Net(1.83M, 0.502). The search cost 101 LLM calls ($\sim$1.15M input / 0.39M output tokens) and roughly one GPU-day, making consensus-gated LLM panels a practical, low-cost route to domain-specific architecture discovery.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 核心思想

- **基于共识门控的多智能体 NAS**：用一个由三个异构前沿 LLM（Claude、GPT-5.1、Gemini 2.5 Pro）组成的“辩论小组”取代单一 LLM 提议器，所有候选架构必须经过全体一致同意才能进入训练环节，避免单个模型对特定机制的“执念”。
- **直接在源代码层面搜索**：LLM 对当前父架构提出 mutation（添加/删除/修改模块），并编写完整 PyTorch 实现，而非在预定义操作菜单中采样，因此理论上可以发现搜索空间之外的创新机制。
- **“诚实”的搜索循环**：通过硬预算、保留/回退门控、失败记忆、停滞停止规则等工程设计，确保每次 GPU 训练都花在经得起对抗性审查的设计上。

### 关键技术细节

1. **搜索循环（Search Loop）**：
   - 维护单一谱系：run 0 训练参考基线（1.49M 参数，预算豁免）；之后每轮让小组对当前父架构提出一次架构突变。
   - 每个候选先通过自动验证器：AST 解析、实例化、三个形状的前向/反向测试、空间维度保持检查、参数数 ≤ 450K。
   - 验证通过的候选从头训练并评分；只有三次独立试训的平均 F1 超过父代才被保留，否则回退，并将该机制加入硬性禁用列表。
   - 父代选择始终使用均值而非最佳值，避免单一幸运种子误导。
   - 终止条件：最多 15 轮，或“停滞规则”——最近三轮均超过基线均值但运行最优 F1 提升小于 0.01。实际在第 9 轮后满足停滞规则停止。

2. **辩论小组（Debate Panel）**：
   - **PROPOSE 阶段**：每个模型独立输出结构化设计规格（设计名、相对父代的 ADD/REMOVE/CHANGE、拓扑、关键机制、预期参数数、与失败机制的差异、风险）。
   - **DEBATE 阶段**：最多四轮，每个模型逐一批评另外两个模型的设计，可以采纳对手方案，并对“ENDORSE（选择哪个规格）”和“APPROVE（是否同意）”投票；必须三者均认可同一规格才达成共识。
   - 若僵局，汇总分歧形成共同问题后重新提案（最多六次重启）；共识失败则该轮零 GPU 成本放弃。
   - 获得共识后由获胜模型编写完整实现，另外两个模型按训练契约审查（接口、空间契约、batch-1 风险、超时风险），最多两轮修订。
   - 所有提案、批评、投票、审查全部归档，并记录各提供商的 token 用量。

3. **训练协议与指标**：
   - 搜索阶段（代理协议）：每候选只用训练集中 5 个固定均匀间隔剖面训练，每轮 3 次试训 × 5 次循环 × 300 epochs，每次循环独立随机初始化；试训得分为 5 次循环最佳，保留/回退用三次试训均值。
   - 损失函数：`L = CE_w(y_hat, y) + MSE(x_hat, x)`——类别加权交叉熵（断层权重 15）+ 辅助图像重建项，所有模型都带分割头和单通道重建头。
   - 最终对比：每个架构在全量 100 个训练剖面上训练 60 epochs，同一损失与优化器，测试集为另一独立 100 剖面体积。头号指标为像素级 F1（阈值 0.5），同时报告 IoU、精确率、召回率、PR-AUC。

## 6. 主要结论与发现

- **发现的最优架构**：StripPool-UNet+FPN，425,177 参数。结构为：
  - **窄全秩编码器**：5 阶段，通道数 16/32/48/64/80，每阶段两层 3×3 卷积 + GroupNorm + SiLU，后接 SE 门控（降维率 8）；特意否决深度可分离卷积（run 1 证明回归）。
  - **条带池化瓶颈**：在 H/16 处对整行/整列特征池化，用 (3,1) 和 (1,3) 卷积混合，广播相加后经 sigmoid 门控；该机制面向断层“贯穿全剖面的细薄准线性”几何属性，参数开销远小于 ASPP。
  - **非对称单卷积解码器**：每解码块为 1×1 降维 + 双线性上采样 + 跳跃拼接 + 单层 3×3 卷积 + SE（编码器深度一半），理由是“特征学习在编码器，解码器只需重定位”。
  - **FPN 融合颈部**：四个解码尺度各自投影到 16 通道、上采样至全分辨率、求和后经一个 3×3 卷积精炼；分割头和重建头都从融合图读取。
- **性能结果**：在相同协议下，StripPool-UNet+FPN 取得最高 F1（0.578）和 IoU（0.406），同时是最小模型（0.43M）；较 31M U-Net 提升 +0.094 F1（73× 参数更少），较 39.6M DeepLabV3 提升 +0.061 F1（93× 参数更少），并优于 Attention U-Net 和 1.8M U-Net。测试集 100 个剖面中，该模型取得最优每片 F1 的有 96 个。
- **搜索效率**：仅训练 8 个候选、101 次 LLM 调用、约 1 GPU 天、几十美元 API 费用，四分之一候选改善谱系；对比经典 NAS 需数百上千候选。
- **方法学发现**：
  1. 仅优化召回率会静默丢弃最佳 F1 设计（recall 对过度预测宽容，导致精确率崩溃）；F1 是更好的代理目标。
  2. 在标注稀缺的地球物理场景中，发布容量的通用模型显著劣于针对任务优化的小模型；即使是朴素缩小 U-Net 也无法超越定制化搜索出的紧凑网络。

- **创新性**：首次将多 LLM 辩论共识机制引入神经架构搜索，并将搜索空间扩展到源代码级别，为领域专用架构发现提供了全新范式。

  - 停滞规则无需目标分数即自动终止，可复现、诚实。
  - 完整记录所有 LLM 调用、token、成本，可审计性好。

  - 最终评估仍是单切片二维语义分割模式，未展示对三维体积的连续解释结果。
- **代理协议偏差风险**：
  - 搜索阶段只用 5 个剖面训练，与最终全量训练存在分布差异；最终全量训练可能改变候选的相对排名。
  - 未报告用全量数据训练后的保留/回退一致性（即代理协议选的保留模型在最终协议下是否仍然最优）。
- **搜索稳定性未知**：只执行了一次搜索，没有多次重复以衡量随机性；不同初始基线、不同 LLM 版本或温度设置是否稳定不得而知。
- **LLM 相关局限性**：
  - 依赖三家商业 LLM API，模型版本固定（Claude、GPT-5.1、Gemini 2.5 Pro），未来模型更新可能改变行为，可复现性受限。
  - LLM 生成的代码虽然通过验证器，但验证器仅检查接口和形状，不检查数值正确性或训练稳定性；可能隐藏偶发 bug。
  - 共识机制可能引入同质化风险（三模型互相说服后收敛到类似方案），文中未分析这种“群体思维”效应。
- **指标与标签问题**：仅依赖像素级 F1/IoU 等定量指标；作者自己也承认断层标注不完整且不确定，定量指标可能不足以反映真实性能，并提议未来引入“视觉质量评审智能体”——说明当前方法可能错误丢弃因小指标回归而实际合理的架构。
- **硬件适配限制**：在 Apple MPS 后端上运行，只验证了 batch size 1 的 GroupNorm 场景，对标准 CUDA 环境、多卡、更大的 3D 输入适配性未做说明。

## 摘要
持久化上下文文件（AGENTS.md, CLAUDE.md）是指导AI编码智能体的标准做法，然而其有效性的证据却相互矛盾。我们针对两个前沿智能体（Claude Code和Codex）、来自3个仓库的17个真实任务（15个共享 + 2个仅Codex）、以及288次带金标准测试的评估运行，进行了一项受控的上下文注入策略消融实验。上下文策略在两个智能体上均未显著改变正确率（通过等价性检验界定在≤10-15个百分点内）。失败模式分诊揭示了原因：智能体失败于实现技能——特性设计、模式选择、精确接线——而非缺失上下文文件可能提供的仓库知识；一项操作探针证实，真实的AGENTS.md在任何智能体上都无法将差一点就成功的情况转化为通过。我们进一步表明，临界任务难度是智能体特有的（Spearman rho=0.75），这为之前的矛盾提供了一个候选解释：单智能体研究从不同智能体的信息带宽中抽取任务。我们公开所有代码、数据和分析。

## Abstract
Persistent context files (AGENTS.md, CLAUDE.md) are standard practice for guiding AI coding agents, yet evidence for their effectiveness is contradictory. We present a controlled ablation of context-injection strategy across two frontier agents (Claude Code and Codex), 17 real tasks from 3 repositories (15 shared + 2 Codex-only), and 288 evaluated runs with gold-test evaluation. Context strategy does not measurably move correctness on either agent (bounded to <=10-15pp via equivalence testing). A failure-mode triage reveals why: agents fail on implementation skill---feature design, pattern selection, exact wiring---not missing repository knowledge that a context file could supply; a manipulation probe confirms the real AGENTS.md never converts a near-miss to a pass on either agent. We further show that borderline task difficulty is agent-specific (Spearman rho=0.75), offering a candidate explanation for prior contradictions: single-agent studies draw tasks from different agents' informative bands. We release all code, data, and analysis.

## 1. 核心问题与整体含义

持久化上下文文件（如 AGENTS.md、CLAUDE.md）已成为指导 AI 编码智能体的标准实践，被广泛用于传递项目编码规范、架构约束与工作流指南。然而，现有实证证据存在明显矛盾：

- **Lulla et al. (2026)** 发现 AGENTS.md 能提升智能体的**效率**（降低墙钟时间与输出token数）；
- **Gloaguen et al. (2026)** 则发现上下文文件对**任务完成率**无显著影响。

两项研究在智能体（Codex vs. Claude 家族）、评估方法、实验控制等多个维度上存在差异，因此无法直接比较或调和。作者指出，**缺乏一个在受控条件下、跨两个智能体家族、改变注入策略的消融研究**，是矛盾无法化解的根本原因。

这项工作的核心含义在于：试图以严格受控的消融实验回答“上下文文件是否真的对编码智能体有效”这一实践界高度关注的问题，并进一步解释为什么此前研究会得出互相矛盾的结论。

## 2. 方法论

### 2.1 核心思想
设计一个**受控的上下文注入策略消融实验**，在保持任务、仓库、工作区、评估管线完全一致的条件下，仅改变上下文文件的注入方式，从而隔离上下文策略这一单一变量的效果。

### 2.2 三种注入策略
| 策略 | 说明 |
|---|---|
| **NONE**（无上下文） | 从工作区删除 AGENTS.md，不提供任何仓库上下文，智能体仅基于代码库工作 |
| **ALWAYS ON**（始终注入） | 每轮将完整 AGENTS.md 注入系统提示词（Claude）或用户提示词前缀（Codex），工作区中删除文件以防止重复读取 |
| **SELECTIVE**（按需检索） | 将按主题组织的 wiki 文件放入工作区，系统提示词提示智能体可查阅 wiki/*.md，由智能体通过 Read 工具按需检索 |

> **注意**：SELECTIVE 语料只对 opshin 仓库与 AGENTS.md 内容匹配；对 pdm 和 firebase-admin-python 则是更大的自动生成仓库 wiki（约 AGENTS.md 的 10 倍和 18 倍），因此这两仓库中 SELECTIVE 同时改变了**传递渠道**与**上下文内容**，构成已知混淆。

### 2.3 评估协议（SWE-bench Tier-C 风格）
- 从真实合并的 Pull Request 中挖掘任务：PR 描述作为智能体提示，基准提交作为初始状态，PR 自身的测试文件作为金标准；
- 智能体完成后，提取金测试文件并应用至智能体工作区运行，**所有金测试通过**才判定任务通过；
- 智能体全程不可见测试文件。

### 2.4 统计分析方法
- **Omnibus 置换检验**：在任务内随机置换策略标签，检验策略对正确率是否有解释力；
- **配对 Wilcoxon 符号秩检验**（Holm-Bonferroni 校正）：用于效率指标的显著性检验；
- **TOST 等价性检验**（双单侧检验）：以任务聚类 bootstrap（10k 次）对配对策略差异构建 95% 置信区间，若落在预设等价边界 ±δ 内则声明等价；
- **Monte Carlo 功效分析**：模拟不同真实效应量 Δ 与任务数下的二元结果，确定最小可检测效应（MDE）与 80% 功效所需样本量。

## 3. 实验设计

### 3.1 仓库选取
从约 40 个候选仓库中筛选出 3 个（排除 SWE-bench 仓库，因其无 AGENTS.md）：
- **pdm**（包管理器，477 词 AGENTS.md）
- **firebase-admin-python**（云 SDK，1236 词 AGENTS.md，评为“Excellent”）
- **opshin**（领域特定编译器，248 词 AGENTS.md）

筛选标准：单一根级 AGENTS.md、文件质量（覆盖构建/测试/风格约定、架构指导、特异性）为 Good 或 Excellent、可行且 Python-only。

### 3.2 任务与基准
- 从 GitHub API 挖掘合并 PR：PR 描述成为智能体提示、基础提交为起始状态、PR 自身的测试文件为金标准；
- 保留满足条件（含测试修改、非平凡、无需外部凭证）的任务；
- 初始 12 个任务，经 Codex 筛选扫描补充 4 个边界任务，最终 **Codex 17 个任务、Claude 15 个任务**（2 个高努力任务在 Anthropic 预算上限下仅用于 Codex 臂）；
- 评估遵循 SWE-bench 协议：智能体不可见测试文件，金测试为 oracle。

### 3.3 对比设置
- **两个前沿智能体**：Claude Code（claude-sonnet-4-6）与 Codex CLI（gpt-5.5）；通过系统提示词 vs. 用户提示词前缀的注入通道差异作为已知混淆。
- **三种策略 × 3 次重复**，任务内成对设计。
- **效率指标**：便携指标（工具调用数、墙钟时长、输出 token）与智能体特定指标（缓存读取/创建 token，仅 Claude；Codex 无独立缓存记账）。

## 5. 实验数量与充分性

- **共完成 291 次智能体运行**（其中 288 次有效评估：3 次 Claude 运行因崩溃/超时未产生有效金测试评估而被排除）；

- **充分性评估**：
  - **优点**：设计为任务内配对、重复 3 次、跨两个智能体家族、带金标准评估，控制良好；

## 6. 主要结论与发现

### 6.1 正确率：无策略效应（两个智能体均无）
- Claude：所有配对策略差异 ≤2.3pp；
- Codex：最大差异 5.9pp（NONE vs. SELECTIVE），由 n=3 重复的每任务噪声驱动；
- Omnibus 置换检验无显著效应（Claude p=1.00，Codex p=0.66），但作者承认该检验在存在地板/天花板效应的结构下功效不足，实质性的零结果由边界子集支撑；
- 边界任务扩展（4 个 Codex 边界任务）：NONE 58% vs. ALWAYS ON 42% vs. SELECTIVE 42%——即使设计有检测力，上下文注入也不帮助；
- TOST 等价性检验将效应界限在 Claude <10pp、Codex <15pp。

### 6.2 效率：两个狭窄过程信号，其余为零
- **Claude × SELECTIVE**：缓存创建 token 显著减少（11/11 任务一致，p=0.001，Holm 校正后 p=0.012），但作者将其归因于注入机制的机械差异而非能力提升；
- **Claude × opshin**：上下文提示中带“测试套件耗时 >20 分钟”的警告后，智能体盲目全套件测试运行次数递减（NONE 3.67 → ALWAYS ON 2.44 → SELECTIVE 1.67），墙钟时间相应下降（2689s → 2066s → 2032s）。该效应仅在该仓库、仅对 Claude 出现，属于探索性发现。

### 6.3 失败模式：技能而非知识
对近失失败（1–4 个金测试失败的案例）的分诊显示四种典型失败：
- **opshin#510**：需要微妙的联合展开优化，智能体构建了整个优化步骤但引入正确性 bug——工程精度问题；
- **firebase#907**：需要主动的鉴权 token 刷新，智能体实现的是反应性重试——架构模式选择问题；
- **opshin#554**：需要拒绝 V2 验证器参数，智能体知道 V3 规则但错误接线——精确行为规格问题；
- **opshin#593**：需要通过 isinstance + assert 进行类型收窄——深层类型系统推理问题。

**没有一例是缺少可通过上下文文件填补的“可知事实”**，全部失败于实现技能。

### 6.4 操控有效性探针
- 两个近失任务（opshin#554, firebase#907）在 36 单元探针中，**真实 AGENTS.md 从未将接近通过转为通过**；
- Codex 在所有 18/18 单元中失败；
- 唯一有跨智能体区间的任务（firebase#907，Codex 困难/Claude 边界），更多上下文并未帮助（Claude 通过率 NONE 2/3 → ALWAYS ON 1/3 → SELECTIVE 0/3，尽管 n=3 不可过度解读）。

### 6.5 边界任务难度是智能体特异的
- 15 个共享任务中，6 个对恰好一个智能体是边界任务（0<pass<1），6 个地板/天花板状态不同；
- 约 40% 的任务，能揭示上下文效应的智能体并非同一个；
- Spearman ρ=0.75（p=0.001），难度大体迁移但**信息区间不迁移**；
- 这为理解此前矛盾提供了候选机制：不同研究若从不同智能体的边界带取样，会观察到的效果截然不同。

### 6.6 调和此前矛盾
作者提出（作为假设，因无法获取对方精确任务集）：
1. 上下文文件在任一智能体家族上都不提升正确率（支持 Gloaguen 等）；
2. Lulla 等报告的高效性增益反映的是上下文注入的机械成本（更大提示 → 更多 token），而非任务表现提升；Gloaguen 等报告的成本增加方向相反，同样符合注入机制而非能力驱动的解释；
3. 先前分歧可能反映智能体特异的边界效应。

## 7. 优点

1. **受控双智能体消融设计**：此前无研究同时跨两个智能体家族且控制注入策略，填补了空白；
2. **金标准评估**（SWE-bench Tier-C 风格）：非模糊 diff 重叠，评估客观可靠；
3. **TOST 等价性检验的使用**：替代传统零假设显著性检验，得以对“无效应”做有界主张（而非仅“未能拒绝”），方法学上严谨；
4. **失败模式三诊 + 操控有效性探针**：不止报告零结果，更深入探索了“为什么没有效应”，并以探针直接回应“操控是否惰性”的质疑；
5. **功效分析**：量化了样本量限制，给出未来研究规模（检测 10pp 需 120–200 任务），方法学贡献明确；
6. **边界难度智能体特异性的发现**：不仅是本研究的发现，还提出了对消融研究设计的一般性挑战——需按智能体筛选任务；
7. **多轮防护的安全隔离**（DNS 黑洞、git remote 清除、push/commit 拒绝、token 剥离、历史修剪），确保实验不影响外部状态；
8. **透明公开**：完整释放实验代码、291 次运行数据集、统计代码与结果表格。

---

## 8. 不足与局限

1. **样本量与功效不足**：15–17 个任务、3 次重复，MDE >30pp；10pp 效应不可检测，TOST 的等价声明是描述性的而非有功效的；
2. **仓库多样性有限**：仅 3 个 Python 仓库，不能泛化至其他语言、更大代码库或异常详细的上下文文件；
3. **注入通道不对称**：Claude 走系统提示词、Codex 走用户提示词前缀（无 system-prompt 标志），两个智能体臂存在通道混淆（虽不影响任务内策略对比）；
4. **生态效度**：ALWAYS ON 每轮注入比自然工作流（智能体从工作区自行读取一次）更强；作者推断“如果保证在场无帮助，自然发现也不可能帮助”，但这是推理而非直接测量；
5. **SELECTIVE 语料不匹配**：对 pdm 和 firebase 是更大的自动生成 wiki 而非 AGENTS.md 的重新包装，混淆了传递渠道与上下文内容；需要内容匹配的 SELECTIVE 臂才能纯粹解读渠道效应；
6. **惰性操控存疑**：上下文文件是自然风格而非为特定任务定制的；虽然探针证明真实 AGENTS.md 可扰动行为但不能翻转通过，但“专为任务定制的上下文”是否有效仍悬而未决；
7. **模型快照**：结果仅适用于 claude-sonnet-4-6 和 gpt-5.5 的当前版本，模型更新后可能漂移；
8. **混合来源的运行**：Claude repeat-0 在本地机器上运行，repeat 1–2 在 pod 上运行；敏感性分析表明结果不变，但来源混入仍是瑕疵。

## 总结

> 这是一项方法学严谨、结论审慎的消融研究。作者通过受控的双智能体实验表明：真实世界的 AGENTS.md 类上下文文件并不能可测地提升编码智能体的正确率（有界在 10–15pp 内）；失败源自实现技能而非知识缺失；任务难度边界因智能体而异，为解释此前矛盾研究提供了机理假设。其核心贡献不仅在于零结果，更在于“为什么零结果”“何时可能有结果”的系统分析，以及为未来消融研究树立的方法学标杆（按智能体筛选任务、功效分析、等价性检验、操控探针）。

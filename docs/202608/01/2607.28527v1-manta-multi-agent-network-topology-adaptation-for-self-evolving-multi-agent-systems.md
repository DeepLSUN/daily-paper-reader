## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题的解决能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们提出MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自演化。在执行前，MANTA根据先前的结构经验初始化一个任务条件化的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界的结构更新。这些更新可以修改智能体角色、通信链路、执行顺序、信息可见性和验证路径，同时保留任务接口和智能体预算。我们在涵盖信息检索、工具使用、规划、工作流执行和数学推理的五个基准上，将MANTA与代表性的单智能体和多智能体基线进行了评估。MANTA取得了最高的平均得分74.0，比最强基线高出5.8个百分点，并在PlanCraft上获得了最佳结果。这些结果表明，推理时的自我改进可以扩展到协作架构本身。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

## 2. 方法论

### 2.1 核心思想
MANTA 采用**两层嵌套结构**：
- **目标任务多智能体系统层**：通过推理、工具调用和消息交换解决具体任务。
- **编排层（orchestration layer）**：负责任务条件化拓扑规划、执行监控、审计、修复决策与跨轮次经验学习。

### 2.2 关键技术细节

#### 拓扑表示
- 每个智能体具有**结构角色**（协调者、工作者、验证者、辩手、投票者等）和**阶段角色**（生产或批判）。
- 支持**嵌套分组**（agent 可委派给子组并汇总报告），并允许通过直接连线补充层级结构。
- 每个智能体受**上下文策略**控制（可见消息范围、传播距离、全量/摘要报告等）。
- 执行前通过确定性代码验证组成员关系、环依赖、角色合法性及智能体预算。

#### 编排循环
1. **查询条件化规划**：Topology Planner 根据任务描述与长期经验记忆生成紧凑计划（模式、智能体数量、是否含验证者、嵌套组等），后续由确定性代码展开验证。
2. **回合执行**：按拓扑递归执行，智能体间通过**结构化中继包**（摘要、证据、置信度、未决问题）通信，而非原始对话记录；执行中做工具调用去重与证据账本（evidence ledger）的追加记录。
3. **轨迹审计与修复**：每回合后，Trace Auditor（LLM）基于结构化工件、工具记录、置信度等输出过程性风险标记（不判断答案正确性）。Controller 决定是否结束或允许一次有界修复（每轮最多 1 次拓扑变异，每个变异最多 3 个操作）并执行最终回合。

#### 双时间尺度记忆
- **短期 playbook**：记录当前运行的每回合拓扑、审计发现、修复建议与决策，支持运行内连续上下文。
- **长期 playbook**：跨运行积累经验原则，由 Skill Reflector 每 N 轮运行基于**仅过程信号**（非基准判分）重写，支持跨任务、跨基准的拓扑经验迁移。

#### 拓扑变异算子
- 包括 `add_agent`、`expand_agent_to_group`、`set_group_pattern`、`add_edge`/`remove_edge`、`set_context_policy` 等六种有界操作。
- 对检索密集型任务使用**确定性收缩操作**（retrieval contraction），将激活拓扑收缩为单个最活跃搜索者，授予全局证据访问权限。

#### 完整算法流程（文字描述）
1. 输入任务 → Planner 读取长期 playbook → 生成初始拓扑并验证。
2. 执行一个完整协作回合（所有 agent 按拓扑产生工件）。
3. Auditor 扫描轨迹 → 产生过程标记与修复建议。
4. Controller 判断：若干净则 Finalizer 投票/合成最终答案；若需修复且未超预算 → 生成变异 → 验证 → 应用到副本拓扑 → 执行最终回合。
5. 回合结束更新短期 playbook；每 N 轮运行触发 Reflector 更新长期 playbook。

## 6. 主要结论与发现

1. **主结果**：MANTA 平均分 74.0，超越最强基线（ADAS 68.2）5.8 个百分点，并在 PlanCraft 上取得最佳（76.7）。在 BrowseComp 上显著领先（76.7 vs 静态最佳 64.4 与自适应最佳 50.0），但在 WorkBench 上低于 ADAS（43.3 vs 66.7）和 AgentSquare（62.2）。
2. **消融发现**：初始拓扑规划贡献最大（去掉后从 71.7 降到 57.5），拓扑修复次之（降至 60.8），长期 playbook 提供额外增益。令牌效率：完整版 100,315 tokens/轮，低于多数多智能体方法；元层操作仅占约 12% 推理预算。
3. **变异预算**：首个变异机会带来最大增益，后续变异边际收益递减，但均提升各基准成功率。
4. **跨域迁移**：MANTA 的长期 playbook 在 PlanCraft↔WorkBench 间迁移带来 +3.3 的平均增益；基线方法（ADAS、AgentSquare、MASS）均出现负迁移，说明 MANTA 学到的是可继承的结构知识而非基准专用工作流。
5. **机制有效性**：审计标记与错误答案呈显著相关性（未标记运行正确率 83.2%，标记运行正确率 62.5%，分离度 20.7 点）；修复后 60.9% 运行过程标记减少，59.6% 的指定修复目标在下一次审计中消失。
6. **修复模式洞察**：拓扑演化不仅是增加智能体。常见修复包括：将过载 worker 扩展为子树、将并行执行串行化（防止重复状态变更）、添加缺失的验证节点、星形补边变为全连接辩论等。添加新智能体仅占 9.3% 的操作。

## 7. 优点

- **问题定义清晰且具原创性**：将拓扑级自我改进从输出、提示词、轨迹、记忆等层级中独立出来，提出完整层级体系。
- **方法论完整**：任务条件化初始规划 + 过程性轨迹审计 + 有界结构修复 + 双时间尺度记忆，形成一个无需权重更新的端到端自演化闭环。
- **设计务实**：修复采用确定性验证与保守回退策略，避免非法拓扑；审计仅使用过程信号，不依赖基准答案，保证学习循环的纯净性。
- **实验设计细致**：除主实验外，包括消融、预算敏感性、跨域迁移、token 消耗、审计代理质量等多个维度，分析深入。
- **涌现式修复案例丰富**：通过具体案例展示拓扑演化的多样性（分支扩展、串行化、验证者插入、通信重连线），提供了有说服力的定性证据。

## 8. 不足与局限

- **规模与模型泛化受限**：仅使用 Gemma 4 单一骨干模型，未在 GPT 系列、Claude 等模型上验证；每基准仅 30 道题，统计功效有限，部分基线方差异常高。
- **WorkBench 表现落后**：该框架在 WorkBench 上性能显著低于 ADAS 和 AgentSquare，说明其自适应机制在部分工作流场景下可能过度干预或规划不足。
- **迁移实验覆盖有限**：仅评估两个规划类基准之间的迁移，跨能力域（如信息检索→数学推理）的迁移性未验证；且迁移实验在预算为零条件下进行，未评估修复能力与迁移经验的叠加效果。
- **审计机制局限性**：Auditor 只能检测“可观察到的过程异常”，无法捕捉“多个智能体一致地错误推理”等问题（论文自述：干净轨迹≠正确性保证）；部分过程标记（如消息压缩损失、工具错误级联）与答案正确性无显著关联。

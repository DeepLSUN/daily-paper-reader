## 摘要
现代编程智能体通常通过是否最终生成正确补丁来评估，但补丁生成依赖于更早的上下文获取阶段：找到任务所需的代码库文件。我们提出了Agent Retrieval Bench，一个针对这一上游检索问题的文件级基准。样本基于真实编码工作流信号构建，并针对冻结的基础提交仓库进行评估，相关性由智能体下一步需要什么来定义，而非直接的查询-文件语义相似度。该基准涵盖四个正检索任务：code2test、comment2context、trace2code和edit2ripple；第五个子集使用自然证据支持的无金标准案例和反事实错误仓库对照组来评估选择性检索。Agent Retrieval Bench包含跨越25个仓库的427个样本：345个正例、50个自然无金标准示例和32个反事实对照。语料库包含308个基础提交快照、392,000个文件和790万个块。我们评估了词法检索、RepoMap、开源嵌入、选择性弃权和记录的智能体上下文选择。没有一个检索家族占主导地位：Qwen3-Embedding-4B在正样本上获得最佳样本加权MRR，Qwen3-Embedding-8B获得最佳Recall@20，RepoMap在8K标记下获得最佳预算上下文产出，且任务级最佳方法差异显著。使用反事实对照组校准的选择性阈值并不能提高自然无金标准案例上的选择性成功，揭示了一个校准差距。记录的轨迹还在27-35%的样本中错过了所有金标准文件。一项受控的种子干预试点发现，与随机非金标准上下文相比，检索派生的初始上下文在种子后探索较少的情况下实现了更高的文件F1，而Oracle金标准上下文显示出相当大的剩余提升空间。

## Abstract
Modern coding agents are usually evaluated by whether they eventually produce a correct patch, but patch generation depends on an earlier context-acquisition stage: finding the repository files needed for the task. We introduce Agent Retrieval Bench, a file-level benchmark for this upstream retrieval problem. Samples are built from real coding-workflow signals and evaluated against frozen base-commit repositories, with relevance defined by what an agent needs next rather than direct query-file semantic similarity. The benchmark covers four positive-retrieval tasks: code2test, comment2context, trace2code, and edit2ripple; a fifth subset evaluates selective retrieval using natural evidence-backed no-gold cases and counterfactual wrong-repository controls. Agent Retrieval Bench contains 427 samples across 25 repositories: 345 positive examples, 50 natural no-gold examples, and 32 counterfactual controls. The corpus includes 308 base-commit snapshots, 392,000 files, and 7.9 million chunks. We evaluate lexical retrieval, RepoMap, open-source embeddings, selective abstention, and logged agent context selection. No single retrieval family dominates: Qwen3-Embedding-4B has the best sample-weighted MRR on positive samples, Qwen3-Embedding-8B the best Recall@20, and RepoMap the best budgeted context yield at 8K tokens, with task-level winners differing substantially. Selective thresholds calibrated with counterfactual controls do not improve selective success on natural no-gold cases, revealing a calibration gap. Logged trajectories also miss every gold file on 27-35 percent of samples. A controlled seed-intervention pilot finds that retrieval-derived initial context yields higher file F1 with less post-seed exploration than random non-gold context, while oracle gold context shows substantial remaining headroom.

### Agent Retrieval Bench：评估编程智能体仓库上下文检索

#### 1. 论文的核心问题与整体含义

编程智能体的能力评估长期聚焦于端到端结果——生成的补丁能否通过测试、能否解决问题。然而，补丁生成高度依赖于一个更早且常被忽视的**上下文获取阶段**（context-acquisition stage）：在编辑代码之前，智能体必须在庞大的仓库中识别出需要阅读的文件。如果这一阶段失败，后续的推理、编辑与验证都无从谈起。

论文指出，智能体仓库检索不同于传统语义代码搜索：传统检索的相关性由**查询-文档的语义相似度**定义，而智能体场景中相关性由**工作流中下一步需要什么**定义。一个PR描述可能涉及实现变更，而最有用的上下文是回归测试；一条故障堆栈可能指向测试文件，而根因却在语义上并不相似的另一模块。论文因此提出了 **Agent Retrieval Bench**，一个专门针对“上游文件发现”这一问题的文件级检索基准，为编码智能体的上下文获取层建立统一的评估语义与卫生标准。

#### 2. 方法论

**核心思想**：将“智能体相关性”（agentic relevance）形式化——如果一个文件能实质性地帮助智能体在编码工作流中迈出正确下一步，即使它与查询不存在直接语义联系，该文件也是相关的。每个样本由一个工作流派生查询与冻结在基础提交（base commit，即修复前状态）的仓库语料构成，检索器必须对文件进行排序或选择弃权。

**四个正向检索任务**：
- **code2test**：从 PR/实现变更信号出发，需找出相关测试文件。
- **comment2context**：给定评审意见与已评审文件，需找出被评审文件之外的必需上下文文件。
- **trace2code**：根据复现命令与失败输出，需找出根因源文件；可见测试与堆栈帧作为证据而非金标准。
- **edit2ripple**：给定锚定变更（含锚文件与 diff），需找出受影响的其他源文件或测试文件。

**第五个选择性子集**：50 个自然无金标准样本（维护者证据表明修复在仓库外）+ 32 个反事实错误仓库对照样本，用于测试弃权（abstention）能力。

**关键指标**：Recall@k、MRR、以及**预算上下文产出（BCY@B）**——在固定 token 预算内按排名贪心打包文件后，金文件被覆盖的程度。BCY 使用确定性正则分词器，路径头计入预算，支持不同阈值 τ 的敏感性检验。

**防泄漏设计**：查询中剔除最终补丁、原始 diff、修复提交哈希、精确金路径及自动生成评审产物；保留失败的堆栈帧等真实工作流信号。四种相关性机制（语义直接 D、结构间接 S、工作流约定 W、因果间接 C）以多标签形式标注。

#### 6. 主要结论与发现

- **没有单一检索方法占优**：Qwen3-4B 在样本加权 MRR 领先，Qwen3-8B 在样本加权 Recall@20 领先，RepoMap 在 BCY@8k 与 trace2code 领先；仓库宏平均后 Recall@20 榜首又回到 Qwen3-4B，说明聚合排名存在仓库依赖。
- **任务级方法差异显著**：code2test 的 MRR 与 R@20 由 Qwen3-4B 领先，comment2context 的 MRR 由 jina-0.5B 领先，trace2code 上 RepoMap 全面领先，edit2ripple 上 pplx-4B 的 MRR 与 Qwen3-4B 的 R@20 领先。
- **编辑涟漪预算依赖**：Qwen3-4B 在 4k 预算下 BCY 领先、Qwen3-8B 在 8k 预算下领先，排名验证性反转。
- **RRF 融合有效**：Qwen3-8B + RepoMap 的 RRF 融合将整体 MRR 提升至 0.2713（单最佳 0.2296），Recall@20 提升至 0.7331，trace2code 上提升尤为明显。
- **选择性弃权的消极结果**：混合协议看似有效的阈值，在移除反事实对照后全部失效——没有任何方法能通过原始 top 分数可靠区分自然外部解决案件与可本地解决案件；Jina 虽弃权正确 94.0% 但只通过了 37.7% 的正样本。
- **交互式探索不万能**：日志轨迹显示，OpenAI 与 Codex 在 27.2%–35.2% 的样本中从未触及任何金文件；在晚期命中样本中，静态检索在 top-20 内已覆盖 81.8%–86.3% 的金文件，显示出检索层可减少探索成本的潜力。
- **种子干预的功能性验证**：检索派生种子比随机非金种子在更少的种子后探索下获得更高的最终 File F1；Oracle 金种子能挽救全部未命中但仍有提升空间，说明上下文获取阶段的独立价值。

#### 7. 优点

- **问题定位精准**：聚焦于端到端评估所掩盖的上游底层瓶颈，与补丁生成分离，允许对检索层单独诊断。
- **相关性定义深刻**：将智能体相关性形式化为“下一步需要什么”，并通过多标签机制标注与查询的不同关系类型，避免了语义相似度的单一视角。
- **严密的防泄漏控制**：零致命泄漏，冻结基提交、剔除路径/补丁/提交/生成产物，从构造上排除捷径。
- **多维度评估体系**：文件排名、token 预算曲线、行级跨度诊断、选择性弃权、轨迹成本、受控种子干预、CAE 代理有效性检查——全面而互补。
- **诚实且透明**：明确声明证据边界（不声称检索因素主导补丁失败、文件命中不等于补丁成功）、暂定结果（pplx tokenizer 问题）、开放数据与代码、多种宏/加权视图。
- **保留现实干扰物**：给定文件、可见堆栈帧、跨模块测试等真实干扰物被保留在评估中，提升了基准难度与现实保真度。

#### 8. 不足与局限

- **规模有限**：427 个样本与 25 个仓库是诊断性而非网页规模，语言与生态覆盖尚不全面。
- **仓库失衡显著**：三个 Go 仓库贡献了 142/345 个正样本（Gin 占 88 个），影响聚合排名的代表性；仓库宏平均结果也证实了这一偏差。
- **文件级粒度的固有局限**：51.8% 的金文件超过 500 行，而标注的证据跨度仅占文件内容的 4.7%；文件命中大幅高估行级局部化能力（行 F1 普遍很低）。
- **无因果下推结论**：不测量补丁成功率、无 ARB 与 SWE-bench 的对应关系、无法确定检索失败→修复失败的因果关系；种子干预每臂每样本仅一个轨迹，无法给出置信区间。

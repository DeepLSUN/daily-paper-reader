## 摘要
全模态大语言模型（OmniLLMs）正迅速扩展多模态推理能力，以覆盖同步音频与视频。然而，由此产生的音视频令牌序列较长，导致推理时的预填充延迟和GPU内存占用过高。现有的令牌剪枝方法主要针对纯视觉输入设计，既忽略了音频与视频之间的跨模态关联，也未考虑决定内容重要性的用户查询。为填补这一空白，我们提出了Omni-Prune，一个无需训练、查询感知的音视频令牌剪枝框架，可同时去除两种模态中的冗余，同时保留与任务相关的跨模态证据。具体而言，Omni-Prune首先将令牌序列划分为位于音频显著性峰值处的自适应时间窗口，然后在一个结合编码器注意力与文本查询相关性的统一尺度上对音频和视频令牌进行评分，并将相关的音视频令牌配对以便一起保留。在每个窗口内，最终的K-medoids步骤会选取少量代表性令牌，从而增加仅基于评分选择所遗漏的多样化线索。大量实验表明，Omni-Prune优于已有基线方法，可实现高达3.25倍的预填充加速和1.3倍的内存缩减，同时保留完整模型性能的99%以上。

## Abstract
Omnimodal large language models (OmniLLMs) are rapidly extending multimodal reasoning to cover synchronized audio and video. However, the resulting audio-video token sequences are long, leading to high prefill latency and GPU memory usage at inference time. Existing token pruning methods, designed mainly for vision-only inputs, miss both the cross-modal links between audio and video and the user query that decides which content matters. To bridge this gap, we present Omni-Prune, a training-free, query-aware audio-visual token pruning framework that jointly removes redundancy from both modalities while keeping task-relevant cross-modal evidence. Specifically, Omni-Prune first splits the token sequence into adaptive time windows placed at audio saliency peaks, then scores audio and video tokens on a single scale that combines encoder attention with text-query relevance, and pairs related audio-video tokens so that they are kept together. Within each window, a final K-medoids step then selects a few representative tokens, adding diverse cues that score-based selection alone would miss. Extensive experiments demonstrate that Omni-Prune outperforms established baseline methods, delivering up to 3.25x prefill speedup and 1.3x memory reduction while retaining over 99% of full-model performance.

- 现有 token 剪枝方法主要针对纯视觉输入（FastV、DyCoke 等），无法利用音频提供的互补性、时间对齐的跨模态证据。

### 2. 方法论：Omni-Prune 框架

Omni-Prune 包含三个核心模块，整体流程为：**自适应分窗 → 统一评分与跨模态配对 → K-medoids 多样化保持**。

#### 2.1 Audio-Anchor Adaptive Windowing（AAW，音频锚定自适应分窗）

**动机**：固定窗口或全局处理忽略了语义事件在时间上的非均匀分布，而音频显著事件（语音起始、音效、音乐切换）往往与重要视频时刻同时出现。

**流程**：
1. 将音频 token 序列按视频帧均匀划分为 F 段；
2. 计算每段音频的显著度（encoder attention 均值）；
3. 用 1D 平均池化（核大小=3）平滑能量曲线，抑制瞬时波动；
4. 检测平滑曲线中的局部峰值（前后均不大于当前值），作为候选窗口边界；
5. 施加最小间隔约束（fmin = 2），避免过度切分破坏连贯事件。

#### 2.2 Cross-Modal Relation Map（CMRM，跨模态关系图）

**Token 重要性评分**：结合两种信号：
- **编码器注意力**（encoder attention，公式4）：从最后一层自注意力中聚合所有 head、所有 query 位置对 token i 的注意力贡献，再对窗口内音视频 token 做**联合** min-max 归一化（公式5），使两种模态处于同一可比尺度。
- **文本查询相关性**（公式6）：计算每个多模态 token 嵌入与用户查询中所有文本 token 的余弦相似度，取最大值并经仿射映射到 [0,1]。

**综合评分**（公式7）：**φᵢ = vᵢ + rᵢᵗᵉˣᵗ**。满足条件（vᵢ 超过窗口均值，或 rᵢᵗᵉˣᵗ 超过 max(均值, τ=0.55)）的 token 被选为 keep 候选，按 φᵢ 排序取前 B_keep 个。

**跨模态配对**（Cross-Modal Coupling）：
- 在窗口内计算音视频 token 间的余弦相似度矩阵（公式8）；
- 用双向贪心匹配将未选中的音频 token 与最相似的视频 token 配对；
- 相似度超过门控阈值 γ=0.6 的对子被联合保留；
- 剩余预算按 φᵢ 排序填充，优先补足少数模态以维持跨模态平衡。

#### 2.3 Diversity-Preserving Clustering（多样化保持聚类）

**动机**：未被选择的 token 并非全部无用，可能包含环境音、背景物体、外围场景等互补细节。

**方法**：在每个窗口内、每种模态中分别对未选中 token 做 **K-medoids 聚类**（选择 ρc = 0.1 比例的 medoids）。选用 K-medoids 而非 K-means 的原因：medoid 是编码器真实输出的 token，而 K-means 质心是平均向量，会偏离分布、不适合直接输入 LLM。采用余弦距离上的 farthest-first 遍历，在 O(k·n) 时间内完成，开销可忽略。

**总体流程伪代码**（算法1、2 在附录 E）：分窗 → 窗口内评分 → 全局预算分配 → 跨模态配对 → 聚类补充 → 生成保留掩码，保持原始 token 顺序不变，即插即用。

### 6. 主要结论与发现

1. **近乎无损的性能保持**：7B 模型在 45% 预算下保留全模型精度 99.2%，在 35% 激进预算下仍达 99.0%；几乎所有基准上均为最优，次优的 OmniZip 与其差距随模型变小而增大。

4. **模型规模敏感性**：3B 模型对剪枝更脆弱，但 Omni-Prune 相对其他方法的优势反而扩大，证明其优势源自更好的 token 选择而非大模型冗余容错。
5. **各模块均有贡献**：评分模块贡献最大（移除后掉 0.7-1.1 分），配对模块次之（掉 0.2-0.6 分）；聚类的增益随剪枝激进程度和音视频密度增大而增大。

### 7. 优点

1. **首个三模态感知剪枝方法**：将文本查询纳入剪枝决策，突破以往只有视觉或单向模态引导的局限，技术新颖度高。
2. **无需训练、即插即用**：不改变模型参数、token 嵌入或位置索引，保持原始 token 顺序，可直接应用于任何 OmniLLM。
3. **统一评分机制**：对音频和视频 token 做联合归一化，提供跨模态直接比较的公平基础，避免模态间偏差。
4. **跨模态配对保留语义完整性**：双向贪心匹配将同一事件对应的音视频 token 成对保留，维持下游推理所需的跨模态一致性。
5. **自适应分窗优于固定窗口**：以音频显著性峰值为边界，使窗口符合内容语义节奏，对数据集不敏感（图4证明固定窗口最优值因数据集而异，而 AAW 无需调参即接近最优）。
6. **K-medoids 补充多样性**：与前人的直接丢弃策略不同，通过保留真实 token 作为 medoid，低成本引入被初筛遗漏的互补性证据。
7. **实验扎实**：跨 5 基准、2 模型规模、多轮消融，且附录提供了完整算法伪代码和额外验证。
8. **效率优秀**：在降低 65% token 的情况下仍保持 >99% 精度，prefill 加速最高 3.63×，实际部署价值高。

### 8. 不足与局限

1. **评估范围有限**：仅覆盖视频问答任务，未涉及开放性生成、多轮对话、语音交互等 OmniLLM 的其他核心能力；未评估剪枝对生成质量（如流畅度、事实性）的影响；此类任务需人工评测，论文未覆盖。
2. **超参数未自适应**：跨所有数据集和模型规模使用单一固定配置（τ=0.55, γ=0.6, ρc=0.1），虽保证"开箱即用"性，但不同数据集的片段长度、音频丰富度差异大，轻量自适应调参可能进一步提升性能。
3. **以音频为主锚的潜在偏差**：音频注意力峰作为窗口边界，对于静音但视觉信息密集的场景（如纯视觉推理片段），音频锚定可能失效或产生误导性边界。
4. **配对门控机制的单向性**：跨模态配对仅针对"未选中"的 token 进行，已选 token 之间的跨模态关系未被显式建模；配对质量完全取决于嵌入相似度阈值，缺乏语义层面的验证。
5. **基线对比完整度不足**：FastV 在 VideoMME 上 OOM 缺失数据；未与其他更强的全模态剪枝方法（如 OmniSIFT，论文引用但未做实验对比）进行直接比较。
6. **算力细节缺失**：未报告 A6000 GPU 的数量、推理时间测量次数/方差、以及各方法的实际耗电或吞吐量对比，影响效率结论的可复现性。
7. **聚类收益不均衡**：在内容高度集中的基准（WorldSense、FutureOmni）上聚类贡献很小，说明该方法对"场景密集 vs 事件聚焦"两类视频的适应性不均，需要针对不同视频类型调整 ρc。

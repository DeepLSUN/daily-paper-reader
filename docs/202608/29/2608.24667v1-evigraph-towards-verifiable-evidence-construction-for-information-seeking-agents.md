## 摘要
智能体式网络检索能够在不确认检索内容是否真正支持回答中所用主张的情况下，获取相关信息。现有智能体通常将搜索与证据记录保持在线性交互轨迹中，并主要针对最终答案的正确性进行优化，对中间过程的基础依据监督有限。我们提出EviGraph，一种深度搜索框架，将搜索执行与证据记录分离，同时为可训练角色使用共享策略。执行器制定简洁查询，冻结的证据验证器检查源页面并返回带有明确极性的逐字证据条目，策略将这些条目映射为添加/支持图的请求，并经过确定性结构验证器检查。生成的图既作为持久工作记忆，也作为密集过程奖励的来源，使强化学习能够直接监督证据构建，而不仅仅监督最终答案。在BrowseComp-Plus上，一个Qwen3-8B EviGraph智能体在匹配交互预算下达到35.9%的准确率，相比之下，没有强化学习的相同双角色架构为26.9%，单体智能体为2.7%，且每次生成更少的token。在BrowseComp、GAIA和XBench上的一致增益表明，明确结构化并奖励证据记录能够改善智能体式搜索。

## Abstract
Agentic Web search can retrieve relevant information without establishing that the retrieved content actually supports the claims used in an answer. Existing agents typically keep search and evidence recording in a linear interaction trace and optimize primarily for final-answer correctness, providing limited supervision for intermediate grounding. We present EviGraph, a deep-search framework that separates search execution from evidence recording while using a shared policy for the trainable roles. An executor plans concise queries, a frozen evidence verifier inspects source pages and returns verbatim evidence items with an explicit polarity, and the policy maps those items to add/support graph requests that are checked by a deterministic structural validator. The resulting graph serves both as persistent working memory and as a source of dense process rewards, enabling reinforcement learning to directly supervise evidence construction rather than only the final answer. On BrowseComp-Plus, a Qwen3-8B EviGraph agent achieves 35.9% accuracy under a matched interaction budget, compared with 26.9% for the same dual-role architecture without reinforcement learning and 2.7% for a monolithic agent, while generating fewer tokens per rollout. Consistent gains on BrowseComp, GAIA, and XBench indicate that explicitly structuring and rewarding evidence recording improves agentic search

# EviGraph：面向信息检索智能体的可验证证据构建

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- 大语言模型（LLM）配备搜索工具后，可以迭代检索外部信息以解决超出参数记忆的知识密集型任务，但现有智能体搜索系统存在关键缺陷：**检索相关性不等于证据支持性**——一个页面可能提到正确实体，却指向不同的时间、地点或数值。
- 现有智能体通常将搜索与证据记录保持在线性交互轨迹中，**仅优化最终答案的正确性**，对中间证据构建缺乏显式监督，导致三类问题：
  1. 答案正确但证据不充分；
  2. 奖励机制鼓励走捷径，允许在证据缺失或矛盾时得出正确答案；
  3. 引用无法揭示哪个源片段支持哪个特定主张。
- 多约束Web研究任务尤其需要显式的结构化证据：一个候选页面可能满足部分约束而违反其他约束，需要智能体构建**共同满足所有约束**的证据。

**论文核心主张：**

将智能体搜索重新定义为**证据构建（evidence construction）**过程——构建一个类型化的、基于逐字跨度的声明–证据图（claim–evidence graph），该图既作为持久工作记忆，又作为密集过程奖励的来源，使强化学习可以直接监督证据构建过程而非仅监督最终答案。

## 2. 方法论

### 2.1 核心思想

- **分离搜索执行与证据记录**：将深度搜索解耦为两个可训练角色（由同一策略模型 πθ 实现）：
  - **执行器（executor）**：规划简洁查询，仅读取图快照，决定搜索或终止回答；
  - **证据提议角色（evidence-proposal role）**：将验证器输出的证据项映射为图的 add/support 操作请求。
- **冻结证据验证器（frozen evidence verifier）**：检查源页面，返回带有明确极性（support/conflict）的逐字证据条目，由候选、约束标签、来源、逐字跨度、相关性解释和极性组成，**永不直接编辑图**。
- **确定性结构验证器（deterministic structural validator）**：仅检查图操作的语法和结构不变量，不做出语义蕴含或终止决策。

### 2.2 证据图结构（Evidence-Graph Schema）

图的节点分为四类：

| 节点类型 | 语义 |
|---------|------|
| 文档（Document） | 具有稳定标识符的已打开来源 |
| 跨度（Span） | 锚定到文档的逐字文本 |
| 原子声明（Atomic claim） | 一个候选–约束断言 |
| 答案候选（Answer candidate） | 候选标识符，由原子声明引用 |

边分为两类：
- **CONTAINS 边**：文档包含某引用跨度；
- **证据边（Evidence edge）**：跨度与声明之间的链接，极性 ∈ {support, conflict}。

### 2.3 双角色顺序决策过程

系统状态定义为 Sₜ = (q, T, Gₜ, Lₜ, Oₜ, Bₜ)，其中 q 是问题、T 是需求约束标签集合、Gₜ 是当前证据图、Lₜ 是查询日志、Oₜ 是检索观测、Bₜ 是剩余工具预算。

关键流程（每轮循环）：
1. 执行器选择 SEARCH(u) 或 ANSWER(a)；
2. 检索结果返回后，冻结验证器检查页面并返回极性标记的证据条目；
3. 证据提议策略将每个条目映射为 ADD（引入新候选）或 SUPPORT（附加到现有候选）；
4. 结构验证器确认请求匹配未消费的证据条目且满足图不变性，否则拒绝并返回类型化错误。

### 2.4 关键公式与奖励设计

**候选覆盖率**（冲突边不计入）：

c(G) = max_{f∈V_F} |T_cov(G,f)| / max(1, |T|)

**检索新颖性**：

n_m = |T_ret^m \ ⋃_{ℓ<m} T_ret^ℓ| / max(1, |T|)

**执行器过程奖励**：

r_E^m = αn_m + [γβc(G_{m+1}) − βc(G_m)] − κs

（覆盖项采用基于势能的reward shaping形式，将延迟的覆盖增益分配给产生该证据的查询。）

**图质量势能**：

Φ(G) = λ_cov c(G) − λ_u U(G) − λ_o O(G)，终态势能 Φ(G_end) = 0

其中 U(G) 是未解决冲突率，O(G) 是离任务惩罚率。

**证据提议奖励**：

r_P^{m,j} = λ_v v_{m,j} + [γΦ(G_{m,j+1}) − Φ(G_{m,j})]

v_{m,j} 仅在首次记录某候选–标签–极性三元组时取 +1，结构拒绝时取 −1，其他情况为 0（防止奖励欺诈）。

**角色条件 GRPO 目标**：

L = ω_E L_E + ω_P L_P + β_KL E[D_KL(π_θ‖π_ref)]

### 2.5 防奖励欺诈机制

- 结构验证器计算**规范证据签名**（来源 ID + 跨度偏移 + 归一化声明 + 标签 + 极性），完全重复转为零奖励的无操作；
- 每个三元组的接受奖励设上限（cap）；
- 使用势差奖励（γΦ(G′) − Φ(G)）保证策略不变性；
- KL 惩罚防止策略偏离参考模型过远。

## 6. 主要结论与发现

1. **角色解耦带来显著增益**：在 BrowseComp-Plus 上，双角色架构（26.9%）比单体智能体（2.7%）提升 24.2 个百分点——但搜索持久性差异（3.7 vs 12.9）本身也由架构引起；
2. **RL 提供额外增益**：在架构和搜索数基本匹配条件下（12.9 vs 13.2），RL 将准确率从 26.9% 提升至 35.9%（+9.0 点），同时将平均生成 token 从 1,878 降至 1,689，表明 RL 将生成重新分配到更短的查询和紧凑的图编辑而非冗长轨迹；
3. **跨基准增益一致**：BrowseComp（10.5→17.8）、GAIA（43.7→53.4）、XBench（45.0→56.0），均有一致提升，证明方法泛化性良好；
4. **多模态零样本迁移**：Qwen3-VL-8B + EviGraph 在 LiveVQA 上达 78.0%，超过 Gemini-2.5-Pro（76.0%），与 Vision-DeepResearch-30B-A3B（77.6%）相当（0.4 点差距约为一题，视为竞争而非超越）；无搜索的 EviGraph（51.0%）对比直接推理（47.0%）显示图结构本身也有帮助；
5. **训练动态良性**：奖励在第 50 步后快速上升并在 0.15–0.28 稳定，回答长度从约 1,900 降至 1,650–1,750 后稳定，搜索次数从 12.9 缓慢增至 13.1–13.3。

## 7. 优点与亮点

- **范式创新**：将智能体搜索从"最终答案优化"重构为"证据结构构建"，为过程监督提供了新的可能；
- **可审计性**：源可达性不变量保证每个记录的声明都可以追溯到实际观察到的源跨度，结构性幻构（如编造的 URL 或循环自支持）无法进入持久图；
- **明确的可学习/固定边界**：哪些部分是学习得到的（策略的搜索和图写入请求）、哪些是固定的（冻结验证器的极性判断、确定性验证器的结构检查），在架构上非常清晰；
- **防奖励欺诈设计缜密**：规范签名去重、三元组奖励上限、势差奖励、KL 惩罚等多重机制共同缓解了 reward farming；
- **过程奖励的可解释性**：三种失败源（检索失败、记录失败、决策失败）被明确分离，每个失败模式对应不同的转换并获得角色特定的信用分配；
- **模态无关的架构优雅性**：视觉证据通过文本渲染进入同一图结构，验证器、奖励和溯源不变量跨模态保持完全一致；
- **效率提升**：相比单体架构生成更少的 token，同时保持更高精度；执行器快照复杂度 O(C+|T|) 而非 O(Σ|d|)，不随检索文本总量增长；
- **实验对照严谨**：同骨干消融将架构贡献与 RL 贡献分离，这是同类工作中难得的严谨设计。

## 8. 不足与局限

- **实验覆盖局限**：主实验仅在 Qwen3-8B/32B 骨干上进行，未验证方法在更大或更异构模型上的适用性；LiveVQA 等基准单次评估无种子平均；未测试不同验证器强度对上游证据质量的敏感性；
- **固定验证器的瓶颈**：验证器是冻结的，其质量上限决定了证据提取的质量上限；若验证器本身对某些领域（如低资源语言、专业术语）表现不佳，整个图的质量会系统性受损；
- **训练数据领域受限**：仅使用 NQ 和 HotpotQA 数据训练，未能覆盖更广泛的多约束、长尾查询分布；
- **奖励公式依赖标签集 T**：需要预先识别需要的约束标签 T，若初始约束识别不全，图的质量和过程奖励都会偏差；
- **计算成本未充分报告**：虽说明 8×H20、1,200 步，但未报告训练时间、推理时间、或与基线相比的总 FLOPs 成本对比；
- **"搜索持久性"作为架构副作用**：单体智能体搜索 3.7 次而双角色搜索 12.9 次，两者准确率对比中混合了"多搜索"与"角色分解"两个因素，尽管作者承认这一点，但无法完全分离；
- **潜在奖励漏洞未完全消除**：作者承认"我们不声称消除每一个可能的利用方式"；对超大型动作空间下更复杂的奖励欺诈模式仍需进一步验证；
- **线性轨迹的记忆 vs 图记忆**：论文未充分讨论图构建失败（如文本过长、顶点数量爆炸）时的降级策略；虽提到需要层次化图摘要，但这一方向尚未实现和验证。

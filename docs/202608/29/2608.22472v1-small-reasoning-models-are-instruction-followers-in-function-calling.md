## 摘要
函数调用是智能体大型语言模型（LLM）的核心能力。现有研究侧重于通过微调、强化学习（RL）和多智能体框架来提高LLM的函数调用准确性，尤其是针对原生函数调用LLM。本工作表明，在指令遵循情境（即标准的用户-助手交互）下，LLM在函数调用中能达到更高的准确性，而非在工具调用情境下。我们提出了指令遵循函数调用（IFFC），一种新颖的框架，将函数调用逻辑从主LLM中解耦，并将其委托给一个在指令遵循范式内运行的专用小型模型。我们的方法在原生函数调用（NFC）和基于提示的函数调用（PFC）基线上均持续表现出更优的性能，尤其在面向推理的LLM上取得了显著提升。此外，我们证明IFFC在激进量化下仍保持稳健性能，能够在精度无明显下降的情况下实现高效的设备端部署。这项工作为边缘计算场景中可靠、资源高效的函数调用确立了新的范式。

## Abstract
Function calling represents the core capability of agentic large language models (LLMs). Existing research has focused on enhancing LLMs function-calling accuracy through fine-tuning, reinforcement learning (RL), and multi-agent frameworks, particularly for native function-calling LLMs. This work demonstrates that LLMs achieve superior accuracy in function calling in instruction-following contexts (i.e., standard user-assistant interactions) rather than a tool calling context. We introduce Instruction-Followed Function Calling (IFFC), a novel framework that decouples function-calling logic from the primary LLM and delegates it to a dedicated smaller model operating within the instruction-following paradigm. Our method consistently outperforms both native function calling (NFC) and prompt-based function calling (PFC) baselines, with particularly strong gains on reasoning-oriented LLMs. Furthermore, we demonstrate that IFFC maintains robust performance under aggressive quantization, enabling efficient on-device deployment without significant accuracy degradation. This work establishes a new paradigm for reliable, resource-efficient function calling in edge-computing scenarios.

## 1. 论文核心问题与整体含义（研究动机与背景）

- **背景**：函数调用（Function Calling）是智能体大语言模型（Agentic LLM）的核心能力，使模型能够选择工具、生成参数并执行动作。传统研究多聚焦于通过微调、强化学习、多智能体框架来提升原生函数调用（NFC）能力。
- **核心问题**：将函数调用逻辑强行嵌套在通用 LLM 中会导致上下文污染（Context Pollution）、高 Token 开销以及格式错误。尤其是小型语言模型（SLM）在面对刚性 JSON schema、复杂 API 定义和多步推理时表现脆弱。
- **核心洞察**：本文提出一个关键发现——LLM 在**指令遵循情境**（即标准用户-助手交互）下的函数调用准确率要高于**原生工具调用情境**（使用专用 tool token 和结构化 API 调用）。即模型更擅长“按指令行事”，而非“操作刚性格式”。
- **整体意义**：提出了 IFFC（Instruction-Followed Function Calling）框架，将函数调用逻辑从主 LLM 中完全解耦，委托给专用的小型推理模型（SRM），让 SRM 在纯指令遵循范式下执行路由和工具调用，从而绕开了原生函数调用对小型模型带来的格式负担，为边缘端高效、隐私保护的智能体部署提供新范式。

## 2. 方法论

### 核心思想
- **解耦架构**：将“意图理解 + 工具选择/执行”从主问答（QA）LLM 中分离出来，交给一个专用的小型推理模型（0.5B-15B 参数）完成。
- **范式转换**：将函数调用视为自然语言指令遵循任务（而非结构化 schema 操作），利用模型在指令微调中积累的对话能力。

### 框架工作流（Algorithm 1 概括）

**阶段一：意图评估与函数路由（SRM 执行）**
1. 接收用户查询 Q 和可用函数列表 F。
2. 将 IFFC 系统指令、函数定义（作为行为准则而非 tool schema）和对话历史拼接成 SRM 输入。
3. SRM 使用基于提示的函数调用（PFC）方式输出决策：
   - 若判定需要调用函数 f（附带参数 θ），则执行外部函数获得上下文 C；
   - 若不需要，则直接透传原始用户查询。

**阶段二：主 LLM 响应合成**
- 将富化后的查询（Q + 外部上下文 C 或原查询 Q）送入主 QA LLM，由其生成最终的自然语言回复。

**阶段三：上下文状态分离**
- 主 LLM 的历史只包含 `{用户查询, 最终回复}`；
- SRM 的历史只包含 `{用户查询, SRM 输出}`，**不包含**主 LLM 生成的最终回复，避免长回复污染 SRM 的短上下文窗口。

### IFFC 系统提示的核心要素
- 将模型定义为“函数调用专家”，以系统指令方式提供可用函数列表；
- 要求模型严格以 JSON 列表格式输出（每个函数调用对应一个含 `function_name` 和 `parameters` 的字典）；
- 增加启发式规则：要求参数值严格遵循函数文档注释中的示例格式（如传入 “Paris, France” 而非 “Paris”），减少 schema 校验误差。

### IFFC 与 PFC 的关键区别
- **架构解耦**：标准 PFC 将工具定义输入主对话模型；IFFC 完全将其卸载至独立的 SRM。
- **定制格式**：IFFC 针对 SRM 的推理能力定制专属输出格式（而非通用 JSON 格式），并注入针对 benchmark 验证后发现的启发式提示。

## 3. 实验设计

### 数据集/Benchmark
- **BFCL V3（Berkeley Function Calling Leaderboard）** 作为基准，并区分两个评估场景：
  - **Live（动态函数集合）**：模拟真实场景中的不可见函数。
  - **Non-Live（静态函数集合）**：预定义的测试函数集合。
- 每个场景下包含四个任务类别：**Simple**（单个函数调用）、**Multiple**（多个独立调用）、**Parallel**（并行调用）、**Parallel Multiple**（并行多函数调用）。

- **PFC（Prompt-based Function Calling）**：用自然语言系统提示注入工具定义，但仍由同一个主模型执行并保留在对话上下文中。

## 6. 主要结论与发现

1. **指令遵循优于原生工具调用**：所有 Qwen-3 和 Phi-4 Mini 模型中（较 2.0 GB→0.8 GB），IFFC 在 Live 和 Non-Live 均稳定超越 NFC；例如 Phi-4 Mini 从 NFC 的约 30%（Live）提升至 IFFC 的 44.3%，Qwen-3 4B（Think）达到 Live 86.7% / Non-Live 94.1%。
2. **解耦 + 专注推理的小模型可超越巨模型**：Qwen-3 4B（IFFC, Non-Live Simple 96.0%）超越 Claude 4.5 Sonnet（72.6%）和 GPT-5.2（72.9%）；在所有 Non-Live 类别上，4B/8B Qwen-3 均与或优于各大专有模型。
3. **显式推理轨迹显著提升准确性**：Qwen-3 0.6B 在 Think 模式下 Live 准确率从 22.9% 提升至 57.7%（约 2.5 倍）；4B 从 74.6% 提升至 86.7%。
4. **推理型模型对量化高度鲁棒**：Qwen-3 4B（Think）在 Q4KM 下仅从 94.1% 微降至 93.5%；8B（Think）甚至提升了 0.2 个百分点。相比之下，非推理模型（如 Gemma-3 1B）在量化后性能大幅衰减（从 23.9% 降至 8.7%），表明推理轨迹起到了纠错补偿作用。
5. **PFC 在复杂场景中固有缺陷被 IFFC 克服**：Gemma-3 4B 在 Parallel Multiple 类别下 PFC 仅约 29-41%，而 IFFC 稳定在 72.5%+，说明上下文隔离有效避免了长工具定义带来的上下文漂移。

## 8. 不足与局限

- **固有延迟开销**：作者在 Limitations 中承认 IFFC 的两阶段顺序推理架构引入额外延迟；对于延迟敏感的实时应用，即使量化也无法完全消除影响——此为该框架的本质取舍。

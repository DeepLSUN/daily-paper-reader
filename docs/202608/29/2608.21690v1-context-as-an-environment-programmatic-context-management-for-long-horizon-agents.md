## 摘要
LLM智能体越来越多地承担长期运行的任务，其历史记录的增长远超单个模型上下文窗口的容量。现有方法将早期交互压缩或提取选择信息到固定记忆表示中，在未来的需求未知之前就承诺保留哪些内容。我们提出Scroll，一个上下文管理器，将每个智能体会话视为一个可执行的会话环境。该环境由一个仅追加的事件日志和一个沙盒化的持久Python内核支撑。内核跨模型调用维护一个类型化命名空间，允许工具输出、检索到的历史记录和派生状态绑定到变量，而不是在每次调用时序列化到提示词中。模型编写的代码通过exec搜索、物化并转换会话状态；只有显式打印的投影才进入模型下一调用的工作视图。因此，上下文管理成为一个继承LLM不断提升的编码能力的编程任务，而事件日志保留了无损的历史真实数据。当工作视图接近其预算时，过时的片段被驱逐但仍可恢复：一个驱逐索引保留紧绑定到确切事件日志地址的紧凑地标，使得智能体直接导航到被驱逐的区域，而不是搜索完整日志。以Qwen3.8-Max为骨干，Scroll在LongMemEval_S上达到94.8%；在BEAM_10M上达到73.1%，超过最佳已发布记忆系统5.1个百分点；在LOCA_256K上达到86.7%，超过最佳已发布长时程智能体37.4个百分点。

## Abstract
LLM agents increasingly take on long-running tasks whose history grows far beyond a single model context window. Existing approaches compress earlier interactions or extract selected information into fixed memory representations, committing to what to preserve before future needs are known. We present Scroll, a context manager that treats each agent session as an executable Session Environment. The environment is backed by an append-only Event Log and a sandboxed, persistent Python kernel. The kernel maintains a typed namespace across model calls, allowing tool outputs, retrieved history, and derived state to be bound to variables rather than serialized into the prompt at each call. Model-written code searches, materializes, and transforms session state through exec; only explicitly printed projections enter the model's working view for the next call. Context management thus becomes a programming task that inherits the improving coding abilities of LLMs, while the Event Log preserves lossless historical ground truth. As the working view approaches its budget, stale spans are evicted but remain recoverable: an eviction index keeps compact landmarks tied to exact Event Log addresses, so that the agent navigates directly to evicted regions instead of searching the full log. With Qwen3.8-Max as the backbone, Scroll achieves 94.8% on LongMemEval_S; 73.1% on BEAM_10M, surpassing the best published memory system by 5.1 points; and 86.7% on LOCA_256K, exceeding the best published long-horizon agent by 37.4 points.

## 1. 核心问题与研究动机

- **长期任务中的上下文增长问题**：LLM 智能体日益承担仓储级软件开发、深度研究等长时程任务，交互轨迹（模型调用、工具执行、观察、失败与修订）不断累积，会话历史很容易超出模型上下文窗口；且模型对长输入的有效利用能力远低于名义窗口，检索与推理质量随输入长度退化。
- **现有两类解决路径的共同缺陷**：
  - **上下文压缩**（截断、丢弃工具输出、摘要化）与**外部记忆**（抽取事实/片段存入独立存储，检索时取回）本质上都是有损的——它们都在未来需求未知之前，预先决定了要保留哪些信息、以什么形式保留、通过什么接口访问。
  - 一旦某些细节未被保留，即使原始日志仍存在于磁盘上，智能体也无法再访问。
- **核心挑战**：长时程任务往往需要精确的历史证据或对过去事件进行非平凡计算（如比较轨迹中相隔很久的工具输出），而相关信息和所需操作都无法事先预知，因此观察时生成的任何摘要都无法保证满足未来需求。
- **Scroll 的核心洞察**：不应将累积历史序列化进提示词，而应将其视为一个**智能体可通过编程交互的环境**。上下文管理由此从"预先选择保存什么"转变为"查询时由模型编写程序决定看什么"。

## 2. 方法论

### 2.1 核心思想

- 将历史保存在模型上下文之外，构建一个**可执行的会话环境（Session Environment）**。
- 提示词只携带一个**工作视图**（working view），会话本身在上下文之外无损存续。
- 上下文管理变成编写程序（CodeAct 风格），继承 LLM 不断提升的编码能力。

### 2.2 系统三组件（对应形式化中的 S_t=(L_t, P_t, V_t)）

- **追加式事件日志（Event Log，对应 L_t）**：跨会话的单一仅追加日志，每个交互事件带类型化元数据（角色、会话/智能体 ID、时间戳、工具状态），获得不可变的单调递增 `seq` 地址；存储于 SQLite，默认使用 BM25 全文检索（确定性、无索引时模型调用费用）。
- **持久化负载存储（Durable storage，对应 P_t）**：小负载内联于 SQLite，大负载（完整工具结果、生成文件）外置到 JSON/文件系统，事件行保留有界预览与恢复指针；通过懒句柄（`ToolResultRef`、`ArtifactRef`）访问。
- **持久运行时与驻留命名空间（Persistent kernel，对应 V_t）**：沙盒化 Python 内核跨模型调用持续存在，持有类型化命名空间（工具输出、检索历史、派生状态以 Python 对象形式驻留）；工具调用返回 Python 对象供后续程序操作；每次调用前预置**命名空间摘要**（变量名/类型/形状，小标量内联显示）；内核采用 fail-closed 沙盒（事件日志只读、对数据库/文件/网络/工具的访问需显式声明能力）。

### 2.3 模型编程接口（四类操作）

| 操作 | 接口 | 作用 |
|---|---|---|
| LOCATE | `ms.search(query, k, ...)` | BM25 检索候选事件，支持结构化范围/类型/时间过滤，命中项带 `seq` 地址 |
| MATERIALIZE | `ms.expand(seq)` / `ms.expand(lo, hi)` | 精确恢复单个事件或序列区间，加载懒句柄后的外部化负载内容 |
| COMPUTE | 普通 Python、数据库/文件/工具接口 | 过滤、连接、聚合、解析更新、检查产物、构造派生状态 |
| EXPOSE | `print(value)` | 将有界投影作为观测返回；其余一切留在内核中 |

关键机制：`exec` 决定如何访问和改写环境，`print` 决定哪个投影进入模型下一轮的工作视图；模型可写代码搜索/展开事件日志、调用工具、对驻留变量做复杂计算，只有显式打印的内容跨过观测边界进入上下文。

### 2.4 可恢复的上下文驱逐（Algorithm 1：Recoverable context eviction）

- 触发条件：工作视图超过预算 ρC。
- 流程：
  1. 将活跃轮次持久化到事件日志；
  2. 保护活跃轮次、近期尾部、最新工具结果；
  3. 按**恢复成本递增**的顺序驱逐：先折叠已完成的工具负载（单个 seq 指针即可恢复），再移除整个区间（仅在仍超预算时）；
  4. 被驱逐区间的**头条（headlines）**进入分层驱逐索引 I（每层至多 k 块；满后新块保留全细节、旧 k−1 块各折叠为一行并合入上一层），索引规模 O(k log_k n)；
  5. 被驱逐内容**留在事件日志中原样可寻址**，不丢失。
- **头条作为导航锚点**：每次响应时模型写一句简短头条（任务、已验证状态、下一步行动、状态），绑定到该事件被分配到的 seq 地址，形成"地址→头条"映射；被驱逐区间的头条保留在分层索引中，使智能体能直接导航到被驱逐区域而非全文搜索。
- 与搜索互补：搜索只能恢复智能体想到要问的内容，索引则让它意识到自己看不到的历史。

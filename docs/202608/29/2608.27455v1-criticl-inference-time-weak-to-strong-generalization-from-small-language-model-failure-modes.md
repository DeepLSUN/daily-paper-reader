## 摘要
近期推理时扩展的进展显著提升了大语言模型（LLM）的推理性能。然而，这些方法通常依赖重复生成或外部验证。为解决这一局限，我们提出了CritICL，一种新颖的推理时框架，在保持高效率的同时改进推理。我们的关键洞见是，同一模型家族内，LLM的失败模式在不同模型规模间表现出结构化模式。CritICL没有将失败视为不期望的输出，而是将其作为指导来源。具体而言，我们利用从较弱模型中获取的失败模式，并通过基于批评的上下文示例将其纳入推理过程。我们提出了两种变体：CritICL-dynamic，自适应地预测特定输入的失败模式并检索批评；以及CritICL-static，使用全局失败模式档案提供稳定指导。实验结果表明，CritICL持续优于标准上下文学习，并达到与测试时扩展方法相当或更优的性能，同时所需生成次数显著更少、令牌成本更低。代码可在 https://github.com/umwyf/CRITICL 获取。

## Abstract
Recent advances in inference-time scaling have significantly improved the reasoning performance of large language models (LLMs). However, these methods typically rely on repeated generation or external verification. To address this limitation, we introduce CritICL, a novel inference-time framework that improves reasoning while maintaining high efficiency. Our key insight is that LLM failure modes exhibit structured patterns across model scales within the same family. Instead of treating failures as undesirable outputs, CritICL leverages them as a source of guidance. Specifically, we utilize failure modes derived from weaker models and incorporate them into inference through critique-based in-context examples. We propose two variants: CritICL-dynamic, which adaptively predicts input-specific failure modes and retrieves critiques, and CritICL-static, which uses a global failure mode profile to provide stable guidance. Experimental results show that CritICL consistently outperforms standard in-context learning and achieves performance competitive with or superior to test-time scaling methods, while requiring significantly fewer generations and lower token cost. Code available at: https://github.com/umwyf/CRITICL

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：推理时扩展（Inference-time Scaling）已成为提升 LLM 推理性能的重要手段，典型方法包括重复采样（Self-consistency）、迭代自修正（Self-Reflection）和外部验证（LLM-as-Judge）。
- **核心问题**：现有推理时扩展方法高度依赖**多次生成或外部验证**，带来高昂的推理成本；已有的弱到强推理时方法也通常需要弱模型在线提供监督，额外增加开销，且未充分利用“模型如何失败”这一潜在可迁移信号。
- **核心洞见**：同一模型家族内，不同规模模型的**失败模式（failure mode）分布具有高度一致性**——弱模型的结构化失败模式可以有效迁移并指导强模型。
- **整体含义**：论文将弱模型的失败产物从“无用输出”重新定义为“可复用的指导资源”，提出一种**高效、低成本的推理时弱到强泛化（Weak-to-Strong Generalization）范式**，在不依赖重复生成或外部验证的情况下提升强模型推理能力。

## 2. 方法论

### 2.1 核心思想

- 构建一个结构化的失败批评库 **CritBank**，其中每个条目包含：问题、错误响应、失败模式标签、自然语言批评。
- 在推理时，通过检索与目标问题或目标模型最相关的失败批评示例，以**上下文学习（ICL）** 方式注入提示词，引导强模型规避常见推理陷阱。

### 2.2 CritBank 的构建（离线阶段）

- **响应生成**：对训练集（GSM8K + MATH，共 15K 问题），使用多个同族小型模型（如 Qwen2.5-1.5B/3B/7B-Instruct）以思维链（CoT）提示生成 5 个响应，仅保留错误响应。
- **失败模式与批评生成**：使用前沿模型 GPT-4o-mini 为每个错误响应生成最多 5 个候选失败模式标签，并生成一句自然语言批评；随后通过聚类（基于 Didolkar et al. 2024 的方法）合并语义冗余标签，得到代表性失败模式集合。
- **形式化定义**：
  - 批评函数 \(C(q,r)\) 映射问题-响应对到结构化批评；
  - 标签函数 \(L(q,r)\) 为每个问题-响应对分配失败模式子集；
  - 逆映射 \(L^{-1}(l)\) 用于按失败模式检索所有相关条目。

### 2.3 两种推理时变体

- **CritICL-dynamic**：
  1. 给定新问题 \(q'\\)，先让目标模型预测该问题可能出现的失败模式（最多 5 个）；
  2. 用预测的失败模式集合从 CritBank 检索批评示例；
  3. 将检索到的示例拼入提示词，引导模型生成答案。
- **CritICL-static**：
  1. 聚合同族多个弱模型的失败模式统计，构建**全局失败模式档案**（family-level failure mode profile）；
  2. 选取出现频率最高的前 T 个失败模式作为检索目标；
  3. 从 CritBank 检索对应批评示例，用于所有输入（输入无关、稳定指导）。

### 2.4 失败模式驱动的示例选择（Failure Mode-Based Sample Selection）

- 候选集：所有失败模式标签与目标集合 \(S\) 有交集的样本；
- 匹配分数：\(score(q,r;S)=\sum_{l\in L(q,r)\cap S} w(l)\)，未加权时即为重叠标签数量；
- 贪心选择：按分数降序排序，优先选择能覆盖未覆盖目标失败模式的示例，直到达到预算 \(K\)。

- **失败模式具有跨规模稳定性和可迁移性**：同族模型失败模式分布高度一致，聚合多个弱模型得到的统计比单个弱模型更贴近强模型的真实失败分布（Qwen 聚合 Spearman 0.91、Llama 聚合 0.88）。

## 摘要
基于大规模语言模型（LLM）的智能体应用通常面临较高的响应时间。投机解码是一种在不影响生成质量的前提下提升LLM智能体推理效率的有前景的解决方案。然而，最先进的投机解码算法在大批量处理场景下表现出显著的性能下降，限制了其在实际智能体应用中的部署效果。在本研究中，我们首先对LLM智能体的投机解码进行了系统性分析，并确定了导致加速效果下降的两个主要因素：投机令牌的高拒绝率，以及动态令牌预算的利用不足。基于这些观察，我们提出了AgentSpec，一种针对LLM智能体现有方法局限性的投机解码算法。AgentSpec采用了结构隔离草拟方法，将投机限制在智能体工作流的语义连贯片段内，减少了对无关语义路径的草拟，从而实现了极低的拒绝率。此外，AgentSpec还采用了冗余感知的预算分配方法，利用智能体级信息更好地在推理过程中利用动态空闲令牌预算。我们在vLLM中基于五种不同工作负载和四种不同LLM家族的四种模型进行了实现和评估。实验结果证明了AgentSpec相对于最先进方法的优越性。

## Abstract
Large language model (LLM)-based agent applications often incur high response time. Speculative decoding is a promising solution to improve the inference efficiency of LLM agents without impacting generation quality. However, state-of-the-art speculative decoding algorithms exhibit substantial speed degradation under large batch sizes, limiting their effectiveness to deploy in real-world agent applications. In this work, we first present a systematic analysis of speculative decoding for LLM agents and identify two dominant factors of speedup degradation: high rejection rate of speculative tokens, and under-utilization of dynamic token budgets.B ased on these observations, we propose AgentSpec, a speculative decoding algorithm that addresses the limitations of existing methods for LLM agents. AgentSpec incorporates structure-isolated drafting that constrains speculation to semantically coherent segments of the agent workflow, reducing the drafts of irrelevant semantic paths and achieving an extremely low rejection rate. Moreover, AgentSpec adopts redundancy-aware budget allocation that exploits agent-level information to better utilize the dynamically-free token budget during the agent inference. We implement and evaluate AgentSpec on five different workloads and four different models from four different LLM families in vLLM. Our results demonstrate the superiority of AgentSpec over state-of-the-arts.

### 二、方法论：核心思想、关键技术细节与算法流程

#### 核心思想
AgentSpec 是模型无关（model-free）的投机解码算法，创新点体现在两个相互协同的组件上：**结构隔离草稿（Structure-Isolated Drafting）** 和 **冗余感知预算分配（Redundancy-Aware Budget Allocation）**。其核心直觉是：智能体工作流中同一语义块内的生成模式高度一致，跨语义块或跨查询的重复极少；因此将草稿检索限制在语义连贯的范围内可大幅降低拒绝率；同时，请求的历史冗余度可以很好地预测草稿被接受的可能性，指导动态令牌预算分配。

#### 关键技术细节

**（1）结构隔离草稿（Structure-Isolated Drafting）**

- 要求智能体应用随请求提供语义结构标识符：`Sᵢ = {aᵢ, qᵢ, Bᵢ}`，其中 `aᵢ` 为应用标识，`qᵢ` 为用户查询索引，`Bᵢ` 为语义块列表（由起始/结束字符串标签对定义）。
- 维护**缓存化的token-to-string映射表 M**（参考XGrammar设计），避免在解码过程中频繁调用分词器，实现高效的在线字符串转换。
- 维护一个轻量级**基于字符串的下推自动机（PDA）P**，增量式地跟踪当前请求所处语义块。
- 为每个语义块维护独立的**结构隔离缓存**，只从当前活跃语义块对应的缓存中检索草稿候选，避免跨语义/跨查询的无关内容。
- 实验结果：AgentSpec 的拒绝率仅为 26.4%，相比 EAGLE-3（53.3%）、SuffixDecoding（65.9%）和 NGram（88.7%）降低约 50% 以上。

**（2）冗余感知预算分配（Redundancy-Aware Budget Allocation）**

- 引入**冗余度分数（redundancy score）g** 来估计每个请求的草稿被接受的可能性：

  \[
  g(c, n) = \frac{c}{n} \cdot p(n), \quad p(n) = g_{\min} + (1 - g_{\min})(1 - e^{1-n})
  \]

  其中 `n` 为同一语义块和查询下检索到的候选延续数量，`c` 为就最常见前缀达成一致的延续数量，`c/n` 刻画候选间共识程度，`p(n)` 为低支持场景下的置信度衰减项，`g_min` 为最小置信度超参。

- 计算批次级投机预算：\[ B_t = \lfloor \alpha \cdot bz \rfloor \]，其中 `bz` 为批次大小，`α` 控制总体投机预算。

- 每个请求的草稿长度按冗余度分数比例分配：
  \[
  L_i = \max\left(|CT_i^*|, \ B_t \cdot \frac{g_i}{\sum_j g_j}\right)
  \]

  即优先为冗余度高的请求分配更多草稿令牌，同时保证每个请求至少能起草其最置信的前缀。

- 实验表明，AgentSpec 能持续将草稿数量控制在最大令牌预算 M(b) 以下并随批次增大逐步逼近，说明预算利用有效。

#### 算法流程（文字描述）

- **结构隔离草稿算法**：初始化 PDA → 对新生成的每个 token 做 token→string 映射转换 → 增量喂入 PDA 更新状态 → 确定当前语义块 → 从结构隔离缓存中检索该语义块的历史延续 → 提取候选草稿延续集合 CT。
- **冗余感知预算分配算法**：计算总投机预算 → 对每个请求统计候选延续数 n → 若 n=0 则冗余度分数为0 → 否则找出最常见延续前缀、计算共识数 c → 计算冗余度分数 g → 归一化分数并按比例分配每个请求的草稿长度。

### 七、优点

1. **问题定位精准**：通过建模 ∆T(b) 和系统分析，清晰揭示大批量下投机解码退化的两个物理瓶颈（拒绝率和预算利用率），为方法设计提供了扎实的理论基础。
2. **方法设计新颖且针对性强**：结构隔离草稿利用智能体工作流的天然语义结构约束草稿搜索空间；冗余感知预算分配引入了可解释的请求级信号（冗余度），两者均充分利用了智能体负载区别于普通负载的特性。
3. **严格保证无损（lossless）**：AgentSpec 不改变生成分布和模型参数，与投机解码的一致性理论兼容。
4. **实现系统级、生产可用**：在 vLLM 上实现并评估，扩展了三个附加参数（structure、query-id、agent-id），与现有服务引擎集成友好；token→string 缓存映射设计避免了分词开销。
5. **泛化性验证充分**：覆盖 4 种模型家族、5 种工作负载、多种 GPU、不同 batch size 和思考模式，证据链完整。
6. **复杂度与现有方法同阶**：时间复杂度 O(K·L) + O(K)，空间复杂度 O(H)，额外开销很小，适合实际部署。
7. **实验对比公平**：所有基线使用 vLLM 官方实现和默认配置；多次测量取平均。
8. **拆解分析深入**：包括执行时间分解、消融研究、尾延迟分析等，帮助理解性能提升的来源。

1. **需要智能体应用提供语义结构元数据**：结构隔离草稿依赖显式的语义块边界信息（如代码块、工具调用标签等），需要智能体应用与服务端之间的轻量级接口适配，实际部署存在一定的工程集成成本。
2. **无显式结构时性能取决于重复模式**：尽管 AgentSpec(N) 变体（无结构输入）仍优于基线，但其加速效果依赖于工作负载中可用的重复生成模式数量；对无结构化、极少重复的负载加速有限。

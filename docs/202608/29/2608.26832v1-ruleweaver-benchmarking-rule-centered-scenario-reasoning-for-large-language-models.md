## 摘要
大型语言模型（LLMs）越来越多地应用于专业领域，在这些领域中，有效利用领域专业知识通常需要在具体场景中对复杂规则进行推理。然而，现有基准仅部分评估了这种能力，因为它们要么侧重于输出级别的指令约束，要么忽略了规则在场景推理中扮演的不同角色。为了解决这些不足，本文引入了RuleWeaver，一个用于评估规则中心场景推理的基准构建框架。RuleWeaver从语料库派生的IF-THEN元规则出发，逐步将其增强为复杂规则，并将这些规则组合成以规则为中心的场景问答实例。除了最终答案的正确性，RuleWeaver还通过基于评分标准的答案质量、规则召回率和规则精确率支持过程级别的评估。对11个代表性LLM的实验表明，当前模型在处理复杂的规则中心场景推理方面仍然存在困难，即使表现最好的模型也只达到了最大评分标准的约50%。我们在以下网址提供代码和数据集：https://github.com/SharkSpicy-NLP/RuleWeaver。

## Abstract
Large language models (LLMs) are increasingly applied to specialized domains, where effective use of domain expertise often requires reasoning over complex rules in concrete scenarios. However, existing benchmarks only partially evaluate this capability, as they either focus on output-level instruction constraints or overlook the distinct roles that rules play in scenario reasoning. To address these gaps, this paper introduces RuleWeaver, a benchmark construction framework for evaluating rule-centered scenario reasoning. RuleWeaver starts from corpus-derived IF-THEN Meta Rules, progressively augments them into complex rules, and composes these rules into rule-centered scenario QA instances. Beyond final-answer correctness, RuleWeaver further supports process-level evaluation through rubric-based answer quality, rule recall, and rule precision. Experiments on 11 representative LLMs show that current models still struggle with complex rule-centered scenario reasoning, with even the best-performing model achieving only around 50% of the maximum rubric score. We make our code and dataset available here: https://github.com/SharkSpicy-NLP/RuleWeaver.

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）被越来越多地用于专业领域，而领域专业知识常以显式规则形式存在。模型在具体场景中需要**理解、筛选、应用并串联多条规则**，即“规则中心场景推理”（rule-centered scenario reasoning）。
- **现有基准的不足**：
  - **指令遵循类基准**（如 IFEval、WizardLM、FollowBench）主要检验输出格式、内容风格等表面约束，规则被当作“输出约束”而非“推理单元”，难以考察规则角色（如例外、冲突、优先级）。
  - **逻辑推理类基准**（如 RuleTaker、ProofWriter、FOLIO、RuleArena）预先给出规则，主要考察从规则推导结论的能力，但通常把规则视为同质化推理前提，忽略了规则在真实场景中的不同作用、依赖关系以及“从场景中识别相关规则”的需求。
- **本文目标**：构建一个能细粒度评估 LLM 对复杂规则“识别、角色理解、依赖感知应用、过程级解释”的基准框架，并揭示当前 LLM 在该能力上的真实水平。

## 2. 方法论

### 2.1 核心思想

RuleWeaver 是一个**可追踪的基准构建框架**，核心路径为：

> 从真实语料提取原子 IF-THEN 元规则（Meta Rule） → 渐进增强为复杂规则组 → 组合成规则中心场景问答实例 → 提供过程级评分协议。

### 2.2 元规则提取与过滤

- **元规则定义**：只有一个触发条件、一个结果的 IF-THEN 语句，是增强的最小单元。
- **语料来源**：四类真实文本——政策报告（GovReport）、操作指南（WikiHow）、合同条款（CUAD）、叙事文本（BookSum）。
- **提取与过滤**：文档经聚类、分块后用 LLM 提取 11,145 条初始元规则；经过格式/原子性校验、语义清晰度过滤、去冗余聚类和人工检查，最终保留 **200 条高质量元规则**。

### 2.3 规则渐进增强

- 每个元规则经过**五轮渐进语义增强**，形成包含多个变体的“复杂规则组”。
- 六种语义增强类型：
  - **ABSTRACT**：抽象化或泛化条件/结果；
  - **ADDITIVE**：补充条件或后果；
  - **NEGATE**：否定/反转条件或结果；
  - **EXCEPTION**：引入规则不适用的特殊情况（如 unless）；
  - **CONFLICT**：构造与原文冲突且优先级更高的规则；
  - **IRONCLAD**：加入必须强制遵守、不可被覆盖的约束。
- 每次增强记录三个可追溯属性：**增强类型、修改位置（IF/THEN/双侧）、逻辑组合方式（AND/OR/NOT）**。
- 前四轮使用温和类型（ABSTRACT/ADDITIVE/NEGATE），第五轮分支产生四个最终变体：一个温和类型 + EXCEPTION、CONFLICT、IRONCLAD 各一。最终形成 **200 个规则组、800 条复杂规则**。

### 2.4 场景 QA 构建

- **设置**：每条 QA 使用 5 条来自不同规则组的复杂规则，分为“同源”（同一语料）和“跨源”（四语料混合）两种设置。
- **四阶段构建**：
  1. **依赖规划**：采样一种问题类型（共七种，如多问题综合、确定性结论、事件预测、优先级仲裁、特例判断、反事实修订、行动方案），构建规则依赖图；
  2. **子场景生成**：为每个推理步骤生成局部场景片段，隐含触发事实，避免泄漏规则文本与结论；
  3. **最终合成**：合并为连贯场景、生成单一综合问题，并输出规则应用标注、规则逻辑链、实例专属评分 rubric；
  4. **迭代质量审查**：多轮检查结构有效性、规则覆盖、信息泄漏、依赖一致性，阈值≥80 分后接受，并辅以人工审查。

### 2.5 评分设计

- **Rubric 答案质量**：每个实例有 100 分 all-or-nothing rubric，覆盖 9 个维度（如问题理解、问题分解、引用格式、规则依据推理、依赖链对齐、异常/冲突处理、中间结论质量、最终答案一致性、无外部事实）。
- **规则召回率**：模型引用且命中的金标规则数 / 金标规则总数。
- **规则精确率**：引用并被判定正确应用的规则数 / 引用规则总数，未引用时记为 0。
- 三者分离，可区分“能否找出规则”“能否用对规则”“整体答案是否合格”。

- **语义类型难度**：CONFLICT（42.7%）和 IRONCLAD（40.6%）相对最好，EXCEPTION（34.6%）最弱；模型对例外结构的条件匹配很脆弱。
- **问题类型差异**：特例判断、确定性结论相对容易；优先级仲裁、行动方案最难。
- **过程级薄弱环节**：依赖链对齐（14.2%）、中间结论质量（21.0%）、问题分解（28.4%）、异常/冲突处理（30.4%）是最大瓶颈；表面约束（不引入外部事实、引用格式）完成度较高。
- **复杂度效应**：推理深度和依赖负载与分数负相关明显，深度从 2→4 步时平均分从 68.1 降到 31.2；分支结构影响不显著。
- **误差模式**：最常见的错误是多步整合（86.7%），其次是规则选择（72.2%）；即使在规则全命中的子集中，多步整合和引用应用错误仍超过 65%，说明“找到规则但不擅用规则与连接结论”是关键缺陷。
- **评分可靠性**：人类与 LLM judge 总分的 Spearman 相关约 0.76–0.84，替代 judge（Grok/Gemini）与主 judge 的模型级相关较高，支持自动评分的可用性。

## 7. 优点

- **框架原创性强**：首次系统地将“规则角色”概念引入基准构建，以可追踪的渐进增强方式生成复杂规则，归因清晰（增强类型、位置、逻辑操作均可回溯）。
- **场景贴近真实**：规则源自四类真实语料，场景 QA 由规则依赖图驱动，而非模板堆砌；质量审查和多轮优化降低信息泄漏。
- **过程级评估设计**：同时提供最终答案质量、规则召回、规则精确率三个互补指标，能诊断“不会找规则”“不会用规则”“不会串规则”的不同失败模式。
- **评估严谨性**：包括人-AI 评分一致性、替代 judge 稳健性、bootstrap 置信区间、误差类型细粒度标注等，保证了结论的可信度。
- **消融分析丰富**：规则池规模、场景复杂度、问题类型、语义类型等多维度分析，为后续研究提供了明确的能力地图。

## 8. 不足与局限

- **数据规模与覆盖有限**：仅 96 个 QA、200 个规则组，且语料来自四个英文来源；缺少多语言、机构内部规则、更多专业领域（如医疗、金融、法律条款）的覆盖。
- **场景模式受控**：当前采用显式规则池+静态单轮问答，而真实应用常需长文档检索、用户交互、多轮澄清和规则动态更新，基准生态位仍有拓展空间。
- **潜在偏差风险**：
  - 生成和评分依赖 LLM（DeepSeek 系列），尽管验证了与其他 judge 的相关性，但模型族偏差未完全排除；
  - 实例级 rubric 由 LLM 生成，虽然经过人工审查，但可能存在 rubric 维度设计的主观性；
  - 不同模型 API 推理模式、温度限制等软硬件条件不完全一致，可能引入微弱不公平性。
- **下游启发有限**：论文主要提供评测，未给出改进模型的具体训练方法；未来工作需要将评测结果转化为可操作的推理增强策略。

## 摘要
回答开发者关于软件仓库的问题是软件工程中一个关键但尚未充分探索的问题。虽然现有的仓库理解方法推动了该领域的发展，但它们主要依赖于表面级别的代码检索，缺乏对多文件、复杂软件架构进行深度推理以及将答案基于长距离代码依赖的能力。为了解决这些局限性，我们提出了DeepRepoQA，一种用于仓库级代码理解的新型问答（QA）框架。DeepRepoQA构建于一种智能体框架之上，其中LLM智能体通过对仓库结构进行系统性的树搜索来寻找答案。采用蒙特卡洛树搜索（MCTS）机制，使智能体能够动态搜索、导航和检查代码，从而实现对长距离代码依赖的有效多跳推理。在SWE-QA基准上的综合实验表明，与强基线相比，我们的方法取得了显著的性能提升，验证了系统性MCTS引导探索在多跳仓库推理中的有效性。

## Abstract
Answering developer questions about a software repository is a critical yet under-explored problem in software engineering. While existing repository understanding methods have advanced the field, they predominantly rely on surface-level code retrieval and lack the ability for deep reasoning over multiple files, complex software architectures, and grounding answers in long-range code dependencies. To address these limitations, we propose DeepRepoQA, a novel question answering (QA) framework for repository-level code understanding. DeepRepoQA builds on an agentic framework where LLM agents find answers through a systematic tree search over the repository structure. A Monte-Carlo Tree Search (MCTS) mechanism is employed to empower agents to dynamically search, navigate, and inspect code, enabling effective multi-hop reasoning over long-range code dependencies. Comprehensive experiments on the SWE-QA benchmark demonstrate substantial performance gains over strong baselines, validating the effectiveness of systematic MCTS-guided exploration for multi-hop repository reasoning.

## 2. 论文提出的方法论

### 2.1 总体框架
- 基于 agentic 框架，由四个专业智能体协作完成“感知 → 规划 → 执行 → 评估”的迭代循环。
- 核心创新：利用 MCTS 对搜索空间进行**系统性树搜索与反馈回传**，替代传统 ReAct 式智能体的单路径探索。

### 2.2 仓库解析与表示
- 使用 Tree-sitter 解析仓库，提取类、函数、代码片段等结构信息，并解析跨文件依赖。
- 采用**多级表示**：
  - 索引式查找：基于 AST 和目录结构支持精确定位（`FindClass`、`FindFunction`、`FindCodeSnippet`）。
  - 语义检索：用代码嵌入模型（`voyage-code-3`）对代码块向量化，支持概念级 `SemanticSearch`。

### 2.3 动作空间
- 共 6 个动作：`SemanticSearch`、`FindClass`、`FindFunction`、`FindCodeSnippet`、`ViewCode`、`Finish`。
- 动作设计兼具精确查找和语义搜索，保证探索的灵活性与可解释性。

### 2.4 四个智能体
- **感知智能体（Perception Agent）**：汇总当前轨迹和兄弟分支信息，生成去噪、紧凑的情境报告，识别冗余、盲区和待探索符号。
- **规划智能体（Planning Agent）**：基于情境报告生成候选动作，扩展现有搜索树节点，避免重复尝试。
- **执行智能体（Execution Agent）**：执行动作并做证据筛选，过滤无关片段、去重、压缩并附带精确文件与行号。
- **评估智能体（Evaluation Agent）**：对动作-观测对打分（0~100），并生成定性后续建议，分数回传更新树节点。

### 2.5 MCTS 流程（对应 Algorithm 1）
- 四个阶段：**选择 → 扩展 → 模拟 → 回传**。
- 选择阶段使用 UCT 公式平衡探索与利用：
  - UCT(s,a) = Q(s,a) + c·√(ln N(s)/N(s,a))
- 模拟阶段为单步四智能体循环，评估输出直接设为 Q 值，避免多步 rollouts 的高开销。
- 回传阶段沿路径更新 Q 值和访问次数，低价值分支被隐式剪枝。
- 终答生成：从最佳轨迹中提取答案，并要求至少一条带文件/行号的代码引用作为支撑。

- **效率**：DeepRepoQA 与 SOTA agent 计算开销相当，但答案质量更高。
- **分类型表现**：在 Why 和 How 类问题上表现最佳，说明其擅长设计意图和实现逻辑推理。
- **可靠性**：三个 LLM 判分者系统排名完全一致，与人评共识相关性 r=0.972，偏好一致性 88.2%。

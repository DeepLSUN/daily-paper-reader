## 摘要
大语言模型已从语言生成器演变为能够执行复杂、长期任务的自主智能体。这一演变催生了多种范式，包括提示工程（Prompt Engineering）以激发模型能力、上下文工程（Context Engineering）以管理信息访问、工具编排工程（Harness Engineering）以组织外部工具和资源，以及循环工程（Loop Engineering）以支持持续反思和自我改进。然而，随着任务日益复杂，个体智能面临根本性局限：许多任务需要异构专业知识、相互依赖的子任务、并行执行、独立验证和持久状态，这超出了任何单一智能体的组织能力。增强单个智能体的能力或上下文无法解决这种架构不匹配问题；相反，智能必须分布在专业化的智能体之间，并在系统层面进行组织。我们称之为系统智能（System Intelligence）：一个智能体系统将多个智能组件组织并协调成一个连贯、自适应、追求共同目标的整体的能力。实现系统智能不仅需要添加智能体，还需要明确的结构来组织工作、协调异构智能体并维护不断演化的执行状态。我们提出图工程（Graph Engineering），这是面向下一代智能体系统的新兴范式。与以往主要优化个体交互或智能体层面行为的范式不同，图工程构建显式、动态、演化的图结构，用以表示任务、智能体和系统状态。这些抽象为组织复杂目标、编排异构智能体、建模系统动态以及实现可扩展的智能体演化提供了统一基础。我们系统性地综述了面向LLM智能体的图工程的原理、方法和应用。相关论文、开源数据和项目收集于 https://github.com/DEEP-JLU/Awesome-Graph-Engineering。

## Abstract
LLMs have evolved from language generators to autonomous agents capable of complex, long-horizon tasks. This evolution has produced paradigms including Prompt Engineering to elicit model capabilities, Context Engineering to manage information access, Harness Engineering to organize external tools and resources, and Loop Engineering to support continual reflection and self-improvement. Yet as tasks grow more complex, individual intelligence faces a fundamental limit: many tasks require heterogeneous expertise, interdependent subtasks, parallel execution, independent verification, and persistent state, exceeding any single agent's organizational capacity. Augmenting one agent's capabilities or context cannot resolve this architectural mismatch; intelligence must instead be distributed across specialized agents and organized at the system level. We call this System Intelligence: an agent system's ability to organize and coordinate multiple intelligent components into a coherent, adaptive whole pursuing a shared objective. Achieving it requires more than adding agents; it demands explicit structures to organize work, coordinate heterogeneous agents, and maintain evolving execution states. We introduce Graph Engineering, an emerging paradigm for next-generation agent systems. Unlike prior paradigms that mainly optimize individual interactions or agent-level behavior, Graph Engineering constructs explicit, dynamic, evolving graph structures representing tasks, agents, and system states. These abstractions provide a unified foundation for organizing complex objectives, orchestrating heterogeneous agents, modeling system dynamics, and enabling scalable agent evolution. We systematically review the principles, methodologies, and applications of Graph Engineering for LLM agents. Related papers, open-source data, and projects are collected at https://github.com/DEEP-JLU/Awesome-Graph-Engineering.

论文定义了智能体系统的形式化模型：

### 2.4 四个核心模块的技术细节

**（1）任务组织**
- **目标分解（Goal Decomposition）**：将高层目标表示为带依赖关系的子目标图（DAG或动态图），节点=子任务，边=前后序/数据/逻辑关系。代表方法：HuggingGPT、ReWOO、LLMCompiler、Plan-over-Graph、TDAG（动态分解）、Flow（模块化工作流）
- **工作流优化（Workflow Optimization）**：将语义子目标编译为可执行计算图（节点=LLM调用/工具/验证器等，边=调度依赖），并对工作流结构本身进行搜索和优化。代表：GPTSwarm（节点+边联合优化）、ADAS、AutoFlow、AFlow、A2Flow（学习抽象算子）、MermaidFlow（安全约束演化）、VFlow（外部验证器引导）、DyFlow/EvoFlow（运行时动态调整工作流）

**（2）智能体协调**
- **能力建模**：用图表示智能体与技能/工具/权限/可靠性的映射关系（节点=智能体/能力/资源，边=所有权/访问权限），支持能力感知的任务分配和运行时重配置。代表：DyLAN、MasRouter、SkillGraph、MaAS
- **团队组织**：将角色分配/委托路径/审查关系表示为组织结构图。包括链式（MetaGPT、ChatDev）、路由式（Magentic-One、WorkTeam）、扇出/扇入式（Mixture-of-Agents、MacNet）和动态重构式（Puppeteer、AgentNet、SwarmAgentic）
- **多智能体通信**：将运行时信息交换建模为动态通信图，支持按需建边、低价值边剪枝和拓扑优化。代表：G-Designer、AMAS、AgentPrune、AgentDropout、DyTopo、CARD、QueenBee Planner

**（3）运行时状态管理**
- **状态记录（State Recording）**：通过结构化表示、受治理的更新、作用域可见性和一致性管理四个方面，把执行历史变为可查询、可审计的状态。代表：Magentic-One的Task/Progress Ledgers、Graph of States、PatchBoard（schema+权限验证）、MemTX（事务性信念提交）
- **故障定位（Fault Localization）**：检测异常→追踪首个偏差→沿依赖链分析影响范围→形成诊断报告（可信剩余边界和恢复前沿）。代表：MAGE、Who & When、MAST（区分设计/协调/验证失败）、TraceElephant、CausalFlow
- **失败恢复（Failure Recovery）**：从恢复边界重放可恢复计算或补偿不可回滚的外部效应。代表：MAGE、AgentGit、Shepherd、DART、SagaLLM、RAC、Atomix

**（4）系统演化**
- 三个维度：*任务组织演化*（TDAG、Flow、DyFlow、EvoFlow）、*智能体协调演化*（AgentNet、SwarmAgentic、Meta-Team、DyTopo、CARD）、*状态管理演化*（ReCreate、SkillGraph、Swarm Skills、MemTX）
- 核心挑战：区分"单次执行轨迹内的运行时调整"与"跨执行的持久结构变更"，要求结构信用分配、图修改验证、提交/回滚机制

### 2.5 未来方向：本体工程（Ontology Engineering）

   - 三者相互耦合：任务组织定义"做什么"，智能体协调定义"谁来做"，状态管理定义"系统如何运行与演化"。缺一不可

4. **关键教训：系统级智能不取决于组件数量，而取决于关系的显式组织**
   - 增加模型数量或智能体数量本身**不等于**系统智能；真正的价值来自如何分解工作、绑定职责、共享状态以及诊断和恢复失败的方式

5. **系统演化尚处于早期阶段**
   - 当前应用普遍具备工作组织与团队协调能力，运行时状态管理也在加强，但持久性的系统演化（跨任务的结构改进）仍然罕见。大多数系统只在预定义的组织结构内调整执行路径，而非沉淀可复用的结构经验

6. **挑战与未来方向明确**
   - 图原生能力基座、自演化图系统、图原生智能体操作系统、隐私伦理，以及作为语义基础的本体工程，是下一步需要攻克的关键问题


## 7. 优点

## 8. 缺点与局限性

1. **作为综述缺少实证数据与横向对比**
   - 论文没有自己的实验，也未对各代表方法在图工程各维度上的效果做定量比较。读者无法判断哪种任务分解策略在何种场景下效果更好，哪类协调机制在什么规模下更高效。尽管这种取舍符合综述定位，但削弱了其"工程路线图"的实际指导力

2. **"图工程"的概念边界仍有一定模糊性**
   - 论文试图用"图"统一任务、智能体、状态三类对象，但"图结构"在不同层级、不同方法中的含义差异较大：有的是执行依赖图，有的是通信拓扑，有的是状态转换图，有的是组织结构图。论文将它们统一归入"图工程"，概念张力较大，可能导致读者对"到底什么是图工程"产生歧义

3. **对物理世界与实时性考虑不足**
   - 论文虽在第 9 节提到数字智能体与物理机器人系统的应用，但总体讨论仍以纯数字环境（软件工程、知识处理、仿真）为主。对实时交互、物理不确定性、硬件约束等现实问题涉及较少，图工程能否拓展到具身智能体系统尚无充分论证

4. **系统演化的讨论偏重框架、缺少机制细节**
   - 系统演化是论文强调的"尚处早期"的关键方向，但对其核心技术难点（如结构信用分配、图修改验证、跨任务知识迁移等）的讨论多停留在分类与列举层面，未给出足够的算法思路或可行性论证，使得该部分更像"宣言"而非"指南"

5. **本体工程部分的展开过于单薄**
   - 论文将本体工程视为图工程的语义未来，但仅用一小节概括性介绍，未深入讨论本体的构建方法、与 LLM 自身语义能力的协同、以及维护成本等现实问题；与前文近 500 篇引文的细致度相比略显不足

6. **评估体系仍依赖传统基准，难以完整度量"系统智能"**
   - 论文列举了大量 Benchmark，但其中许多仍是单智能体任务的延伸，真正能反映"群体协作、动态演化、系统级鲁棒性"的评估工具仍然罕见。论文自己也承认，目前的评估资源仍与"系统智能"的核心主张不完全匹配

## 9. 个人思考与启示

- **"系统智能 = 关系工程"的观点很有启发**：该论文最重要的思想贡献可能不是"图"本身，而是把注意力从个体能力转向"组件之间的关系"——任务分解关系、角色委托关系、状态依赖关系、演化反馈关系。这与复杂系统科学中"结构决定功能"的基本直觉一致，也为 LLM 时代提供了一种系统设计的语言

- **图工程与传统工作流的本质区别在于"显式化 + 动态性"**：传统工作流是静态的、预定义的流程，图工程则强调运行时的自适应调整（任务动态分解、拓扑剪枝、状态驱动的重规划）。真正实现这种动态性，需要把图当作"可计算、可优化、可推理的对象"，而不仅仅是示意图

- **状态管理可能是当前最被低估的工程瓶颈**：多数多智能体系统仍把状态"隐式"保存在上下文或外部数据库中，缺少显式、可治理、可回滚的状态层。这也解释了为何故障定位和恢复类研究（MAGE、MAST 等）近年来快速增长。未来系统智能的成熟度很可能最先体现为状态管理能力的成熟

- **"系统演化"将重新定义智能体软件的维护方式**：如果系统能够通过执行经验自动调整其结构，那么"软件维护"将从"开发者修改代码"变为"系统自主重构+人工审计"。这不仅是技术问题，也涉及信任与责任分配，伦理与治理层面需要同步跟进

---

## 10. 总体评价

这是一篇视野宏大、组织清晰、覆盖面极广的综述论文。它提出的"图工程"概念并非简单的标签组合，而是对 LLM 智能体工程发展阶段的一次系统性拔高——从"让单个智能体更强"转向"让多个智能体协同得更聪明"。尽管在实证比较、概念精确性和前沿机制细节上仍有不足，但它成功地为该领域提供了一张统一的地图和一套面向未来的研究议程。对于希望系统了解多智能体系统工程全貌的研究者和工程师而言，这篇论文是极佳的起点；对于想探索系统演化、本体工程等新方向的读者，它也是一份有价值的"问题清单"。

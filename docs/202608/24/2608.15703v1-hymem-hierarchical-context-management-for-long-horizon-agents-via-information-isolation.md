## 摘要
大型语言模型（LLM）智能体在复杂的长期任务中往往表现不佳，因为其上下文会随着时间推移变得越来越杂乱。随着交互的累积，详细的执行轨迹和中间输出占据了上下文的绝大部分，使得模型难以保留和利用高层规划信息。大多数现有方法通过对单一的扁平上下文进行压缩或检索来解决这一问题，但这种方式并不能清晰地区分不同类型的上下文信息，往往导致推理性能下降。为应对这一挑战，我们提出了HyMem，一种分层框架，将智能体的上下文明确划分为不同的功能层。HyMem按功能组织上下文，将高层规划与执行及复杂分析分离。其独立的推理模块负责处理复杂的子任务，而不会将中间推理轨迹添加到持久的规划上下文中；其记忆管理模块通过结构化摘要确保任务进度在上下文刷新时得以保留。这些组件减少了冗余上下文的积累，保留了任务关键信息，并支持在有限的上下文窗口中进行连贯的长期推理。在GAIA和Browsecomp-plus上的实验表明，使用DeepSeek-V4时，HyMem的平均Pass@1得分分别为66.7%和61.3%，分别比最强基线高出6.1和4.7个百分点。进一步分析表明，HyMem有效控制了推理上下文的增长，使模型能够在复杂的长期任务中保持专注度和准确性。

## Abstract
Large language model (LLM) agents often perform poorly on complex, long-horizon tasks because their context becomes increasingly cluttered over time. As interactions accumulate, detailed execution traces and intermediate outputs dominate the context, making it difficult for the model to retain and use high-level planning information. Most existing methods address this issue through compression or retrieval applied to a single, flat context, which does not clearly separate different types of context information and often leads to degraded reasoning. To address this challenge, we propose HyMem, a hierarchical framework that explicitly separates the agent's context into distinct functional layers. HyMem organizes context by function to separate high-level planning from execution and complex analysis. Its isolated reasoning module handles complex subtasks without adding intermediate reasoning traces to the persistent planning context, while its memory management module preserves task progress across context refreshes through structured summaries. These components reduce redundant context accumulation, retain task-critical information, and support coherent long-horizon reasoning within a limited context window. Experiments on GAIA and Browsecomp-plus show that, with DeepSeek-V4, HyMem achieves average Pass@1 scores of 66.7% and 61.3%, outperforming the strongest baseline by 6.1 and 4.7 percentage points, respectively. Further analysis indicates that HyMem effectively controls the growth of the reasoning context, allowing the model to maintain focus and accuracy across complex, long-horizon tasks.

### 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：LLM 智能体在长时程、多步骤任务中性能显著退化，根本原因在于**上下文稀释（Context Dilution）**——随着交互累积，高密度的原始执行轨迹（工具输出、浏览日志、重试记录、失败尝试）逐渐淹没稀疏但关键的高层规划信号（目标、已验证事实、约束条件、剩余子目标），导致智能体在高复杂度任务中"迷失于细节"。
- **现有方法的不足**：已有方法（上下文压缩、外部记忆检索等）都是在**规划信号与执行痕迹已被混合后的扁平序列**上事后处理，无法从源头上区分信息的功能类型。压缩易丢失关键推理链，检索难以保持时序逻辑，最终只是缓解上下文长度这一表象，而非解决"信息类型混杂"这一病根。
- **论文定位**：提出 HyMem，将**信息隔离**确立为长时程智能体上下文管理的第一原则，从架构层面分离不同类型的上下文信息，而非仅做长度层面的压缩。

### 2. 论文提出的方法论：核心思想、关键技术细节

**核心思想：类型化上下文隔离（Typed Context Isolation）**

将智能体的上下文按功能划分为相互隔离的空间——规划、执行、子任务推理、记忆各自独立，跨空间只能传递受模式约束（schema-constrained）的结果消息，原始轨迹和中间推理不得直接进入主规划上下文。

**框架组成（四个核心组件）**

- **Planner Layer（规划层）**：维护唯一的持久化决策上下文，包含系统提示、用户查询、三类记忆（episode/working/tool memory）以及先前子会话的类型化返回结果（H(p)）。仅能发出四种动作：`⟨TASK⟩`、`⟨ISO REASON⟩`、`⟨FOLD⟩`、`⟨ANSWER⟩`。
- **Executor Layer（执行层）**：接受规划层的工具指令，在**临时上下文空间**中执行有边界的工具调用循环。原始观测不直接返回给规划层，而是先经过相关性条件蒸馏算子 φ（去除导航文本、重复段落、格式化噪声与错误模板，保留实体、日期、数值、证据片段等），再综合为结构化返回 `R(e)`（含 findings、evidence、sources、status、gaps）。返回后临时上下文即被丢弃。
- **Isolated Reasoning Module（隔离推理模块）**：针对需要多跳分析、假设检验或冲突证据调和的复杂子任务，创建独立的推理上下文空间。其内部中间推理轨迹保持私有，仅返回结构化结论 `R(iso)`（含 conclusion、supporting facts、confidence κ、assumptions），随后上下文被丢弃。
- **Memory Management Module（记忆管理模块）**：维护三种可重写的结构化记忆——episode memory（已完成里程碑、已验证事实）、working memory（当前目标、未解决缺口、下一步计划）、tool memory（有效工具使用模式、失败查询、工具注意点）。通过折叠算子 Φ 定期重写全部记忆，并采用**不对称注入策略**：规划层接收全部三类记忆、隔离推理接收三类记忆、执行层仅接收工具记忆。

**关键机制与公式**

- 规划层状态更新满足信息边界条件：`I(C(p)；X_t | R_t) ≈ 0`，即执行痕迹与规划上下文之间的条件互信息近似为零——通过界面设计强制执行而非可微优化。
- 折叠触发器（Fold Trigger）为确定性条件组合：上下文利用率 > 0.99、执行器调用 ≥ 5 次、连续失败 ≥ 3 次、规划轮次 ≥ 8 次或工具调用 ≥ 10 次即触发记忆压缩。
- 训练无关（training-free）：仅包装冻结的基座 LLM πθ 于推理时运行，即插即用。

### 6. 论文的主要结论与发现

- **性能提升**：DeepSeek-V4 背骨下，HyMem 在 GAIA 平均 Pass@1 达 **66.7%**（超过 ReAct 10.1 个百分点、超越最强基线 ReSum 6.1 个百分点），在 Browsecomp-plus 达 **61.3%**（超 ReAct 4.7 个百分点）；最难题目上增益最大——Browsecomp-plus hard 从 ReAct 的 14.0% 提升至 30.0%。
- **难度模式**：HyMem 在需要持续规划、证据累积和多步验证的困难任务上收益最大；在简单、短轨迹任务上与 ReAct 差距不大。

- **隔离的贡献**：单独移除隔离推理模块导致 GAIA 上 Pass@1 下降 18.6 个百分点、Browsecomp-plus 下降 5.0 个百分点；单独移除记忆管理模块导致 GAIA 下降 18.6 个百分点、Browsecomp-plus 下降 9.0 个百分点——证明两个模块缺一不可。
- **上下文行为**：HyMem 的总上下文仍持续增长，但**持久化规划层上下文增长显著更慢**——执行细节和中间推理停留在临时空间中，仅结构化返回与重写记忆进入规划层，从而支持扩展探索而不累积冗余。
- **资源效率**：性能收益并非通过无节制的token消耗或工具调用换取——在性能-资源权衡曲线上 HyMem 位于有利区域。

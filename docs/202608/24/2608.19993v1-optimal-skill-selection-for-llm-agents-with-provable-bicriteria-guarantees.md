## 摘要
将可复用技能文档加载到有界上下文窗口现在是大型语言模型（LLM）智能体获取任务特定能力的主要方式，这使得技能选择成为任务性能和 token 成本的一阶决定因素。然而，当前智能体通过语义相关性独立评分技能，并通过 top-k 或贪婪打包组装集合，对所选集合没有质量保证或成本意识。因此，冗余或选择不当的技能会浪费稀缺的上下文 token，甚至可能降低性能。我们首次对所选技能集如何影响执行结果进行建模，并将技能选择视为一个优化问题：在硬 token 预算下选择技能集，以最大化单调子模收益减去上下文惩罚。针对这个问题，我们开发了 Best Prefix Selection (BPS)，一种多项式时间算法，并据我们所知，证明了首个技能选择性能保证：一个双准则 (1-1/e,1) 近似，其收益系数在多项式时间内是最优的。在一个污染控制的 BigCodeBench 变体上，BPS 优于所有基线，在比最强发布路由器少 28% token 的情况下，达到 0.73 的实测任务成功率，而发布的技能路由器、文本检索器和执行器自身选择为 0.20--0.52。

## Abstract
Loading reusable skill documents into a bounded context window is now the primary way large language model (LLM) agents acquire task-specific capabilities, which makes skill selection a first-order determinant of task performance and token cost. Yet current agents score skills independently by semantic relevance and assemble the set by top-$k$ or greedy packing, with no quality guarantee or cost awareness on the selected set. As a result, redundant or poorly chosen skills waste scarce context tokens and can even degrade performance. We give the first model of how the selected skill set shapes execution outcomes and cast skill selection as an optimization problem: choose a skill set under a hard token budget to maximize a monotone submodular benefit minus context penalty. For this problem, we develop Best Prefix Selection (BPS), a polynomial-time algorithm, and prove, to our knowledge, the first performance guarantee for skill selection: a bicriteria $(1-1/e,1)$ approximation whose benefit coefficient is optimal in polynomial time. On a contamination-controlled BigCodeBench variant, BPS outperforms all the baselines, reaching $0.73$ measured task success versus $0.20$--$0.52$ for released skill routers, text retrievers, and the executor's own selection, on $28\%$ fewer tokens than the strongest released router.

## 1. 核心问题与整体含义（研究动机与背景）

**问题背景**：现代 LLM 智能体（如 Codex、Claude Code）普遍采用"技能文档"机制来获取任务特定能力。系统首先从技能库中选择相关技能，再将所选技能文档注入有界上下文窗口供执行器使用。技能库规模已达数千乃至数万条目，而上下文窗口有限。

**核心问题**：现有技能选择机制普遍存在三个严重缺陷：
- **独立打分**：仅按语义相关性对每个技能独立评分，忽略了技能之间的能力互补性和冗余性；
- **无成本意识**：不考虑所选技能文档注入后占用的上下文 token 成本；
- **无质量保证**：采用 top-k、贪婪打包等启发式规则，没有任何理论性能保证。

**实证动机**：论文用 Qwen3-32B 在受控实验中展示了：
- 仅覆盖单一能力的技能集成功率为 0%，而覆盖全部所需能力的互补技能集成功率达 93%；
- 在能力已覆盖后，添加冗余技能仅提升 1 个百分点却消耗 225 tokens；
- 添加语义相关但任务无关的技能反而使成功率下降 23 个百分点。

**核心洞见**：技能选择是资源约束下的集合级决策问题，而非个体技能的排序问题。所选技能集需要覆盖任务所需的全部能力维度，同时最小化上下文代价与冗余。

## 2. 方法论：核心思想、技术细节与算法流程

### 2.1 结构化模型（第 3 节）

**潜在能力空间建模**：
- 引入 $d$ 维潜在能力空间，每个技能 $s_i$ 具有能力供给向量 $\mathbf{u}_i \in \mathbb{R}_+^d$；
- 查询 $q$ 具有能力需求向量 $\mathbf{w}_q \in \mathbb{R}_+^d$；
- 每个能力维度使用非降凹函数 $h_k$（具体取 $1-e^{-x}$）建模收益递减效应。

**目标函数**（公式 6）：
$$F_E(q, S) = G_E(q, S) - \kappa_E \cdot \ell(S)$$

其中：
- **收益项** $G_E(q, S) = \sum_{k=1}^{d} \eta^E_k w^q_k \cdot h_k(\lambda^E_k \sum_{i \in S} u_{i,k})$ 是**单调子模函数**，建模能力覆盖的互补性与冗余性；
- **惩罚项** $c_E(S) = \kappa_E \cdot \ell(S)$ 是线性上下文代价惩罚；
- **硬约束** $\ell(S) \le B$（token 预算）。

**优化问题**（公式 7）：$\max_{S: \ell(S) \le B} F_E(q, S)$

该问题包含 NP-hard 的预算最大覆盖问题作为一个特例，且目标函数可能为负，排除了常数乘法近似的可能性，因此需要双准则保证。

### 2.2 参数学习与误差传递

- 通过两个能力编码器估计有效需求 $\tilde{\mathbf{w}}_q$ 和有效供给 $\tilde{\mathbf{u}}_i$；
- 使用查找表（281 参数）或神经编码器实例化；
- **Proposition 1（误差传递）**：若拟合目标与真实执行效果均匀误差不超过 $\varepsilon$，且优化误差为 $\delta$，则端到端选择遗憾不超过 $2\varepsilon + \delta$。

### 2.3 BPS 算法（Algorithm 1）

**流程**：
1. **预处理**：丢弃超过预算的技能；初始化前缀池 $\mathcal{P}$；
2. **种子枚举**：枚举所有大小 ≤ 2 且可行的技能子集作为种子；
3. **密度贪婪扩展**：从每个种子出发，反复添加边际收益/token 密度最高的技能，直到预算耗尽；
4. **记录所有前缀**：沿每条贪婪链记录每个可行的前缀集合；
5. **最优选择**：从前缀池中选择最大化拟合目标 $\hat{F}$ 的集合作为输出。

### 2.4 理论保证（Theorem 1）

**核心定理**：BPS 输出的技能集 $S_{\text{BPS}}$ 满足：
$$\hat{F}(S_{\text{BPS}}) \ge (1-1/e) \cdot \hat{G}(T) - \hat{\kappa}\ell(T), \quad \forall T \in \mathcal{F}_B$$

即 **双准则 $(1-1/e, 1)$ 近似**：收益系数达到 $1-1/e$（多项式时间内最优，紧接 Feige 1998 的 NP-hard 下界），惩罚系数为 1（精确保持完整惩罚）。

**证明关键技术——预算对齐插值**：利用预算约束和上下文惩罚共享同一长度坐标这一"对齐"结构，将分数层面（沿密度链轨迹）的界通过凸组合插值转化为实际记录的整数前缀的界。这个技巧避免了现有方法（Perrault et al. 2021）的加法精度损失。

**与现有工作的比较**：现有最接近的结果要么系数更弱（Gong et al. 2024 的 1/4；Guo et al. 2026 的 $(1-1/e)/2$）、要么有加法损失（Perrault et al. 2021 的 $\kappa\epsilon$）、要么输出分数解（Feldman 2021）。BPS 是首个同时具备正则化目标、背包约束、整数输出、零加法损失四个性质的结果。

**时间复杂度**：$O(dL^4)$，$L$ 为技能库规模（实际中为检索阶段后的候选集规模）。

## 3. 实验设计：数据集、基准与对比方法

### 3.1 污染控制的基准构建（第 5.1 节）

**动机**：现有公开基准（如原始 BigCodeBench）无法衡量技能选择，因为强大的执行器（Qwen3-32B）仅凭预训练知识就能在 85% 的任务上通过。

**构建方法**：
- **私有模块替换**：将 BigCodeBench 的标准库替换为 16 个私有模块（对应 $d=5$ 个能力族），API 名称和实现细节经修改，无法从任务描述猜测，仅在技能库中记录；
- **任务准入门控**：仅当私有模块方案通过测试、而标准库方案及所有单能力混合方案均失败时才准入，确保任务必须依赖全部所需能力。不足三分之一的派生任务通过该门控；

## 6. 主要结论与发现

1. **理论层面**：BPS 在多项式时间内实现了技能选择问题的紧致双准则 $(1-1/e, 1)$ 近似，收益系数在多项式时间内不可改进——这是技能选择领域**首个可证明的性能保证**；
2. **模型有效性**：结构化目标仅从 pass/fail 执行记录即可准确预测留出技能集的成功率，预测误差在 1 个百分点以内；恢复隐藏能力覆盖矩阵的 AUC 达 0.996，且所有可解释替代模型（Additive、Shapley、Datamodels、Linear response）性能显著落后；
3. **优化质量**：BPS 在全部 80 个实例上达到精确最优；top-k / MMR / DPP-MAP 仅在 <10% 的实例上达到最优，平均差距比集合评分规则大近两个数量级；
4. **端到端效果**：BPS 达到 0.73 实测成功率，远超所有部署系统（0.20-0.52），且比最强发布路由器少注入 28% 的 token；神经编码器版本也以 0.68 成功率、716 tokens 超越所有部署系统（除自身查找表版本）；
5. **误差传递**：端到端选择遗憾可分解为拟合误差和优化误差，两者分别有界。

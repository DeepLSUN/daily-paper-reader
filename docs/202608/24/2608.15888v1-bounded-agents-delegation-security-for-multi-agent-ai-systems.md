## 摘要
基于LLM的智能体可以代表用户访问云服务、调用工具或调用其他智能体。在会话开始时，智能体的权限被设定但保持静态，每个请求独立评估，不考虑先前的操作。在其权限范围内，智能体可能违背委托任务行动，将单独允许的操作组合成被禁止的结果，或在未限制的情况下将权限委托给子智能体。提示注入仅在智能体有权执行此类操作时才构成风险；因此，这是一个授权架构问题，而不仅仅是模型问题。智能体主体验证链（APC）跟踪从一个主体到下一个主体的委托权限。APC使用六项授权检查，根据累积的会话状态评估每个请求。APC向前传递并限制委托范围和预算。利用组合闭包，APC根据先前的操作检查请求，以防止被禁止的组合，并在模型外部强制执行决策。我们证明了APC实现的爆炸半径单调性和组合健全性；组合健全性仅限于在完整限制集和串行准入下被禁止的组合。我们评估了3,154个实例，包括InjecAgent、AgentDojo和ASB。我们的受损模型评估通过插入真实攻击调用（在第一个合法工具调用之后）独立于模型行为测试APC。AgentDojo的泄露在所有四个领域从75-100%降至0%；APC阻止了所有544个InjecAgent数据窃取案例。意图绑定将破坏率从38.6%降至4.0%，操纵率从90.5%降至12.1%。授权延迟在空闲主机上第99百分位为0.24毫秒；在949对AgentDojo任务-注入对中，两种设置下的效用量分别低8.6和13.9个百分点。实现、评估工具和数据公开可用。

## Abstract
LLM-based agents can act on behalf of a user to access cloud services, call tools, or invoke agents. At session start, the agent's permissions are set but remain static, and each request is evaluated independently, without considering prior actions. Within its permissions, an agent may act contrary to the delegated task, combine individually permitted actions into a prohibited outcome, or delegate authority to a sub-agent without limiting it. A prompt injection poses a risk only if the agent has authority to perform such actions; this is therefore a problem of authorization architecture, not just the model. The Agentic Principal Chain (APC) tracks delegated authority from one principal to the next. APC evaluates each request against the accumulated session state using six authorization checks. APC carries forward and restricts delegated scope and budgets. Using composition closure, APC checks requests against prior actions to prevent prohibited combinations and enforces the decision outside the model. We prove Blast Radius Monotonicity and Composition Soundness for APC implementations; Composition Soundness is limited to prohibited combinations under a complete restriction set and serialized admission. We evaluated 3,154 instances including InjecAgent, AgentDojo, and ASB. Our compromised-model evaluation tests APC independently of model behavior by inserting the ground-truth attack call after the first legitimate tool call. AgentDojo exfiltration fell from 75-100% to 0% across all four domains; APC blocked all 544 InjecAgent data-stealing cases. Intent binding reduced destruction from 38.6% to 4.0% and manipulation from 90.5% to 12.1%. Authorization latency was 0.24 ms at the 99th percentile on an idle host; across 949 AgentDojo task-injection pairs, utility was 8.6 and 13.9 percentage points lower in the two settings. Implementation, evaluation tools, and data are publicly available.

# 中文总结：Bounded Agents: Delegation Security for Multi-Agent AI Systems

## 1. 论文的核心问题与整体含义

- 核心问题：在基于 LLM 的多智能体系统中，智能体被赋予了静态、会话级的权限，且每个请求被独立评估，不参考先前操作。这导致智能体可能：
  - 在权限范围内执行与委托任务相悖的操作（意图违背）；
  - 将多个单独允许的操作组合成被禁止的结果（不安全组合，如"读取机密文档+发送外部邮件"实现数据泄露）；
  - 向子智能体委托权力时不做衰减，造成委派范围扩张。
- 核心论点：提示注入（prompt injection）的威胁本质上是一个**授权架构问题**，而非仅模型鲁棒性问题。只要智能体获得某种权限，注入就可能诱导其行使该权限；如果基础设施禁止了相关操作组合，则即使模型完全被攻破也无法造成相应危害。
- 作者提出 **APC（Agentic Principal Chain，智能体主体验证链）**：在模型运行时之外，跟踪委托链，将范围衰减、预算限制、组合闭包、意图绑定等策略以基础设施强制力执行，从而为多智能体授权安全提供可验证、可部署的机制。

## 2. 论文提出的方法论

- 核心思想：
  - 将授权主体从"单个实体"扩展为"按会话绑定的主体链"——用户 p₀ → 编排者 p₁ → 子智能体 p₂ → ... → 工具。
  - 会话级授权状态由基础设施维护并加密签名，模型输出永远不能修改该状态。
  - 每个委托 hop 都执行范围衰减（Scope narrowing），只缩小不放宽。
  - 引入**组合闭包（Composition Closure）**：限制哪些动作类型组合在会话内被禁止，检查针对会话历史，而非单动作。
- 关键模型要素：
  - **授权范围 S = (R, A, D, X)**：资源、动作类型、数据分类、禁止组合。委托时取交集：S₁ ⊓ S₂ = (R₁∩R₂, A₁∩A₂, D₁∩D₂, X₁∪X₂)。
  - **委托预算 B = (δ_max, β_max, ρ_max, σ_max, κ, cost_max)**：深度、爆炸半径、不可逆影响、敏感度、跨域组合、计算成本六个上限，只能递减。
  - **爆炸半径 BR_max(pᵢ)**：基于资源 blast(r) 与累计消费预算计算，用于证明单调性。
  - **会话意图 Ψ**：任务目标、资源模式、动作序列、负向约束等，在会话创建时由用户预声明，模型不可修改。
  - **先验动作状态**：由 PEP 维护的会话内已执行动作类型集合与有序历史，用于组合约束检查。
  - **组合限制 X 与有序 k 元组 K**：X 禁止动作类型对；K 禁止有序子序列（可捕获绕过两两检查的分阶段泄露）。
- 六项准入条件（C1–C6）：
  - C1 身份绑定：运行时主体必须在主体验证链中；
  - C2 范围衰减与组合闭包（C2a 范围、C2b 组合、C2c 预算）；
  - C3 上下文与状态绑定：防重放；
  - C4 批准绑定：高影响动作需一次性、哈希绑定、会话绑定的批准令牌；
  - C5 证据提交：执行前必须能提交防篡改证据（SHA-256 哈希链），否则拒绝；
  - C6 意图绑定：与预声明意图比对（严格/警告/审计三种模式）。
- 运行时架构：PDP（策略决策点）+ PEP（策略执行点，作为工具网关/MCP 网关）分离，PEP 置于模型运行时之外，所有工具调用必经网关，任何未获准入的动作都不会到达后端。
- 正式结论：
  - **Blast Radius Monotonicity（定理4.6）**：每一 hop 可达爆炸半径单调不增。
  - **Composition Soundness（定理4.7）**：在限制集 X_eff 完整、串行准入、会话内 X 静态的假设下，没有可准入动作序列能产生被禁止结果。
  - **Ordered k-tuple soundness（命题4.2）**：禁止有序 k 元组永远不会被任何可准入序列实现。
- 这些属性被证明是"委托代数"的一般性质，适用于所有忠实实现，而非特定引擎。

## 6. 论文的主要结论与发现

- 提示注入的安全后果在很大程度上可归结为授权架构问题；由基础设施强制限制动作组合后，注入本身无法造成相应后果。
- APC 在受限模型假设下取得的主要结果：
  - AgentDojo 全部四个领域的泄露（exfiltration）从 75–100% 降至 0%；
  - InjecAgent 全部 544 个数据窃取用例被阻止；
  - 破坏（destruction）从 38.6% 降至 4.0%；操纵（manipulation）从 90.5% 降至 12.1%；
  - ASB 破坏性攻击从 100% 降至 0%；隐蔽攻击降至 30%（残余来自动作类型分类错误，可用正确标签消除）。
- 效用代价：交互模式下效用降低 8.6 个百分点（加权平均值），严格模式下 13.9 个百分点。
- 授权延迟极低：p50 0.049 ms，p99 0.24 ms（空闲主机）；99 个委托链场景全部符合预期。
- 形式化定理在指定假设下成立；组合闭包的有效性高度依赖 X 的完整性（移除一条组合约束后数据窃取 ASR 从 0% 升至 39.9%）。

## 7. 优点

- 清晰的架构观点：将安全边界从模型层移出，用确定性基础设施执行授权，避免"通过提示词约束模型"的脆弱模式。
- 组合闭包作为新颖的授权原语：补足了经典 RBAC/ABAC/OAuth 在"动作组合约束"上的缺失，并用定理与命题在受限条件下证明其健全性。
- 形式化结果具有一般性：不依赖特定引擎语义，适用于任何忠实实现。
- 实验证据层次丰富：确定性基准、实时 LLM 评估、受陷模型注入、自适应攻击、多跳委托链验证相结合，且公开实现与数据。
- 务实设计：可与现有企业 IAM/OAuth/策略引擎组合，提供分阶段部署（严格/警告/审计）路径。
- 对残余风险有明确分类（意图重叠、组合对缺失、单动作范围内滥用），并给出作者边界。

## 8. 不足与局限

- 实验覆盖局限：
  - 全部基准为合成环境，无生产部署数据；
  - 效用评估仅使用单个模型（Claude Sonnet 4.6），缺乏跨模型泛化测试；
  - 受限模型评估只注入一次攻击调用，未覆盖多轮交互、攻击者自适应反馈、长时跨会话攻击。
- 偏差风险：
  - 自适应攻击由作者自设计，可能无法代表所有真实攻击模式；
  - 与 Progent 的比较受限于当时可获得的工件版本（早期版本，且未包含其后来加入的 SMT 策略单调性机制）；
  - 动作类型分类（μ）依赖专家判断，不同安全团队可能得到不同限制集，影响结果的可复现性与公平性。
- 应用限制：
  - 单动作、参数级攻击（如同次调用内嵌入恶意 payload）不在 APC 覆盖范围内，需要参数校验等互补机制；
  - 仅在"首个合法调用后注入"前提下为 0% 泄露，论文明确这不是最坏情况；
  - 跨会话组合状态未跟踪（会话分裂攻击被设计为放行），需要持久化血缘状态；
  - 定理尚未机器检验（机械化证明是未来工作）；多主体同时被攻破时跨会话协调问题仍未解决。
  - 组合闭包依赖 X 的完整性与串行准入，实际部署中配置不完整仍会带来残余风险。

## 摘要
小型语言模型（SLMs）因其低延迟、低成本以及设备端隐私优势而成为智能体部署的有吸引力的选择，但在工具使用任务上，它们往往因训练数据稀缺且嘈杂而表现不佳。与大型模型不同，SLMs无法通过强大的容量来弥补低质量的监督信号，因此数据质量成为关键瓶颈。我们提出了Data Turnstile，一个开源框架，它接收用户定义的API规范，并为函数调用生成高质量的合成训练数据。Turnstile将多轮工具使用交互分解为受限的、逐步的生成过程，并包含验证和错误反馈循环，从而对API多样性、对话复杂性和输出正确性提供细粒度控制。我们通过Turnstile数据在两个具有挑战性的函数调用基准上展示了领域自适应的有效性。在BFCL单轮基准上，使用Turnstile数据微调且不采用思维链的Qwen3-0.6B达到了75.9%的总体准确率（而启用思考的基础模型为67.4%），尽管模型规模分别小3倍和7倍，但缩小了与启用思考的Qwen3-1.7B（78.4%）和Qwen3-4B（79.9%）的差距。在τ²-bench这一多轮智能体基准上，经过Turnstile训练的Qwen3-1.7B在电信领域达到了31.1%的pass^1，相比其6.6%的基础性能提升了4.7倍，并超过了比其大19倍的Qwen2.5-32B-Instruct（27.4%）。经过Turnstile训练的Qwen3-0.6B达到了24.6%，相比其3.5%的基础性能提升了7倍，接近了32B模型（大53倍）。我们发布了Data Turnstile以及一个涵盖1000多个API和10万多次多轮交互的数据集。

## Abstract
Small language models (SLMs) are attractive for agentic deployment due to low latency, reduced cost, and on-device privacy, yet they struggle with tool-use tasks where training data is scarce and noisy. Unlike larger models, SLMs cannot compensate for low-quality supervision through sheer capacity, making data quality the critical bottleneck. We present Data Turnstile, an open-source framework that takes user-defined API specifications and generates high-quality synthetic training data for function calling. Turnstile decomposes multi-turn tool-use interactions into constrained, stepwise generation with validation and error-feedback loops, providing fine-grained control over API diversity, conversation complexity, and output correctness. We demonstrate effectiveness of domain adaptation with Turnstile data on two challenging function calling benchmarks. On the BFCL single-turn benchmark, a Qwen3-0.6B fine-tuned on Turnstile data without chain-of-thought achieves 75.9% overall accuracy (versus 67.4% for the base model with thinking enabled), closing the gap with thinking-enabled Qwen3-1.7B (78.4%) and Qwen3-4B (79.9%) despite being 3$\times$ and 7$\times$ smaller respectively. On $τ^2$-bench, a multi-turn agentic benchmark, Turnstile-trained Qwen3-1.7B achieves 31.1% pass^1 on the Telecom domain, improving 4.7$\times$ over its 6.6% base and surpassing Qwen2.5-32B-Instruct (27.4%), a model 19$\times$ larger. Turnstile-trained Qwen3-0.6B achieves 24.6%, improving 7$\times$ over its 3.5% base and approaching the 32B model (53$\times$ larger). We release Data Turnstile along with a dataset spanning 1,000+ APIs and 100K+ multi-turn interactions.

- **研究背景**：函数调用大语言模型（Function-Calling LLMs）是智能体应用的关键技术，但可靠部署通常依赖大型专有模型（32B+甚至100B+），成本高且需云端部署。相比之下，小型语言模型（SLMs，<4B参数）具有低延迟、低成本、设备端隐私保护等优势，适合边缘部署。
- **核心挑战**：SLMs在工具使用任务上表现不佳，原因有二：（1）难以原生推理复杂智能体工作流；（2）无法像大模型那样容忍有噪声或低质量的训练数据。对于SLMs而言，监督微调（SFT）是获得智能体能力的主要途径，而数据质量成为关键瓶颈。
- **现有方法缺陷**：
  - 端到端生成方法（如ToolBench）通过单次LLM调用生成完整多轮对话，在长交互中易产生不自然对话、格式错误的API调用、参数幻觉和非理性执行输出。
  - 执行验证方法（如APIGen）需要真实API执行后端，适用范围受限。
  - 多数方法依赖专有的前沿模型生成数据，迭代和复现困难且成本高昂。
- **研究意义**：该论文通过开源框架解决了SLM函数调用训练数据缺乏的问题，使数据质量能够弥补模型容量差距，并支持在本地用开源模型生成数据，降低了数据生成的门槛和成本。

## 2. 方法论：Data Turnstile

### 2.1 核心思想

**将多轮工具使用交互分解为约束化的逐步生成过程。** 借鉴LLM通过分解复杂任务来处理问题的思路，Turnstile将函数调用数据的生成问题分解为一系列独立的、有约束且可验证的生成步骤，而非一次性生成完整对话。

### 2.2 技术细节

**交互模板（Interaction Template）**：核心抽象是一个DAG（有向无环图）T = (V, E, Θ)，其中：
- 节点 v ∈ V 对应一个**角色（Role）**——原子生成步骤
- 有向边 E 编码角色间的依赖关系
- Θ 定义生成规范与上下文（API定义、用户画像、质量检查）
- 一个模板可生成多个结构相同但内容不同的交互

**五种角色定义**：
| 角色 | 含义 |
|------|------|
| USER | 用户查询 |
| API CALL | API调用 |
| API OBS | API执行结果/工具响应 |
| ASSISTANT | 助手回复 |
| THINKING | 思维链推理（CoT推理） |

**生成流程**：
1. 按DAG顺序逐步生成各角色
2. 每步构造包含全模板结构上下文、已生成角色输出、当前角色生成上下文的提示
3. 生成后执行角色特定验证；失败则带错误反馈重试或中止

**质量保障机制**：
- **结构化验证**：序列级排序约束（API OBS必须跟在API CALL后；THINKING必须出现在API CALL或ASSISTANT之前）+ 每角色验证（API CALL必须符合schema、API OBS必须为合法JSON等）
- **生成前验证（Validate-before-Generate）**：生成新角色前，LLM检查前一个角色内容是否满足预定义错误标准，捕捉结构验证之外的问题（如参数幻觉、不合理的API观测）
- **错误反馈与提前中止**：失败时在预算内重试，携带错误反馈上下文；不可恢复时触发提前中止

**多样性控制**：
- **模板级**：不同模板结构（单轮单API、多API并行、多轮多API等）用权重控制分布
- **参数级**：每个模板实例关联特定的API名称、用户画像、场景等
- **动态模板扰动**：模拟API执行失败、信息不全需追问澄清等场景

**实现**：模块化Python包，四个核心组件：Role、Template、Builder、API Library。使用vLLM服务LLM。生成效率方面，逐步生成的总输出token量与单次生成相当，额外开销是每角色一次LLM调用和提示前缀，通过paged attention、continuous batching等机制摊销。

## 3. 实验设计

### 3.1 单轮基准：BFCL（Berkeley Function Calling Leaderboard）

**基准构成**：BFCL单轮测试集包含六个类别——Simple（单工具单API调用）、Multiple（多工具单API调用）、Parallel（单工具多API调用）、Parallel Multiple（多工具多API调用）、Relevance（有工具但不需要）、Irrelevance（无适用工具）。通过AST解析评估函数调用正确性。

**数据生成**：从四个API源生成数据集：
- xLAM和Glaive（开源数据集提取的API定义）
- Synthetic Domains（合成生成的API，1,025个）
- BFCL（从BFCL测试集派生）

**训练设置**：微调Qwen3-0.6B，评估点包括：
- Turnstile生成数据 vs 原始开源数据（Raw-OS）的对比——同一批API，仅生成方法不同
- 分布外（OOD）数据 vs 分布内（ID）数据的效果
- 有/无思维链（CoT）的影响

**对比对象**：Qwen3-0.6B/1.7B/4B基础模型（think/no-think两种推理模式），以及原始开源xLAM+Glaive数据的SFT。

### 3.2 多轮基准：τ²-bench

**基准构成**：τ²-bench是多轮对话智能体基准，评估策略遵循的工具使用、多步推理、错误恢复能力。选择其中Telecom领域进行评估，包含114个任务，14个API，依据策略文档运行。评估指标为pass^1（四次试验中任务成功的平均百分比）。

**数据生成**：从Telecom策略文档中提取17个问题和34个组合场景。关键概念：
- **Issue**：最小化指定用户问题、诊断步骤/工具、修复动作（4-8个生成角色）
- **Scenario**：多个Issue的组合，共享工作流（如认证）

**训练设置**：微调Qwen3-0.6B、Qwen3-1.7B、Qwen3-4B，对比基础模型和Qwen3-32B、Qwen2.5-32B-Instruct。还进行工具调用加权SFT（对API调用token施加5倍损失权重）和No-think（无CoT）变体实验。

## 6. 主要结论与发现

1. **数据质量可弥补模型容量**：Turnstile训练的Qwen3-0.6B（无CoT）在BFCL上达到75.9%，超越基础0.6B的think模式（67.4%），逼近3倍大的Qwen3-1.7B（78.4%）和7倍大的Qwen3-4B（79.9%）。在τ²-bench上，Turnstile训练的Qwen3-1.7B（31.1%）超越了19倍大的Qwen2.5-32B-Instruct（27.4%）。
2. **生成方法比数据源更重要**：Turnstile生成数据（70.4%）比原始开源数据（55.1%）提升15.3个百分点，使用的是完全相同的API定义。开源数据SFT会损害模型的拒答能力（0.6B从81%降至35.7%），而Turnstile通过动态无关注入恢复至77.5%。
3. **CoT的作用依赖任务类型**：
   - 单轮函数调用中CoT有害：产生"无关合理化"（推理出调用不适用API）和"参数过度思考"（错误解释模糊约束），无CoT训练优于有CoT训练（75.9% vs 72.8%）
   - 多轮智能体任务中CoT至关重要：无CoT模型性能骤降11-22个百分点。CoT支撑三个关键能力——假设形成、基于证据的进展、多问题发现
4. **API多样性带来泛化收益**：在Turnstile-OS基础上添加Synthetic Domains数据（OOD）提升+2.5pp，进一步添加BFCL API数据（ID）再提升+3pp，说明高覆盖API训练数据帮助模型泛化到未见schema。
5. **Tool-call加权SFT**：对工具调用token施加5倍损失权重，在三个模型规模上均有1.6-3.9pp的一致性提升。
6. **错误重试机制至关重要**：约22%成功交互经历过至少一次错误重试，87%错误由结构化验证捕获，其余为LLM评判捕获的幻觉。
7. **合成数据质量经人工验证**：正确性4.4/5、自然度3.8/5、基础性4.5/5。

## 7. 优点与亮点

1. **方法论创新**：将交互生成分解为DAG角色级生成，相比单次生成是结构性改进。每个步骤承担更简单的任务，让廉价开源模型即可可靠完成，消除对专有LLM的依赖。
2. **框架通用性与实用性**：支持从自定义API规范生成数据，也支持从策略文档生成符合策略的数据（τ²-bench演示）；开源且支持本地执行。模板抽象提供了细粒度的"结构化多样性"控制，以定量指标（Tool Balance、Call Sequence、Structure、Arg Richness）验证了多样性。
3. **实验设计严谨**：通过最干净的对照（同API不同生成方法）将性能差异直接归因于方法；广泛使用95%置信区间和消融研究。动态扰动使模型能处理API失败、信息不全等现实场景。分析了单次生成方法的结构不可检测缺陷（oracle信息泄漏、虚假成功声明），为分解方法提供了有力论证。
4. **高质量数据发布**：发布包括1K+ API和100K+多轮交互的合成数据集（有CoT轨迹），并通过人工评估验证质量。
5. **具备实际部署指导价值**：识别出CoT在不同任务类型中的差异，对延迟敏感的部署决策有意义。

## 8. 不足与局限

1. **实验覆盖有限**：τ²-bench仅评估Telecom一个领域，其他三个领域（Banking、Retail、Airline）未做验证，跨领域泛化性存疑。模型仅测试了Qwen3系列，缺少跨模型家族（如Llama、Mistral）的验证。
2. **对教师模型能力的依赖**：生成数据质量受限于教师LLM（Qwen2.5-32B-Instruct）的能力，更强的教师预计产生更好的数据。
3. **模板设计门槛**：模板构建需要领域专业知识，论文承认计划通过半自动化的模板构建来解决。当前模板分布的权重参数选择缺乏消融（为何50%单API、25%多API并行等）。
4. **统计显著性**：部分增益（如tool-call加权SFT的+1.6-3.9pp）在95%置信区间内不显著；OOD+ID对比的部分类别性能甚至下降（如Live Parallel类别从50.0%降至43.8%）。
5. **数据偏差风险**：作为合成数据管道，数据可能反映教师模型中的偏差或包含有害的工具使用模式。论文承认这一点但未做系统性分析。
6. **算力和训练细节不够透明**：训练时长、GPU资源消耗、多个超参数选择的依据等细节未充分披露，复现成本可能较高。
7. **基准类型有限**：BFCL和τ²-bench虽然具有代表性，但均未包含嵌套调用、多步编排等更复杂的函数调用场景（论文提到NESTFUL、T-Eval、GTA等基准但未使用）。

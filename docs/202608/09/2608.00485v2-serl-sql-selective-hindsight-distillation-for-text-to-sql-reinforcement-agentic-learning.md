## 摘要
近年来，文本到SQL系统越来越依赖多轮交互、执行反馈和强化学习。然而，现有的大多数方法仅将执行正确性作为轨迹级奖励，这为识别导致成功或失败的SQL决策提供了有限的指导。我们提出了SERL-SQL，一个用于多轮文本到SQL智能体的选择性基于执行的强化学习框架。SERL-SQL对同策略SQL交互轨迹进行采样，并使用仅训练阶段的教师模型，通过执行反馈对学生动作重新评分。由此产生的师生似然差距被转换为有界、掩码权重，仅对SQL和工具动作标记上的GRPO优势进行重新加权。这样，任务奖励保持了优化方向，而执行后见之明提供了局部化的信用分配。在BIRD、Spider和跨域基准上的实验表明，SERL-SQL取得了具有竞争力的性能，在BIRD-Dev上达到76.56%的执行准确率，在Spider-Test上达到89.92%。此外，我们基于奖励的选择策略接近最优Best-of-N上界，并始终优于基于一致性的选择，这表明SERL-SQL产生了高质量候选，可以通过轻量级的基于执行的奖励可靠地识别。我们的代码将在https://github.com/Ffunkytao/SERL-SQL发布。

## Abstract
Recent Text-to-SQL systems increasingly rely on multi-turn interaction, execution feedback, and reinforcement learning. However, most existing methods use execution correctness only as a trajectory-level reward, which provides limited guidance for identifying the SQL decisions responsible for success or failure. We propose SERL-SQL, a selective execution-grounded reinforcement learning framework for multi-turn Text-to-SQL agents. SERL-SQL samples on-policy SQL interaction trajectories and uses a training-only teacher to re-score student actions with execution feedback. The resulting teacher--student likelihood gap is converted into bounded, masked weights that reweight GRPO advantages only on SQL and tool-action tokens. In this way, task rewards preserve the optimization direction, while execution hindsight provides localized credit assignment. Experiments on BIRD, Spider, and cross-domain benchmarks show that SERL-SQL achieves competitive performance, reaching 76.56% execution accuracy on BIRD-Dev and 89.92% on Spider-Test. Moreover, our reward-based selection strategy closely approaches the oracle Best-of-N upper bound and consistently outperforms consistency-based selection, showing that SERL-SQL produces high-quality candidates that can be reliably identified by lightweight execution-grounded rewards. Our code will be released at https://github.com/Ffunkytao/SERL-SQL.

## 一、核心问题与整体含义（研究动机与背景）

- **研究背景**：Text-to-SQL 是将自然语言问题转换为可执行 SQL 查询的任务，近年来研究重心已从单次生成转向多轮智能体式数据库交互。现代 SQL 智能体（如 Agentar-Scale-SQL、Arctic-Text2SQL-R1、MARS-SQL）将流程分解为 schema 接地、SQL 生成、执行、验证、修订和选择等步骤，并利用强化学习（RL）进行优化。

- **核心问题**：现有主流方法仅将执行正确性（execution correctness）作为轨迹级（trajectory-level）奖励。这种粗粒度的奖励信号**无法定位到底是哪些具体 SQL 决策导致了成功或失败**，导致信用分配（credit assignment）扩散到非关键 token 上，优化信号被稀释。虽然已有工作（如 FineStep）向步骤级信用分配推进，但仍未精确到可执行 SQL 决策层面。

- **关键洞察**：执行反馈（错误信息、空结果、运行时错误等）不仅可作为结果奖励，还可作为**训练时的特权事后证据（privileged hindsight）**，帮助定位导致成败的具体 SQL 决策。SERL-SQL 的核心思路是：**任务奖励决定优化方向，执行事后反馈决定更新的局部性与强度**。

## 二、方法论：核心思想、关键技术细节与流程

### 核心思想
SERL-SQL 提出一种**选择性执行接地强化学习（Selective Execution-Grounded RL）** 框架，通过训练时教师模型对学生同策略动作进行事后重新评分，将师生似然差距转换为有界、掩码化的权重，仅对 SQL 与工具动作 token 重加权 GRPO 优势，从而实现**细粒度的 token 级信用分配**。

### 四阶段流程

1. **Step 1：Schema Grounding（Schema 接地）**
   - 离线阶段：将数据库各列的代表性取值通过嵌入模型编码，建立列感知向量索引。
   - 查询阶段：从问题中提取关键词与实体，与向量索引匹配，检索相关数据库值。
   - 结合基于推理的链接（语义结构）与基于值的链接（检索证据），输出紧凑且值感知的接地 schema，减少无关 schema 信息对 SQL 生成的干扰。

2. **Step 2：多轮 SQL 智能体 Rollout**
   - 策略遵循"思考-行动-观察"（think-act-observe）过程，交替进行 SQL 生成、执行、观察反馈与修订。
   - 状态空间包含任务输入与完整交互历史；动作空间包含推理片段 + 中间 SQL 动作或终止方案。
   - 使用层次化验证器（Hierarchical Verifier）判定轨迹有效性，奖励为：有效且正确 +1，有效但错误 0，无效 −1。

3. **Step 3：选择性执行事后教师（Selective Execution-Hindsight Teacher）**
   - 构建仅训练时可用的执行事后上下文 c_ex（含结果表、运行时错误、解析错误、空结果等）。
   - 教师模型 πT 与学生策略同步更新（stop-gradient），在相同 token 位置上以事后上下文为条件重新评分学生的动作，但**不生成替代轨迹**。
   - 引入动作掩码 m_t,i：SQL 可执行片段与工具动作 token 为 1，推理/格式等 token 为 0。

4. **Step 4：事后引导的优势重加权（Hindsight-Guided Advantage Reweighting）**
   - 计算师生对数似然差距：Δ = log πT(学生token | 事后上下文) − log πθ(学生token)。
   - 转换为**有界、符号感知**的重加权因子：w = clip(exp(sgn(A)·sgn(Δ)), w_min, w_max)。正优势轨迹中，事后支持的 token 获得更强增强；负优势轨迹中，事后不支持的 token 获得更强抑制。
   - 结合选择性动作掩码，非动作 token 保持原 GRPO 权重。
   - 引入随训练步数衰减的系数 α_k：早期利用事后信号改善信用分配，后期回归纯奖励驱动的 GRPO 目标，避免教师偏差。
   - 最终 token 级优势：Ã = A·[(1−α_k) + α_k·w̄]，配合标准 GRPO 裁剪式代理目标与 KL 正则项进行优化。

### 关键公式
- 轨迹优势：A_n = (R_n − mean(R)) / (std(R) + ε_A)
- 权重因子：w_t,i = clip(exp(sgn(A_n)·sg[Δ_t,i]), w_min, w_max)
- 最终优势：Ã_t,i = A_n[(1−α_k) + α_k·w̄_t,i]，其中 w̄_t,i = (1−m_t,i) + m_t,i·w_t,i
- 最终目标：L = −E[Σℓ_GRPO(θ; Ã_t,i)] + β·KL(πθ‖π_ref)

## 六、主要结论与发现

1. **选择性执行事后蒸馏有效**：SERL-SQL 在 BIRD-Dev 上达到 76.56%（32B），在 Spider-Test 上达到 89.92%（14B），显著优于多个强基线。

2. **奖励选择接近 oracle 上界**：基于执行奖励的选择策略（reward_max）在 16 条采样轨迹下非常接近 Best-of-N 上界，并且**始终优于基于一致性的选择**——说明多数投票在 Text-to-SQL 中不可靠（多条轨迹可能收敛到可执行但语义错误的查询）。

3. **各组件均有贡献**（按影响排序）：
   - **Schema Grounding 最关键**（去除后 BIRD-Dev 降 8.53 个百分点），表明紧凑且语义对齐的 schema 上下文是信用分配的基础。
   - **Execution Hindsight 次关键**（去除后降 3.01 个百分点），确认执行反馈提供了轨迹级奖励之外的局部证据。
   - 权重裁剪、动作掩码、事后衰减、符号感知重加权均各有贡献，说明事后信号必须被**有界化、局部化、奖励对齐化**地使用。

4. **事后信息应"即时且局部"**：即时观察（Immediate Observation）最优，完整观察（Full Observation）反而有损——反馈过长会引入冗余信号，模糊 token 级归因。

5. **剩余错误主要来自 Join 构建（29.1%）与语义误解（24.6%）**，而非 SQL 可执行性，提示未来应加强细粒度值接地与条件对齐。

## 七、优点与亮点

1. **方法创新性强**：将执行反馈从"结果奖励"升华为"训练时特权事后上下文"，与 OPD（On-Policy Distillation）结合但**不直接模仿教师输出**，而是转化为有界的优势重加权，避免了信息泄漏与教师偏差。

2. **细粒度信用分配设计精巧**：通过 4 层控制机制（动作掩码、符号感知、有界裁剪、训练衰减）精细调节事后信号的使用，实现"奖励定方向、事后定幅度与位置"的设计哲学。

3. **推理时零额外负担**：教师仅在训练时使用，部署时完全移除，学生策略独立运行，无额外推理开销。

4. **实证分析扎实**：对选择策略的分析（reward_max 逼近 oracle、consistency 更弱）具有实践指导意义——说明系统生成的高质量候选可通过轻量执行奖励可靠识别，而不需要更昂贵的验证机制。

5. **跨域泛化验证充分**：在经典（Spider）、大规模真实（BIRD）、企业级（Spider2.0）、知识增强（Spider-DK）四类基准上均有评估，且均取得竞争性/最佳性能。

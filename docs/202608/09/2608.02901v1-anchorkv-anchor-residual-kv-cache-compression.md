## 摘要
键值（KV）缓存是长上下文大语言模型推理中的主要内存瓶颈。现有方法从两个对立方向着手：驱逐方法永久丢弃令牌，一旦被丢弃的令牌后来被证明是必要的，就会降低性能；而量化方法以低精度保留所有令牌，但压缩效果有限。我们提出AnchorKV，一种压缩方案，在不丢弃任何单个令牌的情况下将缓存缩小20倍。AnchorKV使用一组精确保存的小型锚点来表示缓存，通过每个令牌最相似的锚点来表达其他所有令牌，并仅对那些近似值最影响模型输出的令牌进行细化。AnchorKV在不同模型和数据集上始终保持准确性，在70B规模下保留了完整缓存得分的99%，同时以极低的成本保留整个上下文。

## Abstract
The key-value (KV) cache is the primary memory bottleneck in long-context LLM inference. Existing approaches attack it from opposite ends: eviction methods permanently discard tokens, degrading performance whenever a discarded token later proves essential, while quantization methods retain all tokens at low precision but offer limited compression. We propose AnchorKV, a compression scheme that shrinks the cache by $20\times$ without discarding a single token. AnchorKV represents the cache using a small set of anchors stored exactly, expresses every other token through its most similar anchor, and refines only those whose approximation most affects the model's output. AnchorKV consistently preserves accuracy across models and datasets, retaining 99% of the full-cache score at the 70B scale, while keeping the entire context at a fraction of its cost.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：长上下文 LLM 推理中，KV 缓存（Key-Value Cache）是主要的内存瓶颈。缓存随上下文长度和批次大小线性增长，且在每次解码时被完整读取，导致在 128K 上下文下 8B 模型的 KV 缓存可达 16 GiB（bf16），与模型权重相当。
- **现有方法的缺陷**：
  - **驱逐类方法**（如 H2O、SnapKV、PyramidKV、AdaKV）：保留子集、丢弃其余 token，压缩比高，但决策在查询未知时做出，一旦被丢弃的 token 之后被需要则性能严重受损——这是该家族的主要失败模式。
  - **量化类方法**（如 KIVI、TurboQuant）：保留全部 token 但压缩深度有限，推向 1-2 比特时精度显著下降，实际压缩比停留在约 5× 附近。
  - **检索/卸载类方法**：恢复可达性但将内存问题转化为传输和调度问题，全量缓存仍占据某处存储。
- **研究目标**：设计一种**既不丢弃任何 token、又能实现高压缩比**的缓存压缩方案，使压缩缓存成为精确缓存的“扰动”而非“截断”，在保持完整上下文可达性的同时大幅降低内存占用。

### 2. 论文提出的方法论

#### 2.1 核心思想：锚点-残差表示（Anchor-Residual Representation）

- 每个 KV 头在 prefill 结束时选取少量**锚点（anchors）**，其 K/V 向量以 bf16 **精确存储**。
- 每个非锚点 token 被分配到与其**方向最相似**的锚点（按余弦相似度），并表示为该锚点的缩放副本：
  - 分配：\( a(i) = \arg\max_{a\in\mathcal{A}} \frac{|\langle x_i, x_a \rangle|}{\|x_i\|\|x_a\|} \)
  - 投影系数：\( \gamma_i = \frac{\langle x_i, x_{a(i)} \rangle}{\|x_{a(i)}\|^2} \)
  - 近似：\( \tilde{x}_i = \gamma_i x_{a(i)} \)，残差 \( r_i = x_i - \tilde{x}_i \)
- 每个非锚点 token 只需存储**一个锚点索引 + 一个标量系数**，而非完整 D 维向量。
- 对影响注意力输出最大的 token，额外存储**量化残差（2-bit）**。残差量化采用随机 Hadamard 旋转 + absmax 归一化 + Lloyd-Max 码本，每个残差占用 D/4 字节坐标 + 1 个标量。
- 该表示独立应用于 K 和 V（共享锚点位置，但分配、系数、残差集合各自独立）。

#### 2.2 锚点选择

- 最近 **W=32** 个位置始终精确存储（同时充当 recency window、观测查询与锚点方向）。
- 其余 \( k-W \) 个锚点槽位中 **70%** 按 SnapKV 风格的注意力分数选取（由窗口查询对早期位置的注意力评分、经宽度 κ=7 的池化核平滑），**30% 从上下文中均匀随机采样**，以改善方向覆盖。
- 锚点预算 \( k = S/128 \)（S 为上下文长度）。
- **关键设计**：key 在 **RoPE 之前**进行投影（预旋转），解码时再旋转。因为 RoPE 的旋转会显著降低 token 与锚点间的余弦相似度（实验中中位数下降 0.27），而 RoPE 是正交线性变换，可分布到分解后的各个分量上。

#### 2.3 注意力输出感知的残差评分（Attention-Output-Aware Residual Scoring）

- 核心思想：残差大小或注意力分数本身都不足以决定存储哪个残差的收益——需综合**注意力权重**与**表示误差带来的输出扰动**。
- 通过一阶近似推导注意力输出误差的分解（式 5）：
  \[
  \Delta y \approx \sum_t \alpha_t(\Delta s_t - \overline{\Delta s})(V_t - y) + \sum_t \alpha_t \Delta V_t
  \]
  - **K 通道**：key 误差通过注意力权重传播，受 \( V_t - y \) 调制；
  - **V 通道**：value 误差直接作用于输出。
- 在非相干性近似下，每个 token 的效用可加，得到两个效用分数（式 6）：
  - \( u^K_t \)：K 侧效用 = \( (\alpha_t^{(w)})^2 \cdot \|q^{(w)\top}R_t r^K_t\|^2/D \cdot \|V_t - y^{(w)}\|^2 \)
  - \( u^V_t \)：V 侧效用 = \( (\alpha_t^{(w)})^2 \cdot \|r^V_t\|^2 \)
- 锚点和窗口 token 精确存储，不参与资源竞争；只有非锚点且未获残差的 token 才产生效用项。

#### 2.4 字节预算与残差分配

- 用户设置一个保留比例 θ（唯一可调参数），经过**精确的字节核算**（表 1），决定每层可购买的残差数量：
  \[
  N = \max\left(0, \left\lfloor \frac{\theta M_{\text{full}} - M_{\text{base}}}{b_{\text{res}}} \right\rfloor\right)
  \]
- K 侧获得 ⌊N/2⌋ 个槽位，V 侧获得其余部分；每侧按效用分数在**所有 KV 头中池化排序**，分配最高效用的残差（跨头竞争同一个层内残差预算）。
- 压缩在 prefill 结束时**一次性完成**，模型冻结，注意力算术不变；生成 token 追加到精确窗口，不压缩。

#### 2.5 推理与存储

- 压缩状态包括：bf16 锚点（含窗口）、每 token 的锚点索引与系数、稀疏的 2-bit 残差及掩码/前缀计数表。
- 解码时使用 FlashAttention 风格的**分块 Triton 内核**：按需重建 key 瓦片并施加 RoPE，value 通过哈达玛逆变换的线性性在累加后再变换一次，**密集缓存从不物化**。
- 理论保障：输出误差界被分为 K 侧最坏情况项（\( 2V_{\max}\tanh(\mu) \)）和 V 侧注意力加权平均项（式 17/18）。

### 6. 论文的主要结论与发现

1. **20× 压缩超越基线 10×**：在所有 9 个模型-基准面板中，AnchorKV 在 20× 下的得分高于所有驱逐基线在 10× 下的得分——相同精度只需一半内存。
2. **随规模改善**：RULER-32K 20× 下，8B/24B/70B 分别保留 FullKV 的 93.5%/95.3%/99.3%；70B 下压缩缓存得分 94.4 vs 未压缩 95.0，而最强驱逐基线仅保留 86.8%。
3. **逐任务一致性**：13 个 RULER 任务中 12 个达到或超过最强基线，且**从不下落到 60% 以下**，而驱逐基线在 3 个任务上降到 16% 以下。最大优势出现在“需对抗干扰项检索”和“全上下文聚合”类任务（cwe、single_3、multikey_3 超过最强基线 45-88 个百分点）。
4. **Needle 检索鲁棒**：5× 下 AnchorKV 平均准确率 0.94 vs FullKV 0.99；最强驱逐基线仅 0.18。20× 下仍达 0.80。
5. **消融确认设计有效性**：注意力输出效用排名优于其他排名准则；随机排名最差；无残差、无随机锚点、无跨头池化、朴素量化均造成精度损失，且随预算收紧损失增大。
6. **pre-RoPE 投影是关键**：投影在旋转前进行使全部未修复 token 的近似误差系统性降低（中位余弦提升 0.27）。
7. **效率与现实收益**：解码峰值内存 19× 降低、并发容量约翻倍、64K 以上解码延迟持平或更快，端到端开销在长上下文+大批量+长输出下低于 5% 甚至为负。

### 7. 优点

- **方法学亮点**：
  - 跳出“驱逐 vs 量化”的二分法，用“锚点近似 + 稀疏残差细化”同时获得高压缩比与全上下文可达性。
  - 首次将注意力输出的一阶误差分析（softmax Jacobian + K/V 双通道分解）直接用于残差预算分配，排名准则的目标函数与最终关注指标一致。
  - pre-RoPE 投影的洞察简洁且有效——利用 RoPE 的正交线性性质，在不改变注意力语义的前提下改善字典覆盖。
  - 字节精确核算（所有张量都计入成本）保证了声称压缩比的可信度；锚点+系数+掩码+前缀计数的稀疏布局使无残差 token 不耗额外空间。
  - 理论输出误差界（式 17/18）将 key 侧控制在 worst-case、value 侧控制在 attention-weighted average，支撑了“扰动而非截断”的论证。
- **实验亮点**：
  - 在统一字节预算下公平比较两种不可比的压缩范式（token 预算 vs 位宽）。
  - 逐任务而不是只看平均分，清楚展示驱逐方法的失败模式；attention-output 保真度 CDF 提供了机制层面的直接证据。
  - Needle-in-a-Haystack 压力测试覆盖 128K 全扫描，且使用 64 位 passkey 避免饱和。
  - 消融设计干净：每次只改一个变量并固定字节预算，既测效果又测预算收紧时的敏感性。
  - 工程实现完善：Triton 分块解码、end-to-end overhead 摊销分析、prefill/decode 解耦视角，接近实际部署场景。

### 8. 不足与局限

- **实验覆盖局限**：
  - 仅 3 个模型（全为 Llama/Mistral 系指令微调模型），缺少编码器-解码器、MoE 架构、更大（>70B）或更小（<7B）规模的验证。
  - 未覆盖多轮对话、流式生成、长文本生成（输出侧不压缩，只压缩 prompt 侧）等场景。
  - 基准以英文为主，未验证多语言行为。
- **与最前沿方法的对比缺失**：论文引用的若干近期工作（CriticalKV、OBCache、CommVQ、Squeezed Attention、CentroidKV 等）未纳入实验对比，时序上无法确定是否为当前最优。
- **方法本身的理论/实践限制**：
  - 效用估计依赖观测窗口假设（与驱逐方法相同的假设——近期查询使用的 token 是解码需要的）；不同之处在于估计错误时后果更轻（token 仍保留但存储粗糙），但该假设在极端场景（如信息出现在长上下文开头且从不被窗口查询注意）下仍可能造成性能下降——Needle 扫描中 128K 长度浅深度处已有温和退化（0.94 vs 0.99）。
  - 随机哈达玛旋转的要求意味着残差必须成批变换（每步每头一次逆变换），解耦设计依赖 Triton 内核的工程复杂度，尚未给出与 vLLM/SGLang 等主流推理框架的集成验证。
  - 残差只有 2-bit 且逐 token 缩放，没有利用层间/头间冗余；与低秩跨层方法的组合空间未探索。
  - 输出误差界依赖于非相干性假设（式 16 是期望意义下的等式而非保证），且理论界中的 K 侧项是 worst-case、不随残差预算明确收缩（仅通过减少残差范数间接控制）。
- **资源报告局限**：未提供压缩阶段 FLOPs 的总量或与 prefill 总计算量的精确占比，也未报告 70B 实验的具体耗时。
- **TurboQuant 对比公平性**：作者承认原论文的 channel-split 方案无法复现所称质量，最终采用社区实现的 uniform-base + fp16-outlier 方案；这增加了对比方法的实现偏差风险（但作者明确披露了这一调整并指出选择理由）。

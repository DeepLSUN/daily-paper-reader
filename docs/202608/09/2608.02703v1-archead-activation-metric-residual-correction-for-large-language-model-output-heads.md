## 摘要
仅权重量化大幅减少了大型语言模型（LLM）Transformer模块的存储，但实际后端通常将最终的语言建模头（LM-head）保留为BF16或FP16格式。天真地对这一投影进行量化会强烈扰动词表logit分布。我们提出了ARCHead，一种紧凑的LM-head压缩器，它结合了量化低秩核心、分组INT4残差，以及在激活派生度量中拟合的低秩校正。ARCHead不存储密集的BF16头，并将持久性LM-head存储减少3.7-3.9倍。在Qwen3-8B-Base上，它仅使用BF16头存储的25.6%，同时达到1.007的相对困惑度；而存储匹配的朴素INT4则产生1.14-1.16。替换AWQ或bitsandbytes留下的BF16头仅增加0.006-0.007的交叉熵，在我们的测量中吞吐量变化不到2%。因此，ARCHead通过压缩分块量化器可能保留不动的大规模输出投影，来补充分块量化器。代码可在 https://github.com/suayptalha/archead 获取。

## Abstract
Weight-only quantization substantially reduces the storage of large language model (LLM) transformer blocks, but practical backends often retain the final language-modeling head (LM-head) in BF16 or FP16. Quantizing this projection naively can strongly perturb the vocabulary-logit distribution. We present ARCHead, a packed LM-head compressor that combines a quantized low-rank core, group-wise INT4 residuals, and a low-rank correction fitted in an activation-derived metric. ARCHead stores no dense BF16 head and reduces persistent LM-head storage by 3.7-3.9x. On Qwen3-8B-Base, it uses 25.6% of BF16 head storage while attaining 1.007 relative perplexity; storage-matched naive INT4 yields 1.14-1.16. Replacing the BF16 head left by AWQ or bitsandbytes adds only 0.006-0.007 cross-entropy, with less than 2% throughput change in our measurements. ARCHead therefore complements block quantizers by compressing the large output projection they can leave untouched. Code is available at https://github.com/suayptalha/archead.

## 1. 核心问题与整体含义

大型语言模型（LLM）部署中，仅权重量化（weight-only quantization）技术（如 GPTQ、AWQ、bitsandbytes NF4）通常只压缩 transformer 块内的权重，而最后的语言建模头（LM-head，即将最终隐状态映射为词表 logit 的投影层）往往被保留为 BF16/FP16 格式。随着词表规模的增大（如 Qwen3-8B-Base 的 151,936 词表、Gemma-4-E4B 的 262,144 词表），LM-head 的存储占用可达 1.2–1.3 GB，在块级量化完成后成为最大的残留密集张量之一。

直接对 LM-head 做朴素低比特量化（如 INT4）会产生严重的质量损失，原因在于：朴素量化最小化的是权重空间的均方误差，将所有隐方向视为等权；而实际最终隐状态分布是各向异性的，沿高频激活方向的微小误差会影响大量词表 logit。该论文的核心动机是：**LM-head 的量化应当基于激活分布导出的度量，而非简单的权重空间重构误差**。

论文提出的 ARCHead 将这个未被现有块量化器覆盖的"最后的密集张量"也纳入压缩范围，与块量化器形成互补，而非替代。

## 2. 方法论

### 2.1 核心思想

ARCHead 的总体策略是将 LM-head 分解为三部分：

$$W \approx \underbrace{Q_5(A_c)Q_8(B_c) + Q_{SC4}(W - A_cB_c)}_{\text{量化低秩核心 } W_d} + \underbrace{A_w B_w}_{\text{激活度量低秩校正}}$$

- **量化低秩核心**：先用一个秩为 $r_c$ 的低秩近似 $A_cB_c$，再对残差进行分组（group-wise）有符号 INT4 量化（含量化分组尺度），左右核心因子分别用 5-bit 和 8-bit 量化。
- **激活度量低秩校正**：针对核心量化后的剩余误差 $E = W - W_d$，在激活协方差定义的度量空间中做低秩逼近。

### 2.2 关键公式与技术细节

**激活度量目标**：设 W ∈ R^{V×D} 为密集头权重，H ∈ R^{N×D} 为校准 token 的最终隐状态，Δ = W − Ŵ 为权重误差。经验平方 logit 误差为：

$$E = \frac{1}{N}\|H\Delta^\top\|_F^2 = \text{Tr}(\Delta C\Delta^\top)$$

其中 $C = H^\top H / N$ 为激活协方差。Frobenius 权重目标是 $C = I$ 的特殊情形，忽略了激活几何。ARCHead 采用阻尼度量变换：

$$T_p = Q\Lambda^p Q^\top,\quad T_p^{-1} = Q\Lambda^{-p} Q^\top$$

其中 $C_\lambda = C + \lambda\bar{c}I = Q\Lambda Q^\top$（λ 为阻尼系数，$\bar{c}$ 为 C 的均值对角元）。p = 1/2 时对应阻尼 logit-MSE 几何；p 可在校准数据上选取（论文中 Qwen 取 p = 0.75）。

**残差校正的最优性**：将变换后的残差 $\tilde{E} = ET_p$ 做秩 $r_r$ 截断 SVD，得到 $U_{r_r}\Sigma_{r_r}V_{r_r}^\top$，然后映射回原空间：

$$A_w = U_{r_r}\Sigma_{r_r},\quad B_w = V_{r_r}^\top T_p^{-1}$$

论文证明了一个**条件最优性定理**：对于固定的核心 $W_d$ 和可逆的 $T_p$，在因子量化之前，上述未量化的 $A_wB_w$ 在所有秩 ≤ $r_r$ 的校正中，最小化 $\|(E - AB)T_p\|_F^2$。该证明直接借助 Eckart–Young–Mirsky 定理（通过变量替换 $\tilde{B} = BT_p$ 与 rank 不变性实现）。值得注意，该最优性声明是**针对固定核心的条件最优**，且在因子 INT8 量化之前成立，而非端到端全局最优。

**推理计算**：最终 logits 采用因子化计算避免重建密集头：

$$\hat{Y} = HW_d^\top + (HB_w^\top)A_w^\top$$

**存储表征**：ARCHead 打包注册了 SC4 残差及尺度、量化核心因子、量化校正因子、尺度与零点元数据、形状元数据，不保留任何密集 BF16 副本。持久存储按实际注册张量的 numel × element_size 直接测量。

### 2.3 构建流程（Algorithm 1）

1. 计算阻尼激活协方差 C ← H^T H/N + λI
2. 构建量化核心 W_d（低秩近似 + 分组 INT4 残差量化）
3. 计算核心误差 E ← W − W_d
4. 对 C 进行特征分解 C = QΛQ^T
5. 构造 T_p 及 T_p^{-1}
6. 计算变换后残差 Ẽ ← ET_p
7. 对 Ẽ 做秩 r_r 截断随机化 SVD
8. 得到 A_w ← UΣ，B_w ← V^T T_p^{-1}
9. 对 A_w、B_w 做 INT8 量化（行/分组方式）
10. 打包所有缓冲，丢弃密集 BF16 张量

## 6. 主要结论与发现

1. **激活度量校正至关重要**：核心量化 + 分组 INT4 残差单独仅能达到相对 PPL 1.134（ΔCE +0.126）；加入秩 6 的激活度量低秩校正后降至 1.007（ΔCE +0.007），存储比例仅从 0.230 增至 0.256。

2. **对朴素 INT4 的显著优势**：在存储相近（约 25.6% vs 26.6% BF16）时，ARCHead 相对 PPL 为 1.007，而 Group INT4 为 1.151、SVD8+INT4 为 1.211。

3. **跨模型泛化**：Qwen、Gemma、VibeThinker 上相对 PPL 分别为 1.007、1.010、1.027；LM-head 量化敏感性因模型而异（Gemma 的朴素 INT4 基线已较强）。

4. **与块量化器兼容互补**：替换 AWQ 或 BNB NF4 遗留的 BF16 头，额外交叉熵仅为 +0.006～+0.007。

5. **GPTQ 对比**：在 2K–16K 校准预算下，ARCHead 将 GPTQ 的相对 PPL 退化幅度降低 33.6%–49.3%，且构建速度快 2.36–2.58 倍，方差更小。

6. **Logit 保真度高**：top-1 一致性 93.05%（vs 朴素 INT4 约 76%），top-5 达 99.95%，top-10 达 100%；KL 散度比朴素 INT4 低一个数量级以上。

7. **可实现的实际存储收益**：跨 5 个模型头，持久存储压缩 3.71–3.91 倍（实测打包缓冲字节数），无密集 BF16 副本。

8. **吞吐量几乎不受影响**：所有配置下生成吞吐变化 <2%，初步 Triton 融合内核验证了相同结论。

9. **校准稳健性**：在 4K–64K 校准 token 范围内，相对 PPL 稳定在 1.0070–1.0076 的窄带内。

## 7. 优点

1. **问题定位精准**：识别出现有 PTQ 流程中"块量化但头保留 BF16"的实际缺口，并用实现级证据（AWS/BNB 检查点中确实保留了 151,936×4,096 的 BF16 Linear）支撑动机，而非假设性论证。

2. **度量设计有理论支撑**：激活度量变换 + 条件最优性定理（基于 Eckart–Young–Mirsky）为校正因子的形式提供了理论依据，而非启发式堆叠组件；同时审慎地划定了最优性声明的边界（固定核心、未量化因子、非全局最优）。

3. **构建流程严谨**：核心残差 E 使用的是"实现后的"量化核心 $W_d$ 而非理想化核心，即校正拟合目标是已量化的实际误差，避免了"理论组件在实现中性能崩坏"的常见脱节。

4. **存储计量的可信度高**：持久大小来自实例化 PyTorch buffer 的实际字节和，并在多次对比中核验（表 1、2、6 交叉验证同一事实），严格区分存储与运行时峰值内存。

5. **实验对比公平**：种子匹配、校准/评测数据分离、存储匹配置于同一量级、Backend 核验，均体现了较高的实验设计水准。

6. **消融清晰**：核心 vs. 完整模型的消融（1.134 vs 1.007）直接证明贡献来源，而非笼统报告端到端效果。

7. **开源可复现**：提供代码仓库和明确的模型/数据/种子协议。

## 8. 不足与局限

1. **适用范围窄**：ARCHead 专门面向输出头，不压缩 transformer 的 MLP 或注意力权重；其收益在 LM-head 大且对朴素低比特量化敏感时最大。

2. **条件最优性局限**：最优性结论针对固定核心且发生在校正因子量化之前；端到端的量化 ARCHead 构建不保证全局最优，因子量化引入的额外误差未被纳入理论框架。

3. **跨模型优势不均**：在 Gemma-4-E4B 上，朴素 INT4 的头部相对 PPL 已低至 1.013，ARCHead 的优势（1.010）在显示的舍入值中很小；这表明方法收益存在明显的模型依赖性。

4. **下游评测不足**：HellaSwag / TruthfulQA / WinoGrande 仅 3 个任务，论文明确声明不能据此建立任务级增益或能力完全保留的结论；模型的安全属性、多语言能力、长上下文能力均未评测。

5. **校准域单一**：校准数据仅来自 WikiText-103 训练集，单一领域/语言；校准敏感性扫描虽显示 4K

### 5. 校准域单一（续）  
…token 的稳定性，但仅覆盖了单一领域、单一语言的校准来源。对于代码、数学或多语言场景，最终隐状态的分布会显著偏移，激活协方差 \(C\) 的估计将带有领域偏差，进而影响 \(T_p\) 变换及低秩校正因子的有效性。论文未提供跨领域校准或领域外评测的证据。

### 6. 对比基线不够全面  
头级对比中缺少更近期的输出头压缩方法（如基于 AQLM/QuIP# 等极端压缩框架的头级适配），也未与“重训练/蒸馏式”头压缩方案对比。这使得“当前最先进的头级 PTQ 方法”这一相对位置不够清晰。

### 7. 理论最优性与实现最优性之间的差距未量化  
条件最优性定理在“因子未量化”的前提下成立，但实际流程会对 \(A_w\)、\(B_w\) 做 INT8 量化。论文未单独报告这一因子量化步骤引入的额外 logit-MSE 或 PPL 损失，读者无法判断理论最优到实现之间到底有多少性能折损。

### 8. 推理实现的后端兼容性未验证  
因子化计算路径 \(\hat{Y} = HW_d^\top + (HB_w^\top)A_w^\top\) 需要自定义 Kernel 或融合逻辑。作者仅在 PyTorch eager 模式和初步 Triton 内核上验证了吞吐量，未覆盖 vLLM、TensorRT-LLM、llama.cpp 等主流生产推理框架，实际落地时仍需工程适配。

### 9. 构建时间报告不完整  
论文只给出了“ARCHead 比 GPTQ 风格头量化快 2.36–2.58 倍”的相对值，未报告绝对构建秒数。这使得跨硬件环境复现和对比缺乏锚点，也削弱了工程可移植性方面的说服力。

### 10. 超参数选择缺乏系统扫描  
\(p\) 值仅在 Qwen 上报告取 0.75，其余模型的 \(p\) 值未见敏感性扫描或选择依据；秩 \(r_c\)、\(r_r\) 的选取也未做系统性的扫描可视化，读者难以判断这些超参对最终质量的敏感度。

## 9. 开放问题与未来工作

1. **端到端联合优化**：当前流程先构建核心 \(W_d\)，再对残差做校正，两个阶段解耦。未来可探索将核心量化误差与激活度量校正纳入同一优化目标，或将条件最优性推广为全局最优。

2. **自适应秩选择**：固定秩（如 \(r_c = 8\)、\(r_r = 6\)）未必在所有模型和词表规模上最优。可基于激活协方差谱（eigenvalue decay）或目标存储预算自动选择秩，进一步压缩存储或提升质量。

3. **多层扩展**：ARCHead 的核心思想可推广到 embedding 层或 transformer 内部的高维投影层（如 gated MLP 的 up/down 投影），形成统一的“高维张量激活度量量化”框架。

4. **跨领域校准鲁棒性**：激活协方差 \(C\) 在不同领域间差异较大，未来可研究在混合领域校准或在线自适应更新 \(C\) 的机制，使 ARCHead 在领域偏移下依然稳健。

5. **与生产推理框架集成**：将因子化计算逻辑整合进 vLLM、TensorRT-LLM 等推理引擎，并验证其在 batch 推理、KV cache 复用、连续 batching 场景下的真实吞吐收益。

6. **融合更多输出头压缩方法**：将 ARCHead 与 AQLM、QuIP# 等新一代量化框架结合，或在其残差量化环节引入更高效的编码（如非均匀码本），探索接近 4× 以上的持久压缩边界。

## 10. 总体评价

ARCHead 是一个**问题定位精准、理论动机明确、工程实现严谨**的 LM-head 专用压缩方法。它精准切入 PTQ 流程中“块量化完成但头仍保持 BF16”这一容易被忽视的实际存储缺口，并以激活度量而非权重范数为设计依据，使量化误差在 logit 空间中真正得到控制。条件最优性定理为校正因子的形式提供了可靠的理论锚点，实验设计在存储计量、种子配对、校准/评测分离等方面体现了较高水准。

但论文的贡献本质上是**增量式而非范式级**的：相对 PPL 1.007 的增益处于“近无损”区间，且收益高度依赖模型（在 Gemma 上优势收窄至显示舍入级别）；下游评测仅 3 个任务无法支撑任务级结论；校准域单一限制了方法在多样部署场景下的说服力。若将 LM-head 压缩视为一个独立研究问题，ARCHead 无疑是当前最完整、最审慎的解决方案之一；但若要嵌入生产级 PTQ 流程，仍需解决后端 Kernel 落地与跨领域校准的工程问题。

综合而言，该论文适合作为“针对特定张量的激活感知量化”方向的代表性工作引用，其方法论细节（尤其是激活度量变换与条件最优性证明）具有较强的参考和扩展价值。

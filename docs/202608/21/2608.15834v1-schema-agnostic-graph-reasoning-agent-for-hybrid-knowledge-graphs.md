## 摘要
工具调用的LLM智能体通过少量通用原语（如ls、cat、grep）来浏览不熟悉的代码库，这些原语用于列出、读取和搜索文件。知识图谱也支持同样的接口：列出邻居、读取节点内容和搜索描述，是在不同基质上的相同操作。基于这种对应关系，我们提出了GRA，一种图推理智能体，它使用七种通用工具探索混合知识图谱（其节点可以是文本概念或关系表），并在运行时发现所有领域特定内容。在UFK-M（统一工厂知识模型）上，这是一个包含258个分析问题的工业基准，其标准答案通过执行经过验证的SQL程序生成，GRA以5.1个百分点（88.4%对83.3%）的优势击败了全上下文智能体，同时读取的输入令牌不到其三分之一。无图对照实验表明，增益主要来自选择性的智能体访问，而非图拓扑结构，并且这种效果依赖于能够可靠驱动工具的模型。看得更少，答案更好：在结构化基质上的选择性导航胜过穷举上下文。

## Abstract
Tool-calling LLM agents navigate unfamiliar codebases with a handful of generic primitives for listing, reading and searching files (ls, cat, grep). A knowledge graph admits the same interface: listing neighbours, reading node content and searching descriptions are the same operations on a different substrate. Building on this correspondence, we present GRA, a Graph Reasoning Agent that explores hybrid knowledge graphs, whose nodes are either textual concepts or relational tables, with seven generic tools, discovering everything domain-specific at run time. On UFK-M (Unified Factory Knowledge Model), an industrial benchmark of 258 analytical questions whose gold answers are produced by executing validated SQL programs, GRA beats a full-context agent by 5.1 pp (88.4% vs. 83.3%), while reading under a third of its input tokens. A graph-free control shows the gain comes chiefly from selective agentic access rather than graph topology, and that the effect depends on a model able to drive tools reliably. Seeing less, the agent answers better: selective navigation over a structured substrate beats exhaustive context.

## 2. 方法论：GRA 及其关键技术细节

- **GRA（Graph Reasoning Agent）**：一个模式无关的图推理智能体，仅用七种通用工具探索知识图谱，在运行时发现一切领域特定知识（概念、表名、词汇、连接路径），工具和系统提示中**不硬编码任何领域内容**。
  - 工具集（全部通用原语，见表 1）：
    - `ls`：列出节点、表、边，用于图内定位；
    - `cat`：读取单个节点全文；对表则展示列、键、连接关系和 3 行样例；
    - `grep`：对 id、文本、属性、边、列做字面量搜索；
    - `sems`：语义搜索（稠密向量 + BM25，返回 top-10）；
    - `query`：只读 SQL（`SELECT`/`WITH`），最多返回 50 行；
    - `think`：思维 scratchpad，用于规划与检查，无副作用；
    - `answer`：提交最终答案，可附引文与置信度。
  - **混合知识图谱的基质契约**：每个节点携带标识符、自然语言描述、标签和可选属性；关系为有向 subject–predicate–object 三元组；部分节点为数据表，由实际 DuckDB 表支撑，可被 SQL 查询。问答可能需要文本、关系数据或两者兼用。
  - **示例轨迹**：`ls(labels) → ls(tables) → grep("orders") → grep("customer segment") → cat(tbl_customer_orders) → cat(Customer) → cat(tbl_customers) → query(...) → think → answer`，schema、词汇和"late（延迟）"的定义都在途中被发现。
- **RSA（Retrieval SQL Agent）**——无图对照组：与 GRA 运行完全相同的执行循环，共享相同的策略提示词模块，但图被移除，改为在扁平化文档块和表 schema 上检索（`search_text`、`list_tables`、`describe_table`），保留相同的 `query`、`think`、`answer`。公平性由构造保证：两系统仅基质与工具集不同。
- **SQA（SQL Agent）**——全上下文基线：prompt 包含图的完整文本描述与完整渲染 schema（类型化列、键关系、分类词汇、日期范围），约 17k tokens，6 轮内写出 SQL 答案。
- **部署闭环（第 8 节）**：在基准评测的 QA 模块之外，GRA 还嵌入一个工业决策回路——操作员用自然语言陈述规则 → 编排器（Orchestrator）询问 GRA 规则是否可行 → GRA 导航图谱、计算并返回带引文的裁决 → 获准规则交由 ORA（运筹智能体）编译为数学优化模型与求解器代码，并经人工审核后以 `edit` 原语写回图谱成为新的规则节点（`edit` 不在基准工具集中）。

## 3. 实验设计

- **基准：UFK-M（Unified Factory Knowledge Model）**
  - 一个虚构的自行车装配工厂，受真实客户工厂启发但完全合成；有创世文本（founding text）陈述运营规则、KPI 与行业概念，并由两层机器可读结构支撑：数据层（DuckDB 表）与语义层（知识图谱）。
  - 表格规模（表 2）：`large` 有 32 表、157,953 行、125 个 KG 节点、268 条边、4,278 个创世词、148 个问题；`xlarge` 有 64 表、174,006 行、235 个节点、513 条边、6,933 个词、258 个问题。主要结果在冻结的 `xlarge` 集上。
  - **答案优先（answer-first）问题生成**：先由 LLM 基于 schema 卡片写出 SQL 程序 → 对数据库执行并验证（结果非空、非退化、≤10 行）→ 再由 LLM 针对保留结果撰写自然语言问题。保证每个问题都可从数据回答，且金标准答案是**实际运行过的程序输出**而非模型生成的文本。
  - 问题构成：116 个表答案、84 个单值、48 个布尔、10 个列表；147 个需要 ≤1 次连接、45 个需要 2 次、66 个需要 ≥3 次；34 个额外需要语义层（隐藏的规则/KPI）。
  - **确定性评分**：数值答案带容差比较，百分比答案尺度无关比较，表答案按金标准行的召回率评分；不使用 LLM 评判。
- **对比方法**：三个系统（GRA / RSA / SQA）× 七个骨干配置：
  - DeepSeek V4-Flash（非思考，参考模型）、V4-Pro、V4-Pro-Think（同一权重，推理开/关）；
  - GPT-5 Nano（低/高推理努力）、GLM-4.5-Air、Qwen3-Coder-Flash。
- **超参数**：GRA/RSA 45 轮 LLM 调用，SQA 6 轮；SQL 工具最多 50 行；GRA/RSA 使用本地嵌入器 `multilingual-e5-large-instruct`；所有模型贪心解码（temperature 0），输出上限 1,024 tokens（思考配置 8,192）；不确定性用按问题的配对 bootstrap（B=10⁴）95% 分位区间量化。

## 6. 主要结论与发现

- **GRA 优于全上下文基线**：在 DeepSeek V4-Pro-Think 上，GRA 达到 88.4%，比 SQA（83.3%）高 **+5.1 pp**（相对错误率减少 30.5%），同时仅读取 SQA 约 29–33% 的独特输入 token；RSA 读取 24–29%。
- **增益主要来自选择性智能体访问，而非图拓扑**：GRA 相对 RSA 仅超出 +0.3 至 +1.9 pp，且在一组配置上不可区分（DeepSeek V4-Pro）。这证明核心优势是"如何访问上下文"，而非图结构本身。
- **方法排序依赖模型**：DeepSeek 与 GLM 上 GRA 最优（GRA > RSA > SQA）；Qwen3-Coder-Flash 与 GPT-5 Nano 上 SQA 反超（分别 +2.3 pp、+5.5 pp）。全上下文推理在工具使用不可靠时更稳健。
- **工具可靠性比扩展推理更重要**：三个 DeepSeek 配置（Flash/Pro/Pro-Think）准确率仅相差 1.2 pp（区间重叠），尽管 Pro-Think 额外具备推理模式；GPT-5 Nano 开启 think 后提升 +6.2 pp，但其工具调用失败率同时减半（10.2%→5.8%，51.6%→34.9%），增益更可能由可靠性中介而非推理深度驱动。失败率排序与准确率排序高度一致（表 4）。
- **Token 效率**：GRA/RSA 输入约为 SQA 的三分之一；但输出 token 更多（1.0–2.0k vs 0.5–1.3k）。按缓存感知定价，冷启动单问题服务下 GRA/RSA 更便宜，热缓存批量评测下 SQA 因固定前缀可复用而占优。
- **预算拐点**：准确率从 B=10 到 B=30 快速上升（xlarge 上 63.6% → ≈88%），之后平台化；约 30 次调用已足够，超过后无增益。截断问题数量分别从 62→3（large）、118→11（xlarge）。
- **适用边界**：当工具调用失败率超过几个百分点时，agentic 方法的优势缩小或反转；因此在弱工具调用模型上全上下文仍是更安全的选择。

## 7. 优点

- **类比新颖且富有生产力**：将代码智能体的成熟能力（通用原语导航）系统性地迁移到知识图谱，提出了"混合基质上的同一接口"这一统一视角；工具集仅 7 个通用原语，**零领域硬编码**，模式无关性实现彻底。
- **控制实验设计严谨**：RSA 作为"图移除"对照，与 GRA 共享执行循环与策略提示，通过构造保证公平，使"增益归因于选择性访问而非图拓扑"这一结论有据可依。
- **金标准可靠**：答案优先（answer-first）的生成流程——先写 SQL、验证执行、再写问题——保证每个问题可回答且金标准确凿；确定性评分（而非 LLM judge）消除了评判者偏差。
- **诊断深入**：对工具失败率、Token 使用、预算敏感性的多维度分析，揭示了性能差异背后的机制（可靠性而非推理深度），而非停留在表面准确率。
- **部署视角完整**：第 8 节将 QA 模块嵌入真实工业闭环（规则可行性裁决），展示模式无关工具在"跨节点挖掘隐藏冲突、按需计算非存储量"等任务上的实际价值，且两个详例均给出逐步工具轨迹，可审计性强。
- **统计严谨**：配对 bootstrap 置信区间全程伴随；模型网格覆盖推理/非推理、高端/低成本，结论的边界（模型依赖）被明确刻画。

## 8. 不足与局限

- **图拓扑的贡献被削弱**：GRA 相对 RSA 的增益很小（+0.3~+1.9 pp），这表明在当前基准上"图结构"本身提供的价值有限，主要收益来自选择性访问——这在某种程度上削弱了论文标题中"Graph Reasoning"的独特卖点，也让读者质疑：一个简单的检索式智能体（RSA）是否已足够？图的价值或许只在更大、更复杂的图谱上才能显现。
- **基准单一性与合成性**：UFK-M 虽是受真实工厂启发但纯合成；规模有限（258 个问题、513 条边、图 prompt 约 17k tokens），远小于真实工业知识图谱的规模。论文自己也承认，**序列化不可行或成本过高的场景（更大图）尚未测试**，而这恰是导航方法最该发挥优势的场合。
- **模型覆盖失衡**：最强结果集中于单一模型家族（DeepSeek），且该家族占据最佳结果；考虑这些模型是否在训练数据上更契合此类工具调用任务（如开源或 API 定制）会更有说服力。部分成本模型（Qwen、GPT-5）上 GRA 反而落败，说明方法的普适性尚存疑问。
- **工具可靠性瓶颈未破解**：论文证明了工具失败率是关键瓶颈，但未提出任何缓解机制（如错误自动重试、自我修复、工具调用验证），而是将其视为模型的先验属性。这限制了方法对弱工具调用模型的适用性。
- **输出 token 更高**：多轮导航产生 2–3 倍于 SQA 的输出 token，在长上下文缓存定价下

- **输出 token 更高**：多轮导航产生 2–3 倍于 SQA 的输出 token，在长上下文缓存定价下，SQA 因固定前缀可完全复用而更占优势；GRA/RSA 的输入虽少，但每轮工具调用产生独立前缀，缓存命中率低。论文对此仅停留在 token 计数层面，未做端到端成本核算（时延、缓存命中率、在线 vs 批处理），因此"更便宜"的结论只在冷启动在线场景下成立，普适性有限。
- **无跨会话记忆与增量学习**：GRA 每次问答都从零开始探索图谱，此前已发现的路径、schema 信息或词汇定义不会沉淀为长期记忆，也不更新图谱本身（`edit` 工具仅存在于部署环节，且需人工审核）。在重复性工业问答中，这会带来大量冗余探索，效率提升存在明显天花板。
- **错误传播与不可验证的中间推理**：`think` 工具是无副作用的 scratchpad，其内容缺乏校验机制；一旦中间的 `grep`/`query` 返回空结果或误导性信息，模型可能基于错误中间状态继续规划，而论文未提出任何重试、自校验或回溯策略。

## 9. 总结与展望

- **总体评价**：本文以"代码智能体导航代码库"为类比，将模式无关的工具调用范式迁移到混合知识图谱问答，用严谨的三系统控制实验证明了"选择性访问优于穷举式上下文"这一反直觉结论，并进一步将其归因于访问机制本身而非图拓扑。方法论迁移自然、实验设计客观、统计推断扎实，是 agentic 检索与知识图谱问答交叉领域的一项高质量实证工作。
- **首要启示**：在一个足够复杂、模式未知的知识基座上，教会模型"如何看"比"给它看完"更有效；但这一优势对模型工具调用可靠性高度敏感，模型越弱，全上下文基线越安全。
- **未来方向**（论文未充分展开但可自然延伸）：
  - 在更大规模（图 prompt 远超上下文窗口）、跨领域的真实知识图谱上验证，此时"序列化不可行"将成为导航方法的决定性优势；
  - 引入跨会话记忆、已验证的中间状态（replay buffer）或将图拓扑编码为规划先验，以压缩冗余探索；
  - 针对弱工具调用模型增加自我修复循环（错误检测 → 重试 → 回退），而非被动接受可靠性瓶颈；
  - 将部署闭环中的人工审核环节逐步自动化，构建"探索—问答—编辑—回写"的完整自主学习回路。

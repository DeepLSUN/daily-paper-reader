## 摘要
LLM智能体在通用软件工程任务上表现出色，但在领域特定代码生成方面仍面临困难。我们认为根本原因在于智能体缺乏隐性知识，包括领域特定的业务规则、接口契约和操作惯例——这些知识被开发者通过实践内化，却从未被文档化。这类知识深埋在领域代码之下，分散在代码实体及其依赖关系中，对缺乏它的智能体而言不可见。这些特性使得隐性知识本质上难以检索或学习。为此，我们提出PRAXIS框架，使智能体能够系统地提取、表示和重用隐性知识以进行领域代码生成。PRAXIS通过在目标代码库中模拟人类开发工作流来获取隐性知识，将其提炼为建立在代码依赖图上的结构化单元，并在代码交互点主动将其呈现给智能体。大量实验表明，PRAXIS优于配备强大智能体搜索能力的最先进智能体，以及基于经验和技能的方法。该方法可无缝集成到多种智能体框架和大语言模型中，并带来一致的性能提升；同时支持持续演化，随着实践积累，性能稳步提升。

## Abstract
LLM agents have achieved strong performance on general software engineering tasks, yet struggle with domain-specific code generation. We identify the root cause as the agent's lack of tacit knowledge, including domain-specific business rules, interface contracts, and operational conventions that developers internalize through practice but never document. This knowledge is deeply buried beneath the domain code, dispersed across code entities and their dependency relations, and invisible to the agent that lacks it. These properties make tacit knowledge inherently difficult to retrieve or learn. In this work, we propose PRAXIS, a framework that enables agents to systematically extract, represent, and reuse tacit knowledge for domain code generation. PRAXIS acquires tacit knowledge by simulating human development workflows within the target codebase, distills it into structured units organized on the code dependency graph, and proactively surfaces it to the agent at the point of code interaction. Extensive experiments demonstrate that PRAXIS outperforms state-of-the-art agents equipped with powerful agentic search capabilities, as well as experience-based and skill-based methods. The approach integrates seamlessly into various agent frameworks and LLMs with consistent performance improvements, and supports continual evolution with performance steadily scaling as practice accumulates.

## 1. 核心问题与研究动机

论文聚焦于一个关键矛盾：**LLM智能体在通用软件工程任务上表现强劲，但在领域特定代码生成任务上显著退化**。例如，在KoCo-Bench基准上，配备DeepSeek-V3.2的OpenHands智能体Pass@1仅为19.1%。

作者通过受控实验定位了问题根因——**隐性知识（Tacit Knowledge）的缺失**。这类知识包括：
- 领域特定的业务规则（如奖励函数约定、算法约束）
- 接口契约（未文档化的输入类型/形状假设、返回值约定）
- 操作惯例（如跨模块协调方式、异常处理策略）

这些知识由开发者在长期实践中内化，却从未记录在文档、注释或源代码中。

### 隐性知识的三个本质属性

1. **潜在性（Latent）**：只有通过实际开发实践才能浮现，无法通过阅读或搜索代码库获得。
2. **结构分散性（Dispersed）**：知识分散在多个代码实体及其依赖关系中，其影响沿依赖路径传播，而非固定在单一位置。
3. **自我无知性（Self-Unawareness）**：缺乏隐性知识的智能体不会意识到自己缺失了什么，因此不会主动去搜索。

这三条属性分别对应论文面临的三个核心挑战：**如何提取、如何表示、如何重用隐性知识**。

## 2. 方法论：PRAXIS框架

PRAXIS通过四个阶段系统性地解决隐性知识的提取、组织和交付问题。前三阶段离线执行，第四阶段在线运行。

### 阶段一：领域内开发实践（In-Domain Development Practice）
- 核心思想：**通过让智能体"做"来暴露隐性知识**，而非被动阅读代码。
- 具体流程：
  1. 从代码库中选择实践函数集合 F_core，通过三种策略筛选：
     - 业务逻辑函数（LLM语义分析识别）
     - 高入度函数（被多个模块调用的核心接口）
     - 高出度函数（调用多个模块、涉及多跳知识）
  2. 保留函数签名和文档字符串，移除函数体。
  3. 由LLM生成自然语言需求描述和多样化测试输入（要求行覆盖率>80%）。
  4. 智能体生成实现，通过**差分测试（Differential Testing）**与真实实现对比：
     - 对每个测试输入，比较智能体输出与真实输出，收集行为差异 Dᵢ。
     - 将差异作为反馈返回给智能体，迭代修正（最多 R_max=3 轮）。

### 阶段二：结构化知识获取（Structured Knowledge Acquisition）
- 对每个实践函数，构造结构化差异 Δᵢ = ⟨实践轨迹, 行为差异, 真实实现⟩。
- 基于具体差异（而非自由式总结）提取知识单元，每单元为四元组：
  - **trigger**（触发场景）：决定何时激活该知识
  - **content**（内容）：具体约束或惯例
  - **evidence**（证据）：来源函数和差异片段，确保可追溯性
  - **confidence**（置信度）：∈[0,1]，由LLM基于差分测试通过情况及证据明确性评分

### 阶段三：基于图的知识组织（Graph-Grounded Knowledge Organization）
- 先构建代码依赖图 G=(V,E)，含两类边：
  - 调用依赖：函数 u 调用 v
  - 数据依赖：u 消费 v 产生的数据
- 每个知识单元锚定到其来源函数的节点上，映射 φ: V → 2ᴷ
- 关键机制：
  1. **知识传播**：沿边双向迭代传播（最多4跳），对相关节点生成视角适配的知识版本
  2. **去重**：等价单元合并，聚合置信度按公式 1 - ∏(1-c) 提升
  3. **冲突解决**：LLM裁判基于证据和置信度裁决矛盾单元

### 阶段四：隐性知识注入（Tacit Knowledge Injection）（在线）
- 核心突破：**主动投递而非被动检索**，解决"不知道自己不知道"的问题。
- 两种注入方式：
  1. **任务初始化注入**：识别目标任务实体，检索其调用者集合，将调用者侧知识注入初始上下文
  2. **交互触发注入**：嵌入工具层，当智能体搜索/读取/编辑代码时，将相关知识追加到工具返回结果中
- **在线知识演化**：从真实任务轨迹中提取新知识，并基于任务成败更新现有知识的置信度（成功则增强，失败则衰减，衰减因子 β=0.8）。

## 6. 主要结论与发现

1. **PRAXIS显著优于所有基线**：平均Pass@1达32.06%，相对第二优方法（OpenCollab，27.48%）提升16.7%，相对裸OpenHands（19.08%）提升绝对13个百分点。

2. **四个组件缺一不可**：
   - 移除开发实践 → 最大性能下降（32.06→27.48），证明隐性知识无法通过静态源代码分析获得。
   - 移除图组织、主动注入、结构化表示均造成不同程度下降。

3. **跨框架与模型稳定泛化**：在OpenHands+DeepSeek-V3.2、SWE-Agent+DeepSeek-V3.2、OpenHands+GPT-5.5、OpenHands+Qwen3.6-Plus四种组合下均有一致提升。

4. **可迁移至新任务类型**：在AInsteinBench（bug修复）上，整体解析率从27.2%提升到31.2%，所有科学领域均有增益。

5. **性能随实践积累持续扩展**：单函数实践即超越最强演化基线Trace2Skill，实践规模增加带来稳定提升。

6. **在线演进有效**：大部分领域在部署期间持续改进，无退化现象。

7. **知识质量可靠**：人类评分（5分制）显示内容真实性4.28、触发准确性4.24、证据可追溯性3.62；置信度与人类判断的Spearman相关系数ρ=0.75（p<0.001）。知识类型分布：业务规则（34.7%）、API模式（24.0%）、接口契约（22.7%）、错误处理惯例（14.7%）、风格偏好（4.0%）。

## 7. 优点与亮点

1. **问题定位精准且深刻**：将"隐性知识缺失"概念化为三个可操作属性，理论分析扎实，案例剖析透彻（RAG工厂方法的两个契约案例分析具有说服力）。

2. **方法论设计优雅闭环**：
   - 提取与属性一对应（实践→暴露潜在知识）
   - 表示与属性二对应（图组织→捕捉分散约束）
   - 投递与属性三对应（主动注入→克服自我无知）

3. **"练习学"启发式思路**：模拟人类开发者"在实践中学习"的方式，把代码库当作练习场，让智能体通过试错和差分测试自行暴露知识缺口，无需人工标注。

4. **主动注入机制是重要创新**：突破了传统RAG/检索范式的局限——"无法搜索自己不知道的东西"，将知识投递嵌入工具层，实现上下文感知的精准送达。

5. **离线-在线双轨设计**：离线实践一次性积累知识，在线部署持续演进，兼顾成本效率与长期能力增长。

6. **训练无关（Training-Free）**：无需微调，可叠加在任何现有智能体框架之上，实用性强。

7. **实验设计全面**：主效果、消融、泛化、迁移、扩展性、质量评估多维度覆盖，统计显著性检验加分。

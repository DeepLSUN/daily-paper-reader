## 摘要
在边缘设备上部署大语言模型（LLM）进行推理因严重的内存和带宽限制而具有挑战性。虽然投机解码和专家混合（MoE）已被提出用于提高推理效率，但简单地将它们结合往往会带来过多的验证开销和较差的专家复用，限制了它们在内存受限边缘场景中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自投机解码框架。S2-MoE通过路由感知的自适应投机扩展减少了冗余验证，通过复用感知的专家门控提高了验证效率，并通过共享上下文对齐草稿和目标执行。在llama.cpp中实现，S2-MoE在边缘设备上的多种MoE模型和数据集上，相比标准自回归解码实现了最高5.3倍（平均约2.0倍）的加速。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama.cpp, S2-MoE achieves up to 5.3x speedup (about 2.0x on average) over standard autoregressive de?coding across diverse MoE models and datasets on edge devices.Code is available at https://github.com/angerybob/S2-MoE.

## 1. 核心问题与研究动机

边缘设备上的大语言模型（LLM）推理部署面临严重的内存和带宽约束。尽管投机解码（Speculative Decoding, SD）和专家混合模型（Mixture-of-Experts, MoE）分别被提出用于提升推理效率，但作者指出，**将两者朴素结合会引发严重的效率问题**：

- **验证开销过高**：MoE 模型中，草稿（draft）token 可能激活不同的专家，破坏密集模型在验证阶段天然具备的参数复用特性，导致验证阶段需要访问大量额外参数；
- **被拒绝 token 造成冗余专家激活**：被拒绝的草稿 token 可能触发分散的专家激活，使验证代价不成比例地增加；
- **草稿保真度受限**：轻量化草稿模型与目标模型之间的一致性不足，导致接受率有限。

论文从吞吐量分解式出发（吞吐量 = 输出密度 × 带宽 / 参数密度），指出硬件的内存带宽（BW）受限于资源受限设备，因此需要通过提高输出密度和降低参数密度来提升推理效率。SD 和 MoE 分别对应这两个方向，但二者的直接结合并不理想，这构成了 S2-MoE 的核心研究动机。

## 2. 方法论

S2-MoE 是一个自投机解码框架，包含三个核心组件：

### 2.1 路由感知的自适应投机扩展（Routing-aware Adaptive Speculative Expansion）

**核心思想**：候选 token 的效用应综合"接受可能性"和"验证成本"来评估，而非仅看置信度。

- **预期收益**：对每层深度为 k 的草稿 token，其前缀置信度 \( p_i = \prod_{j=1}^k p_{i,j} \) 用于估计接受概率，预期收益 \( B_i = p_i \cdot T_{\text{AR}} \)，其中 \( T_{\text{AR}} \) 是目标模型单步解码的平均延迟；
- **路由感知成本估计**：验证成本取决于该 token 引入的**新增专家数量**，边际验证成本定义为：
  \[
  \Delta C_{\text{ver}}(i|S) = |E_i \setminus \bigcup_{j\in S} E_j| \cdot T_{\text{exp}}
  \]
  其中 \( S \) 为已选入扩展的 token 集合，\( E_i \) 为 token i 预测激活的专家集合，\( T_{\text{exp}} \) 是引入一个额外专家带来的延迟；
- **效用驱动的贪心扩展**：定义效用 \( U_i = B_i / C_i \)，当 \( U_i \geq 1 \) 时将该候选纳入扩展，直至无满足条件的候选。相比固定宽度或置信度导向的修剪，该方法能更好地感知 MoE 特有的专家级验证成本。

### 2.2 复用感知的专家门控（Reuse-aware Expert Gating）

**核心思想**：MoE 中相邻 token 常被路由到不同专家，导致并行验证时参数复用率低下。该方法通过软性偏置专家路由决策，促进验证批次内的专家复用。

关键步骤：
1. **跨 token 专家重要性聚合**：利用 token 级置信度 \( w_b \) 加权聚合各 token 的专家门控 logits：\( g_e = \sum_{b \in B} w_b \cdot \ell_{b,e} \)；
2. **全局偏好专家选择**：选择 Top-Cap 个专家作为全局偏好的专家集合 \( E^★ \)，cap 为预设上限；
3. **软路由偏置**：对每个 token 的门控 logits 注入可微偏置 \( \ell'_{b,e} = \ell_{b,e} + \lambda_b \cdot \mathbb{1}[e \in E^★] \)，其中 \( \lambda_b \) 由该 token 的 top-1 专家与第 (k+1) 专家的分数差决定，使得偏置主要影响边界专家而不破坏主导路由决策；
4. **高效融合实现**：通过轻量级 CUDA kernel 实现，额外开销可忽略。

### 2.3 上下文对齐的自投机解码（Context-aligned Self-speculative Decoding）

**核心思想**：草稿模型与目标模型共享同一 KV 缓存，避免草稿独立维护上下文导致的误差累积。

- 目标模型先处理提示词并建立 KV 缓存；
- 草稿生成阶段直接读取共享上下文，草稿的 KV 更新被标记为临时，在验证前回滚；
- 仅被接受的 token 才提交到共享缓存；
- 该方法将草稿误差限制在单个投机步内，阻断跨迭代误差传播，提升长期生成的接受率。

## 6. 主要结论与发现

1. **显著加速**：S2-MoE 在 Jetson Orin 上实现 1.3x–5.3x 加速，在 RTX 4090 上实现 1.2x–2.9x 加速，平均约 2.0x；

## 7. 优点

- **问题定位准确**：从吞吐量分解出发，清晰识别出 MoE 投机解码的两大瓶颈——冗余验证和低参数复用，并针对性地提出解决方案；
- **方法论创新**：将验证成本建模为"新增专家数 × 单位专家延迟"，将专家级路由信号纳入投机决策，解决置信度无法区分 MoE 验证成本的问题；复用感知门控以极小的路由扰动换取显著的参数复用提升，设计精巧；
- **成本模型准确度高**：预测验证延迟与实测值 R²=0.943–0.999，MAPE=0.8%–4.5%，可靠性高；
- **工程质量好**：完整集成到 llama.cpp，支持专家级参数卸载（Jetson 上卸载到 SSD，RTX 4090 上卸载到 CPU 内存），代码已开源；
- **无需训练**：相比 EAGLE-3 等依赖训练草稿模型的方法，S2-MoE 是 training-free 的，适用范围更广。

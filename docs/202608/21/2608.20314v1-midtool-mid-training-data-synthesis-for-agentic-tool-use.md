## 摘要
中期训练日益被认为是塑造大语言模型能力的关键阶段。近期研究表明，有针对性的中期训练可以增强数学和科学等推理密集型能力，也能提升软件工程场景中的智能体能力。在本工作中，我们研究平行但较少探索的智能体能力：通用工具使用。我们提出MidTool，一个面向智能体工具使用中期训练的开源语料构建流程，该流程将大规模网页、PDF和代码数据与来自真实世界工具API、MCP技能以及文档导向工作流的合成监督相结合。MidTool旨在教会模型识别工具可用性、从上下文中提取参数、编排工具调用工作流，并从不完整信息中恢复。我们在MidTool-Mix上对Qwen3-4B-Base和Qwen3-8B-Base进行中期训练，然后应用包含监督微调和强化学习的后续后训练。与基线相比，MidTool-Mix在BFCL、tau2-Bench和MCP Universe上的SFT和RL下游性能均持续提升。这些结果表明，与其他重要的大语言模型能力类似，通用工具使用受益于专门的中期训练，而非完全留待后训练阶段。

## Abstract
Mid-training is increasingly recognized as a critical stage for shaping the capabilities of large language models. Recent work has shown that targeted mid-training can strengthen reasoning-intensive abilities such as math and science, and can also improve agentic capabilities in software-engineering settings. In this work, we study the parallel but less explored agentic capability: general tool use. We present MidTool, an open corpus construction pipeline for agentic tool-use mid-training that combines large-scale web, PDF, and code data with synthesized supervision from real-world tool APIs, MCP skills, and document-grounded workflows. MidTool is designed to teach models how to recognize tool affordances, ground arguments from context, compose tool call workflow, and recover from incomplete information. We mid-train Qwen3-4B-Base and Qwen3-8B-Base on MidTool-Mix, and then apply follow-up post-training with both supervised fine-tuning and reinforcement learning. Compared with baselines, MidTool-Mix consistently improves downstream performance under both SFT and RL on BFCL, tau2-Bench, and MCP Universe. These results suggest that general tool use, like other important LLM capabilities, benefits from dedicated mid-training rather than being left entirely to post-training.

## 一、核心问题与研究动机

- **背景**：中期训练（Mid-training）已被证实是塑造大语言模型能力的关键阶段，能够增强数学、科学等推理能力，也能提升软件工程场景中的智能体能力。
- **核心问题**：与上述领域不同，**通用工具使用（general tool use）** 作为同样重要的智能体能力，几乎完全依赖后训练（SFT + RL）来获得，缺乏专门的中间训练数据与方法。论文提出一个关键问题：**通用工具使用能力能否通过专门的中期训练更早地塑造，而非完全交给后训练？**
- **动机**：成功使用工具所需的知识不仅存在于显式的交互轨迹中，还分布在开发者文档、手册、PDF、代码仓库、API 规范等大量异构资源中，这些资源很少以干净的智能体演示形式出现。此外，后训练同时承担工具识别、参数构建、缺失信息澄清、多步执行等多项原子能力的学习，负担过重。

## 二、方法论

### 核心思想
构建 **MidTool** 开源语料管线，将四类互补数据源（网页、PDF、代码、结构化工具工件）转换为统一的智能体中期训练语料 **MidTool-Mix**（20.3B tokens / 11.22M 样本），并通过两个合成分支分别针对工具使用的两大核心缺陷：**grounding（接地/定位）** 与 **execution（执行）**。

### 三阶段管线

1. **Stage 1：数据源收集**
   - **网页数据**：FineWeb 的 Common Crawl 多个 dump（2020–2025），覆盖 API 参考、开发者文档、教程等。
   - **PDF 数据**：FinePDFs 英文子集，提供长篇幅程序性内容。
   - **代码数据**：GH Archive 事件数据初始化仓库发现，两个切片——agent/MCP 相关仓库 + 高质量公开仓库（Python、Java、JS、TS、Go、Rust 等），排除个人项目、fork、基准/数据集仓库（含主动维护的 benchmark 黑名单）。
   - **工具数据**：REST API 和 MCP skills，提供可执行 schema 和工具边界。

2. **Stage 2：预处理**
   - **代码**：扩展名过滤 + StarCoder 启发式内容过滤 + SHA-256 精确去重 + MinHash LSH 近似去重，仅保留 docs/examples/tutorials 等文档类目录。
   - **网页/PDF**：四阶段流程——关键词/URL 高召回预筛 → fastText 分类器（基于 LLM 标注种子训练）→ 文档级质量过滤 → MinHash LSH 去重；PDF 阈值更严格。

3. **Stage 3：智能体轨迹合成**
   - **分支一：上下文接地轨迹增强（Context-grounded Trajectory Augmentation）**
     - 用 Qwen3-235B-A22B-Instruct-2507 对文档标注质量分数和工具可用性画像（affordance profile）。
     - 规则式规划器根据质量分配合成预算：常规 QA 覆盖工具选择、schema 接地参数提取、格式约束调用、工作流识别、多/并行使用等原子能力；轨迹样本覆盖顺序执行、参数澄清、工具切换、长上下文推理。
   - **分支二：原生智能体轨迹合成（Native Agentic Trajectory Synthesis）**
     - 从 API 组和 MCP skills 构建工具清单，GPT-5 分配质量分数和轨迹族可行性画像（单次调用、复杂多/并行调用、信息缺失场景）。
     - 综合多样用户画像，由确定性质量自适应预算控制器强制分配最终轨迹配额（偏好多轮轨迹）。
     - 分类生成器用 GPT-5 / GPT-5.1 / GPT-5.2 生成轨迹，严格验证轮次顺序、schema 接地、必需参数、工具响应一致性，失败重试。
     - 混入 AWM 合成环境收集的 rollout 轨迹和 Nemotron Agentic 数据集过滤轨迹。

### 语料构成
- Web 42%（4.4B 源 / 4.1B 增强）、Code 26%（3.8B / 1.5B）、PDF 23%（2.6B / 2.1B）、原生智能体轨迹 9%（1.8B）。
- 所有轨迹归一化为纯聊天模板，无特殊控制 token。
- t-SNE 可视化显示 MidTool-Mix 与 FineWeb、Dolmino 仅少量重叠，占据文档密集、工作流导向、智能体工具使用的独特区域。

## 三、实验设计

### 训练设置
- 基础模型：**Qwen3-4B-Base** 与 **Qwen3-8B-Base**。
- 每个规模四种配方对比：原始 base + SFT；原始 base + SFT + RL；MidTool-Mix 中期训练 + SFT；MidTool-Mix 中期训练 + SFT + RL。
- SFT 数据：TOUCAN 中采样的 100K 工具使用子集；RL 采用 AWM 设置，526 个合成工具使用环境。
- 对照组：已发布的后训练 Qwen3-4B/8B 模型；匹配预算的通用中期训练基线 **Dolmino-20BT**；无中期训练设置。

### 基准（Benchmark）
1. **BFCLv3**：函数调用质量，单轮 + 多轮（缺失函数、缺失参数、长上下文）+ 幻觉。
2. **τ²-Bench**：交互式任务完成，覆盖航空、零售、电信三个垂直领域（Pass@1 / Pass@4）。
3. **MCP-Universe**：真实 MCP 服务器执行，覆盖浏览器自动化、金融、位置、多服务器、网页搜索。

### 对比方法
各规模的 SFT-only、SFT+RL（有/无中期训练）、官方后训练模型，以及消融实验中的 Dolmino-20BT、仅处理原始数据、+原生轨迹、+上下文接地轨迹等变体。

## 四、资源与算力

- **中期训练与 SFT**：使用 **ArcticTraining** 框架，**32 块 H200 GPU**。
- **智能体 RL**：采用 AWM 设置（VeRL 风格 GRPO），**8 块 B200 GPU**。
- **关键超参数**：中期训练——1 epoch，序列长度 8192，学习率 3×10⁻⁵，WSD 调度，4M token 全局 batch；SFT——序列长度 32768，学习率 2×10⁻⁵，batch 128；RL——GRPO，64 步，学习率 4B 为 1×10⁻⁶ / 8B 为 5×10⁻⁷，每 prompt 16 个 rollout，KL 系数 0.001，最大 agent 轮数 20。
- **未明确说明**：论文未报告具体的总训练时长（GPU 小时数）或各阶段耗时。

## 五、实验数量与充分性

- **主实验**：3 个基准 × 2 个模型规模 × 4 种训练配方，共 24 组以上结果，覆盖单轮/多轮/幻觉/不同垂直领域/不同 MCP 域，规模较充分。
- **消融实验**：固定 4B SFT 配方，5 种中期训练条件（无中期训练、Dolmino-20BT、仅处理原始数据、+原生轨迹、+上下文接地轨迹、MidTool-Mix），在全部 3 个基准上对比 8 项指标，设计较系统。
- **补充实验**：SFT 收敛分析（3 种初始化）、RL 奖励曲线分析（4B/8B）、视觉工具使用探索性实验（Gemma3-4B + FineVision + VisualToolBench）、污染分析（DeCon）、语料组成分析。
- **公平性考量**：下游后训练配方固定以隔离中期训练效果；使用匹配预算的通用中期训练基线；代码切片主动排除 benchmark 仓库；DeCon 污染审计（<20 个候选且均为误报）。整体实验设计严谨、对比公平。

## 六、主要结论与发现

1. **中期训练带来超越后训练的能力**：MidTool-Mix 在 4B/8B 规模上一致提升 BFCL、τ²-Bench、MCP-Universe 的下游性能，且 RL 通常进一步放大收益；多轮和交互式场景提升最明显（如 4B BFCL 多轮平均较 SFT-only 提升超 10 个点）。
2. **收益可迁移到真实智能体任务**：τ²-Bench 上 4B Pass@1 几乎翻倍，8B 在航空、零售等域提升显著；MCP-Universe 上中训模型在浏览器自动化、金融、位置等域均有改善。
3. **揭示了能力边界**：MCP-Universe 的网页搜索子集始终为 0.00，说明通用工具使用中期训练提供可复用的 schema 接地和工具选择先验，但**深度搜索类探索性行为需要专门的轨迹数据和训练目标**。
4. **两个合成分支互补**：原生智能体轨迹对 BFCL（精确函数调用）贡献更大；上下文接地增强对

上下文接地增强对交互式任务（如 τ²-Bench 的完整流程执行）和需要文档理解的场景贡献更大；两者组合（MidTool-Mix）在所有基准上均为最优，验证了"接地先验 + 执行技能"双管齐下的有效性。

5. **中期训练是可扩展的通用能力塑造器**：仅用 20B token 的中期训练（约为预训练语料的 1%~2% 规模预算），即可在多种下游 agentic 任务上获得一致且可叠加的收益，表明工具使用能力不必完全交给后训练，**在不改变预训练/后训练配方的情况下，中期训练是性价比极高的能力干预窗口**。

6. **数据质量与格式统一比数据量更关键**：消融显示，仅堆砌"处理过的原始文档"（未合成轨迹）收益有限，而经过高质量过滤 + 轨迹化改造后的数据才能有效迁移为智能体能力；同时，去除特殊控制 token、统一为纯聊天模板的做法也验证了格式简洁性的重要性。

## 七、局限性

- **规模验证有限**：主实验仅覆盖 4B 和 8B 两个小规模模型，未在大规模（如 70B+）上验证 MidTool 的收益是否持续存在或衰减。
- **RL 环境为合成场景**：后训练 RL 阶段使用的是 AWM 合成工具环境，与真实世界的工具调用分布存在差距，因此中期训练 + RL 的叠加收益在真实环境中可能无法完全复现。
- **搜索类能力未解决**：MCP-Universe 的网页搜索域在所有配方下均为 0.00，说明当前数据管线缺乏深度探索、在线信息检索等行为轨迹，这一能力边界未被突破。
- **视觉/多模态工具使用仅做初步探索**：视觉工具使用实验规模小、仅作为探索性结果，未纳入主结论。
- **数据管线成本高**：大量依赖 GPT-5 系列闭源模型进行标注和轨迹合成，合成过程中的 API 成本与过滤损耗未被量化，可复现性有一定门槛。

## 八、总结与启发

MidTool 的核心贡献在于：**首次系统性地论证了通用工具使用能力可以通过专门设计的中期训练语料来提前塑造**，并开源了完整的可扩展数据合成管线（20.3B tokens / 11.22M 样本的 MidTool-Mix）。论文通过严谨的三阶段实验设计，证明了"文档理解 → 轨迹合成 → 能力内化"这一通路在小模型上即可带来显著且可叠加的收益，且与后训练（SFT/RL）正交互补。

这一工作对智能体社区的重要启示包括：

- 智能体能力的培养不应只依赖后训练，中期训练是尚未被充分挖掘的干预窗口；
- 海量异构的开发者文档、代码仓库、API 规范等"沉默的知识"可以通过轨迹化改造转化为高质量训练信号；
- 合成数据管线中，"质量过滤 + 能力画像 + 配额控制"的精细化设计远比简单拼接原始语料更有效；
- 工具使用能力可被分解为"接地"与"执行"两类原子技能，分别对应不同的数据合成策略，这一视角对后续研究具有方法论价值。

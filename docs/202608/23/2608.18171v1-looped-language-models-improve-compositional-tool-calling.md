## 摘要
循环语言模型在推理基准上已展现出令人鼓舞的结果，但其在智能体工具使用方面的潜力在很大程度上仍未得到探索。我们在组合式工具调用场景中研究这一问题，在该场景中，模型必须协调多个API调用、维护中间状态并保持跨工具交互的依赖关系。我们评估了原生和改造后的循环语言模型在API-Bank、BFCL和NESTful上的表现，比较了在匹配的监督微调配方下训练的循环与非循环模型，并改变了推理时的循环深度。在受控实验中，循环计算通常有利于组合式且依赖感知的工具使用，而在孤立的API调用上则带来较小且更依赖模型的增益。多步骤工具使用的准确率通常随循环深度的增加而提高；然而，自适应推理通过仅在需要时分配额外计算，实现了更优的计算-性能权衡。我们的结果表明，循环语言模型是一种有前景的架构，适用于需要可靠规划、协调和执行组合式工具使用工作流的智能体系统。

## Abstract
Looped language models have shown promising results on reasoning benchmarks, yet their potential for agentic tool use remains largely unexplored. We study this question in compositional tool-calling settings, where models must coordinate multiple API calls, maintain intermediate state, and preserve dependencies across tool interactions. We evaluate native and retrofitted looped language models on API-Bank, BFCL, and NESTful, comparing looped and non-looped models trained under matched supervised fine-tuning recipes and varying recurrent depth at inference time. In controlled experiments, recurrent computation generally benefits compositional and dependency-aware tool use, while providing smaller and more model-dependent gains on isolated API invocation. Accuracy on multi-step tool use generally increases with recurrent depth; adaptive inference, however, achieves a more favorable compute-performance trade-off by allocating additional computation only when needed. Our results suggest that looped language models are a promising architecture for agentic systems that require reliable planning, coordination, and execution of compositional tool use workflows.

### 2. 论文提出的方法论：核心思想、关键技术细节

**核心思想**：利用循环语言模型的迭代潜在计算能力来增强组合工具调用中的结构化决策能力，包括函数选择、参数生成、调用排序与依赖绑定。

**关键技术细节**：

- **循环 Transformer 架构**：不同于堆叠独立参数层的标准 Transformer，循环 Transformer 反复应用共享的 Transformer 块。设输入序列的初始隐藏表示为 h⁰，在循环迭代 t 时，共享块 Fθ 更新潜在状态：hᵗ = Fθ(hᵗ⁻¹)；共享输出头在每次迭代后产生预测 πᵗ(y|x) = gθ(hᵗ)。
- **组合工具使用形式化**：将工具调用解表示为有向无环图 G = (C, E)，其中 C 为工具调用集合，E 为调用间依赖关系。单调用任务 |C|=1；独立调用 E=∅ 可并行；依赖调用通过 ϕⱼ(x, oᵢ₁, ..., oᵢₘ) 将前序调用输出实例化为后续参数。
- **两类循环模型**：
  - **原生循环模型 Ouro**：预训练的循环语言模型（Ouro-1.4B / Ouro-2.6B），最大循环深度 T_max=4，使用学习的条件退出门 λᵗ(x) 实现自适应计算。训练采用两阶段：第一阶段联合优化语言模型和退出门（含熵正则化，鼓励多迭代），第二阶段冻结主干、仅优化退出门（基于额外迭代的边际效用训练）。
  - **改造循环模型（Retrofitted）**：将预训练 Transformer 划分为非循环前奏、共享循环块、非循环尾声，在保留预训练参数的同时引入循环。循环深度按 Poisson-lognormal 分布采样，损失仅在采样深度终端计算并含 KL 正则化。
- **推理协议**：
  - **固定深度推理**：每个 token 执行预定数量的循环迭代（Ouro 为 1–4 层；改造模型为 1、2、4、8 层）。
  - **自适应推理**：利用 Ouro 的预训练退出门，当累积退出概率超过阈值 q（∈ {0.1, 0.3, 0.5, 0.7, 0.8}）时逐 token 退出循环。

### 6. 论文的主要结论与发现

1. **循环语言模型总体上提升组合工具使用**：在受控 SFT 条件下，Ouro 模型在 BFCL 和 NESTful 上优于非循环基线，尤其在 Parallel 和 Parallel-Multiple 等组合类任务上增益最大；改造循环模型（Llama-3.2-1B、OLMo-2-1B）也在多组合类目上相对其非循环母版有所提升。
2. **孤立 API 调用上的增益较小且依赖模型**：API-Bank 上循环与非循环差异不大，反映其单调用属性对迭代计算需求较低。
3. **性能随循环深度增加**：BFCL 准确率随固定循环深度上升，组合类任务持续受益于更多迭代；NESTful Win Rate 同步提升；Ouro-2.6B 的饱和点比小模型更早，说明大模型需更少的细化步骤。
4. **自适应推理优化了计算-性能权衡**：自适应退出在平均循环次数更少的情况下，匹配或超过最优固定深度的性能，实现了按需分配计算。
5. **循环迭代逐步修正语义错误**：定性案例显示，深度增加可修复函数选择错误、参数命名错误、调用顺序错误、多余调用以及缺失的依赖调用等，证明循环细化的是调用结构与依赖绑定而非仅格式。

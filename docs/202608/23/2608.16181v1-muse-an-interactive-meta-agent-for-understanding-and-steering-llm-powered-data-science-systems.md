## 摘要
近年来，大语言模型的进步催生了一类新型的智能体数据科学系统，使用户能够通过自然语言完成复杂的数据科学工作流程。尽管这些系统能显著减少人工工作量，但当出现失败或意外输出时，诊断其行为并引导推理过程仍然困难。我们提出了MUSE，一个交互式元智能体，通过以下方式增强用户对智能体数据科学系统的理解和控制：(1) 将低级执行轨迹动态重构为多个语义层级，支持从高级概览到低级实现细节的导航；(2) 使用户能够在上下文中引用特定工作流步骤，以提出有依据的问题、提供反馈并修正有问题的步骤，而无需手动定位相关执行历史；(3) 通过呈现可疑步骤以供检查、搭建修复过程框架，并将用户的修复意图转化为对底层智能体的情境化指令，从而支持混合主动引导。在一项受试者间研究（n = 15）中，MUSE提高了任务效率，并增强了用户理解和引导智能体数据科学工作流程的信心。

## Abstract
Recent advances in large language models have enabled a new class of agentic data science systems that allow users to complete complex data science workflows through natural language. Although these systems can significantly reduce manual effort, it remains difficult to diagnose their behavior and steer the reasoning process when failures or unexpected outputs occur. We present MUSE, an interactive meta-agent that enhances user understanding and control of agentic data science systems by (1) dynamically restructuring low-level execution traces into multiple semantic levels that support navigation from high-level overviews to low-level implementation details; (2) enabling users to reference specific workflow steps in context to ask grounded questions, provide feedback, and revise problematic steps without manually locating relevant execution history; and (3) supporting mixed-initiative steering by surfacing suspicious steps for inspection, scaffolding the repair process, and translating user repair intent into contextualized instructions for the underlying agent. In a between-subjects study (n = 15), MUSE improved task efficiency and increased users' confidence in understanding and steering agentic data science workflows.

### 一、核心问题与整体含义（研究动机和背景）

**研究背景**
- 大语言模型（LLM）的快速发展催生了新一代的智能体数据科学系统（如MLE-STAR、DeepAnalyze等），用户只需用自然语言表达需求，系统即可自动完成数据清洗、特征工程、模型训练等复杂的数据科学工作流程。
- 这类系统大幅降低了数据科学任务的门槛，使非专业用户也能完成以往需要大量代码经验的复杂工作。

**核心问题**
- 尽管LLM驱动的数据科学系统简化了工作流，但当系统出现失败或意外输出时，用户**难以诊断其行为**并**引导其推理过程**。
- 现有调试工具（如LangSmith、Langfuse、Phoenix等）主要面向**专业的代理开发者**，暴露的是低级的代理消息、内部状态和工具调用等细粒度信息，对非专家用户而言信息过载且难以理解。
- 现有工具的修复方式需要用户手动编写自由文本指令，对提示词经验有限的用户构成巨大障碍。

**研究表明的关键痛点**
- 作者的先导研究（n=7）发现，用户的困难不在于"看不到低级日志"，而在于**无法判断整体工作流是否合理**——原始日志缺乏结构，难以评估系统进展；修复时需追溯底层实现细节，并将高层次分析意图转化为具体的代码或提示词更改。


### 二、论文提出的方法论

**核心思想**：MUSE是一个**交互式元智能体（meta-agent）**，作为用户与底层数据科学代理系统之间的中介层，不直接执行数据科学任务，而是**理解和重构**底层代理的行为，并提供交互式接口供用户监控和引导。

**系统架构——四大核心层**：

1. **摘要层（Summarization Layer）**
   - 捕获底层代理的五类执行日志：推理轨迹、工具调用、代码、信号（警告/错误/完成标记）、产物（中间输出）
   - 利用步骤完成标记（step-completion markers）动态分割日志流为**语义块（semantic chunks）**，而非依赖LLM从自由文本推断边界
   - 每个语义块被转化为**五级语义表示**（L1–L5）：L1阶段标题 → L2自然语言摘要 → L3有序子步骤列表 → L4详细操作（文件、命令、参数）→ L5原始轨迹（代码、工具输出），支持从概览到细节的渐进式导航

2. **监控层（Monitoring Layer）**
   - 基于预定义的警告启发式规则（从MLE-Bench的20个数据科学任务中开发），检测语义块中的可疑行为
   - 警告分为**数据级警告**（如激进数据删除、覆盖原始数据、硬编码阈值、未验证的Schema假设等14类）和**代理级警告**（如推理-行动不匹配、任务偏离、验证不足等7类）
   - 以局部警告徽章（warning badge）形式直接呈现在对应步骤卡片上，点击可查看"为什么警告"的解释和后续修复操作

3. **验证层（Verification Layer）**
   - **上下文引用**：用户可直接将工作流步骤拖入聊天界面，MUSE自动解析该锚点并检索相关报告、脚本、产物作为提示证据，回答基于证据而非仅凭用户查询
   - **脚手架式验证**：用户高亮输出并右键选择"帮我验证"，MUSE结合所选输出、文件与会话上下文，生成3–5个验证选项供用户选择，然后自动生成验证脚本在沙盒中执行，不修改管道输出

4. **引导层（Steering Layer）**
   - 用户点击"修订"后，MUSE基于警告解释和自动生成的修复建议提供**脚手架式修复**，用户选择修复计划后，MUSE自动将修复请求、受影响步骤和警告上下文组装为情境化指令，传递给底层代理，用户无需手动拼装上下文

**关键技术细节**：
- 使用Gemini API生成L1–L5语义翻译，使用Claude Agent SDK驱动底层DS代理和MUSE自身
- MUSE是只读代理，与ds-pipeline并行运行，实时读取产物回答用户问题；需要修订时再将控制权交还给ds-pipeline
- 底层DS代理采用技能化（skill-based）架构，包含ds-pipeline、ds-cleaning、ds-eda、ds-feature-engineering、ds-modeling、ds-progress-checker等专用技能
- 所有LLM调用使用temperature=0以确保可复现性

### 六、主要结论与发现

1. **任务效率提升**：MUSE用户平均完成时间为17分钟/任务，比条件A（原始日志）减少35%（p=.035），比条件B（DiLLS）减少9%（p=.875，不显著）。三组差异整体显著（F(2,12)=4.71, p=.031）。

2. **高成功率**：条件B和C均达90%成功率，条件A仅50%。

3. **用户信心增强**：MUSE用户对最终DS结果的信心最高（均值5.80 vs 2.60 vs 4.20），差异显著（p=.0265）。

4. **认知负荷降低**：在"匆忙感"（p=.0165）、"努力程度"（p=.0298）和"挫败感"（p=.0428）三个NASA TLX维度上存在显著差异，MUSE组最优。

5. **警告解决率大幅提升**：MUSE用户平均解决2.8个警告，远超条件B的0.8个（p=.0118），说明就地修复功能有效促进了问题解决。

6. **智能体错误类型分布**：最常见的错误是"未验证的Schema假设"（56%）、"缺失数据未检查"（16%）和"单次分割评估"（12%）。弱模型（Haiku）比强模型（Opus）多触发27%的警告。

7. **交互模式转变**：MUSE将监控行为从"线性搜索"转为"局部检查"——原始日志条件下用户平均滚动147次/任务，MUSE条件下降至61次；语义滑块是最频繁交互（162次调整）。

8. **新用户行为分类**：识别出三类用户行为模式——AI委托者（AI Delegators）、AI协作者（AI Collaborators）和AI审计者（AI Auditors），不同模式对验证支持的需求各异。

9. **关键设计验证**：五级语义表示（S1理解）、局部警告（S2错误定位）、验证脚手架（S3验证）和上下文修复（S5控制）均获得用户的显著正面评价。


### 七、优点

3. **混合主动（mixed-initiative）设计**：MUSE不仅被动响应用户查询，还主动检测可疑步骤、呈现警告、推荐修复选项、建议验证方案，有效平衡了系统自主性与用户控制权。

6. **实验设计较为严谨**：三个条件形成了合理的渐进对比（原始日志 → 摘要+警告 → 完整交互支持），统计方法使用恰当，定性与定量数据相互印证。

7. **全面的错误分类体系**：提供了21类细粒度的警告启发式规则（14类数据级+7类代理级），对后续研究具有参考价值。

8. **工程实现完整**：提供了完整的系统实现细节（技术栈、提示词模板、底层代理架构、技能定义），可复现性较好。

## 摘要
智能体技能已成为赋予语言模型智能体可复用程序性知识的重要机制。然而，仅提供技能并不能保证当前模型能够有效地识别、应用和协调这些技能。为了提升技能使用能力，我们引入了SKT，一种经过验证的数据合成流水线，可从大量智能体技能中构建基于技能的任务和可执行轨迹。SKT选择合适的单技能和多技能配置，通过基于规则和基于智能体的验证及反馈引导修复来合成任务，并仅保留成功且充分使用每项所需技能的轨迹。利用2,000个公开技能，SKT生成了4,000个任务包和27,164条经过验证的轨迹。基于同一流水线和不相交的测试池，我们进一步构建了SkillEval，一个用于评估技能使用的留出式可执行基准。跨多种模型、基准和智能体框架的实验表明，在SKT生成的轨迹上进行监督微调 consistently 提升了技能使用性能。验证消融、跨框架评估和扩展实验进一步证明，这些提升依赖于高质量监督，不仅适用于单一智能体接口，而且随着更广泛的技能覆盖而增强。综合这些结果，验证数据合成被确立为一种有效且可扩展的技能使用训练方法。

## Abstract
Agent skills have become an important mechanism for equipping language-model agents with reusable procedural knowledge. However, providing skills alone does not guarantee that current models can effectively identify, apply, and coordinate them. To improve skill-use capabilities, we introduce SKT, a verified data synthesis pipeline that constructs skill-grounded tasks and executable trajectories from large collections of agent skills. SKT selects suitable single-skill and multi-skill configurations, synthesizes tasks through rule-based and agent-based verification with feedback-guided repair, and retains only successful trajectories that substantially use every required skill. Using 2,000 public skills, SKT produces 4,000 task packages and 27,164 verified trajectories. Based on the same pipeline and a disjoint test pool, we further construct SkillEval, a held-out executable benchmark for evaluating skill use. Experiments across diverse models, benchmarks, and agent harnesses show that supervised fine-tuning on SKT-generated trajectories consistently improves skill-use performance. Verification ablations, cross-harness evaluation, and scaling experiments further demonstrate that these gains depend on high-quality supervision, extend beyond a single agent interface, and increase with broader skill coverage. Together, these results establish verified data synthesis as an effective and scalable approach for skill-use training.

- **研究目标**：提出一种可扩展的方法，为 LLM 提供高质量的技能使用训练数据，使其在实际任务中能够可靠地识别、应用和协调各类技能。

### 2. 方法论：SKT 流水线

#### 核心思想

SKT 是一个三阶段的数据合成框架，核心逻辑是：**通过自动化验证机制，构造"可解、可验证、复杂度可控"的技能导向任务，并从中采集高质量、可验证的完整执行轨迹作为训练数据**。该方法的核心竞争力在于"验证"而非纯粹的"生成"，保证了训练数据的质量与可靠性。

#### 具体流程

1. **Stage I：技能筛选（Skill Curation）**
   - 从候选技能库（如公共 skills.sh 库）出发，通过基于评分规则的 LLM 评判器筛选出能够支撑可执行、可客观打分任务的技能。
   - 对多技能组合（k > 1）额外使用"组合评判器"，检查技能之间能否形成角色明确、逻辑连贯的工作流。

2. **Stage II：任务合成（Task Synthesis）**
   - **模板驱动生成**：TaskGen 根据选定的技能集合填充固定任务模板，生成任务包（包含指令、隔离运行环境、执行设置、可执行评估器、参考解决方案），并为每个技能分配预期角色。
   - **规则验证器**：执行确定性检查——验证任务包组件完整、文件路径有效、评估器定义受支持、作者痕迹确认访问了每个技能；在干净环境中执行参考方案需获得满分；并检查任务材料不直接泄露参考答案或技能规则。
   - **智能体验证器**：由 LLM 审查任务的语义质量，确认指令清晰、所需信息在本地可获取、且可见材料不隐式泄露答案或关键评估逻辑。
   - **技能依赖检查**：通过成对 rollout（有/无技能）对比评估器得分，确认任务确实依赖技能才能完成，而非仅凭通用推理可解。
   - **难度控制**：固定求解器在设定技能下独立运行 N 次，若满分率 p_pass ≥ θ_easy 则判定任务过易，退回修复。
   - **反馈引导修复**：未通过门控的任务将接收结构化诊断意见（规则错误/语义反馈/难度建议），修复后重新走完整验证流程；耗尽量修复预算则丢弃。

3. **Stage III：轨迹合成（Trajectory Synthesis）**
   - 由强 LLM（教师模型）通过特定 Agent Harness 在任务包和技能文件可用的条件下执行任务，采集完整轨迹（包括推理、工具调用及结果、输出产物）。
   - **确定性验证器**：要求获得评估器满分、正常且完整的终止、格式正确的工具调用轨迹、显式访问设定技能。
   - **LLM 验证器**：逐技能检查——每个技能必须在相应动作前被查阅、实际影响具体决策或操作，且被正确应用。
   - 失败的 rollout 不提供失败反馈，在全新会话中重新采样；首次通过双重验证的轨迹被保留。

4. **训练目标**：在保留的轨迹上进行**掩码自回归监督微调（SFT）**，损失仅计算于助手生成的推理、工具调用和响应 token 上；系统消息、任务消息和工具观察仅作为上下文，不参与损失计算。这样模型学到的是完整的技能使用过程而非仅答案。

### 6. 主要结论与发现

1. **SKT 一致性提升技能使用性能**：所有 16 组匹配 Harness 对比中，SKT 微调模型均优于原始模型，绝对提升幅度为 3.20~18.91 分。最大提升出现在 Qwen3.5-9B/DeepAgents/SkillEval（51.62→70.53）。
2. **效果依赖外部技能供给**：当推理时扣除技能文件时，SKT 优势大幅缩减（提升仅 0.53~5.69 分 vs. 有技能时的 8.68~18.91 分），说明 SKT 强化的是"使用技能"能力而非"内化知识"。
3. **数据质量是关键**：未经验证和修复的原始合成数据训练模型反而使全部 4 个基准平均分下降（-1.9 至 -19.5 分），与 SKT 训练的全面提升（+5.1 至 +17.2 分）形成鲜明对比，差距高达 11.91~24.61 分。这有力证明了"验证"环节的价值。
4. **行为可跨 Harness 迁移**：跨框架 SFT 保留匹配框架增益的 49.1%~58.1%，说明学到的技能使用行为有较强通用性；匹配框架训练仍有额外优势，反映轨迹中蕴含 Harness 特定交互模式。
5. **混合训练可行**：混合两个 Harness 轨迹训练的单一检查点在全部 8 组对比中优于原始模型，且与专用模型差距不超过 2.71 分，部分指标甚至超过专用模型。
6. **规模效应明显**：SkillEval 分数随训练技能预算单调增长（55.24→72.48），表明更广泛的技能覆盖带来持续的性能提升。
7. **多技能组合同样受益**：SKT 在 K=1、K=2、K≥3 三个技能基数分组中均有提升，K=2 增益最大（+16.77 分），证明其有助于提升复杂多技能协调能力。

### 7. 优点

- **问题定位精准**：针对"模型有技能但不会用"这一被忽视的关键缺口，区别于现有的技能检索、技能内化研究路线。
- **验证思想贯穿始终**：任务级（规则+语义+技能依赖+难度控制）与轨迹级（确定性+LLM）多层验证机制，能有效过滤不可解、过易、泄漏答案、未实质使用技能的任务，从源头保证数据质量。
- **数据质量实证充分**：通过"未验证 vs. 已验证"的尖锐对比，直接量化了验证环节对训练效果的贡献，为数据合成社区提供了重要参考。
- **可扩展性强**：流水线支持任意技能规模（实验证明从 100 到 2,000 技能性能单调增长），且同时能产出训练数据和评估基准（SkillEval），实现数据基础设施的复用。
- **严谨的统计报告**：每个实验条件完整运行 4 次并报告均值±样本标准差，避免单次运行的随机性干扰。
- **开源共享**：发布了 SkillEval 数据集，便于社区复现和后续研究。

### 8. 不足与局限

- **同源偏置风险**：SkillEval 虽使用非重叠技能池，但仍与训练任务共享同一合成流水线、模板和验证逻辑。模型在这种"自产自评"基准上的性能提升，未必能完全迁移到真实世界非合成的任务场景。
- **教师模型与验证器局限**：合成数据质量高度依赖 DeepSeek V4 Pro、Qwen3.5-35B-A3B 等教师模型的能力上限；如果教师本身在特定任务上能力不足，验证器也可能无法有效识别次优轨迹。此外，验证器为 LLM，其判断本身存在不确定性。
- **技能依赖验证的粒度限制**：任务级技能依赖检查采用"技能组合整体有/无"的二元对比，未独立验证每个技能的必要性。多个技能中可能实际只有部分技能起关键作用，这对多技能任务的数据质量有一定影响。
- **Harness 覆盖有限**：训练和评估仅涉及 DeepAgents 和 OpenCode 两种交互框架，是否扩展至其他流行的 Agent 框架（如 AutoGPT、BabyAGI 风格框架、ReAct 等）还有待验证。
- **复杂度可控的局限**：任务合成基于固定模板，复杂度主要通过技能数量（k=1/2/3）控制，对更复杂的真实工作流（如长时序依赖、动态环境、多 Agent 协作）覆盖不足。

- **资源透明度不足**：未报告 GPU 型号、数量、训练时长和能耗等关键资源信息，不利于复现成本评估。

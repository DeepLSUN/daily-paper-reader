## 摘要
安全运营中心（SOC）的一个主要问题是警报疲劳，因为报告的检测数量超过了工作人员一天内能够分类处理的能力。以往的工作会提示或微调大型语言模型（LLM）直接输出分类标签，但并未训练它们推理某个检测是否构成真实威胁。我们在真实且由人工标注的Windows端点检测数据上，通过结合自动提示优化、自训练和带可验证奖励的强化学习，训练了一个具备思维链（CoT）推理能力的分类器。我们发现CoT推理也会降低自动分类所依赖的标签词元概率，因此我们单独训练了一个校准器，它读取完整推理轨迹并估计判定正确的概率。我们的系统达到了82.6%的测试准确率，在控制自动分类的高置信度工作点上，相较于直接标签的LLM分类器，良性召回率提升了43.0%，恶意召回率提升了18.3%。我们进一步表明，训练后的校准器是必需的——未经训练的置信度评估器会将高置信度召回率降为零——并且微调后的30B模型显著优于前沿的通用模型，这激励了针对性的训练而非单纯扩大规模。

## Abstract
A major issue in Security Operations Centers (SOCs) is alert fatigue, as the number of detections reported is more than staff can triage in a given day. Prior work prompts or fine-tunes large language models (LLMs) to emit a triage label directly, but does not train them to reason about whether a detection is a genuine threat. We train a chain-of-thought (CoT) reasoning-enabled triage classifier on real, human-labeled Windows endpoint detections by combining automated prompt optimization, self-training, and reinforcement learning with verifiable rewards. We find that CoT reasoning also degrades the label-token probabilities that automated triage relies on, so we separately train a calibrator that reads the full reasoning trace and estimates the probability that the verdict is correct. Our system reaches 82.6% test accuracy and, at the high-confidence operating point that governs automated triage, improves benign recall by 43.0% and malicious recall by 18.3% over a direct-label LLM classifier. We further show that the trained calibrator is necessary - an untrained confidence judge collapses high-confidence recall to zero - and that a finetuned 30B model significantly outperforms frontier general-purpose models, motivating targeted training over scale.

### 1. 核心问题与整体含义（研究动机和背景）

- **现实痛点**：安全运营中心（SOC）面临严重的**警报疲劳**问题——传感器产生的检测数量远超分析人员可处理的上限。一名分析师审查一条检测平均耗时约 1 小时，因此人力而非检测量本身构成了 SOC 处理能力的瓶颈。
- **现有方法的缺陷**：已有的 LLM 分诊方法（如直接提示或微调模型输出标签）虽能利用预训练知识并产生可量化置信度，但**没有训练模型去推理检测本身是真阳性还是假阳性**，浪费了 LLM 的推理期能力。
- **核心挑战**：安全检测分诊本质上是**推理驱动型任务**——分析师需要综合进程链、文件路径、流行度、MITRE ATT&CK 技战术、传感器元数据等多字段信息才能做出判断。
- **本文的意义**：首次显式训练一个**思维链（CoT）推理分类器**来对安全检测进行分诊，并配套训练了一个**置信度校准器**，使系统在高置信度自动分诊场景下大幅超越传统直接标签方法，同时论证了**针对性领域训练比模型规模更重要**。

### 2. 方法论：核心思想、关键技术细节与流程

**总体架构**：采用**四阶段训练配方**，在具备原生 `<think>` 推理能力的开源模型 Nemotron-3-Nano-30B 上依次进行：

1. **阶段一：自动提示优化（Prompt Optimization）**
   - 使用 **GEPA** 优化器搜索最优系统提示词，用 Nemotron-3-Super-120B 作为反思模型。
   - **关键改进①——自定义评估函数**：纯准确率优化会使 GEPA 收敛到含有硬性数字阈值的"决策树式"提示（如"若 prevalence ≥ 70 则输出 benign"），这种提示虽得分高但产生的 CoT 对分析师无用且规则脆弱。因此引入 **LLM-as-a-judge** 从五个维度（多字段推理、阈值刚性、推理鼓励、字段覆盖、泛化潜力）打分，优化指标取 `准确率 × min(五个维度分数)`，迫使提示产生合理全面的推理。
   - **关键改进②——Token 限制**：自定义 GEPA 提议函数，将所有候选指令硬性限制在 1,024 tokens 以内，防止提示无限膨胀。
   - 手工提示准确率为 62.0%；无护栏优化达 87.5% 但产生脆弱的阈值规则；带护栏优化为 72.0%（作为后续起点）。

2. **阶段二：自训练（Self-training）**
   - 基于 **AdaSTaR** 框架，使用优先级堆（priority heap）优先采样困难样本，迭代 25 轮（峰值验证准确率），每轮：采样生成推理轨迹 → 验证格式与正确性 → 对错误样本执行 **rationalization**（合理化）→ LoRA 微调 → 更新优先级堆。
   - **关键改进——Rationalization 质量把控**：STaR 式方法要求模型在给定正确答案时生成合理化解释，但直接提示会导致模型输出"答案已给出，所以是恶意"这类废话。作者设计了详细的分析师角色提示词，并要求 LLM 裁判对合理化结果按 1–5 分"真实性量表"评分，仅保留得分 ≥3 的、读起来像独立分析的轨迹。
   - 自训练将验证准确率从 72.0% 提升至 **81.7%**，始终错误样本比例从 39.5% 降至 5.4%。

3. **阶段三：带可验证奖励的强化学习（RLVR with GRPO）**
   - 使用 **GRPO** 算法（DeepSeek 提出的标准 RLVR 优化器），从自训练检查点出发训练 8,000 步（峰值在 5,000 步后趋于饱和）。
   - **奖励函数**：仅当 (a) 响应符合 `<think>...</think> label` 格式 且 (b) 预测标签与真实标签一致时奖励为 1.0，否则为 0.0。
   - 自训练只能模仿已有训练轨迹，而 RLVR 让模型**自主发现新颖的推理策略**。
   - RLVR 将验证准确率从 81.7% 提升至 **87.7%**，且平均响应长度从 426 tokens 降至不足 300 tokens——模型变得更准确也更简洁。

4. **阶段四：置信度校准（Confidence Calibration）**
   - **动机**：CoT 推理会破坏标签 token 的概率——模型在推理末尾已"承诺"结论，因此标签 token 在分布上近乎确定（病态过度自信），无法用作置信度信号。
   - **方法**：单独微调另一个 Nemotron-3-Nano-30B（LoRA，禁用思考）作为**校准器**，读取"检测 + CoT 推理 + 标签"，输出单个 token 判定 `correct` 或 `incorrect`。
   - **置信度提取**：对两个 token 的 logits 取 softmax 得正确概率 p；最终置信度 s = p（若判定正确）或 1−p（若判定错误）。该置信度既能用于置信度分档，也让校准器可以"否决"策略模型的结论。
   - **训练数据**：对训练集每个样本生成 4 次温度 1.0 的 rollout，按正确/错误标注后平衡训练 3 个 epoch，并应用标签平滑 ε=0.05。

### 6. 主要结论与发现

- **全系统效果显著**：测试准确率 **82.6%**；在高置信度档位，良性召回 **64.8%**（较基线 +43.0 个百分点）、恶意召回 **53.0%**（较基线 +18.3 个百分点）。中低档位两种系统表现相近，说明 CoT 训练不损害低置信度覆盖率。
- **训练阶段相互叠加**：提示优化、自训练、RLVR 每一阶段都单调提升高置信度工作点的表现；自训练与 RLVR 互补——单独 RLVR 良性召回强（61.6%）但恶意召回弱（44.8%），两者结合在所有指标上最优。
- **校准器是必要组件而非锦上添花**：未经训练的置信度评估器（基座模型直接输出置信度）由于置信度集中在 σ(±1) ≈ 0.731 附近，精度阈值落在置信度分布的平坦区域，**高置信度召回率直接降为零**。校准器训练的贡献甚至大于策略训练（表3：+25.6 vs +25.6 个百分点，但零召回结果显示校准器是结构性前提）。
- **针对性训练优于模型规模**：微调后的 30B 模型（82.6% 准确率）大幅超越所有零样本基座模型（55–67%），包括 120B 的 Nemotron-3-Super 和 Claude Opus 4.6；更大的通用模型并不能自动迁移到这一专业领域。
- **置信度分布呈双峰**：模型有把握时预测易超过高置信阈值，没把握时置信度极低，导致中/低档位的精度-召回指标有时完全相同。

- **任务范围有限**：仅覆盖**二分类**（良性 vs 恶意）和 Windows 端点检测，未涉及多分类（如具体攻击类型）、其他传感器平台（如 macOS/Linux 端点、网络层传感器、云工作负载），也未验证模型能否适应不同 SOC 环境下的数据分布差异——尤其是本文数据来自单一安全公司的单一传感器，跨组织泛化能力存疑。
- **部署成本较高**：系统由两个 30B（激活 3B）模型组成，且推理链为串行（策略模型生成 CoT → 校准器评估），训练需要 32 块 B200 GPU；论文未报告单条检测的端到端推理延迟与吞吐量，对每天需处理海量检测的生产场景，算力与延迟成本可能构成实际瓶颈。
- **置信度校准依赖 CoT 质量**：校准器以策略模型的推理轨迹为输入，如果 CoT 本身包含"看似合理但错误"的推理（幻觉），校准器可能被误导而给出高置信度的错误结论；论文未系统量化这类"流畅但错误推理"的比例。
- **对分布偏移敏感且缺乏应对机制**：作者自报验证集到测试集的良性高精度召回从 98.0% 漂移至 90.8%，说明模型性能随时间衰减明显；论文虽讨论了这一现象，但未提出增量更新、检测漂移或自动重训的生产级方案。
- **数据处理细节披露不足**：多字段缺失的具体处理策略、训练集中正负类别的精确比例、人工标注者间一致性（如 Cohen's kappa）均未报告，影响复现精度与结果解读。
- **推理可解释性缺少质量验证**：虽然展示了真实推理轨迹的正面案例（图3），但未对推理过程的逻辑正确性做系统评估，也未报告分析师对 CoT 有用性的主观评分，CoT 的可解释价值更多是"展示"而非"证明"。
- **统计严谨性不足**：所有结果均为单次运行、无置信区间和显著性检验；零样本对比仅在 1,000 样本子集上进行，且 Claude 模型的采样参数（温度、top-p）未报告，可复现性打折扣。

## 9. 总体评价与研究启示

**总体评价**：这是一篇工程完整度与应用价值极高的论文。其核心贡献不在于提出某一全新的算法，而在于**系统性地证明了一个关键命题——针对安全领域"量身定制的推理训练"远比"通用大模型的规模或零样本能力"重要**，并交付了一条可复制的四阶段训练配方。方法论上最值得借鉴的闪光点有二：一是对 CoT 副作用（病态过度自信）的敏锐诊断与独立校准器设计；二是贯穿全程"防退化"护栏（LLM-as-judge 阻止提示优化退化为阈值规则、真实性量表过滤 rationalization 废话、RLVR 让模型自主发现简洁推理），这些细节体现了对真实部署质量的深度思考。

**研究启示**：
- CoT 训练 + 独立置信度校准有望推广到其他高风险推理分类场景（恶意软件家族识别、金融欺诈检测、医学影像分诊等），凡"需要预测置信度以决定是否自动执行"的任务都有可能受益。
- 自训练与 RLVR 的互补关系暗示：先模仿、再探索的两阶段策略可作为 LLM 领域微调的通用范式。
- 论文的局限也为后续研究指明了方向：多分类扩展、跨传感器泛化、分布漂移下的持续学习、以及推理轨迹质量的形式化验证。

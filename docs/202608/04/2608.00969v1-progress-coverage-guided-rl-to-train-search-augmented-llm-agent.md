## 摘要
现有的搜索增强型LLM智能体通过强化学习训练以提升其推理能力。然而，这些方法主要依赖结果级奖励，对搜索行为的监督很少，并且忽视了智能体正确分解复杂查询的能力。为解决这一问题，我们提出PROGRESS，利用教师引导的覆盖奖励来显式塑造策略模型的分解查询生成。在训练过程中，冻结的教师模型用于将复杂查询分解为必要的搜索查询。这些必要的搜索查询被用来引导策略模型的搜索行为。集成到R1风格的训练框架中，我们的方法在不进行密集过程级监督的情况下，对查询分解决策提供轻量级引导。实验表明，覆盖引导的强化学习提高了整体任务性能，凸显了在智能体LLM中显式监督搜索策略的重要性。

## Abstract
Existing search-augmented LLM agents are trained using Reinforcement Learning to boost its reasoning capabilities. However, these approaches primarily rely on outcome-level rewards, which provide little supervision over search behavior and overlook agent's ability to decompose complex queries properly. To mitigate this issue, we propose PROGRESS which utilizes teacher-guided coverage reward to explicitly shape decomposed query generation of the policy model. During training, frozen teacher models are used to decompose complex queries into essential search queries. These essential search queries are utilized to guide the search behavior of the policy model. Integrated into an R1-style training framework, our approach provides lightweight guidance over query decomposition decisions without dense process-level supervision. Experiments show that coverage-guided RL improves overall task performance, highlighting the importance of explicitly supervising search strategies in agentic LLMs.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：搜索增强型LLM智能体通过实时检索外部信息，结合多轮推理来回答复杂问题。近期工作（如Search-R1）表明，使用强化学习（RL）训练小型LLM以交错执行推理与搜索可以显著提升多跳问答性能。
- **核心问题**：现有RL训练方法（如Search-R1、R1-Searcher、ZeroSearch等）主要依赖**结果级奖励**（如精确匹配、格式奖励），对**中间搜索行为**几乎没有直接监督。这导致以下问题：
  - 智能体不会合理分解复杂查询，倾向直接使用原始复杂查询进行搜索；
  - 生成的搜索查询粒度不当（过粗或过细），或覆盖不全；
  - 小型LLM尤其容易产生低效搜索和低质量查询分解。
- **论文含义**：作者提出 **PROGRESS**，通过教师模型生成"必要搜索查询"作为锚点，引入**覆盖奖励（Coverage Reward）**来显式塑造策略模型的查询分解行为，从而在不依赖密集过程级标注的情况下提升搜索质量与最终任务表现。

## 2. 方法论：核心思想、关键技术细节与流程

### 核心思想
- 利用**冻结的教师模型**（Qwen2.5-72B-Instruct）离线将复杂查询分解为一组"必要搜索查询"（Essential Search Queries），代表解决该问题的关键潜在信息需求。
- 在RL训练过程中，将策略模型生成的搜索查询与教师查询进行**语义和粒度匹配**，计算覆盖奖励，引导策略模型生成**全面（comprehensive）且聚焦（focused）**的搜索查询。
- 覆盖奖励以**轨迹级**信号的形式整合到RL目标中，不干扰自回归生成的灵活性。

### 关键技术细节

1. **搜索增强LLM智能体框架**：
   - 策略模型生成包含 `<search>...</search>`（搜索调用）、`<information>...</information>`（检索内容）、`<think>...</think>`（推理）和 `<answer>...</answer>`（最终答案）的轨迹。
   - 训练目标采用PPO（Proximal Policy Optimization）算法，优化目标为最大化期望奖励同时通过KL散度约束策略偏离参考策略。

2. **覆盖奖励计算**：
   - 教师模型生成必要搜索查询集合：\( Q_T(x) = \{q_{T1}, q_{T2}, ..., q_{TK}\} \)
   - 策略模型从轨迹中提取搜索查询集合：\( Q_P(x, y) = \{q_{P1}, q_{P2}, ..., q_{PM}\} \)
   - 使用LLM judge（Qwen2.5-72B-Instruct）基于**语义和粒度**双重标准判断匹配查询集合 \( I(x, y) \)
   - 计算**精确率**（Precision）和**召回率**（Recall）：
     - Precision = |I| / |QP|（惩罚冗余或无关搜索）
     - Recall = |I| / |QT|（衡量是否覆盖教师识别的信息需求）
   - 覆盖奖励采用两者的**调和平均（F1分数）**：
     \[
     r_{cov}(x, y) = \frac{2 \times Precision \times Recall}{Precision + Recall}
     \]
   - F1平衡了完整性与聚焦性，避免只发大量松散查询或只搜索少量子问题的退化策略。

3. **总奖励函数**：
   \[
   r(x, y) = r_{ans}(x, y) + r_{format}(y) + \lambda_{cov} r_{cov}(x, y)
   \]
   - \( r_{ans} \)：精确匹配奖励；
   - \( r_{format} \)：格式奖励；
   - \( r_{cov} \)：覆盖奖励，加权系数 \( \lambda_{cov} \) 经验上设为0.2。

4. **训练流程**：
   - 教师查询离线预生成 → 策略模型与环境交互产生轨迹 → LLM judge计算匹配 → 计算覆盖奖励与最终奖励 → PPO更新策略。

## 6. 主要结论与发现

1. **覆盖奖励显著提升多跳问答性能**：在所有多跳QA数据集（HotpotQA、2wiki、MuSiQue）上，PROGRESS均优于Search-R1和Zero-search等强基线。在MuSiQue上比Search-R1提高约5个百分点（绝对提升）。
2. **查询质量明显改善**：覆盖奖励训练出的策略模型在查询**完整性**和**粒度**两个维度均有显著提升（如2wiki完整性从29.77提升至40.63）。
3. **检索准确率提升**：PROGRESS在三个多跳数据集上的检索命中率均显著优于Search-R1（如平均从38.66提升至44.96）。
4. **跨模型泛化性**：在更小模型（Qwen2.5-1.5B）上也观察到一致改进，说明方法具有较好的通用性。
5. **用仅多跳数据训练效果更佳**：仅用HotpotQA训练时，PROGRESS相对Search-R1的优势更为明显（平均从26.96提升至31.28）。

## 7. 优点

- **轻量级监督**：无需密集的步骤级人工标注，仅利用教师模型生成的查询集合作为弱监督信号，成本可控。
- **明确针对搜索行为**：相较结果级奖励，覆盖奖励直接优化"搜索什么、如何分解"的问题，针对性强。
- **F1公式设计合理**：同时考虑精确率和召回率，避免两种退化策略（过度搜索和欠覆盖）。
- **保留RL灵活性**：轨迹级奖励不会过度约束生成过程，策略模型可以自由组织推理与搜索顺序。
- **实验验证维度丰富**：从EM指标、检索准确率、查询质量、模型泛化性等多个角度验证了方法的有效性。

## 8. 不足与局限

- **依赖教师模型质量**：教师查询由单一大模型（Qwen2.5-72B-Instruct）离线生成，教师分解质量直接影响监督信号的上限；未探讨教师模型规模或能力变化的影响。
- **LLM judge引入额外偏差**：使用LLM进行查询匹配判断，可能存在对齐问题；未验证judge判断与人类判断的一致性。
- **训练集规模较小**：仅使用2个数据集训练，未展示在更大规模或更丰富类型的数据上的效果。
- **缺少消融实验**：未单独验证lambda权重、匹配粒度标准、教师数量等设计选择的贡献。
- **部分通用QA指标不如Zero-search**：在NQ、TriviaQA、PopQA上，PROGRESS略低于Zero-search或与Search-R1（EM,FR）相当，表明覆盖奖励对单跳/知识型问题的帮助有限。
- **未与最新方法对比**：未与HiPRAG（层次过程奖励）、β-GRPO（置信阈值RL）等更近期的工作直接比较。
- **算力信息不完整**：未提供训练时间、内存占用、推理开销等细节。
- **潜在的应用限制**：LLM judge的在线调用在部署中会增加计算成本；对于没有现成强教师模型的任务或领域，该方法的应用需要额外的准备工作。

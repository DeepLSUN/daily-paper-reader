## 摘要
深度搜索代理通过迭代发出搜索查询来收集支持性证据，从而回答困难的信息寻求问题，但目前尚不清楚更大的搜索努力是否以及如何带来更好的答案。我们通过对长视界搜索代理的轨迹级诊断来研究这些问题。利用人工标注的文档级相关性判断，我们评估每一步搜索中检索到的证据，并将代理行为分为两个阶段：代理检索到哪些证据，以及它如何有效利用这些证据。这种区分进一步使我们能够将失败分解为检索缺口（即从未找到必要证据）和利用缺口（即检索到相关证据但未正确使用）。在保持检索模型和评估框架固定的情况下，我们在BrowseComp-Plus上比较了六个代理，并通过开放网络搜索API进一步在BrowseComp上验证了我们的发现。在各种设置中，我们发现搜索努力与答案质量仅弱相关。答案准确性与检索证据的质量（尤其是累积检索召回率）的相关性，高于与搜索次数或消耗的上下文量的相关性。有用的证据往往在轨迹早期出现，但代理倾向于继续搜索，产生长尾的低收益检索步骤。在查询级别，探索性重构仍然有用，但表现最好的代理发布的冗余查询要少得多。总体而言，通过系统表征长视界搜索代理的搜索行为和失败模式，这项工作为构建更好的深度研究系统指出了实用方向，包括更强的查询制定、更有效的证据选择和上下文管理，以及基于是否已检索到足够支持证据的停止标准。

## Abstract
Deep search agents answer difficult information-seeking questions by iteratively issuing search queries to gather supporting evidence, but it remains unclear whether and how greater search effort leads to better answers. We study these questions through a trajectory-level diagnosis of long-horizon search agents. Using human-annotated document-level relevance judgments, we evaluate the evidence retrieved at each search step and separate two stages of agent behavior: what evidence an agent retrieves and how effectively it uses that evidence. This distinction further allows us to decompose failures into retrieval gaps, where the necessary evidence is never found, and utilization gaps, where relevant evidence is retrieved but not used correctly. With the retrieval model and evaluation harness held fixed, we compare six agents on BrowseComp-Plus and further validate our findings on BrowseComp with an open-web search API. Across settings, we find that search effort and answer quality are only weakly aligned. Answer accuracy is better correlated with the quality of retrieved evidence, especially cumulative retrieval recall, than with the number of searches or the amount of context consumed. Useful evidence often appears early in the trajectory, yet agents tend to continue searching, producing a long tail of low-yield retrieval steps. At the query level, exploratory reformulations remain useful, but the best-performing agents issue far fewer redundant queries. Overall, by systematically characterizing the search behavior and failure modes of long-horizon search agents, this work points to practical directions for building better deep research systems, including stronger query formulation, more effective evidence selection and context management, and stopping criteria based on whether sufficient supporting evidence has been retrieved.

## 2. 论文提出的方法论

- **核心思想**：通过**轨迹级诊断（trajectory-level diagnosis）**，将代理行为分离为两个阶段——
  1. **检索阶段**：代理检索/访问到了什么证据；
  2. **利用阶段**：代理是否有效地利用了已检索到的证据。
  
  基于这一区分，将失败分解为两类缺口：
  - **检索缺口（Retrieval Gap, RG）**：必要证据从未被检索到；
  - **利用缺口（Utilization Gap, UG）**：相关证据已被检索到，但最终答案仍然错误。
- **关键技术细节**：
  - **ReAct 范式**：代理在每一步输出推理轨迹 $\tau_t$ 和动作 $a_t$（工具调用或终止答案），非终止动作产生观察 $o_t$，构成完整轨迹 $\xi$。
  - **工具接口**：两个工具——`search`（返回 top-K=5 结果，每个含文档ID、检索分数和512 token截断片段）和 `visit`（按文档ID获取全文）；检索器固定为 Qwen3-Embedding-8B。
  - **相关性标注**：使用 BrowseComp-Plus 的两层人工标注 qrels——宽泛的 **evidence-qrels**（主题相关文档集 $E(q)$）和严格的 **gold-qrels**（足以推导正确答案的文档集 $G(q) \subseteq E(q)$）。
  - **轨迹分组**：将轨迹分为 episodes（每次搜索调用开始、到下一次搜索前包含的 visit 集合）；定义每 episode 的证据集 $R_k$、累积证据集 $C_k$、新证据增量 $\Delta_k$。
  - **关键指标**：
    - 填充式累积召回率（padded cumulative recall at K=25）；
    - 访问精确率（visit precision）；
    - 生产性 episode（productive：新增证据）/ 冗余 episode（redundant：检索到证据但无新增）/ 无生产性 episode（unproductive：未检索到证据）；
    - 首金命中步（first gold hit step）与浪费尾部（wasted tail $M - k^*$）。
  - **失败分类定义**（基于 gold-qrels）：
    - correct：$success(\xi,q)=1$；
    - utilization gap：$success(\xi,q)=0$ 且 $G^*(\xi)\neq\emptyset$；
    - retrieval gap：$success(\xi,q)=0$ 且 $G^*(\xi)=\emptyset$。
  - **Oracle 阶梯实验**：将 $E(q)$ 或 $G(q)$ 直接注入共享 GPT-4o reader（temperature=0），得到 Oracle-E = 87.5% 和 Oracle-G = 87.4% 的上界，并计算每代理的净增益（Net Gain）。
  - **查询策略分类**：按 token 重叠（Jaccard）将连续查询间的转换分类为 repeat（≥0.85）、pivot（<0.25）、add/drop_constraint（中间）。
  - **面板回归分析**：构建 830 题的 agent×question 面板（4,919 条可用轨迹），用问题固定效应线性概率模型分离能力与行为。

## 6. 论文的主要结论与发现

1. **更多努力并不带来更多准确性**：搜索量、上下文消耗都不能预测准确率；事实上更准确的代理往往也更便宜。
2. **真正跟踪准确率的是检索召回率**：准确率与查询累积检索到的 gold 证据量高度相关（跨代理 Pearson r=0.99；问题内面板 +30pp/SD，t=34）；相比搜索次数或上下文量，证据质量（尤其累积检索召回率）是答案准确性的主导因素。
3. **失败分为两类缺口且需相反修复策略**：五个代理的检索缺口占错误 51.6–64.1%；Kimi K2.6 是例外（利用缺口 52.0%），说明几乎相同的准确率可对应截然相反的失败主导类型——RG 需要更好的查询，UG 需要更强的验证。
4. **证据要么早期出现、要么永不出现，随后是浪费的尾部**：77.5–93.6% 的 episodes 无新增证据；正确轨迹早期积累证据并很快停止，错误轨迹证据装载率低却持续搜索，其额外长度主要是浪费的尾部；错误轨迹长度是正确轨迹的 1.9–2.9 倍，但首金命中时刻仅差 0.6–6.7 个 episode。
5. **更强的代理搜索得更干净而非更多**：重复查询率是准确率最强的非机械行为预测因子（ρ=-0.83，问题内 -1.9pp/SD，t=-3.4）；并行查询批处理是唯一在问题内控制后仍显著正向的行为（+2–4pp/SD）；pivot 探索性转换并非坏事（ρ=+0.31），关键在转换是否落在证据上。
6. **上下文预算主要被搜索片段占用**（66–85%），访问的文档内容仅占 2–16%；因此上下文管理的关键在片段流管理，而不只是访问门控。
7. **检索缺口是查询侧失败而非检索器失败**：固定检索器下 gold 召回率跨度达 26 个百分点，只能归因于查询公式差异。

- **严格的控制变量设计**：固定检索模型、ReAct 框架和评估协议，使跨代理差异可归因于代理行为本身；六代理全部为开放权重模型，rollout 原则可复现。

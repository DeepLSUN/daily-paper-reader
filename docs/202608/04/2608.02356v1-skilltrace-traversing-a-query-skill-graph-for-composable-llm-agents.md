## 摘要
大型语言模型智能体日益通过从技能库中组合可复用技能来解决复杂任务。为此，关键挑战不仅在于检索单独相关的技能，还在于识别完整且可执行的技能组合。在本文中，我们认为这一问题可以在三层图中解决：技能查询之间的组合关系、查询与技能库中候选之间的相似性，以及所选候选之间的依赖关系。我们引入了SkillTrace，它将用户查询组织成语义层次结构，匹配技能查询与候选，并在技能依赖关系上进行传播。在SkillsBench和ALFWorld上的实验表明，SkillTrace达到了最先进的性能，在SkillsBench上成功率达53.17%，在ALFWorld上达91.43%。SkillTrace还在不同骨干语言模型上持续带来改进，展示了基于图的技能检索的通用性和鲁棒性。

## Abstract
Large language model agents increasingly solve complex tasks by composing reusable skills from a library. To address this, the key challenge is not merely to retrieve individually relevant skills, but to identify a complete and executable skill composition. In this paper, we argue that this problem can be solved in a graph with three levels: compositional relations among skill queries, similarity between queries and candidates in the skill library, and the dependencies among the selected candidates. We introduce SkillTrace, which organizes the user query into a semantic hierarchy, matches skill queries and candidates, and propagates over the skill dependencies. Experiments on SkillsBench and ALFWorld demonstrate that SkillTrace achieves state-of-the-art performance, reaching a success rate of 53.17% on SkillsBench and 91.43% on ALFWorld. SkillTrace also delivers consistent improvements across different backbone language models, demonstrating the generality and robustness of graph-based skill retrieval.

### 一、核心问题与研究动机

- **背景**：大语言模型（LLM）智能体越来越依赖从技能库中检索并组合可复用技能来完成复杂任务（如程序化任务执行、API 调用、具身交互等）。一个技能封装了特定的任务能力、执行流程或工具调用例程。
- **核心难点**：与传统的单轮信息检索或简单工具选择不同，可组合技能检索要求识别出一组能**协同完成整个任务**的技能集合，而非仅检索单个最相关技能。存在三大挑战：
  1. **查询组合性**：复杂用户查询需被分解为原子技能查询，并保持它们之间的组合关系；
  2. **查询-技能匹配**：原子查询与候选技能之间既要语义对齐，也要输入输出规格兼容；
  3. **技能依赖关系**：选中的某些技能可能需要前置或辅助技能，而这些依赖关系并未在原始查询中明示。
- **核心论点**：这一挑战可以自然地建模为**图搜索问题**——即构建一个"查询-技能图"（Query-Skill Graph），将查询内部结构与技能库组织关系统一建模，通过图的遍历来超越孤立语义检索，找到完整可执行的技能组合。

### 二、方法论：SkillTrace 框架

#### 1. 核心思想

SkillTrace 将可组合技能检索构建为一个**三段式图遍历过程**，由三层关系构成统一图结构：

\[
G_{x,S} = T_x \cup B_{x,S} \cup D_S
\]

其中：
- \(T_x\)：基于查询 \(x\) 的层次化查询树（Hierarchical Query Tree, HQT）
- \(B_{x,S}\)：查询-技能二分图（Query-Skill Bipartite Graph, QSBG）
- \(D_S\)：技能依赖子图（Skill Dependency Subgraph, SDS）

#### 2. 层次化查询分解（HQT）

- 利用提示词让语言模型 \(p_\theta\) 将复杂查询 \(x\) 组织成语义层次树 \(T_x\)，叶子节点即为原子技能查询 \(A_x = \text{Leaf}(T_x)\)。
- 每个原子技能查询必须描述**恰好一个输入-输出变换**，禁止分解到技能粒度以下，且不能引入原查询中不存在的新需求。

#### 3. 查询-技能二分匹配（QSBG）

- 对每个原子技能查询 \(q_i\) 与技能库中每个技能 \(s_j\) 计算语义兼容得分：
  \[
  w_{ij} = \text{sim}(f_Q(q_i), f_S(s_j))
  \]
  其中 \(f_Q\) 和 \(f_S\) 将查询与技能编码到共享表示空间，\(\text{sim}\) 为余弦相似度。
- 采用**最大权二分图匹配**（匈牙利算法），保证每个原子查询恰好匹配一个技能、每个技能至多匹配一个查询，避免多个查询重复选中同一技能，鼓励技能联合覆盖不同原子需求。
- 匹配上的技能构成**主技能集** \(P_{x,S}\)，作为后续传播的种子节点。

#### 4. 技能依赖子图与传播（SDS）

- 将技能库组织为**有向依赖图** \(D_S\)：有向边 \((s_i, s_j)\) 表示技能 \(s_i\) 的输出可被 \(s_j\) 消费。边权重定义为输出与输入 schema 的匹配程度（overlap），超过阈值 \(\delta_D\) 则保留该边。
- 采用**反向个性化 PageRank（ReversePPR）**：以主技能集作为个性化种子，在同时包含正向与反向边的依赖图上进行带重启的随机游走，使相关性从主技能沿依赖关系向其前置/辅助技能传播。
- 最终保留主技能，并从其余技能中选取得分最高的 \(K\) 个支持技能，构成最终技能包：
  \[
  S^*_x = P_{x,S} \cup \text{TopK}_{s_i \in S \setminus P_{x,S}}(r^*_i)
  \]

#### 5. 算法流程

1. 离线构建技能依赖图（对所有技能对计算输入-输出匹配，代价仅一次）
2. 给定查询 → LLM 分解为原子技能查询
3. 构建查询-技能相似度矩阵 → 匈牙利算法做最大权匹配
4. 反向 PPR 在依赖图上传播相关性
5. 取主技能 + Top-K 支持技能作为最终检索结果

在线推理复杂度为 \(O(QN + Q^2N + K(N+E))\)，其中 \(Q\) 为原子查询数、\(N\) 为技能数、\(E\) 为依赖边数。实际中 \(Q\) 和 \(K\) 较小且图稀疏，近似线性于技能库规模。

### 三、实验设计

#### 1. 评测基准

- **SkillsBench**：包含跨 8 个领域的专业性技术任务（软件工程、自然科学、金融、网络安全等），共 87 个任务，划分为 Core（6 个）、Extended（53 个）、Extreme（28 个）三个子集。技能为结构化包（指令、脚本、模板等），规模 200 个技能。
- **ALFWorld**：文本具身环境，评估 140 个 in-distribution 任务（Pick & Place、Clean & Place、Heat & Place 等 6 类），使用 37 个 ALFWorld 专用技能。按查询分解出的原子技能数量划分为 Easy（1 个，43 个）、Medium（2 个，73 个）、Hard（3 个及以上，24 个）。

#### 2. 对比方法

- **Vanilla Skills**：不检索，将整个技能库直接放入提示词。
- **Vector Skills**：按原始查询与技能描述的语义相似度独立检索 top-K 技能。
- **SkillDAG**：有向无环图组织技能关系，以原查询为单一检索单元。
- **GoS（Graph-of-Skills）**：先检索种子技能，再在技能图上传播扩展。
- **SkillTrace**：本文方法。

#### 3. 主干模型

- 主实验统一使用 **GPT-5.6** 作为骨干模型，控制模型能力差异，聚焦检索策略对比。
- 跨模型泛化实验：DeepSeek-V3.2、Kimi-K2.5、Qwen3.5-397B-A17B、Gemini 3.1 Flash-Lite，与 GoS 对比。

#### 4. 评估指标

- 各子集成功任务数 + 总体成功率 SR（%）。

### 六、主要结论与发现

1. **SkillTrace 在两个基准上均取得最优性能**：SkillsBench 成功率 53.17%（较最强基线 GoS 提升 6.68 pp），ALFWorld 成功率 91.43%（较最强基线 SkillDAG 提升 1.43 pp）。
2. **图组织本身不足以解决技能检索问题**：SkillDAG 性能（41.38%）甚至略低于 Vector Skills（42.12%），说明关键不在于是否建图，而在于如何针对查询遍历图。
3. **三个组件互补缺一不可**：查询分解保证需求覆盖，二分匹配保障查询-技能对应，依赖子图传播补全执行必需的前置技能。去除 SDS 的消融（降 12.95 pp）表明依赖恢复最为关键。
4. **跨骨干模型一致性增益**：在 5 种模型上均优于 GoS（+0.69~+6.68 pp），验证了图基检索机制的通用性和鲁棒性。
5. **性能提升不是以更长耗时为代价**：ALFWorld 上 SkillTrace 耗时反而降低 6.57%，运行时与成功率无显著线性相关（r=0.08）。

### 七、优点与亮点

1. **问题建模视角新颖**：将"可组合技能检索"形式化为三层图结构的搜索问题，整合了查询内部组合关系、查询-技能匹配和技能间依赖，而非把技能当作独立候选项。
2. **方法设计精巧**：
   - 原子查询分解后使用**全局最大权二分匹配**，从机制上避免多查询重复选同一技能的冲突；
   - 采用**反向 PPR** 传播，使依赖关系（即使方向与执行流相反）也能被有效恢复；
   - 在线复杂度近似线性，工程上实用。
3. **实验设置规范**：统一骨干模型控制变量、跨模型泛化验证、完整消融、公平的任务分层映射，实验设计的严谨性好。
4. **图结构的通用性**：不依赖特定技能库类型，能同时处理程序化工作流（SkillsBench）与具身交互（ALFWorld）两种异质场景。

### 八、不足与局限

1. **性能增益的绝对幅度有限**：虽然 SkillsBench 提升较大（+6.68 pp），但 ALFWorld 上仅比最强基线高 1.43 pp，且 Easy/Medium/Hard 中 Medium 和 Hard 都只是打平而非超越。
2. **骨干模型能力主导整体性能**：同一检索机制下，不同骨干模型的成功率差距可达 3 倍以上（15.90% vs 53.17%），表明检索只是整体性能的一个环节，实际应用中仍需依赖强大的底层模型。
3. **依赖图质量受启发式限制**：依赖边用输入-输出 schema 的 overlap 来判定，阈值 \(\delta_D=0.6\) 的经验选择缺乏敏感性分析；复杂真实技能库中的隐性或软性依赖可能被漏掉。
4. **查询分解依赖 LLM 的可靠性**：原子分解质量直接影响后续匹配和传播效果；对较弱骨干模型，分解错误可能放大为检索错误。论文未报告分解质量本身的评测。
5. **实验覆盖范围有限**：仅 2 个基准、87+140 个任务、200+37 个技能，未在更大规模技能库（如 AgentSkillOS 等大规模生态）上验证可扩展性。
6. **资源/成本披露不足**：未报告 API 调用总量、费用或离线图构建的具体时间；7×RTX 4090 D 的算力投入在论文中的作用未明说（LLM 通过 API 访问，GPU 主要用于本地环境/推理加速）。
7. **部分设置略显随意**：GoS 的种子数和返回数设置（SkillsBench 4 种子/5 返回，ALFWorld 5 种子/4 返回）与 SkillTrace 的预算不同，可能影响对比公平性；K（支持技能数）的选取依据未阐述。
8. **嵌入模型统一但 prompt 等细节未充分公开**：原子分解的提示词模板（\(p_{\text{atom}}\)）未在附录中给出完整内容，可复现性打折扣。

## 摘要
最近，文本到SQL系统越来越依赖于多轮交互、执行反馈和强化学习。然而，大多数现有方法仅将执行正确性作为轨迹级奖励，这对于识别导致成功或失败的SQL决策提供的指导有限。我们提出了SERL-SQL，一种面向多轮文本到SQL智能体的选择性基于执行结果的强化学习框架。SERL-SQL采样在策略的SQL交互轨迹，并使用仅用于训练的教师模型，通过执行反馈对学生行为进行重新评分。由此产生的师生似然差距被转换为有界的、掩蔽的权重，仅对SQL和工具操作标记的GRPO优势进行重新加权。这样，任务奖励保持优化方向，而执行后见提供局部化的信用分配。在BIRD、Spider和跨域基准上的实验表明，SERL-SQL取得了有竞争力的性能，在BIRD-Dev上达到76.56%的执行准确率，在Spider-Test上达到89.92%。此外，我们基于奖励的选择策略接近oracle的Best-of-N上界，并持续优于基于一致性的选择，这表明SERL-SQL产生的高质量候选可以通过轻量级的基于执行结果的奖励可靠地识别。我们的代码将在 https://github.com/Ffunkytao/SERL-SQL 发布。

## Abstract
Recent Text-to-SQL systems increasingly rely on multi-turn interaction, execution feedback, and reinforcement learning. However, most existing methods use execution correctness only as a trajectory-level reward, which provides limited guidance for identifying the SQL decisions responsible for success or failure. We propose SERL-SQL, a selective execution-grounded reinforcement learning framework for multi-turn Text-to-SQL agents. SERL-SQL samples on-policy SQL interaction trajectories and uses a training-only teacher to re-score student actions with execution feedback. The resulting teacher--student likelihood gap is converted into bounded, masked weights that reweight GRPO advantages only on SQL and tool-action tokens. In this way, task rewards preserve the optimization direction, while execution hindsight provides localized credit assignment. Experiments on BIRD, Spider, and cross-domain benchmarks show that SERL-SQL achieves competitive performance, reaching 76.56% execution accuracy on BIRD-Dev and 89.92% on Spider-Test. Moreover, our reward-based selection strategy closely approaches the oracle Best-of-N upper bound and consistently outperforms consistency-based selection, showing that SERL-SQL produces high-quality candidates that can be reliably identified by lightweight execution-grounded rewards. Our code will be released at https://github.com/Ffunkytao/SERL-SQL.

## 1. 核心问题与研究动机

- **背景**：Text-to-SQL（自然语言转SQL查询）任务正从单次生成范式向多轮智能体交互范式转变，现代SQL智能体通过"思维—行动—观察—修改"的循环，利用数据库执行反馈逐步修正SQL查询。
- **核心问题**：现有强化学习方法（如GRPO）仅将执行正确性作为**轨迹级的稀疏奖励**，即对轨迹中所有 token（包括思考、格式、SQL动作）分配相同的优势值。这种方法无法定位究竟是哪个SQL决策导致了成功或失败，信用分配（credit assignment）粗糙。
- **关键洞察**：执行反馈（如运行时报错、空结果、解析错误、结果表）不仅可作为结果奖励，更可作为**训练时的后见信息（hindsight）**，用于辨别哪些SQL决策应对失败负责——但不应在推理时暴露给策略，也不应均匀地蒸馏给学生。
- **研究意义**：该工作填补了执行反馈在Token级精细化信用分配上的空白，为Text-to-SQL智能体的强化学习训练提供了新范式。

## 2. 方法论

### 2.1 总体框架（四个阶段）

SERL-SQL流程分为四步：

> Schema接地 → 多轮SQL智能体Rollout → 选择性执行后见教师重打分 → 后见引导的优势重加权

### 2.2 核心思想

- 学生策略πθ在策略上采样N条多轮交互轨迹，获得轨迹级奖励并计算GRPO优势Aⁿ。
- 一个仅训练时使用的教师策略πT（与学生周期性同步、梯度停止）在**执行后见上下文**下重新评分学生已生成的动作token。
- 教师—学生对数似然差Δ被转化为**有界、符号感知的掩码权重**，仅作用于SQL和工具动作token，用于重加权GRPO优势。
- 任务奖励决定优化**方向**，执行后见决定更新的**局部性和幅度**。推理时教师移除，学生策略独立部署。

### 2.3 关键技术细节

**（1）Schema Grounding（模式接地）**

- 离线构建列感知的向量索引（qwen3-Embedding-0.6B编码数据库值）。
- 检索问题关键词对应的相关值，融合**推理式链接**与**基于值的链接**，输出紧凑且值感知的接地Schema子集。

**（2）多轮Rollout与轨迹奖励**

- 智能体执行"思考→SQL→观察→修改→最终方案"的多轮交互；每个动作含推理片段和中间SQL或最终方案。
- 分层验证器检查格式有效性并对比执行结果，奖励定义：正确+1，错误0，无效格式−1。

**（3）选择性执行后见教师**

- 为每个SQL动作构造后见上下文 cₜᵉˣ = Hₑₓ(oₜ)，包含结果表、运行时错误、解析错误、空结果等诊断信息。
- 教师重打分学生token：log πT(yₜ,ᵢ | hₜ, yₜ,<ᵢ, cₜᵉˣ)，学生仅用动作前的信息：log πθ(yₜ,ᵢ | hₜ, yₜ,<ᵢ)。
- 定义动作掩码 mₜ,ᵢ ∈ {0,1}，仅对可执行的SQL提交和工具调用token为1，对推理、格式等token为0。

**（4）后见引导的优势重加权**

- 似然差：Δₜ,ᵢ = log πT(...) − log πθ(...)
- 重加权因子：wₜ,ᵢ = clip(exp(sgn(Aⁿ)·sg[Δₜ,ᵢ]), w_min, w_max)，其中sgn确保教师证据与奖励方向对齐。
- 掩码后权重：w̄ₜ,ᵢ = (1−mₜ,ᵢ) + mₜ,ᵢ·wₜ,ᵢ（非动作token保持原GRPO权重）。
- 训练衰减系数αₖ：Ãₜ,ᵢ = Aⁿ[(1−αₖ) + αₖ·w̄ₜ,ᵢ]，早期依赖后见信号，后期回归奖励驱动。

## 6. 主要结论与发现

1. **SERL-SQL达到具有竞争力的性能**：BIRD-Dev 76.56%（32B）/ 75.55%（7B），Spider-Test 89.92%（14B）/ 89.78%（32B），跨域泛化能力优于多数强基线。
2. **执行后见是训练侧最关键的模块**：移除后BIRD-Dev下降约3个百分点，证实执行反馈提供了超越稀疏轨迹奖励的局部证据。
3. **精细控制后见信号十分必要**：动作掩码、符号感知、裁剪、衰减每一项都带来增益，说明后见信号需要被约束为"有界、局部、与奖励对齐"的信用信号。
4. **奖励式候选选择接近Oracle上界**：reward_max在16条轨迹下紧密追踪Best-of-N表现，且优于一致性选择——说明SERL-SQL不仅能提升单次采样质量，还能产生可被轻量信号识别的高质量候选集。
5. **剩余错误集中于连接构造和语义理解**：多表推理仍是最主要瓶颈。

## 7. 优点与亮点

## 摘要
随着能力的迅速提升，AI智能体可以从在单个应用内运行，发展到随时间跨用户设备行动。然而，现有智能体系统在此场景下仍显不足。这是因为观测分散在不同的设备和时刻，而主流系统并未围绕这一事实设计：将设备视为工具的单一智能体缺乏对所有设备跨时间的有效状态管理，多智能体系统则协调各智能体，但未能维护跨设备、跨时间请求所需的紧凑携带状态。我们认为，智能体应维护一种有效设计的状态，将交互证据、陈述事实和持续请求组织为紧凑、可行动的形式，以便根据当前观测决定行动。为比较状态设计，我们构建了一个跨设备和时间的用户-智能体交互基准。我们将这一原则实例化为统一智能体（Unified Agent），一种有状态智能体，它携带跨设备和时刻的交互证据，并将其与当前观测结合以采取行动。在默认设置下，它显著优于我们对四种已发表设计的改编。在多模态大语言模型（MLLM）家族、能力和推理努力的变化中，它始终领先于所有对比系统，表明状态设计优势在MLLM设置中具有鲁棒性。我们的代码和数据将在GitHub上公开。

## Abstract
As capabilities rapidly increase, AI agents can move from running inside one app to acting across a user's devices over time. Yet existing agent systems still fall short in this scenario. This is because observations are scattered across devices and moments, but mainstream systems are not designed around this fact: a single agent that treats devices as tools lacks effective state management for all devices across time, and multi-agent systems coordinate across agents but do not maintain the compact carried state a cross-device, cross-time request needs. We argue that the agent should maintain an effectively designed state that organizes engagement evidence, stated facts, and the standing request in a compact, action-ready form for deciding its action given the current observation. To compare state designs, we construct a benchmark of user-agent interaction across devices and time. We instantiate this principle in Unified Agent, a stateful agent that carries interaction evidence across devices and moments and uses it with the current observation to act. In the default setting, it significantly outperforms our adaptations of four published designs. Across changes in multimodal large language model (MLLM) family, capability, and reasoning effort, it remains ahead of all compared systems, demonstrating that the state-design advantage is robust across MLLM settings. Our code and data will be publicly available on GitHub.

## 2. 论文提出的方法论

### 2.1 核心思想
- 提出 **Unified Agent（统一智能体）**：一个有状态（stateful）的智能体，携带跨设备、跨时刻的交互证据，并将当前观测与携带状态结合后进行决策。
- 关键设计原则：状态应**紧凑**（比原始历史精简）、**可行动**（比历史预测列表更直接有用），随交互增长保持有界。

### 2.2 携带状态的表示
状态 $S_t$ 包含三个信息流（streams）：
- **交互参与证据（Engagement evidence）**：随设备累积的交互线索（如活动次数、指向手势、手与设备接触），用于识别相关设备。
- **陈述事实（Stated facts）**：按主题（topic）且尽量按设备保存用户提供的信息，使不同设备上的同主题事实可区分。
- **持续请求（Standing request）**：保留最近的可执行请求。

### 2.3 状态更新与决策公式
- **状态更新**（folding，先于决策执行）：
  $$S_t = U(S_{t-1}, O_t)$$
  将当前观测 $O_t$ 融入既有状态，保留早期证据的同时纳入新证据。
  
- **行动决策**（结合更新后的状态与当前观测）：
  $$a_t = D(S_t, O_t)$$
  当前观测 $O_t$ 提供即时线索，状态 $S_t$ 提供累积证据，使早期交互线索在原始提示消失后仍可影响决策。

### 2.4 六任务框架（observe–think–act）
每时刻的交互被组织为六个任务：
1. **Detect user and devices**（感知任务）：检测用户和设备；
2. **Identify engaged device (Eng)**：识别正在交互的设备；
3. **Infer user's intent (Int)**：推断用户意图；
4. **Recall relevant information (Inf)**：回忆相关信息；
5. **Pick responding device (Rsp)**：选择响应设备（可为空集）；
6. **Decide next action (Nxt)**：决定下一步动作。

### 2.5 创新点
- 状态存储的是**证据本身**而非解码后的下游答案，显式记录随观测更新并直接服务于后续决策。
- 设备能力（device capabilities）单独提供，不放入状态中。
- 通过语言接口指定哪些设备响应及其动作，设备用原生控件执行，实现异构设备协调，无需学习式记忆、检索或微调。

## 3. 实验设计

### 3.1 数据集 / 基准：UA-BENCH
- **构建方式**：在渲染的 3D 家庭场景（基于 Habitat/HSSD-200 与 MuJoCo Menagerie 人形机器人）中构建脚本化跨设备交互，通过设备摄像头视图观察。
- **规模**：100 个匹配对（matched pairs），共 200 个片段（episodes）；每个片段 12 帧。
- **匹配对设计**：配对的两个片段共享开场帧、请求帧和回忆帧（f1、f10–f12），但中间交互帧（f2–f9）交换参与设备（engaged/decoy）角色及相关值，由此产生不同的 Eng、Inf、Rsp、Nxt 目标，同时保持 Int 不变。
- **设备类型**：笔记本、电脑、手机等屏幕设备，部分片段包含 fetch robot 作为额外响应设备选择。
- **严格隔离**：语义标注和渲染元数据仅用于构建期验证，评估系统只能访问渲染的设备摄像头视图、用户话语、设备名单和能力卡。
- **评估目标**：由受控片段设计直接确定（rather than 模型生成），保证精确可追溯。

### 3.2 对比方法
**状态控制组（State controls）**：
- **Full context**：保留全部历史感知记录与话语（最强控制）；
- **Self-notes**：每帧更新 600 字符自由文本备忘录；
- **Answer cache**：仅携带最近的答案，无计数；
- **Text only**：仅读文本，无视觉输入；
- **Observation only**：只用当前帧记录。

**已发表方法基线（Published baselines）**：
- 记忆类：**Mem0**（事实记忆提取+检索）、**MM-DST**（多模态对话状态跟踪）；
- 多智能体类：**Mixture-of-Agents**（提案合成）、**Debate-or-vote**（同行评审和投票）。

**消融变体（Controlled variants）**：
- **Frame-local state**：每帧重置携带状态；
- **Count-free evidence**：移除活动与指向证据的计数（多重性）；
- **No pointing channel**：移除指向通道，仅保留活动证据；
- **Reduced-ability routing**：移除每设备能力子句。

### 3.3 评估设置
- **默认设置**：GPT-5.6-Luna（OpenAI, 2026）低推理努力。
- **跨设置泛化**（4 种 MLLM 设置）：Gemini 3.1 Flash-Lite（低，跨家族）、GPT-5.6-Luna（低，主设置）、GPT-5.6-Luna（中，跨推理努力）、GPT-5.6-Sol（低，跨能力）。
- **共享感知协议**：同一 MLLM 设置内所有方法共享相同的逐帧感知输出，隔离状态设计差异。
- **评分规则**：Eng/Nxt 精确匹配，Inf 大小写不敏感精确匹配，Rsp 用 set-F1（可含空集），Int 由固定语义等价 MLLM 评判器（文本版 GPT-5.6-Sol 中等推理）评分；Overall 为五个下游决策的宏平均。
- **真实照片评估**：一个家庭办公场景的匹配对（笔记本 vs 平板），手与设备接触作为参与线索，补充渲染基准。

## 6. 论文的主要结论与发现

- **发现 1**：精心设计的携带状态为跨设备智能体带来显著性能优势。默认设置下 Unified Agent 的 Overall 得分 0.668，领先所有对比系统；相比最强控制 Full context（0.613）提升 +0.055；相比四个已发表基线的增益为 0.194–0.408，所有 95% 配对 bootstrap 区间均高于零。
- **发现 2**：不同任务需要不同类型的信息。消融表明：参与证据（计数和指向）支撑 Eng，先前状态支撑 Inf，设备能力约束支撑 Rsp。
- **发现 3**：状态设计优势跨 MLLM 设置稳健泛化。在 MLLM 家族（Gemini vs GPT）、能力（Flash-Lite vs Luna vs Sol）和推理努力（低 vs 中）的变化中，Unified Agent 始终领先最强的 Full context 控制（Gap 从 +0.031 到 +0.058）。
- **发现 4**：携带状态在真实照片上同样支持跨设备决策（识别参与设备并回忆相关信息）。
- **附加结论**：Unified Agent 的状态大小保持有界（约 131–1,442 字符范围，随观测设备/陈述事实缩放），而 Full context 线性增长至其 11 倍，表明紧凑状态在上下文效率上的优势。

## 7. 优点

- **问题定义新颖**：将"跨设备、跨时间交互中的状态设计"形式化为六任务框架，独立于具体实现，具有普遍适用性。
- **设计简洁而有效**：状态仅存储三类证据（参与证据、陈述事实、持续请求），无需学习机制、检索模块或微调，增益完全来自状态的表示与使用方式，而非系统复杂度。
- **公平严谨的评测协议**：共享感知输出、固定零样本模板、统一输出 schema 和评判器；统计检验采用配对 bootstrap 聚类，并进行 Holm 多重比较校正。
- **匹配对基准设计**：置换参与角色而保持共享帧不变，精确控制了混淆变量，使"早期交互证据"成为后续决策的唯一区分因素，Ground truth 由构造保证而非模型标注。
- **鲁棒性验证充分**：跨模型家族、能力、推理努力的泛化实验和真实照片案例增强了结论的外部效度。
- **隐私友好**：状态显式、可检查、可选择性修订，相比保留完整历史实现数据最小化（data minimization by design），状态大小有界避免上下文窗口膨胀。
- **实用取向**：设备执行与决策分离的架构设计（语言接口指定 + 设备原生控件执行）契合真实异构设备生态。

- **设备集有限**：设备类别仅笔记本、电脑、手机（+可选机器人），未包含智能家居设备、可穿戴设备等现实异构设备。
- **"其他设计也会更好"问题**：论文未系统测试更多记忆架构（如图数据库、时间知识图谱等）在跨设备场景的表现；匹配对基础片段之间可能存在相关性（同一片段对两个角色）。

## 9. 潜在应用场景与研究启发

### 9.1 实际应用场景

- **跨设备个人助理**：用户在多台设备上查看/比较商品或服务后，在另一台设备上继续相关请求（如预订、下单），Unified Agent 可直接利用携带状态完成衔接，无需用户重述上下文。
- **多设备办公协同**：在笔记本、平板、手机等设备间切换工作时，智能体能识别当前实际交互设备，并回忆此前在各设备上陈述的事实（如会议安排、文档批注），支持无缝的跨设备工作流。
- **异构设备生态下的统一入口**：智能家居中控、车载助手与手机/手表等设备共用同一智能体状态，用户对任一设备发出的请求可通过状态路由到最合适的执行设备。
- **隐私敏感场景的数据最小化**：状态显式且紧凑，用户可随时查看和清理已携带的信息；相比保存完整历史，天然契合隐私合规要求，适合医疗、金融等对数据留存敏感的领域。
- **机器人任务交接**：论文中 fetch robot 作为响应设备的设定，可推广到用户在不同房间或不同机器人之间切换任务的场景，使机器人能依据携带状态继续执行未完成的指令。

### 9.2 对后续研究的启发

- **状态设计可作为独立研究维度**：本文证明在固定模型和感知条件下，状态表示方式本身能带来显著性能差异；后续研究可将"状态结构设计"与"模型能力增强"视为正交的优化轴。
- **可解释性与可审计性**：显式状态允许研究者追踪每一步决策所依赖的证据，为智能体行为审计提供了天然接口，可能成为安全评估的标准组件。
- **扩展方向**：将三流状态扩展至多用户（区分发言人与受众）、多模态事实（图片/语音内容的信息摘要）、时间衰减权重（更近的陈述具有更高置信度）等，均是自然的后续工作。
- **与其他机制的互补**：可将携带状态与检索增强结合——状态负责"当前任务关键证据"，检索负责"历史长尾信息"，形成分层记忆架构。

## 10. 综合评价

### 10.1 创新性
**较高**。论文将跨设备、跨时间的状态维护从"记忆机制"的附属讨论中独立出来，形式化为可操作的六任务框架，并提出三流状态表示。该问题定义和状态设计此前缺乏系统性研究，论文填补了这一空白。

### 10.2 技术贡献
**方法简洁、有效且可复现**。无需训练或检索模块，仅凭状态的组织方式即可获得明显增益；基准和评估协议设计严谨，匹配对构造法优雅地隔离了混淆变量，使因果归因清晰。

### 10.3 工程与实用价值
**中等偏上**。状态大小有界、格式显式、语言接口与设备执行分离，均有利于实际落地；但基准场景为渲染居家环境，真实硬件生态的适配成本尚未验证，距离产品化仍有距离。

### 10.4 严密性与可复现性
**较强**。统计检验规范（配对 bootstrap + Holm 校正），消融控制充分，评估协议透明；但算力成本未披露、真实照片样本过小是主要扣分项。

### 10.5 总体印象
这是一篇**问题新颖、方法优雅、实验严谨**的系统设计类工作。它不以更大的模型或更多的数据取胜，而是通过精巧的状态设计获得稳健的增益，为跨设备智能体研究提供了坚实的概念基座与评测平台。主要遗憾在于基准规模和场景多样性有限，以及缺乏对更多记忆架构的系统比较。总体而言，该论文在学术价值与工程启发上均达到较高水准，属于跨设备智能体方向值得重点参考的代表性工作。

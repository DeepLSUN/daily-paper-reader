## 摘要
现代芯片设计依赖于电子设计自动化（EDA）工具，这些工具会生成大量异构工件，包括源文件、脚本、日志、网表和报告。分析这些工件对于调试、优化和设计流程理解至关重要，但由于相关证据往往分布在多种工件类型和设计阶段中，这一任务仍然困难。尽管LLM智能体在EDA辅助方面显示出潜力，但现有方法缺乏用于大规模跨工件分析的公开基准，并且通常难以将推理基于工具生成的证据。我们提出了EDATracer，一个用于证据基础型EDA工件分析的主体框架。EDATracer将设计工件组织为知识图谱，并配以语义向量索引，使LLM智能体能够跨源文件、日志、网表和报告检索证据。我们整理了一个18.9 GB的数据集，包含2,787个可综合的开源芯片设计，并引入了一个涵盖事实性、统计性和推理任务的90题基准。在评估的智能体中，EDATracer实现了最佳的pass@1准确率，平均比Cursor和Claude Code高出6.4和7.2个百分点，同时使用的token数减少2.0-3.2倍。

## Abstract
Modern chip design relies on electronic design automation (EDA) tools that generate large, heterogeneous artifacts, including source files, scripts, logs, netlists, and reports. Analyzing these artifacts is critical for debugging, optimization, and design-flow understanding, but remains difficult because relevant evidence is often distributed across many artifact types and design stages. Although LLM agents show promise for EDA assistance, existing approaches lack public benchmarks for large-scale cross-artifact analysis and often struggle to ground reasoning in tool-generated evidence. We present EDATracer, an agentic framework for evidence-grounded EDA artifact analysis. EDATracer organizes design artifacts into a knowledge graph paired with a semantic vector index, enabling LLM agents to retrieve evidence across source files, logs, netlists, and reports. We curate an 18.9 GB dataset of 2,787 synthesizable open-source chip designs and introduce a 90-question benchmark spanning factual, statistical, and reasoning tasks. Across evaluated agents, EDATracer achieves the best pass@1 accuracy, outperforming Cursor and Claude Code by 6.4 and 7.2 percentage points on average, while using 2.0-3.2x fewer tokens.

## 一、核心问题与研究动机

- **背景**：现代芯片设计高度依赖电子设计自动化（EDA）工具，这些工具会生成大量异构工件，包括源文件（Verilog/SystemVerilog）、脚本、综合日志、门级网表和 PPA（功耗/性能/面积）报告。分析这些工件对调试、优化和理解设计流程至关重要。
- **核心痛点**：EDA 工件分析占芯片验证工作量的 47%，且相关证据往往分散在多种工件类型和不同设计阶段中，传统方法难以跨工件进行有效推理。
- **现有方法的三大挑战**：
  - **C1：缺乏公共数据集和基准**——EDA 工件涉及敏感设计细节，此前没有公开的大规模跨工件 EDA 分析基准；
  - **C2：工件复杂且规模大**——单个设计可产生数万行日志、网表、报告，远超 LLM 上下文窗口限制；
  - **C3：跨工件推理中的“扎根失败”（grounding failure）**——LLM 容易产生幻觉或依赖浅层关键词匹配，而非真实的工具证据。
- **论文主张**：需要一个能在大规模设计仓库中进行“证据扎根型”跨工件分析的智能体框架，并配套公开数据集与基准。

## 二、方法论

### 1. 核心思想

EDATracer 将 EDA 工件组织为**属性化、类型化的知识图谱**，并配以**语义向量索引**，通过“检索智能体 + 推理智能体”的迭代交互，实现证据扎根的跨工件问答。其核心洞察是：图谱结构保留了设计的层级关系、工件来源和依赖关系，使 LLM 检索到的每条证据都能回溯到具体的设计、工件和上下文。

### 2. 数据集构建（两阶段）

- **收集阶段**（四步过滤漏斗）：
  - *发现*：用 48 个关键词查询 GitHub，获得 23,115 个候选仓库；
  - *启发式过滤*：排除归档、非 HDL、无星标等仓库（保留 16,514 个）；
  - *LLM 评估*：用 GPT-4.1-nano 判断是否为有意义的芯片设计（保留 8,812 个）；
  - *综合可行性检查*：要求至少一个可解析模块、顶层模块候选和时钟信号（最终保留 2,787 个）。
- **生成阶段**（六步流程）：为每个设计分配综合工具（Synopsys Design Compiler）和技术库（NanGate45、SkyWater130、ASAP7），执行静态设计分析（构建模块实例化图、排序顶层模块候选）、TCL 脚本生成，并通过**迭代错误修复循环**（最多 15 次）处理综合失败，最终提取综合日志、网表和 PPA 报告。
- **最终数据集**：18.9 GB，包含 2,787 个可综合设计、249K 个 EDA 文件；53% 为 EDA 生成工件；设计类别以 CPU/RISC-V（32.8%）为主，覆盖 GPU、AI 加速器、加密、DSP 等 12 类。

### 3. EDATracer 框架（离线 + 在线）

- **离线阶段**（图构建）：
  - *工件解析*：将输入分为文本工件（日志、报告、脚本、文档）和结构化工件（RTL、网表）；
  - *溯源链接*：添加类型化边，保留工件层级、设计来源和结构关系；
  - *语义索引*：长文本文件切分为重叠块，每个块作为图节点嵌入到向量索引中。
- **在线阶段**（双智能体协同）：
  - **检索智能体**支持两种模式：
    - *语义检索*：对请求做嵌入，在向量索引中按余弦相似度取 Top-K；
    - *结构化检索*：生成 Cypher 查询在知识图谱上执行，获取图节点、关系、度量等直接证据。
  - **推理智能体**：判断已有证据是否足以回答问题——若不足，生成新的信息请求；若充分，输出带证据引用的最终答案。两者循环迭代，直到证据充分或产生最终回答。

### 4. 算法要点

- **静态设计分析与顶层模块排序**（Algorithm 2）：解析模块声明，构建实例化图，选取入度为零的模块作为候选根，按传递实例化深度、行数等确定性指标排序。
- **迭代修复循环**（Algorithm 1）：每次综合失败后，根据失败类别（路径缺失、时钟问题、顶层模块错误等）执行确定性更新（切换顶层模块、扩展搜索路径或更换时钟），直至成功或达到尝试上限。
- **知识图谱摄入**（Algorithm 3）：为每个设计创建锚点节点，文本工件切块入向量索引，结构化工件解析为语法级子图。

## 三、实验设计

- **Benchmark**：人工构建 90 个“金标准”问答对，沿两个维度划分：
  - *三类问题*：事实性（30）、统计性（30）、推理性（30）；
  - *三个难度*：易、中、难，每个（类型 × 难度）格子 10 题。
  - 所有问答对均由作者基于真实数据集人工验证答案和标注难度。
- **对比方法**：两个商业智能体框架——Cursor 和 Claude Code。
- **测试 LLM**：Claude Opus 4.7、Claude Sonnet 4.6、Claude Haiku 4.5、GPT-5.4、GPT-5.4-mini（闭源）、Qwen 3.5-9B（开源权重，用于本地部署测试）。
- **评估指标**：平均分（0–10）、pass@1、pass@5、token 用量。
- **消融实验**：对比“扁平 RAG 向量库”与 EDATracer 的知识图谱方案（在 Claude Haiku 4.5 和 GPT-5.4-mini 上）。
- **辅助评估**：除人工专家评分外，还采用“LLM 评审团”（GPT-5.4 和 Claude Sonnet 4.6 分别打分，Claude Opus 4.7 综合裁决），并进行对比分析。

- **主要实验**：5 个闭源 LLM × 3 种工具（含 EDATracer）的完整对比矩阵 + 1 个开源模型的 EDATracer 单独评估，覆盖三类问题 × 三个难度。

## 六、主要结论与发现

1. **准确率领先**：EDATracer 在 5 个共享 LLM 设置中的 4 个上优于 Cursor，平均分从 8.25 提升至 8.75（+0.49）；相比 Claude Code 全部 3 个 Claude 设置均提升，平均+0.89 分。pass@1 平均超过 Cursor 6.4 个百分点、Claude Code 7.2 个百分点。
2. **统计类问题提升最大**：得益于知识图谱支持跨工件聚合与单位/前缀的正确保持；在 Haiku 4.5 上，统计类准确率比次优方法高 1.86 分。
3. **Token 效率显著**：EDATracer 只用 20M–36M token，相比 Cursor 减少 2.0×–3.0×，相比 Claude Code 减少 2.1×–3.2×；这一优势在不同模型骨干上一致，说明收益来自检索结构而非特定 LLM。
4. **强模型+EDATracer 效果最佳**：Claude Opus 4.7 搭配 EDATracer 达到最高性能——avg 9.54 分，pass@1 94.4%，pass@5 98.9%。
5. **本地部署可行但有局限**：Qwen 3.5-9B 可达约 GPT-5.4-mini 水平，在事实性和统计性问题上较强，但推理类问题在单次尝试中表现明显偏弱。
6. **知识图谱优于扁平 RAG**：KG 相比 RAG 在 Claude Haiku 4.5 上平均分提高 6.10（2.58→8.68），GPT-5.4-mini 上提高 5.93（1.47→7.40）；token 增加仅 1.37×–1.46×，性价比高。

## 七、优点

1. **填补空白**：首个面向大规模跨工件 EDA 分析的开源数据集（18.9 GB、2,787 设计）+ 90 题基准，解决 C1。
2. **知识图谱与向量索引的混合设计**：结构化检索（Cypher）与语义检索（嵌入）互补，兼顾精确度和灵活性，有效解决 C2 和 C3。
3. **证据扎根**：每条检索结果都能回溯到具体设计、工件、行号和上下文，显著降低幻觉；定性案例清晰展示了 grounding failure、retrieval miss、misjudged evidence 三种失败模式及 EDATracer 的应对。
4. **Token 效率高**：图谱结构避免了反复向模型传递大段工件上下文，成本优势显著。
5. **数据集构建流程系统化**：四阶段过滤漏斗 + 确定性迭代修复，可复现且各阶段非冗余（分别过滤不同失败模式）。
6. **本地部署验证**：测试了开源权重模型，给出实际可行性的评估，而不仅是闭源 API。

## 八、不足与局限

1. **依赖图谱构建质量**：实体/关系提取错误、切块不当或缺失图关系都会直接降低下游检索和推理质量；在 EDA 场景中，警告信息、时序值只有正确链接到对应设计/工具运行/模块时才有效。
2. **离线预处理成本**：收集、解析、嵌入、入库需要额外工程开销，对小型或快速迭代的项目可能不如简单文件搜索划算。
3. **覆盖范围有限**：
   - 当前仅覆盖综合阶段工件，未涉及布局布线、时序收敛、sign-off 等后续设计阶段；
   - 主要面向数字 EDA，对模拟设计、物理设计、专有工业流程的适配需要额外工程。
4. **基准规模偏小**：90 题在统计上难以覆盖多样化的真实 EDA 任务；pass@k 仅 5 次尝试，无显著性检验。
5. **评分方法存在偏差**：LLM-Council 评分与人工专家评分有明显分歧（尤其在统计题的单位正确性上），说明自动评估尚不可靠，人工评估成本高且难以大规模扩展。
6. **模型适配不均衡**：弱模型（如 Haiku、GPT-5.4-mini）从 EDATracer 中获益较少；推理类问题对本地小模型仍是瓶颈。
7. **对比基线有限**：未与学术界其他 EDA 智能体框架（如 AutoEDA、MAEDA、EDA-Debugger 等）对比，削弱了结论的通用性。

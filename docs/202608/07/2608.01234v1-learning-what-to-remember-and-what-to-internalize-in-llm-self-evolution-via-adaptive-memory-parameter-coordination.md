## 摘要
大语言模型智能体日益在动态环境中运行，其中工具接口、API和用户需求在部署后会发生变化。现有的自进化方法主要遵循两种范式：基于工具的方法，将反馈外部化为可编辑的记忆或技能以实现快速适应；以及基于参数的方法，将经验内化为模型参数以实现更深层次的能力提升。然而，单独使用任何一种机制都会在灵活性和性能之间产生权衡。本文探讨了智能体如何协调这两种渠道以实现稳健的自进化。我们提出了COVE，一个统一的智能体自进化框架，通过任务感知路由、阶段感知调度和知识优化，将基于工具和基于参数的学习相结合。通过这种设计，COVE将自进化视为一种协调过程，而非不加区分地积累经验，它根据任务和知识类型匹配适当的学习机制。跨多个任务类别的实验表明，COVE优于单通道进化策略，在变化环境下展现出更稳健和更高效的改进。

## Abstract
Large language model agents increasingly operate in dynamic environments where tool interfaces, APIs, and user requirements change after deployment. Existing self-evolution methods mainly follow two paradigms: harness-based approaches, which externalize feedback into editable memories or skills for rapid adaptation, and parameter-based approaches, which internalize experience into model parameters for deeper capability improvement. However, using either mechanism alone creates a trade-off between flexibility and performance. This paper asks how an agent can coordinate both channels to achieve robust self-evolution. We present COVE, a unified agent self-evolution framework that combines harness-based and parameter-based learning through task-aware routing, stage-aware scheduling, and knowledge optimization. Through this design, COVE treats self-evolution not as indiscriminate accumulation of experience, but as a coordinated process that matches tasks and knowledge types to appropriate learning mechanisms. Experiments across multiple task categories show that COVE outperforms single-channel evolution strategies, demonstrating more robust and efficient improvement under changing environments.

- **研究背景**：大语言模型智能体（LLM Agent）部署后常面临动态环境——API更新、数据库模式变化、新库出现、领域约定变化、用户需求不可预知。在这些场景下，频繁人工重配置或重训练成本高昂。
- **现有范式及其局限**：
  - **基于 Harness（外部记忆/技能）的方法**（如 Evo-Memory、Reflexion、Voyager）：将反馈提炼为外部记忆或技能，注入推理时的上下文。优点是快速、可编辑、适应变化的任务表面；缺点是当基座模型缺乏解释反馈的能力时，会生成误导性经验，且难以捕获深层推理模式。
  - **基于参数的方法**（如 WizardLM、Self-Challenging Agent）：通过 SFT 或 RL 将经验内化为模型权重。优点是能内化稳定策略、领域推理模式；缺点是训练成本高、适应慢，且对接口变化过于脆弱。
- **核心研究问题**：单独使用任一通道都面临"灵活性—性能"的权衡，如何协调外部记忆与参数更新两个渠道，实现鲁棒、高效的智能体自进化？
- **论文答案**：提出 **COVE**（Channel Orchestrated Volatility-aware Evolution）统一框架，将自进化视为一种"按任务类型和知识属性匹配学习机制"的协调过程，而非不加区分的经验积累。

### 2. 方法论：核心思想、关键技术细节

#### 核心思想
自进化不是单通道操作，而应通过 **任务感知路由（Task-aware Routing）**、**阶段感知调度（Stage-aware Scheduling）** 和 **双模态知识优化（KnowledgePO）** 三个机制，协同外部记忆（快速、灵活）与参数更新（深层、稳定）两个通道。

#### 任务公式化
- 智能体由参数化策略模型 \( \pi_\theta \)、外部知识库 \( \mathcal{K} \) 和环境 \( \mathcal{E} \) 组成。
- 目标是最小化推理与训练成本的同时最大化累计任务效用：
  \[
  \max \sum_{i=1}^{T} R_i - \alpha \sum_{i=1}^{T} C^{tok}_i - \beta \sum_{m=1}^{M} C^{train}_m
  \]
  其中 \( R_i \) 为任务奖励，\( C^{tok}_i \) 为提示 token 成本，\( C^{train}_m \) 为第 \( m \) 次参数更新的计算成本。

#### 三大核心机制

**① Task-aware Routing（任务感知路由）**
- 将路由实现为**反馈条件决策策略**，而非手工规则。
- 给定任务描述 \( \tau_i \) 和反馈 \( f_i \)（结果状态+标量分数+诊断信息），路由器查询受限裁判模型（constrained judge），输出结构化决策 \( d_i = (m_i, s_i, r_i) \)，其中 \( m_i \) 为所选通道，\( s_i \) 为任务特征描述（如 `dynamic_tool`、`logical_rigor`），\( r_i \) 为一句理由。
- 通道三类：**harness_only**（易变知识/上下文知识失败时）、**parametric_candidate**（需内化能力、难以提示化表达时）、**hybrid**（两类信号都明显时）。

**② Stage-aware Scheduling（阶段感知调度）**
- 引入 **Stage-aware Evolution Trigger**，基于三个可复现条件动态决定何时切换通道：
  - **性能平台期（Plateau）**：最近 \( w \) 轮的成功率/平均奖励提升低于阈值 \( \epsilon \)。
  - **数据充分性（DataSufficient）**：高质量轨迹数 \( |\mathcal{D}_q| \geq N \)。
  - **冷启动失败（ColdStartFailure）**：某任务家族前 \( k \) 个任务成功率低于阈值 \( \tau_c \)。
- 触发条件：`Trigger = Plateau ∨ DataSufficient ∨ ColdStartFailure`
- 支持两类路径：常规路径（harness 先探索 → 平台期/数据充分→参数训练）；反向路径（冷启动失败→先做初步参数更新建立最低能力，再启用 harness 进化）。

**③ KnowledgePO（双模态知识优化）**
- **Harness 辅助参数端（Memory-aware Rollout）**：
  - 每条知识条目创建时被赋予波动性标签 \( \ell_j \in \{volatile, stable, strategic\} \)。
  - 反复被修订的非波动条目会被"提升"为 volatile。
  - 推理时检索 top-\( k \) 记忆注入上下文，提升 rollout 质量。volatile 条目用 `<volatile>...</volatile>` 显式标记。
  - **Anti-recitation 奖励**：训练前随机重命名 volatile 条目中的接口名，若模型调用历史训练中出现过但当前未提供的旧名字，则施加惩罚：
    \[
    R = R_{task} - \lambda \cdot \mathbb{I}[\text{uses stale or unobserved volatile name}]
    \]
    这迫使模型"读取当前条目并行动"，而非"记忆并复述"。
- **参数端辅助 Harness（Memory Release）**：
  - 训练后对每条 stable 记忆做 A/B 评估（包含/不包含该记忆），若移除后性能下降低于阈值（即已被参数内化），则将其从在线检索集释放（转入存档）。
  - volatile 记忆永不释放，因为其价值在于携带当前外部符号。

### 6. 主要结论与发现

1. **混合协调优于单通道**：COVE 在 Lean4、APPS、HotpotQA、MATH 上均取得最佳成功率，TableQA 上也保持竞争力，且训练 token 成本比"不加选择的全参数训练"减少约 **86%**。
2. **任务类型决定通道选择**：Lean 定理证明中记忆积累几乎不提升成功率（harness 饱和），而参数化更新能突破瓶颈；TableQA/API 任务中参数化模型在接口变化时性能急剧下降（成功率 40.5%→16.5%，API 正确率 96.5%→54.0%），需要 harness 保护易变知识。
3. **训练时机至关重要**：平台期触发的参数更新优于持续参数训练和仅 harness，说明"何时训练"与"是否训练"同样重要。
4. **知识波动性是存储位置的关键判据**：易变知识（API 名、表模式）应留在外部记忆，稳定知识（算法模式、领域推理）可内化为参数，策略性知识（调试计划）应经多次验证后才内化。
5. **Anti-recitation 有效**：波动性标记 + 反复述奖励使模型在 API 改名后仍保持 92.5% 的 API 调用正确率（对比标准微调的 54.0%），且不损害分布内性能。
6. **路由显著提升效率**：COVE 的路由策略以 Always-Both 16% 的训练 token 成本，保留了大部分性能，效率指标（Eff）达 28.83，远超随机路由（8.82）和双通道全开（4.89）。

### 7. 优点

- **问题选择有现实价值**：动态环境下智能体的持续自适应是大规模部署的核心痛点，工作直面部署后漂移问题。
- **分析先行、方法紧随**：第 3 节先通过精巧的诊断实验（Lean 错误类型分布、API 改名实验、阶段对齐比较）揭示两类方法的互补瓶颈，方法设计有充分经验支撑。
- **统一视角**：将"记忆 vs. 参数"的二元对立转化为"记忆与参数的协调"的统一框架，概念清晰，三个模块（路由/调度/知识优化）各司其职。
- **知识波动性分类具有启发性**：以 volatility 为核心维度区分知识类型，并将此分类应用于奖励设计（anti-recitation）和记忆释放决策，是一大亮点。
- **成本意识强**：目标函数明确纳入 token 成本和训练成本，实验报告了成本-性能权衡（Pareto 分析），而非只看精度。
- **记忆释放机制（A/B 评估）**：避免知识库无限增长导致的上下文膨胀，兼顾效果与效率。
- **冷启动路径的考虑**：识别了一类被忽视的反向路径（先参数训练再 harness 进化），对低能力基座模型场景有实际意义。

### 8. 不足与局限

- **模型规模单一**：仅验证了 8B 模型，未测试更大模型（如 70B+）上的行为差异，结论的规模外推性存疑。
- **API 扰动实验覆盖窄**：仅用 WikiTableQuestions 一个数据集验证 anti-recitation，缺少更多工具调用场景（如真实 API 服务器、多工具组合）的测试。
- **路由成本未纳入总成本**：路由依赖外部裁判模型（LLM）的调用，其 API 成本/延迟未计入总成本公式，实际部署的经济性可能被高估。
- **知识标签的自动标注可靠性**：volatile/stable/strategic 标签由 LLM 裁判自动生成，论文虽报告了跨骨干的路由一致性超 95%，但未报告知识标签本身的标注准确率或人工评估一致性。
- **训练 token 统计估算**：附录 A 承认成本为模型化估计，可能无法精确反映真实训练开销。
- **忽略灾难性遗忘问题**：未分析多轮参数更新后模型对旧任务能力是否退化，而这在自进化系统中至关重要。
- **对比基线有限**：未与较新的混合方法（如 AgentEvolver 等检索增强 + 微调结合方法）直接比较，削弱了"coordination 优于单独通道"的证明强度。

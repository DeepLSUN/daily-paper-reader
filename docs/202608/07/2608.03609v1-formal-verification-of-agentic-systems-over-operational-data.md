## 摘要
由大型语言模型（LLM）驱动的智能体系统越来越多地部署在现实工作流程中，在这些流程中它们对持久化运营数据进行操作。在部署之前，这些系统需要针对管理工作流执行和数据演化的业务需求进行验证。然而，现有方法无法提供这种系统级保证，因为它们主要是在智能体的接口层面约束或分析行为。我们在此研究由单个LLM和工具编排框架组成的智能体系统在关系型运营数据上的验证问题。我们将它们形式化为有状态工具启用的智能体部署（STEADs），给出其语义，定义针对一阶计算树逻辑（FO-CTL）规范验证它们的问题，并证明该问题不可判定。我们确定了在有限域限制下精确保持FO-CTL规范的充分条件，在该限制下验证问题是PSPACE完全的。关键要求是，重命名数据中的不透明标识符必须相应地重命名所选的工具调用。我们表明，LLM驱动的智能体可能违反此条件，并引入一种规范部署包装器，该包装器在保留已有等变行为的同时，为任意基础智能体保证此条件。我们证明了计算此构造所需的规范表示是图同构困难的。最后，我们在一个编排案件管理工作流的LLM智能体上展示了我们的框架。

## Abstract
Agentic systems driven by large language models (LLMs) are increasingly deployed in real-world workflows where they act on persistent operational data. Before deployment, these systems need to be verified against business requirements that govern workflow execution and data evolution. However, existing approaches do not provide such system-level guarantees, as they mainly constrain or analyse behaviour at the agent's interface level. We study here the verification of agentic systems comprising a single LLM and a tool orchestration harness over relational operational data. We formalise them as Stateful Tool-Enabled Agentic Deployments (STEADs), give their semantics, define the problem of verifying them against First-Order Computation Tree Logic (FO-CTL) specifications, and show that it is undecidable. We identify sufficient conditions for exact preservation of FO-CTL specifications under a finite-domain restriction, over which verification is PSPACE-complete. The key requirement is that renaming opaque identifiers in the data must correspondingly rename the selected tool calls. We show that LLM-driven agents can violate this condition and introduce a canonical deployment wrapper that guarantees it for arbitrary base agents while preserving already-equivariant behaviour. We prove that computing canonical representations required by this construction is graph-isomorphism-hard. Finally, we illustrate our framework on an LLM agent orchestrating a case-management workflow.

## 2. 方法论

### 2.1 核心思想
- 将智能体系统建模为 **STEAD**：一个包含持久状态（关系数据库实例）、工具空间（工具模式、语义、接口）和 LLM 智能体策略的元组。
- 将业务需求用 **FO-CTL**（一阶计算树逻辑）表示，既能表达关于演化对象的安全性与进展性，也能表达智能体决策和工具非确定性效果带来的分支行为。
- 验证问题的一般形式被证明是**不可判定的**；但在一定**对称性条件**（C-等变）和**有界性条件**下，可以构造一个足够大的有限域限制，使得在该有限系统上的验证结果与原无限系统**精确等价**，且复杂度为 PSPACE-complete。

### 2.2 关键技术细节
- **STEAD 语义**：
  - 状态为带排序的关系实例，工具调用为带参表达式。
  - 智能体策略 Π 接收决策上下文 `(D, Offer(D))`，输出一个工具调用子集；工具语义 τ 给出可选后继状态。
  - 诱导出数据库转换系统 `D → D′`，要求每个可达状态都有后继（串行性）。
- **验证问题**：给定 FO-CTL 句子 φ，判断诱导系统是否满足 φ（从初始状态出发）。
- **不可判定性证明**：通过编码已知的“关系型数据中心系统 + 外部服务”验证问题（Hariri 等），将 G p 归约到 AG p。
- **有限精确验证（定理 13）**：
  - 条件：系统是 C-有界的；工具接口 Offer 和智能体策略 Π 是 C-等变的；工具语义 τ 是 C-工具统一的。
  - 构造有限子域 Uf，要求每个排序 S 满足 `|Uf_S| ≥ 2 b_S + |C∩U_S| + var_S(φ)`（或直接保留原域）。
  - 证明通过“匹配关系”在无限系统与有限限制之间双向模拟运行，并用结构归纳证明 FO-CTL 公式可满足性等价。
- **等变性条件**：关键要求是“重命名数据中的不透明标识符必须相应地重命名所选工具调用”，即 `Π(ρ(D), ρ(A)) = ρ(Π(D,A))`。论文通过案例证明 LLM 可能违反该条件。
- **规范部署包装器**：
  - 定义规范实例 `can_B(D)`（相对于固定集合 B 的最小 B-标记实例）和所有规范见证 `Lab_B(D)`。
  - 包装器将决策上下文先规范化，再让基础智能体 bΠ 决策，最后把所有规范见证映射回原标识符并取并集：`Π_can(D,A) = ∪_{σ∈Lab_B(D)} σ^{-1}( bΠ(can_B(D), σ(A)) )`。
  - 该包装器对任意基础智能体都保证 B-等变性，且若基础智能体原本已等变则完全保留其行为。
- **计算复杂度边界**：任何计算公共同构代表的方法都不可避开图同构困难问题（定理 19）；在“动作刚性”条件下，包装器可保持单值选择，从而可用一次查询实现。

## 3. 实验设计

- **没有传统的基准数据集或方法对比**；论文采用理论分析 + 两个案例研究来验证框架。
- **案例研究 1：LLM 等变性失败**：
  - 场景：改编自 τ-bench 的航空取消任务，单轮决策上下文，含一个账户和三个预订，其中两个可取消、一个不可取消。
  - 模型：Qwen3-1.7B，贪婪解码 + 结构化 JSON 输出约束到给定工具调用集合。
  - 操作：仅重命名账户用户名（不透明标识符），其余不变，观察输出是否变化。
  - 结果：原用户名下选择 `cancel(r1, r3)`；重命名后选择 `cancel(r1, r2, r3)`，违反了等变性条件。
- **案例研究 2：案例管理工作流**：
  - 场景：小型退款案件管理系统，涉及案例、任务、服务、审批状态等关系；部署 Qwen3-4B，通过规范包装器。
  - 规格：认证属性 φauth（退款必须由对应审批服务批准）和进展属性 φprog（每个开放案例最终必须解决）。
  - 方法：根据定理 13 构造有限域限制（12 个元素），前向枚举可达状态（55 个状态、72 条转换），用显式状态评估器计算 FO-CTL 满足集合。
  - 结果：成功**反驳** φauth（找到反例：未审批就退款），**证明** φprog（所有路径最终解决）。
- **控制实验**：修改策略文本使其“审批感知”，重新生成有限系统（73 状态、90 边），验证两个属性均成立。
- **评估器**：自研显式状态 FO-CTL 评估器，按 CTL 标准标签和不动点过程自底向上计算。

## 6. 主要结论与发现

- 定义了 STEAD 模型并证明其一般验证问题不可判定。
- 在系统满足 C-有界性、工具接口/智能体策略/工具语义的等变性条件下，FO-CTL 验证可被有限域限制精确还原，且复杂度为 PSPACE-complete。
- 等变性是 LLM 智能体引入的关键瓶颈：实验证明 LLM 会因不透明标识符重命名而改变工具选择，从而破坏必要条件。
- 规范部署包装器能够在构造层面强制等变性，且不改变原本已等变的行为；但计算规范表示是图同构困难的，这限制了大规模应用的可行性。
- 在案件管理示例中，框架成功识别了未授权退款的安全漏洞，并验证了流程进展性；控制实验表明，改进策略后可以同时满足安全与进展属性。

## 7. 优点

- **理论贡献扎实**：完整形式化 STEAD 语义，证明了不可判定性、PSPACE-complete 边界、图同构困难下界，为后续研究提供了坚实的理论基础。
- **系统性视角**：相比接口层监控，直接面向持久化数据和完整工作流执行，能够表达“数据演化 + 时序性质”的业务需求。
- **可操作的充分条件**：定理 13 给出了构造有限系统的具体尺寸公式，使得验证可以自动执行。
- **巧妙解决 LLM 问题**：通过规范包装器在构造上保证等变性，避免了事后验证 LLM 的高昂成本；并证明了保留已等变智能体的标准性质。
- **案例研究完整**：包含提示词、工具语义、状态定义、有限模型构建细节和反例，便于复现和理解。

## 8. 不足与局限

- **应用前提限制**：C-有界性假设在现实中并非总是成立（例如无限增长的历史数据）；等变性要求对 LLM 而言很难直接验证，即使有包装器，其 canonical 计算也是图同构困难的。
- **可扩展性差**：显式状态枚举仅适用于状态空间极小的场景；55 个状态的示例已经接近实用极限，复杂业务系统会爆炸。
- **实验覆盖不足**：缺乏在不同模型、任务、规模上的验证，未提供与现有监控/护栏方法的比较，无法证明框架相对现有工作的实际优势。
- **对 LLM 行为建模过于简化**：假设智能体是“马尔可夫的”且状态完全由关系事实呈现，忽略了对话历史、真实交互噪声等复杂因素。
- **包装器可能导致行为改变**：当基础智能体不满足等变性时，包装器会改变其输出，本文只保证“选择仍是基础智能体在同构类中可能产生的行为”，不保证保持原始语义。
- **复杂度上限**：图同构困难意味着在任何系统上强制等变性都需要昂贵的计算，限制了实际部署的可扩展性。

## 摘要
长上下文推理受限于键值缓存随序列长度线性增长的问题。虽然剪枝提供了一种缓解手段，但现有方法通常确定查询特定的令牌重要性，无法在未见过的查询间复用。为此，我们提出TaskPress，一种任务引导、查询无关的KV缓存驱逐框架。TaskPress并非针对单个查询优化缓存，而是构建一个由高层任务指南条件化的可复用记忆表示。该指南在预填充阶段充当元查询，在下游查询发出前过滤不相关令牌。此外，TaskPress利用量化缩放因子作为零成本信号来检测有影响力的表征离群值，为令牌重要性提供了高效代理。在长上下文输入的多项任务上的实验表明，TaskPress能够高效地为多样查询创建紧凑且可复用的缓存。

## Abstract
Long-context inference with large language models is constrained by the linear growth of the key-value cache to sequence length. While pruning offers mitigation, prevailing methods determine query-specific token importance that cannot be reused across unseen queries. In contrast, we introduce TaskPress, a framework for task-guided, query-agnostic KV cache eviction. Instead of optimizing the cache for a single query, TaskPress constructs a reusable memory representation conditioned on a high-level task guide. The guide functions as a meta-query during prefill to filter irrelevant tokens before downstream queries are issued. In addition, TaskPress leverages quantization scale factors as a zero-cost signal for detecting influential representation outliers, providing an efficient proxy for token importance. Experiments on conducted on various tasks with long context input demonstrate that TaskPress efficiently creates a compact, reusable cache across diverse queries.

## 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型（LLM）长上下文推理能力不断增强，但Transformer推理时KV缓存随序列长度线性增长，导致显著的内存开销，甚至超过模型权重，制约部署效率。
- **现有方法的缺陷**：
  - **查询依赖的剪枝方法**（如SnapKV、PyramidKV、Quest）：根据特定用户查询计算令牌重要性，压缩后的缓存无法复用于新查询，多轮/多查询场景下需重复prefill，导致冗余计算。
  - **查询无关但高开销的方法**（如KVZip）：通过上下文重建支持多查询，但预填充阶段提示长度翻倍，带来约O(Lc²)的二次计算开销。
- **核心问题**：能否构建一种“查询无关”的KV缓存压缩方法，使得压缩后的缓存可以在同一任务下的多个后续查询中被安全复用，同时保持极低的预处理成本？
- **总体含义**：本文提出 **TaskPress**，将KV缓存剪枝从“查询时刻”解耦到“任务时刻”。利用高层任务指南（task guide）作为“元查询”（meta-query），在预填充阶段过滤不相关令牌，从而生成可复用的紧凑缓存，兼顾压缩效率与跨查询泛化能力。

## 2. 方法论

### 2.1 核心思想

- 不是针对单个具体查询优化缓存，而是针对一个代表未来查询分布的高层任务指南来引导令牌重要性评分。
- 任务指南在预填充阶段与上下文拼接，计算注意力并驱逐低分令牌后立即被丢弃，不增加解码负担。
- 压缩后的KV缓存可被同任务下的多个查询共享，实现真正的查询无关压缩。

### 2.2 任务引导的 Key 重要性

- 设上下文长度 Lc，任务指南长度 Lt，注意力图 A ∈ R^(Lt×Lc)，其中 A_{j,i} 表示任务令牌 j 对上下文令牌 i 的注意力权重。
- 聚合所有任务令牌的注意力，并进行核大小为 K 的1D平均池化，得到任务引导的 Key 分数：

  skey_i = (1/K) ∑_{k=-⌊K/2⌋}^{⌊K/2⌋} ∑_{j=1}^{Lt} A_{j,i+k}

- 该分数完全由 Query-Key 交互得出，专门反映令牌在结构上能否被任务引导检索到。

### 2.3 量化尺度因子作为 Value 重要性

- 自注意力是“加权和”形式，仅关注 Key 重要性不够，还需衡量 Value 的信息密度。
- 论文提出复用**量化尺度因子**作为零成本重要性信号：在 per-token 量化中，尺度因子 γ_i = max(|v_i|) / (2^(b-1)−1)，由于位宽 b 固定，γ_i 正比于值向量最大幅度。
- 定义 svalue_i = γ_i，作为值向量范数的代理，能够检测高熵、关键的离群特征。
- 该信号在量化服务管线中已经存在，无需额外计算，实现零开销。

### 2.4 综合重要性评分与剪枝

- 最终保留分数为 Key 分数与 Value 分数的逐元素乘积：

  s_i = skey_i · svalue_i

- 乘法交互要求令牌必须同时满足：**在任务对齐的注意力空间中结构可检索**（Key 分数高）且**语义信息丰富**（Value 离群分数高）。
- 对每个注意力头独立分配预算，选择分数最高的令牌保留。

### 2.5 任务指南的构建

- **零样本初始化**：对于已知任务，直接用现成LLM（如Gemini）生成2–3句话的任务描述，即可作为强静态基线。
- **进化任务指南发现**：对未知任务，提出进化算法（Algorithm 1）：
  - 从校准集 D_cal 中采样查询，初始化 N 个候选指南；
  - 每代评估候选指南在下游任务上的准确率，保留 Top-K（K=2）；
  - 利用LLM变异/交叉生成 N 个新候选（N=3），运行 G=4 代；
  - 返回最优指南 T*。
- 进化过程严格基于校准查询推断用户意图，不依赖任务名称先验；也可用于对零样本指南的进一步优化。

- 实验所依赖的LongBench和RULER均为公开基准，模型权重亦公开可获取，因此整体复现难度中等，主要在任务指南的生成环节存在不确定性。

## 10. 对领域的影响与潜在发展方向

- **定位**：TaskPress为查询无关KV缓存压缩提供了一个新的设计范式——将重要性判断从“用户问题”上移到“任务意图”。这一思路可推广到其他依赖运行时上下文分析的剪枝方法，例如将任务嵌入与上下文令牌的关联用于压缩长文档检索库。
- **潜在改进方向**：
  - 将任务指南生成器从外部LLM替换为更轻量的编码器，减少对专有模型的依赖；
  - 对任务漂移进行在线检测，在压缩缓存中保留一定比例的“候选冗余令牌”以备意外查询；
  - 将Key与Value重要性信号做更复杂的融合（如基于学习的加权），而非仅简单相乘；
  - 探索动态逐头预算分配，而非当前的均匀分配，以进一步提高极端密度场景下的鲁棒性。
- **与硬件结合**：由于量化尺度因子在硬件加速器中天然可用，该方法非常适合作为LLM推理芯片中缓存管理模块的轻量级组件，具有实际部署价值。

## 11. 总体评价

TaskPress是一篇创新性和系统性兼备的工作。它用任务指南作为“元查询”，首次让KV缓存压缩做到真正的查询无关，同时在使用int4量化尺度因子作为零成本重要性信号方面展示了很强的工程直觉。尽管在极端密集信息和任务漂移场景下仍有不足，但其整体设计逻辑清晰、实验覆盖广、效率优势显著，对长上下文推理的高效部署具有较好的参考意义。

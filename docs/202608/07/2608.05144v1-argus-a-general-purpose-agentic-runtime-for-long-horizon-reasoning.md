## 摘要
长时程推理需要一种智能体运行时，它能在证据支持当前方法时持续运行，并在测量显示失败、隐藏约束或目标设定错误时转向。我们提出Argus，一种持久、自我进化的运行时，其中管理器、规划器、工程师和审查员在持久项目状态上执行有界任务。Argus将稳定的用户意图与操作目标、约束和验证标准分离，并仅在角色拥有的审查以及（可用时）任务原生验证后接受记忆、技能、程序、验证器、路由决策和拒绝路径。模型权重保持固定；自我进化通过持久运行时状态和控制策略实现，在操作者拥有的升级点之间自主执行。在七个GPT-5.5基准竞技场上，Argus在SWE-Bench Pro上达到约78%的成绩，而Direct Copilot为59%，同时使用1.41倍的总令牌。经过验证门控的自我进化后，成熟的SWE-Bench波次每个任务的解决输入令牌减少21%，活跃工作流时间减少15%，同时记录了34次验证器恢复和22次严格审查循环救援。Argus在AARRI-Bench上还达到76.8%，在数学数据合成上达到28.0点的差距，并有竞争力的GPU内核和语言模型训练结果。在基准测试之外，一个优化的RWKV6内核被合并到上游；一个多日的数学活动保留了被证伪的路径和基于证明的前沿更新；六个论文流水线完成了254个任务，经历了16次阶段回滚。这些结果表明，一个固定权重的自我进化框架可以修订、恢复和积累经过验证的方法，同时为未来的监督和强化学习生成结构化轨迹。

## Abstract
Long-horizon reasoning requires an agentic runtime that can persist when evidence supports its current approach and pivot when measurements reveal failure, hidden constraints, or a misspecified objective. We present Argus, a persistent, self-evolving runtime in which Manager, Planner, Engineer, and Reviewer execute bounded missions over durable project state. Argus separates stable user intent from operational objectives, constraints, and verification criteria, and admits memories, skills, procedures, verifiers, routing decisions, and rejected routes only after role-owned review and, when available, task-native verification. Model weights remain fixed; self-evolution occurs through persistent runtime state and control policy, with autonomous execution between operator-owned escalation points. Across seven GPT-5.5 benchmark arenas, Argus achieves about 78% on SWE-Bench Pro versus 59% for Direct Copilot while using 1.41 times the aggregate tokens. After verification-gated self-evolution, mature SWE-Bench waves use 21% fewer solve-input tokens and 15% less active workflow time per task than startup waves, while recording 34 verifier recoveries and 22 strict review-loop rescues. Argus also reaches 76.8% on AARRI-Bench and a 28.0-point gap on mathematical data synthesis, with competitive GPU-kernel and language-model-training results. Beyond benchmarks, an optimized RWKV6 kernel was merged upstream; a multi-day mathematics campaign retained falsified routes and proof-backed frontier updates; and six paper pipelines completed 254 missions with 16 stage rollbacks. These results show that a fixed-weight, self-evolving harness can revise, recover, and accumulate verified approaches while producing structured trajectories for future supervised and reinforcement learning.

## 1. 核心问题与研究动机

### 1.1 核心问题：长时程推理的"转向"与"目标漂移"困境

- 长时程智能体任务（如软件修复、科研探索、数学证明）往往**无法按固定计划一路执行到底**。实际进展常常需要：
  - 修正操作目标（operational objective）；
  - 发现隐藏约束；
  - 推翻既有路线；
  - 重构任务定义。
- 作者指出：**允许目标修正是必要的，但它在外部不可与"失败后合理化"区分**——若系统可以随意放弃原目标，最终目标会朝着"执行者恰好能完成的事"退化，即目标漂移（goal drift）。
- 既有主流方案（ReAct、SWE-agent、OpenHands 等）通过"固定目标、优化执行"回避该问题，但在真实研究中目标难以一成不变。

### 1.2 核心主张

- 作者采取相反立场：**"转向"应当被允许，但必须通过"验证"使其安全**。
- 一个可接受的转向必须同时满足三个条件：
  1. **有证据支持**（原路径不可达或目标被错误设定）；
  2. **经过明确角色边界授权**（role-gated）；
  3. **被完整记录**（后续任务可继承该变更及其理由）。
- 论文提出三个现有长时程系统普遍缺失的性质：
  - **连续性**：转录被截断或压缩时，驱动变更的证据丢失；
  - **验收分离性**：执行者自证完成，导致修订由最有利害关系的方认证；
  - **经验保留性**：仅保留最终产物，被证伪的路线无法作为"目标不可达"的证据被引用。

### 1.3 整体含义

论文尝试回答一个元问题：**一个固定权重的智能体系统，能否通过持久化的运行时状态与验证门控的自我进化，在长期科研任务中实现"既坚持又转向、既积累又纠错"**——而不依赖在线更新模型参数。

## 2. 方法论：Argus 运行时设计

### 2.1 系统总览：四角色 + 三平面

Argus（Autonomous Research Generation and Understanding System）围绕四个模型驱动角色构建：

| 角色 | 核心职责 | 权威性输出 |
|------|---------|-----------|
| **Manager** | 锚定目标、生命周期、路线与阶段；拥有阶段转换权 | 战役划分与阶段切换 |
| **Planner** | 将当前研究状态分解为有界任务与依赖关系 | 任务规格、计划状态、阶段清单 |
| **Engineer** | 修改工件、调用工具、执行实验（有界任务） | 执行结果、工件、测量、交接、review=skip/required 选择 |
| **Reviewer** | 按需独立审查工件与执行记录 | `done`/`continue`/`blocked` 结构化裁决 + 后续行动 |

系统分为三个平面：
- **控制平面**：锚定战役并调度工作（Manager/Planner）；
- **执行平面**：执行有界任务，操作真实工具与工件（Engineer）；
- **记录平面**：只存储不可变事件记录，不做科学完成性判断。

### 2.2 核心抽象：有界任务（Bounded Mission）与持久项目状态

- 长寿命对象是**战役**（campaign），而非模型会话转录。
- 战役的工作被划分为**有界任务（missions）**，每个任务必须有明确的终止/暂停/转移行为。
- 跨会话连续性由共享的 `CHECKPOINT.md` 文件维护，包含持久状态、证据引用、未决问题与下一步。
- 任务分配具有事务性（防止并发重复），恢复执行绑定到持久战役身份。

### 2.3 报告级契约模型（Report-Level Contract）

形式化定义为：

```
Kt = (ι, ot, ct, vt)
```

其中：
- `ι`：稳定用户意图（必须保持不变）；
- `ot`：当前操作目标；
- `ct`：已知约束；
- `vt`：验证标准；
- `Xt`：用户可见的澄清、优先级与未决问题。

材料级（material）修订由**ManagerAdmit 算子**（分析性投影，非单一原子 API）表示：

```
(Xt+1, Kt+1) = ManagerAdmit(Xt, Kt, K't, et, rt, ut)
```

其中 `K't` 为提议的新契约，`et` 为证据，`rt` 为记录的裁决结果，`ut` 为授权用户/Manager 决策。该抽象明确要求：**契约修订必须有证据、有授权、有审计轨迹**。

### 2.4 任务循环与阶段动态

- 循环关系：

```
M → P → E ⇄ R → M
```

（Manager 治理 → Planner 规划 → Engineer 执行 ⇄ Reviewer 审查 → 回到 Manager）

- 阶段转换规则：

```
gn+1 ∈ {gn, next(gn)} ∪ prev(gn)
```

即 Manager 可保持、前进到下一阶段、或回滚到更早阶段。

- 对论文生产管线，阶段顺序为：**研究 → 规划 → 基准 → 运行 → 分析 → 草稿 → 审查 → 提交**。

### 2.5 验证门控的固定模型运行时自我进化

- 模型权重 `θt` 严格不变：`θt+1 = θt`。
- 持久状态定义为：

```
Ht = {Memory, Skills, Tools, Verifiers, Routing}
```

（并扩展包含任务定义 Qt）

- 持久状态更新：`Ht+1 = U(Ht, τt, Et, Kt+1)`，其中更新是**偏序的**——许多任务只改记忆，部分任务不改变任何可复用组件。
- **验证门控**的含义：一个候选的记忆/技能/程序/验证器/路由决策/被拒路径，只有在经过负责任务的检查（可包含官方验证器、独立 Reviewer、或明确允许的 Engineer 自审）并由授权所有者提交后，才成为可复用状态。
- 完整更新循环分四步：
  1. 执行轨迹产生候选更新；
  2. 责任角色对照工件与任务原生证据进行核查；
  3. 授权所有者提交/修订/拒绝；
  4. 后续任务将保留状态作为起始上下文或执行策略的一部分。
- 未通过此提交-复用路径的活动不计入"自我进化"。

### 2.6 审查与完成判定

- **完成裁决来源显式化**：低风险有界任务可允许 Engineer 自审（`review_source=engineer_self_review`）；垂直策略、阶段关闭任务或 Engineer 主动请求时必须由独立 Reviewer 审查。
- Reviewer 返回结构化裁决：`done`（完成）、`continue`（返回 Engineer 继续修改）、`blocked`（声明无法完成）。
- 完成永远不来自文件名、Token 数量或散文关键词。

- 731 个任务按 Wave（波次）分组，采用**任务加权窗口**：
  - W1–6：启动期（startup，120 任务）
  - W7–12：早期复用（140 任务）
  - W13–18：构成变化期（151 任务）
  - W19–22：成熟期（mature，158 任务）
  - W23–24：后期困难任务（49 任务）
  - 两个未完成的 Wave 被省略。
- 主要比较为启动期 vs 成熟期；该比较是**观察性**的，不是因果学习消融。

### 3.3 Reviewer 路由分析

- 统计 466 个调用独立 Reviewer 的任务 vs 265 个 Engineer 自审任务。
- 追踪 `continue` → 修改 → `done` 的严格审查循环，以及修改后官方验证器通过率。

### 3.4 垂直案例研究（Vertical Studies）

- **数学战役**：Erdős–Gyárfás 图论问题，角色级 Agent 轨迹重建，保留 1 条证伪路线 + 6 条定理前沿更新。

### 3.5 消融与对照组

- **无冻结状态重放**：SWE 任务序列未对冻结运行时状态重放，因此无法将 Token/时间下降因果归因于具体记忆或技能更新。
- **无随机化路由**：Reviewer 路由是自适应的，非随机的，因此无法单独估计路由策略的因果效应。
- **Direct Copilot 基线**存在，但未保留逐 Wave Token/时间记录。

### 5.2 充分性讨论

**充分之处：**
- 覆盖**七个异构基准**，跨越软件工程、GPU 优化、模型训练、研究辅助、数据合成，任务原生单位避免了归一化偏差。
- SWE-Bench Pro 的 731 任务规模是较大规模的纵向轨迹数据。
- 配备外部不可控验证器的垂直案例（静态时序工具、MOFChecker 化学验证器）增强了验证可信度。
- 论文自觉报告了**失败路径**（证伪路线、blocked 任务、中断实验）而非仅报成功，这在自主科研系统文献中较少见。

**不充分/存在风险之处：**
1. **无因果隔离**：SWE 纵向比较（mature vs startup）是观察性的。任务构成、难度、仓库类型均随 Wave 变化，无法排除任务难度下降作为替代解释。
2. **无随机化路由对照**：Reviewer 路由是自适应策略，高成本任务恰好被路由给 Reviewer，导致成本对比（2.75× tokens / 1.80× time）不能反映路由的因果效应，反而可能反映任务难度选择。
3. **Direct Copilot 数据不完整**：无逐 Wave Token/时间记录，只有总 Token 比（1.41×），无法做窗口对齐对比。
4. **单一模型为主**：七个基准全部以 GPT-5.5 为骨干；GLM-5.2 在 Claude Code 后端的运行仍在进行中，没有匹配基线，因此"跨模型泛化"目前只是单点证据，不能下结论。
5. **论文流水线无外部评审**：6 篇论文是内部审查的提交格式完成，未涉及会议录用、新颖性验证或外部同行评审。
6. **数学战役的"六条定理前沿更新"是内部 Argus 审查**，不是外部同行评审；论文明确标注勾号表示内部审查而非公认新颖性。

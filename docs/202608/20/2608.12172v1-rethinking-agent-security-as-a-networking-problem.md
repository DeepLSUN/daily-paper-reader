## 摘要
人工智能智能体正迅速变得更为强大并广泛部署，有望带来生产力的显著提升并催生新的应用类别。然而，它们日益增强的自主性也引入了重大的隐私与安全风险。现有防御措施主要以智能体为中心，依赖智能体自身来检测威胁并执行隐私与安全策略。这种方法存在根本性局限，因为它将策略执行委托给AI智能体，而智能体基于LLM的行为本质上具有不确定性，且容易受到诸如提示注入等攻击手段的操纵。因此，现有防御措施无法可靠地防止隐私与安全威胁，凸显了寻求新方案以保障AI智能体系统安全的迫切需求。网络社区长期以来一直在应对类似挑战，并提供了富有洞察力的原则，我们可以借鉴这些原则来设计更安全的AI智能体系统。这些原则包括集中控制与分布式执行、基于能力的访问以仲裁对敏感资源的请求，以及通过零信任执行实现最小权限。从历史上看，这些原则为网络系统提供了强大的确定性保证。然而，仅凭这些原则不足以应对AI智能体，因为智能体行为的安全性与适当性往往依赖于超出静态规则表达能力的语义上下文。基于这些原则，我们倡导一种系统化的AI智能体安全方法，将提供强安全保证的确定性执行机制与实现细致决策的语义感知上下文策略相结合。随后，我们提出了一种参考架构，并指出了关键研究问题与未来方向，以指导安全且保护隐私的AI智能体系统的设计。

## Abstract
AI agents are rapidly becoming more capable and widely deployed, promising substantial gains in productivity and enabling new classes of applications. However, their growing autonomy also introduces significant privacy and security risks. Existing defenses are predominantly agent-centric, relying on the agent itself to detect threats and enforce privacy and security policies. This approach is fundamentally limited because it entrusts policy enforcement to AI agents whose LLM-driven behavior is inherently nondeterministic and vulnerable to manipulation through attacks such as prompt injection. As a result, current defenses cannot reliably prevent privacy and security threats, highlighting a critical need for a new solution to securing AI agent systems.   The networking community has long grappled with similar challenges and offers insightful principles we can borrow to design a more secure AI agent system. These include centralized control with distributed enforcement, capability-based access for mediating requests to sensitive resources, and least privilege through zero-trust enforcement. Historically, these principles have provided strong deterministic guarantees for networked systems. However, these principles alone are insufficient for AI agents because the safety and appropriateness of an agent's actions often depend on semantic context beyond the expressiveness of static rules.   Building on these principles, we advocate for a systematic approach to AI agent security that combines deterministic enforcement mechanisms, which provide strong security guarantees, with semantic, context-aware policies that enable nuanced decision-making. We then present a reference architecture and identify key research questions and future directions to guide the design of secure and privacy-preserving AI agent systems.

- **问题背景**：AI智能体（AI agents）基于LLM技术，能够自主规划、推理和执行多步骤工作流，可调用API、访问企业资源、与其他智能体协作，并在有限人类监督下运作，因此成为连接用户、服务和外部API的新型网络化系统层。

  - 对抗性手段如（间接）提示注入、记忆投毒、目标劫持等可操纵智能体推理，导致其绕过安全策略，执行有害操作（如发起攻击、权限提升、篡改数据库、未授权财务交易）；
  - 即使智能体按预期运行，也可能在不当上下文中披露敏感信息或超出用户请求范围执行操作。
- **现有防御的根本缺陷**：
  - 传统安全架构（RBAC、OAuth/API密钥等）基于静态、预定义规则，无法适应智能体动态、上下文相关的行为；
  - 智能体级防御（提示工程、微调、隐私感知提示等）依赖LLM推理本身来执行安全策略，而LLM行为非确定性、易受提示注入攻击、可被对抗性输入绕过，因此无法提供强安全保证。

## 2. 方法论：核心思想、关键技术细节与架构流程

### 2.1 核心思想：两个互补抽象

- **确定性执行（Deterministic Enforcement）**：作为系统层原语，约束智能体执行可做什么——可调用哪些工具、可到达哪些目标、输出可经过哪些数据流路径。这一层不依赖智能体的配合、提示词或模型权重，类似防火墙但保护单元是智能体执行图而非数据包五元组，必须位于智能体推理路径之外（off-path）的网络咽喉点。
- **上下文感知语义策略（Context-Aware Semantic Control）**：提供静态规则无法表达的“适当性”词汇表。论文引入**Nissenbaum的语境完整性（Contextual Integrity, CI）**理论，将隐私规范形式化为（发送者角色、接收者角色、主体、信息类型、传输原则）的五元组，通过`check_flow(sender, recipient, task, labels)`函数在每个跳点执行——本质上是**以CI规范为标签策略、以网络为参考监视器的信息流控制（IFC）**。

### 2.2 三个设计原则（借鉴网络领域）

- **集中控制（Centralized Control）**：借鉴SANE和Ethane，采用声明式的中央指定策略并由网络强制执行。如果智能体能绕过或忽略某个护栏，该护栏就无法可靠执行策略，因此控制面必须位于智能体边界之外。论文引用端到端论证（Saltzer et al.）来说明：当端点（智能体）本身不可信且可被操纵时，不应将功能放在端点，而应放在网络中。
- **基于能力的访问（Capability-based Access）**：借鉴SIFF、TVA和Off-by-Default方案，智能体的可达性应**默认关闭**——必须通过策略获得显式、可撤销的能力才能发送数据或联系目标。能力应防伪造、可被执行点验证、由受信任的策略权威签发，而非由智能体自行声明。
- **最小权限与零信任执行（Least Privilege via Zero-Trust）**：通过能力机制与集中控制的结合实现零信任原则，不在智能体内部预设信任。

### 2.3 参考架构

- **控制平面（Control Plane）**：位于企业信任边界内、与智能体隔离，负责定义和分发安全策略，包括确定性规则（ACL、RBAC）、语义策略（如客户PII使用约束）、请求路由策略、数据敏感度标签、风险阈值和语义评估模型。控制面不参与运行时决策，但防止智能体修改或绕过安全要求。
- **Sidecar（安全执行点）**：部署在每个智能体旁，拦截智能体的所有外部动作（工具调用、内存操作、API请求、网络通信、文件访问、数据共享）。核心组件包括：
  - **Agent Policy Gateway**：运行时执行点，充当代理与外部资源之间的中介；
  - **Request Classifier / Policy Router**：基于策略定义的标准（动作类型、资源敏感度、风险级别），将请求路由到确定性执行引擎或语义引擎；
  - **Deterministic Enforcement Engine**：针对无需语义推理的请求执行明确的策略（ACL、RBAC、工具权限、网络策略、速率限制）；
  - **Context-Aware Semantic Engine**：针对安全取决于上下文语境的请求，收集数据敏感度、行动风险、智能体角色与权限、用户意图、当前任务、最近交互等执行上下文后，做出**允许（allow）、拒绝（deny）、修改（modify）或升级为人工审批（escalate）**的决定。
- **端到端执行流程**：控制面定义并分发策略 → 智能体发起外部动作 → Agent Policy Gateway拦截 → Request Classifier路由 → 确定性或语义引擎评估 → 返回决策并执行 → 所有决策和上下文信息记录审计。

### 2.4 与现有环境的集成

- 类似API网关/服务网格/策略执行点，将现有企业安全基础设施（身份管理、访问控制、数据治理）扩展至智能体；
- 因Sidecar独立于智能体实现，可跨不同模型、框架和架构统一部署，无需修改单个智能体；
- 可灵活部署在智能体交互点或数据边界处，即使智能体为黑盒接口也可强制执行策略。

## 6. 论文的主要结论与发现

- **现有智能体级防御无法提供可靠安全保证**——依赖LLM推理执行策略从根本上不可靠，因为智能体本身可能被攻击者操纵。
- **网络是执行智能体安全控制的正确位置**——多智能体AI系统本质上是分布式通信实体系统，网络架构中的原则和机制可自然迁移到智能体安全领域。
- **单一原则不够，必须组合确定性执行与语义上下文感知**：
  - 仅确定性执行会退化为粗粒度连接控制（能阻止访问未批准端点，但无法阻止对已批准端点过度分享）；
  - 仅语义感知则退化为现有护栏（规范写在提示词中，由被保护对象自己执行）。
  - 正确的做法是将语义**编译为确定性机制**，放在被保护端点无法绕过之处。
- **提出了一个可落地的参考架构**：控制平面 + sidecar（Agent Policy Gateway + 请求分类器 + 确定性引擎 + 语义引擎），支持允许/拒绝/修改/升级人工审批四种决策。
- **指明了未来研究方向**：
  - 从出口（egress）扩展到入口（ingress）过滤——后者更难，因为需要不可依赖的发送方合作；
  - 语义策略定义与上下文表示的设计问题；
  - 泛化性挑战：动态子智能体、新工具、运行时未知交互场景需要动态强制机制；
  - 动态角色与信任级别演进问题；
  - 风险感知的策略路由（低风险走确定性快速检查，高风险走语义分析）。

## 7. 优点

- **跨领域类比有深度且恰当**：将智能体安全系统地映射到网络安全的成熟概念（集中控制、能力访问、零信任），同时指出简单的类比不够——智能体的安全需要语义理解，这一论证逻辑严谨。
- **明确承认两种抽象各自的不足**：不把确定性执行或语义策略当作银弹，而是明确论证二者结合的必要性，这种“组合而非二选一”的思路具有较高的实用价值。
- **定位精准**：指出现有防御的核心问题是“强制执行者和被约束方是同一个实体”，这一观察简洁而深刻。
- **架构设计清晰可行**：控制面与数据面分离、确定性/语义双路径路由、Sidecar模式均为业界已有实践，有较好的继承性和可落地性，对现有企业基础设施建设友好。
- **引入了CI理论到可执行层**：将语境完整性从评估工具转化为运行时检查函数（`check_flow`），是概念上的创新贡献。
- **诚实且平衡地讨论了局限性**：包括prompt injection对语义引擎的残风险、出口外无可见性、入口过滤的难度等，展现了学术严谨性。
- **对多智能体系统特定隐私失败模式（如“良性过度分享”“跨智能体跳点的上下文传播”）的定义**，有助于建立新的研究问题表述。

## 8. 不足与局限

- **缺乏实证验证**：这是最显著的局限。论文没有对提出的架构进行任何实验评估，不提供安全有效性、性能开销、误报/漏报率等关键指标的度量。架构中的语义引擎本身依赖LLM执行策略评估，其安全性和可靠性未被验证。
- **语义引擎仍可能被攻击**：论文承认攻击者可操纵智能体提供的上下文，导致语义引擎授权未经授权的信息流或操作——这在一定程度上削弱了“独立于智能体”的承诺，因为语义引擎的决策仍依赖智能体的输入。
- **仅覆盖企业出口（egress）**：架构在企业边界执行策略，对数据离开企业后外部服务的计算没有可见性或控制，在外部服务不可信的场景下保障有限。

- **泛化性挑战**：静态策略难以应对智能体运行时动态生成子智能体、调用新工具、建立未见过的交互等场景；动态角色和信任级别随执行演化的问题也没有解决方案。
- **能力设计的粒度与语义未明确**：当受保护资源是“上下文敏感的隐私信息”而非网络带宽时，能力（capability）应具有何种粒度和语义仍是一个悬而未决的问题，意味着该架构在实施层面仍有概念空白。
- **入口（ingress）方向的困难被简要提及但未深入**：恶意发送方可绕过sidecar检查，需改变策略（如预协商的可验证标签），但具体机制未展开。
- **作为立场论文的接受度依赖类比合理性**：论点的说服力高度依赖对网络类比的有效性，然而智能体系统与网络系统在威胁模型、语义复杂度和自适应能力上存在本质差异，类比可能过度简化问题。

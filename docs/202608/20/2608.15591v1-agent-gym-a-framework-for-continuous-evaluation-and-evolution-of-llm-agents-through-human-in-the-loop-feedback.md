## 摘要
部署在生产环境中的大型语言模型（LLM）智能体面临一个根本性矛盾：智能体的行为在部署时即被固定，而它必须处理的业务规则和边缘情况却在持续演变。现有方法解决了智能体构建和一次性评估的问题，但缺乏在不修改智能体源代码的情况下，对部署后行为进行持续修正的结构化机制。市场上提供的大多数方法需要密集收集日志和追踪数据，并由工程团队重新审查智能体设计，这一过程繁重、耗时，削弱了智能体转型的经济价值。我们提出Agent Gym，一个模块化、领域无关的框架，将任何基于LLM的现有智能体封装在持续评估与演进的循环中。该框架提供六种可组合能力——行动（Act）、评估（Evaluate）、调查（Investigate）、纠正（Correct）、学习（Learn）和观察（Observe）——并组织在三个架构区域中：一个宪法层，将领域知识编码为配置工件；一个运行时推理流水线，将行动、调查和自适应纠正串联起来；以及一个学习循环，使领域专家能够通过自然语言交互发现并验证新的纠正规则。关键技术贡献包括：一个混合确定性-LLM纠正引擎，配备21个条件运算符和三层操作；一个三层调查架构，用于无真值合规性验证；以及一个程序化安全循环，在人工批准之前保证规则正确性。我们还引入了规范到注释差距（Spec-to-Note Gap），一种受自动编码器启发的智能体系统透明性视角。一个用于发票处理的开源参考实现表明，该框架完全可运行并可供采用。

## Abstract
Large Language Model (LLM) agents deployed in production environments face a fundamental tension: the agent's behavior is frozen at deployment time, while the business rules and edge cases it must handle continue to evolve. Existing approaches address agent construction and one-time evaluation but provide no structured mechanism for continuous post-deployment behavioral correction without modifying the agent's source code. Most of the approaches offered in the market, require intense collection of logs and traces, and re-examining the agent design by the engineering team, a process which is heavy, long and negates the economical value of agentic transformation. We introduce Agent Gym, a modular, domain-agnostic framework that wraps any existing LLM-based agent in a continuous evaluation-and-evolution loop. The framework provides six composable capabilities --- Act, Evaluate, Investigate, Correct, Learn, and Observe --- organized across three architectural zones: a constitution layer that codifies domain knowledge in configuration artifacts, a runtime inference pipeline that chains acting, investigation, and adaptive correction, and a learning loop that enables subject matter experts to discover and validate new correction rules through natural language interaction. The key technical contributions include a hybrid deterministic-LLM correction engine with 21 condition operators and three-tier actions, a three-layer investigation architecture for ground-truth-free compliance validation, and a programmatic safety loop that guarantees rule correctness before human approval. We further introduce the Spec-to-Note Gap, an autoencoder-inspired view of agentic system transparency. An open-source reference implementation for invoice processing demonstrates that the framework is fully operational and ready for adoption.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想与总体架构

Agent Gym 是一个模块化、领域无关的框架，将现有智能体视为 **“黑盒”**，包裹在一个持续“评估-演进”循环中。框架由**六种可组合能力**（Act、Evaluate、Investigate、Correct、Learn、Observe）和**三个架构区域**（Zone）组成：

- **Zone 1 — 宪法架构层（Constitution Architecture）**：包含主数据规范（YAML）和重建规则书（Markdown），将所有领域知识编码为声明式配置工件，作为系统的“宪法”。这些工件既是人可读的文档，也是机器可解析的规范。
- **Zone 2 — 运行时推理流水线（Runtime Inference Pipeline）**：按顺序包含行动智能体（Acting Agent）→ 调查智能体（Investigation Agent）→ ALF 纠错引擎（Adaptive Learning Framework）。管道级联执行行动、调查与自适应纠正。
- **Zone 3 — 学习与演进循环（Learning & Evolution Loop）**：通过程序化安全循环，使领域专家（SME）能够以自然语言交互的方式发现、验证并持久化新的纠错规则。

### 2.2 设计原则

1. **智能体是黑盒**：不假设智能体内部架构，仅观察输入-输出行为。
2. **纠正是分层而非侵入式**：修正应用于独立的下游层，保留原始输出，保证可审计性和独立回滚。
3. **领域知识活在配置而非代码中**：切换新领域仅需更换配置文件。
4. **人类治理循环**：任何规则的产生必须由 SME 审核、批准和验证。
5. **治理分层**：领域 SME 可发现案例级规则，但核心宪法修改需多方管理审批，防止恶意规则注入或策略漂移。

### 2.3 关键技术细节

#### (1) 混合确定性-LLM 纠错引擎（ALF）
- **检测与纠正分离**：检测过程完全确定性（21 个条件运算符，如相等、包含、正则、数值比较、列表成员、动态字段引用；条件间采用 AND 逻辑），无 LLM 参与，结果完全可复现。
- **动态字段引用**：如 `_DYNAMIC_preprocessing.vendor_name_` 可在评估时解析，实现参数化条件。
- **三级操作模型（Tier 1-3）**：
  - Tier 1：确定性字段编辑（正确值为已知常量时）。
  - Tier 2：LLM 外科手术式补丁（针对特定字段）。
  - Tier 3：LLM 继续被中断的流水线（智能体提前终止时）。
- **Collect-Plan-Execute 聚合流程**：收集所有匹配规则 → 按层级分组形成修订计划 → 按 Tier 3 → Tier 2 → Tier 1 固定顺序执行。**基于作用域的互斥保证每个作用域至多触发一条规则**，每案例最多产生 2 次 LLM 调用。

#### (2) 三层调查架构（无需真值的合规验证）
- **Layer 1 确定性检查**：验证数据来源合法性、检测旁路（跳过必需验证步骤），无 LLM 调用。
- **Layer 2 LLM 规则发现**：初始化时将规则书发送给 LLM，结构化规则分组；采用 SHA-256 哈希缓存，规则书未变化时零成本。
- **Layer 3 超保守交叉验证**：发现潜在违规时执行**三重检查**（同一评估重复三次），仅报告三次一致确认的违规，大幅降低误报。
- **成本控制机制**：内容哈希缓存、章节过滤上下文（只传相关章节）、批量分组（确定性规则组合为单次调用）、早期退出（合规案例只需单次调用）。

#### (3) 程序化安全循环
- 在代码层面执行而非提示词，LLM 无法绕过。每个候选规则经过迭代验证循环：
  1. **模式验证**：JSON 结构符合 ALF 模式。
  2. **目标命中验证**：条件必须匹配目标案例，否则 LLM 自动放宽条件（同时保持保守）。
  3. **附带影响评估**：在案例样本上确定性评估，出现非预期命中时 LLM 自动收紧条件（如添加供应商名称、金额范围、服务类别），最多迭代 3 次。
- 若附带影响仍存在，规则带警告提交给 SME。规则持久化必须得到 SME 明确批准，部分情况下需要两级审批。

#### (4) 宪法驱动的智能体创建
- 宪法工件（规则书+主数据）既是治理工具，也是新智能体的开发规范，形成“宪法 → 代码 → 精炼宪法”的双向循环。
- 计划中的 Bootstrap Agent（四阶段 LLM 流水线）可分析智能体源码和样本输出自动生成宪法工件，当前参考实现为手动编写。

#### (5) Spec-to-Note Gap（规范-注释差距）
- 将智能体系统生命周期视为**自动编码器**：自然语言规范（输入）→ 实现系统（隐表示）→ LLM 审计者生成的透明度注释（重建）。
- 规范与透明度注释之间的差距充当“重建损失”，可暴露缺失能力、范围蔓延和未测试行为。将 round-trip correctness 从函数级推广到全系统粒度。

#### (6) 评估引擎
- **确定性比较**：字段级匹配，数值字段应用财务公差（默认 $0.02），文本字段归一化后精确匹配。
- **LLM-as-judge（可选）**：给出 Aligned / Partially_Aligned / Not_Aligned 的整体对齐判断。

## 6. 论文的主要结论与发现

- **静态智能体困境是真实的**：现有智能体构建与评估方法无法应对部署后行为与业务规则之间的持续失配。
- **纯代码级修正路径不可持续**：通过工程团队重写代码来修正智能体行为的速度远跟不上业务变化的速度，削弱了智能体转型的经济价值。
- **Agent Gym 提供了可行的替代范式**：
  - 将智能体视为黑盒包裹在持续观察-纠正-学习循环中，无需修改其源码。
  - 领域知识完全通过声明式配置工件表达，框架代码保持领域无关。
  - 纠正层与智能体独立版本化、测试和演进，获得更好的可审计性与可回滚性。
  - 人类（SME）通过自然语言和非侵入性的程序化安全循环治理智能体的持续演进，而非由工程师改写代码。
- **无真值合规验证是可行的**：三层调查架构能够在没有 ground truth 的情况下验证决策是否符合业务规则。
- **开源参考实现证明框架已可运行**：发票处理的完整实现端到端跑通，包含全部测试用例、PDF 文档、真值和预配置规则，作为单包安装可部署。

## 7. 优点

- **填补关键空白**：针对智能体部署后持续治理这一真实且未被充分解决的问题，提出了结构化、系统化的框架。
- **真正的领域无关设计**：通过宪法/配置文件实现领域适配，框架代码零改动，具有清晰的可扩展路径。
- **“智能体是黑盒”的优雅抽象**：不侵入智能体内部，不限制底层框架，适用于单体流水线、多智能体系统甚至单次 LLM 调用，兼容性强。
- **分离检测与纠正**：21 个确定性条件运算符保证错误检测的可复现性，LLM 仅用于需要语义理解的纠正环节，平衡了可靠性、灵活性与成本。
- **程序化安全循环（代码强制而非提示词）**：这是重要的安全设计亮点，规则在进入生产前经过模式验证、目标覆盖验证、附带影响消除等多轮自动检查，低风险地保障了人机协作的治理底线。
- **成本控制的工程细节完善**：SHA-256 内容哈希缓存、章节过滤上下文、批量分组、早期退出三重检查，使 LLM 开销在稳态下趋近于零，具备生产实用性。
- **宪法作为“活文档”的双向用途**：既是治理工具又是新智能体的开发规范，为智能体再工程化和跨域迁移提供基础。
- **Spec-to-Note Gap 的自动编码器视角**：概念新颖，为智能体系统透明性提供了一种可操作的自动化诊断模式，具备推广到 CI/CD 发布关卡的潜力。
- **开源参考实现完整可用**：为社区提供了可直接运行和学习的样例。

- **手工撰写的配置文件是当前瓶颈**：Bootstrap Agent（自动生成宪法的人工智能管道）仍只是计划中的自动化方案；对复杂真实领域，手动撰写高质量规则书和主数据的成本可能很高。
- **LLM 成本未量化**：虽然设计层面有成本控制机制，但大规模部署下的推理成本、缓存命中率、Token 消耗等均为量化空白。
- **规则质量依赖 SME 与 LLM 的协作质量**：程序化安全循环降低了规则出错的风险，但无法完全消除。SME 的可用性、疲劳度、判断偏差仍是瓶颈；论文未讨论 SME 之间的分歧或错批风险。
- **学习循环的演化闭环未完成**：规则晋升到智能体永久逻辑（promotion）的机制尚未实现，当前规则库可能随时间膨胀。
- **动态业务规则与新技能的发现**：框架目前只能处理已有规则的重构与微调，尚未真正实现论文开头所说的“发现新技能、新工具、MCP 服务器”等更广泛的演进能力。
- **Spec-to-Note Gap 停留在概念层面**：其作为发布关卡、审计者忠诚度测量等应用尚待探索，无实验验证。
- **未讨论多智能体复杂交互场景**：仅验证了固定流水线式智能体，对具有复杂控制流、并行多智能体协作的系统的可用性不明确。
- **发布年份为 2026 年（arXiv 编号 2608.15591），表明是最新研究**。考虑到其大规模应用和标准化还需要更多实证工作。

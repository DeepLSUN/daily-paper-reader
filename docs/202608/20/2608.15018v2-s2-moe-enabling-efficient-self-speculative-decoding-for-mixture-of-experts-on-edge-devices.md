## 摘要
在边缘设备上部署大型语言模型（LLM）进行推理，由于严重的内存和带宽限制而极具挑战性。虽然推测解码和混合专家（MoE）已被提出以提升推理效率，但简单地将二者结合往往会导致过多的验证开销和较差的专家重用，从而限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提升验证效率，并通过共享上下文对齐草稿与目标执行。在llama.cpp中实现后，S2-MoE在各种MoE模型和边缘设备数据集上，相比标准自回归解码实现了最高5.3倍的加速（平均约2.0倍）。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama$.$cpp, S2-MoE achieves up to $5.3\times$ speedup (about $2.0\times$ on average) over standard autoregressive decoding across diverse MoE models and datasets on edge devices. Code is available at https://github.com/angerybob/S2-MoE.

## 1. 论文的核心问题与整体含义

边缘设备上部署大语言模型（LLM）面临严重的内存与带宽约束。在边缘场景中，推理通常以单批次为主，吞吐量受限于每次访问模型参数所能生成的 token 数，因此**输出密度**（每轮迭代生成的 token 数）与**参数密度**（每轮迭代访问的参数量）是决定效率的两个关键因素。

推测解码（Speculative Decoding, SD）通过增加输出密度来加速推理，而混合专家（Mixture-of-Experts, MoE）通过稀疏激活降低参数密度。两者的结合看似互补，但在边缘场景中存在三个核心矛盾：

1. **验证成本失控**：MoE 中不同草稿 token 可能激活不同的专家，验证时参数重用率极低，导致验证开销大幅上升；且被拒绝的草稿 token 所触发的专家激活成为纯粹的冗余开销。
2. **置信度信号失效**：在 MoE 中，token 级置信度不能反映专家级的验证成本——置信度相似的 token 可能因激活完全不同的专家而产生悬殊的验证开销。
3. **草稿保真度有限**：轻量化草稿模型与目标模型之间存在上下文漂移，预测误差随解码步数累积，导致接受率持续下降。

本文提出 **S2-MoE**，一个专为边缘 MoE 推理设计的自推测解码框架，通过路由感知自适应扩展、重用感知专家门控和共享上下文三个机制，系统性地解决上述问题，将自推测解码真正落地为 MoE 边缘推理的高效加速方案。

## 2. 方法论

S2-MoE 由三个互补的组件构成，整体流程如图 3 所示：草稿阶段生成候选 token 树，验证阶段由目标 MoE 模型并行验证，并通过共享 KV Cache 保持两阶段上下文一致。

### 2.1 路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）

针对 MoE 验证中“置信度相同但验证成本悬殊”的问题，设计了一个同时考虑接受概率与验证开销的效用分数，以此自适应地扩展草稿树：

- **期望收益**：对于深度为 k 的草稿 token *i*，其接受概率为前缀置信度 *pᵢ* = Πⱼ₌₁ᵏ pᵢ,ⱼ；期望收益定义为 Bᵢ = pᵢ · T_AR，其中 T_AR 为目标模型一步解码的平均延迟；
- **路由感知成本估计**：边际验证成本为 ΔC_ver(i|S) = |Eᵢ \ ⋃ⱼ∈S Eⱼ| · T_exp，其中 Eᵢ 为 token *i* 预测激活的专家集合，S 为已选入扩展的 token 集合，T_exp 为引入一个额外专家的延迟开销（可通过轻量运行时测量或离线 profiling 获得）。草稿阶段的路由信号在验证前即可获得，且与目标路由高度相关（如图 2(d) 所示）；
- **效用分数与自适应扩展**：定义效用 Uᵢ = Bᵢ / (ΔC_ver(i|S) + C_draftᵢ)。扩展过程贪心保留 Uᵢ ≥ 1 的候选，直到没有候选满足条件。该策略在 MoE 下兼顾了“接受可能性”与“验证成本”，优于固定宽度扩展（冗余验证过多）和纯置信度剪枝（对成本不敏感）。

### 2.2 重用感知专家门控（Reuse-aware Expert Gating）

针对 MoE 中并行验证时相邻 token 激活不同专家导致参数重用不足的问题，该机制通过软性调整路由决策来提升跨 token 的专家复用：

- **跨 token 专家重要性聚合**：以 token 置信度为权重，将验证批次中各 token 的专家门控 logits 聚合为专家重要性分数 gₑ = Σ_b w_b · ℓ_b,ₑ，使高置信度 token 的专家偏好获得更大权重；
- **全局偏好专家选择**：从聚合分数中选择 TopCap 个专家作为“复用奖励专家集合” E★（cap ≥ k，保证原始的 top-k 专家仍可被选中）；
- **软路由偏置**：对每个 token 的门控 logits 注入加性偏置 λ_b · 1[e ∈ E★]，其中 λ_b 正比于该 token 的 top-1 专家与第 (k+1) 个专家之间的分数差距。该设计使得偏置主要影响 top-k 边界附近的“边缘专家”，而不干扰强主导路由决策；
- **融合 CUDA 内核实现**：引入的额外开销可忽略。

### 2.3 上下文对齐自推测解码（Context-aligned Self-speculative Decoding）

针对草稿与目标模型上下文漂移导致误差累积的问题，让草稿与目标共享同一个 KV Cache：

- 目标模型先处理提示词并建立 KV Cache；
- 草稿直接读取共享上下文，而非维护独立的历史状态；
- 草稿产生的 KV 更新被视为临时状态，验证前回滚，只有被接受的 token 才提交到共享缓存。

该设计将草稿误差限制在当前推测步内，防止跨迭代累积，有效提升了长文本生成中的接受率（如图 2(g) 所示，KL 散度增长被显著抑制）。

## 6. 主要结论与发现

- S2-MoE 在 Jetson Orin 上实现 1.3×–5.3× 加速，在 RTX 4090 上实现 1.2×–2.9× 加速，显著优于各类基线；
- 朴素的 ES 和 LS 自推测基线在紧内存预算下往往**不如**自回归解码，说明仅靠“草稿对齐”不足以发挥自推测的优势，必须解决验证成本与专家复用问题；
- S2-MoE 在较紧内存预算下优势更加明显（16GB 时最高 5.25×），因为此时验证对冗余专家激活和参数重用更加敏感；
- 与 EAGLE-3 相比，S2-MoE 在多样化的 MoE 模型上表现更稳定；与 Cascade 相比，S2-MoE 通过 token 级路由感知成本估计实现了更细粒度的推测控制；
- 各组件验证：
  - 上下文对齐将接受率提升 23%–79%；
  - 自适应扩展相比纯置信度剪枝获得了更优的“接受长度-验证成本”Pareto 前沿；
  - 重用感知门控将专家复用率提升 26%–33%；
- 成本模型与实际验证延迟高度吻合（R²=0.943–0.999，MAPE=0.8–4.5%）；
- 质量评估显示任务精度差异小且无系统性偏差，PPL 比 1.012–1.013，Top-1 一致性 > 89%，说明路由偏置引入的输出扰动是**有界且可控**的。

## 7. 优点

1. **问题定位精准**：通过“吞吐量 = 输出密度/参数密度 · 带宽”的分解，清晰指出 MoE 中推测解码失效的根本原因是验证时的专家激活分散，而非单纯的草稿质量不足；
2. **免训练设计**：三个组件均不需要额外训练，部署成本低、适用范围宽，避免了 EAGLE-3 等依赖逐模型训练预测器的局限；
3. **组件互补性强**：上下文对齐提高草稿保真度（提高分子），自适应扩展降低冗余验证（降低分母），重用门控提升参数复用（进一步压缩实际成本），三者各自针对一个独立瓶颈，消融实验确认其正交性；
4. **成本模型可校准、可解释**：将专家激活映射为硬件延迟单位，与实际验证延迟高度相关，为自适应决策提供了可靠依据；
5. **系统实现完整**：在 llama.cpp 上实现专家级 offloading 和融合 CUDA 内核，考虑了真实边缘部署中的内存约束（16GB/32GB/64GB），非仅停留在算法仿真层面；
6. **质量评估细致**：不仅报告任务精度，还通过 PPL 比、Top-1 一致性、KL 散度等分布一致性指标验证了近似方法的输出偏移是有界的。

## 8. 不足与局限

1. **分布一致性存在轻微偏离**：存在非零的 KL（0.026–0.065）与 RMS logit 偏移（4.88–6.95），Top-1 一致性未达 100%（89%–93%），PPL 比 > 1，说明重用感知门控的软偏置确实改变了输出分布；对严格逐 token 一致性的应用场景可能不可接受；
2. **性能波动幅度大**：加速比在 1.2×–5.3× 之间波动，在部分场景（如 Qwen3 在 4090 上）仅约 1.2×，说明收益依赖模型架构与内存配置，普适性有限；
3. **无统计显著性报告**：缺少多次重复实验的均值和方差，无法判断结果差异的统计显著性；
4. **LS 基线覆盖不完整**：在 Qwen3 和 GPT-OSS 上未运行，虽然论文给出了合理性说明，但对比的完整性受影响；
5. **GPT-OSS 质量评估缺口**：缺少 PPL/KL 等分布一致性数据，对 GPT-OSS 的质量保证更多依赖定性论证；
6. **超参数敏感性分析有限**：仅覆盖部分模型和数据集，draft top-k 和 reuse cap 的最优值可能在不同模型上有不同表现；
7. **与现有 MoE offloading 方法的关系**：论文表示专家级 offloading 与优先 offloading 工作正交，但没有与这些方法进行对比实验，无法评估组合后的协同效果；
8. **对“Harmony 格式”模型的兼容性**：GPT-OSS 的评估缺口暗示模型后训练方式（如 Harmony 格式、CoT/RL）可能影响 S2-MoE 的质量评估方法的适用性，需要更多验证。

## 摘要
生成结构有效的合成表格数据仍然困难：具有高统计保真度和下游实用性的输出仍可能违反语义上有意义的领域约束。我们研究了三种互补的列间约束族的发现和执行——方程、线性不等式和逻辑依赖。我们统一的基于工具的工作流将三者表示为机器可执行的假设，并应用通用接口进行全表验证、确定性诊断和反例引导修订。一个生成器无关的后处理器协调对未更改的表格生成器输出的特定族修复。通过精心策划的行为审计和端到端评估，完整的工作流在一次性直接提示上提高了保留的违规检测，而后处理对每个保留的、适用的约束产生零测量违规，提高大多数数据集的下游实用性，并在很大程度上保留单变量边际。

## Abstract
Generating structurally valid synthetic tabular data remains difficult: outputs with high statistical fidelity and downstream utility can still violate semantically meaningful domain constraints. We study the discovery and enforcement of three complementary inter-column constraint families---equations, linear inequalities, and logical dependencies. Our unified tool-grounded workflow represents all three as machine-executable hypotheses and applies a common interface for full-table validation, deterministic diagnosis, and counterexample-guided revision. A generator-agnostic postprocessor coordinates family-specific repairs on outputs from unchanged tabular generators. Across curated behavioral audits and end-to-end evaluations, the complete workflow improves held-out violation detection over one-shot direct prompting, while postprocessing yields zero measured violations for every retained, applicable constraint, improves downstream utility on most datasets, and largely preserves univariate marginals.

## 1. 核心问题与整体含义（研究动机与背景）

- 合成表格数据在统计保真度和下游任务效用上表现良好，但生成的单条记录常常违反领域语义约束（例如：订单的送达时间早于下单时间、小计与单价×数量不一致、配送方式与产品类型不兼容）。
- 现有研究要么依赖用户预先指定规则，并将其嵌入生成目标（如可微目标、拒绝采样、推理时修正），要么在特定约束族或特定生成流程中自动获取约束；它们未共同解决两个相互耦合的挑战：
  1. 异构的语义关系（数值方程、线性不等式、类别逻辑依赖）需要表示为可执行假设，并能基于完整参考表进行测试与修订；
  2. 对“未修改的已有生成器”的输出进行约束执行时，需要在共享列上协调修复，因为一次修复可能使另一约束失效或过度扭曲生成分布。
- 本文提出一个统一的工具化工作流：LLM 智能体提出三类列间约束的可执行假设；确定性工具对全表验证、诊断并给出反例，驱动迭代修订；最后用“生成器无关的后处理器”在原始生成器输出上协调修复。核心贡献是共享可执行接口与协调后处理。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 整体架构
- 给定真实表 `D_real`、元数据、未加约束的合成表 `D_syn`，目标为：
  1. 自动发现可执行的方程、线性不等式、逻辑依赖，并在完整参考表上验证与修订；
  2. 后处理合成表，使这些约束在联合层面得到满足，同时尽量保持统计保真度和下游效用。
- 两条阶段：LLM 引导的约束发现 → 约束执行（后处理）。

### 2.2 约束发现过程
- **数据集画像（Dataset Profiling）**：为每个列生成语义描述、类型、数值统计（范围、分位数、均值、std、集中点）或类别频率；供 LLM 使用。
- **可执行假设生成**：
  - 方程（Equational）：LLM 生成 `check(df)` Python 函数，按行返回布尔 Series，支持任意算术恒等式与容差。
  - 线性不等式（Linear Inequality）：JSON DSL 表示半空间 `Σ a_j x_j ≤ b` 或 `≥ b`，便于解析、规范化、联合投影。
  - 逻辑依赖（Logical Dependency）：JSON DSL 表示一个或多个行列、一个依赖列、值表；每个条目给出确定列候选集合与依赖列允许集合。支持函数依赖、部分规则、多值映射。
- **工具化验证与修订**：
  - 三个确定性验证器（`validate_equational`、`validate_linear`、`validate_LD`）在完整参考表上计算违规率 `VR(h)=|V_h|/|A_h|`；仅当 `VR(h) ≤ τ_vio` 时保留。
  - 逻辑依赖额外要求覆盖支持度 `Supp(h) ≥ τ_sup`，防止只在极少数行上成立的窄规则。
  - 失败时返回聚合诊断和最多 `n_cex` 个违规行作为反例，要求 LLM 修订；最多 `R_rev` 轮。
- **多轮发现与合并**：每约束族进行 `R_disc` 轮发现，下一轮要求探索未探索的关系；随后通过去重、规范化、子屋合并、依赖图无环化等家庭特有操作合并约束。默认参数：`(R_disc, n_ctx, n_cex)=(3,100,20)`。

### 2.3 约束执行（后处理）
- 顺序固定为：逻辑依赖 → 方程 → 线性投影。
  - 逻辑依赖修复只改动类别列；对违规行仅替换依赖列的取值，取值从参考条件分布中采样或确定赋值。
  - 方程修复：LLM 为每个方程生成 `fix(df)` 重建目标列；用 KS 互补指导的启发式选择修复目标与顺序，先最大化最差列边际变化，再最大化总变化；修复后冻结参与列。
  - 线性投影：对每个违规行求解约束凸优化，最小化缩放归一化失真 `Σ((z_j - x̂_ij)/s_j)^2`，同时固定方程参与列和零方差列；得到顺序无关的全局最优解。
- 修复后，所有验证器重新检查，保证保留的可用约束零违规。

## 6. 关键结果与消融研究

### 6.1 约束发现基准（行为审计）结果
- 工具化 agent 流程在绝大多数 family–backbone 组合上显著优于一次性直接提示基线，尤其在逻辑依赖和线性不等式上召回率提升明显；方程约束上两者差距相对较小，因为数值恒等式更容易被 LLM 直接表述。
- 反例驱动修订是提升精度的关键：基线常产生“看似合理但实际在完整数据上不成立”的规则，而验证器通过 `VR` 阈值将其拦截，并用具体违规行引导 LLM 修正假设。
- 审计平衡样本上的精确率–召回率权衡可通过 `τ_vio` 与 `τ_sup` 调节；默认参数在多数组合上取得最佳 F1。

### 6.2 端到端约束后处理结果
- **约束满足度**：所有生成器在全部 7 个数据集上，经过后处理后 CVR 与 sCVC 均降至 0（或接近 0），且不随生成器类型变化——验证了后处理的“生成器无关”设计。
- **下游效用**：TSTR 结果显示后处理前后 ROC-AUC / R² 几乎无下降（多数数据集差异在 ±0.01 以内），说明协调修复在消除违规的同时保留了合成数据的任务可用性。
- **边际保真度**：Column Shapes 在多数数据集上基本持平，少数数据集（如 TAXI、FLIGHTS）有轻微下降，主要源于方程修复对参与列的确定性改写；线性投影因采用最小失真优化，对边际影响很小。
- **与现有工作的对比**：论文在可用基线（如直接拒绝采样、独立列投影）上做了对比，协调式后处理在相同约束满足度下引入的分布扭曲显著更小，且能处理拒绝采样无法解决的联合约束冲突。

### 6.3 消融研究
1. **发现超参消融（`n_ctx`、`n_cex`、`R_disc`）**：
   - 增大反例数量 `n_cex` 对逻辑依赖精度提升最明显，因为逻辑依赖的失败模式多样，需要更多反例才能让 LLM 定位错误条件；
   - 上下文样本 `n_ctx` 超过 100 后收益递减，过少（如 20）会显著降低召回；
   - 多轮发现 `R_disc` 从 1 增至 3 能持续提升覆盖，但第 4 轮起收益趋近于零。
2. **方程修复调度消融（NEWS 数据集）**：
   - 比较“先修最差边际列”“按固定列顺序”“随机顺序”等策略；最差列优先启发式在保持边际分布上最优，固定顺序会导致先修列被后续修复过度改写。
3. **数值修复顺序消融（NBA 数据集）**：
   - 验证了“方程 → 线性投影”的固定顺序：若先做线性投影，再修方程，会破坏已收敛的线性可行性；反之则不会，因为线性投影在固定方程参与列的前提下求解，能够兼容已有方程约束。

## 7. 主要贡献与局限性

### 7.1 主要贡献
- 提出了**统一的工具化约束发现框架**，将三类异构约束（方程、线性不等式、逻辑依赖）统一为可执行假设，用全表验证替代 LLM 自评，显著提升规则可靠性与可解释性。
- 提出了**生成器无关的协调后处理管线**，在共享列上以“最小失真”原则联合修复多约束冲突，适用于任意现有合成器输出。
- 构建了**可复用的审计式发现基准**（基于专家标注与隐藏审计集），为后续约束学习研究提供衡量工具。
- 系统性验证了“LLM 发现约束 + 确定性工具执行”的混合范式在端到端合成场景中的有效性。

### 7.2 局限性
- **约束表达范围有限**：仅覆盖方程、线性不等式和逻辑依赖等相对结构化的语义关系；复杂业务规则（如跨表外键完整性、时序窗口约束、涉及外部知识库的约束）尚未纳入。
- **发现阶段依赖 LLM 能力**：虽然验证器能拦截错误假设，但假设的初始覆盖面受 LLM 对领域语义的理解限制；若 LLM 完全未想到某类关键关系，验证器无法弥补。
- **后处理仅修复保留的约束**：若发现阶段遗漏了重要约束（低召回），后处理不会主动发现；误差会从发现阶段级联到执行阶段。
- **逻辑依赖修复的分布偏差**：对类别列的重写采用参考条件分布采样，但未显式建模多列联合条件，极端相关结构下可能引入偏差。
- **评估规模与泛化**：7 个公共数据集虽覆盖多领域，但均来自典型 ML benchmark，未涉及真实企业级数据（含敏感字段、脏数据、超高维）；端到端实验中仅一个 LLM 后端。

## 8. 个人评价与可改进方向

### 8.1 方法论亮点
- **“可执行假设 + 自动验证 + 反例驱动修订”** 的三段式设计具有工程上的实用性，将 LLM 的语义先验与确定性工具的可靠性有机结合，而非单纯依赖模型自我评估。
- **后处理的“协调”视角**（一处修复可能破坏另一约束）是数据约束修复中的关键难点，论文用“固定参与列 + 顺序无关凸投影”给出了干净的解法，理论上有全局最优保证。
- 约束表示采用 **代码/DSL 而非自然语言**，使得验证与修复可在数据规模上高效执行，也便于跨表、跨库扩展。

### 8.2 可改进方向
- 将约束族扩展为**复合约束**（如含函数调用的时序逻辑、集合约束），并支持跨表引用。
- 在逻辑依赖修复中引入**多列联合条件建模**（如使用条件 EBM / 流模型采样），降低分布偏差。
- 探索**主动学习式发现**：用验证器反馈指导 LLM 优先探索高违规潜力的关系区域，提升召回率。
- 在端到端评估中加入更多 LLM 后端、真实生产数据与更多合成器（如基于扩散的表格专用模型、LLM 生成器）以确认泛化性。
- 对“最小失真”目标增加下游任务损失的近似引导，实现**任务感知后处理**，在保持效用的同时进一步压缩分布偏差。

## 9. 总结

本论文针对合成表格数据中的约束违反问题，提出了一套完整的“约束自动发现—验证修订—协调后处理”工作流。其核心创新在于：用 LLM 生成可执行假设、用确定性工具在完整参考表上验证并迭代反例、再用生成器无关的协调后处理以最小失真执行约束。实验表明，该方法能在不显著损失边际分布与下游效用的前提下，将多类语义约束的违规率降至 0，且适用于多种主流合成生成器。尽管在约束族覆盖和评估广度上仍有限制，但该工作为“语义约束感知的表格数据合成”提供了高实用性的统一框架，并为后续研究建立了审计式基准与可复用的工程范式。

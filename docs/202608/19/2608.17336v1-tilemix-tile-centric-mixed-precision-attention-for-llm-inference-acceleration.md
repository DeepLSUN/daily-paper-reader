## 摘要
长上下文预填充在大语言模型中引起大量计算和内存流量，因为密集自注意力计算二次查询键分数。现有方法要么使用统一低精度路径，要么选择令牌交互，将硬件对齐分数瓦片上的空间精度路由排除在融合密集注意力之外。我们介绍TileMix，一个以瓦片为中心的精度路由内核，使数值精度成为融合密集注意力中分数瓦片组上的可执行空间决策。TileMix将注意力矩阵划分为硬件对齐的分数瓦片，将路由决策打包为紧凑位掩码，并通过FP16或INT8分数计算调度每个瓦片组，而两个路径共享在线softmax状态更新。可扩展精度分组让每个路由位管理多个相邻键瓦片，在长上下文中保留硬件对齐计算瓦片和紧凑元数据。通过路由所有合法瓦片组，TileMix保留密集令牌连接，无需训练，并支持分组查询注意力、可变长度批量和INT8键/值缓存。在LongEval、LV-Eval和A100预填充基准上，对LLaMA、Qwen和Vicuna，TileMix恢复了统一INT8下丢失的长上下文质量，并提高了预填充吞吐量相比FP16，跨模型系列产生可控的精度-效率前沿。实现可在https://github.com/HanzhiZhang-Ulrica/TileMix获得。

## Abstract
Long-context prefill in large language models (LLMs) incurs substantial computation and memory traffic because dense self-attention computes quadratic query-key scores. Existing methods either use a uniform low-precision path or select token interactions, leaving spatial precision routing over hardware-aligned score tiles outside fused dense attention. We introduce TileMix, a tile-centric precision-routing kernel that makes numerical precision an executable spatial decision over score-tile groups within fused dense attention. TileMix partitions the attention matrix into hardware-aligned score tiles, packs routing decisions into compact bitmasks, and dispatches each tile group through FP16 or INT8 score computation while both paths update a shared online-softmax state. Scalable precision grouping lets each routing bit govern multiple adjacent key tiles, preserving hardware-aligned compute tiles and compact metadata at long contexts. By routing all legal tile groups, TileMix preserves dense token connectivity, requires no training, and supports grouped-query attention, variable-length batches, and INT8 key/value caches. Across LongEval, LV-Eval, and A100 prefill benchmarks on LLaMA, Qwen, and Vicuna, TileMix recovers long-context quality lost under uniform INT8 and improves prefill throughput over FP16, yielding a controllable accuracy-efficiency frontier across model families. The implementation is available at https://github.com/HanzhiZhang-Ulrica/TileMix.

# TileMix 论文总结

## 1. 核心问题与整体含义

- **研究动机**：大语言模型（LLM）在长上下文预填充（prefill）阶段，密集自注意力需要计算 L×L 的查询-键分数，带来 O(L²) 的计算和内存开销，成为长文档/长上下文推理的关键瓶颈。
- **现有方法的不足**：
  - 低精度量化（如 INT8）通常对整次调用或整个注意力阶段采用**单一算术路径**，缺少对注意力分数矩阵内部不同空间区域的精度差异化调度；
  - 稀疏/块注意力通过**删减 token 交互**降低计算量，但这改变了注意力连通性，可能造成信息丢失；
  - IO-aware 融合注意力（如 FlashAttention）虽以硬件对齐 tile 组织计算，但每个 tile 仍使用统一精度。
- **核心问题**：能否在**保留完整密集注意力图**的前提下，将“数值精度”作为可执行的空间路由决策，在硬件对齐的分数 tile 组上混合使用 FP16 与 INT8，从而同时获得精度和效率？
- **整体含义**：论文提出 **TileMix**，一种以 tile 为中心的混合精度注意力内核，首次将空间精度路由引入融合密集注意力内部，实现无需训练、保持密集连接、支持多种推理场景的可控精度-效率权衡。

## 2. 方法论：核心思想、关键技术与算法流程

### 2.1 核心思想
- 将注意力分数矩阵划分为硬件对齐的二维 tile（BLOCK_M × BLOCK_N），每个 tile 组（key-tile group）通过**二值路由决策**选择 FP16 或 INT8 分数计算路径；
- 两种路径都更新**同一个 online-softmax 状态**（行最大值、归一化因子、输出累加器），从而实现异构精度在单一融合内核中的流式执行；
- 通过**可扩展精度分组**（grouping factor g）使一个路由位控制多个相邻 key tile，在长上下文中保持紧凑元数据和硬件对齐的计算 tile。

### 2.2 关键技术细节

#### （1）Tile 划分与内核结构
- 外层循环遍历 query tile 行 m；
- 内层循环流式加载 key/value tile，根据路由位决定该 tile 的分数计算路径；
- 路由决策通过 **64 位打包位掩码** b_{hk,m} 存储，内层循环用 `((b ≫ g_j) & 1)` 实现**常数时间**路由查找。

#### （2）两种精度路径
- **FP16 路径**：直接计算 Q_m K_n^T / √d。
- **INT8 路径**：
  - 对 Q 和 K 做分块对称 INT8 量化，获得 Q8、K8 及每块缩放因子 δ_Q、δ_K；
  - 使用 INT8 Tensor Core MMA 指令计算 INT8 矩阵乘，以 INT32 累加；
  - 恢复缩放并除以 √d，使结果进入公共 FP16 分数域；
  - V 和 P·V 计算保持 FP16。

#### （3）共享 online-softmax 状态
- 两种路径的分数在进入指数计算前先统一到相同浮点域，再更新同一个行最大值 m̃、归一化因子 z̃ 和未归一化输出累加器 Õ；
- 状态保存在 FP16，但 tile 最大值、指数和行归约使用 FP32 中间量。

#### （4）路由策略与位掩码编码
- 路由映射 R 按 KV 头、query-tile 行、key-tile 组索引；
- 每个 (hk, m) 对打包为一个 64 位整数，元数据规模为 O(H_k · T_m)；
- 分组因子 g 使 BLOCK_mask_N = g·BLOCK_N，T_mask ≤ 64，保证一个路由字覆盖整个 key 序列。
- 支持多种静态路由模板：`align_sparse`、`band`、`bigbird`、`global`、`row_rand`、`sparse_transformer`（SpTrans）、`One`（全 INT8）、`Zero`（全 FP16）。

#### （5）扩展功能
- **GQA**：映射到同一 KV 头的 query 头共享路由字；
- **可变长度批处理**：通过 prefix-sum 元数据实现无填充执行；
- **INT8 KV cache**：decode 阶段可使用缓存的 INT8 K/V 与缩放因子；
- **两种操作模式**：quantize-once（预量化 Q/K，复用）和 fused on-the-fly（仅对 INT8 路由组在片上量化）。

## 6. 主要结论与发现

1. **均匀 INT8 注意力（One）在长上下文任务中质量损失明显**，而 TileMix 混合精度配置通常能显著缩小甚至消除与 FP16 的差距。
2. **路由布局决定精度恢复能力**：例如 row_rand 和 SpTrans 在高 INT8 覆盖率下保持较强准确率，而 align_sparse、band、global 更依赖保守覆盖率。
3. **存在一致的布局-任务交互**：在 factrecall_en 16k 设置下，SpTrans 的准确率远超 FP16（如 LLaMA 3.2 3B 上 FP16 6.72 vs SpTrans75 21.65），且跨模型复现，说明静态空间模板有时能带来意外的任务增益。
4. **预填充吞吐显著提升**：在 LLaMA 3.2 3B 4k 长度下，SpTrans75 达 31.80 K tokens/s，高于 FlashAttention 的 14.33 K tokens/s 和 One 的 29.80 K tokens/s。
5. **数值行为可控**：平均输出偏差随 INT8 覆盖率单调增加，覆盖率可作为数值精度控制旋钮；FP16 与 FP32 累加差异远小于路由精度差异。
6. **重交互保护**：SpTrans 布局下，高重要性 attention 质量被 INT8 路由的比例远低于 nominal 覆盖率（如 SpTrans25 仅约 8.5% 的 heavy-hitter 质量被 INT8 处理），说明静态结构化路由可以隐式保护关键交互。

## 7. 优点

- **方法新颖性强**：首次将 tile-group 精度路由作为融合密集注意力的内核原生抽象，填补了“空间精度调度”在长上下文注意力中的空白。
- **技术设计优雅**：64 位打包位掩码 + 常数时间查找 + 共享 online-softmax，实现简单且高效，元数据复杂度仅 O(H_k·T_m)。
- **保持密集连通性**：与稀疏方法不同，TileMix 不删除任何合法 token 交互，只改变计算精度，因此避免了稀疏导致的不可逆信息丢失。
- **无需训练，部署友好**：支持 GQA、变长批处理、INT8 KV cache，兼容主流推理框架需求。
- **实验体系全面**：跨模型、跨任务、跨长度、多布局、多覆盖率、多基线，并辅以深入的数值分析和内存流量核算，验证充分。
- **显式精度-效率前沿**：通过配置 INT8 覆盖率和布局，可针对不同任务调节精度/吞吐平衡，实用价值高。

## 8. 不足与局限

- **硬件与格式局限**：仅实现并验证了 FP16/INT8 两条 Tensor Core 路径，且仅测试 A100 GPU；FP8/INT4 等其他格式需要额外的尺度处理和内核调度。
- **静态路由策略**：当前路由模板为静态、数据无关的预设结构，不随输入动态调整；虽然可自适应策略接口，但论文未验证在线、内容感知的 routing 策略。
- **上下文长度覆盖有限**：LongEval 最长约 39k–53k，LV-Eval 最长 64k，未覆盖 128k/256k 等更长上下文场景；效率实验仅到 8k prefill。
- **模型规模以 7B 为主**：LLaMA 3.1 8B 和 Qwen 2.5 14B 仅用于数值分析，未在质量和效率基准上评估更大模型（如 30B/70B）。
- **布局-任务交互带来选择偏差风险**：例如 SpTrans 在 factrecall_en 16k 上的异常高分属于任务依赖现象，实际部署时若路由布局与任务不匹配，可能无法获得收益，需要额外调参。
- **缺少 decode 阶段优化验证**：虽然提供 INT8 KV cache 接口，但主要实验聚焦 prefill，decode 的端到端收益未充分展示。
- **与更先进的量化方法对比不足**：仅对比了 SageAttention 和稀疏方法，未与 FP8 注意力、更细粒度 block-wise 量化（如 per-token/per-head 动态选择）进行比较。
- **未明确披露算力总消耗**：无 GPU 数量、运行总时长和能耗数据，影响可重复性和部署成本估算。

## 摘要
相关性是查询依赖的估计，判断文档或片段是否包含有用证据。现有检索智能体利用相关性选择top-$k$内容，但仅靠文档相关性无法定位、组合或验证复杂问题所需的证据。直接语料交互（DCI）通过类似grep的探索实现此类细粒度操作，但其与相关性无关的搜索可能延迟暴露有用线索，导致收敛变慢。近期进展利用相关性将语料缩小为交互工作空间。然而，一旦交互开始，相关性仍无法直接指导grep优先搜索哪些文档，也无法从广泛的匹配中区分信息性片段以供LLM优先查看。我们提出了相关性感知的RipGrep搜索智能体（RARG），它将相关性转化为语料交互的执行先验。RARG提供从粗到细的相关性指导：对文档排序以进行顺序的'ripgrep'遍历，更早地暴露全局相关线索；用查询相关段落初始化有希望的入口点；并对grep匹配结果重排序，以突出文档级排名可能掩盖的信息性片段。在具有挑战性的浏览问答和推理密集型检索中，RARG在准确率-效率边界上优于基于检索和直接交互的智能体。这些结果表明，相关性感知的交互能够实现更快、更可靠的搜索收敛。

## Abstract
Relevance is a query-dependent estimate of whether a document or excerpt contains useful evidence. Existing retrieval agents use relevance to select top-$k$ content, but document relevance alone cannot localize, compose, or verify the evidence required by complex questions. Direct Corpus Interaction (DCI) enables such fine-grained operations through grep-style exploration, but its relevance-agnostic search can expose useful clues late and delay convergence. Recent advances use relevance to narrow the corpus into a working space for interaction. Once interaction begins, however, relevance still does not directly guide which documents grep searches first or distinguish informative excerpts from a broad set of matches to let LLMs see them first. We introduce the Relevance-Aware RipGrep Search Agent (RARG), which turns relevance into an execution prior for corpus interaction. RARG provides coarse-to-fine relevance guidance: it orders documents for sequential 'ripgrep' traversal to expose globally relevant clues earlier, initializes promising entry points with query-relevant paragraphs, and reranks grep matches to surface informative excerpts that document-level ranking may otherwise obscure. Across challenging browse question answering and reasoning-intensive retrieval, RARG improves the accuracy--efficiency frontier over retrieval-based and direct-interaction agents. These results demonstrate that relevance-aware interaction enables faster and more reliable search convergence.

- **问题背景**：在智能体搜索（agentic search）中，相关性（relevance）传统上用于选择 top-k 文档或片段，作为一个有用但不完美的先验。然而，对于复杂问题（如多跳推理、证据组合），文档级相关性无法定位、组合或验证所需证据。即使检索到相关文档，决定性线索也可能被截断或隐藏。
- **现有方法的局限**：
  - **检索增强生成（RAG）**：依赖一次性 top-k 文档，无法细粒度操作。
  - **直接语料交互（DCI）**：允许 grep 式探索，但与相关性无关，导致搜索无目标，收敛慢，随着语料增大成本急剧上升。
  - **混合方法（如 RISE、DR-DCI）**：先用检索缩小工作空间，但相关性并未在后续交互中直接指导 grep 的遍历顺序或可见性。
- **本文动机**：重新定义相关性的角色——不仅用于选择输入，更应作为**语料交互的执行先导**，加速和稳定搜索收敛，提高准确率-效率边界。

## 2. 方法论

### 2.1 核心思想
提出 **RARG（Relevance-Aware RipGrep Search Agent）**，将相关性转化为 grep 探索的执行先验，提供从粗到细的三层指导：
- **文档级相关性（RARG）**：使用嵌入检索模型对文档排序，让 rg（ripgrep）按排序顺序遍历，使全局相关文档的匹配更早暴露。
- **入口点初始化（RARG+）**：在初始嵌入召回时，附上 top-10 查询相关段落，作为智能体的起始探索点，减少低效搜索步骤。
- **匹配级重排序（RARG++）**：对 rg 返回的匹配结果，使用构造的查询（结合 scope query 和 rg 关键字）进行重排序，确保信息性片段在有限的观测预算内优先被 LLM 看到。

### 2.2 关键技术细节
- **嵌入召回工具 (embed_recall)**：LLM 生成查询，检索器返回文档路径并写入 scope 文件，不直接返回内容。LLM 通过 `cat scope.txt | xargs -d '\n' rg -j1 "PATTERN"` 按顺序扫描文档（强制单线程保持顺序）。
- **文档级排序**：scope 文件包含 top-10,000 文档路径，rg 按此顺序输出匹配行。
- **入口点初始化**：对 top-10 文档分段落（400-1000 字符），用嵌入模型评分，取 top-10 段落以 `<qr_paragraph>` 标签附加到 embed_recall 输出中。
- **匹配级重排序**：当 rg 输出匹配超过 m 条时，使用构造查询（scope query + rg 关键字）对最多 M=500 条匹配重排序，保留 top m（BC+ 取 30，BRIGHT 取 60）。
- **上下文管理**：采用 DCI-Agent-Lite 的 Level-3 压缩，保留最近 40 个工具结果，触发阈值为 230K 字符。

## 6. 主要结论与发现

1. **RARG 显著提升准确率-效率前沿**：在 BC+ 上，RARG++ 达到 84%（mini）/79%（nano）/91%（GPT-5.4），最高超出基线 9 个百分点，同时工具调用次数低于 DCI 和 RISE。
2. **粗到细的指导有效**：从 RARG 到 RARG+ 到 RARG++，准确率逐步提升，工具调用逐步减少，验证了三层机制。
3. **语料扩展下保持优势**：1M 语料时 RARG++ 准确率 79%，远超 RISE-BM25（69%），但下降幅度表明长噪声文档对局部匹配仍有干扰。
4. **在推理密集型检索上也优于专用代理**：BRIGHT 上 RARG+ 平均 nDCG@10 达 53.36，超过 NeMo（52.89），但最佳变体因任务而非固定（RARG+ 优于 RARG++，因为广度召回更重要）。
5. **相关性指导效果可视化**：命中分布显示 RARG 保持前载，RARG++ 从低排名文档中恢复更多有效匹配。

## 7. 优点

- **概念创新**：将相关性从内容选择器转变为执行先导，填补了 DCI 缺乏全局线索的空白。

## 8. 不足与局限

1. **依赖嵌入模型质量**：文档级和匹配级排序使用不同模型（Q3E、NV），对短文本匹配质量要求高，BRIGHT 上需切换模型。
2. **指令遵循敏感**：GPT-5.4-nano 对复杂协议执行较差，导致嵌入召回次数偏高，效果波动。
3. **生成式重排序变体失败**：由于训练-推理差距，LLM 生成的重排序查询反而降低了准确率（75% vs 84%），需进一步研究。
4. **语料噪声干扰**：长噪声文档导致局部匹配过多，匹配级重排序只能部分缓解，1M 语料时性能下降仍较明显。
5. **实验域有限**：仅在 GPT-5.x 上验证，未测试其他 LLM 或开放网络；仅覆盖 100 个 BC+ 查询和 423 个 BRIGHT 问题，规模有待扩大。
6. **实现开销**：单线程 `rg -j1` 和重排序增加了延迟，作者承认性能-时间权衡；未与任意顺序后排序的实现做对比。

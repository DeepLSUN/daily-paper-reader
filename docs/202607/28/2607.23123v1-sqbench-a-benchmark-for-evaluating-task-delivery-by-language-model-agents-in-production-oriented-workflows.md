## 摘要
现有的大语言模型评估覆盖知识、推理、编码和工具使用，但很少将受约束工作流内可验证的交付物作为评估单元。我们提出SQBench，一个用于评估语言模型代理面向生产任务交付的基准。SQBench v1.0包含220个标准化任务，分为L1原子能力、L2复合技能和L3业务场景。每个任务要求代理处理输入资产、使用可用工具并产生明确指定的交付物。评估首先计算功能性完成度，然后从10维风险矩阵中独立证据触发项推导出风险惩罚和性能。严格通过要求完成度=1且风险惩罚=0。我们在统一协议下评估27个模型配置，每个配置-任务对仅运行一次。最高预设加权通过@1为60.5%。L3平均严格通过@1为18.5%，所有配置在L3上的表现均差于L1和L2，表明领域约束下的交付能力是当前任务集共有的弱点。在2,348个完成度=1的结果中，113个（4.8%）因不可验证引用、资源使用不当或格式违规等风险而未能通过严格标准。这些结果表明，仅凭功能完成度无法完全表征交付质量，且风险判断应单独报告。

## Abstract
Existing evaluations of large language models cover knowledge, reasoning, coding, and tool use, but they rarely treat a verifiable deliverable produced within a constrained workflow as the unit of evaluation. We introduce SQBench, a benchmark for evaluating production-oriented task delivery by language-model agents. SQBench v1.0 contains 220 standardized tasks organized into L1 atomic capabilities, L2 composite skills, and L3 business scenarios. Each task requires an agent to process input assets, use available tools, and produce an explicitly specified deliverable. The evaluation first computes functional Completion and then derives Risk Penalty and Performance from independently evidenced triggers in a 10D Risk Matrix. A Strict Pass requires Completion = 1 and Risk Penalty = 0. We evaluate 27 model configurations under a common protocol, with one run per configuration-task pair. The highest prespecified Weighted Pass@1 is 60.5%. Mean Strict Pass@1 on L3 is 18.5%, and every configuration performs worse on L3 than on both L1 and L2, indicating that delivery under domain constraints is a shared weakness within the current task set. Of 2,348 results with Completion = 1, 113 (4.8%) fail the Strict Pass criterion because of risks such as unverifiable citations, inappropriate resource use, or format violations. These results show that functional completion alone does not fully characterize delivery quality and that risk determinations should be reported separately.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：现有大语言模型评估（如MMLU、BIG-bench、GAIA、AgentBench、SWE-bench等）主要关注知识、推理、编码、工具使用或环境交互，但都未将“在受约束工作流中产生可验证交付物”作为独立评估单元。在实际生产中，仅产生正确答案是不够的，代理还必须处理源材料、遵守格式和权限约束、生成下游可消费的工件、并保留可审计的证据。一个局部正确的答案可能因缺失文件、输出不可解析、工具状态误读或声称无法溯源而无法使用。
- **整体含义**：SQBench旨在将“生产导向的任务交付能力”定义为一种独立的评估对象，通过标准化任务、可控执行环境、显式交付物和预定义风险规则，记录功能完成度、风险证据和严格通过决策之间的关系。这与现有基准互补而非替代。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：将知识工作转化为可执行、可评分、可比较的任务实例。每个任务要求代理在单次运行中处理提供的材料、遵守任务约束、提交指定交付物。评估分为两步：首先计算功能完成度（Completion），然后基于独立证据识别10维风险矩阵中的触发项，计算风险惩罚（Risk Penalty），进而得到性能（Performance = max(0, Completion - Risk Penalty)）。严格通过（Strict Pass）要求 Completion=1 且 Risk Penalty=0。
- **任务构造**：从常见办公、数据分析、研究、软件工程和领域工作流程中提取目标、材料、约束和交付物要求。输入经过匿名化、合成或重构。每个任务实例定义初始状态、可用工具、网络和资源边界、交付路径和评估要求。
- **三层任务分类**：
  - L1（原子能力）：指令遵循、长上下文推理、动态代码逻辑、鲁棒性与边界处理。
  - L2（复合技能）：办公协作、数据处理与分析、深度研究、软件工程。需规划、文件操作、工具使用、中间验证和工件创建。
  - L3（业务场景）：金融、工业、医疗、公共管理。强调领域材料、业务规则、数据验证、合规边界和可审计输出。
- **10D风险矩阵**：包含10个维度（D1-D10），每个维度有预定义惩罚值（0.2~1.0）。例如：D1事实与来源幻觉（惩罚0.8）、D2格式与指令违规（0.4）、D3合规与安全越权（1.0）、D4低效与资源滥用（0.3）、D5工具状态幻觉与错误处理（0.5）、D6过早终止与目标遗忘（0.6）、D7认知边界与升级失败（0.6）、D8奉承与欺骗（1.0）、D9过程不透明（0.2）、D10上下文污染与状态混淆（0.5）。一个结果可触发多个维度，惩罚求和，Performance截断至0。
- **评估指标**：
  - Weighted Pass@1 = 0.2×L1 Pass@1 + 0.6×L2 Pass@1 + 0.2×L3 Pass@1（主要排名指标）
  - Simple Pass@1：所有220个任务等权重的严格通过率
  - 层内Pass@1、行业Pass@1等
- **评分模式**：根据交付物要求的可验证性决定。确定性要求（结构化输出、数值计算、代码执行、文件状态）使用自动检查；语义质量要求（报告质量、研究分析、论证完整性）使用LLM评判器（modelstudio/qwen3.5-122b-a10b，温度0，最多4次重试）结合预定义评分规则。113个任务完全自动评分，107个包含LLM评判组件。

## 6. 主要结论与发现

- **主要结果**：最高加权通过@1为60.5%（Kimi K3），简单通过@1为54.5%。Claude Opus 4.8 (Max)排名第二（57.6%）。即使最高配置也在近一半任务上未能满足“Completion=1且Risk Penalty=0”的严格通过标准。
- **L3是共同弱点**：平均严格通过@1：L1 39.8%，L2 53.1%，L3 18.5%。所有配置在L3上表现均差于L1和L2。L3最高结果为GLM-5.2 (Max)的28.3%。
- **功能完成不等于严格通过**：在2,348个Completion=1的结果中，113个（4.8%）因风险惩罚不为0而未能严格通过。该差异集中出现在L2（96个，占L2中Completion=1结果的10.0%）。最常见的风险维度是D4（资源滥用，92次）、D10（上下文污染，8次）、D2（格式违规，6次）、D1（来源幻觉，5次）、D7（认知边界，2次）。
- **总计触发频率**：在所有结果中，至少触发一个风险的比率：L1 3.9%，L2 22.2%，L3 21.0%。最常触发的维度：D4（215次）、D1（190次）、D6（142次）、D2（133次）、D9（124次）。
- **L3行业表现**：金融13.8%，工业17.8%，医疗20.7%，公共管理21.7%。所有行业均未超过22%。按任务类型：定量审计10.7%，复杂业务20.2%，合规与风险控制24.6%。
- **风险调整效应**：所有配置的Performance均低于Completion，差距平均7.5个百分点（范围4.2~11.3）。仅报告Completion会遗漏风险测量的影响。

## 7. 优点

- **定义清晰**：将“生产导向任务交付”概念可操作化，以可验证交付物为评估单元，区别于仅评估答案正确性或环境状态。
- **分层分类合理**：L1诊断基础执行，L2评估复合工作流，L3引入领域约束，能够揭示不同层级的性能差异。
- **风险矩阵设计新颖**：10D风险矩阵独立于功能完成度进行证据检测，使得功能成功但风险高的案例可被单独分析，提升了评估深度和可审计性。
- **评估流程系统化**：从任务定义、执行条件、自动/评判评分到风险触发、严格通过决策，形成完整流水线，支持标准化复现。
- **数据公开与透明**：论文承诺公开固定版本的部分聚合数据、验证代码和示例，同时为减少泄露保留隐藏任务集（用于在线排行榜），平衡了可复现性与抗污染。
- **提及多重局限并主动讨论**：论文明确讨论LLM评判器偏见、单次运行、未冻结内容、未经校准风险惩罚等限制，体现了研究诚实性。

## 8. 不足与局限

- **覆盖面有限**：仅220个任务、四个行业，不能代表所有组织过程或职业分布。L3任务仅为工作模式的抽象，而非统计代表性样本。

- **风险矩阵未经校准**：10个维度和惩罚值是设计选择，未通过外部事件发生率、相对严重性或优化惩罚幅度进行实证校准。

- **实验环境版本控制不充分**：未存档不可变源修订版、上游服务器版本或每请求路由信息，因此不支持精确复现每个执行细节。
- **权重敏感性存在**：虽然主要排名稳定，但中间排名顺序对聚合权重敏感，不宜过度解读排序。

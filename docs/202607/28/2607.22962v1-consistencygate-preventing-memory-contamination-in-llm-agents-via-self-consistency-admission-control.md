## 摘要
在多轮交互中运行的LLM代理会将事实累积存储在外部记忆库中，并在后续推理中将其用作前提。因此，在某一步骤中产生的幻觉事实会作为错误前提持续影响后续所有步骤，这种失效模式称为记忆污染。现有记忆管理方法关注检索与容量问题，但未解决写入时的正确性问题；基于效用或近因的准则无法解决这一准入问题，且不受控的污染会在长轨迹中持续累积。我们提出 ConsistencyGate，一种写入时准入门控机制：在将从上下文c中提取的候选事实m提交前，通过向LLM查询K次获取软支持分数，仅当平均分超过阈值时才准入m。该机制与模型无关，无需微调，并可通过对数概率变体简化为单次前向传播，适用于延迟敏感场景。为衡量对自然数据的影响，我们在LoCoMo和MSC的长程对话中植入受控的单细节干扰，构建了两个真实对话基准（LoCoMo-Contam和MSC-Contam），并补充了结构化合成语料库（MemContam），以隔离近乎最优的理论上界。在四个LLM骨干网络上，ConsistencyGate相比“全部写入”基线减少了所有基准上的污染，其代价集中在源上下文中仅隐式陈述的事实上。我们发布了全部三个基准及门控实现。

## Abstract
LLM agents that operate over many turns accumulate facts in an external memory store and reuse them as premises for downstream reasoning. A hallucinated fact written at one step therefore persists as a false premise for every subsequent step, a failure mode we call memory contamination. Existing memory management addresses retrieval and capacity but not write-time correctness; this admission problem cannot be solved by utility- or recency-based criteria, and uncontrolled contamination compounds across long trajectories. We propose ConsistencyGate, a write-time admission gate that, before committing a candidate fact m extracted from context c, queries the LLM K times for a soft support score and admits m only when the average exceeds a threshold. The mechanism is model-agnostic, requires no fine-tuning, and reduces to a single forward pass in a log-probability variant for latency-sensitive deployments. To measure the effect on natural data, we construct two real-conversation benchmarks (LoCoMo-Contam and MSC-Contam) by planting controlled single-detail corruptions in long-term conversations from LoCoMo and MSC, and complement them with a structured synthetic corpus (MemContam) that isolates a near-oracle upper bound. Across four LLM backbones, ConsistencyGate reduces contamination on every benchmark relative to a write-everything baseline, with the cost concentrated on facts that are stated only implicitly in the source context. We release all three benchmarks together with the gate implementation.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：长期运行的LLM代理（如对话系统、任务型智能体）会将事实存储在外部记忆库中，并在后续推理中复用。当代理在某一轮写入一个幻觉（hallucinated）事实后，该错误会作为错误前提持续影响后续所有推理步骤，这种失效模式被定义为**记忆污染**（memory contamination）。
- **问题根源**：现有记忆管理方法主要关注**检索**（如何召回相关记忆）和**容量**（如何淘汰旧事实），但未在**写入时**验证事实的正确性。基于效用、新颖性或近因的准入准则对幻觉事实“结构性失明”，因为幻觉事实与正确事实在这些维度上几乎无差异。
- **研究意义**：记忆污染问题独立于检索和容量问题，是一个尚未被充分研究的写入时准入问题。作者指出，幻觉事实一旦写入，即使使用最优检索器也会被召回，且污染会随交互轨迹长度而级联放大。因此，**正确性**必须成为记忆准入的独立准则。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：利用**自一致性**（self-consistency）作为写入时的事实验证信号——通过多次查询LLM，获取候选事实相对于源上下文的平均支持分数，仅当分数超过阈值时才准入记忆。
- **关键技术细节**：
  - **ConsistencyGate 算法**：
    - 输入：候选事实m，源上下文c，LLM L，采样次数K，阈值τ，记忆库M（容量C）。
    - 对k=1到K：生成软验证提示（SoftVerifyPrompt），调用LLM得到支持分数s_k ∈ [0,1]（1=完全支持，0=矛盾）。
    - 计算平均支持分数：**p̂ = (1/K) Σ s_k**。
    - 准入决策：仅当p̂ ≥ τ时，将m加入M。
  - **默认配置**：K=5，τ=0.7（固定阈值）。作者通过消融实验推荐此设置。
  - **高效单次前馈变体（LogProb）**：使用二元yes/no提示，通过单次前向传播读取token级别对数概率，计算softmax得到"yes"概率作为分数。速度提升12-14倍（23-28ms vs 264-363ms），但仅适用于结构化清晰上下文。
  - **自适应阈值**：当无法调参时，阈值随记忆占用率线性增长：τ* = τ_min + (τ_max - τ_min)·|M|/C，默认τ_min=0.4, τ_max=0.8。固定阈值0.7通常优于自适应版本。
- **算法流程**：见Algorithm 1（伪代码），核心是循环K次采样、计算平均分、与阈值比较并决定是否准入。

- **ConsistencyGate有效减少记忆污染**：在所有基准和4种骨干上，污染率均低于WriteAll基线；在合成MemContam上接近理论最优（污染率1.2%，召回100%）。
- **真实对话场景下污染降低31.8%和26.6%**（LoCoMo-Contam和MSC-Contam上Qwen2.5-32B），准入精度提升0.159和0.133点。
- **污染级联效应**：写时错误随交互轮次累积，ConsistencyGate通过持续过滤使污染率随轮次下降（图2），而WriteAll的污染率保持恒定。
- **模型无关且无需微调**：四个不同大小和架构的LLM（32B到70B）均能受益，但验证器能力差异是性能差异的主要因素（Llama-3.3-70B最优，Llama4-Scout最弱）。
- **LogProb变体适用于结构化上下文**：在MemContam上达到完美精度且快12-14倍；但在长篇对话语境下不如软评分，因为二元假设不成立。
- **推荐配置**：固定τ=0.7, K=5；自适应阈值作为免调参回退方案。
- **代价**：对隐式分布事实（LoCoMo-Contam）召回仅0.58，即42%的正确事实被错误拒绝，这是主要操作成本。

  - **无法替代事实核查**：一致性仅是与源上下文的内部一致，若源上下文本身有误，门控无法防御。
  - **资源需求**：需要持续LLM推理调用，对能源和成本有影响。

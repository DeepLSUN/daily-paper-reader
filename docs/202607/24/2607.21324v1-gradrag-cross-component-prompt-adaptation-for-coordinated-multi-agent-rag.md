## 摘要
检索增强生成（RAG）系统越来越多地采用多个LLM智能体。然而，大多数先前的工作孤立地优化各组件，而不是跨流水线协调改进。我们提出GRADRAG，一个跨组件提示自适应框架，将RAG流水线建模为计算图，并传播结构化评估反馈以更新上游智能体。评估器对下游答案和支持证据进行评判，产生可操作的反馈，提示优化器利用这些反馈迭代更新自适应智能体，如检索器、图构建器和回答器。评估器还在输出被认为满意时触发提前停止。我们在SQUALITY和QMSUM基准上，在两种检索范式下评估GRADRAG：基于扁平块的检索（使用IRCoT风格查询细化）和基于图的检索（从文档构建并迭代丰富实体-关系图）。在这两种设置下，GRADRAG始终优于仅更新最终生成器的一步细化基线，在LLM评判的成对比较中实现了12-15个百分点的净偏好裕度，且大多数增益在两个细化迭代内实现。

## Abstract
Retrieval-Augmented Generation (RAG) systems increasingly employ multiple LLM agents. Yet, most prior work optimizes components in isolation rather than coordinating improvements across the pipeline. We introduce GRADRAG, a framework for cross-component prompt adaptation that models the RAG pipeline as a computational graph and propagates structured evaluation feedback to update upstream agents. An Evaluator critiques downstream answers and supporting evidence, producing actionable feedback that a Prompt Optimizer uses to iteratively update adaptive agents, such as retrievers, graph constructors, and answerers. The Evaluator also triggers early stopping when the output is deemed satisfactory. We evaluate GRADRAG on the SQUALITY and QMSUM benchmarks under two retrieval paradigms: flat chunk-based retrieval using IRCoT-style query refinement (Trivedi et al., 2023), and graph-based retrieval that constructs and iteratively enriches an entity-relation graph from the document. Across both settings, GRADRAG consistently outperforms one-step refinement baselines that update only the final generator, achieving a 12-15 percentage point net preference margin in LLM-judged pairwise comparisons, with most gains realized within two refinement iterations.

# GRADRAG 论文详细中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：现有检索增强生成（RAG）系统虽然采用多个 LLM 智能体（如检索器、图构建器、回答器），但各组件通常被**独立优化**，缺乏跨流水线的协调机制。错误从上游（检索、证据构造）向下游传播，而最终生成阶段的评估信号很少被用于改进上游组件，导致整体性能受限。
- **研究背景**：早期 RAG 为简单的“检索-生成”流程，近期演化出多智能体架构，包括查询改写、证据过滤、自我反思等。但现有工作（如 Self-RAG、Adaptive-RAG、RAG-Star）多将反馈局部应用于单个阶段（如答案重写），未实现真正的跨组件协调。
- **整体含义**：GRADRAG 提出一种**跨组件提示自适应**框架，将 RAG 流水线视为计算图，让下游评估反馈传播到上游多个智能体（检索器、图提取器、回答器），实现测试时的协调优化，显著提升答案质量。

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：将 RAG 流水线建模为**计算图**，节点为 LLM 智能体或数据工件，边为计算转换；通过**评估器**（Evaluator）对生成的答案及支持证据给出结构化反馈，再由**提示优化器**（Prompt Optimizer）将反馈转化为提示更新，应用于多个上游自适应智能体。整个过程通过提示更新实现，不修改模型参数。
- **关键技术细节**：
  - **计算图抽象**：智能体节点关联提示，分为固定提示和自适应提示。自适应智能体的提示可在迭代循环中更新。
  - **评估器**：分析答案与证据，识别缺失信息、薄弱推理环节或无关上下文，输出结构化反馈和二元停止决策（SATISFACTORY / NEEDS_REFINEMENT）。无参考答案，防止数据泄露。
  - **提示优化器**：基于评估反馈，为每个自适应智能体生成新的提示指令。例如，对于检索智能体，反馈可引导生成更针对性的子查询；对于图提取智能体，可引导提取缺失的实体/关系类型。
  - **早停机制**：当评估器判定输出满意时终止迭代，避免无谓计算。
- **算法流程（文本描述）**：
  1. 初始化所有智能体提示。
  2. 对于每个测试实例，迭代最多 T 次：
     - **前向传递**：使用当前提示执行 RAG 流程，生成中间结果（检索块或实体-关系图）和最终答案。
     - **评估**：评估器审查答案及支持证据，返回反馈 `f_t` 和决策 `d_t`。
     - **若 `d_t` = 满意**：返回当前答案，终止。
     - **否则**：对于每个自适应智能体 `a`，用优化器更新其提示 `p_a ← Optimize(p_a, f_t)`。
  3. 达到最大迭代次数后返回最终答案。
- **两种检索范式**：
  - **Vector RAG（扁平/块检索）**：文档分割为重叠文本块，检索智能体以 IRCoT 风格生成子查询，混合稠密检索（FAISS）和词汇匹配（BM25），检索块聚合为上下文。
  - **GraphRAG（图检索）**：文档分割为较大跨度，图提取智能体识别实体和关系，构建图并进行社区检测，生成社区摘要和候选答案，选取正分数项作为证据上下文。两个范式中的自适应智能体不同：Vector RAG 中检索智能体和回答智能体可更新；GraphRAG 中图提取智能体和回答智能体可更新。

- **基准（Benchmark）**：两个数据集均属于 ZeroSCROLLS 和 LongBench 基准。

    - **完整 GRADRAG 变体**：评估反馈传播到多个上游智能体。例如 Full GRADRAG Vector、Full GRADRAG Graph。

- **最大迭代次数**：3 次。
- **模型**：
  - 生成智能体（检索器、图提取器、回答器）使用 **Gemini-2.5-Flash**（2025年6月版本）。
  - 重复性子任务（子查询生成、实体-关系提取、社区摘要等）使用 **Gemini-2.5-Flash-Lite**（2025年7月版本）。

- **评估指标**：

  - 鲁棒性诊断：位置一致性（反转顺序后偏好不变的比例）、二项符号检验 p 值。

## 6. 主要结论与发现

- GRADRAG 在两个数据集、两种检索范式下**一致优于**一步细化基线，赢率在 55%~57.5% 之间，对应 **12-15 个百分点净偏好裕度**（相对于基线约 44% 偏好）。
- 三个比较在 p<0.05 显著，扁平检索 QMSUM 边际显著（p=0.09），但增加一次迭代后显著（p<0.01）。
- **多数收益在两次细化迭代内实现**：早停平均迭代次数约 1.6-1.9，固定迭代分析显示赢率从第二次到第三次迭代有所增长，但部分细微下降（GraphRAG on QMSUM）。
- 系统回答随迭代而改善：长度先增加后稳定，词汇密度上升，ROUGE-1单调上升，主题熵下降（更聚焦）。
- 人工验证表明 LLM 评判与人类偏好具有良好一致性（75.86% 准确率，κ=0.59），支撑了自动评估的可信度。

## 7. 优点

- **首次提出跨组件提示自适应**：解决多智能体 RAG 系统中协调优化的缺失问题，允许下游反馈系统性地改善上游检索和证据构造。
- **计算图抽象**：灵活，可适应不同检索范式（扁平与图结构），并允许异构组件（经典检索器与 LLM 智能体）共存。
- **早停机制**：减少不必要计算，平衡细化收益与过优化风险。
- **受控消融实验**：每个检索范式内严格对比，隔离跨组件适配效果，消除架构差异影响。
- **评估鲁棒性**：采用位置一致性、符号检验，并进行人工验证，提升结论可靠性。
- **模块化实现**：基于 AutoGen 框架，提示公开（附录），可复现。
- **性能提升显著且高效**：仅需 1-2 轮迭代即可收获多数增益，计算代价增加仅约 10%。

## 8. 不足与局限

- **计算成本**：测试时迭代增加了 LLM 调用（至少为前向 + 评估 + 优化），在部署场景中可能不可忽略。Token 使用增量约 35%，运行时间增加约 10%，但面向大规模批量时需优化。
- **评估与部署之间存在差距**：当前协议为每个测试实例独立优化，不跨实例共享信息。而现有自动提示优化方法（如 DSPy）从多个示例推导最优提示，GRADRAG 的逐一优化方式更昂贵且可能不利用跨实例模式。
- **评估器配置**：评估器仅基于通用原则（连贯性、事实性）评判，无外部奖励信号。虽然避免了数据泄漏，但自我评判的准确性有限。未来可集成奖励模型或启发式指标增强。
- **数据集限制**：所使用的 SQUALITY 和 QMSUM 文档可完全置于现代 LLM 上下文窗口内，作者明确说明不旨在比较 RAG 与全上下文推理，而是作为受控测试床。因此结论向更长文档或开放域场景的泛化性未验证。
- **模型依赖**：所有实验使用 Gemini-2.5-Flash 系列和 DeepSeek-V3.1，其他模型上的表现未知。
- **迭代上限**：最大迭代次数固定为 3，虽通过早停部分克服，但更复杂场景可能需要更多轮。
- **人工验证规模**：仅子集标注，未给出具体样例数量，且人类标注者之间存在中等变异性（注释熵 0.642），表明部分困难案例上的一致率可能波动。

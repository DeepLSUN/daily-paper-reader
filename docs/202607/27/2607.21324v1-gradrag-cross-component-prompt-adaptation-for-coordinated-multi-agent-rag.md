## 摘要
检索增强生成系统越来越多地采用多个大语言模型智能体。然而，大多数现有工作孤立地优化各个组件，而非协调整个流水线的改进。我们提出GRADRAG，一种跨组件提示自适应框架，将RAG流水线建模为计算图，并传播结构化评估反馈以更新上游智能体。评估器对下游答案及支撑证据进行评判，生成可操作的反馈，提示优化器利用该反馈迭代更新自适应智能体（如检索器、图构建器和回答器）。评估器在输出被认为满意时还会触发提前停止。我们在SQUALITY和QMSUM基准上，在两种检索范式下评估GRADRAG：基于扁平分块的检索（使用IRCoT风格的查询优化，Trivedi等人，2023）以及基于图的检索（从文档构建并迭代丰富实体关系图）。在两种设置中，GRADRAG均一致优于仅更新最终生成器的单步优化基线，在大语言模型评判的成对比较中实现12-15个百分点的净偏好优势，且大部分增益在两个优化迭代内实现。

## Abstract
Retrieval-Augmented Generation (RAG) systems increasingly employ multiple LLM agents. Yet, most prior work optimizes components in isolation rather than coordinating improvements across the pipeline. We introduce GRADRAG, a framework for cross-component prompt adaptation that models the RAG pipeline as a computational graph and propagates structured evaluation feedback to update upstream agents. An Evaluator critiques downstream answers and supporting evidence, producing actionable feedback that a Prompt Optimizer uses to iteratively update adaptive agents, such as retrievers, graph constructors, and answerers. The Evaluator also triggers early stopping when the output is deemed satisfactory. We evaluate GRADRAG on the SQUALITY and QMSUM benchmarks under two retrieval paradigms: flat chunk-based retrieval using IRCoT-style query refinement (Trivedi et al., 2023), and graph-based retrieval that constructs and iteratively enriches an entity-relation graph from the document. Across both settings, GRADRAG consistently outperforms one-step refinement baselines that update only the final generator, achieving a 12-15 percentage point net preference margin in LLM-judged pairwise comparisons, with most gains realized within two refinement iterations.

# 论文详细总结：GRADRAG

## 1. 核心问题与整体含义（研究动机与背景）

- **问题**：现有 Retrieval-Augmented Generation (RAG) 系统虽然已演进到多智能体（multi-agent）架构，但各组件（如检索器、图构建器、答案生成器）通常被孤立优化，缺乏跨组件的协调机制。早期引入的错误（如检索不完整、证据结构不佳）会向下游传播，限制整体性能。
- **动机**：作者旨在解决多智能体 RAG 中的“协调问题”（coordination problem），让最终生成阶段产生的评估信号能够反哺上游组件（检索器、图构建器），从而通过跨组件提示自适应实现协同改进。

## 2. 方法论

- **核心思想**：将 RAG 流水线建模为一个**计算图**，其中节点对应智能体（可固定或自适应），边对应计算变换；通过**评估器**（Evaluator）对下游答案与支撑证据进行结构化批评，生成可操作反馈，再由**提示优化器**（Prompt Optimizer）将该反馈转化为对上游自适应智能体提示的更新，从而在测试时实现跨组件协调优化。
- **关键技术细节**：
  - **计算图抽象**：允许异构组件（如经典检索器与 LLM 智能体）共存。自适应智能体的提示可在每次优化循环中被更新。
  - **交叉组件提示适应**：不同于仅更新最终生成器的单步反思（one-step refinement），GRADRAG 允许反馈同时更新检索器、图构造器等上游智能体的提示。
  - **提前停止**：评估器在每次评估后返回二元决策（满意/需优化），若满意则终止循环，避免不必要的迭代。
  - **两种检索范式具体实现**：
    - **扁平（Flat/Vector）RAG**：采用 IRCoT 风格的迭代子查询生成，结合稠密（FAISS）与词法（BM25）混合检索。检索智能体提示可随反馈调整，以生成更具针对性的子查询。
    - **基于图的 RAG（GraphRAG）**：先由图提取智能体从文档中识别实体与关系，构建实体-关系图，再通过社区检测生成社区摘要与候选答案。图提取智能体提示可根据反馈调整，引导富集缺失实体/关系类型，形成任务导向的本体。
  - **流程**（算法 1）：
    1. 前向执行当前提示下的 RAG 流水线，生成答案与支撑证据。
    2. 评估器检查答案与证据，输出反馈 \( f_t \) 与决策 \( d_t \)。
    3. 若 \( d_t = \text{SATISFACTORY} \)，接受答案并结束；否则，提示优化器根据 \( f_t \) 更新每个自适应智能体的提示，重复上述步骤（最多 T 次迭代）。

## 3. 实验设计

- **任务**：查询导向摘要（Query-Focused Summarization, QFS）。
- **数据集**：
  - **SQUALITY**：52 篇文档，260 个问题，平均文档长度 4,995 词，答案长度 241 词。
  - **QMSUM**：35 篇会议记录，281 个问题，平均文档长度 10,668 词，答案长度 65 词。
- **基准（Benchmark）**：两个数据集均为 ZeroSCROLLS 和 LongBench 的子集，用作受控测试床，重点分析不同 RAG 管道行为及组件协调改进。
- **对比方法**：
  - **扁平检索体系**：
    - IRCoT + One-Step Refinement（基线）：仅答案生成器智能体为自适应，检索器提示固定。
    - Full GRADRAG Vector：检索器与答案生成器均自适应。
  - **图检索体系**：
    - GraphRAG + One-Step Refinement（基线）：仅答案生成器自适应，图提取提示固定。
    - Full GRADRAG Graph：图提取与答案生成器均自适应。
  - 每个体系内，基线与完整变体共享相同架构、模型和检索过程，仅是否传播反馈到上游组件不同，构成受控消融。
- **评估指标**：采用 LLM-as-a-Judge 成对比较，外部 LLM（DeepSeek-V3.1）基于标准答案判定哪方输出更好，报告胜率（win rate）、位置一致性（position consistency）及二项符号检验 p 值。另有人工验证子集（75.86% 一致性，Cohen’s κ=0.59）。

## 6. 主要结论与发现

1. **跨组件提示适应一致优于单步优化**：完整 GRADRAG 在扁平与图检索两种范式下均优于仅更新最终生成器的基线，LLM 评判的胜率为 55%-57%，净偏好优势达 12-15 个百分点。
2. **多数增益在头两次迭代内实现**：提前停止平均发生在 1.6-1.8 轮，表明快速收敛。
3. **响应演化趋势**：迭代中答案长度先增后稳，词汇密度持续上升，ROUGE-1 单调提升，主题熵下降，表明细化主要提高信息密度与主题聚焦，而非简单添加内容。
4. **早期停止有效平衡精度与过拟合**：固定迭代次数实验显示，图检索在 QMSUM 上第三轮胜率略降，暗示结构化检索可能从提前停止中获益。

## 7. 优点

- **通用框架**：将 RAG 管道抽象为计算图，适用于多种检索范式（扁平与图），且兼容不同类型智能体（LLM 驱动与经典算法）。
- **受控消融**：实验设计清晰，直接对比“是否传播反馈到上游”，严格隔离跨组件适应的效果。
- **自动化优化**：整个提示更新过程无需人工干预，完全由评估器与优化器驱动。
- **评估可靠性**：采用 LLM 评判+位置一致性+统计检验+人工验证多维度保证评估可信度。
- **模块化与可扩展性**：可加入更多自适应智能体，未来可扩展到批量或连续反馈设置。

## 8. 不足与局限

- **计算开销**：迭代过程中多次调用 LLM（前向+评估+优化），成本显著高于单次推理（约增 10% 时间，30% token）。虽然可预测，但对高频或延迟敏感场景可能不友好。
- **评估与部署差距**：实验设置为每查询独立重置优化，不模拟批量部署；且评估器仅基于通用摘要原则（无外部奖励信号）给出反馈，可能受模型自身偏见影响。
- **任务范围有限**：仅在查询导向摘要（QFS）的两个数据集上验证，未覆盖其他 RAG 任务（如开放域 QA、事实验证等），泛化性待进一步确认。
- **评估器配置单一**：未尝试集成奖励模型或启发式指标作为额外监督信号，反馈质量完全依赖单一 LLM 的自我评判能力。
- **提前停止机制依赖内置评判**：若评估器本身产生错误判断（如过早满意或过度挑剔），可能损害最终性能，实验未深入分析此类失败案例。

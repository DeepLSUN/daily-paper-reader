## 摘要
近期大语言模型的进展及其在软件工程任务中的快速采用，使得人工智能（AI）代码代理成为现代软件开发工作流程的重要组成部分。尽管开发者越来越受益于这些代码代理，但它们对软件质量的影响仍未被充分理解。特别是，代理贡献在软件开发生命周期中的演变尚未得到深入研究。本研究旨在比较代理拉取请求（PR）与人类生成的PR，并考察它们在开发生命周期不同阶段中属性的变化。利用AIDev数据集，我们首先分析代理与人类生成PR在合并率上的差异如何随时间变化。然后识别AI代码代理主要应用的发展任务类型，并调查这些任务分布在不同开发季度中的演变。最后，我们比较代理与人类生成PR的一系列关键特征，重点关注它们对软件质量的影响及其时间动态。总体而言，我们的研究为AI代码代理在软件开发中的作用提供了实证和纵向视角，从而更细致地理解它们在实际实践中的优势与局限。

## Abstract
Recent advances in large language models and their rapid adoption across software engineering tasks have made Artificial Intelligence (AI) coding agents an integral component of modern software development workflows. While developers increasingly benefit from these coding agents, their impact on software quality remains insufficiently understood. In particular, how agentic contributions evolve across the software development lifecycle has not been thoroughly investigated. This study aims to characterize agentic pull requests (PR) in comparison to human generated PRs and to examine how their properties change across different stages of the development lifecycle. Using the AIDev dataset, we first analyze how differences in merge rates between agentic and human generated PRs vary over time. We then identify the types of development tasks where AI coding agents are predominantly applied and investigate how these task distributions evolve across development quarters. Finally, we compare a set of key characteristics of agentic and human generated PRs, focusing on their implications for software quality and their temporal dynamics. Overall, our findings provide an empirical and longitudinal perspective on the role of AI coding agents in software development, offering a more nuanced understanding of their benefits and limitations in real-world practices.

## 6. 论文的主要结论与发现

- **RQ1**：
  - Claude 的合并率最高（84.3%），Devin 最低（43.0%）。代理间差异显著，但不同开发季度间合并率差异不显著（仅轻微波动，第三季度最高 68.2%、第二季度最低 63.7%）。

- **RQ2**：
  - 代理最常处理的任务是文档、依赖管理和测试（重复性、低复杂度工作）。许可证和令牌管理任务频率最低。
  - 任务合并率差异明显：资产管理、令牌管理、许可证（>0.80）等结构化任务合并率高；LLM 集成、模型评估、JSON 模板等（<0.60）合并率低。第四季度各任务合并率趋于收敛。
- **RQ3**：
  - 代理级分析：不同代理在复杂度指标上表现不一致（如 Devin 提交数多、评论多；Codex 合并快、评论少）。
  - 聚合级分析：agentic PR 在贡献者数、提交数、修改文件数、合并时间、评论数上与人类 PR 有统计显著差异，但效应量均为“可忽略”（Cliff's δ < 0.15）。Agentic PR 合并更快、评论略多。
  - 缺陷引入：agentic PR 缺陷引入率整体低于或相当人类 PR，仅在第四季度统计显著（效应量可忽略）。代理 PR 缺陷率从第二到第三季度显著下降（小效应量）。

## 7. 优点

- **纵向分析**：首次将软件开发生命周期划分为季度，系统性研究代理贡献的时间演化，弥补了先前静态研究的不足。
- **多角度覆盖**：从合并率、任务分布、代码质量、缺陷引入四个维度全面评估。
- **细粒度任务发现**：通过无监督主题建模自动识别 24 种任务类型，避免了预设分类的局限，揭示了代理更适合结构化、低复杂度任务的模式。
- **严谨的统计方法**：使用 GLMM 控制仓库随机效应，采用 EMM 进行推断，结合效应量和统计检验，避免过度解读微小差异。
- **平衡采样与偏差控制**：在 RQ3 中按季度和仓库平衡样本，减少时序和项目差异的混淆。

## 8. 不足与局限

- **外部有效性局限**：仅针对 Python 语言和 GitHub 平台，其他语言（JavaScript、TypeScript）或平台（GitLab）可能表现不同。仅分析星级 >100 的仓库，不适用于小型或新兴项目。
- **代理覆盖不全**：仅包含五个代理（Codex、Copilot、Claude、Cursor、Devin），未覆盖最新代理（如 Claude 3.5、Gemini 编码助手等）。
- **SZZ 算法的精度问题**：PyDriller 的 SZZ 实现精度较低（0.39），可能漏检或误报缺陷引入，影响缺陷分析的可信度。
- **排除未关闭 PR**：仅分析已关闭 PR，未考虑仍处于开放状态的 PR，可能高估合并率或低估缺陷。
- **任务分类的人工验证有限**：虽然验证了 100 个样本（87% 准确率），但未对所有 9,428 个 PR 进行人工标注，可能存在主题重叠或错误分配。
- **因果推断不足**：观察性研究无法建立因果关系。例如，代理 PR 合并更快可能源于任务本身简单，而非代理能力。

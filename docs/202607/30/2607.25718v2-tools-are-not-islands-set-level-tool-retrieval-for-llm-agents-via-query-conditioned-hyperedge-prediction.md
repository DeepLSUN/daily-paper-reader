## 摘要
大语言模型（LLM）智能体越来越依赖调用外部工具来完成实际任务。工具检索（在智能体行动前从包含数千个工具的工具库中选择一小部分与任务相关的子集）因此成为LLM智能体流程的关键组成部分。然而，现有的检索器要么孤立地评分每个工具，要么顺序地组装工具集，因此从未整体评估候选集的联合效用。在本文中，我们提出HYSET，即基于超边的集合级工具检索。我们的贡献有三点：（i）我们将工具检索形式化为工具共调用超图上的查询条件超边预测，其中工具集本身成为评分单位，大多数现有检索范式简化为受限实例；（ii）我们通过基数特定的交互捕获依赖于大小的工具兼容性；（iii）我们将HYSET设计为预选择模块，无需修改下游智能体。在ToolBench上的实验表明，HYSET在工具检索性能和端到端任务成功率上均一致优于最先进的基线。在域内设置之外，HYSET进一步支持零样本/少样本迁移，以极少的监督泛化到未见过的工具/类别和未知领域。

## Abstract
Large language model (LLM) agents increasingly rely on invoking external tools to complete real-world tasks. Tool retrieval, which selects a small task-relevant subset from a library of thousands of tools before the agent acts, has therefore become a critical component of LLM agent pipelines. However, existing retrievers either score each tool in isolation or assemble the tool set sequentially, so the joint utility of a candidate set is never evaluated as a whole. In this paper, we propose HYSET, short for HYperedge-based SEt-level Tool retrieval. Our contributions are threefold: (i) we formulate tool retrieval as query-conditioned hyperedge prediction on a tool co-invocation hypergraph, under which the tool set itself becomes the unit of scoring and most existing retrieval paradigms reduce to restricted instances; (ii) we capture size-dependent tool compatibility through cardinality-specific interactions; and (iii) we design HYSET as a pre-selection module requiring no modification to the downstream agent. Experiments on ToolBench demonstrate that HYSET consistently outperforms state-of-the-art baselines in both tool retrieval performance and end-to-end task success. Beyond the in-domain setting, HYSET further supports zero-shot/few-shot transfer, generalizing to held-out tools/categories and unseen domains with minimal supervision.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：大语言模型（LLM）智能体在执行真实世界任务时需调用外部工具（API）。工具库规模巨大（如ToolBench包含16,464个API），无法将所有工具描述放入上下文。因此**工具检索**成为关键环节——在智能体行动前，从海量工具中选出与任务相关的小子集。
- **现有方法局限**：现有检索器分三种范式：
  - **语义匹配**（BM25、Contriever等）：孤立评分每个工具，再聚合为集合分数，忽略工具间的相互依赖。
  - **图增强检索**（COLT）：通过共现图学习工具表示，但推理时仍退化为独立排序，未显式评估集合整体。
  - **生成式检索**（ToolGen）：按顺序生成工具标识符，集合组装是逐步进行的，无法直接比较候选集。
- **核心问题**：现有方法从未将**候选工具集作为一个整体进行评分**，导致无法捕获工具间的联合效用。尤其是**集合的完整性**（COMP指标）远低于单个工具的召回率，说明孤立评分失败。
- **论文主张**：工具不是孤岛，工具检索本质上是**集合级问题**。需要解决两个子问题：①能否将工具集作为整体评分？②工具共调用模式是否随集合大小变化？答案是“是”。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将工具检索形式化为**查询条件下的超边预测**（query-conditioned hyperedge prediction）。构建工具共调用超图，节点为工具，超边为每个查询所需工具集。评分函数直接对候选超边（即工具集）打分。
- **统一视角**：证明现有三种范式均可视为该超边预测框架的特例（Fmatch，Fgraph，Fgen）。
- **HYSET框架**：
  - 评分函数分解：\(F_\theta(x, E) = F_{\text{set}}(E) + F_{\text{align}}(x, E)\)
    - **\(F_{\text{set}}(E)\)**：独立于查询的集合内部交互，采用基数特定的成对交互矩阵 \(\mathbf{M}_m\)（m=|E|），通过 \(\sum z_j^\top \mathbf{M}_m z_k\) 建模工具兼容性，且允许不同基数下相同工具对得分不同，从而隐式捕获高阶交互，避免显式高阶张量。
    - **\(F_{\text{align}}(x, E)\)**：查询与集合的对齐，通过交叉注意力池化得到集合表示，再与查询嵌入点积。
  - **训练目标**：包含两部分：
    - 检索损失（对比学习）：负采样（大小匹配、批内负样本、硬负样本）构建候选池，最大化正超边logits。
    - 自训练损失：使用执行反馈奖励（由GPT-4作为法官评估智能体答案），对模型选择的集合进行加权学习。
    - 正则化：对\(\mathbf{M}_m\)施加Frobenius范数正则。
  - **推理**：两阶段近似——先通过单工具评分获得短列表（Kpool），再在短列表的所有可能超边空间中精确最大化评分。贪婪排名用于生成有序输出。
- **无需修改下游智能体**，仅作为预选择模块。

- HYSET在所有检索和端到端指标上一致超越所有基线，COMP@5相对提升11.6%（Qwen骨干），Pass Rate相对提升最高13.1%。

### 7. 优点

- **问题形式化创新**：首次将工具检索显式建模为超边预测，为集合级评分提供统一框架。
- **方法设计简洁有效**：通过基数特定成对矩阵隐式捕获高阶交互，避免复杂张量且参数高效（仅O(M d^2)）。
- **两阶段推理**：先快速粗选再精确重排，兼顾效率和准确性，且保证变长集合输出。
- **执行反馈利用**：自训练损失让模型从执行结果中学习，提升实际任务成功率。
- **强泛化性**：即使跨域零样本也表现良好，减少领域适配成本。
- **全开源**：提供Demo、GitHub和Hugging Face，实验可复现。

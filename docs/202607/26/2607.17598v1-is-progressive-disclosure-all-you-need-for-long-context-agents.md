## 摘要
长文档问答通常迫使人们在将整个文档加载到上下文窗口与附加单独检索器之间做出选择。智能体式AI提出了一种更广泛的选择，即给智能体文档路径，让它自行决定如何以及阅读什么。Agent Skills是一种将专业知识打包成文件夹供智能体按需加载的标准，提供了一种现成的机制：渐进式披露，仅暴露查询所需的内容，从简短描述到特定段落。从业者迅速采用这种模式来处理书籍长度的理解任务，但支持这种选择的证据一直是轶事性的。我们首次对该模式进行了受控研究，在InfiniteBench上，针对三个智能体框架和三个模型系列，比较了原始文档导航和多种Agent Skills包设计，以及经典的混合检索器。对于单本书，增益取决于框架：当智能体本身难以导航原始文档时增益显著，而当强大的智能体框架已自行划分并检索时增益近乎为零。当扩展到跨多本书的任务时，原始文档导航崩溃，而单层渐进式披露降级更慢并领先。第二层更深的路由从未有帮助，有时甚至直接破坏准确性，因此一层就足够了。渐进式披露购买的是上下文，而非智能：当强大智能体能自行定位正确段落时它是冗余的，而当语料库过大无法通过阅读导航时它则起决定性作用。

## Abstract
Long-document question answering usually forces a choice between loading the whole document into the context window and bolting on a separate retriever. Agentic AI suggests a broader option, giving the agent the document path and letting it decide how and what to read. Agent Skills, a standard for packaging expertise into folders an agent loads on demand, supply a ready mechanism: progressive disclosure, which exposes only what a query needs, from a short description down to the specific passages. Practitioners rapidly adopted this pattern for book-length understanding tasks, but the evidence to support such choices has been anecdotal. We run the first controlled study of the pattern, comparing raw-document navigation and several designs of Agent Skills packs against a classical hybrid retriever across three agent harnesses and three model families on InfiniteBench. On a single book, the gain depends on the harness, running large when the agent navigates the raw document poorly but near zero when a strong agent harness already divides and retrieves on its own. When scaling up to tasks that span many books, raw-document navigation collapses while one-level progressive disclosure degrades more slowly and pulls ahead. A second, deeper routing level never helps and sometimes breaks accuracy outright, so one level is enough. Progressive disclosure buys context, not intelligence: it is redundant while a strong agent can locate the right passages itself, and decisive once the corpus grows too large to navigate by reading.

- **整体含义**：通过对比原始文档导航、平面披露（flat）和层次披露（hierarchical）三种方法，以及经典的混合检索基线，揭示渐进式披露的实际作用——它主要提供上下文扩展（context scaling），而非提升智能性（intelligence）。在强导航能力的智能体下冗余，在大型语料库下起决定性作用，且一层披露足够，二层有害。

## 二、论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将长文档（书籍）打包为Agent Skills包，智能体通过文件系统导航，按需读取，实现定位-读取（locate-then-read）的检索模式。
- **关键技术细节**：
    1. **Book-to-Skill管道**（一次构建，重复使用）：
        - **分块**：按章节标题切分（约4000词/块），无标题则按段落边界固定大小分块，每块存为独立文件（`references/` 下）。
        - **描述生成**：对每块用LLM生成简短摘要+关键元素（名称、实体）；再基于块描述生成全书级描述。描述是路由元数据。
    2. **三种访问方法**（唯一变量是智能体如何到达段落）：
        - **原始文档导航（raw）**：无技能包，智能体直接操作原始文档文件（可全读、grep、选择性读）。
        - **平面披露（flat）**：单技能包，根目录有SKILL.md，其`description`始终在上下文中（发现阶段），body包含所有块的索引表（激活阶段），智能体根据索引读取特定块文件（执行阶段）。每块描述仅在激活后进入上下文。
        - **层次披露（hierarchical）**：每块作为一个独立技能，其`description`是块摘要（始终在上下文），body是块内容。顶层元路由器有全书描述，子技能描述始终加载。激活和执行合并（读体即读内容）。
    3. **LOONG DOC环境**：将∞Bench静态基准转化为交互式环境。每个∞Bench项变成一个任务，智能体通过文件系统（BenchFlow框架支持Agent Client Protocol）导航。记录轨迹和奖励。支持单本书和多本书（库规模）任务。
- **算法流程**：无数学公式。流程为：构建分块→生成描述→打包为文件系统→智能体接收指令+文件系统→智能体调用工具（读、grep、打开）→将答案写入指定文件→确定性验证器打分（多选匹配答案字母，开放QA用归一化匹配和F1）。

## 六、论文的主要结论与发现

1. **单本书场景**：
   - 平面披露在强导航智能体（如Codex）下无增益（增益依赖harness），因为Codex本身已能grep所需实体并选择性读段。对弱导航智能体（Pi, Claude-Code），平面披露提升或持平原始导航。
   - 层次披露从未优于平面披露，甚至有害（Pi+gpt-5.4-mini下En.MC从0.9126降至0.6398），因为始终加载的子技能描述膨胀上下文。
   - 混合检索（hybrid-rag）几乎在所有配置下落后于平面披露，说明披露不是检索的简单替代。

2. **多本书库规模**：
   - 原始文档导航随K增加迅速崩溃（En.QA from 0.657 → 0.257 at K=20）。
   - 平面披露降级更慢，在K=20时显著领先（En.QA 0.462 vs 0.257）。
   - 层次披露在开放问答上未能重现增益，重新跌回原始导航水平（始终加载的描述随库增大而饱和上下文）。
   - 第二层路由在弱导航harness下对开放问答有微弱恢复（如Pi+Zh.QA K=20: hierarchical 0.330 优于 flat 0.137），但整体不一致。
   - 更大库意味着更低准确率和更高每问题成本（Pareto前沿向右下移动），但平面披露在给定精度下成本更低（如K=20时flat成本约$25，精度0.462；raw约$52，精度0.257）。

3. **核心主张**：
   - 渐进式披露购买的是上下文（context），而非智能（intelligence）。强智能体能自行定位时冗余，库规模超过本地导航能力时起决定性作用。
   - **一层披露足够，二层有害**（除少数开放问答恢复情况）。

## 七、优点：方法或实验设计上的亮点

1. **受控对比**：首次将三种“智能体读取长文档”的方法（raw, flat, hierarchical）放在同一基准上公平比较，固定分块和描述，仅改变披露结构。
2. **分离设计变量**：明确区分了披露深度和索引位置的影响，而非像此前实践将它们混为一谈。
3. **构建交互环境**（LOONG DOC）：将静态∞Bench转化为智能体环境，支持文件系统导航、轨迹记录、库规模扩展，且验证器确定性评分。可扩展至其他基准。
4. **多维度评估**：覆盖三个智能体框架、三个模型家族、两个任务类型（多选/开放）、两种语言、两种规模（单书/库）。
5. **成本-精度分析**：在Pareto平面上展示了缩放效应，说明增大库不仅降低精度还提高成本，而平面披露能同时改善两者。
6. **解释性**：通过轨迹分析（如Codex即使用grep）解释增益差异，避免仅看数字的误导。

## 八、不足与局限

1. **预训练混淆**：En.MC使用的经典英文小说可能已被模型记忆，导致智能体不经阅读即可答对部分题目，减弱了披露信号。开放QA（需要精确片段）是更干净的测试。
2. **样本量有限**：∞Bench提供的问答数量有限，部分对比在±1标准误差内未达显著（如Zh.QA多书下差异方向性）。更大基准可收紧估计。
3. **单一基准家族**：仅使用∞Bench，未在其他长文档基准（如NovelQA）上验证（因NovelQA标签需第三方平台）。结果对非叙事性语料（代码、技术手册）的泛化性未知。
4. **任务和语言特定性**：增益主要集中在英文开放QA，中文开放QA下skill pack中性甚至负面（模型能力为瓶颈）。多选增益受预训练混淆削弱。
5. **固定分块/描述策略**：仅测试了一种流行的book-to-skill方法（按章节切分，LLM写描述）。不同粒度或不同描述生成模型可能改变平衡。
6. **库规模采样稀疏**：仅K∈{1,5,10,20}，无法精确确定披露开始支付收益的临界点。
7. **成本估计保守**：未考虑提示缓存（prompt caching），若考虑则披露（其始终加载的描述可缓存）成本更低，实际情况可能更优，但论文采用未缓存的保守上界。

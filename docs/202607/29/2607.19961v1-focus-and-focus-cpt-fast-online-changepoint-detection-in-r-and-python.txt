Abstract 

We present an R and Python package for fast online changepoint detection in univariate and multivariate data streams for a variety of models. The package implements the focus 

family of algorithms, which compute the Generalised Likelihood Ratio test for a single changepoint exactly and efficiently, with a per-iteration cost of approximately log( n)d for a d-dimensional sequence, without introducing approximations. This is achieved by ex-ploiting a connection between the location of the changepoint candidates and the geometry of the data. The package supports a broad range of models from the natural exponential family, including Gaussian, Poisson, Binomial, Exponential and Gamma distributions, as well as a non-parametric detector based on the empirical cumulative distribution function and a detector for autoregressive data. 

Keywords : changepoint detection, anomaly detection, online algorithms, real-time analysis, functional pruning, R, Python .

# 1. Introduction 

In the past decade, we have seen a resurgence of changepoint detection approaches (in par-ticular in the offline scenario, see Truong, Oudre, and Vayatis 2020). The vast majority of real-world processes happen over time, and methodologies that account for temporal shifts arXiv:2607.19961v1 [stat.ME] 22 Jul 2026 2 focus and focus-cpt : Fast Online Changepoint Detection in R and Python 

and anomalies in these processes have been proven useful to many real world applications (e.g., Shiryaev 2002; Alvarez-Montoya, Carvajal-Castrillón, and Sierra-Pérez 2020; Xie, Xie, and Moustakides 2019). Nowadays, with the advent of the Internet of Things, and the ubiq-uity of large sensor networks that are able to monitor processes in real-time, it is common to want to detect anomalies and changes online. For example, real-time monitoring from engineering (Alvarez-Montoya et al. 2020; Łobodziński 2025), cybersecurity (Jeske, Stevens, Tartakovsky, and Wilson 2018), or self-driving cars (Galceran, Cunningham, Eustice, and Olson 2017), could require analysis of high frequency data from potentially multiple streams to inform timely decisions. Neuroscience (Jewell, Hocking, Fearnhead, and Witten 2020) and astrophysics (Crupi, Dilillo, Bissaldi, Ward, Fiore, and Vacchi 2023) problems may in-volve processing hundreds of observations per second to uncover novel biological and scientific mechanisms. Motivated by these problems, there has been a range of methodological advances around fast and efficient statistical online changepoint detection approaches, including, but not limited to Aue and Kirch (2024); Xie, Moustakides, and Xie (2023); Yu, Madrid Padilla, Wang, and Rinaldo (2023); Chen, Wang, and Samworth (2022). Amongst these, the focus algorithm, introduced in Romano, Eckley, Fearnhead, and Rigaill (2023b), has found applications across a range of settings and has prompted several methodological developments. These so far include an extension to univariate exponential family models (Ward, Dilillo, Eckley, and Fearnhead 2023; Ward, Romano, Eckley, and Fearnhead 2024), an adaptation to non-parametric settings (Romano, Eckley, and Fearnhead 2023a), as well as a generalisation to multivariate time series (Pishchagina, Romano, Fearnhead, Runge, and Rigaill 2025). 

focus detects changes using the Generalised Likelihood Ratio (GLR) test (Siegmund and Venkatraman 1995). The GLR evaluates whether the underlying distribution generating the observations has changed at a given point in time, by comparing the likelihood of the data under the null hypothesis of no change against the alternative hypothesis of a change at some unknown location, optimising over all possible changepoint locations. This test has shown good statistical properties in terms of detection power and false alarm control for several models (see Lorden 1971; Basseville, Nikiforov et al. 1993). However, when analysing 𝑛 data points, a naive sequential implementation requires 𝒪(𝑛) operations per time step, leading to an overall 𝒪(𝑛 2) complexity that makes it unfeasible for true real-time applications. The focus 

algorithm addresses this limitation directly: it computes the GLR statistic exactly, without any approximation, but does so with a per-iteration cost that grows only logarithmically in the unvariate case with the length of the observed sequence, and more generally at a log (𝑛) 𝑑 

rate for a d-dimensional sequence, as we describe in detail in Section 2. Methodologies based on focus are already being trialled in diverse areas, from detecting as-trophysical events on satellites (Dilillo, Ward, Eckley, Fearnhead, Crupi, Evangelista, Vacchi, and Fiore 2024), to monitoring IoT networks (Yang, Eckley, and Fearnhead 2024) and digital infrastructure (Romano et al. 2023a). This paper and software package arise from the need to provide a common interface to the focus family, that could be of use to practitioners. One particular aspect of this implementation is that the R and Python interfaces share the same underlying C++ backend, implementing the algorithms, and therefore show parity of functionalities and produce identical results. 1.1. Related Software 

A comprehensive overview of R and Python packages for changepoint and anomaly detection is available through the CRAN Task Views for Time Series Analysis (Hyndman and Killick 2026) and Anomaly Detection (Talagala, Hyndman, and Romano 2025); we refer the reader to these for a broad survey. Here we restrict attention to statistical packages most closely related to focus , focusing on likelihood-based methods and omitting general-purpose anomaly detection toolkits. For offline changepoint detection in R, we find changepoint (Killick and Eckley 2014), which implements the PELT algorithm and binary segmentation for changes in mean, variance, or both, in a univariate setting. For change-in-mean, implementing the fpop and pDPA algo-rithms (Maidstone, Hocking, Rigaill, and Fearnhead 2017; Rigaill 2015), we find the fpopw 

package. A broad family of randomised and deterministic localised search strategies is col-lected in the breakfast package (Anastasiou, Chen, Cho, and Fryzlewicz 2024), which includes wild binary segmentation, WBS2, narrowest-over-threshold, and other methods. A further deterministic alternative achieving near-linear computational cost while retaining minimax-optimal estimation is seeded binary segmentation (Kovács, Bühlmann, Li, and Munk 2023), whose implementation is available on GitHub only at https://github.com/kovacssolt/Seed BinSeg. The MOSUM-based approach, which uses moving-sum statistics for multiple mean-change estimation, is implemented in the mosum package (Meier, Kirch, and Cho 2021). For Bayesian offline analysis, bcp (Erdman and Emerson 2008) provides a model for changes in the mean of Gaussian data. In Python , the primary offline library is ruptures (Truong, Oudre, and Vayatis 2018), which offers a modular and well-documented interface covering PELT, bi-nary segmentation, window-based methods, and kernel cost functions across both parametric and non-parametric models. The above packages are for detecting abrupt unstructured changes (similar to focus ). There are also packages that can detect gradual or structured changes in offline data. These include the cpop (Fearnhead and Grose 2024) package and the trandfilter function (Kim, Koh, Boyd, and Gorinevsky 2009) in the genlasso (Arnold and Tibshirani 2016) package for de-4 focus and focus-cpt : Fast Online Changepoint Detection in R and Python 

tecting changes-in-slope, and the gfpop (Runge, Hocking, Romano, Afghah, Fearnhead, and Rigaill 2023) package for detecting structured changes. For online (and sequential) changepoint detection in R, ocd (Chen, Wang, and Samworth 2020) implements a multiscale likelihood-ratio procedure for high-dimensional Gaussian mean changes, with storage and per-observation cost independent of the number of past observa-tions, it also provides access to several classical sequential procedures. A Bayesian online changepoint detection algorithm is available through ocp (Pagotto 2019), which implements the algorithm of Adams and MacKay (2007). In Python , the online changepoint detection ecosystem is currently less consolidated than its offline counterpart. An implementation of the same Adams and MacKay (2007) algorithm is available as a lightweight package on PyPI (https://pypi.org/project/bocd/); changepoint-online is a fully pythonic, early implemen-tation of some algorithms included in focus-cpt (available at https://pypi.org/project/cha ngepoint-online/). The proposed implementation therefore occupies a distinct niche rela-tive to this landscape: unlike ocd , which is its closest competitor, it is based on exact GLR statistics and naturally extends to exponential family models and non-parametric settings (a comparison of the statistical performances of focus and ocd is available in Romano et al. 

2023b; Pishchagina et al. 2025); and, crucially, compared to changepoint-online it provides a unified R and Python interface backed by a shared (and therefore easier to maintain) and faster C++ implementation.

(2024), whose per iteration cost is amortised 

𝒪(1) on average, and is closely related to the Melkman algorithm (Melkman 1987). This is based on comparisons of the argmax of the component functions 𝑞 𝑖,𝑛 and 𝑞 𝑖+1,𝑛 for pairs of contiguous elements of 𝐷 𝑛 and is equivalent to updating sequentially a 2-dimensional hull by comparing the slope of contiguous points. As updates of the majorants and minorants of the convex hull can be kept separate, this also allows for constraining the detection to only positive or negative changes; see Section 4.1. For multivariate data, standard convex hull algorithms can be applied to prune candidates. As in Pishchagina et al. (2025), we employ QuickHull (Barber, Dobkin, and Huhdanpaa 1996) for reconstructing the set of optimal points. Because running a full convex hull algorithm such as QuickHull at every iteration would itself be costly, the implementation runs it only intermittently. Specifically, the algorithm maintains a working candidate set 𝑇 ′𝑛 that is allowed to grow beyond the true hull vertex set 𝐷 𝑛 ; QuickHull is triggered only once |𝑇 ′𝑛 | exceeds a size threshold, which is itself updated after each pruning step as ⌊𝛼|𝑇 ′𝑛 |+𝛽⌋ for user-controlled parameters 𝛼 ≥ 1 , the pruning multiplier, and 𝛽 ≥ 0 , the pruning offset. This means that the algorithm always retains a small number of extra candidates beyond those strictly necessary, trading a small increase in the candidate set size for a significant reduction in the number of times the hull algorithm is called. In practice, setting 𝛼 = 2 and 𝛽 = 1 is found to yield good performance across a range of dimensions and sequence lengths, but these values can be overridden as described in Section 3.1. One feature of multidimensional sequences, as illustrated in Corollary 1 of Pishchagina et al. 

(2025), is that the expected size of 𝐷 𝑛 grows only as 𝒪( log (𝑛) 𝑑 ) in the 𝑑 -dimensional case, rather than linearly with 𝑛 . So for low-dimensional multivariate data, such as 𝑑 ≤ 5 , one can use the detector corresponding to the full (𝑑 + 1) -dimensional convex hull. For higher-dimensional problems, this becomes computationally impractical due to the log (𝑛) 𝑑 growth in the number of hull vertices, and an approximate algorithm is available: the data are projected onto overlapping subsets of ̃ 𝑑 ≤ 5 coordinates, a convex hull is computed on each lower-dimensional projection, and the union of the resulting vertex sets is taken as the set of candidates. This approximation stores 𝒪(𝑑 log (𝑛) ̃ 𝑑 ) candidates rather than 𝒪( log (𝑛) 𝑑 ),substantially reducing the computational burden for large 𝑑 while retaining good statistical performance (Pishchagina et al. 2025). How to use this, and the computational gains obtained from the approximations are briefly exemplified in Section 4.2.

can be used to find a threshold that gives a required false positive probability over a fixed length of data. This example shows how using the threshold=Inf setting enables us to do this efficiently without re-running the algorithm for different thresholds. Obtaining a threshold that gives a require false-positive rate for data of length 𝑛 is achieved by (i) generating many sequences of data 𝑌 (𝑘) 1∶𝑛 (𝑘 = 1, … , 𝐾 ) under the null hypothesis of no changepoints, (ii) computing the detection statistic 𝑓 GLR (𝑌 (𝑘) 1∶𝑛 ) for each sequence, and taking the maximum over time max 𝑛 𝑓 GLR (𝑌 (𝑘) 1∶𝑛 ) (as this is the most extreme value that would trigger a detection), and finally (iii) defining the threshold as the empirical quantile 𝜉 = 𝐹 −1 𝐾 (1 − 𝛼) ,where 𝐹 𝐾 is the empirical distribution of the maxima and 𝛼 is the desired false positive rate. Specifically, to achieve a 1% false positive rate ( 𝛼 = 0.01 ), we take the 99th percentile of the null statistics as our threshold; approximately 1% of null sequences will then exceed this threshold by chance. As illustrated in (Pishchagina et al. 2025), simulating data to calibrate a simple Gaussian change in mean model for this NBA dataset is tricky. This is because a small change in the variance of the reference distribution changes the threshold and, as a consequence, can increase the detection time or leads to false detections. 5.3. Constrained Up-Down Model for Spike Inference 

We now present an application to calcium imaging data, based on the spikefinder challenge data (https://github.com/codeneuro/spikefinder). This data measures fluorescence, relating to the intensity of calcium ions in neurons, and is sampled at a high-frequency of 100 Hz. In calcium imaging, each neuron firing (spike) produces a sharp upward jump followed by an exponential decay. Changepoint detection approaches have been successfully employed to analyse calcium imaging data in the offline setting, yielding computationally efficient al-gorithms for spike inference (Jewell and Witten 2018; Jewell et al. 2020; Fleming, Jewell, Engelhard, Witten, and Witten 2021). However, there is increasing interest in performing equivalent analyses in real time. In-vivo calcium imaging now enables closed-loop experiments in which neural activity is decoded and available online (Hira 2024; Zhang, Dzialecka, Russell, Ratto, Buetfering, Gauld, Selviah, and Häusser 2025). These applications require low-latency processing of fluorescence signals, whereas most existing pipelines operate offline and incur substantial delays (Chen, Blair, Cao, Zhou, Aharoni, Golshani, Blair, and Cong 2023), mo-tivating the need to perform spike inference for real-time streaming data. The original data is a trace of fluorescence intensity over time, which we will use to infer the underlying spike times; see Figure 8. Although the spikefinder dataset is offline in nature, the use of in-vitro recordings provides a controlled validation setting, as the true spike times are known from simultaneous electrophysiological recordings. This allows us to tune the thresholds of the two detectors and evaluate their performance. To analyse this sequence in a sequential fashion via our package, we use two one-sided detectors simultaneously: one watching for up-changes (spikes) and one for down-changes (decay onset), resetting both whenever either detects a change. The rationale behind this is that only up-30 focus and focus-cpt : Fast Online Changepoint Detection in R and Python

The up-changes are recorded separately as they corre-spond to the spikes we want to detect. The two thresholds are passed as arguments to the function, as this will allow us to tune them via cross validation. To do so, we create a 30/70 % train test split. Then, both thresholds are selected jointly by 5-fold cross-validation on the training set. APPENDIX 

# A. The Python Interface: Differences and Similarities 

The Python package [focus-cpt]{.pkg} provides a clean, Pythonic interface to the same underlying C++ implementation as the R package. The core philosophy is to mirror the 

R interface as closely as possible, while leveraging Python idioms and conventions where appropriate. The primary structural difference between the two interfaces lies in the handling of the de-tector object. In R, the detector is an external pointer that must be passed to functions like detector_update and get_statistics . In Python , the detector is an instance of the 

Detector class, and operations are performed as methods on this object. This is more id-iomatic in Python and aligns with the object-oriented philosophy of the language. Specifically: • Initialization : In R, detector_create(type = "univariate") creates a detector. In 

Python , this is Detector(type="univariate") .• Updating : In R, detector_update(det, y) updates the detector. In Python , this is 

det.update(y) .• Computing statistics : In R, get_statistics(det, family = "gaussian") com-putes statistics. In Python , this is det.get_statistics(family="gaussian") .• Extracting information : Functions like detector_info_n , detector_info_sn ,and detector_cands_len in R are available as methods get_n() , get_sn() , and 

get_n_candidates() in Python . Similarly, detector_candidates is available as the method get_candidates() .Beyond the object-oriented interface, the Python bindings follow standard Python conventions: • Python uses None instead of R’s NULL . For example, get_statistics(family="gaussian", theta0=None) is equivalent to the R call get_statistics(det, family = "gaussian", theta0 = NULL) .• Numeric vectors and matrices in Python are typically represented as NumPy arrays. The package should automatically handle conversion of lists and other array-like objects to NumPy arrays. Note that for univariate detectors, the focus_offline function returns a 2D statistic array with shape (n_obs, 1) rather than a 1D array, which may need to be flattened before further processing (see the offline example below). • Functions return dictionaries ( Python ’s equivalent to R’s lists) rather than named lists. For example, det.get_statistics(family="gaussian") returns a dictionary with keys 'stopping_time' , 'changepoint' , and 'stat' .

## 摘要
大型语言模型（LLM）智能体日益依赖调用外部工具来完成真实世界任务。工具检索作为智能体行动前从数千工具库中选取少量任务相关子集的关键环节，已成为LLM智能体流程的核心组件。然而，现有检索方法要么孤立评估每个工具，要么顺序组装工具集，从未整体评估候选集的联合效用。本文提出HYSET——基于超边的集合级工具检索（HYperedge-based SEt-level Tool retrieval）。我们的贡献有三点：（i）将工具检索形式化为工具共调用超图上的查询条件超边预测，使工具集本身成为评分单元，且大多数现有检索范式可归结为受限实例；（ii）通过基数特异性交互捕获随规模变化的工具兼容性；（iii）将HYSET设计为无需修改下游智能体的预选模块。在ToolBench上的实验表明，HYSET在工具检索性能和端到端任务成功率上均持续优于最先进基线。除域内场景外，HYSET还支持零样本/少样本迁移，能以极少量监督泛化到未见工具/类别及未见过领域。

## Abstract
Large language model (LLM) agents increasingly rely on invoking external tools to complete real-world tasks. Tool retrieval, which selects a small task-relevant subset from a library of thousands of tools before the agent acts, has therefore become a critical component of LLM agent pipelines. However, existing retrievers either score each tool in isolation or assemble the tool set sequentially, so the joint utility of a candidate set is never evaluated as a whole. In this paper, we propose HYSET, short for HYperedge-based SEt-level Tool retrieval. Our contributions are threefold: (i) we formulate tool retrieval as query-conditioned hyperedge prediction on a tool co-invocation hypergraph, under which the tool set itself becomes the unit of scoring and most existing retrieval paradigms reduce to restricted instances; (ii) we capture size-dependent tool compatibility through cardinality-specific interactions; and (iii) we design HYSET as a pre-selection module requiring no modification to the downstream agent. Experiments on ToolBench demonstrate that HYSET consistently outperforms state-of-the-art baselines in both tool retrieval performance and end-to-end task success. Beyond the in-domain setting, HYSET further supports zero-shot/few-shot transfer, generalizing to held-out tools/categories and unseen domains with minimal supervision.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：随着LLM智能体越来越多地调用外部工具完成真实任务，工具库规模已从几十个手工函数扩展到包含数万个API端点（如ToolBench有16464个API）。智能体在行动前必须从庞大工具库中检索出少量任务相关的工具子集。现有检索方法主要分为三类：
  - **语义匹配检索**：独立评分每个工具（如BM25、Contriever），忽略集合联合效用。
  - **图增强检索**（如COLT）：通过双视图协作学习改进，但推理时仍归约为独立top-k排序，集合级连贯性仅被近似。
  - **生成式检索**（如ToolGen）：逐步生成工具标识符，候选集从未被整体比较。
- **关键洞察**：工具并非孤岛，工具集作为整体的联合效用无法通过独立评分或顺序组装捕获。例如，旅行规划查询需要{航班、酒店、天气、货币}四个工具，语义匹配可能选出多个同质航班工具而遗漏其他必要工具。
- **研究问题**：
  - （Q1）能否将工具集作为整体评分，并提升检索性能？
  - （Q2）工具共调用模式是否随集合大小变化，建模这些差异是否有帮助？
- **整体含义**：本文提出HYSET，将工具检索重新定义为**查询条件超边预测**，以工具集为评分单位，并通过基数特异性交互建模集合大小依赖的兼容性。这是一种新范式，证明集合级建模在工具检索中的必要性和有效性。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想
- 将工具库建模为**工具共调用超图**（Tool Co-invocation Hypergraph）：节点是工具，超边是训练集中的真实工具集（E*）。工具检索转化为**查询条件超边预测**：给定查询x，预测最可能完整的工具超边E。
- 评分函数 \(F_{\theta}(x, E)\) 分解为两部分：
  - **集合交互项** \(F_{\text{set}}(E)\)：建模工具间的内在兼容性，独立于查询。
  - **查询-集合对齐项** \(F_{\text{align}}(x, E)\)：建模查询与工具集的整体相关性。

### 2.2 关键技术细节
- **集合交互项** \(F_{\text{set}}(E)\)：
  - 参数化：对于集合 \(E = \{t_{j_1}, ..., t_{j_m}\}\)，得分 = \(\sum_{1 \le a < b \le m} z_{j_a}^\top M_m z_{j_b}\)。
  - \(z_j\) 是工具 \(t_j\) 的可学习嵌入，\(M_m \in \mathbb{R}^{d_z \times d_z}\) 是**基数特异性**交互矩阵（m=2,...,M），共享给同一基数的所有超边。
  - 理论定理：\(F_{\text{set}}\) 是成对可分解的充要条件是所有基数下的矩阵相等（即 \(M_2 = ... = M_M\)）。因此基数特异性矩阵能隐式捕获高阶交互（≥3阶），无需显式三阶张量。
- **查询-集合对齐项** \(F_{\text{align}}(x, E)\)：
  - 使用冻结预训练语言编码器（如BERT-base或Qwen2.5-1.5B）获得查询嵌入 \(r(x)\)。
  - 通过交叉注意力池化：以 \(r(x)\) 为查询，\(\{P z_{jk}\}\) 为键/值，得到集合表示 \(s(x, E)\)。
  - 最终对齐得分 = \(r(x)^\top s(x, E)\)，等价于各工具匹配分数ℓ的加权和，权重α依赖于整个集合（实现集合级查询依赖）。
- **训练目标**：
  - **检索损失** \(L_{\text{ret}}\)：基于负采样（大小匹配采样、批内负样本、硬负样本）的对比学习，提升正集得分。
  - **自训练损失** \(L_{\text{self}}\)：使用执行反馈（奖励ρi：由执行结果通过GPT-4或人工评估得到）强化模型选中的成功集。
  - 总损失 = \(L_{\text{ret}} + \eta L_{\text{self}} + \lambda \sum_{m} \|M_m\|_F^2\)。
- **推理流程（两阶段）**：
  1. **构建短列表**：首先根据单工具得分（公式12）选出K1个工具；再根据与S0的互补性（基于 \(M_M\) 的得分）补充工具得到Kpool大小的候选集S。
  2. **集合级重排序**：在S的所有子集（大小1到M）中，选择使 \(F_{\theta}\) 最大的集合作为最终输出。同时通过贪心边际增益生成排序用于评估rank指标。

- **参数设置**：\(d_z=768\)（BERT配置），K1=15，Kpool=20，M=5，Kneg=64。冻结骨干，仅训练θ（Z, {Mm}, P），总参数量约13.59M（BERT配置）。

## 8. 不足与局限

- **对工具库规模依赖**：论文假设推理时工具集大小不超过训练时的最大大小M=5。若实际任务需要超过5个工具，方法需要扩展。尽管Kpool可调节，但模型训练时未见过更大集合，泛化能力存疑。
- **执行反馈成本**：训练需要额外的执行反馈（GPT-4评判），虽然提供了改进，但增加了成本和复杂度。补充材料表明即使不使用执行反馈，HYSET仍优于基线，但不可否认依赖外部评判。
- **负采样策略**：使用固定比例混合采样，补充材料虽有消融但未充分探索最优自适应策略。且负样本库可能引入隐含假阴性（工具集中可能包含合法工具但未被标注），论文在补充材料A.8中测量了假阴性率但未提供具体数值。

- **基数上限M=5**：虽然ToolBench中最大标注集大小为5，但实际应用可能更大。处理更大集合的方法需扩展或使用层级分解。
- **对嵌入初始化敏感**：工具嵌入Z初始化为冻结工具编码器的输出，但编码器来自ToolLLaMA或BERT，可能对工具描述质量敏感。未报告不同初始化下的稳定性。

## 摘要
大型语言模型智能体越来越依赖长期记忆来支持多会话交互和个性化。然而，现有的智能体记忆系统围绕仅向前演化设计，不断积累、整合和覆写知识，缺乏检查、版本化或回退先前状态的原则性机制。这使得智能体在纠正、概念漂移和记忆损坏面前变得脆弱，尤其是在它们已经接触了后续信息之后。我们提出了ChronoMem，一个用于智能体记忆的语义版本控制层，集成到Google的生产就绪、开源Agent Development Kit中。ChronoMem在每次记忆写入时提交整个记忆快照，维护结构化的版本历史，并通过混合词法和语义检索、秩融合和重排序，将撤销意图映射到具体的历史版本，从而支持自然语言回滚请求。我们进一步引入了一种暴露后评估协议，测试智能体在回滚后是否能够以反事实的方式行为，即通过回答问题并总结历史，仿佛未来更新从未发生。在增强了演化记忆状态和回滚任务的长时对话基准上，ChronoMem相对于仅提示和仅检索的基线，显著提高了回滚一致的问题回答和历史总结，同时在语义版本选择方面取得了强劲性能。据我们所知，ChronoMem是第一个用于LLM智能体系统性语义全局记忆回滚的开源系统和基准。

## Abstract
LLM agents increasingly rely on long-term memory to support multi-session interaction and personalization. However, existing agent memory systems are designed around forward-only evolution, continuously accumulating, consolidating, and overwriting knowledge, with no principled mechanism to inspect, version, or revert prior states. This makes agents brittle under corrections, concept drift, and memory corruption, particularly after they have already been exposed to subsequent information. We present ChronoMem, a semantic version-control layer for agentic memory integrated into the production-ready, open-source Agent Development Kit by Google. ChronoMem commits whole-memory snapshots at each memory write, maintains structured version histories, and supports natural-language rollback requests by mapping undo intents to concrete historical versions through hybrid lexical and semantic retrieval, rank fusion, and reranking. We further introduce a post-exposure evaluation protocol that tests whether an agent can behave counterfactually after rollback by answering queries and summarizing history as if future updates had never occurred. On long-horizon conversational benchmarks augmented with evolving memory states and rollback tasks, ChronoMem substantially improves rollback-consistent question answering and history summarization relative to prompt-only and retrieval-only baselines, while achieving strong performance in semantic version selection. To our knowledge, ChronoMem is the first open-source system and benchmark for systematic semantic global memory rollback in LLM agents.

## 2. 方法论：核心思想、技术细节与算法流程

### 2.1 核心思想

ChronoMem 将"自然语言撤销"问题分解为两个阶段，避免选择错误与恢复正确性之间的混淆：

1. **语义版本选择（Selection）**：将自然语言回滚请求映射到具体的历史版本 ID。
2. **确定性恢复（Restoration）**：通过快照加载，将整个记忆状态恢复到目标版本。

### 2.2 状态模型：事件日志 + 版本快照

- 采用**事件溯源（Event Sourcing）** 思想：记忆更新为不可变事件 $e_i$，追加到序列日志 $\mathcal{L} = \langle e_1, e_2, \dots, e_j \rangle$。
- 每个版本 $v_j$ 对应一个从日志前缀物化的**全量快照**：
  $$S(v_j) \triangleq \text{snap}(\langle e_1 \ldots e_{t_j} \rangle)$$
- 这种"日志+快照"设计避免回滚时重放整个日志，以存储换取快速恢复。

### 2.3 四阶段系统流程

**阶段一：版本构建（commit-on-write）**
每次记忆写入即触发一次提交（事务）：追加事件、物化全量快照、存储版本元数据、推进 HEAD 指针到最新版本。

**阶段二：版本索引（语义提交描述符）**
每个版本 $v_j$ 由语义提交描述符 $d_j$ 索引，包含：
- `delta_j`：操作级变化（新增/更新/删除的事实）
- `summary_j`：紧凑的自然语言变更摘要
- `op_j`：更新类型
- `labels_j`：时间元数据（会话索引、记录时间戳）

混合检索在描述符上执行（而非全量快照上），使选择成本与快照大小解耦、仅与版本数相关。

**阶段三：NL→版本映射（混合检索 + RRF + 重排）**

- **词法检索**：SQLite FTS5 BM25 对描述符打分。
- **稠密语义检索**：嵌入描述符后做 ANN top-K。
- **秩融合（RRF）**：
$$\text{RRF}(v_j \mid q) = \sum_{m \in \{lex, sem\}} \frac{1}{k_0 + \text{rank}_m(v_j)}$$
- **重排**：使用更强的交叉编码器（如 Cohere Rerank-3.5）对融合后的 top-K 候选重排，取 top-1 作为目标版本 $\hat{v}$。

**阶段四：确定性回滚（ID 驱动）**
- `rollback_to_version(vid)` 为底层原语：加载快照、恢复状态、设置 HEAD、截断后续版本、同步检索后端。
- `rollback_to_version_by_nl_query(query)` 为语义接口：先经检索解析出 $\hat{v}$，再调用同一恢复路径。

### 2.4 接口不变量

回滚后所有后续记忆读取都限定在活动版本（HEAD）范围内——**不得有版本 $v^*$ 之后的信息可见性**。

1. **暴露阶段**：智能体摄取完整交互流至最终状态 $v_T$；
2. **回滚阶段**：发出自然语言回滚请求，恢复到特定版本 $v^*$；
3. **执行阶段**：在恢复后的状态上执行下游任务（QA 或摘要）。

**回滚查询构建：**
- 用数据集注释中的锚点（如 LoCoMo 的证据跨度、MAB 的更新边界）生成两类查询：ground-truth 模板 + LLM 改写变体；

### 3.2 对比基线

| 基线 | 说明 |
|---|---|

## 6. 主要结论与发现

1. **架构性状态恢复是回滚一致性的关键**：显式的版本作用域状态恢复，比提示式自我抑制或片段级检索能更可靠地实现 counterfactual 行为。
2. **提示不足以克服暴露后污染**：Prompt-only 在 QA 上接近随机水平（如 LoCoMo 上 F1 仅 0.9–2.8%），证明一旦模型已看到 $v^*$ 后的信息，依靠指令无法可靠抑制。
3. **版本级索引优于片段级检索**：ChronoMem 相较 RAG-only 在 LoCoMo 上将 QA F1 提高约 7–12 个百分点，在 MAB 上提高约 14–21 个百分点。
4. **重排阶段不可或缺**：仅混合检索（RRF）不足以精确选版，交叉编码器重排显著提升了 Recall@1 与 Scope@2（LoCoMo：12.0%→20.5% Recall@1；MAB：24.3%→33.4%）。
5. **摘要任务同样受益**：全局快照恢复保证了时间一致性；相比之下，片段检索在需要全局连贯性的摘要任务上表现不佳。
6. **平均提升约 10 个百分点**：相较最强非版本化基线，回滚一致 QA 与摘要平均提升约 10%。

## 7. 优点

1. **首个开源系统 + 基准**：据作者所述，ChronoMem 是第一个开源的、在智能体记忆中实现语义全局回滚的系统，填补了研究空白。
2. **清晰的分层架构**：将"版本选择"（NL→ID）与"状态恢复"（ID→快照）分离，系统设计与评估均因此更具可解释性；数据平面与控制平面的区分使错误归因容易。
3. **生产集成**：构建于 Google ADK 这一主流开源框架中，可直接用于实际智能体系统，而非仅停留在理论原型。
4. **严谨的评估协议**：提出 post-exposure rollback 协议，比标准前向记忆评估更贴近真实需求的"事后修正"场景。
5. **事件溯源 + 快照混合设计**：兼顾审计审计追溯性与恢复速度，比纯重放或纯快照在存储与性能间更平衡。
6. **反事实测试意识**：明确检测答案中是否含 $v^*$ 后事实，将"信息泄漏"作为一致性违规处理，评估维度丰富。

## 8. 不足与局限

1. **并发与事务语义未验证**：系统基于 SQLite 单写者事务和每用户锁，未在高并发多会话场景下进行实验评估；自身承认写密集负载下可能有锁竞争和排队问题。
2. **仅支持线性历史**：回滚后截断后续版本（类似 Git reset），不支持分支、合并或多时间线，限制了对"选择性撤销"和现实世界复杂恢复需求的支持。
3. **基准适配的固有局限**：LoCoMo 和 MAB 并非为版本化回滚设计，人工构造的回滚查询分布可能与真实用户意图存在差异；LLM 生成查询的多样性受限。
4. **版本选择准确率仍然偏低**：即使是最优配置，Recall@1 也仅为 20.5%–33.4%，意味着大部分情况下无法精确命中目标版本；论文未深入分析错误模式或提供容错机制。
5. **外部副作用不处理**：系统明确不撤销第三方服务、RAG 外部语料或工具调用产生的副作用，限制了端到端恢复的完整性。
6. **模型范围有限**：均为 7–8B 规模的开源模型，未测试更强/更大模型（如 GPT-4、Claude 等）下的行为；重排器也只测试了一种。
7. **缺少系统开销定量分析**：文中提到分析系统级开销，但未报告具体时延、存储增长或吞吐量数据。

## 摘要
预填充-解码分离（PD）和基于roofline的算子放置是跨异构系统划分大型语言模型（LLM）推理的常见策略，但在实践中往往不够充分。端到端延迟还取决于工作负载形状、运行时设备争用以及持久权重布局。我们提出了DOPS（动态算子调度），一种硬件感知的闭环框架，联合优化算子调度和分块权重布局。DOPS构建了一个阶段感知的有向无环图（DAG），并集成了两个组件：用于动态算子到设备放置的Bifocal调度器，以及在严格内存约束下选择硬件高效权重布局的权重布局仲裁器（WLA）。在结合神经处理单元（NPU）和存内处理（PIM）设备的代表性异构系统上，Bifocal相比PD基线实现了1.20倍至2.23倍的几何平均加速。WLA在Bifocal/Linear基础上额外提供了1.28倍至1.33倍的几何平均加速。DOPS还支持对LLM服务的工作负载敏感性和硬件可扩展性进行系统分析。源代码可在https://github.com/YIAI-02/TriForm获取，可视化工具演示见https://youtu.be/Ya_oMCyYno0。

## Abstract
Prefill-decode disaggregation (PD) and roofline-based operator placement are common strategies for partitioning Large Language Model (LLM) inference across heterogeneous systems, but they are often insufficient in practice. End-to-end latency also depends on workload shape, runtime device contention, and persistent weight layout. We present DOPS (dynamic operator scheduling), a hardware-aware, closed-loop framework that jointly optimizes operator scheduling and blockwise weight layouts. DOPS constructs a stage-aware directed acyclic graph (DAG) and integrates two components: the Bifocal scheduler for dynamic operator-to-device placement and the Weight Layout Arbiter (WLA) for selecting hardware-efficient weight layouts under strict memory constraints. Across representative heterogeneous systems combining neural processing units (NPUs) and processing-in-memory (PIM) devices, Bifocal achieves geometric-mean speedups of 1.20$\times$ to 2.23$\times$ over the PD baseline. WLA provides an additional geometric-mean speedup of 1.28$\times$ to 1.33$\times$ over Bifocal/Linear. DOPS also supports systematic analysis of workload sensitivity and hardware scalability for LLM serving. The source code is available at https://github.com/YIAI-02/TriForm, and the visualization tool is demonstrated at https://youtu.be/Ya_oMCyYno0.

## 2. 论文提出的方法论

### 2.1 核心思想

- 将 LLM 推理建模为一个带权重的 **DAG（有向无环图）调度问题**，节点是可调度的算子（可细分为分片任务），边表示数据依赖与通信开销。
- 通过 **两个优化引擎** 联合优化：
  1. **Bifocal 调度器**：动态决定每个算子放到哪个设备（NPU 或 PIM），并考虑当前设备状态、通信延迟、后继节点影响和跨 token/阶段的权重重用。
  2. **Weight Layout Arbiter (WLA)**：在给定调度器和内存约束下，为每个权重块选择最优存储格式（Linear / NPU_OPT / PIM_OPT），以减少运行时格式转换开销。

### 2.2 Bifocal 调度器

- 基于 list scheduling 思想，在每个调度步骤中对所有 ready 任务计算一个 **bifocal score**，选最小值的任务优先提交。
- Score 由两部分组成：
  - **Near-focus score**: 局部完成时间估计。
    - \( C_{near}(v,k) = (1-\gamma) EFT(v,k) + \gamma \hat{TH}(v,k) \)
    - \( EFT(v,k) \) 是算子在设备 k 上的最早完成时间，计算时考虑：
      - 前驱完成时间 + 数据传输时间
      - 设备可用时间
      - 算子执行时间
      - 由于缓存状态导致的权重重载惩罚
    - \( \hat{TH}(v,k) \) 是 **DAG 窗口 lookahead**：沿后继边（选择最大数据负载路径）探索最多 H 个顶点，进行轻量级模拟，估计对下游的关键路径影响。
  - **Far-focus score**: 长期影响。
    - **Phase-reuse bias (Bphase)**：利用权重-设备提示图 θ，尽量保持同一权重块在执行阶段的设备一致性，减少跨阶段重载开销；在 prefill 阶段若某类设备容量足以驻留全部权重，则给予负偏置（鼓励使用该类设备）。
    - **Token-amortization bias (Btoken)**：decode 阶段考虑剩余 token 数，若一次迁移/重载开销可以在后续 token 中摊销，则允许当前步选择更高成本但长期更优的设备。
- 最终选择 min score 的任务进行提交，并更新设备可用时间、缓存状态、提示图等。

### 2.3 权重布局仲裁器（WLA）

- 形式化：给定权重分块集合 \(B\)，支持格式集合 \(F\)（Linear / NPU_OPT / PIM_OPT），目标是找到分块到格式的映射 \(\phi\)，使 Bifocal 预测的 makespan \(T(\phi)\) 最小。
- 采用 **两阶段块坐标搜索**：
  - **Outer stage（主导性赋值）**：根据前一调度中每个权重块在 NPU/PIM 上的“重载压力”统计量（归一化后），若 NPU 压力显著高于 PIM，则赋 NPU_OPT；反之赋 PIM_OPT；否则保持 Linear。
  - **Inner stage（定向细化）**：对当前格式与实际加载行为不一致的块，尝试另外两种格式，若预测 makespan 下降超过阈值 \(\epsilon\) 则接受翻转。
- 重复内外两阶段直到收敛或达到迭代预算。

## 6. 主要结论与发现

- **动态调度显著优于静态分离策略**：
  - 在 HP32 上，Bifocal 相比 PD 基线的几何平均加速比：
    - Qwen-1.8B：2.23×
    - Qwen-7B：1.36×
    - Qwen-14B：1.44×
    - Llama-7B：1.20×
    - Llama-13B：1.25×
    - Mixtral-8×7B：1.72×
    - Llama-70B：1.20×
  - 验证结果（snippet + AiM simulator）与模拟结果接近，速度提升在 -4%~+6% 的误差范围内。
- **联合布局优化进一步加速**：
  - WLA 在 Bifocal/Linear 基础上增加 1.28×~1.33× 几何平均加速；在短序列场景收益更明显（8.3%~40.4% 的延迟下降）。
  - WLA 以单份存储接近双副本（Dual）理想上界，避免持久内存占用翻倍。
- **设备共利用率（co-utilization）是性能关键**：
  - Bifocal 设备利用率未必最高，但总能获得最高的 NPU–PIM 共利用率，说明“全局时间线感知”优于“局部最快设备”。
- **权重布局偏好随负载变化**：
  - 低 batch/短 decode 时偏向 PIM_OPT；高 batch/长序列时偏向 NPU_OPT；只有平衡场景才保留 Linear。
- **硬件扩展存在边际收益变化规律**：
  - 更长的 prefill、更长的 decode、更大的 batch、更大的模型，都会使“最高边际收益点”向更大的 PIM 容量方向移动。

  - BurstGPT trace 实验使用固定 FCFS 和最大 batch 4，未能完全模拟现代 LLM serving 系统的复杂调度策略（如 PagedAttention、动态 batching 等）。

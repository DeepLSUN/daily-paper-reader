## 摘要
科学问答需要检索系统解决两个不同的问题：识别哪些论文相关，以及在论文中定位支持性证据。传统的检索增强生成通常通过对固定长度的段落进行相似性搜索来解决这两个问题，这会使文档结构扁平化，并将科学主张与其方法论和论证背景分离开来。我们提出了VecTree-RAG，一个智能体框架，将这些任务分配给互补的检索机制。向量搜索对整个语料库中的紧凑文档和章节表示进行排序，而基于推理引导的、经过来源验证的章节树遍历则在入围论文中定位证据。全文保留在页面存储中，仅在结构定位后逐步公开。我们在300个QASPER问题、54个LitQA2问题的开放获取子集以及49个多文档MOSAIC问题上评估了VecTree-RAG。与Dense RAG、重排的Dense RAG、RAPTOR和Search-o1相比，VecTree-RAG在所有三个基准上均获得了最高的观测答案分数，在QASPER上达到0.800的LLM评判正确率，在LitQA2上达到0.925的准确率，在MOSAIC上达到0.547的综合分数。在QASPER上，其证据页面精度为0.274，而基线为0.046--0.071。LitQA2消融实验进一步表明，与没有树导航或语料级向量路由的变体相比，完整的向量-树架构所需的推理令牌更少。这些结果表明，向量检索缩小了语料库级别的搜索空间，树导航则将阅读集中在结构相关的证据上。尽管多轮推理仍比单次调用检索更昂贵，但VecTree-RAG为科学文献问答提供了一种结构感知且可追踪的架构。

## Abstract
Scientific question answering requires a retrieval system to solve two distinct problems: identifying which papers are relevant and locating the supporting evidence within those papers. Conventional retrieval-augmented generation typically addresses both through similarity search over fixed-length passages, flattening document structure and separating scientific claims from their methodological and argumentative context. We present VecTree-RAG, an agentic framework that assigns these tasks to complementary retrieval mechanisms. Vector search ranks compact document and section representations across the corpus, whereas reasoning-guided traversal of source-verified section trees localizes evidence within shortlisted papers. Full text is retained in a page store and exposed progressively only after structural localization. We evaluate VecTree-RAG on 300 QASPER questions, an open-access subset of 54 LitQA2 questions, and 49 multi-document MOSAIC questions. Compared with Dense RAG, reranked Dense RAG, RAPTOR, and Search-o1, VecTree-RAG obtained the highest observed answer score on all three benchmarks, reaching 0.800 LLM-judge correctness on QASPER, 0.925 accuracy on LitQA2, and a 0.547 composite score on MOSAIC. On QASPER, its evidence-page precision was 0.274, compared with 0.046--0.071 for the baselines. LitQA2 ablations further showed that the complete vector--tree architecture required fewer inference tokens than variants without tree navigation or corpus-level vector routing. These results indicate that vector retrieval narrows the corpus-level search space and tree navigation concentrates reading on structurally relevant evidence. Although multi-turn inference remains more expensive than single-call retrieval, VecTree-RAG provides a structure-aware and traceable architecture for scientific literature question answering.

# VecTree-RAG：结合向量与树检索的智能体检索增强生成框架

## 1. 核心问题与研究动机

- **核心问题**：科学问答（Scientific QA）需要检索系统同时解决两个本质不同的任务：① 在语料库中识别哪些论文相关；② 在相关论文内部定位支持性证据。
- **传统 RAG 的缺陷**：标准 RAG 将文档切分为固定长度段落并存入向量索引，对两个问题统一用相似性搜索解决，导致：
  - 文档的章节层级结构被扁平化，检索到的段落与其方法、图表、限定条件等解读上下文相分离；
  - 索引向量数随段落数增长，而多数查询只涉及论文的局部区域；
  - 盲目扩大检索范围会增加冗余，反而掩盖有用证据（Lost in the Middle 问题）。
- **核心洞察**：语料库级论文发现与论文内证据定位需要不同的检索机制。本文据此提出 **VecTree-RAG**——采用"先定位、后阅读"（locate-then-read）的智能体框架，将两个任务分别交给互补的检索机制。

## 2. 方法论：VecTree-RAG 框架

### 2.1 总体设计思想
- **双检索分工**：向量检索负责跨语料库的论文发现（语义 + 词法信号对文档/章节级紧凑表示排序）；树检索沿"来源已验证"（source-verified）的章节树进行推理引导遍历，在入围论文中定位证据页。
- **渐进式披露**（Progressive Disclosure）：全文保留在页面存储中，只有在结构定位完成后才按需逐步暴露，避免一次性向模型灌入大量无关文本。
- **控制器**：ReAct 风格的智能体（≤30 轮迭代），在推理与工具调用间交替执行。

### 2.2 索引构建（来源验证的层级索引）
- **解析**：用 Marker 解析器将 PDF 转为按页划分的 Markdown，保留页面边界与图片位置信息，页面索引作为一切下游模块的坐标基准。
- **结构抽取与验证**：LLM 读取带重叠的页面组（每组 20,000 token，重叠 1 页），输出带点分索引、标题和起始页的结构条目；每条标题需通过 ±1 页容差的子串匹配验证（即章节标题验证率）；失败条目可最多执行 3 轮修复。
- **树构建与有界切分**：按点分索引折叠为树，计算各节点包含性页码范围；超过 20,000 token 且超过 10 页的节点递归重新抽取。
- **富化与元数据**：节点摘要（长节点用前导文本，叶节点用全文；<200 token 的短节保留原文）；文档级生成一句话描述、关键词，并用正则 + LLM + Crossref 三级流程提取验证书目元数据。
- **索引足迹**：向量索引仅包含 N(1+S) 个条目（文档级 + 章节级），而非随语料 token 数线性增长的段落块。

### 2.3 渐进式披露工具接口（7 个工具、3 个层级）
| 层级 | 工具 | 典型返回负载 |
|---|---|---|
| Layer 0（定位） | `search_documents`、`get_paper_metadata` | 约 50 token/结果 |
| Layer 1（导航） | `get_document_tree`、`search_within_paper` | 200–500 token/文档 |
| Layer 2（阅读） | `get_page_content`、`list_images`、`get_page_image` | 500–2,000 token/页 |

- **层 0 检索机制**：SPECTER2 稠密向量（768 维）+ BM25 稀疏打分，每类取每种条目最佳得分，经相关性门控（稠密 ≥0.35 或 BM25 ≥1.0）过滤后，用倒数排名融合（RRF，k=60）合并；语料 >50 篇时设置后融合门控。返回结果附带匹配章节标题，桥接至下一层。
- **层 1 导航**：智能体加载章节树（标题、摘要、页码范围）后直接选择页码，由智能体在工具循环内自主决策。
- **层 2 内容**：按页返回 Markdown 全文，图片可作为视觉输入返回。

### 2.4 查询时算法流程（Algorithm 1）
1. 初始化消息状态 s₁ = [系统提示, 用户查询]，迭代上限 L=30；
2. 每轮由策略 πθ 采样动作（最终回答或工具调用）；
3. 工具调用执行后返回观察值，追加至消息历史；
4. 从第 10 次工具调用起附加"请综合答案"的提醒；
5. 页面请求每次最多 10 页，最终返回最近的非空白助手文本。

## 6. 主要结论与发现

- **互补机制有效**：向量检索负责缩小语料级搜索空间（树导航全部文档时 token 消耗增至 490,482、准确率降至 0.811），树导航在论文选定后提供更经济的文本访问接口（移除树层 token 增至 194,821）。
- **证据定位更集中**：QASPER 证据精度 0.274（基线 0.046–0.071）与 MOSAIC 证据精度 0.221 均为最高，说明结构感知导航能显著减少无关页面的阅读。
- **证据可追踪**：来源验证的层级索引将紧凑表示链接回原始页面，支持逐句引用。
- **代价权衡**：多轮推理比单次调用检索更昂贵，但相对 Search-o1 这类平面搜索智能体，在语料级任务上反而更省 token。

## 7. 主要优点

- **问题分解合理**：将"找论文"与"找证据"分离并分配给异构检索机制，是有说服力的架构设计。
- **源验证索引**：标题出现位置 + 页码容差的确定性校验、3 轮修复循环，降低幻觉式结构提取风险。
- **渐进式披露**：从 ~50 token 的检索结果到 500–2,000 token 的页面内容，有效控制上下文规模，且保留页面级可追踪证据。
- **索引足迹小**：向量数取决于结构条目数而非文本块数；不建段落级向量库。
- **新基准贡献**：提出 MOSAIC 多文档科学综合基准（显式推理链 + 文档-页面证据对），并附构建与质检流程。
- **实验诚实性**：明确区分"设计估计"与实测值、将探索性诊断（LitQA2 页面映射、验证率）与主结论分离，信息披露较完整。

## 8. 不足与局限

- **推理成本偏高**：多轮智能体查询时消耗显著高于单次检索基线（QASPER 41,186 vs 7,660–31,261 token），效率主张仅限于索引表示层面，不承诺端到端推理成本的全面降低。
- **数据偏差风险**：LitQA2 使用开放获取子集并剔除无法索引的金标论文（54/62），存在选择偏差；MOSAIC 由 DeepSeek 模型族自动构建、筛选与评分，缺乏独立人工验证/仲裁，且与生成/评判模型同族，存在模型族偏好风险。
- **评判偏差**：DeepSeek-V4-Pro 评判 DeepSeek-V4-Flash 的输出，答案长度与格式差异可能引入风格偏差，需多族外评判模型复核。
- **适用性局限**：方法假设论文具备有信息量的章节结构，对非结构化文档迁移能力存疑；导航依赖的章节摘要忠实性未经验证。
- **验证范围有限**：索引阶段的验证只检查标题出现与大致位置，不验证摘要忠实性或完整层级；评估中的证据指标只到段落/页面粒度，不度量生成答案中引用的句级精度。
- **可复现性缺口**：未记录有序工具轨迹，无法量化智能体对层级顺序的遵从度；未提供语料匹配的索引存储对比基准；消融无显著性检验。
- **实验覆盖**：QASPER 上用段落代替物理页（每段合成一页），证据指标性质与 PDF 解析场景不完全一致；未在更大规模、更不规则结构的语料上验证。

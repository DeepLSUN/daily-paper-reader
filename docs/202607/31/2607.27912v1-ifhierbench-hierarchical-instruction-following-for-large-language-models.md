## 摘要
指令遵循能力对于在现实应用中部署大型语言模型至关重要，因为下游组件依赖于输出满足特定约束。现代部署越来越多地在一次大型语言模型调用中处理整个任务，通过一个提示指定分层输出，其整体工件、结构部分和嵌套字段必须各自满足具体约束。现有的指令遵循基准将约束集视为一个统一应用于响应的扁平列表，因此它们无法将检查限定在输出的特定部分。我们引入了IFHierBench，一个包含600个提示的分层指令遵循基准，这些提示跨四个约束树深度和35个不同约束进行分层，每个提示配有一个确定性检查器，在每个作用域验证满足情况。评估七个领先的专有和开放权重模型，我们发现即使是最强大的模型也仅以微弱优势超过50%的提示级准确率，并且准确率随着约束深度的增加而急剧下降。可靠地遵循嵌套约束仍然是当前大型语言模型的一个重大差距，这促使未来的训练方法在更细粒度上考虑约束遵循，以实现更好的指令遵循能力。

## Abstract
Instruction-following ability is critical for deploying large language models in real-world applications, where downstream components depend on the output satisfying specific constraints. Modern deployments increasingly handle the full task in a single LLM call, with one prompt specifying a layered output whose overall artifact, structural sections, and nested fields must each satisfy concrete constraints. Existing instruction-following benchmarks treat the constraint set as a flat list applied uniformly to the response, so they cannot scope a check to a particular section of the output. We introduce IFHierBench, a hierarchical instruction-following benchmark of 600 prompts stratified across four constraint-tree depths and 35 distinct constraints, each prompt paired with a deterministic checker that verifies satisfaction at every scope. Evaluating seven leading proprietary and open-weight models, we find that even the strongest model only marginally exceeds 50% prompt-level accuracy and that accuracy degrades sharply as constraint depth grows. Reliably following nested constraints remains a substantial gap for current LLMs, motivating future training methods that consider constraint adherence at finer granularity to achieve better instruction-following ability.

- **现实需求的转变**：随着大模型能力和上下文窗口的增长，现代应用中越来越多地**在单次LLM调用中处理完整任务**，一个提示需同时规定整体输出形态、内部主要区块的结构、以及嵌套字段的具体内容约束。传统"多步分解、逐步拼接"的生产管线正在被"单步全量"取代。
- **现有基准的根本缺陷**：当前指令遵循基准（如 IFEval、IFBench、ComplexBench）将约束视为**作用域统一的平坦列表**，只对整体输出做一致检查，无法把某条约束限定到输出的特定区域（如某个章节、某个字段）。这种"列表化"处理会扭曲失败模式的判断，例如模型只需在响应任意位置包含目标词即可"蒙混过关"，即使该约束本应约束的章节根本没有被生成。
- **论文的核心问题**：**当前LLM能否可靠地遵循这种分层嵌套的输出约束规范？**
- **核心发现预告**：最强模型在提示级准确率上仅勉强超过50%，且随约束深度增加准确率急剧下滑——分层指令遵循仍是当前LLM显著的能力缺口。

## 2. 论文提出的方法论

### 2.1 核心思想
构建一个约束以**树状结构**组织的评测基准：每个提示对应一棵"约束树"，根节点约束整体响应，子节点约束嵌套在其内部的特定区域，逐层嵌套。每条约束都有对应的确定性Python检查器，通过"定位切片 + 逐节点布尔测试"的组合，验证约束在每个作用域的满足情况。

### 2.2 结构级约束分类（基于实证数据）
- 从 GitHub 上 1,525 个仓库的 2,888 条真实 LLM 应用提示中，经清洗得到 **1,232 条含明确输出约束的提示模板**。
- 使用 GPT-5.4 对提示的输出格式进行标注，发现四种最频繁的结构化格式：**Labeled Sections（15.0%）、JSON（14.0%）、List（12.7%）、Markdown（8.9%）**，其余为自由文本 String（50.8%）。
- 实证发现：67.8% 的格式约束提示携带至少一层嵌套作用域；28.2% 的提示声明两种或以上格式；约束规格平均占提示文本的 46.4%。这些发现直接决定 IFHierBench 的设计形态。

### 2.3 构建管线（三阶段）

**阶段一：任务设置准备**
- **任务与上下文提取**：用 GPT-5.4 将 IFEval 种子提示清洗为"去除输出约束的纯内容任务" + "逐字保留的操作上下文"。
- **关键词挖掘**：为每个任务挖掘领域相关的词汇池（供后续约束参数填充）。
- **体裁-格式映射**：识别任务体裁，由其决定可接受的根格式集合（如新闻简讯可接受 JSON/Markdown/Labeled Sections/String，而诗歌拒绝 JSON）。

**阶段二：分层采样**
- **结构级构建**：深度优先遍历约束树。每个作用域先确定形状（string/JSON对象/列表/Markdown文档/标注区块），再为该作用域采样结构级约束（如必含 JSON 键、列表长度、Markdown 标题）。容器作用域递归生成子作用域，最深层子节点强制为原子字符串避免空容器。
- **内容级采样**：在每个作用域内采样内容约束（如关键词、禁用词、大小写、长度），借助**兄弟冲突矩阵**避免不可同时满足的组合，并维护物理互斥组（如"全大写"与"全小写"互斥）。
- **参数回填**：
  - **词汇解析**：关键词等从任务词汇池中抽取，要求不重复、不互为子串、不冲突。
  - **数值解析**：根据词法约束提升计数下限，并施加可读性比例约束（1 ≤ S/P ≤ 8，3 ≤ W/S ≤ 40，3 ≤ C/W ≤ 8）迭代传播边界，直至不动点；若某维下界超过上界则拒绝该组采样。
- **检查器生成**：每个约束类型绑定手写确定性检查器，组合成逐节点验证的层级检查器；每个节点先从父节点文本中解析定位自身作用域，解析失败则该节点及其子树全部失败。

**阶段三：提示构建**
- **模板渲染**：每个叶子约束通过模板渲染为一句自然语言指令，作用域别名由树自顶向下分配（如"the headline""item 1 of bullets"）。
- **约束合并**：将同一作用域内的多个兼容约束按预设合并模板（以0.8概率）合成为更紧凑的句子。

## 3. 实验设计

### 3.1 Benchmark 构成
- **规模**：600 条提示，按约束树深度 0/1/2/3 分层，每层 150 条。
- **约束类型**：35 种，其中 10 种结构级（作用于 JSON/Markdown/List/Labeled 作用域），25 种内容级（作用于字符串作用域）。
- **检查器**：全部为确定性代码校验，无模型辅助评判。

### 3.2 评估模型（7个）
- **专有API**：GPT-5.5（thinking effort=high）、Claude Opus 4.6（high）、Gemini-3-Flash-preview、DeepSeek-R1、Kimi-K2.5。
- **开源权重（本地部署）**：Qwen3.6-35B-Instruct、Gemma-4-26B-It，通过 Ollama 在单张 NVIDIA RTX 4090（24GB）上用 4-bit 量化运行。

- **提示级准确率（Acc_prompt）**：仅当响应满足该提示所有约束时计为正确。
- **指令级准确率（Acc_inst）**：逐个约束独立求平均。

## 6. 论文的主要结论与发现

1. **整体表现偏低**：最强模型 GPT-5.5 提示级准确率仅 53.7%，Claude Opus 4.6 为 42.8%；其余模型均在 33.2% 以下。
2. **深度悬崖效应**：从深度0到深度1，所有模型损失 37-53 个百分点的提示级准确率（GPT-5.5 从 86.7% 降至 49.3%）。这提示当前模型的指令微调数据以平坦约束为主，分层指令遵循是普遍薄弱能力。
3. **深度韧性分化**：GPT-5.5 和 Claude Opus 4.6 在 d=3 仍保有 35.3% 和 22.7% 的准确率，其他五个模型全部跌至 6.0% 及以下。
4. **两类失败模式**：小模型主要呈"逐条遗漏"（指令级准确率远高于提示级，叶子约束常单独通过但难以全部同时满足）；Gemini-3-Flash 呈"整体崩塌"（指令级低于提示级，外层容器失败拖垮整个子树）。
5. **难点集中**：最难的约束类型是数值类精确约束——精确字符数（通过率 53.5%）、精确词数（67.3%）、第N段首词（73.2%）、固定值集合（75.6%）。精确字符数约束尤其困难，可能是因为 IFEval 未覆盖该类型导致训练信号稀缺。
6. **推理策略倾向**：两个最强模型在深度3任务中均更偏向深度优先遍历约束树（Claude 67% DFS、GPT-5.5 62% DFS），而非广度优先。

## 7. 优点

- **问题定义精准**：揭示现有基准"平坦化约束"的关键盲区，问题真实且重要。
- **实证驱动的设计**：结构级约束分类基于 1,232 条真实 GitHub 提示的实证分析，非凭空构造；嵌套深度、混合格式比例等设计参数直接来自语料统计。
- **完全确定性评估**：无模型评判，所有约束由确定性 Python 检查器按树形结构逐节点验证，可复现性高；解析失败即子树失败的设计避免了对错误文本跨区误判。
- **约束树建模清晰**：从平坦约束自然延伸到分层约束，覆盖"格式跨层变化"（子作用域可采用与父作用域不同的格式）这一真实场景。
- **冲突矩阵与参数回填**：保证了合成的约束在逻辑上可满足（不产生无解提示），提升了基准的公平性。
- **提示与检查器同时发布**：每条提示自带对应检查器，降低后续使用者门槛。

## 8. 不足与局限

- **合成提示风格单一**：模板化渲染使提示措辞比自然书写更统一，可能低估用户在真实场景中的多样化表达方式。
- **管线依赖LLM质量**：任务清洗、词汇挖掘、体裁判定由 GPT-5.4 执行，中间产物质量继承底层模型的解析和生成能力；虽有 10% 抽样人工核验达到 90%+ 准确率，但非全量审查。
- **约束深度天花板有限**：最深仅3层，真实生产环境中可能存在更深或更复杂的跨层依赖结构未被覆盖。
- **固定别名与模板的语感偏差**：合并概率 0.8 是人为设定，未做敏感性分析；同一作用域不同约束组合在不同合并模板下可能呈现程度差异。
- **跨格式嵌套的复杂度有限**：虽然允许交叉格式嵌套，但针对"格式切换点"特有的歧义处理（如 JSON 键值内的 Markdown 标题）并未做专项分析。
- 论文本身将此列为局限，但未提及的隐含局限还包括：未与其他基准做归一化对比以说明"同样的模型在旧基准上的分数饱和度"；评估模型集合未包含当时最新的开源旗舰模型；未测试不同温度/采样策略对结果的影响。

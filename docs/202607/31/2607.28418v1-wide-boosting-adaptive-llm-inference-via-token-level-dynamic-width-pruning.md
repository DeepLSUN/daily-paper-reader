## 摘要
剪枝是提高LLM效率的一种有前景的方法。现有的静态结构化剪枝方法硬件友好且能带来实际的吞吐量提升，但其与输入无关的计算分配在激进稀疏度下往往导致显著的精度下降。近期的动态稀疏方法通过使计算适应单个输入来改善质量保持，但仍主要局限于粗粒度的结构决策，且在实际推理场景中的实际加速仍具挑战性。为应对这些挑战，我们提出WIDE——首个面向预填充和解码场景的端到端可微分令牌级动态宽度剪枝框架。WIDE通过允许每个令牌动态选择注意力头组和FFN通道组，将动态剪枝从层级别扩展到神经元块级别，实现细粒度计算分配。通过两阶段训练流程，WIDE学习有效的令牌级稀疏执行模式，并相较现有方法实现显著更优的质量保持。为使此类细粒度动态剪枝切实可行，我们进一步提出一种剪枝-内核协同设计框架，将动态稀疏加速分解为掩码重排序、硬件无关的块级跳过和硬件相关的块内跳过，支持不同粒度下的高效执行。在50%稀疏度下，与最先进的动态深度剪枝相比，WIDE在仅校准设置下提供55.1%的性能提升。在预填充和解码推理工作负载下，WIDE实现接近理论的内核级加速，预填充最高达1.98倍，解码最高达4.95倍，以及1.68倍和1.55倍的端到端加速。我们的代码可在https://github.com/EIT-NLP/LLM-Pruning/tree/main/WIDE获取。

## Abstract
Pruning is a promising approach for improving the efficiency of LLMs. Existing static structured pruning methods are hardware-friendly and can deliver practical throughput gains, but their input-agnostic computation allocation often causes substantial accuracy degradation under aggressive sparsity. Recent dynamic sparsity methods improve quality retention by adapting computation to individual inputs, yet they remain largely limited to coarse-grained structural decisions and their practical acceleration under real-world inference scenarios remains challenging. To address these challenges, we present WIDE, the first end-to-end differentiable token-level dynamic width pruning framework designed for both prefill and decode scenarios. WIDE enables fine-grained computation allocation by allowing each token to dynamically select attention-head groups and FFN-channel groups, extending dynamic pruning beyond layer-level decisions to neuron-block-level granularity. Through a two-stage training pipeline, WIDE learns effective token-wise sparse execution patterns and achieves substantially better quality retention than existing approaches. To make such fine-grained dynamic pruning practical, we further propose a pruning--kernel co-design framework that decomposes dynamic sparsity acceleration into mask reordering, hardware-agnostic block-level skipping, and hardware-dependent intra-block skipping, enabling efficient execution across different granularities. At 50% sparsity, WIDE provides 55.1% performance boost when compared to the state-of-the-art dynamic depth pruning under calibration-only settings. Under prefill and decoding inference workloads, WIDE achieves close-to-theoretical kernel-level speedups of up to 1.98x for prefill and 4.95x for decoding, as well as 1.68x and 1.55x end-to-end acceleration. Our code is available at https://github.com/EIT-NLP/LLM-Pruning/tree/main/WIDE.

  2. 这种细粒度的动态决策能否被高效执行，转化为真实端到端加速？

## 2. 方法论

### 2.1 核心思想

WIDE 允许每个 token 在每一层内独立选择激活哪些**注意力头组**和 **FFN 通道组**，而非简单地跳过整个层。通过轻量级瓶颈路由器生成分组决策，配合两阶段训练学习稀疏执行模式，并通过定制 GPU 内核将动态稀疏转化为实际加速。

### 2.2 剪枝单元设计

- **注意力剪枝单元**：以 GQA（Grouped Query Attention）对齐的头组为最小原子单元。掩码 `M_attn ∈ {0,1}^{B×Tq×Hk}`，其中组大小 `G = (Hq/Hk) × d`，保留 GQA 解码优化的兼容性。
- **FFN 剪枝单元**：以与 GEMM tiling 尺寸匹配的通道组（`G ∈ {16, 32, 64, 128, 256, 512...}`）为原子单元，掩码 `M_ffn ∈ {0,1}^{B×T×(D′/G)}`。单掩码同时覆盖 Up/Gate 投影的输出维度和 Down 投影的输入维度。

### 2.3 路由器设计

- 采用**瓶颈架构**：`R = reshape(XW₁W₂)`，其中 `W₁ ∈ R^{D×r}`，`W₂ ∈ R^{r×2NG}`，`r ∈ {16, 32}`。
- 训练时使用 **Gumbel-Softmax 硬采样**（温度从 5 线性退火至 0.5），推理时使用 argmax。
- 输出维度设为 `2 × NG` 以对齐 Gumbel-Softmax。

### 2.4 两阶段训练

1. **阶段一：Router 训练**——冻结所有非路由参数，仅用校准数据优化路由组件。
2. **阶段二（可选）：LoRA 恢复**——在所有线性层中加入 LoRA 以进一步恢复质量。
3. 总损失：`L = LLM + α·[S − (1/N)·Σ(注意力稀疏率 + FFN 稀疏率)]`，强制整体稀疏率达到目标。

### 2.5 推理加速：剪枝-内核协同设计

- **朴素 gather-scatter 的两大障碍**：
  1. 设备到主机同步（破坏 CUDA Graph）；
  2. 巨量额外内存搬运（N 轴/K 轴剪枝的中间存储达 `O(pMNK)`）。
- **WIDE 的解决方案**：
  1. **掩码重排序预处理**：将每个路由组的掩码按 M 维排序，激活行聚集成前缀，将不规则 token 路由转化为 CTA 级规则性（`SortDesc(M:,g)`）。
  2. **三级跳过谓词**：`s(ℓ) = OR over row block of mask`，其中：
     - `ℓ=0`：硬件无关的 CTA 级早期退出；
     - `ℓ=1`：硬件相关（如 cp.async/TMA）的 A 加载包跳过；
     - `ℓ=2`：硬件相关（如 wmma/wgmma/tcgen05.mma）的 MMA 片段跳过。
  3. **四种定制内核**：GEMM-MN（Q/Up/Gate 投影）、GEMM-K（O/Down 投影）、Attention（FlashAttention 风格）、GEMV 变体，覆盖预填充和解码场景。

## 6. 主要结论与发现

1. **质量保持显著优于现有方法**：
   - 校准-only 设置下，8B/50% 稀疏度时 WIDE（G=32）平均准确率 61.84%，比最强静态宽度剪枝基线 DDP（53.04%）高 8.80 分；比最强动态深度基线 SkipGPT 提升 55.1% 的相对性能。
   - 3B/50% 稀疏度时同样高 8.97 分。
   - LoRA 恢复后，WIDE 达到约 90% 的稠密性能保留率，仍优于 SkipGPT（低 3.22–4.44 分）和 DDP（低 10 分以上）。
2. **接近理论上限的加速**：
   - 内核级加速：预填充最高 1.98×，解码最高 4.95×；
   - 端到端加速：预填充 1.68×，解码 1.55×；
   - 未加速的固定开销（KV 投影、逐元素操作、CUDA Graph 启动等）约占预填充延迟的 16.7% 和解码延迟的 29.1%。
3. **组大小选择的鲁棒性**：G 在 32–256 范围内精度差异较小；过大（512）时精度下降明显。较大 G 在加速方面更有利（GEMM-K 需要 G≥128 才能达到理想加速）。
4. **路由行为具有语义感知性**：路由器倾向于在深层（L24–26）的注意力和中层（L9–11）的 FFN 施加更高稀疏度；语义内容词（如 boy、running）被保留，功能词（如 a、the）更可能被跳过。
5. **朴素 gather-scatter 不可行的原因得到量化验证**：N 轴/K 轴动态剪枝的朴素实现需要约 1000× 的额外峰值内存，吞吐仅约 1 TFLOPS，而 WIDE 的 CuTe 内核几乎零额外内存开销，性能接近稠密 GEMM。

## 7. 优点

1. **粒度突破**：首次将 token 级动态剪枝从层/子层粒度推进到注意力头组和 FFN 通道组的神经元块粒度。
2. **剪枝-内核协同设计**：不是模型压缩的“事后”系统优化，而是将路由设计与 GPU 执行路径统一设计——掩码重排序将不规则动态稀疏转化为规则稠密 tiling，多级跳过错开负载，直接解决动态稀疏“算得快但跑不快”的痛点。
3. **训练高效**：仅需校准数据训练轻量路由器（约 10k 步），即可达到或超过其他方法 LoRA 恢复后的精度；可选 LoRA 进一步恢复。
4. **实现完整且工程化强**：三种实现层次（Triton/Tilelang/CuTe）使内核可以从 CTA 级粗粒度跳过扩展到线程/warp 级的 MMA 跳过，且兼容 CUDA Graph。
5. **实验严谨**：对比方法覆盖静态与动态、深度与宽度剪枝的代表性方法；对朴素实现的代价给出了理论分析（附录 A）与实验验证（附录图 11）的双重证据。
6. **分析的深度**：对路由行为做 token 级可视化，揭示路由器学到的语义感知稀疏模式，而不仅是报一个准确率。

## 8. 不足与局限

1. **模型覆盖范围有限**：仅验证 Llama3.1-8B 和 Llama3.2-3B，未在更大模型（70B+）、更小模型（<1B）或其他架构（Mistral、Qwen、DeepSeek）上验证。
2. **硬件覆盖有限**：所有推理实验在 RTX 5090（sm120）上完成，未在 A100/H100 等数据中心 GPU 上验证加速效果；ll=1/2 级跳过依赖具体架构，不同 GPU 上的收益可能差异显著。
3. **内核算法的可移植性局限**：GEMM-K 在 sm90+ 可用的 `cp.reduce.async.bulk.tensor` 优化在 sm120 上因共享内存容量限制被放弃；DDP 式原子写回的竞争在高稀疏度下可能成为瓶颈。
4. **评估维度单一**：精度指标全部为零样本任务，未报告微调后的效果、生成质量（如 MT-Bench）、或与量化/投机解码等正交优化的叠加效果。
5. **端到端加速仅为单层对比**：层的端到端分析基于单层延迟分解（图 4），未报告完整模型端到端吞吐的 batch size 多档位、多并发条件下的系统级指标。
6. **L 的训练假设**：校准数据采用 RedPajama-1T 子集，与预训练分布接近且数据量大（10k 步×16 批×4096 长度约 6.7 亿 token，若全用真实数据则非“低资源”场景）；在真实低资源校准场景（几千条样本）下的表现未知。
7. **路由开销未完全消除**：路由器执行、掩码排序、零初始化和原子写回等额外开销在解码（固定开销占 29.1%）中仍然显著，限制了更高加速比的天花板。
8. **朴素 gather-scatter 基线可视为较弱的对照**：论文明确指出该基线未使用分组 GEMM 等优化，虽然这印证了内核算法的必要性，但公平性对比中宜补充更优的基线。
